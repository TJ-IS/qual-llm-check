# Bounded delegation protocol

Delegation is optional. Use it only when work is independent enough to reduce elapsed time or add a distinct capability.

## Send a frozen package

Include:

- task ID and one narrow responsibility;
- applicable requirement-control IDs, statuses, and exact clauses from `docs/research_program/requirement_registry.md`;
- exact manuscript, paper, major section, and predecessor status;
- canonical ledger files and exact relevant headings/entries;
- original source files and complete sections to inspect;
- accepted claims, open questions, and rejected source uses;
- explicit exclusions and non-goals;
- acceptance gates and required return schema;
- whether file edits are allowed.

Send the authoritative clauses and relevant ledger entries behind each control ID. A list of IDs or a prose summary without the rule/source text is not a sufficient package.

For sentence-prototype work, also send the frozen authority-corpus manifest, the relevant function/query used for discovery, each target paragraph, the candidate's exact source paragraph and carrying-section window, and the current prototype status. Author protocols may use a looser function match but may not omit a prototype. Punctuation is returned as a prototype-comparison dimension, not an independent count verdict.

When possible, record a content hash or timestamp for the frozen inputs. If inputs change, invalidate or explicitly rebase the package.

## Require evidence-level output

The return should state:

- requirement-control IDs actually applied and any conflict found;
- originals and complete sections actually read;
- claim/source/location/boundary records;
- proposed paragraph or artifact change;
- competing interpretation or rejection reason;
- confidence and unresolved blocker;
- files changed, if authorized.

Reject generic advice that cannot be traced to the package evidence.

## Avoid redundant review

Do not launch several agents to perform the same broad manuscript review. Prefer non-overlapping packages such as source verification, feasibility, citation-network tracing, or a specific section's macro-structure. Independent duplication is justified only for a named high-risk decision, and its stopping rule must be explicit.

The primary agent must directly inspect decisive source text, current user correction when relevant, and the returned prose. Agent agreement is not acceptance. When an agent exposes materially incompatible operative requirements, the primary agent preserves both readings and asks the user to adjudicate; it does not use agent majority as the tiebreaker. Integrate the useful result into the canonical ledger and requirement registry when a durable rule changed; do not create an isolated agent-only ledger.
