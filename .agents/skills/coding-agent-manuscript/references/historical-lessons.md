# Historical calibration

The task catalog is `docs/research_program/conversation_catalog.md`; current normalized controls and supersessions are in `docs/research_program/requirement_registry.md`. A task-level catalog is not proof that its message-level requirements entered the skill. Apply these durable lessons:

- Open coding and competing-theory comparison improved early construct work; theory chosen before comparison caused anchoring.
- v3/v3.1/v7 showed that complete-looking architecture, citation totals, paragraph counts, hashes, and internal audits can create false finality.
- v8 showed that data/participant feasibility must be a hard early gate; paper three was correctly withdrawn only after its burden became explicit.
- The 2026-08 public-data screening succeeded because scope, prompt, model, and execution were frozen before the complete run. Its later manuscript phase failed when the task expanded into a long writing Goal.
- v10 established full-section authoritative comparison, but user review exposed sparse/repeated citations, punctuation habits, construct overload, and weak design-principle mapping.
- v11 improved persistent evidence and citation-network ledgers. v15 still failed at macro level: headings were fragmented, major sections were sparse, and methods/evaluation dominated. Atomic mappings did not protect the reader-level argument.
- Earlier sentence-anchor work optimized semantic similarity and mapping coverage without protecting macro prose. The confirmed `M-ANCHOR-01/L26` instead requires every visible sentence to learn from a verified authoritative IS writing prototype after the major-section argument is established. Similarity concerns rhetorical function, construction, citation responsibility, local logic, and punctuation function—not identical claims or wording; novel methods and expected results use looser functionally analogous disclosure prototypes.
- Natural scholarly prose and audit-language separation remain active under `M-PROSE-01`. The independent punctuation-zero branch is superseded under `M-PUNCT-01/L24`; punctuation is inspected inside sentence-prototype and paragraph comparison.
- Classical theory can remain valid while an old paper is unsuitable as the current writing paradigm. Use recent full sections for prose calibration and verified lineage for old theory.
- Requirements must survive task boundaries through a public normalized registry and, when needed, a private minimal-excerpt provenance audit. Raw transcript dumps remain excluded.

Therefore:

1. Use repository checkpoints, not Goal completion, as continuity.
2. Write and compare one complete major section at a time.
3. Separate evidence quality, macro narrative, feasibility, and style gates.
4. Preserve user corrections as rejection records, not temporary chat feedback.
5. Use agents sparingly with exact ledger/source packages.
6. Finish bounded sections, then run a separate whole-manuscript integration gate.
7. When material requirements conflict, present both readings, consequences, and a recommendation to the user. After confirmation, update the authoritative rule, requirement registry, private provenance audit, and conflicting mandatory ledgers in the same checkpoint.
