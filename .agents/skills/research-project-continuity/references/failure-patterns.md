# Failure patterns and corrective controls

## Long-running Goal drift

**Symptom:** requirements, literature review, three manuscripts, screening, and audit accumulate into one Goal; completion is declared after high cost while the visible paper remains weak.

**Control:** one inspectable artifact or complete major section per checkpoint; repository state and user acceptance replace Goal status.

## Mechanical acceptance substitution

**Symptom:** hashes, mapping coverage, citation counts, banned-punctuation scans, or paragraph counts produce `PASS` despite thin arguments or poor prose.

**Control:** metrics trigger direct inspection. Major-section narrative, evidence responsibility, feasibility, and human-visible prose have separate gates.

## Ledger-to-prose leakage

**Symptom:** every debt, construct, or validation item becomes a heading or sentence, fragmenting the section.

**Control:** build reader questions and paragraph functions first; keep most governance state in the ledger.

## Evidence summary drift

**Symptom:** an agent summarizes a few source fragments, then compares the manuscript to the summary rather than the original section.

**Control:** directly inspect the complete carrying section and, when possible, adjacent major sections. Preserve exact source boundaries.

## Redundant delegation

**Symptom:** multiple agents repeat broad reviews, create disconnected ledgers, and consume time without resolving a named decision.

**Control:** frozen non-overlapping packages, evidence-level return schema, explicit stopping rule, and primary-agent spot check.

## Late feasibility

**Symptom:** prose and theory expand before data identity, participants, access, or analysis topology are viable.

**Control:** feasibility is an early hard gate; demote, redesign, or withdraw rather than hide the burden.

## Mixed-status history

**Symptom:** a successful screening phase causes a later failed manuscript phase—or vice versa—to receive one global verdict.

**Control:** label artifacts and phases separately; preserve predecessor/successor and user-correction records.

## Silent contradiction resolution

**Symptom:** a newer skill entry, agent consensus, or convenient interpretation quietly overrides an older mandatory ledger, so the repository appears consistent while the user never approved the trade-off.

**Control:** register the requirement as `conflict`, freeze both readings and affected decisions, present consequences and a recommendation to the user, and update all owners only after confirmation.
