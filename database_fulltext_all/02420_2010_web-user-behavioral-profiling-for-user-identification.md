# Web user behavioral pro<sup>fi</sup>ling for user identi<sup>fi</sup>cation

Yinghui (Catherine) Yang

Graduate School of Management, University of California, Davis, One Shields Ave., Davis, CA 95616, United States

## a r t i c l e i n f o

Article history: Received 3 January 2008 Received in revised form 24 January 2010 Accepted 4 March 2010 Available online 9 March 2010

Keywords: Data mining User pro<sup>fi</sup>les User identi<sup>fi</sup>cation Behavioral patterns

## a b s t r a c t

In this paper, we propose a simple, yet powerful approach to pro<sup>fi</sup>le users' web browsing behavior for the purpose of user identi<sup>fi</sup>cation. The importance of being able to identify users can be signi<sup>fi</sup>cant given a wide variety of applications in electronic commerce, such as product recommendation, personalized advertising, etc. We create user pro<sup>fi</sup>les capturing the strength of users' behavioral patterns, which can be used to identify users. Our experiments indicate that these pro<sup>fi</sup>les can be more accurate at identifying users than decision trees when suf<sup>fi</sup>cient web activities are observed, and can achieve higher ef<sup>fi</sup>ciency than Support Vector Machines. The comparisons demonstrate that pro<sup>fi</sup>le-based methods for user identi<sup>fi</sup>cation provide a viable and simple alternative to this problem.

## 1. Introduction

The development of Information Technology has led to an explosion of data. Businesses now gather and store more consumer data than ever before. Similarly, the amount of recorded data associated with individual users has grown tremendously in recent years. This is particularly true in the online world. User information is collected through online registrations and surveys. Moreover, information about a web user's activity is often collected surreptitiously, even as the user browses the web. Ef<sup>fi</sup>ciently summarizing user-level information so that it can be used effectively in electronic commerce is an important problem.

User pro<sup>fi</sup>les can help to summarize the large amounts of information available from a user and to achieve goals such as product recommendations and personalized information delivery. A user pro<sup>fi</sup>le can include explicit information provided by users through registration and surveys [5,31]. Demographics such as a user's name, telephone number, address and information about hobbies are often offered by users explicitly. The simple facts about users' activity or transactions can also be categorized as explicit information. For example, such facts can include the frequency of a user's visit to a web site, the average amount of money spent per purchase transaction and the most purchased product category. A user pro<sup>fi</sup>le can also contain implicit information that is generated from analyzing users' activity often through more sophisticated statistical or data mining techniques (e.g. <sup>fi</sup>nding usage rules [4]).

In this paper, we build implicit user pro<sup>fi</sup>les for the purpose of user identi<sup>fi</sup>cation. Previous research on web user identi<sup>fi</sup>cation has focused mainly on the use of tracking techniques such as cookies, logins and keys [20,23]. Below, we de<sup>fi</sup>ne the problem of user identi<sup>fi</sup>cation based on user pro<sup>fi</sup>les built on web usage patterns. We establish a user pro<sup>fi</sup>le for each user from a group of known users based on their web activities, and a given anonymous web session or a series of sessions can get matched (or identi<sup>fi</sup>ed) to be one of these users or none of these users (i.e. if the matching score is very low, then we can say that the user is not matched to any one of the pro<sup>fi</sup>les). This is different from most biometric-based identi<sup>fi</sup>cation (e.g. <sup>fi</sup>nger print or iris identi<sup>fi</sup>cation). For example, <sup>fi</sup>nger print identi<sup>fi</sup>cation is able to handle very large scale identi<sup>fi</sup>cation problems because there is a unique match between the <sup>fi</sup>nger print and a user. Behavior-based identi<sup>fi</sup>cation will be less accurate when it comes to large scale problems because many users could share similar behavioral patterns. Therefore, identifying web users based solely on their online behavior rather than using tracking techniques is a dif<sup>fi</sup>cult problem. Under cases where user identi<sup>fi</sup>cation based solely on behavior is not feasible, behavioral information can be used together with other tools to achieve better performance. For example, for a large online retailer, several user accounts may share the same IP address (e.g. members of the same family). The retailer might be able to identify the members sharing the same IP address (assuming that there is some known login information from this IP address which can be used to build user pro<sup>fi</sup>les). The ability to further identify users within the shared IP address can help achieve higher performance for many applications.

The Federal Financial Institutions Examination Council (FFIEC) advocates that authentication methodologies should involve multiple channels to avoid exploiting single channel authentication systems. Behavioral pattern-based user identi<sup>fi</sup>cation systems, if designed properly, may provide one such additional channel in a multi-channel approach. Designing such a system will require developing accurate user identi<sup>fi</sup>cation models. This in turn requires a deeper understanding of the factors in user behavior that can result in greater accuracy in user identi<sup>fi</sup>cation. Our research in this paper focuses on <sup>fi</sup>nding such factors in capturing users' behavioral patterns using user pro<sup>fi</sup>les.

The recurring nature of one's behavior can potentially bene<sup>fi</sup>t user identi<sup>fi</sup>cation. Behavioral patterns can represent the repeating elements in users' activity. In the web context, such patterns can capture web users' repeat visits to certain sites (e.g. in 40% of the days, a user visits yahoo.com). Some more examples are: (a) 80% of a user's web sessions<sup>1</sup> are over one hour long. (b) The number of pages a user visits in a web session is often between 5 and 10. (c) Most of a user's sessions start with cnn.com. The extent to which a behavioral pattern repeats itself can be captured by the strength of a behavioral pattern. In this paper, we pro<sup>fi</sup>le web users according to the strength of their behavioral patterns. The behavioral patterns are learned from users' web browsing activity (e.g. visiting msn.com is a frequent behavioral pattern). Such frequent behavioral patterns can be discovered using existing frequent pattern discovery methods (e.g. Apriori [2]). Metrics similar to support and lift are used to measure the strength of a behavioral pattern. For example, if 50% of a user's web sessions contain MySpace.com, then 50% measures the strength of the pattern — visiting MySpace.com in a web session. If we consider MySpace.com as an item, then 50% is the support of this item [2]. A list of behavioral patterns together with metrics measuring their strength is stored in a user's pro<sup>fi</sup>le. At a certain point of time, user pro<sup>fi</sup>les are built <sup>fi</sup>rst on the data before that time (the pro<sup>fi</sup>ling stage), and then are applied to the data observed after that time point in order to identify users (identi<sup>fi</sup>cation stage).

We conduct extensive experiments on user-centric web data to evaluate the effectiveness of using our pro<sup>fi</sup>ling approach to identify web users. We compare our pro<sup>fi</sup>le-based user identi<sup>fi</sup>cation procedure with the classi<sup>fi</sup>cation models and demonstrate that pro<sup>fi</sup>lebased methods can be more accurate at identifying users than decision trees when suf<sup>fi</sup>cient web activities are observed, and can achieve higher ef<sup>fi</sup>ciency than Support Vector Machines. The comparisons demonstrate that pro<sup>fi</sup>le-based methods for user identi<sup>fi</sup>cation provide a viable and simple alternative to this problem.

User identi<sup>fi</sup>cation based on behavioral information can be applied in various situations. It can be directly applied to situations where enough distinctive information about the users is available. Such situations could include small to medium sized web sites, intranets and environments with shared computers. Sometimes user identi<sup>fi</sup>cation is the ultimate goal and sometimes it is an intermediate goal to help achieve better personalization and targeting. Even though the data set we used in this paper is user-centric (a richer source for researching web user behavior [33]), the same idea can be applied to data collected by a web site as well. The site-centric data has very detailed behavioral information about pages users visited within the site. If a web site is able to capture enough information about its users, the site can adopt the same method of pro<sup>fi</sup>ling to capture the strength of users' behavioral patterns. If a site can identify a user who is not explicitly signed in, there may be opportunities for targeted recommendations. When the scale of a site gets large, which makes identi<sup>fi</sup>cation based solely on behavioral information infeasible, behavioral patterns can be combined with other tracking tools to enhance performance (see the Conclusion section for more detailed discussion).

There are also potential client-side applications that can bene<sup>fi</sup>t directly from pro<sup>fi</sup>ling user-centric data. First, af<sup>fi</sup>liated web sites can share data among themselves (e.g. Windows Live ID, originally Microsoft Passport, is based on similar ideas of sharing information among af<sup>fi</sup>liated web sites). User pro<sup>fi</sup>les across these af<sup>fi</sup>liated sites can certainly help them coordinate product recommendations. Second, users may opt-in to download client-side software from a trusted third party that will track client-side activity to build user identi<sup>fi</sup>cation models. Such models may be used to provide behavioral authentication services on behalf of the user. Other potential client-side or user-centric applications can also be found in existing research [14,15,29].

The contributions of this paper are as follows. First, we introduced a simple, yet powerful method for generating user pro<sup>fi</sup>les from web usage data. The pro<sup>fi</sup>les capture the strength of user behavioral patterns. We conducted systematic experiments to compare the performance of the pro<sup>fi</sup>le-based approach and the classi<sup>fi</sup>cation models, and have found good results. Second, this paper is among the <sup>fi</sup>rst to study user behavior patterns in web usage data for the purpose of user identi<sup>fi</sup>cation. We applied user pro<sup>fi</sup>les for a new application — user identi<sup>fi</sup>cation, and proposed a framework for pro<sup>fi</sup>ling and identifying users. The framework was applied in the user-centric web browsing context and was demonstrated to be effective at identifying users.

The rest of the paper is organized as follows. In Section 2, we survey the research on user pro<sup>fi</sup>ling and user identi<sup>fi</sup>cation. Section 3 formulates the problem of using user pro<sup>fi</sup>les to identify users and describes the detailed procedure for user pro<sup>fi</sup>ling and user identi<sup>fi</sup>cation. In Section 4, we extensively evaluate the proposed method using 140 sub-datasets derived from a large dataset that captures user-centric web browsing activity. Finally, we discuss limitations and future work in Section 5. We also include the procedures used to ef<sup>fi</sup>ciently update user pro<sup>fi</sup>les and user rankings in the Appendix.

## 2. User pro<sup>fi</sup>les and user identi<sup>fi</sup>cation

In the data mining community, user pro<sup>fi</sup>ling is often studied in the context of personalization [4,25] and fraud detection [7,13,18,19]. In the information retrieval community, user pro<sup>fi</sup>les are used for personalized information retrieval or <sup>fi</sup>ltering [12,16,37].

Constructing accurate and comprehensive user pro<sup>fi</sup>les of individual users is one of the key issues in developing personalization applications. A user pro<sup>fi</sup>le normally contains a list of variables [8,9] and/or conjunctive rules (e.g. association rules [2,3] and classi<sup>fi</sup>cation rules [6]). Ref. [4] studies user pro<sup>fi</sup>les as a set of rules. Their focus is on rule validation since there are large numbers of rules discovered for each user. Rules validated by experts serve as the user pro<sup>fi</sup>les. Instead of just individual user pro<sup>fi</sup>les for personalization, there has also been work on learning aggregate pro<sup>fi</sup>les, such as the work of Ref. [25], which builds pro<sup>fi</sup>les that can apply across groups of users who may have similar interests. They use clustering to generate aggregate user pro<sup>fi</sup>les which are evaluated in the context of providing recommendations as an integrated part of a personalization engine. Rather than learning pro<sup>fi</sup>les from click-stream data, Ref. [17] describes an approach that unobtrusively monitors user activity on pages (such as how much the user scrolls) to build pro<sup>fi</sup>les that capture user interest in speci<sup>fi</sup>c pages or content.

There is also other user pro<sup>fi</sup>ling work based on web usage data that is not associated with personalization. Ref. [27] generates user pro<sup>fi</sup>les from various web log <sup>fi</sup>les of a web site. They assume that the owner of the web site de<sup>fi</sup>nes a list of topics and associates each web page with one or more of these topics. A user pro<sup>fi</sup>le is generated according to the time the user spent on the web pages of different topics. Ref. [30] generates pro<sup>fi</sup>les from server logs of a career web site. A user pro<sup>fi</sup>le is generated from the number of clicks on job openings. Ref. [34] builds a rule-based web user pro<sup>fi</sup>ling platform that can be applied to different web services to generate user pro<sup>fi</sup>les from their usage data, and the platform is not tied to any speci<sup>fi</sup>c applications. None of the previous research on user pro<sup>fi</sup>ling using web usage data has considered user identi<sup>fi</sup>cation based on user-centric data.

The use of pro<sup>fi</sup>les for fraud detection is crucial, since it is not possible (in real time) to extract and analyze all the associated records in order to detect a potentially fraudulent deviation in behavior. Using pro<sup>fi</sup>les for fraud or intrusion detection is often studied in the context of telecommunication and network intrusion. For fraud and intrusion detection, pro<sup>fi</sup>les are used in two ways: in signature-based detection methods, and in anomaly detection methods [9,10]. In signaturebased methods, a library of aberrant attack pro<sup>fi</sup>les (called signatures) is stored in a signature data base. Pro<sup>fi</sup>les of user's recent traf<sup>fi</sup>c are then compared to these signatures to detect fraudulent behavior. In anomaly detection, the pro<sup>fi</sup>le for each entity is itself the baseline for comparison. A well formulated pro<sup>fi</sup>le captures the typical behavior of a user, allowing one to compare recent events to the appropriate pro<sup>fi</sup>le to ensure that the behavior is within the norm. New traf<sup>fi</sup>c for a user is compared against their individual pro<sup>fi</sup>le to determine if the user's behavior has changed. A signi<sup>fi</sup>cant departure from the baseline is a signal that the account may have been compromised [9]. The pro<sup>fi</sup>ling problem within the context of fraud detection was <sup>fi</sup>rst studied in Ref. [13] in the cellular phone industry. The call data is organized by account, and each call record is labeled as fraudulent or legitimate. The rule learning system is applied to an account's calls and it produces a set of rules that serve to distinguish, within that account, the fraudulent calls from the legitimate calls. The performance of the system was compared with that of manual systems. Ref. [18] also studies telecommunication fraud. They implement three different variable-based user pro<sup>fi</sup>les and each pro<sup>fi</sup>le's ability to characterize user behavior in order to discriminate normal activities from fraudulent ones is tested using feed-forward neural networks. The evaluation schema in the fraud detection domain is more straightforward than that for personalization. The performance measurement is simply the accuracy in identifying fraud in the testing data (both false positive and false negative).

In the information retrieval context, a user pro<sup>fi</sup>le takes into account the feedback of the retrieval task, that is, the relevance of the previously returned documents. Research in information retrieval is now moving into a personalized scenario where a retrieval or <sup>fi</sup>ltering system maintains a separate user pro<sup>fi</sup>le for each user. In this context, user pro<sup>fi</sup>les are often generated to capture users' feedback (both explicit and implicit) to the retrieval results. Users can indicate explicitly whether a retrieved document is relevant, or the retrieval system can implicitly guess out the users' feedback based on users' interaction with the documents (e.g. mouse and keyboard usage, page, navigation, book-marking, and editing) [37]. Such pro<sup>fi</sup>les often contain a list of words [12]. The evaluation is on the retrieval performance. This type of pro<sup>fi</sup>le is not the focus of this paper.

There is currently no research on building user behavioral pro<sup>fi</sup>les from web usage data for the purpose of user identi<sup>fi</sup>cation. Previous research on web user identi<sup>fi</sup>cation has mainly focused on using tracking techniques such as cookies [20], web bugs [20], login [23] and keys [23]. Ref. [1] also disclosed several ways of identifying users and collecting demographic information and market information, including branding a browser with a unique identi<sup>fi</sup>cation in each user request, identifying a user by key strokes or mouse clicks, gathering demographic information using multiple datasets and by monitoring network traf<sup>fi</sup>c. Very limited research is being done on analyzing web users' behavior for user identi<sup>fi</sup>cation. Our previous research [28] sheds some light on the possibilities of user identi<sup>fi</sup>cation based on users' web usage behavior, and it demonstrates that users can be identi<sup>fi</sup>ed, to some extent, based on their behavior if enough information is observed. In our current research in this paper, we further investigate whether user pro<sup>fi</sup>les can help to identify users based on their behavioral patterns.

Recently, with the widespread use of technology, there has been substantial interest in identifying unique behavioral characteristics that can possibly serve as identi<sup>fi</sup>ers in domains outside of web usage. Ref. [26] shows that users have distinct mannerisms in which they use computer keyboards, and that users have unique keystroke dynamics. Ref. [11] extends this work to the use of mouse movements in addition to keystroke dynamics, and they note that the combination can often be used to uniquely identify humans. Ref. [22] shows that authors have unique writing styles that enable identifying them from text. In a similar vein, Ref. [21,35] shows that users have unique writing patterns when they author content for online message boards.

## 3. Building user pro<sup>fi</sup>les for user identi<sup>fi</sup>cation

User identi<sup>fi</sup>cation through behavioral patterns is a new and exciting area of research. In this paper, we propose a simple yet powerful (as shown in the experiments) pro<sup>fi</sup>le-based method for user identi<sup>fi</sup>cation.

A general framework for user identi<sup>fi</sup>cation based on user pro<sup>fi</sup>les is depicted in Fig. 1. User pro<sup>fi</sup>les are built from consecutive web sessions with known user IDs. These pro<sup>fi</sup>les are used to predict the owner of future anonymous web sessions (i.e. user identi<sup>fi</sup>cation). More speci<sup>fi</sup>cally, we assume a web browsing dataset containing N users $U =$ $\{ u _ { 1 } , u _ { 2 } , . . . , u _ { N } \}$ . We pick la time T as the present time. Before time T, user u<sub>i</sub> has $E ( u _ { i } )$ number of web browsing sessions $\{ e _ { i } ^ { 1 } , e _ { i } ^ { 2 } , . . . , e _ { i } ^ { E ( u ) } \}$ , where $u _ { i } { \in } \{ u _ { 1 } , u _ { 2 } , . . . , u _ { N } \}$ . The sessions are ordered by time. The problem of building user pro<sup>fi</sup>les for user identi<sup>fi</sup>cation is de<sup>fi</sup>ned as learning the pro<sup>fi</sup>les of users by using sessions observed before time T to help in identifying users after time T, upon observing anonymous sessions.

At time T, upon observing the web activity (organized into labeled web sessions with known user IDs) of N users $( U = \{ u _ { 1 } , u _ { 2 } , . . . , u _ { N } \} )$ ), the user pro<sup>fi</sup>le for user $u _ { i } ( \mathrm { f o r } i = 1 \mathrm { t o } N )$ is constructed from user u 's web sessions or together with other users' web sessions (Pro<sup>fi</sup>ling Stage, see Section 3.1). Looking forward from time T, a series of web sessions coming from an anonymous user is observed. Based on the behavioral patterns we observe from the list of new sessions, we estimate the likelihood that these new sessions are generated by a certain user (Identi<sup>fi</sup>cation Stage, see Section 3.2).

The curved arrows indicate that each component in the procedure is dynamic. As new data comes in, we can update the present time T and update the user pro<sup>fi</sup>les incorporating more recent data. When time T and the user pro<sup>fi</sup>les are <sup>fi</sup>xed, we can also update the user rankings used for user identi<sup>fi</sup>cation as we observe more anonymous sessions (see the Appendix for methods used to update user pro<sup>fi</sup>le and rankings ef<sup>fi</sup>ciently). The users ranked on the top are the users who are most likely generating the new anonymous sessions.

## 3.1. Profiling stage

The <sup>fi</sup>rst stage in the procedure illustrated in Fig. 1 is to build user pro<sup>fi</sup>les. We <sup>fi</sup>rst construct user pro<sup>fi</sup>les based on the within-user strength of behavioral patterns, then both the within-user strength and the overall strength of behavioral patterns. Let $P _ { \mathrm { a l l } } { = } \{ P _ { 1 } , P _ { 2 } { , } { \ldots } , P _ { K } \}$ be the list of patterns we consider when building the pro<sup>fi</sup>les. K is the number of candidate patterns considered. Below, we de<sup>fi</sup>ne the within-user strength of a behavioral pattern.

## De<sup>fi</sup>nition 1. Within-user pattern strength.

For a given user, the within-user strength of a behavioral pattern is equivalent to the support of a pattern among all the sessions of this user (i.e. the number of sessions containing this pattern divided by the total number of sessions of a user).

Fig. 2 illustrates the pro<sup>fi</sup>ling procedure that uses the within-user strength of behavioral patterns (i.e. within-user support). For the rest of the paper, we refer to this pro<sup>fi</sup>ling method as the support-based pro<sup>fi</sup>ling method.

Steps 1–4 select the candidate patterns we use for building the pro<sup>fi</sup>les. The candidate patterns are the union of the top X strongest patterns from each user. For each user, we select the top X patterns with the highest within-user strength, and then combine them together to form the set of patterns we use later for building pro<sup>fi</sup>les. The rationale behind this selection heuristic is that a pattern must be strong for at least one out of the N users in order for it to be of interest. We use M to discover the top patterns within each user. If we consider visiting a site or combination of sites as the format of a pattern, $M _ { 1 }$ can be frequent itemset discovery methods such as Apriori [2]. There can be various ways to select candidate patterns depending on the format of the pattern.

Step 5 computes the within-user strength of all the candidate patterns for every user, and user pro<sup>fi</sup>les are created. For each user, the pro<sup>fi</sup>le is a vector containing $K = | P _ { \mathrm { a l l } } |$ numeric numbers, where $| P _ { \mathrm { a l l } } |$ is the number of candidate patterns. Each number in the pro<sup>fi</sup>le corresponds to the within-user strength of a candidate pattern. For example, if the top patterns for user A are {cnn.com, yahoo.com, amazon. com}, and the top patterns for user B are {msn.com, yahoo.com, myspace. com}, then the patterns we consider when building pro<sup>fi</sup>les for both user A and B are {cnn.com, yahoo.com, amazon.com, msn.com, myspace. com}. For user A, the pro<sup>fi</sup>le could look like (0.8, 0.6, 0.5, 0.01, 0), and the pro<sup>fi</sup>le for user B could be (0.01, 0.7, 0.03, 0.8, 0.6).

In the <sup>fi</sup>eld of information retrieval, the term weighting function known as IDF (Inverse-Document-Frequency) is widely used, usually as part of a TF-IDF function. The intuition was that a term which occurs in many documents is not a good discriminator, and should be given less weight than one which occurs in few documents, and IDF was a heuristic implementation of this intuition [32]. In data mining, a corresponding term is lift. In the context of web user browsing sessions, the lift of a pattern can be de<sup>fi</sup>ned as the frequency of a pattern within a user's sessions divided by the frequency of the pattern across all users. A lift value greater than 1 indicates that a pattern is more likely to happen for this user than expected. Because IDF has been proven to be very successful in information retrieval, in this paper, we will also investigate using lift of patterns to represent user pro<sup>fi</sup>les, to see if it has any advantage over support.

Before presenting the pro<sup>fi</sup>ling procedure based on lift, we <sup>fi</sup>rst need to de<sup>fi</sup>ne the overall strength of a pattern and the relative pattern strength.

De<sup>fi</sup>nition 2. Overall pattern strength.

The overall strength of a behavioral pattern p (for i=1 to K) is $\frac { | D ^ { p _ { j } } | } { | D | }$ <sup>∣</sup>, where |D| is the total number of sessions from all users and D<sup>p</sup>j is the number of sessions from all users that contain behavioral pattern p .

De<sup>fi</sup>nition 3. Relative pattern strength.

For user u (for i=1 to N) and patterns $p _ { j } ~ ( \mathrm { f o r } ~ j = 1 $ to K), the relative strength of a behavioral pattern $p _ { j }$ for user u is $\frac { \left| D _ { u _ { i } } ^ { p _ { j } } \right| / \left| D _ { u _ { i } } \right| } { \left| D ^ { p _ { j } } \right| / \left| D \right| } ,$ where $\left| D _ { u } \right|$ is the number of sessions from $u _ { i } , \left| D _ { u _ { i } } ^ { p _ { j } } \right|$ is the number of sessions from user u that have behavioral pattern $p _ { j } , \left| D _ { u } \right|$ is the total number of sessions from all users and $\left| D ^ { p _ { j } } \right|$ is the number of sessions from all users that contain behavioral pattern p .

For a given user, the relative strength of a behavioral pattern is equivalent to the lift of a pattern<sup>2</sup> (i.e. the support of the pattern within this user divided by the support of the pattern across all users, which is the same as the within-user strength of this pattern divided by the overall strength of this pattern).

Fig. 3 below illustrates the pro<sup>fi</sup>ling procedure using lift.

Similar to Fig. 2, Steps 1–4 select the candidate patterns for building the pro<sup>fi</sup>les. Step 5 calculates the overall strength of the candidate patterns. The overall strength of a given pattern is actually the support of that pattern across all user sessions. Step 6 computes the within-user strength of all candidate patterns for each user. In step 7, user pro<sup>fi</sup>les are created. Again, for each user, the pro<sup>fi</sup>le is a vector containing $K = | P _ { \mathrm { a l l } } |$ numeric numbers. Each number in the pro<sup>fi</sup>le corresponds to the relative pattern strength of a candidate pattern.

## 3.2. Identification stage

The second stage in Fig. 1 is the user identi<sup>fi</sup>cation stage. In this stage, the user pro<sup>fi</sup>les that were previously built are used to help in identifying the owner of future sessions. User identi<sup>fi</sup>cation is based on the difference between two pro<sup>fi</sup>les which is captured in the distance function de<sup>fi</sup>ned in De<sup>fi</sup>nition 4. The distance between two pro<sup>fi</sup>les is de<sup>fi</sup>ned as the Euclidean distance between two vectors.

## De<sup>fi</sup>nition 4. Distance between two pro<sup>fi</sup>les.

For two pro<sup>fi</sup>les $R _ { 1 } = ( a _ { 1 } , a _ { 2 } , . . . , a _ { \mathrm { K } } )$ and $R _ { 2 } = ( b _ { 1 } , b _ { 2 } , . . . , b _ { K } )$ , the distance between $R _ { 1 }$ and $R _ { 2 }$ is $\sqrt { \sum _ { j = 1 } ^ { K } \ ( a _ { j } - b _ { j } ) }$

When new sessions are observed after time T, we assume that these sessions are from the same anonymous user. Given this list of sessions, we can use a similar method to calculate the support and lift values of all the candidate patterns for that anonymous user. The candidate patterns are still the ones generated based on all of the user sessions before time T. The overall pattern strength used to calculate the lift value is also calculated from all the user sessions observed before time T. Since sessions coming from all N users are observed before time T, the overall pattern strength calculated from sessions before time T is more accurate. Also, since the new sessions after time T are from the same user, it is unfeasible to compute the overall pattern strength from the data after time T. Instead, in the identi<sup>fi</sup>cation stage, the within-user strength of all the candidate patterns for the anonymous user is computed from the new sessions after time T. The pro<sup>fi</sup>le for that anonymous user is based on the within-user strength calculated from sessions after time T and the overall pattern strength calculated from sessions before time T. The user pro<sup>fi</sup>les constructed for all the N users in the pro<sup>fi</sup>ling stage are then compared with the pro<sup>fi</sup>le of this anonymous user to decide the identity of the anonymous user.

Fig. 4 illustrates the detailed procedure for user identi<sup>fi</sup>cation, based on relative pattern strength. The procedure based on withinuser pattern strength is similar, so we do not repeat it here (the difference is explained at the end of Fig. 4).

Step 1 calculates the within-user strength of all the candidate patterns for this anonymous user, based on newly observed sessions from this anonymous user. In Step 2, the within-user strength is then divided by the overall pattern strength computed before time T. This forms the user pro<sup>fi</sup>le (after time T) for this anonymous user. In Steps 3 and 4, this anonymous pro<sup>fi</sup>le is compared with all of the user pro<sup>fi</sup>les constructed from sessions before time T. De<sup>fi</sup>nition 4 is used to calculate the distance between two pro<sup>fi</sup>les, and the users are ranked according to the distance between their pro<sup>fi</sup>les and the anonymous pro<sup>fi</sup>le. The ranking can change dynamically as W (the number of newly observed sessions) changes. This approach for identi<sup>fi</sup>cation is similar to the idea of k-nearest neighbor with k being 1. If we were to assign a label to the anonymous user, we would pick the pro<sup>fi</sup>le with the smallest distance and assign the user ID of that pro<sup>fi</sup>le to the anonymous user. Of course, we can also assign several user IDs to the anonymous user, with the associated likelihood values based on the distance.

Over time, we observe more and more user activities, and so the user pro<sup>fi</sup>les may change. In the Appendix, we provide a procedure to update user pro<sup>fi</sup>les, based solely on incremental sessions. This procedure allows us to calculate the updated user pro<sup>fi</sup>les without looking at the sessions before time T, which can be much more ef<sup>fi</sup>cient. Also in the Appendix, we include a procedure to update user rankings as we observe more anonymous sessions, when time T and the user pro<sup>fi</sup>les are <sup>fi</sup>xed.

## 4.1. Data

User-centric data provides bene<sup>fi</sup>ts in understanding user online behavior for the following reason. Site-centric data represents an incomplete picture of user behavior on the web because it does not capture a user's activity on external sites. User-centric data, on the other hand, is data collected at the user level, so it captures entire histories of web sur<sup>fi</sup>ng behavior for each user. The dataset that we use was provided by a commercial data vendor and it captures the web browsing history of a panel of users who volunteered to be tracked in this manner. The data provided to us is the browsing behavior of a sample of 50,000 users over one year.

The raw data has simple summary statistics for each web session, speci<sup>fi</sup>cally the name of the site visited, number of pages seen, the starting time and duration of a session. In order to have adequate data for testing (speci<sup>fi</sup>cally in order to have enough number of sessions for each user) and to have adequate features that can be constructed from the data we adopt a user-centric perspective here, where a session is one continuous period of user activities where a user may visit multiple web sites.

Rather than running our method on the entire dataset, we create multiple datasets by combining data from a speci<sup>fi</sup>c number of users. This enables us to explicitly study the effect of the number of users/ classes and to deal with data sparsity by selecting only those users for whom enough data is available. Speci<sup>fi</sup>cally, we create several subdatasets by combining sessions belonging to 2, 5, 10, 20, 50, 75 and 100 different users.<sup>3</sup> That is, for each such sub-dataset, the dependent variable (user ID) may take 2, 5, 10, 20, 50, 75 or 100 different values, respectively. However, since each such sub-dataset represents only one sample of a chosen set of users, we repeat the random selection process twenty times to create 140 datasets. To each of those datasets, we apply the two pro<sup>fi</sup>ling methods as well as two classi<sup>fi</sup>cation methods for comparison. There are three additional criteria that we use when selecting the users, discussed below.

First, each panelist in the sample represents a single computer that is tracked; hence, we restrict our selection of users to those corresponding to a household size of one in the household demographic <sup>fi</sup>le provided. However, we note that this does not guarantee that only a single “person” uses each computer.

Second, we need to sample users that have a suf<sup>fi</sup>cient level of browsing activity such that we have enough out of sample data on which the models can be tested. The larger the (minimum) number of sessions per user, the larger the training as well as the testing datasets used. However, using a higher value may bias the sample toward users who are particularly active online. In the experiments here, we use 300 sessions as the minimum cutoff (i.e. we choose users who have at least 300 sessions in the data).

Third, when a given number of users are selected, the priors in the data are unequal to start with. For instance, when constructing a dataset of three users, the number of sessions for each user may be 300, 600 and 2100, resulting in class priors of 0.1, 0.2 and 0.7 respectively. A naïve classi<sup>fi</sup>er predicting the most frequent class will start with an accuracy of 70%. To avoid this from introducing any accuracy bias, we select the same number of sessions for all of the users selected in any given sub-dataset. In the previous example, this would mean selecting the <sup>fi</sup>rst 300 sessions for each user. Since the original sessions are ordered by time, the sessions selected in this manner will still be ordered by time. This guarantees exactly equal class priors. For example, a 20 user dataset would have exactly 5% class priors for all the classes. Note that this would mean having to ignore the later sessions of some of the users selected.

After the user screening process, we have 2798 quali<sup>fi</sup>ed users. We then randomly select sessions from these users to form the sub-datasets as discussed earlier. Each sub-dataset is then split into a training set and a validation set. For each user in a sub-dataset, we keep the <sup>fi</sup>rst 2/3 of their sessions in the training dataset (data before time T) and the last 1/3 of the sessions in the validation dataset (data after time T).

## 4.2. Experimental design

For each of the 140 sub-datasets, we implement three methods to predict user IDs (identify users) — the support-based pro<sup>fi</sup>ling method, the lift-based pro<sup>fi</sup>ling method and the classi<sup>fi</sup>cation method. User pro<sup>fi</sup>les are constructed using all of the user sessions in the training set (corresponding to all the sessions before time T in Fig. 1), and are then used to predict user IDs in the validation set (sessions after time T in Fig. 1). In the identi<sup>fi</sup>cation stage, the number of sessions observed (the sliding window size) is changed. We use 10 different sliding window sizes, 1, 10, 20, 30, 40, 50, 60, 70, 80, 90, and 100, to investigate how sliding window size affects the predictive accuracy. Each sliding window contains multiple sessions. The number of sessions contained in a sliding window is the size of the sliding window. For each session, we observe all the web sites visited in that session. For multiple sessions in a sliding window, we are able to compute the support and lift of all the candidate patterns (selected using only the training set). The sessions in a sliding window correspond to the new observed sessions $\{ e _ { 1 } , e _ { 2 } , \ldots , e _ { W } \}$ mentioned in Fig. 4. For each sliding window, we predict the user IDs using the two pro<sup>fi</sup>ling methods and the classi<sup>fi</sup>cation method.

Table 3 shows both the absolute and relative improvement of the best pro<sup>fi</sup>ling method over the classi<sup>fi</sup>cation model.

As shown in Tables 1, 2 and 3, the support-based pro<sup>fi</sup>ling method signi<sup>fi</sup>cantly dominates the classi<sup>fi</sup>cation model when the size of the sliding window gets larger and the number of users increases. The liftbased pro<sup>fi</sup>ling method performs best when the number of users is small. The classi<sup>fi</sup>cation model performs best when the sliding window size is small. In the cells where the classi<sup>fi</sup>cation method performs the best, the difference in performance between the classi-<sup>fi</sup>cation model and the pro<sup>fi</sup>le-based method is small (lower left corner in Table 3). But the advantage that the pro<sup>fi</sup>le-based method has over the classification model gets much larger as the size of the sliding window grows (lower right corner in Table 3). Also, as the number of users increases, the decrease in accuracy for the pro<sup>fi</sup>ling method is not as dramatic when the sliding window size increases (e.g. for sliding window size 100, the accuracy decreases from 95.29% to 87.36% for the support-based pro<sup>fi</sup>ling method, but the accuracy decreases from 88.56% to 38.04% for the classi<sup>fi</sup>cation method). The highest relative improvement, as shown in Table 3, reaches 135.17%. When the sliding window size is small, the pro<sup>fi</sup>ling method doesn't show an advantage because not enough sessions are observed to portray an accurate picture of a user's behavior. For higher numbers of users, say 100, the support-based pro<sup>fi</sup>ling method achieves accuracy as high as 87.36%. This is a dramatic increase from the baseline. For example, when there are 100 users, the chance of guessing the correct user is only 1%. One implication of this result is that when enough sessions can be obtained, the pro<sup>fi</sup>ling method is the best choice. Otherwise, the classi<sup>fi</sup>cation model is better.

As shown in Fig. 6, for all different numbers of users (each corresponding to a line in the Fig. 6), the trend is clear that the improvement in accuracy increases with the size of the sliding window. The 3D surface in Fig. 7 shows that the pro<sup>fi</sup>ling-based methods demonstrate more bene<sup>fi</sup>t as the number of users (the dif<sup>fi</sup>culty of the problem) and the sliding window size (the amount of information available) increase.

We also compared our methods with Support Vector Machines (SVMs), which has been shown to be highly accurate in classi<sup>fi</sup>cation [24]. ## 5. Conclusions

In this paper, we propose an approach to build user pro<sup>fi</sup>les that can be used to identify users. Our experiments show that this approach can be highly effective and ef<sup>fi</sup>cient. This paper is among the <sup>fi</sup>rst to study user behavior patterns in web usage data for the purpose of user identi<sup>fi</sup>cation. As discussed in the introduction, there are many potential applications for this approach. Once the pro<sup>fi</sup>les are proven to be effective at user identi<sup>fi</sup>cation, they can be further utilized for other applications such as targeted advertising, product recommendation and fraud detection.

While it is a simple yet powerful approach, it also has some simplifying assumptions and limitations. (a) As time changes, users behavioral patterns may change. Even though we have considered updating user pro<sup>fi</sup>les as discussed in the Appendix, we have a <sup>fi</sup>xed set of candidate patterns. Essentially, this set of patterns can also evolve over time. Moreover, more recent behavior can play a more important role in determining what a user's future behavior is like. In future work, more weight can be placed on most recent activities to take this into consideration. (b) The approach works well in situations where there are many repeated visitors. On sites where occasional users dominate, and a majority of the users do not login, it might be more bene<sup>fi</sup>cial to assign users to various groups based on their behavior instead of attempting to uniquely identify them. (c) In the identi<sup>fi</sup>cation stage, we assume that the sessions we observe after time T are from the same anonymous user. There needs to be methods (e.g. IP addresses or cookies) to connect consecutive sessions. In cases where this assumption does not hold, identi<sup>fi</sup>cation can only be done on fairly short periods of web activities, which can be quite dif<sup>fi</sup>cult. (d) Because of the dif<sup>fi</sup>culty in obtaining online fraud data where one logs in using someone else's identity, we cannot directly test the effectiveness of the method on fraud detection. But the results in user identi<sup>fi</sup>cation can shed some light on the application of fraud detection, and the method can be slightly modi<sup>fi</sup>ed in the identi<sup>fi</sup>cation stage to detect fraud. (e) In our experiments, the maximum number of users in each sub-dataset is 100. Since we were not able to extend the experiments to much larger number of users, we cannot conclude that our method can be applied to large scale problems. Therefore, we should either restrict our method to small and medium sized applications or convert the problem itself to manageable scale (see more discussions about this in the Introduction and the future work below).

In the future, this work can be extended in several directions. (a) More experiments can be conducted to further investigate the conditions under which the pro<sup>fi</sup>le-based method or a certain classi<sup>fi</sup>cation model works the best. This is always a dif<sup>fi</sup>cult problem, but some insights can be of value. (b) When data is available, the approach can be applied to more applications, such as fraud detection and product recommendation. (c) In large scale problems with huge number of users, when direct user identi<sup>fi</sup>cation based on behavioral patterns alone becomes infeasible (e.g. due to lack of suf<sup>fi</sup>cient information to distinguish users), behavioral features can be combined with other tools to help identify users. For example, for a large online retailer, several user accounts may share the same IP address (e.g. members of the same family). The retailer might be able to identify the members sharing the same IP address (assuming that there is some known login information from this IP address which can be used to build user pro<sup>fi</sup>les). Being able to further identify users within the shared IP address can help achieve high performance for personalization. Another solution for the large scale problem is to focus on segment level instead of individual level. The problem can be converted into a segment identi<sup>fi</sup>cation or segment assignment problem. One such approach is to <sup>fi</sup>rst cluster users into different segments based on pro<sup>fi</sup>le similarities. Future unknown users can be assigned to the segment that has the highest pro<sup>fi</sup>le similarity. While the segment-based solution for large scale problems is not proven in this paper, it remains a viable research question in our future work.

## A.1. Updating user profiles

Over time, we observe more and more user activity, and the individual user pro<sup>fi</sup>les may change. The procedure in Fig. 1A updates user pro<sup>fi</sup>les based solely on incremental sessions. This procedure allows us to calculate the updated user pro<sup>fi</sup>les without looking at the sessions before time T. Here, we only provide the update procedure for lift-based pro<sup>fi</sup>ling, since the update procedure for support-based pro<sup>fi</sup>ling is similar.

Once the user pro<sup>fi</sup>les before time T are calculated, we simply need to incorporate the new sessions between time T and $T _ { 1 }$ into the old user pro<sup>fi</sup>les in order to generate the updated user pro<sup>fi</sup>les at time $T _ { 1 \cdot }$ We do not need to follow the pro<sup>fi</sup>ling algorithm in Fig. 3 and we do not need to use any session before time T. This can be much more ef<sup>fi</sup>cient.

The set of candidate patterns $P _ { \mathrm { a l l } }$ does not require frequent updates. It can be updated when there are signi<sup>fi</sup>cant amount of additional sessions that need to be considered for generating candidate patterns.
