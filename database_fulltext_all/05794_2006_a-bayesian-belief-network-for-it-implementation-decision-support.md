# A Bayesian Belief Network for IT implementation decision support<sup>☆</sup>

Eitel J.M. Lauría <sup>a,⁎</sup>, Peter J. Duchessi <sup>b</sup>

<sup>a</sup> School of Computer Science and Mathematics, Marist College, 3399 North Road, Poughkeepsie, NY 12601, USA <sup>b</sup> School of Business, University at Albany, State University of New York, 1400 Washington Avenue, Albany, NY 12222, USA

Received 20 April 2005; received in revised form 5 October 2005; accepted 22 January 2006 Available online 9 March 2006

## Abstract

Bayesian Belief Networks (BBNs) are graphical models that provide a compact and simple representation of probabilistic data. BBNs depict the relationships among several variables and include conditional probability distributions that make probabilistic statements about those variables. This paper demonstrates how to create a BBN from real-world data on Information Technology implementations. The paper also displays the resulting BBN and describes how it can be incorporated into a DSS to support “whatif” analyses about Information Technology implementations. The paper combines techniques originating from artificial intelligence, statistics, and computer-based decision making. © 2006 Elsevier B V All rights reserved

Keywords: Information Technology (IT) implementation; Bayesian Belief Networks (BBNs); Decision Support Systems (DSSs)

## 1. Introduction

Information Technology (IT) implementation is the most researched IT topic, especially over the last two decades. This phenomenon is primarily due to the role IT plays as an enabler of improved business performance and to the surprisingly low success rate of IT implementations [24]. The reasons for poor and sometimes catastrophic IT implementation outcomes include organizational factors (e.g., insufficient education and training), IT implementation planning factors (e.g., misalignment of IT applications with company objectives and strategies), and technical factors (e.g., inadequate disaster recovery capabilities). As a result, past and present implementation research focuses on isolating and relating the factors that explain IT implementation success, or conversely failure. Benjamin and Levinson [4] report that companies are not realizing IT benefits because investment is heavily biased towards technology rather than towards managing changes in business processes, organizational structure, and culture. According to Griffith and Northcraft [10], fewer than 10% of IT implementation failures stem from technical problems. Instead, most IT failures result from human or organizational difficulties, including users' misunderstanding of technology and poor technology management.

Generally, researchers use structural equation modeling (SEM) techniques (e.g., LISREL and partial least squares), which are statistical techniques that identify and relate multiple implementation factors, to develop models of successful IT implementation. This paper takes a different tack and introduces Bayesian Belief Networks (BBNs) as an alternative approach to building IT implementation models. BBNs are probabilistic inference engines that can be used to reason under uncertainty. Because many IT implementations are extremely difficult, expensive, and precarious undertakings, designers of Decision Support Systems (DSSs) for IT implementations will have to think “out of the box” and appeal to multiple methods from various disciplines (e.g., inference and reasoning under uncertainty techniques from computer science) to build truly innovative systems that provide practical advise to decision makers. This perspective is the motivating force behind the current work.

To extend the current state of the art on IT implementation models, in general, and on IT implementation DSSs, in particular, this paper has two primary objectives: (1) describe how to build a BBN for IT implementation, and (2) describe how a BBN supports a model-driven IT implementation DSS, specifically a client-server implementation DSS. In satisfying these objectives, the paper makes three important contributions to the literature: (1) it provides a methodology for building a BBN for IT implementation; (2) it portrays IT implementation as one BBN; and (3) it provides proof of concept of how BBNs can be incorporated into DSSs for IT implementation. In fact, there is little, or nothing, about these important topics in the extant literature.

The following section provides a short overview of DSSs and IT implementation DSSs. Next the paper introduces BBNs, describing both inference and learning from data. Then the paper describes a methodology for building BBNs from IT implementation survey data, sharing some of the trials and tribulations of constructing a BBN from real data, and presents one BBN for IT implementation.<sup>1</sup> The paper also demonstrates how decisions makers would use a BBN-driven DSS to understand the implications of IT implementation decisions. Finally, the paper provides a summary, which includes future research opportunities.

## 2. Decision Support Systems for IT implementation

As noted by Shim et al [33], DSSs have evolved over the past three decades, taking on both a narrower or broader definition. Two major types of DSSs can be considered, namely data-driven and model-driven DSSs. Data-driven DSSs include online analytical processing (OLAP) applications and data mining applications. OLAP applications allow users to think of a database as having multiple dimensions and to query those dimensions in various combinations. Users can use the queries to analyze relationships among the various dimensions and their associated data elements, aggregate data over time periods, and present data in multiple formats (e.g., graphical formats). Data mining applications identify specific, unknown patterns in databases and data warehouses that typical queries cannot reveal. These applications can include one or more algorithms, including neural network algorithms, tree induction algorithms, and/or clustering algorithms. Users apply the algorithms to identify hidden patterns in the data.

Model-driven DSSs are computer-based applications that allow users to apply quantitative and/or qualitative models to data to solve complex semi-structured and unstructured problems. Generally, model-driven DSSs contain three components: a data management module, which is a database or data warehouse; a model management module, which contains one or more models that are pertinent to the problem under investigation; and a dialog module, which portrays various options (e.g., model selection), allows users to enter and change inputs, and provides access to the data and model management modules. Via the dialog module, users interact with a DSS and can perform sensitivity, or “what-if,” analyses to gain more insight into the problem and its potential solutions. Traditional model-driven DSSs, which incorporate operations research models, have evolved over time. Some DSSs include knowledge models that provide inferencing capabilities. The knowledge models support the other components or act as independent components and can use rules, BBNs, or other formalisms.

Obviously, any model-based DSS for IT implementation would contain model management, data management, and dialog modules. The model management module could contain one (or more) qualitative, quantitative, or knowledge model(s). The nature of the problem, objectives of the model builders, available data, and/or availability of implementation expertise would determine the number and types of models in the DSS. Using the models, users should be able to access their companies' overall preparedness for an IT implementation based on a number of pertinent attributes. Additionally, these models should support “what-if” analyses. For example, users should be able to evaluate the impact of changing one or more implementation steps or activities (e.g., development of formal policies and procedures) on the attainment of specific benefits. The data management module would contain data about a company's implementation to be analyzed by the model(s). If an empirical model appears in the model management module, it is highly likely that the data management module would also have to support the database on which the empirical model is based. Model builders would have to update the empirical models to account for changes in technology, vendor practices, and implementation practices over time. Finally, an IT implementation DSS would require a user interface that would facilitate the application of the model(s) to the data and provide practical recommendations for users to consider.

Researchers and practitioners have developed and are using data- and model-driven DSSs in a variety of domains, including vehicle routing [5,16], store assortment analysis [3], and sales forecasting [13,23]. Moreover, there is plenty of ongoing research on Bayesian networks in a wide range of decision-making related fields. Anderson and Vastag [1] use BBNs for causal modeling in operations research. Van Koten and Gray [34] follow a Bayesian network approach to predict object-oriented software maintainability. Kristensen and Rasmussen [19] have built a BBN for decision support in agriculture. Cornalba and Guidici [7] employ BBNs to assess operational risk management in banks. Anderson et al. [2] apply BBNs to develop management models in the context of transportation service satisfaction. However, there is little research about applying BBNs to IT implementation decision support. (We could find no research about IT implementation DSSs that incorporate BBNs in the extant literature).

## 3. Bayesian Belief Networks

A BBN is a graphical model that combines elements of graph theory and probability theory. A BBN describes a set of causal relationships among a set of variables of interest, a set of conditional independence assumptions, and their related joint probabilities. A directed acyclic graph (DAG) portrays the causal relationships among the variables, or nodes, depicting both dependent (i.e., related) nodes and independent (i.e., unrelated) nodes. Each node represents a variable that has an associated conditional probability distribution. As noted by Russell and Norvig [31], the conditional independence assumptions make BBNs more compact than models based on full joint probability distributions. Consequently, BBNs can contain a large number of variables without causing exponential growth of the conditional probability factors, which result from direct application of the product rule. This visual arrangement provides a convenient knowledge representation. However, the real power of BBNs manifests itself as the network applies the rules of Bayesian inference to propagate the impact of evidence on the probabilities of selected outcomes. A BBN can answer queries, or “what-if” questions, about the variables that appear in the network. Such queries may include diagnostic reasoning (i.e., reasoning “upwards” from effects to cause), predictive reasoning (i.e., reasoning “downwards” from cause to effect), or inter-causal reasoning (e.g., given two mutually exclusive causes, evidence on one of them “explains away” the other one). When used in this way, BBNs can be thought of as powerful probabilistic inference engines.

## 3.1. Structure and parameters of Bayesian networks

A DAG depicts a set of variables, $X _ { 1 } , X _ { 2 } , \ldots , X _ { n } ,$ and their relationships, as portrayed in Fig. 1. Each node of the DAG represents a variable and the directed arcs represent the parental relationships among the variables. At each node, there is a conditional probability distribution for the variable given its parents' values. The joint probability distribution of a DAG's variables is:

$$
\begin{array}{l} p (X _ {1} = x _ {1}, X _ {2} = x _ {2}, \ldots , X _ {n} = x _ {n}) \\ \qquad = p (x _ {1}, x _ {2}, \ldots x _ {n}) = \prod_ {i = 1} ^ {n} p (x _ {1} | x _ {p a (i)}). \end{array}\tag{1}
$$

In this notation, $p ( x _ { 1 } , \ x _ { 2 } , . . . , x _ { n } )$ represents the probability of a specific combination of values $x _ { 1 } , x _ { 2 } ,$ $\cdots ^ { x _ { n } }$ from the set of variables $X _ { 1 } , X _ { 2 } , . . . , X _ { n } ,$ and $x _ { \mathrm { p a } ( i ) }$ represents, as a vector, the list of direct parents of $X _ { i } ,$ as depicted by the DAG. BBNs are locally structured, meaning that each node interacts with a bounded set of neighbors (in this case the set of parent nodes). Currently, a super majority of the research on the application of BBNs incorporates discrete distributions for the variables. We use discrete distributions here as well. Given, for example, a BBN with n nodes, where each node has an average number of parents equal to k and supposing that each node is binary, the number of values required to specify the full probability model would be $n { \cdot } 2 ^ { k }$ . This is a much smaller number than $2 ^ { n }$ which would be the number of values required in a fully connected network.

3.2. Learning a Bayesian Belief Network's parameters and structure from data

Given a data set of N cases ${ \cal D } { = } \{ { \bf x } ^ { ( 1 ) } , { \bf x } ^ { ( 2 ) } , { \bf \phi } . . . , { \bf x } ^ { ( n ) } \}$ , where each $\mathbf { x } ^ { ( k ) }$ is a row vector representing a conjunction of observed states $x _ { 1 } ^ { ( k ) } , x _ { 2 } ^ { ( k ) } , . . . , x _ { n } ^ { ( k ) }$ of $X _ { 1 } , X _ { 2 } , . . . , X _ { n } ,$ modelers have to determine the underlying structure and parameters of the BBN, which includes the specification of the conditional independence assumptions among the networks variables, as portrayed by a DAG, and the set of associated parameters θ, the conditional probability distributions that quantify the dependencies among the network's variables.

When modelers know the structure of a BBN and the data set has no missing values, they need to estimate just the BBN's parameters. In this situation, maximum a posteriori (MAP) estimation computes the BBN's parameters. The MAP process requires a parameter prior probability distribution and calculates a set of relative frequencies. To obtain the relative frequencies, the MAP process counts the occurrence of each value of a given variable, given each configuration of parent values. Generally, modelers use a conjugate Dirichlet parameter prior probability distribution, when the likelihood distribution is multinomial, as in the case of discrete BBNs. The Dirichlet distribution modifies the relative frequencies to derive the final parameter estimates. Appendix 1 provides a more complete account of the mechanics associated with parameter estimation.

When the structure of a BBN is not known, in addition to estimating model parameters, modelers must also identify the BBN's correct structure. This amounts to finding the simplest, least expressive network structure, or group of network structures, that bests describe the BBN's joint probability distribution over the data set. Generally, modelers search for the best BBN using a practical search-and-score procedure. Search-and-score algorithms are optimization methods that heuristically search the space of network structures for the BBN that best matches the training data.

Search-and-score algorithms have two components: a search procedure to scan the space of feasible networks and a scoring function to evaluate the fit and complexity of the networks. Greedy search algorithms, such as Cooper and Herskovits' K2 [6], and Markov Chain Monte Carlo (MCMC) methods, such as Simulated Annealing [17], heuristically search the space of BBN structures, using scoring functions to choose among the candidate networks. Modelers can resort to different scoring functions. The Bayesian Information Criteria (BIC) [32,11], a commonly applied score, uses the log maximum likelihood of the data as a measure of the network fitness, penalized by the complexity of the network. BIC describes complexity in terms of the dimensionality of vector parameter θ. Lam and Bachus [20] have used scores based on the Minimum Description Length (MDL) Principle [28]. Rodriguez [30] and Lauría [21] have applied an Information-geometric (Info-geo) score based on the updated version of MDL [29] that takes into account the geometry of the underlying statistical model. The info-geo score takes the form:

$$
- \log p (D | \hat {\boldsymbol {\theta}}) + \frac {| \boldsymbol {\theta} |}{2} \log \frac {N}{2 \pi} + \log \int \sqrt {\det \mathbf {I} (\boldsymbol {\theta})} d \boldsymbol {\theta}\tag{3}
$$

where the first term is minus the logarithm of the likelihood calculated at the maximum likelihood estimator θ<sup>ˆ</sup>, the second term measures the complexity given by the number of parameters in the BBN and the last term measures the complexity given by the geometrical properties of the BBN. For a detailed description, see Lauría [21].

## 3.3. Inference in Bayesian Belief Networks

Fully parameterized BBNs may be used for several different inferential tasks, including classification (mapping a data item into one of several pre-defined categories), prediction (predicting the value of a dependent variable given new evidence), and diagnosis (given the evidence of an effect, inferring the most likely cause). Because a BBN defines a joint probability distribution, any probability can be computed from the network by specifying the joint probability distribution and applying basic rules of probability, such as the product rule and marginalization.

A BBN does not have to contain many variables for the joint probability distribution to become intractably large. In an attempt to enhance the performance of the inference process, researchers have developed several algorithms, both exact and approximate. The bucket elimination method [8] uses the factorized expression of the joint probability distribution to reduce the number of calculations in the marginalization procedure. Pearl's message passing algorithm [26] provides an improved approach for singly connected DAGs (graphs where no pair of nodes has more than one path). The algorithm propagates new evidence over the network by sending messages to neighbour nodes, connected by arcs, to obtain information about the joint probability distribution that is defined by the network and the existing evidence. The algorithm has been extended to multiple connected DAGs where messages are passed in a junction tree that maps the original BBN [22,14]. Also, several approximate algorithms have been devised, based on Markov Chain Monte Carlo sampling [25,12] or a combination of these methods [15]. For more details see Korb and Nicholson [18].

## 4. Building a Bayesian Belief Network for an IT implementation Decision Support System

A BBN for an IT implementation DSS needs to incorporate and interrelate a large number of human, organizational, cultural, technical, and IT benefit factors. The BBN for the IT implementation DSS is based on the experiences of companies implementing client server systems and on a statistical analysis of the associated data, which identifies the key implementation and benefit factors for client-server implementation. The BBN provides the overall dependency structure among the factors and the associated conditional probability distributions. By querying the BBN, users can investigate the relationship between the factors and gain more insight into how to conduct a successful implementation, given a company's existing situation and given certain actions (e.g., formation of a steering committee) taken to prepare for and execute a clientserver implementation.

## 4.1. Client-server data set

The data for deriving the BBN is based on a nationwide survey of companies implementing client-server systems. Based on an analysis of 350 questionnaires, the study identifies the primary factors that affect successful client-server implementations, associated benefits, and potential pitfalls. The principal investigators use a review of the existing literature, the knowledge of client-server implementation experts, and their own implementation experience to identify critical clientserver implementation scale items that collectively comprise the questionnaire.

Over a dozen experienced systems developers, consultants, and senior managers participated in the development of the questionnaire, reviewing drafts of the questionnaire; adding, deleting, and modifying items; and rephrasing questions. About another dozen mangers completed the questionnaire, providing additional input about content and length of time to complete the questionnaire. The process of developing the questionnaire and the thorough pretest established content validity. Bartlett's test for sphericity was highly significant and measures of sampling adequacy were between 0.83 and 0.88, indicating that there are significant correlations among the items and that factor analysis would produce suitable results. Subsequent factor analyses, using the maximum likelihood extraction method with an oblimin rotation (δ = 0), identified a set of 13 implementation factors and four benefit factors. The implementation factors and benefit factors explained 59% and 62% of the total variation, respectively. All factors had exceptionally high loadings for all items, providing evidence of satisfactory construct validity. Cronbach alphas ranged between 0.65 and 0.83, suggesting satisfactory reliability. (For a more detailed account of the literature and theory behind the selection of implementation items, pretest process and all statistical analyses behind the development of the implementation and benefit factors, see Duchessi and Chengalur-Smith [9].)

The implementation factors are Information System (IS) Maintenance, Project Management, Vendor Support, Organizational Arrangements, Business Planning, IS/User Interaction , IS Management's role, Functional Management's Role, Application Complexity, Application Suitability, Reengineering Intention, Application Analysis, and Standards and Integration. IS Maintenance represents the degree to which the IS group maintains client-server application. Generally, the IS group is responsible for maintaining computing infrastructure and utility services across business functions in client-server environments. Project Management portrays the quality of the rollout and ability to meet target dates. On-schedule projects and well-planned rollouts are important aspects of client-server and other IT implementations. Vendor Support depicts the extent of vendor support. Companies require extensive vendor support, especially when they are implementing new, unfamiliar technologies. Organizational Arrangements represents the earnestness of the steering committee and quality of project team. Steering committees require someone with full authority and have to provide the requisite resources. Project teams should have technical people on board and be aggressive about in their migration planning. Business Planning represents the nature of business planning and IT strategy formulation. Companies that have a well-integrated business and IT strategy formulation process are prepared to integrate client-server and other technologies into their businesses. IS/User Interaction evinces the working relationship between the IS Group and users. IS groups that help line managers understand how to use Information Technology and that partner with user communities can increase the chance that client-server applications will be used as intended. IS Management's Role represents IS management's ability to integrate computing infrastructure planning with business area requirements. Good planning helps companies successfully satisfy business requirements through new client-server and other IT applications. Functional Management's Role measures functional management's contribution to IT strategy and requirements analysis. To ensure that the correct applications are in house, functional managers need to contribute to IT strategy formulation and determine client-server requirements. Application Complexity represents the overall complexity (e.g., implementation involves all business functions) of a clientserver implementation project. Generally, less complex applications have a higher success rate. Application Suitability represents the ability of a client-server application to enhance users' performance. Suitable applications will improve users' performance, stimulate use, and are more apt to succeed. Reengineering Intention depicts a company's intention to redesign business processes as part of the implementation effort. Application Analysis represents the approach for soliciting users' requirements and testing system evaluation. Companies that use prototyping to determine detailed specifications, integrate users into system testing, and use a pilot to evaluate client-server architecture are likely to avoid important implementation problems (e.g., inadequate network capacity). Standards and Integration measures quality of vendor evaluation and systems integration. A thorough scoring of all vendors is important to ensure that the company selects vendors that can meet all their needs. The benefit factors are Operational, Competitive, System, and Financial Benefits. Operational Benefits represent low level but important benefits, including reduced decision-making time, improved integration of business information, and better control of the business; Competitive Benefits portray competitive improvements (e.g., improved competitive position); and Financial Benefits (e.g., improved financial posture). In summary, of the 13 implementation factors, only one, Application Analysis, is technical in nature, the other factors address the human and organizational issues associated with client-server implementations. Thus, our effort makes success mostly a function of human and organization issues rather than a clientserver system per se.

These implementation and benefit factors provide the input for building a BBN for the IT implementation DSS. The BBN takes as nodes the implementation and benefit factors. The data set of 350 companies provides the data to discover the BBN's overall structure and parameters, or associated conditional probability distributions. The selected search procedure (described below) examines several candidate BBNs before making a final selection based on the scores obtained from designated functions.

## 4.2. Methodology

The formal procedure for building the BBN consists of several steps, and Fig. 2 provides a high-level view of those steps.

Step 1, Reduce Dimensionality, advocates using a dimensionality reduction technique (e.g., cluster analysis, factor analysis, and multidimensional scaling) to reduce the number of factors, or parameters, requiring estimation, especially when the number of observations does not permit the formulation of larger networks. For example, via factor analysis, model builders can develop a parsimonious set of factors for inclusion in a BBN. We use factor analysis to obtain the thirteen implementation factors and a composite benefit factor, Benefits, that averages the four initial benefit factors.

Step 2, Rescale and Discretize Data, suggests that model builders replace missing values with averages to avoid dropping observations. In the present case, this action has negligible impact due to the very low incidence, 3%, of missing values. By eliminating missing values, model builders can use maximum a posteriori (MAP) estimation with Dirichlet priors to calculate parameters rather than a much slower alternative, typically the expectation-maximization algorithm. Additionally, Step 2 advocates discretizing the data to simplify measurement of each factor and to permit the application of model selection algorithms that operate on discrete BBNs. In the present case, respondents use a five-point rating scale to evaluate each company on the initial set of factors; however, we convert this evaluation into a binary scale, with “low” and “high” values. The binary rescaling allows us to further reduce the number of parameters requiring estimation. We perform this activity to balance the number of parameters with the existing sample size. On average, if each node has four parents, a binary network of 14 nodes requires estimation of just 224 (14.2<sup>4</sup>) parameters. If each node has five possible values, then

14 factors require estimation of 8,750 (14.5<sup>4</sup>) parameters, which is well beyond the 350 available observations.

Model builders should realize that data reduction techniques and the use of lower level scales (e.g., our binary scale of “high” and “low”) will reduce the granularity of the requisite measures. Importantly, highly granular measures will limit the accuracy of inputs, namely item and/or factor (e.g., Application Suitability) evaluations, and outputs, namely item and/ or factor (e.g., Benefits) values and associated probabilities. Yet, the granularity of any analysis is a function of the number of available cases: the greater the number of cases the greater the granularity of the analysis permitted. Consequently, model builders should strive for large data sets, which would allow them to go beyond a nominal level of measurement, as used here, and incorporate higher measurement levels, including ordinal, interval, and ratio scales, which permit greater accuracy in measuring inputs and outputs.

In Step 3, Define Semantic Constraints, model builders may consider using several precedence constraints to ensure face validity. For example, the constraints make sure that all implementation factors explain benefits. Precedence constraints are by nature domain specific. We use two algorithms to heuristically search the network space, namely simulated annealing and K2 (see Step 4 below). In the case of Simulated Annealing, the search algorithm enforces the precedence constraints, limiting some, not all, of the variables to pre-established, well-defined, time-precedence relationships. We base the existing constraints on the knowledge of client-server implementation experts, the authors experience in implementing client-server systems, and past IT implementation research.<sup>2</sup> We use a restriction matrix to portray the precedence constraints. Each cell in the matrix represents a potential relationship, or DAGdirected edge, given by an ordered row-column pair. A cell containing a 1 defines a constraint, allowing a search algorithm to eliminate from consideration all networks with that relationship.

The K2 algorithm requires ordered variables. For consistency purposes, we order the variables according to the restriction matrix used in simulated annealing. We compute the column totals of the restriction matrix and use the totals to rank the nodes: nodes with a smaller number of restrictions rank higher in the ordering. For those nodes with equal number of restrictions, we apply face validity considerations and our own expertise.

In Step 4, Search for Candidate Models, model builders employ several heuristic search algorithms (e.g., Simulated Annealing, greedy search algorithms, and genetic algorithms) to discover the BBN's structure and associated parameter estimates. We use a modified Simulated Annealing algorithm, which permits semantic constraints, and Cooper and Herskovits' K2 algorithm [6] to heuristically search the space of network structures, applying two different scoring metrics, namely Bayesian Information Criteria (BIC) [32] and the Info-geo score [30,21]. We also apply three different Dirichlet equivalent sample sizes, namely 1, 5, and 10. We use the combination of search algorithms, scoring metrics, and Dirichlet equivalent sample sizes to test the robustness of the search process to reach similar optima, or the same optimum.

Simulated Annealing is a Markov Chain Monte Carlo search method. At each step in the search procedure, to jump from the existing state of the Markov chain of networks to another state, the algorithm perturbs the existing network by performing three possible operations, namely arc addition, arc removal, or arc reversal. The modified Simulated Annealing algorithm restricts these operations by enforcing both structural constraints to ensure acyclicity and by considering only the parent arrangements, as determined by the semantic constraints implemented through the restriction matrix. The outcome of the three operations is a list of neighbor networks. From the list, the algorithm randomly picks one network, scores it with one scoring metric, and compares it with the existing network. If the chosen neighbor network has a score higher than the existing network, the algorithm accepts the neighbor network as the new existing network and uses it to create the next list of potential neighbor networks to further explore. If the chosen network has a score lower than the existing network, the algorithm rejects it with a given probability, reapplies the operations to the existing network, and generates another list for consideration. In theory the algorithm should converge to a global optimum; however, there is no guarantee due to imposed time constraints.

The K2 algorithm [6] chooses an order over the variables of the BBN and uses a greedy local search procedure that, for each variable $X _ { i }$ in the ordering, incrementally adds a parent from the remaining variables, $( X _ { 1 } , X _ { 2 } , . . . , X _ { i - 1 } )$ . It selects the parent that most increases the score. This procedure is repeated independently for each variable $X _ { i }$ until no node increases the score, or the number of parents of $X _ { i }$ exceeds a given threshold. (Note that the local search algorithm implemented by K2 can lead to just local maxima). Simulated Annealing performs a global optimization and is not restricted by the ordering of the nodes, but it is typically slower than greedy search algorithms, such as K2, and can take time to converge to a global optimum.

In Step 5, Benchmark Candidate Models, model builders compare the candidate BBNs that are discovered above. These candidate BBNs result from applying several combinations of two search algorithms (Simulated Annealing and K2), two scoring metrics (BIC and Info-geo) and three Dirichlet equivalent sample sizes. Benchmarking involves comparing the predictive accuracy, or error rate, of candidate BBNs and choosing the BBN with the highest classification accuracy. To compute predictive accuracy, we use the standard tenfold cross-validation [35]. Tenfold cross-validation divides the data set into ten partitions, or folds. For each fold, the procedure holds out one-tenth of the data set for validation and uses the remaining nine-tenths to derive the BBN's parameters. Using the specified BBN, the procedure predicts the value of each variable for each case in the one-tenth holdout, given the values of the variables in its Markov blanket.<sup>3</sup> This routine is repeated over the ten folds, to get an overall predictive accuracy for each node in the network. Finally, the procedure averages the values of overall predictive accuracy for each of the BBN's variables to obtain one overall predictive performance, namely the mean overall predictive accuracy of the BBN.

As mentioned earlier, a DAG conveys the structure of a BBN. Fig. 3 shows the DAG associated with the BBN, or model, having the highest mean overall predictive accuracy. The model shows the pertinent factors (e.g., Business Planning) and their interrelationships. For example, the DAG indicates that Reengineering Intention (Node 10), Applications Suitability (Node 12), and Project Management (Node 13) directly affect Benefits; the remaining factors indirectly affect Benefits through those factors. The mean overall predictive accuracy of the model is 82%, suggesting that it is one valid model for a clientserver implementation DSS. We chose this model because it has the highest predictive performance among the set of candidate networks, which are all very similar in terms of their structure, demonstrating the robustness of the search procedure and the final model.<sup>4</sup>

The associated conditional probability distributions, or conditional distribution probability tables, provide the parameter estimates and complete the BBN. Fig. 4 displays the discrete conditional probability distribution tables of the existing model, which uses “low” and “high,” as previously mentioned, to score each of the factors. For example, in Fig. 4, the conditional probability distribution for Benefits (Node 14) shows the probability of receiving “low” and “high” benefits, for various combinations of “low” and “high” values of Reengineering Intention (Node 10), Applications Suitability (Node 12), and Project Management (Node 13). With a BBN's structure and the conditional probability distribution tables, model builders have a fully specified BBN that can be used as an inference engine to explain dependencies among variables, answer queries, and perform prediction given new evidence, as demonstrated in the next section.

In Step 6, Apply the Selected Model, model builders embed the chosen BBN into a DSS for answering IT implementation queries. Because of the nature of BBNs, the queries can be about any factor, or combination of factors, in a network. BBNs can estimate the values of any subset of factors in a network, including dependent and independent factors, given the values of the remaining network factors. Additionally, they provide probabilities for the estimated values, which are easy to comprehend and especially informative to decision makers. These characteristics partially separate BBNs from traditional SEM techniques, which can estimate the values of only the dependent variables in a network, given the values of the independent variables, and which lack the ability to make probability statements.<sup>5</sup>

## 5.2. Decision support for client-server implementation

To demonstrate a BBN's potential as a probabilistic model in a client-server implementation DSS, we examine two cases. The first case demonstrates how to evaluate a company's overall preparedness for attaining client-server benefits, given some evidence (i.e., values for certain variables, or attributes) about the company. The second case demonstrates how to assess the probabilities of attaining both intermediate results and benefits, as the evidence changes. The latter case provides one instance of a “what-if” analysis.

Consider a company with several less than favourable attributes. The company has poorly defined goals and strategies, misaligned business and IT strategies, and the CIO makes negligible contributions to strategy. Thus, Business Planning is “low” with probability 1. IS management fails to integrate business requirements into the IT strategy, does not plan the computing infrastructure, and fails to align the company's application portfolio with existing goals and strategies. This evidence suggests that IS Management Role is “low” with probability 1. The company rarely forms IT steering committees and, if it has a steering committee, the steering committee rarely meets and infrequently provides adequate resources. Additionally, project teams have few technical people and provide little migration direction for IT projects. Collectively, this evidence suggests that Organizational Arrangements is low with probability 1. Moreover, the IS group hardly works with users, users don't consider the IS group as a partner, and the company rarely selects vendors based on meaningful criteria. These attributes indicate that the meaningful IS/User Interaction is “low” with probability 1. Vendor products do not easily integrate, users have little input into the design of a client-server application, and pilots and test systems are rarely used for implementation. In line with the evidence, Application Analysis is “low” with probability 1. Finally, the company is on the verge of implementing a clientserver application that spans several business functions and incorporates existing legacy systems and is considering going “cold turkey” with the client-server application, suggesting that Application Complexity is “high” with probability 1. Given this situation, what can the company expect in terms of being able to reengineer associated business processes; develop a suitable application that improves users' performance; have an on-time, well-planned roll-out; and gain business benefits, including increased organizational performance, improved system accessibility, and improved financial posture? Specifically, for these variables, what are the values and the associated probabilities?

A DSS equipped with the existing BBN would apply the rules of Bayesian inference to propagate the impact of the above evidence (i.e., “high” or “low” designations with probability 1) to estimate the values and associated probabilities of the remaining attributes, namely Application Suitability, Reengineering Intention, Project Management, and Benefits. Execution of the existing BBN suggests that the company has only a 19% change of reengineering (Reengineering Intention = high), slightly less than 50% chance of achieving a suitable application (Application Suitability = high), no chance of being on time and having a well-planned roll-out (Project Management = low), and a 36% chance of attaining benefits (Benefits = high).

To demonstrate “what-if” analyses, prior to pursuing an intended client-server implementation, suppose the company decides to better organize its approach to client-server implementations. Recognizing that it would take a long time to change existing business planning and IS strategy formulation conventions because of cultural issues, it decides to modify specific IT implementation practices, which are relatively easy to change. Thus, the company makes improvements in the way it organizes for the implementation, including the development of steering committee and project team which meet on a regular basis, suggesting that Organizational Arrangements is “high” with probability 1. The company also involves users in all phases of the client-server project, rigorously test vendors' products, and employs iterative prototyping to determine specification. This revised approach indicates that Application Analysis is “high” with probability 1. Finally, the company emphasizes the need to use plug-compatible components, and mandates that the client-server application be aligned with the IT strategy. This situation would suggest that Standards and Integration is “high” with probability 1. By changing some aspects of its implementation approach, what can the company expect? Can the company expect an improved posture to reengineering, a more suitable application, and business benefits? Once more, a DSS equipped with the existing BBN would apply the rules of Bayesian inference to propagate the impact of the changes to estimate the values and associated probabilities of the remaining attributes. Concerning the intermediate dimensions, execution of the existing BBN indicates that the company would have a 61% change of successfully reengineering the affected processes (Reengineering Intention = high); slightly less than 53% chance of achieving a suitable application (Application Suitability = high); 47% chance of being on time and having a well-planned roll-out (Project Management = high); and just over a 50% chance of attaining anticipated client-server benefits (Benefits = high). To continue with the “what-if” analyses, users can introduce other changes, or combinations of attribute values, including more effective business planning, IS management, and IS user interaction, to determine the overall affect on all intermediate attributes, or factors, and on the final benefits.

The existing BBN can also provide probabilistic explanations for its outcomes. Basic probability rules and Bayes Theorem provide a vehicle for understanding the logic behind all outcomes and their associated probabilities, preventing a BBN from becoming a “black box” to users. By sequencing the Bayesian probability rules applied in determining outcomes, the existing DSS would provide a logic trace similar to the rule traces used by rule-based expert systems in explaining their logic, thereby providing a proven knowledge explanation facility.

## 6. Summary and future research opportunities

BBNs are powerful knowledge representation formalisms that are known for providing a compact and simple representation of probabilistic data. This paper demonstrates how to create a BBN from realworld data, specifically the client-server survey data set. The existing BBN depicts the relationships among several different client-server implementation and benefit factors. Additionally, the paper describes how the BBN can be incorporated into a DSS to support “what-if” analyses of client-server implementations.

Our methodology for estimating the BBN for client-server implementation uses heuristic model searching techniques and algorithms to estimate the structure and parameters of the BBN. The approach discretizes the original rating scale to just two values and it calculates the model's parameters by applying MAP estimation with varying Dirichlet priors. The approach also employs two scoring metrics, BIC and Info-geo, to provide candidate networks at each step of the search process. Moreover, the approach restricts the search space by incorporating several semantic constraints to ensure face validity. Our methodology does not preclude the use of other techniques and algorithms.

As additional research, model builders should construct BBNs for other types of IT implementations because, for example, the factors that determine clientserver implementation success (or conversely failure) may not explain e-commerce implementation success. Moreover, the implementation factors that appear here may change over time as companies and IT professionals become better at managing IT implementations, necessitating the development of another data set and BBN model. Finally, this paper only demonstrates proof of concept of how BBNs can be incorporated into DSSs for IT implementation. Although the classification accuracy of the existing model is high, the model could be applied to one or more real-world cases for further validation.

BBNs are an emerging tool for DSS, especially for decision making under uncertainty. This paper should provide the impetus for other researchers to begin exploring the ample research opportunities associated with incorporating BBNs into DSSs for IT implementation decision-making.

To estimate the prior $p ( \pmb \theta | \mathcal G )$ , conjugate analysis is used. For each of the most popular statistical families there exists a family of distributions for the parameter such that, if the prior distribution is chosen to be a member of the family, then the posterior distribution will also be a member of that family. Such a family of distributions is called a conjugate family. Choosing a prior distribution from that family will typically simplify the computation of the posterior. The conjugate prior for a multinomial distribution is the Dirichlet distribution. Following Ramoni and Sebastiani [27], the notation $\Theta _ { i } ( j ) \sim D _ { i } ( \alpha _ { i j 1 } , \it { \Omega } \cdot \cdot \cdot , \alpha _ { i j r _ { i } } )$ indicates that each vector of parameters ${ \bf \theta } _ { { i } } ( j )$ follows a Dirichlet distribution with hyperparameters $\alpha _ { i j 1 } , ~ . . . , ~ \alpha _ { i j r _ { i } }$ This means that the posterior distribution of $\mathbf { \boldsymbol { \mathsf { \mathbf { \theta } } } } _ { i } ( \ r _ { j } )$ is $D i ( \alpha _ { i j 1 } + N _ { i 1 ( j ) } , . . . , \alpha _ { i j r _ { i } } + N _ { i r _ { i } ( j ) } )$ The Dirichlet prior has a simple interpretation in terms of imaginary counts. The quantity $\begin{array} { r } { \alpha _ { i j } = \sum _ { k = 1 } ^ { r _ { i } } \alpha _ { i j k } } \end{array}$ is the local precision on ${ \bf \theta } _ { { i } } ( j )$ , and $\begin{array} { r } { \alpha _ { i } = \sum _ { j = 1 } ^ { q _ { i } } \alpha _ { i j } } \end{array}$ is the global precision on $\mathbf { \boldsymbol { \mathsf { \mathbf { \mathbf { \theta } } } } } _ { i } ,$ the number of imaginary observations for all the conjunctions $\{ x _ { i } ^ { ( t ) } = k$ and configuration $x _ { \mathrm { p a } ( i ) } ^ { ( t ) } = j \}$ of a given node $X _ { i } .$ . Assuming that all variables $X _ { i }$ have the same prior sample size ${ \alpha = } \alpha _ { i } ,$ $\alpha _ { i j k }$ can be calculated from α as $\boldsymbol { \alpha } _ { i j k } { = } \boldsymbol { \alpha } / ( \boldsymbol { q } _ { i } { \cdot } \boldsymbol { r } _ { i } )$ therefore distributing α uniformly among the parameters of each conditional probability table at each node. Dirichlet's precision parameter α is known as the equivalent sample size and represents the strength of the prior in terms of imaginary observations. The maximum a posteriori (MAP) estimate of each parameter in vector θ is then calculated as:

$$
\tilde {\theta} _ {i k} (j) = \frac {N _ {i k} (j) + \alpha_ {i j k}}{\sum_ {k = 1} ^ {r _ {i}} N _ {i k} (j) + \alpha_ {i j k}}\tag{5}
$$
