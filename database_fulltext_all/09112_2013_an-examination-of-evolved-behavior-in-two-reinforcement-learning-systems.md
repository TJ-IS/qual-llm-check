# An examination of evolved behavior in two reinforcement learning systems

David A. Gaines, Ram Pakath ⁎

Decision Science & Information Systems, School of Management, C. M. Gatton College of Business & Economics, University of Kentucky, Lexington, KY 40506-0034, US

a r t i c l e i n f o

Article history: Received 19 May 2012 Received in revised form 13 January 2013 Accepted 21 January 2013 Available online 31 January 2013

Keywords: Genetic Algorithm (GA) Reinforcement Learning System (RLS) Learning Classi<sup>fi</sup>er System (LCS) Extended Classi<sup>fi</sup>er System (XCS) Machine Learning (ML) Iterated Prisoner's Dilemma (IPD)

## a b s t r a c t

Using agent-based simulation experiments, we assess the relative performance of two Reinforcement Learning System (RLS) paradigms – the classical Learning Classi<sup>fi</sup>er System (LCS) and an enhancement, the Extended Classi<sup>fi</sup>er System (XCS) – in the context of playing the Iterated Prisoner's Dilemma (IPD) game. In prior research, the XCS outperforms the LCS in solving the Animats-and-Maze and Boolean Multiplexer test problems. Our work has overlaps with and is an extension of such efforts in that it allows assessment of each system's ability to (a) cope with delayed environmental feedback, (b) evolve irrational choice as the optimal behavior, and (c) cope with unpredictable input from the environment. We <sup>fi</sup>nd that while the XCS is considerably superior to the LCS, in terms of four key performance metrics, in playing IPD games against a deterministic, reactive game-playing agent (Tit-for-Tat), the LCS does better against an unpredictable opponent (Rand) albeit with signi<sup>fi</sup>cant evolutionary effort. Further, upon examining each XCS enhancement in isolation, we see that speci<sup>fi</sup>c LCS variants equipped with a single XCS feature, do better than the traditional LCS model and/or the XCS model in terms of particular metrics against both types of opponents but, again, usually with greater evolutionary effort. This suggests that if of<sup>fl</sup>ine, rather than online, performance and speci<sup>fi</sup>c performance goals are the focus, then one may construct relatively-simpler LCS variants rather than full-<sup>fl</sup>edged XCS systems. Further assessments using LCS variants equipped with combinations of XCS features should help better comprehend the synergistic impacts of these features on performance in the IPD.

## 1. Introduction

Learning Classi<sup>fi</sup>er Systems (LCS; [13]), based on a machine learning paradigm called Genetic Algorithms (GA), evolve syntacticallysimple rules called classi<sup>fi</sup>ers to guide system performance in an unknown environment. The Extended Classi<sup>fi</sup>er System (XCS; [28]) is a re<sup>fi</sup>nement of this model, differing primarily in its assessment of classi<sup>fi</sup>er utility by focusing on Payoff Prediction Accuracy in lieu of Predicted Payoff Magnitude and in deploying a “Niche” GA, instead of a “Panmictic” GA, for procreation. Both systems belong to a family of systems called (Evolutionary) Reinforcement Learning Systems. Under appropriate circumstances, such as solving Boolean Multiplexer (i.e., Boolean Mux) functions (see Appendix A for a description) and guiding Animats through Maze-like environments (e.g., see [27]), speci<sup>fi</sup>c XCS implementations evolve “optimal” classi<sup>fi</sup>er sets that better “display” evolved knowledge.

The test environments just mentioned involve building arti<sup>fi</sup>cial systems capable of evolving rational behavior in deterministic problemsolving settings where a system receives immediate feedback/input to its actions from its environment. While the Boolean Mux is a “single-step” problem (i.e., consists of a single input–action–reward sequence), the Animats-and-Maze problem is generally a multi-step problem (i.e., consists of a series of input–action–reward sequences that terminates with a <sup>fi</sup>nal reward following a <sup>fi</sup>nal input–action pair). A single-step problem environment offers immediate payoff/reward to a learning system whereas in a multi-step environment, payoff is usually delayed (until the <sup>fi</sup>nal step). The Boolean Mux and particular instances of Animats-and-Maze (e.g., Woods 1 [27]) provide an environment that is Markov with respect to payoff, while other instances of the latter (e.g., Woods 7 [27]) do not possess this property. In Boolean Mux and particular Animats-and-maze problems, system-environment interactions result in uniform/symmetric updates to a system's knowledge base (i.e., its classi<sup>fi</sup>er set). Other Animats-and-Maze problems result in “asymmetric updates,” that could impact a system's generalizability.

In this research, we examine the relative performance of LCS and XCS in the Iterated Prisoner's Dilemma (IPD) game-playing setting. This setting shares some features in common with the Boolean Mux and/or speci<sup>fi</sup>c Animats-and-Maze settings and also offers other, interesting features. It can be set up as an environment: (i) that is deterministic/predictable or stochastic/unpredictable, (ii) that allows modeling a series of independent, one-step problems or interdependent, multi-step problems, (iii) that does or does not possess the Markov property, (iv) that offers immediate or delayed feedback/input to the learner, (v) that allows for symmetric or asymmetric knowledge-base updates in the learner, and (vi) that permits the evolution of rational or irrational behavior as the optimal behavior by the learner. Given this <sup>fl</sup>exibility, we set up experiments to assess, in particular, each system's ability to (a) cope with delayed feedback, (b) evolve irrational choice as the optimal behavior, and (c) cope with unpredictable input from the environment, each of which are test-setting features not explored enough, or at all, in prior studies with LCS and XCS.

Using agent-based simulation experiments, we compare and contrast the evolved behavior of speci<sup>fi</sup>c LCS and XCS implementations in terms of key performance metrics when each is pitted against a deterministic, reactive IPD game-playing opponent (Tit-for-Tat) and also a completely stochastic player (Rand). Our interest is in examining to what extent the posited advantages of XCS over LCS hold in the IPD game-playing test environment when playing against TFT (i.e., when environmental characteristics (a) and (b) mentioned above are present). Simulated games against Rand allow us to examine performance degradations that should occur when the environment is chaotic (i.e., when characteristic (c) is present). We also test several variants of the base LCS model, each incorporating one of the many distinguishing characteristics of the XCS paradigm but otherwise retaining all of the base LCS's features, with a view to discerning to what extent each XCS feature, taken in isolation, contributes to performance against TFT and Rand.

The remainder of this paper is organized as follows. In Section 2, we provide background information on the LCS and the XCS paradigms. In Section 3, we summarize the hypothesized bene<sup>fi</sup>ts of the XCS system over other Reinforcement Learning Systems, as documented in prior literature. In Section 4, we describe the IPD game and further elaborate on its choice as our test environment. In Section 5, we describe our agent-based simulation experimental methodology and present experimental <sup>fi</sup>ndings. Section 6 offers concluding thoughts and future research directions.

## 2. Background

This section introduces the reader to essential features of the two paradigms of interest to this research with a focus on highlighting distinguishing characteristics.

## 2.1. The Learning Classifier System paradigm

A Learning Classi<sup>fi</sup>er Systems (LCS) is a Machine Learning paradigm <sup>fi</sup>rst posited by Holland [13]. Using a Genetic Algorithm (GA), a LCS learns syntactically-simple string rules, called classi<sup>fi</sup>ers, to guide its performance in an unknown environment. A “classi<sup>fi</sup>er” system derives its name from its ability to “classify” inputs from its environment into sets, and to recommend actions based on those sets.

Holland drew upon Darwin's [9] theory of enhanced survival of <sup>fi</sup>tter entities to model adaptation by an arti<sup>fi</sup>cial system. This idea later became the basis of research areas like Evolutionary Computation, Adaptive Behavior, and Arti<sup>fi</sup>cial Life [20]. Holland [13] postulated that a system could learn to perform a task by repeated trial-anderror attempts at maximizing environmental rewards to the system. This approach is today formalized as Reinforcement Learning, a form of unsupervised learning and a major branch of Machine Learning research [20]. In Reinforcement Learning, information about whether the system response to input was good or bad (usually in the form of payback) is provided following system response [16].

Fig. 1 depicts a general Reinforcement Learning scheme. Reinforcement Learning is frequently chosen as the learning mechanism in machines because it is often unclear what steps a machine must follow to achieve de<sup>fi</sup>ned goals (and, it is also dif<sup>fi</sup>cult to predict how the machine's actions will affect the environment). However, because goals are known, rewards can be attached to them. An appropriate reward mechanism is often much easier to implement than prescribing appropriate behavioral steps [28].

A Learning Classi<sup>fi</sup>er System has three major components: (a) a Rule and Message Subsystem, (b) an Apportionment of Credit Subsystem, and (c) a Classi<sup>fi</sup>er Discovery Mechanism. Each is brie<sup>fl</sup>y described below.

(a) Rule and Message Subsystem: Each classi<sup>fi</sup>er (or rule) consists of a conditional statement whose constituents are words drawn from the ternary alphabet (0, 1, #). The restricted alphabet set allows for the power of Genetic Algorithms to be applied in discovering new rules but does not diminish the representational capacity of classi<sup>fi</sup>ers.

Each classi<sup>fi</sup>er, C→A (S), has a “condition” statement, C, as the antecedent linked by $\hat { \textbf { d } } ^ { * } \xrightarrow { } ^ { * }$ symbol to an “action” statement, A, as the consequent, and an associated “strength” value, S. The condition and action portions are of <sup>fi</sup>xed lengths and each location in the condition and action is associated with a speci<sup>fi</sup>c meaning. The condition could use the entire ternary alphabet (i.e., 0, 1, and #) whereas the action is restricted to be binary (i.e., 0 and 1 only). The strength values are relative; therefore, a range limit is set. For example: 10101000110011##100#→11100001(32.9). The condition is used to match input binary (i.e., 1–0) strings obtained from the environment or from prior LCS actions. The “#” symbol is called a “wildcard” symbol and would match inputs with either a “1” or a “0” at that location. More “general” classi<sup>fi</sup>ers (i.e., with more “#” symbols) are more likely to match more input strings than more “speci<sup>fi</sup>c” classi<sup>fi</sup>ers (i.e., with fewer # symbols).

(b) Apportionment of Credit Subsystem: The apportionment of credit subsystem facilitates the adiustment of classifier strengths as the LCS evolves. Strength adjustments occur via three interrelated mechanisms: Auction, Reinforcement and Punishment, and Taxation. The classi<sup>fi</sup>er system's detectors receive environmental input and assemble the input into “messages.” Each classi<sup>fi</sup>er attempts to match its condition with each environmental message and those that match, bid for the privilege of executing their action (i.e., “<sup>fi</sup>ring”) in an auction. Each classi<sup>fi</sup>er's bid is a function of its strength and speci<sup>fi</sup>city with larger bids by stronger and more-speci<sup>fi</sup>c classi<sup>fi</sup>ers. Random noise is added to each bid to allow exploration of the classi<sup>fi</sup>er set by allowing less-quali<sup>fi</sup>ed (i.e., less speci<sup>fi</sup>c and/or strong) classi<sup>fi</sup>ers to <sup>fi</sup>re on occasion in addition to exploitation (i.e., allowing the most-quali<sup>fi</sup>ed to <sup>fi</sup>re). The victorious classi<sup>fi</sup>er pays its bid to the environment and has its strength reduced by the same amount for the privilege of <sup>fi</sup>ring.

Finally, taxation is levied on each classi<sup>fi</sup>er per iteration (called a “life tax”) and on each classi<sup>fi</sup>er that submits a bid during an auction (called a “bid tax”). The purpose of the “life tax” is to reduce the strength of classi<sup>fi</sup>ers that rarely or never are matched and therefore provide little or no utility. The purpose of the “bid tax” is to weaken classi<sup>fi</sup>ers that bid on every step but seldom win because of their low speci<sup>fi</sup>city. The <sup>fi</sup>ring classi<sup>fi</sup>er's effect (upon executing its action) will be either bene<sup>fi</sup>cial or detrimental to the environment. With this feedback, the apportionment of credit subsystem appropriately uses reinforcement and punishment to increase or decrease the strength of the classi<sup>fi</sup>er.

Computer simulations show that the exact mechanism for the apportionment of credit subsystem is not critical to the learning ability of the classi<sup>fi</sup>er system, although some forms result in more or less ef<sup>fi</sup>cient learning than others [23].

(c) Classi<sup>fi</sup>er Discovery Mechanism: An LCS deploys two Classi<sup>fi</sup>er Discovery Mechanisms: (i) a Genetic Algorithm, and (ii) a Triggered Cover Detector Operator.

(i) The Genetic Algorithm: The foremost mechanism, the Genetic Algorithm (GA), provides the bulk of the discovery and learning capability found in an LCS. A GA is a stochastic search algorithm based on the mechanics of natural selection [9] and population genetics. Genetic Algorithms are patterned after natural genetic operators (Selection, Reproduction, Crossover, and Mutation) that enable biological populations to effectively and robustly adapt to their environment and to changes in it. Genetic Algorithms are theoretically and empirically shown capable of robust search in complex spaces [12]. While performing its search, a GA balances the need to retain population diversity (exploration) so that potentially important information is not lost, with the need to focus on <sup>fi</sup>tter portions of the population (exploitation). While opinion is divided on the relative importance of Crossover versus Mutation in a GA, it is generally acknowledged that Selection plays a critical role in such systems. In many GA implementations, though, by biological analogy and based on empirical studies, the Mutation rate is set to be considerably less than the Crossover rate.

LCS systems maintain constant size populations. Therefore for each new individual created, another individual must be eliminated. There are two broad strategies for population renewal — using a Generational Replacement Genetic Algorithm (GRGA) or a Steady State Genetic Algorithm (SSGA). A GRGA replaces the entire population with each generation whereas an SSGA replaces only a small portion of the population. Many LCS implementations use the SSGA approach.

(ii) Triggered Cover Detector Operator: The “triggered cover detector operator” (TCDO) is a rule generation mechanism that is only activated when no classi<sup>fi</sup>er matches (i.e. covers) any environmental message. It responds by producing one new classi<sup>fi</sup>er that would match some message. The action part is randomly generated on the binary alphabet.

For the system to begin learning, it must be equipped with an initial set of classi<sup>fi</sup>ers (an initial population) which usually is randomly generated. In addition, parameters such as the population size, the length for each condition and action, and the probability of assigning a 1, 0, or # at each location, must be pre-de<sup>fi</sup>ned. The randomly generated initial classi<sup>fi</sup>ers are most likely of low quality and are considered nothing more than guesses. The classi<sup>fi</sup>er system interacts repeatedly with the environment, receiving feedback with each interaction and allowing the guesses to be ranked. These iterations constitute the classi<sup>fi</sup>- er system's major cycle (also called an epoch). After each epoch, the GA is applied, effectively mating the best guesses. With increasing epochs, the quality of the guesses also increases as the system learns. With some learning behind it, the population of classi<sup>fi</sup>ers may be thought of as a population of hypotheses. As epochs pass, successful hypotheses will exchange information via the Genetic Algorithm. These offspring will replace disproved hypotheses with more plausible (but as yet untested) and, increasingly, more speci<sup>fi</sup>c hypotheses. The co-existence of general (or default) hypotheses and speci<sup>fi</sup>c (or exception) hypotheses allows the classi<sup>fi</sup>er system to handle novel situations by general hypotheses while the exception hypotheses allow it to deal with known, particular situations. When the LCS has met criteria to be considered learned, the classi<sup>fi</sup>ers may be considered as well-attuned behavioral heuristics and rules.

In closing, we note that two considerations must be accounted for when determining the initial strength assigned to a new classi<sup>fi</sup>er created by either the GA or the TCDO: (a) The strength should not be too low, otherwise the new classi<sup>fi</sup>er will never win an auction and therefore never get a chance to prove itself better (or worse) than existing classi<sup>fi</sup>ers; and (b) The strength should not be too high, otherwise the new classi<sup>fi</sup>ers will be tried too often, overruling existing classi<sup>fi</sup>ers that perform well, and may lead to unstable performance. Computer simulation studies conclude that TCDO-generated classi<sup>fi</sup>ers should be assigned the average classi<sup>fi</sup>er population strength, while the GA offspring should have the average parental strength [24].

## 2.2. The Extended Classifier System paradigm

The Extended Classi<sup>fi</sup>er System (XCS) model is an extension of the LCS paradigm that seeks to overcome the following LCS weaknesses [27].

(1) Classi<sup>fi</sup>ers operating in unusually-high-payoff environmental niches could dominate future populations as they grow disproportionately stronger and increasingly proliferate over time. Lower-strength classi<sup>fi</sup>ers risk being purged, potentially negatively impacting overall system performance.

(2) In deferred-payoff systems, classi<sup>fi</sup>er's that <sup>fi</sup>re early and set the stage for another classi<sup>fi</sup>er to <sup>fi</sup>re and accrue a reward later, will tend to be less <sup>fi</sup>t over time (despite reward back-propagation using bucket-brigade-like algorithms). Useful genetic material could potentially be lost.

(3) An LCS is unable to distinguish between more speci<sup>fi</sup>c and more general classi<sup>fi</sup>ers that offer the same payoff, on average. The more general versions that tend to match environmental states more often, tend to proliferate. But, an LCS has no mechanism to assure that a general classi<sup>fi</sup>er will yield (actual) payoff close to expected payoff.

In response to such concerns, researchers have developed alternative LCS models. Among the more noteworthy are the Resourcedriven LCS [4], the Latent Learning LCS by Riolo [23], and the Payoff Accuracy-driven LCS by Wilson [27,28]. Our interest is in what is the most promising of the three: Wilson's Payoff Accuracy-driven LCS model, called XCS. In XCS (the “Extended Classi<sup>fi</sup>er System”), classi<sup>fi</sup>- er <sup>fi</sup>tness is based on the accuracy of a classi<sup>fi</sup>er's payoff prediction instead of its magnitude. The second major difference is that the GA is not applied to the entire population (i.e., is not a “Panmictic GA”), but to a selected subset called the Action Set (i.e., is a “Niche GA”).

An XCS relies on payoff prediction and, as such, there is room for prediction error. The strength/<sup>fi</sup>tness of a classi<sup>fi</sup>er is an inverse function of prediction error and measures a classi<sup>fi</sup>er's reliability. Copies of all classi<sup>fi</sup>ers that match a given input are placed in a Match Set. XCS requires that the number of diverse actions represented by the classi<sup>fi</sup>ers in the Match Set exceed a pre-speci<sup>fi</sup>ed threshold. If not, additional “covering” classi<sup>fi</sup>ers are generated. A covering classi<sup>fi</sup>er's condition is identical to the input, but each conditional element is generalized (i.e., set to “#”) with prede<sup>fi</sup>ned probability.

Next, XCS calculates a Prediction Array which contains the system-predicted payoff for each action associated with classi<sup>fi</sup>ers in the Match Set. Each prediction is a <sup>fi</sup>tness-weighted average of the predictions of all classi<sup>fi</sup>ers in the Match Set advocating that action. From the actions in the Prediction Array, XCS selects an action to perform using a process called Biased Exploration (i.e., whereas most of the time XCS performs the action with the highest predicted payoff (“exploitation”), on occasion (with some pre-de<sup>fi</sup>ned probability), XCS will perform any one of the actions in the Array (“exploration”)). This is done because the actual reward for an action, is an uncertain quantity. Exploration allows an XCS to sample and determine the value of a more diverse set of actions. Once an action is selected, copies of all corresponding classi<sup>fi</sup>ers in the Match Set are placed in an Action Set.

The chosen action is performed and an environmental reward is received. XCS updates the rules in the Action Set based on the received reward. This includes updates to each rule's system-predicted reward, its prediction error, and its <sup>fi</sup>tness. An important feature of <sup>fi</sup>tness assessment in an XCS system is that a classi<sup>fi</sup>er's <sup>fi</sup>tness is an estimate of its accuracy with respect to the accuracies of other classi<sup>fi</sup>ers in the Action Sets in which it participates.

Unlike LCS, XCS begins execution with an empty population. An initial classi<sup>fi</sup>er is generated through covering. XCS also resorts to covering subsequently, whenever no matching classi<sup>fi</sup>ers are available. However, the vast majority of new classi<sup>fi</sup>ers are generated using a GA.

Periodically, a GA is called upon to modify the population of classi<sup>fi</sup>ers present in the Action Set (i.e., the GA operates as a “Niche GA” and not as a Panmictic GA as in the LCS). Based on their <sup>fi</sup>tness's, the GA chooses two classi<sup>fi</sup>ers from the set. In doing so, an XCS uses a parent selection procedure called “Tournament Selection.” In this approach, parents are chosen via a series of tournaments arranged between a predetermined number (k) of population members chosen at random. From those chosen, the “nth <sup>fi</sup>ttest” member is chosen for procreation with a probability, $\mathtt { p } \ast ( 1 - \mathtt { p } ) ^ { \mathrm { n } - 1 } , ( 0 \mathrm { < p } \mathrm { < } 1 ; 1 \mathrm { \leq n } \mathrm { \leq k } )$ . The larger the value of k (i.e., the “tournament size”), the greater the “selection pressure” — weaker individuals have a smaller likelihood of being selected for procreation. This is in contrast to “Fitness Proportional” selection used in LCS where the likelihood of any individual in the population being selected for procreation is proportional to its <sup>fi</sup>tness.

The selected classi<sup>fi</sup>ers are reproduced, crossed, mutated, and inserted in the population. The parents stay in the population competing with their offspring. XCS also uses a feature called “Subsumption Deletion,” where a more speci<sup>fi</sup>c classi<sup>fi</sup>er is deleted if an accurate, experienced, and more general classi<sup>fi</sup>er exists. Also, because classi<sup>fi</sup>er creation could result in duplication, XCS retains one copy of each duplicated classi<sup>fi</sup>er with an associated “numerosity” count indicating how many copies of it exist. This allows for storage savings and ease of computation. Consequently, whereas in an LCS duplicate classi<sup>fi</sup>ers could exist (unless deliberately avoided through mutation) with different associated <sup>fi</sup>tness values, in an XCS all copies have the same <sup>fi</sup>tness value.

Unlike in an LCS, in an XCS, the population size does not stay <sup>fi</sup>xed but varies between 0 and a pre-speci<sup>fi</sup>ed maximum, N. If the number of classi<sup>fi</sup>ers in a population (as determined by adding their individual numerosity values) exceeds the preset population size value, excess classi<sup>fi</sup>ers are deleted. Classi<sup>fi</sup>ers are selected for deletion based on an estimate of the average size of the Action Sets in which each classi<sup>fi</sup>er has participated. Classi<sup>fi</sup>ers participating in larger-thanaverage-sized Action Sets are deleted more often. As a result, Action Sets are about the same size. This has the impact of balancing resource usage across environmental niches. Hence, deletion in XCS is based on “Resource Balancing” whereas in an LCS it is “Fitness Proportional.” Table 1 summarizes the key architectural differences between LCS and XCS systems.

## 3. Posited bene<sup>fi</sup>ts of the XCS paradigm

Prior research [6] suggests that XCS is able to evolve more desirable classi<sup>fi</sup>ers over time than those evolved using a traditional LCS as it possesses two key abilities:

(a) The ability to generate a “complete payoff mapping” of all classi<sup>fi</sup>ers to expected payoff predictions for the problem under consideration, and

(b) The ability to evolve classi<sup>fi</sup>ers that are “maximally general,” subject to a prede<sup>fi</sup>ned accuracy criterion.

The net impact is that an XCS system evolves a more comprehensible population of classi<sup>fi</sup>ers which requires fewer system resources and adapts better to new problems. These advantages have collectively been described as constituting an optimal population or optimal solution. Each of the two abilities is discussed below.

## (a) Complete payoff map

XCS evolves an internal representation that determines the quality of each possible action in each possible environmental state. This representation comprises a “non-overlapping,” “minimal,” “accurate,” and “complete” set of classi<sup>fi</sup>ers. The system also accurately maps all classi<sup>fi</sup>ers in this set to payoff predictions. A “non-overlapping” population means that no part of the problem space is described more than once. A minimal population contains the smallest number of classi<sup>fi</sup>ers required to describe the entire problem space. In practice, the terminal populations in an XCS system tends to be highly compact with only a few extraneous classi<sup>fi</sup>ers. Because XCS uses “accuracy-based” <sup>fi</sup>tness, it also tends toward generating highly-accurate terminal classi<sup>fi</sup>ers where each classi<sup>fi</sup>er correctly predicts the payoff accrued upon its <sup>fi</sup>ring. A complete map is one that has an estimated payoff for each classi<sup>fi</sup>- er. Whereas systems such as Q-Learning also do this, XCS's advantage is that it tends toward generating complete mappings using a minimal classi<sup>fi</sup>er set instead of an exhaustive set.

(b) Maximally general classi<sup>fi</sup>ers

A learning system “generalizes” when it treats seemingly different situations equivalently as the situations have equivalent consequences for itself. It does so using signi<sup>fi</sup>cantly less complex internal structures than the raw environmental data [26]. Classi<sup>fi</sup>ers express generalizations using the “don't care” symbol (#) in their conditions. Thus, a classi<sup>fi</sup>er with condition 00# matches both 000 and 001 (i.e., treats these inputs as equivalent). However, there are various levels of generalization: a classi<sup>fi</sup>er may be over-general, maximally (optimally) general or sub-optimally general [14].

An over-general classi<sup>fi</sup>er matches too many input conditions and, therefore, some of the inputs it matches may pay off at different rates. This implies payoff-prediction inaccuracies. A maximally general classi<sup>fi</sup>er is one which matches only inputs that payoff at the same rate, and which cannot become more general (i.e. one cannot add any more #s to the condition)

Support for the above-mentioned advantages of XCS has been found in simulation experiments assessing XCS's ability to “solve” the $6 \mathrm { - } , 1 1 \mathrm { - } , 2 0 \mathrm { - } , 3 7 \mathrm { - } ,$ and 70-Boolean Mux Functions [5,14,28] and XCS's capacity to guide an animat's way through grid-like “woods” (i.e., maze) environments [19,26]. Such test settings apart, both paradigms have been applied to several real and realistic problems spanning game playing, solving puzzles, design, engineering, control, data mining, function approximation, and others. A comprehensive discussion of LCS and several variants of it, including XCS, along with applications may be found in [25].

## 4. The Iterated Prisoner's Dilemma problem as a test bed

The Prisoner's Dilemma game, due to Flood and Dresher of the Rand Corp. [11], is well-known and widely studied. We provide a brief description as it is central to this work. In a Prisoner's Dilemma, two competing players have the choice of either cooperating with (C) or defecting against (D) one another. Each receives a payoff based on its action (C or D). If both cooperate, each receives a reward of $\mathrm { R } _ { 2 } .$ If both defect, each receives a relatively smaller reward of $\mathsf { R } _ { 3 } .$ If one defects while the other cooperates, the latter gets a sucker's payoff of $\mathtt { R } _ { 4 }$ while the defector gets the highest possible payoff, $\mathrm { R } _ { 1 } .$ The payoffs have the following properties: $\mathtt { R } _ { 1 } > \mathtt { R } _ { 2 } > \mathtt { R } _ { 3 } > \mathtt { R } _ { 4 }$ and $\left( \mathsf { R } _ { 1 } + \mathsf { R } _ { 4 } \right) / 2 < \mathsf { R } _ { 2 } .$ In this paper, we set $\mathrm { R } _ { 1 } = 5 , \mathrm { R } _ { 2 } = 3 , \mathrm { R } _ { 3 } = 1$ and $\mathtt { R } _ { 4 } = 0$ . Thus, mutual cooperation is preferable to mutual defection (i.e., $\mathsf { R } _ { 2 } > \mathsf { R } _ { 3 } )$ and repeated cooperation yields better reward on average than alternately cooperating and defecting. However, because $\mathsf { R } _ { 1 } > \mathsf { R } _ { 2 }$ and ${ \mathrm { R } } _ { 3 } > { \mathrm { R } } _ { 4 } ,$ a player is also tempted to defect, resulting in con<sup>fl</sup>ict between group goal and self goals. Two “rational” players should each defect and, therefore each receive a payoff of $\mathsf { R } _ { 3 } ,$ while two “irrational” players can cooperate and each receive a greater payoff of $\mathrm { R } _ { 2 } .$ An extension of this game is the Iterated Prisoner's Dilemma (IPD) where a player has multiple game “encounters” with another over time. A player has the choice of exploiting prior experience in subsequent encounters. An IPD “tournament” consists of a series of IPD games against a single or multiple opponents.

The PD/IPD model has been studied in a variety of applications in organizational, economic, and societal settings. It has also been used to study the evolutionary behavior of LCS game playing systems [2,3,8,22]. The IPD setting offers the following particular test environment features in evaluating XCS relative to LCS, some of which are unique to it:

First, the conventionally-used test beds for the XCS model, Boolean Mux and the Animats-and-Maze problems focus on evolution guided by rational choice. Given the payoff structure for the IPD game, with particular opponents, irrational behavior could net greater total reward to a learning system than rational behavior. A well-known instance is the Tit-for-Tat (TFT) player who begins by cooperating but thereafter pays back a defection in the preceding encounter with a defection of its own in the current encounter. With such an opponent, a system should learn to (irrationally) cooperate over time as this is the only reward-maximizing strategy. There also exist other TFT-like deterministic and stochastic strategies (e.g., Two-Tit-for-Tat (TTFT), Generous TFT (GTFT) or Hostile TFT (HTFT aka Joss's strategy)) where irrationality pays. Thus, the IPD setting allows one to measure evolutionary behavior in learning systems where rational choice is not necessarily the “optimal” evolved behavior.

Second, the Boolean Mux setting constitutes a “single-step” test setting [15]. A single-step test problem is one where there is a single input-action-reward sequence and, therefore, a system's past actions do not in<sup>fl</sup>uence future environmental inputs. The IPD problem, like many Animats-and-Maze problem instances, constitutes a multi-step test setting when “reactive” opponents like TFT (or its variants) are deployed. A multi-step setting is one de<sup>fi</sup>ned by a series of input–action–reward sequences. Here, past actions in<sup>fl</sup>uence future input. With a TFT-like opponent, the opponent's subsequent moves (that constitute environmental input to the LCS/XCS) are in<sup>fl</sup>uenced by the system's prior moves. Multi-step settings are more complex for a learning system to cope with.

Third, with the IPD problem setting, we can introduce delayed environmental feedback using opponents like TFT and its variants. For instance, TFT introduces a one-step delay in providing feedback to a learning system (i.e., the opponent responds to the system's current move with a counter-move in the next encounter) and TTFT provides both a one- and a two-step delayed feedback depending on the system's current move. Consequently, with TFT and variants, a learning system must adapt to predicating action in an encounter on its actions in the immediately-preceding and, perhaps, prior, encounters. The delayed feedback feature is one not shared by the Boolean Mux or the Animats-and-Maze test settings.

Fourth, unlike Boolean Mux and particular Animats-and-Maze problems, when reactive opponents like the TFT are deployed, the IPD game setting is non-Markov with respect to the payoff, p. An environment has the Markov property if the agent's immediate perceptions provide all of the information necessary for it to choose the best action in every situation; otherwise, it is non-Markov [21]. Stated differently, in the case of XCS, the environment is Markov if knowledge of states preceding the current state, x, and action, a, will not allow an improvement in predicting payoff, p, and thus, determine the best action choice. If the environment is non-Markov, a system must resort to memorycreating mechanisms to transform the problem to Markov to make more informed action choices [28]. This is the case with the IPD problem with a TFT-like opponent where recollection of past action choices by the XCS and the opponent are crucial for system evolution. Thus, the IPD setting would allow one to test LCS and XCS in a setting that calls for short-term memory given our emphasis on exploring on-line learning and adaptation by the two paradigms. While we do not do so in this research, the IPD setting would allow the study of the impacts of alternative memory designs on a learning system.

Fifth, unlike Boolean Mux and particular Animats-and-Maze instances, the IPD game could result in “asymmetric” updates to a learning system's knowledge base. This situation is related to a concept called, “categorical regularity” [28]. A categorical regularity, $( \{ \mathbf { x } \} , { \mathsf { a } } ) \to \mathbb { p } ,$ is an assertion that states that for all members of the set of environmental states {x}, the performance of a given action $\ " { \bf q } \ "$ will yield the same payoff “p.” All states in {x} are equivalent in this respect with regard to action “a.” A common instance is where an action results in payoff of 0 at many environmental states. An environment could contain several such categorical regularities, associated with different sets of states and actions.

In prior experimentation, XCS has portrayed a strong ability to detect and capture all possible categorical regularities. In the case of Boolean Mux problems, each categorical regularity covers an equal portion of the input domain. Consequently, random inputs to a Boolean Mux-solving XCS result in all portions of the system's classi<sup>fi</sup>er population being updated and subjected to genetic transformations (via the GA application) at roughly the same rate (i.e., knowledge base updates are “symmetric” and takes place near-uniformly across all content). In the case of the IPD game, the input to a system is a history of moves made by the classi<sup>fi</sup>er and its opponent. When playing against a deterministic, reactive opponent such as TFT, the input environment does have categorical regularities and each does cover an equal portion of the environment. However, inputs to the system are not random — the input is a <sup>fi</sup>nite history of strategic action choices made by the system and TFT. As such, particular classi<sup>fi</sup>ers in the population that match this non-random history would tend get exercised a lot more during the evolutionary process than others resulting in particular population niches being updated and subjected to genetic activity at substantially greater rates than others. So also with an opponent like Rand, as we subsequently clarify, the Defect action is the only prudent action and classi<sup>fi</sup>ers that advocate this action tend to be exercised more often during evolution. The resulting knowledge-base asymmetry could negatively impact the generalizability of a learning system (i.e., its ability to generate a suf<sup>fi</sup>cient number of maximally-general classi<sup>fi</sup>ers). The IPD setting allows one to examine the differential impacts of such asymmetry on LCS and XCS.

Sixth, the IPD setting also allows us to introduce noise into player interactions, an issue that has received comparatively little research attention with XCS systems. For example, an opponent called HTFT (also called Joss's strategy) is TFT-like but occasionally (i.e., with some pre-de<sup>fi</sup>ned probability) turns “hostile” (and hence the “H” in its name) and defects when TFT recommends cooperation. Similarly, Rand is a strategy that cooperates or defects with equal likelihood at each encounter. Testing how well LCS and XCS cope with unpredictable behavior is possible with the IPD setting.

## 5. Experimental methodology and results

We examine steady-state behaviors of LCS and XCS using agent-based simulation experiments. Agent-based simulation models are appropriate for situations when the system is best modeled as a collection of agents who interpret the world around themselves and interact with one another via some pre-de<sup>fi</sup>ned schema [10]. In the current research, the individual classi<sup>fi</sup>ers in an LCS or XCS system constitute the agents and the schema consists of the LCS and XCS paradigms that direct and control the actions of their respective agents. Thus, both LCS and XCS are multi-agent systems. The literature on agent-based systems identi<sup>fi</sup>es several kinds of agents — simple re<sup>fl</sup>ex agents, model-based re<sup>fl</sup>ex agents, goal-based agents, utility-based agents, learning agents, etc. [24]. LCS and XCS are learning agents. By carefully de<sup>fi</sup>ning the agents' interactions, environment, and reward structure, an agent can be programmed to “learn” by tying varying reward levels to varying performance levels [28].

We attempt to determine whether the previously-observed superior performance of XCS over LCS (see Section 3) hold in the IPD gaming environment with two different kinds of opponents — TFT and Rand. This research uses comparative experiments [18]. Speci<sup>fi</sup>cally, various pairings of LCS- and XCS-based agents with competing agents (i.e., TFT and Rand) constitute the two sets of circumstances; the results of trials using these differing circumstances are then compared to assess relative performance.

## 5.1. Experiment set 1a

In our initial experiments, we allow an LCS and an XCS system to play the IPD game against a deterministic, reactive agent playing the Tit-for-Tat (TFT) strategy, the best human-generated strategy for playing the IPD [2,3]. Recall that TFT begins by cooperating and, thereafter, repays a defection or a cooperation by the learning system in any encounter with a corresponding defection or cooperation in the immediately following encounter. This introduces a one-step delay in environmental feedback to a learning system.

We designate the LCS used in this experiment as LCS-0. LCS-0 is characterized by the typical LCS system features as shown in Table 1 with the following choices applied where Table 1 indicates more than one approach: Classi<sup>fi</sup>er Deletion is done with the more widely-used Steady State GA (SSGA). Classi<sup>fi</sup>er Fitness Updates involve a limited reward back-propagation mechanism whereby a <sup>fi</sup>ring classi<sup>fi</sup>er shares portions of its accrued reward with enabling classi<sup>fi</sup>ers from the recent past. The XCS maintains all of the features listed in Table 1.

Both LCS and XCS use a number of other parameters in their operation. Several are common to both models and must be identically operationalized. A listing with a brief description of, and values recommended for, each parameter is provided in Appendix B [7,17,27].

In assessing comparative performance, we used four measures: Number of Unique Classi<sup>fi</sup>ers, Proportion Correct, System Error, and Percent Optimal. These measures are de<sup>fi</sup>ned below.

Number of Unique Classi<sup>fi</sup>ers (#-Unique): As noted earlier, XCS physically stores one copy of each classi<sup>fi</sup>er with an associated “numerosity” count. The LCS also permits duplicate classi<sup>fi</sup>ers, unless explicitly avoided using mutation. To discern its ability to generate unique classi<sup>fi</sup>ers, we allowed LCS-0 to maintain duplicates. In both cases, #-Unique is a count of the number of distinct classi<sup>fi</sup>ers over the preceding 50 encounters (designated as one “generation”). The #-Unique measure assesses an agent's ability to represent its knowledge compactly and ef<sup>fi</sup>ciently. Agents with smaller #-Unique values are generally more comprehensible and require fewer system resources [27].

Proportion Correct (%-Correct): This measure reports the proportion of the last 50 encounters in which the system responded correctly [27]. Larger %-Correct values suggest greater learning ability. What is the correct system response is opponent dependent. From the IPD payoff values described earlier (i.e., $\mathrm { R } _ { 1 } = 5 , \mathrm { ~ R } _ { 2 } = 3 , \mathrm { ~ R } _ { 3 } = 1$ and $\mathrm { R } _ { 4 } =$ 0), with TFT, mutual cooperation yields the highest total reward of $2 ^ { * } \mathrm { R } _ { 2 } = 6 .$ If the learner focuses instead solely on self-reward, it will be encouraged to repeatedly “experiment” with defection to its detriment. Therefore, against TFT, the correct response is that which maximizes the sum of the rewards earned by both players.

System Error: System Error, as originally de<sup>fi</sup>ned [14], is a measure of the absolute difference between the system-predicted payoff and the actual payoff for a given state-action pair. It measures the prediction ability of a system. In our work, we calculate System Error as the sum of the squared differences between the system-predicted and actual rewards for each state-action pair in the previous 50 encounters. This value is then converted to a “per encounter” average squared error value. We use squared error in keeping with conventional statistical practice of emphasizing relatively large errors.

Percent Optimal (%-Optimal): %-Optimal is the proportion of the “optimal population” (see de<sup>fi</sup>nition below) of classi<sup>fi</sup>ers present in a system at any given time step [17]. This measure is useful as a measure of the progress of the genetic search, prior to and post stabilization. Assessing %-Optimal requires more trials than for %-Correct because even after the classi<sup>fi</sup>er system has begun responding correctly to all inputs, it may still require more time to discover the optimal population [17]. In our experiment, we operationalized %-Optimal by determining the average proportion of the optimal classi<sup>fi</sup>er set present in the population during the preceding 50 encounters. In the case of TFT, the optimal population is de<sup>fi</sup>ned as in Table 2.

## 5.2. Experiment set 1b

A key driver for the XCS model, as previously noted, is its payoff-prediction accuracy feature unlike LCS that is guided by predicted-payoff magnitude. One would expect that in circumstances where accurate prediction is impossible or extremely dif<sup>fi</sup>cult, XCS's performance should degrade. To ascertain this, we repeated the above experiment by replacing TFT with Rand which either cooperates or defects with equal likelihood at every encounter. When playing against Rand, many of the challenges noted when playing against TFT do not apply (i.e., we are no longer dealing with a multi-step problem, there are no feedback/input delays to cope with, no longer is irrational behavior the optimal evolved behavior, and the environment is already Markov with respect to payoff eliminating the need for a short-term memory mechanism). Rand, instead, introduces a different challenge — that of an unpredictable environment.

With Rand, evolving to a state of consistent mutual cooperation is impossible. The only options an opponent has are to sucker Rand, be suckered by Rand, or settle for mutual defection. Of the three options, the option to avoid would be getting suckered by Rand. Therefore, the best system strategy is to always defect. To induce the learning system toward consistent defection the feedback provided is the reward accrued to the learning system only (and not, as with TFT, the total reward for both players). With this inducement, knowledgebase updates will continue to be asymmetric (i.e., only classi<sup>fi</sup>ers advocating defection would tend to be heavily re-used when approaching and post stabilization). In sum, with Rand a learning system is faced with two challenges — an unpredictable environment coupled with asymmetric knowledge-base updates.

Given its unpredictability, one cannot de<sup>fi</sup>ne an Optimal Population for Rand. This is because, regardless of historical moves made by either player, Rand's subsequent moves are unpredictable and history-independent (i.e., no longer does the 3-encounter memory serve any purpose to the learning system.) As such, one cannot articulate a single, de<sup>fi</sup>nitive Actual Payoff value to be expected for any move made by a learning system because payoff is conditional upon Rand's unknown random behavior.

Also, while LCS-0 takes almost twice as long as XCS, it converges to a value that is a third that of XCS. Despite the signi<sup>fi</sup>cantly greater effort expended in evolving to a stabilized state, LCS-0 clearly performs much better than XCS against Rand in generating a more compact set of (unique) classi<sup>fi</sup>ers. ## 5.3. Experiment set 2a

Recall, from Section 2, that two key architectural differences between the XCS and the LCS paradigms are the latter's reliance on Payoff Prediction Accuracy and a Niche GA (instead of Predicted Payoff Magnitude and a Panmictic GA as with the LCS). The two models have other differences as well as summarized in Table 1. We repeated this for each characteristic, in effect creating eight different LCS models where each model is identical to the base LCS model, LCS-0, in all respects except the one characteristic being perturbed. This was done with a view to discerning the impact of each characteristic taken in isolation. Further research will be needed to explore the joint impacts of combinations of characteristics, particularly the more promising ones. Another excellent performer, LCS-4 (Biased Exploration Action Selection) posts a rate of 0.0153 which is about twice XCS's error rate but smaller than LCS-0's. LCS-8 (Payoff Prediction Accuracy-driven) proved to be an extreme outlier posting the highest error rate of 1.0203 with the highest stabilization encounter count of 190,000. We are able to build several LCS-0 variants that do on-par or better than XCS and LCS-0 with regard to System Error. The only characteristics that seem to adversely impact System Error are Variable Population Size and the use of Payoff Prediction Accuracy instead of Predicted Payoff Magnitude.

From the above analyses, we see that %-Optimal, where XCS scores 97.26%, is the one performance measure that proves the most challenging for the LCS-0 perturbations. We also see that many of the variants work substantially harder at achieving stabilization when compared to LCS-0 and XCS. Individual characteristics that together give XCS its power over LCS-0 in playing against TFT, also offer less than their synergistic effect when used in isolation. However, if one is concerned with optimizing a particular measure to the exclusion of the others, and with of<sup>fl</sup>ine performance (i.e., performance post evolution) rather than online performance (i.e., performance during evolution), then we do have several alternative LCS models that are simpler to construct than a full-<sup>fl</sup>edged XCS to choose from.

## 6. Concluding remarks

In this paper, we examine the performance of the Learning Classi<sup>fi</sup>er System (LCS-0) and the relatively more recent, Extended Classi<sup>fi</sup>er System (XCS) models in an Iterated Prisoner's Dilemma (IPD) game playing setting. The setting chosen permits us to test both reinforcement learning systems (RLS) in terms of their respective abilities to (a) cope with delayed environmental feedback, (b) evolve irrational choice as the optimal behavior, and (c) cope with unpredictable input from the environment. The IPD setting also allows setting up both single-step and multi-step test environments.

We pit both systems against two IPD game-playing strategies — the Tit-for-Tat (TFT) strategy and the utterly Random (Rand) strategy. We observe that features that make XCS a substantially superior performer to LCS against the deterministic, reactive TFT strategy do not offer the same bene<sup>fi</sup>t against the unpredictable Rand strategy. Indeed, XCS's performance lags LCS's against the latter and substantially so according to some of our performance metrics. We conclude that the LCS paradigm continues to remain useful in settings that are unsuited for XCS's idiosyncrasies.

To further comprehend the two paradigms, we construct and test variants of the LCS paradigm, where each variant incorporates just one of XCS's unique features, to assess to what extent each feature plays a role in XCS's success against TFT, when considered in isolation. We discern particular variants that do better than XCS and/or LCS-0 with respect to particular metrics. We also understand that no single variant outperforms both XCS and LCS-0 in terms of all four metrics. Finally, we see that the more successful variants usually entail much more effort in that they take longer to attain a stabilized state with respect to the measure of interest. We conclude that it would be possible to construct variants of the base LCS paradigm (i.e., LCS-0), that outperform XCS and are simpler to construct than XCS, if computational effort is not a concern (i.e., of<sup>fl</sup>ine performance is of interest) and if one were focusing on particular performance metrics and not all of them. We repeat the experiment with Rand and <sup>fi</sup>nd several LCS variants that signi<sup>fi</sup>cantly outperform XCS in terms of #Unique and System Error but with greater evolutionary effort, signi<sup>fi</sup>cantly so in the case of System Error. The % Correct measure showed no appreciable gains with any of the Variants. Also, with Rand, we <sup>fi</sup>nd variants that outperform XCS across multiple measures. As such, if of<sup>fl</sup>ine performance is the focus, then we have several LCS variants to choose from that do better than XCS against Rand.

While we have constructed variants that incorporate a single XCS enhancement each, it seems very likely that these features interact in complex, synergistic ways as no single variant that we examined did better than LCS-0 or XCS in terms of all four performance metrics. It would, therefore, be instructive to build and examine variants that incorporate carefully-selected combinations of XCS features, perhaps combinations selected from features that showed promise in our experiments. Also, we have taken a bottom-up approach by introducing XCS features to LCS-0 in creating LCS variants. One may, instead, take a top–down approach by progressively stripping XCS of its features, in effect creating a set of XCS variants. Exploring LCS, XCS, and variants of both systems against other deterministic strategies like TTFT, TFTT, etc., should prove insightful in examining the impact of multi-step delays in environmental feedback. Stochastic counterparts to such deterministic strategies like GTFT, HTFT/Joss, and others, with systematic manipulation of defection probabilities, should help us better comprehend when and why LCS begins outperforming XCS.

## Appendix A. The Boolean Mux Function (Affenzeller, et al. [1])

The Boolean Mux Function problem involves identifying the appropriate data bit in a bit string given its address in bit-string form. The input to the Boolean L-Mux function is a bit string consisting of k address bits $\mathsf { a } _ { 0 } , \mathsf { a } _ { 1 } , \mathsf { a } _ { \mathrm { k } - 1 }$ , and $2 ^ { \mathrm { k } }$ data bits $\mathbf { d } _ { 0 } , \mathbf { d } _ { 1 } , . . . , \mathbf { d } _ { 2 - 1 } ^ { \mathrm { k } }$ arranged in a bit string with length ${ \mathrm { L } } = { \mathrm { k } } + 2 ^ { \mathrm { k } }$ as follows: $[ \mathsf { a } _ { 0 } , \mathsf { a } _ { 1 } , . . . . , \mathsf { a } _ { \mathrm { k } - 1 } , \mathsf { d } _ { 0 , }$ $\mathbf { d } _ { 1 } , . . . , \mathbf { d } _ { 2 } ^ { \mathrm { ~ k ~ } } - 1 ]$ . The value returned by the L-Mux function is the value of the particular data bit addressed by the k address bits supplied as input. For example, if k=3 address bits, we have $2 ^ { 3 } = 8$ data bits and input length $\mathrm { L } = 2 + 8 = 1 1$ . Given $\mathtt { a } _ { 0 } \mathtt { a } _ { 1 } \mathtt { a } _ { 2 } = 1 0 1$ , the 11-Mux singles out data bit d to be its output (the decimal equivalent of address 101 is 5). The task of a reinforcement learning system is to decode the mapping between address bits and data bits through repeated exposure to a function with randomly generated address bits.
