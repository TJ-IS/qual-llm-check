## a b s t r a c t

The SimMOp framework for generating solutions to simulation optimization problems containing multiple objectives is presented. The complexity within this subject is the con<sup>fl</sup>icting multiple stochastic outputs whose estimates are only available through simulation. The framework combines a simulation model, a non-exhaustive heuristic search algorithm with an embedded multi-objective optimization technique, and database technologies to generate a set of good quality solutions. The goodness of solutions is measured from a multi-objective and stochastic perspective through analysis after the search phase of the methodology. The methodology has been tested using a discrete-event simulation model based on inventory theory.

## 1. Introduction

Discrete-event simulation is a powerful computational technique for studying dynamic systems containing stochastic elements. Simulation models are constructed to emulate the features of real world systems too complex to be investigated analytically and provide good approximations to the relevant performance measures. Amongst the key aspects of good model development are the processes of veri<sup>fi</sup>cation and validation. These procedures ensure that the designed model works as it is intended and that it is an accurate representation of the system able to provide the desired information to solve formulated problems. The aim of this work is to detail the SimMOp methodology for the optimization of multi-objective simulations and is therefore concerned with model analysis rather than the speci<sup>fi</sup>c work of a modeller. An overview of all aspects in the <sup>fi</sup>eld of discrete-event simulation modelling can be found in Law and Kelton [12].

Once a successfully developed simulation model is given relevant values for the input parameters it is run to collect the output data. Due to the stochastic nature each run of a simulation model is made up of multiple replications and data is collected as mean values with variances over these repeat evaluations. Each individual combination of input parameters, known in simulation as a system, represents an individual scenario for the simulation model. If an analyst is using only a few scenarios experiments can be designed to easily obtain the best, however, it is often preferred to <sup>fi</sup>nd the scenario that optimizes model output from a more extensive set, in which case simulation optimization is required.

In general, for a multi-objective minimization problem with m objectives and n input parameters we have min $F ( \theta _ { i } ( \Psi _ { j } ) , \varepsilon ) ,$ where $\varTheta _ { i } \equiv \{ \theta _ { 1 } ( \psi _ { 1 } , \psi _ { 2 } , . . . , \psi _ { n } ) , \theta _ { 2 } ( \psi _ { 1 } , \psi _ { 2 } , . . . , \psi _ { \mathrm { n } } ) , . . . , \theta _ { m } ( \psi _ { 1 } , \psi , . . . , \psi _ { n } ) \}$ represents a vector of the m objective values evaluated at Ψ a vector of the n simulation input parameters and ε is a term representing the statistical error in the data. Therefore an optimization algorithm is seeking the optimal solution $\psi ^ { \star }$ that gives the minimum value for $E ( F ( \Theta _ { i } ( \Psi _ { j } ) , \varepsilon ) )$ .

For each evaluated vector of input parameters an estimation of the set of the model's stochastic output measures is made. Correct output analysis of a simulation model is as crucial to good simulation as is thorough model development. Traditional simulation output analysis involves determining a suf<sup>fi</sup>cient level of accuracy within the data through the construction of con<sup>fi</sup>dence intervals, the calculation of probability that estimates are within a relative error amount from an exact measure, or measuring the probability of a value being above or below a desired level [9]. For a given desired level of accuracy the number of replications required to achieve this can be found through sampling estimates of the output mean and variance.

There has been signi<sup>fi</sup>cant research into the optimization of single objective simulation problems [7,11]. The review of Fu [6] shows the four main approaches are those that guarantee asymptotic convergence, approaches which guarantee optimality under the consideration of no sampling variability, those which guarantee optimality within a prespeci<sup>fi</sup>ed probability and approaches that are based around robust heuristics. Theoretical work is based on the <sup>fi</sup>rst three approaches, while variations of the last are used in practice. Fu [6] also states there are four categories of techniques used to obtain optimal solutions in simulation optimization problems. These are statistical methods (response surface methodology, ranking and selection and multiple comparison procedures), metaheuristics (simulated annealing, tabu search and genetic algorithms), stochastic optimization (random search and stochastic approximation) and others that include ordinal optimization and sample path optimization. Simulation optimization techniques can be divided between input parameter types, the models with continuous decision parameters and those with discrete decision parameters. Gradient based methods are used for continuous parameters; these include gradient estimation, stochastic approximation and sample path optimization. Techniques for optimizing models with discrete parameters include statistical selection, random search and metaheuristics.

A good example of how common heuristic approaches can be adapted to different classes of optimization problems is given by Simulated Annealing [10] and the SimMOp framework draws upon concepts and ideas from this technique. A thorough overview of how this search technique has been adapted for various optimization problems is given by Suman and Kumar [19]. As this paper considers multi-objective optimization adaptations from the Simulated Annealing literature will be discussed in order to provide insight into the requirements of a potential optimization strategy. Simulated annealing has been adapted for multi-objective combinatorial optimization through changing the acceptance probability function to consider potential moves in situations when some objective values improve to the detriment of others. The Multiple Objective Simulated Annealing (MOSA) algorithm [20] uses a weighting scheme, varied over multiple runs, to generate an approximation of the set of nondominated solutions. The Pareto Simulated Annealing (PSA) algorithm [5] uses annealing on a set of current solutions to simultaneously determine the non-dominated frontier. Weightings are used in this algorithm to ensure solutions are dispersed along the entire frontier. Constraint handling in these two algorithms, and most other adaptations of simulated annealing, is done through penalty functions. These functions consider violations through modifying the decision space to an unconstrained one and allocate a penalty value to the output, based on the magnitude of violation.

Simulated Annealing has also been adapted to solve stochastic combinatorial problems, which include discreteevent simulation. Simulated Annealing algorithms are combined with statistical measures to decide on potential moves and to justify solution quality. The papers of Alkhamis and Ahmed [2], Ahmed and Alkhamis [1] and Wang and Zhang [21] use con<sup>fi</sup>dence intervals, ranking and selection, and hypothesis testing respectively. Sample estimates of objective value functions are used in these algorithms and the signi<sup>fi</sup>cance tests determine the best solutions. The statistical testing methods used in stochastic optimization are heavily dependent on the number of independent evaluations used. Signi<sup>fi</sup>cant amounts of simulation replications are required to ensure the optimal solutions are found with accurate evaluations. Simulated Annealing is a memoryless heuristic capable of reevaluating solutions, a feature that is exploited in the work of Alrafaei and Andradottir [3] in which they determine convergence to the optimal solution in two ways. The <sup>fi</sup>rst selects the solution visited the most during the search and the second, the parameter combination that has the best estimated average performance measure amongst those visited. Features from all these techniques are incorporated into the optimization framework suggested in this work.

As the consideration of the SimMOp framework is multi objective combinatorial simulation problems, the preferred optimization approach will be to develop a metaheuristic search algorithm in combination with a method to analyse the output. Due to the con<sup>fl</sup>icting nature of the multiple outputs there will not exist a single solution capable of simultaneously optimizing the output. Different approaches are utilized to provide a balance amongst the objectives and a set of nondominated solutions can be provided to a decision-maker known as Pareto optimal [14] solutions. These are the feasible solutions that dominate other solutions by being at least as good with respect to every objective and strictly better with respect to at least one objective. There are two main approaches for obtaining a set of non-dominated solutions, Pareto and scalarization methods. The Pareto front of non-dominated solutions can be obtained in multiple ways including using multiple objective heuristic algorithms. Pareto search algorithms, like PSA, generate an approximation of the Pareto set through maintaining a population of current solutions and determining if the candidate solutions dominate members of the existing set. Although multi-objective optimization heuristics are not common in the simulation optimization literature, a popular area for research is in ranking and selection for models containing multiple performance measures. Ranking and selection (R&S) is used for in problems that contain only a small number of feasible systems (normally less than 30). Variations on R&S include picking the best solution with a certain probability or picking a set of a pre-determined number of the best values for further analysis. For example, Butler et al. [4] compare a set of good solutions to a multiple-objective problem through using multiple attribute theory in combination with multi-objective ranking and selection (MORS) to determine the best con<sup>fi</sup>guration of a system.

The following sections outline the basis for the designed optimization methodology, describe the framework for storing and analysing signi<sup>fi</sup>cant stochastic data and explain the integration of the above optimization features. This is followed by a test problem to demonstrate the effectiveness of the methodology.

## 2. SimMOp rationale

The complexities of solving a stochastic multi-objective problem require the design of a dedicated solution methodology.

There are many issues speci<sup>fi</sup>c to simulation optimization that must be resolved.

1. How do you thoroughly investigate parameter settings while remaining computationally efficient?

• For the search algorithm incorporated within this framework it is impossible to use exact evaluations when comparing alternative outputs, due to the signi<sup>fi</sup>cant computational effort involved in providing solutions with manageable variance.

• It will be possible in many cases to determine which possible system is preferable with comparisons using a smaller number of replications. Through allowing reevaluation of good points as the search continues the desired accuracy level can ultimately be achieved as the number of replications increases.

• The combinatorial optimization problems considered allow for the re-evaluation of potential solutions through the discrete nature of the input parameters.

2. How do you ensure statistical accuracy within the solutions?

• This method requires that alongside the storage of simulation output an indicator of the amount of evaluation replications that have occurred is maintained. This measure will provide con<sup>fi</sup>dence in the accuracy of the data used in decision-making, as statistical testing on results will require this level of re-evaluations as a measure of sample size.

• An important part for a stopping mechanism for a search using this approach is to ensure enough evaluations have taken place to provide suf<sup>fi</sup>cient results before termination. All results obtained require some statistical tests, however, the output data might suggest that further evaluations are required in order to effectively use the statistical analysis.

• The optimization methodology used during the search process will be concerned with the mean of the output, while the variances in the data will be considered during the post-search analysis.

3. What features are required for the multi-objective optimization process?

• During a search two types of parameter selection are required: the selection of different candidates to evaluate and the choice of which of the evaluated systems is preferred as the basis for next iteration. All stored data will not be used during the comparison stage, only the current neighbourhood evaluations. This will aid ef<sup>fi</sup>ciency in the search as the amount of data will become signi<sup>fi</sup>cantly large and using multiple comparisons would be expansively costly.

• Commonly in multi-objective optimization the objectives are combined into a single performance function to quantitatively measure a system's effectiveness, by using techniques like goal programming or distance metric based methods [15]. Scalarization methods use utility functions, decision-maker's preference weights and normalization to combine the incommensurable multiple objective evaluations into a single value. A good approximation to the optimal value for this single expression can then be found using heuristic search techniques and by using multiple functions of this type a set of suitable Pareto solutions can be obtained.

• Attempting to develop the entire Pareto set is not desirable during the search phase of the SimMOp methodology while using inef<sup>fi</sup>cient output. The existing variance in the output due to insuf<sup>fi</sup>cient model replications will cause the incorrect classi<sup>fi</sup>cation of nondominated solutions during each iteration of the search process. Decisions on the non-dominance of output values can only be made con<sup>fi</sup>dently after enough simulation replications have occurred and it is impractical computationally to use this amount of evaluation at each step of the search process.

• Multi-objective techniques that use a set of scaled, weighted performance functions are preferred as they ensure <sup>fi</sup>nding Pareto ef<sup>fi</sup>cient solutions while avoiding unnecessary evaluations of the system that perform poorly. A test showing non-dominance which incorporates the stochastic nature of the output and is used after the search phase of SimMOp concludes.

4. What further features in this process are required for effective optimization?

• The structure for the search process is that from an initial solution an iterative process sequentially generates further candidates from a neighbourhood of potential solutions until the user-de<sup>fi</sup>ned stopping criteria are met. An important feature of a search algorithm used with this approach is that it must favour re-evaluating potentially good solutions to increase the accuracy in the noisy results.

• To aid this the selection process used to construct neighbours of the current solutions should incorporate a feature to allow the inverse of any moves. As the process is designed to increase the replications for the good systems, the solutions picked by the selection function will be immediately re-evaluated before the neighbours are created and evaluated in the next iteration of the search process.

• A further feature of a general search process would be a selection function for the evaluated solutions that allow occasional acceptance of poorer solutions. This will aid the avoidance of selecting a local optimum which could potentially trap the search and will ensure that the global solutions to multi-objective problem are obtainable.

• There are two main types of software used in developing simulation models, packages and languages [17]. Whereas simulation packages often work as a ‘blackbox’ with the logical justi<sup>fi</sup>cation of the model output unknown by the user, through using a simulation language the modeller has full control over all details of the simulation. This is a requirement for the SimMOp methodology to allow the detailed interaction of the framework components.

## 3. Methodology framework

## 3.1. Methodology initialisation

Fig. 1 shows the <sup>fl</sup>ow of information in the SimMOp framework, in the <sup>fi</sup>rst stage a simulation model is constructed that has been subjected to a veri<sup>fi</sup>cation and validation process to check for correctness. The model analysis should be undertaken with the decision-maker and will involve the formulation of weighting schemes to be used on the model output during the search evaluations. The simulation model can be considered as a subroutine in the computer language code of the search algorithm. This algorithm generates the input parameter settings which are used in the model to evaluate the output measures. The simulation output, the mean values and the variances of the model performance measures, are stored in tables of a relational database, which allows the intelligent storage of the model data. To increase search ef<sup>fi</sup>ciency the algorithm will employ insuf<sup>fi</sup>cient evaluations with noisy output estimations and attempt to re-visit the preferred solutions to achieve necessary accuracy. The algorithm will seek to optimize these outputs using multi-objective optimization techniques as described in the previous section.

The initial use for a search algorithm will be an exploratory phase to provide knowledge of the potential numerical values achievable for the model output. The information of the maximum and minimum attainable values for the model performance measures is required for the normalization of the performance value functions. These initial searches will produce results quickly due to the single objective nature of the problems and will be initiated from the corner points of the decision space in order to provide the database with global output information to ensure that diversi<sup>fi</sup>cation exists within the analysis. The optimization of a single function may require multiple search runs, the starting point for each run can be obtained by using the best current solution in the database table. This will lead to an intensi<sup>fi</sup>cation of the search for the region containing the present good solutions. The search runs for the differing performance function evaluations can be initialised by random generation, selection using a database query to determine the best current solution or chosen using a distance function [16].

For an effective set of Pareto solutions it is essential to have a diverse knowledge of the decision space to effectively approximate the entirety of the non-dominated frontier. Appropriate selection of search starting points, along with good use of the exploration phase of the analysis, can aid the diversi<sup>fi</sup>cation of the exploration region. However, the strength of the decision-maker's weighting scheme for the performance functions should ensure the various solutions are in differing, but unknown, regions of the decision space.

## 3.2. Model output analysis using database technology

The optimization process will be aided through storing the actual simulation output data for each speci<sup>fi</sup>c parameter setting allowing other function values to be calculated from these values. Thus the simulation output stored during the optimization of a speci<sup>fi</sup>c function can be investigated for distinct function to determine the best known current value. Complications for an ef<sup>fi</sup>cient search arise due to the large decision space and the complex model output containing local optima. Therefore the algorithm needs the potential to explore the entire decision space, while not requiring evaluations for all systems, while containing the ability to move away from local optimum values to ensure obtaining global solutions. The use of insuf<sup>fi</sup>cient simulation output for the algorithm measurements allows faster evaluations and means the search can quickly move through decision space regions containing unfavourable output values. The effectiveness of the process was aided by allowing the step length for the neighbourhood moves to be decreased during the search run. If the search starts signi<sup>fi</sup>cantly away from desired solutions it can move towards better regions quickly due to greater size of potential moves. As the number of iterations of the search increase and better solutions are evaluated the incremental nature of the moves will then allow intense search within these regions.

A relational database will provide the component for storing and analysing the signi<sup>fi</sup>cant amounts of data that will be created during simulation optimization. The design of tables within a database provides the necessary connections between model inputs and outputs and the Structured Query Language (SQL) allows the viewing and analysis of existing data to determine the accuracy of the simulation output and the values of the various optimization functions. The existence of an Open Database Connectivity (ODBC) module within the simulation model code allows an interface that uses the SQL to access a database. Schulze and Potschka [18] have created these <sup>fi</sup>les, together with the necessary DLL, for the simulation language relevant to this study. The features of the SQL that are relevant to the SimMOp methodology are the abilities to aggregate data with similar identi<sup>fi</sup>ers and to construct function values from all the data. This allows the data of the re-evaluated input parameters to be measured in a single group with an indication of the total number of replications that have occurred. SQL also provides the means to analyse the output data as required in the post-search phase of the SimMOp methodology and present the solutions.

## 3.2.1. Database analysis for combinatorial problems

Combinatorial optimization problems contain constraints together with the objective functions. Constraints on the decision parameters are handled through not allowing the search to evaluate infeasible combinations of input for the simulation model to avoid unnecessary computer evaluations. The search process, for reasons comparable to that of comparing dominance of solutions, cannot consider constraints on the performance measures during the search process. Deterministic search algorithms can penalise candidate solutions for constraint violation while considering potential moves, however, the sampling errors within stochastic output used during the search in this methodology prohibit this from occurring in the selection function. The effects of any constraints on the model output can only be examined when suf<sup>fi</sup>cient replications of the model have been made to have con<sup>fi</sup>dence in the output values. Thus the task of the search algorithm is to create a database that contains suf<sup>fi</sup>cient output, to be examined during the postsearch analysis phase, to obtain the suitable solutions for the multi-objective optimization problem.

## 4. Search process

## 4.1. Sort and Pick algorithm

Although the methodology presented is designed to be adaptable to any multi-objective simulation model with discrete parameters the following discussion relates in part to an (s,S) inventory model, to be described in the following section. Each evaluation of the model during the search consists of 1000 replications of the simulation. The number of replications used for each evaluation was determined during the initial model investigation phase and was decided as a

balance between the amounts required to counter some of the stochastic effects on the data and to avoid unnecessary computational time overly evaluating each system. For this model the performance measures are formulated into four objectives which are then combined into a single function value, to be optimized. This function is normalised through knowledge of the ideal and anti-ideal values for all of the output measures. These values, which provide the range for scalarization, are easily obtainable using single objective optimization on each of the model performance measures. By including decision-maker's preference weights to the summation of the objectives different functions can be incorporated into multiple search runs. The optimal values of these functions will be useful for the user in determining the preferred input system for the simulation model. The Sort and Pick algorithm, detailed in the <sup>fl</sup>ow chart in Fig. 2, is a neighbourhood search that has been developed jointly with the SimMOp framework to test effectiveness of the methodology. From an initial solution, in subsequent iterations known as the current solution, three candidate solutions are obtained and evaluated. The parameters in this model are three pairs, therefore each possible candidate represents a change in one of the parameters in each of the pairs. The selection of which of the two parameters to change and of whether the moves are an increase or a decrease is determined by using uniform random number generators.

The <sup>fi</sup>rst candidate solution, for example, represents a selection, via a random number with equal likelihood, of one of the <sup>fi</sup>rst parameter pairing. A second random number is used to determine the nature of the move, whether to add or subtract the current move step length. This step length is lowered through the search run dependent on the iteration number to allow greater intensi<sup>fi</sup>cation of the search regions as the process progresses.

Prior to any simulation model evaluations a check is made on the feasibility of the parameter values. If a parameter value changes to a value beyond one of its limits it is set as the maximum/minimum allowable value. The output from the current parameter evaluation and the three feasible neighbourhood selections are placed into an array. The elements within the array are then sorted using a sorting algorithm, therefore it is essential that the constraints ensure a simulation run occurs to avoid an empty element existing in the output array. A new current solution is then picked from the array to be the base for the subsequent search iteration. The Sort and Pick algorithm uses the simulation model output for the sorting while the model input parameters are picked to generate future candidate solutions.

Fig. 2. Flowchart of the Sort and Pick search.

For the search process used here the array element with the most preferred output, the lowest mean value, was always picked. It is possible to use a selection function that will give a probability of picking the non-best simulation output, as in selection within Simulated Annealing, as an aid to avoid becoming trapped at a suboptimal solution. Due to the level of stochasticity within the simulation evaluations, however, this enhancement to the search algorithm is deemed unnecessary as the error contained in the output will mean occasional selection of inferior solutions. The parameter combination that is selected as the current solution will be re-evaluated within the subsequent search iteration, this feature helps to ensure that suf<sup>fi</sup>cient simulation replications can take place within a more ef<sup>fi</sup>cient time frame. The sort and pick algorithm as described above if allowed just a single run with a <sup>fi</sup>nite number of iterations is unlikely to solve a large complex simulation optimization problem. By using multiple intelligently designed search runs, however, the optimization process is achievable.

## 4.1.1. Search run length and stopping mechanism

A feature in the design of any search algorithm is a method for terminating the search at a suitable solution. Stopping mechanisms designed to continue until further improvements in the solution are not achieved are undesirable in the SimMOp framework due to the stochastic nature of simulation output. The mechanism used in the Sort and Pick search runs was a <sup>fi</sup>xed number of iterations with an initial search of two runs, each of 250 iterations, used to begin the optimization process. This number of iterations allows the search to reach a region containing good solutions, without fully exploring the region. This initial search is run twice to ensure that the correct region was discovered, with the starting points for these searches chosen from the numerical corner points of the parameter space. The database is then queried through grouping by input parameters, averaging the mean values of the model output for each group and sorting the resulting table in terms of an expression equivalent to that used as the optimization function during the search run. This process indicated a clearly de<sup>fi</sup>ned region in decision space containing the good solutions. Each of the model parameters within the best database values where found to acquire only a few adjoining values. The size of the search space, when only considering these new values, is signi<sup>fi</sup>cantly reduced, and the search code can be easily adapted to allow changes to the region of feasible input parameters for subsequent search runs.

## 4.2. Using model constraints to improve search process

The search code is constructed to verify the values of the parameters to avoid unnecessary model evaluations during a search. These constraint values can be re-designed as variables and not given the <sup>fi</sup>xed numeric values from the model description. These variable values can be changed after each search run to represent the new restricted region containing the good solutions. With a signi<sup>fi</sup>cant reduction in parameter space the subsequent search runs can be shortened, with the iteration number being lowered to 150 per run in this case. The search process, as in the initial search run, employed two separate runs within each new region of parameter space. The paired search runs and the selection of differing starting points is formulated to provide greater coverage of the feasible region during a search run to increase the likelihood of evaluating the optimal parameter setting. The process of searching within decreasing feasible regions can continue, while it is still successful, until suf<sup>fi</sup>cient output replications have been made. As the search continues a narrow range of parameter settings can be intensely explored leading to the re-evaluation of these preferred systems and the desired increase of replications.

Occasionally a point will be investigated during a search that appears to have a good solution but will contain parameter values from outside the desired region observed in the database. The existence of this potentially good solution prevents the reduction of the parameter region to be explored in the subsequent search runs. A single solution point removal is possible through further replications of this model setting to remove any stochastic effects that have created an arti<sup>fi</sup>cially good solution. The process of individual point removal is possible with only minor changes to the search algorithm code, using the desired values for the parameters for this point as both the maximum and minimum values for the constraint variables will ensure the search can only evaluate this point. This process of using the model constraints to force the search to only evaluate a single parameter setting is also useful at the culmination of the search process. After multiple search runs have reduced the size of the parameter space, it is possible that some of the output within the <sup>fi</sup>nal table has insuf<sup>fi</sup>cient simulation replications for the desired level of statistical accuracy. The con<sup>fi</sup>dence within this output can be reinforced through adding the necessary amount of model replications through using the point by point evaluation method described above.

Clearly if the extra evaluations fail to remove a parameter setting the parameter region reduction cannot occur and the system should be considered as a potential solution. In situations where the input parameters converge to the boundary of an arti<sup>fi</sup>cial region this could indicate that the reduction made was possibly incorrect and should be further investigated by the analyst.

## 5. Test example

## 5.1. Model description

In order to examine the pro<sup>fi</sup>ciency of the various aspects of the SimMOp methodology a test simulation model was required. In the initial phase of testing the simulation model language and the database connectivity effectiveness a model with known results was desired. An inventory model example was taken from the text of Law and Kelton and adapted to the SLX simulation language (Wolverine Software [8]). SLX allows the user to control behaviour of many system elements through a C-like framework while providing the adaptability to construct a search algorithm along side the model code and provide the mechanism for coupling with the database software through a Windows Dynamic Link Library (DLL). The results given in the original text were replicated, within the con<sup>fi</sup>nes of model stochasticity, to verify that the model, the database storage system and initial search strategies were effective. The described methodology is designed to solve multi-objective simulation problems therefore the effectiveness in the optimization process in a single objective problem is extraneous. The initial model used as software veri<sup>fi</sup>cation had the potential to be adapted to become a more effective problem. The original model contained only a single output, or objective when considered in an optimization problem, which consisted of three individually calculated costs; ordering, holding and shortage. This third cost is incurred when the inventory level is negative and demand is unable to be met. The shortage cost placed on each backlogged item until the order was ful<sup>fi</sup>lled consists of a cost for maintaining records of demand to be met through next inventory order and also a loss of goodwill charge, considered as a cost of lower future demand. The loss of goodwill charge was removed as it was deemed too subjective compared to other clearly de<sup>fi</sup>ned costs, and was replaced with a measure of time spent with a negative inventory. The amount of time spent on average per month was therefore introduced as a secondary objective alongside a total cost objective. The length of each individual simulation evaluation, taken from the original problem, is the <sup>fi</sup>rst 120 months of operation for the inventory system.

An assumption for the model, taken from the original problem, is that the initial inventory level for each product is 60 items. A reasonable initial inventory level is bene<sup>fi</sup>cial to avoid a warm-up period for simulation data collection. All the relevant data, the per item holding costs, ordering costs, shortage cost and statistical distributions are designed in the multi-objective model to ensure an interesting problem with a high level of con<sup>fl</sup>iction within the objectives.

The extra items held within the inventory model offered the possibility to construct further problem objectives. It was assumed that the delivery of orders would be limited to a <sup>fi</sup>xed maximum size due to the potential nature of the delivery method. The cost objective is designed to include an incremental cost per item ordered only and not consider a set up cost for each order. A <sup>fi</sup>xed cost would exist for each order placed and it was determined that rather than including a numerical value a measure of the utilization of orders would be incorporated. The maximum order size was set at 100 items and a measure of how much of the order was used was included to ensure that the cost to the system would be used effectively. In situations when the required number of order is greater than the maximum allowed then each amount ordered per item is scaled based on the items percentage of the total order. As determining the amount to order from the inventory policy and then reducing the order size is inef<sup>fi</sup>cient a <sup>fi</sup>nal objective was introduced to minimize the total amount of unsatis<sup>fi</sup>ed orders. The model was investigated during the initialisation phase to determine the number of simulation replications to suf<sup>fi</sup>ciently analyse the output data, for the described model this number was 50,000 replications.

The new model consists of six input parameters, with each of the three items having a pair of parameters as described above, therefore the vector of input parameters for a system in the model is $\Psi ( s _ { 1 } , S _ { 1 } , s _ { 2 } , S _ { 2 } , s _ { 3 } , S _ { 3 } ) .$ . The 10 model outputs together with the lower and upper values obtained for them that are required for the normalization within the optimization functions are given in Table 1. These simulation model outputs are formulated into four objectives in the manner described in Table 2. Objectives 1, 2 and 4 are minimization problems whereas objective 4 is to be maximized. Therefore the multi-objective simulation problem given by the model can be given as min $F ( \left( \theta _ { 1 } , \ \theta _ { 2 } , \ \theta _ { 3 } , \ \theta _ { 4 } \right) , \ \varepsilon )$ and the search algorithm determines the solution Γ(Ψ(s<sup>⁎j</sup>, S<sup>⁎j</sup>)). This is a set of the j input vectors that represent the system inputs that generate the appropriate solutions to the decision-maker's j weighted performance functions.

## 5.2. Search results and analysis

This simulation model was optimized within the SimMOp framework using the Sort and Pick algorithm incorporating <sup>fi</sup>ve different weighting schemes within the performance function. The <sup>fi</sup>rst scheme gave equal weighting to all four objectives, the second gave a minor preference towards the cost objective, the third a signi<sup>fi</sup>cant preference to the time with backorders objective, the fourth weighting scheme favoured objectives three and four, the linked ordering objectives, and the <sup>fi</sup>nal weights were in preference of the utilization objective. These weighting schemes together with the best three obtained solutions for each are given in Table 3. The table contains the mean values of the objective values from the repeated system evaluations together with the variance in these values. In four of the cases a region of good solutions was found, investigated thoroughly and suitable information was made available for an analyst. For the cost objective weighting scheme it was quickly apparent that the solution would be on the low boundary of decision space and the search was terminated with minimal computational time required. From the result in Table 3 it can be seen that a single preferred system selection was not achievable for each weighting scheme as values for the mean objective function are similar for more than one system. The solutions to this problem also contain comparable levels of error within the average output, where differing levels of variance could be used to aid decisions in situations where mean values are equal. However, this could be caused by the non-existence of a single preferred solution and does not prevent an analyst from knowing the best output values and a range of input system that can produce them.

Justi<sup>fi</sup>cation of the results is required from both a multiobjective and a stochastic perspective. A performance index was introduced by Lee et al. [13] as an aid to a multi-objective ranking and selection amongst a small set of good solutions for a multiobjective simulation model. The index is used to determine the ranking of the solutions in terms of the probability of being nondominated. The process can be used to demonstrate the ef<sup>fi</sup>ciency of solutions obtained using SimMOp and incorporates the stochastical nature of the model output which is not included in the search selection process. The index calculates cumulative probability of the simulation model output performance measures, assumed to be independent and continuous, being dominated. A performance index value close to 0 represents a strong likelihood of an ef<sup>fi</sup>cient solution whereas dominated solutions have a value nearer 1. As used by Lee et al. [13] the original methodology selected the best k scores from a small feasible region to solve problems with knowledge there exists k non-dominated solutions, irrespective of the performance index scores. In essence the comprehensive search used in this methodology obtains a small set of solutions that have a high likelihood of being non-dominated, and the index is applied to verify their ef<sup>fi</sup>ciency. The desired performance index value was found to be very close to 0 for each of the <sup>fi</sup>ve preferred solutions with a guaranteed probability. From the results inTable 3 the nondominance of the objective values for the different weighting schemes can be seen to support this result. To demonstrate the effectiveness of this method results could also be taken from the database to show the existence of dominated solutions. The performance index measure showed that the output for the selected model parameter combinations belong to the set of ef<sup>fi</sup>cient non-dominated solutions and thus represent multiobjective solutions to the complex stochastic simulation optimization problem.

The con<sup>fi</sup>dence within the results found, and in the process of decision parameter space reduction, is provided by the initial model investigation phase, the determination of ideal and antiideal values and the spread of search starting points which ensure good coverage of the entire feasible parameter region. By ensuring all output data is maintained during each phase of the simulation optimization methodology the analyst can gain greater con<sup>fi</sup>dence in the ultimate results. These results obtained clearly demonstrate the ability for the search process to obtain good solutions from differing regions of the decision space and aid a multi-objective decision-maker, as required.

## 6. Conclusions

The SimMOp optimization framework has been designed to solve complex simulation models with multiple objectives. The method demonstrated uses a search heuristic in combination with database technologies and the SQL to ef<sup>fi</sup>ciently and effectively handle the signi<sup>fi</sup>cant amount of data needed in this environment. The search phase of the methodology must ensure suf<sup>fi</sup>cient evaluations of the simulation model in regions containing the global solutions. Through selection of starting points for multiple search runs and information gained through querying the database the important intensi<sup>fi</sup>cation and diversi<sup>fi</sup>cation of the search can be achieved. The post-analysis stage of this method examines the database to retrieve the desired feasible non-dominated solutions. Through adapting the constraints that occur naturally in a model with information obtained by <sup>fi</sup>xed length search runs good solutions can be found in reasonable computational time with no prior knowledge of the expected output required. The variances for each model output are stored from each independent batch of model replications and are incorporated in the decision-making from the <sup>fi</sup>nal table of output in statistical testing to demonstrate the nondominance of the solutions. The post-search phase of the methodology provides con<sup>fi</sup>dence to the decision-maker as to the quality of the multi-objective solutions.

Areas for further research using the SimMOp framework include the design of a suitable example, with known results, in order to test the rates of convergence for the search algorithm. Also research incorporating different optimization approaches into the search phase would prove bene<sup>fi</sup>cial. For example the ability to view the database at the end of each search run would allow the use of an interactive approach in which preference weights can be varied according to decision-maker's requirements.
