# Documenting Information Systems for Management: A Key to Maintaining User Satisfaction

William J. Doll and Mesbah U. Ahmed
The University of Toledo, College of Bussiness Administration,
Department of Management, 2801 W. Bancroft Street, Toledo,
OH 43606, USA; tel.: (419) 537–2850

Executives responsible for the information system function need to be concerned about developing a base of satisfied users and maintaining continuing user satisfaction after implementation. This article focuses on user satisfaction among on-going user managers, explores the role of good user documentation, and examines the results of a survey of 144 user managers from 55 firms. The results indicate that good user documentation appears to be an important factor in insuring user understanding and continuing user satisfaction. Thus firms considering alternative ways of keeping users satisfied (i.e., personal computer applications, end user computing, or information centers) might well examine their user documentation practices before exploring other alternatives.

Keywords: Documentation, User Satisfaction, User Documentation.

## 1. Introduction

Data processing managers and systems analysts realise the importance of the user during information systems development. Among the user related concepts being advocated are “user friendly” software $[14,15]$ , managing user expectations $[6]$ , user developed applications $[13,17]$ , end user computing $[3,12,18]$ , information centers $[2,8,10,16,21]$ and application development without programmers $[9]$ . This increasing interest in user related concepts is motivated, in part, by widespread user dissatisfaction with applications developed by conventional methodology $[9]$ .

With the widespread use of personal computers and information centers, the 1980's may be remembered as the decade of the user. Keeping them satisfied may be essential to reducing overall data processing costs by avoiding the development of inappropriate personal computer applications [11,19]. Although much of the MIS literature focuses on how to implement projects successfully, information system managers also need to be concerned about maintaining user satisfaction after implementation.

User documentation is a written explanation of what application software does and how to use it. Schaeffer [20] suggests that user documentation is important for generating a satisfying user image of the systems department, making work more efficient and pleasing, reducing costs and confusion, eliminating confusion and frustration, and improving management control and employee morale. However, despite the growing interest in user related concepts, little is known about the role of user documentation in maintaining user satisfaction.

## 2. The Role of User Documentation

Good user documentation goes beyond explaining “how to use” the system. It is written to improve user understanding of the system and is an educational as well as a training tool. The development of effective management information systems requires that managers understand “how their system works” as well as “how to use it” [1]. Grimm [7] suggests that even the best system developed would be worthless unless users understand it. He maintains that users can understand a system only through complete, well-written user documentation.

In the systems design process, many firms only develop a difficult-to-understand technically oriented design which emphasizes physical rather than logical aspects. This is a programming rather than a user oriented documentation approach. Other firms use an expensive “dual documentation” method – writing one set of technical documentation and another that is user oriented. Despite its important role in improving user understanding, user documentation has remained a unpopular topic.

User documentation has been described as data processing's weakest link. It is often put-off until the last minute, written hastily by non-professional writers, and considered a nicety rather than a necessity. The lack of good user documentation is often a bone of contention between users and systems personnel. The issues of who should write the documentation, when it should be written, and how much documentation should be provided can be controversial.

Among academics, user documentation has been neglected. Although good user documentation has been considered an important component of “user friendliness" [14,15] and has been associated with MIS development success [5], most literature has focused diffusely on user participation/involvement and the problem of achieving successful system implementation. The amazing success of well documented micro software packages such as VISICALC has gone largely unnoticed by researchers or been attributed to the desire of users for the "independence" afforded by micros.

## 3. Assessing User Documentation Practices

To assess current user documentation practices and to examine the impact of user documentation on user satisfaction, one hundred forty four (144) user managers from fifty five (55) Ohio firms were surveyed. The sample included firms from a variety of industries and firm size categories (see Table 1). User managers were then selected by asking the D.P. director of the firm to identify the departments which were their major users. The user managers were asked what functional or application areas they were responsible for, whether they had good user documentation for the systems they were using and how satisfied they were with these systems.

The D.P. managers were also asked about the size of their film, their D.P. staff, their D.P. budget, and whether they had good user documentation of existing systems. To measure the D.P. manager's perception of whether good user documentation was available, a five point scale (Almost always, Most of the time, About half of the time, Sometimes, Almost never) was used. In general, the user manager's perception of whether they had good user documentation corresponded quite well with the D.P. manager's assessment (see Appendix A).

The user managers were given a list of functional or application areas and asked to indicate their area(s) of responsibility (see Table 2). Accounting (64 managers - 44%) and financial applications (52 managers - 36%) were the most common areas of responsibility. Many of the 144 respondents had two or more areas of responsibility. Thirty seven respondents indicated that they were responsible for both financial and accounting applications. Twenty respondents were responsible for both manufacturing and accounting applications and nineteen respondents were responsible for both manufacturing and marketing applications (e.g., order processing and sales reporting).

The data (see Table 1) indicates that good user documentation is often lacking. Only 54.9% of the user managers felt that they had good user documentation. The percentage of user managers reporting good user documentation was highest in health care (76.9%), low in finance, banking & insurance (43.8%) and lowest in educational institutions (28.6%).

Good user documentation was apparently less available in larger firms. The percentage of user managers reporting that they had good user documentation decreased consistently as firm size increased. Although firms with larger D.P. staffs and more substantial D.P. budgets might be expected to do a better job providing user documentation, the data indicated otherwise (see Appendix B). Finally, Table 2 indicates that some functional or application areas are, perhaps, more likely to have good user documentation.

## 4. Impact of User Documentation on User Satisfaction

To assess the impact of documentation on their satisfaction, user managers were asked eleven questions about the systems they were using. These questions are shown in Table 3. The user managers responded using the same five point scale, which was reversed on some questions so that a higher score always represents a more favorable response. The eleven question user satisfaction scale had a reliability (Chronbach's alpha) of 0.90.

The data suggests that good user documentation may have a dramatic and continuing impact on user satisfaction. Table 3 contrasts the responses of user managers who felt that they had good user documentation with those who lacked it. The eleven questions showed that user managers with good documentation reported significantly (p < 0.001) higher levels of satisfaction.

User managers with well documented systems found them easier to use, reported greater trust in their information, felt that the systems met their needs, and considered them to be more enjoyable to use. Managers with good user documentation also considered the system less troublesome and less difficult to operate. With good user documentation, the user managers were less likely to want the systems modified or redesigned and were satisfied because they received up-to-date reports from the systems when they wanted them. However, good user documentation appeared to have little impact on perception of the accuracy or need to correct the information of these systems.

Schaeffer's contention that user documentation can be an important tool for making the user's work more enjoyable and less frustrating is supported by these results. This suggests that user documentation can play an important role in generating a favorable user image of the systems department. Finally, to serve as a basis for decision making, manager must “trust” the information they receive. Good user documentation which is written to improve user understanding of the system may enhance trust and improve management’s understanding of just how the information provided by the system helps to meet their information needs.

## 5. Summary and Conclusions

These survey results suggest that user documentation may play an important role in both improving user understanding and maintaining user satisfaction with operational applications. Almost half of the user managers surveyed felt that they did not have good user documentation of their systems. Quite apart from the serious management control issues inherent in this lack of user documentation, user departments pay a cost in terms of confusion, frustration, lower efficiency, and lower employee morale.

In a micro computer environment, users have alternatives which never previously existed. Keeping users satisfied may be essential in avoiding excess data processing costs by developing only appropriate applications. Although good user documentation is expensive, supporting information centers or end user computing can also be costly [11]. For some applications, firms may find user documentation a less expensive and more satisfactory alternative [4].

To avoid a costly “dual documentation” approach, it may be desirable to develop the detailed design as “user documentation” rather than programmer documentation (i.e. documenting the system only once and from the perspective of the user). Developing user documentation early as part of the systems development process rather than as an afterthought should help insure that DP “programs what it specified” rather than “specifies what it programmed”. Most structured approaches to systems design take this approach without explicitly dealing with “user documentation”.

Finally, the user documentation problem is more severe in large organizations. Willingness appears to be the critical factor. The systems department needs to develop a “user orientation”, adopt a broader view of their job, and consider the job unfinished if users do not have a well written document which explains “how the system works” as well as “how to use it.”
