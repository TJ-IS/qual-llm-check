# The Quality of User Documentation

William J. Doll and Gholamreza Torkzadeh

The University of Toledo College of Business Administration, Dept. of Information Systems and Operations Management, The University of Toledo, 2801 W. Bancroft Street, Toledo, OH 43606, USA

Encouraging quality user documentation is an important area for top management involvement in MIS development. User documentation enhances the value of an application to the user and improves user satisfaction. Yet, no practical managerial tools for measuring the quality of user documentation exist. This paper develops two instruments for measuring user perceptions of the quality of their documentation. The reliability and validity of these instruments are examined. Where the goal is to identify specific strengths and weaknesses of existing user documentation, a more comprehensive fifteen item instrument is recommended. Where only a summary evaluation is desired, a short 3 item alternative form proves sufficient. With these instruments, management can more easily monitor and control the condition of their firm's user documentation.

Keywords: Documentation, user documentation, user satisfaction, management, top management involvement

The author of many articles in academic and professional journals including the Academy of Management Journal, the MIS Quarterly, Information & Management and the Journal of Systems Management, Dr. Doll has a doctoral degree in business Administration from Kent State University and has worked as a senior analyst on the corporate staff of management systems analyst on the corporate staff of Burroughs Corporation.

## 1. Introduction

Organizations have made substantial investments in computerized business systems that are used by many people over a long period of time; however, they have generally failed to provide adequate documentation. Good user documentation facilitates communication between users and analysts, enhancing the value of these applications for the user [9]. Yet, only half of the operational applications have good user documentation [4]. Despite its importance in improving user understanding, user documentation remains an unpopular topic among the analyst/programmer community. Without senior level management involvement, the situation is not likely to improve.

Encouraging quality user documentation has been identified as one of the most important avenues for top management involvement in MIS development [3]. The firms who are more successful in their MIS development efforts have project development policies which encourage well written and easy to understand user documentation; however, managerial tools for systematically measuring the quality of user documentation do not exist.

User documentation is desirable because effective MIS/DSS systems require that users understand how their application works as well as “how to use it” [1]. In the systems design process, many firms develop difficult-to-understand technically oriented designs which emphasize physical rather than logical design aspects. This programming rather than user oriented documentation approach does little to encourage meaningful user involvement in systems design.

![](/api/attachments/33DMT9N8/fulltext/images/18b09019c5e205e437399418c6ea99549594b85d217119c86baa2c9057f55d9f.jpg)

User documentation consists of written or visual explanations (e.g., manuals, procedures, films, tutorials, online help instructions, operating instructions, etc.) concerning what the application software does, how it works, and how to use it. Such documentation is written to improve user understanding of the system. It is an educational as well as a training tool.

Although good user documentation has been considered an important component of “user friendliness” [10,11], the academic literature has neglected this topic. In exploratory studies, user documentation has been associated with MIS development success [3] and user satisfaction [4]. Also, Furest and Martin [5] have suggested that “self-documentation” plays an important role in improving user understanding of decision support applications. The professional literature has frequently cited its importance [6,12–14].

A tool for measuring the quality of user documentation would permit more rigorous academic research on user documentation's impact on user satisfaction and MIS development success. Also, top management and MIS directors need a managerial tool for assessing and controlling the condition of their user documentation. This paper defines user documentation and presents an instrument for assessing its quality. Using a sample of eighty one (81) users, the reliability and validity of this instrument is assessed. Finally, recommendations for using this instrument are discussed.

## 2. Research Methods

User documentation (as defined above) was conceptualized as having one inherent attribute (i.e., how well it is written) and three functions (i.e., helping the user understand what the software does, how it works and how to use it). The researchers did not consider “use” as a measure of the quality of user documentation. Many factors other than the quality of documentation may affect its use (e.g., the complexity of the application, the familiarity of the user with the application, etc.). The researchers generated 37 items to measure user perceptions of how well their documentation is written and how well it performs these three functions.

An instrument which included these 37 items as well as a 20 item scale measuring user satisfaction was developed. The user documentation questions used a five point scale: strongly disagree = 1; disagree = 2; neutral = 3; agree = 4; strongly agree = 5. To assess the reliability and validity of the user documentation scale by the nature and type of application, users were asked whether their application was a micro or mainframe application, whether it was an end user developed application, and whether it was a monitor, exception reporting, inquiry or analysis application [2]. This instrument was pilot tested using in-depth personal interviews with three managers and revised.

Next, a structured interview questionnaire was developed asking users how satisfied they were with the user documentation available, how it could be improved, and how important good user documentation was to them. Further, this structured interview questionnaire instructed the interviewers to examine a copy of the user documentation and record their perception of its quality.

Data were gathered by research assistants who first interviewed users and then administered the questionnaire. A sample of 96 users were interviewed from a manufacturing firm, two hospitals, a city government office, and a university. Fifteen users who did not have any user documentation were excluded from the sample. Approximately an equal number of usable responses were obtained from each organization.

To assess whether the 37 item instrument was capturing the phenomena we were interested in, the structured interview responses were compared with the responses to the 37 questions. In general, users expressed the feeling that good user documentation was important. Furthermore, their level of satisfaction with this documentation and the specific areas needing improvement corresponded quite well with their responses to the 37 items.

To shorten the questionnaire, screening criteria were used to select items based on their reliability and criterion related validity [7]. First, items were excluded if their corrected item total correlation (each item's correlation with a scale composed of the other thirty six) was below 0.5 and exclusion would not significantly reduce Cronbach's Alpha (a measure of reliability or internal consistency). Secondly, items were also excluded if their correlation with a criterion question ("Overall, how would you rate the quality of the user documentation available for this application.") was below 0.5. The criterion question used a five point scale: $1 = \text{non-existent}$ ; $2 = \text{poor}$ ; $3 = \text{fair}$ ; $4 = \text{good}$ ; $5 = \text{excellent}$ . Finally, the validity of the resultant shortened scale was assessed in construct validity terms by examining whether it had the expected theoretical relationship with user satisfaction.

## 3. Results

The screening criteria described above enabled the researchers to reduce the 37 items to fifteen, a shorter yet highly reliable and valid instrument. Table 1 describes these fifteen items, their correlation with the criterion question and the corrected item total correlation (based on the 15 items). Summary statistics on each item are provided in the appendix. The 15 item scale had a reliability of 0.95 (using Cronbach's Alpha) and a criterion related validity of 0.86. The individual items show considerable internal consistency with the corrected item total correlations ranging from 0.56 to 0.85. The correlation between the individual items and the criterion ranged from 0.50 to 0.78.

To determine whether this user documentation scale had the expected theoretical relationship with user satisfaction (i.e., construct validity), the researchers examined the correlation between the 15 item user documentation scale and user satisfaction. User satisfaction was measured using a 20 item scale which had a reliability of 0.96 and a criterion related validity of 0.83 (p < 0.000). As expected by theory, the 15 item user documentation scale had a correlation of 0.44 (significant at p < 0.000) with user satisfaction.

Where the goal is to identify the strengths and weaknesses of existing user documentation, the 15 item instrument provides a more comprehensive tool. This scale can also be used to compare the quality of an application's user documentation with quartile scores. Further data is needed to develop a more accurate set of scores. However, based upon these 81 applications, tentative quartile scores are 45 (lowest quartile), 54 (median) and 60 (upper quartile).

Where only a summary evaluation of the quality of user documentation is desired, a shorter three item alternative form can be used – questions 1, 3 and 6. These items have the highest correlation with both the criterion and the corrected item total. Moreover, they appear to capture the essence of good user documentation – complete, well written, and describing step-by-step how to use the software. This three item alternative form has only slightly lower reliability (alpha = 0.90) and criterion related validity (0.83) than the 15 item form. This alternative form has a correlation of 0.95 (p < 0.000) with the 15 item questionnaire.

Table 2 describes the reliability and criterion related validity of the 3 and 15 item scales by nature and type of application. Both scales appear to have more than acceptable reliability and validity for micro as well as mainframe applications; for monitor, inquiry or analysis applications; and for end user developed applications as well as those developed by more traditional methodology. In most cases, the reliability and validity are slightly higher for the 15 item scale.

Reliability for both the 3 and 15 item scales are consistently above the 0.80 minimum standard for basic research. Furthermore, the 15 item scale's reliability is consistently above the 0.9 standard suggested for use in applied settings where important decisions will be made with respect to specific test scores [8].

## 4. Discussion and Conclusions

Many firms have made substantial investments in computerized information systems. These applications are used by many people over a long period of time. User documentation plays an important role in maintaining user satisfaction, improving user understanding, and enhancing communication between users and analysts during the systems development process. The effective use of MIS/DSS in organizations requires that users understand how their application works as well as "how to use it". Quality user documentation protects the investment in information technology by enhancing the value of an application to the user.

Despite its important role in improving user understanding, user documentation has remained an unpopular topic. User documentation is data processing's weakest link. It is often put-off until the last minute, written hastily by non-professional writers, and considered a nicety rather than a necessity. The lack of good user documentation is often a bone of contention between users and systems personnel. Without guidance from senior level management, this situation is not likely to improve.

Encouraging quality user documentation is an important avenue for top management involvement. The more successful firms have better user documentation of existing systems. As new projects are implemented, the MIS directors of these more successful firms require user documentation which is well written and understandable to the user. Ideally, user documentation efforts should begin early in the system life cycle to encourage user management understanding, involvement, and control of logical designs decisions.

To examine the condition of their firm's user documentation, top management as well as MIS directors need a tool for assessing the quality of user documentation. This paper reports the development of such a tool. Conceptual and operational definitions of user documentation have been provided. User documentation is conceptualized as having one inherent attribute (i.e., how well it is written) and three functions (i.e., helping the user understand what the software does, how it works, and how to use it). A fifteen item scale and a shorter three item scale for measuring the quality of user documentation have been described. The results suggest that both these scales have adequate reliability and validity and might be used with confidence across a variety of applications.

For the first time, validated and easy to use instruments for assessing the quality of user documentation are available. With these instruments, it becomes practical to monitor and control the condition of a firm's user documentation. One application's or vendor's documentation can be systematically compared with another's. Where poorly documented applications are identified, the more comprehensive 15 item scale may suggest where improvements can be made. Such efforts may improve the quality of user documentation and protect a firm's investment in information technology by enhancing the value of the application for the user.

These instruments should also encourage more rigorous academic research on user documentation, its value for facilitating user involvement in design, and its impact on user satisfaction and MIS development success. Future research efforts should focus on developing a larger sample to develop more accurate quartile scores (standards) for evaluating the quality of user documentation and addressing the research issues identified above. Also, further research is needed to determine whether user documentation has the same impact on user satisfaction across different types of applications.
