# End User--IS Design Professional Interaction - Information Exchange for Firm Profit or End User Satisfaction? \*

James R. Marsden

University of Kentucky and University of Arizona, USA

David E. Pingry

University of Arizona, USA

In the present paper we argue that the interaction between the end user and IS design professional directly impacts the firm's profitability. A goal-driven (profit maximization) IS design strategy is set out and its implications for the end user-IS design professional interaction are detailed. It is shown that a structured information exchange between the two is necessary if the required searches are to be completed and profit maximization achieved.

Keywords: End user, Profit maximization, Process models, End user satisfaction, Information system economics, Information system design, Optimization, Goal driven design.

## 1. Introduction

The information exchange between company management and information system (IS) development professionals is a critical element in obtaining the maximum benefit from IS expenditures. Much of the past focus in IS design has emphasized end user satisfaction. It is our contention that this emphasis, while perhaps sounding appropriate, has nevertheless had a most deleterious effect on the quality of IS design strategy development.

A key element here is the view that one of the firm's objectives - profit maximization - should serve as the guide post for its operations. If this optimum is to be attained, the individual components within the firm structure must interact in optimal ways. This holds for all components, including is planners and end users. We argue for a systems approach that integrates rather than separates the activities of the elements within the system.

## 2. End User Satisfaction and Profit Maximization

If the IS design professional succeeds, the key end user, the firm, will be “satisfied”. But this satisfaction should come about because the firm’s objectives are served by the chosen IS design. It is our position that IS’s should be treated as any other input to the firm’s production process. The decision on the IS design and implementation should be made in the same way as every other firm investment decision, i.e. based on its contribution to the success of the firm.

The usual situation reported in the literature presents the end user as a middle level manager or line employee of the firm. In this interpretation, there are three reasons why the interaction between the end user and the is designer may not be consistent with the firm's profit maximization (PMAX) goal:

1. poor communication and imperfect information exchange due to a bad design strategy;

2. objectives of people that differ from those of the firm;

3. lack of knowledge or ability on the part of individuals.

Nothing short of better skill development can address and solve the last problem. The second is actually a special case of the more general principle-agent problem. The impact of this problem on the IS design is discussed in Ciborra [7] and in Isaac and Pingry [13]. The first of the problems is the focus of this paper. We assume that the agents (IS users) are willing and able to provide the necessary information, but are not called upon to do so, because of the IS design strategy being utilized.

Employing an is design strategy that focuses on end user satisfaction tends to obfuscate the firm's objectives in favor of emphasizing feasible or tolerable solutions. A system design life cycle (SDLC) emphasizing end user satisfaction can be represented as some version of the following steps:

1. Determine what end product (tasks to be completed) is required.

2. Use systems analysis and design (SAD) tools to describe the product.

3. Check the description for completeness, consistency, and non-redundancy.

4. Check logical description with the end user. If user needs are met (i.e. the user is satisfied), go on; if they are not met (i.e. the user is dissatisfied), go back to 1.

5. Determine one or more alternative physical designs to produce the end product.

6. Compute the costs of these alternative designs.

7. Check the design and associated costs with the user. If the user cost/benefit requirement is met, go to on; if not, go back to 1.

8. Implement the system.

If the IS design professional follows this pattern of steps, the system produced may satisfy the end user since it meets a prescribed cost/benefit criterion. However, completing the outlined steps in no way guarantees an optimal choice. Since the design search is conducted only over a limited subset of alternatives, there may be many better (higher net benefit levels) options that are not considered. Little can dissipate an end user's satisfaction faster than learning of an alternative system with better profits. Finding an IS design that satisfies consistency, completeness, and minimal cost/benefit conditions may indeed be necessary, but is hardly sufficient to provide profit maximization. The key to IS design is to conduct a goal driven search over the feasible design space utilizing profit maximization as the firm goal. Since searching is not a costless endeavor, it should be pursued only so long as its marginal benefits exceed its marginal costs.

If the is designer fails to thoroughly search the set of feasible alternatives, the result may not be a happy one for the end user. Many of us have experienced “pain” after having made what seemed like a “great buy” and seeing the same item being sold elsewhere for much less. Or, having purchased a “stripped down model”, we find that the deluxe model (which we really wanted) does not cost much more. For the interaction between end user and is designer to be successful, the information exchange that takes place must allow the designer to search the whole feasible space.

The is design professional best knows the cost and capabilities of hardware and software. The end user best knows the value (the contribution to profit) of completing each of the possible tasks. The inter-relationship between the two is analogous to the interaction between supply and demand in a market, where the end user is the "demander". As in a market, full information availability is necessary to reach optimum choices. If information is costless, then the closer we are to full information, the closer to the optimum; the more limited the available information, the less likely we are to reach the optimum. How many of us would choose a grocery store where we could not see the possible choices, but could only describe what we wanted to a clerk who then made the selection? In making purchases, we often use experts (e.g. consumer reports, checking out others' opinions on products). But the net value of an expert depends both upon the cost of using the expert and upon our ability to ask the right questions and to provide information for the decision making. The same is true in the is setting where the interaction of end user and is design professional must go beyond the minimal flow evidenced in the current "eight step" design process outlined above.

## 3. PMAX-SDLC and Its Implications for Expanded End User-IS Design Professional Interaction

In a recent paper [17], we formally stated an alternative IS design strategy, PMAX-SDLC, driven by the goal of profit maximization. This goal driven framework has several implications for the end user-IS designer interaction. In particular, fulfilling the PMAX objective calls for redirecting their information exchange in order to evaluate the necessary variables and conduct the required searches.

In the PMAX-SDLC approach, we utilize a mathematical process model (PM) formulation. We chose this framework over the more standard mathematical programming models since the latter frameworks tend to be “solution driven” rather than “problem driven”; i.e. the mathematical structure is selected so that a particular algorithm can be used and the solution can be said to have certain properties (convergence, global optimality, etc.). Such a choice often relegates accuracy of representation to a secondary role. We argue that accuracy of representation and a direct link to the firm’s goals (such as profit maximization) are both necessary. If optimal is design is the goal, then it is essential to have a measure of success.

It is our argument that IS design must be goal driven. If not, design heuristics are arbitrary and the choices are also arbitrary. The question therefore is: Is there a class of models that can be used in IS design and that are problem driven, while being linked directly to the stated PMAX objective? The PMAX-SDLC problem is a member of a more general problem class that can be solved using engineering process models (PMS), which are detailed mathematical representations of the production process. Individual PMS fully characterize the stock and flow relationships. As evidenced by their engineering roots, the PMS attempt to represent the underlying process rather than provide some functional approximation. PMS were introduced for use in economics and management problems because of dissatisfaction with previously standard techniques (see Bever et al. [5] for a discussion of this history).

Using a PM framework, we formally have stated (see Marsden and Pingry [7]) the IS design problem as:

$$
\begin{array}{l} \max _ {i} \left\{\text { REVENUE } (\text { ISP } i) - \min _ {j} \text { COST } (\text { ISD } j) \right\} \\ \text { s.t. } = \begin{array}{l} T [ \text { ISD } j, \text { ISP } i ] > 0 \\ V [ \dots ; \text { ISD } j ] > 0 \end{array} \end{array}
$$

where

ISPi is the ith logical perspective of the IS design, a set of revenue enhancing and/or cost reduction activities which can be accomplished with the IS, for instance, target advertising, price differentiation, inventory reduction, CAD/CAM, etc., usually described using a data flow diagram. ISDj is the jth physical perspective of the IS design, a set of specifications that describe how a specific set of individuals, equipment, and procedures are to be networked to create a particular IS, usually described by a system flow chart. T[...] is the transformation between ISDj and ISPi; the constraint requires that the physical design (ISD) must be feasible for the associated information product (ISP). V[...] is the mathematical network representation of the allowable ISDj's and ISPi's; this constraint requires that the products and designs investigated be within the allowable set; the specific interior arguments not listed here would typically include such things as ledger or file updates or forecasts that make up the information product. REVENUE (ISPi) is the value of the revenue enhancement or cost reduction provided by the various information products in ISPi. COST (ISDj) is the cost of the necessary man-machine inputs for ISDj. The indicated inner minimization problem involves a search over feasible physical designs (ISD's) for each information product (ISP). The outer maximization problem involves a search over the individual ISP-ISD pairs where the ISD is the cost minimizing method of obtaining the accompanying ISP.

Though this representation appears complex and somewhat imposing, we are able to appeal to many earlier results to simplify its solution. For example, the inner minimization problem is identical to focusing on PM cost function approximations. Earlier authors (for example, Bever et al. [5,6], Griffith [11,12]) have provided techniques for determining non-stochastic bounded cost estimation and continuous function approximations. Bever et al. [5] set forth non-stochastic procedures (based upon numerical analysis results) for determining both point and interval estimates as well as determining elasticity of substitution measures.

Search costs are an important consideration in the final PM solution chosen. In the PM problem specification set forth here, search costs would be included in each “Cost (ISDj)” (i.e. cost is incurred each time a solution is considered) and in each “Revenue ISPi” (i.e. cost is incurred each time a task set or information product set is considered). The impact of search costs and alternative search strategies (including the use of numerical analysis techniques for solution approximations) are discussed in Bever et al. [5].

In fact, the basics of the PM procedure can be found in the IS literature. Nunamaker, Nylin, and Konsynski [19] followed a pattern similar to the PM approach in dealing with the problem of “automatic design and optimization of program modules”. The authors took the hardware, operating systems, and file structures as given. But, if these were allowed to vary and the solution technique generalized, then the problem would be analogous to our inner minimization problem. For an example of the direct use in MIS of an operations research model applied to response design and data allocation, see Ahituv [2].

In addition to convenience and the ability to utilize important existing results, the use of the PM to characterize the IS design problem emphasizes the need to expand the current end user-IS designer interaction. The information needed to conduct the necessary searches (both the inner minimization and the outer maximization) must come from one of two sources, the end user or the IS designer.

We posit that the REVENUE (ISPi) information is the realm of the end user while the COST (ISDj) information lies in the realm of the IS design professional. Rather than having the IS design professional put forth a set of “sample IS’s” based upon end-user descriptions of what is wanted, we argue that the efforts of each should be focused on utilizing individual expertise in order to accomplish information exchange.

Is the suggested approach too complex? Does it ask too much? We answer no. Avoiding the demand of such information development makes the selection/design decision ad hoc. The questions that must be addressed are no different from ones that are continuously faced in a firm's decision making. Take, for example, a firm attempting to decide on an important capital investment. Do the firm "designers" simply discuss what would "satisfy" the end-users? Would the PMAX firm choose a satisficing investment decision (meeting minimum cost/benefit and end-user satisfaction measures) rather than conducting a thorough search over investment alternatives to maximize the cost/benefit relationship?

There have been several recent contributions to the literature that signal growing awareness of the importance of a market approach to the selection and implementation of a firm's information system. Information is neither a free good that should always be supplied nor is it so valuable a good that its return to the firm will always exceed its cost. Like all other inputs, information is an item whose value to the firm lies in the increased net returns it makes possible. This basic realization, while hardly surprising, is the heart of the needed revision in IS selection and evaluation procedures.

The situation we are now facing in IS design is characteristic of areas that undergo rapid innovation. At first, the question that dominates is: "What can it do?" There is a struggle to avoid being left behind. Implementation tends to dominate evaluation. Understanding how to utilize the technology overwhelms the question of when it should be used. The issue of net gain is put on hold. Eventually, however, the economic reality of the firm's decisions are felt. Each choice has an economic impact, whether or not it was anticipated. The choice of an IS, whether due to convenience, convention, or hard economic sense, will result in "bottom line" impact.

4. End User and iS Designer - The Need for Structured Exchange

In our approach, there is mutual impact between the end user and the designer; it occurs because of the exchange of revenues and costs in the PM framework. The approach extends the early suggestions of Lucas [15,16] focusing on end-user involvement in creative IS design. There should be formalization of the design process to allow utilization of the results of related disciplines in reaching an optimum choice. The end user may know (or be able to closely approximate) the revenue contribution (or cost reduction) of performing a task: generating a forecast or producing a particular report. But the same end user may have little idea of the costs of each of the information products. The IS design professional interacting with the end user can structure the ISP-ISD space that must be searched if a PMAX IS is to be chosen.

This is actually a natural extension of a variety of recent IS work. Kriebel and Raviv [14] suggested the advantages of using the economic paradigm “to view the organization as a marketplace for computing and information services which contains elements of supply and demand”. Their presentation assumes independent operation of each information site and a single value criteria (speed) rather than the more complete (and complex) PM formulation. Ahituv and Wand [4] applied the information economics model approach to an information evaluation problem with two business performance criteria: expected payoff and risk. This model, though caveated by the authors as but an initial step that relied heavily upon subjective attitudes towards risk, raised important issues in IS evaluation. Among these was the need to assess the IS in terms of its contribution to achieving the firm’s objectives.

In his analysis of the impact of external information channels on the innovativeness of software development groups, Zmud's [20] focus is not explicitly on market concepts. But they are nevertheless woven through his work. Greer and Kropp [10], considering a more narrowly defined problem involving timeliness of information, focused directly on economic trade-offs: the opportunity cost of information decisions.

In their study of the relationship between performance and increased computerization (including increased information manipulation capabilities measured by software characteristics), Cron and Sobol [8] raise the following point:

...In today's intensely competitive business environment, it is increasingly important for management to link all important decision to bottom-line performance. As advances in technology make computers available to a wider number of businesses, even to those usually thought of as being small, the issue of intelligent computer adoption and usage becomes increasingly relevant to the business community in general. (p. 180.)

Our approach is fully consistent with the suggestions found in Ackoff's [1] foundation paper, where he emphasized the critical problem of user (manager) information needs:

Most MIS designers "determine" what information is needed by asking managers what information they would like to have. This is based on the assumption that managers know what information they need and want it.

For a manager to know what information he needs he must be aware of each type of decision he should make (as well as does) and he must have an adequate model of each. These conditions are seldom satisfied. Most managers have some conception of at least some of the types of decisions they must make. Their conceptions, however, are likely to be deficient in a very critical way, a way that follows from an important principle of scientific economy: the less we understand a phenomenon, the more variables we require to explain it. Hence, the manager who does not understand the phenomenon he controls plays it "safe" and, with respect to information, wants "everything". The MIS designer, who has even less understanding of the relevant phenomenon than the manager, tries to provide even more than everything. He thereby increases what is already an overload of irrelevant information.

The moral is simple: one cannot specify what information is required for decision making until an explanatory model of the decision process and the system involved has been constructed and tested. Information systems are subsystems of control systems. They cannot be designed adequately without taking control into account. (p. B-149–150.)

Ackoff also emphasized that end-users need not understand the physical complexities of 1s's, but must understand how to use them and how to integrate the information flows to maximize the furtherance of organizational performance.

In reporting the "Minnesota Experiments", Dickson, Senn, and Chervanty [9] called for general theoretical analysis, emphasizing the contribution that specific experimentation could provide. A key part of their suggestion involved a movement away from "quasi-random" selection of user characteristics to be examined towards a theory or theories that integrated these dimensions".

Initial efforts at completing end user-IS designer information exchange will no doubt include various estimates that will be sharpened over time. In fact, we conjecture we will find that results will carry over across related applications. This should hold especially true in industries with “tight technology”; i.e. where firms utilize similar production technology.

The end user has the advantage in determining the necessary revenue impact values while the IS designer has the advantage in determining the cost values and the ISD specifications feasible for producing the information products of a given ISP. Optimally planning, measuring, and controlling the investment in and utilization of an information system is an issue whose time has come. As competition tightens, firms and organizations can no longer presume that additional information systems that reduce tangible costs necessarily contribute to overall firm profitability. To date there has been little progress in developing techniques to measure or incorporate the necessary values into the IS design decision problem. To this end, we have suggested the use of a process model framework and the need to restructure the interaction between end user and IS design professional, to specify the information necessary to perform the ISP-ISD searches required in the PMAX problem formulation.

Consideration of end user satisfaction must be put in the context of net gain to the firm. The firm is the true end user who obtains satisfaction from net profit (increased revenue or decreased costs) accruing from optimal is design strategies. The is design problem is an integrated problem that calls for inputs from the end users and the is design professional in a structured way that enables the is choice to be made on the same basis as all other important input selections – the contribution to net profitability.
