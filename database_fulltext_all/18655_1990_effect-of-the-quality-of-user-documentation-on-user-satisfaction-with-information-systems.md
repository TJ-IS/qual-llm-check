# Effect of the Quality of User Documentation on User Satisfaction with Information Systems

Leopoldo A. Gemoets and Mo Adam Mahmood
College of Business Administration, University of Texas at El Paso, El Paso, Texas 79968, USA

User documentation plays an important role in implementation success of an information system through its user satisfaction. Yet, very little rigorous research has been undertaken in relating user satisfaction to user documentation. This article first re-validates two existing user documentation and user satisfaction instruments. This is followed by a rigorous attempt to determine the effect of user documentation on user satisfaction, using a canonical correlation analysis. The results indicate that user satisfaction of a system is strongly influenced by its documentation. The research provides a set of guidelines, arrived at empirically, for IS managers to ensure the design of highly efficient and effective user documentation for a system, by monitoring and controlling the entire process of documentation. These guidelines can also be used to identify and rectify a poorly documented system by using a set of user satisfaction criteria.

Keywords: User documentation, User satisfaction, User documentation effect, User documentation guidelines.

## 1. Introduction

User documentation plays an important role in information systems implementation success. Effective information systems not only mandate user understanding of their needs and also that they be knowledgeable. It has also been suggested that the use of an information system is directly related to the user community's sense of satisfaction [2]. User documentation consists of written or visual explanations that, in principle, must show “what the application software does, how it works, and how to use it” [7]. Needless to say, the effectiveness of the documentation in conveying this information efficiently and effectively is a measure of its quality. It is apparent that, in order to achieve implementation success through user satisfaction, an information system must have good documentation.

The importance of documentation has been reflected in statements in professional journals.

Dr. Mahmood has published in MIS Quarterly, Decision Sciences, the Journal of Management Information Systems, Information and Management, the Journal of Systems Management, Data Base, the International Journal of Policy and Information, the Journal of Computer-Based Instruction, INFOR: Canadian Journal of Operation Research and Information Processing, and others. He had also presented papers in international, national, and regional meetings of different professional organizations.

For example, Morland [15] and Myers [16] suggested documentation as a tool for making software applications “user friendly.” Schaffer [19] advised the use of good documentation for increasing efficiency and decreasing processing costs. Kendall and Losee [13] indicated that good documentation reduces user dependencies on the MIS department. Barbuto [3] implied that documentation facilitates installation, operation, use, evaluation, and maintenance of a system. Wilson [20,21] cited the overall importance of user documentation. Guillemette [22] worker on a reader-based documentation measure.

In spite of its theoretical advantage and the widespread interest shown by practitioners in professional literature, very little rigorous research has been conducted in this area, especially in the effect of user documentation on user satisfaction with information systems. As a matter of fact, there are only two empirical studies $[7,8]$ in the area.

The first study related user documentation to user satisfaction. The instrument used to measure satisfaction was not, however, validated. Also, no instrument was developed for evaluating user documentation. Furthermore, user documentation was measured using only one question: Do you have good user documentation? Therefore, the result is based on a univariate, rather than multivariate statistical analysis to determine the magnitude of multivariate relationships between the two sets of items [10,11].

The second study, at a later date, provided a validated user documentation instrument to measure the quality of user documentation. It used item-total correlations and correlations with an overall documentation question (criterion) to validate the instrument. However, it stopped short of exploring user documentation as a means for information systems implementation success through user involvement and user satisfaction. The need for further research, especially in the area of relating user documentation to user satisfaction, is evident from previous discussion. This was especially emphasized when Doll and Torkzadeh [7] stated,

“a tool for measuring the quality of user documentation would permit more rigorous academic research on user documentation's impact on user satisfaction and MIS development success.”

In spite of this, the research on user documentation is mostly based on conceptual discussions and technical literature but very little empirical research. Rigorous research should be undertaken to verify or deny many of the claims being made. The objective would be to investigate the impact of user documentation on user satisfaction. Using a sample of 80 user and IS managers, the user satisfaction instrument (originally designed by Pearson [2,18] and later empirically validated by Ives, Olson, and Baroudi [12]) and user documentation instrument [7] were re-validated. This was followed by a rigorous attempt to relate user satisfaction and documentation items using canonical correlation analysis. Finally, recommendations for improving satisfaction through documentation were provided.

## 2. Research Methods

In order to empirically examine the impact of documentation on user satisfaction, the aforementioned user documentation and satisfaction instruments were used. The documentation instrument contained 15 items that verify “how well the documentation is written,” and “how well it helps the user understand what the software does, how it works, and how to use it” (see Appendix A). The documentation instrument used 5-interval Likert-type scales [strongly disagree = 1, disagree = 2, neutral = 3, agree = 4, strongly agree = 5]. The Doll and Torkzadeh [7] instrument proved to be a consistent measure of user documentation. A factor analysis of 80 observations revealed 8 factors [Appendix A]. All 15 items were loaded at 0.50 level or higher on these 8 factors, proving its validity. The 15-item instrument has a reliability of 0.93 which is comparable to Doll and Torkzadeh’s [7] finding of 0.96.

The modified satisfaction instrument contained 20 items (see Appendix B). It also used 5-interval Likert-type scales (very unsatisfactory = 1, unsatisfactory = 2, neutral = 3, satisfactory = 4, very satisfactory = 5). It was modified, because it was originally designed to “measure general user satisfaction with EDP staff and services, information product, and user/involvement/knowledge rather than satisfaction with a specific application” [7]. Therefore, items such as attitude of DP/MIS staff, relationship with the IS staff, priority determination for allocation of IS resources, and vendor support for hardware and software were excluded because they were inappropriate (i.e., they were not application specific). Several redundant output information-related items (such as precision, timeliness, and volume of output information) were also excluded. Also, the Ives, Olson, and Baroudi [12] user satisfaction instrument does not include the ease of use aspect of an information system [7]. It has been found to be important for implementation success of an information system by other researchers [4,9]. Several application-specific items (such as ease of use, overall cost-effectiveness, meets user needs, the improved development process, data security, and percentage of hardware and system downtime) were added to the instrument.

To make sure that the modified Ives, Olson, and Baroudi [12] instrument was suitable for rigorous research, the instrument was validated using factor analysis and its Cronbach's [6] alpha reliability tested. The reliability of the instrument was found to be 0.91. This satisfies the minimum standard of 0.80 suggested for basic research and 0.90 indicated for use in applied investigation [17]. A factor analysis of 80 user satisfaction observations revealed 10 factors (a scree plot [5] was used to decide on how many of these to retain). All 20 items were loaded at 0.50 level or higher on 10 factors, proving the instrument's validity.

## 3. Results

To determine the relationships between user satisfaction and documentation items, a canonical correlation analysis was performed using user satisfaction criteria as dependent and user documentation criteria as independent items. Canonical analysis can be used to decide whether two sets of items are statistically independent of each other in a linear sense or, conversely, to determine the magnitude of multivariate relationships between the two sets $[10,11]$ . By simultaneously considering both multiple dependent and multiple independent variables, it is possible to control for suppressor or moderator effects which may exist among the various dependent variables.

The first canonical relationship suggests that a well-organized user documentation that provides formal instructions for the use of a system, clearly explains the system capability by describing the function of each program module or procedural step of the system, and thereby provides a means to review and judge the overall system. This clearly goes a long way towards making users satisfied by presenting an easy-to-use system that meets their needs and provides accurate output, and in the process helps them understand the system better, thereby increasing their confidence in the system. Simply put, an organization interested in making users very satisfied should make sure that their documentation has the aforementioned qualities.

The first canonical relationship also suggests that in order to moderately satisfy the users, documentation must be concise, easy to use, complete, and describe how to avoid most common problems or mistakes. This type of documentation will increase user confidence in the completeness of the output, the competence of systems personnel, the correctness of the developmental process, and the accuracy of communication between the IS department and users.

The second canonical relationship highly emphasized the accuracy and completeness of output as dependent variables, and completeness of user documentation and relevancy and usefulness of user documentation as predictor variables. The moderately emphasized dependent variables are: (a) overall cost effectiveness of a system, (b) system responsiveness to changes in user needs, and (c) flexibility of data and reports available from the system. Similarly, the moderately emphasized predictor variables are that the documentation: (a) is presented in a simple and straightforward manner, (b) is well written, (c) is concise, and (d) describes how to enter and manipulate data.

The second canonical relationship suggests that the accuracy and completeness of output information is very important for truly satisfying the users. This can be achieved by making sure that a complete user documentation, that contains useful and relevant information about the use of the system, is available. It also suggests that, for moderate satisfaction with the system, users must be content in terms of its: (a) overall cost effectiveness, (b) responsiveness to changes in user needs, and (c) flexibility in providing data and reports through a well-written, concise documentation that is presented in a simple and straightforward manner, and that describes how to enter and manipulate data.

## 4. Discussion and Conclusions

Canonical correlation analysis convincingly demonstrates that there is a significant relationship between user satisfaction and user documentation of a system. In other words, user satisfaction with the system can be considerably enhanced by developing proper user documentation. This confirms the suspicion of Doll and Ahmed [8] that “good user documentation may have a dramatic and continuing impact on user satisfaction.”

Canonical analysis also provided interesting insight into the relationship between user satisfaction and documentation items. It broadly separated these two sets of items into those related to users' primary (as represented by the first canonical function) and secondary interests (as suggested by the second canonical function). As expected, the highly emphasized satisfaction items of primary interest are related to the system itself (e.g., easy to use, meet user needs, etc.). The associated documentation items are those that facilitate the understanding and use of the system (e.g., formal instructions for use of the system, clearly explained system capabilities, etc.). Apparently users are primarily interested in documentation items that enhance their knowledge and understanding of the system and facilitate its use. This supports the contention by Branscomb and Thomas [4] and Goodwin [9] that ease of use is an important factor for information systems success. It also confirms Barbuto's [3] statement that the documentation can be used in evaluating a system. The findings of this research, however, refute Doll and Ahmed's [8] contention that "good user documentation appeared to have little impact on perception of the accuracy [of information from a system]."

The moderately emphasized satisfaction items in the primary interest area are related to the IS department and the competence of its personnel (e.g., hardware and systems downtime, quality and competence of systems personnel, etc.). The associated moderately emphasized documentation items focused on quality of the documentation (e.g., it is concise, easy to use, etc.). The implication here is that quality of documentation can enhance the image of the IS department and its personnel. This supports the contention by Schaffer [19] that user documentation can be used to make use of the system “more enjoyable and less frustrating” and thereby generate a favorable image of the IS department.

The highly emphasized user satisfaction items in the secondary area define how the accuracy and completeness of output information is related to completeness and usefulness of relevant information in user documentation. The implication here is that accuracy and completeness can be used as a surrogate measure of user satisfaction, which depends on having complete user documentation providing useful and relevant information.

The moderately emphasized satisfaction items reflect user concern over cost effectiveness of an information system and its flexibility in meeting user changing needs. The second canonical function emphasizes that this concern can be achieved through well-written, concise, and straightforward documentation. This supports the contention by Schaffer [19] that good user documentation can be used for achieving overall cost effectiveness of a system and the statement by Ackoff [1] that an effective information system requires users to know “how to use it.”

It is interesting to note that several user satisfaction items (such as feeling of participation, currency of output information, reliability of output information, data security, lead time for new system development, relevancy of output information, and control over IS services received) were not loaded at or above the 0.20 level. The implication is that such items were not influenced by user documentation. Therefore IS managers should look for an alternative source to accomplish these goals.

It is also interesting to note that two user documentation items (e.g., accuracy and satisfaction) were not loaded at or above 0.20 level. It is not obvious why. Our conjecture is that documentation satisfying other criteria is already accurate and satisfactory; therefore, these items became redundant and failed to play any role in user satisfaction.

## 5. Conclusions and Implications

The fundamental conclusion of this research is that user satisfaction of a system is strongly influenced by its documentation. This confirms some statements in the literature, but at the same time contradicts some assertions by previous researchers.

To improve documentation directly related to user satisfaction, the research divides documentation items into two groups: those related to users' primary and secondary interests. Within the primary interest area, the users highly emphasized the following characteristics in an information system documentation:

a. provide formal instructions for its use;

b. explain its capability;

c. be well organized;

d. provide a means to review and judge it; and

e. describe the function of each program module or procedural step included in it.

They also moderately emphasized that documentation:

a. be concise;

b. describe how to avoid most common problems and mistakes;

c. be easy to use; and

d. be complete.

Within the secondary interest area documentation, as a matter of high priority, must:

a. be complete; and

b. provide useful and relevant information;

and, as a matter of moderate priority, it must also:

a. be provided in a simple and straight forward manner;

b. be well written;

c. be concise; and

d. describe how to enter and manipulate data.

It is interesting to note that the users emphasized, as a matter of both primary and secondary interests, documentation completeness. These guidelines, if followed correctly, should enable an IS manager to design highly effective user documentation. They can also be used to “monitor and control” the quality of user documentation and thus be an effective tool in information resource management. The process will allow an information systems manager to identify a poorly documented system and to alleviate the problem identified.

This research should also encourage further investigation in user documentation especially how it can be used to facilitate user and top management involvement in the developmental process. A large sample size could also investigate the effect of the size, type, or functional areas of an organization, and the impact of different types of applications on user documentation. Finally, the cost effectiveness of documentation development should be considered; it is important that resources expended for documentation do not outweigh its value.
