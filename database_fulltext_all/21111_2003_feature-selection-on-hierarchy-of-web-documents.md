# Feature selection on hierarchy of web documents

Dunja Mladenic´ <sup>a,b,</sup>\*, Marko Grobelnik <sup>a</sup>

<sup>a</sup>Department of Intelligent Systems, J. Stefan Institute, Jamova 39, 1000 Ljubljana, Slovenia <sup>b</sup>Carnegie Mellon University, Pittsburgh, PA, USA

## Abstract

The paper describes feature subset selection used in learning on text data (text learning) and gives a brief overview of feature subset selection commonly used in machine learning. Several known and some new feature scoring measures appropriate for feature subset selection on large text data are described and related to each other. Experimental comparison of the described measures is given on real-world data collected from the Web. Machine learning techniques are used on data collected from Yahoo, a large text hierarchy of Web documents. Our approach includes some original ideas for handling large number of features, categories and documents. The high number of features is reduced by feature subset selection and additionally by using ‘stop-list’, pruning low-frequency features and using a short description of each document given in the hierarchy instead of using the document itself. Documents are represented as feature-vectors that include word sequences instead of including only single words as commonly used when learning on text data. An efficient approach to generating word sequences is proposed. Based on the hierarchical structure, we propose a way of dividing the problem into subproblems, each representing one of the categories included in the Yahoo hierarchy. In our learning experiments, for each of the subproblems, naive Bayesian classifier was used on text data. The result of learning is a set of independent classifiers, each used to predict probability that a new example is a member of the corresponding category. Experimental evaluation on real-world data shows that the proposed approach gives good results. The best performance was achieved by the feature selection based on a feature scoring measure known from information retrieval called Odds ratio and using relatively small number of features. <sup>D</sup> 2002 Elsevier Science B.V. ## 1. Introduction

In many different aspects of our lives, we are facing the well-known information overload problem. The problem is even more emphasized with the growing amount of text data in electronic form and the availability of the information on the constantly growing World Wide Web. There are number of services offered to help the users in finding the needed information; we could hardly imagine using the Web without search engines and Web indices of documents. An example of such index of Web documents is Yahoo! hierarchy used as an example in this paper. The problem we address here is automatic document categorization when dealing with high dimensionality of the data and a hierarchical structure of content categories. Today, the practice is to have manual maintenance of a document hierarchy, which requires a number of editors that check each new document and find the right position(s) in the hierarchy, restructure the hierarchy, evaluate the documents, etc. The part of that work, especially involving documents nicely fitting to some of the existing categories, does not require deeper understanding of the text but it still time consuming for human. The whole process is expensive and in some sense time critical, since we would like to have new documents inserted in the hierarchy as soon as possible (in days or maybe weeks but definitely not years). Thus, even some semiautomatic way of performing that task may be of great help. In this paper, we address a part of that problem and investigate appropriate machine learning methods that leads us to proposing an approach for document categorization into a large hierarchy of categories.

In propositional learning, a problem domain is given by a set of examples, where each example is described with a class value and a vector of feature values. Features used to describe examples are not necessarily all relevant and beneficial for inductive learning. Additionally, a high number of features may slow down the induction process while giving similar results as obtained with a much smaller feature subset. Feature subset selection is commonly used when learning on text data, since most text domains are characterized by several tens of thousands of features. Growing interest in the usage of machine learning on text data is especially stimulated by the intensive growth of the World Wide Web that can be seen as a widely accessible, large, distributed source of text data. The problem of automatic document categorization is well known in information retrieval and usually tested on publicly available data bases (e.g. Reuters, MEDLINE). Here we use machine learning for document categorization using one of the existing Web hierarchies, the Yahoo hierarchy [13]. In this way, the current situation on the Web captured in a Web hierarchy is used. The proposed approach is not limited to Web hierarchies and can be applied on other hierarchies of documents, for instance, MED-LINE, the standard hierarchy of medical abstracts.

The paper is structured as follows. Section 2 gives a brief overview of feature subset selection as used in machine learning and describes the approach commonly used in text learning. Several known and some new feature scoring measures used for feature selection on large text data are described in Section 3. Section 6 gives experimental comparison of these measures on the real-world data that is described in Section 4. The properties of compared scoring measures and their results are discussed in Section 7.

## 2. Feature subset selection approaches

Feature subset selection for inductive learning has already been addressed in machine learning. The problem of selecting a subset of features can be seen as an optimization problem. The whole search space for optimization contains all possible subsets of features, meaning that its size is $\begin{array} { r } { \dot { \sum } _ { i = 0 } ^ { F } \binom { F } { i } = ( 1 + 1 ) ^ { F } = 2 ^ { F } } \end{array}$ where $F$ is the number of features and i is the size of the current subset. Different methods have been developed and used for feature subset selection in statistics, pattern recognition and machine learning, using different search strategies and evaluation functions. The following search strategies are commonly used in feature subset selection: (a) forward selection—start with an empty set and greedily add features one at a time, (b) backward elimination—start with a feature set containing all features and greedily remove features one at a time, (c) forward stepwise selection—start with an empty set and greedily add or remove features one at a time, (d) backward stepwise elimination—start with a feature set containing all features and greedily add or remove features one at a time, (e) random mutation— start with a feature set containing randomly selected features, add or remove features randomly selected features one at a time and stop after a given number of iterations.

According to John et al. [18], there are two main approaches to feature subset selection used in machine learning: filtering approach and wrapper approach. In information retrieval and also in text learning, the whole process of feature subset selection is usually simplified with the assumption of feature independence. In this way, the solution quality is traded for the time needed to a find solution, justified by the large number of features usually present in text domains.

## 2.1. Filtering approach

In the filtering approach illustrated in Fig. 1, a feature subset is selected independently of the learning method that will use the selected features. There are methods in statistics that are used to reduce the number of features, like principal components analysis or factor analysis [28] that will not be addressed in this paper. Here we briefly describe several feature subset selection algorithms used in machine learning that are based on the filtering approach.

![](/api/attachments/R42CRGNE/fulltext/images/e1ab2c2615c15f116bdf0d233438ceb91cf02037ca01f5b1036160328550668d.jpg)  
Fig. 1. Illustration of the filtering approach to feature subset selection. Evaluation function does not include characteristics of the machine learning algorithm that will use the selected features.

Almuallin and Dietterich [3] developed several feature subset selection algorithms including a simple exhaustive search and algorithms that use different heuristics. They based their feature subset evaluation function on conflicts in class value occurring when two examples have the same values for all the selected features. In the first version of the feature subset selection algorithm called FOCUS, all the feature subsets of increasing size are evaluated until a sufficient subset is encountered. Feature subset Q is said to be sufficient if there are no conflicts. In other words, if there is no pair of examples that have different class values and the same values for all the features in Q. The successor of that algorithm FOCUS-2 prunes the search space, thus evaluating only promising subsets. Both algorithms assume the existence of a small set of features that forms a solution and their usage on domains with a large number of features can be computationally infeasible. This is the reason why search heuristics are used in the next versions of the algorithm, resulting in good but not necessarily opti mal solutions. The idea is to use forward selection until a sufficient subset is encountered. Cardie [8] uses decision tree induction for feature subset selection. The idea is that only the features that appear in the induced decision tree are selected for learning using Nearest Neighbor algorithm. In this algorithm, the optimization process is based on feature selection measure (in this case information gain ratio 3.1) that is used in the greedy search to induce decision tree. Kira and Rendell [20] assigned weight to each feature and used nearest neighbor algorithm to update the weights. Training set is randomly sampled and the weights updated based on the difference between each selected example and its two nearest neighbors: the nearest hit—nearest neighbor having the same class value and the nearest miss—nearest neighbor having the opposite class value. Koller and Sahami [21] proposed an algorithm for feature subset selection that uses backward elimination to eliminate predefined number of features. The idea is to select subset of features that keeps class probability distribution as close as possible to the original distribution that is obtained using all the features. Evaluation function used to select the next feature to be deleted is based on Cross entropy described in Section 3.2. The algorithm finds for each feature a subset of K features such that the feature is approximated to be conditionally inde-

pendent of the remaining features. Reducing K to 0 means having much faster algorithm that is actually the same as the feature selection algorithms commonly used on text data (see Section 2.3). Liu and Setiono [27] used random sampling to search the space of all possible feature subsets. The predetermined number of subsets is evaluated and the smallest having inconsistency rate below the given threshold is selected. They define inconsistency rate as the average difference between the number of examples with the same values of all the selected features and the number of examples among them having the same, most frequent class value among these examples. Noise handling is enabled by setting the threshold to some positive value. If the threshold is set to 0, the evaluation is based on consistency check as used in [3]. Pfahringer [38] proposed using Minimum Description Length as an evaluation function of feature subset. In order to calculate Minimum Description Length of a feature subset, training examples are represented with a simple decision table that contains only features from the subset. He used a search that adds or removes features one at a time. The search starts with the randomly selected feature subset found to be the best among a fixed number of randomly selected feature subsets. He reported that his method performs at least as well as the wrapper approach applied on the simple decision tables and scales up better to large number of training examples and features.

## 2.2. Wrapper approach

The idea of the wrapper approach is to select feature subset using the evaluation function based on the same learning algorithm that will be used for learning on domain represented with the selected features (see Fig. 2 for illustration). Instead of using subset sufficiency, entropy or some other explicitly defined evaluation function, a kind of ‘black box function is used to guide the search. Namely, evaluation function for each candidate feature subset returns estimated quality of the model induced by the target learning algorithm using the feature subset. The idea is similar to automated model selection, where pruning parameters for decision tree induction are set by an optimization algorithm [32,33]. This can result in a rather time-consuming process since for each candidate feature subset that is evaluated during the search, the target learning algorithm is usually applied several times (e.g. 10 in case when 10-fold cross validation is used for estimating a model quality). Here we briefly describe several feature subset selection algorithms developed in machine learning that are based on the wrapper approach.

![](/api/attachments/R42CRGNE/fulltext/images/322384bf7681b8843a8353c37ba26cceb7f5c812d0d38b9577ddd3f6b5cb3995.jpg)  
Fig. 2. Illustration of the wrapper approach to feature subset selection. Evaluation function is using the machine learning algorithm that will use the selected feature subset.

Aha and Bankert [2] used a wrapper approach for feature subset selection in instance-based learning. They proposed a new search strategy that performs beam search using a kind of backward elimination. Namely, instead of starting with an empty feature subset, their search randomly selects a fixed number of feature subsets and starts with the best among them. Bala et al. [5] and Cherkauer and Shavlik [10] used a wrapper approach for feature subset selection for decision tree induction. Their method uses genetic algorithm to perform the search. Caruana and Freitag [9] developed a wrapper feature subset selection method for decision tree induction. They proposed a new search strategy that uses adding and removing features (backward stepwise elimination) and additionally at each step removes all the features that were not used in the decision tree induced for the evaluation of the current feature subset. John et al. [18] defined notion of strong and weak relevance of a feature and used a wrapper feature subset selection for decision tree induction. Skalak [42] used a wrapper approach for feature subset selection and for selecting a subset of examples to be stored in instance-based learning. Instead of using deterministic search strategy as used in Refs. [3,9,18], he used random mutation. Vafaie and De Jong [43] used a kind of wrapper approach where instead of using AQ15 for evaluation and learning, the evaluation is performed using the approximation of model quality estimated by AQ15 that selects feature subset which maximally separates classes using Euclidean distance. Their method uses genetic algorithm to perform the search.

## 2.3. Approach used in text learning

Most of the feature subset selection approaches used in machine learning are not designed for the situations with a large number of features. The usual way of learning on text defines a feature for each word that occurred in the training documents. This can easily result in several tens of thousands of features. Most methods for feature subset selection that are used on text are very simple compared to the described methods developed in machine learning. Basically, some evaluation function that is applied to a single feature is used. All the features are independently evaluated, a score is assigned to each of them and the features are sorted according to the assigned score. Then, a predefined number of the best features is taken to form the solution feature subset (see Fig. 3). In our experiments described in Section 6, we observe the influence of the number of selected features to the performance of different feature scoring measures.

## 3. Features scoring in text domain

Scoring of individual features in feature subset selection approach used on text data can be performed using some of the measures used in machine learning for feature selection during the learning process. For instance, Information gain used in decision tree induction [39] can be used to score the features. In machine learning, several measures are known appropriate for different kinds of class and feature values. In our case, we have a binaryvalued class (is the document relevant for the target concept?) and binary-valued features (does a feature occur in the document?). Notice that for the purpose of feature subset selection, frequency is replaced by occurrence or nonoccurrence of a feature. This section gives description of different feature scoring measures that we experimentally compared including known measures that were already used for feature selection in text domains and some new measures we propose here.

## 3.6. Variants of odds ratio

We propose several variants of Odds ratio since, in our preliminary experiments, it was found to be the most promising feature scoring measure. As can be seen from Section 3.5, Odds ratio does not take into account frequency or probability of word occurrence.

Our experiments show that Cross entropy for text gives better results than Mutual information for text while the main difference between them is that Cross entropy for text additionally takes into account the probability of word occurrence P(W) (see Eqs. (3) and (4)). Thus, we propose a variant of Odds ratio that is weighted by the probability of word occurrence. The idea was to test if taking into account word probability would improve the results of Odds ratio as is the case with Mutual information. Our experiments show that the results of Odds ratio and its variant that includes probability of word occurrence are not significantly different (see Section 6).

$$
\begin{array}{r l} \text { WeightedOddsRatio } (F) & = P (W) \\ & \times \text { OddsRatio } (W) \end{array}\tag{8}
$$

where $P ( W )$ is the probability that word W occurred in a document (probability that feature F has value ‘true’).

We also try two simple measures inspired by Odds ratio that we call Log-probability ratio and Expprobability difference. The idea was to see if these simplified formulas still have similar behavior as Odds ratio (confirmed by experiments in Section 6). Both measures aim at capturing difference in the conditional probability of word occurrence in different class values. This makes them appropriate for problems where one of the class values is the target value and we want to identify examples having the target class value (e.g. identifying relevant documents).

$$
\operatorname{LogProbRatio} (F) = \log \frac {P (W \mid C _ {1})}{P (W \mid C _ {2})}\tag{9}

## 5. Learning from hierarchy

The problem domain is represented as a classification hierarchy of examples. There is some work in machine learning addressing domains with hierarchy of features (e.g. Ref. [40]) but domains with example or classification hierarchy have been only recently explored. Koller and Sahami [22] proposed an approach to hierarchically classifying documents. They used the Reuters dataset that ‘does not have a predetermined hierarchical classification structure’, so they ‘identified labels that tend to subsume other labels, and used those as the higher level topics’. In their hierarchy, all documents are placed at the bottom of the hierarchy in tree leaves. Documents are represented as Boolean word-vectors with features representing words selected using greedy algorithm that eliminates features one by one using Cross entropy measure (see Eq. (3)). They compared several learning algorithms and learn document category from the hierarchical structure, dividing classification task into a set of smaller problems corresponding to the splits in the classification hierarchy nodes. They give results on three domains each having a three-level hierarchy that is based on up to 1000 documents and the biggest having 12 nodes. McCallum et al. [30] also developed an approach for learning from class hierarchies based on shrinkage and reported results on the two bottom layers of the Yahoo hierarchy. However, this approach does not address the problem of documents being placed in any hierarchy node. Rather, they used the same assumption as used in Ref. [22] that all the documents are places in the leaves.

The Yahoo hierarchy and the defined domains we are using here are much bigger, have predetermined hierarchical classification structure with document not necessarily placed only in the hierarchy leaves. This means that some documents sitting in the nonleaf nodes are too general to be classified into any of the existing leaf nodes. A classifier using these nonleaf documents should consider classification into any of the hierarchy nodes (not only leaf nodes).

We use the Yahoo hierarchy for two learning problems: assign categories and assign a set of keywords to a document. For a new document, the learned model returns for each category (and the corresponding set of keywords) from in the text hierarchy the probability that the document is its member. One possibility is to use ‘flattened’ approach and generate one huge classifier with many class values, each value corresponding to one category. Additionally to the high number of class values, a large number of features is needed in order to cover all the variety of the large number of documents included in different categories. As pointed out in Ref. [22], an alternative idea is to split the whole problem into subproblems and use a local feature subset selection on each subproblem. We use the hierarchical structure to define subproblems each corresponding to the individual Yahoo category. For each of the subproblems, a classifier is constructed that predicts the probability for a document to be a member of the corresponding category and thus be characterized by the corresponding set of keywords.

In our approach, documents are represented as feature-vectors as described in Section 5.1. A set of positive and negative examples for each subproblem are constructed from the given hierarchical structure as described in Section 5.2. Learning using the naive Bayesian classifier is described in Section 5.3. The final result of learning is a set of specialized classifiers each based only on a small subset of features. The whole system architecture showing the different phases is given in Fig. 5.

## 5.1. Document representation

Document categorization is here based on the usage of machine learning techniques on large text data. We based document representation on featurevectors using the bag-of-words representation as commonly used in learning on text data (e.g. [4,6,7, 11,17,24,34,37,45]). In learning on text data, one of the frequently used approaches to reduce the number of different words used as features that we also apply here is to use the publicly available ‘‘stoplist’’ containing common English words [14]. We extended document representation by generating new features that represent not only single words (unigrams) but also up to five words (1-grams, 2-grams, . . . 5-grams) occurring in a document as a sequence (e.g. ‘machine learning’, ‘world wide web’). Since we have previously removed words contained in the ‘‘stop-list’’, some features that represent word sequences can actually capture longer sequences like for instance, ‘Word for Windows’ that is represented as the 2-gram ‘Word Windows’ or ‘winners will be posted at the end of each 2-week period’ that is represented as the 5-gram ‘winners posted end 2- week period’. In this way, we can capture some characteristic word combinations and also increase the number of features. For example, in the whole Yahoo hierarchy from 317,522 features representing single words (before removing low frequency features) we get 1,410,303 features (before removing low-frequency features) representing word sequences containing one or two words.

The 20 most frequent features among 255,602 features including up to five consecutive words used in the whole Yahoo hierarchy represent the following words: services, information, page, web, Internet, software, links, systems, design, university, computer, products, service, site, home, music, business, international, online, world having frequency from 37,792 (services) to 15,056 (world). Features with the lowest frequency among the included features mostly represent longer word sequences (e.g. worldwide marketing? website design service, funded programme provide assistance training). The proportion of words with higher frequency is much smaller than the low frequency words. For instance, among 255,602 features, about 3300 features have frequency greater than 300, about 8500 greater than 100 and about 67,000 greater than 10 (see Fig. 6). In our experiments, we removed all the features with frequency less than 4, thus our frequency graph in Fig. 6 shows only the features that occur four or more times (the minimum value at y-axis is 4).

We additionally reduce the high number of features by pruning low frequency features as suggested in Refs. [11,17,45]. The process of feature generation is performed in passes over documents, where i-grams are generated in the i-th pass only from the candidate features of length i-1 generated in the previous pass. This process is similar to the large k-itemset generation used in apriori algorithm [1] for building association rules. Algorithm in Appendix A gives the process of feature generation.

## 5.3. Learning on text data

A separate classifier for each of the defined subproblems is induced using naive Bayesian classifier on text data in a similar way as described in Refs. [17,31,34], or Ref. [36]. In these approaches, documents are represented as word-vectors where a feature is defined for each word position in the document having word at that position as a feature value. The assumption about feature independence used in naive Bayesian classifier is here clearly incorrect. According to Ref. ## 6. Experiments

The approach is tested using our machine learning system Learning Machine [15] that supports usage of different machine learning techniques on large data sets with especially designed modules for learning on text and collecting data from the Web.

## 6.1. Experimental setting

In our comparison, we include 11 feature scoring measures. Information gain given in Eq. (1) was included as the well-known measure used in machine learning and also some text-learning experiments. Three of the included measures were reported to work well on text data: Cross entropy for text in Eq. (3), Mutual information for text in Eq. (4) and a very simple measure proposed in the text-classification domains [45]. This third measure is calculated either as the number of documents that contain word W referred to as document frequency DF(W) or as the number of occurrences of word W referred to as term frequency TF(W). This measure requires the stop words removal. We use the second definition: Freq( $F ) = \mathrm { T F } ( W )$ . Inspired by the way Cross entropy for text is derived from Information gain, we propose Weight of evidence for text as given in Eq. (5).

Preliminary experiments show that Odds ratio is the most promising measure, thus we included four variants of Odds ratio. Random scoring measure included as a baseline measure was defined to score each word by a random number between 0 and 1.

## 6.2. Domain description

The experiments were performed on different domains defined from Yahoo hierarchy as described in Section 5. Results of the naive Bayesian classifier are given on domains representing five of the top 14 Yahoo categories, whose characteristics are given in Table 1.

In our experiments, we observe the influence of the number of selected features to the system performance. The number of selected features is measured here relatively to the category size expressed by the number of features in positive examples. We refer to this relative number of features as Vector size, since it determines the size of the vectors used to represent the documents. For instance, if we have 100 different features in positive examples and we set the vector size to 0.5, the feature selection takes $1 0 0 \times 0 . 5 = 5 0$ best features from all the features (collected from positive and negative examples and sorted according to their score). Recall that we get our categorization results from the set of independent classifiers, each potentially having different number of features. Thus, we express the vector size as a factor of the number of features in positive examples, since the set of negative examples is the same for all the classifiers. In this way, a classifier for a larger category is using more features than a classifier for some smaller category, while both classifying the same testing example.

Reported are classification results on independent set of (500 for the bigger and 300 for the two smaller domains) testing examples selected randomly from the actual Web documents accessible from the corresponding hierarchy domain. The reported results are averaged over five repetitions using hold-out method, i.e., we keep 500 (300) items from Yahoo Web documents out of the training data. The actual Web documents these items point to are used as the testing documents.

## 6.3. Evaluation

Precision and recall are model quality estimates commonly used in information retrieval. Precision is defined as proportion of correctly classified examples in the set of all examples assigned the target class value (similar to classification accuracy measured for one class value), while recall is defined as the proportion of correctly classified examples out of the all examples having the target class value. Precision and recall should be maximized. An ideal system would have precision and recall of (1) Perfect precision can be achieved by a system that classify no example into the target class value, while perfect recall can be achieved by a system that classify all examples into the target class value. Thus, usually the value of both is reported. Evaluation measures for text-classification systems are discussed in more details in Ref. [26]. $F _ { - }$ measure is a combination of Precision and Recall commonly used in information retrieval, where the relative importance of each is expressed with the value of parameter b $. F _ { \beta } = ( ( 1 + \beta ^ { 2 } ) \mathrm { { P r e c i s i o n } \times \mathrm { { R e c a l l } ) / \beta } }$ $( \beta ^ { 2 }$ Precision + Recall). $F _ { 0 }$ is the same as precision, $F _ { \infty } ;$ is the same as recall, $\beta$ can have values between $0$ and $\infty$ . Usually, results are given for $\beta$ values of 0.5 (we care more about precision than about recall), 1.0 (we do not have preferences regarding precision or recall) and 2.0 (we care more about recall than about precision). Additional to precision and recall, we report $F _ { 2 } ,$ since we care more about recall than about precision. Namely, for the user that wants to classify a new document, it is easier to ignore few categories among the predicted categories than to check the rest of several hundreds or thousands categories to find the missing ones.

We report average Precision and Recall for category prediction and for keyword assignment. The data provided in Yahoo hierarchy 4 enables mapping from predicted categories to keywords. Precision and Recall for each testing example is calculated based on the set of correct categories (keywords) and the set of predicted categories (keywords). In the experiments by the predicted categories, we mean all the categories whose classifier predicts probability over 0.95 that the document is a member of the corresponding category. The predicted set of keywords is obtained as a union of the keywords assigned to all the predicted categories. In other words, Precision and Recall are calculated for the fixed probability threshold that is here set experimentally to 0.95 (for details, see Ref. [16]). Notice that one testing example can be originally assigned to several categories, since it can be referenced from several parts of the hierarchy. In such case, all these categories are taken as correct and also used to form the set of correct keywords and compared to the set of predicted categories (keywords). Predicting any of the correct categories is sufficient for the correct classification.

Additionally, we report two values that nicely match our intuition, rank and probability assigned to the correct category. For each testing example, we observe a list of categories each assigned a probability as the result of consulting the corresponding subproblem classifier. Sorting categories according to that probability gives ranking that we use to get the rank of the correct category. For instance, in the classification results given in Table $^ { 4 , }$ the correct category has predicted probability 0.999932 and is the topmost category (it is assigned rank 1). In case of several categories having the same probability, the middle rank is taken, i.e. 2 in the case of 3 top categories having the same probability and 1.5 in the case of 2 top categories having the same probability. If there are more correct categories, the one with the highest predicted probability is considered. To get summary results over testing examples, we give median with the lower and upper quartile. The reason for reporting median instead of the mean value is that some of the testing examples are rather nontypical of their category, containing, e.g. a welcome page or only one sentence asking for language preference or an error message or a page giving redirection. These nontypical examples can be detected by the system from the low probabilities assigned to all categories. In our opinion, for the practical usage of our approach for document categorization, such nontypical examples should be rejected by the system, meaning that human categorization is required. This can also be used to indicate the need for extending the current hierarchy. Here we include them in testing in order to get a fair estimate of the system performance.

In order to enable operational usage of the system on larger domains, we include the following pruning mechanisms. When classifying testing example, only classifiers that share at least three highly scored features with the example are considered. More specifically, a classifier is required to assign a nonzero conditional probability given the positive class value P(Wjpos)>0, to at least three highly scored features that are contained in the testing example. We refer here to this condition as pruning level 3. The same conditional probability P(Wjpos) is used in a naive Bayesian classifier when calculating probability that the testing example should be assigned a set of keywords corresponding to the given classifier. In case that none of the features contained in the testing examples is assigned nonzero probability by a classifier, a prior probability is returned (in our case for most classifiers the prior probability of positive class value is < 0.01). To select highly score features, we sort features according to the assigned score and take so many best features as needed that their summary score represents 70% of the summary score assigned to all the selected features. We tested different pruning levels (1, 2,. . . 15) on several domains as described in Ref. [16] and found that level 3 is one of the best performing levels.

## 6.4. Experimental results

Comparison of different scoring measures in Fig. 9 shows rank and probability assigned to the correct category on domain Reference. It can be seen that the best performance in probability is achieved by Odds ratio for vector size 1 – 1.5 and by Cross entropy for text for vector size 0.5– 1. The best performance on Reference in rank is achieved by Cross entropy for text and Term frequency for vector size 0.5. Slightly worse but still very good performance is achieved by Odds ratio for vector size 1–2.

In addition to the classification performance, we observe the number of considered categories to see how the different scoring measures contribute to the efficiency of the classification. Recall that we introduced a pruning mechanism such that during the classification phase, we consider only the categories whose classifiers share a certain number of features with the testing document. This mechanism can be seen as a prephase of classification and works well if properly supported. For instance, if some of the features selected for one category are common to many documents, then this category will be considered for most of the testing documents even though many of the documents do not belong to that category. The common features may have very small influence on the classification performance, but hurt the efficiency. We primarily observe the classification performance in terms of precision and recall and use the number of considered categories only as an additional evaluation. Fig. 10 shows influence of vector size to the number of considered categories in classification when different scoring measures were used. Notice that for most scoring measures, low number of features (small vector size in graphs) gives better performance than high number of features. This shows that our learning algorithm benefits from feature selection that can be seen here as removing noise in the data. It can be seen that for Random scoring, this number grows with the growing vector size. Similar is true for Information gain, but the initial values are much higher and the growth is slower. For the other measures, the number of considered categories remains the same for vector sizes >1.5. The exception is Weight of evidence for text that has the smallest number of considered categories growing from 10 for vector size 3 to 18 for vector size 15. Odds ratio is the second best in the low number of considered categories, significantly better than the other measures that achieve comparable results in rank and probability (Cross entropy for text and Term frequency). Cross entropy for text is the worse in the number of considered categories (65 for vector size 0.5 and almost 80 for the larger vector sizes).

## 7. Discussion

We experimentally compared 11 feature scoring measures on five data sets: Information gain, Cross entropy for text, Mutual information for text, Frequency, Weight of evidence for text, Odds ratio and four variants inspired by Odds ratio as the most promising for our domain and Random that we used as a baseline measure.

## 7.1. Domain characteristics and feature scoring

In our first experiments on learning from text data [34], words were scored using Information gain as given in Eq. (1) and learning was performed using the naive Bayesian classifier the same way as used in Ref. [17]. It turned out that many features with high score were not very useful for our classification problem. Namely, Information gain assigns higher score to the features that make better distinction between class values. One of the practical problems we noticed in our experiments if small feature subset was used is that a new document that should be classified, often contained very few or even none of the selected features and thus was classified to the majority class value (negative). This pointed out that in case of using majority class value as the default classification, efforts should be put in getting better description of the other class values. The problem here is to identify documents that have the positive class value, meaning that one class value (the target class value) is different from the other class value. This additionally confirms that we should focus on the target, and here minority, class value. This is also confirmed by experiments reported here where the best results are achieved using Odds ratio and its variants, that is characterized by favoring features characteristic for positive examples (see Section 3.5).

In our experiments, the best-performing features scoring measures are Odds ratio and its variants, while the worst performing are Random and Information gain. The other scoring measures we tested perform comparable or worse than Odds ratio and better than Information gain. A closer look to the highly scored features by Odds ratio and by Information gain (see Appendix B) explains the huge difference in their performance and poor performance of Information gain. While Odds ratio favors features characteristic for positive examples (high $P ( F | \mathrm { p o s } ) \rangle$ , Information gain does not make distinction between class values. Since we have unbalanced class distribution with most examples having negative class value (for most categories over 90%), most of the features are characteristic for negative examples. This means that most of the features highly scored by Information gain are characteristic for negative class value (just the opposite of Odds ratio!).

## 7.2. Previous findings vs. our findings

Yang and Pedersen [45] give experimental comparison of five measures for feature selection in text categorization on word-vectors representing documents. Their experiments confirm our observation that a rather small feature subset should be used since it gives either better or as good results as large feature subset or all the features. We also agree in the observation that a simple Frequency of feature (used after stop word removal and calculated either using term frequency or document frequency) achieves very good results. For larger subsets (vector size <sub>z</sub> 4), the performance in rank of all methods became insensitive to the additional features (see Fig. 9). For instance, on Reference for larger feature subsets, Odds ratio and Weight of evidence for text achieve about the same rank around 14, Random achieves rank 20– 30, Term frequency around 40 while the other three measures achieve rank about 50. For larger feature subsets (vector size >3), the predicted probability of the correct category is almost 0 for all the measures. We additionally observe that poorly performing scoring measures (Random, Information gain) for smaller feature subsets get better results if more features are included. For larger subsets, the performance of Random and Information gain scoring is not sensible to the additional features. The possible explanation is that more randomly selected features means also selecting more good features.

7.2.1. Information gain: good or bad for text learning?

Our results disagree in the performance of Information gain, which after a closer inspection is not so surprising. Information gain was one of the best performing measures on domains used by Yang and Pedersen [45], while we found it performing similar or worst than random on our domains. The reason for that we find in the difference in our domains (in our case highly unbalanced class distribution in most cases with less than 1% positive examples) and the problem definition (addressing a number of binary problems as we have vs. addressing one multiclass problem).

We both use learning for document categorization but different approach to domain definition is used. Their machine learning domain is defined to include one class value for each category, while we split the problem into subproblems each corresponding to one category and having Boolean-valued class. The result of learning is in our case a set of specialized classifiers instead of one huge classifier including a union of features characteristic for different categories. Each of our subproblems is characterized by a highly unbalanced class distribution where the minority class values is the target class value (a document is a member of the category).

The other important issue is the selection of classification algorithm. Yang and Pedersen [45] used k-Nearest Neighbor and Linear Least Square Fit mapping. The specific of Naive Bayesian classifier we are using is that it considers only features that occur in a classification document. This means that a highly scored feature should be features that will probably occur in new documents (have high P(W )). If<sub>\_</sub> $P ( \overline { { W } } ) \gg P ( W )$ , then high value of Information gain means that the second part of Information gain formula $P ( \overrightarrow { W } ) \sum _ { i } \ P ( C _ { i } \mid \overrightarrow { W } ) \log ( ( P ( C _ { i } \mid \overrightarrow { W } ) ) / ( P ( C _ { i } ) ) )$ is high. In other words, knowing that W does not occur in a document brings useful information about the class value. On the other hand, the used classification algorithm is based only on the features that occur in a document. This means that most of the selected features will probably not occur in a document ( P(W) is high). If some of such features occur in a document, then the value of cross entropy between the class variable and the feature occurrence is important. In other words, the first part of the formula is important but the feature was selected because of the high value in the second part of the formula. Our hypothesis that a good feature selection measure should take into account characteristics of the used classification algorithm is confirmed by the experiments. Cross entropy for text achieves very good results in our experiments. It equals Information gain calculated only for one of the feature values—W meaning word does occur.

In Ref. [45], tested scoring measures are compared across several criteria: favoring common features, using class value, using feature absence and experimental performance. They conclude that the three measures (Frequency, Information gain and $\chi ^ { 2 }$ statistics) achieving the best results on their domains (Reuters-22173, a subset of MEDLINE) all favor common features.

## 7.3. Conclusions and open questions

Table 8 gives characterization of the feature scoring measures compared in our experiments. We also observe if the feature scoring measure makes difference between the class values that is important for our domains having one class value as the target class value. The best results are achieved by Odds ratio and its variants that assume the problem has Booleanvalued class and one of the class values is the target class value (asymmetric misclassification costs). Between these measures, no significant difference in performance was observed. The next group of measures achieving good results all favor common features (Term frequency, Cross entropy for text, Weight of evidence for text). Mutual information for text differs from Cross entropy for text only in not favoring frequent features and achieves worse results. Information gain differs from Cross entropy for text only in using feature absence and achieves poor results.

Our conclusion is that in general the most important characteristics of a good feature scoring measure for text are: favoring common features and considering domain and algorithm characteristics. For learning algorithms that ignore feature absence (e.g. a naive Bayesian classifier on TF-document representation we are using), it is important that a scoring measure also ignores feature absence. For the domains with binaryvalued class where one class value is the target class value, the most important characteristics of a good feature scoring measure is to make difference between the class values and favor features characteristic for the target class value.

In this way, the selected features are features expected to have the greatest influence to the posterior probability of class values returned by naive Bayesian classifier. ## Appendix A. Algorithm for n-gram generation

Algorithm in Fig. 14 gives the whole process of new feature generation. In the first pass, all single words not contained in the ‘stop-list’ and having sufficient frequency (here we check for frequency >3) are taken LargeNGramSet. Word sequences of size 2 up to MaxNGramSize (here set to 5) are generated using several pruning criteria. In each pass, all documents are checked one by one using a window NGramQueue to get a sequence of words. Before the next word is added to the window (a window is moved one word to the right), the word is checked for being a proper word (not a number or a special symbol), for not being in the ‘stop-list’ Stop-WordSet and for being included in the current set of word sequences LargeNGramSet. The window is reset when the next words is not a proper word or is not included in the set of word sequences generated so far.
