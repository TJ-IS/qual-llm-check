# User Interface Consistency Across End-User Applications: The Effects on Mental Models

JOHN W. SATZINGER AND LORNE OLFMAN

JOHN W. SATZINGER is on the faculty of the CIS Department of Southwest Missouri State University. He holds a Ph.D. in MIS from the Claremont Graduate School and was on the faculty of the University of Georgia from 1991 to 1996. Dr. Satzinger has published articles on user interface design, group support systems, and end-user training in journals such as Journal of Management Information Systems, Database, Accounting, Management, and Information Technologies, and Information Systems Management. He is also coauthor of The Object-Oriented Approach, a book on object-oriented information system development.

LORNE OLFMAN is Associate Professor of Information Science at Claremont Graduate University (formerly Claremont Graduate School). Dr. Olfman's research interests are in the areas of organizational memory and end-user training. He has been involved in promoting these two research domains through research studies, and through coordination of mini-tracks at the Hawaii International Conference on Information Systems and the AIS Americas Conference.

ABSTRACT: Consistent user interfaces across applications are thought to facilitate transfer of learning because a user can draw on existing knowledge when using a new application. But despite the interface consistency guidelines and standards that are based on transfer of learning assumptions, few studies have investigated the effects of interface consistency, especially when a user interacts with multiple applications. The user's knowledge of a computer application is often described as a mental model. This study tested whether the consistency of the user interface across applications affects mental-model development when a user learns and uses multiple applications. One hundred and fourteen participants learned two prototype cooperative work applications in a controlled laboratory setting. Interface consistency across applications was manipulated for two attributes commonly referred to in interface design guidelines: the visual appearance of the display screen and the action language syntax. As hypothesized, inconsistent action language syntax across applications resulted in more user actions to complete tasks. Inconsistent visual appearance, however, resulted in greater accuracy, which was surprising. This study provides support for the consistency guideline for action language syntax, but a distinctive visual appearance rather than a consistent one might help the user form more accurate mental models when initially learning multiple applications. Schema theory is used to explain both the expected and the unexpected results. Implications and promising research directions are proposed.

KEY WORDS AND PHRASES: interface consistency, mental models, user interface, user learning.

A WIDELY ACCEPTED USER INTERFACE DESIGN GUIDELINE is to provide consistent user interfaces for end-user application programs [32]. Consistent user interfaces across applications are thought to facilitate ease of learning and use, because if all applications look and operate the same way, a user can draw on existing knowledge when learning any new application [3]. The user's knowledge of an application is often described as a mental model or schema [6, 15, 39, 45], and the process of applying knowledge from one application to another is referred to as transfer of learning [21, 35].

The transfer of learning assumption behind the user interface consistency guideline led to interface design standards advocated by industry leaders such as IBM, Microsoft, and Apple $[2, 4, 26]$ . The benefits of consistent user interfaces across applications are thought to be so salient that application developers have tried to enforce copyrights for the look and feel of successful user interface designs $[42, 43]$ . The proliferation of end-user applications and client-server organizational systems makes ease of learning and use a critical consideration for information systems managers $[48]$ . At the same time, it is becoming clearer to both application developers and information systems researchers that creating applications that are easy to learn and use is extremely difficult $[16]$ . Controlling the consistency of applications remains a complex if not impossible task $[32]$ .

A few researchers have challenged the desirability of interface design standards based on the consistency guideline, largely because too much emphasis on interface consistency can focus designer attention away from carefully studying and supporting the user's task $[1, 16, 18]$ . Further, researchers working on the next generation of user interfaces argue that inevitably it will be necessary to break free of current interface standards to be able to take advantage of innovative interface devices and interaction techniques $[22, 30, 33]$ . Applications developers may increasingly need to evaluate the effects of departures from interface consistency when making design choices. Information systems managers may increasingly need to consider the effects of interface consistency when adopting end-user packages and when developing client-server organizational systems.

The key to understanding the user performance effects of interface consistency is better understanding of the process behind the development of the user's mental models of multiple applications, particularly the way the development of one mental model affects another. Learning each computer application is an ongoing process; changes in user knowledge occur with each use [7]. Although previous research has demonstrated that transfer of learning occurs in the computer domain [14, 19, 21, 51], no studies have been found that examine the effects of interface consistency when a user interacts with multiple applications. The type of consistency or degree of consistency required to facilitate the development of accurate mental models for multiple applications remains largely unexplored. The user interface is so complex [29] and user interface consistency has so many dimensions [18] that a series of carefully controlled studies will be required before the effects of user interface consistency can be better understood.

This paper integrates key concepts about the user interface, interface consistency, and the mental-model development process, and then reports the results of a laboratory experiment that tests whether the consistency of some key attributes of the user interface across applications affects the mental-model development process and user performance during initial learning. The attributes of the interface manipulated in the experiment are commonly referred to in interface design guidelines—the visual appearance of the display screen and the syntax of the action language $[25]$ . These two attributes make up part of the “look” and the “feel” of the interface, respectively $[22, 23]$ .

The attributes manipulated in the experiment are precisely defined in terms of the four-level model of the user interface proposed by Foley and van Dam $[13]$ . Inconsistent visual appearance was operationalized by changing some syntactic and lexical attributes of the presentation language across applications, resulting in two different display screen layouts. Inconsistent syntax of the action language was operationalized by changing the sequence required for selecting objects and operations in the menus, resulting in two different menu hierarchies across applications. All other attributes of the interfaces were carefully controlled. Therefore, the laboratory experiment tests the effects of two out of a large set of possible interface inconsistencies across applications as a first step. The discussion of the key concepts in this paper provides the foundation for a larger program of research.

## The User Interface and Research on Interface Consistency

THIS SECTION REVIEWS USER INTERFACE CONCEPTS AND THE TYPES of user interface consistency to provide a foundation for this research. Previous research on user interface consistency is then reviewed, and the need for additional research is discussed.

## The User Interface

To Moran [29], the user interface consists of everything the user comes into contact with while using the system—physically, perceptually, and conceptually. The user's conceptual view of the interface develops from the total behavior of the system, so the interface is more than an add-on component of an application. Generally accepted models of the user interface [3, 16, 23] are based on the language model of human-computer interaction [13]. Human-computer interaction is viewed as a form of communication between two parties that have quite different sending and receiving capabilities. For example, the computer has traditionally been limited to displaying messages and symbols on a screen. At the same time, the computer is also quite limited in its ability to receive and interpret information. Therefore, the human user is typically required to specify information for the computer using keys on a keyboard or clicks of the mouse.

Designing the user interface, then, involves designing two languages that differ in the way communications between user and computer are expressed. The two languages are commonly referred to as the action language and the presentation language [3, 16]. The action language, expressed by the user, is used to tell the computer which operations to perform on the objects in the application. The presentation language is used by the computer to ask about the objects and operations requested and to provide the resulting information. Both languages allow communication about a common task domain.

Foley and van Dam [13] developed a four-level model of the user interface represented in figure 1. The concepts in this model are used extensively in the sections that follow. The first level, the conceptual model, defines the task domain about which the user and computer communicate (the objects manipulated, the relationships among objects, and the operations possible to manipulate objects). The next three levels define the semantic, syntactic, and lexical levels of the two related languages that are required for communication to occur.

The action language and the presentation language each have a semantic, syntactic, and lexical level. The semantic level refines the meaning of the words in the language (these follow from the concepts developed into the conceptual model). The semantic level also includes objects defined as part of the presentation language that control or support human interaction, such as a menu object, a dialog box object, or a prompt object. Therefore, the physical implementation details of the user interface begin with the semantic level.

The syntactic level defines the grammar used to combine words into sentences. For the presentation language, syntax includes visual arrangement, such as shape and size, and temporal arrangement, such as when objects appear or disappear. For the action language, the syntax defines the sequence of user actions required to complete a message. The lexical level defines the way words in the language are actually expressed. For the presentation language, a word might be expressed by displaying text or symbols using various combinations of font, color, and line. For the action language, a word might be expressed by pressing a particular key or clicking the mouse over a particular object on the screen.

## Types of Interface Consistency and Previous Research

Interface consistency across applications, the focus of this paper, is one of three types of interface consistency important to interface design. Any one application might be internally consistent in terms of design choices made at any level of the user interface (internal consistency). Any one application might also be more or less consistent with the task environment of the user (analogical consistency). Interface consistency across applications (external consistency) refers to the extent to which similar design choices at all four levels of the interface are made for two or more applications. The degree of interface consistency across applications is quite difficult to define $[44]$ . Figure 2 reviews the types of interface consistency and highlights the attributes of the interface manipulated across applications in this study. For a complete discussion of the types of interface consistency, see Grudin $[18]$

Relatively few empirical studies have addressed user interface consistency. A few studies have reported benefits resulting from internally consistent action languages [17, 37]. One study, reported by Kellogg [20], manipulated the internal consistency of the conceptual model of an electronic mail application. Learning and performance benefits resulted from consistency. Analogical consistency has also been found to benefit initial learning because the user is already familiar with the underlying conceptual model [9]. User training studies have also investigated the benefits of emphasizing analogical consistency in training materials to leverage existing user knowledge during the mental-model formation process [11, 45].

Figure 1. Four Levels of the User Interface

No studies have examined the effects of external consistency on the development of multiple mental models, although transfer of learning from one application to another has been the focus of previous research. Kieras and Polson [21] propose the cognitive complexity model, based on the GOMS model of Card, Moran, and Newell [8], to predict transfer of learning from one application to another. Tests of the model have shown rules known for operating one application are applied when using a new application. One experiment investigated transfer of learning from one word processor to a new version of the same word processor with changes in the action language [14]. Differences in action language structure (syntax) were not difficult to transfer, but changes in command names (semantics) were difficult. Another experiment examined transfer effects from one word processor to a different word processor [19]. Differences in action language structure (syntax) were more difficult to learn than different key assignments for commands (lexical). It should be noted that the applications used in these studies were commercial applications, and specific types and degrees of inconsistencies across applications were difficult to isolate and operationally define.

![](/api/attachments/S97RHUTW/fulltext/images/f930aad55a6fb2ff0ac367821659d23dd33ee6ee8a56c6f33dda4f98ce9704cf.jpg)  
Figure 2. Types of Interface Consistency and the Interface Levels Manipulated across Applications (\* indicates levels manipulated in the experiment reported here)

Only one study investigated transfer of learning from one application to another application of a different type $[51]$ . The two applications included a text editor and a graphics editor, both with graphical user interfaces. The objects manipulated in the applications differed, but the operations performed and the procedures followed were structurally equivalent in terms of Kieras and Polson's model $[21]$ . Transfer effects were observed; however, interface consistency was not manipulated.

Karat et al. [19] concluded that there was a need for studies using a framework that more carefully controls the attributes of the interface when studying the effects of interface consistency. In addition, the model is difficult to operationalize for some types of consistency [35], and the effects of consistent visual appearance are not taken into account. This paper responds to these concerns by using the Grudin [18] framework and the Foley and van Dam [13] interface model to describe and manipulate the consistency of applications (described above).

However, there are several other issues raised by the Kieras and Polson approach that must be addressed in interface consistency research. First, Karat et al. [19] concluded that transfer of learning studies should be conducted across different applications, particularly where the user might routinely switch between applications. Second, the Kieras and Polson transfer of learning model applies more to expert users and might be misleading with novice users [50]. Therefore, the next section develops the case where users routinely learn and use multiple applications, explained in terms of mental models and grounded in user training research.

## Multiple Applications and the Mental-Model Development Process

A USER'S KNOWLEDGE OF A COMPUTER APPLICATION, FOR EITHER a novice or an expert, can be described as a mental model [6, 15, 45, 49, 50]. In information systems research, the terms “user's model” and “user's conceptual model” are often used interchangeably with mental model [3, 16, 29]. How the user's mental model is formed and expanded is a central concern of user training research (e.g., [11, 46]), so research on the effects of interface consistency across applications on the mental-model development process can draw on Bostrom, Olfman, and Sein's [7] user training framework. However, research involving multiple applications requires consideration of additional factors beyond interface consistency. Therefore, a multiple application research model was developed for this study to extend the user training framework.

## Multiple Application Research Model

Bostrom, Olfman, and Sein [7] model user learning as a multistep process. Initially, characteristics of the system, characteristics of the user, and characteristics of the training environment interact to change the user's knowledge of an application. Later, when using the application to complete tasks, changes in user knowledge continue. Therefore, the user's mental model of an application continues to develop over time.

The multiple application research model extends the user training framework by adding additional factors that apply when a user learns and uses two applications (figure 3). The first additional factor is degree of interface consistency across applications, which is explored in this paper. The other additional factors, degree of integration and degree of concurrent use of the applications, are expected to interact with user interface consistency, so they must be controlled in interface consistency experiments. Degree of integration is defined as the extent to which multiple applications share data objects. Degree of concurrent use is defined as the extent to which multiple applications are used during the same work session. For a complete description of the multiple application research model, see [44].

Other factors are retained from the user training framework. The training environment and the task environment are expected to affect the mental-model development process in the case of multiple applications. In addition, user characteristics such as cognitive traits, prior experience, and motivation affect the mental-model development process $[7, 45, 46]$ .

## Performance Indicators

User performance is the outcome of interest in user training research [45], and changes in the accuracy of the user's mental model of an application are usually used to explain performance effects. The relationship between accurate mental models and performance is well established. Users with more accurate mental models are thought to make fewer mistakes and to interact with the system more efficiently $[49]$ . This is because the mental model is used to anticipate the effects of actions and therefore determines actions performed $[29]$ . The actions performed (correct or incorrect) and the speed with which they are performed (faster or slower) are typical user performance indicators in user training research $[46]$ . User performance indicators have also been used to infer transfer of learning in tests of the cognitive complexity model $[21, 35]$ .

The relationships among the performance indicators are complex. For example, faster performance might be attempted at the expense of correctness, or correctness might be attempted at the expense of speed, regardless of the accuracy of the mental model. Therefore, a set of performance indicators and a multivariate test are desirable when studying user learning and performance.

## Schema Theory and Mental-Model Development

Schema theory [5, 39, 40] can be used to explain the mental-model development process when a user learns and uses computer applications. Schemata are knowledge structures that store concepts in human memory, including knowledge of how to use the concepts. They are used when interpreting sensory data, retrieving information from memory, organizing actions, and determining goals and subgoals. Each schema is linked to a network of sub-schemata that collectively represent an individual's knowledge about a domain. Rumelhart [39] describes the central function of schemata as constructing interpretations of events, objects, or situations (i.e., the process of comprehension). Schemata are also used to mentally run scenarios to anticipate the effects of actions [50]. A schema is activated when incoming sensory information fits the pattern of concepts and relationships represented in the schema. Once activated, additional information that helps explain the external situation is inferred based on associated sub-schemata that are in turn activated. The set of schemata activated at one time makes up our mental model of the situation faced at that time [39, 50].

In schema theory, learning is thought to involve either adding additional facts to existing schemata (accretion), making minor changes to existing schemata to account for a more sophisticated view of the world (tuning), making major structural changes to schemata based on new information (restructuring), or creating entirely new schemata when existing schemata do not account for observed phenomena (schema induction) [40]. Accretion and tuning are the more common learning processes. Tuning, for example, can involve replacing a constant with a variable and a range of possible values, or it can involve generalizing separate facts to a constant that universally applies. Restructuring and schema induction result only after considerable effort [39].

Since a schema is organized as a network of associated concepts and structures (sub-schemata), it is reasonable to think of a user's mental model of a computer application as a network of associated schemata. Learning a computer application might involve learning new concepts and procedures, and also establishing appropriate associations and then tuning existing knowledge. Associated schemata may include knowledge of the task the application supports, knowledge of general computer concepts, and knowledge of other known computer applications. Once activated, changes in all associated schemata might occur when interacting with a computer application. Therefore, a user's knowledge of all computer applications might continue to change each time any one computer application is learned or used. See Shneiderman's [47] syntactic/semantic model of user knowledge for a comprehensive framework describing the types of knowledge required to understand and use computer applications.

## Interface Consistency and Mental-Model Development

Learning a new application with a consistent user interface might involve accretion and tuning of existing schemata. On the other hand, learning a new application with an inconsistent user interface might require restructuring existing schemata or even schema induction, both of which require more effort $[39]$ . Further, the restructuring process might have a detrimental effect on knowledge of other computer applications if inconsistent (or incorrect) knowledge becomes associated with existing schemata, although restructuring is probably less likely when the user knows the other application well. Mental-model researchers refer to this detrimental effect as interference $[49]$ . Learning an inconsistent application will not only be more difficult, but might also result in inaccurate mental models of other applications.

In addition, since schemata are activated based on sensory input [39], the visual appearance of an application (presentation language) might affect which schemata are activated when learning or using the application. Users rely on visual similarities when differentiating between known and unknown systems [49], and if a new application appears similar to previously used applications, activation and then accretion and tuning of existing schemata might be facilitated. On the other hand, if the new application appears different from previously used applications, the number of inferences made about the application based on existing knowledge might be reduced and learning by accretion and tuning might be inhibited.

Both consistent action language and consistent visual appearance across applications might independently affect the mental-model development process. But there is also a possible interaction effect between the appearance of consistency and the actual consistency of the action language. If consistent visual appearance activates schemata of similarly appearing applications but the action language is actually inconsistent, then the accuracy of both mental models might be affected. The user's knowledge of the second application might be incorrect when the wrong rules are inferred from knowledge of the first application. At the same time, the user's knowledge of the first application might more likely be incorrectly restructured. Therefore, an application that appears consistent but is actually inconsistent with another application in some way (perhaps in the conceptual model or in the action language) might be the most detrimental design choice.

The effects of interface consistency across applications might also depend on the nature of the applications and the way they are learned and used. For example, integrated applications share many common concepts, so they probably share more sub-schemata than nonintegrated applications. Therefore, changes in knowledge about one integrated application might more easily result in changes in knowledge of the other. The benefits of consistent interfaces and the detrimental effects of inconsistent interfaces might both be magnified with integrated applications. Further, when two applications are used concurrently to complete a work task, schemata associated with both applications are activated in rapid succession. Therefore, it is more likely that changes in knowledge of one application result in changes in the other. Again, the benefits of consistency and the detrimental effects of inconsistency might both be magnified when two applications are learned and used concurrently $[44]$ .

## Hypotheses

Based on this discussion of interface consistency, learning, and user performance, two main effects and one interaction effect were hypothesized (stated below in alternative form). The first hypothesis addresses the effect of consistent visual appearance of applications: whether similar visual appearance activates schemata of similar applications to facilitate accretion and tuning, resulting in more accurate mental models and thus better performance. The second hypothesis addresses the effect of consistent action language syntax for operating the applications: whether applications using consistent action language syntax result in accretion and tuning without restructuring, thus resulting in more accurate mental models and better performance.

H1: Consistent visual appearance of the user interface across applications will result in better user performance when a user initially learns and uses both applications.

H2: Consistent action language syntax for the user interface across applications will result in better performance when a user initially learns and uses both applications.

A third hypothesis was proposed based on the possible interaction effect of consistent visual appearance and inconsistent action language syntax for two applications: whether a consistent appearing application that incorporates inconsistent rules of operation might have the most detrimental effect on the mental model development process.

H3: Consistent visual appearance of the user interface when the action language syntax across applications is actually inconsistent will result in poorer performance when compared with applications that have both inconsistent visual appearance and inconsistent action language syntax.

## Research Method

## Participants

PARTICIPANTS IN THE EXPERIMENT INCLUDED ONE HUNDRED AND FOURTEEN undergraduate students enrolled in an introductory management information systems course at a western university. They were offered extra course credit for participating in a two-hour training session where they would learn how to use two new computer applications. The sessions were conducted in a training lab that contained IBM PS/2 personal computers with color monitors and mice. The participants were chosen because they were novice computer users with no previous exposure to cooperative work applications and limited knowledge of interface design principles and guidelines. Most of the participants' computer experience was in an introductory computing skills course previously taken at the university.

## Treatments

Two applications supporting cooperative work were designed specifically for the experiment. The first is called NUCLEUS; it supports creating work groups and structuring information used by them. The second is called PIPELINE; it supports communication among work group members during and between meetings. These two applications were designed to work together to support work group tasks. They have consistent (and integrated) conceptual models in terms of the objects manipulated and the operations performed (figure 4).

Semantic-level design choices for both applications are also consistent: They both use menus, dialog boxes, selection lists, prompts, error message boxes, and data entry panels with buttons and check boxes. Finally, action language lexical design choices

Work group members then use the information structure by either browsing through it or typing in additional information. Any person can review work groups to see a summary of the work group. The two independent variables were the degree of consistency of the visual appearance and the degree of consistency of the action language syntax across applications. Consistent versus inconsistent visual appearance was operationalized by designing two versions of the presentation language that could be used for either application. Presentation language syntactic- and lexical-level attributes were therefore manipulated to give two distinct visual appearances to otherwise consistent applications. $^{1}$ One design allows menus, dialog boxes, and panels to overlap on the screen, while the other design places menus in a separate area of the screen. The designs also differ in the location of prompts. These are the syntactic-level differences. Lines appearing on the screen and background color also accentuate the different appearance of each design; these are lexical-level differences. Neither version resembles the pull-down menu interface style described in design standards (e.g., Windows) to control for any previous experience of participants in the study.

Consistent versus inconsistent action language syntax was operationalized by designing two menu hierarchy structures for NUCLEUS and PIPELINE. The object-first hierarchy places objects manipulated in the first menu and the operations performed in a sub-menu. The operation-first hierarchy places operations performed in the first menu and objects manipulated in a sub-menu. Both designs use the same objects and operations in the action language (semantics), and these menu items are selected with the mouse (lexical). Although the order of selecting objects and operations is merely reversed in the two designs, the user is required to frame different interaction strategies when interacting with the applications, giving them a different "feel." Completing a task with each design requires the same number of user actions, however.

Any combination of the two presentation language designs and action language syntax designs could be used to implement either NUCLEUS or PIPELINE. Presentation language consistency and action language consistency across applications were therefore operationalized as independent dimensions. As a result, a completely randomized, two-by-two factorial experimental design was used. The two main effects hypotheses (H1 and H2) plus the interaction effect hypothesis (H3) were tested simultaneously. The resulting four experimental conditions therefore included having participants learn and use two applications with one of the following:

1. Consistent visual appearance and consistent action language syntax;

2. Consistent visual appearance but inconsistent action language syntax;

3. Inconsistent visual appearance but consistent action language syntax;

4. Inconsistent visual appearance and inconsistent action language syntax.

Figure 5 shows NUCLEUS and PIPELINE screen prints for condition 1. The visual appearance and the action language syntax (menu hierarchy) used are consistent. Figure 6 shows screen prints for condition 4, where both the visual appearance and the action language syntax (menu hierarchy) used are inconsistent. Conditions 2 and 3 were created by using appropriate combinations of these screens.

All versions of the implemented applications were considered equally easy to learn and use in isolation because they include the same ease-of-use features and they are consistent in all ways except as specifically described. Therefore, any performance effects would result from interface consistency across applications and not from differences in ease of learning and use for any one version of an application. Several information systems doctoral students evaluated the designs to confirm this. All design choices were also evaluated in terms of preference using undergraduate student subjects, and no differences were found in preference for all combinations of visual appearance and menu hierarchy designs.

## Procedure

Participants signed up for one of fourteen two-hour sessions. Upon arrival at the computer lab, participants were randomly assigned to a computer preloaded with the software for one of the experimental conditions. They then completed a short background questionnaire on computer experience. Next, the participants worked individually through a tutorial manual to learn the basics of both applications. The first part of the manual briefly described the two applications and explained that the tutorial versions of the applications only simulated multi-user versions—a message sent to a person was not actually received, for example. The second part of the manual included step-by-step instructions that led participants back and forth between the two applications. For example, first they created a work group using NUCLEUS, and then they sent a message to all work group members using PIPELINE. Next they added a new work group member using NUCLEUS, and set up a meeting for the work group using PIPELINE, and so on.

## Dependent Variable

User performance was the dependent variable assessed by three performance measures. The first performance measure was the accuracy of the work completed when interacting with both applications. For example, each participant created and modified work groups, sent messages and scheduled meetings, and created and modified information structures for use in meetings, alternating between NUCLEUS and PIPELINE. The accuracy of the work completed for each participant was objectively scored using an answer key by one evaluator in random order and blind to treatment. One point was assigned for each defined outcome on the answer key. For example, one point was assigned for each of the following for creating a work group: It was created, it was created only once, the title was correct, the objective was correct, the leader was correct, and the members were correct. A higher overall score was thought to indicate that participants developed more accurate mental models because they could concentrate on task completion rather than system operation. Less accurate mental models might require the user to divide attention between the task and the operation of the application.

The second user performance measure was the number of user actions required to complete the experimental tasks. A log file captured a record of each user action. Fewer interactions with the applications indicated more accurate mental models because fewer incorrect selections and less backtracking to make corrections occurred. Errors of this type are referred to as slips $[34]$ , which would be expected to occur if knowledge of one application were incorrectly applied to the other application when the applications are inconsistent.

The third user performance measure was the overall time to complete the experimental tasks. Less time to complete the tasks indicated more accurate mental models of the applications. With inconsistent applications, more time might be spent deciding what to do or backtracking to make corrections. The log file captured the time of each user action, so the overall time to complete all tasks was captured automatically.

Since the three user performance measures are indicators of one dependent variable, they were expected to be highly correlated. In addition, the relationships among user performance measures were expected to be complex. Therefore, MANOVA was selected as the appropriate statistical procedure for data analysis because differences for the three measures could be evaluated simultaneously.

## Controls

The applications were integrated and used concurrently, which controlled for the other multiple application factors (see figure 3). Degree of integration of the applications was controlled by designing integrated applications specifically for this study. Degree of concurrent use of the applications was controlled by the specification of the order of tasks completed. Participants switched back and forth between applications when completing tasks. The training environment was controlled by having participants learn and use both applications in one session. User characteristics were controlled by random assignment. Responses on the background questionnaire were used to test the effectiveness of random assignment (number of applications previously used, frequency of computer use, length of computer use, access to a computer, and previous use of a mouse), and no significant differences were found. $^{2}$

## Results

ALL PARTICIPANTS COMPLETED THE TUTORIAL AND EXPERIMENTAL TASKS within the allowed time. $^{3}$ Generally, participants were quite interested in the applications, worked carefully through the session, and thought the applications were relatively easy to learn and use (based on written comments made at the completion of the session).

Table 1 summarizes the means and standard deviations for the three performance measures. The scores for accuracy of the work were relatively high, averaging almost 30 out of 34 possible points. Fifteen percent of participants received perfect scores. The average number of user interactions recorded was 184, well over the 129 required to complete the tasks without errors or slips. The experimental tasks took on average just over 16 minutes. As expected, the three user performance measures were correlated (all p < 0.01). Participants completing the tasks more accurately took less time (r = -0.32) and required fewer interactions (r = -0.30). Those taking more time made more user interactions (r = 0.64). A power analysis [10] indicated that the experimental design would detect a medium effect size of 0.26 (for power of 0.8). This indicates that the design could detect mean differences of 1 accuracy point, 14 user interactions, and 1.4 minutes in terms of the three dependent measures of accuracy, user interactions, and time, respectively. Cohen's criterion for a medium effect size is 0.25 for two-way factorial designs, which translates to the proportion of variance accounted for by a main effect (eta $^{2}$ ) of 0.0588.

MANOVA assumption tests indicated the need for transformations because, although the univariate homogeneity of variance tests were not significant, the multivariate homogeneity of dispersion matrices test was significant. Natural log transformations applied to user actions and time for tasks corrected this (Boxes M = 24.18, $F_{18,37412} = 1.275$ , p < 0.192) with no change to the MANOVA results.

Table 2 summarizes the results of the MANOVA tests. The visual appearance by action language syntax interaction effect was not significant, so the two main effects were examined. Both the visual appearance main effect ( $F_{3,108}=2.848, p<0.041$ ) and the action language syntax main effect ( $F_{3,108}=5.440, p<0.002$ ) were significant. Therefore, both the consistency of the visual appearance and the consistency of the action language syntax across applications affected user performance. Univariate tests of each performance measure were conducted to interpret these results.

Table 3 summarizes the visual appearance effect for each of the three performance measures. Of the three measures, accuracy of the work was significantly different ( $F_{1,110} = 7.192, p < 0.008$ ). Table 4 summarizes the action language syntax effect; the number of user interactions was significantly different ( $F_{1,110} = 8.869, p < 0.004$ ). Therefore, although user performance was affected by both the consistency of the visual appearance and the consistency of the action language syntax across applications, different measures captured the performance differences.

However, the cell means in Table 5 and the treatment means in Table 6 reveal that the direction of the effects differed for the two independent variables. Consistent action language syntax resulted in better performance in terms of number of user interactions, as expected. However, inconsistent visual appearance resulted in greater accuracy, which is surprising. Only H2 was supported (consistent action language syntax across applications results in better performance). As stated, H1 (visual appearance) and H3 (the visual appearance-action language syntax interaction) were not supported by the data.

## Discussion

WHAT DEGREE OF CONSISTENCY OR TYPE OF CONSISTENCY of the user interface across applications facilitates the development of accurate mental models during initial learning? This study, which focused on the consistency of a few attributes of the user interface, presents some useful, initial insights. Two main findings are discussed below—one that confirms a benefit of consistent action language syntax and one that surprisingly provides evidence for a benefit from inconsistent visual appearance. Both have implications for systems developers and for information systems researchers concerned with underlying theory.

## Consistent Action Language Syntax across Applications

First, even with equivalently easy to learn and use applications, consistent menu hierarchy design strategies across applications produced measurable differences in user performance. The consistency of the syntax of the action language used to communicate with the computer, therefore, seems to affect the mental-model development process and user performance. This finding agrees with studies based on transfer of learning [21, 35] and other studies of action languages [17, 20, 37].

The number of user interactions with the applications was greater when the action languages were inconsistent, indicating that participants made more trial-and-error interactions when completing tasks. Rules known for one application were probably incorrectly applied when using the other application, resulting in errors and slips $[34]$ . In terms of schema theory, it is possible that incorrect associations between schemata or the necessary restructuring of schemata might have resulted in two inaccurate mental models.

Since the inconsistency was introduced in the menu hierarchies, the errors and slips might have been immediately noticed and then corrected quickly by backtracking. Evidence for this follows from the fact that there were no differences in time to complete the experimental tasks. In addition, the accuracy of the work was not measurably affected. Although the degree of inconsistency introduced did not create serious problems for the participants in accomplishing the tasks, the number of user interactions indicated some confusion and uncertainty about operating the applications. Had the action language syntax been inconsistent beyond the menu hierarchies, slips and backtracking in the middle of a task might have resulted in measurable differences in time and accuracy.

Although the proportion of variance accounted for by the main effect was small, and only one performance variable accounted for the performance difference, it should be noted that the experiment manipulated only one level of action language consistency to isolate specific effects. The practical significance of the result is that, if one subtle inconsistency measurably affects performance, the cumulative effect of many such inconsistencies might be detrimental.

This study only measured user performance immediately after an initial training session, but the consistency of the action language syntax would likely continue to make a difference when the applications were later used regularly by end users. With high levels of practice, menu navigation and other procedural steps become near automatic processes, where the execution proceeds outside awareness $[8, 28]$ . Inconsistent menu hierarchies when switching back and forth between two applications, however, would make achieving automaticity difficult. Either the user would have to slow down and consciously attend to the menus or errors resulting from slips might continue to occur $[34]$ .

## Consistent Visual Appearance across Applications

The other important yet surprising result concerns the consistency of the visual appearance of the applications. Here, contrary to design guidelines and standards, inconsistent visual appearance resulted in better user performance, at least as captured by the accuracy measure. It was hypothesized that performance would degrade with inconsistent visual appearance because activation of schemata of similar applications might be less likely. Inferences based on existing knowledge and accretion and tuning of existing schemata might be more difficult. The accuracy of the user's work might be affected because more accurate mental models would allow the user to concentrate on task completion rather than system operation.

Although inconsistent visual appearance was expected to have a benefit when the action language syntax across applications was inconsistent (the interaction effect, H3), the direction of the actual main effect found was not expected. Even though the proportion of variance accounted for was quite small, there are some alternative explanations with important implications. First, since NUCLEUS and PIPELINE are integrated applications, they have many concepts and relationships in common. Using one application might result in activation of a number of shared schemata. Also, since the applications were used concurrently, schemata applying to both applications might remain activated in the user's memory. Therefore, both integration and concurrent use might have washed out the effect of consistent visual appearance. The visual appearance effect might be more powerful with nonintegrated applications or with applications not used concurrently. Additional research on the benefits of consistent visual appearance is certainly called for, and degree of integration and degree of concurrent use of applications are certainly important factors in the multiple application research model to manipulate in future research.

But why did inconsistent visual appearance result in better performance? The integration and concurrent use of the applications, as discussed above, probably led to the simultaneous activation of many schemata. During initial learning and use, the participants might have formed one global mental model of cooperative work rather than two separate cooperative work applications. Consistent visual appearance might have made it more difficult to sort out the separate functions of the two applications. However, inconsistent visual appearance provided visual cues that might have initially helped the participants form two separate mental models. With additional use, the visual cues might have continued to help participants differentiate between the applications, providing feedback about which application they were working with at that moment. With applications learned concurrently, a distinctive visual appearance rather than a consistent one might result in more accurate initial mental models for the applications. Even minor lexical differences in color, font, or line might provide sufficient cues.

The benefits of distinctive visual appearance might also extend beyond initial learning even when applications are not used concurrently. Schemata might be more selectively activated when a user interacts with an application, resulting in less mental-model interference and a lower cognitive load. Another possible benefit might apply when attending to multiple windows. A distinctive visual appearance might aid visual search and facilitate attending to the correct window when working simultaneously with multiple applications in separate windows.

The accuracy effect found in this study should be interpreted with caution. The accuracy scores overall were quite high, resulting in a possible ceiling effect, and the effect size was small. Nevertheless, the issues raised by the higher accuracy scores when learning and using multiple applications with inconsistent visual appearance are intriguing. The psychology literature exploring visual discrimination, defined as the ability to see that two patterns differ in some way, and visual recognition, defined as the ability to know that a pattern being viewed has been seen before, might be used to guide additional research $[27, 41]$ .

## Implications for Developers

Based on this first experiment, there are several implications for systems developers. Consistent menu hierarchy strategies across applications are beneficial, but this is only an indicator of performance improvements when syntactic consistency is manipulated. It is still not clear how to select or even whether to select a standard menu hierarchy strategy. This study did not compare two strategies; it merely measured performance differences when strategies were inconsistent. Both the object-first and the operation-first strategy have merits for these applications (shown in figures 5 and 6 for NUCLEUS). The optimal strategy may be determined by the nature of the user's task. For example, one user might need to perform a series of operations on work groups, such as create a work group, add a member to another work group, and delete yet a third work group. For this user, the object-first strategy is optimal. Another user, or even the same user at a different time, might need to perform a series of create operations for different objects, such as creating a new instance of a person, creating a work group, and then creating information. This time, the operation-first strategy is optimal. In the experimental tasks used for this study, however, both strategies were optimal because the user switched to the other application after completing only one task.

In either case, the resulting menu hierarchy will be intuitive primarily because the objects and possible operations follow directly from the conceptual model designed to support the user's task. Indeed, the one-paragraph description of NUCLEUS shown in figure 4 contains most terms that find their way into the menus themselves: work group, people, information, review, create, modify, copy, and delete. These specific terms were chosen after considering a wide variety of terms to describe the conceptual model of NUCLEUS. To a user, it seemed more natural to describe the application as one where work groups are created or modified (analogical consistency) than one where a new file for a work group is opened and saved or edited and formatted (external consistency to standard window pull-down menu interface designs).

PIPELINE was described consistently with NUCLEUS: Meetings are created or modified for work groups; messages are sent to people or work groups; people participate in meetings and conferences for work groups. This conceptual model is consistent (and integrated) with NUCLEUS in the way it, too, is analogically consistent with the user's task environment. Again, PIPELINE is not described as an application where a new file for a meeting is opened and saved or edited and formatted. In practice, careful consideration of the user's task environment and a clear and meaningful, user-oriented conceptual model of the application might provide benefits that far outweigh consistency enforced through a design standard, even consistent menu hierarchies. Interface consistency and coordinating consistency across applications remain extremely complex to achieve. Nothing is implied by these findings that contradicts the arguments against interface consistency made by Grudin [18].

The possible benefits of distinctive visual appearance might be more immediately useful in practice. New object-oriented application development tools make it fairly easy to generate graphical user interfaces with mouse support, windows, menus, dialog boxes, and buttons. System developers might feel freer to experiment with alternative screen appearance for their applications if it makes the underlying conceptual model of the application clearer to the user. At the same time, a distinctive visual appearance for the application might actually provide benefits in both learning the application and later interacting with the application in multitasking modes, although more research is needed to confirm this effect.

## Limitations

Several limitations of this research should be noted. User performance was measured only after initial training. More differences in performance might have been detected if the applications were used in a later session. In addition, the participants were given clear and appropriate training materials, which helped provide initial mental models of the applications as recommended by Sein and Bostrom [45]. More differences in performance might have been detected if less training were provided; however, initial training was included in the experimental design to help control for differences in participant experience with computer applications.

This research is also limited in terms of the type and degree of consistency tested. Only a few attributes of the user interface were manipulated, and the manipulations were subtle in order to isolate small but important effects. The action language syntax manipulation was limited to the menu hierarchy, where errors and slips were not too costly in terms of accuracy and time. A less subtle manipulation might have allowed a more complete analysis of these errors, providing additional insight. The visual appearance manipulation, on the other hand, did provide a distinctive visual appearance for each application, but the expected visual appearance effect may have been washed out by the integration and concurrent use of the applications as discussed above.

Finally, the applications were relatively easy to learn and use compared with other applications used by participants, which also made performance differences difficult to detect. However, the experimental tasks were arguably as complex as those used in user training studies, and it should be noted that this research is concerned with the effects of interface consistency on the mental-model development process independent of ease of use. Externally consistent applications are not necessarily easy to use, and easy-to-use applications are not necessarily externally consistent. Ease of use was controlled deliberately, as were the training environment, the degree of integration, and the degree of concurrent use.

## Promising Research Directions and Conclusions

Although any number of interface consistency manipulations might be tested in followup studies, additional research seems most promising in several areas. Additional research should be conducted to explore the possibility that distinctive visual appearance of applications aids in the formation of separate, more accurate mental models during initial training. Further, the possibility of a benefit of distinctive visual appearance when interacting with multiple applications in multiple windows should also be explored. Consistent spatial location for windows has been suggested to aid the user when interacting with multiple windows $[28]$ , but, since maintaining consistent location is difficult with window managers, distinctive visual appearance might be an important alternative.

Some other questions about visual appearance remain unresolved. First, does consistent visual appearance for applications facilitate transfer of learning by activating schemata of similar applications? This might best be tested when applications are not learned and used concurrently. Second, is consistent visual appearance for applications that are actually inconsistent in some subtle way a particularly detrimental design choice? This question remains important because information systems managers are increasingly being asked to reengineer existing organizational systems to client-server applications with graphical user interfaces $[48]$ . Redesigning the visual appearance of screens to conform to a graphical user interface standard will not guarantee consistent or easy-to-use applications. But superficial consistency might have additional detrimental effects.

Additional research should also be conducted to examine different types of consistency. Inconsistent conceptual models across applications can introduce inconsistencies in all layers of the action and presentation languages making up the interface. For example, the use of terms to describe the objects in the applications and the operations performed find their way into menus, messages, and prompts. At the same time, the number of applications and the various sources for these applications make it unlikely that these terms will be consistent, even if the applications share data. For example, integrating packages from multiple vendors and integrating organizational systems with end-user applications is becoming more common. Therefore, the impact of consistent conceptual models should be studied.

No one experiment can possibly address all issues concerning interface consistency. As with all information systems research, a series of controlled studies are required. This initial experiment confirmed an effect found in previous studies (consistent action language syntax), but did so across two different applications, with applications other than text and graphics editors, and with the user switching back and forth between the applications. Although the visual appearance results were surprising and inconclusive, the possible benefit of distinctive visual appearance is another important outcome of this research.

We believe our approach to the study of interface consistency and the mental-model development process will lead to greater understanding of how users learn and use computer applications. The attributes of the user interface were carefully manipulated;

the mental-model development process and schema theory were used to predict user performance effects of consistency and to explain the results; a multiple application research model extended from user training research was used to design and control the experiment. We also believe our approach will provide insights that will help application developers evaluate the effects of departures from interface consistency when designing an interface that more effectively supports user tasks. The additional research proposed should help increase our understanding of the effects of interface consistency on mental models.
