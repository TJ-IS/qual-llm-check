## How to use the history

Classify material into four non-interchangeable layers:

1. **authoritative_evidence** — source PDFs/Markdown, Otero corpus, frozen prompts, verified bibliographic records, and corpus-integrity audits.
2. **accepted_workflow_patterns** — prompt confirmation, resumable execution, source-role ledgers, citation-network discovery, data-identity checks, feasibility/withdrawal gates, and bounded checkpoints.
3. **superseded_drafts** — v3, v3.1, v7, v8, v10, and v15, each retained with its replacement reason.
4. **failure_and_user_corrections** — false completion after mechanical scans, construct/citation defects, Goal drift, redundant agent review, late feasibility, and fragmented macro narrative.

Use prior prose as a candidate or counterexample unless the current-state file explicitly marks it accepted. When a task contains both a successful run and failed manuscript work, split those statuses rather than assigning one verdict to the whole task.

## Deliberate exclusions

- Do not copy raw private task transcripts into Git. This catalog contains stable IDs and distilled lessons sufficient for recovery.
- Do not include credentials or configuration values from troubleshooting tasks.
- `Read Codex goal objective` adds no durable research artifact.
- Configuration/task-loading diagnosis belongs to operational history, not the manuscript or screening evidence base.
