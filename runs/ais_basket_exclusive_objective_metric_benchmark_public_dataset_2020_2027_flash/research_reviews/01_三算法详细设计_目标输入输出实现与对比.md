## 算法一：RL 驱动的对抗攻击生成（AttackRL-Agent）

### 1.1 目标（Objective）
给定目标编码智能体 A（黑盒或灰盒）与任务集 T，学习攻击策略 π_att：对任意任务 t，π_att 生成的上下文操纵 c_t（恶意 issue、投毒文档/配置、工具描述变体）以最大概率诱导 A 产出**"功能正确但带漏洞"的补丁**或执行**有害动作**（读取敏感文件、外发数据、执行危险命令），同时满足三个约束：
- 隐蔽性：被现有 guardrail/检测器发现的概率 ≤ δ（与研究二联动）；
- 多样性：攻击覆盖攻击面分类的多个通道（越狱/注入/投毒/供应链）；
- 可迁移性：跨 scaffold/模型有效。

形式化：maximize E[ASR] = E_{t~T, c~π_att}[1{harmful(A(t, c))}]，约束 detector 发现率 ≤ δ。

### 1.2 输入（Input）/ 输出（Output）
输入：
- 目标 agent 的可调用接口（输入 issue/上下文 → 输出轨迹与补丁）；
- 任务集：SWE-bench Verified 子集（公开）；
- 上下文通道 schema：issue 文本、仓库文件（README/文档/配置）、工具描述（MCP schema）；
- 危害判定器：漏洞检测（CodeQL 安全规则/安全 lint）+ 有害动作清单（敏感路径、命令黑名单）；
- 攻击面分类（来自 JAWS-Bench/AgentDojo 的公开攻击类别）。
输出：
- 策略网络权重 π_att（生成式条件文本策略）；
- **攻击库 D_att**：大量（任务, 操纵后上下文, agent 轨迹, 结果标签）样本——研究二/三的直接输入；
- 评估报告：ASR、隐蔽性（被基线检测器发现率）、多样性（类别覆盖）、可迁移性（跨 2–3 个 scaffold/模型）。

### 1.3 实现方式（Implementation）
1. **对抗 MDP**：状态 s_t =（任务嵌入, agent 轨迹前缀摘要, 已注入内容）；动作 a_t = 一次上下文编辑（先选通道 c∈{issue, 文件, 工具描述}，再生成内容）；转移 = agent 在沙箱中执行后的环境更新；奖励 r = 危害信号（漏洞补丁 +1 / 有害动作 +1 / 拒绝或正常 0）− λ·检测器得分（隐蔽惩罚）− κ·编辑成本。
2. **层次生成式策略**：高层分类头选择攻击通道；低层条件文本生成（微调 LLM 或冻结 LLM + 可学习编辑 token）。用 PPO 更新（与 RLbreaker 同族，但动作空间是"仓库上下文编辑"而非纯文本回复）。
3. **危害判定器**：规则+模型混合——CodeQL 安全规则（注入/路径遍历/命令执行）+ LLM-as-judge（用人工校验集校准）。
4. **训练循环**：生成攻击 → 目标 agent 沙箱执行 → 收集结果 → 策略更新；多轮迭代，报告训练曲线与最终 ASR。
5. **对比基线**：SWExploit 式恶意 issue 模板、FCV 式漏洞诱导、XOXO 式跨源投毒。

### 1.4 与现有文献相比的好处（Advantages）
| 对比对象 | 现有做法的局限 | 本算法的改进 |
|---|---|---|
| SWExploit / FCV（静态模板攻击） | 人工设计模板，覆盖面窄、易被识别 | 自动探索攻击模式，覆盖多通道，可学习 |
| JAWS-Bench（越狱评估基准） | 是基准不是生成器 | 本算法产出可复用攻击库，可反哺基准 |
| RLbreaker / ARLAS（通用 LLM 越狱） | 奖励绑定"模型顺从/拒绝"，对象是对话模型 | 奖励绑定终端危害（漏洞补丁/有害动作），对象是带工具调用的编码智能体 |
| RADAR r-VAC（DRL 攻击器） | 恶意软件状态空间的样本变形 | 迁移到编码智能体的上下文操纵动作空间；新增隐蔽性奖励（攻-检联动） |

### 1.5 为什么值得做（Why）
- 现实：Claude Code 16 个 CVE、GitLost 私有仓库泄漏、skill 投毒已发生；但安全评估依赖人工攻击模板，无法系统度量防护水平。
- 学术：方向 A 综述结论——"RL 攻击器直接用于 coding agent"是明确空位（RADAR 范式未落地编码场景）。
- 生态：攻击库开源 = 社区鲁棒性评估资产（对标 CyberSecEval/MalSkillBench 的资产价值）。

## 算法二：实时攻击检测（AgentShield-Detect）

### 2.1 目标（Objective）
在线流式判定"当前输入/轨迹是否正被攻击"，输出逐时间步攻击概率 p_t；在保持低漏报的同时把误报压到不干扰正常开发（误报率阈值约束），且对研究一攻击器具有低对抗绕过率（检测器自身鲁棒）。

### 2.2 输入 / 输出
输入（流式）：
- 文本通道：issue/文档/工具描述原文（逐段进入）；
- 轨迹通道：事件日志流（工具调用、文件读写、token 消耗、退出码）；
- 结构通道：agent-工具-文件异构图（动态更新）；
- 弱标签：公开 PR 评审/issue 讨论数据（#32 众包式弱标签）。
输出：
- 每个时间步 p_t 与告警（触发降权/隔离/人工审查）；
- 可解释定位：哪段文本/哪个行为贡献最大（衔接 Shapley 归因）；
- 指标报告：P/R/F1、AUC、检测延迟（首个告警时间）、误报率、对抗绕过率。

### 2.3 实现方式
1. **三通道特征工程**（迁移 51 篇 IS 检测谱系）：
   - 文本意图特征（#28 情感+方面工程）：句法/词法/意图类别（请求动作、权限提升、数据外发），区分"表面礼貌 vs 深层恶意指令"；
   - 行为特征（#30 行为+文本联合）：工具调用序列模式、敏感路径访问、异常频率/突发性；
   - 结构特征（#25 第三方请求结构）：工具调用图、依赖结构异常。
2. **模型层**：轨迹自编码器（重建误差=异常分，无标签训练，Trajectory Guard 式）+ 异构图 GNN（agent-工具-文件）节点/边异常分类 + 时序融合头输出 p_t；弱标签半监督训练（#32 范式）。
3. **对抗鲁棒化**：以研究一攻击库为对抗样本做对抗训练，报告对抗绕过率（攻-检共演化）。
4. **流式实现**：滑动窗口 + 增量推理，报告端到端检测延迟。

### 2.4 与现有文献相比的好处
| 对比对象 | 现有做法的局限 | 本算法的改进 |
|---|---|---|
| 通用 guardrail（LLM 过滤器） | 黑盒、不可审计、不报误报 | 三通道可解释特征 + 显式误报率优化 + 可审计 |
| Trajectory Guard / AgentSight | 纯行为/系统级异常，看不到"文本正常但意图恶意"的注入 | 补文本通道与结构通道，融合 IS 弱标签方法论 |
| CyberSecEval 类静态扫描 | 事后扫描，非在线 | 在线实时，可联动防御 |
| #25/#28/#30/#32（原始对象） | 对象是网站/评论/机器人 | 首次把 IS 检测特征工程系统迁移到编码智能体攻防 |

### 2.5 为什么值得做
- 检测是防御的第一道防线：没有它，攻击直到漏洞合入/数据泄漏后才被发现（GitLost 事件即此类）。
- 方向 E 综述结论：agent 攻击检测缺少 IS 方法论（特征工程/图结构/弱标签）的系统迁移——本研究直接补位。
- 可解释告警支持人工审查，工程可落地（误报率有明确约束）。

## 算法三：效用保持的鲁棒化（AgentDefense-Robust）

### 3.1 目标（Objective）
在 ASR 显著下降的同时，保持良性任务完成率不塌（**Autonomy Tax 受控**：防御训练后 Robust Resolve Rate 不低于基线的可接受损失），并利用研究二检测器实现运行时响应（降权/隔离/回滚）；给出可复现的训练协议与评估规范（双指标 + RAUC）。

### 3.2 输入 / 输出
输入：
- 良性任务集（SWE-bench Verified 全量）+ 研究一攻击库 D_att；
- 研究二检测器（运行时门控模块）。
输出：
- 鲁棒化后的 agent 策略（微调权重或 LoRA）；
- 运行时防御规则（门控阈值、降权/隔离/回滚动作表）；
- 评估报告：ASR、Robust Resolve Rate、RAUC、成本、Autonomy Tax 检验。

### 3.3 实现方式
1. **离线训练三件套**：
   - 对抗重训练（#26 ARText 模式）：良性+对抗样本混合微调；
   - 偏好优化 DPO：（被攻击 prompt → 安全响应 vs 有害响应）偏好对训练；
   - RL minimax（#49 RL-RO 模式）：与研究一攻击器做对抗博弈，防御策略在最坏攻击下优化。
2. **运行时**：p_t 门控——p > θ_high 隔离（沙箱执行或不执行）；θ_mid < p ≤ θ_high 降权（忽略可疑上下文片段）；支持回滚（撤销可疑编辑）。
3. **评估协议**：双指标（ASR + Robust Resolve Rate）+ RAUC（性能-扰动曲线下面积，ARText 式）+ Autonomy Tax 检验（防御前后良性完成率对比）+ 成本报告。

### 3.4 与现有文献相比的好处
| 对比对象 | 现有做法的局限 | 本算法的改进 |
|---|---|---|
| CodeSentinel / TokenWall / ClawGuard（推理期规则） | 启发式规则、不训练 | 训练级鲁棒化 + 规则混合，泛化到未见攻击 |
| MOCHA（微调防御） | 只报拒绝率提升（拒绝≠任务成功） | 双指标 + RL 博弈 |
| RADAR RL-RO | 未报告良性效用 | 把 Robust Resolve Rate 作为第一约束（Autonomy Tax 是已知未解问题） |
| 纯规则 guardrail | 无端到端证据 | 训练+检测联动，有闭环评估 |

### 3.5 为什么值得做
- Autonomy Tax（arXiv:2603.19423：防御训练可致 99% 任务超时）是防御训练的核心未解问题——"不塌的鲁棒化"本身是新贡献。
- 双指标评估规范（ASR + 良性效用）在攻防文献中无系统工作（RADAR 只报 ER/FPR）。
- 工程落地：训练协议 + 运行时门控可直接部署。

## 三算法如何拼成闭环（数据流与接口）

1. 研究一输出攻击库 D_att → 研究二对抗训练输入、研究三对抗重训练输入；
2. 研究二输出检测器 → 研究三运行时门控模块；
3. 研究一攻击器与研究三防御器在同一环境中形成 minimax 博弈（攻-防共演化）；
4. 共享评测协议：ASR、检测率/误报率、Robust Resolve Rate、RAUC、成本——三个研究在同一指标语言下可加总，末章做端到端组合验证。
