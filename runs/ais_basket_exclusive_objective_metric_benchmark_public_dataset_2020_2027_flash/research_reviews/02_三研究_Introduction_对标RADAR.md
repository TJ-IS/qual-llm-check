## 研究一（攻击生成）Introduction

**P1（对标 RADAR P1：背景与价值）**

大语言模型驱动的编码智能体（coding agent）正被广泛采用，将自动化带入软件开发的日常流程。编码智能体已展现出在仓库级任务上的能力，能够自主完成缺陷修复、功能实现与测试维护（Jimenez et al. 2024）。例如，在公开基准 SWE-bench Verified 上，主流 agent 的修复成功率已从早期的个位数提升至 65%–80%，主流厂商（如 GitHub、OpenAI、Anthropic）已将编码智能体嵌入开发者工作流。大型企业调查显示，开发者正日益依赖这些智能体完成关键代码变更。

**P2（对标 RADAR P2：问题）**

然而，编码智能体已被发现易受对抗性信息操纵的攻击——对手通过精心修改 agent 读取的上下文（issue 文本、仓库文件、工具描述），使 agent 生成"功能正确但带漏洞"的补丁或执行有害动作。例如，恶意 issue 可诱导自动修复 agent 生成带漏洞补丁（攻击成功率 0.91，SWExploit）；工具描述注入可使攻击成功率从约 50% 提升至 87%（QueryIPI）；恶意 skill 包可在 agent 加载时植入载荷（DDIPE）。尽管编码智能体日益被依赖，**现有攻击大多为人工设计的静态模板，覆盖面窄、易被识别，如何系统生成多样化、可迁移、能逃避检测的对抗攻击序列，目前知之甚少**——这进而阻碍了对编码智能体防护水平的系统度量与防御训练。

**P3（对标 RADAR P3：理论动机）**

对手对编码智能体的攻击本质上是序贯决策：对手通过一连串动作（改写 issue、注入文档、修改工具描述）逐步操纵 agent 的信息环境。强化学习（RL）专门研究行动者与环境在离散时间步上的序贯交互（Sutton and Barto 2018），因此适合仿真对手的逐步攻击动作。鲁棒优化（RO）的思想进一步表明，有效防御要求有效的对抗攻击仿真（Kolter and Madry 2018）——没有系统生成的攻击，就无法系统评估与训练防御。

**P4（对标 RADAR P4：工件与评估）**

基于计算设计科学范式，我们开发 AttackRL-Agent，一个基于 RL 的编码智能体对抗攻击仿真框架。AttackRL-Agent 将攻击建模为对抗 MDP（状态=仓库+issue+轨迹摘要；动作=攻击通道选择与内容生成；奖励=危害信号−隐蔽惩罚），以 PPO 训练生成式攻击策略，并在 SWE-bench Verified 与 AgentDojo 上实例化。我们与静态模板攻击（SWExploit、FCV 式）及通用 RL 越狱方法（RLbreaker）对比，报告 ASR、隐蔽性、多样性与跨模型可迁移性。本研究作出三点贡献：第一，据我们所知，这是**首个面向编码智能体的 RL 攻击仿真框架**，覆盖 issue、仓库文件与工具描述三类攻击通道；第二，提出带隐蔽性奖励的攻击动作序列建模，能生成静态模板无法覆盖的攻击模式；第三，产出的攻击库为检测与防御研究提供可复用的训练资产。

【研究问题】如何自动生成多样化、可迁移、能逃避现有防护的编码智能体对抗攻击（上下文操纵）？RL 攻击仿真相对静态模板攻击是否显著提升攻击成功率、覆盖面与可迁移性？

## 研究二（实时检测）Introduction

**P1（对标 RADAR P1：背景与价值）**

为保护编码智能体，组织正在部署防护机制：输入过滤（guardrail）、沙箱隔离、权限控制与行为监控。这些机制被期望在攻击造成危害前识别威胁。产业界已出现可观测的防护需求：私有仓库数据泄漏事件（GitLost）与编码助手的远程代码执行漏洞（Claude Code 系列 CVE）表明，攻击在真实开发环境中已经发生。

**P2（对标 RADAR P2：问题）**

然而，现有防护被发现存在两类缺陷。其一，主流防护依赖黑盒 LLM 过滤器或静态规则，对"文本表面正常但意图恶意"的间接注入与新型攻击漏报率高——恶意 issue 穿透 guardrail 的比例达 66.5%，且拒绝几乎全部来自模型层而非系统防护（IssueTrojanBench）。其二，防护的误报会打断正常开发流程，但现有研究极少报告误报率约束。IS 文献在欺诈网站、欺诈评论与社交机器人检测中已证明特征工程、图结构与弱标签方法的有效性（#25/#28/#30/#32），**但这些方法论尚未被系统迁移到编码智能体的攻击检测，如何实时、低误报、且检测器自身对攻击鲁棒地进行检测，目前知之甚少**。

**P3（对标 RADAR P3：理论动机）**

攻击检测在结构上等同于信号检测问题：需要从"正常行为"与"攻击行为"的混合流中分离异常。IS 检测谱系提供成熟方法论——文本意图特征（#28）、行为+文本联合（#30）、结构特征（#25）与众包弱标签（#32）。同时，检测器自身也是对抗目标：攻击者会优化攻击以逃避检测，因此检测器需要以对抗样本训练，并报告对抗绕过率。

**P4（对标 RADAR P4：工件与评估）**

基于计算设计科学范式，我们开发 AgentShield-Detect，一个面向编码智能体对抗攻击的实时检测框架。该框架以三通道特征（文本意图、行为序列、工具调用结构）输入轨迹事件日志，结合无标签轨迹自编码器与 agent-工具-文件异构图 GNN，输出逐时间步攻击概率；以研究一攻击库为对抗样本进行对抗训练。我们在公开正常轨迹与攻击库上评估 P/R/F1、AUC、检测延迟、误报率与对抗绕过率。本研究作出三点贡献：第一，据我们所知，这是**首个将 IS 检测谱系系统迁移到编码智能体攻防的实时检测框架**；第二，提供可解释、低误报约束的检测输出，支持人工审查；第三，报告检测器自身的对抗鲁棒性（绕过率），填补防护评估的空白。

【研究问题】如何从编码智能体的输入文本、行为轨迹与工具调用结构中实时识别对抗攻击？三通道特征融合与对抗训练能否在低误报下实现高检测率，并保持检测器自身对抗鲁棒？

## 研究三（效用保持的鲁棒化）Introduction

**P1（对标 RADAR P1：背景与价值）**

鲁棒化是编码智能体攻防的最终目标：让 agent 在对抗环境下仍能安全完成任务。防御训练（安全微调、偏好优化）已被证明能提升模型对恶意输入的拒绝率（如 MOCHA 显示微调防御可提升拒绝率最高 32.4 个百分点），运行时防护（规则过滤、推理期检测）也已出现（CodeSentinel、TokenWall）。RADAR 进一步证明，鲁棒优化与强化学习结合（RL-RO）可将恶意软件检测器的对抗鲁棒性提升约 7 倍（Ebrahimi et al. 2025）。

**P2（对标 RADAR P2：问题）**

然而，防御训练被发现存在"自主性税"：防御训练在提升鲁棒性的同时可能严重破坏 agent 的良性任务能力——一项系统测量显示，防御训练后 agent 99% 的良性任务超时（基线 13%）（Autonomy Tax）。现有编码智能体防御的局限有三：其一，推理期规则防御不训练，难以泛化到未见攻击；其二，防御评估大多只报告拒绝率或 ASR，**不报告防御后良性任务完成率（Robust Resolve Rate），无法判断防御是否以牺牲任务能力为代价**；其三，RADAR 的 RL-RO 范式针对恶意软件检测器，尚未在编码智能体情境中落地，且其评估未包含良性效用。如何在保持良性任务效用的前提下鲁棒化编码智能体，目前知之甚少。

**P3（对标 RADAR P3：理论动机）**

鲁棒优化（RO）提供了把对手纳入学习过程的框架：防御者与攻击者构成两玩家博弈，有效防御需要对抗攻击训练（Madry et al. 2018）。对抗重训练（#26 ARText 模式）与偏好优化（DPO）提供了把攻击样本转化为安全行为的训练机制。同时，运行时检测（研究二）可作为门控信号：检测到攻击时降权、隔离或回滚。训练级鲁棒化与运行时门控结合，才能在提升鲁棒性的同时约束良性效用损失。

**P4（对标 RADAR P4：工件与评估）**

基于计算设计科学范式，我们开发 AgentDefense-Robust，一个效用保持的编码智能体鲁棒化框架。该框架以对抗重训练、偏好优化与 RL minimax 三种机制离线训练（对抗样本来自研究一攻击库），并以研究二检测器实现运行时门控。我们在 SWE-bench Verified（良性）与攻击库（对抗）上评估双指标——ASR 与 Robust Resolve Rate——以及性能-扰动曲线下面积（RAUC）与 Autonomy Tax 检验。本研究作出三点贡献：第一，据我们所知，这是**首个把良性效用作为第一约束的编码智能体鲁棒化框架**，显式处理 Autonomy Tax；第二，将 RADAR 的 RL-RO 范式落地编码智能体情境并扩展出检测-防御运行时闭环；第三，建立"ASR + Robust Resolve Rate"双指标评估规范，填补防御评估的空白。

【研究问题】如何在编码智能体上实现鲁棒化而不支付自主性税？对抗重训练、偏好优化与 RL minimax 的何种组合能在 ASR 显著下降的同时保持良性任务完成率，且运行时检测联动能否进一步提升鲁棒-效用权衡？
