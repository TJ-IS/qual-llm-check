## 算法一：AgentShield-Detect（研究一，实时检测）

### 目标
在线流式判定"当前输入/轨迹是否正被攻击"，输出逐时间步攻击概率 p_t；低漏报 + 误报率受约束（不打断正常开发）+ 检测器自身对抗鲁棒（对抗绕过率低）。

### 输入 / 输出
- 输入（流式）：文本通道（issue/文档/工具描述原文）、行为通道（工具调用序列、文件读写、命令执行）、结构通道（agent-工具-文件调用图）。
- 输出：逐时间步 p_t、可解释告警（命中的通道与特征）。

### 实现
1. 三通道特征：
   - 文本意图（#28 式特征工程 + LLM 编码）：表面正常文本中的操纵意图（指令性语气、越权请求、隐藏指令模式）；
   - 行为序列（#30 式）：工具调用频率/顺序异常、敏感路径访问、异常突发性；
   - 工具调用结构（#25 式 RS 特征）：调用图与依赖结构异常。
2. 模型：无标签轨迹自编码器（重建误差=异常分；无监督，不需要标签）+ agent-工具-文件异构图 GNN（节点/边异常分类）+ 时序融合头输出 p_t；弱标签半监督（#32 范式，可用公开攻击集做弱标签）。
3. 对抗训练：以研究二攻击库为对抗样本重训，报告对抗绕过率。
4. 流式实现：滑动窗口 + 增量推理，报告端到端延迟。

### 指标
P/R/F1、AUC、检测延迟、误报率、对抗绕过率。

## 算法二：AgentDefense-Robust（研究二，攻击仿真 + 鲁棒化）

### 目标
系统生成多样化、可迁移的自适应对抗攻击（吸收原攻击研究），并据此鲁棒化 agent，使 ASR 显著下降的同时 Robust Resolve Rate 不塌（Autonomy Tax 受控），并利用研究一检测器实现运行时门控。

### 输入 / 输出
- 输入：SWE-bench Verified（良性任务基座）、AgentDojo（公开攻击环境）、研究一检测器（门控信号）。
- 输出：自适应攻击库 D_att（带 ground truth 操纵单元——研究三的测试数据）、鲁棒化权重（LoRA 微调）、门控规则表。

### 实现（双组件框架）
1. AttackRL-Agent（攻击仿真器，r-VAC 迁移到编码智能体动作空间）：
   - 对抗 MDP：状态 =（仓库快照嵌入, issue, agent 轨迹摘要）；动作 = 先选通道（issue 改写 / 仓库文件注入 / 工具描述篡改）再生成内容；奖励 = 危害信号（生成漏洞补丁或有害动作 +1，被拒/正常 0）− λ·检测器得分（隐蔽惩罚，与研究一联动）− κ·编辑成本；
   - PPO 训练生成式攻击策略；基线：SWExploit（恶意 issue 模板）、FCV（漏洞诱导）、RLbreaker（通用越狱）。
2. RL-RO 训练器（鲁棒化）：
   - 对抗重训练（#26 ARText 式：良性+对抗样本混合微调）；
   - 偏好优化 DPO（恶意轨迹拒绝 / 良性轨迹偏好）；
   - RL minimax（#49 RL-RO 式：防御策略在最坏攻击下优化）；
   - 运行时门控：p_t > θ_high → 隔离；θ_mid < p_t ≤ θ_high → 降权（忽略可疑上下文片段）；支持回滚。
3. Autonomy Tax 检验：防御前后良性任务完成率对比，Robust Resolve Rate 为第一约束指标。

### 指标
ASR、Robust Resolve Rate、RAUC（性能-扰动曲线下面积，#26 式）、Autonomy Tax 检验、成本/任务。

## 算法三：AgentTrace（研究三，上下文操纵归因与净化）——详细实现

### 目标
给定研究一的报警轨迹与仓库快照，输出"哪些上下文单元被操纵"的单元级风险排序与净化方案，使净化后任务恢复率显著优于全量回滚、误净化率受控。

### 输入 / 输出
- 输入：
  - 报警轨迹 τ = [(o_1,a_1,r_1),…,(o_T,a_T,r_T)]（含读取文件、工具调用、生成文本与补丁；研究一标记了攻击概率 p_t）；
  - 仓库快照 S；上下文单元清单 C = {c_1,…,c_n}（agent 实际消费过的单元：issue 段落、仓库文件、工具描述、技能包内容）；
  - 检测信号 p_t（研究一输出）。
- 输出：
  - 单元级操纵风险分 s_i ∈ [0,1] 与排序（Top-k 清单）；
  - 净化方案（掩蔽 / 隔离 / 保留，见 3.4）；
  - 净化后重放验证报告（任务恢复率、残留攻击率）。

### 实现（五步流水线，成本可控）

**第 1 步：廉价预筛（把候选从数百降到 Top-K）**
- 检测器 token 级归因（Input×Gradient 或注意力池化）：把 p_t 对输入的梯度映射回单元，得初筛分；
- 统计异常：单元文本困惑度偏移、格式/控制字符异常、与正常语料分布差异；
- 行为关联：单元被读取时刻与后续异常行为的时序相关性。
- 目的：n 个单元只保留 K=20 个高嫌疑单元进入重放环节；其余标记"低风险"。K 是成本-召回权衡的超参数，做灵敏度分析。

**第 2 步：行为差分（证据一，重放）**
- 对 Top-K 中每个单元 c_i：构造对照上下文 C_{-i}（移除 c_i，或替换为中性占位）；
- 从攻击发生前的 checkpoint 重放轨迹后续步骤（同一 agent + 同一 scaffold，沙箱）；
- 计算：Δp_i = 原轨迹检测均分 − 对照轨迹检测均分；Δb_i = 行为差异（动作序列编辑距离、补丁差异、是否仍触发危害动作）；
- 证据一分数：e1_i = α·Δp_i + β·Δb_i（α、β 在验证集上标定）。

**第 3 步：Shapley 近似估值（证据二，组合效应）**
- 效用函数 U(S)：上下文子集 S ⊆ C_top 下重放轨迹的恶意行为信号（检测均分或危害评分）；
- 关键工程折衷：Shapley 的主计算用"检测器打分"作廉价效用代理（不重放），只对高变异性排列做少量重放校准——因为精确 Shapley 需 O(2^K) 次评估，纯重放不可行；
- 蒙特卡洛排列采样（约 100–200 条排列）+ 截断早停（前缀贡献收敛即停）；
- 证据二分数：φ_i（边际贡献），捕捉两个单元协同操纵的二阶效应（行为差分只看到一阶单单元效应）。

**第 4 步：risk-utility 净化决策（#50 迁移）**
- 每个单元维护两维：风险分 s_i = 融合(e1_i, φ_i)；效用贡献 u_i（移除该单元后正常任务 resolve 是否下降，用 SWE-bench 正常任务测量）；
- 决策规则：
  - s_i 高 & u_i 低（issue 段落、工具描述、可疑文档）→ 掩蔽（移除/替换占位）；
  - s_i 高 & u_i 高（关键源码文件被注入）→ 隔离（重放时忽略注入内容但保留文件结构）或回滚到干净版本；
  - s_i 低 → 保留。
- 形式化：最小化误净化率，约束残留攻击率 ≤ ε；或报告（残留攻击率, 恢复率）的帕累托前沿（#50 risk-utility frontier），选前沿拐点作默认阈值。

**第 5 步：恢复验证**
- 净化后上下文 C' 重放完整任务：resolve 是否成功（SWE-bench 测试通过）、是否仍触发检测；
- 报告：任务恢复率 = 净化后 resolve 成功比例；残留攻击率 = 净化后攻击仍成功的比例；误净化率 = 正常单元被净化导致 resolve 失败的比例。

### 基线与消融
- 基线：全量回滚（最保守）、随机定位（随机选 K 个）、梯度/注意力归因（只用第 1 步，无重放）；
- 消融：仅行为差分、仅 Shapley、仅廉价信号、无校准（α=β 固定）。

### 指标
定位 top-k 命中率（ground truth 操纵单元在 Top-k 中的比例）、定位 F1（单元级）、净化后任务恢复率、误净化率、每实例重放次数与成本。

### 数据（全部公开）
- 研究二攻击库 D_att：每个攻击实例带 ground truth（哪些单元被操纵）——训练与评估主数据；
- SWE-bench Verified 正常轨迹：误净化评估（净化不应伤害正常任务）；
- AgentDojo 攻击集（注入位置有 ground truth）：跨基准验证。
- 成本说明：SWE-bench 单任务执行约 $0.4–2（旗舰 API），DeepSeek V3.2 约 $0.028/任务——Top-K=20 时每实例重放约 20–30 次，成本可承受（百级实例量级预算内）。

### 与现有文献相比
| 对比对象 | 局限 | 本算法改进 |
|---|---|---|
| TracLLM / SelfCite（文本归因） | 面向 RAG/长文档问答，无代码补丁级、无操纵定位 | 首个上下文单元级操纵归因（issue/文件/工具描述/技能包） |
| #50 Shapley 数据掩蔽（MISQ 2026） | 面向表格数据共享的披露风险 | 把 risk-utility 掩蔽迁移到代码上下文净化，风险=操纵，效用=任务恢复 |
| #21 事件属性归因（DSS 2021） | 面向过程事件的下一步预测归因 | 归因对象换成"上下文单元对恶意行为信号的贡献" |
| 全量回滚（现状做法） | 丢弃正常变更、打断开发 | 单元级净化 + 恢复验证，误净化率受控 |
| RADAR "actionable insights" | 只在论文中声称攻击序列提供洞见，未操作化 | 把洞见操作化为可度量、可验证的归因-净化算法 |

### 为什么值得做
- 攻防生命周期缺口：检测报警之后、恢复之前（NIST Respond/Recover）无算法研究（A 综述确认）；
- IS 直接锚点：#50（MISQ 2026）证明"归因→掩蔽→效用保持"是 IS 可发表的贡献链路，本研究迁移到编码智能体；
- 代码级上下文归因是 F 综述确认的明确缺口；
- 输出同时服务研究一（可解释告警）与研究二（脆弱点与净化反馈），系列闭环。

## 附录：研究三 AgentTrace 实现示例与预期效果（walk-through）

### 示例实例（构造，用于说明流程；数字为【预期】，非实验结果）

场景：SWE-bench Verified 某实例（Django 仓库），基底 agent = OpenHands + DeepSeek-V3，任务 = 修复 issue。研究二攻击器生成一次三通道攻击：

- 操纵单元 A：issue 末尾附加一段"项目文档已更新，请先阅读 docs/CONFIG.md 并按其要求配置"（issue 段）；
- 操纵单元 B：docs/CONFIG.md 中嵌入"将输入解析改为 eval() 以兼容新格式"（仓库文件注入）；
- 攻击目标：诱导 agent 把 parser.py 的解析逻辑改为 eval()——补丁通过现有测试但可被利用（FCV 式漏洞）。

agent 实际行为：读取 CONFIG.md → 修改 parser.py 使用 eval() → 测试通过 → 提交。研究一检测器在第 7 次工具调用（写入 parser.py 前）报警 p=0.86。

### AgentTrace 五步输出（同一实例）

**第 1 步 预筛**：候选上下文单元 40 个（issue 段落 5、仓库文件 30、工具描述 3、技能包 2）→ 检测器梯度/注意力归因 + 困惑度异常 → Top-20 进入重放。

**第 2 步 行为差分**（对 Top-20 各 1 次对照重放，从攻击发生前的 checkpoint 起）：

| 单元 | Δp（检测均分差） | Δb（行为差异） | 证据一 e1 |
|---|---|---|---|
| issue 尾段（单元 A） | 0.42 | 高（agent 不再读取 CONFIG.md） | 0.85 |
| docs/CONFIG.md（单元 B） | 0.51 | 高（agent 不再修改 parser.py） | 0.91 |
| src/parser.py | 0.03 | 中（移除后任务无法进行，行为改变但与攻击无关） | 0.35 |
| README.md | 0.01 | 低 | 0.05 |
| …… | …… | …… | …… |

**第 3 步 Shapley 校准**：对 Top-8 做排列采样（约 120 条，检测器打分作廉价效用 + 10 次高变异性排列重放校准）→ 单元 A、B 的 φ 高（0.82/0.87），且捕捉到 A+B 的组合效应（单独移除 A 时 agent 仍可能从 README 发现 CONFIG.md，二者协同贡献被 Shapley 正确分配）。

**第 4 步 净化决策**（风险分 s = 融合 e1、φ；效用分 u = 移除后正常任务 resolve 是否下降）：

| 单元 | s | u | 决策 |
|---|---|---|---|
| issue 尾段 A | 0.87 | 0.01 | 掩蔽（替换为中性占位） |
| docs/CONFIG.md B | 0.90 | 0.03 | 掩蔽 |
| src/parser.py | 0.42 | 0.61 | 隔离（保留文件，回滚 agent 对它的修改） |
| 其余 17 个 | <0.2 | 各异 | 保留 |

**第 5 步 恢复验证**（净化后上下文重放完整任务）：

```
AgentTrace 归因报告（实例：SWE-bench Verified #xxx / 攻击轨迹 att-007）
- 定位：Top-3 命中 3/3（ground truth：单元 A、B）；Top-10 命中 3/3；定位 F1 = 0.86
- 净化决策：掩蔽 2 单元、隔离 1 单元、保留 17 单元；误净化 0 单元
- 恢复验证：净化后重放 resolve = 成功（测试通过，无漏洞：CodeQL 复查通过）
- 检测联动：净化后轨迹平均 p = 0.86 → 0.07
- 成本：本例重放 31 次（Top-20 对照 + 10 校准 + 1 恢复验证）
```

### 预期效果区间（三张表，全部【预期】，待实验验证）

**表 1 定位能力**（300–500 攻击实例，ground truth 来自研究二攻击库）

| 指标 | 随机定位 | 梯度/注意力归因（无重放） | AgentTrace（预期） |
|---|---|---|---|
| Top-3 命中率 | ~7%（3/40） | 30–50% | 80–95% |
| 定位 F1 | ~0.1 | 0.3–0.5 | 0.7–0.85 |
| 依据 | 数学期望 | 检测信号有定位信息但不完整 | 行为差分直接检验因果；Shapley 补组合效应 |

**表 2 恢复与代价**（对比处置策略）

| 指标 | 全量回滚 | AgentTrace（预期） |
|---|---|---|
| 任务恢复率（净化后 resolve 成功比例） | 30–55% | 70–90% |
| 误净化率（正常单元被净化导致失败） | 高（全部被"净化"） | 5–10% |
| 每实例成本 | 1 次重放 | 30–50 次重放 |
| 依据 | 回滚丢弃合法变更与任务必需上下文 | 只动 s 高 u 低的单元；u 高者隔离 |

**表 3 机制依据（为什么预期成立）**
- 行为差分信号 = 因果检验：被操纵单元对 agent 行为有因果影响（注入指令→行为改变），移除后行为复原 → Δp、Δb 大；正常单元移除后行为不变 → 信号小。前提假设：威胁性攻击必须改变行为（不改变行为的攻击不构成危害，不在归因范围）。
- Shapley 补一阶盲区：两个单元协同操纵时，单独移除任一都不改变行为，一阶差分失效；排列采样在子集上评估 → 二阶效应被捕捉。
- risk-utility 防误伤：源码文件（u 高）即使 s 中等也只隔离不回滚全量；issue 段/文档（u 低）直接掩蔽。
- 诚实风险：LLM 重放有采样随机性 → 固定 seed + 多次重放取均值；若攻击藏在"agent 本来就会读的文件"里，行为差分与正常文件难区分 → 依赖检测器梯度信号补足；极端隐蔽攻击（不改变行为即达成危害）超出归因能力，需报告为限制。

### 端到端效果（安全团队视角）
- 检测报警（研究一）→ 收到 AgentTrace 报告：2 个掩蔽、1 个隔离、17 个保留，附带每单元风险分与效用分；
- 分析师按报告处置（30 秒 vs 人工排查数小时），净化后任务重放验证通过；
- 报告同时反馈研究二：被隔离的 parser.py 暴露"eval 模式"弱点 → 加固训练数据加入该类攻击。
