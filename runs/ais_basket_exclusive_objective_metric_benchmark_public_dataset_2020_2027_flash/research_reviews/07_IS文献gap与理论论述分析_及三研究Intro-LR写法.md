## 一、六篇的论述结构拆解

### #26 ARText（JMIS 2022）——"三原因式 IS 文献缺口 + kernel theory"
| 环节 | 原文做法 |
|---|---|
| 开场 | 机器学习+大数据 → 组织用预测分析做关键决策 → **应用域清单**（垃圾评论/垃圾邮件/欺诈 app/金融/HR/医疗/自动驾驶） |
| 问题 | 对抗攻击是 emerging threat → 组织依赖模型 → **一句抽象**："输入由受该决策直接影响的人提供"的领域尤其危险 → 实例（垃圾评论精心修改绕过检测）→ 后果（声誉/财务损失） |
| gap | "SML 模型的脆弱性不是新问题……但在新兴应用中值得研究，**原因有三**：First，IS 文献未充分承认这一安全威胁；Second，IS 文献评估只关注预测性能（accuracy），鲁棒性评估 understudied；Third，缺乏评估导致部署了脆弱应用 → urgent need" |
| 理论 | **Technology Threat Avoidance Theory（TTAT）作为 kernel theory**：威胁评估维度→鲁棒性评估模型；应对维度→鲁棒化设计原则 |
| 贡献 | 评估模型 + ARText 系统 + 两个测试床（垃圾评论/垃圾邮件）实证 |

### #50 Shapley（MISQ 2026）——"问题深化式 gap + 公理理论"
| 环节 | 原文做法 |
|---|---|
| 开场 | 数据是最有价值资源 → 隐私重要性（Pavlou 等 IS 隐私研究）→ 消费者/企业/监管三视角（GM/Ford 数据共享、$79M 损失、GDPR/CCPA） |
| 问题 | 数据共享给外部分析师（Kaggle/Amex 例子）→ 披露风险分两层：直接披露 → **推断性披露**（Facebook 推断、Uber 司机家址） |
| gap | "掩蔽 confidential 属性不足以解决推断性披露风险"——**nonconfidential 特征也贡献风险，特征级 risk-utility 权衡未被解决**（此前只在数据集级研究） |
| 理论 | Shapley 合作博弈公理（正文理论部分）：公平分配特征对风险/效用的贡献 |
| 贡献 | 三贡献：整体视图（fair attribution）、特征级 risk-utility 权衡 + risk-utility frontier、model-agnostic 框架 |

### #32 社交机器人（ISR 2023）——"现象驱动 gap + 理论解决设计难题"
| 环节 | 原文做法 |
|---|---|
| 开场 | 社交媒体吸引网络对手 → 机器人规模化攻击 → **现象**：FCC 评论区被机器人轰炸 |
| 转折 | **"但有一个被忽视的现象：越来越多的用户能识别机器人并点名"** → "Analysis of such human–bot interaction is limited in existing literature. This research seeks to address this major knowledge gap" |
| 深化 | 现有检测靠行为启发式 → 对手有规避能力（arms race）→ 社区呼吁新特征 → **即使最新文本挖掘也没用众包标签** |
| 难题 | 用户识别能力不等（"definitely found a bot" vs "I think I may have found a bot"）→ 如何系统加权 credibility，避免 ad hoc |
| 理论 | **Speech Act Theory**：按"评论想完成什么动作"评估每条众包标签 → "has not previously been used for crowd-generated labels in security informatics——novel application" |
| IS 身份 | "calls for more design science work in premier IS journals (Agarwal and Dhar 2014, Goes 2014, Rai 2017)" |

### #38 语音金融（MISQ 2023）——"理论驱动三挑战式 gap"
| 环节 | 原文做法 |
|---|---|
| 开场 | 金融科技 → 投资者用非结构化数据 → **现象钩子**：对冲基金雇 CIA 前特工读声纹 |
| 目标 | 用管理者声纹预测财务风险（波动率）→ 为什么选它（期权市场 7.5 万亿美元、Black-Scholes）→ "不争议"的预测目标 |
| gap | 会计/金融文献证明语言信号有价值，**但非语言声纹的样本外预测力 largely unknown**（现有研究只做 in-sample） |
| 深化 | **三个设计挑战**：time variation（问答环节音高降 4Hz）、vocal-verbal integration（非语言沟通理论：声纹肯定或否定语言）、vocal complexity——每个挑战都由理论推导，且 "prior studies have ignored..." |
| 贡献 | 理论驱动设计框架 + 6000+ 音频数据集 + 显著更高的预测精度 + 期权交易经济收益 |

### #11 金融中介（JAIS 2020）——"双理论对推导 gap"
| 环节 | 原文做法 |
|---|---|
| 开场 | 金融中介重要 → 互联网削弱信任 → 金融危机 → **现象钩子：《华尔街之狼》电影**（Belfort 骗 1,513 客户、$200M 损失）→ "preventing the next Wolf of Wall Street" |
| gap | 现有研究识别市场操纵，但**忽视了识别"可能实施不当行为的中介"**；LinkedIn 自披露信息有不同外部验证水平 → "self-disclosed information...has not yet been considered" |
| 理论 | **信息操纵理论（IMT, McCornack 1992）+ warranting theory（Walther et al. 2009）**：各推导一条可检验论断（欺骗者自披露与可靠者不同；外部验证增加检测价值）→ 论断即研究问题 |
| 贡献 | 理论确认（IMT/warranting 成立）+ 分类器 + 经济价值（赔偿金/罚款）评估 |

### #49 RADAR（MISQ 2025）——"威胁-理论动机-工件"（已读）
| 环节 | 原文做法 |
|---|---|
| 开场 | 攻击规模上升 → AI 防御 agent 被开发 → 能力（96% 精度）→ 采用（Avast/Symantec/Endgame）→ 依赖（69% 调查） |
| gap | 对抗攻击脆弱性定义 + 两个实例 + "While...increasingly relied on..., little is known about strengthening the robustness" |
| 理论 | RO（两玩家博弈）→ AAE 推论；RL（序贯交互）→ 适配攻击仿真 |
| 贡献 | 框架 + RL 攻击方法 + RL-RO 方法，ER/FPR 双指标，7 倍鲁棒性 |

## 二、五种 gap 论述模式（可直接选用）

| 模式 | 代表 | 适用场景 | 适用本研究 |
|---|---|---|---|
| A. 三原因式 IS 文献缺口 | #26 | 对象是"IS 文献没考虑的新兴应用/新评估维度" | 研究二：IS 鲁棒性文献只处理分类器（RADAR/#26），没有编码智能体；IS 评估只报攻击侧指标，不报良性效用 |
| B. 问题深化式 | #50 | 已知方法解决了问题的浅层，深层未被解决 | 研究三：防护止步于"报警"，"位置级处置"（归因+净化）未被解决；全量回滚是唯一手段但代价高 |
| C. 现象驱动式 | #32 | 现实出现一个被文献忽视的现象/信号源 | 研究一：单通道防护被跨通道攻击绕过（IssueTrojanBench 66.5%）；检测报警后无法处置的现象 |
| D. 理论驱动三挑战式 | #38 | 对象有方法难以克服的固有结构挑战 | 研究二：内容级语义操纵、危害动作时序截止、任务绩效 vs 分类精度（三个设计挑战） |
| E. 双理论对推导式 | #11 | 两个理论各推一条论断，论断即 gap | 研究一/三：信息操纵理论（欺骗留痕）+ warranting（外部验证/多通道交叉验证） |

## 三、IS 算法论文的共同特征（"IS 味"清单，投稿前逐条自查）

1. **现象级开场钩子**：电影（华尔街之狼）、CIA 前特工、FCC 评论轰炸、69% 调查、96% 精度——具体、有画面、可验证。不是"随着 LLM 的发展"这种空话。
2. **gap 落在"IS 文献/实践层面"**：不是"精度不够"，而是"IS 文献没有考虑 X""IS 评估忽视 Y""组织实践需要 Z 但不知道怎么做"（#26 的三原因全部是 IS 文献视角）。
3. **一句抽象把情境特殊性上升为普遍问题**：#26"输入由受决策影响的人提供"；#38"样本外预测力"。#50"推断性披露"。#32"人类认知能力未被利用"。这决定了特殊性是否"站得住"——不是换数据集，而是新的问题维度。
4. **理论服务于两个目的**：推导设计原则（为什么这样设计，对齐 #38/#26）；界定 gap 边界（理论说哪些维度重要，gap 是这些维度未被研究，对齐 #11/#50）。
5. **贡献与 gap 一一对应**：First/Second/Third 回应前面列的缺口（#26 三原因 ↔ 评估模型+增强系统；#50 三贡献 ↔ 特征级权衡）。
6. **IS 身份锚点**：设计科学呼吁（Rai 2017、Agarwal & Dhar 2014、Goes 2014）+ IS 经典理论（TTAT、IMT、warranting、非语言沟通、Shapley、RO）+ IS 谱系（欺诈/机器人检测）。

## 四、三研究的 Intro & LR 具体写法（差异如何自然论述）

### 研究一（检测）：现象驱动 gap（#32 式）+ 双理论推导（#11 式）
- **开场钩子**：编码智能体的真实攻击事件（Claude Code CVE、GitLost 私有仓库泄露、MalSkillBench 3,944 个恶意技能包）→ 组织部署防护。
- **现象转折**："然而，一个被忽视的现象正在出现：单通道防护（输入过滤/规则）对跨通道、跨步骤的攻击系统性失效——66.5% 的恶意 issue 穿透 guardrail，拒绝几乎全部来自模型自身而非防护系统（IssueTrojanBench）。"
- **一句抽象**："编码智能体攻击的检测，需要同时利用文本、行为与工具调用结构三类线索，并须在危害动作完成前触发——IS 检测谱系（欺诈网站 #25、欺诈评论 #28、假评论者 #30、社交机器人 #32）已证明多通道线索的价值，但尚未迁移到这一情境。"
- **理论**：信息操纵理论（IMT，#11 同源：欺骗者在信息操纵中留痕）+ warranting 理论（外部/交叉验证增强可靠性）→ 设计原则 1：三类线索互补交叉验证；设计原则 2：线索在时序中展开，须早期捕获 → 三通道特征 + 逐时间步检测。
- **贡献回应 gap**：First（谱系迁移+三通道融合框架）、Second（可解释、低误报约束输出，支持人工审查）、Third（检测器对抗鲁棒评估规范）。

### 研究二（攻击+鲁棒化）：三原因式 IS 缺口（#26 式）+ 三挑战（#38 式）
- **开场钩子**：RADAR 已证明 RL-RO 可将恶意软件检测器鲁棒性提升约 7 倍；编码智能体攻击已在真实环境显现（CVE/GitLost）。
- **一句抽象**："编码智能体是长程、开放性、带工具调用的自主任务执行者——其鲁棒化与分类器鲁棒化有本质区别：攻击是内容级语义操纵而非连续扰动，防御代价是任务完成率而非分类精度。"
- **gap（三原因）**：First，IS 鲁棒性文献（#49/#26）的对象是分类器/检测器，编码智能体的内容级操纵与效用代价未被处理；Second，IS 防御评估只报攻击侧指标（ASR/ER），不报良性任务完成率——防御训练可致 99% 任务超时（Autonomy Tax），评估缺口使组织无法判断部署价值；Third，缺乏"效用约束的鲁棒化"指导，组织部署了可能脆弱或不可用的 agent。
- **理论**：RO（方法论理论，与 RADAR 相同）→ minimax 设计原则；信息质量理论（DeLone & McLean：任务绩效依赖所读信息质量，攻击=信息质量操纵）→ 防御必须显式约束任务绩效（Autonomy Tax 的理论依据）。
- **贡献回应**：First（RADAR 范式完整落地编码智能体）、Second（RL 攻击仿真方法与攻击库）、Third（ASR+Robust Resolve Rate 双指标规范）。

### 研究三（归因）：问题深化式 gap（#50 式）+ 公理理论
- **开场钩子**：事件响应是安全运营的标准环节（NIST：Detect→Respond/Recover）；检测报警之后，安全团队必须知道"哪里被操纵"才能处置。
- **一句抽象**："编码智能体被操纵的单元（issue 段落、仓库文件、工具描述、技能包）具有语义边界、依赖结构与差异化效用——归因可以单元级进行，净化可以用重放验证恢复，这是表格数据掩蔽（#50）没有的问题维度。"
- **gap（问题深化）**：现有防护止步于"报警"——报警不提供位置信息；全量回滚虽可清除攻击，但丢弃正常变更、打断开发（"运行时的自主性税"）；IS 数据决策文献（#50）已证明"归因→掩蔽→效用保持"链路，但代码上下文单元的归因与净化未被研究。
- **理论**：Shapley 合作博弈公理（#50 同源：效率/对称/哑元/可加性 → 公平分配影响）+ 归因服务于决策（risk-utility）→ 设计原则 1：单元级公平归因；设计原则 2：净化决策显式权衡风险与效用。
- **贡献回应**：First（单元级归因框架）、Second（Shapley 近似+行为差分两阶段方法）、Third（"定位命中+恢复效用"双指标规范）。

## 五、与"形式化差异表"的关系（重要）

- 技术差异表（目标函数、约束、指标的形式化差异）**不直接写进论文**，它是设计文档（05 号文档）的用途。
- 论文里，差异通过三个渠道自然体现：① 开场钩子+现象叙事（#32 FCC、#38 CIA、#11 电影）；② 一句抽象（把情境特殊性上升为普遍问题维度）；③ gap 的表述落在"IS 文献没有考虑这一维度"（#26 三原因）。
- 写法检验标准：如果删掉"编码智能体"四个字，换成"欺诈评论/恶意软件/表格数据"，论文的 gap 和贡献是否还成立？若仍成立，说明特殊性没有论述出来——需要回到"一句抽象"重新提炼。

## 六、待办
