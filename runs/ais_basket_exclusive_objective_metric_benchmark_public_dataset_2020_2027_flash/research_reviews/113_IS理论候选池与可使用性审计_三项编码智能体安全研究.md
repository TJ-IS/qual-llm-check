# IS 理论候选池与可使用性审计：三项编码智能体安全研究

## 0. 审计结论

本轮不再以“概念上能否解释 coding agent”作为理论入选标准，而采用更严格的问题：**这个理论能否在现有公开数据、可承担的标注工作和一篇算法论文的实验设计中被正确使用？**

审计后的暂定结论如下。

1. **研究一暂不设社会理论为核心。**最可行的是问题结构型范式：从公开任务、可操纵载体、agent 轨迹、状态差分和可执行危害形成攻击过程形式化。`Choice and Chance` 只能作为有限的过程参照；技术可供性、鲁棒优化和安全博弈均不宜成为核心。
2. **研究二优先考虑“任务条件能力暴露＋最小权限/安全控制配置”的形式化路线。**犯罪机会理论保留为竞争候选，但只有目标适合性和守护变量能从公开数据稳定测量时才进入。现有“单元操纵风险”不能先定义后找理论。
3. **研究三采用分层理论架构最合理。**数字化高可靠组织与 frame problem 提供“自动快速路径＋人类例外处理”的元需求；动态入侵防御/反馈控制定义在线状态和动作；信号检测、基率与期望效用约束评价。集体正念不能被归给算法主体。

这意味着理论质量不等于理论数量。研究一完全可以没有一个宏大社会理论；研究三也可以让组织理论只负责设计要求、控制理论负责算法，而不要求一个理论贯穿所有层次。

## 1. 可使用性审计框架

### 1.1 十二项硬条件

| 维度 | 审计问题 | 一票否决情形 |
|---|---|---|
| 行动者 | 理论主体是攻击者、agent、开发者、安全团队还是组织？ | 把人类认知/动机直接赋给算法 |
| 分析层次 | 构念属于单元、动作、轨迹、任务、仓库或组织？ | 不说明跨层聚合规则 |
| 生成机制 | 理论机制是否实际生成当前数据？ | 轨迹被牵强解释为沟通或自我披露 |
| 构念现成性 | 公开数据中是否已有构念指标或可验证代理？ | 必须先完成独立的构念发现研究 |
| 映射唯一性 | 原始事件到理论变量是否有可复现规则？ | 研究者可随意把任意特征命名为构念 |
| 标注成本 | 是否可由自动日志、状态差分或有限专家标注获得？ | 依赖无法获得的组织访谈/长期田野 |
| 参数可估 | 概率、成本、容量和效用从何而来？ | 核心结果依赖无依据的任意权重 |
| 计算后果 | 理论改变输入、状态、动作、目标、约束或评价中的哪项？ | 移除理论后算法完全不变 |
| 同研究可证伪 | 能否设置理论消融、机制效度或边界实验？ | 只能在讨论中宣称解释力 |
| 范围相称 | 使用理论是否把一篇算法论文扩展为两项研究？ | 先做质性发现/量表开发再做算法 |
| 方法兼容 | 理论的静态/动态、独立/交互假设是否匹配数据？ | 静态边际归因用于强序贯交互而无修正 |
| 模仿风险 | 是否与某篇参照文献形成对象替换式同构？ | 理论—算法—评价链几乎原样搬用 |

### 1.2 评级语言

- **A：可进入当前设计。**构念现成、映射清楚、直接改变算法，且可在同一研究检验。
- **B：有条件保留。**解释适配，但需先验证部分测量或边界；不得先写入核心理论。
- **C：只作背景/补充。**可说明重要性、边界或评价原则，但不产生核心算法。
- **D：排除。**主体/层次错配、需要独立发现研究、无法测量，或模仿风险不可接受。

## 3. 研究一候选审计：攻击生成与威胁过程

### 3.1 候选比较

| 候选 | 主体/层次适配 | 数据与测量 | 对算法的作用 | 主要问题 | 评级 |
|---|---|---|---|---|---|
| **公开轨迹驱动的威胁过程形式化（问题结构型）** | 攻击载体—agent 动作—环境状态—危害结果完全同层 | 原始任务、调用日志、文件/进程差分、PoC/测试均可记录 | 定义状态、动作、成功条件、覆盖度和验证器 | 必须证明不是任意 taxonomy；需要跨基准稳定事件模式 | **A** |
| **信息安全妥协过程（Choice and Chance）** | 目标组织视角与攻击路径相关，但原文是网络告警和组织层 | 蓄意/机会、扫描/探测/攻击状态未在 coding-agent 基准中天然标注 | 若测量成立，可约束路径类别和阶段转移 | 原理论由扎根研究发现，详细测量未完成；移植可能主观 | **B−** |
| **数字操作的 frame problem** | 能解释 agent 无法处理开发者未预见状态 | 未见/框架外状态很难仅靠标签直接确认 | 可支持自适应压力测试与未见攻击评价 | 不解释攻击者如何选择和实施攻击 | **C** |
| **鲁棒优化＋RL** | 对抗者与防御者形式匹配 | 状态、动作、奖励可得 | 直接产生 min-max 与攻击策略 | 与 RADAR 高度同构；若没有防御训练，内外层问题也不成立 | **D** |
| **Stackelberg/安全博弈** | 仅在防御者策略同时内生时成立 | 需攻击者类型、双方效用、信念与控制效果 | 可求攻防均衡 | 当前研究一只生成攻击；效用和信念缺少可靠来源 | **D** |
| **技术可供性** | 关系性概念可宽泛描述能力实际化 | 现有基准没有感知/实际化构念；通常需情境化发现 | 若强行使用只能产生研究者自定能力清单 | 过宽、主观、需额外质性与构念验证，范围失控 | **D** |
| **MDP/RL** | 适合序贯决策 | 轨迹可记录 | 提供求解器 | 是方法形式，不是 IS 领域理论；不能单独承担必要性与贡献 | 方法，不评级 |

### 3.2 暂定理论—算法链

研究一建议采用以下最小链，而不是另找一个听起来新颖的核心理论：

> coding agent 在混合信任工作区中以序贯行动改变环境 → 一次性输入扰动无法表达跨通道状态实际化 → 由公开基准和真实执行定义统一的攻击事件模式与危害状态 → 以约束序贯搜索/RL 探索路径 → 用功能保持、真实危害、跨仓库迁移和状态覆盖共同评价。

这条链的 IS 贡献必须落在“行动型信息系统的威胁过程与可复用设计知识”，而不是宣称 RL 本身是理论创新。`Choice and Chance` 的保留条件是：至少两个公开基准能够按预注册规则自动映射到其路径/阶段变量，并且理论版过程模型相对纯事件模型产生可检验的泛化或防御洞见。否则删除。

## 4. 研究二候选审计：事前授权与守护配置

### 4.1 候选比较

| 候选 | 主体/层次适配 | 数据与测量 | 对算法的作用 | 主要问题 | 评级 |
|---|---|---|---|---|---|
| **任务条件能力暴露＋最小权限/安全控制配置（问题结构型）** | 任务、能力、权限、控制和结果同层 | 正常轨迹给出能力需求；攻击轨迹给出暴露；控制成本可实验/情景化 | 直接定义最小充分授权、控制选择、效用与安全约束 | 与既有安全控制分配接近，必须加入任务条件授权、跨能力依赖和 agent 工具副作用 | **A−** |
| **多层犯罪机会理论** | 攻击者、适合目标、失效守护与当前情境基本匹配 | 目标可达性/价值、权限和守护部分可测；攻击者动机难测，可固定为威胁条件 | 产生目标适合性、守护有效性与跨层汇合表示 | 迁移到问题段落/文件时可能仍主观；多层效应需足够样本 | **B** |
| **犯罪特定机会结构** | 强调组织情境、守护互依和犯罪者成本收益 | 原文为概念模型/案例，变量较多且依赖本地组织知识 | 可用于安全审计 taxonomy | 需要组织过程、员工和部门数据，不适配公开 agent 基准 | **C/D** |
| **Shapley 风险—效用归因** | 可把任务风险分配到单元/能力 | 只要可反复移除单元并运行就可计算 | 产生单元边际风险和效用 | 序贯交互违背简单联盟假设；计算昂贵；与 2026 MISQ 论文模仿风险高 | **B−** |
| **基率＋期望效用/信号检测** | 面向部署决策与组织成本 | 预测混淆矩阵和部署基率可得 | 校准阈值、评价预算与误报损失 | 不解释哪些任务前变量产生风险 | **A（补充层）** |
| **保护动机/威胁规避理论** | 主体是进行威胁评估与应对的人 | agent 或优化器没有人类应对认知 | 最多产生组织采用元需求 | 不能生成单元风险和自动分配规则 | **D（核心）** |
| **代理理论** | 表面上有 principal 与 agent | coding agent 没有自利偏好、契约激励或信息租 | 若强行使用会引入虚构效用 | 对抗注入导致的目标偏转不是经典道德风险 | **D** |

### 4.2 两条竞争架构

**架构 A：任务—权限—控制的问题结构型路线（当前优先）**

1. 从正常任务轨迹学习各任务单元完成所需的能力集合及依赖；
2. 从攻击轨迹估计能力与不可信载体汇合时的危害概率/损失；
3. 在任务可完成性、最小权限、安全预算和审批容量约束下选择权限、沙箱、验证、回滚与人工审批；
4. 评价攻击损失、正常任务通过率、授权面积、审批负荷和参数不确定性。

其优势是数据映射直接、理论负担小。其新颖性门槛也更高：必须证明 coding agent 权限是随任务临时形成、能力之间存在序贯依赖、同一合法工具在不同任务中产生不同暴露，因而不能由传统静态资产—控制配置模型解决。

**架构 B：犯罪机会驱动路线（条件候选）**

1. 把攻击者动机固定为威胁情景，不试图从公开数据推断心理动机；
2. 以资源价值、可达性、权限、持久性和影响范围测量目标适合性；
3. 以来源验证、沙箱、最小权限、审批、测试和回滚测量守护；
4. 以任务单元—任务—仓库三个层次建模机会汇合；
5. 预测器估计机会，优化器配置守护。

其保留条件是上述指标能在公开任务中达到高标注一致性，且理论分组相对通用多模态特征带来机制可解释的跨仓库泛化，而非只增加特征名称。

## 5. 研究三候选审计：运行状态控制与人类升级

### 5.1 候选比较

| 候选 | 主体/层次适配 | 数据与测量 | 对算法的作用 | 主要问题 | 评级 |
|---|---|---|---|---|---|
| **数字化高可靠组织＋frame problem** | 主体是人类与数字操作构成的组织，适配安全运营 | 已知/未知事件、自动处理、升级、规则更新可记录；完整正念构念需组织研究 | 推出自动快速路径、证据保留、人类升级和学习闭环 | 不能说算法“正念”；公开基准难评价组织层涌现结果 | **B（元需求）** |
| **动态入侵防御/反馈控制** | 状态、控制动作、扰动和运营容量与运行门控同层 | 告警/动作流、误报漏报、队列和延迟可测或情景化 | 直接定义状态更新、放行/限权/阻断/升级与动态损失 | 需避免照搬传统 IDS；必须加入任务意图、工具副作用和持久状态 | **A（计算内核）** |
| **信号检测、Bayes、基率与期望效用** | 适配检测与处置阈值 | 混淆矩阵、基率、动作代价可计算 | 防止低基率高准确率假象，选择成本敏感阈值 | 不生成轨迹表示或状态转移 | **A（评价/决策层）** |
| **正常事故理论** | 适配复杂交互和紧耦合的系统风险 | 耦合与复杂性可部分由调用/依赖图测量 | 可支持降低耦合、隔离和恢复设计 | 很难从有限基准验证“事故不可避免”等组织命题 | **C** |
| **数字韧性** | 组织恢复与适应层面相关 | 连续性、恢复、适应通常需纵向组织数据 | 可说明恢复价值 | 过宽，难生成门控器；与用户批评的可供性问题相似 | **C/D（核心）** |
| **TTAT** | 原主体是受威胁的人/组织 | 运行轨迹不是威胁评估认知 | 最多支持评估和应对元需求 | 不能推出三档阈值和自动动作 | **D（核心）** |
| **信息操纵理论＋担保理论** | 需要攻击者自我披露和外部验证信息 | agent 日志不是攻击者的自我呈现，调用图也非天然担保 | 现有三通道只能事后牵强对应 | 行动者、沟通关系和生成机制均错配 | **D** |
| **问责理论** | 主体是会因可识别、审计而改变行为的人 | agent 不会因心理问责而系统加工 | 可支持人类操作员界面与审计制度 | 不能解释被注入 agent 的自动行为 | **D（核心）** |

### 5.2 推荐的分层架构

研究三可采用“组织理论给元需求、控制理论给工件、决策理论给评价”的三层架构。

| 层 | 理论来源 | 只承担的作用 | 可观察变量 | 不允许越界 |
|---|---|---|---|---|
| 组织层 | 数字化高可靠组织、frame problem | 自动处理已知事件；保留例外；把框架外事件升级给人；用处置结果更新规则 | 自动处理率、未知攻击召回、升级负荷、专家纠正、恢复/规则更新时间 | 不把单个算法或 agent 称为正念主体 |
| 控制层 | 动态 IPS、反馈控制 | 形成在线状态，联合选择放行、限权、阻断、升级与恢复 | 风险状态、工具副作用、队列、延迟、环境差分 | 不把静态三阈值包装为动态控制 |
| 评价层 | 信号检测、Bayes、期望效用 | 结合部署基率和不对称成本选择工作点 | TPR/FPR、基率、危害、干扰、人工成本 | 不以 accuracy/F1 单独证明部署价值 |

研究三相对研究二的必要性可由“信息集扩展”形式化。设任务前信息为 \(I_0\)，包括问题、仓库、工具、技能和默认权限；第 \(t\) 步新增信息 \(O_t\)，包括计划、调用参数、工具返回和环境差分。研究二选择初始控制 \(C_0=f(I_0)\)；研究三选择运行控制 \(C_t=g(I_0,O_{1:t})\)。只要 \(O_t\) 包含任务前不可得且与危害相关的信息，运行控制就具有独立且互补的必要性，无需声称 \(f\) 错误或无效。

## 6. 排除候选的详细记录

### 6.1 技术可供性：为何从首选撤回

技术可供性并非简单的功能列表，而是行动者在特定目标和情境下对技术行动可能性的感知与实际化关系。严格使用要求回答谁感知、为实现什么目标、在何种组织条件下实际化，并通常需要情境化发现与验证。当前公开 coding-agent 基准主要标注输入、工具、轨迹和结果，不标注攻击者/开发者/agent 的感知可供性。

两种使用方式都不可接受：

- 若把 read/write/execute/tool-use 直接命名为 affordances，理论没有增加区别于普通能力清单的测量或计算约束；
- 若按理论严格操作化，则需先开展访谈、开放编码、构念开发和效度检验，显著扩展范围并使结果依赖研究情境。

因此可以用“授权能力”“工具能力”“状态改变”作为普通描述，但不以可供性为核心理论、构念标签或攻击空间来源。

### 6.2 `Choice and Chance`：为何降级而非立即采用

原文通过访谈、观察、网络搜索和文档回顾的扎根过程发现构念，再用数百客户的安全告警部分验证。作者明确指出组织控制、吸引力和 Internet presence 的详细测量工具仍是后续研究，部分实证只使用可得代理。若本项目跳过相同发现过程，直接把 agent 动作命名为 information scan、targeted probe 和 targeted attack，会掩盖测量缺口。

它仍保留 B−，因为“机会攻击与蓄意攻击并存、攻击从信息获取向妥协推进、控制主要抑制阶段转化而非攻击数量”可能为 coding-agent 跨步骤攻击提供有价值的边界命题。是否保留由自动映射率、标注一致性和跨基准复现决定。

### 6.3 集体正念：为何只能位于社会技术层

[High Reliability in Digital Organizing](../../../database_fulltext_all/12734_2019_high-reliability-in-digital-organizing-mindlessness-the-frame-problem-and-digital-operations1.md) 对本项目尤其重要，因为它直接研究计算机安全公司的算法化运营。原文的核心不是“算法可以正念”，而是算法天然受 frame problem 限制；集体正念通过人类的情境敏感处理监视和改进高速、规模化但 mindless 的数字操作而涌现。

所以只有当研究三包含可实施的人类升级接口、证据摘要、队列/容量和反馈更新时，该理论才真正改变工件。若研究三仍只是自动二分类器加三个动作阈值，应删除集体正念，仅保留动态控制和成本敏感决策。

## 7. 理论采用前的最小实证预检

在改写 34—36 前，建议先做三个小规模、低成本预检，而不是先写理论章节。

### 7.1 研究一：路径构念映射预检

- 从 RedCode、恶意 issue、工具投毒和恶意 skill 各抽取不少于 30 条可执行实例；
- 用不引用理论名称的事件模式标注“载体—agent 动作—环境转移—危害”；
- 再由独立标注者尝试映射 `Choice and Chance` 路径/阶段；
- 若大量事件无法唯一映射、kappa 低或理论映射不增加预测/覆盖信息，删除该理论。

### 7.2 研究二：能力与机会变量可得性预检

- 在正常软件任务中记录完成任务实际使用的文件、命令、网络和工具能力；
- 在攻击任务中记录同一能力是否成为危害必要条件；
- 检查“目标价值、适合性、守护有效性”的标注一致性及缺失率；
- 对比问题结构变量与犯罪机会分组的跨仓库泛化；只有后者稳定增益且可解释才采用理论。

### 7.3 研究三：分层控制可实施性预检

- 确认执行框架能在高影响动作之前截获调用，而不只是事后记录；
- 为自动处理与人工升级定义可测容量、延迟和成本；
- 检验未知攻击/分布外状态是否能被不确定性或状态差分稳定识别；
- 若无法实现人类升级闭环，不使用集体正念表述。

## 8. 当前推荐与需导师/作者确认的分叉

### 8.1 当前推荐

- **研究一**：问题结构型；理论贡献聚焦 coding-agent 攻击过程形式化和执行验证，序贯搜索只是方法。暂不采用技术可供性，`Choice and Chance` 等待映射预检。
- **研究二**：优先改造成任务条件的能力—权限—控制配置问题，以最小权限、安全控制随机优化和任务可完成性为形式基础；犯罪机会只在测量预检通过后进入核心。
- **研究三**：以数字化高可靠组织/frame problem 说明分层人机闭环的必要性，以动态 IPS/反馈控制生成门控，以基率—成本评价部署价值。

### 8.2 下一轮确认需要聚焦的两项实质选择

1. 研究二是否接受从“预测恶意单元并分配防护”向“预测任务所需能力与风险暴露、配置最小充分权限和守护”移动？这是增强 coding-agent 特殊性、同时避开既有安全控制分配同构的最大结构性改动。
2. 研究三是否愿意把“人工升级、证据摘要与处置反馈”纳入工件边界？若不纳入，就不应使用集体正念/数字化高可靠组织作为核心设计依据。

在这两个选择确认前，不宜直接重写三篇论文正文。可以先完成上述预检的数据字段表与小样本标注方案，避免再次出现理论先行、操作化随后勉强拼接的问题。
