# 可行性约束下的三研究一体化修正方案：公开 Benchmark 与 AttackRL 数据契约

## 0. 文档定位

本文是对 111—113 号分析的后续校正，不覆盖这些历史文件，也不直接改写 34—36 号论文正文。校正来自四项不能让位于理论新颖性的现实约束：

1. 三项研究原则上使用公开可获取的数据、代码和可执行环境，不把私有企业日志、真实审批容量、访谈或长期组织田野设为完成条件。
2. 研究一开发的 coding-agent 特化 AttackRL 必须是有独立贡献的核心工件，同时为研究二和研究三生产可复用、有真值的数据。
3. 研究二保留任务执行前的静态攻击预测。coding-agent 攻击的特殊困难是恶意目的可以潜藏在看似正常且功能相关的 issue、代码、配置、依赖和工具描述中，而不是静态方法天然无效。
4. 研究三利用 agent 运行后才出现的计划、调用、返回值和环境状态变化。其必要性来自新增信息，而不是通过否定研究二建立。

这四项约束决定研究问题、理论、数据和算法。任何候选理论若要求重新发现情境可供性、获取私有组织参数或把研究二改造成另一类权限优化问题，即使概念上相关，也不应进入当前三项研究的核心。

## 1. 修正后的总命题

### 1.1 coding agent 的特殊性应落到两个可检验机制

编码智能体不是只输出代码文本的模型，而是在混合信任的软件工作区中读取信息、规划、调用工具、修改文件并执行代码的行动型系统。它带来两个彼此关联但信息时点不同的安全机制。

第一，**攻击更容易潜藏**。issue、注释、配置、代码、依赖说明和工具元数据本来就是完成软件任务所需的信息。攻击者不必提交一个外观明显的恶意 prompt，而可以把诱导伪装成功能需求、修复建议、构建说明或可信工具能力。单个对象可能看似合理，恶意性却潜藏在任务声称、仓库结构、工具能力和预期副作用之间的关系中。这为研究一的隐蔽攻击生成和研究二的异构静态预测同时提供必要性。

第二，**行动会产生任务前不存在的新证据和新风险**。agent 的计划选择、调用参数、工具返回、文件差分、命令、网络和进程状态只有执行开始后才可观察。即使任务前筛查正确地降低了风险，具体行动仍可能因环境反馈、跨步组合或攻击适应而偏离原目标。这为研究三提供独立必要性。

二者不能混写。研究二处理 `I0`，即任务开始前可获得的信息；研究三处理 `I0 + O1:t`，其中 `Ot` 是第 `t` 步新增的运行证据。研究三拥有更多信息，不等于研究二没有价值。

### 1.2 三项研究是一条数据与决策链

```text
公开正常软件任务、公开攻击样本与可执行环境
                         │
                         ▼
研究一：coding-agent 特化 AttackRL
  选择攻击通道、目标单元与操纵算子，接收 agent/环境反馈，执行验证危害
                         │
              同一攻击回合的两种视图
              ┌──────────┴──────────┐
              ▼                     ▼
      D_att-static             D_att-trace
  任务前快照、操纵位置       动作—观察流、状态差分、时间真值
              │                     │
              ▼                     ▼
研究二：静态预测与定位     研究三：运行风险更新与动作门控
  输出 p0、可疑单元          输入 p0，随 Ot 更新 pt
              └──────────┬──────────┘
                         ▼
冻结防御器后的 AttackRL 自适应压力测试与可选对抗重训
```

这里的联系不是在论文中互相提一句，而是共同的数据主键、标签协议和实验顺序。研究一没有为后续研究生产可用真值，AttackRL 就只是孤立的攻击算法；研究二的静态风险没有作为研究三的先验，二、三之间也只是主题相似。

## 2. 公开数据路线及其角色

### 2.1 可作为主干的公开资源

| 公开资源 | 已有对象 | 在本项目中的角色 | 不应承担的角色 |
|---|---|---|---|
| [SWE-bench 官方数据说明](https://github.com/SWE-bench/SWE-bench/blob/main/docs/guides/datasets.md) | 真实 GitHub issue、仓库、base commit、补丁与测试；含完整集和 Verified 等公开子集 | 提供正常软件任务、仓库状态和功能测试；构造 issue、仓库文件与配置攻击通道 | 本身没有 coding-agent 攻击标签，不能直接当安全 benchmark |
| [SWE-Gym](https://github.com/SWE-Gym/SWE-Gym/blob/main/README.md) | 约 2.4K 个可执行软件任务、训练环境和 agent 轨迹 | 提供 RL 环境、正常任务轨迹、功能奖励与可扩展任务池 | 不能用正常轨迹自动替代危害验证器 |
| [RedCode](https://github.com/AI-secure/RedCode) | 代码 agent 的不安全执行与生成任务、Docker 环境和任务专用验证 | 提供危害类别、执行环境、攻击种子、外部危害验证和独立测试 | 不应把 RedCode 的单任务攻击空间直接等同于本研究的跨工作区 AttackRL |
| [AgentDojo](https://github.com/ethz-spylab/agentdojo) | 公开的 agent 攻击/防御环境、间接 prompt injection 任务和执行评价 | 借鉴威胁模型、攻击/防御协议；作为跨 agent 情境的外部边界测试 | 不是 coding-agent 主 benchmark，不能替代仓库级软件任务 |
| [RedCodeAgent](https://github.com/1mocat/RedCodeAgent) | 自动 red-teaming agent、记忆/工具箱与执行验证 | 研究一必须比较或清楚讨论的直接先例；可作为基线或攻击种子来源 | 不能再声称本研究是首个自动代码 agent 红队系统 |

IssueTrojanBench、JAWS-Bench、MalSkillBench、SkillJect、MCPTox 等前沿工作可在数据和代码正式公开、许可证允许、验证器可复现时加入独立测试。核心设计不能依赖尚未稳定发布的未来数据。

### 2.2 建议的主干组合

最稳健的最小组合是：

- 用 SWE-bench Verified/Lite 或 SWE-Gym 的小子集提供正常任务、仓库和功能测试。
- 用 RedCode 的危害类别与可执行验证器提供攻击目标或外部测试。
- 用公开恶意 issue、工具描述、skill 或代码攻击样本初始化操纵算子库。
- 由研究一 AttackRL 在统一 sandbox 中生成 `D_att`，而不是等待一个恰好同时包含静态快照、完整轨迹和两类真值的现成数据集。

这种组合符合公开 benchmark 的主流实现方式：复用真实任务与公开环境，自行添加与研究问题一致的处理、标签和实验协议。公开数据不等于只能原样使用现成标签。

## 3. 研究一：AttackRL 是核心工件和上游数据生产器

### 3.1 研究问题边界

研究一不研究一般 LLM jailbreak，也不只做 prompt 的同义改写。它研究的是：在真实软件任务和工作区约束下，攻击策略如何选择 agent 会读取的异构对象，依据 agent 与环境反馈逐步调整操纵，并在保持表面任务功能的同时诱发可执行危害。

相对于 RedCodeAgent 等已有自动红队工作的增量不能只写成“我们使用 RL”。至少需要同时满足下列差异中的三项：

1. 状态显式包含任务、仓库结构、可操纵对象、agent 历史和环境反馈。
2. 高层动作选择攻击通道、目标单元和操纵算子，低层生成器只负责实例化内容。
3. 奖励同时包含功能保持、实际危害、隐蔽性与攻击面覆盖，而不是只以 judge 成功为终点。
4. 攻击成功由测试、PoC 或环境状态验证，不由另一个 LLM 的有害性评分单独判定。
5. 每个回合自动导出研究二和三所需的两种数据视图与时间真值。

### 3.2 可实现的层级 AttackRL

建议把巨大文本生成空间拆成“可训练的小策略＋受约束的内容实例化”。

**状态 `st`**

- 任务：issue/指令、目标测试、语言与仓库类型。
- 工作区：文件/依赖图、配置、工具/技能清单、当前差分。
- 攻击历史：已用通道、目标单元、算子、预算与失败原因。
- agent 反馈：读取了什么、拒绝/接受、计划和工具返回的摘要。

**高层离散动作 `at`**

- 通道：issue、代码/注释、配置/构建文件、依赖、工具/技能元数据。
- 单元：具体段落、AST 节点、文件、依赖项、工具描述字段。
- 算子：新增、替换、重定位、跨对象拆分、条件触发、伪装为功能需求等。
- 继续、换通道、回退或停止。

**低层实例化**

LLM 根据高层动作生成受 schema 和语法约束的候选改动。RL 不必直接在整个 token 空间训练，从而显著降低样本和计算成本。

**奖励**

可以从如下可测部分形成约束奖励：

`R = wh × Harm + wu × Utility + ws × Stealth + wc × Coverage − wb × Budget − wi × Invalid`

- `Harm`：PoC、环境状态或安全测试验证的实际危害。
- `Utility`：原任务测试、构建或任务完成是否保持。
- `Stealth`：静态基线、规则扫描器和被攻击 agent 是否容易发现；必须报告其具体定义，不能只用主观 LLM 分数。
- `Coverage`：是否探索新的通道、单元、攻击家族或状态路径。
- `Budget`：回合数、候选数、token、工具调用或墙钟时间。
- `Invalid`：语法错误、构建失败、无法执行或越出 sandbox。

权重不宣称为真实组织偏好。主结果应同时报告各原始分量，并做 Pareto 或敏感性分析，避免一个任意加权总分掩盖结果。

### 3.3 低成本训练路线

1. 用公开攻击样本和规则模板做行为克隆或离线 warm start。
2. 在 50—100 个公开任务上训练离散高层策略，缓存不变的构建与静态分析结果。
3. 先固定一个开源 agent scaffold、一个主要模型和 3—4 个攻击通道；MVP 跑通后再扩模型和框架。
4. 对昂贵执行只保留通过语法/构建预筛的候选，并设置每任务固定预算。
5. 与模板、随机/启发式搜索、无反馈变体、扁平动作空间及 RedCodeAgent 可兼容部分比较。

这比一开始训练端到端文本策略更可行，也仍然保留 AttackRL 的核心：策略依据软件状态和 agent 反馈学习如何选择攻击路径。

### 3.4 研究一的独立贡献与系列贡献

研究一自身至少评价：执行验证 ASR、功能保持率、隐蔽性、跨仓库/跨模型迁移、攻击面覆盖、查询/执行成本和失败类型。

系列贡献则评价其数据是否真正提高后续防御：

- AttackRL 数据相对于固定模板数据是否提高研究二在未见攻击家族上的静态检测与定位。
- AttackRL 的完整轨迹是否提高研究三在首次危害前的检测与干预。
- 冻结研究二、三后，AttackRL 是否能发现新的规避路径；对抗重训是否降低规避率。

这组下游证据能证明 AttackRL 不只是追求更高 ASR，而是有用的攻防基础设施。

## 4. 共享数据契约：同一回合，两种合法视图

### 4.1 回合级公共字段

| 字段组 | 最小字段 | 生成方式 |
|---|---|---|
| 身份与划分 | `episode_id`、`task_id`、`repo_id`、`base_commit`、数据来源、split | 公开任务元数据与预注册划分 |
| 环境 | agent 框架、模型、工具/权限配置、container image、seed | 运行配置自动记录 |
| 攻击策略 | policy/checkpoint、攻击家族、通道、目标单元、算子、预算 | AttackRL 动作日志 |
| 静态状态 | 原始快照、攻击后快照、对象图、修改 diff、操纵单元标签 | 攻击应用前后自动保存 |
| 运行轨迹 | 时间步、计划/消息、工具名、参数、返回值、文件/进程/网络差分 | agent wrapper 与 sandbox 记录 |
| 真值 | 功能结果、危害结果、首次风险显现步、首次危害动作步、最终持久差分 | 测试、PoC、规则与人工小样本复核 |
| 成本 | token、模型调用、工具调用、执行时间、构建时间 | 系统计数器 |

### 4.2 `D_att-static`：研究二能看的内容

研究二只能看到 agent 开始运行前的当前快照及其公开元数据。干净—攻击配对可用于训练期的对比学习或产生标签，但测试时不得把干净副本作为输入，否则任务会退化成 diff 检测。研究二标签包括：

- 任务级：clean/attacked、攻击通道、攻击家族。
- 单元级：被操纵段落、文件/AST 节点、配置项、依赖或工具字段。
- 结果级：该静态攻击在目标 agent 上是否实际成功，可作为难度或后验分析标签，不作为测试输入。

### 4.3 `D_att-trace`：研究三能看的内容

研究三按时间顺序接收事件，不得访问未来步骤。标签包括：

- `t_signal`：攻击影响首次在计划、调用或环境差分中形成可观察证据的时间。
- `t_harm`：第一个会实际造成危害且应在执行前拦截的动作时间。
- 每步风险类型、关联静态单元、动作是否可逆、门控后的任务与危害结果。

只有记录 `t_harm`，才能评价“是否在危害前发现”，而不是用整条恶意轨迹做普通离线分类。

## 5. 研究二：潜藏攻击的静态预测不是弱化版本

### 5.1 研究问题与必要性

研究二应明确限定为：agent 尚未执行时，能否从公开可获得的异构软件对象中发现并定位被伪装成功能性内容的攻击。

其重要性不能写成“目前没有研究静态预测”。更有力的逻辑是：

1. coding agent 必须读取自然语言和代码化对象才能工作，安全系统无法简单移除这些输入。
2. 攻击者可以把恶意目的嵌入功能合理内容，使孤立文本、代码或工具扫描都容易接受其表面解释。
3. 执行前是成本最低且能避免危害实际化的决策窗口；公开任务已经提供 issue、仓库和工具元数据，因此静态筛查具有现实可行性。
4. 难点不在“有没有静态信号”，而在能否联合对象表面与对象关系，识别攻击者难以同时维持的跨对象一致性。

### 5.2 当前最适合继续验证的理论路线

第一候选是 [SIGHT 所采用的信号理论路线](../../../database_fulltext_all/01598_2020_design-principles-for-signal-detection-in-modern-job-application-systems-identifying-fabricated.md)。该研究面对的是早期筛查中的虚假信号：容易操纵的表面自报使信号系统失灵，设计者需要减少对此类信号的依赖，并结构化收集更难操纵、诊断力更高的替代信号。可迁移到本研究的不是人类说谎时的心理生理特征，而是三个可检验机制：

- 攻击者以较低成本操纵 issue、注释或工具描述中的表面任务信号。
- 代码/依赖结构、对象间关系、来源历史或能力声明与实际代码之间的关系可能更难被同时操纵。
- 联合表面信号与替代信号应比单一内容信号更能抵抗未见攻击和自适应攻击。

第二个算法范式来自 [MISQ 假网站检测](../../../database_fulltext_all/10376_2010_detecting-fake-websites-the-contribution-of-statistical-learning-theory.md)。高度伪装的假网站会复制合法网站的文本、图像和风格，但研究仍能使用公开静态的文本、源代码、URL、图像和链接结构做检测。它对本研究最重要的启示是：潜藏性不否定静态预测，反而要求领域特定的异构表示、结构关系和跨域泛化测试。

这一路线仍是候选，不应在跑出机制消融前写成已证实理论。若“较难操纵的替代信号”在 AttackRL 自适应攻击下没有稳定优势，则退回领域结构化静态检测，而不勉强保留信号理论。

### 5.3 可实现的模型与实验

**输入视图**

- 内容视图：issue、注释、配置文本、工具/技能描述。
- 代码视图：AST、调用、数据流、依赖与构建结构。
- 关系视图：任务声称—目标文件—预期改动—工具能力之间的一致性。
- 来源视图：公开可得的仓库、提交、包或工具元数据；缺失时模型必须可退化运行。

**输出**

- 任务级攻击概率 `p0`。
- 单元级可疑分数与定位。
- 通道/攻击家族作为辅助任务，可选而非必须。

**预算与动作**

研究二可以保留“预算化预置防御”，但预算必须来自公开实验可测量对象：`top-k` 审查单元、允许调用的静态分析器数量、token/墙钟时间、允许拦截或深检的任务比例。预测后的动作可简单定义为通过、深检、隔离运行或拒绝，不必估计真实企业审批成本和人员容量。

**关键比较**

- 纯 LLM/text、纯代码扫描、纯来源信号。
- 早期融合、晚期融合、关系/图模型。
- 去掉替代信号、去掉跨对象一致性、去掉配对对比学习。
- 固定模板攻击、AttackRL 攻击、未见攻击家族和冻结检测器后的自适应攻击。

**核心指标**

任务级 AUROC/AUPRC/F1、单元定位 Recall@k/IoU、校准、预算下攻击召回、残余执行 ASR、正常任务误拦截率、功能完成率、token/时间和扫描调用数。

## 6. 研究三：运行时的必要性来自新增证据

### 6.1 不与研究二冲突的正式表达

设研究二在任务开始前的信息集 `I0` 上给出 `p0 = f(I0)`。agent 第 `t` 步运行后出现观察 `Ot`，研究三计算 `pt = g(p0, O1:t)` 并选择动作 `Ct`。只要 `Ot` 包含任务前无法获得、且与危害相关的信息，研究三就具有独立价值。

因此不写：

> 静态方法无法检测攻击，所以必须运行时检测。

应写：

> 静态筛查利用执行前可得信息提前识别潜藏攻击；运行时方法进一步利用计划、调用参数、工具返回和环境差分等新增证据，在攻击经 agent 行动实际化之前更新风险并控制高影响转移。

### 6.2 理论与计算内核

研究三当前最可行的核心不是集体正念，而是 IS 安全文献中的 [动态入侵防御与主动/响应式决策](../../../database_fulltext_all/01230_2007_intrusion-prevention-in-information-systems-reactive-and-proactive-responses.md)，结合序贯检测、Bayes 更新或反馈控制。它们可以直接改变工件：

- 状态：`p0`、历史风险、当前计划/工具/环境证据、剩余预算和动作可逆性。
- 扰动：攻击诱导、agent 规划变化、工具返回和环境状态变化。
- 控制：放行、延迟/限权、阻断、请求确认或在 sandbox 中继续观察。
- 损失：未拦截危害、误拦截正常任务、延迟和计算开销。

数字化高可靠组织与 frame problem 可以说明自动规则难以预枚举全部运行状态，但当前公开 benchmark 无法检验集体正念、真实团队容量和组织学习。除非未来另做社会技术实验，它们只应作为边界背景，不应决定算法或贡献主张。

### 6.3 可实现的模型与实验

1. 用研究二的 `p0` 和可疑单元初始化风险状态；另设无 `p0` 变体检验二、三连接是否有增益。
2. 把每个 plan/tool call/result/diff 编码为事件，使用轻量时序模型、状态空间模型或事件图更新 `pt`。
3. 在工具真正执行或文件/网络状态提交前设置 wrapper hook，使模型可以事前门控；只有事后日志的框架不能用于主要阻断实验。
4. 正常任务与攻击任务都在公开 sandbox 中运行，比较只检测、检测加门控、静态 `p0`、纯运行模型和静态—运行联合模型。
5. 冻结研究三后，让研究一 AttackRL 根据运行反馈寻找延迟触发、跨步拆分和良性动作掩护等规避路径。

**核心指标**

- 危害前检测率与危害前阻断率。
- `t_detect − t_signal` 和 `t_harm − t_detect`，即发现延迟与安全裕度。
- 攻击成功率、正常任务完成率、误阻断和平均运行开销。
- 风险校准、未见攻击家族泛化和自适应绕过率。
- 与研究二连接的增量：联合模型相对于仅 `p0` 和仅运行轨迹的提升。

## 7. 数据共享不等于循环论证

研究一生成研究二、三的数据是系列优势，但必须防止“用自己的攻击训练，再用同类攻击证明自己的防御有效”。建议同时设置四道隔离。

### 7.1 四类互斥划分

1. **仓库互斥**：同一仓库及其相近 commit 不跨训练、验证和测试。
2. **攻击家族互斥**：至少保留整类未见通道或操纵策略作测试。
3. **生成策略互斥**：测试包含不同 AttackRL checkpoint、不同攻击生成器和非 RL 公开攻击。
4. **环境互斥**：至少在另一 agent 框架或模型上做迁移测试。

### 7.2 分阶段冻结协议

- 阶段 A：研究一训练 AttackRL，固定版本 `AttackRL-v1`，生成第一版 `D_att`。
- 阶段 B：冻结 `D_att` 划分，训练研究二和三，不允许攻击器根据防御结果在线改变测试样本。
- 阶段 C：冻结研究二和三，再用未参与训练的 `AttackRL-v2` 或自适应策略做压力测试。
- 阶段 D：可做对抗重训，但将其报告为防御增强结果，不与阶段 C 的干净泛化结果混合。

### 7.3 两套结果分别报告

- 内部机制证据：在 `D_att` 上检验设计组件、定位和时序机制。
- 外部有效性证据：在 RedCode、公开 issue/tool/skill 攻击或其他可复现数据上检验迁移。

若外部数据只有任务级标签，也可以只报告任务级检测和 ASR，不应为追求整齐而制造单元或时间真值。

## 8. 理论选择的可使用性结论

| 研究 | 当前首选 | 为什么适合实现 | 采用前必须通过的检验 | 当前排除/降级 |
|---|---|---|---|---|
| 一 | 公开数据约束下的攻击过程形式化；`Choice and Chance` 仅作候选参照 | 状态、动作、反馈、执行危害和持久差分都可从 sandbox 自动获得；直接约束 AttackRL | 路径/阶段若不能自动稳定映射或不增加设计知识，就不使用行为理论 | 技术可供性排除；RADAR 式鲁棒优化链避免复用；安全博弈暂不适用 |
| 二 | 虚假信号、信号可操纵性与替代信号诊断力；假网站检测提供结构化静态范式 | 所有核心对象在任务前可见；AttackRL 自动提供配对和定位真值 | 替代信号必须在未见家族和自适应攻击下显示增量，且能解释何以较难操纵 | 权限配置、犯罪机会降为扩展；保护动机、代理理论排除 |
| 三 | 动态入侵防御、序贯检测/反馈控制；基率与成本敏感评价 | action–observation、环境差分、干预和延迟均可公开实验 | 必须能在 `t_harm` 前拦截，且 `p0 + Ot` 相对单独输入有增量 | 集体正念/HRO 降为背景；数字韧性、TTAT 不作算法核心 |

技术可供性仍然排除。它过大、关系性强，通常要求在具体行动者、目标和组织情境中发现“感知—实际化”构念；公开 benchmark 不提供这些变量。把 read/write/execute 简单改名为 affordance 不产生计算价值，严格操作化又会扩展成独立质性研究。

## 9. 三篇引言可采用的重要性链

### 9.1 共同母链

1. 软件开发者把仓库读取、修改、测试和执行逐步委托给 coding agents；这些系统的价值来自对信息系统采取行动，而不只是生成文本。
2. 行动发生在混合信任的工作区。完成任务所需的 issue、代码、配置、依赖和工具描述同时可成为攻击载体，使恶意目的潜藏于功能合理内容。
3. agent 又会依据环境反馈进行多步规划和工具调用，使局部信息操纵能够转化为持久代码或系统危害，并在运行中产生任务前不可见的新证据。
4. 因此组织不仅需要知道 agent 是否回答了有害文本，还需要系统发现可执行攻击、在执行前识别潜藏操纵，并在行动展开时根据新增证据控制危害实际化。
5. 三项研究依次提供 AttackRL 与公开攻击基准、任务前静态预测、运行时风险更新和门控，形成一条可复现的攻防链。

### 9.2 三项研究的独立收束

- **研究一**：如果攻击评价仍停留在一次性 prompt 或固定模板，组织就无法发现攻击者如何利用软件工作区的多类对象和 agent 反馈形成可执行危害，也无法获得训练前置与运行防御所需的系统真值。
- **研究二**：coding-agent 攻击可伪装成功能相关的软件对象；执行前又是避免危害实际化的最低成本窗口，因此需要联合内容、结构、关系与来源的静态预测，而不是把潜藏性误写成静态方法无用。
- **研究三**：agent 执行会暴露计划、调用、返回值和环境差分等 `I0` 中不存在的信息，并可能产生新的跨步风险；运行时方法利用这一信息增量补充静态先验，在首次危害动作前做控制。

### 9.3 禁止形成的关系

- 不写“研究二无法发现新风险，因此研究三更先进”。
- 不写“研究三弥补研究二失败”。
- 不写“研究一只是为后二项研究造数据”。
- 不写“理论越多越符合 IS”。

更准确的关系是：研究一既有独立的攻击设计与评价贡献，又提供共享数据；研究二和三分别在不同信息集与决策时点降低同一攻击实际化过程中的风险；研究三对研究二做信息增量更新，而不是替代。

## 10. 最小可行验证与停止条件

### 10.1 第一阶段 MVP

- 50—100 个公开软件任务。
- 一个可控 agent scaffold 和一个主要模型。
- issue、代码/注释、配置/工具描述中的 3—4 个攻击通道。
- 每个任务固定较小攻击预算，功能与危害验证器必须先稳定。
- 导出 `D_att-static` 和 `D_att-trace`，完成回合 ID、静态位置与时间真值核对。
- 研究二至少完成内容基线、结构基线和跨视图模型。
- 研究三至少完成无 `p0`、仅 `p0` 与 `p0 + runtime` 三组比较。

### 10.2 进入扩展阶段的门槛

只有同时满足下列条件才扩大任务、模型和攻击空间：

1. 功能与危害验证器的一致性达到预注册标准。
2. AttackRL 相对模板/随机基线在危害、隐蔽性或覆盖中至少一项有稳定增益，且没有以功能崩溃换取 ASR。
3. 研究二的测试输入无干净副本和运行信息泄漏，未见仓库结果可复现。
4. 研究三能够在实际危害动作前拦截，而不是只做整轨迹事后分类。
5. 两种数据视图能从同一回合自动生成，不依赖大规模人工重标。

若某个候选理论不能在上述 MVP 中改变一个可观察字段、模型组件、约束或可证伪实验，就暂不写入核心理论。先跑通数据—算法闭环，再依据真实失败类型继续检索和选择理论，符合导师文章中“理论构念必须进入计算设计”的基本范式。

## 11. 下一轮文献检索的聚焦问题

当前不宜继续无边界扩大理论列表。下一轮只需围绕三个能够改变设计的问题定向检索：

1. IS 安全文献中是否存在比 `Choice and Chance` 更贴合“攻击者依据系统反馈选择跨对象攻击路径”、且能由公开执行日志直接测量的过程理论。
2. 信号理论在自动化欺骗、虚假数字对象或算法筛查中的哪些构念可以严格迁移到 issue—代码—工具关系，并如何证明某类替代信号更难操纵。
3. 动态入侵防御、序贯决策和反馈控制文献如何定义危害前检测、响应动作与动态损失，以便直接形成研究三的状态、门控与评价。

文献只有在回答这三个问题之一并通过公开数据可使用性审计时才进入候选池。这样可以避免再次出现理论先行、实现随后被迫迁就的情况。
