# 三研究最小可发表单元重划：研究一的评价与研究三的非降级判据

## 0. 文档定位

本文回应两个会改变三篇论文边界的问题。第一，AttackRL 是否只是研究二或研究三的上游模块，因而不应独立成篇？第二，运行时研究是否会被降级为“不断对新输入重复运行研究二的静态算法”？本文只做结构判定，不覆盖既有草案，也不预设三篇一定维持原边界。

## 1. 结论先行

### 1.1 研究一不应以“构建 AttackRL”作为唯一目标

这一担忧成立。若研究一的叙事仅为“开发 AttackRL—生成攻击—导出 `D_att` 供后二项研究使用”，那么它在系列中的功能确实更像上游方法模块。尤其从 RADAR 出发看，攻击仿真只是其第一阶段；RADAR 的总目标是通过攻击—防御循环增强防御智能体的稳健性。因此，把相似的攻击阶段单独拆出，却不增加独立的安全问题、决策输出和效用评价，会显得研究单元被人为切开。

但是，这并不意味着研究一现在必须删除。近年权威 IS 安全算法论文显示，攻击或威胁发现算法可以独立成篇，前提是它不止输出“更多样本”，而要把发现转化为可验证的主动安全知识或决策支持。研究一可被重构为：

> **编码智能体工作空间攻击路径的自动发现与攻击面诊断。**

其第一目标是开发情境特化的 AttackRL，在固定公开任务、固定 victim agent 和相同攻击预算下，更有效地发现保持正常任务功能但造成可执行危害的攻击路径；第二目标是把已验证路径抽象为可迁移的工作空间攻击面情报，对对象、通道、关系或 agent 配置进行风险排序，并检验该排序能否在未见任务与独立攻击方法下提高后续测试或简单加固的单位预算收益。

这样，`D_att` 只是复现记录和系列共享数据，不是研究一的终点，更不是 benchmark。研究一的终点是“发现什么风险、如何优先处置这些风险”的可验证知识。

### 1.2 目前不必立即发明一个全新的第三主题，但必须设置停止条件

当前更稳妥的顺序不是立刻另造一个研究，而是先验证上述双目标版本是否成立。原因是它与近年 IS 主动网络威胁情报论文的最小可发表单元相符，也保留了三项研究之间必要但不过度依赖的联系。

若 MVP 无法同时证明以下两点，则研究一不再单独成篇：

1. AttackRL 在等预算、等 victim、等 oracle 下，相对直接强基线稳定增加经执行验证且保持功能的攻击发现；
2. 从训练阶段攻击路径得到的攻击面排序，能够前瞻性预测未见任务、未见 agent 或独立攻击算法的成功位置，或使固定加固预算获得更大的危害降低。

第一点失败意味着 AttackRL 算法本身没有增量；第二点失败意味着它只能造攻击，不能形成 IS 意义上的主动安全情报。此时应将 AttackRL 并入研究二的对抗训练/稳健评价或研究三的自适应压力测试，并另行检索一个新的研究主题，而不是继续用数据集贡献勉强维持研究一。

### 1.3 研究三目前确实存在被降级为“实时重跑研究二”的风险

现有研究三以三通道特征、滑动窗口、逐步概率和阈值门控为主。审稿人完全可能提出一个强而简单的替代解释：把截至时点 `t` 的所有可见内容拼接为前缀 `I_t`，重复运行研究二的分类器 `f(I_t)`，再对分数设阈值即可。如果论文没有证明状态记忆、事件顺序、行动后果和干预反馈带来超越这一基线的增量，研究三只是研究二的在线部署方式，而不是独立研究。

研究三要独立，研究对象必须从“攻击分类”改为“危害实际化之前的序贯干预”。研究二回答某个任务/工作空间在执行前是否含有潜藏攻击；研究三回答在 agent 行动改变环境、产生新证据且防御动作也会改变后续轨迹时，何时以及如何控制下一次高影响状态转移。其输出应是干预策略而非仅有风险分数。

## 2. 权威 IS 安全算法论文如何使一个算法成为完整研究

### 2.1 NPETD：算法性能之外，还要发现有用的新威胁

Abbasi 等（2022，MISQ）的 NPETD 不是以“提出一个非参数主题模型”收束。论文先在 darknet marketplace 上与 SOTA 基线比较新威胁发现的 recall、F-measure、topic coherence 和处理时间，再在大型 hacker forum 中展示实际发现的新兴主题及其对受害组织和执法部门的意义。其完整研究单元为：

`领域中的未知威胁问题 → 情境适配的发现算法 → 有效性与效率比较 → 真实语料中的威胁发现及其实践含义`。

研究一可模仿的是“技术发现能力＋被发现安全知识的独立价值”，而不是主题模型细节。对应地，AttackRL 的攻击成功率只是第一组结果；第二组结果必须说明新发现路径如何改变对 coding-agent 工作空间攻击面的认识和测试优先级。

### 2.2 EVA-DSSM：一个算法连接数据，另一个度量支持优先级决策

Samtani 等（2022，MISQ）先以 EVA-DSSM 自动连接 Dark Web exploits 与已知 vulnerabilities，再构造 DVSM，将 exploit 日期与 vulnerability severity 转化为设备风险优先级。论文用四个 testbed 和大量强基线评价链接算法，用医院和 SCADA 公共案例以及专家评价检验风险排序的实践效用。其结构直接说明，“发现/连接算法＋基于输出的决策度量”可以构成一个完整的 IS 计算设计研究。

研究一可以借鉴这一双输出结构，但不能照搬综合分数：

- 输出一：经执行 oracle 验证的工作空间攻击路径；
- 输出二：基于这些路径估计的攻击面暴露分布或风险排序，用于决定下一单位红队预算或简单加固预算投向何处；
- 独立评价：在冻结排序后，用未见任务、未见 agent 或非 AttackRL 攻击方法检验 top-k 排序的前瞻命中率和单位预算危害降低。

这一步解决“AttackRL 的结果除了供研究二、三训练还有何用”的问题。

### 2.3 DTL-EL：算法产生的标签被解释为战术、运营与战略 CTI

Ampel 等（2024，MISQ）的 DTL-EL 主要工件仍是一个算法，但论文没有只报告分类分数。它明确解释自动 exploit labeling 如何支持战术 red teaming、运营监测/优先化和战略趋势分析；评价包括来源域设计、迁移增量、替代迁移方法、层级消融以及一个面向组织使用的界面实例。这说明单一算法可以独立成篇，但必须满足三项要求：领域数据特性进入算法、强基线与消融能够识别设计增量、算法输出能够形成明确的安全工作流价值。

对应到研究一，工作空间对象关系必须真实进入状态与动作，而不是只出现在文字中；AttackRL 必须与当前自动红队方法比较；路径输出必须进入攻击面诊断或测试优先级，而不是止于语料导出。

### 2.4 RADAR：既证明 AttackRL 可以评价，也证明“只剩攻击阶段”的叙事风险

RADAR 的第一阶段单独比较 r-VAC 与八类非 RL/RL 攻击方法，以 evasion rate 评价攻击仿真；其后才评价稳健化、重复博弈和实际 detector 设计。这提供两点相反但兼容的证据：

1. 攻击算法并非无法评价。它可以在固定 victim、固定输入、固定动作约束和固定预算下，以经验证的规避/危害结果与成本进行比较；
2. RADAR 的总研究问题是防御稳健化，攻击生成承担服务于外层目标的角色。若研究一既沿用其攻击逻辑，又没有形成自己的外层安全目标，就容易被认为是只拆出了 RADAR 的 Phase 1。

因此，本研究不再把“为研究二、三造数据”当成研究一的第二目标，也不复制 RADAR 的攻击—防御稳健化。更合适的外层目标是工作空间攻击面的发现、诊断与优先化。

## 3. 研究一的可评价协议：不是 benchmark 论文，但可以公平比较算法

### 3.1 三类对象必须分开命名

| 对象 | 定位 | 可以支持的主张 | 不可支持的主张 |
|---|---|---|---|
| 外部公开 benchmark/环境 | 固定任务、victim 和官方或可复现 oracle | 在其覆盖范围内与已发表方法进行可比评价 | 自动代表所有 coding-agent 工作空间攻击 |
| 基于公开任务构建的工作空间 testbed | 为对象级操纵加入固定 schema、sandbox 和 harm/utility oracle | 在披露的实验设计中比较发现效率、功能保持和迁移 | 未经社区采用即自称通用 benchmark |
| `D_att` | AttackRL 运行产生的完整回合记录及静态/轨迹视图 | 复现、机制分析和研究二/三训练 | 作为证明 AttackRL 优于自身的独立 benchmark |

### 3.2 试验单位和冻结项

公平比较的试验单位应为：

`公开任务 × 公开仓库 × victim agent/模型 × 可操纵通道 × 固定攻击预算`。

在运行攻击算法前冻结以下内容：任务划分、victim 版本、sandbox、允许的通道/算子、最大查询数/执行数/token/墙钟时间、正常功能测试、危害 PoC、失败与无效的判定、随机种子和停止条件。攻击算法不得各自使用不同 oracle 或不同最大重试次数。

### 3.3 AttackRL 的第一目标如何评价

主要指标不应是传统分类 accuracy，而应是受约束搜索算法的结果：

1. **功能保持条件下的验证攻击成功率**：同时通过原任务测试和危害 PoC 的比例；
2. **发现效率**：首次验证成功所需的查询、执行、token 和墙钟时间，以及固定预算下的发现曲线面积；
3. **独立复现率**：成功路径在全新运行、不同 seed 或兼容 victim 上再次造成同类危害的比例；
4. **迁移性**：未见仓库、未见攻击通道和未见 victim 上的成功率；
5. **预定义攻击面覆盖**：只在事先公开的通道—对象—关系本体内报告覆盖，不宣称覆盖未知攻击全集；
6. **无效与功能破坏率**：把编译失败、测试破坏和越出 sandbox 的候选单独报告，防止以破坏正常功能换取高 ASR。

强基线至少包括固定模板/人工种子、随机或启发式搜索、无反馈 LLM 攻击、与 T-MAP 类似的轨迹驱动演化搜索、与 RedCodeAgent 兼容的经验/工具选择方法，以及 AttackRL 的无对象关系、无层级动作和无多目标约束消融。只有在同预算和同 oracle 下比较，才可以评价算法好坏。

### 3.4 第二目标“攻击面诊断与优先化”如何评价

从训练任务中得到路径后，研究一不直接把任意权重相加成一个“权威风险分”。更稳妥的是估计一个有明确概率含义的量，例如：

> 在给定 victim、权限配置和攻击预算下，某个对象/关系/通道导致功能保持型可执行危害的条件概率，及其不确定区间。

可以进一步形成对象级或配置级风险排名。评价时先冻结估计器和排名，再在未见任务上使用独立攻击方法或后续时间批次进行验证：

- top-k 高风险对象实际包含多少新验证攻击；
- 相对频次、权限数量、静态关键词和均匀分配等基线，风险排名的 AUPRC、NDCG、校准误差与 concordance；
- 在相同加固预算下，只对 top-k 对象采用最简单且预注册的隔离/只读/确认措施，能够降低多少攻击成功率，同时损失多少正常任务效用；
- 排名能否跨仓库、跨 agent 和跨攻击算法迁移。

此处的简单加固实验只用于验证情报的决策价值，不开发研究二的输入检测算法，也不开发研究三的运行时控制策略。

### 3.5 SOTA 声明边界

研究一可以声称的是：“在某些公开任务/环境、指定 victim、相同攻击预算和统一 oracle 下，AttackRL 相对所复现基线取得更好的功能保持型攻击发现结果。”若工作空间 testbed 是我们基于公开任务派生的，则只能写“在本研究 testbed 中优于所评估方法”，不能把它写成社区 SOTA。`D_att` 只作为 corpus 发布。

## 4. 三项研究的重新分界

| 研究 | 分析单位 | 核心未知量 | 主要输出 | 决策时点 | AttackRL 的角色 |
|---|---|---|---|---|---|
| 一：攻击发现与攻击面诊断 | 多次红队回合形成的对象—关系—行动路径 | 哪些工作空间结构在给定预算下可被利用，风险集中在哪里 | 发现策略、验证路径、攻击面风险排序 | 系统测试与部署设计阶段 | 核心算法 |
| 二：潜藏攻击的静态预测 | 一个尚未执行的任务—工作空间实例 | 该具体实例是否被操纵，恶意单元在哪里 | 任务风险、单元定位、执行前处置 | 执行前 | 训练/压力测试数据来源之一；外部 benchmark 仍独立 |
| 三：高影响行动的序贯风险控制 | 一个进行中的状态转移及其历史 | 在新证据和干预会改变后续轨迹时，应何时采取何种控制 | 允许、影子执行、限权/确认、阻断等策略 | 每个高影响动作提交前 | 冻结控制器后的自适应对手与压力测试来源之一 |

该分界的关键不是时间上依次发生，而是三者优化的对象不同：研究一优化安全测试的发现与优先级，研究二优化执行前的实例筛查，研究三优化闭环行动控制。

## 5. 研究三如何证明不是“实时运行研究二”

### 5.1 必须正面纳入的最强简化基线

定义研究二的静态模型为 `p_t^static = f(I_0 ∪ O_{1:t})`，即把截至 `t` 的所有可见前缀重新编码后分类。该方法必须成为研究三的显式基线，且与研究三匹配可见信息、调用模型、计算预算和阈值/FPR。不能只与关键词或无状态单点检查比较。

若研究三不能稳定优于这一基线，就说明运行时信息有价值，但专门的运行时算法没有增量；此时研究三应作为研究二的在线扩展实验，而不能独立成篇。

### 5.2 独立问题应从检测改为闭环控制

研究三的正式状态可写为：

`s_t = (p_0, history_t, proposed_action_t, provenance_t, authority_t, reversibility_t, budget_t, environment_t)`。

研究三在动作产生真实副作用前，从 `allow`、`shadow/sandbox`、`restrict/confirm` 和 `deny` 中选择控制 `c_t`。控制会改变实际执行的动作、下一时点能观察到的证据和剩余成本。因此，优化对象是累计危害、误阻断、延迟和资源成本，而不是当前时点的分类误差。这种防御—轨迹反馈是静态分类器重复运行无法自动解决的。

### 5.3 算法必须利用三类“静态前缀重跑”无法等价表达的结构

1. **顺序与路径依赖**：相同事件集合以不同顺序出现，可能代表正常调试或逐步权限升级；打乱顺序的消融应显著破坏结果。
2. **行动后果与可逆性**：同样的风险概率面对只读查询、可回滚写入和不可逆外部发布时，应产生不同控制；仅对概率设统一阈值无法表达这一点。
3. **干预的内生反馈**：选择 shadow、限权或确认会产生新观察并改变 agent 后续规划。算法必须学习“先安全观察还是立即阻断”的价值，而非只消费被动形成的轨迹。

适合实现的算法内核是风险状态估计器加受约束的序贯控制器。风险状态估计器可以使用事件序列与对象/数据来源图；控制器可从 sandbox 中记录的干预回放学习，或使用模型预测/保守离线强化学习在已知安全约束内选择动作。研究二的 `p_0` 只是初始先验，不是研究三的核心算法。

### 5.4 必须完成的非降级实验

| 比较 | 要回答的问题 |
|---|---|
| 仅 `p_0` | 执行前筛查本身能避免多少危害？ |
| 对每个前缀重跑研究二 `f(I_t)` | 专门的运行时算法是否真的必要？ |
| 仅运行时前缀、无 `p_0` | 静态先验是否提供增量？ |
| 有状态检测但统一阈值 | 记忆序列是否足够，还是需要行动敏感的控制？ |
| 风险状态＋动作后果、但无干预反馈 | 反馈价值来自哪里？ |
| 完整闭环控制器 | 在同误报、同延迟或同资源预算下，能否提高危害前阻断和正常任务效用？ |

主要结果至少包括首次危害前阻断率、安全裕度 `t_harm - t_intervene`、累积危害成本、正常任务完成率、误阻断、平均延迟/计算成本，以及在 AttackRL 冻结后自适应攻击下的残余 ASR。单纯报告逐步 AUC/F1 不足以证明研究三的独立性。

### 5.5 最新技术前沿进一步抬高了研究三门槛

2025—2026 年的 agent 安全研究已经包括：MELON 的 masked re-execution 与动作依赖比较、AgentArmor 将运行轨迹转为控制流/数据流图进行策略检查、Fides 的信息流控制、ClawGuard 的工具边界规则执行，以及 PASTABench 对提前干预和最佳干预时点的评价。因此，“使用轨迹”“逐工具调用检查”“运行时阻断”和“加入数据流图”均不能单独构成新颖性。

研究三若保留，增量必须聚焦于 coding-agent 工作空间中特有的、可执行检验的闭环决策：对象级来源如何沿读—改—测—提交路径影响行动，行动的可逆性和持久副作用如何改变门控选择，以及有限观察/确认预算如何在安全与任务完成之间分配。

## 6. 当前建议与下一步决策

当前首选不是新增一个完全无关的研究，而是暂时保留三项研究，并把研究一和研究三都提升到可证伪的最低门槛：

1. 将研究一从“AttackRL＋数据语料”改为“AttackRL 攻击发现＋攻击面诊断/优先化”；
2. 将研究二限定为具体任务实例的执行前静态识别与定位；
3. 将研究三从“流式检测＋阈值门控”改为“动作后果敏感的序贯风险控制”，正面击败重复运行研究二的基线；
4. 先在小型公开 MVP 上验证研究一的两个门槛和研究三的非降级门槛，再决定是否重排论文，而不是先写满三篇后才发现研究单元不成立。

若研究一的第二目标无法前瞻验证，则把 AttackRL 并入二或三，并启动新研究检索。备用方向不应立即定题；任何候选都必须先通过“独立问题、公开可实现、强外部基线、与二/三不重合”四项审计。当前可进一步考察但尚未通过文献竞争审计的方向，是 coding-agent 持久修改的来源追踪与最小损失恢复：在防控失效后，定位受攻击信息影响的代码/配置/动作，只撤销受污染的状态并保留正常工作。该方向已有 2026 年 agent recovery、semantic transaction 和 rollback 工作，不能在未完成竞争检索前作为新研究承诺。
