# 三篇新稿权威行文与跨篇术语终审

## 1. 终审原则

本轮形成三篇彼此衔接、又能独立回答研究问题的研究稿。终审采用功能参照原则。肖老师的两篇近期 ISR 论文是首要参照，主要用于校准研究对象的特殊机制如何推出方法挑战、理论构念如何转化为算法组件，以及研究问题如何闭合到经验评价。

其他近期权威 IS 文献按照段落功能进入比较。网络安全分析论文用于校准公开资料、标签真值和迁移评价。RADAR 用于校准攻击操作、功能保持与资源预算。近期最优控制和强化学习论文用于校准动态状态、有限时域价值与反馈政策。

这种参照关系不要求三篇稿件与任何单篇原文具有相同标题、段数、篇幅或论证次序。每个来源只在其功能与当前研究问题相合时被采用。旧文可以提供理论语义，现代权威文章承担行文与研究呈现范式。公开预印本、数据集和代码仓库负责事实与协议核验，不承担权威 IS 写作模板。

终审设置四道硬门槛。第一，每个完整大节写完以后重新打开多篇对应原文，并记录写后发现的偏差与具体回改。第二，理论必须改变计算对象、算法结构或可检验机制。理论名称本身不构成贡献。第三，数据划分、训练输入、输出接口、预算、停止条件和比较资格必须能够由公开资料和明确协议实施。

第四，每个段落只承担一个主要论证功能。每句话也应有一个可以明确指出的中心命题。连续二至四句只推进一个主要功能。终审分别标记研究对象、理论机制、算法实现、数据协议、评价指标和证据边界。同一窗口若发生跨层切换，就返回原文比较并重排论证次序。方法总览可以在总关系已经建立后集中列出同层组件。组件正文则须按照输入、运算和输出逐步展开。句长、分号和并列词数量只用于发现疑点，不能代替逐句判断。

### 2.1 句法层级的原文参照

原文比较表明，权威论文并不完全排斥枚举。Xiao et al. (2023) 在方法总览中集中说明三个理论要求及其计算响应，随后把预处理、表示、构念计算和联合预测分别展开。Xiao et al. (2024) 也先给出方法导航，再按数据、掩码和注意机制说明各自的输入与输出。两篇文章中的集中枚举具有明确边界，只负责告诉读者后文将出现哪些同层组件。

安全研究采用相近的职责分离。Ampel et al. (2024) 先宣布测试床的四个组成部分，后续段落再分别说明来源、字段和标签形成。RADAR 先限定攻击假设，再说明输入和阶段，随后才定义状态、动作与回报。本文只学习这种功能分离，不沿用个别英文长句的高密度表面形式。

据此，三篇稿件采用以下句法判据。

- 同一句中的并列项必须处于同一分析层级，并共同服务一个中心命题。
- 数据来源、标签资格、模型输入、计算机制和评价用途分句说明。
- 公式以前先界定计算对象。公式以后再解释变量及其作用。
- 实验段落先说明问题，再说明比较条件，最后说明指标。
- 版本清单、记录字段和多项指标优先交由表格或独立句承载。

必要的输入模式、方法总览和同类指标清单可以保留。它们不得同时引入新的理论关系、因果主张或比较边界。终审先用长句、分号和高频并列词定位候选，再逐句判断其概念是否跨层。机械计数本身不构成合格证据。

## 3. 三篇研究的共同主线

三篇研究围绕编程智能体安全形成发现、识别和控制的连续证据链。

论文一研究哪些工作空间对象会成为攻击路径的首入口。未预选首入口对象的分支进入机会探查。机会探查可以直接形成行动实际化，也可以在取得对象证据后汇入目标选择。执行前已有对象证据的分支直接从目标选择开始。无论对象证据来自机会探查还是执行前证据，目标选择分支随后都通过行动实际化形成可确认后果。冻结的独立探查器再估计不同路径之间的竞争转移。该研究输出经确认的攻击路径和首入口对象条件诊断。

论文二研究工作空间操纵如何在智能体执行以前被识别。TARF 从受检制品提取表面证据。可信任务 $q_i$ 和政策 $P_i$ 为任务关系与能力含义提供判断条件。平台接入配置 $A_i$ 和实际权限 $C_i$ 为能力分支提供平台侧情境。历史干净与受攻表现用于估计各类证据的可靠性并完成融合。该研究输出任务风险、对象证据和版本化能力证据接口。

论文三研究智能体开始行动以后，真实调用、返回和环境变化如何改变后续风险。STFC 同时定义基线初始化和 TARF 增强初始化。增强配置接收冻结 TARF 的三项执行前接口。两种配置都依据实际运行历史形成动态状态。

STFC 在每个决策点估计候选响应的条件转移和剩余价值。在正常效用约束以及三动作轨道适用的转交率约束下，政策最小化安全损失与响应负担。该研究输出状态反馈政策。

三篇研究由此分别回答三个不同问题。攻击发现解释防御需要面对哪些可行路径。执行前识别利用可恢复条件与工作空间关系形成风险证据。其三项冻结接口可以增强论文三的状态初始化。运行控制随后根据真实调用和环境反馈更新状态并选择响应。

## 4. 编程智能体情境的特殊性

编程智能体的任务对象同时具有信息与行动属性。自然语言说明、代码、配置、脚本和工具规范会进入模型上下文，也会连接到可执行软件环境。执行前暴露由对象内容、任务关系和可达能力共同决定。行动开始以后，返回和环境变化继续改变风险状态。

这一特征改变了安全攻防的研究单位。孤立文本或代码片段不足以表示完整暴露，工作空间中的对象和关系共同形成攻击机会。表面危险接口也不足以直接确定风险，相同能力在不同任务和政策条件下可能具有不同含义。智能体行动还会产生新的返回、文件变化和能力状态，使风险在任务过程中演化。

三篇算法分别对应这些变化。AttackRL 搜索由对象、行动和确认组成的路径。TARF 在可信条件下融合内容、任务关系和能力后果。STFC 把真实历史、响应条件转移和剩余价值纳入运行政策。

这些情境机制所产生的计算要求共同建立三项研究的重要性与必要性。

## 5. 理论—算法—检验映射

| 研究 | 指导理论 | 理论实际改变的算法设计 | 对应经验检验 |
|---|---|---|---|
| 论文一 | 信息安全妥协的选择—偶然路径模型 | 区分首入口对象尚未预选的机会探查与已有对象证据的目标选择；显式表示两类路径的汇合、进展和竞争结果 | 信息边界消融、路径发现、确认效率、竞争转移、对象条件诊断和未见任务资源配置 |
| 论文二 | 信号理论 | 区分制品发送者、可信任务与政策以及多类可观察信号；能力分支另读取平台接入与权限情境；建立三类证据及反馈可靠性逻辑 | 同政策正负、跨政策反转、分支隔离、边掩码、可靠性、单分支与联合操纵成本、固定资源处置 |
| 论文三 | 最优控制理论 | 明确动态状态、可选响应、响应条件转移、有限时域剩余价值、约束和状态反馈政策 | 静态与动态状态、即时与剩余价值、二动作与三动作、约束实现、反事实一步转移和端到端控制 |

理论的使用强度依据研究任务调整。论文一的理论集中组织攻击机会、目标选择、行动实际化和诊断。具体网络仍采用算法术语。论文二的信号理论限定证据分工与反馈可靠性逻辑，具体融合函数作为设计选择接受评价。论文三的最优控制理论直接给出算法求解对象。三篇由此形成与各自研究任务相称的理论嵌入深度。

本研究以变量可观察性、机制可计算性和经验可检验性作为理论选择标准。表中三项理论都能在公开资料条件下形成明确的变量与接口，并分别导向可执行算法和对应检验。这些条件使理论能够在现实资料约束下承担可复核的设计职责。

## 6. 数据链与信息隔离

共同数据链固定如下。

| 数据部分 | 论文一 | 论文二 | 论文三 |
|---|---|---|---|
| train | 学习 AttackRL 并形成训练路径档案；AttackRL 冻结后由独立探查器另行生成诊断训练记录，两类记录分库存放 | 训练 TARF，各合格比较方法可使用相同强阳性 | 采集完整轨迹、一步成对分支和校准续跑；过滤后的 $D_{\mathrm{att}}$ 种子只作训练增强，并在接收训练任务中重新执行 |
| dev | AttackRL 模型选择与预算规则 | 可靠性、超参数、校准与阈值 | 约束、候选模型、阈值和轨道选择 |
| test-discovery | 冻结 AttackRL 的发现与诊断终评 | 不用于 TARF 开发或终评 | 不进入 STFC |
| test-defense | 攻击器与防御工件共同锁定后生成防御无关路径 | 冻结 TARF 的未见路径与压力终评 | 预先分为互斥 $D_{\mathrm{cf}}$ 和 $D_{\mathrm{e2e}}$，分别做一步反事实和端到端控制 |

$D_{\mathrm{att}}$ 是内部攻击路径档案和研究语料。每条确认路径保存 AttackRL 对象稳定标识、修改快照和源码或区段记录。跨篇使用另行生成版本化派生映射，使对象标识与 TARF 制品稳定键保持为两个标识空间。

派生映射在每个修改快照上把一个 AttackRL 对象标识对应到零个、一个或多个 TARF 制品稳定键。该快照中仍然存在且能够稳定解析的文件节点对应一个版本化制品键。删除、重命名或解析失败保留实际映射结果及其原因，可恢复谱系另行记录。代码、文档或配置内部单元对应所属制品键及区段。目录节点只展开为零个或多个后代制品键。

TARF 的位置变量 $z_{iv}$ 与可观测掩码 $M_{iv}^{\mathrm{loc}}$ 始终落在所属制品稳定键上。内部区段只保存为标签证据锚点。它不形成另一套位置标签。

完整档案继承基础任务的不可拆分原子组身份。攻击结果、功能结果和诊断记录随路径入档。$D_{\mathrm{att}}$ 用于内部归档、训练增强、机制分析和封存结果记录。面向社区的比较继续使用外部公开测试床。

论文二只把满足 $Y_i^{\mathrm{conf}}=1$、$R_i^{\mathrm{att}}=1$ 且 $R_i^{\mathrm{fun}}=1$ 的确认路径派生为强阳性。匹配干净的完整实例提供负例。失败尝试、预算耗尽和证据不足记录保持未标注或删失。

论文三先要求种子能够通过冻结的跨来源家族映射。过滤程序剔除冻结外推家族、对应生成器或模板谱系，以及与 dev、test-discovery、$D_{\mathrm{cf}}$、$D_{\mathrm{e2e}}$ 或隔离池对象构成精确重复或近重复的种子。保留种子绑定 train 接收任务并继承其原子组身份，随后在该训练任务中重新执行。

论文三训练所需的执行前证据通过嵌套折外 TARF 产生。最终 TARF 只在 STFC 训练资料上重新拟合，然后为 dev 与两个 test-defense 子集生成冻结接口。运行标签来自相应任务的重新执行。论文二的测试输入始终保持为执行前字段。

## 7. 公共资料与公允比较

三篇研究分别在相容轨道中报告结果。公开资料按照研究单位、信息时点、标签含义和输出粒度分轨使用。

| 公开资料或轨道 | 合理承担的评价 | 证据边界 |
|---|---|---|
| MalSkillBench | 技能包级静态扫描、TARF-S、原生工具固定点 | 缺少独立可信任务、政策与实际权限，不能验证完整 TARF 或运行控制 |
| SKILL-INJECT | 编程智能体政策条件、同政策正负、跨政策反转、干净效用与端到端运行 | 静态标签与运行结果分开；任务级可信政策形成 $P_i$ 并保留为模型输入 |
| RepoGuardBench | 代码仓库配对迁移、载体定位和功能结果 | 只有上下文可恢复子集进入完整 TARF；不同发布层级分报 |
| AgentDojo | 一般工具智能体运行防御与 AttriGuard 原生复现 | 作为跨情境补充，不承担编程智能体主要构念证据 |
| 公开编程任务环境 | AttackRL 的路径发现、功能保持与预算比较 | 各方法共享可见信息、操作范围和资源上限 |

静态结果按照包级判断、任务级风险和制品定位三种输出粒度分表。运行结果按照原生复现、共同二动作和三动作扩展分表。冻结 TARF、滚动 TARF、前缀风险编码器、一步贪心、一般动态控制与 STFC 依据响应权限进入相应运行轨道。AttriGuard 在原生复现成功并通过新增环境准入以后进入对应数值表。

领先性主张限定为预注册的相容轨道、公开资料版本和实际进入数值表的比较方法。可训练方法共享输入和训练资格。冻结外部工具保留原生配置和固定点。复现规则不足的方法进入文献比较。数值结论保持在相同任务、输出粒度、信息时点和响应权限以内。

## 8. 跨篇术语规范

| 固定术语 | 统一含义 |
|---|---|
| 编程智能体 | 三篇研究的共同研究对象；正文不混用 coding agent、编码智能体等变体 |
| 工作空间对象 | 可由关系图寻址的节点，可以是完整制品，也可以是其内部的软件单元 |
| 制品 | TARF 的完整受检与定位单位；段落、语法区块和配置项是制品内部单元 |
| 可信判断条件 | 论文二从受检制品发送者之外恢复的任务 $q_i$ 与政策 $P_i$；论文三继续用 $P_i$ 表示可信政策 |
| 平台接入与权限情境 | 论文二的平台控制接入配置 $A_i$ 与实际授予权限 $C_i$；用于界定制品能够连接的能力 |
| 情境完整 | 论文二的 $q_i$、$P_i$、$A_i$ 与 $C_i$ 均能从受检制品发送者之外恢复 |
| 可信任务与政策 | 可信判断条件中的任务目标与组织规则 |
| 操纵 | 在可信任务和政策条件下未经授权、且可能改变智能体信息或行动的制品变化 |
| 攻击路径 | 从初始工作空间经候选行动、环境反馈与确认形成的序列 |
| $D_{\mathrm{att}}$ | 内部攻击路径档案；通过版本化派生映射连接 AttackRL 对象与 TARF 制品，不称 benchmark |
| 任务风险 | TARF 在执行前输出的实例级概率 |
| 对象证据 | 按 TARF 制品稳定键排列的模型分数向量，与真实位置标签分开 |
| 能力证据接口 | 冻结 TARF 能力分支的边权、聚合表示、后果表示、掩码和版本 |
| 运行状态 | 论文三式（2）的状态记忆 $b_{it}$、可信政策 $P_i$、精确待执行调用 $a_{it}$ 和剩余步骤 $r_{it}$ |
| 状态初始化 | 两种配置使用相同 $F_0$。基线以形状匹配的 $c_p$、$c_{z,i}$、$c_{g,i}$ 替代三项 TARF 接口，并保留对象掩码、邻居掩码与接口版本 |

## 10. 实施阶段需要兑现的工件

当前稿件是可实施的研究设计，经验数值仍需由后续实现产生。实施阶段必须锁定公共数据版本、代码提交、模型快照、解析器、环境、智能体版本、任务提示、工具配置、预算、随机种子和结果判定程序。动态公开仓库还要保存提交 SHA、依赖锁与文件哈希。

论文一需要首先验证机会头的信息隔离。实施还要检查证据出现后的目标选择、操作库覆盖、候选生成终止、路径确认成本和诊断标注一致性。

论文二需要分别报告 $q_i/P_i$ 与 $A_i/C_i$ 的可恢复比例。关系抽取准确率、情境完整的 TARF 样本规模和低基率校准也需在正式训练以前普查。

论文三的实施门按固定顺序运行。身份关系图先形成不可拆分原子组，超过规模阈值的连通分量整体进入隔离池。程序再按照预注册优先序检验候选攻击家族。当前候选家族的完整原子组先进入 $D_{\mathrm{e2e}}$，其余原子组同时形成 train、dev、test-discovery 和 $D_{\mathrm{cf}}$。第一个满足全部协议下限的候选成为确认性外推轴。

未找到可行候选且至少一个候选仍为计算未决时，轨道记为计算未决。只有全部候选均取得不可行证明时，轨道才记为预注册不可行。

划分工件固定求解器、目标函数、稳定次序、随机种子和最大尝试次数。它只读取原子组身份、规模、候选家族成员关系和冻结分层字段。

论文三的主控制比较要求逐调用接口通过七项准入：精确待执行调用捕获、效果发生前截获、固定反馈注回同一会话、环境状态恢复、下一决策点捕获、威胁契约覆盖和重复重放。基本响应与扩展响应另行接受实现核验。不合格的智能体—接口组合不进入主控制比较。

每轮 $C_k$ 条校准续跑的成本单独核算。经验覆盖率和经验宽度分别报告。转移支持、价值支持和策略迭代收敛分别进入诊断。

AttriGuard 的公开工件复现与新增环境适配单独记录。只有原生复现与目标环境准入都成立时，它才进入相应数值表。

这些条件属于预注册和工件实现要求。正文通过正向的研究对象、算法和评价逻辑建立贡献，具体版本与执行清单在实施材料中兑现。
