# 多模态 coding-agent 安全资源核验与纳入决策

## 一、结论

多模态值得进入三篇研究，但适合成为贯穿攻击发现、执行前识别和运行控制的情境层，而不是独立增加第四篇论文。其价值来自编程智能体把图像纳入软件行动：问题截图和设计稿能够决定应修改的界面与代码，技能中的视觉制品能够引导工具调用，程序执行又会产生页面截图、错误窗口和渲染结果。安全问题因此发生在“视觉信息进入判断—智能体采取行动—软件状态改变—新视觉观察返回”的过程中。

这项特征并非编程智能体独占。网页智能体和计算机使用智能体同样处理截图。编程情境的特殊性在于视觉信息同时连接真实代码仓库、开发工具和可验证的软件结果。相同图像内容可能只在特定任务、文件和权限关系下构成风险。行动以后形成的新截图还会改变后续代码编辑和工具选择。论文应据此强调跨模态软件关系与行动反馈，不把“模型能够看图”本身写成研究贡献。

纳入顺序分为三层。第一层保留现有文本、代码和技能公共主轨，使三篇核心结论不依赖视觉资料。第二层加入 SWE-bench Multimodal 与能够完整冻结的 SKILLJECT-IMAGE，形成正常视觉软件任务和编程图像攻击。第三层加入 VPI-Bench、CyberSecEval 3 Visual Prompt Injection 与 WAInjectBench，分别承担行动迁移和内容组件检验。ImageNet-C 与 ImageNet-P 只提供标准扰动操作。

SWE-bench Multimodal 的公开文本存在 617 与 619 两种计数。论文正文、官方会议版本和数据说明采用 619 项，真实实施还应以冻结任务清单和提交哈希决定最终样本数。SKILLJECT-IMAGE 出现在 workshop 版本，当前 SkillJect arXiv v3 的摘要和公开仓库说明主要覆盖文本与脚本闭环。因此，图像资产、任务映射、裁判和许可证必须在进入实验表以前逐项冻结。该资源适合作为条件性近邻，不应成为三篇完成的唯一依赖。

CyberSecEval 3 和 WAInjectBench 都具有公开图像安全资料，但其结果止于模型响应或内容标签。它们能够检验 TARF-M 是否识别视觉表面信号，也能够检验 MSFC 的视觉编码是否在破坏下稳定。它们不能证明风险是否经编程智能体的文件编辑、命令或工具调用实际化。行动级证据继续由 SkillJect-Image、VPI-Bench 和本研究可执行任务承担。

## 三、三篇论文中的具体联系

论文一把图像视为异质工作空间对象。AttackRL 可以选择图像区域、图文引用或界面—代码联系，并在受约束操作中改变视觉显著性、跨模态拆分或引用路径。候选只有在沙箱行动和原任务功能均得到确认时才成为攻击路径。这样评价的是跨对象攻击发现，而不是普通图像生成或分类。SWE-bench Multimodal 提供基础软件任务，SKILLJECT-IMAGE 提供最近邻攻击，ImageNet-C/P 只提供感知操作。

论文二把多模态放入信号理论的三项计算责任。图像语义、OCR 文字和局部区域形成提供者可控制的表面信号。问题单对截图的引用、界面部件与代码文件的联系形成任务验证。视觉内容引导的命令、文件或网络操作形成能力验证。CyberSecEval 3 与 WAInjectBench评价表面分支，SWE-bench Multimodal 评价正常软件关系，Skill-Inject 和可冻结的 SKILLJECT-IMAGE 评价任务条件或行动后果。三类结果分别报告。

论文三获得最强的多模态必要性。开始时已经存在的图像只进入 TARF-M 时间零先验。程序运行、页面渲染或工具调用以后才出现的截图成为 MSFC 的新观察。允许、重规划或终止会改变下一幅截图及后续可达行动，因而需要响应条件转移和有限期价值。SWE-bench Multimodal 检验正常视觉信息保存，SKILLJECT-IMAGE 检验编程图像操纵，VPI-Bench 检验视觉行动迁移。内容级资料只检验观察编码。

## 四、无需训练视觉基础模型的实现

每项图像对象保存来源、内容哈希、首次可见时点、引用它的任务或文件、OCR 文字、候选区域与冻结视觉表示。确定性来源边优先来自 Markdown 引用、问题附件、DOM 或组件标识、构建记录和工具事件。语义模型只补充带置信度和来源标记的候选边。对象在任务起点已经存在时进入论文一、二；由智能体行动产生时进入论文三。

图像编码采用冻结视觉编码器、OCR 和区域提议。论文二学习表面、任务与能力分支及可靠性门，论文三复用该表示并追加时间与事件关系。感知稳健性通过 JPEG 压缩、模糊、噪声、亮度、缩放、遮挡和连续小扰动实现。每项变换保存参数和随机种子，并重新运行具有视觉能力的智能体。OCR、区域定位、风险判断和最终行动结果分开报告。

最低可行版本先完成公开文本与技能主轨，再在 SWE-bench Multimodal 开发任务上接入冻结图像编码。第二阶段加入 CyberSecEval 3 和 WAInjectBench 进行组件外测。只有当 SKILLJECT-IMAGE 的资产与运行器能够完整冻结时，才进入编程图像攻击主表。VPI-Bench 置于论文三外部有效性阶段。这个顺序使视觉扩展增加证据范围，而不改变公共数据可行性。

## 五、benchmark 与领先性能边界

每项公共资源保留原生任务、划分、输入通道、裁判和指标。SWE-bench Multimodal 的解决率不与视觉注入检测 F1 求平均，VPI-Bench 的行动攻击成功率也不与 Skill-Inject 的编程任务效用合并。跨资源只比较组件效应、方法排序方向与置信区间。

研究者在 SWE-bench Multimodal 上添加的图像安全变换属于配对压力测试资料。它可以公开任务主键、变换、哈希和重放脚本，但不继承 SWE-bench Multimodal 的官方 benchmark 身份。ImageNet-C/P 的操作迁移到软件截图以后同样形成本文协议，不形成 ImageNet 排行榜结果。

多模态领域领先主张至少需要满足共同公共任务、相同图像输入、相同受测智能体、相同工具权限、相同结果裁判和相同运行预算。SKILLJECT-IMAGE 只有在这些条件下能够端到端重跑时，才与论文一或三进入同一数值表。CyberSecEval 3 和 WAInjectBench 可以支持内容级领先表现，VPI-Bench 可以支持视觉行动外部表现。编程智能体多模态安全的主要主张仍需在具有软件目标和行动后果的任务上成立。

## 六、最终纳入决定

多模态进入三篇正文及评价设计，研究定位保持为 coding-agent 安全过程中的跨模态对象与反馈。论文一和论文二把它作为重要的情境扩展与机制检验，论文三把运行中新增视觉观察作为动态控制独立性的直接来源。核心算法不依赖私有图片或重新训练视觉基础模型。

公共资源按四项责任冻结。SWE-bench Multimodal 承担正常软件功能，SKILLJECT-IMAGE 承担条件性编程图像攻击，VPI-Bench 承担行动级迁移，CyberSecEval 3 与 WAInjectBench 承担内容组件。ImageNet-C/P 提供稳健性操作。该安排能够体现多模态的研究价值，也保持三篇之间的连续性、公开数据可行性和公允比较边界。
