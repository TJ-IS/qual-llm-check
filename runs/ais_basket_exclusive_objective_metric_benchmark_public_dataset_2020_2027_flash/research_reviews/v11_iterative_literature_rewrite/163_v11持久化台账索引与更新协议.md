## 2. 状态词

主张和可行性统一使用以下状态。

- `绿色` 表示证据、测量和实施路径已经明确，仍需正常验证。
- `黄色` 表示方案可行但存在需要预检、版本冻结、样本量或实现验证的条件。
- `红色` 表示当前证据或实施链不闭合，正文必须降级，不能按既定贡献写作。
- `灰色` 表示尚未阅读或核查，不能据此形成论文主张。
- `排除` 表示已发现层级错配、事实错误或不可接受泄漏，保留记录以防重新引入。

## 3. 更新触发器

出现以下任一情况时必须更新相应专账。

1. 新文献直接引用核心理论或修正旧构念。
2. 公开论文、仓库、基准版本或许可发生变化。
3. 一个理论映射、算法公式、标签字段或实验基线发生变化。
4. 预检显示事件不可稳定标注、执行不可重复、样本稀疏或预算不可承受。
5. 一篇论文的输出字段、时间边界或主键改变，并影响另外两篇。
6. 权威原文比较揭示新的通用模仿规律。
7. sub-agent 返回与既有台账冲突的证据。
8. 研究问题数量、主要结果或工件范围改变，导致整节责任需要收缩或重排。
9. 同大节或前后相邻大节对照发现构念、分析单位、标签、estimand 或贡献在节间改变身份。
10. 权威原文比较发现新的段落推进、句间依赖、删减或可读性规律，或现稿虽通过结构检查却仍难以复述主线。
11. 来源依赖的事实、理论、既有方法、数据或结果句无法找到可核原文，作者综合缺少输入来源与推理桥，任一可见句缺少经完整原文上下文核验的写作原型，作者协议缺少作者主语、计划时态、可行性、主检验或失败动作，或目标稿哈希变化导致既有责任映射失效。
12. 联合核、option 生命周期、随机运行 estimand、确认重复、路径等价类、资格折、依赖组、实际计算或封存后迭代任一口径变化。
13. 审计输入、脚本内容、工件 schema、活动文件角色或 `supersedes` 关系改变，即使正文哈希与路径名称未变。
14. 机械脚本的扫描范围改变，或 prose 统计被用于标题、表格、公式、算法和图注也受约束的全文验收。
15. 联合验收发现结构、语义、引文或 pilot/实施四轨的结论发生变化，或派生工件与规范台账之间无法双向追溯。
16. 正向主线回修会删除、合并、移位或替换含有分析单位、公式、训练、评价或失败协议的范围，必须登记协议保留差分。
17. 正文哈希变化后需要迁移逐句映射，或精确同句、上下文变化、重复文本与新增单元之间的身份无法唯一确定。

## 4. 更新顺序

先在私密历史审计中复开原始消息并复用或分解要求原子，再判定其为通用、单次运行或单篇特有。随后更新唯一承责的 domain skill、reference 或规范台账，搜索并处置相反旧规则，并在同一检查点更新公开 [requirement_registry](../../../../docs/research_program/requirement_registry.md) 的基线判定、当前控制、处置与替代关系。文献工作仍先更新 165 中的来源证据和谱系，再把来源特有的段落与句级发现写入 175，随后更新对应论文专账中的主张、可行性和风险并修改正文。若改变 sub-agent 所需上下文或回传格式，再更新 171。终审时检查全部要求原子均有处置、替代图无环、公开文件无私密原话，并避免只改正文而失去决策记录。

## 6. 审计责任

主代理对台账最终内容负责。sub-agent 可以发现证据、提出冲突或建议修改，但不能以其结论替代原文核查。主代理至少抽查每项高风险结论的正文位置、参考文献和适用边界，并在 171 的回传审计区登记采纳、修正或拒绝。

需要重复独立分析时，各 sub-agent 在完成原文对照以前不得读取其他代理回传。主代理另外完成一次同节与三节窗口复核，再处理冲突；相同结论只提高复核优先级，不因票数自动成立。

## 7. 文件管理规则

1. 163 至 172 与 175 是当前唯一规范台账集。相同责任不得另建 `新版`、`最终版`、`补充版` 或日期副本，内容更新直接写回唯一主文件并追加更新日志。
2. 公开 requirement registry 只存规范化要求、当前控制、历史基线判定和处置关系。163 只做索引、状态词、路由和文件管理。164 只存通用写作标准。165 只存来源证据与引用谱系。168 至 170 只存对应论文的主张和可行性。171 只存多代理模板。172 只存文献发现方法和网络追踪。175 只存来源特有的句级论证、可读性模仿与正文回修记录。私密历史原话只进入被 `.gitignore` 排除的日期化审计，不复制到公开仓库。
3. 单轮逐节审计、统计 JSON 和脚本属于派生产物，不进入规范台账编号。后续派生产物统一放入 `audit_artifacts` 子目录，并由相应审计稿引用。
3a. 三篇逐句映射是绑定具体稿件哈希的派生证据，固定命名为 `论文一_v12逐句功能与权威原文映射.md`、`论文二_v12逐句功能与权威原文映射.md` 和 `论文三_v12逐句功能与权威原文映射.md`，统一放在 `audit_artifacts`。它们保存逐字目标句与权威原句，但不复制通用规范；稿件哈希变化即降为历史快照，完成回修和覆盖复核后才可更新文件中的活动哈希。
3b. 同一命名模式只能承担一种工件角色和 schema。`sentence_mapping_pN_v12.json` 只保存逐句 records，`sentence_mapping_pN_v12_root_audit.json` 只保存 validator 汇总，分层样本与根代理叙事另名保存。活动 README 或 manifest 登记 role、schema、正文/输入/脚本/输出 SHA256 与 `supersedes`；禁止用 `current`、`latest` 或 `final` 名称替代这些绑定。
3c. 机械审计必须区分 prose 解析范围与参考文献前完整正文范围。引用密度、段长和跨稿句子重复可使用 prose；标点、占位与完成式结果措辞必须另扫标题、表格、公式、算法和图注。活动输出与 README 明示范围，未扫描不能写成通过。
3d. 每个阶段性联合验收只保留一个共同入口报告和一个活动角色清单。共同报告分列结构覆盖、语义映射、引文支持和 pilot/实施，不以任一轨替代其他轨；角色清单登记 role、schema、SHA256 与 `supersedes`，但不能替代 164、165、168 至 172 与 175 的规范经验。manifest 不登记自身哈希，避免自引用造成不可收敛的循环绑定；其身份由生成脚本哈希、固定路径和外层交付记录承担。联合报告发现的新规律、失败模式或撤回判断必须先写回唯一责任台账，再更新报告。sub-agent 只收到报告而未收到相关规范台账时，视为上下文未完整传递。
3e. 根代理复核叙事不能替代逐项结构化人读证据。每个分层样本必须同时保存双侧完整上下文，以及非空的目标谓词、来源论证动作、双侧谓词签名、单元责任、逻辑方向、段内角色、不匹配、最终判定和复核备注；判定须与映射状态一致，样本还须保存实际复核数、上下文完整性和输入绑定。活动 manifest 必须以专用 `root_stratified_review_json` schema 逐项验收这些字段，并把样本自报的正文、清单、映射、records 与样本生成器哈希同活动角色实物交叉比对，再把每个样本 ID、状态、目标句、来源句及行号同当前 records 逐项核对。普通 JSON 可解析、文件存在、记录数正确、自报 `binding_errors=[]` 或叙事声称“已复核 N 项”均不足以证明人工原文复核完成。
3f. 实质回修的连续段链属于绑定稿件版本的派生证据，统一放入 `audit_artifacts`，保存目标连续段落、权威连续段落、given-to-new、主语链、协议后移位置、逐句锚点与稿件 SHA256。段链记录不能复制通用规则，也不能替代逐句映射；正文哈希变化后旧段链降为历史输入，必须以新稿重新定位。
3g. 规范台账中的正文变更叙述也必须绑定实物。`planned`、`proposed_by_agent`、`written_to_candidate`、`merged_to_active`、`semantic_audited` 与 `released` 分开使用，并同时登记稿件路径、SHA256、小节或段落定位、证据工件与 `supersedes`。缺少绑定的旧“已修改”或“已闭合”叙述按未核历史意图处理，不能仅因位于规范台账而自动成为当前事实。
3h. 候选稿另建候选角色清单，不覆盖稳定活动 manifest。候选角色至少包括正文、逐句清单、清单迁移队列、协议保留差分、代理提案、独立落地复核、引用与机械审计、联合报告和 Markdown 链接审计，并固定每项 role、schema、SHA256、输入绑定和 unresolved state。迁移队列只区分唯一同句、上下文变化、重复文本、新增或重写与删除，不能充当正式映射。候选清单即使完整且机械门通过，也必须显式保持 `active_baseline_superseded=false`、`semantic_alignment_pass=false`、`citation_support_pass=false`、`pilot_implementation_pass=false` 和 `release_pass=false`，直至相应证据真实完成。
4. 已冻结的 v10 文件不回写。v11 规范台账可以迭代，但每次实质修改在文件末尾登记日期、触发证据和受影响文件。
5. 文件被重命名或迁移以前先更新本索引，并检查所有相对链接、绝对路径任务包和跨任务记忆。没有完成引用更新时不移动规范台账。
6. 新增台账前先判断能否写入现有职责。只有出现新的长期对象、独立更新周期和独立读取场景时才新增文件。
