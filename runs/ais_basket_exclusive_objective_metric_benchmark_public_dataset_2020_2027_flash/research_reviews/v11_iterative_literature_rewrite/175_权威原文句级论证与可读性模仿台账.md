# 权威原文句级论证与可读性模仿台账

## 1. 文件角色

本台账持久保存权威顶级 IS 论文在大节、段落和句子三个层面的论证手法，以及这些手法对三篇编程智能体安全论文造成的实际改写。它与 [164_权威文献对标与多代理写作验收标准](./164_权威文献对标与多代理写作验收标准.md) 分工使用。164 只保存已经上升为通用验收标准的规则，本台账保存来源特有的句链观察、可迁移骨架、不可模仿之处和逐轮回修记录。

本台账不是佳句摘抄集，却要求每个读者可见句持续学习一个可核的权威 IS 例句。模仿对象是句子承担的推理功能、句法构造、引文责任与位置、信息披露顺序、前后依赖、主语稳定性、标点功能和段落收束方式；不复制受版权保护的原句，也不要求目标句与原型具有相同领域内容或英文表面语序。

Requirement registry 的现行状态优先于本台账任何追加历史。`M-ANCHOR-01/L26` 已确认为逐句写作原型覆盖，`M-PUNCT-01/L24` 的独立标点阈值已被替代。责任分类仍按 `M-PROTOCOL-01` 分轨；写作原型不得冒充实质证据。后文旧 no-anchor、候选分支或零标点记录只保留历史作用，不能自行恢复为现行规则。

## 3. 句级拆解字段

每个被采用的权威段落必须先记录完整段落及其所在大节，再按句子填写以下字段。不得只摘最漂亮的一句。

| 字段 | 记录内容 |
|---|---|
| `source_window` | 原文核心大节及前后相邻大节 |
| `paragraph_question` | 该段只回答的一个问题 |
| `sentence_function` | 情境事实、后果、既有能力、局限、理论桥、设计选择、评价承诺、结果解释或边界 |
| `given_to_new` | 本句从上句承接的已知信息，以及句末新增并交给下句的信息 |
| `subject_chain` | 连续句的主语是否稳定，何时以及为何换主语 |
| `logical_relation` | 因果、对照、递进、限定、实例化、归纳或问题化 |
| `information_load` | 本句是否同时承担定义、机制、实现、评价或边界中的两项以上 |
| `closure` | 段末如何把前文收束为下一段必须解决的问题 |
| `transferable_skeleton` | 可迁移的抽象推理骨架，不保留原文措辞与专名 |
| `nontransferable_content` | 依赖原文对象、数据、结果或理论，不能移植的部分 |
| `manuscript_change` | 触发三稿的删除、合并、拆分、移位或改写位置 |

句子功能标签只是检索工具。最终判断必须解释为什么该句放在此处、若提前或延后会破坏什么依赖，不能以标签序列代替细读。

### 3.1 逐句覆盖记录的文件规则

`M-PROTOCOL-01` 当前为 `active`，下列责任分类持续适用。`M-ANCHOR-01/L26` 当前为 `qualified`：每个读者可见自然语言句在验收前都须有写作原型，但原创协议只要求功能相似的披露原型，不要求相同内容或措辞。

规范台账只保存稳定字段和可复用规律，三篇正文的逐句责任表分别放入 `audit_artifacts`，避免把数百个目标句复制进本文件。每份表必须绑定目标稿 SHA256，并在参考文献以前覆盖每一个自然语言句子。每条记录先分类为 `source_dependent_claim`、`author_synthesis`、`author_protocol_or_expectation`、`internal_cross_reference` 或其他明确责任。来源依赖的事实、理论、既有方法、资源、数据与经验结果保存可核原文、论文题名、原文小节、精确行号与完整段落窗口；作者综合保存各输入来源和显式推理桥；作者协议或预期保存作者身份、计划时态、实现对象、可行性、主检验和失败动作。写作原型另行记录抽象推理骨架与不可迁移边界，并优先从 ACAA、DSDL 及功能匹配的近期顶级 IS 完整大节中选择；它不替代实质证据。

责任表至少包含 `target_id`、`target_lines`、`target_sentence`、`responsibility_class`、`requires_substantive_source`、`requires_writing_prototype`、`paragraph_task`、`sentence_function`、`given_from_previous`、`new_for_next`、`authority_sentence`、`authority_source`、`authority_sentence_lines`、`authority_paragraph_lines`、`authority_section`、`adjacent_sections_read`、`input_sources`、`reasoning_bridge`、`match_dimensions`、`citation_responsibility`、`citation_support`、`punctuation_function`、`author_protocol_fields`、`transferable_skeleton`、`nontransferable_boundary`、`prototype_status` 和 `revision`。写作原型状态只使用 `PROTOTYPE_SEARCH_OPEN`、`PROTOTYPE_CANDIDATE`、`PROTOTYPE_REVISE` 与 `PROTOTYPE_VERIFIED`，并与实质证据状态分列。`WAITING_FOR_SOURCE` 仍用于来源依赖责任尚无足够直接证据的情况，正文与映射保留 `[[待补文献：具体责任]]`，不得计入通过。结构标题不冒充句子，公式、算法步骤、图表标题、表格自然语言和脚注则按各自责任另建记录，不以解析器排除为由漏审。若正文哈希改变，旧责任表立即降为历史快照，必须重新生成清单并复核所有变化句及其前后句；只有清单和稿件重新同哈希，才可恢复相应状态。

一篇权威原文句可以为多个目标句提供相同推理骨架，但每次复用都必须单独解释匹配维度，不能把一个来源句或窗口笼统覆盖整节。反之，一个目标句若同时承担现象、机制、实现和评价，不能通过列出多个来源句把过载合理化，仍应拆句或移位。来源依赖句找不到可核原文时必须待补或回修，作者综合缺少输入来源与桥梁时必须回修。作者协议、计划方法和预期诊断也必须寻找功能相似的权威披露原型；只有内容同构要求放宽，缺少任何经上下文核验的原型时仍须扩检或回修。主题相似、关键词重合和笼统段落功能不能替代原型核验或实质证据。

## 4. 可读性与杂乱诊断

### 4.1 段落主任务

一个段落只保留一个占主导地位的关系。定义研究对象、陈述现实后果、比较既有方法、提出理论解释、说明工件和列出评价条件通常分属不同段落任务。若一句或一段同时出现三个以上层级，先判断哪些信息应后移到综述、方法、评价或边界，不用增加连接词掩盖拥挤。

### 4.2 句间依赖

优先采用从已知到新信息的推进。句首承接上一句已经建立的对象，句末引入下一句要处理的困难。连续三句若各自更换主语、分析单位或时间点，却没有显式关系，视为逻辑跳跃。出现这、该、上述、这种时，前一句必须存在唯一可回指对象。

### 4.3 句内负载

定义句不同时塞入算法、实验门槛和失败降级。机制句不同时承担实现细节与贡献宣告。方法句先给输入、变换和输出，再给公式或实现例外。评价句先提出要排除的竞争解释，再给比较对象、共同条件和指标。一个长句包含两个以上转折或三个以上并列责任时，必须重写或拆分。

### 4.4 正向主链与边界

正文先让读者理解为什么存在问题、为什么既有方法不足、本文为何作出某项设计，再说明该设计不能证明什么。连续出现不得、不等于、只有、若失败、降级等语句时，把识别边界集中到理论边界、方法保障或评价拒绝规则，不让审稿答辩打断主论证。

### 4.5 列表信息的安置

资源名称、字段、版本、基线、指标和预检门槛如果超过三项，优先放入表格、方法小节或评价协议。正文只保留驱动推理的一到两个代表性对照。综述不能按论文逐篇点名，而应先给比较维度，再用来源支撑形成的研究流和不兼容性。

### 4.6 句式模仿边界

允许模仿的骨架包括现象到困难、能力到不兼容、理论关系到设计约束、组件到竞争解释、结果到有限贡献。禁止复制连续原句、独特比喻、数据、结论和专名替换式改写。中文新版应形成自然中文论证，不追求英语从句和标点的外观相似。

## 6. 多代理强制上下文

任何句级写作或可读性审计的 sub-agent 在开始前必须读取 164 第 3、4、6、8、9 节，本台账第 2 至 5 节，165 中对应来源条目，对应论文专账，以及目标稿和权威原文的完整三节窗口。任务包必须提供绝对路径和具体原文范围。

代理回传至少包含以下内容。

1. 按自然段给出唯一段落任务和句子功能序列。
2. 标出主语漂移、概念换名、限定前置、清单化、重复定义、因果跳跃和段末不收束的具体行号。
3. 为每个问题给出原文中同功能段落的完整行号，而非一条代表句。
4. 给出可迁移的抽象句链和不可复制的内容边界。
5. 说明建议是删除、合并、拆段、移位还是改写，并指出对前后段的影响。
6. 在独立审读完成前不得读取其他代理回传。主代理必须重新阅读同一原文窗口并逐项抽查。
7. 逐句映射按 `M-ANCHOR-01` 为每个可见句记录原型。脚本命中只算候选；代理必须读原句、完整原段、承责大节和可承受的相邻大节，分列七项匹配维度。作者协议允许较宽松的功能同类原型，不允许 no-anchor。
8. 同时核查目标句当前引用承担的责任。句型原型匹配不等于事实或理论证据充分；暂时找不到合格来源时必须登记具体缺口并使用待补文献占位，不能把相邻适用来源升级成直接支持。

## 7. 持久发现记录

### R001 研究阶段必须匹配

- 触发：2026-08-23 用户纠正上一轮审计重心。
- 发现：当前目标是写作引言、综述、理论、方法和评价设计。把尚未撰写真实结果及末节列为主要不足，会遮蔽已写部分的论述质量问题。
- 通用规则：审计优先级与当前写作阶段一致。除非用户要求完整稿验收，未进入写作范围的后半篇只登记为未来里程碑，不进入当前缺陷排序，也不能稀释句级逻辑、可读性和方法叙事问题。
- 传播：164 的阶段匹配规则、171 的任务包和本轮三篇新版。

### R002 结构齐全不等于论述清楚

- 触发：三篇 v11 均有引言至评价设计的完整标题链，但用户指出阅读仍感到杂乱、低可读性和逻辑性差。
- 发现：标题数量、引用闭环、禁用标点和组件映射只能排除机械问题。段落若由边界声明、资源清单和多项设计责任串接，仍会缺少读者能够复述的单一主链。
- 通用规则：每节验收增加一句话主线复述、逐段唯一任务、句间 given-to-new 链和删去边界句后的正向论证完整性。任何一项不能通过，机械检查不得判定写作完成。
- 传播：164、171 和三篇新版的逐段重写。

### R003 审计说明不能代替正文论证

- 触发：根代理逐节通读三篇 v11，并与 RADAR、ARText、ACAA、DSDL、DeepIA 的对应大节直接比对。
- 发现：三篇 v11 都把大量来源资格、不可迁移边界、字段禁用、跨论文接口和失败降级写在正向主链中。这些信息本身大多正确，却不断迫使读者从研究问题切换到作者的审计过程。权威原文通常先完成现象、缺口、机制、工件和检验的正向链，再在最靠近风险的位置交代一项必要边界。
- 通用规则：主叙事中的每条边界必须回答一个局部误读风险。纯粹记录查证过程、书目截止、其他论文不能支持什么、系列论文如何共享字段等内容，优先进入台账、附录或方法协议。删除边界句以后若段落仍不能复述出正向主张，说明需要重写主链，而不是补充更多免责声明。
- 传播：三篇 v12 引言和综述先删除审计过程叙述；理论与评价只保留会改变构念、输入、比较或结论门槛的边界。

### R004 benchmark 必须排除竞争解释

- 触发：直接比对 RADAR Evaluation、CLHAD Performance Evaluation、DTL-EL Experiments and Evaluations、DeepIA Empirical Evaluation 与 Explainable DRL Benchmark Models and Evaluation。
- 发现：高质量 benchmark 不是算法名清单。RADAR 先把实验映射到两个工件阶段，CLHAD 以单语、机器翻译和跨语言迁移三类替代解释分组，DTL-EL 依次检验来源域设计、是否需要迁移、哪类迁移更强以及转移哪些层，DeepIA 让层级分类与标签嵌入分别检验两类专家知识，Explainable DRL 让短视策略、无记忆策略、一般可解释模型、循环状态和不同注意机制逐项竞争。
- 通用规则：每个主要基线都要写出它保留了什么、删去了什么以及它排除哪种解释。先按竞争解释分组，再在组内列代表算法；不允许先列模型，再事后赋予理论意义。组件消融只回答组件增量，不能替代与外部强方法的总体比较。
- 传播：论文一按探索、一般学习、一般门控、证据条件机制和确认协议分组；论文二按表面信息、同字段一般关系、来源审计筛查、融合校准分组；论文三按即时规则、事实前缀重评、一步规划、开放环计划、响应条件滚动控制分组。

### R005 数据与任务单位先于模型比较

- 触发：直接比对 DSDL Evaluation、DeepIA Empirical Evaluation、CLHAD Performance Evaluation、DTL-EL Experiments and Evaluations 与 Explainable DRL Empirical Analysis。
- 发现：这些原文在进入比较前先说明真实分析单位、标签、时间或来源划分、样本形成、共同训练条件和指标。现稿三篇虽已具备这些要素，但常把资源资格、字段隔离、预算、基线与指标拆散到很多小节，使读者难以先建立一张完整的实验图。
- 通用规则：评价开头用一个测试床段落回答五件事：实例是什么、标签是什么、怎样划分、所有方法共享什么、主要结果是什么。随后用一张“实验问题—竞争解释—比较—证据”表固定实验架构。资格核查和故障处理放到后部，不打断 benchmark 进入。
- 传播：三篇 v12 评价设计统一先给测试床与共同条件，再给实验责任表和分实验说明。

### R006 工件、方法与组件名称必须固定层级

- 触发：论文一独立代理审计指出“AttackRL”有时指搜索器，有时指包含表示、确认与档案的完整工件；根代理复读方法总览、搜索与评价段后确认该问题。
- 发现：同一专名跨段改变外延，会让读者无法判断 benchmark 替换的是整个工件还是某个组件，也无法判断性能增量归属于表示、搜索或测量协议。
- 通用规则：首次出现专名时用一个等式式句子冻结层级，例如“完整工件由 A、B、C 组成，B 是核心学习组件”。此后总体比较必须声明替换哪一层，其余层是否共享；组件消融只能使用组件名，不再借用完整工件名。
- 传播：论文一固定完整路径发现工件及搜索器层级；论文二固定 TARF-M、表面分支、验证分支和融合器；论文三固定 RIFC、状态编码器、转移模型和滚动规划器。

### R007 公式与算法必须遵守因果披露顺序

- 触发：论文一独立代理发现确认标签在定义确认过程以前进入奖励，伪代码又在确认以前更新策略；根代理复读第 4.5–4.6 节后确认。
- 发现：即使所有符号最终都有定义，读者仍会依据披露顺序理解实际运行时序。先使用未来步骤才能产生的量，或让伪代码顺序与正文不同，会形成方法逻辑矛盾而不仅是行文不顺。
- 通用规则：按输入可用时点披露算法。先定义原始执行与触发条件，再定义附加确认或标签，再定义使用这些量的损失或奖励，最后说明参数更新。公式、流程图、伪代码和评价复现必须采用同一顺序；若训练实际不等待后续确认，则不能靠移段掩盖，必须改变目标定义。
- 传播：论文一固定为首次命中触发配对确认，候选生命周期结束后计算含确认标签的奖励并更新。论文二按分支训练、融合、校准、处置顺序；论文三按事实状态、转移展开、首项响应、事实新观察、重新求解顺序。

### R008 先冻结估计对象，再允许出现统一分数

- 触发：论文二独立代理发现单一风险记号同时覆盖静态恶意、行动实际化与视觉内容风险；根代理对照 DeepIA、DSDL 与 CLHAD 的问题定义和评价单位后确认。
- 发现：共享编码器、接口或工件不意味着不同标签属于同一概率。若 outcome、观察窗、目标总体、抽样框、agent-policy 条件或基础发生率不同，统一分数会让校准和外部有效性失去含义。
- 通用规则：方法开头依次写分析实例、outcome、观察窗、目标总体和抽样框，再写输入与输出。异质标签分别命名、建 head 和校准；共同接口只统一字段结构。辅助定位、区域或能力真值必须称中间诊断，不能倒推主 outcome 成立。
- 传播：论文二以 $Y^{act}$ 为主 outcome，静态与视觉轨独立；论文一确认路径数和路径等价类独立；论文三控制点预测、前缀响应差异和完整回合策略价值按嵌套单位分层。

### R009 局部模型证据与闭环工件证据分层

- 触发：论文三独立代理发现状态、转移、规划与完整策略混在同一比较层；根代理对照 RADAR、DeepIA、ARText 和 Explainable DRL 的实验责任后确认。
- 发现：下一事件预测、响应条件分布、尾部价值误差和完整回合安全效用使用不同分析单位与 estimand。局部模型更准不能自动证明闭环策略更好；闭环更好也不能识别究竟由哪项局部责任造成。
- 通用规则：评价至少区分局部表示、局部动态或结果、组件置换和完整工件。局部实验使用其直接预测责任，组件置换把候选版本放入同一冻结下游系统，完整策略从共同初始状态运行。每层分别写单位、共享组件、唯一变化和允许主张。
- 传播：论文三形成五层 benchmark；论文一把总体搜索、证据机制、表示与确认测量分开；论文二把主行动风险、理论或来源反事实、校准和诊断边界分开。

### R010 每个可见句必须有可核对的权威写作原型（受 R056、R057 限定）

- 触发：2026-08-24 用户把逐句模仿从段落窗口参考收紧为逐目标句的权威原句记录，并明确找不到高度一致原句时应反向修改正文。
- 发现：仅记录来源窗口和抽象句链仍允许审计者用一个宽泛段落替多句背书，无法判断某句是否承担了过多责任、处于错误位置，或只是主题相近。逐字保存目标句和权威原句后，主语角色、句子功能、逻辑关系与段内位置才能被复核。
- 通用规则：参考文献前每个自然语言句子必须接受责任分类、段链审查和写作原型核验。来源依赖的事实、理论、既有方法、资源、数据与经验结果另有来自直接阅读完整承责大节及相邻窗口的可核实质原文，并保留精确句行与段落窗口。作者综合保存输入来源与推理桥。作者协议或预期同样寻找权威披露原型，但内容匹配可以更宽松。任何类别都不允许以自动相似度、关键词或多个低相关来源拼接为通过。
- 传播：164 的多代理任务包与终审清单、171 的回传模板、三篇 v12 映射文件及其覆盖校验器。

### R011 句型锚点与引文支持是两条独立验收轨

- 触发：2026-08-24 用户指出逐句模仿可能反向暴露当前引文支持不足，并允许暂时保留明确占位。
- 发现：某个目标句可以在权威原文中找到高度一致的论证结构，但正文引用仍可能只支持相邻情境、一般方法或背景事实，不能支持该句的机制、测量或数据主张。反之，一个引文准确的句子也可能因负载、位置或主语链不合格而没有可用句型锚点。
- 通用规则：逐句表分别记录 `match_dimensions` 与 `citation_support`。引文责任按现象、理论机制、测量、方法、benchmark 和数据事实分类；支持不足时先收缩主张或补原文。暂时无法修复者在正文与映射写 `[[待补文献：具体责任]]`，状态为待补文献，不能用相邻桥梁或主题相似来源放行。
- 传播：164、171、三篇论文专账、三篇 v12 正文和逐句覆盖校验器。

### R012 来源事实、本文操作化与写作原型必须分账

- 触发：论文一第二轮引文审计发现，ACAA 的分模态架构、ARText 的语义保持边界和 CTI 工件的字段保留做法，被扩写成异质输入的必要条件、可执行功能保持或资料价值机制。
- 原文特征：权威论文通常先准确说明前作实际完成的对象、动作与结果，再用明确转折引出自己的设计选择；写法相似并不改变证据责任。
- 通用规则：每条记录分设 `source_fact`、`author_operationalization` 与 `writing_prototype`。前者只能复述来源直接实施或发现的内容，第二项必须用本文定义、预注册或新增标明作者责任，第三项只用于句子功能和论证位置模仿。三者不得互相替代。
- 传播：164 的引用责任、165 的文献记录、168 至 170 的专账、171 的代理回传和三份逐句映射。

### R013 资源身份必须拆成论文、数据、方法与实现

- 触发：论文二复核发现同一项目名被交替用于论文、数据集、攻击方法和仓库版本，造成 benchmark 能力与算法证据混写。

- 通用规则：每个资源条目增加 `resource_kind`、`version`、`used_component` 与 `evidence_role`。正文提到资源时必须说明它承担数据内容、任务协议、方法机制还是实现可得性；同名不同版本不得合并支持一句主张。

### R014 负向文献覆盖需要能力矩阵

### R015 派生协议优先标明作者责任

- 触发：论文一把同仓库与共享模板分组、配对重放、内容中性对照、裁判校准和统计退化方案整体挂给只实施其中局部先例的论文。

- 通用规则：派生样本分组、防泄漏、回放、负对照、人工测量和统计方案若无直接来源，写成本文预注册或本文新增，并留下具体待补责任。相邻文献只承担它原文实际实施的那一部分，不以主题接近背书整套协议。

### R016 算法叙事必须闭合时间、状态与确定分支

- 触发：论文一需要把结果前对象证据与最终攻击结果分开；论文三需要闭合完整历史编码与在线递推，并把平台终止从学习转移中移出。
- 原文特征：DSDL 按信息形成时点组织过程表示、状态更新与结果预测，RADAR 和 Explainable DRL 则把状态、动作、反馈、终止和评价接口按执行顺序披露。
- 通用规则：运行中门控证据不得含最终 outcome；完整历史编码与递归更新必须定义等价关系并验证；确定性拒绝或终止进入完整决策核的显式分支，不进入学习转移核或其损失；不适用的辅助 head 必须全局删除或掩码。任何一项缺失都使 Bellman 或序列模型叙事未闭合。
- 传播：164 的方法验收、168 与 170 专账、171 方法代理任务包及论文一、三正文。

### R017 不确定性对象不能合并成安全保证

- 触发：论文三曾把校准概率、集合覆盖、模型分歧和分布外支持共同称为置信度。
- 原文特征：权威实证论文把预测概率、误差或稳健性检验绑定各自估计对象，不用单一术语跨越不同统计责任。
- 通用规则：校准概率、覆盖集合、集成分歧、分布外支持分数与选择性预测分别命名、实现和评价。它们可以共同进入策略，但每项只允许产生自己的主张；没有覆盖定义和验证时，不得称区间或保证。
- 传播：164、170、171 与论文三评价。

### R018 后继状态闭合不自动等于结果闭合

- 触发：论文三已经用冻结更新器闭合模拟状态，但即时结果仍依赖原事件和终止类型；若只对后继状态核积分，不可逆压缩会丢失 Bellman 计算所需信息。
- 原文特征：Explainable DRL 先分别定义状态、动作和奖励，再让长期价值承接这些对象；有限期方法把终止边界放在递推以前，而不让价值公式反推已经丢失的事件。
- 通用规则：若结果头依赖事件、终止或动作，规划核保存联合 $(o,m,z')$，不能只保留 $z'$。运行器确定的行动上限在学习分布之后、状态更新之前写入。吸收态保留终止类型与终点头所需摘要，吸收只表示不再转移。
- 传播：164 的方法标准、170 的控制核专账、171 的算法审计字段和论文三。

### R019 层级动作必须按生命周期披露

- 触发：论文一的关系探查与证据确认被写入同一动作分布，导致 option 选择、option 内操作和终止后重选没有明确时点。
- 原文特征：算法型权威论文按阶段或接口先定义进入条件，再定义阶段内操作与输出；不会让一个概率同时承担启动和持续控制。
- 通用规则：层级动作分别定义 option 启动、内部原子动作、继续或终止及终止后的再次选择。权重只在声明的生命周期边界决定 option，活动 option 未终止时不能重新抽样。预算、奖励、状态更新和评价都绑定相同边界。
- 传播：164、168、171、论文一的方法与逐句映射。

### R020 资源同名或同接口不生成共同 estimand

- 触发：论文二把静态技能标签、视觉内容标签和模型注入成功率放入同一 head 或校准叙事，并把一次随机智能体运行写成任务级二元真值。
- 原文特征：DeepIA 与 ACAA 先固定每项资料的观察单位、标签和实验责任，再比较方法；它们不会因为输入接口类似就合并结果总体。
- 通用规则：每个资源分别记录分析单位、标签空间、未确认状态、目标总体、抽样规则、基础发生率和校准器。未确认样本不自动视为阴性。随机运行 outcome 要么以版本、解码和种子索引的单次运行作为单位，要么对预登记执行条件分布定义任务级发生率，不能在两者之间滑动。
- 传播：164、165、169、171 和论文二资源表、方法及评价。

### R021 资格、门选择与缺失接口必须在训练侧冻结

- 触发：论文二的辅助 head 资格和实例门仍可能根据后期分区表现改变，且固定融合与条件门的截距、尺度和缺失处理不对等。
- 原文特征：ACAA、DSDL 与 DeepIA 均先在训练或验证阶段确定模型结构，再让较后资料承担评价；比较组先锁定共同输入和容量责任。
- 通用规则：在训练侧预划互斥资格折，只用于冻结标签手册、覆盖门、辅助 head 与 mask。融合开发、门选择、校准和封存测试不能新增标签或改变资格。固定融合与条件门共享缺失向量、截距、尺度、容量和预算，并加入等参数常数门；后期失败只降级结论，不重定义工件。

### R022 理论代理与真实取得过程必须分开检验

- 触发：论文二把来源可靠度、证据移除依赖和行动前可取得性直接命名为 screening 构念，并把人工更改 provenance 字段当作 receiver initiation。
- 原文特征：ACAA 明确区分客户注意与神经注意；Dawson 区分行动者发信与接收者查询或第三方取得。构念名称、软件代理和真实过程分别承担不同责任。
- 通用规则：先把软件字段称为候选代理，只有收敛、区分和判别效度通过后才使用理论构念名称。同载荷 provenance 变化只识别来源状态敏感性；receiver initiation 还需随机或受控改变真实查询、重算或第三方取得过程并保存日志。没有过程操纵时，结论限于 provenance 信息价值。
- 传播：164、165、169、171、论文二理论、方法与机制实验。

### R023 单责比较必须核对实际计算与资料

- 触发：论文三把即时规则到完整一步模型的多接口变化称为模型化未来，把开放环与滚动求解的名义共同上限视为实际计算相等。
- 原文特征：RADAR 与 Explainable DRL 先说明每个 benchmark 保留和缺少的能力，再只解释对应差异；不能由配置编号推断因果阶梯。

### R024 发现真值需要稳定确认与冻结等价类

- 触发：论文一把一次命中、一次重放和一次中性对照称为稳定确认，又以仅含入口、操作和结果的签名计数不同路径。

- 通用规则：随机智能体产生的主要标签至少需要预登记的独立重复、运行顺序、种子、阈值、缺失处理和误差或边界报告。发现数还要在封存前冻结语义代码本，训练新颖性与最终计数使用同一等价类；盲审只复核代码本应用，不在看到结果后改定义。直接方法来源不足时保留具体待补责任。

### R025 分组、迁移与封存迭代不能混用

### R026 理论性质与作者代理之间必须保留证据落差

- 触发：论文三借用 information state 的充分性语言，但当前状态只能通过下一事件、终点结果、递归闭包和下游替换接受经验检验；这些作者选择的任务不能证明源理论的精确充分条件已经成立。

### R028 通用方法内核与作者协议要在相邻句分界

- 触发：论文一同时引用 option、PPO、随机搜索评价和 ground-truth 计数来源，但当前稿的冻结目标、候选生命周期、确认阈值、路径代码本和分组统计均由作者另行规定。若只在长段末尾放一个通用框架引文，读者容易把整段协议误认为来源原文已经实施。

### R029 全覆盖映射仍需防止高复用伪对齐

- 触发：论文二和论文三第一版映射在目标数量、字段、路径与行号上全部通过旧 validator，但论文二把一条 DeepIA 训练资料句用于 106 个包含信号理论、标签隔离、一致性和结果单位的异质目标，论文三把 `Evaluation metric` 表头用于 28 个状态、转移、尾部与降级表值，并批量写成四维一致。

- 传播：164 的逐句标准与终审清单、171 第 23 项、`audit_sentence_mapping.py`、三份最终映射和 `audit_artifacts/README.md`。

### R030 锚点去重不能替代细粒度语义同构

- 触发：论文三第二版映射已把所有单锚点复用压到八次以内并清除结构 invalid，但分散抽查仍发现 Hansen 方法事实映到经验系数结果、价值方程引入映到嵌入步骤、图边 schema 映到联邦模型聚合、时间破坏检验映到偏好嵌入，以及失败回退映到多视图归属。

### R031 人工语义抽样必须同时看到目标段和权威原文段

### R032 细粒度功能类别相同不等于谓词同构

- 触发：论文二的重建候选把“SWE-bench 将问题说明、版本化仓库和功能测试置于同一真实软件任务”映到“现有漏洞标签程序依赖耗时人工流程”。映射把两句都标为来源事实，并把“来源对象与直接能力”模板重复写进四维一致理由。
- 发现：R030 的细粒度类别仍可能被代理当作新的粗标签。两句可以同属来源事实、本文操作化、算法步骤或表值，却分别执行组成、限制、比较、因果、数量报告或失败降级等不同谓词。重复类别名称不是语义分析。
- 根代理反例：在论文二中间稿分层样本的七个“通过”项中，六项仍把关系效应检验映到文献缺口、对象到能力关系映到综述结构、screening 边界映到互动未知、比较前提映到情境差异、扰动曲线先例映到攻击后果、共同控制条件映到结果摘要。只有 `P2-U0713` 的多模型共同条件比较与 DTL-EL 的多训练资料、共同验证集比较暂时保持同一比较算子和控制角色。该正反对照说明段名、类别与来源真实性都不是通过依据。
- 通用规则：类别只用于候选检索。最终判定为每句建立谓词签名，至少记录主语类型、关系或论证算子、宾语或结果类型、限定条件与时序。四维匹配理由必须逐项解释这些成分的对应，不能把功能标签换词重述。主语与宾语可替换为领域对象，但关系方向、结果角色和段内论证动作必须保持同构；否则标回修并更换锚点。

### R033 公式或表格的共同外形不等于共同论证责任

- 触发：论文一样本把条件分段训练标签公式映到注意力权重公式，把 GAE 优势与价值目标映到无限期策略回报目标，把“知识来源及其责任”首列表头映到 `Perspective`。这些记录均把单元类型相同写成句子功能、逻辑关系与段内位置一致。
- 发现：公式、表格、算法和图注仍包含不同言语行为。条件定义决定何时取哪个值，优化目标说明被最大化或最小化的对象，递推连接时期，估计量定义样本到参数，约束限制可行域。表头也分别承担分类、来源、条件、指标、结果或拒绝责任。版式和节位相同只证明需要同类候选池，不能证明目标对象或推理动作一致。

### R034 规范公式采用数学方法源与权威 IS 披露双锚点

- 触发：论文一的 GAE 优势与价值目标在当前权威 IS 小池中没有同一数学对象，代理因而把它映到 RADAR 的无限期策略回报目标。两式都含折扣和求和，却分别承担优势估计或值目标与策略优化目标，R033 判为错配。

### R035 方法公式要呈现定义节点、后续实现节点与本文适配

- 触发：论文一原先把 PPO 作为更新来源，却在同一方法段使用 GAE 公式。回读显示 GAE 原文式 16 定义 TD 残差的指数加权无限和，PPO 第 5 节又直接引用 GAE 并给出固定长度轨迹上的截断式。只引 PPO 会模糊定义责任，只引 GAE 又会丢失更接近本文有限序列的后续实现先例。

### R037 代理回传经验必须合并为带来源的持久台账增量

- 触发：多轮原文复核已经产生 GAE 到 PPO 的定义与实现谱系、逐句锚点高复用、谓词伪对齐和高风险作者协议等关键经验。若这些判断只留在会话摘要或某个代理的最终消息，跨轮继续时仍可能丢失，新的代理也会重复旧错误。

- 通用规则：每个代理最终回传必须提供 `ledger_delta_type`、`target_ledger`、`evidence_pointer`、`conflict_or_supersedes` 与 `unresolved_state`。根代理逐项核对原文后，将通用标准写入 164 或本台账、文献责任写入 165、论文约束写入 168 至 170、引用发现规则写入 172、任务规范写入 171；旧判断被推翻时保留撤回理由。公共台账由根代理单点合并，合并后重新执行相对链接、活动稿哈希和审计工件绑定检查。

### R038 状态分布不是优化目标，边界也必须有共享谓词

- 触发：论文三旧候选有 151 个机器通过项。代理按 R036 逐条读取目标同段和来源完整段落后，151 项全部被否决，重新检索只暂留一个拟通过。随后若把大量回修转为边界以减少 blocker，仍可能用较温和标签掩盖没有原文骨架的事实。
- 发现：高通过率不证明映射质量，低通过率也不说明审计失败。逐句强制覆盖时，大量作者协议、具体字段、冻结时点和拒绝条件本就可能没有权威论文中的同构原句。`边界句` 不是模糊相似类别，而是来源确有一个可迁移谓词或展示责任、同时存在明确不可迁移限定的证据结论。
- 通用规则：通过、边界、回修和待补数量都不得成为优化指标。边界至少保存共享谓词、相同段内功能、目标与来源各自限定及不能迁移的责任；只找到主题、名词、单元外形或同节位置时保持回修。代理回传审计前后分母和迁移理由，根代理按抽样准确率而非通过率验收整份映射。
- 传播：163、164 多代理标准与终审清单、171 第 32 项、三篇最终映射、各论文专账与联合验收报告。

### R039 结构化谓词字段是待检假设，不能自证原文同构

- 触发：论文一映射曾把 U0049 判为通过，字段中自报目标与来源主语均为“被引方法或研究”。根代理直接通读 ARText 的 Predictive Analytics、Adversarial Attacks 与 Defense 三节后发现，目标句把动作归给 ARText 工件，所选原文却只定义一般 adversarial sample；主语身份与实施责任不同。U0112 又把 RADAR 第 143 行的有限动作、功能保持和规避奖励与第 145 行的防御反馈拼成一个单段共享谓词，字段齐全仍不能成立。
- 发现：`target_predicate_signature`、`authority_predicate_signature`、`match_dimensions` 和 `shared_predicate` 都是审计者提出的可证伪解释，不是原文证据。若先用类别标签把双方都写成“被引研究”，就会掩盖研究、工件、一般构念、样本、算法、组件和作者协议之间的主语切换；若跨段拼接多个局部谓词，也会制造原文不存在的单句责任。
- 通用规则：拟通过项先分别逐字抽取目标与来源的实际主语、算子、对象、限定、时序和 `unit_role`，保留原句或完整段落中的对应文字，再填写结构化签名。研究与工件、工件与一般构念、方法与样本、来源事实与作者推论任一角色变化均不得用上位类别抹平。一个目标复合谓词只有在同一来源段落的显式句链共同承担时才可通过；跨段或跨节拼接只能分责引用、降为边界或回修。根代理必须独立直读全部拟通过项及分层样本，validator 只验字段和覆盖，不能验语义真实性。
- 传播：163、164 多代理标准与终审清单、171 第 33 项、论文一重建任务包、三篇最终映射与联合验收报告。

### R040 活动审计工件必须用内容哈希绑定全部输入

- 触发：机械审计发现论文一映射在一次 validator 输出后又以同名路径重写，正文哈希没有改变，旧审计因此曾短暂表现为“正文绑定正确”，实际映射内容已经不同。论文三旧审计也早于 validator 规则升级。只保存路径和正文 SHA256 无法识别清单、映射或审计脚本的同名覆盖。
- 发现：逐句验收是 `正文 → 清单 → 映射 → validator` 的派生链。链上任一内容变化都会改变结论；路径稳定和正文稳定都不能证明下游产物仍与当次运行相同。审计规则本身变化时，旧输出即使输入未变也不能自动继承。
- 通用规则：每份活动 validator 输出必须同时保存当前正文 SHA256、清单 SHA256、映射 SHA256 和 validator 脚本 SHA256，并检查清单记录的正文哈希等于磁盘正文当前哈希。README、专账与联合报告引用审计结论时绑定这四类哈希；同名文件任一哈希变化，旧输出立即降为历史快照并重跑。样本文件和根代理叙事另绑定所用映射 SHA256。路径只用于定位，不能单独证明版本身份。
- 传播：163、164 多代理标准与终审清单、171 第 34 项、三篇最终 validator、审计 README、各论文专账与联合验收报告。

### R041 机械验收必须并列声明 prose 与完整正文范围

- 触发：现有标点和完成式措辞脚本为了统计句子与引用而排除了表格、公式、算法、图注和标题。本轮只有另做参考文献前完整正文扫描，才确认三稿这些区域的非占位受限标点也为零。仅引用原脚本的 prose 结果会把未扫描误写成通过。
- 通用规则：引用、段长和跨稿句子重复继续使用明示的 `prose_scope`；标点、占位、完成式结果措辞及其他全文约束必须另输出 `full_body_scope`，覆盖参考文献标题以前的标题、表格、公式、算法、图注和普通段落。两类结果分字段报告，任何一类不得冒充另一类。脚本输出保存自身 SHA256，README 和联合报告写明使用哪一范围。

### R042 文件名不决定工件角色，同一命名模式不得承载不同 schema

- 触发：旧 `sentence_mapping_p3_v12.json` 实际只有 validator 汇总，而论文一、论文二的同名模式文件包含逐句 records。自动流程若按文件名读取，会把两种不兼容 schema 当成同类活动证据；`current`、`latest` 或 `final` 等名称还会随重跑漂移。
- 通用规则：活动工件先冻结角色和 schema，再冻结名称。`sentence_mapping_pN_v12.json` 只保存逐句结构化 records，`sentence_mapping_pN_v12_root_audit.json` 只保存 validator 汇总，根代理样本和叙事使用独立名称。README 或活动 manifest 为每项登记 role、schema、正文/输入/脚本/输出 SHA256 与 `supersedes`；路径存在性和 Markdown 链接通过只证明可定位，不证明角色或版本正确。中间产物不得使用 `current` 冒充活动结论。
- 传播：163 文件管理规则、164 多代理标准、171 第 36 项、三篇最终映射命名、审计 README、活动 manifest 与联合验收报告。

### R043 引文事实支持与写作原型同构必须允许不同结论

- 触发：论文三 U0084 与 U0148 的被引管理响应研究在完整原文中能够有限支持“响应进入领域动态”这一事实，但代理为目标句选择的写作锚点分别承担资料综述、方法定义或其他段责，不能据事实大致成立就判句型同构。反向情形也存在，U0054 与 RADAR 的研究问题到命名工件句型同构，却不为 RIFC 的状态、转移、结果头或规划方法提供引文证据。
- 发现：`citation_support` 回答目标主张是否由当前引文直接、有限或不支持，映射 `status` 回答目标句能否从原文迁移同一写作谓词与段内责任。一个来源可以承担事实而不是写法原型，也可以提供写法原型而不承担目标内容。把两轨强制合一会诱发主题锚定或证据冒领。
- 通用规则：逐句记录必须允许 `citation_support=直接或有限支持` 与 `status=回修` 并存，也允许 `status=通过` 与 `citation_support=不支持或待补` 并存。先分别复核被引原文责任和写作原型，再决定能否由同一句或同一显式句链兼任；不能兼任时保存双锚或保留回修。联合报告分别汇总语义映射轨和引文支持轨，不以任一轨替代另一轨。
- 传播：163、164 多代理标准第 22 项与终审清单、165 的 L047、170、171 第 37 项、三篇映射与联合验收报告。

### R044 根代理复核叙事不能替代逐项结构化原文判断

- 触发：论文二旧分层样本已经保存 46 组目标段与来源段，但 `review_target_predicate`、`review_authority_action`、双侧签名、`review_unit_role`、逻辑方向、段内角色、不匹配、判定和备注十类逐项字段全部为空。与此同时，根代理叙事写有 50 个不重复单元、分类错配 0/50，普通 JSON manifest 也通过，造成“有人读完成”的结构化假阳性。

### R045 正向论证主线与审计契约必须分层披露

- 触发：根代理重新通读三篇 v12 后发现，很多段落同时说明研究现象、资源身份、字段资格、模型接口、失败降级和禁止声称。直接对照 ACAA、DSDL 与 RADAR 的连续窗口显示，权威稿先完成情境、失配、理论或方法关系、研究问题和命名工件的正向生成，再在理论、方法与评价中逐层披露资格、比较和拒绝条件。
- 原文特征：ACAA 与 DSDL 在引言中用连续段落把数据或过程困难变成研究问题和专门组件，方法总览再按组件顺序展开。RADAR 先从鲁棒性困难进入 RO 与 RL 的互补责任，再在 Research Gaps and Questions 集中列缺口，在 Proposed Design 报告假设、输入、阶段和输出，最后于 Instantiation 与 Evaluation 披露测试床和 benchmark。严格边界仍存在，但不会在同一推进段反复打断主线。
- 通用规则：引言、综述收束与理论桥接优先回答为什么需要这一设计以及每项责任如何产生下一项责任。只有阻止分析单位、构念或 outcome 立即漂移的边界可以留在主线。字段白名单、资源资格、分区、校准器、mask、随机化程序、统计细节和完整失败降级放到它们首次被计算或检验的位置。回修不是删除审计责任，而是为每项协议指定后置落点，并确认方法和评价仍完整承接。
- 诊断字段：每段记录 `positive_spine_claim`、`necessary_boundary`、`deferred_protocol`、`protocol_destination` 与 `forward_handoff`。同一段若没有单一可复述主张，或连续以“不、不能、只有、否则、未、不得”推进而没有新的正向关系，先判为叙事层级混杂，不用连接词继续加固。
- 传播：163、164 引言与逐节标准、165 的 L048、168 至 170、171 第 39 项、三篇第一轮实质回修与后续逐句重建。

### R046 句级锚点之外必须保存连续段链的 given-to-new 和主语链

- 触发：三篇稳定映射已经覆盖每个句子，仍有大量句子被判回修。即使单句各有来源，连续段落也可能重复定义、切换主语、提前进入协议或没有把段末的新信息交给下一段。用户要求至少比对同一大节，条件允许时读取核心大节及前后大节，因此单句记录不足以恢复原文的整体精髓。
- 原文特征：ACAA、DSDL 与 RADAR 的相邻段落都维持可追踪的 given-to-new。上一段形成的不足在下一段成为已知前提，段落主语通常围绕同一研究对象、理论关系或组件持续，段末再产生下一段要解决的困难。权威稿不是把若干正确句子并排，而是让段落之间形成单向累积。
- 通用规则：每次实质回修至少以三个连续自然段为一个 `paragraph_chain_record`。记录目标稿小节和段落全文、每段唯一任务、继承信息、新主张、主语或论证对象、句子功能序列、段末交接、对应权威原文完整段链、可迁移骨架、不可迁移内容和逐句锚点。若单句锚点有效而段链没有共同推进，优先重排或重写目标段，不把句级通过累加成段落通过。
- 验收：sub-agent 必须回传连续段链而非散点建议，根代理直接读取目标与权威双方完整段链。正文修改后，逐句清单和映射需要重建，但段链记录还要绑定新稿 SHA256 和精确小节，不能只引用旧行号。
- 传播：163、164 逐节与多代理标准、165 的 L048、171 第 40 项、三篇专账、段链回修提案和活动审计 README。

### R047 台账中的正文变更状态必须绑定稿件哈希和精确位置

- 触发：本台账 8.1 曾写“论文一引言压缩为五段”，但当前活动稿 `E379F0E...C496` 的引言仍有九个实质段。旧记录没有区分建议、候选改写和已进入活动稿，也没有绑定稿件哈希，因而在跨轮恢复时会把计划误当成事实。

- 通用规则：任何 `manuscript_change`、`已回修`、`已闭合` 或同义字段必须同时保存 `change_state`、`manuscript_path`、`manuscript_sha256`、`section_or_paragraph_locator`、`evidence_artifact` 与 `supersedes`。没有这些字段的旧变更叙述降为历史意图或未核状态。根代理在每轮开始和结束分别核对活动稿实物。稿件哈希变化时，旧变更、段链、句级清单和审计状态按各自绑定规则失效，不能选择性继承。

### R048 正向主线压缩必须保存协议保留差分

- 触发：三名代理的 v13 提案有效识别了引言与总览中的叙事拥挤，但部分建议以整段范围替换。若按范围直接执行，论文一的基础对象评分和一般进度匹配、论文二的资源专属 outcome 与训练资格、论文三的联合核、结果头和 Bellman 接口会与重复叙事一起被压缩。这些对象正是构成可执行方法和可拒绝评价的协议，不是可以靠“后文详述”默认保留的枝节。
- 原文特征：ACAA、DSDL 与 RADAR 都在引言或设计总览中提供清晰正向链，同时在后续方法、实例化和评价中保存足够细的输入、组件、训练、比较与失败责任。权威稿的可读性来自分层披露，而不是从全文删除技术契约。
- 通用规则：每项删除、合并或整段替换先生成 `protocol_retention_record`，至少列出旧稿协议对象、旧位置、正向主线中的最小必要提及、新位置、公式或算法身份、评价或失败使用者和保留核对结果。正文回修后逐项证明协议仍存在、名称和变量身份未变、下游仍能引用；找不到新位置的项目视为误删，不能以候选稿更短或段落更顺替代。

### R055 引用簇必须逐主张原子分责

- 触发：论文二评价句把 AUPRC、对数或 Brier 得分、校准和多重检验并列，而现有来源只分别支持 proper scoring、calibration 或特定错误控制。统一括号会让部分支持遮蔽未支持项。

### R056 作者自定的预期方法与未来结果不要求内容完全相同的权威原句

- 触发：2026-08-26 用户进一步限定，本文预期做法和结果因研究对象与既有工作不同，不一定存在完全相同的历史原句。该纠正限定 R010 的普遍适用范围，但不撤销来源依赖主张的直接原文责任。

### 8.25 写作原型边与原创协议诚实收束写法

### 8.28 论文二与论文三批量闭环的段责写法

R213，一个方法段若同时包含来源事实和原创实现，优先使用四步短链。先写来源能做什么，再写它没有证明什么，随后写本文冻结的具体协议，最后写失败时如何降级或退出。这样可以减少句尾引文堆叠，也能让读者立即分辨历史事实与作者承诺。

R214，表示段要把诊断与证明分开。未来事件头、终点头、proper score、连续误差和经验覆盖可以诊断不同对象，但每个对象通过都不能自动升级为决策充分或总体有效。段末应落到一个可拒绝的主门，而不是把多个指标合成空泛的稳健性。

R215，统计段按假设、适用边界和作者动作排序。先交代交换性、独立组或聚类重采样等来源条件，再指出本文依赖结构的差异，最后写经验报告和失败退出。不要先列一串方法名，再在段尾用一句统一兜底。

### 8.29 v15 引言的权威原文反向改写规则

R219，多个 benchmark 在同一句承担不同裁判谓词时先拆句。每个事实句只写一个资源、一个动作和一个结果，再用后续综合句比较共同能力与边界。把三个来源放进一个引文组不能替代谓词分责。

R220，引言中的相邻文献只保留产生研究问题所必需的关系。认证类型、实证设计、字段清单和来源控制者等实现先例应进入理论或方法大节。后移不等于删除，其引用价值由后文的适用性桥继续承担。

R221，冻结检索的样本数、编码字段和完整能力矩阵原则上留在综述或定位大节。引言可以引用该冻结综述并陈述范围内的联合缺口，但必须紧接语料边界，不能把局部编码升级为领域穷尽性结论。

R222，结果型权威原句可以为尚无结果的论文提供评价披露顺序，例如资料、比较器、主要结果与允许推论的排列。迁移后必须改为计划式或成立条件，`semantic_support_from_authority_sentence` 固定为 false，不能复制完成式结果。

R223，逐句原文映射的收束条件是目标句、当前稿件哈希、原句全文、题名、小节、行位、四维匹配和迁移边界同时可核对。根代理直接完成这些项并通过一次合并机械验收后，不再为同一稳定引言启动同义 sub-agent 复核。只有原句错位、复用超过阈值、正文哈希改变或来源责任冲突才重开。

### 8.30 逐句写作原型的用户裁决与检索规则

R226，L26 的现行含义是“每句学习权威例句的写法”，不是“每句找到内容相同的证据句”。每个读者可见句都要记录修辞功能、句法构造、引文支持如何安置、given-to-new、段内位置、标点功能和不可迁移内容。任何自动分数都只能给出 `PROTOTYPE_CANDIDATE`。
