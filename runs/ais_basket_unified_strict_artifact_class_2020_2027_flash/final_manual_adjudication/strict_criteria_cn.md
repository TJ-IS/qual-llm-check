# 2020–2027 AIS Basket 全文严格筛选标准（最终版）

本轮是“客观指标 × 运行软件制品 × 类级设计贡献”的资格筛选。三组门槛必须同时通过；证据不足即排除。心理学相关理论按照既定流程留作下一阶段细筛，本轮不作为纳入门槛。

## A. 完全客观且居于核心的结果指标

必须同时满足：

1. 指标构念能够脱离人的感受、偏好、意义理解和价值判断而成立；
2. 指标值可由物理记录、系统日志、交易事实、固定操作规则或外部事实标签确定性得到；
3. 作者用于证明制品成功的所有核心终点均为客观指标；
4. 提升该客观指标是最终设计目标和核心贡献，而非可行性检查、操纵检验、附加结果或理论关系中的一个变量。

下列情况必须排除：

- 专家、学生、客户、众包者或研究者判断质量、意义、相关性、价值或“答案是否恰当”，再计算 accuracy/F1；
- 标签代表个人偏好、主观决策、审美、隐私担忧、公平感、信任等主观构念；
- 客观结果和主观结果共同构成不可分割的核心成功标准；
- 文章核心是解释心理、行为、制度或组织过程，客观绩效只是因变量或验证材料。

主观变量只有在其明确只是机制解释、操纵检验或非核心补充，而最终制品成败完全由客观结果判定时才不触发排除。

## B. 作者实质设计并运行软件制品

必须同时满足：

1. 存在可识别、可重复实例化的软件制品类别；
2. 作者实质设计或修改界面、交互、反馈、工作流、系统规则、推荐/检测/决策模块或自动化组件；
3. 制品或组件被实际实现并运行，而非只提出概念或未来集成设想；
4. 客观结果改善能够归因于制品设计，而非仅归因于数学模型、求解器、实验处理、领域政策或市场机制。

系统、平台、DSS、framework、tool、app、GUI 或 design science 等命名本身均不能证明资格。

## C. 贡献必须指向一类软件制品

必须同时满足：

1. 制品类别与核心任务不依赖当前公司、数据集、医院、城市、业务案例或实验而成立；
2. 论文提供该类软件可复用的功能结构、交互、反馈、工作流、系统规则或组件机制；
3. 研究问题或贡献声明明确指向该类软件应如何设计、配置或运行；
4. 软件不是一次性案例方案、传播外壳、演示器、实验材料、数据收集渠道、求解脚本或计算载体；
5. 实际运行实例确实实例化了作者声称的类级机制。

## 强制反事实检查

移除当前案例名称、数据集、专门界面和“system/DSS/tool”等命名后：

- 若只剩算法、方程、预测框架、优化器、市场/业务机制或领域方案，排除；
- 若仍留下作者贡献的、关于某类可运行软件制品应如何设计的知识，才可能纳入。

## 特别边界

- 算法可以是合格制品的核心组件，但必须被转译为某类软件的设计原则、设计特征、功能结构或工作流，并在运行实例中接受最终客观指标评价；
- 多数据集、benchmark、ablation、架构图或生产潜力不能单独使算法获得软件制品资格；
- 不强制要求特定 baseline/control/ablation 形式，但必须实际评价设计目标；
- 严格性优先于数量，不以期刊、标题或作者自称替代全文证据。
