# 用户要求与提示词对应关系

## 基础要求 1

用户要求：以提升某个客观可测量的指标为最终目标和核心贡献；该指标不依赖任何人类主观感知来测量。

提示词落实为 `objective_metric.pass`：同时检查指标的客观性、在文章中的核心地位，以及文章是否用它实际验证改进。有人参与任务不自动构成主观测量；人的主观评分、感知和态度构念明确排除。

## 基础要求 2

用户要求：通过改造或设计软件制品的一部分或全部来实现；文章必须明确该设计属于某类软件制品。

提示词落实为 `software_artifact.pass`：同时抽取软件制品类型、被设计部分、二者的组成关系及其与客观评价的连接。通用算法只有被文章明确定位为软件制品模块或功能时才可能通过。

## 进一步细筛

用户要求：必须体现理论指导；该理论不是纯数学或 CS 意义上的理论，而是心理学相关理论。

提示词落实为 `theory_guidance.status`：只在基础筛选通过后检查，并要求形成“心理学相关理论/命题 → 心理或行为机制 → 具体软件设计 → 客观指标”的可追溯链条。理论仅用于引言、假设标签、事后解释或研究测量时不通过。

## 刻意没有加入的条件

未加入 IS 独特性、贡献抗过时、coding-agent 可迁移性、博士论文适配性、可复制性、期刊等级或研究资源要求，避免改变用户本次给出的筛选边界。
