# 全文纳入与概念矩阵编码手册

## 最终纳入

全文必须证明论文的研究对象、实际任务、系统/智能体能力或理论问题直接涉及下列编程行动之一：编写、生成、补全、理解、检查、调试/修复、修改/重构、测试程序。

程序制品包括源代码、可执行数据库查询、电子表格公式/脚本、低代码/可视化/终端用户编程产生的可执行逻辑。软件项目、团队、组织或一般开发工作只有在具体编程活动是不可替换的核心对象时才纳入。

技术论文可纳入，但必须是生成式、学习式或自主智能体直接执行规定行动；纯确定性静态分析、编译、传统测试生成或优化算法不因操作代码就自动纳入。Secondary review 单列，不与 primary study 混合计数。

## 概念矩阵字段

1. **bibliographic identity：** EID、DOI、题名、年份、来源；
2. **evidence role：** primary empirical / design-and-evaluation / conceptual / secondary review；
3. **actor：** human_only / human_ai / agent_only；
4. **program artifact：** source code / database query / spreadsheet logic / low-code-visual / other executable logic；
5. **programming action：** write / generate / complete / understand / inspect-review / debug-repair / modify-refactor / test；
6. **programming situation definition：** 原文实际把什么活动算作编程，边界是什么；
7. **task and setting：** 参与者或智能体做了什么任务，使用何种语言、工具、数据和环境；
8. **method：** 实验、准实验、调查、访谈、观察、日志/仓库、设计科学、benchmark、综述等；
9. **unit of analysis：** individual / dyad / team / organization / project-community / code-artifact-agent / multiple；
10. **sample/study identity：** 样本量、参与者、数据集，以及与其他论文复用同一样本的证据；
11. **theory/framework：** 只记录原文明示名称；
12. **variables：** 自变量、中介、调节、因变量；没有则留空；
13. **findings：** 与直接编程任务相关的主要发现；
14. **human-agent relation：** 智能体是否生成建议、执行任务、解释、检查，人与智能体如何分工；
15. **evidence：** 至少两条可定位的短证据，分别支持“编程是核心”和“研究方法/任务”；
16. **quality/limitations：** 外部效度、样本、任务真实性、工具过时、benchmark-only 等限制。

## 论文数与研究数

同一论文包含多个独立样本时，论文计数为一、study/sample 计数可大于一；多篇论文复用同一数据集时，论文分别列出，但综合时只计一个独立实证设置。无法确认时标记 `sample_independence_unclear`，不得猜测。
