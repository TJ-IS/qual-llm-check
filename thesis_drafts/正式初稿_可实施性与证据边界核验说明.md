# 《有限信息预算下 Coding Agent 的仓库上下文获取决策研究》可实施性与证据边界核验说明

核验日期：2026 年 8 月 11 日

## 1. 核验结论

这篇论文的三项研究已经形成一条可以真实实施的累积链，但“有公开 benchmark”不等于“所有训练标签和实验结果均已现成”。更准确的判断是：

- 研究一具有现成任务、仓库快照、检索金标准和下游评价环境，可以直接进入算法开发；结构关系单元需要用静态分析从仓库派生。
- 研究二具有现成任务、检索器实现条件和下游环境，但“不同任务应采用何种来源配额”的 oracle 标签需要在公开任务上离线枚举生成。
- 研究三具有现成探索任务、仓库环境和过程评价基础，但公开 benchmark 不直接提供“在每个前缀停止的反事实任务效用”；该标签必须由固定流程进行前缀回放产生。

因此，研究一和研究二满足“成熟 benchmark + 可运行公开情境”的强条件；研究三满足“成熟公开情境 + 可规范生成研究标签”的条件，而不是“停止标签已经现成”的更强条件。

## 2. 三项研究的可实施性

| 研究 | 可直接使用的公开基础 | 需要自行产生的数据 | 最小可行实验 | 主要风险 | 收缩方案 |
|---|---|---|---|---|---|
| 研究一：SBCS 上下文项选择 | ARB 的仓库快照、金标准、no-gold 与预算指标；ContextBench 的文件/符号/跨度金标准；RepoBench、CrossCodeEval 的检索与补全任务 | 由解析器产生的定义—引用、调用、导入、测试关系；统一候选切分与 token 成本 | 先在 ARB/ContextBench 比较同候选池、同 token 预算下的 BCY、Recall、冗余和结构覆盖，再接 RepoBench/CrossCodeEval | 图解析语言覆盖；金标准覆盖不一定转化为下游收益 | 若图组件不稳定，保留“成本与冗余感知的预算打包”并如实报告图组件无增量 |
| 研究二：TMA 多源配额 | 同一公开任务可运行 BM25、dense、graph 三类来源；ARB、CodeRAG-Bench、ContextBench 可评价候选质量 | 缓存各来源完整排序后枚举离散配额，生成任务级配置效用和 oracle regret；小规模端到端配置标签需运行固定模型 | 三来源、四档配额，先用检索代理效用训练浅层配置器，再在分层子样本校准下游效用 | 全配置端到端调用昂贵；来源实现差异可能混入范式效果 | 全量使用检索代理，端到端只做预先分层子样本；结论限定为固定来源实现和预算范围 |
| 研究三：EMS 序贯停止 | SWE-Explore-Bench 的探索任务/过程信号，ContextBench/ARB 的金标准，SWE-bench 的可执行环境 | 固定 continuation policy 下的上下文前缀、每个前缀的下游效用、继续成本和后向归纳停止标签 | 先生成检索代理前缀标签，再在小型端到端子样本对每个前缀运行固定修复器 | 回放成本高；单次生成噪声；固定路径标签不是全局最优搜索标签 | 结论限定为固定 continuation policy 的最优停止；使用全量代理评价加小规模端到端效度检验 |

## 3. Benchmark 的功能边界

| Benchmark | 适合回答 | 不足以单独回答 |
|---|---|---|
| RepoBench / CrossCodeEval | 快速迭代检索、上下文打包和跨文件补全 | 真实 issue 修复、长时程探索停止 |
| ARB | 全仓检索、预算收益、no-gold、选择性检索 | 固定下游修复器的真实补丁效用 |
| ContextBench | 文件—符号—跨度—编辑位置的细粒度覆盖 | 多轮继续/停止的反事实收益 |
| CodeRAG-Bench | 检索—生成—执行联合比较 | 自然形成的多轮停止标签 |
| SWE-Explore-Bench | 探索路径、有效信息出现时点、过程噪声 | “若提前一轮停止会怎样”的完整反事实补丁效用 |
| SWE-bench Lite / Verified | 最终补丁与测试通过 | 低成本高频算法开发和纯检索机制识别 |

结论是这些 benchmark 应按层组合，而不是选一个基准承担整篇论文。研究开发顺序应由廉价的检索代理实验开始，在算法冻结后才进入昂贵的端到端修复。

## 4. 与 IS 文献的实质连接

本文没有把 coding agent 牵强类比为人类决策者，而只迁移可以形式化的决策结构：

| IS 文献命题 | Coding-agent 情境化 | 算法落点 | 必需证据 |
|---|---|---|---|
| 信息价值取决于其支持的终局决策，而非孤立准确率 | 金标准命中未必改善补丁 | 任务效用与检索代理效用分开估计 | 检索改善能否传递到固定下游 agent |
| 信息项具有异质获取成本 | 代码跨度 token 长度、调用和时延不同 | 边际集合价值除以成本 | 同预算覆盖、同效用成本和帕累托曲线 |
| 异质信息服务需要选择与配置 | BM25、dense、graph 质量、重叠和成本不同 | 任务条件下的来源配额 | oracle regret、来源交互、成本后增量 |
| 序贯获取应在边际收益低于边际成本时停止 | 每轮新增覆盖、稳定性、来源一致性和执行反馈可观测 | 有限时域 continue/stop | stop regret、过早/过晚停止、端到端效用 |

这些连接分别来自 Otero AIS Basket 本地全文中的有成本信息获取、决策中心型信息采集、分布式信息检索和停止搜索文献链。正文已经同时写明原情境、可迁移命题和迁移边界。

## 5. 肖帅勇论文写法的借鉴范围

借鉴的是两篇 ISR 论文的论证结构，而不是其顾客满意、顾客注意或深度网络的具体构念：

1. 从一般理论提出可核验命题；
2. 把命题情境化为代码仓库中可观察的变量；
3. 由情境变量推导设计要求；
4. 让每项设计要求对应一个算法组件；
5. 为每个组件安排专门的中间指标、端到端增量、消融和解释性分析。

该逻辑已经集中落实在初稿第 2.7 节、第 3.4 节和表 3-1，并贯穿第 4—6 章的“理论分析—设计要求—算法—分层评价—边界条件”。正文明确禁止把模型权重或停止特征写成 LLM 的心理注意、理解或认知机制。
