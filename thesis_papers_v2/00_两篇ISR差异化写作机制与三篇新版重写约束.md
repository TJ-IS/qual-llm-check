# 两篇 ISR 的差异化写作机制与三篇新版重写约束

> 本文件服务于三篇新版，不再把某一篇文章的段落顺序当成通用模板。分析对象以肖帅勇参与的两篇 *Information Systems Research* 论文为主。

## 一、上一版究竟错在哪里

上一版的主要问题不是缺少章节，而是章节之间的推动力不够自然。三篇都使用“从过程看”“从层次看”“由此提出”等相同路标，造成了三种假象。

第一，三个研究仿佛来自同一张概念框架，只是更换名词。实际上，候选打包、来源配置和检索停止面对的是三种不同的决策结构。它们不应拥有相同的引言节奏。

第二，coding agent 被当成算法的应用场所，而不是值得研究的信息系统情境。读者看到了 token、图和检索器，却没有充分看到开发任务怎样展开，agent 在何处依赖仓库信息，错误上下文如何改变修改，检索成本又如何进入真实部署。

第三，算法说明像功能清单。代表性、覆盖、成本、风险、校准和退化都被写进同一段，但没有明确哪个矛盾是算法必须解决的核心矛盾。肖帅勇的论文虽然组件较多，每个组件都只回应一个已经讲清的方法挑战，并且在算法出现之前，读者已经知道为什么必须有它。

标点统计也证实了僵化问题。ACAA 全文约 11.7 万字符，英文分号只有 24 个。DSDL 全文规模相近，英文分号约 20 个。上一版三篇只有 3.7 万至 4.1 万字符，却分别使用 86 至 102 个中文分号，另有 31 至 49 个英文分号。大量并列压缩了本来应该逐句展开的因果关系。

## 二、ACAA 为什么这样写

ACAA 的中心任务不是简单提出一个更强预测模型，而是先改变“哪些评论值得用于销售预测”的理解。文章把惯常的评论帮助性推向顾客注意力，再把注意力变成能够进入模型的指标。它的行文顺序由这一概念转变决定。

### 1. 引言的真正推动力

第一段先完成价值链：评论影响购买意愿，所以评论可能揭示未来销售。销售预测又具有运营价值，因此评论提供了不同于历史销量和市场变量的顾客需求视角。

第二段没有立即提出模型，而是检验一个直观方案，即把所有评论送入预测模型。文章随后从现实行为和既有方法两方面说明该方案为什么会偏。顾客不会处理全部评论，既有模型也没有有效区分评论。

第三段回到销售形成机制。只有被认真阅读的评论才更可能改变购买意愿。顾客注意力由此不是装饰性概念，而是评论影响销售之前必须满足的条件。

第四段故意回顾帮助性共识，再用顾客偏好异质和冲突发现削弱这一共识。新概念的必要性不是来自“帮助性研究不够新”，而是来自帮助性无法稳定回答哪类评论会首先获得注意。

第五、六段才使用过程和空间视角。它们不是通用写作路标。注意力本身是浏览行为，所以需要区分接收与评价，也需要说明注意力如何在评论集合、子集、单条评论和评论元素之间移动。若研究对象不是一个具有过程和粒度的行为构念，就没有理由复用这两段。

第七段逐个推出四项注意力指标。理论的任务不是提供背景，而是解释为什么某个观察量有资格代表顾客注意力。该段随后提出“如何利用这些指标”的第二个研究问题，并命名制品。

第八段只用几句话解释两个组件怎样实现四项指标。读者在此之前已经理解每个组件的必要性，所以该段不需要再次罗列全部缺口。

第九段报告数据、主要结果和意义。由于原文实验已完成，语气可以是完成体。新版在实验运行前不能机械模仿这一语气。

### 2. ACAA 的算法写法

ACAA 第三节反复使用一条清晰链条。理论先说明顾客会关注什么。文章再指出标准注意力机制为什么不能表达这种关注。最后才给出专门兼容函数或权重机制。

例如，语义多样性不是与时效性、投票和图文交互一起塞入总目标。文章先解释异质偏好为何产生语义多样的评论集合，再指出常用相似性兼容函数会偏向相关而冗余的评论。新机制只解决这一个矛盾。后续实验也单独检验它。

因此，模仿 ACAA 不能写成“理论给出四个词，模型加入四个模块”。真正要模仿的是：每个模块出现前，读者已经知道现有算子在哪一个数学关系上与研究情境冲突。

## 三、DSDL 为什么完全不同

DSDL 研究的不是一个需要四粒度分解的新注意力概念。它面对一种新出现的商业运营模式，以及该模式中特有的数据和决策困难。因此，引言没有复用 ACAA 的过程—粒度结构。

### 1. 先把研究情境写成熟

第一段从实时互动商业模式切入，说明更紧密的顾客—零售商互动为什么带来销售机会。

第二段花费整段解释“线上邀请、线下体验”模式。文章交代零售商、呼叫服务商和潜在顾客分别做什么，服务商如何获得报酬，呼叫如何连续发生，以及这一模式与等待顾客主动到来的在线销售有何不同。这一段尚未谈算法，却使后续预测任务具有清楚的组织边界。

第三段把预测价值落实为一个资源配置矛盾。潜在顾客很多，呼叫能力有限。若第一通电话后就能识别高响应意愿顾客，服务商便能把后续跟进能力投向更有希望的对象。预测任务因此不只是提高 AUC，而是改善有限营销能力的配置。

第四段说明该情境为何难。新顾客没有完整画像，呼叫却同时包含产品、顾客和互动信息。语音对话既是数据机会，也是非结构化难题。预测还必须尽早完成，因为呼叫能力和运行成本有限。

第五段才比较相似预测任务。文章不是说现有方法一般性能不足，而是指出它们建立在丰富画像和结构化特征上，恰好不满足目标情境。

直到第六段，期望不一致理论才进入。理论被用来组织语音中原本难以直接监督的期望、体验和满意度，而不是给深度模型附加解释标签。

### 2. 三个研究问题直接生成三个组件

DSDL 的 RQ1 来自没有画像却要估计个性化动态期望。对应方法是根据属性出现频率和顺序构造偏好模板。

RQ2 来自体验同时存在于文本、语音以及顾客—坐席交错问答中。对应方法是跨视图注意模型。

RQ3 来自理论变量没有真实标签，而黑箱模型又有较强预测能力。对应方法是带双向稀疏约束的对比学习，再把理论满意度与隐藏表示联合用于预测。

每个问题都包含一个具体的数据缺口或监督缺口。每个组件只处理该缺口。文章最后才说明三个组件如何协同。

### 3. DSDL 的算法说明为何清楚

DSDL 在方法章节先定义数据如何切分成对话片段，再解释每个矩阵的业务含义。频率表示偏好强度，顺序表示优先程度。顾客与坐席的两个序列之所以交叉注意，是因为回答者和提问者的角色会改变体验的形成。对比学习之所以需要稀疏约束，是因为总体满意的顾客也可能在不重要的属性或片段上不满意。

这种写法的关键是让矩阵、损失项和约束都拥有情境解释。它没有先展示一个复杂总损失，再事后为每一项寻找理由。

## 四、两篇 ISR 共享的稳定原则

两篇文章行文不同，但共享以下原则。

1. 先让读者理解研究情境中的决策，再讨论预测或算法。
2. 研究意义来自决策后果，不来自“该方向很热门”。
3. 缺口是现有方法与情境要求之间的具体不匹配，不是笼统的性能不足。
4. 理论必须改变表示、算子、损失或评价。理论只出现在文献综述中不算理论驱动。
5. 一个研究问题对应一个清楚的方法挑战。一个组件不能同时宣称解决五种问题。
6. 方法名出现前，读者已经知道它为何需要存在。
7. 公式之后立即解释变量在研究情境中的含义。
8. 主实验检验预测或决策效果。后续实验逐步排除更简单解释。
9. 探索性分析用于返回研究问题，而不是展示所有可画的图。
10. 句子以递进和因果连接为主。并列内容较多时拆句，不依赖连续分号压缩。

## 五、三篇新版采用不同母型

### 新版论文一：有限窗口中的决策就绪代码证据

论文一借鉴 ACAA 的“改变核心评价对象”逻辑，但不复用过程—粒度表述。

现有系统常把相关性高的代码看成好上下文。新版把核心对象改为“决策就绪代码证据”。一个上下文包只有同时呈现修改对象及其必要依赖，才足以支持代码行动。篇章重点是解释为什么候选被检索到不等于形成可行动证据。

算法只保留一条主线：把 query 诱导的定义、调用、配置和测试关系转为证据义务，选择单位 token 能补齐最多未满足义务的代码跨度。冗余递减不是第二个独立模块，而是“已覆盖义务不再重复计价”的自然结果。

暂定方法名：依赖完备上下文打包器，Dependency-Complete Context Packing，DCCP。

### 新版论文二：异质仓库检索服务的任务匹配

论文二借鉴 DSDL 的“先成熟刻画运营模式”逻辑。

开篇先写清 coding agent 的仓库检索服务栈。agent 收到 issue 后需要向词法索引、向量索引或代码图取得证据。服务拥有不同维护成本和响应方式。全部调用会增加延迟和候选处理量，单一固定来源又可能漏掉某类任务的唯一证据。

研究问题只问一件事：在执行检索之前，怎样为当前任务选择一个小型检索组合。新版不同时研究连续配额、代理—端点双重校准、尾部风险和在线停止。

算法只保留一条主线：离线枚举少量可运行检索组合，用统一打包后的任务效用生成组合次序，再学习基于任务与仓库特征的成本敏感排序。

暂定方法名：任务匹配检索组合器，Task-Matched Retrieval Portfolio，TMRP。

### 新版论文三：迭代探索中的证据充分性

论文三借鉴 DSDL 的“动态理论变量进入序列模型”逻辑，但采用信息充分性和序贯决策理论。

开篇具体描述 coding agent 如何从 issue 出发，读取入口文件，发现新符号，运行测试，再发起下一次检索。停止太早会在缺少调用者或测试约束时修改。停止太晚会引入重复代码、延迟和额外模型调用。

研究问题分成两个自然步骤。第一个问题识别当前证据是否仍在实质改变代码问题表示。第二个问题把这种状态转成停止与继续的价值比较。

算法只保留一个核心量：下一轮检索的净增量价值。目标满足、最新增量和表示稳定只用于估计这一量，不再各自宣称为独立算法贡献。标签由独立前缀回放和固定路径后向归纳获得。

暂定方法名：前缀价值停止器，Prefix-Value Stopping，PVS。

## 六、新版强制写作约束

1. 三篇正文均不得出现“从过程看”和“从层次看”。若确有过程关系，用具体行动描述。
2. 三篇引言不得共用段落数量或相同开头句式。
3. 每篇只保留一个中心算法命题。辅助特征和训练技巧不得升级为并列贡献。
4. coding agent 情境必须交代任务触发、参与者或系统角色、信息流、行动后果、资源约束和失败代价。
5. 每个公式之后必须解释它对代码任务意味着什么。
6. 正文中文分号目标为零。复杂并列拆为短句。
7. “因此”“由此”“综上”只在确实完成推导时使用，不作为段落模板。
8. 不用“六层证据”“四个层次”等元写作词代替实质内容。
9. benchmark 在说明可运行性时出现，不能在研究问题尚未成立前充当研究意义。
10. 所有结果保持 `[待实验]`，但结果段应明确什么结果会支持或否定主张。

## 七、后续逐句审计标准

新版的逐句审计不再要求三篇对应 ACAA 的同一行。审计将回答五个问题。

1. 这句话是否只完成一项任务。
2. 它是否继承前一句已经建立的事实或推论。
3. 它是否改变了论证状态，而不是换词重复。
4. 下一句是否需要它才能自然出现。
5. 句中的算法名词是否已经获得情境解释。

只有同时满足这些条件，才算真正模仿肖帅勇的学术写作逻辑。
