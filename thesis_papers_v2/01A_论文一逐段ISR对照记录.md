# 论文一逐段 ISR 对照记录

> 对照原则：每写完一个正文段落，立即回看 ACAA 或 DSDL 中承担相近职责的原文句群。记录只分析句子功能与承接关系，不复制原文措辞。

## 摘要

### 对照原段

- ACAA 摘要的句间推进是：既有研究及其惯常测量方式 → `however` 指出该测量不能稳定服务预测 → 以客户注意力重定义有价值的评论 → 将新构念分解为可实现指标 → 设计与指标逐一对应的方法 → 用预测和表征结果验证方法。
- DSDL 摘要采取另一条路线：先指出实时互动商业模式带来的机会 → 锁定一种具体业务模式和预测任务 → 并置管理理论与复杂数据处理能力 → 用一个方法承接三个相互依赖的学习任务 → 依次报告预测、机制和解释性结果。
- 两篇摘要都先让读者相信“原来的任务定义或数据用法不够”，然后才命名模型。它们没有先罗列网络组件或优化技巧。

### 本段逐句功能

1. 将 coding agent 放入仓库级缺陷修复和功能维护，并交代当前按相关性截取候选的惯常做法。
2. 用“然而”否定“高相关即足够”的隐含前提，并把缺证据落实到影响判断和修复验证失败。
3. 引入“可行动上下文”，把研究对象从候选相关性转到一组证据能否共同支持维护决策。
4. 命名 DCCP，并只交代一条核心选择逻辑，即按 token 成本选择仍未满足的证据义务。
5. 说明去冗余为什么是该目标的内生结果，避免把它包装成第二个算法模块。
6. 交代目标的计算结构及其实际含义，即在严格预算内可以求得可解释的近似解。
7. 说明固定检索器和 agent 的比较设计，并保留尚未产生的实验结果，避免虚构结论。

### 回看后修改

- 原第一句仅说“当前文件之外的代码证据”，没有建立成熟研究情境。修改后明确了仓库级缺陷修复和功能维护，以及 coding agent 使用检索器的具体位置。
- 原第二句止于列举定义、调用、配置和测试。修改后增加这些缺失如何导致 agent 只能定位局部代码、不能判断影响和验证修复，使缺口具有任务后果。
- 原方法句使用冒号罗列两个动作，读起来像组件清单。修改后把两个动作写成一条连续的选择规则。
- 原第六句过早列出“部分枚举与惰性贪心”。摘要现只保留可运行、可解释的近似求解，具体求解器留到方法部分。
- 原末句使用中文分号连接评价设计与结果占位。现改用逗号，并维持“尚未实验”的真实状态。

### 段末接口

摘要留下的关键承诺不是“提出许多模块”，而是：相关性排序为什么不能保证可行动性，证据义务如何被定义，以及一个边际覆盖目标能否在固定预算下改善 agent。引言必须先建立前两个问题，不能直接进入次模优化。

## 引言第 1 段：建立研究情境

### 对照原段

- ACAA 引言第一段不是一般性描述“评论很重要”。其五句话依次完成：评论连接消费者与产品 → 评论影响购买意愿 → 购买意愿使评论具有预测销量的潜力 → 销量预测具有运营价值 → 评论提供了区别于传统量化变量的顾客视角。每句话都把上一句的对象推进到下一项研究结果。
- DSDL 第一段先从数字技术导出实时互动商业模式，再说明这些模式改变了顾客与零售商的互动距离，最后把这种变化连接到参与度、销量和满意度。第二段才展开特定模式的参与者、支付关系和行动顺序。
- 因而，成熟情境不是“有一个公开 benchmark”的同义词。读者首先要看到谁在做什么、这种工作方式改变了什么，以及研究对象在该工作方式中处于什么位置。

### 本段逐句功能

1. 从基础模型与开发工具的结合，引出仓库级 coding agent 这一软件工作方式。
2. 依次呈现 issue、搜索、阅读、修改、测试和反馈，使 agent 的多步活动可以被具体想象。
3. 将仓库级修复与当前文件补全区分开，并用信息分散解释“先决定看什么”的必要性。
4. 说明委托搜索与验证活动可能改变开发者角色，同时指出定位、范围遗漏和无效调用是部署结果，而非纯模型分数。
5. 在工作方式已经讲清之后，再用 SWE-bench 说明它已有可重复观察的任务环境。
6. 收束到本研究的关键投入：能够在成本约束下支持修改与验证的仓库证据。

### 回看后修改

- 初稿第三句直接转入 SWE-bench，使情境重要性看起来来自 benchmark 的存在。修改后先补出仓库信息的分散性及 agent 的查看决策，再把 benchmark 作为“可观察性”证据。
- 初稿把搜索、理解、修改、测试压在一个对比句中。修改后用完整工作序列呈现这一业务过程，并单独说明它和当前文件补全的差别。
- 新增第四句，将仓库信息获取连接到开发者监督方式与部署后果。这样末句的“实际价值”有了组织使用层面的前件。
- 保留末句对生成能力与信息供给能力的区分，为下一段讨论现有检索做法留下接口。

### 段末接口

第一段只证明仓库证据是 coding agent 的关键投入。第二段应顺着“系统如何提供这些证据”介绍相关性排序这一直接做法，并在同一段内让它暴露出具体失效，而不能提前命名 DCCP。

## 引言第 2 段：检验直接做法

### 对照原段

- ACAA 第二段先承认“把所有评论放入模型”是从既有发现自然得到的做法，再指出有限注意力使这一做法产生偏差。后半段不是另换话题，而是继续说明既有数据处理和模型处理为何没有区分真正会发挥作用的评论。
- DSDL 的挑战段先指出新模式缺少个人资料，再解释语音互动恰好包含哪些可用信息以及为什么必须尽早预测。随后的文献段用同一组情境差异说明相似任务的方法为何不能直接移用。
- 两篇文章都没有仅凭“现有方法不够好”宣布缺口，而是先还原现有方法成立所依赖的条件，再证明焦点情境破坏了这些条件。

### 本段逐句功能

1. 说明从检索分数到最终提示上下文的直接做法，并承认多类候选生成器都可以位于该流程前端。
2. 揭示这一做法的两个隐含假定：候选价值可以脱离集合判断，排序后的价值可以在拼接中保持。
3. 指出仓库证据同时存在内容重叠和功能互补，直接破坏上述假定。
4. 用解析函数例子展示：最相关的多个片段可以重复解释局部代码，却把调用者和回归测试挤出预算。
5. 把例子收束到任务后果，即“找到了相关代码”仍可能“不足以完成修复”。
6. 公平承认语义、数据流和图方法改善了候选发现，同时界定它们没有自动解决的集合选择问题。
7. 明确区分候选发现和上下文成包，为下一段引入新的价值判准做准备。

### 回看后修改

- 初稿中的反例使用“词面较远”，这只能准确描述词法检索。修改为“同 issue 的直接匹配较弱”，使失效机制同样适用于语义和结构候选排序。
- 保留“解析函数—调用者—回归测试”这一单一反例，不再添加长度、中心性、压缩等旁支。它足以同时展示重复证据和缺失互补证据。
- 段末没有提出算法或研究问题，因为这一段的唯一任务是证明相关候选与可行动上下文包并不等价。

### 段末接口

既然单项相关性无法判断一个候选加入现有集合后的作用，下一段必须回到软件修改本身，说明什么样的证据关系才使上下文能够支持行动。该段应像 ACAA 第三段回到购买机制一样，从任务机制推出新构念，而不是从优化工具推出构念。

## 引言第 3 段：从修改机制推出新构念

### 对照原段

- ACAA 第三段从“销量最终来自购买意愿”开始，继而说明认真阅读的评论更可能影响购买意愿，于是“客户注意力”成为评论预测价值的必要前件。它不是因为注意力机制容易实现才选择该构念。
- DSDL 从期望不一致理论出发，先判断语音中哪些内容可以表示体验，再指出没有用户画像时难以取得动态期望，随后才提出学习策略。理论构念、情境数据和算法对象在同一条链上。
- 对本研究而言，相应的任务机制必须来自软件修改本身：补丁需要遵守依赖并满足预期行为。若不先成立这一点，“证据义务”就只是优化者自行规定的标签。

### 本段逐句功能

1. 把仓库级修改正确性连接到程序依赖和预期行为，并明确排除单片段相似性作为充分条件。
2. 说明定义、调用、配置和测试分别回答修改中的什么问题，而不是仅列出四种文件类型。
3. 因为它们回答不同问题，推出一种证据不能稳定替代其他证据。
4. 因为已回答的问题无需重复回答，推出相同关系证据的边际价值递减。
5. 将“可行动上下文”定义为能够共同回答任务关键问题的集合，并把未回答问题操作化为证据义务。
6. 限定依赖完备性的边界，防止它被误解为遍历全仓库。
7. 将候选价值改写为对当前集合中未满足义务的边际贡献，直接连接后续算法目标。

### 回看后修改

- 初稿首句用“减少关键不确定性”解释证据作用。这一表述过于通用，不能说明为何 coding agent 情境不可替换。修改后以“补丁是否符合程序依赖与预期行为”作为任务结果的直接前件。
- 保留四类证据，但每一类都配有不同的决策作用。它们不是四个算法组件，而是用来证明证据互补性的例证。
- 明确写出依赖完备性是任务条件化的，而非仓库全量覆盖。这既控制理论边界，也保证后续 benchmark 上可以标注和计算。

### 段末接口

第三段已经给出可行动性的任务机制。下一段应与 IS 文献对话，检验“有用信息”或“高质量信息”的既有判准是否足以替代这一构念，并说明为何集合条件化、成本约束和行动后果需要被同时保留。

## 引言第 4 段：与 IS 信息价值研究对话

### 对照原段

- ACAA 第四段先承认信息质量、论证质量和 helpfulness 都能解释评论价值，再指出这些指标不能稳定识别对异质消费者真正有影响的评论。其作用不是增加引用数量，而是证明新构念没有被已有构念覆盖。
- Wang and Strong（1996）原文把数据质量定义为数据消费者的“适用性”，并明确将相关性与完备性列入更广的信息质量维度。原文没有讨论代码仓库或集合打包。
- Mookerjee and Mannino（1997）原文区分信息获取成本与分类准确性，目标是在不牺牲准确性的情况下降低预期获取成本，并指出概念形成与检索策略分离会造成设计损失。
- Saar-Tsechansky and Provost（2007）原文比较 error-centric 与 decision-centric acquisition，核心判断是统计误差的昂贵改善可能不改变、甚至损害决策准确性。

### 本段逐句功能

1. 用“适合当前任务”而非“本身准确”确立 IS 信息质量的起点。
2. 明确标记从一般信息质量到仓库证据的推论，同时指出该理论尚未给出预算内的代码集合选择规则。
3. 从案例检索研究取得成本约束和检索—任务概念联合设计的依据。
4. 从决策中心主动学习取得“指标改善不等于行动改善”的依据。
5. 合并为两个设计要求：面向修改行动计价，并相对于 token 与处理成本计价。
6. 说明直接移用的边界：IS 原文没有代码关系这一计算单位。
7. 将程序依赖情境化为证据义务，使 IS 原则能够进入可运行算法。

### 回看后修改

- 原第二句写成“这一观点支持在仓库检索中……”，容易让人误以为 Wang–Strong 已得出代码检索结论。现改为“据此推论”，并明确原理论没有说明应取得哪组代码。
- 没有把 completeness、relevance、cost 和 decision value 各自做成算法组件。它们共同约束一个对象，即代码片段对未满足证据义务的成本调整边际贡献。
- 保留 Mookerjee–Mannino 的“联合设计”含义，但不照搬其决策树或属性询问算法，因为 coding agent 的候选单位与依赖结构不同。

### 段末接口

第四段已经给出设计要求与情境化单位。下一段应据此提出唯一研究问题并命名 DCCP，说明一条核心算法如何同时实现义务补足与预算控制，不能再并列引入代表性、压缩、排序校准等新主张。

## 引言第 5 段：研究问题与算法主线

### 对照原段

- ACAA 在 RQ2 之前先汇总已经推导的注意力指标，DTV-AMI 的两个组件只是把这些指标落实为注意力机制。后续方法说明仍逐项回指顾客到达、浏览和多模态权衡，没有额外增加一个无法解释的技术模块。
- DSDL 的第三个问题出现在动态期望和动态体验都已构造之后，其学习目标承担的是把二者合成满意度并服务预测。算法对象的出现顺序严格依赖前文的构念顺序。
- 对本文而言，义务来自第三段的软件修改机制，成本来自第四段的 IS 获取逻辑。算法段只能把这两个已出现对象合入选择规则。

### 本段逐句功能

1. 提出唯一研究问题，把研究边界固定在候选生成之后、agent 使用之前的预算打包。
2. 命名 DCCP，并明确冻结候选检索器，防止把检索器改进混入贡献。
3. 用 issue 锚点和仓库可追溯关系生成证据义务，说明优化对象从何而来。
4. 把候选片段映射到义务集合，并给出唯一选择分数：单位 token 的未满足义务增益。
5. 从同一目标推出降重和补缺，不把二者分拆为额外模块。
6. 交代加权覆盖的计算结构、预算约束、求解路线与可解释日志。
7. 给出唯一可检验主张，并固定同预算、同检索器、同 agent 的比较条件。

### 回看后修改

- 初稿称配置和测试关系“可以静态验证”。回看算法与情境的对应关系后，将其改为仓库索引中“可追溯”的关系，避免承诺完整静态证明。
- 没有恢复旧稿的设施位置代表性组件。语义重复只在其覆盖相同义务时被降权，这使降重仍服务于依赖完备，而非成为独立目标。
- 没有在研究问题前增加一个“识别哪些指标”的独立 RQ。义务类型将由修改机制、仓库关系和可标注性共同确定，是 DCCP 的输入构造，不是另一篇研究。

### 段末接口

第五段已经说明 DCCP 做什么。下一段需要说明怎样用现成、可运行的 benchmark 检验这一个主张，并把“证据完备性”与真实 agent 结果连接起来。评价层次必须少而必要，不能再写成六层清单。

## 引言第 6 段：可运行的经验检验

### 对照原段

- ACAA 的引言收束先解释方法如何落实已经推导的注意力指标，再报告同一酒店情境中的预测与表征结果，最后把结果解释为客户注意力的价值。
- DSDL 的收束也只保留预测表现、表征表现和对所学满意度的解释。它没有为了显得全面而把所有可计算指标逐项列为贡献。
- 两篇文章都让经验结果回到核心构念。对本文而言，金标准覆盖只有传导到固定 agent 的任务结果，才支持“可行动性”而非“另一个离线检索分数”。

### 本段逐句功能

1. 声明研究已有可运行的公开环境，不把实现寄托在未来自建完整 benchmark。
2. 指定 ARB 与 ContextBench 为核心场地，并准确说明二者原生提供的查询、仓库、金标准与预算条件。
3. 坦白证据义务不是现成标签，说明关系规则与人工抽检这一新增数据工作。
4. 将 RepoBench 与 CrossCodeEval 限定为多语言跨文件稳健性检验，而非与 issue 修复并列的另一研究主题。
5. 用冻结候选、相关性和模型实现受控比较，只改变打包器。
6. 保留三类必要结果：外部金标准证据、下游任务结果和资源成本。
7. 给出解释门槛，防止仅凭内部义务覆盖指标宣称 agent 受益。

### 回看后修改

- 初稿用“第一步、第二步”组织四个 benchmark，重新产生了人为的阶段结构。修改后改为核心评价与稳健性检验，依据是任务贴合程度，而非形式上的两阶段。
- 明确 ARB 与 ContextBench 没有现成证据义务标签。公开 benchmark 使任务、仓库和外部金标准可用，但关系抽取与抽检仍是本研究必须完成的工作。
- 没有把运行成本、六类消融和多模型迁移各写成独立“层次”。它们只用于回答核心改进是否真实、是否值得成本。

### 段末接口

引言的实质论证已经闭合。若增加最后一段，只应概括理论贡献、设计贡献和经验贡献分别改变了什么，并清楚限制尚未完成的实验状态，不能重复摘要和方法清单。

## 引言第 7 段：贡献边界

### 对照原段

- ACAA 的末段再次说明每种机制怎样实现已经推导的客户注意力，随后用真实结果把性能提升解释回客户注意力价值。

- ACAA 的每个指标先给行为或理论来源，再说明该来源为何形成特定模型要求。指标不是从模型方便性倒推。

### 本段逐句功能

1. 把锚点来源限定为推理时可见信息。
2. 列出从 issue、命令输出和错误位置中抽取实体的可实现规则。
3. 为无显式实体任务规定冻结检索器种子这一低置信度回退。
4. 规定唯一名称和重名名称的解析方式。
5. 为每个锚点保存来源、位置、规则和置信度。
6. 明确排除金补丁、金标准和事后测试信息，并说明锚点的唯一作用。

### 回看后修改

- 无需修改正文。信息时点、解析歧义、回退与来源日志均已明确。
- 低置信度种子的数量与权重折扣必须预先固定，并在消融中报告，否则检索器偏差可能被 DCCP 放大。

### 段末接口

下一段从每个锚点生成关系义务。每种义务都必须回答一个明确的修改问题，并说明何时生成、何时不生成，不能无条件为所有锚点套同一张关系清单。

## 方法第 4 段：关系义务的生成

### 对照原段

- ACAA 对 semantic diversity 的论证先从评论者与阅读者偏好异质推出集合需要互补，再指出 affinity attention 会造成冗余，最后才设计不相似性机制。
- DSDL 的方法挑战段把信息内容、表达方式、产品属性和问答角色分别连接到满意度形成中的具体作用，再决定怎样提取与组合。
- 相应地，代码关系只有回答修改中的实际问题时才形成义务，不能因为图索引里有某种边就一律加入。

### 本段逐句功能

1. 规定义务由锚点附近真实存在的仓库关系触发。
2. 解释定义、入向影响和出向依赖分别回答什么修改问题。
3. 规定只有真实配置或注册引用存在时才生成激活义务。
4. 规定测试直接引用、相同调用路径或 issue 点名时才生成验证义务。
5. 补充错误轨迹中的定位关系。
6. 以一跳和候选可覆盖性控制规模并保持打包目标可解。
7. 保存义务来源，并明确四个作用名称不是四个模块。

### 回看后修改

- 无需修改正文。每类关系均有任务问题、触发条件和可追溯记录。
- 默认一跳是可实现性选择，不宣称足以覆盖所有多跳修改。两跳扩展应作为稳健性分析，并报告候选与义务规模增长。
- 内部优化只包含候选可覆盖义务。评价必须另报全仓可生成义务到候选可覆盖义务的损失，以区分上游检索失败与打包失败。

### 段末接口

下一段定义义务权重与候选覆盖。权重必须先说明业务含义，再给公式，并控制一个锚点拥有大量调用者时的度数偏置。

## 方法第 5 段：义务权重与候选覆盖

### 对照原段

- DSDL 4.4 先解释“提及频率与先后顺序为何表示偏好”，再定义矩阵元素，公式之后又分别解释对角项和非对角项的业务含义。
- 两篇 ISR 的数学结构都服务于前文关系，不以复杂公式本身作为意义来源。
- 本段相应先说明锚点、关系类型和具体义务，再给权重公式，之后解释归一化如何防止高出度符号支配选择。

### 本段逐句功能

1. 定义锚点下实际出现的关系类型集合与具体义务集合。
2. 给出以锚点置信度为总量、按类型和关系数两级归一的默认权重。
3. 解释该权重怎样控制仓库度数偏置并平衡实际出现的证据作用。
4. 将学习型权重降为训练集稳健性分析，避免新增一个必要模型。
5. 用索引证据位置定义候选是否覆盖义务。
6. 定义候选覆盖集合及多对多关系。
7. 区分全仓义务与候选可覆盖义务，用于拆解上游检索损失。

### 回看后修改

- 把上一段重名锚点“共享原始置信度”改为“共同分配原始置信度”，避免多个解析各自复制相同权重。
- 无需修改本段公式。符号均在出现前定义，公式后也有明确的 coding-agent 含义。
- 训练型关系权重不能在测试集或下游结果上调参。主结果使用等权归一化，学习型权重只作附加检验。

### 段末接口

下一段可以给出集合目标。目标中不应再次加入独立的相关性、多样性或压缩项，否则会破坏“一个算法主线”和当前权重含义。

## 方法第 6 段：唯一集合目标

### 对照原段

- ACAA 的 semantic diversity 机制先指出 affinity compatibility 会强调相似评论并造成冗余，再让新的 compatibility 结构响应互补评论。
- DSDL 的公式段在公式后分别解释矩阵项怎样表示提及强度和时间优先级，数学项始终有情境含义。
- DCCP 相应只让“义务是否已经出现”决定边际收益，次模性质是这一情境关系的数学结果。

### 本段逐句功能

1. 定义任意集合的加权义务覆盖函数。
2. 解释截断函数为何让每项义务只计一次。
3. 从同一函数推出重复证据零增益与互补证据正增益。
4. 给出硬 token 背包约束下的最大化问题。
5. 解释长度为何进入取舍。
6. 说明非负、单调和次模性质。
7. 限定内部覆盖与真实修复价值仍需经验连接。

### 回看后修改

- 无需修改正文。公式只有一项收益和一项预算约束。
- 相关性只通过锚点来源和候选池间接发挥作用，不再作为独立加和项。若实验发现完全不相关的图邻居被选中，应改进义务生成，而非临时加相关性正则。
- 该数学形式与 Bala（2026）的通用次模打包近似，后文贡献必须持续落在代码义务构造和 coding-agent 验证。

### 段末接口

下一段说明怎样求解。应先解释为什么不能精确穷举，再给可运行算法、复杂度和保证，不能把近似保证写成主要研究意义。

## 方法第 7 段：最优性审计与理论边界

### 对照原段

- DSDL 4.7 先呈现总体优化目标，随后立即解释最小化它能够同时产生何种预测结果和理论构念，最后把训练细节交给附录。公式并不自行构成贡献，必须由其研究用途来收束。
- ACAA 4.5 只交代能够复现整体优化流程的关键环节，没有把常规梯度计算包装成另一项方法创新。
- DCCP 的整数规划因而被限定为小实例审计工具，其作用是衡量实用求解器而不是替代它；经典近似算法也只界定理论可达性。

### 本段逐句功能

1. 承接上一节目标，指出尚缺“实用解离最优组合多远”这一测量能力。
2. 明确整数规划仅用于候选规模允许时的审计。
3. 在公式前定义候选选择变量和义务覆盖变量。
4. 以同一义务价值和 token 预算写出精确模型，不引入新的效用项。
5. 说明最优解或有效上界怎样转化为经验最优差距和运行时间。
6. 规定超时结果不能被误报为最优值。
7. 交代经典 $1-1/e$ 保证依赖的枚举与直接实现成本，解释其不作为在线默认方案的原因。
8. 收束三者分工：理论算法提供参照，整数规划审计小实例，惰性贪心负责主实验与部署。

### 回看后修改

- 把开头从笼统的“实用求解速度不能说明接近最优”改为承接前述目标的缺口句，使本段不是突然增加一个求解器。
- 公式后先写它实际返回的最优解或上界以及由此计算的量，对应 DSDL 在公式后解释结果用途的写法。
- 明列 $O(|C|^5)$ 的直接函数值计算量，并将 Sviridenko（2004）限定为理论参照。本文不把经典保证归到默认惰性算法名下。
- 整数规划使用与 DCCP 完全相同的 $F(S)$ 和预算约束，不能被称作第二项算法贡献。

### 段末接口

既然精确审计和理论算法都不是在线方案，下一段必须给出唯一的生产求解流程，并说明它为何能利用加权覆盖的边际收益递减性质。

## 方法第 8 段：惰性边际密度求解

### 对照原段

- ACAA 4.5 没有从优化器名称开始，而是先沿“预处理—表征—机制—预测”重述数据怎样进入模型，再交代反向传播更新哪些参数。该段的作用是把前述组件收束为一条真正可执行的过程。
- DSDL 4.7 在总体目标之后立即解释最小化该目标同时得到什么预测产物和理论产物，使求解仍然服务于研究情境，而不是成为孤立的数学展示。
- DCCP 的对应段因此先交代精确枚举为何不可作为默认实现，再依次说明候选优先级、惰性重算、停止条件和可回溯输出。

### 本段逐句功能

1. 说明候选组合随规模增长，建立采用近似求解的现实必要性。
2. 给出默认求解器及其最终用途，即形成交给 agent 的上下文。
3. 定义单位 token 新增义务价值这一候选优先级以及堆中的保存对象。
4. 说明候选出堆后必须根据当前集合重算真实边际密度。
5. 分开说明纳入、更新上界和因预算跳过三种处理结果。
6. 用次模性解释旧值为何构成安全上界以及惰性计算节省了什么。
7. 给出停止规则和最佳单片段修正，避免密度贪心漏掉一个高价值长片段。
8. 说明算法除上下文外还输出什么选择轨迹，以及轨迹怎样回到程序关系证据。

### 回看后修改

- 在段首补入“全部可行组合无法作为大型仓库默认方法”，使求解器先回应计算情境，再进入数据结构和更新步骤。
- 将原先由中文分号连接的出堆判断拆成两句，避免把条件、动作和例外挤在同一句中。
- 把末句从泛化的“可重放轨迹”改成“沿选择轨迹回溯到具体关系证据”，明确该产物为何对本文的可解释主张有用。
- 本段不声称该实用贪心具有 $1-1/e$ 保证。保证、精确小实例核验与生产求解器的边界在下一段单独说明。

## 讨论第 3 段：面向行动的信息获取成本

### 对照原段

- 本段也把贡献定位为方法规则：它把 IS 中已有的成本敏感与决策中心原则，落实到检索后、agent 前的代码证据组合点。

### 本段逐句功能

1. 用两篇既有 IS 研究界定成本与最终决策的规范要求。

### 回看后修改
