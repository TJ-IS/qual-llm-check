# 论文二逐段 ISR 对照记录

> 对照主文：DSDL 为主要母型，ACAA 用于检查概念与算法之间是否存在真实承接。每个条目均在目标段落写成后回读原文，再决定修改或保留。

## 引言第 1 段：从能力扩展落到检索服务

### 对照原段

- 写成目标段后，逐句回看 DSDL 引言第 1 段。原段第一句以数字化、数据和人工智能带来的实时互动模式开场，第二句立即命名这类模式的关键优势，第三句补充让优势成为可能的沟通通道，第四句把优势连接到销售机会，第五句再把研究兴趣落到互动中的顾客满意度。它不是用技术趋势直接证明研究价值，而是连续补出“新模式—关键能力—组织结果—待改善对象”。
- 同时回看 ACAA 引言第 1 段。其写法把评论、购买决策、销售预测和运营用途串成价值链，提醒目标段不能只罗列检索器名称，必须说明检索选择怎样影响 agent 的修改行动与平台成本。

### 本段逐句功能

1. 第一句只说明 coding agent 相对局部补全发生了怎样的能力扩展。
2. 第二句把仓库证据取得放到开发者提交任务之后、agent 修改之前，建立本文研究的具体决策位置。
3. 第三句说明平台为该决策提供哪些性质不同的可运行服务。
4. 第四句解释这些服务为什么不能被当作同质替代品，并首次引入成本差异。
5. 第五、六句把检索选择连接到信息机会与平台支出，为下一段具体描写服务调用方式留下接口。

### 回看后修改

- 初稿曾以“检索已成为关键基础设施”直接开场。回看 DSDL 后删去该判断，因为它跳过了 coding agent 的任务触发、信息流和行动位置。
- 将“多种检索器各有所长”拆成具体对应关系：错误字面量对应词法匹配，自然语言对应稠密语义，文件全局结构对应仓库摘要，跨符号依赖对应代码图。这样检索器名称已经获得情境含义。
- 在段末同时写信息机会与获取成本，没有提前宣称哪一种组合更优，也没有在研究问题尚未成立前搬出 benchmark 数字。

### 段末接口

下一段需要像 DSDL 对参与者、付费关系和连续呼叫的交代一样，具体说明开发者、agent、检索服务与打包器怎样协作，以及一次“检索组合”到底是什么。只有先把运行单位定义清楚，后文的成本敏感选择才不是抽象模型。

## 引言第 2 段：把检索组合写成可观察的运行单位

### 对照原段

- 段落完成后，重新逐句阅读 DSDL 引言第 2 段。该段不是抽象定义一种商业模式，而是依次交代适用零售商、潜在顾客的线上行为、零售商对服务商的委托与付费、坐席的连续呼叫、同被动线上销售的差别，以及集中互动带来的管理意义。
- 对照后确认，本段也必须让每个系统角色执行一个可观察动作。冻结仓库提供共同对象，检索服务返回候选，编排器决定调用集合，打包器统一处理候选，agent 最后消费上下文。若缺少这条行动链，“组合”会退化为算法作者任意拼接的若干模型。

### 本段逐句功能

1. 第一句说明可调用服务在任务到达前已经存在，排除把索引建设同逐任务选择混在一起。
2. 第二句规定各服务接收同一任务，并按预先固定的配置返回候选。
3. 第三句给出检索以后、agent 以前的共同处理流程，确定组合效果的落点。
4. 第四句正式定义分析对象为同一任务中共同启用的服务配置集合。
5. 第五句用四种可实现配置说明集合元素是什么，并排除连续配额优化。
6. 第六句规定决策时点与允许使用的信息，防止组合器偷看检索结果或金标准。
7. 第七句把组合选择解释为对信息来源成本的前置配置决策。

### 回看后修改

- 保留“服务配置”而不是只写“检索器”。相同 BM25 或稠密模型在不同 top-k 下具有不同成本与候选量，只有把 top-k 固定进配置，离线枚举的选择对象才可复现。
- 明确索引在冻结提交上预先建立。组合器的逐任务成本主要是查询、合并和候选处理成本，索引建设与存储成本将在部署分析中作为仓库级固定成本单列，不能虚构为每次查询成本。
- 明确组合选择早于检索结果。这一点对应 DSDL 在第一次电话结束后才预测的决策时点写法，使后文的训练特征与部署输入拥有相同信息边界。
- 回看后未增加更多平台组件。当前行动链已经足以定义决策，继续加入重排序器、查询改写器或在线反馈会使研究对象失焦。

### 段末接口

下一段应建立资源配置矛盾。它需要具体比较“所有服务都调用”和“永远只调用一个固定服务”的后果，并说明任务匹配何以能够同时改变证据取得与运行成本。该段不能提前介绍 TMRP。

## 引言第 3 段：全调用与固定来源之间的资源矛盾

### 对照原段

- 写完后再次逐句阅读 DSDL 引言第 3 段。原段先命名预测为何关键，继而用“巨大潜在顾客市场—有限呼叫能力”建立数量矛盾，再说明广泛呼叫为何在时间与容量上不可持续，最后给出及时预测怎样改变后续资源分配。
- 本段没有机械复制“一方面—另一方面”，而是保留其论证结构：先给出两个可操作的极端政策，分别说明代价，再用真实场地中的异质结果证明折中不是作者凭空设定，最后说明任务匹配可能改变什么。

### 本段逐句功能

1. 第一句提出全调用政策及其直接好处。
2. 第二句把全调用的代价拆成服务执行、候选处理和有限预算竞争。
3. 第三句转到固定服务政策，说明它节省成本但形成稳定盲点。
4. 第四句引用 ARB 的总体召回、预算产出和分任务赢家差异，为盲点提供外部证据。
5. 第五句把统计差异转成开发任务上的信息需求差异。
6. 第六句用三类任务分别说明词法、语义与结构来源何时可能有用，但使用“可能”而不是把例子写成未经检验的定律。
7. 第七句给出任务匹配的预期资源效果，仍未命名方法。

### 回看后修改

- 把初稿中“调用全部服务会降低质量”的绝对说法改为可观测代价。全部调用必然增加相应查询与合并工作，但是否降低最终上下文质量取决于共同打包器，不能在实验前宣判。
- 采用 ARB 的已报告异质结果，而没有把 benchmark 当作研究意义。它在此只负责证明不同检索族并非同质，也没有一个来源在所有任务与预算上占优。
- 示例严格对应 ARB 的 trace2code、comment2context 与 edit2ripple 信号，没有凭空列举安全审计、架构迁移等无法在核心场地运行的任务。

### 段末接口

资源矛盾成立以后，下一段需要说明为什么任务匹配本身困难。关键不是“选择空间很大”，而是检索前看不到结果、服务价值由任务与仓库共同决定、组合价值又不等于单个服务分数相加。

## 引言第 4 段：检索前任务匹配的具体困难

### 对照原段

- 段后回读 DSDL 引言第 4 段。原段先把困难定位为个人信息缺失，再同拥有丰富信息的传统情境比较，随后说明语音同时容纳产品、顾客和互动信号，最后补入“必须尽早且低成本判断”的时点约束。其作用不是堆叠挑战，而是说明可用数据既不充分又有潜力，方法必须从有限信号中恢复决策对象。
- 本段相应地把检索前状态写成一种反事实缺失：系统看得到任务与仓库表征，却看不到各检索服务尚未返回的候选，更看不到它们经过同一打包器后的实际任务收益。

### 本段逐句功能

1. 第一句声明匹配困难，但不重复上一段的成本矛盾。
2. 第二句区分可见任务线索与不可见服务结果。
3. 第三句说明同一线索会因仓库组织方式改变诊断价值，把仓库条件纳入问题。
4. 第四句把价值判断从单服务推进到组合。
5. 第五、六句分别用重复与互补说明为什么单服务平均分不可相加为组合价值。
6. 第七句排除“任务类型分类器 + 固定赢家”这一更简单解释。
7. 第八句准确规定待估计对象为统一预算下的组合任务收益减查询成本。

### 回看后修改

- 删除了“任务特征和仓库特征很多”这一无效表述，改成同一个错误词在不同命名与依赖条件下为何具有不同检索价值。
- 将方法困难限定为两个关系：条件异质性与组合互补性。没有把在线停止、动态配额、查询改写或尾部风险一并列为问题。
- 末句仍未引入学习模型名称，只把后文必须预测的量说清楚。该处理对应 DSDL 先让个人信息缺失与语音数据价值成立，再进入相关方法比较的节奏。

### 段末接口

下一段进入相近技术工作。它应逐类说明现有研究改变了检索器、是否检索或 agent 的探索方式，却没有在检索前对一个可运行服务目录进行成本敏感的组合选择。缺口必须落到决策对象不同，不能只说“缺少统一框架”。

## 引言第 5 段：相近工作为何没有回答组合选择

### 对照原段

- 段后回读 DSDL 引言第 5 段。原段先列举最接近的三类预测任务，再用两个一一对应的情境差异排除直接迁移：既有对象拥有丰富个人信息，目标对象没有。既有方法处理定量特征，目标数据是非结构化语音。缺口因此是输入前提不成立，而不是文献没有使用新模型名。
- 本段采用相同的“最近邻工作—决策对象差异”逻辑，但不复用两项编号。候选发现、结构导航与选择是否检索都同本文相近，却分别停在服务内部或二元开关上。本文要选的是多个既有服务构成的集合。

### 本段逐句功能

1. 第一句先概括现有工作的两类主要决策，不先给出批评。
2. 第二句列出三项跨文件检索工作及其各自改变的来源。
3. 第三句说明图方法把检索推进到导航与多跳定位，同时限定它们仍在优化候选发现。
4. 第四句给出最接近的选择性检索工作，并准确说明其决策是对既定检索的启停。
5. 第五句承认这些工作为组合选择创造了服务条件，再指出未覆盖的前置集合决策。
6. 第六句用两个不可替代关系收束缺口，防止后文把平均赢家或二元开关当作充分基线。

### 回看后修改

- 没有写“现有研究忽视成本”。Repoformer 明确研究效率，图方法也报告成本。真实缺口是它们没有把成本用于多个服务配置之间的逐任务组合选择。
- 没有贬低结构检索。RepoGraph 和 LocAgent 在本研究中是候选服务，也是组合器可能选择的对象。两层可以衔接，但不能把改变候选发现的方法写成本文同层竞争者。
- 将 Repoformer 定位为最重要的直接基线之一，而不是用“只做二分类”将其轻描淡写。后续实验必须检验组合选择是否真有超出选择性启停的价值。

### 段末接口

下一段需要进入 IS 理论，而不是立即给方法。理论应解释为什么平均最优服务不等于当前任务最有价值的信息来源，以及为什么取得信息的成本必须同最终代码行动共同评价。候选理论必须改变目标函数或评价，不做装饰引用。

## 引言第 6 段：用匹配与获取成本规定算法应优化什么

### 对照原段

- 目标段写成后，逐句回看 DSDL 引言第 6 段。原段先给出满意度与购买意愿的稳定关系，再把线上体验与期望引入目标情境，最后用不一致关系说明满意度怎样形成。理论在该段结束时已经规定后文必须表示期望、体验及其差，而不是给模型附上一段背景。
- 本段也要求两篇 IS 文献各改变一项设计。任务—技术匹配把预测输入规定为“任务与仓库要求—检索组合功能”的对应关系。信息获取成本把输出目标规定为经过共同打包后的任务收益减服务成本。

### 本段逐句功能

1. 第一句声明理论将提供算法规范，避免空泛的“提供理论基础”。
2. 第二句提取 TTF 中技术功能、任务要求、使用与绩效的必要关系。
3. 第三句把抽象技术功能翻译为三类检索服务处理仓库线索的差异。
4. 第四句规定匹配发生在任务—仓库要求与组合功能之间，而不是服务平均排名之间。
5. 第五、六句引入信息取得成本，并准确使用既有表示固定时仍可进行成本敏感采集的结论。
6. 第七句排除只优化金文件概率的目标。
7. 第八句把部署价值收束为共同预算下外部任务改善是否抵偿服务成本。

### 回看后修改

- 初稿写入 Mookerjee and Mannino（1997）关于“概念形成与检索策略联合优化”的主要结论。回到原文后删去，因为 TMRP 冻结各检索器并没有联合学习其内部表示，保留该句会把方法贡献说大。
- 改用该文明确支持的第二项结论：即使概念形成与检索策略分离，成本考虑仍能显著减少信息取得成本。这与固定服务目录下的组合选择真实对应。
- 没有把 TTF 直接变成一个可测量心理构念。本文只迁移其规范关系，并将在方法中公开定义任务—仓库特征、组合功能和外部绩效，避免用理论名称替代操作化。

### 段末接口

理论已经规定了输入关系与结果目标。下一段可以提出唯一研究问题，并在同段给出 TMRP 的最小方法承诺。方法只需回答怎样从离线可运行组合结果学习一个检索前排序，不应再产生多个研究问题。

## 引言第 7 段：唯一研究问题与 TMRP 的最小承诺

### 对照原段

- 写完以后回到 DSDL 引言第 47 段逐句检查。原段在理论基础之后，先解释为什么语音适合取得体验，再说明期望无法直接观察、会动态变化且源于异质偏好。研究问题出现时，它恰好概括前面的困难。方法名随后立即出现，后续两句只说明偏好模板与片段矩阵怎样回应动态期望。
- TMRP 段也让研究问题概括已经建立的三项约束：检索前决策、任务—仓库条件、收益与成本共同评价。方法说明随后只保留离线枚举、学习组合次序和在线选择三步。

### 本段逐句功能

1. 第一句用一个研究问题锁定决策时点、条件、选择对象和结果标准。
2. 第二句命名 TMRP，不另造并列构念。
3. 第三句说明离线怎样得到每个可行组合的可观察结果。
4. 第四句指出学习对象是同一任务内的组合次序，并排除独立服务打分。
5. 第五句规定在线阶段只用检索前特征选择一次。
6. 第六句给出唯一可证伪命题及三类直接对手。

### 回看后修改

- 将“真实任务收益”改为“可观察任务收益”。benchmark 的金上下文与固定 agent 结果是可运行代理，不能被称为任务真实价值。
- 没有像 DSDL 一样提出三个研究问题。论文二的困难可以由一个成本敏感组合排序统一处理，若拆成任务识别、互补预测和成本控制三问，会重新造成用户此前批评的算法清单。
- 没有承诺联合训练检索器、打包器或 agent。三者冻结后，组合次序的效果才可单独识别。

### 段末接口

引言仍需要一个经验场地与贡献边界段。该段应说明哪些公开数据能为同一任务运行所有组合、取得金上下文并记录成本，同时诚实区分直接核心场地、迁移场地与尚不具备原始数据的附加场地。

## 引言第 8 段：公开场地与主张成立条件

### 对照原段

- 完成目标段后回看 DSDL 引言末段。原文用方法总称收束三个组件，随后报告真实销售场景中的预测与表示结果，最后说明解释性分析提供何种认识。由于原文实验已经完成，它可以使用结果性语气。
- 论文二目前只能保留相同的闭环功能，不能模仿完成体。目标段依次说明直接场地、外部 issue 场地、补全迁移场地、识别协议和支持主张所需的结果组合。

### 本段逐句功能

1. 第一句声明设计具有可运行场地，回应用户对“现成数据与 benchmark”的硬要求。
2. 第二句说明 ARB 同时具备任务、冻结语料、金文件、可运行基线和选择性样本，为什么它是直接场地。
3. 第三句说明 ContextBench 的规模、语言、人工金上下文与评价程序，为什么它能检验 issue 迁移。
4. 第四句把 RepoBench 限定为已知光标的跨文件补全迁移，不与 issue 结果混算。
5. 第五句规定仓库外推与唯一变化项，建立识别条件。
6. 第六、七句明确没有结果，并给出主张成立的外部证据与成本条件。

### 回看后修改
