# 什么时候停止查找：面向 Coding Agent 初始仓库探索的前缀价值停止

> English title: When Should a Coding Agent Stop Searching? Prefix-Value Stopping for Initial Repository Exploration
>
> 稿件状态：研究设计稿。所有实证结果均待按本文方案运行，不报告虚构数值。

## 摘要

Coding Agent 在首次编辑前反复搜索和读取仓库，停止过早会遗漏接口与测试约束，停止过晚则引入重复上下文、延迟和额外调用。现有代码检索研究主要改善是否启动一次检索或返回什么证据，软件工程 Agent 的提前终止研究则集中于补丁生成与选择，尚未直接评价初始探索中下一次证据获取是否值得。本文借鉴信息系统研究中的认知停止线索与边际信息价值，提出前缀价值停止器 PVS。该方法将事项满足、最新证据差异和问题表示稳定编码为可观察前缀状态，并以外部目标上下文质量减累计仓库 token 成本定义效用，再通过固定路径后向归纳构造下一次检索的净增量价值标签。单层 GRU 学习这一价值，在满足验证仓库质量约束的阈值下决定继续检索或开始首次编辑。实证方案以 ContextBench 的人工目标上下文完成仓库外前缀检验，以 SWE-Explore 的留一 Agent 家族标签检查跨轨迹迁移，并在 SWE-rebench V2 的 500 项预注册可执行样本上比较基础 Agent、PVS、EET 与 EET+PVS。本文不预报实验优势。只有 PVS 在减少获取成本的同时保持上下文质量与任务解决率非劣，并优于固定预算、单一停止线索和序列无关学习器，才能支持任务条件化的前缀价值停止主张。

## 1 引言

Coding Agent 正在把自然语言软件问题转化为可执行的仓库修改。收到 issue 后，Agent 通常先查看目录与候选文件，再沿着符号定义、调用关系和测试线索反复搜索与阅读，随后才生成补丁并运行测试（Jimenez et al. 2024, Xia et al. 2025）。这段首次编辑前的仓库探索连接了问题描述与代码行动。它决定 Agent 在动手修改时看见了哪些约束，也消耗上下文窗口、模型调用和工具执行时间。因此，初始探索不仅是补丁生成的准备步骤，也是一个需要管理的信息获取过程。

在本文关注的典型场景中，维护者以 issue 描述缺陷或功能需求，基础 Coding Agent 据此提出搜索、定位符号或读取文件等工具调用，仓库工具则返回相应代码证据。一次返回往往暴露新的类、调用者或测试，使 Agent 可以继续提出下一次检索。Agent 也可以结束探索，使用当前证据开始生成首次代码编辑。过早结束会使遗漏的依赖转化为错误补丁，继续查找则会占用有限的执行预算。本文研究的不是如何生成下一条查询，而是基础 Agent 已经提出一项新的仓库证据获取动作时，是否值得执行该动作。

这一选择不能简化为“检索越多越好”。如果 Agent 只找到 issue 直接点名的函数便开始修改，它可能尚未看见调用者施加的接口约束，也可能遗漏规定预期行为的测试。相反，当已有证据不再改变候选修改位置、故障解释或测试义务时，继续打开相邻文件往往只带来重复内容，并推迟首次编辑。新增证据的价值还取决于任务本身。一个明确给出文件路径和失败测试的局部缺陷，与一个只描述跨模块异常的 issue，不应共享同一探索长度。真正需要判断的不是已经查找了多少次，而是执行下一次证据获取后，预期改善能否补偿其新增成本。

一种直接做法是为所有任务规定相同的搜索轮数、返回 token 数或时间上限。这类预算能够截断无休止的探索，却把不同任务的证据需求压成同一尺度。另一种做法是让基础 Agent 自行宣布已经获得足够信息，但这一判断与它生成查询、解释代码和规划补丁时的同一内部状态相互纠缠，难以独立检验。两种做法都没有利用每次返回后出现的新证据来重新评价下一次检索。它们控制了探索何时必须结束，却没有回答何时继续已经不再值得。

相邻研究已经触及“是否还要继续”的不同部分。Repoformer 在仓库级代码补全前选择是否进行一次检索，RepoGraph 则用代码图改善 Agent 每一步能够取得的结构证据（Wu et al. 2024, Ouyang et al. 2025）。这些方法主要改变检索是否启动或检索返回什么，没有评价多轮探索中某一前缀之后的下一次证据获取。EET 已经为软件工程 Agent 学习提前终止规则，但它停止的是补丁生成和候选选择阶段，而不是首次编辑前的仓库查找（Guo et al. 2026）。开放域问答中的 TASR 使用答案重复与置信度判断迭代检索是否结束，却没有可直接对应仓库修改充分性的答案状态（Kieback et al. 2026）。这些边界把本文的缺口限定为一个具体决策：在不改变基础 Agent 下一步查询策略的条件下，根据当前探索前缀判断是否执行它已经提出的下一次仓库证据获取。

信息系统研究为这一判断提供了比固定轮数更贴近任务的起点。Browne et al.（2007）发现，人们会以待满足事项、最新信息差异或问题表示是否稳定来判断搜索是否充分，而且采用何种停止规则取决于任务结构与表征方式。该发现描述的是人类搜索者使用的认知线索，不能被直接解释为语言模型具有相同心理机制。规范性的信息搜索观点则要求比较额外信息的预期价值与获取成本（Browne et al. 2007, Mookerjee and Mannino 1997）。据此，本文把待满足事项、最新增量和表示稳定转化为 Agent 探索前缀中可观测的信号，但不让任何一个信号单独决定停止。三类信号只共同估计一个规范目标，即基础 Agent 所提下一次检索的净增量价值。

本文据此提出研究问题：如何利用 Coding Agent 当前可见的探索前缀，判断是否应当执行首次编辑前的下一次仓库证据获取？为回答该问题，我们设计前缀价值停止器（Prefix-Value Stopping，PVS）。训练时，PVS 在一条既有探索轨迹的每个可停止前缀上，分别计算当前停止的证据质量与累计成本，并通过固定路径后向归纳得到继续一次所能带来的净增量价值。运行时，一个轻量序列模型使用当前任务线索、待满足事项、最新证据增量、问题表示稳定度、已用成本和下一动作属性来预测该价值。预测价值为正时，基础 Agent 提出的检索照常执行。预测价值不为正时，PVS 阻止更多首次编辑前的仓库读取，并要求基础 Agent 使用现有证据开始修改。PVS 因而只学习何时退出一条给定的探索路径，不选择下一条查询，也不把固定路径上的价值标签解释为整个搜索图的最优策略。

这一研究可以在现成的公开资源上实际运行。ContextBench 提供 1,136 个来自 66 个仓库、覆盖八种语言的 issue 任务及人工标注的目标上下文，适合生成并评价逐步探索前缀（Li et al. 2026）。SWE-Explore 提供 848 个来自 203 个仓库、覆盖十种语言的任务，还记录行级核心证据、可选证据及其被读取的步骤，适合检验停止规则能否迁移到不同轨迹来源（Zhang et al. 2026）。SWE-rebench V2 则提供 32,079 个可执行任务、预构建环境和测试套件，可从中预先固定一个分层样本，检查节省初始探索是否最终损害补丁正确性（Badertdinov et al. 2026）。三个资源分别承担前缀学习、跨来源迁移和代码后果验证，因而不会把同一批自动生成标签同时充当训练依据与最终成功证据。

本文不把减少检索次数本身视为成功。只有当 PVS 相对不加控制的基础 Agent、固定预算和单一认知线索减少证据获取成本，同时使上下文质量与任务解决率保持在预先规定的非劣界限内，停止主张才获得支持。EET 及其与 PVS 的组合将另外进入端到端成本对照，用来检验发生在不同阶段的两类停止能否互补。若序列模型不能优于使用同一即时特征的简单分类器，动态建模主张也应被否定。在这些检验通过的条件下，本文将说明描述性停止线索如何被转化为面向人工 Agent、由外部任务结果校准的序贯设计原则，也将为 Coding Agent 提供一个不改写基础检索策略即可挂接的停止控制器。在三篇研究构成的系列中，论文一决定已检索证据怎样组成可行动上下文，论文二决定任务开始时启用哪些检索服务，本文则决定这些服务驱动的初始探索何时结束。三篇论文共同管理 Coding Agent 的检索供给，但分别控制上下文打包、检索组合和探索终止三个不重叠的决策。

## 2 理论背景与研究缺口

### 2.1 Coding Agent 的迭代仓库探索

仓库级 issue 解决要求 Agent 在修改前把自然语言症状定位到具体代码。不同系统以不同方式完成这一转换。Agentless 采用仓库、文件和符号的分级定位，AutoCodeRover 利用抽象语法树与程序结构反复取得候选位置附近的代码，SWE-agent 则让模型经由专用接口自行搜索、查看、编辑和执行程序（Xia et al. 2025, Zhang et al. 2024, Yang et al. 2024）。这些系统的自治程度不同，但它们都需要把有限的仓库证据交给后续修改。对于交互式 Agent，每次工具返回还会改变下一步可发现的对象，因而最终上下文不是一次排序的静态结果，而是连续行动积累出来的证据前缀。停止器必须保留这种顺序，否则它无法区分“较早发现关键测试”和“在大量重复读取后才碰到同一测试”。

仓库检索研究主要改进这条证据序列中的内容。RepoGraph 将定义与引用等关系组织为代码图，为基础系统提供结构导航，Repoformer 则在代码补全场景中避免一次不必要的检索（Wu et al. 2024, Ouyang et al. 2025）。与之互补，ContextBench 可以在文件、符号、代码区间和编辑位置等粒度评价 Agent 实际查看的上下文，SWE-Explore 可以按行级核心证据评价覆盖、噪声和排序效率（Li et al. 2026, Zhang et al. 2026）。前一类工作改善可取得的证据，后一类工作使前缀质量能够被外部测量。不过，优质检索器在证据趋于饱和后仍可能返回重复内容，固定预算下的评价指标也不会自行产生逐步停止动作。本文利用这些检索方法与评价资源，但把研究单位由完整检索结果改为每一次可停止的证据前缀。

### 2.2 信息搜索的停止规则与信息价值

规范性信息搜索把停止写成价值与成本的比较：搜索者应当继续取得信息，直到额外信息的预期价值不再超过获取成本，同时还要考虑过早停止造成的预期损失（Browne et al. 2007）。信息系统设计能够改变这一比较，因为检索组织方式会改变取得决策所需信息的成本（Mookerjee and Mannino 1997）。不过，信息的价值不能只由检索相关性定义。决策中心的信息获取研究主张，应按新信息能否改善后续行动结果来评价获取决策（Saar-Tsechansky and Provost 2007）。在仓库探索中，目标代码区间的覆盖与噪声可作为修改前的可重复中间结果，补丁测试则检验这一中间结果是否真正转化为正确行动。本文因此用外部标注的上下文质量衡量当前证据收益，并在独立的可执行任务上检验这种收益能否保持任务解决率。

Browne et al.（2007）进一步归纳了人们实际结束在线搜索时使用的五类认知规则。待满足事项规则检查预先形成的事项是否已经满足，差异阈值规则检查新信息是否仍有实质差异，表示稳定规则检查对问题的内部表示是否停止变化。信息量阈值规则在累计信息达到预设数量时停止，单一条件规则则只围绕一个关键条件搜索。该研究还发现，规则使用会随任务是否结构化以及搜索者采用分解式还是整体式表示而变化。Coding issue 也同时包含可分解的显式线索与需要逐步形成的整体故障解释，因此本文将事项满足、最新差异和表示稳定编码为连续前缀信号，并把固定信息量与单一条件规则保留为可被击败的简化基准。这一迁移借用的是停止判断所需的信息结构，而不是关于语言模型认知过程的心理假设。

“足够”而非“最多”的信息观也出现在 IS 决策研究中。Mullins and Sabherwal（2022）在信息系统支持的团队中发现，客观信息量与决策绩效呈受情境调节的倒 U 形关系。该结果说明新增信息可能先改善决策，随后因处理负担而降低绩效，但其因果机制建立在人类与团队的工作记忆之上。本文不把这种认知负荷机制移植到语言模型。它只提供一个需要在 Agent 情境中重新检验的边界命题：当证据收益逐渐饱和而调用成本继续增加时，完整探索路径未必是最佳停止点。PVS 将用可观察的前缀质量、成本与最终测试结果直接检验该命题，而不以人类过载作为代理解释。

### 2.3 研究缺口

上述研究之间缺少的不是另一种仓库检索器，而是把证据充分性线索转化为可执行停止动作的价值连接。Coding Agent 文献能够产生逐步证据，公开 benchmark 也能测量一个前缀覆盖了什么，但二者没有说明当前停止与沿既有路径继续之间哪一个更有价值。IS 文献提供待满足事项、信息差异、表示稳定以及边际价值—成本原则，却没有把这些概念操作化为人工 Agent 的序列状态。填补这一缺口需要解决两个相连的测量问题。第一，每个前缀的质量必须由独立于基础 Agent 自我判断的外部证据定义。第二，在不声称观察到所有替代查询结果的前提下，必须为既有路径上的继续动作构造可学习的价值标签。PVS 分别用公开目标上下文和固定路径后向归纳处理这两个问题，其结论也只适用于给定探索策略上的退出选择。

## 3 前缀价值停止方法

### 3.1 决策边界与问题定义

PVS 只控制首次代码编辑之前、会向上下文加入仓库内容的动作，包括目录查看、文本搜索、符号或图查询以及文件区间读取。运行命令与测试的输出可以进入可见历史，但不由 PVS 阻止，因为它们提供的是执行反馈而非仓库内容检索。每当基础 Agent 已提出下一项受控动作、工具尚未执行时，系统形成一个停止检查点。若选择继续，该动作正常执行，返回内容并入新的证据前缀。若选择停止，系统拒绝更多首次编辑前的受控动作，并向基础 Agent 发出使用当前证据开始修改的指令。首次编辑完成后，全部工具权限恢复，Agent 可以依据测试失败继续查找代码。后续查找不属于 PVS 的决策范围，但会被记录为补偿性搜索，用来检验过早停止是否只是把成本推迟到编辑之后。

对任务 \(k\)，固定基础 Agent、模型、提示词和工具配置所形成的探索策略记为 \(\pi_b\)。该策略在首次编辑前产生 \(H_k\) 次受控动作及返回，轨迹写为 \(\tau_k=(x_k,a_{k1},o_{k1},\ldots,a_{kH_k},o_{kH_k})\)，其中 \(x_k\) 是 issue 与仓库元数据。执行第 \(i+1\) 次受控动作之前的可见状态为 \(s_{ki}=(x_k,h_{ki})\)，\(h_{ki}\) 包含此前全部模型消息、工具动作、代码返回和执行反馈。PVS 的实际输入是检查点 \(d_{ki}=(s_{ki},a_{k,i+1})\)，因为下一动作的类型与查询内容在工具执行前已经可见。索引 \(i\) 从 0 到 \(H_k-1\)，所以模型既能在尚未取得任何仓库证据时允许第一次检索，也能在任一后续返回后结束探索。目标上下文 \(g_k\) 只用于离线构造标签和评价，不进入运行时状态。

### 3.2 固定路径上的前缀价值标签

令 \(R_{ki}\) 表示状态 \(s_{ki}\) 中已经向 Agent 展示过的去重代码区间集合。前缀证据质量 \(q_{ki}\in[0,1]\) 使用相应 benchmark 的外部目标上下文计算，ContextBench 采用代码区间 F1，SWE-Explore 采用行级 F1，并按其官方规则处理可选证据。主分析把累计返回的仓库内容 token 数 \(T_{ki}\) 作为 PVS 直接控制的获取成本，令 \(c_{ki}=\min(T_{ki}/B,1)\)，其中基础 Agent 的预注册初始探索上限 \(B=32{,}000\)。当前停止的前缀效用定义为

\[
u_{ki}(\lambda)=q_{ki}-\lambda c_{ki}, \qquad \lambda\ge 0.
\]

这个式子不把更多代码本身当作收益。只有新增区间提高了相对外部目标上下文的精确率或召回率，质量项才会改善，而重复或无关内容只会增加成本项。token 成本便于跨模型与工具复现，工具调用数、墙钟时间和按实际价格折算的费用将在稳健性分析中替换 \(c_{ki}\)，用来检验结论是否依赖单一成本口径。

完整记录轨迹后，本文从最后一个证据前缀向前计算固定路径上的最佳停止效用。令 \(V_{kH_k}=u_{kH_k}\)，对 \(i=H_k-1,\ldots,0\) 递推

\[
V_{ki}=\max\{u_{ki},V_{k,i+1}\}, \qquad
\Delta_{ki}=V_{k,i+1}-u_{ki}.
\]

\(V_{ki}\) 表示从当前前缀开始、只能沿已记录动作继续时所能取得的最高效用，\(\Delta_{ki}\) 则表示放弃立即停止并至少执行下一项检索的净增量价值。由于 \(V_{k,i+1}\) 已经使用执行下一动作后的累计成本，它同时计入下一次获取及可能继续到更晚前缀的代价。训练目标是回归 \(\Delta_{ki}\)，其符号给出固定路径 oracle 的继续或停止标签。该标签只需重放日志并评价各前缀，不需要为每个前缀重新生成补丁。它也不估计未被 \(\pi_b\) 选择的查询结果，因此不能支持“全局最优检索策略”这一更强结论。

标签构造使用轨迹解析器恢复每次工具调用实际展示的文件与行区间，再按仓库的固定提交逐前缀调用官方评价器。ContextBench 的人工目标上下文是主训练与主检验依据。SWE-Explore 的目标上下文来自成功修复轨迹，因此在迁移实验中要用其公开构建脚本重新聚合标签，并排除当前受评 Agent 家族贡献的轨迹。排除后不足三条独立成功轨迹的任务不进入该项分析，防止同一探索路径既定义 gold 又被 gold 评价。主结果预注册 \(\lambda=0.1\)，并在 \(\{0,0.01,0.02,0.05,0.1,0.2,0.5,1\}\) 上报告完整质量—成本前沿。这样，停止偏好在测试结果出现前即已固定，其他 \(\lambda\) 只说明结论对价值权衡的敏感度。

### 3.3 可观测的前缀状态

PVS 首先表示任务结构与待满足事项。静态任务特征包括 issue 长度、编程语言、仓库规模，以及 issue 中显式文件路径、符号名、失败测试、堆栈帧、复现步骤和预期行为的数量。系统在探索开始前用正则规则提取路径、符号和测试锚点，再用冻结的 Qwen2.5-Coder-7B-Instruct（Hui et al. 2024）以贪心解码和固定 JSON schema 将其整理成定位、行为、接口与验证四类证据事项。每个输出锚点必须能在 issue 中逐字回查，否则即被丢弃，模型不能补充新的代码事实。每次返回后，系统根据已展示路径、符号和测试名称与事项锚点的匹配，更新已满足事项比例、尚未满足类别数及最近一次满足发生的距离。该表示把 Browne et al.（2007）的待满足事项规则变成可审计状态，同时保留任务是否提供明确分解线索这一条件。

PVS 随后描述最新信息差异与问题表示变化。最新增量特征包括本次返回新增的文件、代码行、符号和事项数量，返回内容与既有证据的 token 重复率，以及当前查询与此前查询在路径和标识符上的重合度。表示稳定特征来自一张固定 schema 的问题状态卡，字段只包含候选修改文件与符号、故障解释、接口约束和待运行测试。同一冻结模型在每次取得新代码后依据当前可见前缀更新状态卡，每个条目必须附带已展示的文件与行号证据，否则由程序丢弃。系统以相邻两张卡片的字段集合变化率和故障解释的词项变化率衡量表示是否趋稳，未新增代码的检查点直接复用上一张卡片。原始状态卡、证据指针与差异值全部缓存，使人工抽检和重复计算可以定位到同一前缀。最新增量与表示稳定只是对继续价值的不同观测角度，不分别触发停止。

最后一组输入描述资源状态与已提出的下一动作。资源特征包括累计仓库 token、受控动作数、模型调用数、已用墙钟时间及其相对上限的比例。动作特征包括工具类型、查询长度、是否含 issue 锚点、与既往查询的最大重合度，以及由递归标志、通配符和目标路径深度刻画的查询范围。所有连续变量只用训练仓库的统计量标准化，缺失值以单独标志表示。任务结构、三类停止线索、资源状态和动作特征在每个检查点合成一个事件向量。该向量不含目标上下文、后续返回、最终补丁或测试标签，部署时可以在工具执行前完整取得。

### 3.4 停止器的学习与决策

PVS 用单层 GRU 编码截至当前检查点的事件向量序列（Cho et al. 2014）。若第 \(i\) 个事件向量为 \(e_{ki}\)，则

\[
h_{ki}=\operatorname{GRU}(e_{ki},h_{k,i-1}), \qquad
\widehat{\Delta}_{ki}=w^{\top}h_{ki}+b.
\]

GRU 的作用不是重新表示代码文本，而是保留事项满足、最新增量和状态卡变化在多个检查点上的方向与持续时间。输出层只回归一个净增量价值。训练采用 Huber 损失，并先在任务内平均各前缀损失，再在任务间平均，避免长轨迹因检查点更多而获得过高权重。隐藏维度、dropout、学习率和早停轮次只在训练仓库内的验证折选择。每个 \(\lambda\) 独立训练同一结构，主模型只对应预注册的 \(\lambda=0.1\)。

部署决策采用 \(\widehat{\Delta}_{ki}>\theta\) 时继续、否则停止的单阈值规则。阈值 \(\theta\) 只在验证仓库上选择为满足两个约束时的最大值：所选前缀平均质量相对完整路径下降不超过 0.01，且选择点早于固定路径 oracle 的任务比例不超过 5%。若没有候选阈值同时满足约束，则关闭 PVS 而让基础 Agent 正常运行。若事项解析或状态卡生成失败，当前检查点也默认继续。无论做出何种选择，系统都记录输入特征、预测值、阈值、动作及恢复后的补偿性搜索。该规则把误停风险置于节省成本之前，也使每次停止可以被前缀级日志复核。

## 4 实证设计

### 4.1 研究场景与公开数据

主研究场景使用 ContextBench 的 1,136 个 issue、66 个仓库和八种编程语言。该数据为每项任务提供人工目标上下文，官方工具能够从 Agent 轨迹恢复文件查看与代码区间并计算多粒度指标（Li et al. 2026）。我们用官方 runner 配置 mini-SWE-agent，以 Qwen2.5-Coder-32B-Instruct、温度 0、默认提示词和统一工具集为每个任务生成一条不受 PVS 干预的完整轨迹，初始探索最多返回 32,000 个仓库 token。全部任务按仓库分入五个互斥折，同一仓库的任务不会跨越训练、验证和测试。每轮以三个折训练、一个折选择超参数和阈值、一个折测试，并轮换五次。所有前缀标签只由当轮训练与验证仓库生成，测试仓库的人工上下文仅在模型冻结后用于评价。

跨来源迁移使用 SWE-Explore 的 848 个 issue、203 个仓库和十种语言。其官方构建器能够从成功修复轨迹识别文件读取、shell 搜索与代码区间，并以至少三条轨迹聚合行级核心和可选上下文（Zhang et al. 2026）。对每个有公开逐步记录的 Agent 家族，我们先移除该家族轨迹，再重建其余家族形成的目标上下文，随后把 ContextBench 上训练并校准的 PVS 原样应用于被移除家族的探索前缀。该实验不更新特征标准化、模型权重或停止阈值。主要结果按 Agent 家族和编程语言分别报告，再在任务层汇总。若 PVS 只在 mini-SWE-agent 与 ContextBench gold 上有效，却不能迁移到不同轨迹来源，本文只能主张同策略截断，不能主张通用停止设计。

最终代码后果在 SWE-rebench V2 上在线检验。该公开资源含 32,079 个横跨 20 种语言和 3,617 个仓库的可执行任务，并提供预构建镜像与测试信息（Badertdinov et al. 2026）。在观察任何方法结果前，我们从能够成功启动镜像、复现基准测试且问题描述完整的任务中固定 500 项，按语言与官方难度元数据分层，并限制每个仓库最多五项。随后以相同 mini-SWE-agent、Qwen2.5-Coder-32B-Instruct 和解码设置运行基础 Agent、PVS、EET 与 EET+PVS 四种条件。EET 使用官方实现，其经验数据只来自这 500 项之外的开发任务。SWE-rebench V2 不提供供 PVS 使用的目标上下文，因此这项实验只把冻结的 PVS 当作在线控制器，以测试通过、总 token、调用数、墙钟时间、首次编辑时间和补偿性搜索评价真实后果。

### 4.2 对照方法

第一组对照检验是否需要任务适配与多信号估值。基础 Agent 保留其原始探索长度，固定量规则分别在第 2、4、8 或 12 次受控动作后停止，并由验证仓库选择一个统一值。待满足事项规则在所有可提取事项均被命中时停止，单一条件规则在 issue 首个显式路径、符号或测试被命中时停止。差异阈值规则在连续两次返回均未增加文件、符号或事项时停止，表示稳定规则在问题状态卡连续两次不变时停止。若某条规则的触发条件在预算内从未出现，它退回基础 Agent 的原始停止点。这样的对照直接检验 PVS 是否比 Browne et al.（2007）的单一规则及固定信息量更有效。

第二组对照检验序列学习和停止阶段。Ridge 回归与梯度提升树使用同一检查点的完整事件向量预测 \(\Delta_{ki}\)，但看不到此前事件序列。固定路径 oracle 使用真实 \(\Delta_{ki}\) 选择停止点，只作为不可部署上界。TASR 依赖开放域问答中的重复答案和答案 logit margin，Coding Agent 在首次编辑前没有同构答案变量，因此不直接移植其阈值，上一段的状态卡稳定规则作为可执行的近似比较（Kieback et al. 2026）。EET 不进入前缀 F1 比较，因为它不停止仓库读取，而是在 SWE-rebench V2 的端到端实验中与基础 Agent、PVS 和二者组合比较（Guo et al. 2026）。这一安排分别回答序列历史是否必要、PVS 距固定路径上限多远，以及探索停止能否与后续阶段停止互补。

### 4.3 测量、识别与统计检验

前缀实验的共同结果单位是方法所选停止点 \(\hat i_k\)。主要质量指标为该点的区间或行级 F1、召回率、精确率和加权核心覆盖，主要成本指标为累计仓库 token、受控动作数、模型调用数与墙钟时间。过早停止损失定义为 \(L_k^{pre}=\max_{j\ge \hat i_k}q_{kj}-q_{k\hat i_k}\)。再令 \(q_k^*=\max_i q_{ki}\)，并令 \(i_k^{\delta}\) 为最早达到 \(q_k^*-\delta\) 的前缀，取 \(\delta=0.01\)，过度搜索成本定义为 \(L_k^{over}=\max\{c_{k\hat i_k}-c_{k i_k^{\delta}},0\}\)。前者回答所选点之后还有多少外部证据质量未获得，后者回答达到近似最佳质量后又付出了多少成本。模型层另外报告 \(\Delta\) 的 MAE、符号判断准确率与按预测值分箱的校准误差，但不以这些指标替代真实停止点结果。

统计推断以仓库为聚类单位。本文先在每个仓库内计算任务均值，再用 10,000 次分层 bootstrap 对仓库和仓库内任务重抽样，报告成对差异及 95% 置信区间。主前缀主张必须同时满足两项条件：PVS 相对完整基础轨迹的平均 F1 非劣界限为 -0.01，且累计仓库 token 的差异上界低于 0。PVS 与固定预算、单规则以及序列无关学习器的比较使用仓库均值上的成对置换检验，并以 Holm（1979）方法校正多重比较。在线实验把任务解决率的非劣界限预注册为 -2 个百分点，同时要求总 token 或墙钟时间至少一项显著下降。任何质量非劣条件未通过时，成本下降只能被报告为效率—质量权衡，不能支持“无实质性能损失”的结论。

### 4.4 实施细节与可复现性

机制分析从只含静态任务、资源和下一动作特征的 GRU 开始，分别加入事项满足、最新差异和表示稳定，再与三者同时进入的完整 PVS 比较。另将完整事件序列随机打乱，或只保留当前事件，以检验性能是否来自真实时间次序。任务按是否含显式路径、符号、失败测试或复现步骤预先分为高结构与低结构两组，分别报告三类信号的移除损失。该分组只检验 Browne et al.（2007）关于任务条件的设计启发，不解释为人类认知机制在 Agent 中得到复制。敏感度分析改变 \(\lambda\)、初始 token 上限 \(B\in\{16{,}000,32{,}000,64{,}000\}\)、状态卡更新频率和冻结解析模型。最后随机抽取 100 项测试任务，并纳入所有 \(L_k^{pre}>0.05\) 的严重误停，逐项回看 issue、前缀、状态卡、预测值、后续关键证据与补偿性搜索，以辨认失败来自事项遗漏、表示假稳定还是成本判断错误。

复现实验发布固定的任务清单、仓库提交、容器镜像、五折划分、提示词、JSON schema、模型版本、解码参数、价格快照和随机种子。代码按轨迹导入、前缀重放、特征构造、后向标签、模型训练、在线拦截与统计分析七个命令组织，每一步输出带内容哈希的中间文件并支持断点续跑。状态卡只在新增代码后批量生成并缓存，所有方法共享同一缓存，避免把表示成本只计入 PVS 的某个实验条件。正式运行前先在跨五个仓库的 50 项任务上完成预演，要求轨迹解析器能够恢复至少 95% 的人工抽检受控动作，官方评价器能够复算前缀指标，全部镜像能够重复启动。未达到预演门槛时先修正解析与环境，而不开始模型比较。该流程把主要工作量限制在公开轨迹生成与容器执行上，不需要另建人工标注集。

## 5 预期贡献与边界条件

本文的核心主张取决于一组联合结果，而不是某一个预测分数。若 PVS 在未见仓库上减少返回 token，并同时通过前缀质量非劣与在线解决率非劣，它才说明初始仓库探索存在可学习的提前停止空间。若完整 PVS 进一步优于固定量、单一停止规则和序列无关学习器，结果才支持任务条件、多类充分性线索与历史次序需要共同进入继续价值估计。若优势只出现在 ContextBench 而不出现在留一 Agent 家族的 SWE-Explore，方法价值应限定于同一基础策略。若离线质量保持但在线解决率下降，则外部目标上下文不足以代表补丁所需信息，本文的标签设计而非阈值微调应被重新审视。

在上述证据成立时，本文对 IS 停止研究的贡献不是声称人工 Agent 使用了人类认知规则。它把 Browne et al.（2007）的待满足事项、差异阈值和表示稳定重新定位为数字行动者在某一时点可观测的充分性线索，并把它们置于统一的边际价值—成本判断之下。这个设计区分了“什么现象让停止看起来合理”与“继续一次是否实际值得”，从而连接描述性停止规则与规范性信息价值。它还以外部目标上下文评价信息获取，以可执行测试评价后续行动，扩展了决策中心信息获取从一次样本选择到多步数字探索的应用范围。Mullins and Sabherwal（2022）的“足够信息”关系在这里也被转写为可证伪的前缀命题，而不是未经检验的人类认知负荷类比。

对 Coding Agent 研究，PVS 提供的是一个阶段明确的控制器，而不是新的查询生成器。只要基础系统能在执行前暴露搜索或读取动作，并在执行后记录返回区间，词法、稠密、图结构或可学习检索器都可保持原样。PVS 与 EET 的区别也转化为可组合的系统接口：前者决定何时以当前证据开始首次编辑，后者减少补丁生成与选择中的无效迭代。对完整论文系列，TMRP 在任务开始时选择检索服务，PVS 在服务产生逐步证据时决定何时结束初始探索，DCCP 则在给定 token 预算内把取得的候选组成依赖完备的可行动上下文。三个 artifact 共享“信息收益必须抵偿取得与处理成本”的主线，但各自只改变来源组合、探索时长或上下文打包中的一个决策。

本文存在四项明确边界。第一，后向标签只在基础策略已经走过的路径上比较停止点，不能评价另一条未执行查询，也不能替代检索策略学习。第二，人工或轨迹聚合的目标上下文仍可能漏掉可行修复所需证据，所以必须把在线测试作为独立结果，而不能把前缀 F1 当成代码正确性。第三，事项与状态卡依赖冻结小模型，即使有原文锚点和代码指针仍会产生表示误差，因而需要确定性特征变体与人工抽检。第四，PVS 只决定首次编辑何时开始，不管理测试反馈后的再次搜索，也不终止补丁生成或选择。研究结论应相应限制为公开 issue-resolution 环境中、给定基础探索策略的初始仓库证据获取。

## 6 结论

本文把 Coding Agent 首次编辑前的仓库探索界定为一个可反复观察的停止决策，并提出 PVS 估计基础 Agent 下一次证据获取的净增量价值。PVS 将 IS 搜索研究中的事项满足、最新差异和表示稳定作为前缀信号，以外部上下文质量与 token 成本构造固定路径标签，再由轻量序列模型决定继续或开始编辑。ContextBench、SWE-Explore 与 SWE-rebench V2 分别使前缀学习、跨 Agent 迁移和代码后果检验可以在公开条件下完成。本文目前提供的是可执行且可证伪的研究设计。只有成本下降同时通过上下文质量与任务解决率的预注册非劣检验，PVS 才能被认为比固定轮数和单一停止规则更适合管理 Coding Agent 的初始仓库探索。
