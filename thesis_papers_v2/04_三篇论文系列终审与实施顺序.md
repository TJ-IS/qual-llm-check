# 三篇论文系列终审与实施顺序

> 终审结论：三篇设计可以构成同一博士论文系列，也都有公开 benchmark、数据或执行环境支持，但实施成本不相同。DCCP 最适合先做，TMRP 次之，PVS 最后做。这里的“可实现”指数据对象、算法输入输出、比较方法和评价程序已经能够明确落到代码，不表示实验结果已经获得。

## 1 三篇是否真的是三个研究问题

三篇共享的现象只有一个：Coding Agent 必须在有限计算与上下文条件下取得足以支持代码行动的仓库信息。它们没有把“检索”拆成三个名称，而是分别控制三个不同决策。

| 论文 | 决策时点 | 唯一控制变量 | 输出 | 主要外部结果 | 不能声称什么 |
|---|---|---|---|---|---|
| DCCP | 检索器已经给出候选、上下文尚未交给 Agent | 预算内保留哪些代码片段 | 一个依赖义务尽可能完备的上下文包 | 金上下文存留、固定 Agent 结果、补偿性搜索 | 不能声称改善了候选发现或选择了检索器 |
| TMRP | 任何服务结果尚不可见 | 本次任务调用哪个小型服务组合 | 一个检索服务集合 | 融合后金上下文、查询成本、固定 Agent 结果 | 不能声称动态调配查询或改进了底层检索算法 |
| PVS | 基础 Agent 已提出下一次仓库获取动作、工具尚未执行 | 执行下一动作还是开始首次编辑 | 继续或停止 | 所选前缀质量、取得成本、在线解决率 | 不能声称选择了下一查询、管理编辑后搜索或求得全局策略 |

运行时接口可以写成：

```text
任务到达
   │
   ├─ TMRP：先选本次启用的信息来源
   │
   ├─ 基础 Agent 与检索服务产生逐步证据
   │       └─ PVS：每个首次编辑前检查点决定是否还取下一份证据
   │
   └─ DCCP：在给定 token 预算内把已取得候选组成可行动上下文
           └─ Agent 编辑与测试
```

论文编号不是系统发生顺序。论文一先定义“什么样的信息集合才对行动有用”，论文二再研究应为任务启用哪些来源，论文三最后把静态供给扩展到多步探索何时终止。这种理论展开顺序与系统中的 TMRP—PVS—DCCP 顺序并不冲突。

## 2 公开资源是否足以开工

| 资源 | 已公开的关键对象 | 在系列中的角色 | 终审判断 |
|---|---|---|---|
| Agent Retrieval Bench | 427 项任务、冻结提交语料、345 项正检索金文件、82 项选择性检索样本、基线与预算指标 | DCCP 和 TMRP 的结构化主场地 | 能直接运行，但发布较新，必须先锁定数据清单、代码提交与校验和 |
| ContextBench | 1,136 项 issue、66 个仓库、人工金上下文、轨迹抽取器、统一 runner 与多粒度 evaluator | 三篇共同的 issue 场地 | 是当前最重要的共享基础设施，能够同时支持静态包、服务组合和探索前缀评价 |
| RepoBench / RepoBench-R | Python、Java 跨文件补全数据、预构造候选和官方指标 | DCCP、TMRP 的候选受限边界检查 | 成熟且便于跑，但不能替代真实全仓库定位证据 |
| SWE-Explore | 848 项 issue、203 个仓库、十种语言、成功轨迹聚合的行级核心与可选上下文、公开构建与评价代码 | PVS 的跨 Agent 来源迁移 | 可以运行，gold 来自成功轨迹，必须采用留一 Agent 家族重建，避免自我评价 |
| SWE-rebench V2 | 32,079 项任务、20 种语言、3,617 个仓库、预构建镜像、测试与运行代码 | PVS 的端到端代码后果 | 能运行且规模充足，真正瓶颈是算力、镜像和 Agent 运行时间，不是缺少数据 |

因此，“有 benchmark 但没有对应情境”这一风险目前已经排除。仍未排除的是工程和资源风险：仓库快照能否全部取得、容器能否稳定启动、轨迹解析能否恢复实际阅读区间、开放权重模型吞吐能否承担数千次 Agent 运行。这些必须通过预演而不是文字承诺解决。

## 3 现实实施顺序与停止门槛

### 第零步：只建一次的公共底座

先建立统一的任务清单、`repo—commit` 检出器、代码区间规范、token 计费、候选缓存、轨迹事件 schema、官方 evaluator 适配器和仓库级折分。每个产物用数据修订、代码提交与内容哈希寻址。共享底座可以减少重复工程，但每篇的标签、控制变量和结果表必须单独生成，不能让一篇的测试结果进入另一篇的训练或调参。

### 第一优先：DCCP

DCCP 的选择器是确定性次模打包，核心工作是候选规范化、程序关系索引和义务生成，不需要先训练大型策略模型。先在少量 ARB 与 ContextBench 任务上复算官方指标，再检查一跳定义、引用、调用、配置和测试关系能否被人工回查。只有官方指标能复现、候选池中确有互补证据、义务抽检显示关系理由可信，才扩大到完整静态实验。最后再做 100 项、三个种子的固定 Agent 下游实验。这个顺序能最早判断“程序义务”究竟是有效表示还是人为命名。

### 第二优先：TMRP

TMRP 复用底座，但需要为每项任务缓存四个检索服务的完整输出并重建所有小型组合。先固定 Lexical、BM25、稠密检索与 RepoMap 四项主目录，验证同一候选适配器、RRF 和打包器对所有组合公平，再构造 11 个行动的结果矩阵。只有不同任务或仓库条件下的最优组合确有可学习异质性，且 AutoFolio-combination 与 APPS 迁移都能稳定运行，才值得训练 TMRP。RepoBench-R 的 192,000 项适合用缓存做边界检验，不应在主场地尚未成立时先消耗大量计算。

### 第三优先：PVS

PVS 需要完整逐步轨迹、每个前缀的官方重放、状态卡缓存和在线拦截器，是三篇中工程和计算风险最高的一篇。先用 ContextBench 跨五个仓库的 50 项任务完成解析预演，再训练固定路径标签。随后用 SWE-Explore 做冻结迁移，最后才进入 SWE-rebench V2 在线试验。设计稿中的 500 项、四条件意味着至少 2,000 次长程 Agent 运行，尚未计入失败重试与 EET 经验构造。它在公开资源上可做，但是否按 500 项执行必须在不查看方法差异的基础设施预演后，根据单任务成本、镜像成功率和功效分析决定，并在正式预注册前冻结。算力不足时应调整样本设计，不能运行一部分以后再挑任务。

## 4 与 IS 文献的真实连接

三篇同 IS 对话的方式不是给代码算法贴理论标签，而是让 IS 构念改变决策对象、算法目标和允许的结果解释。

| 论文 | IS 对话 | 实际迁移到算法的内容 | 经验上必须验证的连接 |
|---|---|---|---|
| DCCP | 任务适用的信息质量、有成本信息取得、决策中心评价 | 信息价值成为“任务—已有集合—待执行修改”共同决定的边际义务覆盖，token 成为取得与处理成本 | 内部义务覆盖必须传导到外部金上下文和代码行动，不能以自定义目标自证 |
| TMRP | 任务—技术匹配、有成本信息取得、结果与过程后果 | 匹配对象从单项技术变为共享融合与预算约束的服务组合，标签使用融合后质量减实际成本 | 必须超过通用算法选择和并行组合选择的直接迁移，否则贡献只能写成场景应用 |
| PVS | 认知停止规则、边际信息价值、“足够信息” | 待满足事项、最新差异和表示稳定只作为可观察信号，共同预测下一次检索的净增量价值 | 不能把人类认知机制归因给模型，必须用外部前缀质量、成本和在线测试检验停止后果 |

肖帅勇两篇 ISR 最值得借鉴的也正是这种写法。ACAA 从既有测量失灵推出新概念，再把概念拆成可计算指标并嵌入专门机制，适合 DCCP 对“可行动上下文—义务—边际覆盖”的展开。DSDL 让理论构念保留差异后进入模型，并用预测、解释和实例分析共同回答业务问题，适合 PVS 对三类停止信号与统一价值的处理。TMRP 位于二者之间，既要像 ACAA 一样先改变匹配对象，又要像 DSDL 一样证明理论条件确实改善组合预测。三篇都不复制原文措辞，也不把原文的固定段式当模板。

## 5 跨篇复用与论文独立性的红线

ARB 与 ContextBench 可以被论文一和论文二共同使用，因为前者固定检索器、只替换候选打包，后者固定融合与打包、只替换服务组合。这种共享能控制 benchmark 差异，却不能被写成两个独立数据源的重复验证。若两篇使用相同任务，还应分别保存候选生成清单和外层测试结果，禁止用论文一的测试表现选择论文二的服务、特征或成本参数。

PVS 应以 ContextBench 前缀为主训练对象，以 SWE-Explore 的留一 Agent 家族和 SWE-rebench V2 的可执行任务提供真正不同的外部证据。它可以调用 TMRP 选出的服务或 DCCP 形成上下文作为附加系统组合，但主实验必须固定二者，不能把三个算法同时启用后的总体改进分摊成三篇各自贡献。

共同工程可以复用，核心识别不能复用。允许共享的是仓库检出、区间规范、tokenizer、关系索引、日志 schema、成本计量和容器管理。不允许共享的是测试折调参、gold 驱动的规则修改、事后样本排除和用另一篇的结果定义本篇标签。

## 6 写作终审

三篇正文均保持“一个现象、一个决策、一个算法、一个主张”的最小结构，没有把特征、信号或消融分别包装成研究内容。每篇另有逐段 ISR 对照记录，记录对应原段、逐句功能、句间接口和回读后的修改。第三篇又完成了作者—年份、参考文献、公式转义和禁用表达终审。全系列不报告虚构实验结果，贡献段均先写结果组合允许何种结论，失败时应把主张收缩到哪里。

最后的实施判断不是“三篇都已经完成”，而是“三篇都已经具备可编码、可比较、可证伪的研究协议”。最稳妥的开工点是公共数据底座与 DCCP 小样本预演。只有这一步真实跑通，后续 TMRP 与 PVS 才应进入全量计算。
