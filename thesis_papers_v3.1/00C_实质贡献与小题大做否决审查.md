# 实质贡献与“小题大做”否决审查

> **权威提示（2026-08-15）。** 本文件保留“小题大做”否决标准与历史审查证据，但不再定义现行题位或写作授权；后者仅以 `00F_现行题位与设计稿授权.md` 及当前 `01/02/03` 正文为准。现行三题依次为 EUMN（实际返回 → 来源约束 OT/F → 残余一次补取或 ACT-NOW → post-reacquisition F → U/Y）、OIWG（**DEMOTE / DESIGN-ONLY / NO-RUN**）与 AVEP（world likelihood → Bayes → $g_e^{FB}$ → distributional CQL）；下文旧候选、旧冻结规则和旧跨篇时序均仅作历史记录。

## 一、审查目的

本审查不判断模型是否复杂，而判断研究是否创造了足以支撑博士论文一章的新能力。简单输入或低维输出本身不是问题。ACAA 最终输出酒店销售预测，DSDL 最终输出客户响应概率，二者的输出都不复杂。它们仍能形成方法贡献，是因为理论揭示了既有方法系统性遗漏或反向处理的高价值中间机制，并使该机制成为可训练、可检查、可消融且能改善外部决策结果的算法对象。

因此，给一个普通路由器、集合选择器或停止分类器增加更多网络层、损失项和约束，不会自动增加实质贡献。若研究所控制的决策只影响极少任务，强基线留下的可恢复空间很小，或者理论部件只能改善内部指标而不能改变补丁与测试结果，则无论写作多精细，都应降格或终止。

## 二、从两篇肖文提炼的“成章”逻辑

### 2.1 ACAA 的论证链

ACAA 先把在线评论、购买意愿、销售预测和产品运营连成外部结果链，而不是从一种新注意力公式起笔。原文第 39 行说明评论可揭示未来销售，并把销售预测连接到运营和价值创造。第 41 行进一步指出，把全部评论无差别输入模型会产生系统性偏差，因为顾客在有限时间内只会实际感知其中一小部分，而既有模型又没有有效区分评论。第 45 至 47 行说明内容 helpfulness 不能稳定替代初始注意，关键缺口发生在 yielding 之前的 reception 阶段。第 49 至 55 行再把遗漏的信息处理阶段沿粒度分解为评论集、子集、单条评论和模态元素，并连接到 2,685 家酒店、约 120 万条文本评论、19.7 万张评论图像与月入住率。

真正使方法不可由普通 attention 直接替代的是方向冲突。第 87 行指出，常规 affinity compatibility 偏好相似键，而语义多样性要求强调互补且非冗余的键，二者会给出方向相反的权重。第 102 至 116 行逐项把时效、互补、投票和文本—图像权衡从理论关系变成方法要求。第 175 至 218 行又分别改写兼容函数、时间与投票权重以及模态融合。第 294 至 312 行不只报告最终预测，还检查中间权重是否表现出理论预期模式，再逐部件消融。由此，贡献不是“四个小技巧之和”，而是恢复一个既有方法缺失的信息处理阶段，并证明该阶段的内部表示与外部销售结果同时成立。

### 2.2 DSDL 的论证链

DSDL 同样先建立结果杠杆。原文第 35 至 41 行从实时商业互动、有限营销能力和庞大潜客市场的矛盾出发，说明及时预测会改变客户资源配置、邀请成功率和营销效率。第 43 行指出既有方法依赖丰富个人资料和量化特征，与新客户、无个人资料和多模态语音这一输入结构不相容。第 45 至 51 行没有把“满意度”作为普通输入特征，而是指出真正缺失的是偏好与动态期望、交错形成的体验、期望—体验失验，以及随对话累积的满意度状态。

第 83 至 99 行把这条潜在过程逐层转换成方法挑战。偏好模板承担无个人资料时的期望表示，cross-view attention 承担顾客—坐席交错体验，带方向的对比目标承担正负失验，属性和片段双向稀疏承担累积满意度的异质性。第 267 至 307 行分别比较理论满意度表示、深度表示及二者结合，并检查期望、体验、累积满意度及损失协同。动态满意度单独具有预测力，且与黑箱表示结合进一步提高结果，这才证明理论创造了一个可独立使用的中间状态，而非给分类器附加解释。

### 2.3 可迁移的八步纪律

1. 先确定外部行动或经营结果，说明结果为何重要以及当前资源约束为何使该决策具有杠杆。
2. 证明既有方法不是“还不够准”，而是在一个覆盖面可观的情境中系统性看不见、压缩掉或方向相反地处理关键结构。
3. 用理论识别一个原输入输出定义中不存在的中间状态、关系或决策对象。
4. 从理论对象逐项推出方法挑战，说明普通相似度、注意力、分类器或通用集合网络为何不能自然满足。
5. 让多个算法部件构成同一机制链，而不是把若干可能提高效果的技巧并列堆放。
6. 对中间状态本身进行可观察验证，并用等参数通用替代物和逐部件消融检验不可替代性。
7. 让外部行动结果、资源结果和中间机制结果共同成立，不以内部 recall、loss 或校准改善替代实际价值。
8. 明确数据适用条件和失效边界。写作只能准确呈现这条链，不能替没有 headroom 的问题制造贡献。

### 2.4 目标博士论文为何不是三个局部技巧

目标博士论文的系列逻辑也提供了一个反面约束。其总问题不是分别优化三个相邻的小参数，而是移动文娱平台如何在不同内容获取模式下同时影响用户内容使用、创作者内容生成以及平台的当前和未来活跃度。摘要第 23 至 31 行先建立双边平台可持续性这一总结果，再让内容获取模式机制成为后续决策模型的共同基础。点击模式研究同时决定推荐集合、页面和二维位置，并用异质性处理效应平衡用户与创作者；滑动模式研究还要决定动态内容序列并平衡当前与未来结果。两个模型的状态、目标和优化几何均发生实质变化，实验又把结果折算为参与者活跃度，而不是只报告预测误差。

这意味着本系列不能仅凭“候选前、候选后、交互中”三个时点就自动成立。若三个时点各自只控制很小的 token 或少数服务选择，流程完整也仍可能是三篇小题。系列需要一个足够大的共同结果，例如仓库信息基础设施投入、错误首次修复与返工、软件行动成功及每次解决成本，并要求每篇控制该结果中不同但可观的一类决策杠杆。决策时点区分只是防重叠条件，不是贡献规模证据。

## 三、实质贡献的量化审查框架

每篇先导实验至少估计五个量。它们不是通用发表阈值，而是本系列在大规模训练与写作以前使用的治理指标。

1. **机制可达率** \(\pi_{reach}\)。公开任务中有多少比例具备理论机制发挥作用所需的输入结构。
2. **决策触发率** \(\pi_{decision}\)。在控制候选、预算和骨干以后，有多少任务会因理论机制而改变实际选择或停止，而不只是改变一个内部分数。
3. **强基线后剩余空间** \(H_{base}\)。真实集合或行动 oracle 相对最强匹配基线还留下多少外部结果与成本空间。
4. **可学习回收率** \(r_{learn}\)。部署时可见特征能回收多少 oracle-regret gap。oracle 很强但不可预测，同样不能形成算法贡献。
5. **外部结果杠杆**。机制触发层的结果差 \(\delta_T\) 折算到全部任务以后，理论上限约为 \(\pi_{decision}\delta_T\)。复杂模型不能突破这个覆盖率上限。

若某机制只在 20% 的任务改变选择，即使触发层的绝对成功率提高 5 个百分点，总体上限也只有约 1 个百分点。若它只在这 20% 的任务节省 25% 输入 token，而成功率不变，总体 token 降幅上限也只有约 5%。因此，报告显著性而不报告机制覆盖率、触发层效应和全样本上限，会掩盖“小题大做”。

### 3.1 三级立项门

下列三级必须顺序通过，不得用同一个 `GO` 同时指称现象存在、模型可学习和论文成立。

1. **MECHANISM-PROCEED** 只判定机制是否可达、是否改变选择，以及在统一搜索与成本账下是否留有 oracle headroom。它不允许恢复论文写作。
2. **MODEL-PROCEED** 只判定部署时可见特征能否回收预注册比例的 oracle-regret gap，并在仓库隔离验证中优于等预算通用模型。它只允许进入外部 Agent 检验。
3. **CHAPTER-GO** 要求外部 patch/test、Pass@1、每 solve 成本或等价软件行动结果在未参与发现与调参的任务上达到预注册门，并报告不确定性、非劣界和全样本效应。未加限定的 `GO` 只能指这一级。

小样本筛查未观察到机制时，先判定其是有力否决还是统计上不确定。只有预注册规模具有足够否决能力时才能 KILL；否则标记 INCONCLUSIVE 或 DEMOTE，不得用低功效的否决门节省后续论证。

### 4.1 旧论文一 RFGP 的历史否决条件

论文一不能把“多文件任务很多”当作关系机制的覆盖率。只有当修复前候选池存在预算可容纳的关系路径、完整包相对删除、同仓库 sibling、文本保持重连和类型打乱均产生外部行动差，并且 path-aware pack 与真实 singleton-utility unary oracle 或 graph-aware 强基线发生选择翻转时，才算机制真正触发。

先导实验应分别报告可达率、扰动有效率、选择翻转率和最终联合触发率。若联合触发不足约 10%，只有二元配对有效而长度 3 至 4 的关系没有额外作用，或 graph-aware SetR、path-augmented RepoShapley 与等参数 hypergraph scorer 复制相同行为，则终止独立章节。联合触发约 10% 至 20%、仅一个关系家族或单一 Python 场地成立时，最多降格为机制子研究。只有联合触发达到约 20%，跨至少两类关系与两个场地，并相对最强 graph-aware 基线产生约 2 个绝对 solve-rate 点，或 solve-rate 非劣且 pass-per-token 提高约 10%，才恢复完整写作。

### 4.2 旧论文二 FIT-USE 的历史否决条件

论文二当前风险最高，因为它很可能只是把一个小动作空间包装成复杂集合政策。必须先回答：信息服务调用和装入究竟占 Agent 总成本多少，最佳服务是否随任务稳定变化，全调用劣于严格子集是否普遍，subset 或 quota 的外部 patch/test oracle gap 是否足够，以及 issue 与任务无关摘要能否预测该 gap。

建议在 100 项任务、每项 6 至 8 个配置、两个种子的 pilot 中直接否决下列情形：oracle 相对最佳固定策略的 patch/test 增益不足约 5 个百分点且等成功率总成本降低不足约 15%；跨仓库策略不能回收至少一半 oracle-regret gap；全调用劣于严格子集的任务不足约 20%或主要由基础设施失败造成；服务正互补和负冗余只零星出现；方向不足/过量与高高/低低均衡不产生普通 set router 方向相反的结果；PATCH_CONTEXT 与实际修改和测试依据缺乏一致性；完整服务家族留出不能迁移。

这些条件任一涉及核心主张失败时，不应把 FIT-USE 继续写成论文。特别是 A→R→U 的嵌套概率若只保证标签定义的逻辑顺序，却不提高真实补丁与成本结果，只是一个规范化测量头，而不是新算法能力。

截至 2026 年 8 月 14 日，冻结的 ARB 60 题官方基线已显示 top-20 并集相对逐题最佳单一方法仅 2/60 严格改善。因此，旧 FIT-USE/服务集合组合路线在本轮治理中记为 **NO-GO**。这项结果只检验旧式服务并集，不包含 query-only obligation、深度程序、语义细化类型或错误绑定拒绝，因而不是后来 refinement-proof formulation 的否决依据；官方 `gold_coverage@8k` 还是 legacy 8K character packing，也不得冒充 canonical token-budget BCY。

### 4.3 旧论文三 SA-VOI 的历史否决条件

论文三必须同时存在两种可干预错误：相当比例的任务会过早 HANDOFF，也有相当比例的任务会在没有正价值行动时继续搜索。只有一侧存在时，复杂的双专家与全候选证书很可能不如一个固定 handoff 或简单阈值。

约 80 项任务、400 条分支的 pilot 至少需要检验适用任务比例、base action 与候选 oracle 的分歧率、HANDOFF 最优和继续最优的双向占比、配对标签符号一致性、任务类型与专家优势交互以及固定 SuperScout handoff、ECLoop、普通 critic 和 CodeRescue 式成本路由。若适用比例不足约 30%，oracle 与 base 分歧不足约 20%，HANDOFF 优或继续优的任一方向不足约 10%，重复标签符号一致率低于约 0.70，双专家交互不成立，或收益不能进入 Pass@1 与每 solve 成本，则停止或降格。

## 五、写作中不得用来替代实质贡献的做法

- 不用更多公式、更多头、更多消融或更长方法名证明问题重要。
- 不用 Coding Agent 的总体重要性替代当前局部决策的实际杠杆。
- 不把“尚未有人把这些已有部件组合在一起”自动写成新能力。
- 不把内部 recall、路径完整度、逻辑一致性、置信区间收窄或 retained-use proxy 改善写成软件行动价值。
- 不用 theory-inspired 命名掩盖普通网络能产生相同行为的事实。
- 不因 benchmark 公开可运行就断言研究问题值得一章。公开环境只证明可检验，不证明有可恢复 headroom。
- 不预写提升，也不在 pilot 未完成时把条件性机制写成已被证实的系统性事实。

## 六、当前治理决定

三篇旧正文暂停在摘要和极少量引言，不再以既有蓝图直接扩写。RFGP、FIT-USE 与 SA-VOI 只作为历史否决样本保留。论文一的行动充分配方族与论文三的边际再取得—修复能力配置仍是 conditional candidates；论文二原定的 query-only refinement-proof 检索程序继续保持 formulation-level **NO-GO**，不得把旧 FIT-USE、Stage-0 或 generic provenance guard 自动恢复为候选。论文二现在只有一个可接受否决实验的剩余假说：**claim–hunk–test observed-interventional warrant closure**；红队已将其状态收紧为 **`DEMOTE / 仅保留80题机制KILL pilot / NO-RUN`**，不是 conditional GO，也不是获准写作的 primary chapter。

论文二先前完成的 Stage-0 反例检查仍保持原判，不因本次 NO-GO 而恢复。其当时冻结的 60 题 exact-identifier-lineage 输出平均 8,000-token canonical BCY 为 0.3583，gold 后验上界 0.3750，RepoMap 为 0.3806；三遍扫描约 4.43 GB，54/60 题虽返回三榜外文件，只有 6/60 题命中 gold。该 whole-token 代理仍是独立的 **NO-GO** 历史诊断，不能充当新的 P2 方案。

whole-token 诊断的开发报告仍见 `pilot_reports/arb60_exact_identifier_lineage_development_v0.md`。它没有执行 call/import/test/dependency 语义，也没有资格推进或否决后来提出的 refinement-proof formulation；后者的否决来自下面独立的 proof-feasibility 审计，不得混写成 Stage-0 效果结论。

随后进行的 query-only 资产审计又收窄了可执行边界。ARB 正 release 的 `kind=file` 文本在 8,000 字符处截断，Python `symbol` chunks 也来自跨语言正则切分、独立截断并删除首尾空白；它们不能无损恢复完整 Python 源码。因此只用发布 chunk 的 sparse AST 证据仍只能称局部工程诊断，不能用它通过任何立项门。

该 reserve 的 source blocker 已用逐 commit 完整 Git blobs 清除：16/16 个未见 snapshot、5 个仓库、24,668 条 snapshot×path rows 与 15,230/15,230 条 Python AST 均通过核验。机器在当时曾输出 legacy 状态字符串 `READY_FOR_SEMANTIC_INDEX_BUILD`，它现在只作为资产审计记录保留，不再构成任何构建授权；当前治理状态是 **`SOURCE_LOCK_VERIFIED_HISTORICAL_NO_AUTHORIZATION`**。机器报告 SHA256 仍为 `DE53103C2DB6D89D35C41BE00BB6D888BA73EFD3E317B7581761809EF2EAE337`，Markdown 报告 SHA256 仍为 `E1C087A4611A4AD272484049046952E4105AF9F363E4394CF5E030C927C6938C`。

随后用纯合成反例完成了 refinement-proof feasibility diagnostic。`semantic_ast_index.py` SHA256 为 `C281BB6A0EDC613DE64E50EE37F48CF81ABC9BF34E949FA90E5885C6D2FA19CF`，`test_semantic_ast_index.py` SHA256 为 `D907338C4A0074029C3B46C5D06344CE2699767EC8E6ED86AEBF8E6765FA4D49`，19/19 tests 通过。`globals()`/`vars()` 命名空间写入、`exec`、运行时 rebinding 与 monkeypatch 表明，proof-grade Python runtime identity 需要接近完整的动态语义分析；fail-closed 后，symbol identity 的 `CERTIFIED` 核只剩同模块、稳定顶层、simple-Name 关系，跨模块 symbol 候选必须标为 `DYNAMIC`，无法承载原定跨文件 relational-depth 机制。

若把主张收窄为 assumption-bound static lineage，通用 `provenance/equality guard` 在相同 entity ID 与 witness 上即可复制，理论不再创造独特可行域。因此 refinement-proof formulation 判为 **NO-GO**：正式 build 已叫停，约 3.46 GB 临时产物已删除；没有建立 SQLite、没有发布 index、没有运行 Click/ARB16、没有读取 gold、没有 scoring 或训练。该判断只否决这一 formulation，不宣称整个 P2 题位科学 KILL；剩余假说必须使用独立 benchmark、标签、工件和门，不继承 ARB readiness 或旧 program 输出。

剩余假说的部署输入必须是 gold-free 白名单：冻结 benchmark revision 下的自然语言 issue/Feature Request、base repository snapshot、正式部署轨允许看见的 FTP test 源码与其修复前失败输出，以及由这些输入确定性派生的仓库事实。RACE 外测的 Gold/Reference Patch、Test Patch 中未公开部分、Reference Reasoning、reference-derived changed-file/hunk 标签、隐藏 PTP、官方 evaluator 输出和任何由这些对象反推的字段都不得进入 claim、边标签、训练、推断或选择；它们只可在 80 题全部输出封存后进入评价，20 题 Reference Reasoning 也只能作封存后的 constructor 审计。claim constructor 输出 `claim_id/trigger/subject/expected_observable/polarity/scope/source_span/ftp_observability/UNRESOLVED`；无法从白名单得到的 claim 必须标为 `UNRESOLVED` 或 `UNOBSERVED`，不得用 gold 补齐。

RACE-Bench Lite 的 100 个 feature-addition 实例只承担两个相连但不混写的责任：先用按 SHA256 预分的 20 题做 `schema-slot` 低成本 offline screen，冻结预测后才解锁其 developer-accepted Reference Reasoning 检查 claim recall/overprediction；该 screen 不是第二个题目、不是模型贡献，也不能证明 warrant。余下 80 题才用于可执行的自然现象 pilot：agent 只见官方 Feature Request 与 FTP，PTP、Gold Patch、Reference Reasoning 和官方 resolved 结果隐藏至候选、claim、warrant score 与比较对全部封存以后。SWE-Gym 的不同责任是后续生成大规模候选/干预监督并在仓库隔离后训练一个本地非平凡 checkpoint；它不能用自己的 verifier 结果替代 RACE-Bench 的 hidden PTP/official evaluator 外测。

这里的 hunk rollback 只构成**冻结 patch、冻结测试与冻结执行环境下的观察性干预证据**。single-hunk rollback 不能证明 claim 级语义因果，也不能识别联合必要、可替代 hunk 或测试未覆盖行为。标签必须显式保留 `INDIVIDUAL_WITNESS|JOINT_ONLY|SUBSTITUTABLE|NON_IDENTIFIABLE|INFRA`，并让 hunk 数不超过 4 的候选接受完整 coalition/proper-subset 矩阵；generic single-hunk ablation 和读取相同 coalition matrix 的 multi-hunk indivisibility/delta baseline 都是强基线，不是本文机制。[IBugFinder](https://doi.org/10.1145/3660828) 已对 partial-patch powerset 进行枚举并总结八类 multi-hunk 关系，[TRIM](https://arxiv.org/abs/2607.18161) 已以 trajectory hierarchy 最小化 agent patch，并把 DD-Hunk 作为确定性基线；因此 rollback、ddmin、patch minimization 或“发现联合 hunk”均只能是标签生产与 prior-art 边界，不能写进贡献句。

这一假说是否“小题大做”由三道反包装门决定。第一，只能从预冻结普通生成器产生的自然 agent patches 学习稳定的 `SUPPORT|REFUTE|MISSING`；正边可来自自然成功候选，但计入门槛的负/拮抗边必须来自自然失败候选，`MISSING` 是未识别/无稳定效应，不是负例。若 signed triangle 在自然数据上没有可重复负/拮抗边，它就严格退化为 minimum-claim coverage；rewire/sign-shuffle 只能作破坏结构的消融，不能用来合成主现象。第二，在相同底模、输入、token、候选数和 forward-pass 预算下，test augmentation、通用 patch verifier、普通/多样化 beam、generic hunk ablation、multi-hunk indivisibility、minimum-claim coverage 与等参数通用图模型必须看见同样的原始证据。第三，只有 80 题冻结 KILL pilot 同时达到以下全部硬门才允许重新讨论升格：至少 `25/80` 题在同一 claim/test 下存在两个以上共同必要 hunk，而非多个独立 claim 的单 hunk 覆盖；至少 `20/80` 且横跨至少 4 个仓库存在跨重复运行稳定的正边与负/拮抗边。机制层 `W` 要求**同一个 claim/test 分量**同时具有 joint-necessary hunk 与自然 `SUPPORT+REFUTE/ANTAGONISTIC`，不能由同题不同 claim、test 或 candidate family 拼接，且至少 `16/80`、覆盖至少 4 个仓库；仓库 held-out `SUPPORT|REFUTE|MISSING` macro-F1 不低于 0.75；相对 generic coverage 和同参数图模型至少多 resolved `5/80` 且至少 4 个仓库方向一致，其中至少 3 个净新增解决必须在 PTP 解锁前封存的同分量 edge-neutralization 后失去 official resolved；至少 8 个新增正确 patch 不在任何 baseline completed-patch pool，其中至少 5 个的具体 hash 或对应选择必须被同分量 neutralization 消除。rewire 与 sign-shuffle 在 `W` 内各消掉至少一半增益；最强 posthoc verifier 仍不能把差距追到 2 题以内。即使全过，也只重新立项，不获得任何三级门。

这 80 题是有界否决筛查，不是确认性效果实验。只有至少 64/80 题完成预注册 candidate 与 intervention matrix、且覆盖至少 4 个仓库时才具备否决资格；否则记 `INCONCLUSIVE` 并维持 DEMOTE。升格判定把未完成单元保留在 80 的 ITT 分母且不计成功；KILL 判定则作相反方向的最坏情形敏感性：每个 `NON_IDENTIFIABLE/INFRA` 单元都先当作潜在 `W`、潜在自然负边和潜在理论方法优势。只有在这一最有利于理论的补全下，`W` 发生率的一侧 95% 精确上界仍低于预注册 20% 最小相关率，才可 KILL；“自然负边为零”只有全部 80 题均完成负边识别时才能单独触发 KILL。等价性 KILL 也必须在把未完成结果赋为最大理论优势后，generic coverage/graph 的配对仓库聚类 95% 区间仍完全落入 resolved 差异 `[-0.025,0.025]`，且不存在任何已观察或可能被缺失单元隐藏的基线池外新正确解。其余任一升格门未过只维持 DEMOTE，不得含糊写成“DEMOTE 或 KILL”。

论文一的前置审计也发现，“配方族相对逐题最佳单一配方”是不可实现的比较，因为逐题 oracle 已经取最大。现行门已改为依次区分冻结 first-restart one-MSC、后验 `family_oracle_ceiling` 与只用部署可见特征的学习策略；只有 MODEL-PROCEED 才能把后者的 gap 回收记为算法能力。8 题 micro 只产生 one-deletion-local candidates，正式配方必须在 24 题阶段补齐全部 proper subsets 才能称 inclusion-minimal。即便发现低重叠集合，若 family-level 监督不改变 held-out patcher 的选择与官方测试，论文一仍应 DEMOTE，因为 SWEzze 已经明确承认充分上下文不唯一。

论文三继续保持 **NO-RUN**。公开异质模型的聚合成功率不能拼成同一 handoff 上的 cheap/strong 四格，ARB 的固定最少读取轨迹也不能替代 SWE-Gym pre-edit repair 过程。取得合格逐行动轨迹以后，最多先做不调用模型的 checkpoint/one-more 兼容性普查；它只能判断某个冻结 policy 是否值得建设基础设施，不能报告 VOI、tier switch 或 repair uplift。四格方法本身仍可能只是一般成本敏感 router；只有共同 seed 的 tier-specific outcome/cost 增量、取得前后最优 tier 的 argmax crossing，以及相对 generic four-action router 的可学习增益同时成立，才保留理论专属性。

后续只有两条合法路径。第一，找到一个更大的自然问题，使理论创造新的中间状态或决策能力，并以公开 benchmark 的外部行动结果识别。第二，保留当前问题，但把上述机制覆盖、oracle headroom、可学习性和强基线对照分别放入 MECHANISM-PROCEED、MODEL-PROCEED 与 CHAPTER-GO。在任何一种路径中，肖文的段落逻辑只能用于准确呈现已经成立的因果链，不能用于把小技巧写成大贡献。
