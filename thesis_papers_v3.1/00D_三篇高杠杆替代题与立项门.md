## 一、当前决定

本文件不是三篇论文的新摘要，而是恢复写作以前必须通过的立项审查。v3 的 DCCP、TSMI 与 PVStop 证明了三个决策时点可以区分，却没有自动证明每个局部决策都具有足以支撑博士论文一章的结果杠杆。v3.1 最初提出的 RFGP、FIT-USE 与 SA-VOI 又分别面临被压缩为“图感知集合选择器”“服务集合路由器”和“成本敏感 critic 加停止阈值”的风险。因此，三篇现有正文继续冻结。论文一、三只有通过预注册三级门才可成为正式论文；论文二旧 refinement-proof formulation 已在正式 pilot 前因可实现性—独特性两难判为 NO-GO。其唯一剩余假说 claim–hunk–test observed-interventional warrant closure 经红队审查后只保留为 **DEMOTE/80题机制KILL pilot/NO-RUN**，不是 conditional GO。当前资产和执行禁令见 `00E_三项否决Pilot执行协议与本地资产台账.md`。

当前治理对象是：

1. 论文一改为**行动充分的上下文配方族学习**。它不再预测一条关系路径或一个片段分数，而是学习多个可替代的、经执行和完整一步删除矩阵确认的 one-minimal 充分证据集合。
2. 论文二原拟的**语义细化类型的信息义务检索程序编译**继续保持 formulation-level **NO-GO**；唯一允许新写 pilot 协议的假说是**自然 agent candidate patch 上的 claim–hunk–test 观察性干预 warrant 闭合**，其中负/拮抗边必须来自自然失败候选，但当前仅为 **DEMOTE/KILL pilot**，不得写论文二正文。
3. 论文三优先考察**自适应信息交付与修复能力配置**。它不再只预测继续或停止，而是联合决定是否再取得一次信息，以及当前证据应交给廉价修复器、强修复器还是弃权。

论文一、三仍只是 conditional candidates，不是已经成立的贡献。论文二旧 formulation 的 NO-GO 来自 proof feasibility audit；新假说又因 generic minimum-claim coverage、IBugFinder/TRIM 与 patch-verifier 退化威胁被预先 DEMOTE，只允许一次具有明确否决责任的 80 题冻结 pilot。论文三另保留“判别竞争修复方案的信息探索”作为互斥备选，但不得把两条路径合并成一个多模块控制器。

### 1.1 统一三级门

1. **MECHANISM-PROCEED** 要求机制在预注册总样本中可达、会改变实际选择，并在统一搜索和成本账下留有 oracle headroom。它只授权生成训练标签。
2. **MODEL-PROCEED** 要求本地训练模型仅使用部署时可见特征，在仓库隔离验证中回收预注册比例的 oracle-regret gap，并优于等预算通用强模型。它只授权外部 Agent 评价。
3. **CHAPTER-GO** 要求在未参与发现、标签生成和调参的公开任务上，patch/test、Pass@1、每 solve 成本或等价外部结果达到预注册门槛，并报告任务/仓库聚类不确定性和非劣界。未加限定的 `GO` 一律只指 CHAPTER-GO。

## 三、论文一：行动充分的上下文配方族

### 3.1 自然问题与系统性标签错误

给定任务 \(x\)、冻结候选池与冻结修复策略 \(p\)，配方族为 \(\mathcal M_{x,p}=\{S_1,\ldots,S_L\}\)。本轮预注册只接纳 \(|S|\leq5\) 的成员；其成员必须在预注册随机性准则下支持 \(p\) 产生通过官方测试的补丁，而且每个 proper subset 都已完成同一确认矩阵并被判为不充分。只检查一步删除得到的是 one-deletion local minimum，只能用于早期筛查，不能进入正式配方族。若 \(\{A,C\}\) 与 \(\{B,C\}\) 都在 \(\mathcal M_{x,p}\) 中，那么 \(A\) 与 \(B\) 是对当前修复策略的可替代证据；\(C\) 只能称为当前已穷尽候选空间中观察到的共同核，除非搜索覆盖证明支持更强的必需性。该对象不被定义为跨所有 repairer 的绝对充分性；对未见修复器的迁移另作外部可携性检验。

[SWEzze](https://arxiv.org/abs/2603.28119) 不仅用遗传搜索与分层 delta debugging 寻找一个 one-minimal sufficient context，其正文也已明确说明 sufficient contexts 通常不唯一。它随后取任一 one-MSC 作为逐片段压缩监督。因此，本研究不能声称首次发现非唯一充分上下文，也不能以“最小充分上下文”“可执行压缩”或“训练小压缩器”为贡献。待验证的窄边界只是：把已知的非唯一性操作化为 family-level 监督、共同核与替代组表示，是否在超过 multi-restart OCD 后验家族以后还能改善可部署选择和外部修复结果。

### 3.2 理论驱动的非显然实现

表征理论允许同一深层程序事实由不同表层证据组合忠实呈现；有效使用又要求充分性由后续行动而不是静态 qrel 决定。理论不会逻辑必然地推出某个具体 OR-of-AND 网络，因而 Hungarian 匹配、普通 multi-set decoder 和近似 DNF 都必须作为理论无关强替代物。理论真正约束的是：训练对象必须对同一事实的可替代表层实现保持 family-level 不变性，并同时区分跨配方共同核和只在集合级失败的近充分负例。

标签生成必须分成三个不重叠阶段。discovery 用冻结修复策略 \(p\) 的预注册 restart 和 discovery seeds 找候选集合；confirmation 用不重叠 seeds 对每个 \(S\) 及其全部一步删除集合完成完整 `required-patcher × seed` 矩阵，任何缺失单元都不能证明最小性；held-out patcher 只在家族冻结后检验迁移，不参与 \(\mathcal M_{x,p}\) 发现或阈值调整。模型一次输出若干集合假设与充分度，并用近充分失败集构造集合级 margin。部署时只能依据可见特征预先选一个配方；若允许顺序尝试多个配方，所有生成、测试、token 和墙钟成本均计入策略账，不得事后挑选成功配方充当可部署 oracle。

中间机制必须单独评价：oracle-family recall、替代证据组召回、共同必需核 F1、集合删除后的失败率、跨 seed 与跨修复器的配方迁移。外部结果必须是官方测试、resolve@1、pass-per-token 和有重复运行的稳定性。ContextBench 的 gold context 只能作为辅助表征效标，不能替代可执行充分性。

### 3.3 直接威胁与否决 pilot

SetR 已经研究训练式集合选择，RepoShapley 已经研究带符号的 coalition utility，[SWEzze](https://arxiv.org/abs/2603.28119) 已经研究非唯一的最小充分上下文，[RepoDistill](https://aclanthology.org/2026.findings-acl.217/) 已经研究细粒度预算分配。因此，强基线必须包括 one-MSC SWEzze、multi-restart OCD 产生的后验家族、计入全部尝试成本的 sequential fallback、graph-aware SetR、RepoShapley、CVaR/重复运行版本以及等参数通用 multi-set predictor。

第一阶段先做 `00E` 的 8-task micro-screen。它只用于验证 harness、标签完整性和 one-deletion-local 现象方向；少于两题出现低重叠局部候选时判为 **INCONCLUSIVE**，不得仅凭 8 题 KILL。24 题必须在首次运行前一次性盲抽并冻结，前 8 题只构成其中的 micro 子集，不能看到结果后另抽 16 题。进入 MECHANISM-PROCEED 时，每个计入配方族的候选必须补齐全部 proper subsets 的确认矩阵；约 25% 的任务应具有两个或以上 Jaccard 不高于 0.60 且不由重复片段造成的 inclusion-minimal 配方，并报告从任一冻结 one-MSC 监督产生的替代证据假负例率。对同题家族后验选择成功成员只能形成 `family_oracle_ceiling`；它相对预先冻结的 first-restart one-MSC 政策至少留下约 5 个百分点外部成功空间，才说明存在值得学习的上界，但不计部署收益。若采用顺序 fallback，则次序必须在结果前冻结并把每次生成、测试、token 和墙钟全部收费。MODEL-PROCEED 才要求仓库隔离的学习模型仅凭部署可见特征回收至少一半 `family_oracle_ceiling` 相对 first-restart one-MSC 的 regret gap，并优于等参数通用 multi-set predictor。CHAPTER-GO 才要求在未见的 30 至 50 个 SWE-bench Verified 任务和 held-out patcher 上，相对强 SWEzze/multi-restart 基线提高约 3 个绝对 resolve 点，或 resolve 在预注册非劣界内且再节省约 15% token，并给出任务/仓库聚类不确定性。若在具有否决能力的 24 题或后续样本中充分集合普遍高度重合、替代证据假负例不影响可学习策略、multi-restart OCD 与通用 multi-set predictor 已复制全部可部署收益，或收益不进入官方测试，才 KILL 该题。

## 四、论文二旧题复盘：refinement-proof formulation NO-GO

本节保留原设计是为了说明否决发生在哪里，不再构成活动候选或执行授权。source readiness、synthetic tests 和代码完整性都不能越过本节末的 formulation-level NO-GO；原定 ARB16/60 门已停用。

### 4.1 原拟自然问题与普通程序规划仍不够的原因

真实仓库任务可能要求 `failure frame → definition → callers → affected tests` 或 `anchored edit → dependents → regression tests`。调用 grep、图检索和测试检索这三个服务，并不等于它们以正确的输入—输出关系工作。尤其是前一步找到的符号身份必须在后续调用者与测试检索中保持；一个同类型但属于另一符号的结果会让普通工具类型检查通过，却不能满足当前任务的信息义务。

普通检索 program 已经非常拥挤。[REAPER](https://www.amazon.science/publications/reaper-reasoning-based-retrieval-planning-for-complex-rag-systems) 已面向异质索引与 API 生成多步 retrieval plan；[PROGRAM](https://aclanthology.org/2026.findings-acl.1090/) 已把多跳检索写成 logical、temporal、causal 等程序类型；[PyRAG](https://arxiv.org/abs/2605.12975) 已明确把 intended-entity drift 视为问题，并用显式中间变量、data dependency、Python 执行与 compiler-grounded runtime repair 实现 multi-hop RAG program synthesis；[Agent JIT](https://mast.stanford.edu/pubs/jit_planner/) 也已用 tool specifications、pre/postconditions 和 minimum-cost plan。因而“首次把检索写成 DAG”“首次使用变量保持数据流”“首次 typecheck 工具调用”或“首次用于代码”都不能成为主张。直接强基线必须包含 PyRAG-style 显式变量/dataflow 与 runtime repair；本题的窄边界只是执行前的仓库实体语义细化、义务闭合和错误绑定硬拒绝是否创造额外行动价值。

### 4.2 原拟理论驱动实现

TheoryOn 的算法先例表明，理论对象若具有有序层级和前一输出对后一任务的先决关系，工件应保留这一中间产品链，而不是把它们池化成一个标签。表征忠实又要求表层取得链保持深层实体与关系身份。两者结合后，类型系统必须从粗粒度 `Symbol → Callers` 升级为带实体变量的语义细化类型，例如 `Def<s>`、`Call<caller=c,callee=s>` 和 `Import<src=f,dst=g>`。类型变量统一确保后一算子消费的仍是同一任务实体；同类型但错误实体的 swap program 必须成为硬负例。算法杠杆只能来自方向明确、带 witness 的 direct call/import/ref edge；`AS_TEST` 只可对同一实体做 unary cast，`TESTS_FOR`、双向 import、隐式 transitive closure 或 task-to-relevant-test 魔法算子一律禁用。

模型输入只含部署时可见的 query 白名单、修复前仓库 schema 与 typed primitive catalog；reference PR/patch/diff、changed-file/result、gold/qrel/evidence 及由 reference change 或评价结果派生的 symbol/label 全部排除。query 明示文件可作 given anchor，却不算新取得 evidence。输出是静态 program DAG、mandatory-obligation discharge certificate，以及预算内无闭合程序时的 `UNSAT/ABSTAIN`；执行时只把上游绑定传给下游，不按返回质量重规划。gold 解锁前必须封存全部候选程序、逐程序输出/成本、selector features/scores 和唯一 `frozen_query_only_selected_*` 输出；gold scorer 此后只能读锁包。后验最佳程序只作 headroom 上界，不能进入效果/效率门或训练 selector。论文二只研究 operator/binding 层，不能再对候选 span 做 packing，以免与论文一重叠。

机制效标包括 mandatory-hole closure、实体绑定错误率、broken-prerequisite error、真实 relational depth 和义务到 retrieval lineage 的可核验证明。relational depth 只数跨实体/文件的 direct edge；root resolution、lexical lookup、AS_TEST/fixture proof、filter/render 都是 depth 0。所有系统必须看到同一 raw candidates、edge witness 与 `CERTIFIED|AMBIGUOUS|DYNAMIC` 状态，fan-out 也须在 system-specific filter 前按共同 raw ordering 截断。无效执行由独立、gold-blind 的 shared witness checker 判定，合法 zero-result 与系统自身 reject 不计入。外部效标是固定 packer/agent 下的 patch success、FAIL_TO_PASS、token、工具调用和墙钟；若 refinement 只改善形式正确率或 posthoc oracle，不改善冻结部署输出及外部结果，不得称为有效使用。

### 4.3 proof-feasibility 审计与 formulation-level NO-GO

旧 FIT-USE 与 Stage-0 whole-token 路线继续保持各自 NO-GO：前者的官方 top-20 并集只在 2/60 题严格改善，后者冻结输出 BCY 0.3583、gold 后验上界 0.3750，均不超过 RepoMap 0.3806。它们没有执行 refinement proof，不能冒充本次否决证据，也不得因新 formulation 失败而复活。

full-source reserve 的 16/16 snapshot 与 15,230/15,230 Python AST 均通过；机器当时输出的 legacy 状态字符串 `READY_FOR_SEMANTIC_INDEX_BUILD` 仅记录 source lock 已核验，已被当前 **`SOURCE_LOCK_VERIFIED_HISTORICAL_NO_AUTHORIZATION`** 状态取代。随后只在 synthetic counterexamples 上开发并冻结 `semantic_ast_index.py`（SHA256 `C281BB6A0EDC613DE64E50EE37F48CF81ABC9BF34E949FA90E5885C6D2FA19CF`）及其 tests（SHA256 `D907338C4A0074029C3B46C5D06344CE2699767EC8E6ED86AEBF8E6765FA4D49`）；compile、warnings-as-errors 与 19/19 tests 均通过。这证明 diagnostic 子集内部没有剩余 P0，不证明 Python runtime identity 可被静态 certification，也不授权正式 build 或 query-only validation。

关键反例是 `globals()`/`vars()` 命名空间写入、`exec`、运行时 rebinding 与 monkeypatch。若对这些机制 fail closed，symbol identity 的 `CERTIFIED` 核只容纳同模块、稳定顶层 function/async-function 的 simple-Name lexical binding；跨模块 symbol edge 全部只能是 `DYNAMIC`，无法形成原定跨文件 relational-depth proof。若放宽为 assumption-bound static lineage，其全部有效约束又可由取得相同 entity IDs、witness 和 status 的 generic provenance/equality guard 复制，理论不再创造独特可行域。

因此该 refinement-proof formulation 现判 **NO-GO**。正式 build 已叫停，约 3.46 GB 临时产物已删除；不建 SQLite、不发布 index、不运行 Click/ARB16、不读取 gold、不 scoring、不训练。原 `ORACLE-BUILD-PROCEED_16`、MECHANISM、MODEL 与 CHAPTER gates 均未开启，不得把“没有跑门”误记为效果失败或 K1/K2；它们对这一 formulation 已失效。下节新假说另立自然问题、工件与门，不能继承旧路线的 ARB readiness、program labels、代码或结果作为贡献证据。

## 五、论文二唯一剩余假说：claim–hunk–test observed-interventional warrant closure

### 5.1 当前身份、自然问题与直接占位工作

本节不是新论文摘要，而是一份 **DEMOTE/机制 KILL pilot**。自然问题是：Coding Agent 可能在 visible FTP、模型似然或静态 verifier 上偏好一个表面可接受的 patch，却没有用相互支持的修改覆盖 issue 的全部可观察行为主张，甚至某个 hunk 对另一主张或回归测试产生稳定拮抗。只有这种方向错误在自然 agent candidate patches 中频繁出现，负/拮抗边又确实来自自然失败候选，并且该状态改变生成而非只解释/rerank，才可能形成新 P2。手工 bypass、gold patch 删改或 synthetic sign 注入不得用于建立现象。

既有工作把可主张边界压得很窄。[IBugFinder](https://doi.org/10.1145/3660828) 已枚举 multi-hunk patch 的 partial-patch powerset、检测 divisible/indivisible bugs，并总结八类 hunk 关系；[TRIM](https://arxiv.org/abs/2607.18161) 已从 agent trajectory 做 sequence→file→edit 的反事实最小化，并以 DD-Hunk 为确定性基线。[MultiMend](https://arxiv.org/abs/2501.16044) 已训练多语言 multi-hunk patch generator，[MultiFixer](https://arxiv.org/abs/2607.26591) 又以 coordinator–proposer 组织多位置修复与 patch refinement。RACE-Bench 自身也用 file ablation 标注 necessary files。因此 rollback、powerset、ddmin、one-minimal patch、joint hunk、multi-hunk generation 或“测试证明某修改必要”都只能用于标签生成、强基线或 prior-art 边界，不能成为本文贡献。Otter/Issue2Test 式 test augmentation、SWE-Gym/static verifier、ComPass/APPT/LLM4PatchCorrect 式 APCA、SpecRover 式 intent/reviewer、普通/多样化 beam 与等参数图模型也必须进入边界；若最终只是给这些方法增加 claim 特征，维持 DEMOTE。

### 5.2 Gold-free claim、三类边与非因果边界

部署白名单只含冻结任务的 Feature Request/issue、base repository snapshot、该部署轨正式公开的 FTP test 源码与修复前失败输出，以及由它们确定性得到的静态仓库事实。RACE 外测的 Gold/Reference Patch、Reference Reasoning、Test Patch 中未公开部分、reference-derived changed-file/hunk 标签、隐藏 PTP、官方 evaluator 输出及其派生字段不得进入 claim、边标签、训练、推断或选择；80 题只能在全部输出封存后用它们评价，20 题 Reference Reasoning 也只能作封存后的 constructor 审计。claim constructor 输出 `claim_id, trigger, subject, expected_observable, polarity, scope, source_span, ftp_observability, unresolved_reason`；没有白名单根据时输出 `UNRESOLVED/UNOBSERVED`，不能从 gold 补写。

计算对象是有符号三元图。claim–test 边只表示冻结语义对齐器认为某个 visible FTP 观察该 claim；hunk/coalition–test 边来自 visible-FTP partial-patch matrix；hunk–claim 边由模型预测并受前两边监督。自然标签必须是互斥三类 `SUPPORT|REFUTE|MISSING`：加入某 hunk/coalition 使 claim-aligned visible FTP 稳定由 fail→pass 才是 `SUPPORT`，使它稳定 pass→fail 才是 `REFUTE/ANTAGONISTIC`，没有稳定可识别效应、测试未覆盖或干预不可识别一律是 `MISSING`，不得并入负类。隐藏 PTP 只判 official resolved，绝不生成边标签。另存 `INDIVIDUAL_WITNESS|JOINT_ONLY|SUBSTITUTABLE|NON_IDENTIFIABLE|INFRA`，避免 single-hunk 标签吞掉联合与替代关系。

这些边只是在冻结 patch/test/environment 下观察到的干预效应，不是 claim 级语义因果证明。特别是 single-hunk rollback 最多证明该 hunk 对该次执行的条件必要性；它不能排除另一实现、hunk 交互、偶然覆盖或测试缺口。若 signed triangle 缺少稳定自然 `REFUTE/ANTAGONISTIC`，结构平衡损失就退化为普通 minimum-claim coverage；但“自然负边为零”只有全部 80 题都完成负边识别时才能直接 KILL。不足 64/80 时记 INCONCLUSIVE；达到 64/80 但仍有未完成单元时，必须先把这些单元按可能含自然负边的最有利理论情形处理，保守界未触发本节末 KILL 条件就维持 DEMOTE。自然成功候选可提供 support，但只有自然失败候选中也出现跨重复执行稳定的 refute/antagonism，才允许把 signed structure 送入模型。

### 5.3 理论必须改变表示、标签、损失和搜索

表示从 candidate×test 二元矩阵改为 signed claim×hunk/coalition×test 图；标签保留三类边、联合必要与不可识别；损失在 patch NLL 之外同时包含三分类 edge loss、signed-triangle consistency、mandatory-claim hole penalty，以及“visible FTP 增加但留下 refute/unclosed claim”的自然硬负例 margin。等参数 baseline 包括把所有非 missing 边改成正边的 generic minimum-claim coverage、相同图与参数量但 sign-agnostic 的 GNN、直接三分类但无 triangle/closure 的 generic graph model，以及同证据的普通 patch verifier。

推断必须是 hunk-level constrained decoding，而不是生成后 rerank：同一本地训练 checkpoint 在每个完整 hunk 边界更新预测 warrant state，下一 hunk 优先处理最弱的 mandatory unclosed/refuted claim，terminal state 对 unresolved mandatory claim 收取硬约束或冻结大罚项。普通 beam、diverse beam、test-augmented beam 与理论 decoder 使用相同底模、输入、最大 output token、候选数、forward-pass/测试预算和停止条件；规范化 patch hash 去重。理论方法的新正确 patch 必须不在这些方法及所有强基线的 **completed-patch pool** 中。若只是从普通 beam 选得更好，DEMOTE 为 posthoc verifier；若扩大普通等预算搜索即可取得同一 patch，KILL 搜索贡献。

### 5.4 RACE-Bench Lite 20+80 与唯一升格门

[RACE-Bench](https://arxiv.org/abs/2603.26337) Lite 是官方 difficulty-aware 100 题子集。第一次读取任何 Reference Reasoning、Gold Patch、PTP 或 official result 前，用 `SHA256("p2-warrant-v1|"+benchmark_revision+"|"+instance_id)` 排序，前 20 题只作 constructor/schema、Docker、hunk atomizer 与运行账调试，后 80 题形成不可替换的冻结 ITT 分母。20 题可在输出封存后用 Reference Reasoning 检查 claim recall/overprediction，但其结果不得进入论文效应量；`schema-slot` 不构成第二个候选。80 题中 agent 只见官方 Feature Request 与 FTP，PTP/official evaluator 全程隐藏至 claim、自然 candidate pool、干预矩阵、模型与所有 baseline 输出封存以后。

[SWE-Gym](https://proceedings.mlr.press/v267/pan25g.html) 的责任不同：它提供 2,438 个真实可执行 Python tasks、轨迹和候选，用于在与 RACE 外测仓库隔离的 split 上生成三类边监督并**本地训练、保存和校验一个非平凡 checkpoint**。SWE-Gym verifier 不得替代 RACE hidden PTP/official evaluator，RACE Reference Reasoning 也不得成为部署输入。若无法形成仓库隔离、无污染的训练/外测分割，保持 NO-RUN；不得用同题 gold patch 微调后再称 gold-free。

只有冻结 80 题一次性同时通过以下全部条件，才允许把 DEMOTE 改回“可重新立项”；它是低于三级门的 pre-gate screen，不获得 MECHANISM-PROCEED、MODEL-PROCEED 或 CHAPTER-GO。定义 task-level 机制层 `W`：一题只有在**同一个 claim/test 分量**中同时出现第 1 项 joint-necessary hunk 与第 2 项自然 `SUPPORT+REFUTE/ANTAGONISTIC` 时才进入 `W`；同题不同 claim、test 或彼此无共享机制分量的 candidate family 不能拼成交集。

1. 至少 `25/80` 题在自然 candidate patches 上出现跨重复执行稳定、且针对**同一 claim/test** 的两个以上共同必要 hunk；多个独立 claim 各由一个 hunk 覆盖不计。hunk 数超过预注册可穷举上限或出现 infra failure 仍留在 80 的分母并记 `NON_IDENTIFIABLE/INFRA`。
2. 至少 `20/80` 且横跨至少 4 个仓库出现稳定 `SUPPORT` 与 `REFUTE/ANTAGONISTIC` 边；`MISSING` 不得填充该计数。只有达到本节末所定 64/80 完整单元的有效 pilot 才具有 KILL 资格；未完成单元在 KILL 敏感性中必须先按可能含自然负边处理。
3. `W` 至少 `16/80` 且覆盖至少 4 个仓库；否则不仅可能低于预注册 20% 最小相关率，前两项也可能来自无共同机制分量的任务或候选，不能归因于 signed joint warrant。
4. 在按仓库 held-out、阈值完全冻结的 80 题上，`SUPPORT|REFUTE|MISSING` 三分类 macro-F1 至少 0.75，并逐类报告 precision/recall、稳定性与不可识别率。
5. hidden PTP/official evaluator 的 resolved 相对最强 generic minimum-claim coverage 与同参数 generic graph model 至少增加 `5/80`，且至少 4 个仓库内效应方向一致；其中至少 3 个净新增解决必须是 outcome-level `W`-attributed：冻结 decoder trace 显示同一 `W` 分量的 signed edges 改变了 hunk 选择或 terminal closure，且 PTP 解锁前封存的同分量定向 edge-neutralization 在同预算下使该任务失去 official resolved。仅改变选择但仍得到另一正确 patch、任务随机拆分、仅按任务属于 `W` 或 visible FTP 增益均不计。
6. 至少 8 个新增 official-correct patch 的规范化 hash 不在任何 baseline completed-patch pool，其中至少 5 个满足 patch-level `W`-attribution：PTP 解锁前封存的同分量 neutralization 使该具体 hash 或其对应选择消失；这些解必须来自约束解码，不能来自 posthoc 拼接、gold-guided retry 或更大测试预算。此处允许 neutralization 后仍出现另一正确 patch，但它不能反过来计入第 5 项的净 resolved 归因。
7. 在保持节点、度数、边数、sign marginal、候选数与预算的前提下，within-task edge rewire 与 sign-shuffle 在 `W` 内各自至少消掉相对 strongest generic baseline 增益的一半；否则 triangle 结构没有被识别。
8. 最强 posthoc verifier 在同一可合法获得的 baseline completed-patch pool、同训练数据与同预算下，仍不能把 end-to-end resolved 差距追到 2 题以内；若差距只剩 0–2/80，DEMOTE 为 verifier/diagnostic，不成章。

这 80 题只是一项有界否决筛查。至少 64/80 题必须完成预注册 candidate 与 intervention matrix，且覆盖至少 4 个仓库；否则结论为 `INCONCLUSIVE` 并维持 DEMOTE。升格时未完成单元固定留在 80 的 ITT 分母且不算成功。KILL 时使用相反方向的保守补全：每个 `NON_IDENTIFIABLE/INFRA` 单元先同时当作潜在 `W`、潜在自然负边和潜在理论方法优势；据此给 `W` 发生率计算单侧 95% 精确上界，并对方法差异给出按仓库聚类的最坏情形配对区间。只有该上界仍低于预注册 20% 最小相关率才可因低发生率 KILL；“稳定自然负边为零”只有全部 80 题都完成负边识别时才能单独 KILL。generic coverage/graph 的等价性 KILL 也要求最坏情形区间完全落入 `[-0.025,0.025]`，且没有已观察或可能被缺失单元隐藏的基线池外新正确解。其他任一升格门失败只维持 **DEMOTE**。不得降低阈值、换 80 题、把 20 题并入分母或改用 synthetic patches 补数。当前工作区没有 RACE-Bench、Docker、generator、candidate pool、干预 runner 或本地训练 checkpoint，所以本节状态严格为 **NO-RUN**。

## 六、论文三：自适应信息交付与修复能力配置

### 6.1 自然问题与结果杠杆

论文三不再把 stop accuracy 当主要结果。现实决策是：当前 handoff 是否已经足以交给廉价修复器，是否值得让冻结 scout 再取得一次信息，是否必须交给强修复器，还是应当弃权。重要结果是给定 solve-rate 下的 cost-per-solve、强 repair tier 调用率、Pass@1、token、工具和墙钟。

[SuperScout](https://arxiv.org/abs/2608.04804) 已证明一次 repository scouting 与结构化 handoff 可以改变后续 fixer 的成本配置；其 no-router ablation 与 routed system 打平，配对校准又已显示 handoff 会提升较便宜 fixer 而可能损害最强 fixer。因而“信息使 cheap tier 首次可用”这一 repair-frontier redistribution 本身已不新。[Agent-as-a-Router](https://arxiv.org/abs/2606.22902) 已用执行反馈和 regret 组织 coding-task model routing，[Switchcraft](https://www.microsoft.com/en-us/research/publication/switchcraft-ai-model-router-for-agentic-tool-calling/) 已研究面向 agentic tool calling 的最低成本正确模型路由，[CodeRescue](https://arxiv.org/abs/2607.19338) 虽已撤稿，其公开摘要也已覆盖 post-failure recovery/escalation、监督 rollout router 与 conformal cost control。因此，本题的窄边界只能是：给定当前 handoff，冻结 scout **再取得一项**信息的 ex-ante 净价值是否改变最优 repair tier。“成本敏感路由”“scout 后再路由”“信息重分配修复能力”或“conformal 选预算”都不能单独成为贡献。

### 6.2 理论驱动的非显然实现

Mookerjee 与 Dos Santos 的系统价值逻辑把信息选择、停止和最终决策放在同一个目标中；Saar-Tsechansky 与 Provost 又要求信息价值由它是否改变后续行动而不是是否降低预测误差决定。先定义修复层的条件期望系统效用：

\[
Q_m(H)=\mathbb E\!\left[VY-\lambda C_{rep}\mid H,m\right],\qquad Q_{\mathrm{abstain}}(H)=0.
\]

对冻结 scout 产生的下一状态，信息价值是

\[
\operatorname{VOI}(H_t)=\mathbb E_{H_{t+1}\mid H_t,a_{scout}}\!\left[\max_{m\in\{cheap,strong,abstain\}} Q_m(H_{t+1})\right]-\max_{m\in\{cheap,strong,abstain\}}Q_m(H_t)-\lambda\mathbb E[C_{acq}\mid H_t,a_{scout}].
\]

`max` 的对象是两个以上共同 repair seeds 估计的条件期望效用，不是某一次 resolved/failed realization；否则会对四格结果事后取 max 并产生乐观偏差。\(C_{rep}\) 与 \(C_{acq}\) 都是在冻结 rate card 下换算到同一原始成本单位的标量，\(\lambda\) 对二者使用同一效用交换率；不得把已经乘过 \(\lambda\) 的取得成本再次送入公式或工具。成功价值 \(V\)、成本权重 \(\lambda\)、rate-card revision 与非劣界必须在看到四格结果前冻结，并同时报告 cost–Pass@1 Pareto frontier。理论改变算法的地方是取得前后分别比较最优期望修复配置，而不是把 stop 或 success 分数附加一个阈值。

scout policy、revision、seed、decoding 和 checkpoint rule 同样预先冻结，每题只产生一条可复现的 `H_t→H_{t+1}` 轨迹；在该确定性设计下，上式对下一状态的外层期望退化为观测到的冻结转移，而两次 `max_m` 仍必须作用于 repair-seed 的期望效用。不得多跑 scout 再选择最有利 observation。

因子实验在同一检查点构造 `current handoff × {cheap,strong}` 与 `one-more-frozen-scout × {cheap,strong}`，每格使用两个完全共同的 repair seeds，相同 snapshot、tools、prompt 与资源帽。abstain 是两个信息状态下都存在的确定性零效用外部选项，不启动 fixer process，但在两次 `max_m Q_m` 中均参与比较。repair-conditioned paired-uplift network 只预测结果差与成本差，并用 tier-switch 附近的边界加权排序损失；不再加入候选工具选择、双专家、JSD、Bellman 或 first-passage 头。动作固定为继续一次 scout、handoff cheap、handoff strong、abstain。中间机制只检查最优期望效用 tier 迁移率和 paired uplift 对 tier switch 的排序遗憾；外部报告 ITT Pass@1、每原始任务成本、cost-per-solve、强 tier 调用率与完整成本。

### 6.3 直接威胁、备选题与否决 pilot

强基线必须包括 fixed SuperScout handoff、SuperScout router/no-router、issue-only router、普通 partial-trajectory success/cost router、Agent-as-a-Router-style feedback router、Switchcraft-style agentic router、CodeRescue-style router、ECLoop 条件门和 Guided Search critic。约 80 个任务的 pilot 在一个预先由 SHA256 分配的 pre-edit 检查点上构造四格加确定性 abstain 实验。未到达检查点的 applicability failures 不补抽，在 intention-to-treat 分母 80 中记为未触发，并保留已消耗 scout 成本。MECHANISM-PROCEED 要求正 VOI 且最优期望效用 tier 改变的 ITT 状态约占全部 80 题的 20%，并报告 applicability、条件 tier-switch 与 ITT tier-switch 的任务/仓库聚类置信区间。这一门只判定 headroom。MODEL-PROCEED 要求在更大、仓库隔离的标签集上，paired-uplift 学习器至少回收一半 oracle-regret gap，并优于上述普通 trajectory/router 强基线。CHAPTER-GO 要求在独立任务上的 ITT Pass@1 达到预注册非劣界，其配对或仓库聚类 95% 置信区间不越过该界，同时 cost-per-solve、每原始任务成本或强 tier 调用率下降约 15%。cheap/strong 的可解集合嵌套不是 KILL 条件，因为信息仍可使 cheap 在成本加权意义下取代 strong。若冻结 policy 的 checkpoint/applicability 与所有适用任务四格状态未完整记录，则 80 题只记 INCONCLUSIVE；数据有效但点估计未达 16/80 则维持 DEMOTE，不在两种状态间结果后择词。KILL 只在具有预注册功效的后续样本触发以下任一路径：frontier-crossing 率的 95% 上界仍低于预注册最小相关率；固定 handoff/router 在效用与外部结果的等价界内复制全部收益；或降低 strong 使用时 Pass@1 的聚类置信区间越过冻结非劣界。不得因 nested solve sets 或单次 realized max 否决，也不得退回 SA-VOI。

若该题失败，唯一允许的互斥备选是“判别竞争修复方案的信息探索”。它先由冻结 planner 给出 top-2 结构化 repair intents，再只选择能改变两方案 regret gap 的只读信息。由于 [SHERLOC](https://arxiv.org/abs/2606.24820) 已经提供 hypothesis-driven structured diagnosis，并报告下游 resolve 和 token 改善，备选题只有在 top-2 repair intent 覆盖、候选可判别率及实际返工/Pass@1 均留下明显 headroom，且 Guided Search 式普通 critic 无法复制时才可立项。不得把该备选与 repair-tier 配置合并。

## 七、系列边界与共同结果

原设想的概念时序曾让论文二先编译实体绑定检索程序、论文一再选择行动充分配方、论文三最后配置 handoff 与修复能力层；旧论文二 formulation-level NO-GO 后，这不再是当前系列结构。论文一、三必须各自独立成立。新论文二假说仍是 DEMOTE/KILL pilot；只有 80 题全部硬门通过并另行重立项后才能重新进入系列，不能让已有两篇依赖一个未成立工件。

共同结果仍不能只是“上下文更好”，而应是**用更少的仓库信息取得与修复资源，稳定地产生通过测试的软件行动**。当前只有证据充分性的集合结构与信息交付—修复能力配置两个 conditional candidates；P2 只有一个被 DEMOTE 的可证伪假说，尚无获准机制。只有未来三题各自在独立 pilot 中证明影响比例可观、强基线后仍有 headroom，才可重建系列；三个时点的形式区分本身不计贡献。

## 八、恢复写作的硬规则

1. 不在 pilot 完成以前把“系统性错误”“多个配方”“实体绑定断裂”或“tier-switch”写成已经广泛存在的事实。
2. 每篇先报告机制可达率、决策触发率、强基线后 oracle headroom、可学习回收率和折算到全样本的外部结果上限。
3. 任何理论部件都必须对应一个中间对象、一个训练或推断约束、一个可证伪预测和一个等参数消融。只有命名或解释作用的理论不进入主贡献。
4. 每篇必须有一个理论无关的最强通用模型。若它产生相同选择、同样中间行为和外部结果，撤回“非该理论视角想不到”的主张。
