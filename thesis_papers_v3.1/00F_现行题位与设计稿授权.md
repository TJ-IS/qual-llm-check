# v3.1 现行题位、设计稿授权与经验声明边界

## 一、为何需要本文件

`00D_三篇高杠杆替代题与立项门.md` 和 `00E_三项否决Pilot执行协议与本地资产台账.md` 完整记录了 RFGP、FIT-USE、refinement-proof retrieval program、SA-VOI、充分配方族与 repair-tier router 的否决过程。它们继续作为历史治理证据，但不再定义 v3.1 三篇正文的现行题位。本文件自 2026 年 8 月 15 日起承担现行题位与写作授权；历史文件中的执行结果、NO-GO 与资源事实仍然有效，旧题位和“正文继续冻结”规则则由本文件取代。

原规则把“可以撰写完整研究设计”与“已经取得经验贡献”混为一谈，事实上阻断了用户要求的完整 v3.1。现改为两层责任。第一，**设计稿完成**要求自然问题、理论推导、训练数据、模型结构、损失、推断、基线、识别、算力和可证伪门槛完整落文，并逐段完成 ACAA 与 DSDL 双源回读；正文必须使用将来时或研究设计口径，不得编造样本、checkpoint 或结果。第二，**经验完成**仍须依次通过 MECHANISM-PROCEED、MODEL-PROCEED 与 CHAPTER-GO，并交付真实数据、权重、日志和外部结果。设计稿可以先写完，经验主张不能提前出现。

## 二、现行三篇

### 2.1 论文一：代码仓库表征的有效使用机制

论文一不再研究“行动充分上下文配方族”。SWEzze 已明确充分上下文可能不唯一，multi-restart 搜索、PU/soft-label、通用 multi-set predictor 或 DNF 足以复制从 one-MSC 到配方族的大部分技术变化；该题没有独立的深层事实标签，也没有像 ACAA 或 DSDL 那样能够被单独检验的理论中间状态，故撤销章节身份。

现行论文一采用 EUMN。自然问题是 Coding Agent 怎样把仓库工具返回转化为忠实任务表征，怎样用未被忠实覆盖的必要义务指导一次行动前补取，并进一步形成知情的软件行动。有效使用理论的透明取得、表征忠实度与知情行动不再只是解释变量，而分别形成参数分离且先训练后冻结的五维 T 栈、固定等权且不再归一化抵消的命题透明门、逐充分义务束的来源约束传输与 OR 式最小残余、一次补取或 ACT-NOW，以及补取后才形成的行动响应。核心工件是本地训练的 F/关系编码器、逐束最优传输、双有序忠实度头、残余驱动补取指针，以及输出有界行动序列、部署可见约束槽和受限证据引用的行动网络；共享冻结 executor 只接收共同任务/基础仓库状态和这份三元计划，不得另读 raw return 或条件上下文。终端头只承担诊断，不替代实际软件结果。确认性外部责任是未见仓库 family 与未见义务—来源组合上的固定取得预算软件结果和取得后成本；held-out agent/harness 只作预注册迁移副表，方向反转时限制外推而不充当主 PASS 门。

EUMN 只有在四个条件同时成立时才保留章节身份。第一，双层忠实度和证据特异行动响应对终端软件结果提供超过完整通用 veto pool 的独立增量；该池至少含 flat-history Transformer、等参数 raw-return cross-attention、direct-Y/semantic reacquisition policy 与 Context-as-a-Tool，development 只按预冻结唯一主 endpoint 选择最强 $M_0$，其余可忠实运行者仍各自保留独立否决权。第二，原证据、空返回和预算匹配无关返回产生理论预期的特异响应，而非一般文本刺激；全部透明门为零时 F/U 条件增量、证据引用与 executor 条件通路必须精确为零。第三，在同时留出的 repository family 与义务—来源组合上，残余相对最强 $M_0$ 更准确地选择一次有价值补取，并在无正价值时选择 ACT-NOW；按 eligible state 等权计算的方向冲突率 family-bootstrap 下界须至少为 20%，不能以候选对数量放大。第四，两个确认层的主外部结果下界都越过主测试前冻结的 SESOI、正确修复保持非劣，而且 residual-neutralization 与配对的 post-F/证据引用 neutralization **二者分别**消去至少一半完整增量。完整增量非正、任一有支持门失败或任何通用 veto baseline 落入等价区间都 `KILL`；预冻结组合支持不足只记 `INCONCLUSIVE` 且不得补抽。若模型只成为构念评分器或理论排序罕见改变选择，可保留的测量发现必须另行降格表述。

### 2.2 论文二：观察性干预 warrant 闭合的补丁生成

TSMI、FIT-USE 与 refinement-proof retrieval program 均保持 NO-GO。现行论文二只保留 signed claim–hunk–test generator 这一项有界候选。自然问题是：可见失败测试、模型似然和普通 verifier 会不会系统性偏好表面通过却没有以修改支持全部行为主张的补丁，以及带符号的 claim–hunk–test warrant 状态能否在生成过程中产生普通等预算 completed-patch pools 之外的新正确解。

理论对象来自 Toulmin 式 claim–evidence–warrant 和结构平衡操作化，但正文必须明确，hunk rollback 只是在冻结 patch、test 与环境下观察到的干预效应，不是语义因果证明。理论同时改变四处：标签区分 `SUPPORT`、`REFUTE` 与 `MISSING`，图表示保留 claim、hunk/coalition 与 test 三类节点，损失加入 signed-triangle consistency 和 mandatory-claim closure，推断在每个 hunk 边界优先处理最弱未闭合或被反驳的主张。核心工件是本地训练的代码生成 checkpoint、signed warrant graph encoder、edge heads、closure state recurrence 与 hunk-level constrained decoder。

该题仍处于 **DEMOTE / NO-RUN**。完整设计稿只是一份可执行、可否决的研究设计，不表示题目已经重新立项。`00D` 与 `00E` 中冻结的 RACE 20+80 pre-gate、自然负边、同分量 W、基线池外新解和 targeted neutralization 责任继续有效。若 pre-gate 不能同时证明 signed joint mechanism、仓库留出可学习性和外部 official resolved 增益，则论文二题位直接记为 NO-CANDIDATE，不再以新名称继续替换。

### 2.3 论文三：反馈驱动的运行时验证决策

论文三不再研究 one-more scout 与 cheap/strong repair-tier router。该问题是固定一步主动特征取得加成本敏感 uplift/router，Mookerjee、GOAL、SuperScout 和近期 agent router 已覆盖其规范结构与主要系统动作，继续增加神经网络深度不会扩大决策杠杆。

现行论文三采用 AVEP。自然问题是补丁产生以后，真实运行观测怎样形成忠实反馈、修正对终端诊断结果的判断，并改变下一实验、返回编辑、提交或人工转交的长期价值。理论对应三个专用计算对象：任务义务—差分—实验触达图上的诊断条件观测 likelihood，类别与当前任务/补丁状态发生交互的初始诊断 prior 及真实或假设结果后的规范化 Bayesian belief update，以及同时计入错误提交、漏选正确补丁、执行成本与尾部风险的序贯策略。每个候选实验在执行前还须把可能观测、posterior 义务差距与 Submit/ReturnToEdit/Handoff 的下尾行动差聚合为动作特异的反事实分支摘要；被截断结果以保持事件后验质量的规范 OtherBranch 合并，候选与分支分别受冻结的 $E_{\max}$、$O_{\max}$ 约束。核心工件是本地训练的 world checkpoint 与 policy checkpoint，而不是提示词、静态测试优先级或停止阈值。

AVEP 必须与同输入、同预算的 history Transformer、generic POMDP/world model、test prioritization、information-gain policy、direct-Q、mean-IQL/CQL、plain distributional CQL 和完整通用 agent controller 比较。若平面历史模型复制关系 likelihood 和 belief 修正，或普通控制器复制错误提交—成本前沿，理论部件撤回。只有方向冲突状态达到预注册覆盖、full AVEP 在 held-family 真实小分支中回收至少一半相对最强通用基线的 oracle-regret gap、分支摘要 neutralization 抹去至少一半增量，而且等墙钟在线结果同时满足软件结果门，才可保留章节身份；若 BCF、Agentic Rubrics、RETRACE、$T^3$/AReW 式控制或 flat POMDP 落入预注册等价区间，则杀掉独立算法贡献。

## 三、三篇为何不是同一系统切片

论文一的最高单位是任务—代理—证据区域—取得尝试，输出有效使用机制状态，并在首次实质编辑或验证前至多选择一次目标补取或 ACT-NOW；它不生成补丁。其计划中若含验证或提交，也只是首行动前一次性冻结、由共享 executor 落实的 open-loop 骨架，不读取补丁后真实观测再决策。论文二的单位是任务—候选补丁生成过程，输出新的 patch、abstain 和 warrant state，不加载论文一 checkpoint。论文三的单位是已持久化补丁快照—验证实验—真实观测转移；只有它在每项真实观测到达后重算下一实验、ReturnToEdit、Submit 或 Handoff，不生成任意补丁，也不加载前两篇 checkpoint。三篇只共享公开仓库任务、解析器接口和软件执行评价，训练表、标签、损失、权重和部署动作均独立。

## 四、写作与回读授权

三篇自本文件起获准完成**研究设计型正文**。每完成一个实质段，必须在对应 A 文件追加现行回读块，列出 ACAA 与 DSDL 的具体物理行、两篇原段逐句功能、当前段 S1 至 Sn、引用责任、理论—算法映射、强替代物和修改处理。直接复用 v6 已完成段落时仍须重新核对其现行科学责任；原回读记录只有在正文未实质改变且两篇源文定位仍真实时才可迁移。

摘要、引言和贡献段可以说明拟研究的问题、方法和评价，但不得使用“结果表明”“显著提高”“验证了”等完成式经验措辞。结果章节只能写预注册输出、统计责任和可能的证伪解释，不能填入虚构数字。设计稿完成后必须另做一次目标级审计，确认三篇全文、三条现行双 ISR 链、训练工件规格和引用责任均已落盘；真实 checkpoint 与结果仍属于后续经验完成责任。
