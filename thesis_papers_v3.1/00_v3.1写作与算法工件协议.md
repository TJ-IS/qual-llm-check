# v3.1 写作、理论驱动算法与逐段回读协议

## 一、版本定位

v3.1 继承 v3 已核实的研究情境、benchmark 边界、IS 文献责任和两篇 ISR 的论证结构，但不把 v3 的算法设计视为既定方案。三篇研究均可保留问题、重构问题或更换方法。判断标准不是改动幅度，而是最终研究是否形成一个需要本地数据处理与训练才能得到、能够独立保存和复用、并由公开任务检验的算法工件。

论文正文不讨论版本演化，也不以“比 v3 更复杂”作为贡献。版本差异只在本协议和最终交叉审计中记录。

## 二、算法工件硬门槛

每篇论文必须同时交付下列对象。

1. 一个具有本地可训练参数的核心模型。仅调用远程大模型、设计提示词、枚举少量规则、固定阈值、手工加权或把现成模型串成流水线，不构成核心算法工件。
2. 一个从公开仓库任务、代码快照、轨迹、金标准或可执行结果生成监督信号的确定性数据构造程序。模型推断、测试期标签构造和策略选择不得读取部署时不可见的信息。训练 split 的参考补丁或隐藏测试只有在责任明确、与外测仓库隔离且不进入测试期输入时才能生成监督；外测 split 的隐藏对象只可在所有输出封存后评价。
3. 一个由研究理论直接改变的模型结构、兼容函数、损失函数、约束或解码过程。理论不得只用于给普通特征命名，也不得只在贡献与解释部分出现。
4. 一套保存模型权重、特征变换、数据切分、随机种子、优化器状态、训练日志和推断配置的复现工件。完成下载以后，核心模型训练与推断应能在本地环境进行。
5. 一项脱离训练内部目标的外部评价。至少包含公开 benchmark 的原生指标，并在环境允许时包含固定 Coding Agent 的软件行动结果。

## 三、理论驱动实现门槛

每个核心理论机制必须形成以下闭环。

1. 理论命题明确指出什么信息、关系或过程会改变算法判断。
2. 方法挑战说明通用相似度、普通注意力、无约束神经网络或直接动作分类为什么不能自然表达该命题。
3. 算法部件把命题落实为可计算对象，例如有方向的缺口、关系闭合、非线性匹配、动态差异、阶段门控或价值分解。
4. 可证伪预测说明该部件在什么任务条件下应改变选择、排序、停止或预测。
5. 消融逐项移除或替换该部件，且评价其内部行为和外部任务结果。只比较完整模型与通用骨干不足以验证理论机制。

优先采用两篇 ISR 展示的设计逻辑。ACAA 不是把顾客注意作为普通特征输入，而是用及时性、语义多样性、投票意识与模态适应分别改写兼容函数和融合方式。DSDL 不是在预测以后解释满意度，而是把期望、体验与不确认分别表示，再用跨视角注意、对比目标与双向稀疏约束生成动态满意度。v3.1 的理论部件也必须进入表示、学习或推断的关键路径，使其不能被一句“加入理论特征”替代。

两篇 Xiao ISR 始终是逐段句法和论证推进的主模板。`00B_AIS_Basket理论驱动算法参照谱系.md` 中的其他 Basket 论文只承担算法设计参照：Mookerjee、GOAL 与 Hosanagar 展示理论如何改写选择、停止和最终行动，DLDE-MAB 展示理论如何进入硬约束与辅助损失，X-IM、G-FINDER、GDCM、TheoryOn 与 Schema 框架展示理论如何创造中间计算对象、表示几何和有序任务。引用这些论文不能免除每段对 ACAA 与 DSDL 的实际回读。

### 非该理论不可得性审查

每项核心算法部件还要通过一次反事实设计审查。审查者先在不知道目标理论的条件下，仅依据 benchmark 输入、输出与常见机器学习做法写出最自然的基线设计，再与理论方案逐项比较。若理论方案只是给通用相似度、普通注意力、MLP、阈值、正则项或多任务损失更换名称，则该部件不计为理论贡献。合格部件必须满足以下条件。

1. 理论引入了基线不会主动维护的内部对象，例如深层领域关系与表层片段之间的对应、任务需求与技术供给的有方向缺口、尚未满足的事项集合或最新证据的边际差异。
2. 理论改变了信息流或可行域，而不只是增加输入维度。例如完整关系见证才激活可带符号的高阶交互，供给不足与供给过量经过不同的单调分支，任务结构决定使用事项残差还是表征稳定作为状态，而停止必须检查全部候选行动的净价值上界。
3. 理论给出至少一个与通用模型不同的条件行为预测。论文必须预先指出在哪类任务、预算或状态下，两种模型会产生方向相反的选择，并以反事实样本或专门分层检验该预测。
4. 理论部件具有不可替代消融。除了删除部件，还要以最强的通用替代物进行等参数量替换，比较内部机制指标、外部 benchmark 指标和软件行动结果。若通用替代物产生相同行为和结果，则撤回“理论带来独特算法”的主张。
5. 一个理论命题最多只支持它实际推出的部件。工程上必要的编码器、缓存、解析器、索引和训练稳定技巧单列为工程设计，不能通过理论化措辞增加贡献数量。

## 四、非平凡性检查

每篇方法定稿前回答下列问题。

- 若把专属理论部件换成 MLP、普通 Transformer、余弦相似度或 top-k，研究还剩下什么实质算法差异。
- 模型是否学习了个体候选以外的关系、集合交互、方向性缺口或序贯反事实。
- 推断是否面对真实约束，例如 token 预算、服务成本、工具时序或风险上界，而不是只做离线分类。
- 训练标签是否来自足以区分候选、集合或动作作用的反事实或结构扰动，而不是把金标准位置直接复制为标签。
- 近期正式工作是否已经覆盖同一输入、同一动作、同一监督和同一输出。若已覆盖，必须收窄问题或更换算法，不用 IS 术语掩盖技术重合。

### 实质贡献否决门

非平凡算法不等于实质贡献。`00C_实质贡献与小题大做否决审查.md` 继续承担反包装审查，`00D_三篇高杠杆替代题与立项门.md` 和 `00E_三项否决Pilot执行协议与本地资产台账.md` 保留历史候选、否决证据、实际运行单元、数据表、成本账与本地缺口。自 2026 年 8 月 15 日起，现行题位和设计稿写作授权以 `00F_现行题位与设计稿授权.md` 为准。完整研究设计可以在经验三门以前写成，但必须使用拟议、将来和可证伪口径；任何结果、模型权重或机制成立主张仍须由真实运行证明，不能用公开网址或协议文字代替。

1. **MECHANISM-PROCEED** 只表示预注册现象存在：机制可达、会改变选择或停止，且在统一成本账下对最强机制基线留有空间。该判定只授权生成训练数据，不授权声称论文贡献。
2. **MODEL-PROCEED** 表示一个仅使用部署时可见特征的本地模型，能在仓库隔离的验证集上回收预注册比例的 oracle-regret gap，并优于等预算的理论无关强模型。该判定只授权进入外部 Agent 实验。
3. **CHAPTER-GO** 才表示立项：在未参与发现、标签生成或调参的公开任务上，外部 patch/test、Pass@1、每 solve 成本或等价软件行动结果达到预注册门槛，且对应不确定性和非劣界已报告。未加限定的 `GO` 一律只指 CHAPTER-GO。

任一级未达标可判为 INCONCLUSIVE、DEMOTE 或 KILL，但不得把小样本筛查的不确定结果自动写成 KILL。先导实验必须分别估计理论机制的可达率、实际改变选择或停止的触发率、最强匹配基线以后留下的外部结果空间、部署特征可回收的 oracle-regret 比例，以及该局部机制折算到全部任务后的结果与成本上限。

论文二的 warrant 假说当前低于 MECHANISM-PROCEED，属于一次特殊的 pre-gate KILL screen。由于它的核心主张就是 signed supervision 是否能改变生成，该筛查允许先在仓库隔离的 SWE-Gym training split 训练临时 checkpoint，再在冻结 RACE 80 上同时检查机制和 hidden official outcome；但全部通过也只把题目恢复为可重新立项，不计入 MECHANISM-PROCEED、MODEL-PROCEED 或 CHAPTER-GO。若恢复立项，三级门须以新的 discovery、training 与 confirmatory splits 重新预注册和执行，pre-gate 结果不得重复充当正式证据。

审查特别防止三种错误。第一，用更深网络和更多约束包装一个低杠杆的小动作空间。第二，只在极少数任务触发，却用触发层表现代表全部任务。第三，只改善 recall、内部效用、路径完整、逻辑次序或校准，而不改变补丁测试、成功成本或其他独立行动效标。若最强通用基线留下的可恢复空间不足，或者理论机制的全样本作用上限过小，即使方法技术上新颖，也应降格或终止。

两篇肖文的输出本身都是普通预测值，其方法贡献并非来自输出复杂，而来自恢复了既有方法系统性遗漏的高价值中间状态。v3.1 也必须证明新的理论对象具有可观覆盖、会产生方向相反的算法行为、能被中间机制检验，并最终传递到外部行动结果。段落写法不能替代这些证据。

## 五、benchmark 与数据门槛

1. 核心结论至少依托一个公开且具有稳定任务标识、仓库快照或可执行环境的 benchmark。
2. 每个 benchmark 只承担其实际发布的标签责任。文件、AST block、代码行、参考补丁、Agent 轨迹与官方测试不能互相代替。
3. 拟合、调优、校准和测试按规范仓库名隔离。跨资源重复按任务标识、提交、issue、参考补丁与测试变化审计。
4. 预训练或自监督使用的仓库必须记录并纳入隔离。不能以无标签为由把测试仓库加入表示预训练。
5. 数据规模必须支持模型复杂度。样本不足时减少参数、使用结构化自监督或撤回模型主张，不以更多层数制造复杂性。
6. 训练、标签生成和 Agent 评价分别给出 GPU、CPU、token、工具调用与容器小时上界。云端模型可作为受控外部比较，但不得是核心工件存在的必要条件。

## 六、三篇当前题位与组织原则

三个题位都涉及 Coding Agent 的仓库信息与软件行动，但当前不能预设它们已经形成一条完整系统链。每个题位必须有独立自然问题、独立算法工件和独立外部结果；缺失的一篇不能靠另外两篇的概念时序补足。

- 第一篇研究 Coding Agent 怎样把仓库工具返回转化为当前与累计两层忠实任务表征，怎样把未匹配的必要义务转成一次行动前目标补取或 ACT-NOW，并进一步形成证据特异的知情行动；核心工件是 EUMN 机制网络，它不构造静态上下文包，也不控制补丁后的序贯验证。
- 第二篇原定的语义细化类型检索程序继续保持 formulation-level NO-GO。唯一剩余假说研究自然 agent candidate patches 中是否存在非退化的 signed claim–hunk–test warrant，以及该状态能否进入 hunk-level constrained decoding 并产生普通 completed-patch pools 之外的新正确解。该假说仍为 `DEMOTE / 80题机制KILL pilot / NO-RUN`。
- 第三篇研究已生成补丁的真实运行观测怎样形成忠实反馈、修正终端诊断 belief，并改变下一实验、返修、提交或人工转交的长期风险调整价值；核心工件是 AVEP world checkpoint 与 policy checkpoint。

论文一与论文三获得 CONDITIONAL DESIGN-GO，论文二只获得 DEMOTE/DESIGN-ONLY；三者均没有经验 GO。旧“充分配方族”和“repair-tier router”已撤销章节身份，不能从历史 `00D` 恢复。任何题目仍只有通过 CHAPTER-GO 才能声称经验贡献；若 pilot 表明问题已被充分覆盖、机制退化或缺少外部杠杆，应当降格、替换或终止，不得为保持形式上的三篇或概念管线而降低门槛。

当前证据状态必须与题目状态分开记录：ARB 三类正任务、60 题 SHA256 盲抽和官方三-ranker baseline 已就绪，但 top-20 服务并集只在 2/60 题严格优于逐题最佳单方法，故旧 FIT-USE/服务组合题已经 NO-GO。后来取得的 ARB16 full-source reserve 只证明源码可读；synthetic feasibility audit 又表明 proof-grade Python runtime identity 与可被 generic provenance guard 复制的保守静态子集构成两难，因此 refinement-proof formulation 也已 NO-GO，禁止继续 build、评分或训练。新 warrant 假说不继承这些资产或结果，且当前没有本地 RACE-Bench、SWE-Gym、Docker、自然 agent patch 池或 checkpoint，故严格 NO-RUN。数据、readiness、协议和 baseline 均不得写成算法贡献或立项门通过。

## 七、逐段双 ISR 回读协议

每写完或实质改写一个正文段落，立即完成一次回读并写入对应 A 文件。

1. 在 ACAA 与 DSDL 中分别定位承担相同论文功能的原段，记录具体行号和章节位置。
2. 分别按 S1、S2 等编号说明两篇原段每句话或不可分句群的功能，包括建立情境、综合证据、揭示冲突、从理论推出挑战、从挑战推出部件、界定责任或说明评价。
3. 按当前正文真实句号重列新段 S1 至 Sn，并说明每句如何承接前句、为何位于本段、承担何种引用责任。
4. 检查理论句是否在后续方法段得到一一对应的结构、公式、损失或解码实现。若没有对应对象，删除理论句或补全算法。
5. 检查方法段是否能回溯到理论挑战。仅为提高效果而增加的技巧必须标为工程部件，不能伪装成理论贡献。
6. 每次修改后追加当前版回读。旧记录若保留，必须明确标为历史版本并指出被哪一条当前记录取代。

## 八、正文语言与引文

- 引言与综述保持接近 ACAA 和 DSDL 的证据密度。每个经验判断、现有方法能力和研究缺口均由核实过的原文承担。
- 优先引用 ISR、MISQ 等 AIS Basket 原文，以及 CCF-A 或同等级正式论文、官方 benchmark 与官方代码。预印本只在没有正式版本时使用并标明状态。
- 不把面向人的感知或心理构念直接赋予 Coding Agent。理论迁移对象是设计关系、信息结构、可观察状态或规范决策。
- 普通正文少用引号、冒号和分号，不用内部可行性话语、版本比较或资源充足声明组织论证。
- 不预写实验提升幅度。研究设计可以明确将检验什么、比较什么以及何种结果会限制结论。

## 九、最终验收

最终交叉审计至少逐篇核验以下项目。

| 验收对象 | 必须通过的证据 |
| --- | --- |
| 本地算法工件 | 权重、训练脚本责任、数据生成、推断接口与硬件预算均已定义 |
| 理论专属设计 | 至少两项理论命题进入模型关键路径，且有对应消融和机制指标 |
| 实质贡献规模 | MECHANISM-PROCEED、MODEL-PROCEED 与 CHAPTER-GO 的证据责任分开；机制覆盖、选择触发、强基线 headroom、可学习回收率与全样本外部结果上限均已报告，未通过者已降格或终止 |
| 技术新颖性 | 与最近直接工作按输入、监督、动作、输出和评价逐项比较，边界不依赖改名 |
| benchmark 闭环 | 训练、内部评价、外部迁移与 Agent 行动各自使用真实可得的标签或环境 |
| 系列不重复 | 三篇的决策时点、核心状态、动作和输出不同，理论共享不导致算法重复 |
| 双 ISR 写作 | 每个现行实质段均有 ACAA 与 DSDL 的具体原段、逐句功能和当前新段核对 |
| 机械质量 | 引文与书目闭合，公式定界、符号、标题、异常字符和禁用内部话语通过检查 |
