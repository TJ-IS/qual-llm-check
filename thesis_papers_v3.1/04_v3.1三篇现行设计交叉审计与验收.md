# v3.1 三篇现行设计交叉审计与验收

## 一、验收结论与声明边界

本轮验收确认的是三篇**研究设计稿及其理论—算法责任已经写全**，不确认任何经验贡献已经成立。当前工作区仍没有 EUMN、OIWG 或 AVEP 的真实训练 checkpoint，也没有可据以填写主结果表的冻结运行日志。正文中的模型、损失、推断、样本、资源和统计内容均为待执行设计；`DESIGN-GO` 不能替代 MECHANISM-PROCEED、MODEL-PROCEED 或 CHAPTER-GO。

| 题位 | 设计稿判定 | 章节身份 | 不能提前声称的内容 |
|---|---|---|---|
| 论文一 EUMN | DESIGN-COMPLETE | CONDITIONAL DESIGN-GO | 理论状态已经改善补取、真实计划或软件结果 |
| 论文二 OIWG | DESIGN-COMPLETE | DEMOTE / DESIGN-ONLY / NO-RUN | signed warrant 现象存在、模型可学或已产生新正确补丁 |
| 论文三 AVEP | DESIGN-COMPLETE | CONDITIONAL DESIGN-GO | world/belief 已校准、策略已减少错误提交或成本 |

这一判定有意保留不对称性。三篇设计都可以完整、严谨且可运行地落文，但不能为了形式上的三篇而把论文二从 DEMOTE 写成既定贡献；论文一和论文三也只有通过各自的强替代、机制干预与外部结果门以后才保留算法章节身份。

## 二、理论是否真正创造了算法能力

### 2.1 从重要结果到不可替代理论状态

| 论文 | 高价值外部结果 | 通用方法的系统性方向错误 | 理论创造的中间对象 | 直接改写算法的非显然机制 | 真实部署动作 |
|---|---|---|---|---|---|
| EUMN | 固定取得预算下的 resolved、regression-safe resolved 与 solve-per-cost | 把“内容已经返回”当成“任务已被忠实表示”，并让归一化、相似度或直接 Y 分数继续奖励不透明、重复或已覆盖证据 | 五维透明取得、逐充分义务束的增量/任务双 F、所选束残余、补取后 F/传输与三维 U | 独立冻结 T 栈的固定等权门缩减可运输质量且不再归一；逐束 OT/min 实现替代路径 OR；残余在补取与 ACT-NOW 间决策；补取后传输才生成有界行动、约束与证据引用 | 一次目标补取或 ACT-NOW，随后把三元计划交给无 raw-return 通道的共享冻结 executor |
| OIWG | hidden official tests 上的正确多 hunk 补丁 | 可见通过数、模型似然或完成后 verifier 会偏好 bypass patch，即使其 hunk 没有支持全部行为 claim，甚至反驳另一 claim | SUPPORT、REFUTE、MISSING 边，JOINT_ONLY/SUBSTITUTABLE coalition，以及 claim–hunk–test signed component | signed-triangle consistency、mandatory-claim closure 与自然负边 hard negative 共同训练；hunk 边界优先处理最弱未闭合或被反驳的 claim，而不是完成后再打分 | 生成下一 hunk、EOS 或 ABSTAIN |
| AVEP | 等墙钟下的正确提交、较低错误提交与较低人工转交/执行成本 | 信息增益或 direct-Q 可能偏好“更能减少不确定性”的实验，却忽略该结果会把下一步推向错误 Submit、返修或转交 | class-conditioned diagnosis belief、候选实验 posterior、义务差距变化、尾行动差及动作特异的 $g_e^{FB}$ | 先预演观测—Bayes 修正—目标差距—尾行动排序，再把分支摘要送入 action embedding；未显式保留的尾部结果以保持事件后验质量的 OtherBranch 合并 | 下一真实实验、ReturnToEdit、Submit 或 Handoff |

三篇中真正接近“非该理论视角不易想到”的不是编码器深度，而是方向冲突。EUMN 允许较低相似度但能消除高必要度残余的来源压过高相似度重复来源，也允许 ACT-NOW；OIWG 允许 visible tests 更多或 likelihood 更高的候选因 signed refutation 被压低；AVEP 允许信息增益相近的实验因尾行动分叉而取得相反价值。若这些反向选择在真实任务中罕见，或等参数通用模型能够复制，复杂网络本身不构成贡献。

### 2.2 理论责任没有被说过头

有效使用与表征理论支持取得、忠实表征和知情行动的递进责任，却不逻辑蕴含合取门、最优传输或一次补取；这些是 Coding Agent 情境化设计猜想。Toulmin 与结构平衡提供 claim、evidence、warrant 和 signed consistency 的组织方式，却不能把 hunk rollback 升格为语义因果证明；OIWG 因而只使用 observed-interventional warrant。反馈控制与决策中心信息取得支持“观测只有在改变后续行动时才有价值”，却不使 Bayes、CQL、CVaR 或 world model 本身变新；AVEP 的可检验增量只来自关系 likelihood、判断修正和 $g_e^{FB}$ 对行动排序的联合作用。

## 三、对肖文及 AIS Basket 理论驱动算法的真实借鉴

本轮没有把 ACAA 和 DSDL 当作文风模板，而是抽取了它们共同的算法论证纪律。

1. 先建立高价值结果和资源后果。ACAA 以经营预测和有限顾客注意为结果链，DSDL 以有限营销能力和客户响应为结果链；三篇分别以仓库使用后的真实软件行动、正确补丁和错误提交—验证成本为外部责任。
2. 再指出普通计算的方向性错误。ACAA 的普通 affinity 会偏好冗余相似评论，DSDL 的平面预测看不到期望—体验—不确认；本轮对应于“返回不等于忠实”“通过不等于 warrant”“信息增益不等于安全纠正价值”。
3. 理论必须创造可单独观察的中间对象。EUMN 的透明门、双 F 与残余，OIWG 的 signed component，AVEP 的 posterior branch 与 tail-action-gap 均有直接标签或独立机制判据。
4. 中间对象必须进入前向链、损失或解码。三篇不允许只把构念作为辅助头、解释变量或结果后分析。
5. 机制和外部结果必须同时退化。每篇都设置等参数替代、结构 neutralization、方向冲突切片和软件行动效标；内部指标单独改善不构成章节成功。

`00B_AIS_Basket理论驱动算法参照谱系.md` 进一步用 Mookerjee、GOAL 和 Hosanagar 约束信息价值、外部选项和成本行动，用 DLDE-MAB 约束理论进入损失与可行域，用 X-IM、G-FINDER、TheoryOn 和 Schema 类工作约束理论对象怎样进入表示与有序计算。它们承担算法先例和边界责任，不替代每段对 ACAA 与 DSDL 的双源回读。

## 四、三篇的决策对象与 checkpoint 不重复

| 论文 | 决策时点 | 部署可见输入 | 学习与输出 | 明确排除 |
|---|---|---|---|---|
| EUMN | 首次实质编辑或验证之前 | issue、visible failure、base-repo 关系、真实工具返回及来源事件 | 一个 EUMN checkpoint；输出 T/F、一次补取或 ACT-NOW，以及首行动前冻结的有界行动序列、可见约束和受限证据引用 | 不生成编辑 token，不给 executor 旁路 raw return；验证/提交至多是 open-loop 骨架，不依据随后观测重决策 |
| OIWG | patch 正在 hunk-by-hunk 生成 | issue、base repo、visible FTP、当前生成前缀与部署可见 claim/test 状态 | 一个生成 checkpoint；输出 next hunk、EOS、ABSTAIN 与 warrant state | 不加载 EUMN，不做一般上下文压缩，不做补丁后验证控制 |
| AVEP | patch 已持久化以后 | 当前 patch、义务—差分—实验图、已发生真实观测与剩余预算 | world checkpoint 与 policy checkpoint；输出实验或纠正行动 | 不学习任意 patch token；ReturnToEdit 调用固定编辑器，不加载前两篇权重 |

三篇只共享公开仓库任务、解析器接口和软件执行评价。其训练表、监督标签、损失、权重、部署动作和决策时点均独立，因此不能把它们描述成一个大系统的三个可互换模块，也不能用一篇的正结果补足另一篇的经验门。

## 五、最强替代与新颖性否决权

EUMN 的首要否决者不是删除某个头，而是读取相同实际返回和成本的 flat-history Transformer、等参数 raw-return cross-attention、direct-Y/semantic reacquisition policy、Context-as-a-Tool 式主动上下文管理，以及同一冻结 executor 下的直接系统。development 只按预冻结唯一主 endpoint 从完整可比 generic veto pool 选最强 $M_0$；其余忠实适配者仍各有独立否决权。若任一方法在同时留出的 repository family 与义务—来源组合上复制残余选择、ACT-NOW 校准、三元计划和固定预算软件结果，OT/残余只能作为测量解释，独立算法主张必须撤回。

OIWG 必须面对 all-positive minimum-claim coverage、sign-agnostic graph、direct-edge graph、完成后 verifier、ordinary/diverse/test-augmented beam，以及 Agent-CoEvo、MultiFixer、SynFix、CascadeFix、SiblingRepair、IBugFinder 和 TRIM 的 faithful 或明确标注的 style 适配。若优势只来自 hunk ablation、dependency graph、更多候选或 posthoc rerank，signed warrant 没有产生新的生成能力。

AVEP 必须面对相同动作与预算的 information-gain policy、no-branch-summary、参数匹配 direct-Q、mean-IQL/CQL、plain distributional CQL、flat POMDP/history Transformer、固定 test prioritization，以及 BCF、Agentic Rubrics、RETRACE、$T^3$/AReW 式控制。若 class-conditioned prior、Bayes 修正或 $g_e^{FB}$ 被这些通用控制器在校准、regret 与在线软件结果上复制，AVEP 应被杀掉而不是缩小等价区间。

## 六、标签隔离、执行责任与可复现性

EUMN 主测试的任务义务、约束与 R 条件候选只来自 issue、部署可见失败与 base-repo 静态关系，并在分支前由冻结 bucket/SHA 规则构造。gold patch、hidden tests、人工权威跨度及其派生字段不进入模型、补取器、计划候选或 executor；权威跨度只用于盲态标签和事后评分。S/W/R 从同一共同起点产生，条件名称不进入前向。F/U 禁止读取未门控返回；executor 只读共同任务/基础仓库状态和 post-reacquisition 的行动—约束—证据引用计划，且证据只能按最终传输解引用。全部门为零时条件特异内容、证据槽与 executor 条件通路必须精确为零。外部 Y 只由该共享冻结 executor 的真实补丁与运行生成。每个外测月还须使用训练截止早于公开修复/benchmark release 的固定 checkpoint；未知截止或自动更新服务不得进入确认主表。

OIWG 的 visible FTP 可用于候选构造和 observation matrix，hidden PTP 只在全部方法、patch hashes、selectors、targeted neutralization 和资源清单封存以后解锁。G15 的 neutralization 按 visible matrix 与冻结 component hash 产生，不能依据 official-correct 结果后选边。

AVEP 的逐快照 primary diagnosis、辅助失败向量与完整评价只进入离线 world 监督，并仅在 Submit 后形成真实终端后果；它们不进入部署 prior、belief 或 action input。gold fix 只用于轨迹结束后的离线 BSG-VA evidence-role 审计，绝不进入 world/policy 的前向或监督。决策时刻尚未发生的真实观测不得预泄漏；真实实验结果到达以后，它才经冻结 world likelihood 与 Bayes 公式更新下一时刻的部署 belief。执行前的假设观测只能来自冻结 world predictive distribution，不能偷读该实验后来产生的结果。初始 prior 必须让任务/补丁汇总与类别嵌入发生交互，不能使用会在 softmax 中抵消的公共加性项。

三篇都规定权重、特征变换、数据 split、优化器状态、随机种子、模型接口与评价配置的保存责任。当前这些工件仍是规格，不是已经存在的 artifact；任何后续结果必须以实际 manifest、checkpoint、日志和容器记录更新本验收状态。

## 七、物理资源与复杂度边界

EUMN 分别登记训练更新、三条件隔离容器、训练/开发来源探针和外测单位；外测执行数按 method/ablation×task×agent×seed 的实际求和记账，纯表示 replay 另列，直接系统自有工具与模型调用也不得漏计。先导资源测量只能在主测试标签可见前冻结 GPU、container、tool-call、token、wall-time 与货币硬帽。冻结 executor 的计算单列，不得藏入模型推断成本或在基线间重复计费；held-out agent/harness 只进入迁移副表。

OIWG 的现行身份表含 15 个生成臂、3 个 postprocessor 和 1 个 verifier。前瞻容量上限为不超过 4,800 个生成 hashes、240 个 postprocessor hashes 与 5,200 次 visible-FTP intervention executions；19×80 形成 1,520 个 official method—task 评价单元，失败、缺失与 NOT_APPLICABLE 仍保留其状态。由此确定性执行容量不超过 6,720 个 jobs；此外对全部 19×80 方法—任务单元保存聚合资源向量。当前这些 jobs 均未运行。

AVEP 以 trajectory、snapshot-full-eval、branch-enumeration、online-policy 和 model-fit 五类不可互换单位记账。每状态候选实验不超过冻结的 $E_{\max}$，每实验显式/聚合分支不超过 $O_{\max}$；OtherBranch 质量、完整枚举子集上的近似误差、critic 逻辑评价与真实 forward 次数均须记录。超帽运行保留为 cap-exhausted，不得删除或事后扩资。

## 八、章节级否决门

EUMN 必须在未见 family 与未见义务—来源组合两个确认层的残余补取 regret、ACT-NOW 校准和固定预算真实软件结果上同时超过 development 从完整 generic veto pool 预选的最强 $M_0$；其他忠实通用基线仍保留独立否决权。按 eligible state 等权、family bootstrap 后的方向冲突率下界在两个层级都须至少为 20%。唯一主 endpoint、SESOI 与正确修复非劣界须在主测试标签可见前冻结；完整增量下界须越过 SESOI，residual-neutralization 和与 post-F 状态配对的证据引用 neutralization **二者各自**必须消去至少一半完整增量。完整增量非正、任一有支持门失败或任何强替代落入等价区间均撤销章节身份；正交组合支持不足只记 `INCONCLUSIVE`，不得补抽。

OIWG 只有在冻结 RACE 80 上同时满足八项 pre-gate 才能重新立项，其中包括同一 claim/test component 的 joint-necessary 与自然正负边、仓库留出三分类、相对两个 generic 主基线的 hidden official 增益、baseline-pool 外新正确 patch、同分量 targeted neutralization、rewire/sign-shuffle 和 posthoc-verifier 责任。即使全部通过，也只授权重新建立 discovery、training 和 confirmatory splits，不把本次 80 题当成正式章节证据；失败则保持 DEMOTE 或转为 NO-CANDIDATE。

AVEP 要求 IG 与 branch-tail 排序发生方向冲突的有效状态至少占 20%；full AVEP 在 held-family 小分支中相对最强 generic baseline 消除至少 50% oracle-regret gap；移除或打乱 $g_e^{FB}$ 必须抹去至少一半增量；在线软件评价还须越过预注册 SESOI、保持正确提交非劣并使错误提交率至少相对下降 20%。任一直接系统在机制与外部结果上落入等价区间，均杀掉独立算法贡献。
