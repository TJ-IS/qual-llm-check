# 任务—技术匹配与有效使用驱动的信息服务组合：面向 Coding Agent 的集合政策

> **冻结的第一轮候选稿。** FIT-USE 已被判定为 provisional NO-GO，因为其核心决策杠杆仍可能只是 v3 TSMI 的复杂化。当前优先 pilot 已改为 `00D_三篇高杠杆替代题与立项门.md` 中的“语义细化类型的信息义务检索程序”。本稿不再扩写，其摘要不得当作已确定的论文二主张。

## 摘要

Coding Agent 处理仓库级修改任务时，可以从词法检索、稠密语义检索、仓库地图和代码图等信息服务取得实现、测试与依赖证据，但固定调用单一服务可能遗漏任务所需能力，无条件调用全部服务又会增加查询成本，并使重复结果挤占共享上下文。现有检索路由已经能够依据查询选择单个检索器、区分检索质量与生成效用，检索器组合研究也能够从大候选池构造互补 portfolio，因而尚待解决的不是一般意义上的检索器选择，而是候选产生以前如何为一次软件任务联合确定信息服务子集及其取得配额。基于非线性任务—技术匹配和有效使用的层级关系，本文提出 Fit-and-Use Service Policy（FIT-USE），分别表示任务信息需求与服务组合供给，以有方向的不足、过量和共同水平刻画匹配，并在成本约束下输出包含空集的集合—配额政策。该模型进一步以嵌套概率链区分证据被服务取得、经固定融合与装入后得到表征保留，以及出现在 Agent 最终 PATCH_CONTEXT 或等价行动依据中的可观察保留使用；最后一层是 retained-use proxy，不被解释为证据对补丁成功的真实因果效用。研究将从公开仓库任务生成组合—配额缓存与层级标签，在固定本地开放权重 Agent 上以补丁和官方测试作为独立外部效标，并通过任务留出、仓库留出、服务留出、成本前沿和理论机制消融评价该工件。正式实验以前先在 100 项任务上执行预注册先导实验；只有服务价值呈现任务异质性、oracle 组合优于最佳单服务和单路由器、Agent 结果具有可学习变异，且方向匹配或嵌套使用机制产生预期差异时，研究才进入扩大阶段。本文由此把任务—技术匹配从既定技术的事后适用判断推进为候选产生前的信息取得集合决策，同时把取得、有限表征、可观察使用与软件行动的证据责任分开。

**关键词：** Coding Agent；仓库信息取得；任务—技术匹配；有效使用；信息服务组合；集合政策
