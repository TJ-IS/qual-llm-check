# 任务结构自适应的 Coding Agent 信息行动价值控制

> **冻结的第一轮候选稿。** SA-VOI 仍有退化为通用轨迹 critic 加停止阈值的高风险。当前优先 pilot 已改为 `00D_三篇高杠杆替代题与立项门.md` 中的“自适应信息交付与修复能力配置”，竞争修复方案判别只作为互斥备选。本稿不再扩写，其摘要与引言不得当作已确定的论文三主张。

## 摘要

Coding Agent 在首次编辑以前反复搜索和读取仓库，过早交付会遗漏修改依据，继续探索却可能只增加重复上下文与执行成本。现有代码定位、搜索效率与 Agent 停止研究分别改善信息发现、压缩工具调用或控制整条轨迹，但不能在当前仓库状态下比较多项具体信息行动与立即交付的下游净价值。本文依据任务依赖停止线索与系统价值理论，把探索控制重述为候选集合上的序贯信息取得决策：任务结构决定何种过程状态足以表示信息充分性，只有全部候选行动的预期结果收益都不超过取得成本时才允许停止。为此，本文提出任务结构自适应的信息价值控制器 SA-VOI，以 issue 条件门连接逐事项残差专家与修复信念稳定专家，并对冻结生成器给出的四项只读候选分别预测相对于立即 HANDOFF 的结果收益分布和总增量成本分布。SA-VOI 在仓库隔离的校准数据上形成覆盖完整候选集合的净价值上界；仅当所有上界均不为正时输出 HANDOFF，否则选择受支持候选中估计净价值最高的行动。训练监督来自同一探索前缀上的配对执行：HANDOFF 分支立即进入固定下游修复或弃权政策，候选分支执行一项信息行动后沿冻结探索政策运行至自然交付，完整后缀的测试结果与资源差异构成政策条件化标签。核心编码器、双专家、候选价值头和校准工件均在本地训练与保存，SWE-smith、SWE-Gym 和 SWE-rebench 分别承担表示预训练、配对标签与仓库级校准，SWE-bench Verified 承担外部软件行动评价，ContextBench 只承担信息机制分析。研究不预设 SA-VOI 优于通用轨迹评论家；只有同状态行动排序、任务结构与专家优势交互、误停控制和端到端成本—结果前沿同时通过预注册先导门槛，才保留任务结构自适应与集合停止的算法主张。

**关键词：** Coding Agent；仓库探索；信息取得价值；任务结构；停止规则；软件工程智能体

## 1. 引言

面向真实仓库 issue 的 Coding Agent 需要在生成补丁以前把自然语言问题连接到实现位置、程序约束和验证依据。SWE-bench 以冻结仓库、真实 issue 和可执行测试建立了这一任务，SWE-agent 又把目录查看、文本搜索、文件读取和测试执行组织为模型与计算机之间的连续交互（Jimenez et al. 2024, Yang et al. 2024）。SWE-Gym 进一步发布可训练环境与 Agent 轨迹，使搜索行动、工具返回、代码修改和最终测试之间的过程关系可以被复原（Pan et al. 2025）。在这类交互中，每项只读行动都会改变 Agent 随后可见的实体、关系和修复假设，首次编辑因而不是固定流程节点，而是继续取得仓库信息与使用现有证据实施修改之间反复出现的决策边界。
