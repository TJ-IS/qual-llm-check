# 全系列零基重选题与立项闸门报告

> 版本说明　本报告保存零基比较过程。最终三项 Pilot 及其效力以 `00D_三项独立训练Pilot冻结版.md` 为准。最后一轮新颖性审计把“多文件编辑拓扑候选集生成”从优先第二项降为备用，改由“修复位置后验驱动的主动仓库信息取得”进入 Pilot 2；原因是前者与结构化程序修复正式近邻过密，后者虽然同样有强近邻，但拥有可独立检验的动态 belief 与风险下降闸门。

## 一、当前判定

本轮不再以旧三篇为默认起点。原 TSMI、DCCP 和 PVStop 只保留为问题识别材料，不承担新版论文的连续性责任。TSMI 的核心只是对八个或十六个固定动作预测质量与成本后枚举最大效用，工程协议很厚，但学习对象、动作空间和专属计算机制都太薄。DCCP 的确定性关系覆盖可以形成可审计工件，却不天然产生需要训练获得的模型。PVStop 有反事实价值与风险校准，但主要负担落在成对 Agent 运行，训练网络本身较小，而且与其他检索控制题容易挤在同一行动前阶段。三者均不应通过继续叠加模块来补强。

本轮采用更严格的“硬度”标准。一项研究只有同时回答以下问题，才进入新版正文：观察单位是什么，输入张量是什么，监督或反事实标签从哪里来，哪些参数必须由本地训练得到，损失函数为何由理论对象决定，训练与外测如何按仓库隔离，冻结后发布什么 checkpoint，推理时执行什么动作，以及若删除训练工件，提示词或云端模型为何不能等价替代。神经网络、LoRA、GNN 或强化学习只是实现形式，不自动构成研究贡献。

零基审查没有找到一套可以仅凭桌面设计就安全冻结的三篇。当前最合理的完整候选是“充分上下文表征—候选补丁集合生成—风险敏感验证”，因为三篇分别改变上下文集合、补丁候选集合和验证动作，观察单位、标签、训练工件与终点均不同。这个组合仍须分别通过小规模立项闸门。尤其是第二篇，正式近邻最密，现阶段只能列为黄红灯候选，不能先写成既定贡献。

## 二、已否决的系列

### 2.1 检索服务选择与顺序探索

固定服务集合上的小动作选择不再立项。RepoGraph、LocAgent、CodeRAG、ToolTrain、GraphLocator 等正式工作已经覆盖图导航、训练式定位、工具交互和动态邻域扩展。把四个服务改成更多服务、把 GBDT 改成神经网络，仍然不会改变“标准上下文算法选择”的本体。任务—证据缺口探索器也被否决，因为公开数据没有独立标注的任务需求槽、已满足证据状态和缺口真值。若这些中间量由同一个 LLM 自标，它们只是装饰性潜变量，不具备肖文式的独立可检验性。

### 2.2 结构化单补丁生成

简单的“编辑类型—位置—内容”因子化生成不再立项。Hoppity、Recoder、DEAR、KNOD、NTR、CodePlan、CodeStruct、CascadeFix 和多粒度修复工作已经覆盖图编辑、语法约束、多位置修改、模板选择、仓库计划与结构化编辑接口。由 gold diff 确定编辑类型时，训练一个类型分类器再用 LoRA 生成补丁，方法增量不足。多文件编辑拓扑的候选集合生成仍保留为条件性候选，但必须证明集合级拓扑多样性转化为相同预算下的 executable pass@K 与 resolved@K，而不是只改善语法有效率。

### 2.3 纯 testing-centric 三拆

“测试诊断性表征—零结果批量选择—部分结果序贯选择”不能预先拆成三篇。三者共享 candidate×test 矩阵、候选正确标签、outcome world model 和最终补丁判断。第二项只是第三项在空历史下的非自适应特例，第一项很可能只是第三项的编码器。CodeT 已使用候选与生成测试的执行一致性，B4 已在 solution×test 矩阵上进行贝叶斯后验与优化，e-Otter++ 已用多个 surrogate patches 的完整执行矩阵选择测试。该方向至多形成一篇强论文，除非表征效度、并行组合问题和适应性增益分别通过非常严格的独立闸门。

### 2.4 轨迹记忆与通用 Agent 路由

公开轨迹不提供记忆条目的反事实效用。要识别某条经验是有益、无效还是有害，必须对同一任务随机注入或屏蔽记忆并重复完整 Agent 运行。Reflexion、ExpeRepair、subtask memory 和通用 agent memory 已占据直接近邻，且记忆效果强依赖基础模型和序列化格式。通用模型路由、继续或重启控制同样需要大规模分支运行，并受到 RouteLLM、turn-control 和 test-time compute 工作的直接挤压，因此不作为首选系列。

## 三、唯一值得进入立项实验的完整系列

### 3.1 研究一：人工监督的任务充分上下文表征

唯一问题是：在固定 token 预算下，如何从 issue 与冻结仓库中学习一个跨文件、代码块和行区间一致的任务充分上下文分布，使模型选择的不是“最终被修改的位置”，而是人类判断完成任务前需要读取的证据。

主监督来自 ContextBench 的人类 gold spans。文件层由 gold path 给出，语法块层由固定 Tree-sitter 规则将 gold span 投影到最小包含块，因此必须明确语法块是本文适配层，不冒充官方第四类标签。patch locus、成功轨迹读区间和 RepoExec dependency invocation 只能进入来源专属辅助头，不能与人类 needed-context 合并为同一真值。训练、调参与测试按仓库族隔离，ContextBench 之外的集合只承担迁移或行动结果。

建议架构是冻结的本地代码编码器加二十至五十百万参数的异构图与集合网络。文件概率采用多标签 Bernoulli，块和行使用条件因子化，令 \(p_b=p_f p_{b\mid f}\) 与 \(p_l=p_b p_{l\mid b}\)，从参数化上保证子节点概率不超过父节点，避免三个独立 listwise 分布之间的伪一致性。预算解码器在 token 约束下选择嵌套节点，并保留最小父级标题和路径。损失由人类上下文多粒度排序、条件层次似然、来源专属辅助任务、预算违反与概率校准构成。

独立工件包括图构建规范、候选召回器、层次表征 checkpoint、来源专属 heads、预算 calibrator 和确定性解码器。最终结果必须同时包含三粒度 gold 指标、父子一致性与校准、来源差异、固定 patch generator 的 resolved/token、反事实交换、下游探针和去图、去层次、去来源头、去预算训练等消融。若只提高 patch-locus recall，或相对简单的层级文本 ranker 没有独立增益，本题撤回。

### 3.2 研究二：固定生成预算下的多文件编辑拓扑候选集

唯一问题是：在固定 K 和生成 token 预算下，如何训练一个候选集合生成器，使不同候选覆盖不同的可执行多文件编辑拓扑，从而提高至少一个候选修复任务的概率，而不是反复采样结构相同的补丁。

训练目标不是单补丁似然。每个 developer patch 先由固定解析器提取文件数、hunk 分布、AST 操作、实体位置和静态依赖边，形成可复算的编辑拓扑标签。SWE-smith、SWE-Gym 和清洗后的真实任务提供 patch 与容器结果，SWE-rebench 的新仓库和新时间任务承担外测。SWE-smith 的 issue 可能由 bug patch 与测试材料合成，因此必须做仓库、生成器族和时间隔离，真实结论不能仅来自该集合。

建议架构是本地七十亿参数代码模型的四至八个 topology-conditioned LoRA experts，外接候选集合 router、AST entity pointer、edit-operation head 和约束内容解码器。单候选损失包含拓扑分类、位置指针、操作分类、内容负对数似然和依赖边监督。集合损失对 K 个候选施加拓扑覆盖、重复惩罚和基于真实 executable/resolved 结果的组内偏好，使模型优化固定预算下的集合覆盖而不是单样本平均似然。

独立工件包括多个 LoRA experts、集合 router、结构 heads、grammar adapter 和固定 K 解码器。立项门是相同 K 与 token 下同时提高 unique executable topology、multi-file pass@K 和 resolved@K，并超过普通温度采样、diverse beam、单 LoRA、NTR、CodePlan 式规划和强开放 coding agent。若只有 patch apply rate 或 AST 合法性提高，本题撤回。由于 CodePlan、NTR、CodeStruct、CascadeFix 等近邻密集，本题是整套中风险最高的一篇，不能在预演前写成既定贡献。

### 3.3 研究三：部分验证矩阵下的成本敏感主动验证与选择性发布

唯一问题是：给定冻结候选补丁集和任务可见测试池，在只观察部分 candidate×test 结果时，如何联合决定下一测试组、停止、选择某一补丁或放弃全部候选，使错误发布损失、漏选损失和验证成本之和最小。

每一个 outcome 标签都来自真实容器执行，候选正确性由独立 official evaluator 产生。测试生成器只能看 issue 与 buggy repository；gold patch 与隐藏测试只生成离线标签，不能进入测试池、模型输入或策略状态。训练需包含至少两个冻结候选生成器，并保留 generator-holdout 外测，防止模型仅识别生成器风格。

建议架构是五至二十百万参数的 candidate-test 二部关系网络。模型包含候选正确性 head、池内 any-correct head、带共享潜变量的相关 outcome head 和成本分位数 head。随机遮蔽完整矩阵形成部署状态，联合损失由候选 Brier 或 BCE、set-level correctness、masked outcome NLL、cost pinball、组内排序和校准组成。终端风险显式比较选错补丁与放弃正确候选的损失，EVI 解码器用预测 outcome 分布计算下一测试组的预期风险下降并扣除总容器成本和尾延迟。

独立工件包括 world-model checkpoint、风险 calibrator、损失比配置和确定性 EVI planner。主结果是风险—覆盖曲线、wrong-release rate、相同风险下的容器成本、相同成本下的 Bayes regret、相对批量策略的 adaptivity gap，以及 candidate-generator 与时间外迁移。若不胜 random、cheapest、coverage、entropy、B4 fixed-budget 或简单批量选择，本题撤回。

## 四、为什么这三篇在概念上能够共存

三篇共享的不是某个模型或一条必须串联的流水线，而是同一张力：有限计算下，Agent 必须把潜在软件信息转化为足以支持并验证行动的任务证据。研究一处理行动前的证据表征，动作是上下文集合。研究二处理行动产生，动作是具有集合多样性的补丁候选集。研究三处理行动后的验证信息取得，动作是测试组以及选择或放弃。三篇可以未来组合，但当前实验必须分别冻结上游，不能用前一篇成功来替后一篇识别。

这比旧三篇更接近目标博士论文的逻辑。研究一建立共同的任务证据表征问题。研究二在无反馈的静态生成情境中处理多样行动。研究三在有反馈的序贯验证情境中处理未来信息价值。它们不是把同一个动作分成候选前、候选后和停止，也不是把同一矩阵拆成编码器、批量解码与序贯解码。

与肖两篇 ISR 对照时，后续写作不应以“用了 HGT、LoRA 或 EVI”作为硬度证据。研究一必须把任务充分性变成条件层次概率并独立验证。研究二必须把集合级编辑拓扑变成可训练的 router、结构 heads 和集合损失并验证中间拓扑。研究三必须把候选正确信念、相关测试结果和成本变成可校准状态，并验证 belief quality、EVI regret 和最终风险。每篇都要完成“理论构念—专门张量—联合损失—中间表征检验—行动结果—消融”闭环。

## 五、先做实验而不是先写满论文

### 5.1 主动验证预演

先抽一百个 repo-disjoint 任务，使用两个本地冻结生成器，每任务至少十六个候选和十个任务可见测试，形成至少一万六千个矩阵格子，并对测试做三次稳定性运行。至少五十个任务必须同时含正确和错误候选，至少七成测试稳定，且测试结果不能近似对所有候选恒定。若这些条件不满足，研究三及 testing diagnosticity 均停止。

### 5.2 充分上下文预演

在 ContextBench 中先按仓库划出开发与封存子集，固定高召回候选生成器，报告 candidate oracle recall。训练一个层级文本基线和最小图模型。只有在人类 gold、父子校准和固定 generator 下游结果三个方面都出现增益，才进入完整模型。若图模型只复现 patch locus，研究一停止。

### 5.3 候选集合生成预演

从 SWE-smith 与 SWE-Gym 选取至少三百个多文件任务，先测 developer patch 的拓扑分布与普通本地模型 K 次采样的拓扑塌缩程度。仅当拓扑多样性与 pass@K 或 resolved@K 存在稳定关联，且一个轻量 topology router 能在相同 token 下提高两者，才投入多专家 LoRA。否则不以“更复杂的生成器”续命，直接重选第二篇。

## 六、资源与决策顺序

预演顺序应是研究三、研究一、研究二，而非按论文编号。研究三的标签最硬，矩阵是否具有信息增益可最快证伪。研究一的数据规模较小但人类标签责任最清楚。研究二算力和新颖性风险最高，应最后投入。

主动验证的一百任务预演预计需要约五十至一百五十 GPU 小时的候选与测试生成，以及五百至两千容器小时。充分上下文预演可在一至两张二十四或四十八 GB GPU 上完成，约三十至八十 GPU 小时，另需数百次下游容器运行。候选集合预演约需一百至三百 GPU 小时和数千次 evaluator。只有三个闸门均通过后，才估计完整研究的总运行账并撰写结果型论文。

最终冻结规则是：现在冻结问题、标签责任、模型最小结构和撤题门，不冻结论文题目与贡献结论。任何一项预演失败，都必须替换该研究，而不是把失败的构件挪入另一篇或继续增加模块。后续正式写作仍按既定协议，每完成一个实质段立即回读 ACAA 与 DSDL 的原文位置、逐句功能和引用责任；但在预演完成前，只写立项设计，不写成已经成立的论文贡献。
