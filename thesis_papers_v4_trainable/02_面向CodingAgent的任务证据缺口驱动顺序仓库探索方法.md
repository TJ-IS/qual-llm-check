# 已终止方案　面向 Coding Agent 的任务证据缺口驱动顺序仓库探索方法

> 状态说明　本方案在正式近邻与标签闸门后终止，不属于新版三篇论文。公共数据不能独立标注需求槽、证据到需求槽的映射和探索前缀已满足状态，GraphLocator、ToolTrain 与 CoSIL 又已覆盖动态图探索主体。以下文字仅保留立项否决轨迹，不再续写，也不得作为当前研究设计引用。

## 摘要

仓库级软件修改要求 Coding Agent 在有限读取预算内取得支持后续修改的软件证据，但现有定位器与训练型探索代理主要依据目标位置命中或终局修复结果优化动作，难以说明当前已读证据究竟满足了哪些任务要求以及尚缺什么。本文把软件修改任务需要的知识与已取得仓库证据之间的可计算匹配作为顺序探索的中间机制，并提出任务证据缺口驱动仓库取得方法 TEGRA。该方法先以可观察 schema 把任务需要编码为行为与契约需求以及程序依赖需求，再以已读区域形成对应证据表示，并通过显式的需求、证据与缺口张量为数百个 frontier 候选分配下一读取分数。TEGRA 联合学习同一前缀内的多正例排序、类型对应的缺口闭合、通往未来有效证据的软桥接距离和读取成本，并仅以同任务高低终局效用轨迹进行辅助偏好学习。训练将使用 SWE-Gym 与 SWE-smith 可执行任务重新生成的探索轨迹，外部评价使用 ContextBench、SWE-Explore 与仓库隔离的 SWE-rebench 任务，在固定步数或固定行数预算下检验证据覆盖、首次有用证据延迟、缺口识别和冻结修复器的执行结果。本文不预报尚未取得的性能结果，其设计贡献是提供一个可训练、可干预且可在类型识别失败时退回未类型潜变量的仓库探索工件，从而把任务知识与软件证据的匹配从事后解释转化为可证伪的取得机制。

## 1　引言

仓库级问题修复把 Coding Agent 置于短任务描述与大规模软件系统之间。一个 issue 可以只描述外部错误、期望行为和少量复现线索，正确修改却可能依赖实现定义、跨文件调用、配置入口和回归测试。SWE-bench 把这种行动固定为在基准提交上生成能够通过测试的补丁，SWE-Gym 与 SWE-rebench 又把可执行环境和持续采集扩展为训练与时间隔离评价资源（Jimenez et al. 2024; Pan et al. 2025; Badertdinov et al. 2025）。然而，Agent 在作出修改前并不直接观察完整仓库语义，而是通过搜索、读取与导航逐步取得局部证据。每次无关读取都会占用工具轮次、行数与上下文，每次关键遗漏又可能使后续推理建立在错误依赖或不完整契约上。因此，仓库探索不是补丁生成前可忽略的准备工作，而是决定有限计算被转化为何种可行动证据的顺序信息取得问题。
