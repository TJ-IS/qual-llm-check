# 新版三篇研究设计冻结说明

本目录只存放通过零基标签与近邻筛选后形成的三篇完整研究设计。三篇分别研究人工所需上下文的层次表征、修复位置后验驱动的主动仓库信息取得，以及部分候选—测试矩阵上的成本敏感主动验证。正文不得引用同级目录之外的已终止 TSMI、DCCP、PVStop 或 typed task–evidence gap 草稿作为当前方法。

三篇是可证伪的研究设计，不虚构实验结果。方法、数据、训练、推理、评价、资源和撤题条件必须写到可直接实现的程度。各篇可以在未来组合，但当前实证彼此独立，不把前一篇 checkpoint 设为后一篇必要输入。

每完成一个实质段落，作者立即实际读取以下两篇本地 ISR 原文，并在对应审计文件中记录两篇参照段的位置、各自句子或句群的修辞功能、新段逐句功能、引用责任和本轮处理：

- `database_fulltext_all/28706_2024_attending-to-customer-attention-a-novel-deep-learning-method-for-leveraging-multimodal-online-re.md`
- `database_fulltext_all/16409_2023_a-theory-driven-deep-learning-method-for-voice-chatbased-customer-response-prediction.md`

逐段回读只学习论证结构，不复制原句。每一处理论迁移都区分人类或组织层原机制与 Coding Agent 的计算操作化，不能把人的认知、感知或满意直接赋予模型。

三篇共同遵守以下数据边界：训练、调参、校准和测试按规范仓库族隔离；issue、commit、patch、test 和 fork 近重复在跨集合前消除；gold patch、隐藏测试和未来工具返回只在明确的离线标签责任中出现；所有 benchmark 的版本、release、模型 revision、容器镜像和解析器版本均在最终复现表冻结。

在任何一篇生成候选、轨迹、矩阵、标签或解封测试前，三篇共同建立只增不改的 `master_split_registry`。规范实体键为 `(canonical_upstream, repo_family_id, base_commit, normalized_issue_hash)`；`repo_family_id` 由 upstream、fork、mirror、同源包、共享提交祖先、规范包名以及源码 MinHash Jaccard 不低于 0.90 的关系传递闭包确定，issue、patch hunk、AST edit、test 与 gold-context hash 形成任务级近重复边。registry 对每个实体记录 dataset/release、时间戳、paper ID、`role`、首次写入时的代码、数据与容器哈希以及 exclusion reason；`role` 只能取 `pilot`、`train`、`development`、`calibration`、`confirmatory`、`sealed`、`temporal-test` 或 `auxiliary-only`，任何预注册角色迁移都以追加记录保留原值和理由，不覆盖历史。

跨篇可以复用同一 benchmark 的基础设施，但默认不把同一任务或 repo-family 产生的结果计为独立的系列证据。论文一、二、三的 `confirmatory`、`sealed` 与 `temporal-test` families 两两互斥；任一篇承担这三种角色的 family 不得在另一篇进入 pilot、train、development、calibration 或辅助 head 训练。样本供给不足而必须复用时，须在解封结果前标成 `shared-evidence`；三篇仍可各自作任务内方法比较，但系列汇总只计一个独立 family cluster，不得声称三次跨仓库或时间外复现。论文二与论文三共用 SWE-Gym 时，一篇用作开发的 family 在另一篇不能承担确认性责任；三篇的 SWE-rebench 时间外任务分别来自事先签名、互不重叠的 90 天窗口和互斥 families。跨篇不得传递 checkpoint、calibrator、候选、轨迹、测试、补丁、隐藏 outcome 或统计选择；共享 parser 或 encoder 只能作为冻结公共基础设施并记录 revision。

`04_三篇训练算法系列终审与实施路线.md` 是本轮跨篇判定、与两篇 ISR 的硬度比较、micro-pilot 次序和冻结哈希的权威汇总；三篇正文仍分别承担各自可实现规格，04 不替代正文中的标签、公式、资源或撤题条件。
