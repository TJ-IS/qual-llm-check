# 人工所需上下文的层次表征与预算合成

## 摘要

<!-- P01 --> 仓库级 Coding Agent 必须在有限上下文窗口内决定哪些代码应在形成修复方案前被读取，但最终修改位置、成功轨迹中的访问位置与人类协议判断的所需上下文并不具有相同含义。本文研究固定 token 预算下人工所需上下文的学习与合成问题。我们以 ContextBench 发布的 `gold_context` 行区间为唯一人工主监督，按官方定义级 Tree-sitter 对齐规则确定 block、按路径聚合 file，并把未命中区间视为未标注而非负例。本文提出层次所需上下文网络，先由冻结的稀疏检索、稠密检索和静态关系扩展构造候选子图，再以冻结代码编码器和可训练关系图编码器形成任务条件节点表示。模型以文件边际概率、父文件条件下的块概率和父块条件下的行概率参数化嵌套相关性，并以人工主头、补丁位置头、轨迹读取头和参考解依赖使用头分离标签来源。人工主头在 repo、task、candidate 三级等权测度下采用包含已观察正例的全部候选边际计算 nnPU 风险，主训练使用预注册类先验倍数并报告完整 prior sensitivity，kernel mixture proportion 估计只作附录诊断。确认性评价先隔离 pilot families，再在其余仓库族上产生五折 outer-grouped OOF 预测，校准与预算参数只由各 outer-training 集的 inner-OOF 预测拟合，原子覆盖 CP-SAT 随后生成无重复效用且满足真实 token 闭包的上下文包。该设计以候选 manifest、层次 checkpoint、来源专属 heads、折外校准器、预算解码器和固定 patcher 行动日志构成可单独训练、复算和否证的算法工件。

## 1 引言

<!-- P02 --> 真实仓库中的 issue 解决通常要求 Coding Agent 把自然语言任务与分散在多个文件中的定义、调用、配置和测试联系起来，而不是只补全一个已知函数。仓库代码量、依赖范围和可用工具结果往往超过一次模型调用能够稳定处理的上下文，因此 Agent 在生成补丁前必须选择一个有限的代码子集。这个选择会同时影响模型获得的任务证据、输入 token 成本以及后续修复可用的信息基础。ContextBench 将这一中间过程从最终修复结果中分离出来，收集了 66 个仓库、8 种语言中的 1,136 个 issue-resolution 任务，并为任务提供人工核验的 gold contexts（Li et al. 2026）。其评价显示，现有 Agent 往往以较低精度换取召回，且实际探索的上下文与最终使用的上下文之间存在明显差异（Li et al. 2026）。这些现象表明，仓库上下文不只是进入大模型前的工程预处理对象，还需要被作为具有独立标签、成本约束和行动后果的表征问题加以研究。

<!-- P03 --> 现有仓库级方法已经能够用代码图帮助 Agent 导航，或在文件、函数和行等粒度上定位可能需要修改的代码（Ouyang et al. 2025；Chen et al. 2025；Zhang et al. 2025）。CoRNStack 进一步以高质量对比数据训练代码 retriever 与 reranker，ToolTrain 则以监督微调和工具交互强化学习训练多步 issue-localization Agent（Suresh et al. 2025；Ma et al. 2026）。GraphLocator、RANGER、FastContext 与 CodeGrep 分别代表因果图扩展、MCTS 图检索、专用仓库探索模型和 GRPO 训练的检索 Agent（Liu et al. 2026；Shah et al. 2025；Zhang et al. 2026a；Chen et al. 2026）。这些近邻主要以 patch localization、工具轨迹、代码检索对或下游 resolved 为训练和评价责任，证明了检索器可以成为需要本地训练的独立算法工件。本文与它们的直接交集是任务条件仓库检索、图关系和预算上下文输出，而非“首次训练检索器”或“首次使用代码图”。本文的边界在于用独立人工协议标注测量不会必然被修改的充分上下文，并要求 file、definition block 与 line 的概率和预算输出沿 canonical path 一致。成功轨迹中的读取位置受特定 Agent、工具顺序和冗余访问影响，developer patch locus 又只记录最终改动，两者均不能自动替代该人工构念。人工 gold 未覆盖某个候选同样只表示没有获得正标注，不能证明该节点对所有可行修复路径均无用。由此，本文提出研究问题：在固定 token 预算下，如何学习跨文件、定义块和源码行一致的人工所需上下文 score，并把它转化为可供冻结 Coding Agent 使用的嵌套上下文包？

<!-- P04 --> 为回答这一问题，本文把任务充分表征具体化为对人工所需上下文的条件概率估计，而不把模型注意权重或最终补丁位置直接解释为人的判断。候选阶段使用冻结的 BM25、稠密检索和静态关系扩展缩小全仓搜索空间，并把候选对人工 gold 的可达率作为后续模型不可突破的上限。表征阶段在文件、语法块与行节点之间传递任务条件信息，并以父节点条件下的子节点概率保证三个粒度的选择相互兼容。学习阶段以正未标注目标训练人工主头，以来源专属辅助头吸收 patch、trajectory 和 reference-solution dependency 信号，避免较易取得的行为结果覆盖人工构念。行动阶段使用预算校准器和确定性解码器联合考虑相关性、token 成本、冗余与嵌套闭包，而不是分别排序后截断。实证阶段同时评价人工上下文检索、所学层次表征、概率校准和固定 patcher 的任务结果，并以仓库族隔离和标签来源干预识别增益来源。本文由此拟贡献一种面向人类 needed-context 的计算测量、一套与该测量一致的条件层次学习方法，以及连接中间表征、预算行动和修复结果的可复算评价协议。

## 2 理论基础与设计要求

<!-- P05 --> 表征理论认为，信息系统通过结构化表征帮助使用者理解与任务相关的现实状态，表征的价值最终体现为是否支持面向目标的行动（Burton-Jones and Grange 2013）。该理论同时区分获得表征、表征忠实度和基于表征采取行动，因而信息被访问并不等同于信息已被有效用于目标实现。迁移到本文场景时，预算上下文包是冻结仓库相对于特定 issue 的任务表征，Coding Agent 是该表征的计算使用者。这里的表征忠实度不表示所选代码在语法上是否真实，因为仓库代码本身已经存在，而表示上下文包是否保留了人类认为解决任务前需要的代码对象及其层次关系。相应地，检索到更多代码只提高访问范围，只有在有限预算内保留任务相关对象并支持后续修复，才构成与行动目标一致的有效表征。本文只迁移表征、任务适配与行动后果之间的规范关系，不声称模型具有人类理解、认知或意图。该理论映射导出三个评价责任，分别是对人工 needed-context 的测量忠实度、文件至行区间结构的关系忠实度，以及固定 Agent 使用上下文后的行动效用。

<!-- P06 --> 本文将人工所需上下文限定为在给定 issue 和 base-commit 仓库快照下，按照 ContextBench 标注协议被判断为形成解决方案所需的代码区间。冻结 release 的直接人工字段是 JSON 编码的 `gold_context`，每个对象包含 `file`、`start_line`、`end_line` 与 `content`，因此本文不声称另获一套独立的 file 或 block 人工标签（Li et al. 2026）。文件正标记由该字段按路径聚合，行正标记由区间覆盖的非空源码行确定，block 正标记则严格复现官方 evaluator 的定义级对齐：使用其冻结的 Tree-sitter grammar、语言 node-type 表及 canonical file/start/end 坐标，把 gold span 对齐到 function、method、class、interface 或 trait 等定义符号（Brunsfeld 2018；Li et al. 2026）。这些 file/block/line 标记都是同一批人工 span 的确定性视图，而不是三套相互独立的人工判断；正文与结果表将同时给出原始字段、派生规则、无法唯一对齐数和 official evaluator 复核差异。未与 gold span 相交的候选只进入未标注集合，因为发布协议没有证明它对其他有效推理路径无用。developer patch locus、SWE-Explore 轨迹读取和 RepoExec provided dependencies 分别记录最终改动、特定成功轨迹访问与参考解静态依赖事件，只由来源专属辅助头学习而不并入人工主标签。由此，协议一致性、来源区分和固定 Agent 行动分别承担测量、构念边界与外部效用责任；只有三类证据相容，本文才把折外 score 用于预算决策。

<!-- P07 --> 上述理论映射和标签边界导出四项可检验的设计要求。第一，系统必须先说明冻结候选生成器能否使人工 span 进入可学习子图，并把候选不可达造成的损失与重排模型错误分开。第二，系统必须允许多个文件同时为正，并把块和行的相关性表示为父事件条件下的概率，使叶级判断能够向上闭合而父级判断不会无差别扩散到全部子节点。第三，人工判断、补丁位置、轨迹读取和参考解依赖使用必须共享仓库表征但保留独立预测头，使来源间相合可以被利用而来源间冲突仍可被观察。第四，部署输出必须在一个预先规定的集合目标下同时处理预测效用、token 成本、重复内容和父级元数据闭包，使同一模型分数能够对应一个可复算的预算行动。前三项分别约束可见信息、层次关系和测量来源，第四项把这些中间要求连接到 Agent 实际接收的上下文包。任何网络架构都只是实现这些要求的候选工件，若参数量匹配的纯文本层次模型同样满足要求，则不能把关系图编码器本身解释为理论贡献。

## 3 问题定义与数据责任

<!-- P08 --> 设第 \(i\) 个任务为 \(x_i=(q_i,R_i,G_i)\)，其中 \(q_i\) 是 issue 文本，\(R_i\) 是 base commit 快照，\(G_i\) 是 ContextBench 的 `gold_context` spans。
固定解析器按 P06 规则把 \(R_i\) 表示为文件集合 \(F_i\)、官方 definition-level block 集合 \(B_i^{\mathrm{eval}}\)、非空源码行原子集合 \(L_i\)，并为解析失败文件或不在任何合格 definition 内的行建立文件级虚拟闭包块 \(B_i^{\mathrm{virt}}\)；令 \(B_i=B_i^{\mathrm{eval}}\cup B_i^{\mathrm{virt}}\)，虚拟块只作 line 的结构父节点且排除 block 主标签、block nnPU 与 official block 指标，连续行只在渲染阶段合成可读窗口。
候选生成器 \(g_0\) 在查看任何 gold 前冻结：BM25 与冻结 dense encoder 各取前 48 个文件，dense block 通道取前 256 个官方定义块，再沿 import、call、definition-reference 与 test-production 边扩展两跳，每个节点每类关系第一跳至多 16 个、第二跳至多 8 个邻居；虚拟闭包块只随候选文件确定性加入并计入 block 上限。
候选上限固定为每任务 256 个文件、2,048 个 block 和 16,384 个 line atoms；超限时按通道 reciprocal rank、关系跳数、规范路径和稳定哈希依次裁决，gold、patch、trajectory 与测试结果均不得保送节点。
训练按单任务图批次和四层每关系 \((16,12,8,8)\) 邻居采样，推理对冻结候选图全量稀疏传播；这些 top-k、上限、采样 fan-out、随机种子与超限计数写入 candidate manifest。
manifest 另保存查询、提交、parser/grammar 与 encoder revision、各通道原始分数、扩展边、节点坐标和 payload token 区间，使候选不能随监督训练改变。
对 \(k\in\{F,B^{\mathrm{eval}},L\}\)，候选可达性分别报告至少一项 gold 命中任务率、全部 gold 可达任务率和 micro gold coverage，并按上限触发与否分层。
主模型只在 \(C_i=g_0(q_i,R_i)\) 内估计 score，最终输出满足 token 上限 \(T_i\) 和父级 header 闭包的集合；端到端误差因而分解为候选遗漏、候选内估计和预算集合决策，而不由 resolved 单项吸收。

## 4 层次表征方法

<!-- P09 --> 对候选节点 \(v\)，模型输入由冻结代码编码器产生的源码向量 \(e_v\in\mathbb{R}^{d_e}\)、冻结文本编码器产生的 issue 向量 \(e_q\in\mathbb{R}^{d_e}\) 和可复算特征 \(z_v\) 组成。
\(z_v\) 包括 BM25 与稠密通道的原始分数和名次、命中通道、节点类型、路径深度、token 数、解析状态以及相对 issue 词项覆盖，不含 gold、patch 或执行结果。
类型专属投影将 \([e_v,e_q,e_v\odot e_q,|e_v-e_q|,z_v]\) 映射为初始节点表示 \(h_v^0\in\mathbb{R}^{d}\)，所有候选堆叠为 \(H^0_i\in\mathbb{R}^{|C_i|\times d}\)。
关系输入按 contains、imports、calls、defines、references、tests、lexical-neighbor 和 retrieval-channel 分成稀疏边表 \(E_{i,r}\)，并另存父级集合、节点有效掩码和 payload token 区间。
文件、块和行使用不同投影矩阵但共享同一冻结语义编码空间，使后续差异来自可训练的任务交互与关系传播而非分别微调基础编码器。
解析失败文件保留文件与源码行节点并关闭不可得的 AST 关系；解析成功但不在任何官方合格 definition 内的行也保留，两类行都连接到 P08 的文件级虚拟闭包块，该块带失败或 top-level 标志、没有 block 主标签且只承担行级概率与 header 闭包，不用静默丢弃样本。
冻结编码器的名称、权重 revision、tokenizer、最大长度和截断方向与候选 manifest 一同发布，保证输入张量可以脱离训练脚本重建。

<!-- P10 --> 可训练表征器采用四层、八头关系感知图 Transformer，并把每类静态边的反向边显式加入消息传递。令 \(d_h=d/8\)，第 \(\ell\) 层第 \(h\) 个头中节点 \(v\) 接收

\[
m_{v,h}^{\ell}=\sum_{(u,r)\in\mathcal N(v)}\alpha_{uvrh}^{\ell}W_{r,h}^{V,\ell}h_u^{\ell},\qquad
\alpha_{uvrh}^{\ell}=\operatorname{softmax}_{(u',r')\in\mathcal N(v)}
\frac{(W_{\tau(v),h}^{Q,\ell}h_v^{\ell})^\top(W_{r,h}^{K,\ell}h_u^{\ell})+b_{r,h}^{\ell}}{\sqrt {d_h}}.
\]

八个 \(m_{v,h}^{\ell}\) 拼接后经输出投影、类型专属门控、残差和前馈层得到 \(h_v^{\ell+1}\)，使 contains 边交换层次信息、call/reference 边传播跨文件证据、retrieval-channel 边保存候选来源。主配置使用 \(d=512\)、8 头和 4 层，关系 \(K/V\) 矩阵由 4 个共享 basis 的可训练线性组合构成，反向关系只新增系数而不复制整矩阵。基础编码器全部冻结，仅训练输入投影、关系层和各预测 heads；脚本在首个 pilot fit 前输出逐模块参数表，只有总 trainable count 位于 20M 至 30M 才进入主实验。任何宽度、basis 数或 fan-out 调整都只能发生在隔离 pilot families，参数量匹配文本模型同步调整，确认性 outer folds 不再改变。训练产物是接收 candidate manifest 与冻结 embedding cache 的独立 checkpoint，不包含候选生成器、校准器或 patcher 权重。关系图 Transformer 只是结构传播的候选实现，其必要性由删除非 contains 边、只保留 contains 边、同度随机重连和参数量匹配文本层次模型共同检验。

<!-- P11 --> 层次主头不对三个粒度分别拟合互不相干的 softmax。每个文件具有独立 logit \(a_f\) 和边际概率

\[
p_f=\sigma(a_f),\qquad f\in F_i ,
\]

因此同一任务可有任意多个正文件，且 \(\sum_f p_f\) 不受等于 1 的限制。冻结投影为每个 \(b\in B_i\) 指定唯一文件父级 \(c_F(b)\)，并为每个源码行原子 \(l\) 指定唯一父级 \(c_B(l)\)：若存在官方合格 definition 就取最小包含块，否则取 P08 的文件级虚拟闭包块。模型据此估计二元条件概率 \(q_{b\mid c_F(b)}=\sigma(a_{b\mid f})\) 与 \(q_{l\mid c_B(l)}=\sigma(a_{l\mid b})\)，相应边际为

\[
p_b=p_{c_F(b)}q_{b\mid c_F(b)},\qquad
p_l=p_{c_B(l)}q_{l\mid c_B(l)}.
\]

这一因子化对每条 canonical 路径严格保证 \(p_l\leq p_{c_B(l)}\leq p_{c_F(c_B(l))}\)。嵌套类、函数与语句产生的其他包围关系只作为关系表征器中的 contains 边，不进入主概率父集合，也不产生额外 block 正标签。解析失败或不在合格 definition 内的行统一以 P09 定义的虚拟块为 canonical parent；虚拟块的 \(p_b\) 只参与相应 line 边际与预算 header 闭包，排除 block 标签、block nnPU 和 block 指标。跨层评价和预算解码只使用边际 \(p_f,p_b,p_l\)，条件量 \(q_{\cdot\mid\cdot}\) 及父内 listwise 分数只在各自条件事件中解释，不把不同层的归一化分数当作可比较概率。令 \(\operatorname{Ch}_i^+(u)=\{v:c(v)=u,S_v=1,v\in C_i\}\)，并令 \(\mathcal U_i^+\) 只包含 observed-positive 父节点，其中原始 gold 投影产生的每个 observed-positive canonical 子节点都已进入 \(C_i\)。再令 \(\mathcal D_{r,\mathrm{pc}}\) 为仓库 \(r\) 中 \(\mathcal U_i^+\) 非空的任务集合，\(\mathcal R_{\mathrm{pc}}\) 为至少含一个此类任务的仓库集合。单侧正子存在损失按父节点、任务与仓库三级等权定义为

\[
\mathcal L_{\mathrm{pos\text{-}child}}
=\frac{1}{|\mathcal R_{\mathrm{pc}}|}
\sum_{r\in\mathcal R_{\mathrm{pc}}}
\frac{1}{|\mathcal D_{r,\mathrm{pc}}|}
\sum_{i\in\mathcal D_{r,\mathrm{pc}}}
\frac{1}{|\mathcal U_i^+|}
\sum_{u\in\mathcal U_i^+}
\left[
p_u-p_u\left\{1-\prod_{v\in\operatorname{Ch}_i^+(u)}
(1-q_{v\mid u})\right\}
\right]^2 .
\]

该损失只要求已观察父事件能由至少一个已观察 canonical 子事件重构，不检验负父节点或一般边际 OR 等式。乘积中不放入任何未标注子节点，也跳过 observed-positive 子节点候选不完整的父节点，因此不会把未观察到子正例解释为负证据，其独立作用由删除该项的消融检验。

<!-- P12 --> 对监督粒度 \(k\in\{F,B^{\mathrm{eval}},L\}\)，令潜在所需事件为 \(Y_v^k=1\)，人工协议观察到的正标记为 \(S_v^k=1\)，并只采用 \(P(S=1\mid Y=0)=0\) 的单侧标注假设。每个 outer-training 集上的目标测度先对 repo 等权、再对该 repo 内 task 等权、最后对该 task 的同层 candidate 等权：

\[
\mu_k(r,i,v)=
\frac{1}{|\mathcal R|}
\frac{1}{|\mathcal D_r|}
\frac{1}{|C_i^k|},
\qquad r\in\mathcal R,\ i\in\mathcal D_r,\ v\in C_i^k .
\]

令 \(M_k\) 为 \(\mu_k\) 下包含 \(S=1\) 在内的全部 candidate 边际，\(P_k^{\mathrm{obs}}\) 为同一测度的观察正例条件分布 \(P_{\mu_k}(X\mid S=1)\)，\(q_k=P_{\mu_k}(S=1)\)，并令 \(\pi_k=P_{\mu_k}(Y=1)\)。只有在无假阳性且同层满足 \(P(S=1\mid Y=1,X,r,i)=c_k\) 的 SCAR 条件时，才有 \(P_k^{\mathrm{obs}}=P_{\mu_k}(X\mid Y=1)\)；此时非负 PU 风险为（Elkan and Noto 2008；Kiryo et al. 2017）

\[
\mathcal R_{\mathrm{nnPU}}^k=
\pi_k\,\mathbb E_{P_k^{\mathrm{obs}}}\ell(s_v,+1)
+\max\!\left\{0,\,
\mathbb E_{M_k}\ell(s_v,-1)
-\pi_k\,\mathbb E_{P_k^{\mathrm{obs}}}\ell(s_v,-1)\right\}.
\]

这里的边际项必须使用 \(M_k\)，不能用 \(S=0\) 条件集合替代；\(s_v=\operatorname{logit}(p_v)\)，正例条件均值按 \(\mu_k\) 权重在 \(S=1\) 中重新归一化。
若训练通过候选或邻居抽样近似这些期望，程序保存 inclusion probability 并使用 Horvitz--Thompson 权重，另报告权重截断前后的有效样本量。
主训练不把 mixture-proportion estimator 当作已识别真值，而以训练测度下的 \(q_k\) 为层级下界，预注册 \(\pi_k(m)=\min(1-10^{-4},m q_k)\)，主配置固定 \(m=1.5\)，并以 \(m\in\{1,2\}\) 各重训一个敏感性配置；重复值删除，三个配置不得按 outer-test 结果择优。
只有三种 prior 的确认性方向一致且 P17 的复标闸门通过，正文才讨论条件于 SCAR 的潜在概率；否则 \(p_v\) 始终称为 PU score。
KM2 仅在附录作诊断：从 \(\mu_k\) 分别有放回抽取至多 20,000 个 \(M_k\) 与 \(P_k^{\mathrm{obs}}\) 样本，使用 Ramaswamy et al.（2016）Algorithm 1 的 \(\epsilon=.04\)、\(\lambda_{UB}=10\)，把斜率阈值严格定义为 \(\nu=0.8\,s_{\mathrm{init}}+0.2\,s_{\mathrm{final}}\)，其中 \(s_{\mathrm{init}}\) 是 \(\lambda=1\) 处初始斜率、\(s_{\mathrm{final}}=\|\widehat\mu_{M_k}-\widehat\mu_{P_k^{\mathrm{obs}}}\|_{\mathcal H}\)，并在 \(\{0.1,0.316,1,3.16,10\}\) 倍训练中位距离的五个 Gaussian RBF 宽度中选择使该经验 RKHS 距离最大的核。
QP 固定为 CVXOPT 1.3.2，`abstol`、`reltol` 和 `feastol` 均为 \(10^{-7}\)，抽样种子为 11、23、37，按 \(\widehat\pi_k=1-1/\widehat\lambda_k\) 转回先验并报告三种子的分布；该结果不进入训练选择、Go/No-Go 或主张恢复。
批内排序辅助项使用上一轮停止梯度的 PU 后验给未标注节点分配负置信权重，不以单位权重强迫每个 observed-positive 超过全部未标注节点。
所有 prior 与 KM2 诊断共享同一 candidate manifest 和 outer split，避免用重新生成候选吸收假设变化。

对某个 outer-test fold \(o\) 产生层级 \(k\) 的 latent mapping 时，只使用其余四折至少 28 个复标 families 中由 seed 11 inner 模型为未参与自身训练的 family 产生的 OOF raw logits；若任务与层内单位的签名入选概率分别为 \(a_i\) 和 \(b_{iv\mid i,k,S}\)，则每个裁决单位先取得目标测度设计权重 \(\eta_{iv}^k=\mu_k(r,i,v)/(a_i b_{iv\mid i,k,S})\) 并在训练单位内作 Hájek 归一化，主映射以 weighted-Brier isotonic regression \(\widehat g_{o,k}=\arg\min_{g\uparrow,\,10^{-4}\leq g\leq1-10^{-4}}\sum_{(i,v)\in\mathcal A_{-o,k}}\bar\eta_{iv}^k[Y_{iv}^k-g(s_{iv}^{k,\mathrm{innerOOF}})]^2\) 由确定性 PAVA 拟合，随后冻结、分别作用于三个 outer-test checkpoints 的 raw logits 并平均 mapped probabilities；目标 fold 的复标只计算该冻结 ensemble mapping 的设计加权 Brier/ECE，绝不回流候选、网络、prior、来源 head、映射器或解码权重。
层级 \(k\) 只有在至少 25 个训练 families、\(\alpha_k\geq0.67\)、加权有效总样本量至少 200、裁决正例至少 50、且至少发现 20 个 \(S=0,Y=1\) 新正例时，才允许拟合和评价该层的 latent-\(Y\) mapping；门槛逐层执行，不能用 line 数量替 file/block 补足。
selection-propensity 只在 outer-training 裁决 \(Y=1\) 单位中，以同一 \(\bar\eta^k\) 最小化 ridge-logistic 损失 \(\sum_j\bar\eta_j^k\operatorname{BCE}(S_j,\sigma(\beta_0+\beta^\top z_j))+10^{-4}\|\beta\|_2^2\)，其中 \(z\) 固定为 log token 长度、候选初始名次百分位、节点类型、语言和 log repo 候选数且连续量只用该 outer-training 集标准化；\(S=1\) 与 \(S=0\) 各少于 20 时不作 SCAR 诊断，任一特征绝对标准化差异大于 0.10 即拒绝简单 SCAR，只有至少 90% 的设计加权 \(Y=1\) 位于 \(0.05\leq\widehat e_k(z)\leq0.95\)、overlap 权重 \(\eta_j^{\mathrm{ov}}\propto\eta_j\widehat e_j(1-\widehat e_j)\) 的最大归一化质量不超过 0.05 且 Kish 有效样本量至少 100 时，才以 \(\eta^{\mathrm{ov}}\) 重拟合同一 isotonic weighted-Brier 映射作为 overlap-population sensitivity；该敏感性不替换主设计权重映射，也不把 SCAR 或总体潜在概率升级为已识别。
即使没有观察到偏移，正文也只把 latent Brier/ECE 解释为条件于无假阳性、SCAR、不可约性、候选稳定与本复标协议的结果。
任一层未过门时，该层退回 observed-\(S\) AP、PU score 与设计加权复标误差；KM2 结果不参与门槛，且不得通过改阈值恢复潜在概率主张。

<!-- P18 --> 三类来源 head 使用相互隔离的数据入口。对每个 ContextBench outer fold，patch head 只读取 outer-training families 中能够从 base commit 唯一映射的 developer diff；outer-test patch 在上下文包和所有主指标冻结后才用于来源差异评价，且 patch 文件名、hunk 与测试结果从不进入候选、人工特征或人工损失。trajectory head 使用 SWE-Explore 冻结快照中的 848 个 issue、203 个仓库和 10 种语言，将 published core regions 投影为正，将 model-specific optional 与不完整日志按 P13 设为 unknown mask，不把成功轨迹读取解释为人类必需（Zhang et al. 2026b）。dependency head 使用 RepoExec 的 355 个唯一 Python 函数任务，三个 context-level views 按 repository、commit 与 function identifier 去重，查询为函数签名和 docstring，正例只来自参考解静态提取并随任务提供的 dependencies，解析或闭集责任按 P13 记录（Hai et al. 2025）。SWE-Explore 与 RepoExec 先删除同任一 ContextBench confirmatory outer-test family 重叠的仓库，再按 repo-family 以 70%、15% 和 15% 分成辅助训练、诊断和外测；辅助诊断不能替代人工 pilot/OOF 责任，外测也不产生人工 needed-context 结论。Agent Retrieval Bench 的 427 个样本与 base-commit corpora 完全不训练模型，其中 345 个 positives 评价四种工作流的文件检索和 8K budgeted yield，32 个 wrong-repository controls 报告误取，50 个 natural no-gold cases 评价选择性检索（Qin and Xie 2026）。ARB abstention 规则只在 P16 pilot positives 上以不超过 10% 的 false-abstention 率冻结；它没有见过 no-gold，因而 ARB 的 82 个 controls/natural no-gold 只检验分布外迁移，不能被称为已校准拒答。所有来源分别发布查询、事件闭集声明、unknown mask、投影成功率、family 重叠排除和最终分母，任何来源不足或映射失败只关闭对应 head 或外测，不用其他来源补成统一 gold。

<!-- P19 --> 实验按候选可达、层次表征、预算合成和行动传递四级开展，后一级不能替代前一级的失败诊断。本段检验前三级。候选层首先比较 BM25、冻结 dense retriever、reciprocal-rank fusion、CoRNStack retriever/reranker、RepoGraph 与 LocAgent，在同一 base commit、任务集合和 tokenizer budget 下重跑公开实现（Suresh et al. 2025；Ouyang et al. 2025；Chen et al. 2025）。ToolTrain、GraphLocator、RANGER、FastContext 与 CodeGrep 是更直接的训练型或 agentic 检索近邻；只有其公开 checkpoint/代码能在冻结容器中输出可映射的 file/range 且不读取 gold/patch 时才进入同预算结果表，否则在近邻边界表报告训练监督、可运行 benchmark、参数/工具预算、公开工件和缺失原因，不抄录作者论文数值（Ma et al. 2026；Liu et al. 2026；Shah et al. 2025；Zhang et al. 2026a；Chen et al. 2026）。候选受控层让未训练 hybrid score、独立 file/block/line heads、参数量匹配文本层次 Transformer、contains-only 图模型与完整模型读取完全相同的 candidate manifest 和 frozen embeddings。HiLoRM 的监督是 file/function/line fault-localization reward，只作为标签不同的正式近邻，不改称人工上下文基线（Zhang et al. 2025）。表征主指标是 P16 confirmatory OOF 上 repo 等权的 file、官方定义级 block 和 line AP，辅以 nDCG、至少一项与全部 gold recall、observed-\(S\) Brier/ECE 和父子违反率；后两项只表示发布协议标记的内部校准。latent-\(Y\) Brier/ECE 按层通过 P17 门槛后才报告。预算层在 2,048、4,096、8,192 和 16,384 个 patcher tokens 下比较原子覆盖 CP-SAT、line-score token greedy、窗口 density greedy 与层级排序后截断，统一以实际序列化 payload 计费，报告 gold-line coverage、全部 gold 覆盖任务率、gold-token precision、重复 payload、token、gap 和 wall-clock。8,192-token 全体确认任务的 OOF gold-line coverage 是预算主指标，其余预算形成资源响应曲线，所有表并列 candidate-reachable 子集和 oracle ceiling。只有模型在相同候选中改善表征，并在相同真实 token 成本下把改进传到 gold coverage，才进入 P20 的固定 patcher 行动检验。

<!-- P20 --> 行动传递采用 SWE-rebench 的持续任务管线形成时间外测，而不让已被 leaderboard 反复优化的 SWE-bench Verified 独自承担结论（Badertdinov et al. 2025）。P16 的 OOF 评价通过后，研究以全部 ContextBench 可用 families 和固定超参数重训三个最终图 checkpoints 与三个参数量匹配文本 checkpoints，各条件先平均三个 checkpoint score 再生成唯一上下文包；因此 checkpoint seed 是 ensemble 成分，不是额外 patch 试验。令所有 checkpoints、OOF calibrator、decoder、patch adapter、容器和分析代码签名日期为 \(D\)，时间窗口预先固定为 \([D,D+90\text{ days})\)。窗口关闭后先排除与全部主训练或辅助训练 repo-family 重叠的实例，再按稳定哈希取前 200 个 base commit 构建成功、gold patch 触发至少一个 fail-to-pass 且初始 pass-to-pass 全部通过的 Python 任务；不足 200 时使用全部合格项，不延窗或旧题回填，并撤销确认性行动主张。patcher 是冻结的 Agentless-compatible repair adapter：它以 Agentless 指定 commit 的 repair prompt 与 unified-diff parser 替换 localization 输入，只接收 issue、仓库树摘要和一个 8,192-token context pack，关闭搜索、定位、测试生成、补丁 reranking、执行反馈和交互工具（Xia et al. 2025）。生成模型固定为 Qwen2.5-Coder-32B-Instruct 的权重与 tokenizer revision，`temperature=0.2`、`top_p=0.95`、`max_new_tokens=4096`、每次只生成一个 diff，patch randomness 仅用 11、23、37 三个种子（Hui et al. 2024）。每任务比较图 CP-SAT 包、OOF 预先确定的最强参数量匹配非图包和冻结 BM25-dense fusion 包，三条件共享 prompt、序列化、tokenizer 与 patch seeds，形成恰好 \(200\times3\times3=1{,}800\) 次主 generation；不从三个 diff 中挑选最佳。每个 diff 只运行 SWE-rebench official evaluator，resolved 要求全部 fail-to-pass 与 pass-to-pass 通过，并报告 invalid diff、apply failure、timeout、输入/生成 token、GPU time、容器 CPU time和 resolved per 1K input tokens。抽样前 build failure 只进筛选日志；抽样后的共同镜像/evaluator 故障在严格 intention-to-evaluate 中对三条件均记 unresolved，并另报共同可评价分母，模型生成或补丁测试失败只记相应条件 unresolved。每次 generation 硬限 15 分钟，每次 evaluation 硬限 20 分钟；一项任务有 9 个配对 runs，串行计算上限为 315 run-minutes，不再称为“任务总计60分钟”，并行 wall-clock 另行记录。主资源为 1,800 次 generation、1,800 次首次 evaluation、500 A100-80GB hours 与 660 个 8-vCPU/16-GB container-hours，其中后两者含约 10% 的基础设施复跑储备且复跑原因/次数另记。触及任一上限时只保留稳定哈希顺序已完成的共同任务前缀，并把行动研究降为探索性；时间外设计减少直接调参但不证明基础模型从未见过仓库历史。

<!-- P21 --> 机制检验围绕人工测量、层次关系、来源分责和预算行动四个设计要求组织，而不把所有删除项堆成一张无责任的消融表。人工测量比较主 \(m=1.5\) nnPU、\(m=1,2\) prior sensitivity 和把未标注当负例的 BCE，并在 P17 的设计加权复标与可行 propensity sensitivity 上检查方向。层次部分比较独立三层 Bernoulli heads、条件链但删除 \(\mathcal L_{\mathrm{pos\text{-}child}}\)、完整 canonical 链和参数量匹配文本层次模型，评价 AP、条件校准、父子违反率与任务内 gold path 联合排名。来源部分从 human-only 逐一加入 patch、trajectory 与 dependency，再比较全部来源、打乱标签和错误并成单一 gold，并以 outer-training families 拟合 probe、outer-test OOF 表征报告四类来源 AUC 与 confusion。结构部分删除非 contains 边、只删 call/reference、同度随机重连和删除图层，以区分关系信息与参数容量。预算部分比较 P19 四个解码器，并删除 redundancy、以原始名次替 score 或放宽 gap，全部输出仍满足真实 token、原子去重与父 header 闭包。确认性只预注册三个对比：完整图模型相对参数量匹配文本模型的 confirmatory-OOF 三层平均 AP、原子覆盖 CP-SAT 相对 pilot-frozen 最强合法 greedy 的 8,192-token gold-line coverage，以及 SWE-rebench 图上下文相对最强非图上下文的 resolved。ContextBench 的确认性 full graph 与 parameter-matched text 条件在每任务先平均三个 checkpoint seeds，再在 repo 内平均 task、在 family 内平均 repo 并令 family 等权；P15 账本中的 prior、测量、层次、来源与额外结构机制配置只使用预注册种子 11 的 OOF 预测，并与 full graph 种子 11 在任何 post-hoc mapping 前的 raw marginals 配对比较，不作种子平均、也不在看到效应后选择性补跑，因而只承担机制或稳健性责任；行动实验已经把 checkpoint ensemble 成一个包，只先平均三个 patch-generation seeds，再按相同 family 层级聚合。95% 区间以 10,000 次 paired family-cluster bootstrap 的 percentile 区间计算，双侧 \(p\) 值以同一 family 统计量的 10,000 次预注册符号翻转分布计算，三个 \(p\) 值按 Holm 校正；节点、task、repo 和 seed 均不作为额外独立重复。若确认样本或行动样本少于 30 个独立 families，cluster 区间与 \(p\) 值只作描述，确认性门槛自动失败。resolved 另按每个 patch seed 报告共同可评价任务的配对胜负表与 McNemar 结果，但主推断仍是 family-cluster intention-to-evaluate 风险差；连续指标报告 family 均值差、中位数差和配对 rank-biserial correlation，不再使用忽略配对的 Cliff's delta。其余预算曲线、prior、propensity、source probes 与模块干预均报告 effect size 和区间但标为机制或稳健性。结果表依次呈现 candidate oracle、人工表征与条件校准、预算 coverage、固定 patcher resolved、来源与结构干预，使下游改善可回溯，也允许最终结果偶然持平时拒绝中间机制解释。

## 6 预期贡献、适用边界与立项闸门

<!-- P22 --> 本文的理论贡献首先在于把仓库上下文检索重新表述为任务表征的计算测量，并以表征理论区分信息可达、协议内测量忠实度、跨层关系忠实度和面向 Coding Agent 的行动效用。该表述不会把最终修改位置或成功轨迹访问直接等同于人工所需上下文，而使不同来源间的相合与冲突成为可观察的构念效度证据。方法贡献不是再次提出一种图 Transformer，而是把 ContextBench 人工 gold 在 file、本文投影 AST block 和 line 的 canonical 路径上写成多文件 Bernoulli 与父条件概率，结合 PU 边界、来源专属 heads 和零重复效用的预算集合解码，形成从构念到训练目标和行动集合的一致实现。经验贡献在于建立候选 oracle、盲复标、来源干预、中间表征、预算覆盖和固定 patcher 结果逐级相连的协议，使方法对最终修复的作用能够与候选遗漏、标签选择、求解 gap 和基础设施失败分开。对设计科学研究而言，该工件展示了如何把具有规范含义但不完备的人工判断转化为可训练表示，同时保留不可识别假设、行为标签差异和真实资源约束。实践上，发布的 candidate manifest、20M 至 30M 参数 checkpoint、source heads、calibrator、序列化 grammar 和 CP-SAT decoder 允许 Coding Agent 在不微调其 patcher 的情况下获得可审计的 token-budget context pack，并通过效用、成本和失败日志选择部署预算。这些贡献是否成立取决于 P21 的中间表征和行动结果同时提供证据，不能仅凭网络实现、工件发布或某一个 resolved 提升预先宣告。

<!-- P23 --> 本研究的首要边界来自测量本身。ContextBench `gold_context` spans 是特定标注协议下的人工判断，file 聚合和官方 definition-level block 对齐是同一 spans 的确定性评价视图，不是独立人工标签，三者都不能证明未标注代码无用或覆盖全部修复路径。nnPU 的潜在概率解释依赖无假阳性、SCAR、不可约性、候选稳定与预注册 prior；P17 只能发现部分可观察选择偏移，不能证明 SCAR，附录 KM2 也不能修复这一识别限制。冻结候选子图使候选外证据无法被模型恢复，因此 oracle ceiling 必须与每项结果并列。来源 heads 只学习 developer diff、SWE-Explore read events 与 RepoExec provided-dependency events，closed/open masks 和辅助迁移均不能证明它们共享人工构念。四层关系图依赖冻结 Tree-sitter 和静态 call/reference/test 边，对反射、动态绑定、生成代码、非标准构建与解析失败仓库覆盖有限。预算效用只对 line atom 覆盖给分，窗口规则、header 模板、tokenizer、相似度图和固定 patcher 共同限定最优集合，换成可自主搜索 Agent 可能改变机制。ContextBench 八种语言扩大表征范围，但确认性统计仍受独立 family 数约束，SWE-rebench 行动只覆盖可执行 Python 与一个 repair adapter。90 天新 issue 减少针对固定任务的调参，却不能证明基础模型未见过仓库历史。冻结 encoder 降低每 fit 成本但完整 OOF、prior、source 与结构干预仍要求 P15 的大规模本地训练资源；继续微调 encoder 必须作为资源更高的新工件独立评价。

<!-- P24 --> 在任何 confirmatory outer-fold gold 解封和 SWE-rebench 收集前，研究只用 P16 的 10 个 pilot families 执行一次签名 Go/No-Go，并冻结全部超参数、epoch、阈值和资源表。
若可用独立 families 少于 60、确认 folds 不能各含至少 10 个 families，或 P17 不能覆盖至少 35 个 families，则完整确认性设计停止。
候选生成器只有在 pilot 上同时达到 file 至少一项 gold 命中率 0.90、line micro gold coverage 0.80 和全部 spans 可达任务率 0.50 才进入主训练，否则课题缩为候选生成研究。
human gold 与 patch locus 的 median file-set Jaccard 低于 0.90 且平衡节点 source probe OOF AUC 高于 0.55，只被解释为两来源并非经验等同的最低检查而非构念效度证明；任一失败则撤销来源分责主张。
P12 的 \(m=1,1.5,2\) 三个 prior 若使确认性主要方向不一致，则保留 observed-\(S\) 排序而撤销 nnPU 机制与潜在概率贡献。
P17 的样本、逐层一致性、有效样本和新正例门槛逐层决定 latent-\(Y\) mapping，未过层级不得由其他层补足。
条件层次模型相对独立三层 heads 必须使 confirmatory-OOF family-mean 三层 AP 提高至少 0.01、任何层不下降超过 0.005，并使相应 observed-\(S\) Brier 至少降低 2%，否则删除层次机制主张。
完整图模型相对参数量匹配文本模型还须使三层 AP 提高至少 0.01 且 8,192-token gold-line coverage 提高至少 0.02，否则采用文本模型并撤销关系图必要性。
原子覆盖 CP-SAT 相对 pilot-frozen 最强合法 greedy 必须在相同真实 token 下提高至少 0.02 coverage，并使至少 95% 任务在主时限内 gap 不超过 5%，否则不单列预算优化贡献。
行动主张要求 200 个合格任务、至少 30 个独立 families、图上下文相对最强非图条件的 intention-to-evaluate resolved 风险差至少 0.02、family-cluster 95% 区间下界高于 0，且不少于 55% families 的三 patch-seed 平均差为正；任务/family不足、资源触顶或任一条件失败均降为探索性。
任何来源 head 若使人工三层 AP 下降超过 0.005 或 observed-\(S\) Brier 恶化超过 2% 即从最终 ensemble 删除，即使它改善自身事件。
P15 的 14,080 A100-hour 训练上限、P20 的 500 A100-hour 行动上限和全部统计代码在 pilot 首次运行前签名，未获资源或未过门时不得在 OOF/test 后降门槛。

## 结论

<!-- P25 --> 本文把 Coding Agent 的仓库上下文选择界定为人类协议所需证据的条件层次测量与预算集合决策，而不把补丁位置、代理读取或参考解依赖混成同一监督信号。研究据此构建冻结候选生成器、file 到官方 definition-level block 再到 line atom 的条件层次网络、来源专属辅助 heads，以及按原子覆盖去重效用和真实 token 成本的 CP-SAT 解码器。经验方案以隔离 pilot 冻结设计，再沿 family-grouped outer OOF 的候选可达性、协议表征、逐层盲复标、预算覆盖和时间外固定 patcher 行动递进检验，使中间质量与最终修复效用可分别成立或被否定。只有 family、prior、复标、层次、预算、资源和行动闸门同时通过，相应完整机制链才成立；任一环节失败都触发预先规定的缩题或主张撤销。
