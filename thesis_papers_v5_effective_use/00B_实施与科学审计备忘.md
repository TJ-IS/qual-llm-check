# 实施与科学审计备忘

本文件承接不会进入三篇论文主叙事的实施约束、识别风险、资源估计和停止条件。论文正文只保留理解研究对象、算法和证据所必需的正面定义。

## 1. 系列独立性

研究一的观察单位是任务、证据区域与冻结代理轨迹，训练对象是访问、忠实表征和行动使用的有序机制。研究二的观察单位是任务与首次修改前的一次性证据集合，训练对象是个体效用、交互效用和集合充分性。研究三的观察单位是已有补丁后的验证状态转移，训练对象是实验结果世界模型和验证政策。三篇不得共享 checkpoint、校准器、干预标签或主结果；公共解析器、执行容器和冻结编码器版本可以共享，但须记录版本。

研究二不学习停止或多轮搜索。研究三不选择静态代码区域，也不构造首次修改前的上下文。研究一只解释机制，不把研究二或研究三的决策器作为必要下游组件。

## 2. 研究一的识别风险

轨迹中出现某段代码只能识别已观察访问，不能单独识别透明取得、忠实表征或实际使用。透明取得还必须记录取得尝试是否受到错误、截断、延迟、格式和不可寻址界面的阻碍。忠实表征由结构化表征卡中可外部核验的实体、关系和行为命题定义，并同时承担语义正确性与任务充分性；行动使用必须由保留、删除和等长度无关替代的配对干预定义。模型注意权重、自然语言自述和评论后的时间相关性均不能充当机制真值。

表征卡必须由冻结代理在取得后的测量副本中自行提交，随后销毁副本；原行动分支不得看见卡片或评分。规范化程序只能验证 schema、规范地址并按代理原句拆分，不得替代理新增、改写或推断知识。训练 checkpoint 的前向输入只能是部署可见轨迹、代理原始卡片和仓库图，人工命题裁决、干预终点及终端测试只作为监督或留出评价。行动使用是区组层干预效应，不得把同一区组的多种子或三条干预臂伪装成独立自然样本。

正式扩展前先检查三项门槛：结构化命题能否由自动规则与盲复核稳定标注；证据干预是否在控制访问后产生可重复的表征或行动变化；三个有序状态是否保留可区分的误差与增量解释。若三项不能同时成立，研究一应收缩为可观察的证据干预研究，而不解释潜在机制。

## 3. 研究二的识别风险

金标文件或补丁重合只能承担辅助相关性，不能定义集合互补性。互补与替代标签必须来自同一任务、同一冻结修复器和同一预算下的集合干预。冻结修复器在生成补丁前还须输出结构化任务状态卡，由独立协议评价完整性、意义性、清晰性与正确性；集合表征头与行动结果头分别承担中间构念和终端结果，避免用测试通过偷换表征忠实度。结果可见前的 D-最优设计须保证主要个体与二阶列在有限支持域中可估计，未执行集合不填补结果。二阶投影只作设计域内的可解释分解，完整 Set Transformer 学习整个 $V_F(S)$，经同一 outcome-free 投影算子得到的 $r_F$ 只称超出已列二阶项的剩余非加性结构。若盲复核无法形成稳定的任务状态卡标签，绝大多数可估计二阶项接近零，或集合模型的收益完全由单项召回解释，研究二应并入普通静态上下文研究。

同任务设计矩阵不得以卡片评分、测试结果或参考补丁选择列。候选对集合、每任务最大 bundle 数和无法达到满秩时的降级责任必须在任何结果可见前冻结；无法识别的主效应或交互只退出效应监督，不能用模型补值。可微松弛只服务训练，部署解码还必须给出严格满足 token 与类型约束的离散算法、确定性裁决和运行时上界。

正式集合干预前先做跨仓测量 pilot，至少记录四维评分的 ICC 与加权 $\kappa$、单张任务状态卡人工工时、unknown 比例、充分义务束数量、设计矩阵条件数以及每任务可识别主效应和二阶项比例。人工成本不足时优先缩小但保留多仓库的高质量真实任务样本，或把未达识别条件的任务降为 bundle-level 监督；不能用首补丁成功、参考补丁重合或模型自评分替代忠实度标签。

## 4. 研究三的识别风险

验证政策只接收部署时可见的补丁、测试依赖、既有执行结果和剩余预算。隐藏测试、金补丁和未来轨迹只形成终端评价或训练标签。离线策略评价必须覆盖实际在线动作；世界模型校准、行为政策支持和真实在线回放缺一不可。若等成本条件下反馈政策不优于固定失败测试优先、覆盖贪心和静态不确定性策略，序贯信息价值不成立。

补丁正确性、故障解释、观测 likelihood、belief 更新和信息增益必须属于同一个归一化联合概率模型。若使用互斥潜状态，世界模型直接学习条件 likelihood 并作归一化 Bayes 更新；若允许并发故障，则须明确 factor graph 与正确性事件的逻辑关系。不得在 Bayes log-odds 后加入未受一致性约束的任意神经残差，也不得用彼此独立的 Bernoulli 边际计算声称为联合诊断价值。策略训练以一个预注册的 distributional CQL 主方法为准，世界模型仅承担观测、成本与 belief 更新，不再形成第二套 planner。

## 5. 数据与跨篇隔离

三篇共同建立只增不改的数据登记表，键包括规范上游仓库、仓库家族、基础提交和规范任务散列。其字段、开工门和未分配状态见 `00D_master_split_registry.md`；共同构念的不变定义、研究专属载体和不可复用标签见 `00E_跨篇构念与测量词典.md`。任一篇的确认性或时间外测试仓库家族不能进入另一篇的训练、开发或校准。相同仓库家族上的不同端点只能算相关重复测量，不能在系列总结中写成独立复现。

研究一和研究二可共享执行基础设施，但必须使用互斥任务或仓库家族形成主结论。研究三优先使用具有稳定运行时反馈的测试环境，其主场不与前两篇的静态上下文评价重合。

登记表的规范键为 `(canonical_upstream, repository_family, base_commit, normalized_issue_hash)`，并记录数据版本、首次公开时间、论文编号、角色、容器与预处理器哈希以及排除理由。fork、mirror、同源包、共享提交祖先和源码近重复项目先合并为 repository family，再进行任何任务划分。角色至少区分 pilot、train、development、calibration、confirmatory 和 temporal-test，变更只允许追加新记录并保留旧值。任何一篇进入 confirmatory 或 temporal-test 的 family 立即成为系列级 sealed family，不能在另一篇进入训练、开发、校准或辅助头训练；必须复用的项目标记为 shared-development，只能提供相关端点，不能计作独立复现。checkpoint、calibrator、任务卡、bundle 结果、轨迹、补丁、测试及 outcome 不跨篇传递，公共解析器、冻结基础编码器和容器运行器只按版本化基础设施共享。

## 6. 资源分阶段

研究一先以小规模配对干预确认标签可识别，再扩大轨迹与干预数据。研究二先以少量任务和完整设计矩阵确认集合交互存在，再扩展集合运行。研究三先收集固定策略轨迹并检验世界模型校准和动作支持，再进行真实在线政策评价。模型训练资源不是主要风险；代理运行、容器执行和人工作业才是主要成本。

任何全文资源数字都须由实测 pilot 吞吐外推。未获得相应算力、容器和人工复核承诺时，不把保守绝对上界写成预计用量，也不以参数规模替代科学贡献。

研究一的资源 pilot 使用至少 8 个互斥 repository families、16 个任务、2 个冻结 agent、每个 task–agent 2 个证据区和 5 个 seed。由此得到 64 个 task–agent–evidence 超级区组和 `3×5×64=960` 次 S/W/R 受控运行。pilot 必须实测 24GB 单卡配置的峰值显存、每秒样本、容器小时、每张双 card 的双人评分分钟、裁决率、存储和三条件失败率；峰值显存超过 22GB、OOM 非零、有效累积 batch 低于 24 或三条件可重放率低于 90% 时先缩图宽度、LoRA 秩或任务范围。三条件完整交叉只识别受控算法效应，不能凭资源规模改称随机分派。

研究二的运行量为 `R_run=Σ_t M_t K_seed`，两名主评分者形成 `R_rating=2R_run`，分歧裁决、容器重跑和存储另计。正式设计前先做 12—20 个真实任务的支持集与标注 pilot，并冻结任务数、seed 数、评分人时、失败率、条件数和可识别效应比例。当 `M=64`、`K_seed=2` 时，100 个任务已经对应 12,800 次修复器与容器运行、25,600 份主评分，200 个任务对应 25,600 次运行、51,200 份主评分；这些数是规划量级而非预先承诺的正式规模。若 `M_t≥max(2p_t,p_t+32)`、四格频数、评分稳定性或人工资源不能同时满足，应减少候选对或确认任务，不得把未识别效应交给神经网络补值。

研究二在任何 bundle outcome 解封前由构建脚本输出逐模块参数账，至少区分冻结 GraphCodeBERT、初始关系投影、$V_F$ 超图层与 Set Transformer、四个有序头、投影提议层、独立 $V_Y$ 路径和解码层，并保存 `requires_grad` 清单。12—20 任务 pilot 同时在单张 24GB GPU 上运行一次完整 $V_F$ 拟合与一次 $V_Y$ 拟合，记录可训练参数、峰值显存、每 epoch 时间、收敛 epoch、checkpoint 数和超参数候选数；峰值超过 22GB、单阶段超过 24 小时或完整搜索投影超过书面 GPU 上限时，先减小隐藏维度、关系层数或搜索网格，不能靠默认增加多卡维持正文规模。

研究三的 pilot 使用至少 12 个互斥 repository families，每个 family 2 个任务，每任务 2 个初始补丁 seed、每 seed 8 个 behavior episodes、最长 8 个动作并最多一次返修，共 384 episodes 和至多 3,072 个轨迹步。terminal evaluator 以 `(task, environment, patch_hash, evaluator_hash)` 去重缓存。world 与 policy 各自在单张至少 24GB GPU 上从零训练；任一阶段峰值超过 22GB 或超过 24 小时先缩模型。正式资源只按 pilot 的上侧 90% 吞吐外推行为轨迹、唯一补丁终端评价、W3b 的 `task×patch-seed×method×budget×repeat` episodes、逐步日志、容器小时、GPU 小时、存储和 manifest 三人复核。manifest 覆盖低于 95%、weighted kappa 低于 0.80、OTHER 高于 20%、清洁容器成功率低于 95% 或关键行为支持层未达门槛时，先缩语言或动作范围，不进入确认性在线评价。

研发顺序采用便宜致命门优先，而不是按论文编号顺序烧资源。先完成全局 registry 和公共 manifest，再并行跑研究一的数据与标注门、研究二的 12—20 任务设计门和研究三的 384-episode 资源与支持门；只有通过门槛才分别扩大 checkpoint 训练。论文呈现仍按机制测量、行动前静态组合、行动后反馈验证排列，研发开工顺序不构成 checkpoint 依赖。

## 7. 近邻与停止条件

研究一必须正面对照 RepoExec、SWE-Explore 及关于依赖使用和行动变化的研究；研究二必须正面对照 GNNContext、Repoformer、RLCoder、ProCC、RepoShapley 和集合上下文选择方法，尤其检验真实 bundle 干预与高阶集合充分性是否超出 coalition attribution；研究三必须正面对照交互调试、测试优先级、SWE-World、RETRACE 与通用 Agent harness offline-RL 控制器。研究三只有在 typed runtime experiment、显式反馈世界模型、真实执行标签和等成本在线实验取得同时成立时，才与通用 OBSERVE/CHECK/REVISE/SUBMIT 控制分开。相关工作比较以决策时点、标签、动作和终端责任为轴，不以组件名称制造差异。

FastContext（arXiv:2606.14066）当前官方版本已于 2026 年 6 月 30 日因产品知识产权原因撤回，只能作为竞争方向警戒，不能承担正式近邻证据、稳定基线或论文主张锚点。SWE-Explore 当前未撤回，可以在明确其成功轨迹标签责任后保留。

若正式或同期工作已经同时覆盖相同观察单位、同类干预标签、相同决策动作和相同终端结果，则停止用网络组件叠加维持表面差异，重新评估题目。
