# 受限计算下 Coding Agent 的仓库表征有效使用研究

## 1. 系列共同问题

Coding Agent 可以访问规模不断扩大的代码仓库、测试系统与运行时工具，但访问更多信息并不必然带来更好的软件行动。仓库信息只有经过不受工具表面结构阻碍的取得、形成忠实的任务表征并被用于修改与验证，才会转化为软件行动绩效。本系列据此研究一个共同问题：在计算资源有限的条件下，Coding Agent 如何形成并有效使用支持软件行动的仓库表征？

这一问题以 Burton-Jones and Grange（2013）的有效使用理论为共同理论起点。该理论将有效使用分为透明交互、表征忠实度和知情行动三个维度。应用到 Coding Agent，三个维度分别对应代理能否在工具界面、截断和错误等表面约束下无阻地取得仓库表征，取得的表征是否在语义上正确且对当前任务充分，以及代理是否基于该表征采取改善软件状态的行动。系列的三个研究由同一机制连接，但各自具有独立的观察单位、训练标签、算法工件和经验结果。

## 2. 四套系列方案的竞争结果

### 方案 A：有效使用机制、静态证据组合与反馈验证

研究一识别仓库证据由透明取得转化为忠实表征和知情行动的过程，训练有序多任务图网络。研究二面向首次修改前的静态决策，训练能够识别证据互补性与集合充分性的上下文组合模型。研究三面向初始补丁形成后的动态决策，训练运行时实验世界模型和反馈自适应验证策略。三篇分别回答机制、行动前配置和行动后验证，删除任意一篇后其余两篇仍可独立成立。

### 方案 B：当前正确性与未来可变更性

该方案拟研究未来变化选择权、保持可变更性的补丁生成和重构投资时机。其理论张力清楚，但 CodeThread 已直接研究人类与代理中间实现对后续任务的影响，MaintainCoder 已研究动态需求下的可维护代码生成，SWE-Chain、SWE-CI、SWE-EVO 与 SlopCodeBench 又覆盖了连续软件演化。历史提交还只提供一条实际未来路径，不能识别替代补丁面对其他可能未来需求的反事实表现。因此，该方向至多适合合并为一篇多未来分支的补丁学习论文，不适合作为三篇系列。

### 方案 C：测试诊断性、批量测试组合与序贯测试选择

该方案可形成完整的候选补丁与测试结果矩阵，但三个研究共享同一输入矩阵、标签、世界模型和终端决策。批量测试组合是序贯测试选择在空历史下的特例，测试诊断性又是同一世界模型的中间量。B4、CodeT、TC-Bench 和传统补丁验证研究已经覆盖完整矩阵、贝叶斯选择和测试优先级。把该方向拆成三篇会构成明显切片，因此只保留其序贯部分，作为方案 A 的第三项研究。

### 方案 D：有限人类评审注意力与人机互补

该方案拟研究后果性评审位置、人机比较优势路由和个性化证据呈现。其组织问题很强，但第一项研究已经接近既有的评论采纳与后续代码变更研究，后两项研究又需要同一 concern 随机分派给多人和多种代理，以及大规模重复测量的人类证据呈现实验。AIDev 与 c-CRAB 提供重要观察数据，却不提供这些反事实结果。把观察性采纳记录直接当成注意力的因果作用会混入原有修改计划、并发评论和持续集成反馈。该方向因此不进入本系列；其中人机比较优势路由与序贯证据呈现可在未来合并为一篇需要专门人类实验的评审编排论文。

### 冻结选择

系列采用方案 A。旧版 DCCP、TSMI、PVStop、HERA、TEGRA、测试矩阵方案和评审注意力方案均不作为新论文的默认构件。若后续实现需要其中的解析器、候选生成器或执行工具，它们只能作为公共基础设施或比较方法出现。

## 3. 研究一：仓库证据从透明取得到行动的有效使用机制

### 研究问题

在仓库级软件修改中，代码证据在什么条件下由可取得的信息转化为忠实的任务表征，并进一步成为可验证软件行动的依据？

### 理论对象与可计算表示

研究一把有效使用写成取得选择 $Q$、透明取得 $T$、当前尝试的增量忠实度 $\Delta F$、累计任务忠实度 $F^{task}$ 和知情行动 $U$。$T$ 由返回覆盖、截断、错误、延迟和结构化可寻址性共同定义，观察到的访问为 $A=QT$；$\Delta F$ 只评价能够溯源到当前返回跨度与哈希的新命题，因此受当前 $T$ 约束；$F^{task}$ 汇总代理此前全部有效来源形成的任务表征，不因一次取得失败而被清空。$U$ 由原始证据、空返回和等长无关内容三种受控运行的行动与软件状态差值定义，使证据特异作用、一般内容作用和一般刺激作用能够分开。

### 算法工件

输入包括任务描述、候选证据、取得事件与工具返回、仓库异构关系图、代理在隔离测量副本中自行提交的增量卡与任务卡，以及分叉前的部署可见状态。冻结 GraphCodeBERT 基座与可训练 LoRA 产生任务—代码表示，类型化图网络传播调用、引用、包含、测试覆盖和配置关系；Q/T 头、双忠实度头和条件响应头分别预测取得过程、两种忠实度及 S/W/R 下的软件行动结果，独立行动探针只在事后完整轨迹上评价行动表示。训练目标由图结构保持、Q/T、双 F、有序命题匹配、三种受控差值、联合机制和终端软件价值损失组成。最终工件是可本地训练的 EUMN 主 checkpoint、动态仓库节点指针和独立行动探针。

### 标签与证据

透明取得标签来自取得尝试、工具返回、错误、截断、延迟、返回跨度和哈希。增量忠实度要求卡片命题能够溯源到当前返回，累计任务忠实度则评价代理全部既有来源形成的实体、关系、行为和约束是否完整、清晰、正确且对任务有意义。S/W/R 在同一 seed 前缀上完全交叉运行，$S-R$ 表示证据特异差异，$S-W$ 表示总内容差异，$R-W$ 表示一般内容刺激；它们是受控算法效应，不冒充随机处理分派。主实证分别检验 Q/T、双 F、三种行动差值、动态节点指针、联合机制标签和最终软件状态。

## 4. 研究二：预算约束下互补性代码证据组合

### 研究问题

在首次修改前的固定上下文预算下，Coding Agent 如何选择能够共同形成忠实任务表征的代码证据集合？

### 理论对象与可计算表示

单条证据的相关性不能说明一组证据能否共同表示修改所需的实体、行为和约束。研究二将表征忠实度分解为个体证据效用、证据间互补或替代关系以及集合充分性。它由此把静态上下文构造从逐项排序转化为集合级决策。

### 算法工件

任务编码器和仓库超图编码器表示文件、定义块、测试、配置与文档节点。四个有序头形成唯一忠实度 $V_F$；在结果可见前构造的 D-最优有限支持域上，link-scale 投影给出个体项 $u$、二阶项 $c$ 和相对于同一设计域的剩余非加性结构 $r_F$。每个支持集 bundle 与全部预注册 seed 完全交叉运行，集合网络学习完整 $V_F(S)$，确定性预算解码器在 token 与类型约束下输出一次性证据包。隔离的 $V_Y$ 路径只预测首补丁结果，不向忠实度路径回传梯度，也不参与部署解码。最终工件是忠实度集合 checkpoint、结果证据 checkpoint 与可复算预算解码器。

### 标签与证据

集合主标签来自固定修复器在生成补丁前提交的任务状态卡，由盲评分协议分别评价完整性、意义性、清晰性和正确性；这四项的固定聚合定义唯一 $V_F$。$u$ 与 $c$ 是预注册 D-最优支持域上的受控投影系数，不被解释为全部可行集合总体中的固有因果效应；$r_F$ 只表示超出所列二阶列的设计域剩余非加性结构。公开测试、回归和首补丁结果只训练隔离的 $V_Y$ 并检验忠实度能否外化为行动结果，参考补丁或黄金跨度只作辅助诊断。主实证检验卡片测量、支持域效应恢复、留出 bundle 非加性、等预算忠实度以及独立终端结果。

## 5. 研究三：反馈驱动的运行时验证实验选择

### 研究问题

当 Coding Agent 已形成初始补丁时，它如何利用已观察的运行时结果，依次选择最有价值的验证实验，并在有限预算内形成可接受的软件行动证据？

### 理论对象与可计算表示

初始补丁改变了研究对象。此时代理需要取得的不是更多静态代码，而是能够区分故障解释和补丁正确性的运行时证据。每项测试、覆盖切片或跟踪实验的价值取决于当前补丁、既有观察和剩余预算。研究三因此将知情行动写成随反馈更新的补丁信念、实验结果分布、实验成本和未来验证价值。

### 算法工件

关系编码器表示任务、补丁、测试依赖、覆盖和运行轨迹。世界模型在 evaluator-defined 动态终端诊断结果集上学习 categorical prior，以及 masked failure、coverage 与 trace bitset 的归一化条件 likelihood，并用同一联合分布执行 Bayes belief 更新与信息增益计算；不以诊断类别为条件的成本分位数头直接预测动作成本。唯一主策略是带均值与下尾保守正则、单调分位数头和支持门的 distributional CQL，它估计 EXECUTE、RETURN_TO_EDIT、SUBMIT 与 ABSTAIN 的长期价值；世界模型不充当第二个 planner，策略也不生成补丁。最终工件是独立的 AVEP world checkpoint、policy checkpoint、evaluator manifest 和 support gate。

### 标签与证据

标签全部来自真实执行，包括退出状态、失败测试、覆盖 bitset、trace、耗时、返修后补丁和 episode 结束后的终端 evaluator 结果。evaluator-only manifest 在结果前冻结终端测试到任务义务、相对补丁切片和诊断 family 的映射，策略只见部署可见的中间运行结果。分层全支持行为策略生成离线轨迹，关系状态距离、最小样本、propensity、最大权重与有效样本量共同形成支持门；确认性证据来自未见 repository families 上的等端到端墙钟在线 rollout。主实证分别检验 likelihood、belief、信息增益、动作价值分布、支持边界、反馈适应与最终错误提交风险。

## 6. 系列关系

研究一解释仓库表征如何成为行动依据，并给出两条供后续研究实例化而不传递数据或 checkpoint 的设计命题。第一，行动前的信息配置应优化外部测得的表征忠实度，不能用补丁成败替代中间构念；研究二据此学习一次性集合忠实度与预算解码。第二，行动后的信息系统应让真实反馈分别改变任务表征和纠正行动，并同时提供中间与终端证据；研究三据此学习运行时 likelihood、belief 与风险敏感策略。三篇共享有效使用理论和软件行动结果，但观察单位、标签、主模型与决策动作均不同。

| 研究 | 观察单位 | 主训练标签 | 主算法动作 | 独立工件 | 不包含的另篇对象 |
|---|---|---|---|---|---|
| 一 | attempt/evidence 超级区组 | Q/T、增量与累计 F、S/W/R 行动差值 | 测量有效使用机制与节点级行动响应 | EUMN checkpoint 与行动探针 | 不输出预算证据包，不选择运行时实验 |
| 二 | task–bundle–seed | 四维卡片忠实度、支持域投影、隔离首补丁结果 | 首次修改前一次性预算集合 | C4 忠实度/结果 checkpoints 与解码器 | 不测取得透明性，不学习多轮搜索或停止 |
| 三 | patch-state–typed-experiment transition | 真实观测 likelihood、终端诊断结果、成本与回报 | 运行实验、返修、提交或转交 | AVEP world/policy checkpoints | 不选择静态代码证据，不构造首次修改前上下文 |

## 7. 逐段双 ISR 写作协议

每写完一个正文段落，立即完成一次独立回读并记录在对应审计文件中。回读必须读取 ACAA 与 DSDL 原文的对应物理位置，而不是沿用旧审计摘要。每个审计块包含六项：正文段落编号、论文位置与唯一目标效果、ACAA 对应行及句子功能、DSDL 对应行及句子功能、新段逐句功能、来源没有而新段出现的额外功能及处置。

对位判断关注修辞效果。摘要遵循重要现象、具体失败机制、理论构念、专门机制和经验责任的顺序；引言依次建立结果变量、现实后果、现有计算失效、理论桥梁、方法挑战、研究问题、算法回应和证据责任；理论段采用理论命题、情境过程、潜变量和设计要求的顺序；方法构件采用输入、旧计算的具体失效、新公式、参数语义和可观察责任的顺序；结果段采用观察模式、算法机制和理论含义的顺序。

回读不是为每句话寻找辩护。若新段出现来源对应位置没有的资源账、撤题条件、实现哈希、审计说明、首创排除或多项边界清单，应将其移入实施备忘或删除。正文中的数据切分、可见性和识别条件用正面定义表达，项目风险与资源门单独写入 `00B_实施与科学审计备忘.md`。
