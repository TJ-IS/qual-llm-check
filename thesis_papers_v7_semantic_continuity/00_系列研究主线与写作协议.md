# 自主数据流水线构造与演化中的语义连续性：系列主线与写作协议

## 一、系列总问题

本系列研究自主编码代理构造、修改与运行数据流水线时的**语义连续性**。语义连续性是指：数据从源端经过转换节点、代码版本与时间窗口后，仍保持任务所要求的对象总体、记录粒度、连接倍数、缺失含义与时间可用性；当这些含义无法确定时，系统必须把不确定性显式带入质量判断与行动，而不能以“代码可运行、schema 匹配、测试为绿”替代语义正确。

系列共同张力是**快速生成和持续供数**与**保持可用于下游决策的业务含义**之间的平衡。编码代理容易优化可见的编译、schema、行数与终端测试，却可能生成仍可运行的静默语义失真。本系列据此提出总研究问题：在有限计算、有限反馈和持续上游变化下，如何测量、生成并动态维持自主数据流水线的语义连续性？

## 二、共同理论与计算对象

系列以表征理论中的 representational fidelity、informed action 与 disturbance–corrective action 链为 IS 桥梁，以 rule-based data-quality measurement under uncertainty 为主要计算理论。原理论多讨论人使用信息系统；本系列检验其中“表征忠实度—行动—环境扰动”机制能否扩展到自主编码工件，不把代理拟人化，也不把理论名称直接等同于神经网络变量。

共享语义契约由五个家族构成：

\[
\mathcal C=(\text{population},\text{grain},\text{join multiplicity},\text{missingness meaning},\text{time}),
\]

其中 time 区分 event time、valid time 与 availability time。质量规则被分解成谓词集合 \(P\)，节点—谓词—时间状态写为

\[
Z\in[0,1]^{|V|\times |P|\times T},
\]

相应的不确定性写为 \(U\in\mathbb R_{+}^{|V|\times |P|\times T}\)。静态节点—谓词 evaluator 真值记为 \(Q\)，论文三把随环境转移的同类隐藏动态真值另记为 \(Y_t\)；适用性与严重度记为 \(A,S\)。论文一还以 \(E_t\) 表示当前反馈在下一次编辑前是否可见、以 \(O_t^m=\max_{T_m^{on}\le u\le t}E_u\) 表示当前违例 spell 是否曾经曝光；同一 spell 的历史曝光保留，而纠正后再次出现的新 spell 从 \(O^{m+1}=0\) 重新计量。不得把瞬时可见、spell-local 历史曝光、预测分数 \(Z\) 与隐藏真值 \(Q/Y\) 混写。`U` 表示共同的不确定性责任，但各篇估计器和量纲可以不同，必须在各自 measurement system 内校准而不能跨篇直接比较。单调 capacity \(\kappa:2^P\rightarrow S\) 把被满足的谓词集合映射到有序质量水平；谓词分解决定图结构和 proof obligations，不确定性决定概率状态和 proper loss，质量阈值决定动作可行域与风险约束。

五类契约的操作化责任如下：population 比较预期实体键集合与实际集合；grain 检查声明键、函数依赖与聚合层级；join multiplicity 比较每个来源 provenance token 的实际复制数与允许倍数；missingness meaning 区分 observed、structural-NA、unknown、not-yet-available 与 imputed；time 检查 event/valid/availability-time 的顺序与区间约束。隐藏 evaluator 可使用 shadow provenance 与 reason tags，训练和部署输入不得读取未来窗口、隐藏契约答案或终端评测内容。

## 三、三篇研究的递进与独立性

### 研究一：语义可观测债务与失真传播

研究一回答机制问题：在编码代理生成多步数据转换时，三种完整反馈制度如何改变尚未暴露语义违例的累积、传播、掩蔽与纠正？随机化与因果单位是完整 episode，operator/edit transition 是其中的重复测量。三种处理分别为首个端到端候选后的 terminal feedback、阶段级 syntax/schema/runtime feedback、阶段级 semantic counterexample 与 provenance feedback；主估计量是阶段技术制度相对 terminal 制度的总差异，以及在相同阶段放置下语义—来源反馈相对技术反馈的增量，不把三臂误写成可分别识别深度和位置的二因子实验。独立工件 `SC-Prop-18M` 是 18,017,557 参数的 temporal heterogeneous GNN；它分开输出节点契约预测、同节点局部事件、受来源路径约束的跨节点传播事件、发现/纠正离散竞争风险及两项处理前条件制度效应，不生成代码、不选择反馈或运行政策。

### 研究二：语义契约携带式数据流水线生成

研究二回答固定快照下的静态生成问题：在语义义务可能部分可识别且可存在多种合法解释的条件下，契约状态真正反馈进解码过程的训练能否生成保持五类业务含义的数据流水线修改？观察单位是 `repo issue + fixed data snapshot → terminal patch/unsupported/abstain`。主域限定为由完整 EBNF 与 typed AST 封闭描述的 SQL/dbt relational subset 和 DataFrame DSL；`typed IR + typed slots + backend version` 由确定编译器实例化，域外请求必须返回 unsupported 或 abstain。生成期只把模型预测的连续契约/义务状态作为下一节点的 attention 输入，并以结构类型作 hard mask；独立执行器只在完整候选编译后检验可执行义务。确认性成功要求 ordinary tests 全部通过，并存在至少一个由独立证据完全识别的可接受 bundle，其全部 necessary leaves 均由外部执行器证明；bundle 交集只描述歧义而不作弱化 gate。独立工件 `SC-Coder-7B` 使用冻结 Qwen2.5-Coder-7B 主干、100,925,440 个 LoRA 参数和 1,857,797 个辅助参数，共 102,783,237 个可训练参数，以及 contract-state recurrent decoder 与 variable-obligation proof heads；它不处理外生时间变化，也不加载研究一权重。

### 研究三：上游语义演化下的风险敏感连续性控制

研究三回答只有真实状态转移才产生的动态问题：当上游 population、grain、join、missingness 或时间含义沿真实时间改变时，学习政策如何在固定事件窗口内权衡部署可见完整轨迹损害、其上尾严重损害、数据新鲜度、时延与人工成本？隐藏语义真值只监督世界模型并检验外部语义连续性，不进入策略回执、Bellman 标签或风险目标。观察单位是 `真实上游变化 event cluster × downstream pipeline × event window`，同一事件下的 pipeline、动作和种子是组内重复，统计推断以真实事件 cluster 为最高独立单位。独立工件 `SC-Guard-40M` 共 40,108,032 个可训练参数，由 temporal graph world model 与以累计损害、时刻和一次选定的 Rockafellar--Uryasev 阈值增广的标量 IQL policy 构成；候选条件化 actor 对 accept、contract-version route、quarantine、rollback、bounded patch-migrate 与 escalate 的参数化具体 ID 逐项评分，不自由生成代码，也不加载前两篇权重。

三篇的关系是“机制识别—固定状态设计—外部状态转移使静态设计失效后的动态决策”，而不是端到端系统的三个模块。它们仅共享契约定义、parser、resolver、container runner 与 evaluator schema；训练单位、标签、损失、checkpoint、动作空间和确认性样本均独立。删除任何一篇后，另两篇仍须能够单独训练、评价和投稿。

## 四、正文论证结构

每篇正文沿用而不照抄两篇 ISR 的功能顺序：场景价值与决策后果；直觉方案及其失效；理论构念与可计算冲突；研究问题；理论对象到专用张量、算子和损失的一一映射；数据、识别和评价；贡献、局限与结论。引言不先堆架构，方法段不重新发明理论，实验设计不宣称尚未得到的结果。

正文不得使用 `<!-- P -->` 或其他隐藏段落标记。段落定位由审计文件记录“章节—顺序—开头短语”，正文保持正常论文形态。实施门槛、资源签名、撤题条件、跨篇治理和内部审计语言放入 `00B_实施与科学审计备忘.md`，不得侵入三篇正文。

## 五、引文硬约束

每篇正文的引文句比例不得低于 20%，作者—年份引用组不得低于每百句 25 组；引言引文句目标不低于 30%，文献综述不低于 55%且不低于每百句 60 组，理论与设计理据不少于 25%（25%–40%是常见目标区间而非上限，超过时须逐句证明定义、冲突或设计来源责任），方法不少于 10%。每篇使用 65–85 篇独立文献，正文实际使用率不少于 90%；其中 AIS Basket 或同等权威 IS 来源 8–15 篇，核心理论原始或权威发展文献至少 3 篇，旗舰数据库/软件工程/机器学习方法论文至少 10 篇，直接最近邻至少 10 篇。预印本原则上不超过 20%，新 benchmark 例外，但不能承担核心理论责任。

每条引用须承担 D（定义）、S（现状）、C（冲突）、G（缺口）、M（方法来源）、E（数据/评价）或 I（讨论回扣）之一。引言、综述和理论部分连续三个实质主张句没有引文时必须重写；一段末尾用一组文献为整段兜底不算合格。核心构念先引原始或 Basket 文献，再引领域测量和限定证据；算法先引基础算子和最近适配，再说明现成形式为何不满足本研究对象；数据和指标引用官方论文、仓库或版本页。

## 六、逐段双 ISR 回读协议

正文每完成一个实质段，写作者必须立即重新打开 ACAA 与 DSDL 的本地全文，逐句阅读承担相同功能的物理行，然后才写下一段。对应来源为：

- `database_fulltext_all/28706_2024_attending-to-customer-attention-a-novel-deep-learning-method-for-leveraging-multimodal-online-re.md`；
- `database_fulltext_all/16409_2023_a-theory-driven-deep-learning-method-for-voice-chatbased-customer-response-prediction.md`。

审计文件对每段只保留一份当前记录，包含：正文位置与开头短语、当前逐句功能、每句引文功能与权威责任、ACAA 物理行及逐句功能、DSDL 物理行及逐句功能、回读后采取的修改。必须引用真实非空物理行；标题行与正文行要区分。成稿只能证明最终对应记录存在，不能虚构无法由文件证明的写作时间顺序。

## 七、结果责任

三篇均为研究设计，尚无训练 checkpoint、held-out 结果或机制检验结果。正文使用“拟构建、将检验、预期回答”等责任明确的措辞，不把公式复杂度、参数量、算力或研究门槛写成已完成贡献。只有训练工件、折外中间量、确认性终端结果和可复算日志全部存在后，才能把设计层贡献改写为实证结论。
