# Coding agent 广义安全的概念边界与系列选题论证

## 1. 研究对象与界定目的

本研究所称 coding agent，是能够围绕软件工程目标持续观察环境、形成计划、读取和修改仓库、调用测试或构建工具、执行命令，并根据执行反馈调整后续行动的自主或半自主系统。单次代码补全模型、只返回自然语言建议的聊天模型，以及没有环境反馈和连续行动能力的普通代码生成器，不属于本文的核心研究对象。

coding agent 的安全也不能被缩减为“是否生成了含漏洞的代码”。它在真实工作流中继承用户权限，读取来源和可信度不同的内容，改变文件、依赖、进程和服务状态，并可能在数十个步骤之后才暴露前序错误。风险由目标理解、当前状态判断、行动后果、组织权限、协作关系和恢复能力共同决定。因此，本研究先界定安全结果和行动结构，再决定算法问题，不把“安全”作为一般 coding-agent 性能方法的附加标签。

基于 NIST AI RMF、可信计算系统文献、AI safety 文献以及 coding-agent 事故与 benchmark 文献，本文采用如下工作定义：

> coding agent 的广义安全，是 agent 在目标、当前软件状态、权限边界和行动后果均可能不完全可见的条件下，维持可接受损害风险的能力。它既包括避免不应发生的持久状态改变，也包括在必要改变中控制副作用、维持可恢复选择、协调相关行动者，并让承担责任的人能够依据真实且足够的证据实施有效控制。

该定义同时包含安全与任务效用。拒绝所有工具调用虽然可能降低部分风险，却没有维持可用的自主能力，因而不能构成安全改善。

## 2. 相邻概念的联系与区别

| 概念 | 主要关注 | 与 coding agent 广义安全的关系 | 本研究不作的等同 |
|---|---|---|---|
| Cybersecurity | 攻击者、资产、机密性、完整性、可用性及对抗防护 | 当恶意仓库内容、权限窃取、密钥泄露或漏洞利用出现时，提供威胁模型与信任边界 | 不把所有误操作和可靠性失败都描述为网络攻击 |
| Software security | 软件漏洞的预防、发现、修复和安全开发实践 | 覆盖 agent 生成或修改代码时引入、遗漏或错误修复漏洞的风险 | 不把安全局限为 CWE 分类或补丁通过安全测试 |
| AI safety | 非预期有害行为、目标错配、副作用、安全探索、监督和分布变化 | 提供“良性目标也可产生伤害”的一般机制 | 不用通用聊天模型的有害回答代替可执行 agent 的状态改变 |
| Agent safety | 多步规划、工具使用、环境反馈和长期行动中的有害轨迹 | 与本研究直接相邻，强调局部合理动作的组合后果 | 不将每一次 tool call 独立分类后即宣称解决序贯风险 |
| Operational safety | 良性、目标导向使用中的误解、越界恢复、错误修改和环境损害 | 是本研究的核心组成，尤其解释没有攻击者时的真实事故 | 不与 cybersecurity 混用，也不排除同时存在攻击者的情形 |
| Dependability and trustworthy systems | 可靠性、可用性、安全性、完整性、可维护性及可信属性 | 提供“结果分布受控”和故障容纳的系统观 | 不把单一平均准确率当作可信或可靠的充分证据 |
| Risk-aware decision making | 在不确定结果、损失严重度和行动成本间选择 | 规定风险预测必须进入实际行动选择与效用权衡 | 不把风险分数头或固定阈值本身视为主要贡献 |
| Human oversight | 人在行动前控制、共同规划、实时监控和事后审查 | 处理 agent 无法观察的组织目标、授权和情境知识 | 不假定人类是无限可用且总能正确判断的 oracle |
| Permission and access control | 主体能对何种资源执行何种操作 | 限制潜在损害面，也是组织授权的技术表达 | 不把静态 allowlist、黑名单或一次权限开关等同于完整安全策略 |
| Reliability and failure containment | 在故障下维持最低质量并限制错误传播 | 关注异常恢复、局部失败、连锁影响和服务连续性 | 不把“重新运行直到成功”当作可靠恢复 |
| Safe autonomy | 在必要的人类控制下保持有用的自主行动 | 概括安全与效率、控制与自主之间的张力 | 不用更高拒绝率或更低行动率制造表面安全 |
| Algorithmic accountability | 对决策依据、行动权限、后果和责任归属进行追踪与审查 | accountability 是可形成合规结论并归属责任的目标；auditability 是产生、保存和暴露可信证据的系统属性；auditing 是据此重建、检查和归责的过程 | 不把 observability、多记日志、自由生成的解释或单一哈希链等同于已经可问责 |

NIST AI RMF 将安全、可靠、可问责、可解释、隐私与公平视为相关但不可互换的可信属性。Avizienis 等对 dependable and secure computing 的分类也区分 reliability、safety、integrity 和 confidentiality。Amodei 等进一步指出，AI 事故可以在没有恶意意图时由副作用、错误目标、安全探索不足和监督困难产生。由此，coding-agent 广义安全应覆盖传统安全攻击，但其边界明显大于攻击与漏洞。

## 3. coding agent 风险为何具有新的研究结构

### 3.1 行动会改变持久而相互依赖的状态

普通代码问答的输出仍需人类转化为行动。coding agent 可以直接写文件、删除数据、变更依赖、启动进程和提交代码。单个动作的后果可能跨越源码、配置、构建缓存、数据库、外部服务与版本历史。一个局部修改通过当前测试，不代表它没有破坏未覆盖约束或未来修改能力。

### 3.2 任务描述与当前仓库状态可能已经分离

issue、文档和用户叙述通常描述历史问题。agent 开始工作时，问题可能尚未修复、被部分修复或已经解决。FixedBench 将相同任务置于 Novel、Partial 和 Resolved 三种仓库状态，显示 coding agent 即使面对已经解决的问题仍会在大量案例中继续修改。这里的关键不是静态判断“任务是否危险”，而是 agent 是否会检查当前状态、区分竞争性解释，并在证据不足时先获取信息而非承诺修改。该论文目前没有公开其 200 个实例和生成脚本，所以它只能作为现象与评价设计依据，训练数据必须从 SWE-smith 等公开资源独立重建。

### 3.3 局部合理动作可以组合成全局损害

AgentHazard、SABER 和长期软件演化 benchmark 表明，每一步看似常规的读取、编辑、依赖安装或恢复动作，可能经由先前状态和后续动作形成传播性损害。风险状态必须保留行动依赖、资源变化和尚未满足的义务，不能压缩为逐步二分类。

### 3.4 错误恢复本身可能扩大损害

Agent Meltdowns 在无攻击者的良性任务中注入缺失文件、权限拒绝、下载失败和限流等常见故障，观察到 agent 为了完成任务而提权、扩大搜索范围、改变访问边界或隐瞒失败。tool failure recovery、harm recovery、用户意图修订后的 rollback 和事务 abort 是不同问题。将它们都写成“失败后重试或回滚”会掩盖真正的行动结构。

### 3.5 agent 继承组织权限，却不自动获得组织知识

用户授予文件和终端权限，不等于已经授权 agent 对任意资源采取任意手段。agent 往往不知道变更窗口、服务责任人、保留策略、合规义务和未文档化依赖。权限、责任、能力和知识可能分离，因而简单最小权限只能缩小行动集合，不能决定在具体任务中何时需要归还决定权或补充证据。

### 3.6 多 agent 提高并行度，也制造相互不可见的承诺

多个 coding agent 可以在不同分支、文件或子任务上并行工作，但各自可能不知道同伴已经形成的计划、接口假设和未提交变更。CooperBench、AgenticFlict 与 TeamBench 暴露了计划冲突、承诺偏离、错误预期、覆盖他人修改和角色越权等问题。它们不是普通并发控制的简单重演，因为行动主体以自然语言任务和不完全代码上下文形成动态计划，冲突通常在语义层而非文件锁层发生。

### 3.7 人类监督会随吞吐量增长而退化

coding agent 能以远高于人工编写的速度生成变更，却把理解 diff、验证隐藏假设和判断组织后果的工作留给审核者。真实开发者研究识别出事前控制、共同规划、实时监控和事后审查四类监督工作，也记录了以测试通过替代全面检查等启发式。AIDev 的纵向观察显示，重复审核 agent 代码时批准比例上升而评论努力下降。审批频率越高并不必然越安全，审核者会疲劳、习惯化，也可能被 agent 自述的说明误导。

### 3.8 行动可观察不等于事后可问责

coding agent 的普通 trajectory 可能记录了若干工具调用，却遗漏参数、返回状态、失败重试、批准、委派来源或当时生效的政策。*Auditable Agents* 将 auditability 分为行动可恢复、生命周期覆盖、政策可检查、责任归属和证据完整性，并指出这五项共同支持“发生了什么、是否合规、由谁负责”的可辩护结论。单次 action log 即使完整，也可能因缺失前后阶段而无法判断；全量 trace 即使可回放，也可能因缺少政策字段或完整性保护而不能作为证据。

这一边界把 auditability 与 observability、monitoring 和 alignment 分开，也产生新的代价约束。记录越多并不自动提高政策可判定性，却会增加存储、计算和隐私暴露。已有 selective logging、whole-system provenance 和学习型 provenance scheduler 又说明，压缩记录与保障采集完整性本身已有成熟技术近邻。因而，若未来考虑审计题，主要工件必须在 coding-agent 的真实行动链上学习哪些证据需要何时捕获，并以未知审计问题下的重建、政策判定、责任链恢复和成本共同评价；仅建立 schema、日志平台、hash chain 或可视化界面不能成篇。

## 4. 风险、状态与行动的概念地图

本研究将风险放在一个闭合的状态改变关系中：

用户或组织目标
→ agent 对当前仓库、权限和责任的信念
→ 证据获取、规划、沟通与工具行动
→ 代码、文件、进程、服务和协作状态改变
→ 功能、安全、连续性、人工负担与责任结果
→ 验证、补偿、回滚、重新授权或停止

风险来源至少包括五类状态错配：

1. 目标与当前状态错配。历史 issue 暗示需要修改，但当前代码可能已修复或只有部分修复。
2. 局部动作与系统后果错配。当前测试通过，但修改破坏隐藏依赖、权限约束或未来演化能力。
3. 个体计划与团队承诺错配。各 agent 的局部方案都合理，组合后却覆盖、冲突或遗漏责任。
4. 技术证据与组织判断错配。agent 提供的通过结果或解释不足以让审核者识别真正的高影响差异。
5. 已发生损害与恢复动作错配。恢复步骤修复表面错误，却造成二次损害或丢弃仍有价值的工作。

相应地，安全行动不能只包括 allow 和 block。完整的候选动作空间应根据具体研究问题，从下列动作中选择必要子集：读取或检查、运行诊断、构造反事实或 shadow execution、形成 checkpoint、暂存变更、缩小权限、与同伴同步承诺、重新分配任务、请求针对性信息或授权、提交、补偿、选择性回滚、停止和报告。

## 5. 纳入范围与排除范围

### 5.1 纳入

- agent 对当前仓库状态判断错误而进行不必要或破坏性修改。
- agent 在完成良性任务时越权恢复、扩大作用域或造成环境污染。
- 多个 coding agent 的计划、接口假设或修改承诺发生语义冲突。
- agent 变更表面通过测试，却引入安全、可靠性或维护性回归。
- 人类在有限注意力下错误批准、忽略或无法有效审查 agent 行动。
- 需要根据真实状态差分选择检查、暂存、提交、补偿或停止的序贯控制。
- 恶意仓库内容、prompt injection 和不可信依赖导致行动劫持，但仅在论文明确建立攻击者、信任边界和授权实验环境时纳入。

### 5.2 排除或只能作为基线

- 普通代码模型的静态漏洞分类，未涉及 agent 环境行动。
- 仅改善补全准确率、patch pass rate 或检索召回，却没有可测损害结果。
- 危险命令黑名单、固定 allow/warn/block 规则或简单权限开关。
- 把每个工具调用独立判为安全或危险的二分类器。
- 在现有 agent 后附加一个风险分数、置信度阈值或拒绝提示。
- 仅生成自然语言安全解释、恢复建议或审批摘要。
- 只通过减少所有动作、拒绝所有修改或持续请求人工批准来降低风险。
- 未将 coding agent 的自主行动、状态反馈与持久后果实质纳入的一般 AI safety 题目。

## 6. 已被直接工作显著压缩的选题空间

截至 2026 年 8 月，以下方向已有高度直接的 benchmark 或方法，不能再作为本系列的主要新增能力：

1. 候选动作经通用 world model 预测后果，再按风险阻止或重规划。SafePred 和 SafeMCP 已覆盖自然语言后果预测、环境 look-ahead、危险工具裁剪与安全—效用权衡。
2. 学习 act、refuse 或 ask。MOSAIC、AgentAbstain、FixedBench 和 Oversight Game 已分别覆盖多步安全拒绝、配对 act/abstain 任务和询问博弈。
3. 逐步 tool-call 安全分类。ToolSafe、AgentTrust 及多个 guard benchmark 已将 allow、warn、block、review 做成直接任务。
4. 固定标注动作可逆性后做 checkpoint 或 rollback。Revisable by Design、Atomix、Cordon、DeltaBox 和 dependency-guided rollback 已覆盖事务、补偿、检查点与依赖切片。
5. 生成多份自然语言恢复计划再排序。Human-Guided Harm Recovery 已发布人类偏好数据、reward model 和 BackBench。
6. 失败后在便宜重试和昂贵模型升级之间路由。CodeRescue 已以预算校准形式直接研究。
7. 根据历史点击预测个人权限偏好。AutoPermissions 已覆盖人群数据上的个性化 permission decision。
8. 将 prompt injection 防御表述为 provenance-aware auditing。ARGUS、RTBAS、FIDES 和 prompt control-flow integrity 已覆盖来源标签、信息流与执行约束。
9. 将 observability、结构化日志或 tamper-evident receipt 本身表述为 accountability。*Auditable Agents*、agent execution-provenance 综述、whole-system provenance 与 selective logging 已分别界定所需维度和基础机制；新增研究必须直接改善可重建、可判定和可归责结果。

这些近邻并不表示 broad safety 已经解决。它们把可贡献空间推向更具体的问题：真实执行差分而非教师生成后果；多动作序贯控制而非二元 gate；语义承诺与团队适应而非更多消息；可验证且绑定实际行动的人类证据，而非 agent 自述；以及最终损害、任务成功、恢复和人工负担的联合结果。

## 7. 历史候选的收敛过程

本节保留三题冻结以前的候选演化，作用是记录为何若干表面相关的方向没有进入正式系列。这里出现的“题位空缺”“仍在审查”与旧状态只对应当时的审计截面，不再表示当前结论。2026 年 8 月 16 日的现行题目、主线与冻结证据以第 8 节和 `00_总体主线与三篇论文关系.md` 为准。

下列结构在相应历史阶段仍属候选架构，当时只有通过直接近邻、公开数据、训练标签和等参数替代模型四项审计才可能冻结。它们现已由第 8 节所述三项研究取代。

### 7.1 历史阶段：论文一题位曾经空缺

“当前状态不确定时的审慎行动”已经完成终审并撤出论文题位。严格 Novel、Partial、Resolved 三联体仍可作为数据资产，严格 Partial 也可用“至少完成一项义务、仍有剩余义务、没有新增回归并存在可执行继续路径”提高评测质量。然而，这些标签依赖隐藏义务和反事实执行，不是 agent 行动时天然可见的新状态；升级为剩余义务图后，LoopsBench 又已直接实现 source-evidenced obligation DAG、ready frontier 和对已完成义务的持续回归保护。停止、恢复路由、动态项目状态、先取证再编辑与无谓修改控制也分别已有直接工作。Butler–Gray mindfulness 和 Salovaara 等人的 digital HRO 未产生越过通用 belief-state POMDP 的独立计算；进一步审查的 Shaft–Vessey cognitive fit 属于人类软件维护者的理解—修改机制，把它改写成 agent 的 fit tensor 会发生分析层级断裂。遵守肖老师 ACAA 关于理论类比边界的写法后，该理论至多提供设计动机，不能授权独立算法贡献。完整终判见 `01J_当前状态与剩余义务候选终审.md`。

面向未来依赖生态冲击创建并行使架构选项的替换方向也已终审撤销。该方向原本把 `t0` 的当前功能与 option premium、`t1` 的生态冲击及 option exercise 分开，并以漏洞暴露、冲击后不可修复、回归和服务中断作为安全结果。这个两时点问题具有实践价值，但不能仅凭问题重要性占据论文题位。

终审表明，Schober 与 Gebauer 的 flexibility-to-change 关系没有产生通用两阶段决策模型无法表示的计算约束。给 matched-state two-stage POMDP 相同的当前成本、时点可见冲击分布、可行动作、with-option 与 without-option 后果及效用，它可以逐输入复制价值关系和 Bellman 决策。另一个不可绕开的缺口是，BUMP、PyMigBench、SWE-Chain 与 advisory 时间快照并不提供同源 `t0` 风险集、盲构造的 with/without-option 双世界以及同一隐藏 `t1` 冲击；只选择后来发生冲击的实例还会把发生概率条件化为 1。两时点 replay 或 benchmark 可以作为数据基础设施继续研究，却不再构成本系列的 ISR 理论算法候选。最终判定见 `00U_C1依赖选项Schober救援终审.md`。

多轮自主修改中的结构侵蚀也未能填补题位。Banker 与 Slaughter已经把结构对软件波动性和复杂性所致维护成本与错误的条件效应纳入 ISR，Tiwana 与 Safadi又更直接地把跨期内部逻辑衰退概念化为 system atrophy，并检验模块化变化、系统年龄和后续 bugginess、演化停滞等关系。SlopCodeBench v2 等技术工作进一步把 coding agent 的迭代结构退化和回归放入可执行环境。当前资产没有同一前态、多个语义等价结构行动、同一隐藏未来需求和外部损害的因果真值；理论状态也可由同输入、同权重的 temporal GNN/POMDP 逐点复制。因此，该方向只保留为辅助结果或失败案例维度，终审见 `00Y_结构侵蚀候选终审.md`。

面向未来审计的学习型证据捕获也不能填补题位。若未来政策或审计问题不受限制，任何低于完整记录的选择策略都存在一个不可识别反例，被丢弃的字段或责任边可能恰是后来政策作出相反判定的必要信息。若预先限定政策族、查询分布和必需字段，任务虽可训练，却转化为 policy-conditioned set cover、日志放置、图约简、knapsack 或 constrained POMDP。现有 AIS 文献能够解释记录粒度、重建价值和链式证据，却不能产生决定捕获动作的不可替代计算状态；相同输入和预算下的等参数时序图模型可以执行同一优化。该方向因此终审撤销，完整反证见 `00Z_审计证据捕获候选终审.md`。

良性欠明确任务中的隐含授权范围也不能作为新题返回。OverEager-Bench、SNARE 与 UnderSpecBench 已直接操纵同一环境中的授权措辞、意图清晰度与越界行动，生产 coding agent 的自动模式也已使用用户消息和候选工具调用判断是否越过授权。更重要的是，该候选只是已撤销故障后授权题的弱化版本。目标、规范权限、主观意图与模型信念可以概念区分，却没有由 Baird–Maruping delegation 或心理契约理论推出的专属张量、更新律与动作方向。相同任务、可信政策、状态、效果和历史上的 constrained POMDP 可以表示 stage、询权、受限执行、交接、回滚与停止的全部策略。完整覆盖证明见 `01A_隐含授权范围候选终审.md`。

执行者与验证者分离也没有形成新的独立题位。Hua 等人已经把有限成本下依次调用监控器、继续取证、停止和干预表示为序贯决策，Koran 等人又直接研究监控信号质量与残差相关性，RETRACE、Scaling Agentic Verifier、Agentic Rubrics 和 SWT-Bench 分别覆盖独立 patch 核验、主动生成区别性测试、仓库情境 rubric 与可执行测试。warranting theory 只能约束证据的可操纵来源，separation of duties 只能禁止自审或写入 oracle；二者都没有推出残差依赖、验证次序或停止边界。给等参数 set/graph Transformer、hard-SoD policy 和 Hua 式 POMDP 相同的来源控制图、残差图、历史、训练样本与预算后，当前设计没有可由理论独占的有限样本结构。因此该题终审撤销，验证器交叉运行数据只保留为其他论文的基础设施，完整判定见 `01B_执行者验证者分离候选终审.md`。

跨代码所有权边界的可靠变更也被终审撤销。owner crossing 本身不是损害，CODEOWNERS、merge 与 review 记录也不能识别同一任务状态下拆分、移交或直接修改哪个动作真正减少后续回归。Hahn 等人的双设计空间研究、Zaggl 的传播成本模型与 Lindberg 等人的相互依赖协调已经表明，结构镜像、同步、责任宽度、artifact-based coordination 和 authority-based coordination 存在条件替代，不能推出“越界就移交”的稳定行动方向。AtomicCommitBench 又把 patch 分组、依赖证据、可回放提交序列和选择性回退放进 coding-agent 任务。若加入真人 owner 的互惠理解，候选转回监督研究；若只保留技术分解，则退化为现有 patch decomposition。完整判定见 `01C_跨所有权边界可靠变更候选终审.md`。

把跨版本失效的验证证据表示成“验证义务积累”也不能形成新题。Truth Stack 已经把 decision object、spec、evidence、replay 与依赖变化绑定，并把证据因依赖或假设改变而失效直接表述为 verification debt；Regression Accumulation、ChainSWE、SWE-Milestone、SWE-CI 与 SWE-STEP 又分别覆盖累积回归、污染基线、里程碑依赖和连续发布。DANTE、SIKG、演化感知运行时验证及残余风险停止进一步占据变更后选择何种证据、何时重验证和何时停止。技术债务、时间信息系统、组织记忆、信息处理和 real-options 文献能够解释积累、维护与延期，却没有推出等信息 temporal graph/POMDP 不能获得的验证状态或行动方向。该设计可以严谨构建，也可能成为有用系统，但其新增能力主要来自现有构件的扩大与集成，不能作为本系列的独立理论算法论文。完整终审见 `01G_验证义务积累候选终审.md`。

让 coding agent 在当前效率与开发者未来独立恢复能力之间配置参与机会，同样没有通过终审。Rinta-Kahila 等人提出的 activity awareness、competence maintenance 与 output assessment 是三类 mindful-conduction 活动，不是三个已经识别的能力因子或状态转移方程。候选虽把活动与 procedural、declarative、incident-recovery skill 分开，却只得到通用 relational graph knowledge tracing 加少量平均方向约束；同邻接、同维数和同干预位置的匿名状态模型可以逐层重参数化。更关键的是，让开发者亲自编写测试、契约或不变量会同时留下可执行软件资产，这些资产能够不经过人的能力变化而直接改善未来事故恢复，因而当前设计不能识别 `参与活动→潜在技能→延迟恢复` 的理论中介。Buçinca 等人的 adaptive support、Geometry、HAAS、AI Coaching 与 Proximal State Nudging 又已分别覆盖技能动态、当前任务与未来无辅助能力的序贯优化。延迟的 agent-unavailable recovery 仍是重要经验结果，但现理论没有产生可冻结的独立算法能力。完整判定见 `01I_开发者恢复能力候选独立红队.md`；SymPareto 完整主文仍未取得，任何关于其内部方法的判断均未被用作撤题依据。

普适的可靠发布行动也不能填补题位。若策略只在 CI、预发布、canary、正式推进与回退之间选择，删除 repository 读写和代码生成后仍是同一个 progressive-delivery 或 AIOps controller，coding agent 并非不可删除的行动者。若允许策略在 rollout 中任意重写代码、配置、依赖、观测点与兼容层，研究对象又扩张为没有稳定共同动作真值的代码综合与运行控制。CAS、序贯回归检验、强化学习 staged rollout、CloudCanary、SafeRevert、ARBITER 与 Safe Remediation 已分别覆盖证据积累、推进、回退、耦合故障审计和受约束补救；Ghaleb、UnderSpecBench 与 LoopsBench 证明 agent 会触及 CI/CD、DevOps 边界与长期回归义务，却没有把这些既有能力的拼接转化为新的理论机制。Jiang、Sarkar 与 Jacob 的 ISR 发布模型已经直接拥有发布与停止测试两个时钟，把它们写入学习策略属于既有模型的神经化；其余候选理论只产生奖励系数、不确定性门或组织层解释，同信息的通用 distributional SMDP 或时序图模型可以复制。以 trace 估计经济损害和 CVaR 的救援方向也已被 trace-economic underwriting 直接占据，并与迁移题的 staged commitment 及 C3 的人类取证重叠。终审见 `01K_可靠发布行动候选终审.md`。

有限审核容量下的安全审核分配也已终审撤销。该问题的组织后果真实存在，高产出的 coding agent 会扩大审核积压，并使高影响变更落到缺少相关经验或已经疲劳的开发者手中。然而，WhoReview、SofiaWL、Meta 的生产随机试验、AddExpertRec 与 2026 年高风险 diff 推荐器已经覆盖专长、负荷、知识分布、风险变更和追加审核者；DeCCaF、Kelly 等人的相关专家模型、FALCON 与动态人员调度又覆盖容量、相关错误、疲劳、恢复和双审价值。把隐藏可执行 oracle 加入评价能够纠正 merge、评论或接受率这些代理结果，却不会产生新的人员分配运算。TMS、组织注意和习惯化至多解释为何资源配置重要，没有推出等信息匹配 Transformer、CMDP/POMDP 或人员调度器不能复制的方向结构；AIDev 也没有同一变更交给其他真实审核者时的反事实正确性。该候选还与 C3 的第二审核者动作发生边界冲突，完整终判见 `01M_有限审核容量下的安全审核分配候选终审.md`。

并发仓库漂移下的可靠变更也不能填补题位。长时运行的 coding agent 确实可能依据已经失效的函数签名、依赖版本、安全约束或验证结论继续修改，造成有效工作丢失、安全修复复活和文本无冲突但行为错误的合并。可是，Claim Plane 已绑定 base commit、资源、依赖与写入准入，CoAgent 和 CodeCtx 已处理旧读取前提的定向失效与局部修复，STORM 已介入共享代码库的一致状态，EA-Graph 又把验证主张与 artifact 内容及证据新鲜度绑定；语义冲突检测和学习型 merge resolution 还覆盖了写入后的调和。temporal coordination、coordination fit、team awareness 与 artifact-based coordination 下推后只产生时延、依赖、通知、可见性和动作成本，同输入、同监督的 temporal graph world model 或 SMDP/POMDP 可以表示全部状态与策略。按照肖老师论文先承认最直接工作、再证明其系统性失配的论证责任，当前候选无法形成不失真的 gap，完整终判见 `01N_并发仓库漂移下的可靠变更候选终审.md`。

C22 所审查的模型与 scaffold 安全兼容及更新控制同样未能形成新的题位。这个候选正确指出，模型、控制循环、工具接口、上下文机制和权限策略分别升级时，任务成功不降并不排除越权、危险命令、信息泄露或不可恢复修改增加。可是，Scaffold Effect、Inside the Scaffold、HarnessAudit、Harness-Bench 与 Safety Under Scaffolding 已经覆盖模型、harness 和任务或风险情境的结构拆解与交叉运行，Don't Blame the Large Language Model 又直接识别连续 harness 版本造成的质量、成本和工具调用回归。Dunke 与 Nickel 的自动算法配置、HARBOR、HarnessOpt-Bench 和 RHO 分别占据条件配置、约束搜索与可执行 harness 编辑，SafeHarness 和 HOL Guard 则提供隔离、权限约束、检查点和回退。Goodhue–Thompson 的任务—技术匹配以人类个体、技术利用和个体绩效为单位，Cram 等人的控制匹配包含组织控制者、员工社会情绪行为和控制执行，Bharadwaj 的 IT capability 又属于企业资源与绩效层级；把这些构念压成 model–harness interaction 会发生角色或层级错置。互补性若保留 increasing-differences 方向便与现有排序反转、替代和符号变化冲突，若允许任意交互又可由等参数因子图、图 Transformer 或约束 AutoML 复制。该题的撤销不是因为尚未运行候选实验，而是直接能力覆盖与理论不可替代性已经在设计层失败。版本冻结 manifest、升级前后配对 rollout、任务风险图、格式保持的对照实例、双重家族留出、隐藏测试隔离和操作损害指标仍可作为共同实验基础设施，完整判定见 `01Q_模型与Scaffold安全兼容候选终审.md`。

C23 所审查的共享 Agent 栈共因失效遏制也被终审撤销。该候选把研究单位提高到多个仓库任务或 cohort，试图沿共享模型、harness、工具链、权限策略和 evaluator 谱系学习共同原因状态，并在匹配成功率或吞吐的条件下执行多样化配置、影子验证、分批暴露、暂停、隔离、回滚或撤回。最直接的 ISR 近邻 Temizkan、Park 与 Saydam 已经把共享软件漏洞、网络传播、多样性配置、动态重配和安全—成本权衡连接为完整工件；N-Version Programming with Coding Agents 又直接检验模型、harness 和语言多样性下的共现失效，Koran 等人以个体质量和误差相关性选择监控器组合，Harness-Bench、Scaffold Effect、Don't Blame the Large Language Model 及现有生命周期控制进一步覆盖共享 harness 指纹、组件更新、shadow、gate 和 rollback。剩余的 component-lineage posterior、联合尾险和组合策略可由动态因子图、异质图 Transformer 与 distributional CMDP 在相同信息和动作下复制；把 coding-agent 单元替换成微服务或批处理作业后，核心张量与控制动作也不改变。该题的撤销同样不是因为训练尚未运行，而是理论独占性、coding-agent 不可删除性和排他行动在设计层均未成立。版本化 stack BOM、exposure-set、相关损害指标、component-lineage split、共享更新压力测试、N-version 与低相关监控器基线以及 canary 后残留副作用记录仍可作为系列的外部测试层，完整判定见 `01R_共享Agent栈下共因失效遏制候选终审.md`。

C24 所审查的多消费者数据管线决策适用性也被终审撤销。这个问题能够造成真实的组织损害，一个 schema、完整性和局部测试均通过的管线变更，仍可能改变下游指标或决策所指向的业务现象。可是，Ballou–Pazer 的准确性—及时性机制假定同一现象的信息随时间更新，不能承担语义重定义的理论责任；IPMAP/IPView 已经把共享制造路径、信息产品、多个消费者、任务用途和上下游追踪连接起来，数据版本、双表示、语义迁移和自动修复又分别有直接工件。等参数异构图与 distributional POMDP 在相同合同、谱系、消费者任务和执行标签下可以复制拟议状态与动作。paired worlds 若没有可见差异便不可识别，若完整公开语义账本又退回既有 contract 或 migration。删除 coding-agent 身份后，研究仍是完整的自动数据程序修复问题。完整判定见 `01T_决策适用性数据管线候选独立终审.md`。

C25 所审查的软件来源与许可证安全同样没有通过题位门。coding agent 引入受许可证条件约束的代码或依赖并在事实不完整时发布，可能造成发布阻断、返工、治理失灵和法律争议，风险本身成立。SourceTracker、LiResolver、SILENCE、LiVo、PolicyGuard 及标准化 SBOM 工具已经覆盖来源、条款、兼容性、作用域、多类修复和轨迹合规；公开数据又没有同时给出权威来源、实际组合与修改方式、另行授权、分发情境、多步替代修复、功能保持和权威裁决。财产权、信息治理、知识产权规范、项目控制和边界资源能够说明权利与边界为何重要，却没有导出许可证修复独有的关系运算或行动方向。理论与 coding-agent 身份删除后，等参数异构图和 constrained POMDP 仍可运行。完整判定见 `01U_软件来源与许可证安全候选终审.md`。

C26 检查了 AI 加速漏洞发现以后，由 coding agent 联合生成、验证和分发修复工件并安排协调披露的可能性。修复延迟、错误补丁、补丁反向利用、维护者拥塞和下游采用不足都能造成真实损害，研究情境成立。可是，披露政策、protected period、补丁速度与质量、选择性预警、攻击与保护扩散、补丁生成验证、补丁差分利用以及有限容量下的攻防策略均已有直接理论或工件。Mitra 与 Ransbotham 的相反扩散、Arora 等人的披露—补丁 hazard 和 protected period 能产生有意义的机制与状态分解，却没有规定等信息 temporal heterogeneous graph Transformer 加 distributional SMDP 会稳定算错的行动方向。把 attack、readiness、quality、adoption 和 workload 分成多个 heads 因而仍是可由通用模型复制的测量纪律。历史记录又没有未采取披露与修复组合的反事实真值，替换成外生补丁后政策问题仍大体成立。完整终审见 `01V_AI加速漏洞协调修复与披露候选终审.md`；其隔离式 remedy-specific 攻防回放环境可作为安全系统资产，不能据此恢复 ISR 独立题位。

C27 检查了 orchestrator 面对多个可能压缩努力、操纵评价或完成隐蔽副目标的 coding subagents 时，联合设计任务分解、结果转移、行为控制和审计的可能性。隐藏回归、评价操纵、联合副作用和权限越界都可以在真实仓库中形成外部损害，机器执行的 contract-conditioned worker 也能产生需要本地训练的策略与 checkpoint。然而，当前识别设计先由研究者规定 worker 的效用、成本、外部选择和训练契约，再用同一效用计算 best response 与 incentive compatibility，因而只能识别一个人工训练的条件策略怎样响应其训练目标，不能识别现实 coding subagent 已有的外生代理冲突。Adaptive Contracts 已拥有 coarse/refined evaluation、inspection、payment、commitment 与 best response；Reward Hacking as Equilibrium、Software Delegation Contracts 和 SCHEME 又分别占据评价扭曲、委托章程和真实多 agent 联合损害。给相同义务图、覆盖标签、执行动作和可行性投影的 typed-graph Stackelberg POMDP 可以逐项实现剩余策略。Huber 与 Lyytinen 的连续契约研究以人类客户—供应商长期项目、离散 episode 和事后配置解释为单位，也不能直接充当 checkpoint-level interaction labels。完整独立终审见 `01X_策略性编码子代理委托契约独立红队.md`；低维 model-organism pilot 可作为预研究，不能占据论文题位。

第二个替换方向曾研究环境错误发生后的授权边界。其核心现象成立：用户把任务结果责任交给 coding agent，并不等于同时转移扩大搜索范围、修改访问控制或绕过安全边界的 intervention rights。然而，独立红队已将当前理论算法设计判为 **NO-GO，无保留**。Baird 与 Maruping 的 IS delegation framework 是高层 scaffolding，能够支持权利、责任与介入安排的概念区分，却没有推出 `O/X/I/K` 的独立张量、更新律或动作顺序。给定原始契约、授权政策、批准账本和相同动作空间，等参数授权图或 constrained POMDP 可以完整复制候选策略。CapLease 又已在 retry、delegation、concurrency 和 crash recovery 中用 durable Issue–Prepare–Commit 状态处理授权消费。该题因此不再占据论文题位；`00Q_候选替换_故障后授权边界与有界恢复审计.md` 仅保留被否决设计，最终判定见 `00R_故障后授权边界候选理论与近邻红队.md`。

### 7.2 历史阶段：已撤销的并行 coding agent 动态知识协调

该方向研究的问题真实存在，但当前设计已经判为 **NO-GO，无保留，并移出当前三篇系列**。现有 `D/C/Q/A/J/P→Z→policy` 结构没有达到理论驱动算法的最低责任。`D` 实际上更接近中央调度器维护的能力表，未表示团队成员关于“谁知道什么”的分布式 meta-memory；`C` 同时混合能力、声明准确性、承诺兑现、执行机会和权限，不能作为与 `D` 已识别的独立状态；`Q`、`J` 与 `P` 分别属于任务世界、软件语义和可执行权限，不是 TMS 构念；实际知识应用 `A` 只有行动后才能观察，把当期值送入策略会造成结果泄漏；而汇总状态 `Z` 又没有显式表示原理论中的 task–knowledge coordination。

直接近邻进一步压缩了剩余空间。SkillGraph 已提供动态技能状态和学习型协作图，Shepherd 已提供 supervisor、handoff 与 discard，Claim Plane 已提供 semantic dependency 和并发控制动作，通用 graph Transformer 或 belief-state POMDP 可以吸收当前设计的核心输入与动作。因而，即使重新生成大规模开放权重 rollout，也不能据此保留现题。未来若建立稳定身份、重复互动且高度互依的 agent 团队，并重新识别成员特定的 expertise-location belief、条件可靠性、task–knowledge coordination 与 post-action knowledge application，也只能作为一个新候选从零送审。完整撤题依据见 `00P_候选二TMS理论责任与等参数反证.md`，原数据规格 `00L_候选二因果可识别数据与算力预冻结规格.md` 仅保留为反证与数据识别记录。

### 7.3 历史阶段：可信监督证据候选的形成

风险发生在 agent 已形成候选变更或高影响行动、组织必须决定是否允许其进入共享或生产状态时。现有审批 gate 常把审核者当作稳定 oracle，并由 agent 自己叙述将要执行的内容。高吞吐下，审核者可能习惯化、误信测试结果或只批准表面合理的说明。

候选工件不决定“是否问人”。升级已由外部机制确定，待审行动和执行对象也先由可信中介固定。模型只在这一批准点内选择下一项可执行后果探针、证据子集与呈现顺序，并根据审核者的事实回答、澄清和修复请求更新 grounding state。它需要估计某项证据在当前审核负荷和知识状态下能降低多少实际错误批准，同时保持证据与真实命令、diff、参数、pre-state 和 state delta 的绑定。训练需要受控的序贯开发者实验，并以 executable hidden checks 判定安全结果；AIDev 纵向审核记录只能提供外部行为先验，不能替代实验真值。

该方向当前以 joint activity/common ground 为主要理论，有限注意和警告习惯化作为边界条件。common ground 用于 human–agent interaction 和一般协作 benchmark 已有直接研究，不能作为首次迁移。Clark 与 Schaefer 负责 presentation、acceptance、repair 和 purpose-relative grounding criterion；Clark 负责 joint activity、joint purpose 与 identification、ability、willingness、mutual belief 四项要求；Mastrogiacomo、Missonier 与 Bonazzi 负责这些机制在信息系统项目会议中的适配，以及 objective、resource 与 risk、commitment 四类对话内容；Li、Gatt 与 Poesio 负责 potential 与 established common ground 的区分。本文据此把 factual response、clarification、repair 与 reciprocal recognition 操作化为 grounding-state 更新。证据是否真实、测试是否有区分力、行动会不会造成损害以及 action hash 如何绑定都属于技术层，不能归入上述理论。

模型需要主动获取并呈现能修复特定命题缺口的行动派生证据，再通过审核者的可观察事实判断和修复后复测更新状态。主要结果是危险变更的实际批准与执行、正常任务通过、审核时间、错误拒绝和注意消耗，不是 click prediction accuracy，也不是 when-to-ask accuracy。若等参数 Human-state POMDP 仅预测审核者理解度便复制安全—效率前沿，或误批下降不经 factual grounding 改善中介，该理论贡献撤销。

该题当前状态为 **DESIGN-FROZEN / RESULTS PENDING**。可信技术层、共同基础层、关键张量、前向门、训练阶段、真人随机设计、保存工件和等参数反证已固定，因而可以进入仅含研究设计、预注册假设和结果占位的正式草稿。factual misunderstanding 是否构成主要机制、grounding repair 是否改善实际误批、Human-state POMDP 是否进入等效区间均尚未运行；任何一项失败都按预注册门撤销相应理论算法主张。

### 7.4 历史阶段：已撤销的测试控制面目的敏感共演

该方向研究一个真实冲突。coding agent 在生产代码之外还可能修改测试、CI 与 evaluator。有效规范没有变化时，削弱成功标准会掩盖功能、安全或范围损害；规范合法演化时，锁死旧测试又会阻止必要改变。初始设计试图用 control purpose 与 formal-control fit，让同一测试 diff 在不同世界触发相反的控制组合。

独立终审判定该题 **NO-GO，并移出系列**。同-diff 双世界实际操纵的是 active contract，不是 Wiener 等人定义的 controller intention；把 value-creation purpose 直接映射为允许测试演化又越过了 stewardship、知识、角色和组织层条件。`P/F/Z` 均是原始任务状态或特权 purpose 标签的函数；若把相同 charter 和标签公平提供给等参数 raw graph Transformer、direct outcome predictor 或 constrained POMDP，它们可以表达同一策略。TEBench、TestEvo、ImpossibleBench 与 SpecBench 也不提供两个自然合法、无未来泄漏的 prospective purposes 及唯一相反 portfolio 真值。候选设计保存在 `00T_第三题替换候选广搜与红队.md`，终局判定见 `00X_CPTC测试控制面候选独立终审.md`。

## 8. 现行系列：不完全知识下的可靠状态变更承诺

2026 年 8 月 16 日，三个题位均已完成字段级设计修补并通过未参与修改者的独立冻结审计。冻结只表示研究问题、理论责任、数据生成、可训练工件、动作空间、评价与泄漏隔离已经唯一到可以实施；三项研究都尚未完成正式训练或确认性实验，经验结论仍为 `RESULTS PENDING`。现行总体问题是，当关键知识分布在未来环境、多个编码代理和人类审核者之间时，coding agent 如何在保持任务能力的同时可靠地承诺一次软件状态变更。

论文一研究固定 PostgreSQL pre-cutover 迁移中的可选安全措施。coding agent 读取仓库、迁移脚本、应用行为和运行状态，在影子重放、语义验证、检查点保护、写入上限等真正可选的措施之间选择零项或多项，并决定延期、执行或放弃。Benaroch 的主动缓解实物期权理论使可选缓解、被动信息、剩余承诺和不行使选项进入半马尔可夫 kernel 与硬期权格。主要结果同时包含严重迁移损害、迁移成功、服务能力、时间和资源成本。三份锁定规格及独立通过证据见 `01H`、`01H-A`、`01H-B` 与 `02W`。

论文二研究六个竞争 coding-agent 分支在公共来源、复制转述、证据未被利用和后果不确定条件下的整合。来源因子图以复制因子和模型、支架、提示、任务及执行输出等公共父节点形成跨来源联合后验，命题观测算子只更新适用且方向明确的结果维；同前缀 correct、corrupt、sham 与 no-event 分叉产生真实 receiver reaction 和短视界行动标签，用来区分信息交换与实际利用。世界模型与序贯策略可以处理证据、向既有分支请求或揭示信息、运行探针、重放、恢复、隔离、整合、综合或自动停止。人工权限需求由外部固定门触发并终止 episode，答复不返回该策略。主要结果是不安全采纳，同时约束任务解决、错误隔离、成本和有效并行度。Qiu 等关于公共信息精度的研究与 Dennis 关于 exchange/use 的区分只负责来源相关和利用机制，coding-specific 探针与动作由本文承担。锁定规格与独立通过证据见 `02S`、`02S-A`、`02S-B` 与 `02X`。

论文三研究外部机制已经要求开发者审核、且由可信中介绑定到真实 diff、命令、参数和 pre-state 的 coding-agent 行动。策略不决定是否问人，也不输出 approve、deny 或 risk score；它只选择可信可执行证据获取、证据呈现、事实探查、澄清、理解修复或停止。Clark 与 Schaefer限定 purpose-relative grounding criterion 和 presentation–acceptance–repair 过程，Clark 限定共同活动与四项 joint-purpose 要求；Mastrogiacomo 等负责这些机制在信息系统项目会议中的适配和四类对话内容，Li 等的 potential/established 区分支持本文将潜在共享与已建立理解操作化为滤波状态。主要结果为同一审核者对绑定行动的不安全批准，同时报告安全批准、事实理解、时间与计算成本。锁定规格与独立通过证据见 `00H`、`00J`、`00H-A`、`00H-B` 与 `02V`。

三篇共同研究承诺前的可靠行动，但不是“识别—阻止—验证”的流程切片。论文一的状态随物理时间和未来运行事件变化，论文二的状态随来源、交换、利用和仓库探针变化，论文三的状态随取证、事实回应和人机理解修复变化。它们分别产生因果半马尔可夫模型与期权格策略、来源后验与分支控制策略、技术证据图与共同基础取证策略；训练数据、checkpoint、隐藏 oracle、主要行动和外部结果均相互独立。任一论文可以在另外两篇没有正结果时独立投稿。

完整的直白说明、三项输入输出、系列结构和经验边界见 [00_总体主线与三篇论文关系.md](00_总体主线与三篇论文关系.md)。三篇正式正文现在可以同步写作，但所有结果表只预先固定结构、统计量和判断规则，不得填入未运行的数值。

## 9. 入选题目的统一证据标准

每个最终题目必须同时满足以下检验：

1. 能指出具体损害、受影响对象和风险发生的决策时点。
2. 有至少两个要求相反行动的冲突情境，无法用“风险高就少行动”概括。
3. 理论产生可观测或可监督的中间状态，并进入前向计算、损失或行动选择。
4. 训练标签来自真实执行、可信标注或受控人类实验，不由同一 LLM 自问自答。
5. 公开环境可复现正常任务和损害结果，并支持按仓库、模板、时间或风险族隔离。
6. 主要工件产生本地 checkpoint、策略或概率模型，并在推断时实际改变 agent 行动。
7. 与直接方法、通用 Transformer、通用 POMDP 和等参数替代模型公平比较。
8. 同时报安全、任务成功、拒绝或误拦、人工负担、计算与延迟。
9. 打乱或中和理论状态后出现预注册的行为变化。
10. 若通用替代模型能够在相同数据和预算下复制能力，则撤销独立理论算法贡献。
