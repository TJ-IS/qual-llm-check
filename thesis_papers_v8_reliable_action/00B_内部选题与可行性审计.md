## 3. 统一入选门

候选题同时满足以下条件才可进入正文：

1. 风险具有可执行的外部后果，且能够区分正常完成、无谓行动、偶然损害、传播损害和过度拒绝。
2. coding agent 必须观察环境、调用工具并改变状态，普通分类模型不能替代研究对象。
3. 动作空间至少包含两个方向相反且均可能合理的选择，不能由固定阈值解决。
4. 主要监督来自执行结果、可信人工标注或受控实验。
5. 公开数据、容器或严格可构造环境足以训练和评价。
6. 理论产生不可替代的状态、关系或约束，并进入前向计算、损失或策略。
7. 工件需要本地训练并产生 checkpoint、策略或校准模型。
8. 直接近邻没有已经实现同一输入、状态、动作和主要结果。
9. 可与等参数通用 Transformer、图模型、POMDP 或直接策略公平比较。
10. 主要安全改善不能由拒绝所有动作、请求所有审批或缩小任务集合获得。

第 6 与第 9 项不把“通用神经网络在无限数据下具有普适函数表达能力”当作自动撤题理由。有效反证至少需要满足其一：已有直接方法在同一观察、动作和外部结果上实现了该能力；候选理论状态只是原始输入或特权标签的无损重命名，公平交给替代模型后没有新增约束；存在逐输入的精确结构约化且理论没有改变有限样本学习；或者在同参数、同数据、同训练与推断预算的预注册比较中，通用替代经验复制了安全—效用前沿和理论方向冲突。反过来，只声称理论模型可能具有更好归纳偏置也不够，必须说明偏置来自哪条理论机制、在哪类冲突上改变行动，并通过状态打乱、中和和等参数比较检验。

## 4A. 现行三题的冻结证据与独立性

### 4A.1 主动缓解期权格

研究单位是一个固定主协议下的 PostgreSQL pre-cutover migration episode。coding agent 必须读取 repository、schema、迁移脚本和 old/new application 行为，并在主协议之外选择零项或多项可选缓解，或者延期、执行、放弃。训练监督来自共同随机条件下的可执行 sibling rollouts，终局同时记录严重损害、迁移完成、服务能力、资源与时间。Benaroch 的主动缓解实物期权只负责可选措施、被动信息、剩余承诺与不行使选项的时间结构；代码语义、物理 kernel 与措施 executor 由本文承担。第五轮锁定稿是 `01H/01H-A/01H-B`，独立冻结证据是 `02W`。

本题的实证生死门包括：措施排序是否随状态和路径反转；延期是否在被动信息有价值时被选择；放弃是否在合法 outside option 情境出现；主模型能否在任务成功约束下减少严重损害并优于同信息、同标签、等参数的 `G-PhysicalFactoredSMDP`。这些是未来结果门，不影响当前设计可实施性，也不能在正式论文中预写为发现。

### 4A.2 可执行可证明性分支整合

研究单位是一个漏洞修复任务下的六个竞争 coding-agent 分支及其来源、交换、探针和仓库状态。主训练基座从 Vul4J 当前 129 个数据集条目开始，其中 79 个为 PoV-based，50 个为 SpotBugs-only；主分析任务数由 eligibility 与 oracle preflight 得到 $N_{\mathrm{admitted}}$。来源因子图对复制因子去重，并用公共父节点估计跨来源相关；C29-PROP 编译器产生逐命题的十维适用与方向观测；PROCESS_UPDATE 以同前缀真实 receiver reaction 与固定两步行动监督利用状态；五成员世界模型、离线 IQL 与四步悲观 MPC 选择处理、揭示、向既有分支请求、探针、重放、恢复、隔离、整合、综合或自动停止。人工权限需求是外生终止门，不是策略学习何时问人。Vul4J natural official 结果与 secondary overlay stress 通过 1,548 行 eligibility core、独立 evaluator、存储、分母和报告完全隔离。第二轮锁定稿是 `02S/02S-A/02S-B`，独立冻结证据是 `02X`。

本题的结果门包括：多数同源与来源均匀条件是否出现相反的探针或整合排序；在交换量相同的条件下，证据利用状态是否改变后续行动；模型能否同时降低不安全采纳、维持任务解决与有效并行；full-conjunction 和等资源 generic 是否落入预注册等效界。这些结果不得由 synthetic overlay 的频率代替，也不得用拒绝全部或总串行制造。

### 4A.3 可信取证与共同理解

研究单位是外部机制已确定需要人工审核、且由可信中介绑定到 canonical diff、command、parameters、pre-state 与 snapshot 的 coding-agent 行动。策略只获取或呈现证据、提出事实探查、澄清、修复理解或停止，不参与 allow/deny、when-to-ask、risk scoring 和 reviewer assignment。共同基础滤波器围绕外生内容 manifest 学习 potential/established、解释后验、相互确认与 repair；其中 potential/established 的区分来自 Li 等，presentation–acceptance–repair 与 purpose-relative grounding criterion 来自 Clark 与 Schaefer，joint activity、joint purpose 和四项要求来自 Clark，Mastrogiacomo 等负责信息系统项目会议适配和四类内容。技术证据有效性与 action binding 属于独立技术层。确认性实验把参与者一次分入固定四臂，十二个 trial 同臂，主要结果是同一审核者对绑定行动的不安全批准。第五轮锁定稿是 `00H/00J/00H-A/00H-B`，独立冻结证据是 `02V`。

本题的结果门包括：取证是否先改善可观察 factual grounding，再降低不安全批准；safe approval、时间和计算成本是否保持在预注册边界；等资源 Human-state POMDP 是否进入等效区间。伦理审批、招募和正式实验尚未完成，正文只能写计划与占位。

### 4A.4 系列关系与防止机械拆分

三题共同研究不完全知识下的软件状态变更承诺，但训练 episode、动作、checkpoint 与主要结果互不复用。MOL 处理未来环境和物理时间，C29 处理多个代理的相关来源和证据利用，C3 处理人类的事实理解。共享容器、哈希、日志与 code encoder 只能作为基础设施，任何 hidden label、policy weight 或经验结果都不能跨题流动。总体主线见 `00_总体主线与三篇论文关系.md`。

## 5. C1：当前状态不确定时的审慎行动

**当前最终判定是 NO-GO，移出系列；只保留数据资产。** 可执行三状态的数据构造、泄漏隔离和规模门槛曾单独写入 `00G_论文一可执行状态数据构造冻结规格.md`，但该规格只可用于 strict Partial、无谓修改和正确工作保护的评价，不再冻结论文一工件。完整终审见 `01J_当前状态与剩余义务候选终审.md`。本节以下内容保存被否决方案的设计演化，不得继续以 mindfulness、cognitive fit 或 obligation policy 的名称占据题位。

### 5.1 风险与决策点

agent 接收来自 issue 或用户的历史描述后，可能把“曾经存在的问题”当作“现在仍存在的问题”。目标仓库实际处于未修复、部分修复、已修复或替代原因四种状态时，正确行动不同。风险不是一次错误分类，而是 agent 在证据不足时过早修改，随后为了让新修改通过测试继续改变更多状态。

潜在损害包括无谓修改、回归、覆盖正确修复、增加 review burden、破坏可维护结构和延长任务。受影响对象是当前仓库、下游使用者、维护者及组织审核过程。

### 5.2 直接近邻

- FixedBench 正面证明 Novel、Partial、Resolved 三种任务状态下存在 action necessity 问题，并报告 resolved 状态中的大量无谓修改。不过，其 Partial 状态由 GPT-5 nano 生成任意补丁后排除已通过 gold tests 的补丁得到。这个集合可能同时包含真实部分进展、没有进展和新增回归，不能作为严格的部分完成真值。三状态命名和任务本身也已经被该文覆盖，本文不得将其主张为创新。
- AgentAbstain 已有成对 act/abstain 环境和八类触发。
- BLIND-ACT 与 OS-Blind 已研究良性目标下的盲目执行。
- MOSAIC 已训练 act/refuse safety thoughts。
- SafePred 与 SafeMCP 已覆盖通用 consequence prediction、风险评估与阻止/重规划。
- SABER 的另一篇 Small Actions, Big Errors 已将 mutation-gated verification 做成强 scaffold。
- LoopsBench 已把任务表示为 source-evidenced prerequisite DAG，只释放 ready-frontier tests，并持续保留已完成节点的 regression obligations，直接覆盖剩余义务图、可行动前沿和正确工作保护。
- USEagent/USEbench、EviACT、CodeRescue、Agentic Abstention 与 TRIM 已分别覆盖动态项目状态、先取证后行动、失败恢复路由、继续调查或停止，以及减少无谓修改。

因此，“预测是否需要修改”“给一个 abstention head”“先复现再决定”或“mutation 前统一检查”均不足以成篇。

### 5.3 候选理论责任

Butler 与 Gray 的 reliability–mindfulness 理论把可靠性界定为满足最低质量要求并控制结果变异。例行程序能够在稳定情境中支持可靠行动，却也会塑造行动者看到什么，使当前情境被过早纳入历史类别。该文明确区分个体 mindfulness 与 collective/organizational mindfulness。个体层五个面向是对新颖性的开放、对差异的警觉、情境敏感、多重视角和当前导向；组织层五个面向则是对失败的关注、拒绝过度简化、关注实际运行、韧性和让决策迁移至专长。

先前把个体层五个面向称为 mindful organizing，并逐项映射为算法模块，是错误的理论迁移，已经撤销。“对差异的警觉产生可执行义务向量”也没有原文依据。义务向量是由任务测试与行为不变量构造的工程真值，不是 theory-derived state。

当前只保留下列有原文依据但仍需通过算法反证的候选责任：

- 例行/历史预期与当前运行证据分离，避免预学习响应反过来塑造现态感知。
- 将问题解释表示为条件性、可修正的竞争信念，避免过早承诺单一类别。
- 保留弱异常与 near-failure 信号，避免常规成功造成过度自信。
- 在动态情境中创造可继续诊断或恢复的选项，而不把获取更多信息自动等同于更高确定性。

这些责任可以被通用 belief-state POMDP 复制，完整终审也没有找到能够解除反证的理论机制。后续尝试使用 Shaft 与 Vessey 的 cognitive fit 时，又出现了人类软件维护者认知机制到 agent 内部张量的层级迁移断裂。C1 因此终局判为 NO-GO；数据构造可继续，但不能据此恢复 mindfulness 或 cognitive-fit 驱动的独立算法贡献。

Salovaara、Lyytinen 与 Penttinen（2019）关于 digital HRO 的主文提供了更接近自主数字行动的组织层视角，但没有解除这一判定。该文把数字核心、反应性改进和主动预期组织成层，并区分 epistemic 与 pragmatic operations；collective mindfulness 来自人类 mindful operations 与数字 mindless operations 的系统耦合。把这三层直接做成单个 agent 的三个网络模块，或者把五个 HRO 特征做成五个 loss，都会违背其社会技术层级和人类执行责任。完整红队见 `00I_候选一理论责任红队与撤题判定.md`。

若尝试重构该理论，最低中间状态是：

- 历史任务叙述与当前可执行证据的差异表示。
- 多个竞争性问题解释及其未解决证据义务。该结构只有在条件性表征、反常证据保留和 option-creating 动作均能由理论原文支持时，才可计作理论状态。
- 反常或失败信号的保留权重，而非被大多数通过测试淹没。
- 候选动作的新增损害、错误遏制和可回滚结果。泛化 option value 不再归于理论。

方向冲突是：历史描述强烈指向修改但当前证据支持已解决时，模型继续检查或保持状态；初步测试通过但关键异常证据仍与“已解决”冲突时，模型不能立即 abstain。

### 5.4 工件草案

原工作名 Mindful State-and-Action Model 已撤销。strict Partial 数据、义务保持指标或通用 controller 以后均不得以 mindfulness 或 cognitive fit 命名工件。

输入：

- issue、用户目标和历史 patch 叙述。
- 当前仓库的文件、AST、依赖、git、构建和测试状态。
- agent 迄今读取、检查、试改和执行的轨迹。
- 候选检查、shadow edit、修改、暂存、请求信息和保持状态动作。

中间结构：

- 历史—当前双视图编码。
- evidence graph，节点为 claim、文件、测试、运行状态和观测，边为支持、反驳、依赖和时间关系。
- hypothesis belief，至少区分 novel、partial、resolved 和 alternative-cause。
- `b_hist` 与 `b_ops` 的预期—当前冲突、异常证据表，以及候选动作的损害、遏制和回滚结果。

输出动作：

- 读取指定证据。
- 运行针对性诊断。
- 在隔离副本中试改或执行。
- 建立 checkpoint，执行 rollback/restore 或限制错误传播。
- 正式修改并暂存。
- 请求一个范围明确的信息或授权。
- 保持当前状态并提交证据。

训练目标候选：

- 成对状态的对比表征损失。
- hypothesis 校准交叉熵或 proper scoring loss。
- evidence support/contradiction 关系损失。
- 真实 rollout 的 state-delta 与损害预测损失。
- conservative offline RL 或 constrained policy loss。
- task success、unnecessary mutation、regression、行动成本的多目标约束。

### 5.5 数据与切分

- FixedBench：论文使用 200 个 SWE-bench Verified 基础任务，每个含 Novel、Partial、Resolved 状态；截至本次核验，作者没有公开任务 ID、生成脚本、完整实例或数据许可证，因而不能直接作为训练集或复现实例。其 Partial 构造也不保证已满足义务严格多于 Novel 且严格少于 Resolved，不能转换为监督标签。
- SWE-bench Verified：公开 500 个实例和评测字段，但公开 gold patch、test patch、F2P/P2P 只可用于构造开发数据，不得进入最终 agent context。OpenAI 后续审计指出部分测试存在缺陷，正式评价不能只依赖该集合。
- SWE-smith：MIT 许可，官方说明约 52K 任务、26K 轨迹和 250 以上仓库环境；公开轨迹库约 76K 行、4.22GB。它是独立重建可执行义务状态序列的优先来源。构造时必须从测试 patch、运行不变量和依赖约束提取多项义务，再实际执行中间补丁；只有义务满足集合严格单调增加且没有新增回归的中间状态才能标为 partial-progress。
- SWE-bench Verified 只作历史诊断集。主要外部测试使用冻结时间窗的 SWE-bench-Live，并要求任务创建日晚于基础模型公开日和训练冻结日中的较晚者。SWE-rebench V2 只作抽样跨语言鲁棒性来源。
- SABER：716 个 stateful Docker tasks，可提供 accidental、late 与 propagating harm；训练时必须自建 repo/template/risk-family group split。
- Agent Meltdowns Noisy Container：产生错误恢复轨迹，但不可把一般 tool failure 混为 action-necessity 标签。

推荐 split：upstream/fork-network disjoint 主划分，发布日期或 commit 时间作辅助 OOD；同一个 issue 的三种状态、所有 Partial 变体与轨迹前缀必须留在同一 split。再按 base-commit ancestry、修改函数 AST、问题文本、测试签名和 gold patch 相似度去重。

最低数据门槛是 4,000 个严格三联体、80 个独立仓库网络，其中训练 3,000、开发 500、内部 repo-OOD 测试 500；另需至少 300 个新时间窗外测三联体和 40 个外测仓库网络。当前只根据 10,092 个 SWE-smith 组合任务判断其具有初步可能性，尚未运行严格生成，不能宣称门槛已经满足。

### 5.6 基线与反证

- FixedBench 原提示、verify-before-act、reproduce-then-abstain。
- 直接 act/abstain classifier 与 AgentAbstain 风格模型。
- 直接三状态 SFT、Agentic Critical Training 和 Agentic Abstention 的预算匹配适配版。
- SafePred、SafeMCP 可适配版本。
- 等参数 sequence Transformer。
- 等参数 evidence graph Transformer，但不显式区分历史—当前或竞争解释。
- 通用 belief-state POMDP。
- oracle current-state label 与 oracle counterfactual rollout。

机制干预：打乱历史—当前配对、删除反驳边、把 competing hypotheses 合并为单状态、平均稀释关键异常、打乱遏制/回滚结果。若完整模型行为不随这些干预改变，理论状态无效。另设同维度无理论分块 latent-state POMDP，并以预注册等效界判断是否复制理论模型。

### 5.7 算力与工件

可先以 0.5B–3B code encoder 加异构图/轨迹策略训练，单次主训练目标为 2–4 张 80GB GPU 数日级；7B LoRA 仅作为较大版本，不作为最低可行前提。必须保存数据 manifest、容器 digest、base model hash、训练 checkpoint、随机种子、trajectory log 和隐藏 predicate 版本。

### 5.8 终局与未来重新立项条件

- 只能稳定预测 resolved，不能在 partial 与 resolved 冲突中选择不同证据动作。
- 收益完全来自额外测试调用或更大 token budget。
- 一个等参数通用 POMDP 在相同数据下复制结果与机制行为。
- 主要安全提升由少修改或多 abstain 获得，任务成功前沿没有改善。
- FixedBench 及扩展状态无法形成足够规模的 group-disjoint 训练集。
- 严格质量控制后不足 4,000 个三联体或不足 80 个仓库网络，或无法构成至少 300 个新时间窗三联体。

终审已经触发更根本的撤题条件：LoopsBench 直接占据义务 DAG、ready frontier 与 persistent regression obligations；strict Partial 只是依赖隐藏 oracle 的评测切片；cognitive fit 无法无损迁移为 agent 构念；在同结构、数据和行动预算下，generic Transformer、world model 或 obligation POMDP 可以实现相同策略。未来只有 `01J` 第 14 节十二道复活门全部由新证据闭合时，才能作为一个新候选从零立项，不能由更多三联体、更多公式或 policy head 自动恢复。

## 5A. C1′：面向未来依赖冲击创建并行使架构选项

### 5A.1 题位与两时点风险

C1′ 已经终审判为 **NO-GO，并移出系列**。以下内容只保存被否决方案的问题结构、数据缺口和反证过程，不再界定可回到论文题位的 rescue pilot。终局判定见 `00U_C1依赖选项Schober救援终审.md`。

- `t0`：coding agent 为当前功能任务选择依赖并生成可执行 patch，同时决定是否付出当前代码量、复杂度、测试与缺陷成本，创建可替换、可隔离、可降级或可禁用的 dependency boundary。
- `t1`：只有到此时才公开的 CVE、恶意或撤回版本、弃维、breaking release 等 ecosystem shock 发生，agent 必须实际 upgrade、replace、quarantine、disable 或 remove 依赖，并验证功能、安全和服务状态。

风险结果包括已知漏洞暴露时长、shock 后不可修复、功能或安全回归、服务中断、数据/权限暴露面和修复成本。始终不引入外部依赖虽然减少部分暴露，却会失败于 `t0` 功能任务，不能赢得安全评价。

### 5A.2 直接近邻与剩余空间

DepDec-Bench 与 PySelect 处理当前时点的复用、克制、版本或包选择。PyMigBench、library-migration agents、BUMP/BigBag 和 SWE-Chain 处理 shock 已经发生后的 migration、upgrade 或连续维护。Architecture Without Architects 与 AI-Generated Smells 说明 coding agents 会做隐式架构选择并可能增加耦合或架构劣化。现有检索没有发现同一策略在 `t0` 创建 option、再在隐藏 `t1` shock 上行使并以真实执行结果训练。

因此，普通安全版本选择、事后 dependency update、wrapper 模板、always-isolate、architecture smell predictor 或 migration agent 都只能作基线。若后续出现 prospective dependency-shock option construction 的直接方法，立即重审。

### 5A.3 候选理论责任

Schober 与 Gebauer（2011）将 IS flexibility-to-change 表示为系统初始化时为未来修改或升级付出的附加成本，以及未来要求出现后是否行使该 option。救援版只允许该理论规定 `t0` premium、时点可见的 future uncertainty、with/without option、`t1` exercise/no-exercise 与系统外处置必须分开；原文的确定性与 ROA 数值结果不能改写成所有依赖安全决策的普遍定律。

Subramanyam、Ramasubbu 与 Krishnan（2012）的分析单位是 mass-customized ERP business component，结果是开发 effort、defects 与客户现场 customization effort。dependency wrapper、provider-neutral adapter、进程隔离或降级路径不天然等同于其 component granularity。原研究的三个维度、阈值和非单调关系不得作为主理论张量或 shape loss。该文至多作为“当前开发负担可能与下游改变成本冲突”的有限经验镜头；只有新情境中的构念与中介通过独立干预效度后，才可增加理论责任。

被审设计的最低状态是 `C_0` 当前 option premium、`p_0(ω,τ|I_0)` 当时信息下的冲击发生分布、同一 task/shock 的 with-option 与 without-option twin outcomes、可行 exercise paths 及 no-exercise。终审把这些状态和结果逐一交给 matched-state two-stage POMDP 后，Schober 的价值关系与 Bellman recursion 可以精确同构。因此，该理论没有留下通用模型不能复制的内部运算，整题已经触发撤销条件。

### 5A.4 数据、工件与最低 pilot

可执行来源包括 BUMP 的 Java breaking updates、PyMigBench 的真实 Python migrations、SWE-Chain 的连续 package transitions、AIDev/DepDec 的 dependency actions，以及 OSV、GitHub Advisory、registry 和 deps.dev 的时间戳快照。它们不是现成的两时点训练集。风险集必须同时纳入后来发生 shock、长期 stable、right-censored 与 benign-upgrade 的窗口；只保留发生冲击的样本会系统性高估 option。必须在同一 `t0` repo/task 上实际生成多种 candidate designs，让它们承受同一隔离的真实或行为等价 `t1` shock，并用 build、hidden tests、static/dynamic analysis 和 state trace 构造反事实排序。

模型可使用 temporal heterogeneous GNN/world model、hierarchical policy 和本地 code decoder/LoRA。`t0` 输出功能 patch、manifest/lock 与实际 option construction；`t1` 输出 exercise 或 no-exercise 决定、代码 patch 和验证轨迹。训练至少包含当前任务、premium、hazard calibration、未来 exercise success/cost、exposure survival、same-task same-shock counterfactual rank 与 action-feasibility losses；不得保留未经独立验证的 granularity shape loss。

即使把该问题保留为数据或 benchmark pilot，也不得承诺论文级规模或理论贡献。数据仍应按 repository lineage、package family、shock family 和时间分组，并优先使用冻结后的 prospective shock；sealed behavior-equivalent shock 和历史重放只能说明工程可执行性，不能恢复被通用 POMDP 吸收的理论算法责任。模型参数记忆、stable/right-censored 风险集和同一隐藏冲击下的双世界仍是基础设施必须报告的边界。

### 5A.5 立即撤题条件

- 容器 replay、许可证与时间隔离后无法达到数据门。
- boundary variants 只能由 LLM judge 评价，或构造时泄露 `t1` shock。
- `t0` 设计没有真实改变 `t1` exposure、remediation 或 regression。
- always-wrapper、always-isolate、更多 LOC 或更多 tests 解释全部收益。
- `G_b` 无 construct validity，或 defect mediator 与非单调 trade-off 不成立。
- 等参数 raw Transformer、temporal GNN、two-stage world model 或 POMDP 在预注册等效界内复制外部结果与方向冲突。
- 题目退化为 package recommendation、dependency update 或 architecture smell prediction。

- 训练风险集只含已发生 shock 的实例，或无法估计 `t0` 可见的发生率。
- Schober-centered 状态被 generic two-stage POMDP 或 anonymous factorized model在预注册等效界内复制。

`00N_候选一未来依赖冲击与架构选项红队规格.md` 保留最初工程蓝图，`00O_候选一架构选项理论与时间泄漏反证.md` 保留中间救援审查；二者均已被 `00U_C1依赖选项Schober救援终审.md` 的终局 NO-GO 判定取代。两时点数据基础设施即使建成，也不能直接恢复为本系列题目。该旧方案撤销后留下的题位现已由第 4A 节所列“主动缓解期权格”研究填补。

## 5B. C1″ 撤销记录：环境错误后的授权边界与有界恢复

**当前最终判定是 NO-GO，无保留，并从现行三篇系列移除。** 以下两段仅保存问题与原先条件性设计，不再构成 pre-freeze 题位。`00Q_候选替换_故障后授权边界与有界恢复审计.md` 保存被否决蓝图，完整理论、数据、近邻和等参数反证见 `00R_故障后授权边界候选理论与近邻红队.md`。

C1″ 研究 coding agent 在正常路径因文件、依赖、权限、网络或工具错误失效后，是否会把已承担的任务结果责任误当成扩大搜索范围、改变访问控制或绕过边界的介入权。它要求 learned policy 在真实错误状态中选择检查、postcondition verification、授权内替代、shadow execution、最小权利请求、重新委派、停止、回滚或补偿，并同时优化实际任务恢复和越权副作用。

Agent Meltdowns 已直接发现并测量该现象；Failing Tools 与 ToolMaze 已覆盖一般故障恢复；Numbat、Conseca、PCAS、OAP 与 IGAC 已覆盖规则检测、即时策略、确定性授权和 action binding。因此 meltdown detector、危险命令分类或 allow/ask/block 都判 NO-GO。候选只能建立在 Baird 与 Maruping 的 partial transfer of task rights、outcome responsibilities 和 intervention rights 上，并且三类状态必须能够被任务 manifest、外部 policy 与同前缀执行分支独立操纵。

独立审计已经确认当前撤题条件成立。Baird–Maruping framework 能说明权利与责任可以部分转移，却没有推出候选的数值张量和更新律；`O` 还可能退化为任务目标或 reward，`X/I` 多数是外部规范事实，`K` 与持久授权账本重叠。相同原始信息和动作空间下，授权图或等参数 constrained POMDP 可复制候选决策；CapLease 进一步直接覆盖 retry、replan、delegation、concurrency 与 crash recovery 中的 durable authorization consumption。因此不先做大规模训练再决定，也不把三个 head 降格为另一篇的辅助机制。

## 6. C2 撤销记录：多 coding-agent 的动态知识协调

**当前最终判定是 NO-GO，无保留，并从现行三篇系列移除。** 本节以下内容保存被否决方案的数据、模型与反证台账，不能继续被称为预冻结设计或 thesis 题位。独立理论红队见 `00P_候选二TMS理论责任与等参数反证.md`。未来即使满足下述高成本数据条件，也只能把重新定义的设计作为一个新候选从零立项，不能自动恢复 C2。

### 6.1 风险与决策点

多个 agent 并行处理同一仓库的关联任务时，各自的专长、已读上下文、接口理解和任务承诺不同。冲突发生在局部计划形成后、合并或交接前，可能造成修改覆盖、错误接口假设、遗漏验证、重复工作、角色越权及冲突修复回归。

普通文件锁只能识别位置冲突，无法识别两个不同行文件对同一接口或业务不变量提出相反假设。更多通信也不是答案，过量同步可能吞噬并行收益并传播错误信念。

### 6.2 数据与直接工作

- CooperBench：MIT 基础数据含 199 个 feature、12 个仓库、28 个 base commit 和 652 个 feature pair。公开 team trajectories 的主数据来自同一个闭源 deployment、同一 harness 与 seed，只有实现轨迹、patch 和测试结果，没有 checkpoint 异质性、仓库经验、权限或能力漂移。Qwen matched runs 也只是一次已分配任务的 realized outcome，不能给 agent×knowledge 的反事实能力或 TMS 状态标签。
- AgenticFlict：含 107,026 个 merge simulations、29,609 个 textual conflicts 和 336K 以上冲突区域，但公开 clean 数据没有完整源码，也不检测 semantic conflict；它只能提供冲突分布外测，不能监督动态知识状态或 policy 后果。
- AIDev：含 PR、timeline、review、commit、diff 和 repository metadata，可用于观察组织审核，但没有 agent trajectory、checkpoint、权限、hidden functional outcome 或同前缀反事实。merge/review 结果存在明显选择偏差，且每个 patch/file 仍受源仓库许可证约束。
- SWE-smith：当前数据版本与论文卡片存在规模漂移，公开实例和单 agent trajectories 可作为重新 rollout 的可执行底座，却原生不含 TMS 标签。必须冻结 dataset revision、容器和仓库许可 manifest。
- TeamBench：851 个模板、931 个 seeded tasks，OS 层角色分离和 verifier-edit 尝试标签；适合权限与角色行为外测。
- CooperBench 已公开 792 条 cooperator SFT 轨迹和 leader/follower 双策略 SFT 数据；SWEET-RL 已训练协作编码的 stepwise critic 与策略。
- Shepherd 让 supervisor 观察两名 worker 的完整 typed execution trace，并选择 inject、handoff 或 discard；其 CooperBench 应用将 pair pass 从 28.8% 提至 54.7%。
- Claim Plane 用 versioned ChangeIntent、typed resources、依赖和 pre-write admission 控制并行写入。确认性实验显示静态策略主要靠接近全面串行化恢复可靠性，动态策略又受 region undercoverage 与 undeclared scope 影响。它留下的是学习型 semantic-dependency 与选择性并发问题，不是一般并发控制空白。
- Claim Plane 的设计文已经把 semantic dependency model 定义为 independent、A-before-B、B-before-A、hard conflict、commutative 和 uncertain，并用实际写入、联合测试与 serial rescue 构造标签；其 Dynamic Scope v2 动作也已经包含 continue、serialize、replan、escalate 和 deny。因此，语义干涉张量加协作模式分类本身不能成为本文贡献。
- SkillGraph 已用 active skill embedding、running accuracy、failure buffer 和 Graph Transformer 共同更新多智能体能力与拓扑；G-Designer 与 Graph-of-Agents 也已按能力或 model card 调整协作图。动态专长表示和路由本身同样不足。
- CooperBench 的 fixed-ak-v1 已覆盖 conflict prefix trimming、knowledge memo 注入和基于 ground-truth edits 的 correction，而且 evaluation 使用 gold patch proxy 而非轨迹 edit。共享 memo、prefix correction 与 accepted patch overlap 既不能承担新颖性，也不能作为 knowledge application 真值。
- 因此，central planner、message passing、共享 scratchpad、角色 SFT、supervisor、普通冲突预测和通用动态能力路由都应视为已覆盖近邻。

### 6.3 首选理论：Transactive Memory Systems

TMS 不是要求所有成员拥有相同知识，而是团队对知识编码、存储和检索形成认知分工。Kanawattanachai 与 Yoo 将 expertise location 定义为团队成员关于“谁知道什么”的知识，将 cognition-based trust 定义为对他人完成任务的能力与可靠性的信念，将 task–knowledge coordination 定义为成员对任务分解、子任务关系与成员分配的重叠表征。Choi、Lee 与 Yoo 进一步区分知识分享和知识实际应用。因而模型内部的团队信念、外部真实能力、承诺可靠性和应用结果必须分开，不能都用一次任务成功率表示。

TMS 能够产生独立能力的条件很窄。核心问题必须是异质且能力会随执行证据漂移的 coding-agent 团队如何维护“谁知道什么、谁的承诺值得依赖、知识是否真正进入当前修改”的可校准信念，并据此改变任务所有权、先后关系、契约与 handoff。最低理论责任状态为：

- `E^*_{a,k,t}`：由当前协作任务之外、按时间冻结的重复领域 probe 得到的真实能力后验。它是评价与更新依据，不是策略在当前测试任务可直接读取的输入。
- `D_t[a,k]`：团队在时点 `t` 关于 agent `a` 是否掌握知识域 `k` 的 expertise-location belief，而非真实技能标签或静态角色 embedding。
- `C_t[a,k,q]`：将 cognition-based trust 缩窄到结构化事实声明和行动承诺的可靠性成分。必须控制 opportunity、permission 和 `D` 层次，并验证它与能力信念的辨别效度。
- `Q_t[u,k]`：子任务 `u` 的 task-intrinsic knowledge requirement。它是为算法分解而增加的技术状态，不得声称为 TMS 原文的独立构念。
- `A_t[a,u,k]`：知识项是否真正改变当前任务判断、修改或验证，以及是有益使用、有害使用、未使用还是不可判定。消息被发送、读取、提及或检索不能直接算作应用。
- `Z_t[a,u,k]`：由 `D_t`、`C_t`、`Q_t` 和 `A_t` 联合形成的 task–knowledge coordination 瓶颈状态。
- `J_t[u,v,r]`：两个 change intent 的软件语义关系。该状态属于软件 world model，不属于 TMS 理论贡献。
- `P_t[a,tool,path]`：可观测的工具与路径权限 mask。权限改变可行动性，不代表知识改变，禁止塞入 `D_t`。

这套状态避免把共享消息数量当作成功。理论预测早期需要形成专长目录，执行中必须用兑现或违背承诺的证据更新可信度，后期沟通量本身不再关键，真正关键的是任务—知识协调与知识应用结果。任务无相互依赖或团队成员同质且稳定时，TMS 价值应显著下降。最关键的方向冲突实验应固定代码图和 `J_t`，只替换 agent 的领域专长、承诺可信度或知识应用倾向；TMS 策略应改变分配或 handoff，而 Claim Plane 的纯语义控制不应改变决定。

### 6.4 工件草案

工作名：Dynamic Transactive Coordination Policy。

架构：

- heterogeneous temporal graph，节点为 agent、subtask、file/API、test obligation、knowledge item。
- expertise-location 与 credibility 分别采用可更新的 Beta 后验，禁止用一个历史成功率替代二者。
- task–knowledge encoder 和知识应用干预模型形成 `Z_t` 理论瓶颈；主策略不得绕过该瓶颈直接读取所有原始特征，另设允许 bypass 的反证版本。
- 外部 semantic-dependency model 提供 `J_t`，其贡献与 TMS 状态分开报告。
- structured decoder 联合输出任务—agent 分配矩阵、方向化先后关系、带 API/符号/不变量/联合测试义务的契约，以及 handoff 的目标 agent 与 checkpoint。若退化为四类 softmax 再调用固定 prompt，应撤题。

推断动作：

- 建立或修改任务—agent 所有权。
- 向特定 agent 检索特定知识，并绑定待满足的验证义务。
- 请求交叉验证或第二责任人，而非泛化广播。
- 选择方向化的先后关系，或在能力/可信度更新后执行带 checkpoint 的 handoff。
- 提交受约束的接口契约，明确 API、符号、不变量和联合测试义务。
- 暂停、废弃或重新分配尚未提交的冲突修改。

训练信号：

- `E^*` 监督来自 agent profile/checkpoint/time×knowledge domain 的重复、任务隔离、full-tool solo probes，并以多任务多 seed 的 Beta-Binomial posterior 表示。策略只可看到当前时点之前的证据。
- `C` 监督要求 agent 先产生 machine-verifiable claim，至少含 claim type、file/symbol/API/invariant/test predicate 和 horizon。事实声明由代码或测试 verifier 核验，行动承诺由固定 checkpoint 的 diff/test 核验；没有执行机会或无法观察者标为 UNKNOWN。通过 2×2 干预分别改变能力 checkpoint 和 report/commitment fidelity，防止 `C` 退化为 `D`。
- `Q` 不以 gold-patch overlap、slice 或 accepted patch 直接标注。训练任务必须构造两个语义可行但对私有知识 `k0/k1` 要求相反的世界，联合 hidden obligations 证明不存在一个 action 同时满足两世界；另配同仓库同难度、无依赖 witness 的 negative item。
- `A` 使用同一 quiescent prefix 下的 correct packet、内容相反 corrupt packet 和等长度 sham/withheld 三臂，并固定 receiver checkpoint、repo/tool state、未来 collaborator 行为与 paired decoding seed。只有 downstream action 随 `k0/k1` 内容方向一致变化，才标为 application；最终 pass、patch overlap 或消息提及不构成标签。
- 协作动作反事实只能在新的 open-weight harness 的 quiescent barrier 分支。快照必须包含两端 worktree/container、git index、完整 conversation tokens、task/message/scratchpad、permission、tool budget、checkpoint/adapter/tokenizer/template 和 RNG。异步中间时点不得声称可精确恢复。
- 从同一前缀分别运行继续并行、A→B 串行、B→A 串行、targeted query+contract 和 handoff/reassign；team success、conflict-induced regression、overwrite、通信成本、wall-clock 与浪费工作形成策略回报。

损失：

- `L_D`：以任务隔离的 `E^*` 为校准目标的 Beta-Binomial NLL，学习团队 expertise-location belief。
- `L_C`：对可验证 claim/commitment 的 conditional Brier 或 NLL，UNKNOWN 不当作失败，并加入 `D`—`C` 辨别约束。
- `L_Q`：以两世界 contract oracle 为监督的 task–knowledge requirement 损失。
- `L_A`：correct/corrupt/sham 内容交换的四类配对干预损失，区分有益使用、有害使用、未使用和不可判定。
- `L_J`：独立的软件语义关系损失，包含方向排序与校准，但不计作 TMS 理论贡献。
- `L_π`：基于相同初始状态多种协作动作结果的 constrained/CVaR policy loss，同时限制联合回归、时间与通信成本。

### 6.5 理论替代与反证

首要基线：

- central planner、shared scratchpad、固定专家分工、全量广播。
- 等参数 sequence Transformer。
- heterogeneous graph Transformer。
- Claim Plane-SDM 加简单历史成功率。
- Shepherd 的预算匹配 supervisor。
- SkillGraph 的 coding 适配版。
- MoE router。
- generic belief-state POMDP。
- CooperBench 官方多 agent 与强单 agent。

理论中和：

- 打乱 agent—专长对应。
- 冻结失败后的 reliability 更新。
- 打乱 task—knowledge dependency。
- 固定消息内容，只操纵知识是否实际用于 patch，并比较“已发送即已应用”的替代。
- 固定真实能力，只改变过去承诺兑现率，检验 expertise 与 credibility 是否可分。
- 固定任务和代码图，交换两个 agent 的领域专长。
- 中途撤销工具权限、替换 checkpoint 或污染检索结果，检验后验更新与 handoff。
- 删除互依赖，检验 TMS 优势是否按理论消失。

必须分别比较强制通过 `Z_t` 的 TMS bottleneck、允许原始特征 bypass 的模型，以及同标签、同参数的直接 Graph Transformer。若任一通用替代在未见 agent 组合、仓库和任务依赖上复制结果，TMS 只能保留解释作用，不能宣称独立理论算法贡献。

### 6.6 算力与工件

团队状态模型可采用 100M–500M temporal graph，7B–9B policy 只作 QLoRA，模型训练本身不是主要瓶颈。最低 rollout 规划约含 1,920 次 solo capability probes、4,000 条可验证 commitment、2,400 个 Q-positive 及等量 negative、6,000 个短程 application branches 和 6,000 个 terminal policy continuations，预计处理约 2.5–4.5B tokens，并产生 1–3TB 容器缓存与日志。需要至少 4 张 48GB 或 80GB GPU 并行数个 GPU-week；单张 24GB workstation 判定 NO-GO。独立工件包括 TMS state encoder、coordination policy checkpoint、expertise/claim-reliability posterior、data split manifest、container snapshot manifest 和 multi-agent causal replay logs。

训练任务至少覆盖 1,200 个 task families 与 80 个 repo/fork networks，按 lineage、base commit、generator template、两世界 variant 和所有反事实 branch 整组划分；另做时间、未见 checkpoint 与未见 agent-pair 外测。先运行 20 个 repo、120 个 family、200 个 prefix 的 pilot。两世界构造通过率低于 70%、application 非歧义率低于 25%、content-treatment first stage 低于 0.20，或 paired-seed agreement 的 kappa 低于 0.60 时撤题。

### 6.7 撤题条件

- 合作收益只来自更多 token 或更多消息。
- 静态专家路由器或共享上下文即可复制。
- `J_t` 单独或 Claim Plane-SDM 加一个历史成功率即可复制；此时成果属于语义依赖控制，不属于 TMS。
- SkillGraph 的 active-skill 与 running-accuracy 适配版达到相同前沿。
- 无法把知识分享与实际知识应用分开。
- expertise 与 credibility 不能在匹配实验中区分，或知识应用只能由最终结果后验推断。
- 无法生成互不兼容的两世界 knowledge requirement，或只能用 gold patch/slice 相关性代替必要性。
- 无法在 open-weight quiescent prefix 上恢复完整状态并进行 correct/corrupt/sham 与五动作配对分支。
- 资源仅支持单张 24GB GPU，无法完成最小因果 rollout；不得改用 LLM judge 或闭源一次日志填补。
- AgenticFlict 只能用于冲突分类，不能评价 policy 的实际修改后果。
- 安全结果退化为普通 team pass rate，没有 overwrite、越权或 conflict-induced regression。
- 策略退化为总串行、总 handoff、总拒绝，或仍只是四分类路由。
- 无法从同一初始状态获得多种协作动作结果，导致策略价值受不可识别的离线选择偏差支配。

## 7. C3：有限注意下的可验证监督证据

可信取证动作、公开预训练资源和真人实验最低门槛已经单独冻结在 `00H_论文三可信取证与真人实验冻结规格.md`。该规格不表示伦理审批、受试者招募或数据收集已经完成。

### 7.1 风险与决策点

agent 已形成候选命令、patch 或部署前状态时，人类需要决定继续、要求补充证据、修改范围、暂存、拒绝或转交。风险是审核者没有看到真正决定后果的差异，或在重复批准中形成习惯化，错误允许高影响行动。

研究对象不是预测“人会不会点批准”，而是学习在有限注意与不同知识分布下，哪一种绑定真实行动的证据能改变最终执行安全。

### 7.2 直接近邻与必须越过的门

- Oversight Has a Capacity 已把疲劳审核者、选择性分类和倒 U 型 escalation load 做成开放测量系统。
- Oversight Game 与 contextual-bandit extension 已研究 play/ask/trust/oversee。
- Value of Information 已把询问收益减去认知成本形式化。
- HiL-Bench 已构造 300 个含 1,131 个 blocker 的 SWE 与 SQL 任务，并用 32B LoRA 加 RLVR 直接训练何时 ask human；一般的 selective escalation 已被正面覆盖。
- Agentic Abstention 已把 answer、abstain 与继续获取信息写成序贯问题，并在 28K 以上任务上评价及时停止。
- AuthBench 已研究权限 sufficiency 与 tightness，AmPermBench 已评价 coding-agent permission classifier，Codex Auto-review 已部署独立 agent 审批 sandbox 边界动作。
- AutoPermissions 已预测个体化数据授权偏好。
- RTBAS 已实现风险自适应 approval 与信息流标签。
- Consent Integrity 要求审批展示由可信 mediator 从实际行动派生并绑定 exact execution。
- Coding with Enemy 的真人长时实验显示，单个 monitor 警告并不保证有效干预。
- Habituation at the Gate 观察到重复 agent code review 中批准上升、评论努力下降，但没有直接 defect label。
- Tolzin 与 Janson 在 Internet Research 的系统综述已将 common ground 正式用于 human–agent interaction，并综合出 embodiment、social features、joint action、knowledge base 和 conversational-agent mental model 五种机制。因此，本文不能把“首次把 common ground 用于人机互动”作为理论贡献。
- Poelitz、Doshi-Velez 与 Lindley 已发布 human–AI common-ground benchmark，以共同拼图、共享/非共享视图和真人实验测量任务结果、指称协调、澄清与修复。一般 common-ground benchmark 和对话 grounding 也不是空白。
- Li、Gatt 与 Poesio 在 13,077 个不对称对话指称上发现部分 VLM 会把潜在共享信息误当作已经通过互动建立的共同理解。C3 若保留，必须动态区分“可见证据”与“审核者已理解并能据此纠正行动”，不能把证据出现直接标为 grounding。
- BSG-VA 已把 coding-agent 的 post-edit validation command 与精确 working tree 绑定，并在 pinned container 中对 buggy、candidate 和 gold 状态重放相同证据，区分 bug-discriminating、candidate-specific、regression-only 和 misleading evidence。它已有 3,730 个 validation events、643 条 rollouts 和 110 个任务。C3 不能把命令重放、证据角色分类或 bug-contrast feedback 本身作为贡献。
- PICK 已在 regex、LTL 和 access-control 等受限语言合成中主动生成能够区分候选的 concrete scenarios，按信息增益和覆盖选择后询问人类，并公开真人研究与 VSCode artifact。主动为有限人审选择区别性证据不是空白。
- AutoSD 已使用 hypothesis、prediction、debugger experiment、execution observation 和 conclusion 产生可执行 patch explanation，并用真人判断 patch correct/no/unsure；其一项似是而非推理还诱发错误接受。C3 不能退化为 scientific-debugging trace 或 explanation clone。
- CAVA、Proof-Carrying Agent Actions 与 Consent Integrity 已覆盖 canonical action、trusted rendering、hash-bound approval、receipt 和 attestation。精确展示与 action binding 是前置基础设施，不是 C3 新贡献。
- 比较 computer-use agent 监督界面的 N=48 研究已经显示，显示策略会影响攻击发生，但在风险已经可见后并未显著改善干预成功。C3 必须固定 escalation 与候选行动，不再比较监督时点或界面模式。
- FixCheck、SWT-Bench 和 c-CRAB 已覆盖生成测试、fail-before/pass-after 验证与从真实 review comment 构造 executable tests；TraceView、Software Delegation Contracts 和 RevMate 已覆盖轨迹图、静态 evidence bundle、额外上下文检索与 review comments。更多测试、图形化 trace、模板包、普通检索或 rerank 均不足。
- 通用 learned selective explanation 已有 CVAE、selective explanation 与人机研究。学习一个 top-k explanation subset 本身不能构成 C3。

因此，简单 escalation policy、when-to-ask、permission negotiation、fatigue-aware threshold、个性化 approval predictor、更醒目的警告、一般 common-ground 对话 scaffold、静态 evidence selector 或 test generator 都应撤题。C3 只有同时满足四项才可保留：审核已经由外部机制确定；证据锚定 canonical command/diff/pre-state/snapshot hash；学习下一项可执行证据动作、子集与顺序，并依据 reviewer grounding feedback 更新共同理解；以真人 unsafe approval 为主要结果，同时约束 safe approval、审核时间和计算成本。

### 7.3 候选理论责任

当前首选是 joint activity/common ground，有限注意与 habituation 作为边界条件。双层计算图、关键张量、共同基础前向门、训练阶段、随机真人设计与等参数反证已经冻结，当前判定为 **DESIGN-FROZEN / RESULTS PENDING**。共同基础是否经 factual grounding 改善误批、是否越过 Human-state POMDP 仍是待运行的结果门；完整责任与撤题条件见 `00J_候选三共同基础理论责任红队与撤题判定.md`。

common ground 不只是双方分别知道一个事实，还要求各方有证据相信对方也理解共同目标、资源、风险与承诺。grounding criterion 要求在高影响交接之前获得足够的理解证据。若审核界面只展示 agent 自述的摘要，审核者可能与实际命令或 diff 没有形成共同基础。现有研究进一步要求区分 potential common ground 与 established common ground；静态可见信息、完整 diff 或一条确认消息都不能自动证明理解已经建立。

理论只能产生：

- 对 joint objective、允许范围、关键风险和承诺的结构化命题。
- agent 对审核者知识的一阶估计，以及审核者是否已经通过可观察回答、定位或反事实判断形成支持证据的状态。
- 每项命题的 action-derived support、contradiction 和 observability。
- potential/established grounding 状态、grounding sufficiency 与 remaining attention。

还必须显式表示 presentation、clarification、repair、acceptance 的命题级阶段，以及双方是否已有可观察证据认为对方理解并使用了本次修复的 reciprocal-recognition 状态。证据有效性、测试生成、损害预测、action hash 与 hidden oracle 都来自技术层，禁止归因于 common ground。

理论动作不是“多给解释”，而是选择能使关键命题达到 grounding criterion 的最小可信证据，或在无法达到时改变执行方式。

### 7.4 工件草案

工作名：Grounded Oversight Evidence Policy。

输入：

- 用户任务和组织 policy。
- 外部 gate 已经确定必须审核的事件；模型不再决定 ask、allow 或 deny。
- agent trajectory、canonical command、exact parameters、diff、pre-state、snapshot hash、测试与 state delta。
- 变更依赖、可见与隐藏义务。
- 审核者历史正确率、负荷、审查时间和知识域。
- 可生成的可信证据候选，如具体 changed invariant、反事实测试、权限差分、影响路径和未解决冲突。

中间张量：

- proposition × participant belief matrix。
- proposition × evidence support/contradiction tensor。
- evidence observability 与 action-binding mask。
- reviewer attention state 和 expected correction value。

输出动作只作用于审查证据过程，不直接替人批准或拒绝：

- 继续在 sandbox 或 shadow state 中执行。
- 对 buggy/candidate/reference 或其他可构造反事实状态执行一项额外验证。
- 重放并比较一条精确 validation command 的结果。
- 展示 action-bound evidence set，并提出能观察审核者理解的针对性判断问题。
- 根据审核者的正确、错误或不确定回答更新 grounding state，再选择下一项证据。
- 选择第二审核者或知识域拥有者。
- 在证据预算用尽或仍不能达到 grounding criterion 时，把事件交回外部 gate 处理。

训练目标：

- 人类判断与 executable ground truth 的校准损失。
- evidence selection 的 set utility loss。
- unsafe approval、safe rejection、review time 和 alert load 的多目标策略损失。
- 命题 grounding consistency 与 action-binding 约束。
- 不同审核者知识域间的 off-policy 或 contextual policy learning。
- 序贯证据动作的 learned policy loss；静态 top-k 与纯信息增益选择作为强替代。

### 7.5 数据方案

阶段一，公开观察数据：

- AIDev 的 agent PR、review、inline comments、commit diff 和时间线。Hugging Face 数据卡标示 CC BY 4.0，但同时明确各仓库内容、patch 和文件仍服从原仓库许可证；使用时必须按 source repository 筛选并保存许可证 manifest。AIDev 只能提供自然审核行为，不能提供隐藏 defect 或反事实证据真值。
- RevMate 等公开或可申请的 review-comment interaction 数据。
- CooperBench 或 SWE-bench/SABER 产生的候选变更与真实 executable outcome。

阶段二，必须实施受控真人实验：

- 从可安全隔离的 coding tasks 中抽取 safe、unsafe、ambiguous 和 misleading-evidence 条件。
- 每位开发者连续审核多个任务，以观察负荷、学习和 habituation。
- 系统展示必须由 trusted mediator 从真实 diff、命令和 state delta 派生。
- 最终以隐藏测试、policy predicate 与实际执行结果判断，不以参与者 click 作为真值。

形成性试验只用于检查任务和日志。正式实验以至少 90 名具有真实代码审查或命令行经验的 working developers、每人 12–18 个平衡 trial 为规划下限，并在收集前用 participant/task random effects 的模拟功效分析校准。最低三臂是 canonical raw action、预算匹配的最强静态证据包和 learned acquisition/selection/grounding policy。若功效分析要求更大样本，必须扩大。

训练、验证、测试需按 repository、risk family 和 reviewer 分组。最终测试保留未见仓库、未见风险类型和未见审核者三种外推。

### 7.6 公平基线

- 所有 mutation 都审核。
- 固定风险阈值审核。
- Value-of-Information。
- Headroom/FALCON/DeCCaF 风格有限容量 deferral。
- RTBAS 或 risk-adaptive approval。
- 普通 patch summary、完整 diff、随机证据、固定 top-k evidence。
- BSG-VA 证据角色与 bug-contrast feedback。
- PICK 的信息增益/覆盖式 distinguishing scenario selection。
- AutoSD scientific-debugging evidence trace。
- FixCheck、SWT-Bench 与 c-CRAB 的可执行测试证据。
- 等参数 cross-attention evidence selector。
- generic contextual bandit/POMDP。
- Human-state POMDP：显式预测审核者 factual correctness 与 response propensity，但没有 joint-purpose 类型、potential/established 区分和 reciprocal recognition。这是最关键的理论反证。
- Raw-POMDP 与 Proposition Transformer：获得相同 raw trace、命题、动作、标签、参数和预算，但不接受理论更新约束。
- Poelitz 等人的 common-ground benchmark 指标适配版，以及只预测 potential/established grounding 的模型。
- oracle reviewer 与 oracle evidence。

### 7.7 撤题条件

- 无法完成真实开发者序贯实验，只能用 persona LLM 模拟。
- 功效分析、伦理审批或招募无法支持确证性真人实验。
- evidence 与实际动作不能建立 trusted binding。
- 审核策略仍决定是否询问或是否执行，而未固定为 post-escalation evidence problem。
- 模型不能主动取得或重放可执行证据，只能整理已有文本。
- 主要工件只预测 click 或 approval preference。
- 结果只有主观信任、可用性或满意度，没有 executed harm 与正常任务结果。
- 简单 top-k 静态分析告警或完整 diff 即可复制。
- BSG-VA、PICK/AutoSD、Consent Integrity 和 selective-explanation 的组合基线达到相同真人安全—成本前沿。
- common-ground 状态打乱后，人类和系统行为没有理论预期变化。
- Human-state POMDP 在等参数、等数据、等预算下复制安全—效率前沿，或 unsafe approval 的改善不经 action-specific factual grounding 改善中介。
- 证据一经展示就被模型视为已经理解，或只靠静态 evidence selector 获得收益。

## 8. C4 撤销记录：学习型补偿程序

**当前最终判定是 HIGH-CONFIDENCE NO-GO / TERMINAL，无保留，并从现行三篇系列移除。** 旧案审计见 `00V_C4学习型补偿程序终审.md`；针对最新 agent compensation、bounded repair、recovery-command learning 和 program-synthesis 近邻的重开复核见 `01Z_执行后损害补偿程序候选终审.md`。以下内容只保存被否决方案的最强技术版本，不再构成备选题位。

该候选处理损害已经发生后的代码、配置、依赖、进程与模拟外部服务恢复。算法需联合学习 first unrecoverable step、typed effect graph、compensating action synthesis 和 safe-state verifier，输出可执行补偿序列。

直接近邻极强：Human-Guided Harm Recovery 已覆盖自然语言恢复计划排序；AgentRx 覆盖关键失败步；Revisable by Design、Atomix、Cordon、DeltaBox 覆盖 rollback 与 transaction；dependency-guided rollback 已覆盖 provenance slicing、受影响子图和 selective replay。DART 又把 failed-instance localization、recoverable-boundary certification、instance-aligned checkpoint 和 dependency/effect-aware admissible rollback 联结起来。重开复核进一步发现，RAC 已用持久事务日志、执行图、compensation pair 与参数映射执行 post-hoc compensation，Mnemosyne 已覆盖 dependency-closed、evidence-preserving、bounded repair，Ikeuchi 等人 2020 年已经从日志学习可执行恢复命令，PASE 则公开提出 recovery-primitive program synthesis 与 world-model 验证。剩余能力被压缩为 repository-aware 的迁移和动作语法扩展。

原设计认为下列能力可能形成剩余空间，但终审确认它们不足以恢复题位：

- 处理无法精确逆转的 external side effects。
- 生成具体 compensating patch/action，而非找到节点后 revert。
- 执行后以 invariants 和 hidden checks 验证 residual 与 secondary harm。
- 在恢复安全的同时保留未受影响的有效工作。

Tim 与 Leidner 的 digital resilience 将恢复界定为个人、组织和社群面对外生冲击时，通过 IS 的设计、部署和使用实现 continuity、adaptation 与 advancement 的容量。该框架能够解释恢复结果与资源调动，却不能推出 effect graph、first unrecoverable step、补偿动作语法、恢复顺序或训练损失。把三种恢复表现设为输出 head 仍可被通用 temporal GNN 或 POMDP 原样复制，并且局部 agent 错误不自动等同于组织所面对的外生冲击。故本题即使技术上可训练，也不满足本系列的理论驱动算法要求。

## 9. C5 撤销记录：功能正确但安全回归的修改

SecureAgentBench、SecRepoBench、SEC-bench、SECODEPLT 和 Endor/SusVibes 已提供真实仓库、功能测试、安全 predicate、PoC 和 CWE 覆盖。CodeMonitorBench 又在 71,000 个候选上固定 public-test/hidden-oracle 边界，直接研究通过公开测试后仍有隐藏缺陷的监控；RETRACE 已用前向修复理由与反向问题重构给出独立 patch verification 和 targeted revision；Terminal Wrench 与 hacker–fixer loop 已覆盖 verifier reward hacking 与自动 hardening；MPC-Patch-Bench 等领域资源也同时提供功能与安全 oracle。

然而 secure patch generation、functionally-correct-yet-vulnerable patch、red-team program repair 和纵向 security degradation 已有大量直接工作。普通 CodeQL 加语言模型、patch correctness classifier、漏洞 head 或 proof-obligation reranker 都不足。

本题当前判为 NO-GO，不再作为第三题备选。原因不是数据不足，而是可训练动作仍收缩为 patch correctness/risk prediction、generated-test monitoring、verifier hardening 或 revision guidance，且尚无一个由 IS 理论产生、又不能被通用依赖图和学习 verifier 复制的中间结构。未来若出现不同的真实行动空间和可识别理论机制，只能作为新候选重新审计，不能凭现有安全数据集恢复题位。

## 9A. C15 撤销记录：开发者未来独立恢复能力保持

该候选以 agent 当前完成任务时的人类参与配置为行动，以 agent 不可用条件下开发者对延迟隐藏事故的恢复成功、残余损害和人时为外部结果。隔离仓库、随机分派参与动作、延迟复测和本地策略训练均可以实施，因此撤题不以缺少数据或尚无结果为理由。

设计层存在两个不能留给未来显著结果解决的缺口。第一，Rinta-Kahila 等人的 activity awareness、competence maintenance 与 output assessment 是 mindful-conduction 活动，不是独立的 skill state 或状态转移律。候选的 relational graph KT、temporal Transformer 与三项平均方向损失可以被同输入、同维数、同邻接和同干预位置的匿名状态模型逐层重参数化。第二，参与处理会产生测试、契约、不变量和笔记等持久软件资产，这些资产可直接帮助后续事故恢复，造成 `参与→资产→恢复` 与 `参与→能力→恢复` 并存；当前实验不能把总效应归因于理论主张的技能中介。

Buçinca 等人的 adaptive support、Geometry、HAAS、Agents That Teach、AI Coaching 与 Proximal State Nudging 已覆盖当前表现、潜在技能、技能演化、未来独立能力和序贯行动的主要组合。delayed agent-unavailable recovery 仍适合发展为 HCI/SE 实证研究或 benchmark，但在更换理论并分离 person-capability 与 software-asset 通道之前，不得作为本系列论文题位。终局依据见 `01I_开发者恢复能力候选独立红队.md`。SymPareto 仅核验正式元数据与摘要，完整主文仍缺失；本撤题结论不依赖对其内部方法的推测。

## 9B. C18 撤销记录：普适可靠发布行动

该候选把 repository change、CI、预发布、canary、正式推进、持续验证与回退连接成一个安全行动 episode，并以服务中断、数据或安全回归、错误扩散、正常发布成功和交付成本为结果。开源微服务、DevOps-Gym、UnderSpecBench、LoopsBench、Kayenta、Argo Rollouts 与故障注入工具足以支持严谨构造，所以撤题不以环境或算力不足为理由。

对象边界和理论责任在设计层失败。若模型只能在 rollout 阶段选择观察、推进、暂停或回退，repository code change 可以被一个固定 upstream generator 替代，主要工件就是 progressive-delivery/AIOps controller。若模型还能自由拆分提交、增加兼容层和观测点、修改代码、配置与依赖，动作空间失去跨项目稳定真值，剩余增量成为代码综合、world model 和 rollout policy 的系统集成。CAS、anytime-valid 回归检验、强化学习 staged rollout、CloudCanary、SafeRevert、ARBITER、Safe Remediation、Cordon 与 DART 已分别覆盖主要动作和约束；Ghaleb、UnderSpecBench 与 LoopsBench 又占据真实 CI/CD 修改、DevOps 行动边界和长期回归义务。Jiang、Sarkar 与 Jacob 已经直接建模发布与停止测试时钟，其他候选理论只改变成本、认识不确定性或组织解释。把相同状态、动作、监督和预算交给 generic distributional SMDP/POMDP 或 temporal graph 后，当前设计没有不可交换的理论计算。trace-economic underwriting 还封闭了 trace 到经济损害、CVaR 与 pre-loss control 的救援方向。完整终审见 `01K_可靠发布行动候选终审.md`；本题不得以“自主 DevOps”“风险敏感发布”或“端到端 code-to-production”改名返回。

## 9C. C19 撤销记录：有限审核容量下的安全审核分配

该候选只允许在滚动队列中选择指定审核者、单审或双审、开始时点、延后或预定义沙箱，不允许决定是否询问、证据内容或最终批准。主要安全结果原拟由隐藏测试、安全不变量和配置约束判定，并同时报告安全变更吞吐、积压、延迟和人类审核时间。因此，撤题不是因为风险虚假、工件不够“硬”或执行结果无法构造。

决定性失败发生在直接增量和理论计算。WhoReview、SofiaWL、Meta审核者推荐随机试验、风险感知review recommendation、AddExpertRec和高风险diff生产推荐器已覆盖审核者集合、专长、负荷、知识分布、队列与追加专家；DeCCaF、Kelly、multi-expert deferral、FALCON和多技能动态人员调度又覆盖容量、相关错误、双审边际价值、疲劳、恢复与学习。隐藏执行oracle能够把历史merge或评论代理换成真实unsafe approval，却不能把这些既有动作变成新的算法类。AIDev/c-CRAB/BulkPR/OpenL2D分别提供到达流、部分执行oracle、队列任务或合成专家，没有一项给同一真实变更在不同审核者和负荷状态下的随机化潜在结果。TMS、组织注意、习惯化与双过程理论只能建议专长、注意或疲劳状态；把相同输入交给等参数matching Transformer、CMDP/POMDP、restless bandit或通用人员调度器后，没有不可交换的理论运算。该题还与C3的第二审核者动作、C2的TMS和C15的人类技能结果重叠。完整终审见`01M_有限审核容量下的安全审核分配候选终审.md`；不得以“风险感知审核”“有限注意调度”或“真人隐藏oracle”改名返回。

## 9D. C21 撤销记录：并发仓库漂移下的可靠变更

该候选研究 coding agent 在长任务中依据旧快照读取、规划和修改，而人类、其他 agent、CI 修复、依赖 bot 或安全补丁同期改变 upstream、branch 或 worktree 的情形。拟议结果包括有效工作丢失、安全修复复活、文本 clean 但行为错误的合并、任务成功和复验成本；拟议动作包括定向刷新、隔离、重放、语义调和、patch 拆分、重跑义务、移交、终止与提交。问题和执行环境均真实，撤题不以风险虚假或算法不够复杂为理由。

决定性失败是直接能力和理论运算都已被占据。Claim Plane 已把 base commit、资源、依赖和写入准入绑定，CoAgent 与 CodeCtx 已实现旧读取前提的通知、影响定位和局部修复，STORM 管理共享代码库的一致状态，EA-Graph 管理 artifact-bound 证据的新鲜度，ConflictBench、SAM、sMerge 与 Merge-Bench 又覆盖文本或语义冲突检测和调和。temporal coordination、coordination fit、team awareness 与 artifact-based coordination 下推后只留下时延、依赖边、通知、可见性 mask、artifact 特征和动作成本；把相同输入、动作、执行标签、预算和 action mask 交给等参数 temporal graph world model、SMDP/POMDP 或 model-predictive controller 后，没有不可交换的理论运算。AgenticFlict、CooperBench、AtomicCommitBench、LoopsBench、SWE-CI 与 EA-Graph 也不同时提供 agent read/tool trajectory、外生漂移和同前态多个行动程序的后果。完整终审见 `01N_并发仓库漂移下的可靠变更候选终审.md`；不得以“stale-context world model”“时间协调式语义调和”或“仓库漂移感知 controller”改名返回。

## 9E. C22 撤销记录：模型与 Scaffold 安全兼容及更新控制

该候选研究一个真实的版本决策风险。模型、控制循环、工具接口、上下文压缩和权限策略独立升级时，同任务、同环境与同预算下的任务成功可能保持不变，而越权访问、危险命令、信息泄露或不可恢复修改增加。最强设计并非二元兼容分类或模型路由，而是从升级前后配对轨迹预测安全、任务与成本后果，生成最小可执行 harness patch，并选择成组更新、双轨、隔离或回退。HarnessAudit、SABER、Harness-Bench 与开放 harness 足以构造这类沙箱数据，所以撤题不是因为尚未运行实验、数据无法获得或工件不够复杂。

决定性失败发生在直接新增能力和理论责任。Scaffold Effect、Inside the Scaffold、HarnessAudit、Harness-Bench、Safety Under Scaffolding 与 Don't Blame the Large Language Model 已经覆盖 scaffold 结构、模型—harness—任务交互、安全—完成脱钩和连续版本回归；Dunke 与 Nickel 把历史实例驱动的配置、算法生成与运行时控制纳入自动算法设计，HARBOR、HarnessOpt-Bench 与 RHO 又分别实现约束配置和可执行 harness 修改，SafeHarness 与 HOL Guard 提供权限、隔离、检查点和回退。Goodhue–Thompson 的 TTF 以人类个体利用技术并产生个体绩效为单位，Cram 等人的 control alignment 以包含员工社会情绪行为和控制执行的组织 IS process 为单位，Bharadwaj 的 IT capability 以企业资源与企业绩效为单位；三者均不能无损下推为一次 model–harness release。互补性若保留 increasing-differences 约束便与跨模型的替代、排序反转和符号变化冲突，若允许任意正负交互又成为通用因子图、图 Transformer 或约束 AutoML 可以复制的结构。完整终审见 `01Q_模型与Scaffold安全兼容候选终审.md`；不得以“安全兼容学习”“理论化 harness AutoML”或“风险感知成组升级”改名返回。

版本冻结 manifest、升级前后配对 rollout、任务风险图、格式保持的对照实例、模型与 harness 家族双留出、隐藏测试隔离、操作损害指标和 HarnessAudit/SafeHarness/HOL Guard 基线仍可复用。它们适合作为其他研究的共同 CI、消融或外部测试基础设施，不构成新的独立理论工件。

## 9F. C23 撤销记录：共享 Agent 栈下的共因失效遏制

该候选把多个仓库任务或部署 cohort 视为共同暴露单元，研究共享模型、harness、工具链、权限策略或 evaluator 更新如何造成相关的危险命令、安全回归、功能破坏与虚假完成。最强工件沿版本化组件谱系学习共同原因潜状态和联合尾部损害，再在匹配成功率与吞吐下选择多样化配置、影子验证、分批暴露、暂停、隔离、回滚或撤回。SABER、SecureVibeBench、PatchEval、Harness-Bench 与 N-version 工件足以在隔离环境重建 factorial update episodes；建立这些数据虽昂贵但可执行，因此撤题不是因为候选实验尚未运行或暂时缺少公开 benchmark。

终止性证据来自能力覆盖与研究对象删除检验。Temizkan、Park 与 Saydam 的 ISR 论文已经把共享软件漏洞、网络传播、多样性度量、配置优化、动态重配和安全—成本权衡连接成工件，N-Version Programming with Coding Agents 直接测量模型、harness 与语言多样性下的共现失效，Koran 等人按单体质量和误差相关性选择监控器组合，Harness-Bench、Scaffold Effect、Don't Blame the Large Language Model 和 AI 组件生命周期控制又覆盖共享 harness 指纹、版本更新、shadow、gate 与 rollback。最强剩余结构只是 component-lineage dynamic factor model 加 distributional CMDP；等参数异质图 Transformer 和通用策略看到相同谱系、轨迹、风险、成本与 action mask 后可以执行同一运算。若将 coding-agent 单元替换为微服务、批处理作业或其他共享软件 fleet，输入张量、共因 posterior、联合尾险目标和主要动作仍保持不变。完整终审见 `01R_共享Agent栈下共因失效遏制候选终审.md`；不得把 C22 的单实例兼容扩大成 fleet 术语，也不得把 C18 的发布控制或软件多样性配置改名后返回。

版本化 stack BOM、exposure-set 数据结构、相关损害与最坏 cohort 指标、component-lineage split、共享更新压力测试、incident count 与条件概率的区分、Temizkan/N-version/Koran 基线和 canary 后残留副作用记录仍可复用。这些资产适合作为现有研究的多仓库外测层或公共 benchmark，不占据独立论文席位。

## 9G. C24 撤销记录：面向决策适用性的数据管线修复

该候选原本研究多个下游消费者依据同一数据产品作出不同决策时，coding agent 如何识别一个表面通过 schema 与数据质量检查的管线变更，是否仍支持各消费者的真实决策语义，并通过修改转换、版本、兼容层或输出契约减少错误决策。其损害、执行环境和训练工件均可构造，撤题不以“数据工程不重要”或“没有足够复杂的模型”为理由。

终审发现，候选无法形成肖老师论文所要求的 MEC→MAP→ALG 连续责任。Ballou–Pazer 讨论的是同一现象的信息随时间变得更准确却更陈旧，不能为业务语义被重新定义后的 consumer-relative 适用性承担机制责任。IPMAP 与 IPView 已把共享制造路径、信息产品、多个消费者、任务用途和上下游追踪连成直接 MAP；DataPrism、PrismaDV、MellowDB、BiDEL 与数据程序修复工作又覆盖版本化语义、双表示、迁移和修复。把相同原始合同、谱系、消费者任务、执行标签和动作预算交给等参数异构图与 distributional POMDP 后，候选的 `R/Q/H` 状态和动作可被复制。所谓 paired worlds 若不留下可见差异便不可学习，若把完整语义账本公开给模型又退回已有 contract 或 semantic migration。删除 coding-agent 身份后，输入、模型、动作和结果仍构成完整的自动数据管线修复器。完整终审见 `01T_决策适用性数据管线候选独立终审.md`；不得以“consumer-relative safety”“semantic drift head”或“双图决策适用性”改名返回。

## 9H. C25 撤销记录：软件来源与许可证安全

该候选指向真实的组织风险。coding agent 可能在检索、复制、生成和依赖引入过程中带入具有署名、通知、源代码提供、相同许可证、修改说明或其他条件的工件，并在来源、组合方式、授权例外或分发目标不完整时继续合并和发布。最强版本可以构造来源—依赖—许可证—组织政策异构图，训练后果模型与多步策略，并实际执行 replace、rewrite、isolate、seek-permission、generate-notice 或 stop-release 等行动。

终审仍判为 NO-GO。SourceTracker、LiResolver、SILENCE、LiVo、PolicyGuard 和现有 SBOM/许可证工具已经分别覆盖来源、条款、兼容性、作用域、多类修复与轨迹合规；剩余联合系统主要增加集成范围。公开数据没有同时给出权威来源事实、实际链接与修改方式、适用义务、另行授权、分发情境、可执行替代修复、功能保持和权威裁决。以规则求解器合成标签会使学习器复现规则，以缺失事实直接判断又不可识别。财产权、信息治理、知识产权规范、项目控制和边界资源能够解释权利与组织边界的重要性，却没有导出许可证修复独有的关系运算或行动方向；删除理论标签或删除 coding-agent 身份后，等参数异构图与 constrained POMDP 仍可执行同一任务。完整终审见 `01U_软件来源与许可证安全候选终审.md`；其来源 manifest、许可证事实边界和分发假设可供其他研究做合规检查，不能占据独立论文题位。

## 9I. C26 撤销记录：AI 加速漏洞的协调修复与披露

C26 的潜在损害与 coding-agent 工件都是真实的。候选可以让 agent 在授权、隔离的历史漏洞上生成补丁、缓解、回移植和分层披露包，并让 attacker/defender runners 对同一字节工件产生可执行后果。撤题并非因为这个环境不能构造。决定性问题有三项。第一，Cavusoglu、Arora、Mitra–Ransbotham、Vultron/FIRST 与现实 CVD 政策已覆盖披露制度、protected period、补丁速度—质量—采用、选择性预警、相反扩散和多方协调；PatchWeaver、KeaRepair、PatchEval、PoCEvolve、Anthropic N-day、ADAPT 与 VulnGym-APT 又覆盖修复生成验证、patch-as-signal、容量和攻防策略。剩余联合 I/O 是这些能力的交集。第二，理论可合法产生 attack、protection、patch readiness、quality、adoption 与 workload 状态，却没有指出等信息、等标签的通用 temporal graph 与 distributional SMDP 会沿哪个稳定方向算错，也没有给出不可交换的 remedy-specific 运算。第三，历史披露只观察一条行动路径；自建 simulator 若用同一规则生成标签再证明理论 heads，存在循环识别。equalize remedy bytes 或换用外生强补丁后，披露政策仍可运行，说明 coding agent 仅对工件模块不可删除，尚不足以支撑整篇 ISR 题位。完整证据和 41 条强化 `00F` 句级责任见 `01V_AI加速漏洞协调修复与披露候选终审.md`。隔离式 common-seed benchmark 可以另作安全系统项目，不得以“联合 remedy 与 disclosure”改名回到系列。

## 9J. C27 撤销记录：策略性 coding subagent 的委托契约与控制组合

C27 的最强版本不是委托提示词或模型路由。它让 open-weight workers 接收机器执行的任务章程、结果转移和行为控制，在真实仓库里生成 patch 与工具轨迹；principal 再联合选择任务分解、worker assignment、transfer、审计、权限与纠正动作，并以隐藏回归、评价操纵、联合副作用、任务成功和成本评价。该版本在工程上可训练，也通过了窄的 coding-agent 工件删除检验。

独立红队仍判定题位级 NO-GO。核心识别处理由研究者同时规定 worker 的 reward、effort cost、outside option、contract support 与类型，再以同一 utility 和有限 deviation search 计算 best response 与 IC。随机契约只能说明这个人工训练的条件策略如何响应训练目标，不能说明现实 coding subagent 具有外生的隐藏偏好或目标冲突。Adaptive Contracts 已正式化初始信号、选择性精评估、检查、支付和 agent best response；Reward Hacking as Equilibrium、Software Delegation Contracts 与 SCHEME 又分别占据多维质量扭曲、委托章程和真实联合 coding 损害。保留全部 relation semantics、coverage labels、configuration values、IC projection 和执行动作的 typed-graph Stackelberg POMDP 可以逐项实现 ECCG，Huber–Lyytinen 的人类项目 episode、crisp-set conditions、事后 interaction 和 trust/knowledge 演化也不能充当机器 checkpoint 标签。完整 steelman、直接近邻、同信息替代反证及对 01W 句级错锚的核验见 `01X_策略性编码子代理委托契约独立红队.md`。低维 model-organism pilot 只可检验 contract-conditioned 接口，不得恢复论文题位。

## 11. 冻结后的实施事项与结果门

1. 三篇研究设计已经冻结，当前实施顺序是同步完成正式正文、逐段 ISR 对照、引用核验和算法实验规格，再按各自 manifest 构建数据与训练工件。任何实现中发现的字段矛盾必须回到对应锁定稿修正，不能在代码中静默选择一个版本。
2. C3 实施前仍须取得伦理审批、完成人类任务形成性测试和招募可行性检查，并保持 factual-grounding 中介、同一审核者主要结果和等资源 Human-state POMDP 为不能移动的结果门。
3. MOL 实施前须物化 18 app family、72 migration contracts、CodeTwin、operator runner、共同随机 sibling rollout 和 `G-PhysicalFactoredSMDP` quota；所有运行哈希为待实现工件，不能在正文中写成已存在结果。
4. C29 实施前须固定 Vul4J revision/image、1,548 行 eligibility core、六分支 sampler、独立 supervisor/evaluator 和 full-conjunction adapters；natural official 与 overlay stress 始终分开报告。
5. 审计证据捕获已终审撤销。后续若使用 action recoverability、lifecycle coverage、policy checkability、responsibility attribution 与 evidence integrity，只把它们作为其他工件的评价维度，不将日志/schema/hash-chain 或通用选择策略重新包装成独立题位。
6. 隐含授权范围已终审撤销。保留规范权限、主观意图与模型信念的三分法作为数据诊断，不把 scope tensor、询权或多动作 constrained policy 再次包装成新候选。
7. 执行者—验证者分离已终审撤销。异构 verifier 的交叉运行结果、成本和相关残差可作为其他研究的数据资产，不把 source-id、禁止自审硬掩码或多 monitor 序贯调用重新包装成独立题位。
8. 跨所有权边界题已终审撤销。AtomicCommitBench 可作为 patch isolation 资产，Hahn、Zaggl 与 Lindberg 可作为组织边界解释；CODEOWNERS、merge 或 review 不能被用作替代行动的安全真值。
9. 验证义务积累已终审撤销。跨版本 evidence validity、obligation graph、release history 与隐藏回归仍可作为评价维度，不把 stale-evidence debt、变更后重验证或 test-selection policy 重新包装成新候选。
10. 开发者恢复能力保持已终审撤销。延迟 agent-unavailable incident、能力探针和真人随机设计可作为经验资产；不得把 graph knowledge tracing、skill head、参与时长或当前—未来双目标 reward 重新包装成 Rinta-Kahila 理论算法。
11. 普适可靠发布行动已终审撤销。CI/CD 配置语料、DevOps action-boundary、长期 regression obligations 和开源 rollout substrate 可作为其他研究的外测或执行基础设施；不得把 canary、推进、回退、风险分数、CVaR 或大一统 code-to-production controller 重新包装成新题。
12. 有限审核容量分配已终审撤销。reviewer、queue、load与fatigue数据可作为C3外部情境或成本变量；不得把审核者推荐、第二审核者、相关错误、疲劳CMDP或真人隐藏oracle重新包装成独立题位。
13. 并发仓库漂移题已终审撤销。base/current/local tree、read footprint、upstream delta 与语义合并数据可作为其他研究的压力测试；不得把 refresh、rebase、premise invalidation、evidence freshness、semantic reconcile 或通用时序控制器重新包装成独立题位。
