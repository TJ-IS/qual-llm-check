# 目标博士论文的系列组织逻辑借鉴

## 1. 阅读对象

目标文本为：

thesis_collection/浙大-博士-移动文娱平台的内容推荐与展示决策研究-平衡内容生成与使用.md

本文件只记录其组织三个子研究的方法。新系列不沿用移动文娱、推荐、点击—滑动模式、两阶段决策或任何具体算法。

## 2. 原论文如何建立一条主线

摘要第 23–31 行首先建立一个贯穿全文的组织张力：平台推荐通常促进用户内容使用，却可能削弱创作者内容生成；平台持续发展要求同时考虑两端。三个子研究没有各自寻找一个松散的平台问题，而是都服务于“平衡内容生成与使用”这一终局。

主线包含四个稳定元素：

1. 共同情境：移动文娱平台。
2. 共同主体：平台、内容使用者和创作者。
3. 共同张力：短期使用激励与持续内容供给可能冲突。
4. 共同终局：参与者活跃与平台可持续发展。

这些稳定元素使点击与滑动两个不同模式仍属于同一论文。

## 3. 三个子研究为何不是同一模型的机械拆分

### 子研究一

第 25 行及第 247–251 行研究点击与滑动模式下的用户内容使用机制。它处理行为机制，比较质量不确定性、匹配不确定性、获取成本和期望不确认，不直接把后续优化模型拆成第一模块。

### 子研究二

第 27 行及第 253–255 行研究点击模式下的推荐与展示决策。决策变量包括推荐内容集合、页面和页面内二维位置；方法由行为预测、异质性处理效应估计和整数规划构成。

### 子研究三

第 29 行及第 257–259 行研究滑动模式下的序列推荐与展示。滑动使当前展示影响未来使用，决策目标增加当前与未来参与者活跃的平衡，决策变量变成用户下滑中的内容序列，最终使用动态规划。

两篇决策研究共享平衡目标和部分因果估计思想，但情境机制改变了决策对象、状态转移和优化结构。因此，它们不是把同一系统拆成预测、排序和评价三个模块。

## 4. 可借鉴的组织原则

### 4.1 先建立内在张力，再命名三个研究

原论文在提出研究问题之前，用第 231–241 行依次论证创作者生成被忽略、两种获取模式不同、异质性处理效应未知、展示决策结构不同，最后回收到一个总体问题。新系列也应先证明自主状态改变带来的速度收益为何与可靠控制形成内在张力，再说明三种不完全知识如何产生不同决策问题。

### 4.2 共同结果不等于共同算法

原论文的共同结果是内容生成与使用的平衡，但点击研究决定多维位置，滑动研究决定动态序列。新系列可以共同评价安全—任务效用前沿，但三篇必须拥有不同状态、动作、训练标签和模型权重。

### 4.3 情境差异必须改变决策结构

点击与滑动不是标题差异，而是改变用户决策过程、序列相关性、当前—未来权衡和优化方法。对应到现行系列：

- 未来运行条件不完全可见，使数据库迁移必须在可选缓解、延期、执行和放弃之间进行时间条件决策。
- 多 agent 分支共享来源并不等于独立证据，使整合策略必须区分公共来源、证据交换、实际利用和主动可执行探针。
- 人类拥有批准权并不等于已经理解行动后果，使取证策略必须区分潜在共享、已建立理解和事实修复过程。

如果三篇最后都只是同一个 risk score 加不同阈值，就没有达到这种组织强度。

这三项已经分别通过独立设计冻结审计。它们没有把同一风险控制器换三个输入，因为物理时间、来源相关性与人类事实理解分别改变了状态转移、动作语法、训练监督和外部结果。

### 4.4 子研究之间可以有概念递进，但不能相互担保

目标论文的机制研究为后续决策提供依据，但点击和滑动决策各自仍有完整情境、模型、数据和结果。用户对本任务提出了更严格的独立性要求，因此新系列不会让一篇论文的 checkpoint 或正结果成为另外两篇成立的前提。三篇可以共享总体研究张力和必要的容器基础设施，但必须能分别投稿、训练和评价。三个题位独立终审后，共同概念被命名为“不完全知识下的软件状态变更可靠承诺”。

## 5. 不借鉴的部分

- 不照搬“机制研究—两个模式决策”的三段结构。
- 不预设第一篇只能是描述性或实证研究。
- 不采用点击与滑动式二分来制造两个情境。
- 不让三篇共享同一个处理效应估计器或优化目标。
- 不把一篇的中间输出直接作为下一篇唯一输入。
- 不复制章节、句式、公式或结论。

## 6. 对当前系列的具体约束

现行三题用以下六项完成组织核验：

1. 总体张力能否在不提三个模型名称时独立成立。
2. 每篇风险影响的对象和决策时点是否不同。
3. 每篇理论是否产生自己的内部状态。
4. 每篇推断动作是否改变不同的现实关系。
5. 每篇主要数据、标签和 checkpoint 是否独立。
6. 共同结果是否足够统一，同时又没有把三篇压成同一流程的前中后阶段。

六项均已满足。总体张力在不提模型名称时可以表述为：coding agent 能够提高软件状态变更的速度与覆盖面，但关键知识分散在未来环境、其他代理和人类审核者之间，过早承诺会造成实际损害，全面延迟或拒绝又会损害任务能力。论文一影响数据库与服务，决策点是 cutover 前；论文二影响候选修复与仓库，决策点是分支整合前；论文三影响开发者和待执行行动，决策点是固定批准点。三篇分别采用实物期权状态、来源与利用状态、共同基础状态，推断动作分别是缓解格行动、分支控制行动和取证修复行动。训练数据、标签、checkpoint 与 hidden oracle 完全分开，唯一共享的是工程基础设施和安全—任务—成本的评价原则。因此，现行系列借鉴了目标博士论文“共同张力稳定、情境差异改变决策”的组织方法，没有照搬其机制—模式两阶段结构。
