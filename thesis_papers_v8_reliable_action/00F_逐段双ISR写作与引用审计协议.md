# 逐段双 ISR 写作与引用审计协议

## 1. 约束等级

肖帅勇老师是本项目的指导老师，其两篇 ISR 论文是本系列的首要写作与研究设计约束。每个正式段落必须先明确学术功能，再形成句子，不能先写内容后寻找一个表面相似的原文段落。每段完成后立即对照，不等章节写完再批量补审计。严格模仿的是问题建立、证据推进、理论推导、算法落点和贡献回收的功能逻辑；任何原句、近似句式和具体内容均不得复制。

`00C_肖帅勇两篇ISR写作结构图.md` 负责两篇论文的整体结构、引言和理论—算法主链。ACAA 的摘要至方法逐句索引记录在 `00J_肖帅勇两篇ISR全篇逐句逻辑与引文责任索引.md`，经验评价至结论记录在 `00M_ACAA实证贡献与结论逐句逻辑索引.md`；DSDL 的摘要至结论和尾注记录在 `00K_DSDL全篇逐句逻辑与引文责任索引.md`。`00W_肖帅勇两篇ISR源行句段主键Manifest.md` 冻结每个逻辑段的源行集合、语法句 ID、公式/浮动插断、尾注、图像状态，并提供引文密度、句长、段长和标点的可复现 Markdown 代理口径。两篇可获得 Markdown 主文及尾注已完成逐语法句索引，方法公式、表格说明和结果段均在范围内。这一完成状态不扩张到缺失的两篇在线附录和图像视觉内容。正式正文必须持续使用这些索引与主键，不能只精读引言后把其余章节视为普通模板。

审计对象包括：

- 段落是否只承担一个主要功能。
- 每句话对该功能是否必要。
- 句间是否构成事实、机制、边界、缺口和研究行动的可追踪关系。
- 引用是否直接支持相邻主张。
- 每条引用在该句中究竟承担定义、现象、机制、方法、边界或结果中的哪一种责任。
- 理论是否产生计算状态或约束。
- 段尾是否自然把读者推向下一段。

## 3. 写作前的段落卡

每写一段前先填写四项，只保存在对应逐段对照记录中：

1. 段落目标：读者读完后新增且唯一的认识是什么。
2. 前段遗留：本段承接前段哪个尚未解决的问题。
3. 推进动作：本段通过事实、机制、边界、理论或方法中的哪一种完成推进。
4. 下一段接口：本段最后一句留下什么必须继续回答的问题。

如果无法用一句话回答第 1 项，该段尚未形成。若第 4 项只能写“下面介绍模型”，说明前文尚未自然导出方法。

## 3A. 指导老师逐句逻辑门

段落卡通过后，正文中的每一句还必须单独回答六个问题。这个门针对的是肖帅勇老师论文最关键的写作特征：句子并非并列堆放，而是每一句都从上一句取得成立条件，并为下一句提供必要前提。

1. **原文参照单元**：本句主要参照 `00J`、`00K` 或 `00M` 的哪个具体句序单元。参照的是功能和推进关系，不是词语。
2. **承接前提**：上一句已经建立了什么事实、边界或机制，使本句现在有必要出现。
3. **新增命题**：本句给读者增加的唯一可检验认识是什么。若一句含两个需要不同证据支持的核心命题，原则上拆句。
4. **逻辑连接**：本句与上一句是展开、证据、因果、转折、限定、综合还是推导。仅有主题相同不构成逻辑连接。
5. **证据责任**：哪些词组属于文献事实，哪些属于本文推论，哪些属于方法定义或待实验预期。引文必须覆盖到具体分句，不能用句末一组文献模糊支持整句。
6. **后继义务**：本句建立后，下一句必须回答什么。若本句既不完成当前段功能，也不产生后继义务，应删除。

“原文参照单元”必须同时填写 `00W` 的段落主键和语法句 ID，例如 `DSDL-M13 / DSDL-M13-S03`。若参照的是同一语法句中的两个责任，写成 `S03a/S03b`，不得把功能分句误报为两个原文句。

主键能够解析，只能证明参照位置真实存在，不能证明参照功能成立。每条句级记录必须分别填写 `source_function_code` 与 `candidate_function_code`，并说明二者在承接前提、新增命题、逻辑关系、引文责任和后继义务上为何同位。只有主功能相同且推进关系一致时，才可标为“功能同位”。若只能借鉴句子所在位置、长度或章节次序，必须标为“位置参照，非功能同位”；找不到同功能源句时如实记录“无同功能锚点”，再回到两篇全文寻找更合适的句子或重组候选段落，不得为提高覆盖率强行配对。

逐句核对采用以下硬规则：

- 含多个经验事实、理论机制或结果数字的句子，分别定位原文证据；一个来源不能因位置相邻而自动支持全部分句。
- 由多篇文献综合得出的缺口必须标明“本文综合推论”，引用负责前提，不能把综合判断伪装成某一来源的原结论。
- 新算法定义可以没有外部引文，但必须能回指前文理论映射或可复现规格；基础组件、损失或评价方法若沿用既有工作，仍引用一手来源。
- 纯过渡句通常不需要引用，但必须准确回收上一句并限定下一句的讨论对象，不能只写空泛连接语。
- 任何结果句只可连接真实日志、表格与统计脚本。尚未运行时，句子功能只能是研究设计、理论预期或结果占位。
- 每句话最终给出“保留、改写、拆分、合并、删除”之一的判定。只有“保留”而没有承接前提和证据边界的记录，视为未完成审计。
- 不以英文句点次数、自动 NLP 分句或功能分句数替代人工语法句主键。公式跨行、`where` 续句、`whereas/suggesting/reflecting` 复句均按 `00W` 句界处理。
- 每段完成时记录正文句数、字符数（或声明的分词口径）、引文标记数、冒号/分号/破折号/括号等非常用标点，并与功能最近的 `00W` 参照段比较。这是发现异常的诊断，不是模仿英文绝对长度或标点次数的配额。

## 4. 逐句功能编码

每句话必须标为下列一种主功能，必要时允许一个次功能：

| 代码 | 功能 | 可接受证据 |
|---|---|---|
| CXT | 建立具体情境或工作流 | 正式调查、事故研究、组织实践研究、benchmark 事实 |
| IMP | 说明终局结果为何重要 | 组织结果、损害、成本或可靠性证据 |
| DEF | 定义研究对象或概念边界 | 权威标准、综述、经典概念文献 |
| ACK | 承认既有研究已解决的部分 | 被讨论论文的原文方法与结果 |
| LIM | 精确指出适用边界 | 直接近邻的任务、数据、动作或结果限制 |
| MEC | 建立因果、认知或组织机制 | 理论原文和相符的实证文献 |
| CON | 提出相反方向或冲突情境 | 矛盾结果、边界条件、反事实情境 |
| GAP | 收束为尚未解决的问题 | 前述 ACK、LIM、MEC 的逻辑结论 |
| RQ | 提出研究问题或假设 | 前段已经完成的机制推导 |
| MAP | 将理论构念映射为计算对象 | 构念定义、可观察信号、张量或结构 |
| ALG | 解释架构、损失或推断动作 | 可复现的模型与训练规格 |
| EVAL | 解释评价任务、指标或识别逻辑 | benchmark、统计与实验设计文献 |
| RES | 报告真实运行结果 | 只允许已产生并核验的日志、表格和统计 |
| CONB | 回收理论、方法或实践贡献 | 正文已经建立的机制与证据 |
| BND | 报告适用边界和局限 | 数据、识别、外部效度与实现边界 |

一个段落若连续出现三句以上 ALG 而尚未出现 MEC 或 MAP，应检查是否过早堆叠模块。一个引言段若同时包含 RQ、ALG、EVAL 和 CONB，通常需要拆分。

## 5. 引用的功能审计

每条正式引用必须记录：

1. 被支持的正文句子。
2. 该引用承担的功能代码。
3. 原文页、节、行号或可定位短语。
4. 原文证据的中文释义。
5. 支持范围是定义、机制、方法、数据还是结果。
6. 引用是否为一手来源。
7. 元数据、DOI 和正式出版状态。
8. 核验人和核验日期。

引用不得承担超出原文的主张。例如，事故案例库能证明某类损害真实出现，不能直接证明总体发生率；观察性审核数据能说明行为随经验变化，不能单独证明 habituation 的因果效应；benchmark 上的 pass rate 不能推出组织部署中的经济收益。

## 6. 每段完成后的八步核对

1. 删除本段后，全文缺失的唯一逻辑环节是什么。若答不出，删除该段。
2. 给每句话标功能代码。没有功能或只重复上一句的句子删除。
3. 检查句间关系。相邻句必须是展开、因果、转折、限定、证据或回收中的一种。
4. 将主要论断与原文证据逐一配对。找不到直接证据时标为 [待引用]。
5. 对照 ACAA 或 DSDL 相似位置，检查是否先建立问题再引入工件。
6. 检查理论责任。理论构念若没有改变表示、损失或行动，退回方法设计。
7. 检查语气。未运行的实验只能写研究设计、预注册预期和结果占位。
8. 检查段尾。最后一句应形成下一段的必要入口，不使用机械的“下文将介绍”。

完成第 5 步时必须写下所对照原段的句序功能，例如“情境事实—既有做法—机制限制—未解问题”。只填写页码或段号而不说明句序逻辑，视为未完成对照。

此外，还要记录对照原段中每一条引文究竟承担事实、机制、边界、方法选择或结果解释中的哪一项责任。新正文若只因关键词相似而借用同一来源，或者让一条来源支持超出原文范围的句子，均视为未完成对照。

## 8. 不同章节的最低文献责任

### 引言

每个重要事实、损害判断、现有方法能力和研究边界均需来源。引文密度应来自论断密度，不以堆叠作者数量达标。

### 文献综述

按问题机制组织，不按论文名称逐篇摘要。每一小节最后必须把已知能力收束为一个对本研究输入、状态、动作或结果有直接影响的边界。

### 理论

必须回到理论原文。二手综述只能帮助定位。每个理论构念都要回答其可观察信号、计算表示、方向性预期和中和实验。

### 方法

方法引用用于说明可复用的基础组件和直接基线。新机制的必要性必须由前面理论推导承担，不能靠“受到某方法启发”替代。

### 实验

benchmark、数据、指标和基线均引用原始论文或官方资产。所有版本、split、隐藏信息和许可证进入算法与实验规格。

### 讨论

理论贡献回到理论漏掉的机制，方法贡献回到新增的可训练能力，实践意义回到具体行动和外部结果。三类贡献不能合并为一段空泛总结。

## 9. 表达与标点检查

正式正文优先使用句号和逗号。下列模式出现时逐句改写：

- 连续使用“不是……而是……”或“不……也不……”。
- 用引号制造未经定义的新概念。
- 一句话并列三个以上模块、指标或贡献。
- 用冒号、分号和破折号代替逻辑过渡。
- 在动机尚未建立时堆叠模型名称、张量和 benchmark。
- 使用“本文据此不主张”“通过审查”“唯一”“杀掉”等内部语言。
- 三篇使用相同开头、相同段落数或相同转折句。

## 10. 执行责任

正文段落与对照记录同步增长。任何一篇若出现正文已有段落而审计文件没有对应记录，该篇不能进入下一章节。每个对照条目必须引用 `00J`、`00K` 或 `00M` 中具体的论证单元，说明相似的是学术功能、句间推进或引文责任，不能只写“模仿肖老师”。引用核验表中状态不是“已核验”或“待引用”的条目，不得进入参考文献定稿。

两篇肖老师主文的在线附录和图像未在本项目中取得。后续对照只引用已实际阅读的主文内容，不声称已对照缺失材料。
