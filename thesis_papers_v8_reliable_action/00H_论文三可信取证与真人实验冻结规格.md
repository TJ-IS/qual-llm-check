## 2. 四项不可删除的研究边界

候选论文必须同时满足以下四项。删除任一项即回到已有工作，应撤题；满足这些边界也只表示设计可再次送审。

1. 审核事件由外部 policy 或 gate 预先确定，本文不决定 ask、allow、deny 或风险阈值。
2. trusted mediator 以 canonical command、diff、tool arguments、repository/container identity、pre-state、working-tree hash、权限与作用域绑定候选行动。行动或状态变化后，缓存证据必须失效。
3. 模型主动选择下一项 `acquire`、`present`、`factual_probe`、`clarify`、`repair` 或 `stop`，并依据审核者的可观察 grounding feedback 更新 action-specific interpretation。模型不选择第二审核者，人员分配完全交给外部 gate，以免进入 C19 的监督分配问题。
4. 主要结果是真人 unsafe approval，同时约束 safe approval、false rejection、审核时间、人工动作和计算成本。

静态 evidence bundle、测试生成、风险分数、批准路由、explanation reranking 或 canonical renderer 均不能单独成为主要贡献。

## 3. 状态、输入和输出

### 3.1 输入

- 已经确定必须进入审核的事件。
- canonical proposed action，包括真实 diff、command、tool arguments、repository/container ID、pre-state、working-tree hash、权限与作用域。
- agent trajectory 与 trusted mediator 派生的 action/state transition。
- 可用测试、构建、依赖、调用、taint、scope、provenance 和 rollback 工具。
- 剩余审核注意预算、计算预算与 evidence acquisition 成本。
- 审核者在训练分区内合法取得的知识域与历史 factual-response 摘要，以及当前事件中截至时点 `t` 的回答、澄清和修复日志。系统不能把未观察的“当前 grounding belief”当作输入；该状态只能由滤波器估计。

### 3.2 理论责任状态

共同基础理论只负责区分 potential 与 established、估计 action-specific interpretation、保留 grounding phase 与 reciprocal uptake、执行 purpose-relative criterion/gap，并让残余缺口改变 repair。它不生成任务内容、证据事实、风险标签或审批结果。设审核事件包含 `P` 个 action-bound propositions、两名参与者和每个命题的若干解释候选：

- `J_content ∈ {0,1}^{P×4}` 是独立任务作者在 immutable canonical action、pre-state、权限和作用域完成绑定后，从该 binding digest 与 task/action manifest 冻结的外生内容清单。四列仅为 objective、resource、risk、commitment；它不是共同基础模型的预测头，也不是理论自动生成的内容。
- 固定关系 `R_joint→content∈{0,1}^{3×4}` 的三行依次是 identification、ability、willingness，四列依次是 objective、resource、risk、commitment，其非零关系仅为 `objective←identification`、`resource+risk←ability`、`commitment←willingness`。具体文件、状态、权限、测试和后果仍来自 task/action manifest。
- mutual belief 不成为 `J_content` 的第五列，也不与 risk 一一对应。它由 `C_t`、`M_t` 和 purpose-relative criterion 所表示的互动互认过程承担。
- `V_t ∈ [0,1]^{P×2}` 与 `g_pot,t ∈ [0,1]^P` 表示命题对人类与 agent 的实际可访问性以及由此形成的 potential common ground。
- `B_H,t ∈ Π_p Δ^{K_p∪{UNKNOWN}}` 是依据独立 factual response、state prediction 与修复后复测形成的审核者解释后验。它不是直接读取人的真实信念，`UNKNOWN` 不得被并入正确或错误类。
- `C_t ∈ [0,1]^{P×4}` 表示 presentation、clarification、repair 和 `grounding_acceptance` 的命题级互动阶段；阶段标签来自不接触外部结果的独立日志标注，schema 拒绝把 gate-level approve 记为该阶段。
- `M_t ∈ [0,1]^{P×2}` 表示系统已取得审核者理解证据，以及审核者已取得系统接收并使用其 clarification/repair 的可观察 uptake 证据。第二列必须同时有 system-uptake event、human-exposure receipt 与 paired-confirmation item；`C` 与 `M` 不得由同一 response/event 循环定义。
- `g_est,t ∈ [0,1]^P` 是同时依赖 access、解释后验、互动阶段与 reciprocal uptake 的 established-state 估计。它没有可直接读取的真值，只能由与训练 probe 分离的 paired-interpretation 与 transfer items 校准。
- `κ ∈ [0,1]^P` 与 required mask `m_req∈{0,1}^P` 在 binding digest 产生后、任何 participant response、approval 或 hidden outcome 出现前由独立任务作者冻结；criterion manifest 同时冻结 scale version、basis、required-response bank hash、threshold unit 和 sensitivity grid。`κ` 是外生 criterion specification，与随后取得的 factual-grounding measurement/label 分库；`r_t=m_req⊙max(0,κ-g_est,t)` 表示对当前批准目的仍未满足的理解缺口。

单向展示、页面停留、点击、“已读”、approve、harm 或 task success 都不能把命题从 potential 改为 established，也不能定义 `κ`。审核者的正确、错误、不确定回答和 repair 后复测只能更新对应命题；系统还必须以 action-bound uptake 表明它已使用该反馈。action hash、pre-state、working-tree hash、权限或作用域任一变化时，旧 binding digest 及其全部下游对象同时失效，包括 proposition、`J_content`、`m_req/κ`、四个题目 bank、candidate lattice、动态分支承诺、evidence、response 与 `V/B_H/C/M/g_est/r`。新 trial 必须按 `bind → purpose/criterion → generate → commit` 全链重建，旧 criterion 不得进入新行动。字段、时点、标注者和禁止来源以 `00H-A_论文三标签日志与Oracle隔离Manifest.md` 为唯一实现合同。

### 3.3 技术状态

技术表征为 typed action–state-transition–evidence graph：

- action node 绑定 canonical action hash。
- state node 绑定 pre/post snapshot hash。
- evidence node 保存 source、run ID、命令、输入状态、输出状态、cost 与 latency。
- edge 区分 supports、contradicts、causally-discriminates、regression-only、candidate-specific、misleading、depends-on 和 invalidated-by。

这些结构来自执行系统和数据，不得声称全部由 common-ground 理论产生。

### 3.4 可训练动作空间

模型不得输出 approve、deny、allow、risk score 或批准建议。动作分为两类。

取证动作包括：

- 在 sandbox 重放指定 validation command。
- 执行已有 test。
- 生成并执行 mutation、counterexample 或 fuzz test。
- 对 command 执行 dry-run 或 namespace simulation，并捕获文件、数据库、进程或网络 state delta。
- 执行 dependency、call、taint、scope 或 provenance analysis。
- 尝试 rollback/reversibility 并验证恢复后的不变量。
- 请求一项范围明确的缺失事实。

呈现与 grounding 动作包括：

- 选择 action-bound 证据子集及顺序。
- 展开一个 state delta、反例或未满足义务。
- 提出一项 factual comprehension probe。
- 回应审核者 clarification 或 repair。
- 在达到 grounding criterion、预算耗尽或无法继续建立共同基础时停止取证，并把事件交还外部 gate。

`stop` 只结束 C3 的证据循环并返回外部 gate，不表达 approve、deny、risk 或 when-to-ask；需要更换审核者时也由外部 gate 另行处理。

## 4. 训练路线与损失

### 4.1 预训练

先对 evidence validity 与 causal attribution 进行多任务训练：

- validation command 与 snapshot 可比性。
- bug-discriminating、candidate-specific、regression-only 与 misleading evidence 分类。
- action/state/evidence binding 检验。
- 证据支持、反驳和失效关系预测。
- trajectory process evidence encoding。

### 4.2 人类证据价值学习

从独立 logging cohort 的随机或已知 propensity 轨迹学习某项证据对 factual understanding 与 clarification/repair 的边际价值。最终 approval、harm 和 task success 只进入外部策略回报或评价，不能反向生成 `J_content`、`B_H`、`C`、`M`、`κ`、`g_pot` 或 `g_est` 标签。训练可使用 pairwise/listwise evidence-value loss，但必须控制额外时间、文字长度与视觉显著性，并在支持不足时拒绝离线外推。

### 4.3 序贯策略

使用 conservative offline contextual bandit 或 POMDP 学习下一证据动作。动作严格限定为 `acquire/present/factual_probe/clarify/repair/stop`。奖励主项是减少 unsafe approval，约束项是保持 safe approval、降低 false rejection、审核时间、交互次数、运行成本与计算资源；这些外部结果不充当理论状态标签。主策略必须通过 `g_est` 与 `r` 的结构路径更新动作价值；同时训练获得完全相同信息和标签的通用反证模型。

不能把 trust、acceptance、confidence、满意度或 adoption 当作主要 reward。

### 4.4 理论专属损失

unsafe approval reward、evidence validity 和 harm-prediction loss 不属于 common-ground 理论贡献。理论层至少包含：

- `L_interp`：审核者对 action-bound proposition 的 factual interpretation calibration。
- `L_phase`：presentation、clarification、repair 和 `grounding_acceptance` 与交互日志的一致性，不读取 gate approval。
- `L_pot_not_est`：保持静态证据内容不变并打乱互动确认历史时，`g_pot` 应稳定而 `g_est` 应改变。
- `L_reciprocal`：只有形成双方可观察 recognition evidence 的命题才能越过 criterion。
- `L_purpose`：由外生 `m_req/κ` 确定的 objective、resource、risk 和 commitment 必要缺口不能由其他类型的高分抵消。该损失不学习或回推 `κ`。
- `L_effort`：在达到 purpose-relative criterion 后减少人类与系统的总协作努力。

主策略禁止 raw trace 绕过这些状态；允许 bypass 的模型只作反证。乘性或单调门只能称为理论启发且可证伪的结构假设，不能声称由 Mastrogiacomo、Clark 或共同基础理论唯一推出。

### 4.5 架构、关键张量与前向计算

设一个 batch 含 `B` 个审核事件，action–state–evidence graph 最多有 `N` 个节点，最多有 `P` 个 action-bound propositions，每个时点有 `K_t` 个合法候选动作，统一隐藏维为 `d=384`。正式实现由四个可分别保存和替换的训练工件组成。

1. **技术证据编码器 `E_tech`。** 六层 relational graph Transformer 编码 action、pre/post state、command、diff hunk、test、analysis 与 evidence node，得到 `H_tech∈R^{B×N×d}`。边类型、action hash、snapshot hash、执行成本和 evidence validity 作为显式 relation/feature；编码器同时输出 evidence validity、causal-discrimination、cost 与 transition-delta 分布。代码文本的初始表征由冻结的开放权重 code encoder 提供。进入真人 logging 后，code encoder 与 graph Transformer 下部至少四层保持冻结，只有上部适配层和任务头可更新；实际可训练参数上限在支持度模拟前预注册。
2. **命题与共同基础滤波器 `F_cg`。** `H_prop∈R^{B×P×d}` 由已冻结的 `J_content`、task/action manifest 与技术图编码得到；模型只学习 proposition-to-evidence binding 和解释状态，不预测、补写或重排 `J_content`。序贯滤波器消费 `H_prop`、`V_t`、action-bound factual response 与 grounding-act history，输出 `B_H,t、C_t、M_t、g_pot,t、g_est,t、r_t`，并只读取外生 `κ/m_req`。`g_est` 可使用带结构掩码的乘性门，使 potential access、解释后验、互动阶段和 reciprocal uptake 四条路径都留下可干预接口；该门是待证伪的结构假设，而不是理论唯一蕴含。缺失字段保留 `UNKNOWN`，不能由 evidence embedding 直接补成已建立状态。
3. **证据行动转移模型 `T_ev`。** 对每个合法候选 `a_k`，cross-attention 读取 `H_tech、H_prop、r_t`、审核者状态和预算，预测执行后技术状态、命题级 factual-response 分布、`Δg_est`、human effort、latency 与 compute，形成 `Z_next∈R^{B×K_t×(P+q)}`。取证工具的真实可用性由环境 action mask 给出；模型不能生成未授权命令，也不能把 hidden oracle 作为特征。
4. **受约束序贯策略 `π_cg`。** distributional conservative offline POMDP policy 只读取技术摘要、结构状态、候选转移和剩余预算，输出下一项 `acquire`、`present`、`factual_probe`、`clarify`、`repair` 或 `stop`。unsafe approval、safe approval、审核时间和计算成本进入受约束回报；approve、deny、risk、when-to-ask 与 reviewer assignment 均由外部 gate 产生，不属于策略动作。

真人 logging 阶段的容量上限先于 outcome 解封冻结：`E_tech` 的 code encoder 与下部四层完全冻结，允许更新的上部层、adapter 和 heads 合计不超过 15M 参数；`F_cg` 最多两层、状态维不超过 192、可训练参数不超过 10M；`T_ev` 最多两个 cross-attention block、状态维不超过 192、可训练参数不超过 12M；`π_cg` 最多两层、状态维不超过 192、可训练参数不超过 5M。若支持度模拟要求进一步降容，只能在查看 confirmatory outcome 前完成并向所有基线同步；不得事后扩容主模型。

共同基础层的一个可审计实现为

`g_est,t = g_pot,t ⊙ q(B_H,t) ⊙ c(C_t) ⊙ sqrt(M_t[:,1]⊙M_t[:,2])`，

其中 `q` 与 `c` 是单调、可校准的 proposition-wise neural gates。该式只是一项理论启发的可证伪实现；通用网络在表达能力上可以复制它。Human-state POMDP、Raw-POMDP、generic proposition Transformer 和 contextual bandit 获得相同 `J_content`、proposition labels、human feedback、candidate lattice、reward、参数、FLOPs 与搜索预算，理论模型唯一可以不同的是这些共同字段的结构使用方式。

总训练目标写为

`L = λtech Ltech + λinterp Linterp + λphase Lphase + λpe Lpot_not_est + λrec Lreciprocal + λpurpose Lpurpose + λdyn Ltransition + λpol LCQL + λcost Lconstraint`。

每项标签来源和可见时点必须在 `00H-A` 指定的 label manifest 中独立登记。所有通用替代获得产生 `L_interp、L_phase、L_pot_not_est、L_reciprocal、L_purpose` 所需的相同监督，并可通过等容量多任务头使用；不能让 C3 独享损失标签。比较只检验理论结构是否在有限数据、未见 repository/reviewer/risk、方向干预和安全—效率前沿上形成稳定归纳偏置。

### 4.6 训练阶段、划分与保存工件

训练与评价分为四个相互隔离的阶段。

1. 在 BSG-VA、SWT-Bench、c-CRAB、FixCheck 和 action-swap/stale-state 合成分支上预训练 `E_tech` 与 evidence-validity heads。repository、base commit、bug family、generated-test lineage 和任何 gold-derived sibling 必须成组划分。gold/G/hidden 只可在 candidate lattice 冻结后由 evaluator 产生标签。
2. measurement/support pilot 只验证 factual misunderstanding、字段可标注性、action eligibility 与 logging support，并冻结题目、`J_content`、`κ`、界面和随机 logging grammar。pilot 参与者及其交互不能进入策略训练或前瞻检验。
3. 在完全独立的 policy-learning logging cohort 上，以随机或已知 propensity 收集轨迹并训练 `F_cg/T_ev/π_cg`。每个合法动作必须满足 positivity、cell-level raw support、稳定权重 ESS 和截断敏感性；失败 cell 不得离线外推。进入该阶段时冻结 `E_tech` 的开放权重编码器与至少四个底层图层，并限制其余模型容量。
4. 冻结所有权重、阈值、命题、界面、预算和分析脚本后，在完全独立的 prospective confirmatory cohort、全新 repository 和至少一个训练未见 risk family 上进行随机评价。confirmatory participant 的任何响应都不能更新 reviewer model、校准图或策略。

保存的核心工件为 `tech_encoder.ckpt`、`grounding_filter.ckpt`、`evidence_transition.ckpt`、`grounding_policy.ckpt`，另保存 tokenizer/code-encoder revision、graph schema、`J_content` 与 `κ` manifest、action grammar、dynamic branch grammar/template/slot/source-bank Merkle root、deterministic replay executable/seed、constraint multipliers、calibration maps、generator/instantiator/evaluator image digests、candidate-lattice 与 branch-commitment hash、access log、split/lineage manifest、propensity、`micro_randomized_manifest` 与全部随机种子。任何 checkpoint 若使用 gold patch、G state、hidden test、candidate-availability oracle side channel 或 confirmatory-participant interaction，即判泄漏，整个相关 group 退出主分析。

### 4.7 本地算力与运行工件

图编码器、共同基础滤波器与离线策略的首轮开发可在单张 24–48GB GPU 上完成；等参数基线、五个随机种子和超参数匹配的完整训练按 4 张 48–80GB GPU、约 5–14 天规划。主要成本来自 evidence lattice 的容器执行和真人交互，而不是参数量：预注册规模预计需要约 10,000–30,000 个 sandbox execution、数千条随机化审核轨迹、1–3TB snapshot/log/evidence 存储及相应 CPU-container 小时。精确预算在形成性任务通过后用实际时延重新估计，论文在未执行前不得把这些规划写成已消耗资源。

## 5. 可用公开数据及其责任

### 5.1 BSG-VA

BSG-VA Zenodo 提供 3,730 个 validation events、643 条 rollouts 和 110 个任务，可监督 evidence 与 captured state 的可比性、buggy/candidate/gold 结果以及 discriminating、misleading、regression 等标签。其代码未公开，只公布 JSONL，不能声称能够端到端复现原 pipeline。

### 5.2 可执行测试与 review 数据

- SWT-Bench 提供 2,294 个 full、276 个 Lite 和 433 个 Verified task。
- c-CRAB 提供 184 个 PR、234 个经验证的 review comments/tests 和 67 个仓库。
- FixCheck artifact 提供随机测试与 fault-revealing evidence。

这些资源按 repository、time、bug family 和 generated-test lineage 隔离。gold patch、G state 与 hidden tests 只能在 lattice hash 之后由独立 evaluator 产生训练标签或 sealed evaluation outcome，不能进入 generator、命题、候选、mask、排序、模型输入或推断展示。

## 6. 必须新建的数据

现有公开数据没有同时提供固定已升级的 canonical coding action、可选择的多种 action-derived evidence、reviewer grounding 轨迹和每种证据策略对 unsafe approval 的因果效应。因此必须在角色隔离的仓库和容器中构造：

- safe 与 unsafe candidate actions。
- hidden functional、security、scope 和 state-damage oracle。
- 每个 candidate action 在 hidden evaluator 运行前冻结的 oracle-blind evidence lattice。
- 已知 propensity 的 `acquire/present/factual_probe/clarify/repair/stop` 随机分配日志。
- 审核者 factual response、uncertain、clarification、repair、最终批准与时间轨迹。

法定时序为 `T−5 bind → T−4 purpose/criterion/bank → T−3 generate → T−2 lattice-and-branch commit → T−1 sealed evaluation`。candidate generator 只可读取真实部署时可见的 issue/task、canonical action、pre-state、public tests 与 authorized tools。action grammar、静态候选、mask、cost、timeout 和 ordering 必须在任何 logging、human response、approval 或 hidden evaluator 前写入带 hash 的 manifest；G state、gold patch、hidden tests 和 harm label 不得生成、筛选、排序或定时候选。

T−2 还必须承诺 T1 后才可观察的 `clarify/repair` 动态分支。可以预枚举每个可达实例的完整 bytes/hash，也可冻结 branch grammar、template/slot schema、content-instantiator 镜像与版本、allowed factual source Merkle root、parent state/hash、action-bound proposition IDs、budget/cost/latency、termination、runtime input whitelist、deterministic seed 与 replay 合同。分支出现只能由可见 factual response、`UNKNOWN` 或明示 clarification request 触发，不得由 public execution、approval、hidden outcome、G/gold 或 evaluator latency 触发；public execution record 只可填入已触发分支的预承诺 factual slot。相同可见输入必须 byte-for-byte 重放同一 branch instance，且全部基线共用同一分支合同；不能重放时使 trial 失效并重做 bind–commit。

泄漏设计门是成对 mirror noninterference：保持全部 B/public state、部署可见 risk signals、history 和 response 相同，只交换 G/hidden bytes，candidate IDs/bytes/order/mask/cost/latency、generator trace 和 action logits 必须逐字节或按预注册数值容差一致。条件增量 probe 在 public-risk strata 与 visible state 条件化后检验 hidden-only 标识能否额外预测 availability，它只作诊断，不以裸 AUC 把合法 public risk signal 判为泄漏。完整字段、角色、镜像、时序和非干扰门见 `00H-A`。

若无法取得真实开发者数据，候选论文撤销。LLM persona、LLM judge 或 simulated reviewer 只能用于软件调试，不能替代任何训练或评价 cohort。

## 7. 三个互不复用的真人阶段与支持度门

### 7.1 measurement/support pilot

pilot 使用独立参与者检查任务可理解性、factual misunderstanding 是否存在、命题与互动标签是否可靠、每类动作何时合法，以及随机 logging 是否能够覆盖预注册的处理前状态。时点 `t` 的 `S_t^pre` 在抽取当前动作之前冻结，只含 `risk_stratum`、实验前 `baseline_reviewer_support`、`grounding_phase_pre`、`budget_pre`、`class_availability_bitmask`、`eligible_action_set_hash` 与 `public_history_hash`。它不含当前 selected `top_action_class`、`action_subtype`、`candidate_id`、当前动作后的 repair trigger 或任何 outcome。保守规划下限为 48 名 working developers、每人 8–12 个 trial；这一数字不代表已经通过支持度模拟。pilot 只冻结测量和设计，既不训练最终策略，也不承担主要效果结论。

### 7.2 policy-learning logging cohort

logging cohort 与 pilot、confirmatory cohort 完全不同。保守规划下限为 180 名 working developers、每人 16 个 trial，即至少 2,880 个 trial；每个 trial 记录 3–6 个合法决策机会。最终人数和 trial 数由预注册的 eligibility-conditioned simulation 决定，模拟网格至少覆盖五类结果层 `safe/functional/security/scope/state-damage`、三档由实验前技能题定义的 reviewer support、六类动作及 subtype、grounding phase、budget bucket、lattice availability、clarify/repair trigger 与 absorbing stop 可达性、participant/task random effects、15% attrition 和多种轨迹长度。

当前处理单列为 `A_t=(class_t,subtype_t,candidate_id_t)`，不回写 `S_t^pre`。logging policy 采用唯一的两级 mixture grammar。第一级对当前非空的合法顶层 class 集 `C_t` 使用

`p_cls(c|S_t^pre)=(1-ε_cls)q_cls(c|S_t^pre)+ε_cls/|C_t|`，其中 `ε_cls=0.30`。

第二级只在已抽中的 class 内，对按 public-only 规则保留的候选集 `K_t(c)` 使用

`p_cand(k|c,S_t^pre)=(1-ε_cand)q_cand(k|c,S_t^pre)+ε_cand/|K_t(c)|`，其中 `ε_cand=0.40`。

T−2 冻结的不是未来每个状态的数值概率，而是唯一的候选生成、截断和 logging-policy 函数。`CandidateSetFn-v4`、`Cap8Fn-v4` 与 `q-policy-v1` 的 executable/checkpoint hash、输入 schema、dtype、温度、mask 规则、归一化规则和 tie-break 在任何 logging 与 hidden evaluation 前写入 manifest。静态候选直接在 T−2 实例化；动态 branch 只可由上一时点已记录的 visible factual response、`UNKNOWN` 或明示 clarification request，经 T−2 冻结的 grammar、slot、source Merkle root、image 与 seed 决定性实例化。每个 opportunity 必须先枚举全部 public-only 实例。`candidate_content_hash=SHA256(instantiated_bytes)`；`candidate_id` 是 `binding_digest,parent_state_hash,action_class,template_id,slot_bytes,instantiated_bytes,generator_version` 七字段按 T−2 schema 做 canonical CBOR array 编码后取 SHA-256，不使用有歧义的裸字符串拼接。随后在每个 class 内按 `proposition_coverage_count` 降序、`expected_public_cost_millis` 升序、`candidate_content_hash` 小写十六进制升序保留前 8 个；`stop` 只有一个 candidate。retained/discarded IDs、三个排序字段、instance bytes/hash、函数版本与 cap reason 在 `S_t^pre` 之前落盘。随后才生成 `class_availability_bitmask/eligible_action_set_hash`，调用 `q-policy-v1` 并在 cap 后合法集合上计算 softmax；`q` 看不到被丢弃候选，不能影响实例化、排序或 cap。每个机会保存实际 logits、`q_cls/q_cand` 数值、归一化分母与 `sum-to-one` 检查，误差超过 `1e-8` 或版本/hash 不符即使 trial 失效。C3 与所有基线共用相同 retained set、实例 bytes 与 q 函数输入。联合 propensity 为两级概率之积。顶层 class 的下界是 `0.30/|C_t|`，class 内候选的条件下界是 `0.40/|K_t(c)|`；exact-candidate support 只按 cap 后的条件下界报告，不另设与集合规模无关的固定概率门。

主要策略比较与支持主张位于顶层 class；subtype/candidate 只在预注册 family 跨 trial 重现且通过同一支持门时作次级比较。`estimand_cell_id` 只由处理前 coarsening `risk_stratum×baseline_reviewer_support×grounding_phase_pre×budget_pre×class_availability_pattern` 与单列的 `A_t.class` 组成，不能在 state 内重复编码 selected action。每个 opportunity 是一次在抽取 `A_t` 之前完成 `S_t^pre` 和合法集合记录的决策时点；结构不合法 class 不是 opportunity。

支持度只采用 participant 为 cluster 的唯一算法。对 cell `h` 和 class `c`，令 `w_it=I{φ(S_it^pre)=h,A_it.class=c}/p_cls(c|S_it^pre)`，先在参与者内聚合 `W_i(h,c)=Σ_t w_it`，再计算 `ESS_Kish(h,c)=(Σ_i W_i(h,c))^2/Σ_i W_i(h,c)^2`。class-wide 检查只令 `W_i(c)=Σ_hW_i(h,c)` 后套用同一个 Kish 公式，不创建第二种 ESS。raw opportunity、selected rows 与 selected participant clusters 分别计数，不得用 decision-row ESS、task cluster、repository cluster 或三者取最小值替代。每个主要 cell 必须同时达到 eligible opportunities `≥80`、selected rows `≥40`、selected participant clusters `≥30` 和 `ESS_Kish≥30`；每个顶层 class 跨 cell 必须达到 selected participant clusters `≥80` 与 `ESS_Kish(c)≥60`。task/repository 依赖只进入预注册 mixed model 与敏感性方差，不改变 support ESS 定义。

policy-learning logging cohort 的序列 OPE 另用已记录 class×candidate propensity 的 inverse-propensity prefix weight，并按 participant 聚合后套用同一 Kish 公式。这个 logging-OPE weight 的主 cap 为 `10`，另报未截断与 5/10/20 敏感性；它不是第 8.1 节 joint-process density ratio `ρ_s`，也不进入 `IIE_JFG^cl` 的 clever covariate。若超过 5% 的 logging opportunity 被 cap、cap 改变 OPE 方向、任一关键合法 cell 未达门槛，或两个独立实现不能对 synthetic log 重算出相同 denominator、propensity、cell 与 ESS，则继续扩容或把该 cell 标为 unsupported，禁止离线外推。

`E_tech` 的开放权重 code encoder 与至少下部四层图编码器在本 cohort 冻结。`F_cg/T_ev/π_cg` 的可训练容量、层数和参数上限在 sample/support simulation 前写入配置，并与通用基线按可训练参数正负 1%、FLOPs 正负 5% 匹配。不得以增加模型容量替代日志支持。

### 7.3 prospective confirmatory cohort

前瞻检验使用第三批完全独立参与者。保守规划下限为 180 名 working developers、每人 12 个 trial；最终样本由预注册 simulation 选择，使 unsafe-approval 绝对下降 8 个百分点的目标在 participant/task random effects、基线风险率和 attrition 参数网格中达到至少 0.80 power。若 simulation 或中期盲态 nuisance re-estimation 要求更大样本，只扩容而不改效应方向、终点或模型。

confirmatory cohort 使用全新 participant、repository 和至少一个训练未见 risk family；所有 checkpoint、阈值、candidate grammar、界面、预算和分析脚本在第一名 confirmatory participant 进入前冻结。该 cohort 的回答、批准和结果不得回流任何模型或校准器。

确认性试验的唯一随机化单位为 `participant_id`。处理前 `baseline_reviewer_support` 使用已冻结的三个层级，分层值、每名参与者的十二个计划任务及其顺序属性均在分臂前落盘，不得读取处理后响应、过程或结局再调整。四臂枚举唯一为 `A/B/C/D`，每个 support 层中 `P(A)=P(B)=P(C)=P(D)=1/4`。参与者一次分臂后，`arm_persistence=all_12_planned_trials`；同一人的十二个计划 trial 始终保持同臂，不 crossover、不重新随机、不以缺席 trial 换取新分配。只取 D/C 的确认性对比时，已知条件 propensity 唯一为 `P(D|D∨C,H)=P(C|D∨C,H)=1/2`。

分臂的可重放合同使用域字符串 `C3-CONF-ARM-20260816-v1`。首名参与者入组前，服务器生成 256-bit 秘密 `K_arm`，只对外公布并在共同 manifest 写入 `seed_hash=SHA256(K_arm)`，不提前公开 `K_arm`；在真实入组开始前，`seed_hash` 必须是实际 64 位十六进制值，不得保留占位符。令 `m_i=UTF8(domain || stratum_i || salted_participant_id_i)`，其中 `||` 的长度边界、分隔、Unicode 规范化、salt 和 ID 规则都由首例入组前的 schema 唯一规定。计算 `h_i=HMAC-SHA256(K_arm,m_i)`，取前 64 bit 作为无符号大端整数 `u_i`，令 `j_i=floor(4u_i/2^64)`，并按 `0→A,1→B,2→C,3→D` 分臂。salted-ID 规则、字符编码、字节序、映射、allocator 脚本 SHA-256 和 schema SHA-256 一并预提交；allocator 不得读取 trial 过程、人类回应或结局字段。`K_arm` 只在 enrollment lock 后公开以供重放，公开 key 与预先公布的 `seed_hash` 不一致、映射无法重放或出现人工 override 时，该参与者记为 protocol deviation，不得悄然重分配。

primary unsafe approval 由与 C3 交互、接收 evidence 并完成 factual-grounding 测量的同一审核者，在同一 canonical action 上作最终决定。实现必须校验 `interaction_participant_id == final_approver_id` 与 action hash 一致。专家 adjudicator 只判定 sealed safe/unsafe 真值，不替代 participant outcome；外部 gate 不在主试验中换人、增加第二审核者或根据 C3 trajectory 重新路由。

### 7.4 前瞻实验臂与预算

至少包含四臂：

- A：canonical raw action/diff，代表 Consent Integrity 基线。
- B：预算匹配的最强静态/full bundle，组合 BSG discriminating witness 与 AutoSD、TraceView、delegation-contract 风格证据。
- C：获得相同 `J_content`、人类反馈、candidate/branch bytes 与预算的等容量 Human-state POMDP，学习动态 acquisition、selection 与 stopping，但不强制 potential/established、phase、reciprocal uptake 与 criterion 分解。
- D：C3 learned acquisition、selection 与 grounding policy。

oracle evidence subset 只能作为标明不可部署的上界，不能与主方法合并。四臂使用相同 candidate action、candidate lattice、动态分支 bytes、屏幕空间、token、取证时间和总计算预算。D 臂不得额外加入红色警告、风险分数或批准建议，以免把视觉显著性效应误当作证据策略效应。主要外部效果比较为 D 对 C；A、B 提供原始与静态基座。

任务同时包含 safe actions 和具有 hidden functional、security、scope 或 state damage 的 unsafe actions，并保留跨 repository 测试。首版聚焦 repository patch 加 validation command/state delta。若同时加入 shell、deployment 和数据库行动却没有统一 typed transition 表示和每类足够样本，则撤销扩展。

## 8. 结果与统计

主要结果：

- Unsafe approval，由同一交互审核者的 final approval 与 hidden tests、state-delta oracle 及专家 adjudication 产生的 unsafe 真值联合定义；专家不替代审核者决策。

次级结果：

- Safe approval 与 false rejection。
- 批准后任务成功。
- review time、clicks、clarification/repair 次数与 compute。
- 对真实 post-state 的事实预测。
- confidence calibration 与 workload。

总效应分析使用 mixed-effects logistic model 与适合时间结果的 survival/mixed model，报告效应量、置信区间和预注册的多重比较处理。参与者、任务、仓库与风险类型进入随机或分层效应。所有排除规则、主要终点和模型规格在收集正式数据前预注册。

### 8.1 纵向联合取证—grounding 机制识别

机制合同在首名 confirmatory participant 进入前冻结。以 `i` 表示参与者 cluster，`r=1,…,12` 表示预先排序的计划 trial。主比较只取 D 臂 C3 与 C 臂等信息 Human-state POMDP，参与者级处理记为 `A_i=1` 与 `A_i=0`，同一 `i` 的十二个 trial 共用这一不变处理。令 `B_i` 为处理前参与者基线，每个 trial 的处理前向量唯一为 `X_ir=(baseline_reviewer_support,baseline_factual_accuracy_bin,repository_stratum,task_stratum,risk_stratum,task_complexity_bin,canonical_action_type,canonical_scope_bin,public_risk_bin,initial_budget_bin,trial_order_block)`，并以 `X̄_i=(B_i,X_i1,…,X_i12)` 表示整个 cluster 在分臂前冻结的基线与任务序列。各字段、分箱边界、UNKNOWN 类与 manifest hash 都须在 arm assignment 前产生，分析者不得增删。本研究不再把 acquisition、presentation、factual response、clarification/repair 等 treatment-induced history 放在随机中介分布的条件集合中。它们与 reciprocal uptake、预算和疲劳记录、终端 factual measurement 及 measurement 后的安全修复共同组成唯一的纵向联合过程 `Z_ir^J`。神经 hidden state `g_est` 不属于 causal process node；outcome `Y_ir` 是随后由同一审核者对同一 canonical action 作出的 unsafe approval。

固定时间轴为 `T_dec=6` 个互动决策槽和两个终端槽，故 `T_max=8`。每个决策槽 `t=1,…,6` 的子节点顺序固定为 `D_t → U_t → E_t → F_t → C_t^g → K_t`。`D_t` 记录动作前 eligibility、phase 与 budget，`U_t` 记录所选 action class/subtype/candidate family，`E_t` 记录 public execution 与 evidence exposure，`F_t` 记录 action-specific factual response，`C_t^g` 记录 clarification、repair、grounding-acceptance 与 reciprocal-uptake receipt，`K_t` 记录增量 latency、compute、fatigue proxy 与 stop。exact candidate/branch hash 仍保留在审计日志，但 causal node 只使用 outcome-blind、版本冻结的有限 family code。若在第 `s≤6` 槽选择 `stop`，则 `s+1,…,6` 的 `active=0`、动作与事件字段固定为 `NOOP_ABSORB`、增量 cost/latency 为 0、剩余 budget 与最后 phase 只作 carry-forward；这些槽不是缺失值。第 7 槽固定为 silent/no-feedback factual measurement `Z_7=(M_valid,M_obs_bin)`，第 8 槽固定记录 measurement 后请求与实际执行的 safety evidence/repair `Z_8=R_post`。`R_post` 因而是理论过程的一部分，不再被当作 censoring event；真实退出、日志损坏或 final decision 缺失另记 `C_Y`。

每个 trial 的 measurement item bank 在 binding digest 与 `J_content/m_req/κ` 之后、policy-arm randomization 之前写入 hash。每个 required proposition 预先抽取一项直接事实题和一项不同措辞的 transfer item；总题数为 4–8，超出时按 proposition ID hash 的固定顺序截取。全部题目要求离散事实答案及主观概率，不显示正确答案、提示、颜色或校准反馈。连续 `M_obs` 是 required items 的等权 normalized Brier complement；primary causal node 使用固定十档 `M_obs_bin∈{[0,.1),…,[.8,.9),[.9,1]}`，少于 4 个有效 item 单列为 `MISSING_MEASUREMENT`，不填 0。连续值仍用于测量校准和次级描述，不能在 outcome 后改变分档或权重。

确认性数据的 IID 观测单位唯一为参与者 cluster：

`O_i=(B_i,A_i,{X_ir,Z_ir^J,C_{Y,ir},Y_ir}_{r=1}^{12}), i=1,…,n`。

总体 likelihood 唯一写为 `L(P)=∏_i p(O_i)`，不得写成 2,160 个 trial 的 IID 乘积。`p(O_i)` 内部先按 `r=1,…,12` 的计划顺序分解，每个 trial 再按上述八槽顺序分解。第 `r` 个 trial 的 nuisance history 包含 `B_i`、固定的 `A_i`、`X_i1:12` 及该参与者此前 trial 的全部 `Z^J`、measurement、`R_post`、censoring、可见决策与可见结局历史；它不可读取当时尚封存的 hidden safe/unsafe 真值。stop 后的 `NOOP_ABSORB` 仍按固定轴进入 likelihood。学习、疲劳、信任调整与早期 repair 对后续 trial 的影响被允许并作为簇内纵向 carryover 显式建模，不是干扰违例。唯一 no-interference 假设是不同参与者 cluster 之间没有影响结果的跨参与者干扰。

令 `G_a^{J,1:r}(dz^J_{1:r}|X̄_i)` 为臂 `a` 下从第一个 trial 到第 `r` 个 trial 的联合过程序贯分布。当前 trial 内的唯一因子顺序仍为

`G_a^J(dz_ir^J|H_ir^cl)=∏_{t=1}^6∏_{v∈(D,U,E,F,Cg,K)}g_{a,r,t,v}(dz_{ir,t,v}|H_ir^cl,z_{ir,<t,v}^J) · g_{a,r,7}(dz_{ir,7}|H_ir^cl,z_{ir,1:6}^J) · g_{a,r,8}(dz_{ir,8}|H_ir^cl,z_{ir,1:7}^J)`，

其中 `H_ir^cl` 包含 `X̄_i` 和同一 stochastic intervention 已产生的前 `r-1` 个 trial 联合历史。每个 intervention draw 只条件于处理前 cluster 记录和此前已由同一 draw 产生的 process prefix，不条件于实际臂下另存的 `L`。首名 confirmatory participant 进入后，`X̄/Z^J` schema、顺序和版本不得再改变；若发现一个未登记的 treatment 后、decision 前变量同时影响后续 `Z^J` 与 `Y`，当前实验记 `PROCESS_SCHEMA_OMISSION` 并停止因果机制报告，只能在新版本、新样本中重建 estimand，不得在当前数据中临时把它加入 `L` 或 `Z^J`。

确认性 D/C 目标总体唯一为处理前合格且被随机分入 D 或 C 的参与者，在既有处理前 shared-support 规则后每名参与者等权，每名参与者内的十二个计划 trial 等权。令 `μ_r(a,z^J_{1:r},X̄_i)=E[Y_ir|A_i=a,Z_i,1:r^J=z^J_{1:r},X̄_i,C_{Y,ir}=0]`，唯一聚类联合过程目标为

`Ψ_J^cl(a,a*)=E_{X̄_i}[12^{-1}Σ_{r=1}^{12}∫μ_r(a,z^J_{1:r},X̄_i)G_{a*}^{J,1:r}(dz^J_{1:r}|X̄_i)]`，

`IIE_JFG^cl=Ψ_J^cl(1,0)-Ψ_J^cl(1,1)`。

正值表示在保持 outcome arm 为 C3 时，将十二 trial 簇内联合机制过程从 Human-state POMDP 的随机分布替换为 C3 的随机分布所减少的参与者平均 unsafe approval。`z^J_{1:r}` 包含当前与此前 trial 的全部八槽历史；缺失仍由已冻结的 `C_Y` 机制处理，不得 complete-case 删除后重新赋权。这个对象同时承担 executable acquisition、presentation/probe、clarification/repair/uptake 与 factual grounding 的机制责任，不再声称只分解 terminal score。D 对 C 的随机 policy total effect 另行报告；natural、organic、history-conditional mediator shift、单独 `M_obs` indirect effect 与 analyst-chosen shift 均不进入主结论。[Wang et al. (2025)](https://doi.org/10.1515/jci-2023-0013) 的随机干预、纵向 likelihood factorization 与 general longitudinal stochastic-intervention EIC 是 estimator 依据，不规定本研究的固定臂、参与者簇目标或重抽方案。

primary estimator 唯一冻结为 participant-cluster 五折 cross-fitted one-step HAL-EIC longitudinal TMLE，同时联合 target `Ψ_J^cl(1,0)` 与 `Ψ_J^cl(1,1)`。HAL nuisance 对象是 `p(O_i)` 的十二 trial 簇内纵向 likelihood；实现可展开 trial/slot 张量，但不得把展开行当成独立样本。外层 fold seed 固定为 `C3-JFG-CF-20260816-v1`：在实验前 `baseline_reviewer_support` 各层内，以 `SHA256(UTF8(seed)||0x00||UTF8(salted_participant_id))` 升序排列；层内第 `j` 名固定进入 `fold=1+((j-1) mod 5)`。这唯一的 balance rule 使各 support 层的 participant 数跨折之差至多 1；同一 participant 的全部十二个 trial 及全部 row 只能进入同一 fold。repository 不参与 fold 构造。每个训练折内的 binary/categorical process factors、censoring 与 outcome 使用二阶交互 HAL likelihood，连续 process factors 使用同一二阶基与 sectional-variation bound 的 HAL conditional-density estimator；bound 只由 seed 派生的三折 participant-level inner-CV negative log-likelihood 选择，平局取更小 bound。D/C 已知 arm propensity 固定为条件随机化概率 `1/2`。任何其他 TMLE、g-formula 或 IPW 估计不得替换 primary estimator。

区间估计唯一使用 2,000 次 participant-cluster bootstrap。每次在 `arm×baseline_reviewer_support` 层内有放回抽取完整参与者 cluster，保留簇的抽中 multiplicity 与其全部十二 trial。bootstrap 域字符串固定为 `C3-JFG-BOOT-20260816-v1`，实际 seed 及其 SHA-256 在读取确认性 `Y` 前写入 manifest。每个 replicate 完整重拟 nuisance、产生 cross-fit 预测并重跑 targeting 流水线，不得只对最终 trial 行重抽；95% 区间固定为 percentile interval。失败 replicate 不重抽、不补抽；非有限值、违反截断或 ratio 门、与预提交 pipeline 不一致均计入失败率，失败率超过 5% 时输出 `MECHANISM_NOT_ESTIMABLE`，不临时改用另一种区间。repository 依赖只以预注册的 participant×repository two-way influence-curve variance 和 repository-hash leave-group-out nuisance refit 作敏感性；它们不得取代 primary。repository-OOD seed 为 `C3-JFG-REPO-OOD-20260816-v1`，repository 组号固定为 `1+(UInt64BE(SHA256(UTF8(seed)||0x00||UTF8(repository_id))[0:8]) mod 5)`；每次以一组作目标组，其余组训练 nuisance，且目标组 participant 若还在训练组出现则从该次 nuisance training 整体移除。该检验只作外部敏感性。

概率稳定化与 density-ratio 稳定化严格分开。二元 nuisance probability 才截断为 `[0.01,0.99]`；`K` 类概率向量使用 `p_j^tr=0.98p_j+0.02/K`，不逐项截断后破坏归一化。对十二 trial 簇内 joint-process prefix `s`，未裁剪密度比为 `ρ_s=∏_{u≤s}g_{a*,u}(Z_u|X̄,Z^J_{<u})/g_{a,u}(Z_u|X̄,Z^J_{<u})`，它依法可以大于 1；clever-covariate 中只使用 `ρ_s^clip=exp{clip(log ρ_s,-log 20,log 20)}`，即固定裁剪到 `[1/20,20]`。probability truncation 绝不作用于 density ratio。可评价 prefix 指截至 `s` 的全部字段均为实测值或预注册结构码且尚未进入 `C_Y`。对 arm `a`、外层 fold `k`，`clip_rate_{a,k}=Σ_{i,r,s}I(A_i=a,fold_i=k,prefix_{irs}可评价,|logρ_{irs}|>log20)/Σ_{i,r,s}I(A_i=a,fold_i=k,prefix_{irs}可评价)`；分母为 0 直接失败。任一 `clip_rate_{a,k}>0.05`、出现非有限 ratio 或未裁剪与裁剪 `IIE_JFG^cl` 的符号不同，即设 `RATIO_SUPPORT_FAIL`，不作因果报告，也不尝试另一个阈值。

共同支持只由 outcome 解封前的字段决定。对 trial `r` 与 participant `i`，处理前 key 唯一为 `H_ir=(risk_stratum_ir,baseline_reviewer_support_i)`。定义 `N^P_{a,h}=Σ_i I{∃r:A_i=a,H_ir=h}`、`N^T_{a,h}=Σ_{i,r}I{A_i=a,H_ir=h}`，并以 `S_h^count=I{min_a N^P_{a,h}≥20 ∧ min_a N^T_{a,h}≥30}` 判定计数支持。某 action/category 在同一 public history 下由冻结 mask 判为结构不合法时，其 intervention kernel 概率固定为 0，不构成 positivity failure。另令 `B_h=1` 当且仅当 T−2 state machine 在 cell `h` 中存在一个 reference process 可达的 public prefix/category，而 outcome arm 在同一 prefix 将该 category 结构性 mask；该判定只读 grammar、mask、family code 与 public state，不读 `q`、response outcome、approval 或 `Y`。唯一最终指标为 `S_h=S_h^count(1-B_h)`。`S_h^count=0` 记 `BASELINE_UNSUPPORTED`，`B_h=1` 记 `ASYMMETRIC_STRUCTURAL_ZERO`，两者都从 shared-support population 移除且不得用 probability floor 伪造支持。若没有 `S_h=1` cell，固定记 `MECHANISM_NOT_ESTIMABLE`。否则 `P_sup^cl` 固定为 D/C 两臂 shared-support 参与者的合并经验分布，每人等权且每人内十二个计划 trial 等权。定义 `r_a^cl=n_a^{-1}Σ_{i:A_i=a}[12^{-1}Σ_rS_{H_ir}]`；任一 `r_a^cl<0.80`、任一 risk stratum 在任一臂没有 `S_h=1` trial，或存在任一 `B_h=1`，机制分析固定降为 association-only。若支持规则排除了处理前 strata，目标总体解释必须明确收缩为该 shared-support 参与者总体。所有 support、structural-zero 与 ratio 处置均在 sealed `Y` 解封前完成。

因果表达要求 participant-level treatment randomization/consistency、action 与 measurement version consistency、给定 `X̄_i` 和同一参与者既往 joint-process nodes 的 sequential process–outcome exchangeability、上述 baseline 与 sequential overlap、仅跨参与者 cluster no-interference，以及对真实 `C_Y` 的可识别 censoring。参与者内十二 trial 的学习、疲劳、理解修正和前序策略暴露均进入 cluster prefix，不被假定为无干扰。若这些识别假设、80%/stratum support 门、asymmetric structural-zero 门、ratio clipping-rate 门或任一 arm `C_Y≤5%` 门失败，但 cross-fitted HAL initial likelihood 仍有限且可重放，则不再 target 因果参数，只以相同 `P_sup^cl` 报告预先定义的 cluster plug-in `SA_J^cl=E_{P_sup^cl}[12^{-1}Σ_r∫μ̂_r(1,z^J_{1:r},X̄){Ĝ_0^{J,1:r}-Ĝ_1^{J,1:r}}(dz^J_{1:r}|X̄)]`，名称固定为 `standardized joint-process association`，并按上述 2,000 次整 cluster bootstrap 给不确定性。若 HAL/conditional-density 不收敛、任一 outer fold 的 `Y=1` event 少于 10、ratio/EIC 非有限、`PROCESS_SCHEMA_OMISSION`、bootstrap 失败率超过 5%，或两个实现不能逐字段重放 `Z^J`、target、fold、ratio 与 TMLE，则记 `MECHANISM_NOT_ESTIMABLE`，不报告机制数字。两类失败均仍可报告随机 policy total effect；任何 fallback 都不得使用“中介”“间接效应”或“机制被证实”。

mediator measurement 在全部臂使用同一 silent/no-feedback item bytes、顺序 seed、显示时间窗和不可返回正确答案的界面。题目可能促使审核者重新思考，因此 `Y` 只解释为统一 measurement regime 下的最终决定；没有另一个随机化研究时，不外推到未测量制度。measurement 后的安全请求必须允许执行并进入 `Z_8`，不进行第二次 mediator measurement 覆盖 `Z_7`。

micro-randomized grounding encouragement 只构成独立次级机制实验，并使用不与 D-vs-C primary confirmatory trial 或参与者复用的 secondary cohort。在 `repair` 合法、技术 evidence bytes 已固定、至少有一项尚未展示的 micro-transfer item、同一 trial 尚未 encouragement 且参与者不处于前次 active encouragement 后的一 trial washout 时，以已知 `p=0.5` 最多随机一次。treatment 是预先 hash 的中性 paired-uptake request，control 使用等长 bytes；两者不得新增、删改、强调或重排技术事实。renderer receipt 与 human-exposure receipt 共同定义 compliance，缺任一 receipt 记为 noncompliance。次级主分析按 assignment 做 intention-to-treat，以 participant-cluster GEE 估计下一项独立 micro-transfer score 的 proximal difference；complier 分析和 distal unsafe approval 均只作探索。micro item ID 不进入 `Z_7`，该实验不进入 `IIE_JFG^cl` 或 primary longitudinal TMLE。

## 9. 强基线与机制干预

强基线至少包括：

- Consent Integrity canonical renderer。
- BSG-VA evidence role 与 bug-contrast feedback。
- PICK information-gain/coverage distinguishing scenario selection。
- AutoSD scientific-debugging trace。
- FixCheck、SWT-Bench 和 c-CRAB executable evidence。
- TraceView 与 Software Delegation Contracts 静态 evidence bundle。
- 固定 top-k、普通 reranker、等参数 cross-attention selector 与通用 contextual bandit/POMDP。
- Human-state POMDP、Raw-POMDP、generic proposition Transformer 与 contextual bandit：获得与 C3 完全相同的 `J_content`、proposition labels、human feedback、静态 candidate lattice、T−2 dynamic branch/replay contract 与完全相同的分支 bytes、reward、action mask、logging propensity、训练/验证 split、参数、FLOPs、wall-clock、随机种子数和超参数搜索预算。它们可学习任意 human state 或多任务头，只不强制使用 C3 的 potential/established、phase、uptake 与 criterion 分解。

必须实施：

- action swap 与 stale-evidence 检验。替换 diff、command 或 pre-state 后，旧证据必须失效。
- 打乱 potential/established grounding state。
- 保持 evidence/action 不变，打乱 clarification、repair、`grounding_acceptance` 顺序。
- 保持 evidence 不变，交换审核者 factual response。
- 打乱外生 objective/resource/risk/commitment 内容类型，同时保持文本与标签预算不变。
- 在 raw features 不变时 clamp 某一命题的 established state，检验策略是否停止重复证据并转向其他缺口。
- 打乱 evidence–action binding。
- 固定或打乱预算状态。
- 交换证据顺序。
- theory bottleneck 与获得同标签、同信息的 raw-feature bypass 对比。
- 同文字长度、同时间和同视觉显著性的内容干预。
- coding-agent deletion 试验一：保留相同 grounding 界面，但把可执行 action-derived evidence 替换为静态通用解释。
- coding-agent deletion 试验二：保留可执行证据获取和相同预算，但删除 reviewer-state filter 与 repair，只按技术证据价值选择动作。

通用 POMDP 在表达能力上可以逐项复制乘性门、隐状态和策略。理论算法贡献只在预注册的有限真人数据、未见 repository/reviewer/risk OOD、方向性 clamp/shuffle 和安全—效率前沿均未被公平通用模型复制时成立；任何公平模型复制这些能力，即撤销独立理论算法贡献。真人机制分析以决策前可观察的完整 `Z^J` 联合过程为随机干预对象，不把 `g_est` 当成已识别中介，也不把 acquisition、clarification 或 repair 条件化到过程之外。若序列识别假设不成立，只报告标准化联合过程关联；若只有 total effect 而 `IIE_JFG^cl` 与联合过程方向干预均不支持理论路径，优先归因于 evidence quality 或其他直接路径。

## 10. 撤题条件

- 回到 when-to-ask、allow/deny 或二分类 risk score。
- 在策略动作中保留 reviewer assignment 或 second-reviewer，进入 C19 的监督分配题。
- prompt、template、checklist、RAG、top-k 或普通 reranking 成为主要算法。
- 只实现 canonical renderer、hash、receipt 或 attestation。
- 只移植 BSG taxonomy、FixCheck/SWT test generation、AutoSD trace、PICK examples 或 TraceView UI。
- 证据来自同一被审 agent 的自述，不能 trusted replay。
- action/state/permission/scope 变化后 `J_content`、`m_req/κ`、题目 bank、lattice、evidence 或理论状态仍有任一旧对象有效。
- 把 green tests 当作充分证据。
- 只有 LLM judge 或模拟用户。
- 优化 trust、acceptance 或 confidence，而非 unsafe approval。
- 单向显示却宣称建立 common ground。
- 不报告 safe approval、false rejection、时间和计算代价。
- generic 等参数 selector/POMDP 达到相同前沿。
- Human-state POMDP 复制理论前沿，或纵向联合取证—grounding 过程不承担 unsafe-approval 改善的机制。
- evidence validity、test generation、harm prediction、action binding 或 hidden oracle 被归因于 common ground。
- 训练或展示泄露 gold patch、hidden tests 或危害标签。
- candidate generator/branch instantiator 接触 G/hidden evaluator，T−2 未承诺可重放 `clarify/repair` 分支，或成对 hidden-byte mirror 中的 candidate bytes/ID/order/mask/cost/latency/trace/action logits 不一致。
- 以裸 availability AUC 把合法 public risk signal 当作泄漏证明，或在机械 noninterference 失败时仍保留相关 group。
- 把 selected action/subtype 写入 `S_t^pre`，绕过两级 propensity/candidate cap，使用 participant 以外的 ESS 定义择优，或关键合法 cell 未达预注册 opportunity、cluster 与 Kish ESS 门仍作离线外推。
- pilot、logging、confirmatory 与 micro-secondary participant/trial 发生禁止的复用，或 confirmatory response 回流训练。
- primary unsafe approval 不是由与 C3 交互的同一审核者对同一 canonical action 产生，或专家 adjudicator 替代了 participant outcome。
