# 候选二因果可识别数据与算力预冻结规格

## 1. 判定与文件性质

候选二当前最终判定是 `NO-GO / REMOVED FROM SERIES`。本文件只保留“什么数据才足以识别相关状态”的历史规格与反证价值，不再冻结题目、数据路线或 thesis 槽位，也不表示数据已经生成。即使未来满足本文 pilot 门槛，也必须先按 `00P_候选二TMS理论责任与等参数反证.md` 重新定义成员特定 meta-memory、条件可靠性、task–knowledge coordination 和 post-action application，再作为一个新候选从零审查；不能把已有协作日志的观察相关性或本文件的工程规模写成 TMS 机制。

## 3. 状态的理论与技术边界

### 3.1 真实能力与 expertise-location belief

`E^*_{a,k,t}` 是 agent `a` 在时点 `t` 对知识域 `k` 的任务隔离真实能力后验。它由 full-tool solo probes 在多个任务和多个 seed 上估计，仅用于评价和按时间更新。

`D_t[a,k]` 是团队关于谁知道什么的 belief。策略在时点 `t` 只能使用此前 probe、承诺和执行证据，不能读取当前测试任务上的 repeated-rollout oracle。`D` 的评价是对未见任务和未来时点 `E^*` 的校准，而不是一次成功的分类。

### 3.2 claim reliability

`C_t[a,k,q]` 只表示 cognition-based trust 中与结构化事实声明和行动承诺兑现有关的 reliability component。它不能与能力 belief 重复。每条 claim 至少包含：

- claim type；
- file、symbol、API、invariant 或 test predicate；
- 兑现 horizon；
- 当前 opportunity 和 permission；
- 可执行 verifier。

事实声明由代码或测试 verifier 检查，行动承诺由固定 checkpoint 的 diff/test 检查。缺少执行机会、权限或可靠观测时标为 UNKNOWN。必须形成 high/low `D` × high/low `C` 的 2×2 干预：固定 checkpoint 改变 reporting fidelity，固定报告机制改变 checkpoint 能力。

### 3.3 task-intrinsic knowledge requirement

`Q_t[u,k]` 是技术状态，不冒充 TMS 原文独立构念。gold patch overlap、dependency slice、coverage 与 accepted patch 只能说明相关性，不能证明知识必要，因为正确实现可能不唯一。

训练标签来自 two-world contract task。同一 receiver 可见前缀下，私有知识 `k` 有两个语义可行值 `k0`、`k1`；两世界的 hidden obligations 要求不同，而且 generator 必须证明不存在一个 action 同时满足两世界。knowledge item 只允许 API contract、symbol semantics、system invariant、dependency/order fact 或 test obligation。`Q=0` 使用同仓库、同难度但没有 dependency witness 的 matched item。

### 3.4 actual knowledge application

`A_t[a,u,k]` 不是“消息是否发送、读取或提及”。在同一 quiescent prefix 上至少运行三臂：

1. correct knowledge packet；
2. 语义匹配但内容方向相反的 corrupt packet；
3. 等长度 sham 或 withheld packet。

固定 receiver checkpoint、repo/tool state、未来 collaborator 行为和 paired decoding seed。预注册 content-specific action predicate，例如调用签名、symbol、invariant 或 test assertion。只有 downstream action 随 `k0/k1` 的内容方向一致变化，才算 application。输出是 used-helpfully、used-harmfully、not-used、ambiguous，application 与 utility 分开。

数据必须覆盖 `Q1A1`、`Q1A0`、`Q0A1`、`Q0A0` 四格。缺格时，task need 与 knowledge use 仍不可分。

### 3.5 外部技术状态

- `J_t[u,v,r]` 表示 change intents 的 semantic dependency，是 software world model，不计作 TMS 理论贡献。
- `P_t[a,tool,path]` 表示可观测 permission/affordance mask。权限变化改变可执行动作，不代表知识变化。
- `Z_t` 由 `D`、`C`、`Q`、`A` 形成 task–knowledge coordination bottleneck。主模型禁止 raw features 绕过 `Z_t`，另设 bypass 模型作反证。

## 4. 同前缀反事实运行环境

公开日志无法恢复闭源权重、KV cache、随机状态、in-flight tool call 和异步消息队列，不能声称提供同前缀因果反事实。

新 harness 只能在 coordinator-enforced quiescent barrier 分支。分支点没有运行中的模型或工具调用，并快照：

- 两个 worktree/container filesystem 和 git index；
- 完整 conversation tokens；
- task queue、message queue、scratchpad 和 coordination state；
- permission、tool 与 token budget；
- base checkpoint、adapter、tokenizer 和 chat template；
- Python、framework、sampler 与系统 RNG；
- container image 与依赖 digest。

恢复后重新 prefill。GPU 非确定性用 branch-order randomization 和至少两个 paired seeds 处理。任意异步中间时点若不满足这些条件，不得写作“相同初始状态”。

每个 policy prefix 至少运行：continue parallel、A→B serialize、B→A serialize、targeted query+contract、handoff/reassign。可增加 discard，但不得把五动作压成一个协作模式 classifier。

## 5. 任务与 agent 因子

SWE-smith 只作为 container/task 底座。构造 producer-private API/invariant change 与 receiver consumer adaptation 的 two-world contract pairs。CooperBench 与其他公开 team tasks 保留为 external evaluation，不参与 generator 或 policy weights。

至少包含六种 capability profiles，覆盖两个以上开放模型或 checkpoint family，并用同 backbone 的 repair、test、API adapter 控制架构混淆。repo experience 分 0、少量和丰富历史；permission 分三级；drift 包括预注册的 checkpoint/adapter swap、permission revoke 和 retrieval staleness。claim reliability 使用独立 reporting-policy factor。

agent identity 对模型匿名，以能力和执行证据更新 belief。任何 test repo 的历史不得进入离线训练；若允许在线更新，只能使用测试时点之前可观察到的证据。

## 6. 最低数据规模、划分与 pilot 门槛

### 6.1 纸级最低量

- 1,200 个 task families；
- 至少 80 个 repo/fork networks；
- `6 profiles × 8 domains × 20 tasks × 2 seeds = 1,920` 次 solo capability probes；
- 至少 4,000 条 machine-verifiable commitments；
- 至少 2,400 个 Q-positive 及等量 matched negative；
- `1,000 prefix-item clusters × 3 treatments × 2 seeds = 6,000` 个 short-horizon application branches；
- `600 prefixes × 5 actions × 2 seeds = 6,000` 个 terminal policy continuations。

### 6.2 划分

80 个 repo/fork networks 按 50 train、15 dev、15 internal test 初步规划。同一 lineage、base commit、generator template、two-world variant 及其所有 counterfactual branches 必须在同一 split。另做 chronological cutoff、unseen checkpoint 和 unseen agent-pair tests。任何 adapter 或 reporting policy 不得使用 test repo。

### 6.3 pilot

先运行 20 个 repos、120 个 families 和 200 个 prefixes。任一条件触发 NO-GO：

- two-world construction pass rate 低于 70%；
- application non-ambiguous rate 低于 25%；
- correct/corrupt content treatment 的 first-stage effect 低于 0.20；
- paired-seed agreement 的 Cohen's kappa 低于 0.60；
- high/low D × high/low C 无法形成辨别效度；
- Q/A 四格缺失或严重失衡。

## 7. 训练对象、张量与损失

heterogeneous temporal graph 的节点包括 agent、subtask、knowledge item、file/API、test obligation 与 claim；边包括 knows-belief、requires、claims、applies、depends、commits、violates 和 verifies。

主要张量：

- `D ∈ [0,1]^(A×K)`；
- `C ∈ [0,1]^(A×K×Q_c)`；
- `Q ∈ {0,1}^(U×K)`；
- `A ∈ Δ^4^(A×U×K)`；
- `J ∈ Δ^R^(U×U)`；
- `P ∈ {0,1}^(A×T×H)`；
- structured assignment、ordering、contract 和 handoff action tensors。

损失：

- `L_D`：以任务隔离 `E^*` 为校准目标的 Beta-Binomial NLL；
- `L_C`：排除 UNKNOWN 的 conditional Brier/NLL，加 `D`—`C` disentanglement；
- `L_Q`：two-world oracle 的 requirement loss；
- `L_A`：correct/corrupt/sham 的四类 paired intervention loss；
- `L_J`：semantic relation/order calibration，不计作理论贡献；
- `L_pi`：相同前缀多动作结果上的 constrained/CVaR policy loss，同时控制 conflict regression、overwrite、task failure、wall-clock、通信和 wasted work。

## 8. 推断动作与外部结果

策略真正执行：任务所有权调整、方向化先后、针对性知识请求、结构化 contract、cross-verification、带 checkpoint handoff/reassign、废弃未提交冲突工作。普通广播、共享 scratchpad 和固定角色只作基线。

主要外部结果同时报告：

- conflict-induced functional/security regression；
- overwrite、lost work 与 unmet joint obligation；
- both-task success 与 harm-free completion；
- communication tokens、wall-clock、GPU/tool cost；
- wasted implementation work；
- belief calibration、claim-reliability calibration、Q/A identification；
- 未见 agent pair、checkpoint、repo 与 drift 下的风险—成功—成本前沿。

## 9. 算力与复现工件

按公开 Qwen team rollout 的 processed-token 量级，最低方案预计约 2.5–4.5B processed tokens，加容器缓存、分支状态和日志约 1–3TB。至少需要 4 张 48GB 或 80GB GPU 并行数个 GPU-week；单张 24GB workstation 不足以支持该候选。state model 可用 100M–500M temporal graph，7B–9B policy 只作 QLoRA，rollout 而非模型训练是主要瓶颈。

必须保存 base/checkpoint/adapter hash、tokenizer/template、container digest、repo/license manifest、split manifest、generator seed、branch-order、RNG、tool trace、message trace、state snapshots、hidden obligations 和 evaluation version。

## 10. 最强基线与撤题条件

直接基线包括 CooperBench official teams、Cooperator SFT、leader/follower dual policy、SWEET-RL、Shepherd、Claim Plane/SDM、SkillGraph、central planner、shared scratchpad、固定专家、MoE router、等参数 sequence/graph Transformer 和 generic belief-state POMDP。

理论干预包括打乱 agent–expertise、独立操纵 D/C、打乱 Q、交换 correct/corrupt knowledge、删除 A bottleneck、固定 J、撤销 permission、替换 checkpoint、去除 task interdependence 和允许 raw-feature bypass。

出现以下任一情况即撤题：

1. 公开日志或 accepted patch proxy 被当作 D/C/Q/A 真值；
2. 无法构造 two-world knowledge necessity；
3. 无法进行 quiescent-prefix correct/corrupt/sham 与五动作分支；
4. expertise belief 与 claim reliability 不能区分；
5. knowledge sharing 与 actual application 不能区分；
6. Claim Plane+history、SkillGraph 或等参数 generic graph/POMDP 复制风险—成功—成本前沿；
7. 安全改善来自总串行、总 handoff、更多 token 或更多广播；
8. 主要结果只有 team pass rate，没有 overwrite、conflict regression 或 wasted work；
9. pilot 未通过第 6.3 节门槛；
10. 资源不足以完成最小 rollout，且试图用闭源一次日志或 LLM judge 替代。
