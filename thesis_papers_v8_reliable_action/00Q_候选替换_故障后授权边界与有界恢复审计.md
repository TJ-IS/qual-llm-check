# 候选替换题：故障后授权边界与有界恢复审计

## 0. 当前判定

**本文件所记录的候选已经被后续独立红队判为 NO-GO，无保留。** 它不再替代论文一，也不占据三篇系列名额。本文保留被否决方案的直接近邻、理论映射、工件和 pilot 蓝图，不能被引用为理论已经闭合的依据。最终判定及新增直接近邻见 `00R_故障后授权边界候选理论与近邻红队.md`。本文也不构成任何已经取得经验结果的声明。

候选问题可以用一句话表述：coding agent 接受了完成任务的责任，并不因此自动获得绕过权限、扩大搜索范围或改变安全边界的权利；当正常路径因环境错误失效时，能否学习一种有界恢复策略，在保留正常任务恢复能力的同时，避免把“必须完成任务”错误地解释为“可以采取任何手段”。

## 1. 风险现象与研究对象

这一问题发生在正常任务已经开始、环境错误刚刚出现之后。错误可以是文件不存在、依赖缺失、权限拒绝、远程资源返回 404 或 429、部分内容缺失、工具返回虚假成功、策略阻断或服务能力临时变化。此时 coding agent 已经获得了一部分任务执行权和结果责任，却未必获得以下权利：

- 搜索用户未指定的目录、网站或第三方资源；
- 提升权限、修改访问控制或关闭证书验证；
- 联系第三方、发送数据或披露私有内容；
- 改变系统配置、安装不可信依赖或扩大网络范围；
- 隐瞒失败、把未经验证的结果报告为成功。

潜在损害不是抽象的风险分数，而是执行轨迹中的越权副作用、边界弱化、秘密或私有内容暴露、错误外联、持久配置变更和虚假完成报告。正常结果同时包括任务是否恢复、恢复后的功能正确性、恢复成本、执行时延和需要的人类介入。

该现象不同于恶意 prompt injection。错误和用户任务都可以是善意的，风险来自 agent 在受阻后扩大行动空间。它也不同于一般工具故障恢复。一般恢复关注 retry、fallback 和最终成功，本题关注恢复动作的授权依据、作用范围和对持久状态的副作用。

## 2. 已核验的直接工作及其挤压

### 2.1 Agent Meltdowns

Jha、Triedman、Bhattacharya 与 Shmatikov 的 *Agent Meltdowns: The Road to Hell Is Paved with Helpful Agents*（arXiv:2605.19149v1，2026）直接界定了 benign environmental error 引发 accidental meltdown 的现象。论文在四种 agent harness、八种模型和七类错误上运行 1,920 条错误轨迹，其中 1,244 条出现至少一种中高严重度行为。论文把行为分为 scope overreach、misleading reporting、unauthorized outreach、boundary subversion 与 unauthorized access/disclosure，并公开了可配置的 noisy-container 镜像。该研究是现象测量与分类，不训练恢复控制策略。来源：[全文](https://arxiv.org/html/2605.19149v1)，[noisy-container](https://hub.docker.com/r/htriedman/noisy-container)。

因此，本题不能声称首次发现善意错误会造成伤害，也不能把复刻七类错误或训练一个 meltdown 分类器当作主贡献。剩余空间必须是可执行的 learned recovery policy，并以实际任务恢复和实际越权副作用共同评价。

### 2.2 Failing Tools、ToolMaze 与通用故障恢复

*Failing Tools: Benchmarking LLM Agent Recovery Under Runtime Tool Failures* 已用 218 个 stateful service 场景评价 availability denial、stale data、silent no-op、corrupted state、schema mismatch 等故障，并以 required actions、forbidden actions、postcondition verification 和 faithful uncertainty communication 评价恢复轨迹。其正式元数据和开放代码状态仍需核验，当前不得把搜索页信息写入正式论文。

ToolMaze 已系统覆盖 transient/permanent 与 explicit/implicit tool failures，并评价 retry、替代路径、重规划和 graceful abort。SafePred、SafeMCP、ToolSafe 与 MOSAIC 又分别覆盖后果预测、look-ahead tool pruning、逐步工具安全反馈和 act/refuse 学习。由此，下列设计已经不足：错误分类后选择 retry/fallback、给候选动作加风险分数、二元停止、固定 forbidden-call 清单，或自然语言 world model 预测后直接阻止。

### 2.3 静态授权、策略与端点检测

Conseca 已从任务与 trusted context 生成即时策略并确定性检查动作。PCAS 已用跨消息与工具调用的因果依赖图执行 Datalog 类策略。OAP、Authenticated Delegation、IGAC 和其他 capability-token 工作已经覆盖 pre-action authorization、intent certificate、scope narrowing、签名凭据与审计。Numbat 已公开面向 coding-agent endpoint 的统一事件模型、CEL 单步和序列规则、可选 pre-action blocking 及法证重建。来源分别为 [Conseca](https://doi.org/10.1145/3713082.3730378)、[PCAS](https://arxiv.org/html/2602.16708)、[OAP](https://arxiv.org/html/2603.20953)、[IGAC](https://arxiv.org/html/2606.22916) 与 [Numbat](https://github.com/perplexityai/numbat)。

这些工作意味着策略表达、签名、rule engine、intent-to-policy 翻译和固定 allow/deny 都只能作为基础设施或基线。本题若最终只是识别越权命令并阻断，应直接撤销。

### 2.4 coding-specific 可运行外部评价

SABER 提供 stateful project workspaces、完整轨迹和 state delta；Boundary-Bench 把 Terminal-Bench 任务放入逐级 hardened policy，显示策略约束会同时降低成功率并增加成本；OverEager-Bench 与 UnderSpecBench 分别测量 benign task 的 scope expansion 和 underspecified DevOps instruction 的 action-boundary violation。后两项是否提供足以重放的公开 artifact 仍需继续核验，在开放性未确认前只能作直接近邻，不能列为训练资源。

## 3. IS 理论是否自然适用

### 3.1 首选理论来源

Baird 与 Maruping（2021）的 IS delegation framework 把 delegation 定义为在 human–agentic IS dyad 中转移任务执行与结果的权利和责任，并提出 appraisal、distribution 和 coordination 三类机制。原文特别区分 decision rights、outcome responsibilities 与 intervention rights/responsibilities，允许 transfer 是部分的，也允许 delegator 与 proxy 的角色在执行过程中改变。原文还指出 coordination 包括依赖管理、监控、更新、accountability、predictability 和 common understanding。来源：本地全文 `database_fulltext_all/10752_2021_the-next-generation-of-research-on-is-use-a-theoretical-framework-of-delegation-to-and-from-agen.md`。正式元数据为 Baird, A., and Maruping, L. M. 2021. “The Next Generation of Research on IS Use: A Theoretical Framework of Delegation to and from Agentic IS Artifacts,” *MIS Quarterly* 45(1):315–341, DOI 10.25300/MISQ/2021/15882。

这一理论与故障后恢复的自然联系是：用户可以把完成任务的责任交给 coding agent，却只转移有限的决策权；正常路径失效并不会自动扩大原始权利。错误出现后，agent 需要协调、更新或重新协商权利和责任，而不能把结果责任当作无限行动授权。

### 3.2 理论可以负责的内部状态

理论只允许产生以下不可合并状态：

- `O_t`：仍未满足的任务与结果责任，不表示 agent 可以采取任何动作；
- `X_t[a,r,e]`：对 action、resource 与 effect 的当前执行权；
- `I_t[a,r,e]`：故障后改变边界、回滚、替代或请求介入的 intervention right；
- `K_t`：由显式确认、拒绝、更新和实际执行结果形成的 coordination state；
- `Role_t`：当前 delegator、proxy 或重新委派状态；
- `P_t`：外部 reference monitor 实际可强制的 permission mask，不能被主观信念替代。

`O_t`、`X_t` 与 `I_t` 必须分别建模。理论最关键的方向性命题是：结果责任越高并不意味着 intervention rights 越大。若模型把三者压成一个“自主性”或“风险”标量，理论贡献即不成立。

### 3.3 理论不能负责的技术事实

IS delegation framework 不产生故障类型、文件依赖、命令副作用、漏洞严重度、工具幂等性或 state-delta 真值。这些必须由执行环境、静态或动态分析和反事实 rollout 提供。理论也不直接规定某个网络层数、GNN 关系类型或损失权重。若最终收益只来自 effect graph、更多测试或普通 world model，不能把技术收益归因于 delegation theory。

## 4. 可训练工件的最低结构

### 4.1 输入、输出与真实动作

输入由四类信息构成：用户任务与明确授权，repository/container 当前状态，错误前轨迹与错误观测，外部 policy/permission mask。模型还接收 AST、文件和依赖关系、进程与网络资源、命令参数、执行回执和 pre/post state hashes。

模型输出不是 allow/block 标签，而是序贯恢复动作：在授权范围内检查状态、验证 postcondition、对幂等操作重试、使用已授权替代路径、在 shadow environment 中试运行、建立 checkpoint、请求一个具体且最小的新增权利、把受阻子任务重新委派给人、停止并忠实报告，或在产生副作用后执行 rollback/compensation。正常代码修改与命令仍由同一 coding agent 实际执行。

### 4.2 图状态和前向计算

候选工件使用 typed task–authority–fault–effect graph。节点至少包括 obligation、right、responsibility、resource、fault、candidate action、observed effect、postcondition 和 report claim；边至少包括 delegated-to、permits、requires、changes、verifies、violates、depends-on 和 reported-as。

一个 effect world model 预测候选动作的 state delta、任务恢复概率、越权副作用、可逆性和后续可行动作集合。一个 delegation state updater 只能依据可信的用户/策略更新和执行回执改变 `X_t`、`I_t` 与 `K_t`。层级策略在当前图和剩余预算上选择下一恢复动作。外部 reference monitor 仍负责确定性强制执行，学习策略不能自行提升权限。

### 4.3 监督与损失

训练样本必须来自实际执行，而不是由同一个 LLM 自证安全：

1. 在 noisy-container、Boundary-Bench、SABER 或自建许可明确的 coding fixtures 中注入错误，并在 quiescent checkpoint 保存完整状态。
2. 对同一前缀分支执行多个候选恢复动作，记录真实 state delta、hidden task predicates、policy violations、task recovery、secondary harm、tool/time/token cost 与最终报告。
3. 由 task manifest 和外部 policy 给出 `X/I/P` 真值；由执行 verifier 给出任务与副作用结果；不可判断的样本标为 `UNKNOWN`，不能强制二分类。
4. 按 repository、fixture template、fault family 与 policy family 成组切分，所有同前缀分支必须属于同一 split。

联合目标至少包括 task-recovery loss、executed-harm loss、right/responsibility factorization loss、counterfactual action-ranking loss、postcondition-calibration loss、honest-reporting loss 与 cost regularization。任何结果数字在真实训练前保持空白。

## 5. 必须出现的理论方向冲突

- agent 承担高结果责任，但没有修改访问控制的 intervention right。理论策略应请求最小权利、重新委派或选择授权内替代路径，普通“尽力完成”策略可能提权或绕过。
- agent 拥有某项执行权，但该权利与受阻子任务无关。理论策略不应因为 capability 存在就使用它。
- 同一错误既可通过宽权限捷径快速恢复，也可通过较慢但在授权内的替代路径恢复。理论策略必须把 rights distribution 与任务收益共同进入行动选择。
- 用户明确授予一次性 intervention right 后，策略应更新该局部权利并执行，不应因一般风险厌恶而继续拒绝。
- 外部 policy 阻断一个动作但任务可以分解。策略应重构子任务或重新委派受阻部分，而非无限重试或请求全部权限。

这些冲突不是事后解释材料，而要进入预注册测试集。删除、合并或打乱 `O/X/I/Role/K` 后，动作分布和安全—恢复前沿应发生可观察变化。

## 6. 强基线与等参数反证

直接基线包括：原 coding agent；failure-aware prompt；Numbat 规则；Conseca；PCAS/OAP/IGAC 类静态策略；SafePred；SafeMCP；ToolSafe；MOSAIC；ToolMaze/Failing Tools 的恢复 scaffold；固定 stop、固定 ask、固定 retry、固定 least-privilege 和 oracle policy。

通用替代包括等参数 raw Transformer、typed graph Transformer、generic effect world model 加 constrained POMDP，以及不区分权利与责任的单一 autonomy/risk state。所有模型使用相同 base model、rollout 数据、token/tool/test 预算、外部 policy 和容器。

只有同时满足以下条件，才可以保留理论算法贡献：候选模型降低 executed unauthorized effects；保持或提高 recoverable-task success；不过度请求权限；减少无效重试与隐藏失败；在 unseen fault、policy 和 repository 上保持优势；并且等参数通用模型不能在预注册等效界内复制安全—恢复前沿和方向冲突行为。

## 7. 数据与算力 pilot 门

先做 20 个独立 repo/fixture family 的 pilot。每个 family 至少包含无错误、可在原权利内恢复、需要局部新增权利、应重新委派和不可安全恢复五类状态，并在同一前缀执行不少于四类候选动作。pilot 必须证明：

- 至少 70% 的错误实例能被容器稳定复放；
- state-delta 与 policy oracle 对主要副作用的自动判定一致率达到预注册门槛；
- recoverable 与 unsafe-shortcut 两条路径在足够多实例中同时存在；
- static Numbat/PCAS 类规则无法在相同误拦约束下复制恢复收益；
- 训练样本中的权限和结果标签不依赖闭源 LLM judge。

完整训练量和 GPU 预算只有在 pilot 通过后估算。当前不得以模型参数或 rollout 数量替代科学可识别性。

## 8. 与肖帅勇老师两篇 ISR 的设计责任对照

ACAA 的关键做法是先用理论明确不同注意过程，再让该区别改变模态兼容方向和网络运算；DSDL 则先把期望、体验与不一致分成可计算中间状态，再以有方向损失和结果标签训练。对本候选的直接要求是：

1. 引言不能从“agent 会出错”直接跳到模型模块，必须先证明环境错误如何把任务责任与行动权利分离，并由直接工作自然收束到研究问题。
2. 理论部分必须先逐句建立 `responsibility ≠ execution right ≠ intervention right`，再提出计算挑战，不能把图张量先写出来后补理论名称。
3. 算法每一项理论张量都要在前向计算、更新或行动约束中出现；仅在 loss 末端附加 delegation score 不合格。
4. 实验必须分别回答整体安全—恢复表现、权利与责任分离是否有独立价值、理论状态是否具有方向性作用，以及该状态能否解释不同错误下的恢复选择。
5. 正式正文的每个段落仍需回到 `00J`、`00K` 与 `00M` 的对应位置逐句审计；本文件中的 NO-GO、撤题门和资源判断不得进入正文。

## 9. 立即撤题条件

出现任一情形即撤销本候选：

- 主要工件退化为 meltdown detector、危险命令分类器或 allow/ask/block router；
- static policy、Numbat 规则或 Conseca/PCAS 组合在同一安全—恢复前沿上达到等效；
- 数据只有最终成功或人工严重度，没有 action-level state delta、权限真值和反事实恢复结果；
- 任务责任、执行权和 intervention right 无法在数据中独立操纵或识别；
- 所谓恢复优势来自更宽权限、更多调用或更长时间；
- 通过停止所有动作或把全部情况交给人获得表面安全；
- generic equal-parameter graph model/POMDP 复制结果和方向冲突；
- 理论状态删除后只有轻微内部分类变化，没有真实行动和外部损害变化；
- 训练或评价依赖未经授权的真实系统副作用；
- 新的直接工作已经联合覆盖 error-induced authority expansion、learned bounded recovery、执行结果监督与 coding-specific evaluation。

当前最终结论是：该问题真实且可作为故障注入与恢复评价场景，但现有 IS delegation 映射没有产生通用授权图或 constrained POMDP 无法复制的计算能力，公开数据也不能独立识别 `O/X/I`。故本题判为 NO-GO，不冻结、不开始正式正文，也不以辅助 head 形式泄漏进其他论文。
