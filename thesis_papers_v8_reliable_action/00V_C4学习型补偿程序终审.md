# C4 学习型补偿程序终审

## 1. 最终判定

**NO-GO，无保留，并从当前系列候选中移除。**

被审问题具有真实的安全意义。coding agent 已经造成代码、配置、依赖、进程或外部服务状态损害后，系统需要恢复安全状态，并尽可能保留未受影响的有效工作。然而，问题重要不等于当前方案能够形成一篇 ISR 级独立论文。现设计的技术剩余空间已经被压缩为“从故障状态生成并执行补偿动作”，而其主要结构可以由现有语义恢复、事务、依赖回滚、故障定位和通用序贯策略组合得到。更关键的是，拟用的 digital resilience 理论只能界定恢复容量和恢复结果，不能推出 effect graph、补偿动作语法、恢复点、损失函数或行动顺序。理论移除后，算法工件不发生不可替代的变化。

因此，本题不能继续占用 thesis 题位，也不能降格为 C3 的恢复模块。以下内容仅保存撤题证据和未来新题的反证边界。

## 2. 原候选的最强版本

原候选并非普通 rollback。其最强可辩护版本要求模型完成四个联结任务。

1. 从完整 tool trace、repo/process/service state 和 hidden invariant failure 中定位 first unrecoverable step。
2. 构造 typed effect graph，区分已提交副作用、可逆状态、只能补偿的状态和不可逆状态，并识别仍然有效的下游工作。
3. 生成低层、可执行的 compensating patch/action sequence，而非自然语言计划、文件 revert 或依赖切片。
4. 执行补偿后，用隐藏功能检查、安全 invariant 和 state-delta oracle 同时评价 recovery success、residual harm、secondary harm、task salvage 与成本。

这个版本在工程上足够硬，也能产生模型权重、图状态编码器、序贯策略和可执行轨迹。然而，独立论文还需同时满足新增性、可识别监督和理论不可替代性。终审表明后三项没有同时成立。

## 3. 直接近邻对核心能力的挤压

### 3.1 DART 已占据语义恢复边界和有效工作保留

[DART: Semantic Recoverability for Structured Tool Agents](https://arxiv.org/html/2605.23311) 明确区分 controller legality 与 semantic validity。它先定位 failed instance，再认证 recoverable boundary，把 checkpoint 绑定到实例，最后依据 downstream commitments、dependency 和 effect constraints 选择 admissible rollback，无法证明合法时退回 whole-task rerun。其方法已经把“保留有效下游工作时，恢复是否仍具有语义有效性”变成显式判定，而非普通机械 checkpoint。

DART 的当前边界来自人工审核的 boundary configuration，不自动综合通用边界，也不处理任意不可逆外部副作用。这个限制为自动学习留下技术空间，却没有为当前候选自动创造独立贡献。若候选只是学习 DART 的 boundary、checkpoint 或 admissibility predicate，它成为现有语义恢复系统的学习型替代。若候选跨过不可逆副作用并生成补偿动作，它又必须解决下节的数据和理论缺口。

DART 的定理进一步指出，在不补偿、不失效或不联合回滚 committed consumer 的情况下，回滚上游 producer 无法保证语义等价。由此，“保留未受影响工作”和“依赖感知恢复”本身也不能再被列为当前候选的新机制。

### 3.2 其余近邻分别覆盖了恢复问题的关键组成

| 直接工作 | 已覆盖能力 | 对 C4 的约束 |
|---|---|---|
| [Human-Guided Harm Recovery](https://arxiv.org/html/2604.18847) | 从 harmful state 出发，生成自然语言恢复方案，用 1,130 个人类成对判断训练 reward model，并在 BackBench 上执行优选方案 | “恢复也应考虑上下文相关的人类偏好”与 generate-and-rerank 已覆盖；C4 不能以恢复计划排序或人类偏好分数为主贡献 |
| AgentRx, arXiv:2602.02475 | 定位 first unrecoverable step 与 grounded failure category | 单独的故障定位模型只是已有组件 |
| Revisable by Design, arXiv:2604.23283 | I/R/K/X 可逆性类别、earliest-conflict rollback 和 compensation call | 可逆性分类和按冲突点回退不能主张原创 |
| Atomix, arXiv:2602.14849 | transactional tool use、buffered effect 和 compensation handler | effect buffering 与预定义补偿属于基础设施强基线 |
| Cordon, arXiv:2606.17573 | typed lineage、shadow state、recoverable writes、effect outbox 与 commit/abort | provenance、事务阶段化和恢复日志已覆盖 |
| DeltaBox, arXiv:2605.22781 | stateful sandbox 的快速 checkpoint/rollback | 文件系统和进程恢复性能不是策略贡献 |
| Dependency-Guided Rollback Repair, arXiv:2608.10502 | typed dependency graph、受影响闭包、quarantine、selective replay 与 benign preservation | “找到受影响节点并选择性回滚/重放”已被直接覆盖 |
| [Speculative Rollback Correction](https://arxiv.org/html/2606.12485) | 固定窗口分支审查、首个有害偏离定位、rollback 后保留有效前缀并产生模仿训练数据 | 学习型分支回滚、有效前缀保留和 verifier-passing correction 也已有直接近邻 |

这些工作不能单独覆盖“执行不可逆副作用后的 coding-specific compensating program synthesis”。但它们的组合已经覆盖该问题除低层补偿生成以外的状态、边界、定位、恢复设施和评价骨架。当前候选的 headline 因而被压缩为一个狭窄的程序综合问题。

## 4. 公开监督不能识别所需策略

BackBench 提供 50 个 harm-recovery 场景和完整轨迹评价，但其训练监督是自然语言方案偏好，并没有为同一 harmful state 穷举可执行补偿动作及其 state delta。Agent Meltdowns 和 Noisy Container 可以注入正常错误并观察越界恢复，却没有系统给出已经产生外部损害后的多条补偿分支。SABER 提供 coding workspace trace、state delta 和 harm predicate，但公开任务并未为每个已损害状态提供相同前缀下的 recovery action lattice。事务和 rollback 系统的数据又依赖预定义 handler 或受控 workflow。

若要独立训练 C4，必须另建至少包含以下元素的数据环境。

- 同一 pre-harm snapshot、同一实际 harmful action 和可复放的 post-harm state。
- code、config、dependency、process、mock database/network/service 等跨资源副作用。
- 对每个 post-harm state 运行多种 patch、compensation、joint rollback、quarantine、notify、stop 等分支。
- 对每条分支记录功能恢复、安全 invariant、残余损害、二次损害、不可逆暴露、任务保留和成本。
- 将 gold safe state、hidden checks 与实际 agent context 物理隔离，并按 repo、harm generator、resource topology 和 effect family 分组划分。

这类数据可以严谨构建，但当前没有现成公开集合直接提供。若仅用 LLM 生成补偿方案后由 LLM judge 标注，监督会退化为 Human-Guided Harm Recovery 的自然语言代理。若只在 resettable container 中制造文件和进程错误，又无法证明处理了不可逆 external effect。若通过手工 handler 生成 gold compensation，主要能力转回 Atomix/Cordon 类系统配置。

数据缺口本身不是撤题的唯一理由。真正的撤题原因是，即使承担高成本构建，这些数据也只识别一个通用 effect-conditioned recovery policy，仍未识别下面的 IS 理论机制。

## 5. Digital resilience 不能承担算法责任

Tim 与 Leidner 的 [Digital Resilience: A Conceptual Framework for Information Systems Research](https://doi.org/10.17705/1jais.00842) 将 digital resilience 定义为个人、组织和社群通过 IS 的设计、部署和使用从外生冲击中恢复的容量。本地全文明确把 constituent elements 组织为 assets、abilities 与 activities，并将恢复表现区分为 continuity、adaptation 与 advancement。该理论还强调容量是与冲击情境、系统状态、恢复需要以及能力调动方式相关的上限，而非一项孤立技术属性。

这个框架可以支持三类正文命题。

1. 恢复不能只看是否回到某个旧 snapshot，还需区分维持连续性、适应新状态和形成更强后续能力。
2. 恢复结果取决于可调动的资产、能力与活动，而非仅取决于 agent 是否输出一条修复命令。
3. 安全恢复可能与效率、创新或当前任务连续性存在权衡。

它不能从理论上推出以下计算。

- 为什么 effect graph 必须使用某组节点、关系和张量，而不是通用 provenance graph。
- 为什么 first unrecoverable step 是必要潜变量。
- 哪种 action 属于补偿、联合回滚、隔离、通知或继续执行，以及这些动作的先后约束。
- residual harm、secondary harm 与 task salvage 应以何种损失组合进入训练。
- 遇到两个同样实现 continuity、但在动作依赖和副作用结构上不同的方案时，算法应选择哪一个。

将 continuity、adaptation、advancement 设为三个 head 或三个 reward 项，不会解决这一责任缺口。三者是恢复表现的概念分类，不是补偿程序的生成语法。assets、abilities、activities 也过于宽泛，任何 state、tool 和 action 都可被事后归入其中。删除这些名称后，typed effect graph、seq2seq patch decoder、verifier 与 constrained policy 仍可原样训练和执行。

此外，原理论的分析单位是个人、组织和社群应对外生冲击的容量。一次 coding-agent action 造成的局部损害不自动等同于组织面对外生冲击。若把 agent 自身错误同时写成 shock、capacity 和 recovery activity，会混淆冲击来源、恢复主体与技术工件三个层次。

因此，digital resilience 只能成为结果解释或实践背景，不能成为当前候选的理论驱动算法。

## 6. 等参数通用替代反证

终审要求在相同 repo state、trace、effect graph 原始事实、训练分支、参数量、tool budget 和 verifier 下比较以下替代。

1. raw trajectory Transformer，直接从序列预测下一恢复动作。
2. generic heterogeneous temporal GNN，对 resource/action/state 节点做 message passing，再由 constrained decoder 生成补偿程序。
3. generic POMDP，以不确定 world state、外部 effect、动作成本和 hidden invariant belief 选择 inspect、patch、compensate、rollback、quarantine 或 stop。
4. DART/Cordon/Atomix 基础设施加通用 learned program synthesizer。

当前候选无法说明理论模型相对这些替代缺少的计算。所谓 theory-neutral 模型不仅能接收相同 state/effect 信息，也能使用完全相同的外部损害 reward 和 action constraints。digital resilience 的三种恢复结果若作为额外监督，同样可以直接加入通用替代。若通用模型达到相同安全—任务—成本前沿，理论贡献消失；若理论模型获益，也无法排除只是多了 outcome heads 或人工分组标签。

在肖帅勇老师两篇 ISR 论文的标准下，这一缺口是致命的。ACAA 先由注意过程与粒度推出 compatibility direction，再让该方向改变 attention 的前向计算。DSDL 先由 expectation–disconfirmation 推出 expectation、perception、disconfirmation 和累计状态，再让这些状态进入匹配与对比目标。C4 的 digital resilience 只能在模型输出后给恢复结果命名，不能像两篇参照论文那样在前向计算中制造一个理论专有、可被中和实验检验的方向冲突。

## 7. 为什么不把技术空白单独写成论文

“不可逆外部副作用后的可执行补偿程序”仍可能成为有价值的软件工程或 agent systems 研究。撤题不是否认其技术难度，而是拒绝把技术难度等同于本系列要求的 ISR 理论贡献。

若未来出现一项更具体的 IS 理论，能够独立规定恢复主体、承诺关系、资源调动或跨层恢复顺序，并且该规定无法被通用 effect graph/POMDP 复制，则可以从零建立新候选。它需要重新检索直接近邻、重建公开数据和通过等参数反证；不能以本文件中的 C4 自动恢复题位。

## 8. 撤题后保留的资源边界

以下内容可保留为其他研究的基础设施或评价资源，但不再代表 C4。

- DART、Cordon、Atomix、DeltaBox 作为语义恢复、事务和 checkpoint 强基线。
- Dependency-Guided Rollback Repair 与 AgentRx 作为依赖切片和故障定位基线。
- BackBench、Agent Meltdowns、SABER 和 Noisy Container 作为恢复压力测试或 harmful-state 生成素材。
- residual harm、secondary harm、task salvage、不可逆暴露和恢复成本作为广义安全评价维度。
- post-harm state 的 paired counterfactual execution 作为未来数据设计原则。

## 9. 最终撤题条件核对

| 条件 | 证据 | 判定 |
|---|---|---|
| 主要能力是否已被近邻拆解覆盖 | DART、Human-Guided、AgentRx、Atomix、Cordon、Dependency-Guided 与 SRC 分别覆盖边界、偏好、定位、事务、依赖和学习型回滚 | 是 |
| 剩余能力是否具有公开可直接训练的反事实监督 | 没有同一 post-harm state 的 executable compensation lattice | 否 |
