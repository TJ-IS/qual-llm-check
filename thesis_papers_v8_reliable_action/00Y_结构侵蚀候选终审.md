# 多轮自主修改中的结构侵蚀、可靠性回归与故障传播：替换候选终审

## 0. 终局判定

**判定：NO-GO。该候选不得补入三篇论文的独立题位。**

本判定冻结于 2026 年 8 月 15 日。它不是因为现象不重要，也不是因为无法写出一个技术系统。coding agent 反复修改自己的既有实现，确实可能积累高复杂函数、重复逻辑、跨模块依赖和隐蔽回归。决定性问题在于，这一候选同时失守了独立理论空间、广义安全结果、可识别训练真值和等参数理论责任四道门。

第一，Banker and Slaughter（2000）已经说明结构的维护收益取决于软件波动性和复杂性，且过多结构也会产生接口理解成本。Tiwana and Safadi（2024）又直接把系统内部逻辑一致性的跨期衰退概念化为 system atrophy，以模块化变化作为缓冲机制，以系统年龄作为边界，并检验了后续 bugginess、演化停滞和开发者流失。候选希望建立的“结构侵蚀—后续故障—条件化干预”主链已经有比 Banker and Slaughter 更近、更动态的 ISR 理论所有者。

第二，SlopCodeBench v2 已经把 coding agent 自身早期设计、后续自我延展、结构侵蚀和跨 checkpoint 回归置于同一可运行情境。NITR、Constraint Decay、Regression Accumulation、SCAFFOLD-CEGIS、Refactoring Runaway 和 RefactorAssist 又分别覆盖结构 oracle、结构约束失守、跨轮回归、潜在安全退化、失控重构和重构修复。训练一个结构感知策略仍可能带来工程增益，但不能再把现象发现、基本风险机制或一般干预需要作为独立贡献。

第三，公开资源没有提供同一仓库状态下多个语义等价结构行动及其共同隐藏未来需求后果。结构指标、一次观察到的补丁结果和未来测试失败之间不能自动组成行动因果标签。用 agent 生成分支补丁再让另一个固定 agent 完成未来任务可以制造训练信号，但该信号依赖生成策略、下游 agent 和人工设计的未来要求，无法被称为自然的“结构行动真实效应”。

第四，Banker and Slaughter 的交互项、Tiwana and Safadi 的 atrophy、modularity、age 及其交互，都可以作为同一时序异质图或 POMDP 的普通状态。只要等参数通用模型获得相同代码、历史、派生状态、行动集合和训练信号，它就能逐点复制理论模型的前向映射。若禁止通用模型使用这些输入或约束，比较测得的是信息和正则化不对称，不是理论产生了不可替代的算法能力。

因此，本候选最多保留为其他研究的辅助结果、数据构造维度或失败案例分析。它不能以“系统萎缩策略”“结构安全控制器”或近义名称恢复为独立论文。以下内容保留最强可行版本的完整规格，是为了证明判定经过了 steelman，而不是因为该版本已经获准实施。

本文件属于内部选题审计。没有运行本候选的实验，没有生成模型 checkpoint，也没有观察到本文所列的任何预期改进。所有模型、样本量和算力数字均为反事实工程规格或数量级估计。

## 2. 研究对象与广义安全边界

### 2.1 最强版本的研究对象

一个决策实例是仓库 (r) 在第 (t) 次要求到达时的状态：

\[
I_{r,t}=(W_{r,t},q_{r,t},H_{r,\leq t},T^{vis}_{r,t},B_{r,t}),
\]

其中 (W_{r,t}) 是当前代码、依赖和配置，(q_{r,t}) 是本轮要求，(H_{r,\leq t}) 是此前变更与工具轨迹，(T^{vis}_{r,t}) 是当时可见测试，(B_{r,t}) 是执行与权限边界。coding agent 必须修改自己的先前实现，运行工具并把补丁实际应用到仓库。早期结构选择持续存在，因而可能改变未来要求的实现难度、回归概率和故障扩散范围。

候选若成立，主要风险不能写成“代码不够优雅”。它必须至少产生一种可执行外部后果：此前正确行为丢失，安全校验被削弱，关键服务不可用，故障越过模块或服务边界传播，修复窗口关闭，或高影响修改变得难以回滚。受影响对象可以是后续开发者、依赖该代码的团队、运行服务、业务数据或用户。代码复杂度、耦合、重复和 structural oracle 只能作为中间风险状态，不能替代终局损害。

### 2.2 maintainability 与 broad safety 的分界

| 观察或结果 | 在本候选中的地位 | 是否足以证明广义安全改善 |
|---|---|---|
| cyclomatic complexity、复杂度集中、LOC、clone ratio | 结构代理或中间状态 | 否。数值下降可能伴随当前功能失败，也不等于未来损害减少。 |
| 模块数、依赖数、模块化、结构 oracle | 设计状态或约束合规 | 否。更多模块和更少依赖都可能产生新的接口成本；oracle 还可能编码作者偏好。 |
| 后续 requirement 的隐藏测试失败 | 任务可靠性结果 | 有条件可以。必须排除测试设计泄漏，并报告失败严重度、当前任务成功与成本。 |
| 先前已经通过的安全或功能测试在后续轮次回归 | 跨期可靠性或安全结果 | 可以。还需区分一般边界错误和会造成实际损害的关键行为。 |
| 可达漏洞、权限校验删除、敏感数据路径失守 | 软件安全结果 | 可以，但会直接进入 SCAFFOLD-CEGIS 等安全退化近邻的竞争空间。 |
| 失败传播到多个组件、服务或数据资产 | 广义安全的外部结果 | 可以。必须有真实依赖图、执行证据和严重度，不能用静态 reachability 数量冒充事故。 |
| 后续修改耗时、人工审查负担、计算成本 | 组织结果或成本结果 | 重要，但单独仍是维护效率研究。需要与可靠性或损害结果联合报告。 |

这一分界产生一个硬约束。若实验的主要胜利只是 erosion、maintainability index 或 NITR oracle 更好，题目应回归普通软件维护与代码质量，不能保留“安全”定位。若把主要结果改成 security regression，SCAFFOLD-CEGIS 已经直接研究多轮潜在安全退化和门控控制。若把主要结果改成 earlier-requirement regression，Regression Accumulation 和 SlopCodeBench 已经提供直接测量与 rollback gate。若把主要结果改成 failure onset 和 recovery window，Failure as a Process 已经占据时序失败轨迹。候选在三种改写下都不能自然形成未被占据的大空白。

### 2.3 coding agent 情境真正新增了什么

coding agent 带来四项重要变化。它可以在短时间内连续修改大量文件；它会把自己的早期设计作为下一轮起点；它可以同时调用编辑器、终端、测试和版本控制工具；它可能在无人逐行审批时扩大错误影响。这些变化提高了结构退化的速度、路径依赖和组织风险，也使在线干预具有实践价值。

这些变化没有自动产生新的理论计算对象。人类维护者与 coding agent 的提交都可表示为代码图、diff、要求、测试和时间序列。agent 的身份、模型、scaffold、工具调用和自治程度可以加入状态或环境参数。只要这些信号对理论策略可见，同一信号也必须对公平的通用时序模型可见。新行动者改变了数据分布和问题强度，没有使 Banker and Slaughter 的交互项或 Tiwana and Safadi 的年龄—模块化关系成为通用模型无法表达的运算。

## 3. Banker and Slaughter（2000）对理论空间的挤压

### 3.1 原研究实际提出了什么

Banker and Slaughter 研究软件 enhancement，不研究 coding agent。其结构指标是单位 function point 的函数调用，波动性是单位功能上的 enhancement 频率或被修改功能比例，总数据复杂性由单位功能的数据元素刻画。研究样本来自一家大型零售商的 23 个应用和一家商业银行的 41 个应用；错误结果只在零售商样本中可用。研究情境主要是组织内部的旧式业务应用和 COBOL 维护。

理论的关键不是“结构越多越好”。功能分解可以把数据处理局部化，使维护者只理解需要修改的部分；同时，更多函数调用和接口链也会增加追踪成本。结构因而缓冲高波动和高复杂应用的 enhancement cost 与 errors，但过度结构可能反而有害。论文进一步推导，最优结构水平随波动性和复杂性提高。

对当前候选而言，这已经占据三项基础主张。

1. 结构选择具有成本与错误后果，不能只看静态美观。
2. 结构收益受未来变化频率与系统复杂性调节，不存在全局固定最佳结构。
3. 组织或算法若要决定是否重构，必须比较局部化收益与接口理解成本。

### 3.2 它没有提供什么

原研究没有时序代码图、agent actor、结构侵蚀 latent state、逐步故障传播、在线策略、代码生成器或世界模型。其分析单位是应用层面的横截面设计和一段时期内的维护结果，不是每轮 patch 决策。将其迁移到 coding agent 因而可以提出一个新的应用和处方问题，但不能把结构—波动—复杂性权衡本身称为新机制。

更重要的是，它的理论计算形式很容易被通用模型吸收。设结构、波动和复杂性分别为 (S_t,V_t,C_t)，理论所要求的主要状态只是

\[
z^{BS}_t=[S_t,V_t,C_t,S_tV_t,S_tC_t,S_t^2].
\]

普通 MLP、temporal GNN 或 POMDP 的 value network 在获得 (S_t,V_t,C_t) 后可以精确构造或近似这些交互。即使把“低到中等结构有益、过高结构成本上升”写成 convexity 或 cross-partial loss，相同损失也可以施加给参数相同的通用模型。Banker and Slaughter 能指导变量、冲突情境和行为假设，却不能独占一种计算结构。

## 4. Tiwana and Safadi（2024）对理论空间的决定性挤压

### 4.1 与候选几乎重合的理论链

Tiwana and Safadi 将 system atrophy 定义为系统代码内部逻辑一致性的跨期衰退。其主测量为

\[
A_{t_0\rightarrow t_1}=\Delta(\text{cyclomatic complexity}/\text{LOC}),
\]

模块化变化为

\[
\Delta M_{t_0\rightarrow t_1}=\Delta(\#\text{modules}/\#\text{dependencies among modules}).
\]

研究还把未偿技术债、模块差异化演化和代码陈旧视为可能的上游来源。中间理论关系是，模块化增量降低 atrophy，但这种作用随系统年龄增长而减弱。原文进一步讨论，老化且高度萎缩的系统可能因为未知依赖和脆弱性而不适合继续内部重构，实践上可以冻结原生代码，通过 API、wrapper 或外部前端延续其功能。

论文使用 1,354 个 de novo、持续开发的 Java GitHub 系统，构造约 1.89 亿行代码、1,900 万次 code changes 和约 900 万条依赖的跨期 trace。主模型有 23,407 个 system-quarter observations。后续分析将 atrophy 连到较少的长期演化、更多五年后未解决技术问题、开发者注意流失和较少 fork。无论是否接受每一项测量和因果识别，这篇 ISR 已经明确占据了当前候选希望声称的现象、动态状态、条件化缓冲和下游后果。

### 4.2 候选不能再次声称的贡献

当前候选不能声称首次发现系统结构会跨期退化，不能声称首次把模块化作为抗退化手段，也不能声称首次指出结构干预随系统年龄改变。它也不能把“老系统应当 wrapper 或 freeze”作为 theory-to-action 的原创转换，因为 Tiwana and Safadi 的实践部分已经明确提出相同方向。

coding agent 可以让该理论获得新的 actor 和更短时间尺度，却不自然改变构念关系。若使用 Tiwana and Safadi 的原测量，数个 agent checkpoint 是否等于系统季度和年龄尚需重新验证。若改用 SlopCodeBench 的 erosion，又会发生构念漂移：SlopCodeBench 测量的是高复杂函数占全库 complexity mass 的比例，其中

\[
\operatorname{mass}(f)=CC(f)\sqrt{SLOC(f)},
\]

它与系统级 (\Delta(CC/LOC)) 不是同一指标。把二者都叫“结构侵蚀”不能完成构念验证。

### 4.3 coding-agent 新情境为何仍不能独占计算结构

最强迁移会定义

\[
z^{TS}_t=[U_t,A_t,\Delta M_t,Age_t,\Delta M_t\times Age_t],
\]

其中 (U_t) 包含技术债、差异化演化和陈旧性。该状态可以进入 patch decoder、world model 和 action value。理论还可以要求年轻系统优先模块化，老而高度萎缩的系统优先冻结内核并在外部扩展。

然而，这个 action rule 是 age、atrophy、modularity 和 predicted outcome 的条件函数。等参数 POMDP 只需把相同变量放入 belief state，就能学到同一阈值或平滑边界。temporal GNN 只需对同一代码与变更图进行 message passing，就能输出同一动作概率。若理论模型把 (A_t) 和 (M_t) 作为固定预处理输入，公平的通用模型也必须获得它们；此时把理论模型参数复制给通用模型即可得到完全相同的策略。若通用模型只看原始 token，而理论模型额外获得人工构造状态，任何优势都可能来自额外信息和样本效率，而非不可复制能力。

Tiwana and Safadi 因而是本候选的决定性 NO-GO 证据。它比 Banker and Slaughter 更直接地提供了动态现象和年龄边界，同时仍不能支持一个通用模型无法复制的专用计算结构。

## 5. Subramanyam 等人（2012）的有限补充

Subramanyam 等人分析 92 个企业软件 component。component granularity 由 data elements、data-layer interfaces 和 internal interfaces 等子维度操作化。较粗粒度组件可能降低后续 customization effort，却增加当前 development effort 和 defects，且缺陷部分传递到下游成本。收益阈值依赖具体站点和设计环境。

它对当前候选的有效提醒有三项。结构行动必须同时评价当前缺陷和未来修改；多个结构维度不能压成任意单分数；收益可能反转。它不能自然把 coding agent 的 local patch、extract module、adapter、freeze core 和 rollback 排成一条统一 granularity 轴。一个 wrapper 会增加模块和接口，却可能降低业务核心对实现的依赖；一次 extract-method 会增加 callable，却不一定增加组件独立性。理论迁移在行动构念层就不稳定。

这篇论文也进一步挤压“结构—当前成本—未来灵活性”主张，却没有救回算法唯一性。它所要求的多维 granularity、defect mediator 和 customization outcome，同样可以被通用多任务网络或结构化 world model共同预测。

## 7. 最强反事实算法工件

本节故意把候选设计到超过简单分类器、规则 gate 和辅助分数的程度。若连这一版本都不能通过理论与数据门，较弱版本无需继续讨论。

### 7.1 输入、输出与实际行动

输入是当前 requirement、versioned repository、过去 (L) 轮 diff、测试和工具轨迹、当前代码依赖图，以及仅在 (t) 时点可见的 issue 与文档。模型不得读取后续 requirement、隐藏测试、reference patch 或未来 failure label。

输出不是一个 erosion score。模型直接生成或选择并执行结构化 edit program，动作集合至少包括：

1. 在现有边界内完成局部修改；
2. 抽取模块或重整责任边界后完成当前功能；
3. 引入 adapter、facade 或隔离层，并完成当前功能；
4. 对高度老化、脆弱的 native core 保持冻结，在外围扩展；
5. 回滚到最近 verified state，再从该状态重新实现；
6. 在预注册高影响且证据不足的情境停止并请求人工处置。

主要工件必须包含一个有训练权重的 graph-conditioned edit decoder，使理论状态改变生成的 AST/file edit。若只让现有 LLM 产生候选，再训练一个六分类 router，仍不满足独立算法规模要求。

### 7.2 张量与前向计算

在 checkpoint (t) 构造异质代码图 (G_t=(V_t,E_t))。节点包括 repository、module/package、file、class、function、test 和 requirement。关系包括 contains、calls、imports、inherits、reads/writes、covered-by、changed-with 和 implements-requirement。

主要张量为：

\[
X_t\in\mathbb{R}^{N_t\times d_x},\qquad
E_t\in\{0,1\}^{R\times N_t\times N_t},
\]

\[
D_{t-L:t}\in\mathbb{R}^{L\times N_t\times d_\Delta},\qquad
Q_t\in\mathbb{R}^{J_t\times d_q},
\]

其中 (X_t) 包含代码表示、当前复杂度、ownership、test coverage、criticality 和可逆性；(D) 表示每轮修改范围、依赖变化、测试变化与工具反馈；(Q_t) 表示当前 requirement 和验收约束。

理论分支产生两组显式状态：

\[
z^{BS}_t=[S_t,V_t,C_t,S_tV_t,S_tC_t,S_t^2],
\]

\[
z^{TS}_t=[U_t,A_t,\Delta M_t,Age_t,\Delta M_tAge_t].
\]

为了预测传播，还需输出

\[
P^{fail}_{t,h}\in[0,1]^{N_t},\quad h=1,\ldots,H,
\]

以及 severity-weighted future outcome distribution

\[
\widehat Y_{t,h}(a)=
(p_{task},p_{reg},p_{sec},n_{prop},c_{human},c_{compute},c_{wall}).
\]

temporal heterogeneous graph encoder 先聚合代码和变更历史，theory-state cross-attention 再条件化 edit decoder 和 distributional value head。推断时，模型在当前任务成功约束下生成 edit program，在隔离容器应用补丁并运行可见验证。安全收益不能由永久 stop、永久 rollback 或拒绝所有结构变更取得。

### 7.3 训练样本和真值构造

理想训练单位不是一条历史 commit，而是同一 (I_{r,t}) 下的分支集合：

\[
\mathcal B_{r,t}=\{(a_k,p_k,Y_{k,1:H})\}_{k=1}^{K}.
\]

每个 (p_k) 必须在同一基础模型、tool budget、可见测试和 wall-clock 预算下生成。它先通过当前 requirement 的隐藏测试，再面对对所有分支相同、在 (t) 时隐藏的未来 requirement sequence。后续实现 agent 固定，所有分支使用相同随机种子集合和推断预算。标签包括当前成功、历史回归、未来成功、严重度加权安全失败、传播节点、恢复成本、人工介入和计算成本。

可从 SlopCodeBench、SWE-EVO 和 NITR 的状态构造起点；可以用 human/reference refactoring、不同 coding agents 和受控 edit generator 产生候选分支。历史 GitHub commits 只能提供自然结构变化和后续 issues，不能单独提供 action truth，因为人类选择结构的原因、任务难度、团队能力和后续要求共同混杂。

这个构造面临三个不可消除的弱点。第一，未来需求由 benchmark 作者设计，外部损害和严重度缺少自然基准。第二，标签依赖固定 downstream agent；换一个更强 agent，某个结构分支的未来成本排序可能反转。第三，只有被候选生成器探索到的 patch 才有结果，offline policy 会受到 support mismatch。大规模分支 rollout 能减轻但不能消除这些问题。

### 7.4 损失函数

最强版本可使用：

\[
\mathcal L=
\lambda_e\mathcal L_{edit}+
\lambda_y\mathcal L_{outcome}+
\lambda_r\mathcal L_{rank}+
\lambda_s\mathcal L_{state}+
\lambda_p\mathcal L_{prop}+
\lambda_c\mathcal L_{CQL}+
\lambda_t\mathcal L_{theory}.
\]


- $\mathcal L_{edit}$ 训练真实 edit program 或优胜分支的条件生成。
- $\mathcal L_{outcome}$ 对未来 task、regression、security、propagation 和 cost 分布做 NLL 或 proper scoring。
- $\mathcal L_{rank}$ 在 same-state、same-future 分支内比较综合效用，而非跨仓库比较静态指标。
- $\mathcal L_{state}$ 监督 $A,M,S,V,C,U$ 与其变化，但不把这些代理当终局结果。
- $\mathcal L_{prop}$ 监督故障在 test、module 或 service graph 上的到达和严重度。
- $\mathcal L_{CQL}$ 对未被数据支持的行动保持保守，降低 offline extrapolation。

理论方向项至多可以写成：

\[
\mathcal L_{theory}=
[\partial \widehat A/\partial \Delta M]_+
 +[-\partial^2\widehat A/(\partial\Delta M\partial Age)]_+
 +[\partial^2\widehat Y/(\partial S\partial V)]_+
 +[\partial^2\widehat Y/(\partial S\partial C)]_+,
\]

其中前两项表达模块化降低 atrophy 且这一负向作用随年龄减弱，后两项表达结构更能缓冲高波动和高复杂情境。符号只适用于按“更高 $Y$ 表示更差结果”的定义。实际实现还需对适用区间和当前结构成本单独建模。

这些 shape constraints 不能既作为训练目标，又作为 theory validation 的唯一证据。冻结模型后必须在独立干预数据上检验动作和结果方向。即使检验通过，也只能证明该 inductive bias 有效，不证明它不可由通用模型复制。

## 8. 数据切分、泄漏隔离与可复现性

### 8.1 分割单位

1. repository lineage、fork family 和 upstream history 必须整体进入同一 split。
2. SlopCodeBench 的同一 problem 及全部 checkpoints 不得跨 train/test；语言移植版本也应按 problem family 分组。
3. NITR 同一 case 的 micro、multi-step、intended 和 shortcut variants 不得跨 split。
4. calendar-time cutoff 位于起始 checkpoint 之前。测试实例的 future requirements、tests、issues 和 repair commits 在 feature builder 和 retrieval index 中均不可见。
5. agent/model family、scaffold 和 language 至少各留一类 OOD test，以判断策略是否只识别特定生成器的风格。
6. 同一 foundation model 产生的 candidate patches 可以用于训练，但最终主测试必须包含冻结后生成的新 patch branches。

### 8.2 信息隔离

训练标签可以使用未来结果，前向输入不能。feature manifest 需记录每个节点和字段的来源时间、commit hash 和生成脚本。隐藏测试名称、gold diff symbol、future issue text、后续模块名和由未来失败派生的 criticality 均列入黑名单。retrieval corpus 必须按 event time 构建，不能对今天网页做日期过滤后假装历史快照。

结构指标也可能泄漏。若 atrophy 或 propagation label 由未来完整图计算，当前图只能使用 (t) 时点边。任何利用后续 dependency graph 得到的 centrality、community 或 affected-node count 都属于标签侧信息。

### 8.3 复现 manifest

每次训练和 rollout 至少固定：repository commit、benchmark version、problem manifest、hidden-test digest、container digest、base-model hash、LoRA/checkpoint hash、tokenizer、graph extractor version、static-analysis rules、candidate generator、tool and token budget、seed、hardware、timeout、失败与排除原因。公开 release 还应提供 split lineage map、feature provenance、label builder 和所有 action branches，而不只发布最终模型分数。

## 9. 算力与资源审计

以下是反事实估计，不是已发生消耗。

结构抽取本身可以在 32–64 CPU cores、128–256 GB RAM 的服务器上完成，中型多语言仓库和所有版本快照预计需要 TB 级工作盘。真正昂贵的是 action branching 与 future rollout。以 36 个 SlopCodeBench problems、平均约 5 个可决策转移、每状态 8 个结构分支、每分支 4 个未来 rollout seed 计算，单一 downstream agent 已需约 5,760 条完整 rollout；加入 5 个 agent/model families 后约 28,800 条。这个数量仍只覆盖 36 个问题，统计独立单位不是 28,800，而更接近 problem 和 repository 数。

一个 1–3B 参数的 graph-conditioned edit model 可在 4 张 A100 80GB 或多张 24GB 本地 GPU 上以参数高效训练数日；7B 级 edit decoder 的 QLoRA 预计也需 4 张高显存 GPU 才能保持合理 batch 和图上下文。容器执行、编译和测试主要消耗 CPU、内存和磁盘 I/O。若最强基线包含闭源 agent，trajectory generation 还会产生显著 API 成本，不能称为纯本地训练。

算力并非绝对 NO-GO。更根本的问题是，增加 rollout 数不会增加独立仓库、自然未来要求或理论唯一性。即使投入可承受，所得工件仍主要是在小规模人工未来上学习一个可由通用 POMDP 表示的策略。

## 10. 最强基线、公平比较与机制干预

### 10.1 必须比较的基线

1. 原 coding agent 的 just-solve 策略，不加结构提示或干预。
2. SlopCodeBench 的 quality-aware prompt、plan-first 等公开设置。
3. 静态 complexity、dependency、smell 和 architecture-conformance gates。
4. Regression Accumulation 的 Verification Gate，以及同预算 rollback/retry。
5. SCAFFOLD-CEGIS 的 correctness、security monotonicity、anchor integrity 和 diff-budget 组合，在相符安全任务上比较。
6. RefUntangle 或 RefactorAssist 式的 refactoring-aware repair，在相符 Java 任务上比较。
7. always-local-patch、always-refactor、always-wrapper/freeze 和 always-rollback 四类策略。
8. 参数量相同的 temporal heterogeneous graph transformer，直接预测同一多结果分布并生成同一 edit action。
9. 参数量相同的 generic POMDP/world model，获得相同 (A,M,Age,S,V,C,U) 特征和相同 action mask。
10. 参数量相同、具有相同 auxiliary prediction 和 monotonic losses，但不使用理论命名的结构化模型。
11. hindsight oracle，只作为上界，看到未来 requirements 后选择当前分支，不能作为可部署基线。

### 10.2 公平控制

所有学习方法共享起始 repository、base model、candidate或edit vocabulary、可见测试、retrieval corpus、训练 branches、tool calls、token budget、wall-clock cap 和 future rollout seeds。可训练参数控制在预注册容差内。若理论模型使用固定 atrophy/modularity extractor，通用模型也获得相同派生特征。若理论模型拥有 action feasibility mask，通用模型也必须拥有。否则比较无法回答理论责任。

### 10.3 理论中和与冲突实验

- 删除 $z^{BS}$ 或 $z^{TS}$，用相同维数的可训练 latent 替代。
- 在 repository、age 和 task-difficulty 分层内打乱 atrophy、modularity、volatility 和 complexity。
- 单独打乱 $M\times Age$、$S\times V$ 和 $S\times C$，保留主效应。
- 将 theory shape loss 置零，同时维持总损失尺度和训练步数。
- 让等参数通用模型接收同一理论状态，再比较样本效率、校准、OOD 和行动，不只比较最终 pass rate。
- 构造年轻且高增长系统、老化且高 atrophy 系统、高波动高复杂系统、低波动低复杂系统四类冲突情境。理论预期分别偏向早期模块化、冻结/外围扩展、较高结构投资和避免过度结构。若动作分布不随情境变化，理论没有进入策略。
- 对结构指标下降但 future regression 上升的案例做反向干预，防止模型只优化代理。

删除、打乱或中和理论状态应当改变行为并损害终局结果。然而，即使观察到这一点，也只证明当前模型使用了这些状态。真正关键的比较是，获得同样状态的 generic baseline 是否能复制行为。按下节的构造，它在表示上可以精确复制。

## 11. 等参数通用 temporal GNN/POMDP 反证

设理论模型先用固定、无训练参数的函数 $\phi_T$ 从历史 $h_t$ 计算理论状态 $z_t$，再执行

\[
e_t=E_\psi(h_t),\qquad
\pi_T(a\mid h_t)=\operatorname{softmax}F_\theta(e_t,z_t).
\]

建立一个参数量相同的通用模型

\[
\pi_G(a\mid h_t)=\operatorname{softmax}G_{\tilde\theta}(e_t,z_t).
\]

它使用相同 encoder、相同输入 $z_t$、相同 action space 和相同 decoder shape，但不把 $z_t$ 命名为某个理论。令 $G_{\tilde\theta}=F_\theta$，两者对每个历史和动作给出完全相同的概率。这个复制不需要更多参数。Banker and Slaughter 的乘积项、Tiwana and Safadi 的 age interaction、Subramanyam 的 defect mediator 都没有破坏这一包含关系。

若理论模型把 shape constraints 写进训练目标，通用模型可以使用相同约束而不改变参数量。若理论模型使用 hard action mask，通用模型也可使用相同 mask。把这些能力从通用基线中拿走，只能说明先验约束节省样本，不能说明理论模型能做对方做不到的行动。

若要求通用模型只能接收 raw graph，不给 $z_t$，temporal graph transformer 仍可从节点复杂度、依赖和时间学习近似 $\phi_T$。这时理论模型可能在小样本中更快、更稳定，这是可检验的 inductive-bias 优势，却没有达到当前 Goal 要求的“等参数通用替代不能复制”。尤其是 Tiwana and Safadi 已经公开定义这些 trace measures，固定 extractor 也不是本候选的新算法权重。

POMDP 的结论相同。把 belief state 写为

\[
b_t=P(s_t\mid h_t),\quad s_t=(G_t,z^{BS}_t,z^{TS}_t),
\]

再把 utility 定义为任务成功、未来回归、传播、人工和计算成本的函数，普通 POMDP 已经拥有候选的所有状态、转移、观察和动作。理论给出状态解释和先验方向，未产生 POMDP 无法表示的新信息结构。

这一反证不是“通用神经网络理论上什么都能拟合”的空泛论断。这里有一个相同输入、相同形状、相同参数量和相同权重的逐点复制构造。因此，候选明确未通过用户要求的等参数替代门。

## 12. 训练真值与因果识别的终审

### 12.1 公开 benchmark 不能直接提供什么

SlopCodeBench 有自然的 checkpoint sequence，却每个 agent 在每个状态只实现一个实际 patch。NITR 有 intended 和 shortcut oracle，却没有大量仓库和多年未来结果。SWE-EVO 有真实版本历史，却只观察人类实际选择的演化路径。Multi-SWE-bench 有多 agent patches，却主要评价当前 issue，缺少一致未来 requirement。GitHub history 有大量 commits 和 issues，却同时受到 task difficulty、developer skill、review policy、release cadence 和用户规模混杂。

因此，下式中的行动效应不能从现有单路径数据直接识别：

\[
\tau(a_i,a_j\mid I_t)=
\mathbb E[Y_{t+1:t+H}(a_i)-Y_{t+1:t+H}(a_j)\mid I_t].
\]

若 (a_i) 来自人类参考补丁而 (a_j) 来自弱 agent，未来差异可能来自代码能力而非结构机制。若候选分支使用不同 token 或测试预算，差异也不能归因结构。若 future rollout agent 看见不同的错误信息，标签又混入了恢复能力。

### 12.2 人工分支为何仍不是自然真值

same-state branching 可以建立严格的 benchmark 内反事实，却只能回答“在这组人工未来和这个 downstream agent 下，哪个分支更好”。它可以支持算法评价，不足以证明真实组织中的长期损害。要声称 broad safety，还需 severity schema、关键资产或服务拓扑、失败传播的执行路径和外部后果。公开 benchmark 大多没有这些对象。

将 structural erosion 作为 mediator 也不能自动识别机制。若模型在 blocking (A_t) 表示后性能下降，只能说明网络使用该变量。真正的中介效应需要对结构行动和后续结果的共同混杂作出可辩护控制，并且结构测量不能由未来结果反向定义。当前资源未满足这一条件。

### 12.3 真值门判定

这个候选不是完全无法构造数据。可以投入大量算力创建一个受控 counterfactual benchmark。问题在于，benchmark 创建本身会成为主要贡献，而策略学习仍建立在研究者选择的结构动作和未来需求上。即使数据工程成功，理论唯一性仍失败。因此，不建议以“先造数据再看”延缓撤题。

## 13. 独立 NO-GO 门

| 门 | 通过条件 | 当前证据 | 判定 |
|---|---|---|---|
| 广义安全门 | 终局结果是可执行损害或可靠性，不是结构分数 | 公开主资源主要给结构代理和一般 regression；传播严重度缺失 | 未通过 |
| coding-agent 独特性门 | 自主性产生普通维护研究没有的新决策状态或行动约束 | agent 加快路径依赖并扩大影响，但相同状态可进入通用维护模型 | 未通过 |
| IS 理论新空间门 | 理论机制未被直接近邻占据 | Banker and Slaughter 已占结构条件收益；Tiwana and Safadi 已占动态 atrophy、modularity、age 和下游 bugginess | 未通过 |
| 构念有效性门 | 短期 agent erosion 与 ISR atrophy 的映射经过验证 | 两者测量、时间尺度和单位不同；当前只有术语接近 | 未通过 |
| 可训练真值门 | 有 same-state、多行动、same-future 的可靠标签 | 需昂贵人工分支，且标签依赖候选生成和 downstream agent | 未通过 |
| 算法硬度门 | 产生有训练权重的 edit/world/policy model，不是评分头或 router | steelman 可达到，但公开数据不足，弱版本会退化成 gate/router | 条件性可通过 |
| 等参数替代门 | 公平 generic temporal GNN/POMDP 不能复制理论能力 | 存在相同输入、相同参数和相同权重的逐点复制构造 | 明确未通过 |
| 直接近邻增量门 | 相对 SCBench、NITR、SCAFFOLD、Verification Gate、RefUntangle 仍有足够大新增能力 | 剩余主要是 learned structural action policy；现象、指标和多个干预已被覆盖 | 未通过 |
| 独立论文规模门 | 不是另一论文的 mediator、附加指标或 benchmark appendix | 最合理位置是把 erosion 作为其他可靠行动研究的次要机制或失败分析 | 未通过 |
| 可复现与算力门 | 本地训练和公开评价可承受且有足够独立单位 | 模型训练可承受，分支 rollout 昂贵；独立仓库数仍太小 | 条件性未通过 |

任何一项核心门失败都足以暂停候选。当前有六项核心门同时失败，其中理论新空间和等参数替代是不可通过扩大样本修复的终局问题。

## 14. 最终处置与有限复用边界

1. 不将本候选写成独立论文，不为它撰写摘要、引言或算法章节。
2. 不把 SlopCodeBench erosion 改名为 Tiwana–Safadi system atrophy；二者只能在经过正式构念验证后关联。
3. 不用 Banker and Slaughter 的交互项包装普通 temporal GNN，也不把 age-conditioned action head 声称为理论独占计算。
4. 可以在其他可靠行动研究中把结构变化作为 secondary mediator、cost outcome、OOD stratum 或 failure-case annotation，但不能由它承担主要安全贡献。
5. 可以独立构造一个 coding-agent longitudinal structure benchmark，前提是把它诚实定位为 benchmark 或 measurement work，不声称已经形成 ISR 级理论算法论文。
6. 若未来重新送审，不能只增加更多仓库、换一个 GNN 或加入 propagation head。必须同时出现新的 agent-specific IS mechanism、真实外部损害标签、可执行反事实行动数据，以及公平等参数通用模型无法复制的经验能力。Tiwana and Safadi 的现有理论链仍必须作为首要直接近邻，而不是从综述中省略。

终局理由可以压缩为一句话：**结构侵蚀是真实且重要的 coding-agent 风险，但其 IS 机制已被成熟的结构权衡与 system atrophy 理论覆盖，技术现象又被 2026 年多项 benchmark 和干预工作直接占据；在相同信息和行动空间下，理论模型没有通用 temporal GNN/POMDP 无法复制的计算责任。**
