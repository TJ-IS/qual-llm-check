# Coding-agent 未来审计证据捕获候选终审

## 0. 终审结论

**结论：NO-GO。当前不应把“面向未来未知审计问题的学习型证据捕获与保留策略”冻结为三篇论文中的独立一篇。**

这项判断不是因为审计不重要，也不是因为系统实现工作量不足。相反，coding agent 能修改代码、调用工具、跨越权限边界并委派任务，确实使行动恢复、政策核验和责任追踪成为重要的组织问题。否决原因是候选题目前同时遭遇三个不可通过的约束。

1. “未知未来问题”若指不受限制的未来政策或审计查询，那么任何低于完整记录的捕获策略都存在不可识别反例。某个被省略字段或责任边总能成为后来政策作出相反判定所必需的信息。学习不能恢复从未记录且未被可逆承诺的事实。
2. 若把未来问题收窄为已知政策族或可学习的查询分布，任务就成为政策条件下的日志放置、事件选择、图约简、保留期优化或预算化序贯决策。Log20、policy reduction、BEEP、LogApprox、FAuST、whole-system provenance reduction、完整记录与重放以及 Aegis 已覆盖这一算法空间的主要结构。coding-agent action/state/effect/permission/delegation graph 主要改变工作负载和 schema，并未形成不可由通用方法复制的新计算机制。
3. 能自然联系的 AIS 文献可以解释记录粒度、重建价值、链式证据和可追踪性，却没有给出足以唯一决定学习状态、损失函数和捕获动作的理论映射。对照肖帅勇老师 ACAA 和 DSDL 的 MEC→MAP→ALG 责任标准，候选题在 MAP 到 ALG 处断裂。等参数 temporal graph Transformer、submodular selector、constrained RL 或 POMDP 可以执行同一优化。

此外，候选题还面临 C3 的二难边界。若证据在批准点前被主动获取并影响开发者审批，它与 C3 的可信后果取证和 grounding policy 重叠。若证据只服务事后审计，五维 auditability 指标仍是中间结果，不能自动证明原始危险行动减少、损害得到控制或组织责任分配得到改善。

本候选可以保留为三篇论文共享的**可信记录基础设施、评价层或附录性工件**，不能以当前主张独立投稿。只有满足第 13 节的重新开启条件，才值得作为一个新题重新审查。

## 1. 被审候选的精确定义

本终审把候选限定为如下问题，避免把容易成立但贡献较弱的外围工作误当作研究核心。

- 决策时点发生在 coding agent 执行期间，而非事后摘要阶段。
- 环境持续产生 agent action、tool call、pre/post state、external effect、permission、approval、delegation、retry、rollback 和 responsibility relation 等候选证据。
- 在存储、运行时、计算和隐私暴露预算下，策略决定捕获什么、采用何种表示粒度以及保留多久。
- 捕获动作可以是丢弃、仅保存元数据、保存摘要或 digest、脱敏负载、状态差分、完整快照，或者补充记录依赖边和责任边。
- 未来 auditor 使用已保留记录恢复政策相关行动、判定 comply/violate/undecidable，并重建技术因果链和组织责任链。
- 主要贡献不能是日志 schema、hash chain、UI、查询系统、LLM 事后总结、固定黑名单或手工保留规则。

候选最强的新颖性主张只能是：**在未来具体审计问题尚未出现时，coding-agent 特有的结构化执行状态能够支持一个学习型策略，以低于完整记录的成本，仍为后来政策核验和责任重建保留足够证据。** 后续终审均针对这一最强版本，而不是针对较容易实现的固定政策日志系统。

## 3. 与 Auditable Agents 五维的逐项对齐

候选的合理评价不能只用“后来回答对了多少问题”。五维分别约束不同失败模式。

| 维度 | 原文代表指标 | 本候选必须保留的对象 | 选择性捕获的固有风险 |
|---|---|---|---|
| Action Recoverability | ACR、RF | 政策相关 tool/file/network/deployment/approval/delegation action 及参数、对象和结果 | 记录了事件名但遗漏 argument、target、scope 或 output，会出现覆盖高而不可恢复 |
| Lifecycle Coverage | LPC、GB | plan、retry、fallback、approval、handoff、rollback、failure path 和 phase boundary | 只保存成功主路径，会把规避审批的 retry 与正常执行混为一谈 |
| Policy Checkability | SPDR、ADL | 每项政策的 required fields 与跨步关系 | 任一必需字段在所有相关步骤均缺失，判定只能为 ⊥，增加其他无关日志不能补救 |
| Responsibility Attribution | AC、ACD | user→agent→subagent→skill→tool→service 的链或联合责任子图 | 保存直接执行者但丢失委派、动态 skill selection 或批准关系，会把执行因果误当作完整责任 |
| Evidence Integrity | IS、VC | append-only、hash-chained 或 signed record 及验证成本 | integrity 不能由 selector 的预测概率替代；完整性、真实性和保留选择是三个不同问题 |

五维是联合必要条件，不是可以用加权平均互相抵消的五个 reward。尤其是 integrity 应作为可信记录层的硬约束，不应被学习成“某条日志值得签名的概率”。同样，保留 digest 可以证明后来出示的内容未变，却不能让 auditor 从 digest 重建从未保存的参数、状态或责任边。

## 4. 决定性否决：未知未来政策下的不可识别性

### 4.1 最小反例

设一次执行的完整可观察记录为 $T$，候选字段与关系全集为 $F$。捕获策略 $c$ 在预算 $B$ 下产生记录 $R=c(T,B)$。只要预算迫使策略对某些可能执行使用有损表示，就存在字段或边 $f\in F$ 未被可逆保存。

取两个完整执行 $T_0,T_1$，使它们在所有已保存内容上相同，只在 $f$ 上不同。由于未来政策类没有限制，可以构造结构政策 $\pi_f$，令 $f$ 的两个值分别对应 comply 和 violate。例如，两个记录均显示 agent 执行了部署命令，唯一未保存字段是目标账户；未来政策规定只有 production service account 的部署需要双人批准。也可以让唯一未保存项是一次 subagent handoff，从而改变完整责任链。

对 auditor 而言，$R(T_0)=R(T_1)$。任何只使用 $R$ 的判定器都必须对两者给出相同输出，因此至少一个执行被错判。若两者等概率，强制输出二值 verdict 的最高准确率不超过 $1/2$；若允许输出 ⊥，则它避免了假判，却直接降低 SPDR。Auditable Agents 的 required-field 命题正好给出这个后果：政策要求的一个字段在相关步骤均不可恢复，政策就不可判定。

责任归属同样成立。若捕获策略省略某条 delegation、approval 或 dynamic-skill-selection 边，则可以构造两个观察记录相同、责任链不同的完整执行。技术因果恢复和规范责任归属都无法由下游模型补出。

### 4.2 不能规避该反例的常见说法

- **“模型可以预测未来审计价值。”** 预测只对训练分布中的查询价值有效，不能保证未限定政策类。
- **“保存 hash 即可。”** hash 证明某个已知 payload 的一致性，不揭示未保存 payload；除非 payload 可在可信外部存储中取回，此时它实际仍被保留。
- **“图神经网络能推断缺失边。”** 推断得到的是最可能边，不是可作为合规或责任裁决依据的事实证据。
- **“异常事件才需要完整记录。”** LogApprox 已展示这是一个明确 threat model 下的可行点，但未知未来组织政策可能关心当时看来正常的事件。
- **“未来 auditor 可以回到仓库重跑。”** 外部服务响应、临时 credential、并发状态、已删除文件、审批人认知和动态依赖版本常不可重现。只有预先建立完整记录/重放条件时才成立。

### 4.3 无法同时维持的两个主张

候选必须二选一。

1. 保留“任意未知未来政策”主张。此时有效保证趋向完整、可信、可重放的捕获，以及无损压缩、分层存储和资源调度。学习可以优化系统资源，但不能以相关性预测为依据有损删除证据。
2. 指定有限政策族 $\Pi$、查询分布 $p(q\mid o,t)$ 或威胁模型。此时经验学习可识别，但问题变成 policy-conditioned set cover、knapsack、log placement、graph reduction 或 constrained RL，必须在直接近邻上证明 coding-agent 特有机制和 AIS 理论专属计算。

当前候选在第一种表述上不可满足，在第二种表述上贡献不独立。这是本次 NO-GO 的首要依据。

## 5. 直接近邻拥挤与新增能力审计

| 直接近邻 | 它已经决定的动作 | 目标或保证 | 候选剩余差异 | 终审判断 |
|---|---|---|---|---|
| Log20 | 在哪些程序位置插入日志 | 路径区分信息量与指定运行开销 | 对象变为执行期异构事件和责任边 | 从静态 placement 变成在线 selector，不足以单独形成新机制 |
| LogAdvisor | 哪个异常或返回值检查片段应记录 | 模仿已有 logging practice | 标签改为审计价值 | 学习“何时记录”的一般形式已有，必须有新的可识别监督和结果 |
| BEEP | 记录哪些 unit boundary 和 workflow dependency | 最小攻击因果图、避免 dependence explosion | agent unit 和 delegation relation 更语义化 | agent schema 是工程专门化，不能声称首次保存责任链 |
| Policy reduction | 采集 MAC policy 确定的 TCB 子域 | minimal completeness 与存储下降 | 政策在训练后出现 | 未知政策不可保证；政策已知时被该近邻直接覆盖 |
| CPR/DPR/LogApprox | 删除、折叠或近似哪些 provenance event | lossless、causality-preserving 或 attack-preserving validity | 加入 agent action/effect/permission | 必须在 held-out policy 上超过成熟 reduction，而非只换图类型 |
| FAuST | 流式应用若干 provenance reduction module | 安全与吞吐折中 | 学习模块顺序和保留粒度 | 很容易退化成 generic online graph reduction |
| Aegis | 调整任务 queue 和 CPU 资源 | 在压力下避免 provenance event loss，同时控制利用率和公平性 | 候选直接丢弃“低价值”记录 | 对真正未知问题，Aegis 的 complete-capture 路线更有安全正当性 |
| full execution record/replay | 完整保存执行并在后来选择性重放分析 | 将未来分析与原始执行解耦 | 候选节省更多存储或隐私暴露 | 除非给出限定查询分布，否则有损策略不能取代该 oracle |
| Auditable Agents | 规定五维存在与质量指标 | defensible audit 的必要条件 | 学习满足这些维度的最小记录 | 是评价框架，不提供候选独有的理论算法；反而提高了完整性门槛 |

From Agent Traces to Trust 已把 agent 特有 execution unit 列为 reasoning、retrieval、tool invocation、parameter、manifest、permission scope、memory operation、action 和 inter-agent message，并把 support、depend、contradict、invalidate、trigger、update 等列为 provenance relation。因而下列内容本身不能承担论文新颖性：把系统日志升级为异构图、加入 permission/delegation 节点、把 tool output 同时视为 execution 和 evidence、按 runtime/post-hoc 区分时点，或把 audit/recovery 作为 trust function。

coding agent 的确使问题更重要：自然语言计划与真实 side effect 之间存在语义鸿沟，repository state 快速变化，工具调用可组合，subagent/skill 委派使责任链加深，测试通过也不能证明部署、权限或数据后果安全。然而这些特征目前只决定**需要记录的对象和压力测试分布**，没有决定一个非通用的选择算法。若同一 temporal heterograph selector 在网络服务、RPA、browser agent 和 coding agent 上只需更换 node type 与数据，即说明核心仍是通用 provenance selection。

## 6. AIS 理论的 MEC→MAP→ALG 责任审计

这里沿用肖帅勇老师两篇 ISR 论文体现的责任标准：先明确文献揭示的因果或认知机制 MEC，再把机制映射为不可替代的计算状态 MAP，最后说明它如何改变前向计算、损失和动作 ALG。仅把理论术语写成节点名不计入理论算法贡献。

| 候选理论或设计知识 | MEC：原文能承担的机制 | MAP：若迁移到本题必须形成的状态 | ALG：是否能由理论唯一约束 | 终审 |
|---|---|---|---|---|
| Bajcsy et al. 2010 的 documentation–reconstruction 框架 | 未来问题与 observable variable 共同决定信息粒度；重建价值随组织、时间和评价指标变化；粒度与存储/计算成本存在非线性权衡 | $p(q\mid organization,time)$、query-required-field relation、reconstruction-value functional、cost vector | 原文明确讨论这些因素，却没有识别价值数值、概率分布或最优动作；任何预算 selector 都可接收相同输入 | **强问题动机、强直接前身，弱算法所有权** |
| Shao et al. 2005 的 transactional-cycle chain-of-evidence | 业务活动非原子；孤立事件缺少上下文；证据应沿 value transfer、primitive event、document purpose 与 initiator/claimant 构成链 | transaction phase、value/commitment transfer、initiator、claimant、evidence-purpose relation | 在信用卡 SSL 案例中 ontology 清楚；映射到 coding task 的“价值转移”和“claimant”需要研究者手工定义，且不能排序未知未来政策所需字段 | **可形成 mandatory-chain 设计约束，不能支撑学习选择的新理论** |
| Mohan et al. 2006 的 traceability-augmented GDN | 分布在参与者和文档中的知识片段需要语义 link 才能整合并支持决策回放 | actor/problem/argument/proposition 及 justification/trace link | typed graph 和 replay 是直接设计启发，但 W3C PROV 与 agent provenance 已提供更一般结构 | **适合解释 trace relation，不拥有 selector** |
| Vance et al. 2015 的 accountability theory | identifiability、被评价预期、监控意识和 social presence 改变人的 perceived accountability，继而改变违规意向 | 人类知觉和行为意向的实验操纵 | 机器是否保存 snapshot 不等于行为人在行动时是否感知被识别、评价或监控；没有对应的 selector 状态 | **分析层级不匹配，应排除** |
| Auditable Agents 五维 | 五项系统属性共同使事后 accountability 成为可能 | ACR/RF、LPC/GB、SPDR/ADL、AC/ACD、IS/VC | 可产生硬约束和指标，但不是 AIS 行为或组织理论，也不能决定在预算冲突时保存哪条证据 | **评价责任，不是独立理论算法责任** |

### 6.1 一个必须能回答的冲突情境

假设同一时刻只能保存以下三者之一：包含敏感内容的完整 post-state snapshot、一次高成本依赖解析得到的版本闭包、或者 user→agent→subagent→skill 的完整委派边。Bajcsy et al. 只说明重建价值与成本应被同时评估，不能在未知未来问题下排序三者。Shao et al. 会偏向完整 transaction context，却不能判断 snapshot 与 dependency closure 哪个属于后来政策的必要证据。通用模型若获得同一历史 query 分布和成本标签，会作出同样选择。

因此候选不存在类似 ACAA 中由理论改变 compatibility、attention 和 fusion granularity 的计算，也不存在类似 DSDL 中 expectation、experience、disconfirmation direction 和 satisfaction 进入张量及稀疏约束的链条。当前可写出的 loss 仍是重建、政策判定、责任边预测与成本罚项的加权和。这些目标来自任务定义，不来自 AIS 理论不可替代的机制。

### 6.2 等参数反证

若未来试验仍要尝试该方向，理论模型必须与以下替代模型使用相同节点、边、标签、预算、参数量和训练步数比较。

- raw temporal heterograph Transformer；
- graph POMDP 或 constrained actor–critic；
- submodular coverage 加 knapsack projection；
- 直接预测 future query utility 的多任务模型；
- 不含 transaction-cycle type、只含可学习 edge embedding 的等参数模型。

只要通用替代模型在 held-out policy family 上达到相同 auditability—成本前沿，并在机制干预中作出相同选择，就必须撤销独立理论算法贡献，不能把节点标签解释成理论胜利。

## 7. 与 C3 的边界与二难

本项目 C3 已冻结的核心是：外部 gate 已确定必须审批的行动，trusted mediator 已绑定 canonical action 与 pre-state，模型在批准点选择下一项可执行后果探针、证据子集和 grounding repair，以降低真人 unsafe approval。候选证据捕获与它存在如下边界。

| 情境 | 本候选的动作 | 与 C3 的关系 | 结果责任 |
|---|---|---|---|
| 执行前或批准点主动运行 test、dry-run、snapshot、taint 或 rollback probe | 获取缺失证据并影响当次审批 | 与 C3 的 evidence acquisition action 实质重叠 | 应并入 C3，不能另立论文 |
| 执行期间被动选择哪些既有 event/field/edge 写入长期存储 | 为以后未知审计保留记录 | 可与 C3 严格区分 | 不改变当次危险行动，只改善事后可见性 |
| 捕获不足时立即 ask、block、降权权限或停止 agent | 根据记录充分性改变当前行动 | 从 audit capture 扩张为 runtime gate，重新进入批准、权限或风险控制题 | 必须与其他论文重新划界 |
| 事后 auditor 使用记录触发 containment、rollback 或治理修订 | 记录间接影响后续损害 | 可形成独立结果，但需真实审计和处置实验 | 不能只以 ACR/SPDR/AC 代替组织安全结果 |

严格避免 C3 重叠之后，候选能直接声称的只是“以后更容易知道发生了什么”。这很重要，却还不是用户要求的 broad-safety 外部结果。若没有 downstream audit/remediation 环节，论文只能报告记录质量与成本，容易成为 observability 或 audit infrastructure 论文，而不是 coding-agent 可靠行动系列中的独立安全研究。

## 8. 真实外部结果门槛

五维 auditability 指标应作为机制和过程指标。独立论文至少还需要随机化捕获策略，并观察一项真实下游结果。

- auditor 对 comply/violate/⊥ 的正确率、校准和裁决时间；
- 从 agent 行动到确认根因、确认责任链、隔离影响或完成可信 rollback 的时间；
- 处置后的 residual harm、误隔离或错误回滚造成的 collateral damage；
- 相同错误或权限越界在后续任务中的 recurrence；
- 人类调查工时、跨团队争议解决时间及责任分配一致性；
- 因过度记录秘密、个人数据或源代码造成的 privacy exposure；
- 正常任务成功率、吞吐、延迟、存储和计算成本。

“未来问题回答率提高”“责任边 F1 提高”或“日志缩小 80%”均不足以单独证明广义安全。尤其不能通过让 agent 少执行、让 auditor 总判违规，或把所有不确定案例交给人工来取得表面改善。安全、任务能力、人工负担、隐私和资源成本必须共同报告 Pareto frontier。

责任真值还必须分层。可信系统记录可以给出技术因果和委派事实，但“谁应承担组织责任”取决于预先存在的权限规则、职责分配、审批义务、可预见性和裁决程序。把 causal predecessor 直接标成 responsible actor 会把规范结论偷渡进数据；让研究团队一边编写政策一边生成责任标签又会造成循环 benchmark。

## 9. 公开数据、政策与责任真值审计

目前可公开运行的资源只能覆盖局部责任，未发现一个现成数据集同时含有 coding-agent 全量可信执行、外部效果、权限与委派、未来政策 required fields、规范责任真值及不同捕获动作的反事实结果。

| 资源 | 可提供 | 关键缺口 |
|---|---|---|
| DARPA Transparent Computing Engagement 5/CDM | 主机级 provenance、隔离环境 attack ground truth、统一 schema | 不是 coding-agent 任务；没有自然语言委派、agent permission/approval、组织政策或规范责任真值 |
| SWE-agent/OpenHands 等公开 trajectory | thought/action/observation、tool call、patch 和部分测试结果，可重放部分任务 | 轨迹由被审 agent 自身或框架产生，不是独立全知记录；缺少完整 OS effect、秘密/权限代理、审批和责任标签 |
| Open-SWE-Traces 等大规模轨迹集 | 大量 agent interaction，可预训练 action encoder | 规模不能弥补 oracle 缺失；不是 capture-policy counterfactual 数据 |
| Auditable Agents/Aegis 相关 artifact | 小规模 agent topology、结构政策或 provenance runtime 压测 | Auditable Agents 明示没有 end-to-end audit、只处理结构政策且隐私/最小化仍开放；Aegis 没有未来政策和责任裁决 |
| Sysdig/eAudit 与 Aegis 工作负载 | event loss、buffer、runtime、调度行为 | 没有 coding-agent 高层语义和 auditor query truth |

因此必须自建。若只在完整轨迹上离线随机 mask event，得到的是“给定已经发生的完整执行，某种记录能否回答查询”的反事实；它不能识别捕获开销是否改变了调度、agent 行为、race、tool output 或任务结果。涉及这些干扰时，必须在线随机执行捕获策略或使用完整系统 record/replay，并保存 assignment propensity。

## 10. 最强可行自建规格：用于验证否决，不代表候选已获通过

以下规格给出如果研究团队仍要做 pilot，最低限度如何产生可识别数据。它的目的在于设置可证伪门槛，而不是用复杂工程掩盖理论和新颖性问题。

### 10.1 隔离执行与全量 oracle

在无真实生产凭证的容器或虚拟机中运行 OpenHands、SWE-agent 或等价 coding agent。任务使用公开仓库，并注入经授权的风险情境，例如越范围改文件、修改测试以掩盖失败、写入秘密后外传到本地 sink、未批准安装依赖、错误 deployment target、破坏性 shell action、越级 delegation 和失败 rollback。

由独立 trusted recorder 同时捕获四层事实。

1. orchestration 层保存 user instruction、agent/subagent identity、model/tool/skill version、delegation、approval、retry 和 fallback。
2. trusted tool proxy 保存 canonical arguments、permission token、scope、return value、network destination、credential class 和 action hash。
3. OS/eBPF 层保存 process、file、socket、IPC、exec、read/write/delete 等 effect，并与高层 action 对齐。
4. state 层保存 repository tree、关键文件/数据库/服务的 pre/post snapshot、delta、test oracle、deployment target 和 rollback outcome。

完整 oracle graph 的节点至少包括 user、agent、subagent、skill、tool、process、file、repository object、dependency、credential、approval、policy、state、effect、test 和 deployment。边至少区分 issued、delegated、invoked、read、wrote、deleted、spawned、fetched、produced、approved、denied、retried、rolled-back、derived 和 affected。oracle 数据进入隔离、加密、append-only 且签名的存储，不能由被审 agent 改写。

### 10.2 政策与责任真值

政策应由独立团队在看到测试执行之前预注册，并显式列出 required field 和判定程序。首批结构政策可以覆盖：破坏性行动需批准、secret-read 后禁止未净化网络发送、delegation 不得超 scope、不得修改用于验收的 test/control、依赖安装需来源与版本闭包、production deployment 需双人批准、rollback 后必须恢复不变量。

“未知政策”测试不能只把同一模板换变量名。至少要做三类隔离。

- policy instance holdout：同结构的新对象或阈值；
- policy family holdout：训练未见的跨步关系和 required-field 组合；
- post-hoc authored policy：测试轨迹冻结后，由未参与训练设计的审计人员依据完整 oracle 编写政策，再锁定判定程序。

责任标签分两层保存。技术层以 oracle 记录真实 cause/delegation/approval subgraph。规范层依据预注册职责规则，由至少两名独立领域人员和一个分歧裁决程序给出 responsible/answerable actor set、理由与不确定性。若无法取得独立规范裁决，只能声称 causal attribution，不能声称组织责任恢复。

### 10.3 反事实捕获数据

对每条完整 trace $T$，把可捕获单元展开为 event-field-snapshot-edge 候选集。离线阶段可采样多个 mask/representation/TTL 轨迹，计算在同一完整 oracle 下的 action reconstruction、policy verdict、responsibility subgraph 和 privacy exposure。对序贯策略记录每步 action probability，以支持 inverse-propensity 或 doubly robust 估计。

但离线 mask 只在“捕获行为不影响执行”假设下有效。凡是 snapshot、instrumentation、full payload 或动态压缩会改变 runtime、buffer、race 或 agent observation，均需在线随机化若干安全捕获策略，或者依靠完整 record/replay 在相同执行上重放分析。该假设和偏差诊断必须预注册。

### 10.4 模型输入、张量和输出

时点 $t$ 的输入可以规范为：

- temporal heterogeneous graph node matrix $H_t\in\mathbb{R}^{N_t\times d_h}$；
- typed edge index $E_t\in\mathbb{N}^{2\times M_t}$、edge type 和时间差；
- 当前可捕获单元 $U_t\in\mathbb{R}^{K_t\times d_u}$，包含 source、field type、sensitivity、estimated size、latency、replayability 和依赖；
- 预算向量 $b_t=[b_{storage},b_{cpu},b_{latency},b_{privacy}]$；
- 已保留记录的 coverage state、append-only store 状态和 mandatory-field mask；
- 若输入 query/policy prior，则另有 $Q\in\mathbb{R}^{J\times d_q}$。必须承认此时任务已变为 policy-distribution conditioned，而非真正未知查询。

每个候选单元的输出动作是

\[
a_i\in\{drop,metadata,digest,redacted\ payload,delta\ snapshot,full\ payload\},
\]

并输出 retention tier/TTL、是否同步保存依赖或责任边以及存储位置。策略不得输出 allow、deny 或 approval recommendation，否则越出本候选边界。

可实现模型为 temporal heterogeneous Graph Transformer，加 budget-conditioned decoder 和可微 knapsack/projection；序贯版本使用 constrained actor–critic。多任务 auditor heads 只在训练期估计 action/effect reconstruction、policy verdict 和 responsibility edge。这个架构是**通用基线级实现**，不能仅因使用 agent graph 而声称理论创新。

### 10.5 监督信号和损失

- `L_action`：action field、target、argument、pre/post effect 的重建或对比损失；
- `L_policy`：对 comply、violate、⊥ 的交叉熵与 calibration loss，并对 policy-family worst group 使用 distributionally robust objective；
- `L_resp`：技术责任 subgraph 的 edge/node BCE、ranking 或 structured loss；
- `L_recovery`：在实验性 downstream workflow 中对 containment、rollback 和 root-cause decision 的效用损失；
- `C_storage`、`C_cpu`、`C_latency`、`C_privacy`：实测资源和敏感内容暴露成本；
- mandatory required fields、append-only 与签名 integrity 作为硬约束，不得只放入可被收益抵消的软罚项。

一个可审计的总目标可以写为

\[
L=\alpha L_{action}+\beta L_{policy}+\gamma L_{resp}+\eta L_{recovery}
+\lambda_s C_{storage}+\lambda_c C_{cpu}+\lambda_l C_{latency}+\lambda_p C_{privacy},
\]

但这个加权形式来自任务工程，并非上述 AIS 理论独有。所有权重须在 validation policy family 上冻结，并报告多组预算下的 Pareto curve，不能事后挑选单点。

### 10.6 推断时真实动作

推断策略监听 trusted event bus，在字段产生且消失之前选择表示粒度，把内容连同 action hash、source、timestamp、policy version、integrity metadata 和依赖边写入签名的 append-only store，并设置 retention tier。若 mandatory-field 状态不确定，安全 fallback 应是进入完整保护层或延期删除，而非相信模型低风险判断。策略不修改 agent 权限和任务行动。

### 10.7 划分、隐藏测试和泄漏控制

不得对同一 trace 的 event 随机切分。训练、验证和测试至少同时按以下单元隔离：repository、time、agent framework/model family、risk family、policy family、tool/skill、single/multi-agent topology。post-hoc authored policies 在模型、阈值和预算冻结后才能揭示。gold policy verdict、完整 responsibility graph、hidden effect oracle 和完整 snapshot 不得进入推断输入。

每次运行保存 repository commit、container digest、agent/model/tool version、policy manifest、oracle schema、capture-policy checkpoint、配置、随机种子、assignment propensity、完整 trace hash、mask manifest 和裁决版本。跨 split 的代码克隆、相同 issue、相同 injected-risk template 及派生 patch 必须用内容和语义去重检查。

### 10.8 本地算力和工件

以下只是 pilot 规划区间，不是已实测数字。约 1,000 条多层全量执行可能需要约 0.5–2 TB 原始与快照存储、128–256 GB 主存用于离线图构建，以及 1–2 张 24–48 GB GPU 训练 temporal graph model。扩到约 10,000 条执行可能需要 4–8 TB 分层存储和 2–4 张同级 GPU。实际数字必须先以 50–100 条任务测量 event rate、snapshot delta、压缩率和 replay cost 后重估。

独立训练工件至少包括 trajectory encoder、capture-policy checkpoint、auditor heads、policy/required-field registry、sealed oracle graph、counterfactual mask/propensity dataset、container images、配置与 seed manifest。仅交付日志收集器和规则文件不满足算法硬度。

## 11. 公平基线、理论中和与评价

### 11.1 必须比较的基线

- 完整可信 logging 与 full execution record/replay，作为可审计上界；
- lossless compression、分层冷存储和 Aegis 风格 complete-capture resource scheduling；
- 随机、按事件类型分层、固定 mandatory schema 和风险规则；
- Log20 风格 information-theoretic placement；
- BEEP unit/workflow dependency logging；
- MAC policy reduction；
- CPR、F-DPR、S-DPR、LogApprox 和 FAuST 风格图约简；
- greedy set cover、submodular selection、knapsack 和 reservoir sampling；
- 等参数 temporal GNN/Transformer、POMDP、constrained RL 和 direct future-utility predictor；
- oracle policy-required-field selector，以及在同预算下的 oracle query-aware selector。

full logging 可以作为非预算上界单独报告；其压缩、分层存储和 Aegis 版本还应进入相同 CPU、I/O 或总拥有成本的 Pareto 比较。各学习模型使用相同训练 trace、policy labels、参数量区间、决策次数和 hyperparameter budget。

### 11.2 理论中和

- 打乱 transaction-cycle phase、initiator/claimant 和 evidence-purpose 标签；
- 保留 graph adjacency，打乱 typed responsibility/delegation edge；
- 移除 organization/time/reconstruction-value 状态或在 batch 内置换；
- 把所有 trace relation 展平为可学习 edge embedding；
- 删除 mandatory chain constraint，改用相同参数量 raw model；
- 固定总预算，交换 snapshot、dependency closure 和 delegation chain 的理论优先级；
- 允许 raw-feature bypass，检验理论 bottleneck 是否真正改变 capture action。

Vance et al. 的人类 accountability theory 不应强行设置“中和实验”。除非另行操纵 actor 在行动时的 identifiability、evaluation expectation、monitoring awareness 和 social presence，并测量其违规行为，否则该理论没有进入本 selector 的合法位置。

### 11.3 指标

必须完整报告 Auditable Agents 五维指标 ACR/RF、LPC/GB、SPDR/ADL、AC/ACD、IS/VC，同时报告 policy verdict accuracy/coverage/calibration、action/effect reconstruction、responsibility subgraph precision/recall、held-out policy-family worst-group performance。资源侧报告 bytes、CPU、I/O、wall time、buffer loss、privacy-sensitive bytes/fields、retention cost 和 integrity verification cost。

独立论文还需第 8 节的真实 downstream outcome。统计分析应同时给出效应量、置信区间和多预算 Pareto frontier；按 repository、policy family、risk type 和 topology 分层。若只有离线 query-answer 指标，就只能作为 benchmark 或系统基础设施评价。

## 12. 终止门

下列任一条件发生即维持 NO-GO 或停止 pilot，不得通过扩大模型和篇幅继续包装。

1. 仍宣称对不受限制的未知未来政策保持有损记录充分性。
2. 没有独立、全量、可信的 action/state/effect/permission/delegation oracle，或标签主要来自被审 agent 自述。
3. held-out policy 只是训练模板改名，required-field schema 没有真正分布外变化。
4. 规范责任标签由同一研究团队依据自己编写的政策自动生成，且没有独立裁决。
5. 离线 mask 被用于估计会改变执行行为或运行时的 capture action，却没有在线随机化、propensity 或 replay 识别。
6. 等参数 raw temporal graph model、knapsack、POMDP 或 constrained RL 的置信区间覆盖理论模型，或理论中和不改变冲突情境下的动作。
7. 最优策略退化为固定 mandatory schema、只保留异常事件、完整记录加压缩或 Aegis 式资源调度。这些可以成为好系统，却不是本候选声称的新理论算法。
8. 主要结果只有压缩率、ACR、SPDR、AC 或责任边 F1，没有真人审计、恢复、损害控制、复发或调查成本结果。
9. 为取得安全结果，模型开始在批准点主动运行后果探针、组织证据和修复 reviewer grounding。此时应并入 C3。
10. 为减少事后不可审计，模型开始 ask、block、deny 或调整权限。此时研究对象已经变为 runtime risk control，需重新立题和划界。
11. privacy budget 只是一个人工惩罚系数，没有敏感字段 oracle、暴露测量和删除/保留合规验证。
12. integrity 依赖学习分数而非可信 append-only、hash-chain 或 signature 机制。
13. 捕获策略改善了 audit metric，却没有改善任何组织或广义安全结果，或其收益完全由更多存储、更多时间和更多人工介入解释。

## 13. 重新开启条件与有限保留方式

要把本候选重新提交为独立论文，至少需同时出现以下证据。

1. 把“未知”改为有组织依据、可外生验证且不会与研究者标签循环的政策生成过程，并明确可保证的 policy class。
2. 获得独立可信 full-trace、policy-required-field 和两层责任真值；post-hoc policy family 对训练团队真正隐藏。
3. 找到一个 AIS 机制，它不仅说明重建有价值，而且产生不可由 generic graph learner 复制的状态、结构约束和冲突选择；MEC→MAP→ALG 三层均有原文责任。
4. 在相同数据、参数和预算下，理论模型超过 Log20/BEEP/policy reduction/LogApprox/FAuST/Aegis/full replay 与等参数通用模型，并通过理论打乱和中和。
5. 随机化研究证明捕获策略改善真实审计裁决、containment/recovery、责任争议或复发结果，同时控制任务成功、隐私、人工和计算成本。
6. 研究动作严格停留在执行期记录与保留，不侵入 C3 的批准点可信取证和 grounding policy。

在这些条件出现之前，最合理的保留方式是把完整、可信、签名的 agent action/state/effect/permission/delegation recorder 建成三篇论文的共享实验基础设施；用五维指标检查其他算法是否留下可审计记录；把 storage/privacy trade-off 作为实践讨论和系统附录。这样可以保留审计价值，同时不把一个不可识别且直接近邻拥挤的问题强行包装为独立论文。

## 14. 肖帅勇老师研究设计责任对照

本节只审查论证功能，不复制两篇 ISR 的句子。

| 审查层 | ACAA/DSDL 所体现的责任 | 本候选当前状态 | 判定 |
|---|---|---|---|
| 问题情境 | 外部现象逐步收窄到现有算法系统性处理错误的机制 | agent auditability 和资源—证据冲突真实，直接文献充分 | 通过 |
| MEC | 理论文献明确指出被通用模型忽略的相容、期望—体验—不确认等机制 | documentation value 和 chain-of-evidence 解释为什么要保存粒度与上下文 | 部分通过 |
| MAP | 理论构念被映射为有方向、有粒度、有关系责任的中间状态 | query distribution、reconstruction value 和 coding transaction cycle 均需研究者自行补定 | 不通过 |
| ALG | 理论状态改变 attention/fusion、损失、约束及最终动作 | graph encoder、budget decoder、RL 和多任务 loss 均是通用实现；理论不决定关键捕获冲突 | 不通过 |
| 引文责任 | 相邻论断由具体原文机制支持，方法主张不冒充文献事实 | 五维、粒度—成本、证据链和近邻均可由原文支持；“未知查询仍充分”无文献也不可成立 | 不通过最强主张 |
| 机制反证 | 删除、打乱或中和理论机制应产生可观察行为变化 | 预计 raw graph learner 可以复制；尚无不可替代干预 | 不通过 |
| 外部结果 | 结果对应研究现象而非仅模型内部指标 | 当前只有 auditability 与成本，真实组织处置结果尚未建立 | 不通过 |

综合来看，候选的问题重要性可以达到引言门槛，系统工件也可能很“硬”；真正缺失的是可识别的新能力、理论拥有的计算机制和非 C3 的外部安全结果。按照同一严格标准，不能因为该方向新、工程复杂或与 accountability 术语接近而保留。
