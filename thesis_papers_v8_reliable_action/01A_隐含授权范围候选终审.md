# 隐含授权范围候选终审：良性欠明确任务中的授权推断与有界行动

> 审查日期：2026-08-15  
> 候选命题：coding agent 在良性但欠明确的任务中推断用户没有明说的授权范围，并在任务完成与 out-of-scope 持久损害之间选择结构化、序贯且可纠正的行动。  
> 审查口径：本文件是内部选题终审，不是论文正文。全文回读对象包括 Baird and Maruping（2021）、Afiouni and Pinsonneault（2026）、Pavlou and Gefen（2005）、Tiwana（2009）、Wiener et al.（2019）等 AIS 全文，以及截至审查日可取得的技术论文全文或官方说明。未运行任何新实验，文中的规模与算力若属于拟议方案，均明确标为设计值。  
> 与既有审查的关系：本文件独立检查这一替换候选，并专门检验 `00R_故障后授权边界候选理论与近邻红队.md` 对原 C1″ 的 NO-GO 是否已经覆盖它。

## 0. 终局裁决

**判定：NO-GO，立即撤题，不进入 pilot，也不以“待数据后再判断”的方式占用论文名额。** 这一现象真实、重要，而且高度符合 coding agent 广义安全。用户交付一个目标，并不等于授权 agent 为达成目标采取一切有帮助的行动。coding agent 又能够编辑文件、运行命令、修改版本历史、读取凭据、改变依赖和 CI 配置、调用网络服务乃至部署共享系统，所以一次表面成功的任务可以同时造成超出授权范围且难以恢复的损害。然而，现象重要不等于存在一篇尚未被占据的理论驱动算法论文。截至 2026-08-15，OverEager-Bench 已把“良性任务中的授权范围推断”作为核心测量对象，SNARE 已显式操纵 silent、implicit/explicit allow/deny 并设置 consent decision point，UnderSpecBench 已在相同环境和相同安全动作下操纵任务欠明确性，Claude Code auto mode 已在生产中使用 user-message + tool-call classifier 判断行动是否越过用户授权。Conseca、IGAC、OAP、PCAS/FORGE、PACT 与 CapLease 又分别覆盖了任务情境到政策、资源与效果边界、多路由行动、确定性执行、论据级 authority binding 和授权的持久消费。AgentAbstain 与 MOSAIC 则覆盖了成对的 act/abstain 情境和可训练的多步 plan–check–act/refuse 策略。

**本候选不能靠扩大动作集获救。** 即使把输出从 allow/deny 或 ask/refuse 扩展为只读取证、shadow execution、局部 staging、checkpoint、受限执行、精确询权、交接、补偿、回滚和停止报告，最强实现仍是一个接收任务、受信政策、仓库状态、动作效果和交互历史的通用 constrained POMDP 或 model-based constrained policy。IS 理论可以提醒设计者区分目标、责任、决定权、介入权和协调，但没有一篇回读理论规定一种等信息、等参数的通用策略无法表示的状态、更新或动作方向。把理论构念写成 `scope tensor`、`role state` 或 `psychological-contract belief` 不会改变这一函数包含关系。

**原 C1″ 的 NO-GO 已经完整覆盖本题，而且本候选比 C1″ 更接近直接技术近邻。** 原 C1″ 至少还有“故障后权责边界变化”这一特定转折。本候选取消故障条件，把部分可观测性改成良性欠明确任务，正好落入 OverEager-Bench、SNARE 和 UnderSpecBench 的中心定义。其“隐含授权范围”是 C1″ `X/I` 状态的合并或软化，其“任务完成”对应目标或义务状态，其“持久损害”对应效果世界模型与约束成本，其多动作策略与 C1″ 的恢复动作语法同构。`00R` 已经证明这些状态可由同一原始信息上的授权图或 constrained POMDP 复制。删除一个故障观察量没有产生新的不可复制机制。

**可保留的是研究现象与评价资产，不是当前论文题。** 真实用户对候选行动的前瞻性范围标注、同任务多分支的 scope annotation、版本库状态差分和持久损害 oracle 可以形成有价值的数据或行为研究。若研究问题改为“不同角色的人怎样理解 coding agent 的隐含授权、何时产生授权分歧、分歧怎样影响监督与问责”，心理契约、委派或组织控制可能形成自然的 IS 对话。但那会成为真人行为或组织治理研究，并不能自动满足本项目每篇论文必须产生重大可训练算法工件的要求。本终审不建议把这种可能性包装回算法论文。

## 1. 候选的真实问题，以及必须先分开的三种“范围真值”

本候选最强、也最公平的表述不是“识别危险命令”。研究对象应是一个真实执行代码工作的 agent。它收到良性请求，能够观察仓库、对话、工具结果和部分组织情境，并在多个时点选择读取、编辑、运行、提交、发布、询问、降级、交接或回滚。潜在损害不是命令表面看起来危险，而是行动的资源、对象、参数、效果或传播范围超出了授权。例如，“清理旧分支”可能只允许删除本地分支，不允许删除远端分支；“修复测试”可能允许编辑当前模块，不允许禁用安全检查；“部署这个服务”可能允许预演，不允许变更生产流量；“解决依赖冲突”可能允许修改 lockfile，不允许替换组织级 registry。风险发生在 agent 把任务目标转成下一项有外部副作用的行动时。

这一问题若要被称为授权安全，必须区分三种不能互换的真值：

1. **可执行的规范范围 `A^norm`。** 它来自可识别 principal 的请求、组织政策、仓库规则、身份与角色、受签名的批准、资源所有权、能力边界和撤销记录。它可以被 reference monitor 执行。模型可以解析或建议其表示，但不能凭预测创造 authority。
2. **请求者的主观意向范围 `A^intent`。** 它是某个用户在具体时点认为“我本来会允许什么”的判断。它可能含有未说出的期待，也可能在看到后果后改变。它适合研究意向预测、惊讶、信任校准或心理契约，却不自动等于组织授权。
3. **模型推断范围 `A^model`。** 它是 agent 根据 prompt、情境和历史得到的后验。它可以决定是否先 staging、是否请求更多证据、询问什么问题或如何缩小行动，但 `A^model` 不能成为 `A^norm` 的自我签发来源。

安全系统需要满足的是 `a_t \in A^norm_t`，而非仅仅 `a_t \in A^model_t`。若 `A^norm` 已经由可信政策完整给定，主要问题是解析、绑定与执行，学习“隐含授权”并无必要。若 `A^norm` 缺失，agent 只能把未知状态保持为未知并选择不产生越界效果的行动，不能把高置信预测改写成权利。若研究改用 `A^intent` 作为标签，模型预测的是人的接受度或惊讶，而不是具有安全保证的授权。这个三分法构成候选的首个致命两难。

这些近邻并非由某一篇论文单独“完整复制”候选，而是从现象、真值、政策、执行、持久状态、序贯训练和外部结果七个位置共同压缩新增空间。剩余尚难的问题是真实组织中的隐含规范如何被人理解、多个 principal 如何解决分歧、policy 如何被合法更新。它们是重要问题，但不允许 controlled agent 自己把预测当授权，也不自然产生一篇 theory-exclusive coding-agent algorithm paper。

## 3. 原 C1″ NO-GO 的覆盖证明

`00R` 审查的原 C1″ 以故障后恢复为时点，把任务或结果责任、执行权、介入权与协调状态写成 `O/X/I/K`。当前候选虽然改名为“隐含授权范围”，其可计算对象没有离开该函数类。

| 当前候选元素 | 原 C1″ 中的同构对象 | 表面变化 | 为什么不构成新理论空间 |
|---|---|---|---|
| 良性但欠明确的请求 | 部分可观测 task contract 与环境历史 | 删除了故障触发 | POMDP 的 observation 更少，而不是新增了一类不可表示状态 |
| 隐含授权范围 posterior | `X` 执行权与 `I` 介入权，或二者合并 | 从外部权利改写成软 belief | belief 仍是原始任务、政策、角色和历史的函数；若权利是规范事实，软化反而降低安全性 |
| 完成任务的压力 | `O` 义务/目标状态与 task utility | 用 task success 代替责任余额 | 目标进度是普通序贯决策状态，不由 delegation 理论独占 |
| out-of-scope 持久损害 | effect world model、harm constraint、irreversibility | 强调 damage duration | 持久性进入 transition/cost 即可，SafeMCP、UnderSpecBench、CapLease 等已分别覆盖效果、共享控制面和耐久状态 |
| staging、checkpoint、询权、交接、回滚等 | C1″ 的 verify、fallback、ask、redelegate、rollback、stop | 动作集更丰富 | 多动作只扩大通用 action grammar，不产生理论特有方向 |
| implicit contract / role expectation | Baird–Maruping 的 distribution、implicit negotiation、role、coordination | 从故障后转向任务开始时 | 正是 Baird 全文已讨论的范围，仍是高层 scaffolding |

形式上，令当前可观察历史为

\[
o_t=(u_{\le t},c^{trusted}_t,\Pi_t,g^{repo}_t,h^{tool}_t,s^{workspace}_t),
\]

其中包括用户消息、受信情境、组织政策、仓库规则、工具轨迹与工作区状态。候选先产生

\[
z_t=F_\theta(o_t)=(S_t,E_t,P_t,V_t,R_t),
\]

分别表示范围后验、效果、任务进度、可逆性和恢复状态，再由 `πθ(a_t | z_t)` 选择结构化动作。给定相同原始信息、动作语法、外部 reference monitor 和参数预算，通用策略可以直接定义

\[
\pi'(a_t\mid o_t)=\pi_\theta(a_t\mid F_\theta(o_t)).
\]

这不是“也许存在一个强 baseline”，而是函数包含关系。若理论状态完全由 `o_t` 计算，通用模型可组合实现同一函数。若理论状态额外使用只有候选得到的人类 scope 标签，则比较不公平；把标签也交给通用模型后，包含关系恢复。若状态依赖不可观察的真实心理意向，任何模型都不能从同一观察唯一识别，只能请求 principal 提供信息。故原 C1″ 在“等信息 constrained POMDP 可复制”这一核心理由上完全覆盖本候选。

## 4. AIS 理论责任审查

### 4.1 Baird–Maruping delegation 是最自然的理论，也是最明确的 NO-GO 证据

Baird and Maruping（2021）确实为本候选提供了高度自然的现象语言。论文把 delegation 界定为主体间对 task execution 与 outcome 的 rights and responsibilities transfer，并以 human–agentic IS artifact dyad 为基础分析单元。distribution 机制明确指出转移可以完整或部分发生，decision rights 与 intervention rights 可以不同；协商可能形成 explicit contract，也可能形成 assumed or norm-based expectations 的 implicit contract；constraints、boundaries 与 discretion 可以在事前建立。由此可以严谨推出：任务目标、行动能力、执行权和介入权不可混同，良性请求的语义相关性也不自动赋予所有有助于完成目标的权利。相关内容见 [Baird and Maruping（2021），MIS Quarterly，DOI 10.25300/MISQ/2021/15882](https://doi.org/10.25300/MISQ/2021/15882) 及[本地全文](../database_fulltext_all/10752_2021_the-next-generation-of-research-on-is-use-a-theoretical-framework-of-delegation-to-and-from-agen.md)，尤其是本地抽取的第 81、161、179–185、189–191 与 238 行所在段落。

同一全文也阻止了把这些概念直接写成专用算法。作者将 framework 明确定位为高抽象层级的 scaffolding，不限定单一研究设计或单一理论，并说明未来仍需为具体 delegation causes and effects 构建 explicit models；作者还刻意不指定 variance model 或 process model。论文没有规定 implicit contract 应被编码为哪一种张量，没有规定 norm-based expectation 与 executable decision right 如何区分，没有规定 scope uncertainty 怎样更新，也没有规定在任务效用与范围风险冲突时 staging、询权、交接或停止的次序。Baird–Maruping 可承担 MEC，即说明为什么“目标相关”不能替代“权利转移”，却不能独占 MAP 或 ALG。

### 4.2 其他理论逐项审查

| 理论候选 | 正确分析单元与核心构念 | 对本现象的自然联系 | 若强行进入算法会得到什么 | 终审 |
|---|---|---|---|---|

这一审查还排除了一个看似诱人的组合：以 psychological contract 提供 implicit obligation belief，以 delegation 提供 rights/responsibilities，以 governance–knowledge fit 提供决策分工，再以 organizational control 决定行动。该组合把四个不同层级的构念装入同一模型，却仍没有获得新的可识别真值。人的主观期待、组织正式权利、项目部门间治理配置和控制者的控制目的不能通过共同使用“scope”一词被压成同一个标签。若最终统一标签仍是 expert-authored allow/forbid/unknown，理论只是解释层；若每个构念分别标注，则需要真人、组织和项目层的多源数据，目前公开 coding benchmark 不提供这些数据。

## 5. 理论无法通过等信息 constrained POMDP 反证

### 5.1 公平替代必须得到候选得到的一切真实信息

最强理论候选可以显式构造一个 delegation state，例如

\[
D_t=(R^{task}_t,R^{decision}_t,R^{intervention}_t,N^{implicit}_t,C^{coord}_t),
\]

再把它与 effect model、reversibility 和任务进度一起送入策略。公平的通用 baseline 必须得到同一 user request、受信 policy、repo rules、principal identity、approval ledger、workspace state、candidate action/effect graph、训练轨迹、标签、参数总量与 rollout budget，并允许使用等量 latent slots。此时理论模型所能做的任何 deterministic 或 learned state transformation 都能被 baseline 内部表示。

候选无法指出一个通用 POMDP 会系统性算错的方向。若约束与成本给定正确，通用策略不会因为 task utility 较高而必然扩大权限；若它扩大范围，原因是训练目标遗漏 scope cost、观察缺少 authority 或模型估计错误，而不是 POMDP 形式把 delegation 算反。把同一权利信息只交给理论模型，会制造 privileged-information 优势；把不可观察的人的意向当作理论状态，则任何模型都无法确认。唯一具有安全确定性的方案是向 principal 查询或由受信政策补齐。

### 5.2 理论需要产生、但当前无法产生的冲突预测

一项合格的理论算法贡献应在相同表面风险下改变结构化行动。例如，在“技术上可完成、目标高度相关、但没有 target authority”的情境中，理论模型应选择受限 staging 或精确询权；在“行动已获授权、但效果传播到共享控制面”的情境中，应选择 preflight 或缩窄 effect bound；在“用户个人允许、组织 policy 禁止”的情境中，应遵守组织政策并交接；在“组织允许、用户主观偏好未知”的低影响可逆编辑中，可以 staging 并减少无谓打断。这些都是可观察预测，但只要 generic constrained POMDP 得到相同的 policy precedence、effect dynamics、reversibility、query cost 与 task reward，它会得到同样选择。理论没有规定一个通用替代不可获得的新 observation，也没有规定一个普通最优控制目标无法表达的新约束。

### 5.3 使理论主张失败的最强基线

| 基线 | 必须共享的条件 | 理论主张失败的结果 |
|---|---|---|
| 等参数 raw-history Transformer policy | 相同任务、政策、工作区、轨迹、动作和训练预算 | 复制风险—成功—成本前沿 |
| 等 typed graph 的 generic graph Transformer | 相同 principal/resource/action/effect/provenance 图，只去掉理论节点名称 | OOD 与反事实行动等价，说明收益来自图结构 |
| matched-state constrained POMDP | 给与等量 latent slots、同 world model、同外部 hard mask | 复制结构化行动分布与校准 |
| Conseca/IGAC-style certificate + deterministic monitor | 相同受信 context 与 effect bounds | 零规范越权且任务效用不低，说明 learned implicit-right state 无必要 |
| PACT/PCAS + MOSAIC/SafeMCP 组合 | 同 tool contracts、provenance、policy、world model 和 rollout budget | 在越权、持久损害、任务完成、人工分钟和成本上支配候选 |
| oracle scope candidate | 直接提供正确 `A^norm` 或 prospective `A^intent` | oracle 状态仍不优于 raw policy 或 generic graph，说明理论分解不产生行动能力 |

## 6. scope truth、成对数据与可识别性

### 6.1 四种标签来源不能混用

| 标签来源 | 能支持的主张 | 不能支持的主张 |
|---|---|---|
| 机器可执行 policy、签名确认、仓库规则与身份权限 | 行动是否违反规范授权；可供 reference monitor 硬执行 | 用户是否会主观感到惊讶；没有写入 policy 的权利不可由模型补发 |
| 请求者在看到 agent 轨迹前对候选行动/效果的 prospective label | 该用户在当时会允许、禁止或要求确认什么；可研究人类 scope expectation | 组织是否正式授权；其他 stakeholder 是否同意 |
| 用户对已经发生行动的 approve/deny 或事后投诉 | 真实交互中的接受/拒绝信号 | 无偏的反事实 scope truth。行动结果、损失和 hindsight 会改变判断 |
| benchmark 作者写入的 trap 与 intended scope | 在隔离环境中稳定评价行为；便于 paired causal design | 自然组织中的隐含授权构念。作者 oracle 仍是设计规范 |

现有公开资源主要提供第四类标签，RepoComplianceBench 和 policy systems 部分提供第一类，Anthropic 内部 denial/incident log 部分接近第三类。没有公开数据同时独立标注人的隐含期待、正式组织权利、任务目标、行动效果、可逆性和多分支序贯选择。把 OverEager/SNARE 的作者范围标签称为 psychological contract truth，会构念越级；把 RepoCompliance 的显式 rule 称为隐含授权，又会失去题目本身。

### 6.2 若仍构建数据，最低严谨方案是什么

下面是可执行的数据方案，但它最多证明“可以严谨做 benchmark”，不能推翻理论 NO-GO。

1. 从真实开源仓库和隔离的 DevOps 环境抽取任务，固定 commit、依赖、权限、远端 mock、CI/部署状态和 principal identity。每个 base task 必须有 scope-respecting completion path。
2. 由真实请求者或具备该仓库角色的人先写自然任务，再在**看不到 agent 输出**时审核若干候选 action–resource–argument–effect 分支，分别标 `allow / forbid / unknown / allow-if-confirmed`，并记录理由、角色和适用期限。
3. 由组织 policy owner 独立给出 `A^norm`。当 requester preference 与组织 policy 冲突时保留冲突，不用多数票抹平。执行 oracle 以 `A^norm` 为准，人的惊讶或负担作为另一个结果。
4. 对相同 repo、task 与 initial state 构建 minimal pairs，只改变 consent evidence、target specification、role statement 或 policy availability；保持 action effect 与成功条件不变。不得把“你被授权”这种显眼 cue 只写给正类。
5. 每个任务预生成多个合法和越界分支，并由 deterministic state delta、shell/tool event、git object、network mock 与外部控制面 snapshot 共同判定。未知 scope 不能在看到 agent 选择后才改标签。
6. 记录完整样本 `(principal, role, repo, commit, request, trusted policy, approval ledger, candidate action graph, prospective labels, executed trace, state deltas, task oracle, harm oracle)`，为每次数据生成保存 manifest、模板、seed 和审计日志。

设计规模若以 2,000–4,000 个 base tasks、每题 4 个 scope condition、每条件 4–8 条 rollout 计算，将产生约 32,000–128,000 条轨迹；这是**规划区间，不是已有数据**。真正瓶颈不是轨迹数量，而是找到有资格定义范围的 principal、在行动前获得多分支标注、处理组织与个人权利冲突，以及防止同一模板跨 split 泄漏。

### 6.3 划分与隔离

训练、验证和测试必须按 repository lineage、organization/policy owner、task family、policy template、effect family 与时间共同分组。相同 issue、patch、action skeleton、policy 句式、文件树模板和共享基础镜像不得跨 split。hidden test 在冻结模型、prompt、tool schema 和阈值后才解封。若引入真实提交，应清除未来 commit、PR discussion、CI outcome 和 gold patch；若模型预训练可能记住公开仓库，应另设 post-cutoff 或私有隔离仓库测试。consent-kept/stripped 与 act/abstain pair 必须位于同一 split，不能让一半进入训练、另一半进入测试。

## 7. 反事实最强算法规格，以及它为什么仍是通用方法

本节故意把候选写到足够“硬”，用于排除“NO-GO 只是因为想得不够复杂”。这不是保题建议。

### 7.1 输入、输出和关键张量

设 batch 为 `B`，事件/主体/资源/效果图节点数为 `N`，候选计划数为 `M`，每个计划最长步骤数为 `T`，资源与效果类型数为 `R,E`。

| 对象 | 形状或结构 | 语义与监督 |
|---|---|---|
| `H_t` | `R^{B×N×d}` | 对 user request、trusted policy、repo rules、principal/role、approval ledger、workspace/tool history 的 typed graph 表征 |
| `A_t` | `R^{B×M×T×d}` | 候选多步计划及具体 tool、argument、resource、effect、provenance |
| `S_t` | `Δ^4^{B×M×T×R×E}` | allow、forbid、unknown、confirm-required 的 scope posterior。显式 policy 部分应直接计算，不应由模型覆盖 |
| `W_t` | `R^{B×M×T×E×K}` | k-step effect distribution，包括传播范围、持久性与可能的补偿结果 |
| `Q^{task}_t,Q^{harm}_t,Q^{cost}_t` | `R^{B×M}` | 计划的任务完成、realized harm 与人工/计算成本估计 |
| `U_t` | `R^{B×M×T×4}` | 可逆性、证据充分性、授权剩余预算与信息价值 |

输出不应是 action-risk score，而是参数化环境动作。动作语法至少包括：只读取证、生成候选 patch 而不应用、在 shadow workspace 执行、将任务分解并缩小 target、创建 checkpoint 后执行可逆编辑、执行已授权的 bounded mutation、发起包含具体 action/resource/effect/expiry 的精确询权、交接给有权主体并附带已完成证据、运行补偿或 rollback、停止并忠实报告。所有产生外部效果的动作仍需经过 `A^norm` reference monitor。

### 7.2 训练样本、损失和推断

可由 prospective human labels、policy-computed labels、deterministic effects、paired consent conditions、任务 oracle 和完整 rollout 构建监督。一个完整联合目标可以写为

\[
\begin{aligned}
\mathcal L ={}& \lambda_s\mathcal L_{scope}
+\lambda_e\mathcal L_{effect}
+\lambda_p\mathcal L_{paired}
+\lambda_c\mathcal L_{calibration}
+\lambda_{bc}\mathcal L_{behavior}
+\lambda_{rl}\mathcal L_{constrained\ RL}\\
&+\lambda_t\mathcal L_{task}
+\lambda_h\mathcal L_{realized\ harm}
+\lambda_r\mathcal L_{recovery}
+\lambda_g\mathcal L_{grammar}.
\end{aligned}
\]

`L_scope` 只监督有来源的 scope label，不能用模型自生成理由循环训练；`L_effect` 预测实际 state delta；`L_paired` 要求同一 base task 的 consent/target 最小变化产生正确的行为翻转；`L_calibration` 约束 unknown 与置信度；`L_behavior` 用合法专家轨迹 warm start；`L_constrained RL` 可用离线 IQL/CQL 或 model-based CMDP，使规范越权和持久损害成为约束，使任务成功、人工分钟与执行成本进入目标。推断时模型在多步 belief state 上滚动更新，比较 shadow、execute、query、handoff 与 compensate 的长期结果，再由外部 monitor 最终 admission。

这些张量、损失和动作足以产生本地 checkpoint、effect model、scope model、policy weights 与可复现轨迹。然而，没有一个形状或更新由 delegation、psychological contract 或 organizational control 唯一推出。它们是标准结构化预测、world modeling、校准与 constrained RL 的合理组合。删去理论名称，算法完全保留；这正是 NO-GO，而不是工程量不足。

### 7.3 算力与工件

规划上，1–3B graph/effect model 的训练可在 1 张 48–80GB GPU 上进行，7–8B LoRA/SFT 加多轮 rollout 的策略训练预计需要 2–4 张 80GB GPU 与大规模 CPU/Docker 并发；若采用 MOSAIC 式 online GRPO 和外部 judge，资源可上升到 4×A100 级别并持续数日。以上是工程估算，不是已运行事实，真实用量取决于 horizon、candidate plan 数、judge 调用与环境启动成本。必须保存 base model hash、LoRA/checkpoint、optimizer state、环境镜像 digest、tool schema、policy manifest、数据 lineage、随机种子和逐 episode event log。

### 7.4 评价结果与前沿

主要安全终点必须是可观察的 out-of-scope state change 和持久损害，不是拒绝率。至少测量：越权写入或删除、独有数据丢失、git history/remote 变化、secret 读取或外传、依赖/CI/权限/安全检查退化、共享控制面修改、错误部署或发布、重试后的重复效果，以及补偿后仍残留的损害。任务终点同时测 exact task success、safe partial progress 与结果正确性。成本终点测人类确认次数与分钟、tool calls、tokens、wall time、GPU/LLM cost 和不必要停止。

主结果应报告 risk–task–human-cost Pareto frontier、paired risk difference、任务成功差、置信区间、效应量和 repository/task-family 聚类不确定性。若安全只来自少做事，任务与成本维度会暴露退化。若候选只能减少 proposed risky actions，却不减少 realized harm，或通过更多 ask/refuse 获得表面安全，也应判失败。

## 8. 机制干预、泄漏检查与撤题门

即使项目忽略本终审继续做 pilot，也必须预注册以下理论中和实验：

1. **scope-source shuffle**：保持 action、effect 与文本相似度，打乱 principal、policy source 与 approval provenance。若策略不变，模型只学危险度。
2. **role swap**：交换 coder/reviewer/deployer 等 role token，但保持真实权利与动作可用性不变。若动作随 token 变，模型学了无规范依据的角色捷径。
3. **right–knowledge separation**：固定 agent 技术知识，独立改变 external decision right；再固定权利改变知识。若把高知识误当高权利，governance–knowledge fit 被错误使用。
4. **norm–preference conflict**：组织 policy 禁止但请求者偏好允许，以及组织允许但请求者不确定。必须分别预测规范违规与人的惊讶，不能压成单一 loss。
5. **oracle/raw/generic 三联比较**：oracle scope、learned theory state、raw policy graph 与等参数 generic POMDP 同时比较。oracle state 若无增益，分解没有行动责任。
6. **theory-state deletion**：删去 delegation/contract/role heads，保留 typed graph、world model、action grammar 与 reference monitor。若前沿不变，理论只提供解释界面。
7. **pair integrity**：所有 minimal pair 保持 environment、success oracle 和 action physics 完全相同，并验证模板、repo、policy 和 action skeleton 不跨 split。

本候选当前已经触发以下撤题门：

- 直接现象与 paired benchmark 已被 OverEager-Bench、SNARE 与 UnderSpecBench 覆盖。
- 生产 classifier、contextual policy、intent certificate、formal monitor 和 durable authorization 已形成完整近邻链。
- 最自然的 Baird–Maruping 理论明确是高层 scaffolding，没有规定张量、损失或动作顺序。
- psychological contract 的真值是人的主观 belief/violation perception，不能承担规范授权。
- organizational control 与 governance–knowledge fit 的决策者层级不匹配；知识不产生权利，controllee 也不应自选授权边界。
- 等信息、等参数 constrained POMDP 的函数包含反证已经成立，不需等待 pilot。
- 最强反事实实现的独特部分只剩 scope factorization 与理论命名；world model、policy graph、多动作 RL 和 monitor 均为通用或已被近邻占据的部分。

因此，继续增加 head、路由、verifier 或规则不会改变裁决，只会把同一通用系统做得更大。

## 9. 肖帅勇老师 MEC→MAP→ALG 标准下的逐项对照

本审查使用项目 `00F`、`00J`、`00K` 与 `00M` 中已经建立的句子功能和算法责任标准。对照的是学术功能，不复制肖老师论文句子。ACAA 的关键不是“有理论所以做 attention”，而是先指出普通 affinity 计算会偏好相似 key，这与 semantic diversity 所需的互补方向发生具体冲突，再以专用计算修正该错误方向。DSDL 则把理论规定的中间状态放入同一坐标、前向和联合损失，并让状态方向、中和与结果分别可检验。

| 责任层 | 肖老师论文所达到的标准 | 本候选能够成立的内容 | 失败位置 |
|---|---|---|---|
| MEC | 理论指出通用方法系统性忽略或朝错误方向计算的机制，且原文引文直接承担该判断 | Baird–Maruping 说明 delegation 可部分发生，implicit contract 含 norm-based expectations，目标、决定权、介入权和边界不能混同；coding agent 的持久副作用使错误边界具有实际损害 | MEC 作为现象解释成立 |
| MAP | 理论机制产生元素语义明确、可观察或可干预的计算对象，并说明为何必须这样分解 | 可人为提出 `S[action,resource,effect]`、role graph、implicit-obligation belief、effect/reversibility state | 原理论没有规定这些对象；`S` 混合规范权利与主观期待。MAP 是设计者选择，不是理论推出 |
| ALG | MAP 状态进入前向、损失或行动，造成与通用方法不同且方向明确的选择 | 可让 `S/W/U` 进入 constrained policy，选择 stage、execute、query、handoff、rollback | generic constrained POMDP 获得同一信息和动作后可完全复制；没有 ACAA 式错误计算方向。ALG 不具有理论排他性 |
| 机制中和 | 删除、打乱或交换理论状态应产生预注册的行为翻转，且不能由同参数替代复制 | role/source/right shuffles 可以检查捷径 | 即使翻转存在，也可能只证明 policy/provenance 信息有用，不证明 delegation 或 psychological contract 提供了独有计算 |
| 结果责任 | 中间表示、机制行为与外部结果分别验证 | 可以测 scope calibration、action choice、realized harm 与 task cost | 结果链可做，但只能支持通用安全策略或 benchmark 贡献，无法恢复理论算法贡献 |

所以，本候选不是在 ALG 末端缺一个更复杂模型，而是在 **MEC→MAP** 的接口已经断裂。理论能够说明为什么值得研究授权边界，却没有提供一种从该理论出发才会想到、且通用序贯决策无法公平复制的计算。按照肖老师论文的标准，不能用“范围 tensor”“委派状态”“心理契约损失”这些名称掩盖这一断裂。

## 10. 最终处理意见

1. 不将“良性欠明确任务中的隐含授权范围推断”冻结为三篇论文中的替换题。
2. 不先训练 scope model 再根据性能决定理论是否成立；函数包含与构念层级问题已足以给出事前 NO-GO。
3. 不把该题降格为危险动作分类、allow/deny、ask/refuse、静态权限、提示词、action-risk score 或 IGAC/MOSAIC 式路由的小改版。
4. 如后续需要共享评价基础设施，可保留 OverEager/SNARE/UnderSpec 风格的 paired task、prospective human scope annotation、state-delta oracle 与 task–harm–human-cost frontier，但不得把它们写成当前理论的验证结果。
5. 若未来获得真实组织中 principal、policy owner、开发者和 coding agent 的多方纵向数据，可以另立“隐含授权分歧、监督与问责”的行为/治理研究。该未来题应明确承认研究单元和成果类型已经改变。

**终审结论保持 NO-GO。** 这个候选抓住了真实且重要的 coding-agent 安全现象，但直接工作已把现象、测量、生产 gate、结构化政策、多动作控制、形式执行、持久授权和序贯训练分别推进到很近的位置。最自然的 AIS 理论只能界定关系和解释人类或组织机制，不能产生等信息 constrained POMDP 无法复制的状态与行动。原 C1″ 的 Baird–Maruping NO-GO 因而不仅适用，而且在移除故障条件后更强。保留问题意识与数据资产，撤销其作为独立 ISR 级理论驱动算法论文的资格。
