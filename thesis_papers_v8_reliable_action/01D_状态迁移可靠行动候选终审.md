# 状态迁移可靠行动候选终审

> 审查对象：coding agent 在在线数据库 schema/data migration 中生成并实际执行 expand、shadow、dual-write、backfill、validation、cutover、contract、compensation 或 rollback 等多阶段行动。  
> 检索与核验截止：2026-08-15。  
> 终局状态：**CONDITIONAL PILOT / 尚不得进入 thesis FORMAL-FREEZE**。  
> 理论主候选：Michel Benaroch 的 proactive uncertainty-reducing mitigation real options。  
> 本文件是内部选题终审，不是论文正文；尚未运行任何实验，全文不报告性能结果。

## 1. 一句话结论与判定理由

这个问题具有真实而且可执行测量的安全后果，但只有一个收窄后的版本仍值得做验证性 pilot：**给定已经由外部确定的关系型数据库迁移目标，coding agent 在隔离且持续承载旧、新应用负载的在线迁移环境中，学习何时取得信息、何时降低损害发生概率、何时保留恢复能力，以及何时提交 cutover，从而控制数据损失、版本间不一致、服务中断和不可恢复状态，同时保持目标迁移成功、延迟与资源成本。** “任意数据库、配置和部署状态迁移”跨度过大，不能冻结为同一篇论文；配置只能作为应用版本和流量控制的伴随状态，不能扩展为一般 Kubernetes remediation。

本题没有被现有工作完全覆盖。F1、BullFrog、Tesseract、gh-ost、pgroll 与 pg-schema-diff 已经提供安全协议、shadow copy、节流、延迟 cutover、可逆迁移或低锁方案；Dynamite、Mediator 与数据库重构程序综合已经覆盖映射生成及等价验证；Kayenta、CAS 与 ARBITER 已经覆盖 canary 判断和受约束的部署补救；Cordon、RAC、DART 与 SagaLLM 已经覆盖 agent transaction、compensation 和 semantic recovery。因而，expand-contract、shadow、canary、rollback 或一个 typed state machine 都不能再作为新增能力。本题尚存的技术空间仅是：**以真实迁移状态和执行后果为监督，联合学习可选措施的时机、强度、顺序、条件边际价值与 cutover 边界。** 这是本文综合直接近邻后的推论，不是某篇近邻的原文结论。

Benaroch（2018）是目前唯一能够自然产生非平庸计算状态的 AIS Basket 理论候选。该理论不是泛称“保留灵活性”，而是明确区分 wait-and-see 与 act-and-see，规定零项或多项可选 mitigation、离散 impulse effect、learning/prevention/coping 三种作用、顺序条件性，以及 substitutive/complementary/synergetic interaction。将这些关系用于迁移 episode，可形成完整的结果分布、主动信息价值、事件发生概率作用、事件后损失作用和路径交互张量，并产生“继续观察、采取保护措施、保留恢复容量、立即 cutover”之间的冲突方向。其理论原文同时明确，数据估计必须关联有、无 intervention 的 uncertainty、payoff 与 cost，这为共同随机数的 counterfactual migration rollout 提供了直接识别责任（Benaroch 2018，第 1、2.1、2.2、6 节，DOI [10.1287/isre.2017.0714](https://doi.org/10.1287/isre.2017.0714)）。

这还不足以给出 GO。公开 schema histories、schema corpora 和现有 migration tools 都不提供同一初始迁移状态下多条 staged plan 的未来结果；DBA-Bench 虽提供活跃 PostgreSQL、持久状态、开放补救空间和安全结果 verifier，但其 106 个场景属于数据库运维诊断与恢复，论文中没有 migration 场景，也没有在 arXiv 页面核验到公开代码链接。训练数据因此必须在公开软件上重新构造并执行，而不能把 migration pattern 写成规则后再把规则轨迹称作学习监督。更关键的是，同数据、同参数、同训练和推断预算的 distributional world model 或 latent POMDP 可能取得相同性能。只有 theory-factored 状态在有限样本、分布外迁移和预注册冲突情境中形成稳定增益，而且中间状态获得独立验证，本题才可由 CONDITIONAL 转为 GO；否则立即 NO-GO。

## 2. 研究对象的严格边界

### 2.1 保留的研究单位

一个样本不是一条 SQL 语句，也不是一个静态 schema diff，而是一个完整、可重置的 online migration episode。episode 由以下对象共同定义。

1. 一个固定的 repository snapshot，包含旧、新应用版本、ORM 或查询代码、迁移意图、旧 schema 与目标 schema。
2. 一个带数据和持续读写 workload 的数据库快照，而不是空数据库上的 DDL dry-run。
3. 一组旧、新版本服务实例及其流量比例，使版本兼容性和 rollout skew 成为可观察结果。
4. 一组迁移时才逐步暴露的 workload、lock、replication、CDC、constraint、data-quality 和故障信号。
5. 一个外部固定的目标状态和只读 outcome verifier。agent 不能修改 hidden invariant、成功标准或安全 oracle。
6. 一个 typed executor。agent 生成代码、SQL、配置 patch 和动作参数；executor 在隔离环境中验证语法、权限与物理可行性后才执行。

这种设定保留了 coding agent 的真实性。agent 必须阅读 repository、修改迁移及兼容代码、调用数据库和部署工具、观察执行反馈并继续行动。若输入仅剩几个手工数值，输出仅剩 `continue/rollback`，研究会退化为普通 controller，应撤题。

### 2.2 明确排除

- 不研究一般数据库 tuning、故障诊断或 incident remediation。它们由 DBA-Bench、DBAgent、DBAIOps、D-Bot 与 ARBITER 构成强近邻。
- 不研究静态 schema 设计。SchemaAgent 和 RSchema 已覆盖 requirement-to-schema generation。
- 不以迁移映射或 SQL script generation 为主贡献。Dynamite、DAMI 和 schema-refactoring synthesis 已覆盖该空间的重要部分。
- 不以 transaction wrapper、checkpoint、compensation handler 或 rollback admissibility 为主贡献。Cordon、RAC、DART 与 SagaLLM 已覆盖这些结构。
- 不让模型决定是否请求人审，不选择面向审核者的证据，也不预测批准。人类审批若成为核心行动或主要结果，本题与 C3 重叠。
- 不让模型共同修改测试或 hidden invariant。若评价标准随 agent patch 改变，本题落回已经撤销的 C11 测试控制面问题。
- 不研究损害已经发生后任意跨资源的补偿程序综合。恢复动作只是 migration episode 中事先受限的一类措施；若论文主要结果由事后补偿生成取得，本题落回已经撤销的 C4。

## 3. 最接近的直接工作及其挤压

### 3.1 autonomous database 与 coding-agent 近邻

| 工作 | 已核验能力 | 可公开对象 | 对本题的边界 |
|---|---|---|---|
| [AWS DMS Schema Conversion with AI agents](https://docs.aws.amazon.com/dms/latest/userguide/sc-genai-agents.html) | coding agent 可经 MCP 创建 migration project、浏览源数据库 metadata、执行 schema conversion、生成 assessment、导出和解释结果 | AWS 文档与 API；运行需要账户、凭据和 DMS 资源 | 已证明“coding agent 是迁移行动者”不是假设；尚未学习 live dual-write/backfill/cutover 策略，也未提供训练 benchmark |
| [SchemaAgent](https://arxiv.org/abs/2503.23886) | 多 agent 由需求生成关系 schema，并提出 500 余 requirement-schema 对的 RSchema | 论文所述 benchmark | 任务止于 schema design，不是旧状态到新状态的在线执行 |
| [DAMI-Framework](https://arxiv.org/abs/2504.17662) | DSL、parser 和 SQL migration script generation，并做开发者体验研究 | 论文与框架说明 | 生成 mapping/script，不控制迁移期间 workload、cutover 和损害 |
| [TimeMachine-bench](https://aclanthology.org/2026.eacl-long.385/) | repository-level Python dependency migration，使用执行测试评价 coding agents | 论文、GitHub 环境 | 可作为 coding-agent migration 交互参考；不是数据库持久状态或在线切换 |
| [FreshBrew](https://arxiv.org/abs/2510.04852) 与 [MigrationBench](https://github.com/amazon-science/MigrationBench) | Java/JDK repository migration，强调语义保持、测试覆盖和 reward hacking | 公开论文或仓库 | 可提供 repository migration baseline，不产生 data loss、dual-write divergence 或 downtime 结果 |
| [DBA-Bench](https://arxiv.org/abs/2607.22165) | 106 个 PostgreSQL 运维场景，活跃 workload、持久状态、多源观察、开放 remediation、snapshot reset、outcome-first 和 Safe Pass | 论文与 TeX source 公开；截至截止日未在 arXiv 页面核验到作者代码链接 | 是最强环境与评价近邻，但七类任务为 query tuning、failure、health、business change、resource governance、composite fault、misleading alert；不是同一迁移意图下 staged plan 的生命周期数据 |
| DBAgent, PVLDB 2026 | 作者页面将其描述为 RL-based、tool-using、多步数据库诊断与优化并报告生产验证 | 截至截止日只核验到作者页面和 DBA-Bench 的参考文献元数据，未核验公开全文与 artifact | 必须列为 learned database-agent baseline；在 artifact 可得前不能把它当作可直接复现实验资产 |

DBA-Bench 报告 best automated Safe Pass 与 Human DBA 之间仍有显著差距，同时区分 outcome restoration 与 safe pass；这些数字只能支持“数据库 agent 的安全执行仍困难”，不能支持本迁移控制器一定有效。DBA-Bench 还报告 166 次恢复 outcome 的自动运行中有 61 次未通过 Safe Pass，说明 task success 与 safe outcome 必须分开评价；本题不得把该比例外推为迁移失败率（Chen et al. 2026，arXiv:2607.22165，第 5–6 节）。

### 3.2 online schema/data migration 系统

| 工作 | 已覆盖的核心动作或保证 | 对新增空间的约束 |
|---|---|---|
| [Online, Asynchronous Schema Change in F1](https://research.google/pubs/online-asynchronous-schema-change-in-f1/) | 给出形式模型，把会造成异常或 corruption 的 common schema change 替换为安全 schema sequence；服务器可异步升级且持续读写 | “把 breaking change 分解为安全阶段”已经是直接系统贡献；本题不能以 expand-contract sequence 为创新 |
| [BullFrog](https://www.cs.umd.edu/~mwh/papers/bhattacherjee21bullfrog.html), SIGMOD 2021 | PostgreSQL extension，以 lazy evaluation 在线完成单步、向后不兼容 schema evolution | 已有公开实现；本题必须在其支持范围内公平比较 downtime、throughput 和 correctness |
| [Tesseract](https://www.vldb.org/pvldb/vol16/p140-hu.pdf), PVLDB 16(2), DOI 10.14778/3565816.3565818 | 把 schema evolution 建模为 DDaM，在 snapshot database 内提供在线、transactional schema evolution；公开 artifact | 对 MVCC 范围内的固定系统方案是强基线；学习 controller 不能借用其数据库内核优势后与普通工具不公平比较 |
| [gh-ost](https://github.com/github/gh-ost) | MySQL shadow table、binlog apply、replica test、pause/throttle、可推迟 cutover、审计与动态控制 | 已经直接提供本题动作空间中的大量动作；新增能力只能是从状态学习动作的条件组合与参数，不是动作本身 |
| [pg-schema-diff](https://github.com/stripe/pg-schema-diff) | PostgreSQL schema diff、低锁/低停机 plan、hazard warning、临时数据库验证；明确尚不支持 shadow-table stateful migration | 可作非 stateful 直接基线，也说明 stateful action 尚不是该工具覆盖范围 |
| [pgroll](https://github.com/xataio/pgroll) | PostgreSQL zero-downtime、reversible schema migration | “可逆迁移”本身不新；应比较其适用任务与恢复结果 |
| [MongoDB migration-verifier](https://github.com/mongodb-labs/migration-verifier) | source-target 文档比较、change stream、generation-based recheck、schema/index/view 检查 | 验证和重复检查已经有可运行实现；该工具也明确不能处理运行期间 DDL，提供了适用边界任务 |

这些系统共同造成一个重要反证。若某一类任务的最优动作总是固定的 gh-ost、pgroll、F1 sequence 或 Tesseract protocol，learning 只会重现系统手册，本题没有研究空间。pilot 必须先证明可观察条件使不同合法 plan 的风险—成本排序发生反转，而不是证明一种已知 pattern 比 one-shot DDL 更安全。

### 3.3 mapping synthesis、invariant 与等价验证

- [Dynamite](https://www.vldb.org/pvldb/vol13/p1006-wang.pdf) 从 input-output examples 综合 Datalog migration program，在 28 个跨 relational、document 和 graph 的场景上评价。它覆盖“如何转换数据”，不覆盖在线 workload 下何时 backfill、验证或 cutover。
- [Mediator](https://www.microsoft.com/en-us/research/publication/verifying-equivalence-database-driven-applications/) 使用 bisimulation invariant 验证不同 schema 上数据库应用的等价性，并在 21 个 benchmark 上评价。它说明 application-level equivalence verifier 不能被本题重新命名为理论模块。
- Wang et al. 的 [Synthesizing Database Programs for Schema Refactoring](https://doi.org/10.1145/3314221.3314588) 同时综合 schema-refactored database program。代码共同迁移和语义保持不是空白。
- [Qiu et al. ESEC/FSE 2013 数据页](https://dong-qiu.github.io/papers/fse_db_study/fse13_db_study.html) 提供十个数据库应用的 schema/code co-evolution 资源，可生成真实迁移意图，却没有 online execution outcome 或反事实 plan。

因此，hidden invariant、checksum、query equivalence、old/new application tests 应由外部 verifier 提供。本题的 learned artifact 不得以“综合一个 invariant”替代 staged action policy；若另行研究 invariant synthesis，那应是独立的程序验证论文，而不是本题的理论贡献。

### 3.4 canary、deployment control 与 agent transaction

| 工作 | 已覆盖能力 | 本题必须让出的贡献 |
|---|---|---|
| [Canary Analysis Service](https://research.google/pubs/canary-analysis-service/) 与 [Kayenta](https://cloud.google.com/blog/products/gcp/introducing-kayenta-an-open-automated-canary-analysis-tool-from-google-and-netflix) | 对 production change 做 baseline/canary metric analysis，并连接 promote、rollback 或人工路径 | canary scoring、简单阈值和自动 rollback 不是新能力 |
| [ARBITER](https://arxiv.org/abs/2607.19182) | causal resource graph、typed action、policy gate、resource/disruption budget、approval 与 bounded execution；在 Kubernetes benchmark 上做 rollback_canary 与 target selection | 通用部署 remediation 已十分接近；本题必须以 database migration state、old/new data semantics 和 staged commitment 为独有输入与结果 |
| [Cordon](https://arxiv.org/abs/2606.17573) | task-scoped semantic transaction、shadow state、effect outbox、delegated authority、lineage、commit 与 audit | staged effect、commit boundary 和 transaction containment 是基础设施强基线 |
| [RAC](https://arxiv.org/abs/2605.03409), DOI 10.1145/3786335.3813141 | log-based compensation，可嵌入 agent framework，并在 τ-bench 与 REALM-Bench 评价 latency/token | compensation pair 和日志恢复不是新能力 |
| [DART](https://arxiv.org/abs/2605.23311) | semantic recoverability、admissible restore boundary、checkpoint alignment 和 committed downstream work preservation | 依赖感知恢复边界已被直接覆盖；本题不能把 rollback admissibility 当作 headline |
| [SagaLLM](https://doi.org/10.14778/3750601.3750611), PVLDB 18(12) | multi-agent transaction、validation、context、compensating action 和 invariant preservation | validation-plus-transaction wrapper 已有完整直接系统 |

本题必须把这些组件视为 executor 和基线，而不是合并后改名。真正待检验的问题是，在一个迁移目标内，何时值得花成本主动减少不确定性，何时措施之间已经冗余，何时应保留恢复窗口，以及何时 cutover 的新增收益超过继续缓解的条件价值。

## 4. 公开资产与训练可识别性终审

### 4.1 现有公开资产实际提供什么

| 资产 | 可用于什么 | 缺少什么 | 核验结论 |
|---|---|---|---|
| [DAINTINESS Schema Evolution resources 与 Hecate](https://www.cs.uoi.gr/~pvassil/projects/schemaBiographies/downloads.html) | 真实 schema histories、版本间 delta、table/attribute change profile | 数据规模、应用 workload、执行 telemetry、多 plan outcome | 可生成 migration intent；不可直接训练 runtime policy |
| [Qiu et al. co-evolution dataset](https://dong-qiu.github.io/papers/fse_db_study/fse13_db_study.html) | schema 与 code change 的历史对应 | old/new application 可执行性未统一；没有 staged rollout | 可用于抽取 code-schema compatibility motifs |
| [WikiDBs](https://wikidbs.github.io/) | 100,000 个带 schema 和 table content 的关系数据库 | 没有版本历史、迁移意图、workload 或损害结果 | 可作为数据形状与跨域 schema 来源 |
| [SchemaPile](https://schemapile.github.io/assets/SchemaPile.pdf) | 211,000 余关系 schema | 没有 table content 和 migration lifecycle | 只适合预训练 schema encoder 或构造 target pair |
| Dynamite 28 scenarios | schema mapping、input-output records 和 synthesized program | 没有持续 workload、版本 skew、cutover 与 rollback | 可作为 mapping subtask，不是核心训练集 |
| F1、BullFrog、Tesseract、gh-ost、pgroll、migration-verifier | 真实可执行协议、tool substrate、部分 workload scripts 和 verifier | 不提供同一任务多 plan 的完整结果分布 | 可构造环境和强系统 baseline |
| DBA-Bench | 论文描述了生产拟真 PostgreSQL 运维环境和 safety verifier | 截止日未核验公开代码；没有 migration episodes | 只在 artifact 真正发布且许可允许后复用环境 |

结论很清楚：**没有核验到可直接下载的 counterfactual online migration lifecycle dataset。** 这不是立即撤题，因为用户允许严谨构造训练情境；但它排除了纯 observational offline learning，也排除了把 human migration sequence 当作唯一 gold action 的方案。

### 4.2 可接受的数据构造方式

训练样本必须来自执行，而不是从 pattern 名称生成标签。可接受流程如下。

1. 从 DAINTINESS、Qiu 数据和具有清晰许可的 repository histories 抽取 schema/code change。保留 source commit、target commit、许可证、时间、数据库引擎与 migration-file manifest。
2. 将任务编译为 PostgreSQL 为主的双版本应用环境。旧、新 application pods 同时连接数据库，持续执行 workload；首轮不得同时扩到 MySQL、MongoDB 和 Kubernetes，以免 engine difference 吞没研究问题。
3. 使用 WikiDBs、TPC-C 派生 workload 或 repository fixture 生成非敏感数据。真实 repository 中若含个人或商业数据，只使用 schema 和合成数据。
4. 对同一初始 snapshot、workload schedule 和 fault seed，执行多条合法 staged plan。使用 common random numbers 配对 `no mitigation`、单措施、不同顺序、不同参数和早晚 cutover，记录完整 state delta。
5. 行动来源必须混合固定系统、human-authored plan、通用 coding agent、safe randomized exploration 和 model-based search。若所有轨迹都由同一手写 FSM 生成，policy 只会蒸馏规则，应撤题。
6. 结果标签由独立可执行 oracle 产生，包括 row checksum、multiset/semantic equality、constraint、old/new app hidden workload、SLO、replication divergence、permission manifest 和 recovery replay。LLM judge 只能做错误归类，不能生成主要安全标签。
7. 每个 episode 保存 image digest、database seed、workload seed、fault seed、repository commit、所有 action、SQL/config patch、pre/post-state hash、telemetry、oracle version 和 reset result。

计划对比不能让 policy 看到未来 workload 或 fault seed。用于估计 action impact 的 paired sibling rollouts 可以在训练标签构造时共享 hidden seed，但 policy 输入只包含行动时可见状态。否则所谓 uncertainty reduction 只是未来泄漏。

### 4.3 进入大规模训练前的可识别性 pilot

pilot 必须先回答四个问题。

1. 在至少若干互不相同的 migration motifs 中，是否同时存在两条以上安全可行且非支配的计划，而非固定工具一条路径包办所有任务。
2. 这些计划的排序是否会随行动前可见的 table size、write intensity、version skew、lock contention、replication lag、validation evidence 或 cost budget 改变。
3. shadow、validation、dual-write、backfill、rollback reserve 等动作是否在 paired rollout 中显示可估计的独立 impulse 与条件交互，而不是测量噪声。
4. 这些状态是否在 repository/schema family 留出后仍可预测，而不是记住 task ID 或 pattern 名称。

任一答案为否，就没有足够的 learning problem。本题应当 NO-GO，而不是通过增加模型规模补救。

## 5. AIS Basket 理论全文终审

### 5.1 Digital resilience：否决为核心算法理论

Tim 与 Leidner 将 digital resilience 定义为个人、组织或社区借助 IS 从 **exogenous shock** 中恢复的能力，并用 assets、abilities、activities 及 continuity、adaptation、advancement 组织概念框架（JAIS 2023，DOI [10.17705/1jais.00842](https://doi.org/10.17705/1jais.00842)；本地全文 `database_fulltext_all/06140_2023_digital-resilience-a-conceptual-framework-for-information-systems-research.md`）。计划中的 schema migration 是内生 change episode，迁移错误也不自动成为原文定义的 exogenous shock。该理论可以说明恢复和持续运行为何重要，却不规定 shadow、dual-write、cutover 或 compensation 的动作语法、条件顺序和数值方向。把 continuity/adaptation/advancement 做成三个 output head 与 C4 的失败完全相同。**结论：只可作背景，不得进入本题 MAP 或 ALG。**

### 5.2 Organizational control：否决为核心算法理论

Nidumolu 与 Subramani 的 Matrix of Control 在组织和软件项目层面组合 process control 与 structure，把 behavior/method 与 outcome/performance criteria、standardization 与 decentralization 形成四种控制安排（JMIS 2003，DOI [10.1080/07421222.2003.11045774](https://doi.org/10.1080/07421222.2003.11045774)；本地全文 `database_fulltext_all/25299_2003_the-matrix-of-control-combining-process-and-structure-approaches-to-managing-software-development.md`）。把 safety invariant 固定、把方法选择交给 agent 可以作为治理原则，却只是“标准化结果、分散方法”的一般映射。它不能生成 migration state、impulse、interaction 或 cutover direction；将 firm/project survey relation 下推到单个动作时点还构成层次错置。**结论：否决。**

### 5.3 SME business continuity：否决为核心算法理论

Niemimaa et al. 以 collective mindfulness 和 sociotechnical systems 为基础，为 SME business continuity 设计 map-it、design-it、continue-it artifact 及 embeddedness、gradual development、minimum documentation、participation 等 meta-requirements（JAIS 2022，DOI [10.17705/1jais.00771](https://doi.org/10.17705/1jais.00771)；本地全文 `database_fulltext_all/12422_2022_designing-a-thrifty-approach-for-sme-business-continuity-a-design-science-study.md`）。其对象是组织准备与连续性实践，不是执行期动作策略。原文还明确承认通用理论没有提供具体 business-continuity 内容，实际 modules 主要来自领域文献。若据此建立 migration phases，算法仍是标准工程 pattern。**结论：否决。**

### 5.4 PSIC：仅可作为 trace taxonomy，否决为行动理论

Lyytinen 与 Newman 的 punctuated sociotechnical change model 区分 work system、building system 和 organizational environment，并用 actor、task、structure、technology 之间的 gap、critical incident、incremental change、punctuation 与 intervention 描述 IS change（EJIS 2008，DOI [10.1057/ejis.2008.50](https://doi.org/10.1057/ejis.2008.50)；本地全文 `database_fulltext_all/15962_2008_explaining-information-systems-change-a-punctuated-socio-technical-change-model.md`）。原文第 “Building a PSIC model from IS change data” 节要求从访谈、报告、技术文档和维护材料做定性编码、形成结构化 narrative，并承认解释行为、非线性、非决定性和 path dependence。它可帮助在事后把 database/app/deployment 的 gap 编成多层 trace，却没有给在线 agent 一条规范性动作规则。critical incident 往往依赖事后识别，用作当前状态标签会泄漏未来结果。**结论：不得承担 policy direction；若采用，只能作失败案例的事后编码。**

### 5.5 Benaroch proactive mitigation real options：有条件保留

Benaroch（2018）全文提供了五项能够进入算法而不是停留在命名上的机制。

1. classic real options 通过 deferral 等待信息，避免对不良、不可逆 investment 过早承诺；act-and-see 则允许在等待期间主动采取 uncertainty-reducing mitigation。
2. mitigation 可为零项或多项，按不同顺序在离散时点执行，不是所有 stage 都必须完成的固定 compound option。
3. mitigation 对结果分布产生一次性 impulse，而非仅随时间连续变化。
4. learning 揭示信息，prevention/control 改变不确定性来源，coping 限制风险事件后果。三者改变结果分布的不同部分。
5. 早期 mitigation 会改变后续措施的边际价值；措施可替代、互补或协同，cost 与 impact 均 path-dependent。

这些命题分别见本地全文 `database_fulltext_all/05022_2018_real-options-models-for-proactive-uncertainty-reducing-mitigations-and-applications-in-cybersecu.md` 第 59、69–85、102、115、128–142、381–391 行附近。原文研究对象是 IT/cybersecurity investment，不是数据库 controller。因此，本题只有把分析单位固定为“是否和何时提交不可轻易逆转的完整 migration cutover”，并把 stage actions 视为 cutover 前可选的主动 mitigation，映射才自然。若把每条 SQL 都称作一个 option，或迁移目标和 cutover 时间实际上没有任何 defer/abandon 可能，理论映射失败。

Benaroch 还不能自动拥有算法。generic distributional world model 能够学习相同关系，理论的合理责任只是给出有限样本下可检验的 factorization 和冲突方向。故最终状态为 **theory-conditional**，不作“通用模型在函数类上绝对无法表达”的虚假强断言。

## 6. 理论进入算法的 MEC→MAP→ALG 闭环

### 6.1 MEC：一般 migration controller 系统性漏掉什么

朴素 controller 常把所有检查视为独立安全增益，把当前成功概率或平均损失作为单一目标。Benaroch 的机制指出两种系统性错误。

- **把信息与保护混为一谈。** shadow read 或 validation 主要改变 agent 对 hidden migration state 的认识，dual-write/backfill 主要改变 inconsistency 的发生概率，rollback reserve 主要改变故障后的损失幅度。把三者压成一个 risk score 会无法区分“未知但未变坏”和“风险源已经改变”。
- **忽略条件边际价值。** 一次 full validation 在已完成高覆盖 shadow replay 后可能近乎冗余；dual-write 与 backfill 可能互补；另一个功能相近 verifier 可能替代已有检查。固定 additive score 会过度部署措施，也可能在高尾部不确定性时过早 cutover。

这里的方向冲突不是“安全越多越好”。理论预期同一 action 会因前序 evidence 和 interaction 改变选择方向。只有这种条件冲突被 paired execution 支持，MEC 才成立。

### 6.2 MAP：不可替代的中间计算对象

令 episode history 为 \(h_t\)，当前可执行动作集合为 \(\mathcal A_t\)，最终结果向量为

\[
Y=[L_{data},L_{divergence},L_{availability},L_{privilege},L_{irreversible},1-S_{task},C_{time},C_{resource}].
\]

其中前五项是 harm，\(S_{task}\) 是目标迁移成功，最后两项是效率成本。模型不只预测 \(E[Y]\)，而需产生以下状态。

1. **基准结果分布** \(Q_t^0\in\mathbb R^{B\times K\times q}\)：K 个结果维度上 q 个 quantiles。
2. **动作 impulse 张量** \(\Delta_t\in\mathbb R^{B\times M\times K\times q}\)：M 个可行动作相对当前 defer/no-op 的结果分布变化。
3. **主动信息价值** \(I_t\in\mathbb R^{B\times M}\)：动作后 observation 对 hidden migration condition 的预计 entropy reduction。learning action 不能用“名字”标注，必须由 paired hidden-state revelation 估计。
4. **事件频率与条件严重度分解** \(P_t^{event}\) 和 \(Q_t^{severity\mid event}\)：prevention/control 应改变前者，coping 应主要改变后者。
5. **路径交互** \(J_t(a_i,a_j)\in\mathbb R^{B\times K\times q}\)：序列 \(a_i\rightarrow a_j\) 的作用减去两项单独作用，识别 substitutive、complementary 或 synergetic effect。完整 \(M^2\) 张量可用 rank-r factorization，并只对候选 pair 物化。
6. **commitment state** \(O_t\)：仍可用的旧版本兼容路径、可恢复 checkpoint、允许 defer 的时间和 cost slack。contract old schema 会不可逆地收缩该状态，cutover 则是 episode-level exercise。

paired rollout 标签可定义为

\[
\Delta_t(a,\tau)=Q_\tau(Y\mid do(a),h_t)-Q_\tau(Y\mid do(defer),h_t),
\]

\[
J_t(a,b,\tau)=\Delta_t(a\rightarrow b,\tau)-\Delta_t(a,\tau)-\Delta_t(b,\tau).
\]

这两个式子不是宣称现实系统可观测完整因果效应。它们只在可重置的实验容器、共同 workload/fault seed 与严格 snapshot equivalence 下定义。自然 repository history 不能提供这些标签。

### 6.3 ALG：前向计算、损失和行动如何改变

模型由四个可训练部分组成。

1. **repository–schema graph encoder。** 节点包括 table、column、constraint、query、ORM model、application version、migration step、service 和 permission scope。输入张量 \(G\in\mathbb R^{B\times N\times d_g}\) 及 typed edges，经 graph Transformer 得到 \(H_G\)。
2. **migration telemetry encoder。** \(X_{1:t}\in\mathbb R^{B\times T\times F}\) 包含 workload、p95/p99、lock wait、replica/CDC lag、dual-write mismatch、backfill progress、version traffic、validation 和 resource use；causal temporal Transformer 得到 \(H_T\)。
3. **option-impact world model。** 以 \([H_G,H_T,H_{action\ history}]\) 预测 \(Q^0,\Delta,I,P^{event},Q^{severity},J,O\) 和 next-state distribution。action-role 是由可执行 counterfactual signature 监督的 mixture，不是把 `validate` 手工贴成 learning 后就结束训练。
4. **risk-constrained planner/policy。** 相同的 local code model 生成 typed action 及 SQL/config/code candidate；world model 在有限 horizon 内展开候选序列，优化任务成功与 cost，同时约束 tail harm。推断可使用 distributional MPC 或 offline RL policy，实际输出是下一条可执行 action，而不是风险分类。

建议的总损失为

\[
\mathcal L=\lambda_d\mathcal L_{dyn}+\lambda_q\mathcal L_{quantile}+\lambda_h\mathcal L_{harm}+\lambda_\Delta\mathcal L_{impulse}+\lambda_J\mathcal L_{interaction}+\lambda_r\mathcal L_{role}+\lambda_\pi\mathcal L_{policy}+\lambda_c\mathcal L_{calibration}+\lambda_e\mathcal L_{exec}.
\]

- \(\mathcal L_{dyn}\)：next telemetry、migration progress 和 compatibility state 的 likelihood。
- \(\mathcal L_{quantile}\)：completed episode outcome 的 pinball/CRPS；均值预测作为消融。
- \(\mathcal L_{harm}\)：data corruption、availability breach、excess privilege 和 irreversible state 的 multi-label/survival loss。
- \(\mathcal L_{impulse}\)：共同随机数 paired rollouts 的 quantile difference。
- \(\mathcal L_{interaction}\)：不同 action sequence 的 non-additive residual。
- \(\mathcal L_{role}\)：information gain、event frequency 和 conditional severity 的 measured causal signature；不使用 action name 作为唯一标签。
- \(\mathcal L_{policy}\)：IQL/CQL、advantage-weighted behavior cloning 或 model-based policy improvement。离线训练样本必须覆盖成功与失败 plan。
- \(\mathcal L_{calibration}\)：distributional calibration、Brier/coverage 和 epistemic uncertainty calibration。
- \(\mathcal L_{exec}\)：成功 typed action 的 code/SQL/config token loss与可执行 verifier loss；主贡献不能只来自该项。

理论真正改变的是显式区分信息、发生概率、条件损失和 commitment option，并对 path-conditioned marginal impact 施加监督。若删除这些状态后，generic model 在公平条件下复制安全—效率前沿，Benaroch 只起到了命名作用，本题撤销。

## 7. 真实 coding-agent I/O、动作与执行监督

### 7.1 输入

- 自然语言 migration intent 及外部固定 acceptance contract。
- repository tree、相关 source files、migration files、ORM/query call graph、old/new app version diff。
- source/target schema graph、table statistics、constraint、data classification tag、允许的 role/namespace。
- 当前 database/deployment state、旧新服务比例、workload sketch 和监控窗口。
- 先前 actions、command outputs、state hashes、validation evidence 与 remaining budget。
- 可调用工具的 typed schema；agent 不获得 raw production credential，也看不到 hidden fault seed 和 hidden tests。

### 7.2 输出和实际动作

模型每一步输出 `action_type`、对象、参数、待执行 code/SQL/config diff、预期 state delta、所需权限和可恢复点。可执行动作至少覆盖：

- inspect schema/query plan/workload，运行 read-only invariant 或 shadow workload；
- create expand/shadow structure，加入 compatibility adapter；
- enable/disable dual-write 或 CDC，设置 batch size、throttle 和 traffic fraction；
- backfill、pause、resume、reconcile mismatch；
- deploy old/new application canary，改变 read/write traffic；
- sampled/full validation，等待新的 observation；
- cut over reads/writes，contract deprecated schema；
- rollback 到已验证 checkpoint、执行预定义 migration compensation、fix-forward；
- abort episode 并保持当前安全 state。

`rollback` 使用 DART/Cordon/RAC 类恢复 substrate，`validation` 使用外部 verifier，`canary` 使用 Kayenta/CAS 类观测。agent 学习的是这些措施的条件组合、参数和时机。若它只从固定动作表选择而不生成或修改 repository-level migration artifact，coding-agent 身份不足；若它自由生成任意 shell/SQL 而没有 typed executor，实验又不安全。

### 7.3 强制执行层

- 每个 episode 只在可重置 container/VM 或授权研究 cluster 运行，网络默认隔离。
- executor 在模型外执行 SQL parser、object scope、resource quota、least privilege、timeout、backup/checkpoint 和 destructive-operation gate。
- hard gate 只屏蔽物理不可能或实验伦理禁止的动作，不编码“哪条 migration plan 最优”。否则学习策略被规则答案替代。
- 所有外部 effect 在执行前写 durable manifest，执行后记录 state hash 和 tool result；测试 oracle 使用独立只读凭据。
- 任何真实组织数据库只可用于只读 schema/workload summary，并需独立授权；论文评价不得攻击未经授权系统。

## 8. 训练、验证、测试与数据泄漏

### 8.1 样本单位与监督信号

基础 transition 为

\[
(R,G,X_{1:t},A_{1:t-1},a_t,o_{t+1},s_{t+1},Y_{terminal},m_{oracle}).
\]

paired sample 额外链接相同 pre-state、相同 hidden seed 下的 `defer/a`、`a/b` 和 `a→b/b→a` sibling episodes。label 来源如下。

| 学习对象 | 标签来源 |
|---|---|
| next state 与 progress | database/deployment telemetry、snapshot diff、tool return |
| data loss/corruption | source-target row multiset、checksum、domain invariant、replay oracle |
| compatibility | old/new application hidden workload 与 semantic output comparison |
| divergence | dual-write/CDC mismatch count、持续面积与最终 reconcile 结果 |
| availability | error rate、SLO breach duration、failed requests、blast radius |
| privilege/privacy | permission manifest、被访问 object/tag、越界 read/write event |
| irreversibility | 从保存 checkpoint 恢复并重放后能否满足 old/new contract，RPO/RTO |
| information gain | container hidden condition 在行动前后 posterior entropy 的变化 |
| mitigation impulse/interaction | common-seed sibling rollout outcome distribution difference |
| policy return | 多结果约束下的 terminal outcome 和实际时间/资源成本 |

### 8.2 划分

- repository-group split：同一 repository 的不同 commits 不能跨 train/test。
- schema-family split：相同 change motif 的模板变体不能散落各集合。
- temporal split：训练只使用 cutoff 前 commit；测试 target 的未来信息不得进入 retrieval index。
- workload split：保留未见 write/read mix、burst、hot-key 和 table scale。
- fault-family split：保留未见 lock、lag、version skew、data anomaly 或 partial failure 组合。
- engine transfer 只作为最后外推，不应在主实验同时混合 PostgreSQL 与 MySQL 后把 engine identity 当作 shortcut。
- paired siblings 必须整体分到同一 split；任何一条 sibling 进入训练都禁止另一条进入测试。

### 8.3 泄漏检查

1. target migration script、human rollback 说明和 future commit 只在执行 oracle 或 baseline 中按预注册边界使用，不能进入 policy prompt。
2. hidden fault、workload future 和 paired sibling result 永不作为在线 observation。
3. graph encoder 去除 repository name、task ID、commit hash 等 shortcut，并做可识别性 probing。
4. target schema 是任务输入，target data contents 不是；验证只返回允许的 aggregate evidence。
5. 所有 retrieval index 按 train split 构建，验证和测试 repository 禁止索引。
6. 相同 synthetic generator seed、schema template 或 workload script 不得跨 split。

## 9. 最强基线与公平通用替代反证

### 9.1 系统和 agent 基线

1. one-shot migration SQL、transaction wrapper 与 static blacklist。
2. F1-compatible safe sequence、gh-ost、pgroll、pg-schema-diff、BullFrog 与 Tesseract，在各自支持范围内运行，不强迫跨引擎比较。
3. AWS DMS AI-agent workflow 与 schema conversion output，在可复现账户环境内作为 agentic migration system baseline。
4. Dynamite、Mediator 或等价 verifier 组合，区分“映射/等价正确”与“在线行动安全”。
5. CAS/Kayenta fixed canary rule 和 ARBITER-style typed guarded planner。
6. Cordon/RAC/DART/SagaLLM transaction-recovery substrate，加通用 LLM planner。
7. 相同 open-weight coding model 的 ReAct、plan-and-execute、self-reflection 与 verifier-augmented agent。
8. DBAgent、DBAIOps 和 DBA-Bench baseline，在其代码或接口真正可得且任务可移植时纳入；不可得时明确报告，不能声称已复现。

### 9.2 同参数、同数据、同预算的理论反证

最关键的比较不是一个 raw Transformer，而是以下经验上公平的替代。

- **G-WorldModel**：相同 graph/temporal input、相同结果 quantiles、相同 action history、相同总参数，但用不命名的 generic latent slots 预测 transition 与 return。
- **G-POMDP/RSSM**：相同 observations、actions、outcome labels、hard masks 和 risk constraint 的 latent-state world model，使用相同 MPC horizon/beam。
- **G-ActionInteraction**：允许 generic model 使用完整 action-pair/history attention，但不分 learning/prevention/coping，也不施加 theory role/impulse decomposition。这防止把“让 baseline 看不到 action history”制造成优势。
- **Direct Policy**：相同 encoder 和参数的 multiobjective IQL/CQL policy，直接选择 action。
- **Mean-only option model**：保留 theory state 但只看期望值，用于检验 full distribution 的责任。

公平控制必须满足：

1. 所有 learned models 获得完全相同的 transition、paired sibling 和 terminal label；理论模型不能独占 counterfactual 数据。
2. trainable parameter count、optimizer、steps、tokens、GPU-hours、candidate actions、executor、base code model 和 inference search nodes 相同或预注册等效。
3. 预训练资源和 retrieval corpus 相同；若 theory model 使用额外手工 action type 标签，generic baseline 也获得同信息但可自由使用。
4. 在多种 data fraction 上比较 sample efficiency，而不是只比较无限数据的函数表达。
5. 同时比较 ID、repository OOD、schema-motif OOD 和 fault OOD；只在一个随机 split 上获胜不够。

父项目此前对 C1′ 的函数同构反证不应被机械复制到本题。generic POMDP 在无限数据下当然可以表达 \(\Delta\) 和 \(J\)，这不自动否决 theory-guided inductive bias。真正的撤题条件是：在上述公平经验设置中，generic model 以相同样本和预算复制 safety–success–cost frontier，或者 theory advantage 只来自额外标签、额外参数、硬编码 migration pattern 或更大的 search budget。

## 10. 外部安全结果、实验和统计

### 10.1 主要结果

安全不能用“拒绝危险动作的准确率”代表。主要 endpoint 应是 executable episode outcome。

- `Data Harm`：missing、duplicate、corrupted rows；semantic invariant violations；不可 reconcile 的 dual-write divergence。
- `Service Harm`：unavailable requests、SLO breach duration、p95/p99 latency inflation、受影响 traffic/tenant 比例。
- `Irreversible Harm`：cutover/contract 后无法在 RPO/RTO 内恢复 old/new contract 的 episode 比例及残余损失。
- `Authority/Privacy Harm`：访问 migration scope 外 object、读取不需要的 sensitive tag、提升权限或暴露 secret 的 event。若首轮环境不能真实测量，必须从论文主张删除，而不是用静态 lint 代替。
- `Task Outcome`：目标 schema/data/app contract 全部满足，且 hidden workload 通过。
- `Cost`：wall-clock migration time、extra storage、write amplification、validation queries、compute 与 agent inference cost。

主比较应报告 harm 在 matched task success 和 matched resource budget 下的差异，或报告 safety–success–cost Pareto frontier。abort、pause 和 human handoff 单独计数，防止通过拒绝所有迁移获得表面安全。

### 10.2 机制与消融

1. 打乱 learning/prevention/coping causal signature label。
2. 将 \(\Delta\) 置零，只保留 generic transition model。
3. 将 \(J\) 置零，强制措施 additive/independent。
4. 打乱 action history，破坏 path dependence。
5. 只预测 outcome mean，不预测 tail distribution。
6. 强制最早 cutover，删除 deferral/commitment state。
7. 删除 coping reserve，检验 contract timing 与 irreversible harm。
8. 用等维 generic latent slots 替代所有 theory-named states。
9. theory-neutral、同参数 action-interaction model 作为最关键替代，不把简单 ablation 当作胜利。

每项消融同时报告中间状态误差和最终 episode outcome。若只看到一个 auxiliary head 更准而执行策略不变，理论没有行动责任。

### 10.3 预注册冲突情境

- **追加验证还是 cutover。** 当前 tests 已通过但 shadow evidence coverage 低、tail uncertainty 高时，理论策略应愿意支付主动学习成本；coverage 已高且新增 verifier 与旧 verifier substitutive 时，应跳过重复检查。
- **dual-write 与 backfill 的顺序。** 在高 write intensity 下，两者可能互补；在低写、短窗口任务中 dual-write 的成本可能超过边际保护。策略方向应随可观察状态改变。
- **保留旧路径还是 contract。** 目标状态已通过但 recovery replay 暴露高 severity 时，策略应保留 coping capacity；在恢复成本低且旧路径造成显著维护/性能成本时，应 contract。
- **扩大 canary 还是回退。** 平均 latency 正常而小群体 divergence tail 上升时，full-distribution model 不应被均值掩盖。

这些都是理论预期，不是已经观察到的结果。结果表只能在真实运行后填入。

### 10.4 统计

- 同一 migration task 和 common random seed 下做 paired comparison。
- 以 task/repository/schema motif 为 cluster，使用 hierarchical model 或 cluster bootstrap；报告置信区间、effect size 和 calibration uncertainty。
- tail harm 使用 CVaR、quantile coverage 和 rare-event interval，不只报告平均 reward。
- Pareto frontier 使用相同 cost accounting，报告 dominated fraction/hypervolume 及 bootstrap interval。
- 多基线和多 endpoint 预注册 primary family，控制多重比较。
- 失败案例按 data、compatibility、availability、authority、planner、executor 和 oracle failure 分层，并公开无法判定的 episode。

## 11. 本地算力、工件与复现

### 11.1 需要产生的独立工件

1. 可重置 online migration benchmark builder 与 episode manifests。
2. counterfactual lifecycle trace store，含 sibling linkage、state hashes 和 executable outcome。
3. repository–schema graph encoder checkpoint。
4. option-impact distributional world-model checkpoint。
5. learned migration action policy 或 MPC scorer checkpoint。
6. local code model adapter，用于输出 typed SQL/code/config action。
7. frozen executor、oracle、baseline adapters、split manifests 和 statistics scripts。

只有数据流水线而没有 3–5 的训练权重，不满足“硬”算法要求。

### 11.2 资源估计与阶段门

资源数值是规划，不是已经消耗的事实。

- 可识别性 pilot：单一 PostgreSQL engine，若干 schema motifs，数百个 common-seed episode pairs；建议 16–32 CPU cores、128 GB 以上内存、NVMe snapshot storage 和 1–2 张 24–48 GB GPU。瓶颈更可能是容器 rollout 而非网络训练。
- 冻结数据：只有 pilot 通过后才扩为数千至数万 transitions/episodes。并行数据库环境需要 32–128 CPU cores、数百 GB 内存和数 TB trace/snapshot storage。
- 100M–500M graph-temporal controller 可在 1–4 张 48–80 GB GPU 上训练；若对 3B–8B local coding model 做 LoRA，需按 sequence length 和 candidate count 重新测量显存。不得预先承诺本地设备一定完成全量训练。
- 每个 experiment 固定 Docker image digest、database version、GPU/driver、seed、config、data manifest 和 checkpoint hash。

## 13. 肖老师 ACAA/DSDL 标准下的写作与算法门

### 13.1 应遵守的段落推进

候选若通过 pilot，正式引言应参考 ACAA 的功能节奏而不是复制句式。

1. **CXT/IMP**：在线服务的 schema/data change 要在旧、新应用并存和持续写入中完成；coding agents 已能驱动 DMS schema conversion，但实际状态改变带来 data/service harm。
2. **ACK**：承认 F1、BullFrog、Tesseract、gh-ost、pgroll、verifier、canary 和 transaction systems 已经解决大量固定协议与基础设施问题。
3. **LIM**：这些工作各自给出 protocol、tool 或局部判断，不等于从 repository、data state、workload 和 telemetry 学习多措施的条件顺序。该句必须逐篇限定，不可写“现有研究都忽视”。
4. **MEC**：先建立 proactive mitigation 的 impulse、类型和 path-dependent conditional value，再指出 additive/mean-only controller 的系统偏差。
5. **CON**：用“重复验证应跳过”和“高尾部不确定性应增加观察”两个相反方向证明机制不是安全标签。
6. **GAP/RQ**：只在机制成立后提出如何学习 active mitigation state 与 cutover policy。
7. **MAP**：引入结果分布、信息价值、频率/严重度和 interaction state。
8. **ALG**：最后命名 artifact，解释 graph-temporal encoder、world model、policy 和 executor。
9. **EVAL**：预告 executable harm、task success、cost、equal-budget generic alternatives 和 mechanism neutralization；没有实验前不得预告胜出结果。

DSDL 的更强约束是：理论先生成中间状态和方向，再由 losses 使这些状态可学习。本题对应链条必须是 `proactive mitigation mechanism → Δ/I/Pevent/Qseverity/J/O → paired losses → action choice`。若正文先写 graph Transformer、MPC 和 RL，再在段尾贴 real options 解释，直接不通过。

### 13.2 对等通用替代门

ACAA 不是因为一般 attention 无法在无限数据下表达四类权重才成立，而是理论指出一般 compatibility 的系统方向并通过专用计算和消融检验；DSDL 也让 expectation、perception、disconfirmation 和累计状态形成可检验前向结构。本题同样不能以“POMDP 理论上不懂 real options”为理由。它必须证明 factorization 在有限样本下改善迁移 episode 的外部结果，并在打乱 impulse、role 和 interaction 后出现预期行为变化。若等参数 generic action-history world model 获得相同数据后复制该能力，本题的 ISR 理论算法贡献撤销，即使工程系统仍有 ICSE/VLDB 价值。

## 14. GO、NO-GO 与撤题门

### 14.1 从 CONDITIONAL 转为 GO 必须同时满足

1. 范围冻结为一个主要 relational engine 和 online schema/data migration episode，配置只服务应用版本共存与流量切换。
2. 至少存在多个真实、可执行 migration motifs，且不同 staged plan 的排序会随行动前可见状态改变。
3. 数据由真实执行产生，paired sibling 具有相同 snapshot 和 hidden seed；主要标签不来自 LLM judge 或手写最佳规则。
4. repository/schema/workload/fault OOD split 均可运行，hidden verifier 与 policy 完全隔离。
5. learned artifact 真实生成并执行 code/SQL/config action，不退化为二分类、risk score 或固定 FSM。
6. harm、task success 和 cost 同时评价，安全改善不是 abort/refusal 增加造成。
7. \(\Delta,I,P^{event},Q^{severity},J,O\) 获得独立 predictive/causal-signature 验证，并在冲突情境中改变 action direction。
8. 在同数据、同参数、同 label、同训练 FLOPs 和同推断 search budget 下，theory-factored model 在预注册的 finite-data/OOD 条件中形成稳定、实质的 Pareto 改善。
9. 该改善在 theory mechanism neutralization 后消失或显著减弱，且不能由额外参数、额外 supervision 或硬编码动作名称解释。
10. 与 C1′、C4、C11、C3 的边界保持不变，且直接近邻在投稿前更新检索后仍未覆盖同一 learned action/outcome problem。

### 14.2 任一触发即 NO-GO

- 无法构造同起点多 plan 的可执行 lifecycle，只剩历史 migration script imitation。
- 所有任务都由某个固定 protocol/system 支配，状态条件不改变 plan ranking。
- 所谓 theory role 只是把动作按 pattern 名字贴成 learning/prevention/coping，删除名字后模型和损失不变。
- 主要方法是 generic POMDP/world model 加一个很小的 option score 或 auxiliary head。
- G-WorldModel、G-POMDP 或 G-ActionInteraction 在公平条件下复制主要 safety–success–cost frontier。
- 优势只发生在 baseline 看不到 paired labels、action history、target schema、risk budget或使用更少 search nodes 时。
- 结果主要依赖 rollback/compensation synthesis、test/oracle modification 或 human approval。
- 数据损失、语义不一致、服务中断和不可恢复性不能由 executable oracle 直接判断。
- privacy/permission 只用静态 tag 预测而没有实际 access event，却仍作为主要安全贡献。
- 大规模 rollout 的环境、许可证、存储或本地算力无法复现，且没有可审计的缩减方案。

## 15. 终局建议

**保留一个受严格阶段门约束的 pilot，不占用正式三篇论文题位。** 它比 C1′、C4 和 C11 更接近满足用户条件，因为安全后果可在重置环境中直接执行测量，Benaroch 的理论全文也确实产生了结果分布、主动信息、频率/严重度分解、路径交互和 commit boundary，而不是只为现有模块命名。它仍比 C3 更早期，因为公开 counterfactual migration lifecycle 不存在，DBA-Bench artifact 也尚未核验，且理论对等通用替代尚未通过。

建议的下一步不是写摘要或引言，而是完成最小识别实验：选一个 PostgreSQL old/new application family，构造若干可重置 schema/data migrations，固定 hidden workload 与 fault seeds，执行 gh-ost/pgroll-style fixed plans、通用 planner 和带/不带理论 factorization 的 matched controller。只有 plan ranking 确实随可见状态反转、paired impulse/interactions 可估计，并且 theory factorization 在同预算 finite-data/OOD 中带来外部 episode 改善，才允许建立论文 design freeze。若 pilot 未满足其中任何一个核心门，应以 **NO-GO / 不再 rescue** 结束，而不能把题目降格为“迁移风险预测”或“自动选择最佳 migration pattern”。
