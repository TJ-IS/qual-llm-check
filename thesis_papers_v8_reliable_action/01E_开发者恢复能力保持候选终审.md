# C15 开发者恢复能力保持候选终审

> 检索与核验截止日：2026-08-15  
> 候选题：coding agent 长期委派下，开发者未来事故诊断与恢复能力保持  
> 终审结论：**CONDITIONAL GO（严格条件保留，不得直接冻结为三篇之一）**

## 0. 先给结论

这个题目讨论的损害真实存在。coding agent 可以连续读取仓库、规划改动、编辑多文件、调用终端和测试，并把大量实现与验证决定从开发者手中接走。短期任务可能因此更快完成，开发者却可能逐渐失去对特定仓库的程序步骤、接口与不变量、验证证据和恢复路径的掌握。当 agent 随后出错、不可用，或一个最初未显现的事故在部署、依赖更新或异常负载下暴露时，仍负有处置责任的人可能无法及时止损，甚至通过错误修改扩大损害。本文候选的主要安全结果因此不是学习满意度、知识测验或自我效能，而是延迟事故中的可执行隔离、回滚、根因定位和恢复表现。

这个问题也已经非常拥挤。Huang 与 Vishnoi 已经用动态系统形式刻画练习、委派、技能衰减与路径依赖，给出保守依赖更新、前瞻委派成本和练习保持等干预。HAAS 已经在软件工程情境中选择五种人机分工模式。SymPareto 已经在摘要层面把人类技能保持与 AI 能力增长组成双目标任务调度。Buçinca 等人已经用真实人类数据和离线强化学习选择不同 AI 支持形式，同时优化当前准确性和后续学习。Agents That Teach 又直接提出 coding-agent 情境的 knowledge debt、概念图、学习探针和自适应微学习。由此，**“为了防止技能退化而动态分配一些任务给人”不是贡献，“用 POMDP 或离线 RL 平衡效率与学习”也不是贡献。**

候选只有在下列交集上仍可能独立成篇：

1. 研究单位是具体仓库中的代码、接口、不变量、测试、配置、部署与回滚义务，不是抽象任务难度或总技能分数。
2. 三类 mindful-conduction facet 是可观察的工作参与活动，而不是三个可任意命名的 skill head。
3. 潜在能力由独立、可执行任务锚定，至少区分程序执行能力、陈述性领域能力和事故恢复能力；这些能力不能由自我效能或对 agent 说明的复述替代。
4. automation reliance、complacency、facet-specific participation、skill transition 与 future residual-responsibility demand 分开表示，不能压成一个“参与度”分数。
5. 策略动作必须改变真实开发工作中的参与方式，包括预测或执行关键步骤、把 API 或不变量落实为可执行约束、独立构造结果证据、间隔式恢复演练，以及在没有剩余人类责任时允许 agent-only。解释卡片、测验、提醒和微课均不得成为主要动作。
6. 训练数据必须来自真实开发者的随机化或可识别纵向互动，并把初始 agent 变更与数日后、隐藏且独立的事故任务配对。
7. 主要效用必须在延迟的 agent-unavailable 条件下由容器、隐藏测试、状态不变量和恢复后系统行为判定，同时报告初始任务成功、开发时间、人力负担和计算成本。

这些条件在方法上可执行，却尚未被数据和实验验证。Rinta-Kahila 等人的三类 facet 与技能变化的关系来自回顾性案例和系统动力学解释，不是已识别的逐行动因果转移；现有公开数据也不含候选所需的随机行动、潜在能力和延迟事故三联标签。因此本次判定不是无条件 GO。它允许一个受硬门控制的真人 pilot 和数据构建阶段；任何关键识别门、同构反证门或直接工作门失败，都应转为 **NO-GO**，不能降格为教学插件或普通任务路由论文。

## 1. 风险、决策时点与研究边界

### 1.1 潜在损害

候选关注的是一种延迟暴露的 operational-safety 与 dependability 风险。最初的 agent 变更可以通过当时可见测试，短期交付也可以成功。损害发生在未来的隐藏事故中，例如某个错误配置开始影响真实流量，接口不变量在新调用路径上被破坏，依赖升级触发兼容性失败，迁移脚本需要安全回滚，或 agent 服务不可用而人工必须接管。若开发者已经不了解 agent 当初执行的关键步骤、仓库约束和验证义务，其事故控制可能更慢、错误更多、恢复不完整，或者在错误诊断后进一步破坏系统。

风险承受者包括当前开发者、接班维护者、依赖该系统的团队与用户，以及必须为服务中断、数据错误或合规失败负责的组织。这里的安全改善不能靠永久关闭 agent 获得。算法必须在保持初始任务成功和生产率收益的同时，保留人类在未来高需求义务上的独立处置能力。

### 1.2 coding agent 为什么改变了问题

普通自动化通常接管预先固定的功能。coding agent 会根据自然语言目标自行浏览仓库、生成计划、跨文件编辑、运行命令、解释失败并继续修正。它在一次会话中可以形成新的代码结构和验证路径，而开发者只看到最终 diff 或测试摘要。人类没有参与的内容因任务而变，未来事故所需能力也取决于这次具体改动连接了哪些接口、不变量与恢复义务。因此，静态的“每隔几次让人手写代码”无法确定应让谁在哪个义务上做什么。

同时，真实使用数据不能直接证明技能侵蚀。Hamza、Siemon 与 Awan 对 AIDev 中 669 名开发者、103 个仓库的纵向与差分中的差分分析没有发现 agent 采用后开发者减少生产性投入；测试活动还有小幅改善。这个结果否定了“agent 使用量上升必然意味着技能下降”的朴素代理。PR 数量、代码行数、review 时长和 agent 执行比例只能描述行为，不能替代延迟的独立恢复测量。

### 1.3 决策时点

模型在正常开发任务尚在进行时介入。它不决定是否批准一项危险操作，也不在已经固定的人审点选择说服材料。给定当前任务、仓库义务图、agent 轨迹、patch、开发者在相关义务上的历史参与和未来剩余责任，策略选择下一项真实参与动作或 agent-only。数日后的隐藏事故只用于训练和评价，不在初始任务时向开发者或模型暴露。

候选不研究一般职业教育、课程设计、问答式知识检查或自我效能提升。它也不主张所有被自动化技能都应保留。Rinta-Kahila 等人的边界很明确：过时技能可以消退；当人仍对任务负责并需在自动化失败时响应时，关键能力的侵蚀才构成问题。候选据此把未来需求和 residual responsibility 作为策略条件。若一个义务已经永久移交给受保障的服务且开发者没有残余处置责任，agent-only 应当是合法甚至更优的动作。

### 2.2 最接近工作的交集结论

直接工作可以分成四个已经被占据的集合。

第一组刻画长期技能—委派动力学。Rinta-Kahila 等人给出 reliance、complacency、mindful conduction 与 skill erosion 的反馈结构；Huang 与 Vishnoi 给出形式动力学；SymPareto 在摘要层面给出 gain–degradation 双目标任务调度。候选不能再以“技能会因不用而下降”或“调度时加入技能收益”作为创新。

第二组设计学习或技能保持干预。Hardin 等人比较软件训练结构，Shen 与 Tamkin识别 AI 使用模式，Agents That Teach 与 Agentic Education 直接设计学习支架。候选若输出解释、概念卡、理解探针、quiz 或课程顺序，就进入这组已有工作且失去广义安全的外部结果。

第三组学习人机支持与任务分配策略。Buçinca 等人的 offline RL、HAAS 的规则加 bandit、Bayesian-enhanced Q-learning 功能分配和成熟 adaptive-autonomy 文献都已经选择“什么时候由谁做”。候选只有在状态、行动、标签和终端结果均无法由这些方法原样覆盖时才有新能力。

第四组观察 coding-agent 使用、失败与人类行为。Anthropic 的大规模会话分析、AIDev 纵向研究和 coding-agent failure studies 表明专家能力、人工纠正与实际失败都重要，却不识别委派导致的能力变化。它们可用于外部效度、行为先验与任务抽样，不能训练候选的因果转移或证明安全收益。

剩余交集因此被严格限定为：**repo-obligation-conditioned、facet-specific real participation、separately anchored latent human capability、future residual duty，以及 delayed executable incident recovery 的联合学习与行动。**

## 3. 理论责任与同构反证

### 3.1 原理论实际说了什么

Rinta-Kahila 等人把技能分为陈述性知识与程序性知识。其三类 mindful-conduction facet 是工作者有意识参与任务的方式：

- activity awareness 指对具体程序的注意，可通过亲手执行、研究或监督另一个行动者的执行来维持程序性知识。
- competence maintenance 指更新或复习完成任务所需的领域知识，主要是陈述性的。
- output assessment 指审查和验证工作产物，主要调用陈述性判断与解释。

原文的系统动力学链是，任务负担提高 automation reliance；自动化的可靠性、复杂任务处理能力与解释功能也可能提高 reliance。持续 reliance 带来个人和组织 complacency，complacency 减少 mindful conduction，长期缺少 mindful conduction 使知识无法获取或保持并导致技能停滞或侵蚀。技能又是积累历史的 state variable，会影响系统之后的行为。原文同时说明解释功能可能支持 mindful conduction，因此 reliance 与 mindfulness 不是简单互斥开关。

原研究不能承担三项更强主张。它没有证明三类 facet 就是三个可独立测量的技能因子，没有估计某个具体参与动作对下一时点能力的平均因果效应，也没有证明 output assessment 会独立生成一种与陈述性知识不同的“恢复技能”。它的实时纵向观察、细粒度行动状态和管理机制效果都被作者列为未来研究。

### 3.2 必须分开的四类状态

候选若把三 facet 直接写成 `skill=[awareness, competence, assessment]`，就错误地把活动分类变成心理能力分类。任意 generic knowledge tracer 或 POMDP 都可以旋转或置换这三个 latent dimension，模型输出不会改变，理论也没有产生不可替代的表示。救援版必须保留以下分离。

| 状态 | 含义 | 监督锚点 | 不允许的替代 |
|---|---|---|---|
| `X_t(v,f)` | 开发者在义务节点 `v`、facet `f` 上真实发生的参与与暴露历史；`f∈{activity-awareness, competence-maintenance, output-assessment}` | IDE/terminal/patch/test trace、独立提交的计划或可执行约束、执行时间、修改归属 | 自报“我看懂了”、打开过 diff、收到过解释 |
| `K_t(v,k)` | 人在节点 `v` 上的潜在能力；`k∈{procedural, declarative, incident-recovery}` | 无 agent 的关键步骤执行、API/不变量迁移题及可执行实现、延迟事故隔离与恢复 | 把三 facet 名称直接作为三个 head；自我效能问卷；agent 对人的评分 |
| `U_t=(L_t,C_t)` | automation reliance 与 complacency loop；`L_t` 是相关义务由 agent 接管的比例与路径，`C_t` 是对能力或输出风险的低估倾向 | 受控无 agent probe、信心—表现差、主动核验省略、agent 失败后行为；只作有噪观察 | 用 agent token 数代表 complacency；把 reliance 当成 skill 的反号 |
| `D_t(v,k,h), R_t(v)` | 在未来时距 `h` 对该能力的事故需求、损害严重度与人的 residual responsibility | 维护者预注册的 on-call/ownership/恢复义务、版本路线、incident family 的基率与严重度；实验中由任务设计冻结 | 从未来隐藏事故反向泄漏；把所有技能永久设为必需 |

`incident-recovery` 是 coding-safety 的任务能力，不由三 facet 理论直接命名。它必须由延迟、独立、可执行恢复任务锚定。理论只允许提出，程序性与陈述性能力是恢复能力的前因，facet-specific participation 会随时间改变这些能力；恢复能力是否形成可分离因子、怎样从两类知识迁移，必须由测量模型和干预数据检验。

### 3.3 可检验的 MEC→MAP→ALG 链

**MEC。** 在人仍承担未来恢复责任的代码义务上，持续 agent 接管会提高 reliance。可靠的短期产出可能使开发者低估自身知识缺口和输出风险，减少 activity awareness、competence maintenance 与 output assessment。长期缺少这些活动会使相关程序性与陈述性能力难以维持，进而降低未来独立事故恢复表现。若 residual responsibility 为零或技能已经不再需要，技能侵蚀不构成本研究中的损害。

**MAP。** 算法必须分别表示义务结构 `G`、facet-specific participation `X`、可锚定潜在能力 `K`、reliance/complacency loop `U`、未来需求与残余责任 `D,R`。理论方向只施加在有原文依据的路径上：activity-awareness exposure 对程序性能力的平均转移不得被先验设为负；competence-maintenance exposure 对陈述性能力的平均转移不得被先验设为负；output-assessment exposure 对陈述性验证能力的平均转移不得被先验设为负。原文没有支持一个固定一一映射矩阵，交叉迁移、效应大小、恢复能力转移和个体差异都必须从随机数据学习。

**ALG。** 策略不是挑一道题给开发者。它在真实开发任务中选择义务节点、参与 facet、行动形式和时点，使开发者对高残余责任、高未来事故需求且正在衰减的能力执行真实工作，同时让低责任、低需求或已经充分掌握的义务保持 agent-only。训练目标直接约束延迟事故损害、初始任务成功、人类时间和 agent 成本。

### 3.4 理论方向冲突

理论必须在相同表面风险下改变选择，而不是只提供解释。

1. 两个节点当前任务难度和 agent 可靠性相同。节点 A 的开发者仍承担下季度 on-call 与回滚责任，节点 B 已永久移交且没有残余职责。策略应在 A 保留真实参与，在 B 允许 agent-only。
2. 两项行动占用相同人力时间。一个开发者近期频繁阅读说明，却从未亲手执行关键迁移；另一个亲手改代码，却从未独立构造验证证据。前者应获得 activity-awareness 的执行动作，后者应获得 output-assessment 的证据构造动作。单一“人类参与分钟数”无法作出该区分。
3. agent 输出解释可以同时提高理解机会和 reliance。若开发者已经表现出高信心—低独立表现，继续给解释并不等于 mindful conduction；策略应要求其独立产生可执行步骤或证据。
4. 同一节点当前无事故，但距上次独立恢复已很久且未来需求高，策略应安排间隔式恢复演练；若需求低且责任已移交，则不应为了学习而打断生产任务。
5. 当前人工执行可能提高学习却增加即时高风险操作错误。策略应在隔离环境中让人完成关键步骤或演练，并让 agent 承担生产执行，而不是机械地把高风险动作交给能力不足的人。

### 3.5 同构反证与理论撤销条件

通用 Transformer、graph Transformer、knowledge tracer 或 POMDP 在获得完全相同的图、历史、行动和结果后，原则上能够逼近同一策略。候选不能用“通用模型理论上也能表示”以外的空泛说法保护自己。必须完成以下同构反证。

- **facet permutation。** 在训练集内打乱三 facet 名称但保留每个动作、总时长和结果。若延迟恢复与 OOD 表现不变，三 facet 没有算法责任。
- **one-dose collapse。** 把 `X_t(v,f)` 压成一个总参与剂量。若等参数模型不劣，facet-specific MAP 应撤销。
- **latent rotation。** 让等参数状态空间模型自由旋转 `K`。若程序、陈述与恢复 anchor 不能固定坐标，skill heads 没有测量效度。
- **matched-versus-mismatched intervention。** 在同一节点、相同时间预算下，随机分配与当前能力缺口匹配或不匹配的真实参与动作。若两者对对应能力转移和延迟恢复没有可区分影响，理论映射不成立。
- **loop deletion。** 删除 reliance/complacency 路径，只用 exposure history 直接预测能力。若 prospective policy 与机制结果均不劣，反馈环只是叙事包装。
- **residual-duty deletion。** 删除 `D,R`，只按技能最低处干预。若策略不改变或安全—成本前沿不劣，必要技能边界没有进入算法。
- **equal-parameter generic alternative。** 给无理论标签的 graph-temporal encoder + belief-state POMDP/CQL 同样节点、原始行为、参数量、训练样本、action mask 和预算。只有理论结构在参与预算有限、跨仓库或长时距 OOD 下改善延迟事故结果，且中间状态通过独立锚定，才可保留“理论驱动算法”贡献。

如果通用替代复制全部能力，本文仍可能贡献一个真人纵向 benchmark，但不再满足本项目对独立理论算法论文的要求，应从三篇系列中撤销。

## 4. 工件规格

### 4.1 仓库—补丁—轨迹—义务图

每个任务构建异构时态图 `G_t=(V_t,E_t)`。节点至少包括文件、函数或类、API、数据 schema、配置、测试、构建步骤、部署步骤、回滚动作和组织定义的运行不变量。边包括调用、数据流、依赖、共同修改、test-covers、build-before、deploy-before、rollback-of、violates/guards-invariant 和 recovery-dependency。patch hunk、agent tool call、命令结果和开发者动作作为带时戳事件连接到相关节点。

图不是因为理论天然要求 GNN，而是 coding-agent 风险对象确实跨越具体代码义务。若去掉图后只剩“用户做过多少次练习”，候选会退化为一般自适应学习。图抽取可使用静态分析、构建与测试追踪、版本历史和维护者确认；LLM 只能生成待核候选边，不能提供最终 obligation truth。所有实验图必须在隐藏事故标签封存前生成，防止从 future failing test 反推关键节点。

### 4.2 输入、张量与输出

令 batch 为 `B`，截断后的节点数为 `N`，历史窗口为 `T`，facet 数为 3，skill anchor 数为 3，未来时距桶数为 `H`。

- 图编码 `H_G∈R^{B×N×d}`，由 relational GNN 或 graph Transformer 生成。
- 参与张量 `X∈R^{B×T×N×3×q}`，`q` 包括动作类型、独立程度、正确性、耗时、agent 可见程度和是否形成可执行产物。
- agent/repository event tensor `Z∈R^{B×T×m}`，含 patch、tool trace、test state、任务阶段、模型可靠性与变更规模。
- 能力后验 `q_φ(K_t)=N(μ_t,diag(σ_t^2))`，其中 `μ_t,logσ_t²∈R^{B×N×3}`。
- reliance/complacency belief `U_t∈R^{B×N×2}`，与 `K` 分开；这里 `B` 只表示 batch size。
- 需求张量 `D∈R^{B×N×3×H}`、残余责任 mask `R∈{0,1}^{B×N}` 和预期损害 `W∈R_+^{B×N×H}`。
- 动作 mask `M_A∈{0,1}^{B×N×A}` 限制哪些参与动作可在当前 sandbox、时间预算和安全条件下执行。

推断输出不是一个 skill score。策略输出 `π(a,v,f,τ|belief,G,M_A)`，同时给出行为策略支持度、延迟事故价值分布和约束违反概率。低支持或高不确定状态回退到预注册安全分配规则，不允许模型以不确定为由把所有任务交给人。

### 4.3 能力状态与转移模型

基础编码器先用图上的可执行义务预训练。随后采用 graph knowledge tracing / action-conditioned state-space model 更新能力后验：

`K_{t+1}=F_θ(K_t,H_G,X_t,a_t,Δt,U_t)+ε_t`。

`F_θ` 由 relational message passing、temporal Transformer 与 action-conditioned transition head 组成。真实随机行动的 propensity 进入 doubly robust transition loss，避免把“能力高的人更愿意参与”误当成参与效果。没有被随机或有充分重叠支持的动作—状态区域不得外推 policy value。

理论约束采用软单调与符号违例惩罚，而不是伪造确定效应。对有直接依据的平均路径，加入：

`L_dir = ReLU(-∂K_proc/∂X_activity) + ReLU(-∂K_decl/∂X_competence) + ReLU(-∂K_decl/∂X_assessment)`。

这个约束只在义务仍相关、行动成功且测量可靠的支持域内施加。恢复能力、交叉 facet 迁移和不同时间尺度没有理论固定符号，由数据学习。另设 `L_decay` 校准无参与时随时间的转移，但不预先强迫所有节点同速衰减。

### 4.4 训练损失

状态模型的联合目标预注册为：

`L_state = λ1 L_anchor + λ2 L_next-action + λ3 L_incident + λ4 L_graph + λ5 L_DR-transition + λ6 L_dir + λ7 L_cal + λ8 L_KL`。

- `L_anchor`：无 agent 的程序步骤、陈述迁移和恢复任务的可执行正确性负对数似然。
- `L_next-action`：下一次独立关键步骤、约束实现或证据构造结果，用于稠密 knowledge-tracing 监督。
- `L_incident`：延迟 containment、rollback、hidden-test success、residual harm 与 time-to-recovery 的多任务 survival / ordinal / Bernoulli 损失。
- `L_graph`：义务边预测和局部—跨节点对比预训练；不得使用隐藏事故边。
- `L_DR-transition`：基于随机 propensity 或已验证 overlap 的 doubly robust 行动转移损失。
- `L_dir`：理论支持路径的方向违例。
- `L_cal`：Brier、ECE 或 survival calibration 损失，使策略能使用风险分布。
- `L_KL`：状态空间正则，不承担理论方向。

每一项在验证集单独监控。若 `L_dir` 只改善训练拟合而不改善独立 anchor、方向冲突或延迟恢复，应删除并触发理论门复审。

### 4.5 保守离线 RL / POMDP

先用随机化、安全受限的探索策略收集真人轨迹，再训练 conservative offline RL。可实现为 recurrent POMDP belief encoder 加 CQL/IQL；论文必须同时比较二者，不能把选择某个 RL 名称当贡献。回报由真实外部结果构成：

`r = u_initial-task - α·delayed-residual-harm + β·delayed-recovery-success - γ·human-minutes - δ·agent/compute-cost - ζ·initial-delay`。

安全约束至少包括初始 hidden-test success 下限、实验 sandbox 之外零写入、单参与动作人时上限和策略相对 behavior support 的 divergence 上限。用拉格朗日约束或 distributional risk objective 控制 CVaR residual harm。离线策略通过 OPE 只作筛选，最终效果必须在新的参与者和仓库上随机比较 learned policy、强基线与预算匹配策略；不能把离线估值写成安全改善已经发生。

### 4.6 推断时真正执行的动作

动作必须嵌入真实任务，并留下可执行产物。

1. **预测并提交关键下一步。** 开发者在 agent 揭示前提交下一关键 edit/command 及其前置条件；系统在 sandbox 验证其可执行性，再由人或 agent 继续。自由文本猜测不计入有效参与。
2. **执行关键步骤。** 开发者亲自在隔离分支完成一个高义务中心度的 patch、迁移、配置或回滚步骤，并运行规定检查。
3. **落实 API 或不变量。** 开发者把理由转成类型约束、contract、assertion、property test、migration guard 或机器可检查的 acceptance condition；仅解释 API 含义不算动作完成。
4. **独立构造结果证据。** 开发者在看不到 agent 自证摘要和隐藏 oracle 时，编写并运行能够区分修复前后状态的测试、health check、rollback check 或因果诊断命令。
5. **间隔式恢复演练。** 在与早期变更图相连但具体故障隐藏的隔离副本中，执行真实 containment、诊断、回滚与恢复；它同时生成训练标签和能力保持行动。
6. **agent-only。** 当 residual duty 为零，或能力已校准且未来需求低、参与成本超过收益时，由 agent 完成任务。该动作保证模型不会通过强迫所有人手工工作获得表面安全。

提示、解释和界面只负责让动作可执行，不是算法贡献，也不作为主要处理。

## 5. 真人纵向数据与任务对构造

### 5.1 数据为什么必须自建

SWE-bench Verified、SWT-Bench、SWE-EVO、EvoCode-Bench、AIDev 和真实 incident corpus 可提供仓库、patch、测试、长时版本和自然行为，却没有同一开发者在随机参与条件下的能力转移与延迟恢复。把 AIDev review 行为、SWE-bench gold patch 和另一数据集的事故外键拼接，会产生不存在的联合总体。候选需要新建真实开发者纵向数据；用户已允许严谨自建训练情境，因此“当前没有现成数据”本身不是 NO-GO。

### 5.2 两时点成对任务

每个 episode 包含两个严格隔离的阶段。

**`t0` 初始变更。** 固定版本的 coding agent 在容器中完成一个真实 repo-level change。参与者按随机策略在若干义务节点执行不同 facet 的真实行动。初始任务有公开说明和开发测试，但 hidden tests、未来事故和 gold recovery 均封存。所有条件使用相同 agent checkpoint、prompt 模板、token/工具预算与初始仓库。

**`t1` 延迟隐藏事故。** 7–14 天后，在 agent-unavailable 条件下给参与者一个与 `t0` 义务图相连、但不复述原 patch 和测试答案的事故。参与者必须在限定时间内隔离影响、形成诊断、执行修复或回滚，并用独立证据证明系统恢复。事故可以来自真实后续 commit/issue、维护者设计的语义等价 mutation、接口版本变化、隐藏异常输入或恢复路径破坏，但必须由不参与模型训练的维护者和测试作者验证。主研究还需在 28–42 天设置至少一次较长保持波次；若受试者只完成一次短延迟任务，论文只能研究近期保持，不能以“长期委派下的能力侵蚀”表述贡献。

一个有效 pair 必须满足：`t1` 确实调用 `t0` 所暴露的相关知识；不要求记住表面字符串；仅阅读最终 diff 不能直接复制答案；事故可在固定容器中重复；存在至少两条合理诊断路径；hidden oracle 能判定 containment、残余损害和恢复；任务难度在 pilot 中避免全对或全错。

### 5.3 参与者与随机化

可执行路线分两阶段。第一阶段招募约 24–36 名专业或高年级开发者，验证平台、pair 难度、动作接受度、观测可靠性和 7–14 日回访率。这个数量只用于可行性，不用于确证性机制结论。第二阶段根据 pilot 的 time-to-containment、cluster variance、attrition 和最小实践重要效应进行 simulation-based power analysis，预期需要约 120–180 名真实开发者、每人 4–6 个 episode，观察期跨越约 6–8 周，并包含 28–42 日保持波次；最终样本量与时距以公开功效和 attrition 模拟为准，不预先把该范围写成足够。

随机化在参与者×episode 内进行，并按经验、仓库、任务类型和初始无 agent anchor 分层。可采用 micro-randomized trial：在安全 action mask 内，按已知 propensity 随机 facet-matched action、facet-mismatched equal-time action、固定 agent-only 和固定 human-budget 对照。一个参与者不能同时看到同一 task family 的多个事故版本。随机策略必须保证每个拟学习动作在关键状态区间有支持，且不得把真实生产安全交给实验参与者。

### 5.4 监督与标签

| 标签 | 获得方式 | 不能使用的替代 |
|---|---|---|
| 初始任务成功 | sealed hidden functional tests、build、lint/type、state invariants | agent 声称成功、公开测试通过 |
| 程序性能力 | 无 agent 完成关键步骤的可执行结果、顺序错误、恢复所需操作 | 自报熟悉程度、代码阅读时长 |
| 陈述性能力 | 把 API/不变量迁移到新但等价情境并形成机器可检查约束；维护者盲评仅补充 | 选择题或复述 agent 解释 |
| 恢复能力 | 延迟事故中的 containment、诊断质量、正确 rollback/repair、恢复证据 | 即时 debugging quiz |
| residual harm | 事故期间被破坏的不变量数、错误状态持续时间、受影响节点/数据规模、错误修复新增回归 | 单纯失败次数或拒绝率 |
| 人力与成本 | active IDE/terminal time、干预次数、agent tokens、GPU/CPU、初始任务延迟 | 只报告主观 workload |
| reliance/complacency observations | agent 接管比例、主动省略核验、confidence-performance gap、失败后纠偏行为 | token 数等同 reliance、自信等同 skill |

问卷可以测工作负荷、信任和自我效能，作用只限于边界分析与操纵检查，不进入主要安全回报。

## 6. 划分、泄漏与隐藏测试隔离

1. 最终 test 同时按参与者、仓库 family 和时间分离。fork、共同上游、近重复函数与同一 issue lineage 归入同一 split。
2. `t0/t1` pair 是不可拆分的最小划分单元；同一 pair 的 mutation、事故叙述、gold recovery、测试 literals 和变体不能跨 split。
3. 模型输入、检索索引、图抽取和 agent prompt 均不得包含 `t1` incident text、hidden tests、gold patch、gold rollback、F2P/P2P 标识或测试作者说明。
4. 维护者在数据冻结前为每个 pair 生成 manifest：repo commit、container digest、许可证、task family、graph version、可见文件、sealed oracle hash、agent checkpoint、prompt、随机种子和 timeout。
5. 图提取器只在 `t0` 当时可见仓库与执行 trace 上运行。任何以未来 failing test 为依据补出的 edge 只能用于事后分析，不能进入训练或测试输入。
6. 基础模型污染通过任务时间、公开日期、近重复检索和 canary 检查记录。公开 gold patch 的 SWE-bench Verified 只适合开发与诊断；主结论优先使用冻结后的新构造任务或时间更新任务。
7. `t1` 时 agent 必须真正不可用，包括聊天、自动补全、检索摘要与后台生成。允许的文档、搜索和本地工具在各条件间一致并写入 manifest。
8. 数据分析者在主要清洗规则冻结前不知道 treatment 对应的 outcome 汇总。任务作者、干预实现者与 outcome adjudicator 分离。

## 7. 评价方案

### 7.1 预注册主要结果

共同主要结果应为：

- **延迟独立 containment/recovery。** 在限定时间内使损害不再扩大并恢复全部预注册关键不变量的比例；另用 survival model 报告 time-to-containment 与 time-to-full-recovery。
- **residual harm。** 用状态不变量违例的严重度×持续时间、受影响义务节点和新增回归形成预注册向量，不把它任意压成只对本模型有利的单分数。

关键次要结果包括隐藏功能任务成功、诊断路径正确性、错误 rollback/repair 数、初始 `t0` task success、人类 active minutes、初始交付延迟、agent token/tool calls 和本地计算。所有安全改善必须同时报告效率代价，绘制 harm–task-success–human-time Pareto frontier。

### 7.2 强基线与公平比较

| 基线组 | 具体基线 | 公平控制 |
|---|---|---|
| 固定分工 | all-agent、all-human、固定 supervised、每 `n` 次固定 rehearsal、随机参与 | 相同 agent、任务、总时限；另给 equal-human-minutes 版本 |
| 直接理论/调度 | Geometry 标量 skill–delegation policy、HAAS rule+bandit、在取得完整主文后复现 SymPareto 可适配版本 | 不夸大跨域复现；给相同可用状态和 action mask |
| adaptive support | Buçinca et al. offline Q-learning、contextual bandit、risk/current-error heuristic、uncertainty trigger | 相同 logged data、reward、action space和 OPE protocol |
| 学习保持 | SHIELD 式 concept-map/probe、固定 explanation、generation-then-comprehension、固定 spaced practice | 参与时间和 agent token 对齐；主要结果仍是 delayed recovery |
| 能力预测 | scalar BKT/DKT、graph KT+greedy、direct delayed-outcome predictor | 相同图或明确无图版本；不得给候选额外 hidden features |
| 最强同构反证 | 等参数 raw-history graph Transformer；等参数 unconstrained belief-POMDP+CQL/IQL；直接 policy network | 完全相同原始输入、图、参数量±5%、训练样本、随机搜索预算、seed 数、action support 与成本约束 |
| 上界 | oracle skill、oracle future demand、oracle incident family | 只作诊断上界，不进入胜负结论 |

比较不能只做一个低容量 LSTM 来衬托理论模型。调参在 participant/repo-disjoint validation 上完成；所有模型具有相同训练 rollout 和 prospective test 人数。API 模型调用按 token、tool call 和墙钟时间对齐，本地模型按 GPU-hours 与参数量报告。

### 7.3 消融、机制干预与替代解释

- 移除义务图，保留相同序列模型。
- 将三 facet 合为 participation dose。
- 打乱 facet label 与 action mapping。
- 将三 skill anchor 合为 scalar skill。
- 去掉 reliance、去掉 complacency、去掉二者反馈路径。
- 去掉 future demand、去掉 residual responsibility，或把所有义务设为需要保留。
- 去掉 decay/time-since-independent-action。
- 去掉 causal propensity/DR transition，仅用观察相关训练。
- 去掉 `L_dir`，或反转其符号作为理论中和。
- 去掉 conservative penalty/CVaR constraint，比较 OOD 与低支持行动。
- 状态模型冻结后用 greedy policy；policy 直接从 raw history 学习而无显式能力状态。
- 用 explanation-only 替换真实参与，用 equal-time mismatched participation 替换 matched participation。
- 分别中和 procedural、declarative、recovery anchor，检查恢复结果的具体退化路径。

机制检验的最低证据不是“attention weight 看起来合理”。要检验随机 action 是否先改变对应 `X`，再改变由独立任务锚定的 `K`，最后改变 `t1` executable recovery；报告 treatment×facet-match、time lag、residual-duty interaction 和中介不确定性。中介分析不得把未测量混杂假定成已经消除，micro-randomization 只识别有支持的近程行动效应，长程恢复仍需 prospective policy trial。

### 7.4 统计计划

主要分析使用多层 survival / generalized mixed models，participant、repo family 和 task pair 为随机或聚类层；报告绝对风险差、hazard ratio、标准化效应、95% 置信区间与校准区间。对 co-primary outcomes 预注册多重检验控制。对 attrition 报告各条件回访率、原因、Lee bounds 或 inverse-probability weighting 敏感性。策略评价同时报告均值、尾部 CVaR、最坏 task family 和 individual heterogeneity，不能只汇总平均技能或平均时间。

未运行实验前，所有结果表只保留空单元或 `[待运行]`。不得写“策略降低了事故损害”“facet-matched action 提高了恢复能力”或任何显著性数字。

## 8. 本地训练、工件与复现

### 8.1 预期训练工件

- versioned repo-obligation graphs 与 extraction manifests；
- `t0→t1` task-pair dataset、sealed-oracle hashes 与许可证清单；
- graph pretraining checkpoint；
- human-state graph KT / causal transition checkpoint；
- calibrated incident-demand model；
- conservative offline policy checkpoint 与 behavior-policy model；
- prospective trial assignments、propensity log、container rollout store；
- 数据字典、配置、随机种子、split manifest、环境 digest 和统计脚本。

### 8.2 算力估计

图编码与状态模型可在 1–2 张 24–48GB GPU 上训练，预计每个完整 seed 为数小时到一天；offline CQL/IQL 在已缓存图表示上可用单张 GPU。需要至少 5 个独立 seed，并为同构替代分配相同搜索预算。仓库构建、静态分析和 hidden incident rollout 更依赖 CPU、内存和容器并发，建议 32–64 CPU cores、128GB RAM 和数 TB 可版本化存储。若使用代码 encoder LoRA，限定为 7B–14B 开放权重并单独报告训练 token、GPU-hours 与 license；论文不依赖微调 frontier cloud LLM 才能成立。

真正的资源瓶颈是开发者招募、回访和任务维护，不是 GPU。若 pilot 显示完成一个有效 pair 所需人时使确证性样本无法在合理经费和周期内收集，必须撤题，不能以模拟人替代主要数据。

### 8.3 复现边界

公开版本至少提供可再分发仓库的任务、生成脚本、容器、图与去标识 trace。无法再分发的源仓库只提供取得脚本、commit hash 和许可证说明。参与者数据需去除身份、自由文本秘密与组织特征，skill state 不得提供给雇主作绩效排序。模型卡明确它只支持能力保持与实验性工作分配，不用于解雇、晋升或强制监控。

## 9. 与 C3 的边界

| 维度 | C3 固定批准点可信取证 | C15 能力保持 |
|---|---|---|
| 决策时点 | 外部 gate 已决定必须人审之后 | 正常开发和长期委派过程中，未来事故发生之前 |
| 人类状态 | reviewer 对当前 canonical action、risk 与证据的 purpose-relative grounding | 开发者对仓库义务的可执行程序、陈述与恢复能力，以及长期参与历史 |
| 模型动作 | 选择下一后果探针、证据子集、呈现顺序、clarification/repair | 选择真实工作参与、独立证据构造、间隔恢复演练或 agent-only |
| 主要结果 | 当前 unsafe approval、safe approval、审核时间和证据成本 | 数日后 agent-unavailable 的 containment、residual harm、recovery、隐藏任务和人时 |
| 禁止侵入 | 不决定长期技能保持 | 不决定当前是否批准，不优化 reviewer persuasion，不选择 approval evidence presentation |

C15 的“独立构造结果证据”是开发者亲自生成机器可执行验证物，以维持 output-assessment 能力；它不是由 agent 在批准点挑选证据说服审核者。若研究把行动改成 agent 主动运行 test、选择证据并改善当前批准，就与 C3 重叠。若 `t1` 事故改成审核者阅读 agent 解释并判断是否接受，也与 C3 重叠并失去独立恢复结果。

## 11. 硬 NO-GO 门与阶段判定

### 11.1 文献与直接覆盖门

1. 在冻结题目前仍未取得并阅读 SymPareto 完整主文，或主文显示其已经包含真实人类、细粒度 task graph、长期 skill transition 与类似事故结果。前一种情况不得宣称完成直接工作终审，后一种情况直接撤题。
2. 新检索发现工作已在 coding-agent 情境用随机真实参与、repo-level latent skill 和延迟 executable recovery 训练同类策略，且候选只增加理论命名或图 encoder。
3. 候选的新颖性最终被表述为防止 deskilling、动态委派、Pareto 调度、offline RL、spaced practice、knowledge tracing、concept map 或 adaptive autonomy 中的任一单项。

### 11.2 构念与识别门

4. 三 facet 被实现为三个普通 latent head，缺少独立 `X` 与 `K`，或 latent rotation/permutation 后结果不变。
5. procedural、declarative 与 incident-recovery anchor 在 pilot 中不能形成可区分、可靠且非表面记忆的测量；恢复能力若不是可分离状态，可以合并为终端结果，但若合并后理论算法只剩 scalar skill，应撤题。
6. equal-time matched 与 mismatched participation 对对应能力转移没有方向差，或者理论支持路径的可信区间排除最小实践重要效应。
7. reliance/complacency loop 无法由独立观测区分，删除后状态和 policy 均不变。若论文仍把该环作为理论算法贡献，撤题；不能仅改名为 engagement。
8. residual responsibility 只能由模型从未来事故反推，无法在 `t0` 由组织角色、维护义务或任务设计外生冻结。

### 11.3 数据与实验可执行门

9. 无法构建不泄漏的 `t0 agent change→t1 hidden incident` pair，或参与者只需记住原 patch 文本即可通过；任务 pair 不能用更多样本掩盖构造无效。
10. pilot 的事故过易、过难、容器不确定或 oracle 不稳定，使 containment、residual harm 或 recovery 不可重复判定。
11. 7–14 日回访、28–42 日保持波次、每人多 episode 和专业开发者招募在合理预算下不可完成，确证性样本只能靠学生即时 quiz、LLM 模拟人或合成 confidence 代替。
12. 随机 exploration 在关键状态—动作上没有 overlap，offline policy 主要选择日志中未支持动作；此时不得以模型外推替代真人数据。

### 11.4 算法与结果门

13. 等参数 raw-history graph Transformer 或 generic POMDP 在 participant/repo/time-disjoint prospective test 上复制延迟恢复、安全—成本前沿和 OOD 表现；理论结构没有独立、可锚定效用。
14. 改善完全来自更多 human minutes。与 equal-human-time、equal-action-count 基线比较后，不再降低 residual harm 或提高恢复。
15. 策略通过把所有高不确定任务交给人、拒绝 agent 行动或频繁打断获得安全；初始 task success、human burden 或交付时间越过预注册非劣界值。
16. offline OPE 看似提高但 prospective randomized policy trial 不支持主要结果，或尾部 harm 恶化。
17. 工件最终只剩提示、解释、quiz、UI、固定间隔提醒、规则路由或简单风险分数，没有可训练 graph transition 与 policy checkpoint。

### 11.5 系列边界门

18. 模型开始决定批准点是否执行、选择哪些证据说服 reviewer 或以 unsafe approval 为主要结果，立即并入 C3，不再作为独立论文。
19. 模型的核心动作变成事故发生后的机器自动诊断、回滚或补偿，而非事故前的人类能力保持，则需与状态迁移/恢复类候选重新审查，不能沿用本理论包装。

## 12. 阶段计划与当前证据边界

### 12.1 设计冻结前门与未来实证假设必须分开

用户允许严谨自建训练情境，也允许在实验尚未运行时写预注册设计和结果占位。因此，下表两列不能混为一谈。

| 设计冻结前必须已经满足 | 允许留到未来实验检验 |
|---|---|
| 取得并读完 SymPareto 主文，完成所有最强直接工作交集审查 | coding agent 的长期委派在本样本中是否实际导致能力下降 |
| 从原文确认 facet 是参与活动，另行定义并以可执行任务锚定 procedural、declarative 与 recovery state；不得先把三 facet 当 skill heads | facet-matched action 是否比 equal-time mismatched action 产生更大的对应能力转移 |
| 至少在无训练的 task pilot 中证明 `t0/t1` pair 可运行、oracle 可重复、答案不泄漏、事故确实依赖相应义务 | reliance→complacency→参与减少的各条路径效应是否显著、效应多大 |
| 给 residual responsibility 一个 `t0` 可见、外生冻结的来源；明确过时或无责任技能允许 agent-only | 三类能力是否保持完全可分离，恢复能力如何受程序/陈述能力中介 |
| 真人纵向招募、回访、随机化、action support、伦理与隐私方案在合理预算下可执行；不能计划用 LLM 模拟人替代 | graph KT/causal transition 是否在 OOD 上优于 direct predictor |
| 同参数 generic graph-temporal POMDP、TOCHI offline RL、Geometry、HAAS、SHIELD 与 SymPareto 适配基线的比较协议已经冻结 | learned policy 是否降低 delayed residual harm、提高 recovery，效应是否达到最小实践重要值 |
| C3 边界、hidden-oracle 隔离、participant/repo/time split 和结果占位语言已经冻结 | 哪类开发者、仓库、facet、时距或事故 family 获益最多，以及长期 field effect 是否持续 |

左列任一项无法满足，说明研究对象、识别或直接工作边界尚未成立，应在跑大样本前改判 NO-GO。右列出现零结果不表示研究设计事先无效；它们是需要诚实报告的预注册经验命题。只有在完成足够功效、有效操纵和可靠测量后，关键右列命题仍失败，才按照第 11 节的实证撤题门处理。当前 CONDITIONAL GO 不假装这些效果已经存在。

**阶段 A：文献和测量冻结。** 取得 SymPareto 主文；为三类能力设计独立可执行 anchor；完成开发者访谈与认知走查。通过条件是 facet 与 skill 不混淆，任务作者能在不知道 treatment 时判定结果。

**阶段 B：task-pair pilot。** 先不训练 policy，只验证至少两个语言/仓库 family 的 `t0/t1` pair、容器、隐藏 oracle、时距和参与动作。通过条件是任务可靠、回访可行、matched/mismatched 行动产生足够行为差异且没有答案泄漏。

**阶段 C：随机探索与状态模型。** 收集真实 micro-randomized trajectories，训练 graph KT/causal transition，完成 latent rotation、facet permutation、loop deletion 和 equal-param direct predictor。未通过任何核心机制门即停止。

**阶段 D：离线策略与 prospective trial。** 在冻结日志上训练 CQL/IQL/POMDP，先做 support 和 OPE 检查，再在新参与者、仓库和事故 family 上随机比较。只有 delayed containment/recovery 与 residual harm 在人时和初始任务约束下取得预注册效果，才可把候选升级为正式论文。

当前没有实验数据，不报告任何效果、显著性或已训练 checkpoint。本文所有模型与实验内容均是终审后的可执行研究设计，不是已经发生的结果。

## 13. 最终判定

### CONDITIONAL GO

本题比普通“AI 导致 deskilling”更接近一篇独立的 coding-agent 广义安全论文，因为它把损害落在未来 agent 失败或不可用时的真实事故处置，把训练单位落在 repo/patch/trace/obligation graph，把行动落在真实开发参与，把结果落在隐藏容器中的 containment、residual harm 与 recovery。Rinta-Kahila 等人的案例还明确留下了实时纵向行动、状态转移和技能管理机制的研究空白；现有随机 coding-skill 研究、adaptive support、HAAS 与 SHIELD 均没有填上这个完整交集。真实开发者数据可以在隔离、授权的任务对上合理构造，尚无数据或正结果不构成当前自动撤题理由。

但理论算法责任仍然脆弱。三类 mindful-conduction facet 是活动而非 skill heads；原文只支持部分 facet→程序/陈述知识方向，不支持完整三维因果转移。通用 graph temporal POMDP 也具有同构复制能力。候选能否达到 ISR 级别，取决于真实随机数据能否固定能力坐标、验证 facet-matched transfer、证明 reliance/complacency 与 residual duty 提供独立决策价值，并在等参数 generic alternative 与最强直接基线前改善延迟事故的安全—效率前沿。

因此，本题现在只获准进入受控 pilot，不占用正式三篇题位。完成第 11 节全部硬门后可以升级为 GO；任何构念、直接覆盖、数据可执行或同构反证门失败，应诚实改判 NO-GO，不能用更多模块、更多公式或教学界面挽救。
