## 3. 广义安全与 coding-agent 独特性

### 3.1 安全对象是真实的

本题最强的一面是安全结果不需要借“安全”标签制造。风险发生在 agent 执行迁移计划、扩大新版本流量、停止同步、收缩旧 schema 或提交 cutover 的时点。潜在受害对象包括持久数据、旧版和新版应用、依赖数据库的组织流程与终端用户。行动前可观察信号包括 schema/code dependency、lock、lag、version traffic、mismatch、validation coverage、resource pressure 和 recovery checkpoint；未来 workload、潜在数据异常、部分故障及未运行计划的结果不可见。可执行结果可以同时报告：

- source/target row 与 domain invariant 是否保持；
- old/new application 对同一 hidden workload 的语义输出是否一致；
- error rate、SLO breach duration、failed requests 与 blast radius；
- 实际 access event 是否越出 permission manifest；
- 从 checkpoint 恢复并重放后能否满足 RPO/RTO 和旧、新 contract；
- matched task success 与 matched cost 下 harm 是否下降。

这些结果比拒绝率或静态风险分类更接近广义 operational safety。即使没有恶意攻击者，错误迁移也能造成不可逆组织损害。因此，本题在“是否有真实 broad-safety harm”这一门通过。

### 3.2 coding agent 的必要性没有被核心算法证明

01D 把 repository–schema graph、telemetry、action history 作为输入，并要求输出 SQL/code/config diff。这使完整系统可以是 coding agent。然而，当前主要理论工件只消费编码后的图、时间序列和 typed action，核心动作可以由固定 catalog 给出。删除 code generator 和 `L_exec` 后，`Q^0/Δ/I/P/J/O`、world model 与 MPC/IQL 仍原样工作。换言之，论文的主要因果主张目前是“在线迁移 controller 更安全”，不是“coding agent 因理解并修改 repository 而获得一种普通 DBA controller 没有的可靠行动能力”。

强协议进一步放大这一问题。pgroll 已负责 old/new schema coexistence、backfill、write propagation、complete 与 rollback；gh-ost 已负责 copy、binlog apply、pause/throttle 与 postponed cutover。在这些底座上，学习器最常输出的是 `continue/pause/validate/complete/rollback` 和少量数值参数。若 repository 代码语义不改变这些选择，coding-agent 身份只是外围接口。若允许模型自由生成新 SQL、trigger、dual-write code 和 compensation，动作空间与 oracle 又会迅速超过可执行 counterfactual coverage。01D 尚未解决这个二难。

## 5. 公开底座与 same-start counterfactual truth

### 5.1 可运行性不是绝对障碍

用户允许自建训练情境。利用 PostgreSQL snapshot、容器化 old/new application、pgroll/自定义 migration substrate、固定 workload generator、fault injector、semantic verifier 与 reset manifest，机械上可以执行同一初始状态的多个计划。BullFrog 和 Tesseract 还提供 schema-evolution artifact 或 workload 参考；DBA-Bench 证明 active PostgreSQL、persistent state、snapshot reset 与 outcome-first verifier 可以被组合；BranchBench 证明 agentic branch–mutate–evaluate 基础设施正在成熟。因此，不能仅因没有现成 `counterfactual migration lifecycle.csv` 判 NO-GO。

现有公开资产仍只分别提供 schema/change intention、固定 protocol、单一历史路径、运行底座或 verifier。它们没有同时提供：同一 pre-state、多个合法 plan、共同外生随机过程、完整 continuation policy、terminal harm/task/cost，以及可迁移到未见 repository 的 hidden semantics。该部分必须自建，工作量大但原则上可行。

### 5.2 01D 的 `Δ` 与 `J` 标签当前没有定义完整

令 `s0` 为 cryptographically hashed database/application snapshot，`ω` 为不向 agent 暴露的未来 workload arrival、client-version schedule 与 fault schedule，`π` 为执行首动作后的 continuation policy，`H` 为 wall-clock horizon。一个可识别的 sibling outcome 应写成

\[
Y^{a,\pi}(s_0,\omega;H),
\]

而行动效应只能相对于给定 continuation 定义为

\[
\Delta_t^{\pi}(a)=\mathcal D_{\omega}\!\left(Y^{a,\pi}\mid h_t\right)-
\mathcal D_{\omega}\!\left(Y^{defer,\pi}\mid h_t\right).
\]

01D 的 `Q(Y|do(a),h)-Q(Y|do(defer),h)` 没有写出 `π`。这不是符号美观问题。

- 若后续使用固定 `π_b`，标签只表示 `a` 在 behavior policy 下的效果。改变 planner 后，标签一般改变，不能被解释为 mitigation 的不变 impulse。
- 若后续使用各自最优 policy，`Δ` 就是标准 `Q*(h,a)-Q*(h,defer)` 或 advantage。它由 generic belief-MDP/POMDP 已经完整定义，不再是 Benaroch 独有状态。
- 若 `a` 是纯 validation/sensing action，它不改变 latent physical state。固定 continuation 下，它除成本外不改善 terminal physical outcome；其收益只来自 observation 改变后续 policy。此时 `Δ` 已包含 value of information，再增加 entropy-reduction head `I` 会把“获得信息”和“利用信息改变行动”混在两个相关监督中。
- entropy reduction 也不等于 decision value。揭示一个不会改变 cutover/rollback 选择的 hidden bit 可以大幅降 entropy，却没有行动价值。

`J(a,b)` 同样必须指定 `a`、`b` 的 duration、两者之间的 observation、后续 policy 和 horizon。若 action 持续时间不同，共享 wall-clock arrival schedule 会让两个 sibling 遭遇不同的队列和已完成请求；这是现实效应，但不能再把 event-indexed outcome 与 wall-clock SLO 混算。若为保证相同请求数改用 event-indexed schedule，又会扭曲真实 cutover 时钟。严谨环境可以选择 wall-clock semi-Markov 定义，但 01D 尚未作出选择。

### 5.3 pairwise interaction 不能承担完整 path dependence

Benaroch 附录对每条已部署 mitigation path 使用条件 impact/cost 参数。01D 用 rank-`r` 的 pairwise `J(a,b)` 近似。三项措施可能只有在特定前两项和当前 workload state 共同存在时才协同，二阶残差不能恢复三阶及更高 interaction。若再以 generic action-history Transformer 补足，理论 `J` 失去专属责任。若扩大到 full sequence tensor，样本数随动作和深度组合增长，公开 real-repository 情境难以覆盖。

### 5.4 无未来泄漏的最低实现条件

如果另案重做数据，至少要冻结以下 manifest，否则不能声称获得 execution truth。

1. snapshot 包含 database bytes、old/new application image、schema、traffic allocation、checkpoint 与 protocol phase，并以 hash 验证 sibling 起点一致。
2. 外生 workload/fault process 在动作前生成并隐藏；agent 只能看到当时 observation。future seed 和 sibling outcome 只用于训练标签或离线评价。
3. 使用 wall-clock semi-Markov 时间；每个 action 的执行时长、排队、资源消耗和其间 workload 暴露都进入 outcome。
4. 每个 paired label 明确 continuation policy、horizon 与 terminal/censoring rule。不能把不同 planner 产生的 continuation 混成一个 action impulse 数据集。
5. siblings 作为一组进入同一 split；generator template、repository、schema motif、workload family 和 fault family 均做 group/OOD 隔离。
6. semantic verifier、recovery oracle 和 target data contents 不进入 policy observation。oracle 只能在 action 后返回预先允许的 aggregate evidence。
7. action generator 不能同时写 oracle。free-form SQL/code 必须先通过 independent executor grammar、static validity 与 external semantic test。

这些条件说明“窄环境可自建”，也说明 01D 现有标签不能直接开工。数据问题本身不是终局撤题理由；它与理论冗余叠加后，使当前 pilot 没有可验证的独立理论目标。

## 6. Benaroch 全文忠实度审查

### 6.1 原理论真正研究什么

Benaroch（2018）的单位是一个具有不确定 payoff `P` 和 cost `I` 的可延期 IT/cybersecurity investment。管理者拥有改变投资进程的权利而无义务，passive deferral 允许等待新信息，并在 `P<I` 时避免投入。proactive mitigation 在延期期间以成本换取对 underlying investment-value distribution 的有利改变。原文明确区分：

- compound investment 的必经 stages，完成投资需要依序 exercise 全部阶段；
- investment 前零项或多项均可采用的 optional mitigations；
- passive wait 与 active learning/prevention/coping；
- mitigation 对分布参数的离散 impulse；
- 不同 sequence 下 cost 与 impact 的 substitutive、complementary 或 synergetic conditionality；
- 到期时 exercise 或不 exercise investment 的 option value。

原文的 applied case 估计 annual loss expectancy、frequency/loss magnitude、payoff/cost volatility 与 mitigation impacts，并以 option/lattice valuation 比较 mitigation combination。它没有提出 repository graph、telemetry encoder、distributional MPC、belief state、entropy head 或 typed SQL executor。

### 6.2 01D 的映射越过了理论边界

| Benaroch 构念 | 原文责任 | 01D 映射 | 红队判断 |
|---|---|---|---|
| underlying asset/value | 投资 payoff `P`、cost `I` 与 `V=P-I` 的随机分布 | 八维 harm/task/cost vector `Y` | 多目标约束控制不是 option value；未给出风险偏好、scalar value、discount 或 exercise payoff |
| defer option | 等待外生信息，并可在不利时不投资 | pause/继续观察 migration telemetry | 若目标迁移必须完成且 abort 计 task failure，管理者没有真正 non-exercise alternative |
| optional mitigation | 投资前零项或多项可采用；与必经 stage 明确不同 | validation、dual-write、backfill、rollback reserve 等均被放入 option action | dual-write/backfill 对许多 online migration 是 constitutive protocol stage，不是 optional mitigation |
| learning | 改善对 payoff/cost 或 uncertainty source 的认识 | entropy reduction `I` 与 `Δ(Y|do(validate))` | 前者是 generic belief update；后者取决于后续 policy，二者不是两个独立物理效应 |
| prevention/coping | 分别改变事件频率与事件后损失 | `Pevent` 与 `Qseverity|event` heads | 是标准 hazard/loss factorisation；Benaroch 没有规定神经 head 或 exclusive role，实际 action 也常同时作用两者 |
| path dependence | sequence-specific impact 与 cost parameter | pairwise low-rank `J` | 只是二阶近似，不能代表任意 sequence conditionality |
| exercise boundary | 基于 option value 在 expiry 前 defer/mitigate，随后 exercise 或放弃 | risk-constrained MPC/IQL 选择 cutover | 当前 planner 没有 Benaroch lattice 或 option exercise recursion，仍是 generic constrained control |
| flexibility state | right, not obligation；到期、投资与 mitigation cost | old path、checkpoint、slack `O` | 主要是 Cordon/DART/transaction runtime 已有的 recoverability/commitment state |

01D 第 5.5 节已经承认原文对象不是数据库 controller，却随后称 Benaroch “产生” `Q^0、Δ、I、Pevent、Qseverity、J、O`。更准确的引文责任应是：Benaroch 支撑 optional mitigation、distributional impact、conditional sequence 与 exercise valuation；这些神经张量均是 01D 作者的设计推论。尤其 `Q^0/Δ` 是 action-conditioned outcome distribution，`I` 是 belief statistic，`P/Q` 是 hazard factorisation，`J` 是代数残差，`O` 是环境 recoverability state。它们没有一个由原理论给出独有的张量形式或前向方向。

### 6.3 预注册方向也不是 Benaroch 独有方向

01D 的四个冲突情境分别要求低 coverage 时追加 validation、高 write intensity 时考虑 dual-write、recovery severity 高时保留旧路径、tail divergence 上升时不扩大 canary。这些都是 value of information、systems backpressure、recovery planning 和 tail-risk control 的常规方向。

Benaroch 第 6 节还给出一个与 01D 直觉不同的重要敏感性结论：在其模型中，baseline investment uncertainty 越大，单个 proactive mitigation 相对 passive deferral 增加的净价值可能越小，因为单纯等待可以截断更多 bad tail。该方向依赖真正的 passive information arrival 和 non-exercise option。01D 的“tail uncertainty 高所以更愿意支付主动学习成本”并非由该理论自动推出。若 migration deadline 使 passive wait 不产生新信息，这恰好说明 real-options setting 没有成立，而不是理论支持另一方向。

## 7. 同信息通用模型的精确冗余证明

### 7.1 现有 heads 是可逐头置换的

把 01D 的理论模型写成

\[
z=E_{\theta}(R,G,X_{1:t},A_{1:t-1}),
\]

\[
H_{\theta}(z,a)=
(Q^0,\Delta,I,P^{event},Q^{severity},J,O,p(s_{t+1})),
\]

以及

\[
\mathcal L_{T}=\sum_{r\in\mathcal R}\lambda_r
\ell_r(H_{\theta,r},y_r),\qquad
a_t=\Pi(H_{\theta},\mathcal A_t).
\]

构造一个“匿名因子 world model” `G`。它使用相同 encoder、相同 head 数量与形状、相同 action history、相同 paired siblings、相同 labels、相同 loss weights、相同 planner 和 executor，只把输出名改为 `u1,…,u8`。取任意置换 `σ`，令

\[
u_{\sigma(r)}=H_{\theta,r},\quad
y'_{\sigma(r)}=y_r,\quad
\Pi_G(u)=\Pi_T(\sigma^{-1}u).
\]

则对任意输入、任意参数与任意数据集，两个模型的 forward output、loss、gradient 和实际 action 完全相同。若初始化也按该置换耦合，训练的每一步均同构。这不是“无限数据下 Transformer 有普适逼近能力”的宽泛反驳，而是有限样本、有限算力下的精确参数重命名。因此，01D 所希望检验的 sample-efficiency/OOD advantage 在这个最强公平替代前没有可产生差异的计算位置。

### 7.2 多个 heads 还是 full world model 的派生量

若 generic model 已预测完整 `p(s_{t+1},Y|h,a)`，则：

- `Q^0` 是 `defer` 条件下的 rollout distribution；
- `Δ` 是两个 action-conditioned rollout distributions 的差；
- `Pevent` 与 `Qseverity|event` 是同一 outcome law 的普通分解；
- `J` 是两个或多个 `Δ` 的代数组合；
- `I` 由 belief/observation kernel 的 posterior entropy 计算；
- `O` 是环境版本、checkpoint、permission 和 deadline state 的子向量。

把它们各自加成 auxiliary head 可能改善优化或校准，但完全相同的 supervision 可以给匿名模型。若优势来自 theory model 独占 paired labels、role labels 或更多 loss terms，比较不公平；若通用模型也获得这些信息，模型又回到上一节的精确同构。

### 7.3 POMDP 已经原生包含三类作用

在标准 belief-POMDP/SMDP 中，sensing/learning action 主要改变 observation kernel 和 belief；prevention action 改变 transition/hazard kernel；coping action改变 event 后 transition 或 reward/loss；commitment 与 checkpoint 是 observable state；defer、stop、rollback 和 cutover 是动作。01D 使用 mixture role 允许一个 action 同时作用多个 kernel 后，与一般 controlled state-space model 更没有结构差异。Benaroch 的术语可以解释这些 kernel，却没有在现有算法中规定一个与 generic POMDP 相反或额外的运算。

因此，01D 自己第 14.2 节的两条撤题门已经在设计层面触发：理论 role 删除名称后模型和损失不变；G-WorldModel/G-POMDP 可以在相同信息下精确复制，而不只是未来可能经验上追平。

## 8. `Lattice-in-the-loop` 结构救援的独立审查

这一节审查的不是 01D 当前方法，而是一个可能的新方案：神经网络仅估计 mitigation impact/cost 参数，Benaroch 式 zero-or-more option lattice 或 semi-Markov dynamic program 真正执行 sequence 选择。

### 8.1 只有先收窄研究单位，理论对象才可能成立

主 migration protocol 必须由 pgroll/F1-compatible sequence 等底座外部固定。expand、建立同步、完成必要 backfill 和满足 target schema semantics 不得再称作 option。研究动作只能是 cutover 前确实可以做零项、做一项或做多项的安全措施，例如：不同覆盖/成本的 shadow replay、额外 semantic validation、延长 canary、增加独立 checkpoint/failback window，或对已经合法的验证器作条件组合。每一项不采用也必须仍存在一条合法的 target migration path。

还必须存在真实的 `abandon/non-exercise`。若“不 cutover”一律算 task failure，lattice 只是有 deadline 的控制器，不是 real option。可接受的 non-exercise 可以是保持当前稳定版本并取消本次 release，且其组织收益/机会成本被外部结果衡量。`defer` 期间也必须有独立于主动 action 的信息到达过程，例如自然 workload observation；否则 passive wait 只有成本，没有 Benaroch 所比较的 wait-and-see value。

### 8.2 一个可审计的新算法形态

可把 state 写为 `x_t=(b_t,p_t,c_t,r_t,τ_t)`，分别表示对 hidden migration condition 的 belief、已采用的 optional mitigation path、commit/recovery capacity、resource/cost state 和距 expiry 的时间。网络只估计以下参数及不确定性：

- defer 下的 passive observation dynamics；
- learning mitigation 的 observation impulse；
- prevention mitigation 对 event hazard 的 impulse；
- coping mitigation 对 conditional severity/recovery 的 impulse；
- path-conditioned `k(m|p)` 与 impact `η(m|p)`；
- exercise、abandon 和 failure 的外部 outcome distribution。

随后由硬 recursion 选择动作，而不是由 generic policy head直接给 action：

\[
V_t(x)=\max\left\{
V^{abandon}_t(x),
V^{exercise}_t(x),
V^{defer}_t(x),
\max_{m\in\mathcal M\setminus p}
[-k(m\mid p)+\mathbb E V_{t+d(m)}(x')]
\right\}.
\]

如果 harm 不能正当转换为单一 investment value，应在理论上明确采用 risk-sensitive utility/chance constraint，并说明这如何改变 Benaroch 原 lattice；不能一面使用任意 Pareto weights，一面声称复现 real-options valuation。训练时可通过可微 DP 或 parameter loss 学习上述参数，推断时实际执行 lattice 选出的 optional mitigation、defer、abandon 或 exercise。

相对相同参数量的 raw-history POMDP，这个结构确实可能带来非平庸的 finite-data/OOD inductive bias：它硬性保留 zero-or-more、expiry、exercise/non-exercise、action duration、path-conditioned cost/impact 和组合复用，不必为每个完整 sequence 单独学习一个 Q 值。一个普通 history Transformer 在函数类上可以表达最终 policy，却不与该 recursion 的参数和梯度天然同构。因此，不能在实验前仅以“POMDP 足够通用”否决这个新方案。

### 8.3 它仍可能退化为机械搬运或匿名同构

这个救援有三种失败方式。

1. 若只是把 Benaroch 的 spreadsheet/lattice 搬到若干手工 migration actions，参数仍由规则或专家给出，没有新的训练数据、参数估计和执行能力，它是理论应用或 decision-support demo，不是足以独立投稿的算法贡献。
2. 若所有 candidate action 都是固定协议的必经 stage，`max` 只在固定顺序上选择速度，理论对象再次错置。
3. 若一个匿名 constrained SMDP 使用相同 factor graph、相同 learned parameters、相同 recursion 与相同 utility，它当然可逐项置换并得到完全相同动作。这个模型已经复制了 option lattice 本身，不能拿来证明 theory model 具有不同函数类。论文最多主张“Benaroch 导出的结构偏置优于 raw generic control”，不能主张通用决策模型原则上无法表达。更关键的公平替代是：相同真实 state/action/time/masks、相同 distributional transition labels、相同 DP budget，但不使用 learning/prevention/coping impulse 和 option-specific path factorisation的 generic SMDP。

### 8.4 可识别的最小冻结规格与数据闭环

`Lattice-in-the-loop` 并非只要换一个 planner 名称就能冻结。一个可送预注册、但不预写任何结果的新设计，至少应把下面六部分锁成同一个 execution contract。

#### 8.4.1 研究单位和动作边界

研究单位应限定为：**一个目标 schema/data migration 已知、主兼容协议已经确定、系统尚处于可延期且可取消的 pre-cutover compatible state 时，是否以及按何顺序采用额外安全 mitigation。** pgroll 或等价底座负责 expand、old/new compatibility、必要 backfill、同步和最终 complete；这些构成阶段不进入 mitigation lattice。coding agent 的作用是从 repository、migration specification、telemetry 和工具反馈中形成当前 belief，并调用类型化工具执行可选措施。若删去 repository 与 migration semantics 后动作仍不变，实验只能声称数据库控制器，不能声称 coding-agent 机制。

最小 action grammar 可以包含以下五类参数化 operator。它们只是可冻结候选，必须在环境中逐一证明“不采用仍有合法 target path”，并由执行结果识别作用，不能按名称预赋理论 role。

| operator | 实际执行 | 可观察输出与代价 | 需要识别的 kernel 改变 |
|---|---|---|---|
| `shadow_replay(scope, window, rate)` | 在隔离 branch/shadow 上重放一段捕获 workload，不写生产库 | old/new result divergence、异常覆盖、耗时和算力 | 主要改变 observation likelihood，不应直接改善生产 physical state |
| `semantic_validate(invariants, sample, depth)` | 执行跨版本 differential query、业务 invariant 和 lineage check | pass/fail、coverage、counterexample、验证成本 | 主要改变 hidden-defect belief；不能用 entropy reduction直接充当行动价值 |
| `extend_canary(traffic, duration)` | 保持 compatible 双版本并延长受限真实或仿真流量观察 | tail workload coverage、lag/divergence、延期与暴露成本 | 可能同时改变 observation 与 exposure hazard，必须估计混合作用 |
| `create_failback_checkpoint(retention)` | 创建可核验 snapshot/WAL retention，并演练 restore | 恢复成功、RTO/RPO、存储与维护成本 | 在标准化失败发生后改变 conditional severity/recovery，不应被误记为降低事件频率 |
| `apply_temporary_write_cap(rate, duration)` | cutover 前暂时限制写入率或高风险写路径 | lag、冲突频率、SLO 降级和机会成本 | 主要改变 event hazard，同时可能改变正常任务效用 |

action mask 必须排除不合法组合。`create_failback_checkpoint` 可以被更新但不能无限叠加；`extend_canary` 和 `apply_temporary_write_cap` 有真实 wall-clock duration；验证器所读取的 snapshot/version 必须写入 path。至少三项 operator 要在不同 hidden condition 与既有 path 下产生 plan ranking reversal，否则 lattice 只是固定清单。

#### 8.4.2 四类选择的外部含义

- `defer(Δt)`：不采用主动 mitigation，维持 compatible state 并等待 `Δt`。在此期间系统从自然 workload、replication lag、divergence alarm 和旧/新客户端使用状态得到被动 observation，同时承担延期、双版本维护和 expiry 风险。若 defer 不产生任何新信息，它不具备 Benaroch 所需的 wait-and-see 含义。
- `exercise`：在外部 compatibility、data invariant、SLO 与旧客户端退出条件满足时执行 cutover/complete。它不是“模型预测安全”的同义词，成功和损害由隐藏测试、数据一致性与运行 oracle 判断。
- `abandon/non-exercise`：取消本次 release，保留或恢复旧稳定版本，不再追求本次 target migration。它应有可测的延期收益、release 机会成本和后续重做成本，而不是简单映射成一个巨大失败罚值。
- `mitigate(m)`：执行零项、一项或多项上述 operator。rollback 是 exercise 后的恢复动作时，不应混进这个 pre-cutover option set；pre-cutover checkpoint 只改变潜在 failback 后果。

只有在同一外部效用/约束下同时允许 exercise、defer 和 abandon，主动 mitigation 才能与 passive waiting 比较。若组织规则规定截止前必须 cutover，或取消发布永远记为零任务成功，则应诚实改称 risk-sensitive SMDP，撤销 real-options 核心理论责任。

#### 8.4.3 Semi-Markov 信息与后果过程

决策仅发生在 action 完成或预定 review point。令 decision epoch 为 `n`、真实 wall-clock 为 `t_n`、latent migration condition 为 `z`、外生 workload/fault path 为 `ω(t)`，状态为 `x_n=(b_n,p_n,c_n,r_n,τ_n)`。动作 `a_n` 持续 `d(a_n,p_n)`，期间产生 observation stream `o_{t_n:t_n+d}`，下一个 epoch 在 `t_{n+1}=t_n+d`。同起点 sibling 必须共享同一隐藏 `z` 与 wall-clock `ω(t)`，而不是因为某项验证耗时更长就把各 plan 的第 `k` 个 event 错当成相同未来。

网络只估计可由 intervention labels 监督的参数：被动和主动 observation kernel、事件强度或离散 hazard `λ_e(x,a,p)`、给定事件后的 severity/recovery distribution `F_e(y|e,x,a,p)`、action duration、resource/opportunity cost，以及 path-conditioned impulse/interaction。value of information 不另设 `I` head，而由 belief update 后的 lattice continuation value 内生计算。learning、prevention、coping 不是分类标签；它们分别是对 observation、event-frequency 和 conditional-severity kernel 的结构限制。混合措施可以作用多个 kernel，但必须由执行签名而非 action 名称识别。

配对标签写成 `Y^{a,π}(s_0,z,ω;H)`，必须声明 continuation policy `π`、wall-clock horizon `H`、censoring 和 terminal rule。纯 sensing action 的物理 impulse 在固定 continuation 下应接近零；其决策收益只能通过 observation 改变后续 lattice action 出现。coping effect 应在匹配或标准化注入同一事件后比较 conditional severity，prevention effect 则在共同外生 path 上比较 event occurrence。若没有 overlap/positivity，某个 path-conditioned 参数不得从观察数据强行识别。

#### 8.4.4 公开底座与严谨自建闭环

公开资产足以搭环境，但不会自动给出本文标签。最小闭环可把 PostgreSQL 与 pgroll 固定为 protocol substrate，用 pg-schema-diff 补充合法性与 hazard 检查，用公开 OLTP workload 生成可重复流量；从 pgroll 示例、F1/BullFrog/Tesseract 报告的 change motifs 和公开 schema histories 选取 change family，再自建可执行的 old/new application pair、业务 invariant 和 semantic oracle。DBA-Bench 的 snapshot/outcome-first 评价原则与 BranchBench 的 branch isolation 只能作为基础设施范式，不能被写成已经提供 migration counterfactual truth。

每个 episode 应从 content-addressed pre-cutover snapshot 启动。小规模 tier 对零项和所有合法短 sequence 作同种子枚举；较大 tier 用分层随机试验覆盖 action、path 与 hidden-condition overlap，并把未选 sibling 只保留为离线监督或 test oracle。manifest 至少固定 container/image digest、repository 与 schema hash、old/new binary、snapshot hash、action grammar/version、workload/fault wall-clock seed、latent defect injection、oracle version、action duration、continuation policy、horizon 和 terminal/censoring rule。planner 在推断时只能看到当前 history，不能读取 sibling future 或 hidden seed。

划分必须以 repository/application family、migration motif、workload regime、fault/latent-condition family 和 optional-action combination 成组隔离。验证集只调 utility/chance-constraint 与 stopping hyperparameter；测试集同时报告 harm、successful exercise/legitimate abandon、deadline、人工/计算/延期成本和 calibration。这样构造的数据可以支持预注册，并不要求先有现成公开 lifecycle dataset；但如果 executable oracle 只能覆盖固定协议已经保证的 trivial motifs，数据规模再大也不能形成独立研究空间。

#### 8.4.5 当前能否标为 DESIGN-FROZEN

**原则上可以。** 上述 SMDP、action signatures、hard lattice 和同起点执行闭环提供了一个不会因“实验尚未运行”而无法冻结的研究设计。其可检验主张应限定为：在相同数据、参数、transition supervision 与 planning budget 下，theory-derived option factorisation 是否改善有限样本、未见组合和 OOD 的 safety–success–cost frontier。结果仍然只能是预注册假设。

**截至本次审计不可以。** 01D 没有把任何 old/new application family、五类 operator 的 executable implementation、passive observation kernel、exercise/abandon payoff、continuation policy 和 episode manifest 固定下来，也没有给出哪个 action combination 能产生可核验的 ranking reversal。因此新构想当前状态是 `CONDITIONAL / NOT DESIGN-FROZEN`。只有 action/operator manifest、outcome-and-utility manifest、episode-and-split manifest、lattice-and-baseline manifest 四者同时落地并互相引用后，才可不依赖实验结果晋级为 `DESIGN-FROZEN / RESULTS PENDING`。

### 8.5 最窄 rescue 门

只有以下条件全部在一份新的 design specification 中成立，才可把另案标为 CONDITIONAL，而不是沿用 01D。

1. 固定主协议之外至少有三项真正 optional、可按不同顺序采用的措施；不同 state/path 下 plan ranking 必须理论上可能反转。
2. `abandon/non-exercise` 是合法组织行动，有可测收益与机会成本，不是简单给失败一个大罚值。
3. passive defer 有独立信息过程，且 expiry/commitment boundary 明确；否则 Benaroch 的 wait-and-see 与 act-and-see 对比不存在。
4. action duration、continuation policy、wall-clock workload/fault process 和 outcome horizon 全部冻结，从而识别 path-conditioned impact/cost。
5. learning、prevention、coping 参数有独立 executable signature；网络不能只从 action 名称获得 role。
6. lattice recursion 同时进入训练和推断，并在预注册冲突情境中改变实际 action。删除 exercise/abandon、打乱 path parameters 或把 impulse 改为 additive 后，应有明确行为差异。
7. fixed pgroll/gh-ost protocol、CAS/Kayenta、Hillenbrand adaptive migration、generic risk-sensitive SMDP、raw-history POMDP 和等预算 direct policy 均为强基线。
8. 在相同 transition/paired labels、参数、FLOPs 与 search budget 下，lattice 对 raw POMDP 和不含 option factorisation 的 generic SMDP 在低数据、长序列、未见 mitigation combination、repository/workload/fault OOD 上产生稳定的 safety–success–cost Pareto 改善。若优势只来自额外 counterfactual labels 或硬编码最优 plan，撤题。
9. 理论贡献表述限定为可检验的结构约束与组合泛化，不宣称一般 POMDP 无法表达。若 domain-only SMDP 在同样有限样本下复制结果，Benaroch 不再承担独立算法贡献。

这些门目前均未由 01D 满足。故 `Lattice-in-the-loop` 是另案救援条件，不是把本题改判为 CONDITIONAL 的现成依据。第 8.4 节说明了它在设计层面怎样形成闭环，也同时说明当前材料尚未达到 DESIGN-FROZEN。

## 9. 固定强协议支配审查

### 9.1 PostgreSQL 主场景中 pgroll 比 01D 估计得更强

pgroll 官方实现已经把 expand/contract 具体化为 virtual schemas、物理 additive changes、breaking-column replacement、automatic backfill、old/new 双向 write propagation、client-version coexistence、complete 与 rollback。其 `complete` 只应在旧客户端停止使用旧 schema 后发生，rollback 可移除新版本并保留旧版本。对这些支持的 change motifs，合法 path 不是待 learner 发明的变量。

pg-schema-diff 又覆盖 native low-lock plan、concurrent index/constraint、hazard warning 和 temporary DB validation。若任务限制在这些工具支持的迁移，学习器剩下的主要决策是 batch size、delay、额外验证、canary 时长和 complete 时机。Hillenbrand et al. 已经覆盖 schema/workload/SLA 下的 strategy/parameter adaptation，SOPHIA 与 DB2/SMART 类工作覆盖 workload-aware reconfiguration 和 throttling。ISR 论文必须说明为什么 Benaroch lattice 而非成熟 control/optimization 才解决剩余问题。

### 9.2 支持范围外又产生 oracle 二难

扩大到复杂 table split/merge、cross-service dual-write、semantic transform 或 free-form code patch，fixed protocol 不再完全支配，研究空间变大。然而这些任务需要跨应用行为等价、数据 lineage、partial failure 和 rollback semantics 的 task-specific oracle。Dynamite/Mediator 可以承担部分 mapping/equivalence，但不能自动给出每个 free-form multi-step plan 的全生命周期 truth。动作越开放，same-start sibling coverage 越稀疏，rare harmful exploration 越难安全执行。

因此存在一条明显边界：支持 motifs 上 fixed protocol 很强，learner 容易退化为调参；不支持 motifs 上 coding-agent 独特性增强，但反事实标签、oracle 和公平覆盖显著恶化。01D 用一个统一 action space 同时跨越两边，尚未给出能独立成立的中间范围。

## 10. I/O、tensor、loss、action、split、compute 与公平性审计

### 10.1 已经写清的部分

01D 已经明显超过提纲：它给出 repository–schema graph `G∈R^{B×N×dg}`、telemetry `X∈R^{B×T×F}`、action history、结果 quantiles、typed action、multi-loss、repository/schema/workload/fault splits、24–80 GB GPU 级资源估计、Docker/config/seed/manifest/checkpoint 要求，也承诺 matched task success 和 cost 下报告 harm。上述内容可作为新候选的工程底座，不应否认。

### 10.2 尚未冻结且会改变研究问题的部分

| 规格项 | 当前缺口 | 为什么不是普通实现细节 |
|---|---|---|
| input | `R`、graph node/edge schema、可见 target data aggregates 与 hidden condition 未给精确定义 | 决定 policy 是否利用 repository semantics，及 `I` 是否有可验证 latent truth |
| action grammar | 同时列 fixed typed action 和自由 SQL/code/config diff，候选 `M` 的生成与去重不明 | 决定是 coding agent、controller 还是 protocol selector，也决定 counterfactual coverage |
| time | Transformer time step、数据库 wall-clock、action duration、canary window 与 expiry 未统一 | `Δ/J` 和 option lattice 的比较都依赖 semi-Markov 时间 |
| output | `Q^0/Δ/P/Q/J/O` 同时含预测、派生量和环境状态 | 多头不等于多个不可替代理论状态；可能重复监督同一 outcome law |
| labels | information posterior、action role、interaction、terminal outcome 的 continuation policy 未定义 | 当前标签不是 invariant intervention truth |
| loss | 九项 `λ`、role mixture、policy loss在 IQL/CQL/AWBC/MPC 间未选 | 这些选择会改变主要工件、离线支持假定与公平基线，不宜在冻结后再定 |
| objective | 八维 `Y` 如何转为 policy utility、chance constraints 和 risk budget 未定义 | Benaroch 是 value maximisation；任意 scalarisation 会决定 exercise/cutover |
| train/test | group/OOD 思路正确，但 task generator、template leakage 和 paired group manifest 尚无实例 | 没有可审计 manifest 时无法判断真正 OOD |
| baseline fairness | 列表很强，但 modified-engine systems、MySQL gh-ost 和 PostgreSQL tools 的可比 task subset 未冻结 | 不能把不支持任务算 baseline failure，也不能借用更强 substrate 只给本模型 |
| compute | GPU 估计合理，database rollout 才是瓶颈；数千至数万 episode 的 reset/storage/rare-fault coverage 未测 | 不是自动撤题门，但在 open action space 下决定环境是否可运行 |

### 10.3 最强公平基线必须调整

01D 所列 raw Transformer 不是最强反证。对现有 heads，最强基线应是匿名多头 world model，获得完全相同的 paired labels 和每项 auxiliary loss，只删除 theory 名称。对 `Lattice-in-the-loop` 新案，基线应分成：

1. fixed protocol 与 fixed safety margins；
2. CAS/Kayenta-style metric decision；
3. workload-aware heuristic/PI/MPC controller；
4. Hillenbrand-style adaptive strategy；
5. raw-history distributional POMDP/SMDP；
6. 相同 domain state/action/time/masks 与 DP budget、但无 option-specific factorisation 的 generic SMDP；
7. 使用相同 estimated parameters 的 oracle/anonymous lattice，作为计算同构上界而非可被刻意削弱的 baseline；
8. same open-weight coding model、candidate generator、executor、approval 与 search nodes 的 direct policy。

未运行前所有结果栏必须留空。不能把“理论模型预计更节省样本”写成结果，也不能因 fixed protocol 在某些 unsupported task 无动作而宣称模型获胜。

## 11. 肖老师 ACAA/DSDL 的 MEC→MAP→ALG 标准

### 11.1 01D 做对了哪些句子功能

01D 已经有明确的 context、外部 harm、直接近邻 ACK、范围收窄、公开资产、数据边界、算法规格和撤题门。它没有把 F1、pgroll、gh-ost、CAS 或 Cordon 的能力据为己有；也明确把未运行结果写成预期。这符合 ACAA-I4 的“先承认直接文献，再限定其边界”和 DSDL-I7–I9 的“问题—表示—监督困难”推进。其第 13.3 节也正确区分了系统来源承担的事实、Benaroch 承担的理论命题和作者自己承担的 tensor mapping。

### 11.2 关键差距是 MEC 没有指出通用算法的错误计算方向

ACAA-T6a/T6b 先用 selection effect 与 preference differentiation 推出 semantic diversity，再明确指出普通 affinity compatibility 会聚集相似评论并制造 redundancy，因而算法必须改成寻找与 query 互补且 key 间不冗余的方向。ACAA-M10a/M10b 随后把 `key–key redundancy + inverse query matching` 写入公式，并给出可观察权重行为。这里的理论不是多加一个 attention head，而是把常规 attention 的计算方向改了。

DSDL-T2 则先定义 `E`、`F` 与有方向差，DSDL-M15–M18 把两个状态投到同一属性×时间坐标系并严格执行 `S=F-E`。交换顺序、取绝对值或混成一个 latent 后就不再是同一理论。DSDL-M19–M23 让该方向进入代理监督、稀疏约束、预测分支与联合目标；DSDL-E11–E14 又单独评估理论中间状态及双分支协同。

01D 的 MEC 是“朴素 controller 会把信息与保护混为一谈、把措施作用相加”。这一命题缺少直接 controller 文献证据，而且标准 POMDP 已经把 observation、transition、reward 分开，generic action-history model 也不要求 additive。MAP 随后列出的 `Q^0/Δ/I/P/Q/J/O` 没有一个改变通用计算方向：它们都是 action-conditioned distribution、belief statistic、hazard factorisation、interaction residual 或 runtime state。ALG 再把这些对象做成 heads 和 losses，只增加了显式监督，没有出现 ACAA 的“通用 affinity 在本机制下方向错误”，也没有出现 DSDL 的“理论规定不可交换的 `F-E`”。

### 11.3 逐项对照

| 肖老师主键与标准 | 01D 对应 | 红队结论 |
|---|---|---|
| ACAA-I3–I5：外部结果→ACK 近邻→机制缺口 | 安全 harm、协议/agent 近邻、信息/保护与 interaction | 前两步强；第三步把 generic controller 设成 additive/risk-score straw man，证据不足 |
| ACAA-I7–I8：每个理论机制先映射到独立 indicator，再出现 ALG | Benaroch 类别→多个 heads→world model | indicator 大多是通用 decision statistics，原文并未给出这些 neural objects |
| ACAA-T6/M10：理论指出 common attention 的错误方向并改计算 | 只声称 generic latent 可能有限样本较差 | 没有不可交换方向；匿名同头模型精确同构 |
| DSDL-T2–T7：构念、方向、粒度、冲突先于算法 | learning/prevention/coping、path interaction、cutover conflicts | taxonomy 存在，但高不确定性→追加验证并非 Benaroch 的稳定方向，且必经 stage/optional mitigation 混置 |
| DSDL-M15–M23：理论状态进入 forward、loss、output | 多头、多损失、MPC/IQL | 形式上进入，但 loss/heads 删除名称后不变；属于额外 supervision，不是理论计算 |
| DSDL-E11–E14：独立中间状态与机制消融 | 预注册 state error、neutralisation、generic slots | 评价意图正确；当前 labels policy-dependent，且最强 anonymous clone 没有行为差异可检验 |

### 11.4 引文责任边界

正式论文若沿用 01D，以下句子会构成过强引用：

- “Benaroch 产生 `Q^0/Δ/I/P/J/O`。”原文只支持 optional mitigation、distributional impulse、conditional path 和 option valuation；tensor 是作者设计。
- “高 tail uncertainty 时理论要求主动 validation。”Benaroch 的敏感性分析在其假定下可得相反的相对价值方向；数据库方向必须由新的情境机制和数据承担。
- “现有 controller 把所有措施独立相加。”F1/pgroll 固定协议不是 additive score，POMDP/SMART/SOPHIA 类控制也处理 conditional cost/transition；需要直接综述后限缩。
- “同起点 paired rollout 得到 mitigation causal effect。”只有在 continuation policy、time basis、horizon 和 hidden schedule 全部明确后才成立。
- “generic POMDP 只在无限数据下可以表达。”对现有 heads，匿名置换在任意有限数据下已经精确成立。

## 12. 终局撤题门与处置

### 12.1 已触发的决定性门

1. **构念错置。** 既定 migration 的构成阶段被并入 investment 前 optional mitigation；abort/non-exercise 与 passive information process 没有建立，real-options exercise setting 不完整。
2. **理论状态精确冗余。** `Q^0/Δ/I/Pevent/Qseverity/J/O` 与其 labels、losses、planner 可被同参数匿名模型逐头置换；有限样本和训练梯度也完全相同。
3. **行动标签当前不可识别为不变机制。** `Δ/J` 缺 continuation policy 和 semi-Markov 时间，纯 sensing action 的 physical effect 与 policy-mediated value 被混合。
4. **新增空间被强近邻压缩。** 支持 motifs 被 fixed protocol 控制，参数/strategy adaptation 又已有 Hillenbrand、SOPHIA、SMART/utility-control 类近邻。现有设计没有说明剩余能力为什么属于 Benaroch 而不是 generic control。
5. **coding-agent 身份不是核心机制所必需。** 删除 free-form code generation 后主要模型仍成立；开放生成后又缺可覆盖的 execution truth。

其中第 2 条单独已足以按用户规则判 NO-GO。第 1、3–5 条使继续按 01D 做 pilot 的机会成本更高。

### 12.2 不应采用的 rescue

- 不要只给 generic world model 增加 option score、entropy head 或 role classifier。
- 不要把 pgroll 的 expand/backfill/sync/rollback 改名为 learning/prevention/coping。
- 不要让 theory model 独占 paired sibling labels，再与只看单路径的 baseline 比 sample efficiency。
- 不要把更多 action、更多 loss 或更大 code model 当作理论不可替代性。
- 不要把候选降格为“迁移风险分类”“最佳 pattern 路由”后继续占 thesis 题位。

### 12.3 允许的唯一后续动作

若仍认为该领域值得保留，只能把第 8 节当作新的候选规格，从研究单位、action set、exercise/non-exercise、passive learning、SMDP time、parameter labels 和 lattice recursion 重新写起，并在任何大规模数据生成前再做一次独立红队。新方案在第 8.4 节的四份 manifest 闭合且第 8.5 节九项门全部有可执行定义之前，状态只能是 **CONDITIONAL NEW DESIGN / NOT DESIGN-FROZEN / 不占题位**；满足这些设计条件后可以晋级 `DESIGN-FROZEN / RESULTS PENDING`，无需把尚未运行的经验优势伪装成已证实结果。

对 01D 本身的终局处置是：**NO-GO / 撤销现有理论算法方案 / 不再以现有 heads 做 rescue。** broad-safety 现象和数据库实验底座可以留作其他候选的基础设施证据，但不能被计作本论文已成立的贡献。
