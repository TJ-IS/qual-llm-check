# 连续变更中的验证义务积累候选终审

> 审计冻结日：2026 年 8 月 15 日  
> 终局判定：**NO-GO / 不进入 thesis 主系列，也不保留为 CONDITIONAL 题位。**  
> 证据边界：本文件完成的是选题、理论、算法与可执行实验设计终审，没有运行候选模型或生成任何结果数字。下文的架构、损失、资源与实验均为反事实最强设计，不是已取得的发现。

## 0. 终局判定

连续 coding-agent 修改确实会产生一种重要而可测的风险。一次变更可以留下未执行的测试、只对旧依赖有效的检查、未重新验证的性质或已被后续修改削弱的证据。后续 agent 在这些状态上继续实现，可能让隐藏功能回归或安全回归跨任务累积，使最近的“绿色”快照不再是可信回滚基线，并把损害推迟到 release 才暴露。这个现象具有真实的广义安全后果，也能够在隔离仓库、固定算力和隐藏测试中构造可执行研究环境。

本题仍应撤销，原因不是“没有现成完美数据”，也不是“实验尚未跑出正结果”。用户允许严谨构造数据，下面给出的 matched-branch 执行设计在工程上可实施。决定性问题有三项。

第一，候选最窄的概念核心已经被直接工作明确表达。2026 年的 *Truth Stack* 匿名 workshop submission 把 consequential output 表示为包含行动、规格条款、证据和 replay recipe 的 decision object，并直接把 verification debt 定义为下游工作依赖证据已经因依赖变化或不再成立的假设而陈旧的 decision object；其建议又包括显式依赖图、证据重验证、债务预算与 risk-tiered gates。它没有训练控制策略，也没有完成 coding-agent 的纵向实验，但它已经占据“stale evidence—downstream dependence—debt compounding—revalidation/gate”这一现象和表示主张。候选不能再把 typed obligation graph、evidence validity 和高债务 gate 当作概念创新。[OpenReview forum](https://openreview.net/forum?noteId=kIOnjGRPYo)；[可检索 PDF](https://openreview.net/pdf?id=S7lsiMstIN)。

第二，候选想要控制的外部过程已被一组相互补足的直接技术工作覆盖。Regression Accumulation 已在八轮需求演化中测量旧行为丢失，并执行“旧测试检查—失败后回滚和重试”的 Verification Gate；StaminaBench 已把 coding agent 放入最长 100 次连续变更，用程序生成的黑盒测试反馈和 retry 直接延长无错生存期；ChainSWE 已揭示 earlier patch 的 overshoot/undershoot 如何污染后续 bug 的起点；SWE-Milestone、SWE-CI、SWE-STEP、SWE-Chain、SlopCodeBench 又分别提供 milestone DAG、连续 CI、连续 PR、发布链和自有代码继承的纵向环境。与此同时，DANTE、SIKG、既有 CI test selection/prioritization 和增量程序验证已经直接解决“有限预算下运行哪些证据、变更后重跑哪些检查”。将这些能力连接成一个多动作 controller 可能形成有用的 ICSE/ASE 系统，但在当前 Goal 的标准下，连接本身不足以构成 ISR 级独立题位。

第三，也是不可由扩大数据修复的问题，未找到能够拥有该算法的 AIS 理论。技术债务理论给出短期交付与未来偿还义务，temporal IS 给出多个时间视角和模型版本，organizational memory 给出获取、保留、维护、搜索与提取，信息处理观点给出需求与处理能力的匹配，real options 给出等待、主动学习和序贯 mitigation 的条件价值。它们都能改善问题表述，却都没有产生一种同信息、同动作、等参数 temporal graph model 或 POMDP 不能表示的状态变换。把 obligation、principal、interest、event time、observation time、staleness、option value 和 evidence budget 放入节点字段后，公平的通用模型可以使用完全相同的字段、边、执行反馈和风险约束，逐步学习相同策略。若不给通用模型这些输入，优势来自信息特权；若都给，理论专用计算不再不可替代。

因此，本题的诚实结论是 **NO-GO**。下文仍把最强可实现版本完整写出，用来证明撤题没有依赖“设计做不出来”这一错误理由，也为其他保留题复用纵向 benchmark、隐藏测试隔离和 release-level 指标提供边界清楚的技术资产。

## 1. 研究对象与安全边界

### 1.1 最强且不退化的研究单位

分析单位不能是一张 patch 或一次 verifier 判断，而应是同一可执行仓库从初始可信快照到一个或多个 release decision 的连续 episode。第 (t) 次变更前，coding agent 能看到当前仓库、历史 diff、公开需求、已登记的 evidence artifacts、这些证据上次运行的版本与结果、可见依赖关系、剩余测试/算力/时间预算和 release window。未来需求、未来 gold patch、隐藏测试内容及其结果均不可见。

一个“验证义务”在本候选中必须同时满足四项，不能由研究者写一句自然语言备注便算作真值。

1. 它对应一个可执行或可机器检查的 claim，例如旧功能不回归、输入校验仍成立、构建矩阵可通过、依赖升级不破坏接口、迁移脚本保持不变量，或安全扫描不出现特定高影响回归。
2. 它能链接到具体 code entity、requirement/invariant、environment/tool version 和 evidence artifact。
3. 它具有可观察的生命周期。后续变更可以使其从 open、partially discharged 或 discharged 迁移到 stale、invalidated、waived 或再次 discharged。
4. 它最终能由冻结 evaluator 中的执行结果判定，而不是由 LLM judge、风险分数或手工规则自证。

episode 中的 coding agent 是关键行动者。它产生代码、调用工具、选择是否继续实现，并在 controller 指令下运行证据、修复某项未满足义务、暂存或隔离一组修改、拆分 release、回退或停止。若算法只读取 commits 后预测“债务高低”，它会退化为时序分类器；若 controller 只在固定测试清单上做 top-k，它会退化为 CI test prioritization。本候选只有在改变连续 agent 的实际行动并以 release 后果计分时才保留其最强形态。

### 1.2 潜在损害、观察缺口与干预时点

风险发生在每次代码修改完成但尚未无条件合入可信 release baseline 的决策点。受影响对象包括后续维护者、依赖当前仓库的团队、最终用户、业务数据以及需要从最近“绿色”版本恢复的运维人员。主要损害是隐藏功能或安全回归进入 release、未发现错误在后续变更中扩大、可恢复快照被误判为可信，以及为修复累积错误付出额外延迟和算力。

agent 当时可观察的是当前代码和公开证据历史；不可观察的是未来需求、隐藏 oracle、所有潜在环境组合、某次通过是否因 test weakness 或 flakiness 偶然发生，以及当前欠下的验证工作会在什么未来路径上产生多大额外成本。证据也不是永续事实。代码依赖、编译器、第三方库、配置、fixture 或规格改变后，旧证据可能仍留在日志中，却不再支持当前 release claim。

算法介入点是每次 candidate change 产生后及 release boundary 前。最强动作集合为：

- `continue(change-request)`：让固定 coding agent 继续实现当前或下一变更；
- `acquire(evidence-id)`：执行一项尚未取得的测试、property check、build、analyzer 或隔离 workload；
- `revalidate(evidence-id | subset)`：在当前 code/tool/environment snapshot 上重放旧证据；
- `repay(obligation-id)`：向固定 coding agent 发出与特定义务绑定的修复任务并执行其 patch；
- `isolate(change-set)` 或 `stage(change-set)`：把高不确定修改移出当前可发布集合，保持可恢复分支；
- `split(release-partition)`：生成满足依赖闭包的可发布子集和延后子集；
- `stop/revert(snapshot-id)`：停止继续实现并回到已经由 evaluator 重新确认的快照。

安全改善不能由拒绝一切获得。主要比较必须同时报告 release escape、完整任务链成功、release delay、执行算力和 agent token/call 成本。永不发布可能使 escaped regression 为零，却会在任务成功和延迟上失败；每步运行全部测试可能安全但不满足预算效率。研究对象因此是风险、任务和成本的联合前沿，而不是最大化拒绝率。

### 1.3 明确排除

- 不研究一次 patch 是否安全的二分类，当前 patch residual defect 属于 C5/CodeMonitorBench 边界。
- 不研究由谁来验证以及独立 verifier 的 warrant，executor–verifier separation 属于 C14。
- 不研究固定升级点上的人类批准、证据展示或 reviewer grounding，属于 C3。
- 不把复杂度、耦合、重复和 system atrophy 当终局结果，属于 C10；这些最多是 world-model 输入。
- 不以 schema/data migration 的 shadow、dual-write、cutover 或 compensation 为动作语法，属于状态迁移候选；若 episode 包含 migration，只能作为普通变更类型，不能借其专用 real-options 机制补题。
- 不把测试数量、coverage、obligation-node F1、风险 AUROC 或 debt score 作为主要贡献证据。

| Bianculli et al., *Syntax-driven Incremental Program Verification of Matching Logic Properties*, arXiv:2606.08824 | 变更后只重新处理语义受影响的 code chunks，并实验比较 full re-verification | 证明“依赖变化使旧证明需要选择性重验证”已有 formal/incremental verification 路线 |
| Guan and Legunsen, *Instrumentation-Driven Evolution-Aware Runtime Verification*, ICSE 2025 | iMOP 在新版本只重插桩 changed code，复用旧版本 unchanged code 的 instrumentation，并重监测全部 specifications；官方摘要报告 14 种技术，在 48 个项目、1,627 个 revisions、160 个 specifications 上评价，最高比每次从头运行快 29.6 倍 | 跨版本复用旧验证设施、识别 change-affected work 和在 CI 成本内安全重验证已有 runtime-verification 实现；候选不能把“旧证据随变更失效”本身当算法贡献 |
| Jiang et al., *Fine-Grained Analyses for Evolution-Aware Runtime Verification*, ICSE 2026 | FineMOP 用细粒度分析减少对 unaffected specifications 的重监测；官方页面报告 68 个 Java 项目、1,104 个 revisions，最高少重监测 81.04% 的 specifications、加速 4.86 倍，并找到既有对照所发现新 violations 的 99.68%；还与 regression test selection 互补 | 进一步直接占据 dependency/change-aware evidence revalidation。typed obligation graph 若只做 affected-evidence pruning，与这条线的差异不足以支撑独立论文 |
| Lee and Böhme, *Dependency-aware Residual Risk Analysis*, ICSE 2026 | 以 coverage dependency 估计残余风险，并考察风险低于阈值时停止 fuzzing；官方摘要在 FuzzBench 软件上报告相对 GoTu 的估计误差和停止时间改善 | “依赖状态—残余风险—停止取得证据”的决策链已有直接实现。它不是多 commit coding-agent controller，却是本候选 stop action 必须超越的同动作基线 |
| Bubel et al. 2016, *Proof Repositories for Compositional Verification of Evolving Software Systems* 及更早 change-impact/proof-reuse 工作 | 缓存 partial proofs、维护 contracts 与 proof obligations 随实现/产品变体演化 | obligation、proof dependency、reuse 与 invalidation graph 不是 coding-agent 情境才出现的表示 |
| *TestEvo-Bench*, arXiv:2607.02469 | 当前快照从 152 个 Java 项目、59,950 candidate records 构造 746 test-generation 与 509 test-update tasks；显式使用 revision/time 形成 live、leakage-aware executable benchmark | 可训练生成/更新证据 artifact，但仍是 revision pair，而非 multi-release control policy |

DANTE 是 training-free，SIKG 只是 poster，Jamil–Nour 的 case 很小，formal verification 和 evolution-aware runtime verification 又只覆盖特定可执行规范；任何一项单独看都没有完成本候选。然而 ISR 选题的直接空间不能通过逐一指出每项局限，再把所有现有动作并入一个系统来制造。当前最强候选需要把 test selection、change impact、proof/evidence invalidation、runtime re-monitoring、technical-debt repayment、rollback 和 release split 一次性连接。其新增能力主要来自系统集成与更宽 action space，尚未由一种独有 IS mechanism 组织。

### 3.4 当前 patch verifier、monitor 和 benchmark hardening

Liao、Deng 和 Ren 的 CodeMonitorBench 从 71,000 个生成候选中得到 43,677 个 public-test-passing candidates，其中 23,081 个仍在 hidden tests 上失败；问题是在固定 public-check information boundary 下，弱 verifier 能否以低 false-positive rate 找出 residual hidden bugs。[arXiv:2607.20852](https://arxiv.org/abs/2607.20852)。它证明“公开通过不等于可发布”，也提供 current-patch residual defect baseline，但其 action 是 monitor 判定，不维护多任务 obligation stock。

*Hardening Agent Benchmarks with Adversarial Hacker–Fixer Loops* 使用循环攻击和修复扩大隐藏评测覆盖，[arXiv:2606.08960](https://arxiv.org/abs/2606.08960)。这条线说明 evaluator 本身也需要动态 hardening，不能把研究者写的 hidden suite 当完备 specification；但它不管理 release backlog。The Verification Horizon 同样要求 verifier 随生成器共同演化。二者进一步限制候选的证据声明：即使 obligation controller 在某个冻结 hidden suite 上降低 escaped regression，也只能证明对该 evaluator 的改善，不能声称消除了真实意图偏差。

## 4. 设计可行性与经验未证必须分开

### 4.1 设计可行：可以严谨构造，不因缺现成标签撤题

公开资源没有直接给出每一步“应该 defer、revalidate、isolate、split 还是 stop”的自然标签，但这不意味着不能研究。可以在版本化容器中对同一 pre-action snapshot 克隆多个分支，固定 coding model/checkpoint、prompt、tool policy、random seed、time budget 和 future task stream，让不同 action 在真实代码与测试上执行。动作后果由 clean evaluator container 的 hidden tests、wall time、resource counters 和后续 task outcome 给出。只要分支是实际执行而不是由规则打分，数据构造就是可接受的 sequential decision data，而不是提示词或静态 heuristic 蒸馏。

因此，**design-feasible = YES**。至少 ChainSWE、SWE-Milestone、SWE-CI、SWE-Chain、SlopCodeBench v2、StaminaBench 和 TestEvo-Bench 可以提供互补 substrate。研究者还可从公开 commits 构造严格的 chronological release episodes，只要完整保留 license、commit、container、test 和筛选 manifest，并让每个 episode 的未来需求和 hidden evidence 完全隔离。

### 4.2 经验未证：没有结果，不得写成“该机制有效”

当前没有运行以下关键比较：typed-obligation policy 是否减少 hidden regression 进入 release；是否优于 DANTE/SIKG/change-impact、全量测试和 generic POMDP；是否能在相同安全结果下降低 delay/compute；principal/interest 状态是否具备独立效度；release split 和 isolate 是否被正确学习。所有这些都是未检验设计主张。

**empirically-proven = NO**。这只意味着论文不能改用已完成实验的陈述语气，不构成当前 NO-GO 的理由。即使未来实验得到正结果，仍必须先通过理论不可替代与直接贡献门；否则它是一个强工程系统，而非本 Goal 所要求的 theory-driven ISR artifact。

### 4.3 可构造不等于可识别

三个标签风险需要单独处理。

第一，evidence validity 可以由旧 evidence 在新 revision 上实际重放得到，但“没有重跑时已经 stale”只是潜在状态。训练标签应记录 transition 与 survival/censoring，而不能把任何 touched dependency 自动标为 invalid。否则模型只是蒸馏 change-impact rule。

第二，debt principal 可以定义为从当前状态使特定义务重新 discharged 的实际最小或近似最小资源成本，debt interest 则是相对于 matched branch，延后该义务所增加的未来验证、修复和损害成本。二者都需要执行分支估计。若直接用未来 gold patch、future hidden-test content 或研究者预设 severity 生成标签，再不给 baseline 同样信息，就发生未来泄漏和 label privilege。

第三，`isolate/split/stop` 的好坏只有在后续 release execution 中才可比较。用“风险超过阈值则 stop”“依赖跨模块则 split”等规则生成 action label，本质是把手工 policy 蒸馏进网络。可接受的监督来自 randomized exploration、行为策略日志或同 snapshot 的 counterfactual branch return；不能来自候选自己的理论公式。

## 5. AIS Basket 理论终审

### 5.1 技术债务与 control balancing：相关但不拥有 agent policy

Ramasubbu 和 Kemerer 把 technical debt 定义为违反既定标准所形成的未来维护义务，并在 1,824 个 outsourced enterprise-system projects 中检验 control balancing。主文发现，control balancing 只在已识别长期 platform migration plan 的项目中促进 debt remediation；未出现此长期路径时，其关系反而为负。这项 JMIS 研究对候选有两项真实启发：更多控制或更多验证不必然更好；债务可见性、环境波动和未来工作路径会改变 intervention 的方向。[DOI 10.1080/07421222.2021.1870377](https://doi.org/10.1080/07421222.2021.1870377)。

它仍不能承担候选的 ALG。原研究的 unit 是 client–vendor project，control balancing 是 procedural/hybrid/social、tight/relaxed、unilateral/bilateral 控制配置的调整；它没有 evidence artifact、proof validity、test execution 或 release action。把“有 future dependency plan”编码成 graph fan-out，再把 control balancing 改名为 acquire/revalidate，只是跨层类比。agent policy 的动作方向来自执行环境的 expected return，而非原理论规定。

Haki 等人在 Credit Suisse 的 digital nudge clinical research 将 technical debt 管理写成 now-versus-later trade-off，强调目标是把债务控制在可管理水平而非清零，并报告一年的 field evaluation。[DOI 10.1080/0960085X.2022.2088413](https://doi.org/10.1080/0960085X.2022.2088413)。它可支持实践动机和“全测/零债务不一定最优”，但 nudge 面向团队意识与行为，不产生机器 action policy、obligation tensor 或 loss。

Woodard、Ramasubbu、Tschang 和 Sambamurthy 的 design capital 将 option value 与 technical debt 作为数字业务设计资本的两维，技术债务是行使未来设计选项所需的预期成本。[DOI 10.25300/MISQ/2013/37.2.10](https://doi.org/10.25300/MISQ/2013/37.2.10)。它能解释为什么当下未验证状态会压缩未来变更空间，却无法区分应运行哪个 test、哪个 proof 已失效或何时 split release。债务 stock、principal、interest 与 option value 都可以作为普通状态变量进入通用 world model。

Tiwana 和 Safadi 把 system atrophy 定义为代码库内部逻辑一致性的跨期衰退，并在 1,354 个系统、25 年 trace data 上连接 age、modularity、bugginess 与 developer disengagement。[DOI 10.1287/isre.2023.1218](https://doi.org/10.1287/isre.2023.1218)。它属于 C10 的决定性近邻，可作为 accumulated-state 背景；若把本题结果改成 code atrophy 或 complexity，就与 C10 重叠，仍没有 verification-action 算法。

### 5.2 Ariav 的 temporal structure：最贴近 evidence validity，仍是通用数据设计

Ariav 将 planning/control 视为 information-intensive memory processes，明确要求 temporally independent access、multiple time perspectives 和 temporally oriented model management。其记号区分一个变量适用的 period、在何时被知道的 “as-of” 视角以及随时间改变的 model (M)。[JMIS 9(2):77–98，DOI 10.1080/07421222.1992.11517959](https://doi.org/10.1080/07421222.1992.11517959)。

这是本候选最自然的 temporal mapping。一个 test 在 revision (r_e) 对 period/state (s_e) 产生结果，并在 observation time (t_o) 被记录；当前 controller 位于 (t)，tool/environment model 也已有新版本。若只保存 latest-pass bit，就把 event time、record time、applicability interval 和 model version 混成一项，系统会误把历史证据当当前保证。

然而，Ariav 原文提出的是 TOIS 的设计需求，不是验证义务理论。将四个时间字段放进 bitemporal node 能提升数据完整性，却没有给出 action preference 的稳定方向。一个 generic temporal graph transformer 获得同样的 `valid_from/valid_to/observed_at/model_version` 后可以执行相同 attention 和 transition。若这些字段只提供给 theory model，比较测得的是 temporal metadata 是否有用；若公平提供，Ariav 不再独占前向计算。因此它可以指导基础设施 schema，不能承担独立 ISR 算法贡献。

### 5.3 Organizational memory：维护失效证据的理论语言，不产生专用策略

Stein 和 Zwass 的 OMIS 框架以 acquisition、retention、maintenance、search 和 retrieval 五项 mnemonic functions 为底层，并特别指出 maintenance failure 会使决策依赖错误信息；knowledge maintenance 要处理新旧知识整合、selective forgetting 和 truth maintenance。[ISR 6(2):85–117，DOI 10.1287/isre.6.2.85](https://doi.org/10.1287/isre.6.2.85)。它还区分 semantic/episodic、declarative/procedural、过去/现在/anticipative memory，并讨论 design rationale 与 project memory。这些内容可自然说明为什么仅记录“测试曾通过”不足，证据必须保存情境、版本、结果和后续维护。

Bordetsky 和 Mark 的 memory-based feedback control 进一步让 groupware coordination 的 interdependencies、events、actions 和 effects 进入多层 organizational memory，并通过 feedback 支持协调。[ISR 11(4):366–385，DOI 10.1287/isre.11.4.366.11871](https://doi.org/10.1287/isre.11.4.366.11871)。其计算形状与候选 graph 更接近。

两项工作仍不能解决理论责任。五项 mnemonic functions 会自然变成 ingest/store/update/query/replay 五个系统 API，但 API taxonomy 不是学习机制。维护、搜索和提取的最优时机仍由一般 cost/uncertainty dynamics 决定。若把 organizational memory 作为 obligation graph 的名字，恰好触发用户要求的撤题条件。

### 5.4 信息处理观点：给出 capacity–requirement fit，不给出义务语义

Huang、Pan 和 Ouyang 基于 information-processing view，将 task uncertainty 分为环境动态性、任务互依和复杂性，并以 information sensitivity、synergy 和 fluidity 描述不同处理能力；其 Haier case 强调信息处理需求与能力匹配，以及增加处理能力本身有时间、精力和管理成本。[EJIS 23(4):462–480，DOI 10.1057/ejis.2014.4](https://doi.org/10.1057/ejis.2014.4)。

候选可以据此定义 verification demand (D_t) 与 executable evidence capacity (C_t) 的动态缺口：高 dependency fan-out、evidence invalidation 和 imminent release 增加需求，剩余 CPU/GPU/time/test parallelism 决定能力。这个 gap 能进入 policy，避免“债务数越多越优先”的粗糙规则。

问题是 (D_t-C_t) 仍是一般 resource-constrained planning state。相同依赖图、预算和 outcome trajectories 足以让 generic POMDP 学到它。理论也没有说明一项 security property、flaky test、build matrix 和 API compatibility obligation 应怎样 typed、怎样合成或怎样产生 release harm。它能够支撑组织动机和 cost trade-off，不提供不可替代 MAP。

### 5.5 Benaroch proactive real options：有最强方向冲突，也与状态迁移候选重叠

Benaroch 的 ISR 论文扩展 classic real options，使 zero or more proactive uncertainty-reducing mitigations 可以按不同顺序部署，并允许 substitutive、complementary 和 synergistic effects。mitigation 的 impulse 会改变 outcome distribution，其价值取决于此前 mitigation，因而具有 path dependence；原文又区分 learn、prevent 和 cope。[DOI 10.1287/isre.2017.0714](https://doi.org/10.1287/isre.2017.0714)。

在候选中，运行 diagnostic test 是 learn，隔离高影响 change 接近 prevent，保留 rollback baseline 接近 cope；全量验证可能因冗余出现 diminishing value，两个证据也可能互补。这个理论确实能导出比“债务越多越先偿还”更丰富的方向冲突。

它仍未通过两道门。其一，原理论对 mitigation distributional effect 的 factorization 可被同数据的 model-based RL/POMDP 直接学习。把每项 evidence action 的 mean/variance impulse、pairwise interaction 和 order history显式输入，只是一种样本效率 inductive bias。其二，状态迁移候选 `01D` 已把 Benaroch 用于 learn/prevent/cope、staged commitment、cutover 与 recovery。若本题也以该理论为核心，论文系列会出现同一 real-options 模板在两个序贯 controller 上重复使用；若通过 release split 和 rollback 强化差异，又会逐步并入状态迁移题。

### 5.6 理论终审结论

| 理论 | 可合法承担的责任 | 不能合法承担的责任 | ALG 判定 |
|---|---|---|---|
| Technical debt / design capital | now–later、义务 stock、未来变更成本、债务不必清零 | evidence validity、具体 revalidation、release partition | 背景/结果解释，不拥有算法 |
| Temporal IS | bitemporal evidence schema、model/version perspective | action value 与安全方向 | 基础设施设计，不拥有算法 |
| Organizational memory | evidence acquisition/maintenance/retrieval 与错误记忆风险 | 哪项证据何时运行、何时 stop | lifecycle taxonomy，不拥有算法 |
| Information-processing view | verification demand–capacity mismatch、互依/复杂性 | typed obligation semantics、policy factorization | 资源状态，不拥有算法 |
| Proactive real options | wait/act、learning impulse、sequence interaction、distributional effect | coding-specific obligation graph；相对通用 POMDP 的唯一性 | 最强但可复制，且与 `01D` 重叠 |
| Control balancing / digital nudge | more control can hurt、组织实施与意识 | autonomous agent action head | 实践机制，不拥有算法 |

没有一个理论同时给出本题需要的不可替代中间状态、方向关系、聚合顺序和行动约束。将多项理论拼成“debt + bitemporal memory + information capacity + real options”会得到一个词汇丰富的通用 belief-state controller，却不会得到更清楚的 kernel theory。理论数量增加反而使可证伪责任分散。

## 6. 最强反事实 MEC→MAP→ALG 及失败点

### 6.1 MEC：一般 coding agent 会系统性忽略什么

若尽最大努力救题，可以提出如下机制。普通 coding agent 和 single-patch verifier 将证据理解为当前 artifact 的即时属性；连续 release control 则需要把证据理解为有适用条件、有效期和依赖的 intertemporal claim。有限 verification capacity 使一些 claim 被有意延后。后续 change 增加这些未清义务的 principal，并可能通过 downstream dependence 产生 interest。证据动作不仅消费成本，还以不同强度、相关性和顺序改变对 release loss distribution 的认识；因此“运行最多测试”“只看最新失败”“只按当前 defect probability”都会在某些状态下系统性算错。

这段 MEC 由 technical debt、Ariav temporal structure、OMIS maintenance、information-processing capacity 和 Benaroch mitigation interaction 共同启发。问题也在这里暴露：没有一项理论单独拥有完整机制。现象真正的可执行内容主要来自软件测试、持续验证和 coding-agent benchmark，而 AIS 理论负责重新描述。

### 6.2 MAP：理论若成立应产生的中间对象

最强 MAP 是 typed obligation–dependency–evidence-validity graph $G_t=(V_t,E_t)$，附带 belief $B_t$ 与 budget $b_t$。

节点集合至少包括：

- code entity nodes：repository、package、file、class/function、config、dependency 与 deployment unit；
- requirement/invariant nodes：功能、安全、构建、兼容、性能、数据完整性与恢复 claim；
- evidence nodes：unit/integration/e2e test、property checker、static analyzer、build target、fuzz workload、runtime monitor 与人工冻结的 acceptance probe；
- obligation nodes：某 claim 在某 release scope 下尚未得到足够当前证据的 typed responsibility；
- change nodes：agent patch、repair patch、dependency/tool/environment update；
- snapshot/release nodes：staged、isolated、candidate、released、rolled-back 状态。

关系类型包括 `touches`、`implements`、`covered_by`、`depends_on`、`invalidates`、`revalidates`、`blocks`、`inherits`、`contained_in_release`、`causes_failure` 与 `rollback_to`。一条 `invalidates` 边必须来自实际 replay 或保守的待确认状态，不能把静态 change impact 当已发生失败。

节点矩阵可以写为 $X_t\in\mathbb{R}^{N_t\times d}$。每个 obligation/evidence node 的字段至少包含：type embedding、status、event time、observed time、valid-from/to、last-validated revision、tool/environment hash、evidence strength、flakiness posterior、execution cost/duration、harm criticality、reversibility、deadline、estimated principal 与 bounded interest。边张量为 $R_t\in\{1,\ldots,K\}^{|E_t|}$，时间差张量为 $\Delta T_t\in\mathbb{R}^{|E_t|\times q}$。belief $B_t\in[0,1]^{N_o\times c}$ 表示 obligation validity、failure type 和 harm bin 的后验，不把一个 risk score 压成二分类。

### 6.3 ALG：前向计算与行动

1. Temporal heterogeneous graph transformer 对 $X_t,R_t,\Delta T_t$ 做 relation-specific message passing，得到 code、evidence、obligation 和 release embeddings。
2. A survival/transition head 预测证据在下一 change 后继续有效、变 stale 或实际 invalid 的 hazard；link head 预测 change–evidence impact 与 obligation dependency。
3. Latent world model $p_\theta(z_{t+1},o_{t+1}\mid z_t,a_t)$ 预测 action 后 graph transition、evidence outcome、隐藏 regression distribution、repair duration、release delay 和 compute。
4. Dynamic action head 先选择 action type，再 pointer 到 evidence/obligation/snapshot/partition。`split` 使用 dependency-closed set decoder；不允许产生破坏 graph closure 的 release partition。
5. Constrained model-predictive policy 或 offline RL policy 在固定 horizon 内最大化 task/release utility，同时约束 escaped-harm 的 CVaR；executor 将选定动作真正提交给容器、版本控制或固定 coding agent。

一项可复现的联合目标可预注册为：

\[
\begin{aligned}
\mathcal L ={}& \lambda_{dyn}\mathcal L_{dyn}
+\lambda_{ev}\mathcal L_{evidence}
+\lambda_{surv}\mathcal L_{survival}
+\lambda_{link}\mathcal L_{impact-link}\\
&+\lambda_{harm}\mathcal L_{harm-NLL}
+\lambda_{cost}\mathcal L_{Huber(cost,delay)}
+\lambda_{bc}\mathcal L_{behavior}
+\lambda_{rl}\mathcal L_{CQL/IQL}\\
&+\eta\max\{0,\operatorname{CVaR}_{\alpha}(H_{release})-\kappa\}.
\end{aligned}
\]

理论专用版本还可加入 principal/interest consistency、bitemporal validity order 和 mitigation interaction losses，但这些辅助项必须由 executed branches 给真值，并与 generic model 使用相同监督。否则理论模型获得未来 return 的直接分解，baseline 只得到终局 reward，比较不公平。

### 6.4 MEC→MAP→ALG 为什么仍失败

这个闭环在工程上完整，却没有理论不可替代性。MEC 的关键陈述是 evidence validity 会随 change 演化以及预算造成时序权衡，二者在 Truth Stack、continuous verification 和 test-debt work 中已经直接出现。MAP 是异质时序图，SIKG、change-impact analysis、proof repositories 与 milestone DAG 已提供相邻结构。ALG 是 graph world model 加 constrained policy，是一般序贯决策方案。

更严格地说，令 theory model 为

\[
\pi_T(a_t\mid G_t)=h_{\psi}\big(f_{\theta}(G_t),\phi_{debt}(G_t),\phi_{time}(G_t),\phi_{option}(G_t)\big).
\]

若三个 φ 是固定 extractor，它们没有训练权重，公平 generic baseline $\pi_G$ 必须获得相同派生字段；此时把它们视为普通 channels 并复制 $f_\theta,h_\psi$ 即可逐点实现相同 policy。若 φ 是可训练模块，一个具有相同 relation heads 和 hidden width 的 generic graph transformer 可以把相同参数分区解释为普通 latent channels，模型类包含 $\pi_T$。若 theory model 进一步施加 sign、monotonicity 或 path-interaction constraints，generic baseline 也可在不引用理论名称的情况下获得完全相同约束。观察到样本效率差异可以支持 useful inductive bias，却不能证明理论产生 generic model 无法复制的能力。

这不是“神经网络理论上什么都能拟合”的空泛万能论证，而是同一输入张量、同一 action mask、同一参数块和同一 forward graph 的包含构造。候选因此明确未通过用户规定的等参数替代门。

## 7. 训练样本、标签与真实执行设计

### 7.1 episode 与 transition manifest

每个 episode 必须冻结：source benchmark/version、repository URL 与 license、base commit、chronological change stream、container digest、language/toolchain hashes、visible requirement、visible evidence inventory、hidden evaluator manifest hash、release windows、compute/time budget、coding model checkpoint、agent harness commit、prompt/tool policy、seed 和所有分支 parent snapshot。

训练样本单位为

\[
(G_t,H_t,b_t,a_t,y^{ev}_{t+1},G_{t+1},Y^{release}_{t:t+H},C_{t:t+H}),
\]

其中 $H_t$ 是到 $t$ 为止可见 action/evidence history，$y^{ev}$ 是实际 evidence outcome，$Y^{release}$ 是 evaluator-only 的未来 release outcome，$C$ 是 wall time、CPU/GPU seconds、container/test count、tokens 和 dollar-equivalent cost。模型训练可以使用未来 outcome 作 target，推断输入绝不能包含 future requirements、gold patch、hidden test code/result 或由其直接计算的标签。

### 7.2 数据源如何互补

- ChainSWE 提供真实 dependent bug chains、clean Docker evaluation 和 agent-self-state 与 oracle-state 对照。
- SWE-Milestone 提供 milestone DAG 与多语言连续软件演化，但需要核验每个 public artifact 的 v4 schema。
- SWE-CI 和 SWE-STEP 提供长 commits/PR histories 与持续回归检查。
- SWE-Chain 提供 release boundary 和继承自有 package state。
- SlopCodeBench v2 与 StaminaBench 提供可大量重采样的 hidden black-box iterative tasks，适合 policy warm-up 和 matched branches。
- TestEvo-Bench 提供 test creation/update 与 revision timing，可把“取得新证据”和“修复失效证据”变成真实 coding actions。
- CodeMonitorBench 只可作为 single-step residual-risk auxiliary corpus，不能与纵向 test chain 混在同一 test split 后声称 cross-release 泛化。

资源之间的 task ontology 不同，不能简单 concatenate。较严谨方案是先在 synthetic/procedural environments 学 dynamics，再在真实 repository chains 做 offline fine-tuning 和 held-out evaluation；报告每一数据源的独立结果，并把 repository-level external test 作为主要证据。

### 7.3 可执行标签

- evidence outcome：exit status、assertion-level result、coverage/mutation delta、analyzer finding、build matrix cell、flake posterior，均来自执行。
- validity transition：同 evidence recipe 在 versioned snapshot 上 replay；pass→fail、无法执行、semantic oracle changed 与 environment mismatch 分开标记。
- hidden regression：release candidate 在 clean scoring container 上违反此前或当前 hidden invariant；按 functional/security/data-loss/availability 等预注册 severity 分层。
- polluted rollback baseline：controller 选定的 last-good snapshot 在当前冻结 replay suite 或 earlier invariant suite 上失败。
- release delay：从 change arrival 到满足 release rule 的真实 wall-clock/normalized resource time；排队与执行分开。
- task success：整个 change/release chain 的 requirements satisfied，不用单步 pass 平均代替。
- principal：在已探索 repayment branches 中达到 discharge 的最小观测成本上界；不得谎称全动作空间全局最小。
- interest：defer 与 repay-now matched branches 的后续增量成本/损害分布；若无 matched branch，只能标 censored/unknown，不能用 heuristic 填补。

### 7.4 behavior policy 与 counterfactual coverage

初期数据不能只来自一个“合理”手工 policy，否则 offline RL 只能模仿它。需要混合 full-gate、no-gate、random-budget、DANTE/SIKG、change-impact、fixed debt threshold、myopic risk、truth-stack deterministic gate 和 exploratory policy，并在相同 snapshot 上对高分歧动作做 branch cloning。动作 propensity、可行动作 mask 与随机化概率进入 manifest，以便 importance weighting、doubly robust evaluation 和支持集检查。

当 `repay` 调用 coding agent 时，所有 policy 使用相同 generator checkpoint、token/turn limit 和 tool access。policy 只能决定目标义务和时机，不能让 theory model 使用更强 generator。`split` 和 `isolate` 由确定性 version-control executor 实施；dependency closure violation 直接判 invalid action，而不是由 LLM judge 修正。

## 8. 划分、泄漏与隐藏测试隔离

### 8.1 划分单位

1. whole chain/release 必须进入同一 split，不能把前几个 commits 用于训练、后几个 commits 当 test。
2. 先按 repository 和 upstream organization 隔离，再在训练库内部按时间划分；fork、package family 和复制仓库视为同组。
3. 进行 AST/token/test/problem-statement near-duplicate 检查，并对 SWE-bench family 共享源实例做 lineage dedup。
4. 主测试至少包含 unseen repository；有资源时增加 unseen language、unseen obligation type、unseen tool/environment shift 与更长 horizon。
5. benchmark live/versioned 资源必须写 snapshot date；SlopCodeBench 必须明确 v2 36/196，而不混用 v1 20/93。

### 8.2 信息墙

- gold patch、test patch、FAIL_TO_PASS/PASS_TO_PASS 具体内容和 future issue 只存在 evaluator namespace。
- policy container 不挂载 hidden tests、grader、未来 commits 或含答案的 git history；scoring 使用 fresh container 和只读 artifact channel。
- 检索索引只能由 train split 可见文档构建，不能索引整个 benchmark repository 的未来 history。
- principal/interest target 可在训练时由 future branch return 监督，但 raw future events 不进入 encoder；test 时不得在线更新到 hidden result 后再重算同一决策。
- 每个 pretrained code model 记录训练 cutoff 和已知 benchmark contamination；主结论同时在 cutoff 后任务或私有生成但可审计的 hidden instances 上复核。
- 任何 test-generation action 不得读取 gold patch；生成 test 后先冻结，再对 buggy/candidate/reference states 做三方 replay，以区分 discriminating、candidate-specific、regression-only 和 misleading evidence。

### 8.3 防止“标签特权伪装理论优势”

理论模型和 generic baseline 必须得到相同 raw graph、相同 derived timestamps、相同 debt/interest supervision、相同 future-return targets 和相同 action support。若 theory model 使用 manually typed obligation，而 baseline 只看 code tokens，主比较无效。可以另设 raw-only baseline测量 annotation value，但不能用它回答理论不可替代问题。

## 9. 外部结果、实验与统计

### 9.1 主要结果

主要结果必须直接来自 episode execution：

1. escaped hidden regressions per release，以及按预注册 severity 加权的 harm；
2. cumulative unresolved-harm area under the episode time curve，而非终点 debt count；
3. clean full-chain success 和 time-to-first-clean-release；
4. polluted rollback baseline rate，以及成功恢复到 verified snapshot 的比例；
5. release delay、wall time、CPU/GPU seconds、tests/probes executed、coding-agent tokens/calls；
6. 在相同 task-success floor 下的 harm–delay–compute Pareto frontier 和 hypervolume。

obligation status accuracy、evidence-validity AUROC/F1、impact-edge recall、world-model calibration 和 action imitation accuracy只能是诊断指标。即使它们上升，只要 escaped regression、chain success 或成本前沿未改善，就不能写安全贡献。

### 9.2 最强直接基线

- no verification / current visible tests only；
- every available evidence at every step，作为高成本安全上界；
- Regression Accumulation 的 prior-test Verification Gate + rollback/retry；
- StaminaBench-style test-feedback retry；
- static change-impact selection 与 incremental verification；
- DANTE、SIKG、代表性 ML TCP 及 LRTS heuristic；
- Jamil–Nour IBEA 式 feature-versus-test-debt multiobjective selector；
- Truth Stack deterministic high-debt gate、stale-evidence revalidation 和 risk-tier rules；
- current-patch residual monitor / CodeMonitorBench-style verifier；
- myopic expected-risk policy、fixed CVaR policy、model-predictive control；
- equal-parameter sequence Transformer、temporal heterogeneous Graph Transformer 和 latent POMDP；
- oracle future-test policy 只作不可实现上界，绝不与可部署方法并列宣传。

所有 policy 共用同一 coding agent、verifier pool、evidence inventory、branch budget、timeout、tool versions 和 release schedule。若某 baseline 原设计 training-free，不强迫其使用训练预算；同时报告 end-to-end compute，避免新方法通过昂贵 world model 获得不公平优势。

### 9.3 统计设计

在同一 episode/seed 上做 paired execution。escaped regression count 可用 negative-binomial 或 hurdle model；clean-release time 用 survival analysis；binary full-chain success 用 paired bootstrap、McNemar 或 hierarchical logistic model；连续 harm/cost 用 repository-clustered bootstrap。报告 effect size、95% interval、seed/repository variation 和 Pareto uncertainty，不只给均值。

预注册 noninferiority floor：task success 不低于最强可部署 baseline 超过允许界值，才能讨论安全改善。预注册 compute/delay budget；超过预算的 run 不能只删掉。多源 benchmark 以 repository 为随机效应，不把 thousands of transitions 当独立样本夸大显著性。

## 10. 等参数反证、方向冲突与机制干预

### 10.1 公平等参数反证

关键比较不是 theory model 对 raw-token MLP，而是：

| 维度 | Theory-factored model | Generic countermodel |
|---|---|---|
| 输入 | 同一 $G_t,H_t,b_t$ 与所有派生字段 | 完全相同 |
| 参数 | 固定总参数量、hidden width、relation heads | 相同总参数量与预算 |
| supervision | dynamics、evidence、harm、cost、future returns、debt bounds | 完全相同 |
| action mask | 相同 evidence/obligation/snapshot/partition candidates | 完全相同 |
| 特殊化 | 显式 principal/interest、bitemporal validity、mitigation interaction channels | 普通 learned latent channels，不使用理论标签 |
| 评价 | external release outcomes、OOD、sample efficiency、calibration | 完全相同 |

预注册 equivalence margin。若 generic model 在 escaped harm、chain success、delay/compute frontier 上落入等效区间，理论算法贡献撤销，即使 theory model 的中间 node F1 更高。若 theory model 只在小样本更快，应把主张降为 domain-informed inductive bias，仍不足以满足本 Goal 的“不可替代理论能力”。

### 10.2 能检验 policy 方向的冲突情境

1. 当前 open obligations 多，但 change 已隔离、可逆且无后续 dependency。debt-count gate 会阻止；合理 policy 应延后并继续低风险任务。
2. 当前单步 defect probability 低，但一个未重验证 evidence 覆盖高 fan-out core，且下一批任务依赖它。myopic verifier 会继续；跨期 policy 应先 acquire/revalidate。
3. evidence 最近通过，但其 tool、dependency 或 environment hash 已变。latest-pass heuristic 会信任；validity-aware policy 应重放或隔离。
4. 多个 stale tests 高度相关，一个较贵的独立 property check 信息增益更大。test-count/debt-count policy 会跑多项冗余测试；interaction-aware policy 应选独立证据。
5. release deadline 紧、change 低严重度且可独立 stage。full gate 会延迟全部；risk-aware policy 应 dependency-closed split。
6. high-impact irreversible change、evidence weak 且无法在 window 内补齐。task-value policy 会提交；安全 policy 应 stop/revert。

这些情境应由真实 branch execution建立，而不是用设计者规定“正确答案”。更重要的是，它们全部也是一般 POMDP 在 cost、reversibility、fan-out、deadline 和 outcome distribution 上会作出的选择；方向冲突证明需要序贯控制，不证明某个 AIS theory 不可替代。

### 10.3 机制干预

- shuffle obligation type，检验 typed semantics；
- shuffle dependency edges 但保持 degree，检验传播结构；
- reset evidence age 或交换 event/observation time，检验 temporal validity；
- 将 stale/invalidated/discharged status 随机化，检验 lifecycle；
- principal 与 interest 交换或置零，检验 now–later 分解；
- 打乱 mitigation order、删除 pairwise interaction，检验 path dependence；
- collapse outcome distribution 到 mean-only，检验 tail-risk/CVaR；
- 删除 world model、graph encoder、survival head、partition decoder，分别检验算法模块；
- 给 generic model 同样 state 后重复上述干预，判断行为变化是否为 theory-specific，而非任何模型都会使用的有效 feature。

理论中和后若中间 F1 下降而外部 release outcome 不变，理论机制没有行动责任。若 theory model 与 generic model 对干预反应相同，则 feature 有用但理论并不独占。

## 11. 本地算力、训练工件与复现

### 11.1 必须产生的工件

- versioned obligation/evidence graph builder 及 schema；
- replayable container/action executor；
- trajectory/branch dataset 与 immutable manifest；
- temporal graph encoder、world-model、policy checkpoints；
- evidence validity/calibration artifacts；
- hidden evaluator 与 scoring receipts；
- 每个 baseline 的 config、seed、checkpoint、run log 和 cost ledger；
- train/validation/test split manifests、dedup reports 与 contamination audit。

如果最后只留下 graph database、规则 gate 和 API orchestration，没有训练权重、policy/world-model checkpoint 和实际 branch data，就不满足算法硬度。

### 11.2 分阶段资源估计

以下是设计预算，不是已经消耗的算力。

**识别 pilot。** 选择 30–50 条较短 chains，每个关键 snapshot 执行 4–6 个 action branches、3 seeds，目标约 2,000–5,000 transitions。图模型可先控制在 20M–50M 参数，使用 1–2 张 24GB GPU 或 1 张 80GB GPU 训练；真正瓶颈是 2,000–5,000 CPU-container hours、coding-agent inference 和存储。pilot 只回答 action effect 是否有 support、标签能否执行、generic 是否立即等效，不用于写论文结果。

**完整研究。** 若 pilot 通过，目标至少 10,000–30,000 可执行 transitions、数千 matched branches、多个 repositories/languages/risk types。50M–150M graph world model 与 offline RL 可估计为 4 张 A100 80GB 或 8 张 24GB 级 GPU 的 10–30 天级训练/调参与 10,000–30,000 CPU-container hours；保存 repo snapshots、images、logs 和 evidence artifacts 可能需要 2–5TB。若使用 closed-model rollouts，API 版本漂移和不可重复性会成为额外威胁，因此主训练应冻结 open-weight coding model，closed frontier agents 只作外部 evaluation。

这些资源在大型博士项目中并非绝对不可承受。算力也不是 NO-GO 原因。真正问题是投入这些资源后得到的 artifact 仍是 direct-work components 的集成，而且理论状态被公平 generic model 包含。

| 第 9–10 节 | `DSDL-E2` 至 `DSDL-E14b`；`ACAA-P5.2-1` 至 `P5.2-7` | 终态、表示、中间机制、消融、解释分层评价；强基线和多设置不能合并成一张总表 | 已预注册 external、diagnostic、mechanism、equal-model 四层；尚无实验，不能使用结果语气 |
| 第 12–14 节 | `DSDL-Z3–Z6` 对应 `00K` 边界索引 | 局限回到工件真实依赖，预测能力不等于组织结果 | 已区分 design-feasible、empirically-unproven 与 theory-failed；不把未运行实验写成安全改善 |

### 13.2 ACAA 标准下的决定性失败

ACAA 不是简单把理论构念作为 extra features。`ACAA-T5a/T5b` 与 `T6a/T6b` 先从顾客处理机制导出时间衰减和互补/非冗余方向，再在 `M10a/M10b` 对 affinity-based calculation 给出明确反方向计算；`M12` 又处理票数与时间的真实冲突。当前候选虽然能说“旧证据会失效”“未来依赖会增加成本”，但 generic temporal graph 获得相同 validity、fan-out、cost 和 outcome history 后并不会被迫朝相反方向计算。所谓 theory factorization 只是把这些变量预先命名。

因此，若按肖老师的严格要求写正式引言，不能在 related work 后自然落到“现有模型忽略 verification debt，故提出 obligation graph”，因为 Truth Stack 已提供该定义，SIKG/proof repositories 已提供图形近邻，POMDP 又能吸收全部状态。这样写会把 direct work 的存在和通用替代的能力压低，违反 ACAA 的引文与方法责任。

### 13.3 DSDL 标准下的决定性失败

DSDL 的理论状态不是装饰标签。expectation、perception、disconfirmation 与累计状态在 `DSDL-M17_18` 至 `M23` 形成有方向的中间计算，进入 loss，并在 `E13–E14b` 由消融与中间机制结果单独检验。当前候选可以强制一个 debt/interest head，却没有独立自然真值；若用 future branch return 训练，它只是 value decomposition。若 generic world model得到同一 return，也能学习相同 action value。删除 head 后性能下降只证明多任务辅助有用，不证明 technical-debt theory 对算法不可替代。

DSDL 还把“模型预测得好”与“代理员真实受益”分开。相应地，本候选即使 evidence-validity F1 较高，也不能写成 release harm 已降低；只有实际 release episode 才承担外部结果。当前没有这些结果，这一证据边界已守住，但理论责任仍未完成。

### 13.4 引文责任样例

| 拟写论断 | 责任类型 | 可承担来源 | 不得越界的说法 |
|---|---|---|---|
| downstream work 依赖 stale evidence 会形成 verification debt | 直接概念近邻 | *Truth Stack* 相关主文段 | 不得写成本研究首次发现或首次命名 |
| 连续 agent 修改会丢失此前正确行为 | 直接实证 | Regression Accumulation、StaminaBench、ChainSWE | 不得由 technical-debt 理论替代技术事实引文 |

## 14. 撤题门、有限复用与最终处置

### 14.1 已触发的终局 NO-GO 门

| 门 | 合格标准 | 当前证据 | 判定 |
|---|---|---|---|
| 真实安全结果 | hidden release regression、累积 harm、rollback 与 task/cost 联合评价 | 可执行设计完整 | 设计可行，尚未实证；不是撤题原因 |
| coding-agent 必要性 | agent 连续修改并真实调用工具/改变 release | ChainSWE 等 substrate 可满足 | 通过设计门 |
| 数据与训练 | 可由实际 branch execution 构造，不蒸馏规则 | matched clone 方案可行但昂贵 | 通过设计门，经验未证 |
| 直接现象新空间 | stale evidence、downstream dependence、debt/gate 未被直接提出 | Truth Stack 已直接提出；Regression Accumulation/StaminaBench/ChainSWE 已直接测过程和干预 | **未通过** |
| 独立算法能力 | 不是 test selection、change-impact、proof reuse 与 release control 的集成 | DANTE、SIKG、Jamil–Nour、incremental verification 已覆盖各核心动作 | **未通过** |
| 单一 AIS MEC | 理论指出通用算法稳定算错的机制 | 候选需拼接 debt、time、memory、capacity、options | **未通过** |
| MAP 不可替代 | theory 产生 generic model 不自然保留的中间状态 | 所有状态均为普通 graph/time/cost/risk channels | **未通过** |
| 等参数反证 | 同信息 generic Graph Transformer/POMDP 不能复制 | 存在同 forward graph/参数块的包含构造 | **明确未通过** |
| 系列独立性 | 不与 C3、C5/C14、C10、`01D` 借力或重复 | 可通过边界收窄，但 Benaroch 与 release/rollback 易并入 `01D` | 边界可守，不能补救前四项失败 |

只要 direct-work、MEC、MAP 或等参数任一终局门失败，就不应继续占用 thesis 题位。当前四项同时失败。增加仓库、扩大 action space、换更大 GNN 或跑出统计显著改善，都不能自动修复理论 ownership。

### 14.2 可以复用的技术资产

本题撤销后，以下内容可以进入系列公共基础设施，而不能作为第四篇论文暗中保留：

1. whole-chain repository/time split 与 hidden-test namespace；
2. ChainSWE、SWE-Milestone、SWE-CI、SWE-Chain、SlopCodeBench、StaminaBench 的 version manifest；
3. evidence recipe 的 snapshot/tool/environment hash 与 replay protocol；
4. escaped regression、polluted rollback、delay、compute 和 Pareto 指标；
5. matched branch execution、propensity logging 与 label-privilege audit；
6. DANTE/SIKG/change-impact/full-gate/no-gate 等强基线；
7. 对任何保留候选都适用的“单步风险分数不能替代外部 episode outcome”原则。

### 14.3 唯一允许重新送审的条件

未来若出现新的 AIS mechanism，重新送审不能只说“obligation graph 更完整”或“实验终于显著”。必须同时满足：

- 新理论不是 technical debt、temporal metadata、memory lifecycle 或 real options 的重命名；
- 它产生一个当前 generic temporal graph/POMDP 即使获得同一信息、监督、动作和参数也不能实现的结构约束或行动能力；
- 该能力在预注册 conflict cases 中形成与 generic model 不同且被 executable outcome 支持的方向；
- direct-work 更新检索后，Truth Stack 及 continuous-verification/test-selection 路线仍未覆盖这项能力；
- 贡献不与状态迁移候选共同使用 Benaroch 作为相同算法模板。

在这些条件出现之前，不建议做识别 pilot 来“碰碰结果”。当前 failure 是理论与独立空间，不是经验不确定性；投入 full rollouts 只会把一个可以发表为系统工程的集成做得更完整，却不会使其满足本 thesis 的理论标准。

## 16. 最终一句话结论

**验证义务积累是一个真实、重要且可以严谨执行的 coding-agent 广义安全问题；但 stale-evidence debt 与 gate 已被直接提出，累积回归、纵向仓库和预算内重验证已有密集技术近邻，而所有候选 AIS 状态均可在同信息、等参数的 temporal graph/POMDP 中逐点复现，因此它不能成为本 thesis 的独立 ISR 论文题位。**
