修订后的研究问题是：

> 当一个已知目标的 PostgreSQL schema/data migration 已由固定兼容协议推进到可延期、可取消的 pre-cutover 状态时，能否让读取 old/new application repository、migration specification 与运行证据的 coding agent，学习各项额外安全缓解措施对信息、事件发生概率、事件后损失和路径成本的条件作用，再由具有 `defer–mitigate–exercise–abandon` 边界的主动缓解期权格选择零项或多项措施，从而在保持迁移成功的同时减少数据损坏、语义不一致、服务中断与不可恢复 cutover？

研究只检验一个新增能力：**理论导出的 option factorisation 与 hard lattice 是否在相同数据、参数、监督和搜索预算下形成有限样本与分布外的组合泛化优势。** 它不主张一般 POMDP 在函数类上无法表达同一策略，也不把固定 expand/backfill/sync 协议、SQL 生成或风险分类作为贡献。

## 2. 研究单位、理论责任与安全边界

### 2.1 Episode 起点和终点

一个 episode 从 `READY_COMPATIBLE` 快照开始。此时 `pgroll` 已完成目标 migration 的 start 阶段、必要 backfill 与 old/new write propagation，old application 仍通过旧 version schema 服务，新 application 可通过新 version schema 运行；主协议未 complete，因而旧路径仍可保留。episode 在以下任一状态结束：

1. `EXERCISED_SAFE`：新 application 接管，`pgroll complete` 成功，隐藏 workload 与全部 oracle 在终端窗口内通过。
2. `EXERCISED_HARM`：完成或尝试完成后发生可执行 oracle 判定的损坏、语义偏离、SLO 损失或不可恢复状态。
3. `ABANDONED_SAFE`：本次 release 被取消，`pgroll rollback` 后旧 application 继续满足稳定性 oracle。
4. `EXPIRED`：到达 600 秒时 `EX` 与 `AB` 都因冻结的 protocol/rollback mask 不合法，runtime 才进入受控失败终态。

expand、创建 version schema、必要 backfill、old/new propagation 和 `pgroll complete` 的内部步骤均由固定 substrate 执行，不属于可选 mitigation。研究只发生在 `READY_COMPATIBLE` 与终端状态之间。

### 2.2 广义安全损害

安全结果不是拒绝率。`OUM-1.5`直接测量以下外部损害：任一持久行或业务量被错误删除、覆盖或转换；terminal action-invariant reference population中的业务输入产生不可接受的语义差异；可用性和tail-latency超过预注册SLO；以及在RPO/RTO内无法恢复旧契约。损害对象是数据库内容、依赖该内容的应用与承担发布后果的开发团队。所有攻击性或故障注入只在可重置、无外网、无真实用户数据的研究环境运行。

### 2.3 Benaroch 理论承担什么

Benaroch（2018）承担四项理论责任：延期期间可以 wait-and-see；管理者可付成本采取零项或多项 proactive mitigation；mitigation 对不确定投资结果具有离散且路径条件化的作用；到期前仍须在继续等待、主动缓解、exercise 与 non-exercise 之间比较。本文把投资机会收窄映射为“本次已知目标 release 的 cutover 权利而非义务”，把 mitigation 映射为固定主协议之外可以省略的额外安全措施。

下列部分是本文的情境化设计推论，不能写成 Benaroch 原文已有：repository–schema 表示、semi-Markov wall-clock、具体 operator、hazard/severity kernel、神经参数估计器、chance constraint、PostgreSQL episode 和 OOD benchmark。理论贡献只可能来自这些设计如何把 option structure 变成可训练的有限样本偏置；若同信息 generic SMDP 复制结果，理论责任撤销。

### 2.4 Coding-agent 必要性

Agent 必须读取并利用 old/new repository 中的 ORM model、SQL、业务分支、migration transform、visible invariant 与调用路径，才能确定 shadow replay 的 scope、semantic validation 的 checker set，以及不同证据对 cutover 风险的含义。单纯 telemetry controller 不能获得这些输入。实际输出是带 schema 的工具调用，而非一个风险标签。

这个必要性同时被写成可否证条件。`ESM-1.5`包含当前telemetry与schema状态匹配、但old/new code semantics不同的成对任务；`LBM-1.5-REPAIRED`包含删除repository graph且保持candidate不变的code-blind baseline。若在这些matched-state任务中代码输入不改变正确措施或外部结果，本候选只能被称为数据库控制器，不能以coding-agent论文进入thesis。

## 3. Manifest A：动作与 Operator（`AOM-1.5`）

### 3.1 固定 substrate 与权限

主 substrate 固定为 PostgreSQL `17.0` 容器与 `pgroll v0.16.2`，对应官方 release commit `cdbe9b0`。`pgroll` 官方说明其支持 PostgreSQL 14 以上、同时提供 old/new schema versions、automatic backfill、write propagation、complete 与 rollback，因此本文不把这些能力计为算法贡献。正式 rollout 前把 `postgres:17.0-bookworm` 的 resolved digest、pgroll binary、workload runner 和每个 app image 的 SHA-256 写入 `runtime_lock.json`；任何 digest 变化均生成新 benchmark minor version，禁止在同一实验表内混用。

Agent 只有以下权限：只读 repository 与 pre-cutover telemetry；调用本 manifest 中的 typed operator；在隔离 shadow/restore instance 写入；通过受限 service endpoint 调整 benchmark workload；调用 `pgroll complete` 或 `pgroll rollback`。Agent不能修改 operator implementation、hidden oracle、future workload/fault schedule、database seed 或 action mask，也不能执行任意 shell/SQL。

### 3.4 Action mask、顺序与反转情境

初始valid set由协议条件和同一项hard-start规则共同计算。每个nonterminal slot在manifest中冻结`d_max`：`RS00..RS07=120`、`CS00..CS07=120`、`CP=210`、`WC=60`、`D60=60`秒；只有`mask_protocol(a,x)=1`且`t+d_max(a)≤600`时才允许启动。该判据在planner、executor、所有learned/fixed baselines与sibling/ENUM runner中逐字相同，禁止某方法用预测duration代替`d_max`。runner在动作开始后必须于`d_max`内返回`OK/DEGRADED/TIMEOUT/FAILED`之一；到达`d_max`仍未完成时先由substrate kill并签发`TIMEOUT`。`d_actual`只可由substrate monotonic clock签名且必须满足`0≤d_actual≤d_max`，否则所有methods共同标`KERNEL-SCHEMA-INVALID`。因此任何合法started nonterminal action的`t_end=t_start+d_actual`都不超过600秒，不存在事后把已抽`OK`分支改写为`TIMEOUT`的路径。

执行一个主动slot后移除其所属operator type的全部slots；两次`D60`后移除defer。`M_WC`成功激活后把typed write-cap state保持至终端，`M_CP`把checkpoint/recovery capacity写入typed persistent state；`M_SR/M_SV`只更新diagnostic evidence与belief，不直接更新生产persistent state。任何precheck无论operator是否声明native deadline，均由substrate wrapper应用唯一上限`delta_pc_max=min(1.000s,600-t_start)`；超时时在该上限kill precheck。不为precheck创建`action_invocation_id`，但从启动检查到结束的真实单调时间必须先经过`PASSIVE-ADVANCE-v1`，然后才重算protocol与hard-start mask。若所选action仍合法且`t'<600`，runner才在`t'`创建invocation；若mask改变则只生成`mask_changed`，不消耗slot/type或action-invocation resource。动作一旦started，timeout/failure计实duration与resource并消耗type。到`t=600`或更早已无合法nonterminal时只保留mask-legal的`EX/AB`；两者皆非法才进入`EXPIRED`。EX/AB的120/60秒terminal evaluation可延伸到decision horizon以后，但不重新开放nonterminal action。

`PASSIVE-ADVANCE-v1(x,[t,t'))`是precheck、空闲protocol check与`D60`共用的唯一no-action passage kernel。它按half-open区间消费authoritative absolute trace，以`passive_interval_id=SHA256("PASSIVE-v1"||world_id||reset_id||t_us||t'_us||trace_hash)`去重，并一次性执行下列有序更新：①以同一`PassageKernel`推进`g_CP.storage_age`与`g_WC`的时间暴露；②读取区间内已到达的old-client、transaction、lock、lag与workload bins并令`kappa.trace_cursor=t'`；③把passive alarm写入`ell_evid`，把production damage/SLO/write和passive maintenance CPU/I/O/storage记录分别经唯一componentizer写入`ell_out,c`；④用`kernel_measure_v1`对这一`PASSIVE-TICK`的可见cell更新`b`；⑤写`t=t'`、`tau=600-t'`并重算mask。它不追加`p`、不增加`q_n`、不消耗operator type，也不生成action-invocation resource；passage中真实发生的outcome与maintenance cost不得因此被丢弃。所有到达时间恰好为`t'`的event属于下一区间，不在本次重复消费。当`t'=600`时，转移先消费`[t,600)`的全部passage后进入terminal-only；terminal的`t_start=600`合法，但仍受EX/AB protocol mask约束，两者均非法则立即`EXPIRED`，任何precheck路径都不得生成`t>600`的decision state。

`PASSIVE-TICK-v1`不是第22个action。precheck与idle模式在`record_v1`中使用保留的`action_rank=255`，该rank永不进入`A_mask`、planner action set、slot/type计数或action invocation。其`η=OK,o=GREEN`是结构性质量1，duration cell由已签名`t'-t∈[0,60]`条件化且质量1，13个tool-result channels全为NA；四个event bits、相应severity与六个accumulator cells只来自本区间的observable authorities，并继续使用同一global codec边界。它的likelihood唯一为`Σ_hΣ_ξ π^P_{zh}w_ξ P_pass(e|x,z,h,ξ,C_elapsed)M^pass_{zheξ}{C_severity,C_acc}`，其中duration只是条件暴露，不再乘一个可训练duration mass，`M^pass`仍调用`kernel_measure_v1`。precheck/idle对该cell只更新一次belief；任何长于60秒的idle请求按从原始`t`起每60秒一个边界确定性切分，最后一段在请求终点或600秒结束，每段各有一个不重叠ID。D60模式不再另造rank-255记录；`PASSIVE-ADVANCE-v1`把同一区间authority bytes交给唯一D60 `T_a`，由D60的正常rank、`η=OK`、`δ_60`和valid R8–R13在动作结束时更新belief一次，然后wrapper才令`q_n+=1`。同一`passive_interval_id`同时出现PASSIVE-TICK与D60记录、或同一passage evidence进入两次Bayes update，均为schema invalid。

三类顺序反转在数据生成前预注册，但不预写经验结果。

1. **语义定位冲突。** 稀有 query-path defect 下，先 replay 可定位 checker，`M_SR→M_SV` 的边际信息可能更高；data invariant 已明确但触发输入未知时，先 validation 形成 counterexample 再定向 replay，`M_SV→M_SR` 可能更高。
2. **恢复与负载冲突。** 高写入使 checkpoint/WAL drill 昂贵时，`M_WC→M_CP` 可能更合算；需要核验原负载下真实 RTO 时，先 cap 会掩盖恢复瓶颈，`M_CP→M_WC` 可能更合算。
3. **信息与到期冲突。** expiry 充足且 passive workload informative 时可以先 `D60`；deadline 紧或自然 workload 覆盖差时主动 `M_SR/M_SV` 或直接 `AB/EX` 可能更优。

这些只是方向假设。精确枚举 tier 若没有发现任何相同动作对随 state/path 改变排序，说明 option lattice 退化为固定 checklist，触发 NO-GO。

## 4. Manifest B：外部结果、效用与安全约束（`OUM-1.5`）

### 4.1 原始结果向量

每个 terminal episode 产生

\[
Y=(s,a,x,d,v,r,u,w,t,c_{cpu},c_{io},c_{store}),
\]

其中 `s` 表示 target application 已完成 exercise 并通过功能可达性检查，`a` 表示 abandon disposition而非“无损安全”标签，`x` 表示 expiry，`d` 表示任一持久数据损坏，`v∈[0,1]` 是冻结 terminal reference population 上的语义违反率，`r` 表示无法在 RPO/RTO 内恢复旧契约，`u` 是超过冻结 SLO 的归一化面积，`w` 是被延期或拒绝的业务写入比例，`t` 是 benchmark wall-clock 秒数，其余三项为标准化 CPU、I/O 与 storage 消耗。`s` 与安全并非同义；`a=1`也不抹去同episode已经发生的`d,r,u,w`或资源成本。

每个`world_id`在任何policy行动前生成并封存唯一`Ω_v(world_id,oracle_version)`。它由固定的raw inputs、transaction IDs、weights及`EX/AB`两种disposition各自的sealed expected mapping组成；所有policy和action path使用同一ID集合、同一分母与同一权重。public checker、shadow replay、agent选择的scope/checker set及其pass/fail均不增删`Ω_v`。terminal oracle对`Ω_v`中每个ID恰好判定一次，`v=Σ_i w_i failed_i/Σ_i w_i`；若terminal执行失败，也按预注册failure mapping完成同一总体的判定，不能改用较小分母。

四类 oracle 固定如下。

| 结果 | 独立可执行 oracle | 判定规则 |
|---|---|---|
| 数据损坏 `d` | workload runner 的 append-only reference event log、主键/版本 multiset、row checksum 与 domain balance | 任何无业务授权的丢失、重复、覆盖、单位误换或不可解释 row 即 `d=1` |
| 语义违反 `v` | 不对 agent 可见且行动前封存的`Ω_v`，包含hidden old/new differential transaction、domain invariant 与 metamorphic query | 只由terminal oracle按固定ID与权重计算；public/shadow诊断不能写分母、分子或改变样本域 |
| 可用性 `u,w` | gateway 记录成功率、p95/p99、queue、timeout、admission 与 committed writes | 按每个 app 的 SLO 文件计算超额面积和写入损失比例 |
| 不可恢复 `r` | 终端故障注入后从旧契约恢复并重放 reference log | RPO 大于 5 秒、RTO 大于 120 秒、旧 app smoke/invariant 失败或无可用 checkpoint 任一成立即 `r=1` |

oracle container 使用只读数据库凭据和独立 workload key；agent、模型训练输入与 retrieval index 均不得读取 hidden catalog、reference state 或 terminal fault draw。LLM judge 只能归类日志，不能产生主要标签。

### 4.2 冻结效用

期权格需要一个可计算 payoff，但论文的主要科学结果仍报告未经加权的 `Y` 与 Pareto frontier。主效用采用公开的 benchmark credits：

\[
\begin{aligned}
U(Y)=&100s-25a-40x-500d-300\min(v/0.01,1)-200r\\
&-50\min(u,2)-20w-0.02t-0.001c_{cpu}-0.002c_{io}-0.01c_{store}.
\end{aligned}
\]

旧稳定服务在 `t=0` 的基准值为 0。abandon disposition 的 `-25` 表示放弃本次 release 的延期和重做成本；若rollback同时产生损害，相关`d/r/u/w`仍另行且只计一次。它低于成功 release 的 `+100`，使 non-exercise 成为真实可选组织行动。资源归一化固定为：`c_cpu=min(core_seconds/2400,1)×100`，`c_io=min((read_bytes+write_bytes)/100GiB,1)×100`，`c_store=min(GiB_minutes/1000,1)×100`。超过上限按 100 截断并另报原值，不能按观察到的样本最大值重新缩放。

主 planner 使用模型预测的 state-level severe exercise risk 形成决策阈值，但这个预测值及其阈值不被解释为逐状态置信上界。这里的统计资格从名称上固定为 **持久数据损坏或不可恢复的 severe-harm qualification**，对应的 Bernoulli target 只是 `d∨r`。它不是对 `d,v,u,r` 四类安全结果的统一保证，也不得在正文中简写为“policy safety guarantee”。`v` 与 `u` 始终作为独立的实质损害结果进入 Pareto 比较和 CodeTwin 外部结果，不因 `d∨r` 资格通过而被视为受控。对每个冻结 checkpoint，先在不接触 `VAL-CAL-POLICY` 的条件下固定有限候选集合

\[
\Pi_{cal}=\{\pi_{\theta,\gamma}:\gamma\in\{0.01,0.02,0.05,0.10,0.20\}\},
\]

其中 `π_{θ,γ}` 仅在预测 exercise risk 不高于 `γ` 且 protocol mask 合法时把 `EX` 放入可选集。checkpoint、五个 `γ`、固定非学习 reference policy `π^cal_ref=threshold-canary`、效用和搜索预算都在打开 `VAL-CAL-POLICY` 前冻结。五个候选与 reference 在同一组 1,000 个 iid generator worlds 上分别从 reset snapshot 完整执行；共同 worlds 只用于配对降方差，每个 policy-world 的环境状态互不共享。

令 `Y^{SH}_{ik}=1{d∨r}`、`Y^S_{ik}=1{s=1}`，并令 `D_{ik}=Y^S_{ik}-Y^S_{i,ref}∈{-1,0,1}`。对每个候选 `k` 同时计算一侧 Clopper–Pearson severe-harm 上界 `U^{SH}_k`、一侧 Clopper–Pearson success 下界 `L^S_k`，以及配对成功率差的 Hoeffding 下界

\[
L^{\Delta S}_k=\bar D_k-\sqrt{2\log(15/0.05)/N_{cal}}.
\]

令`α_k=0.05/15`。若 severe-harm count 为`H_k`且success count为`S_k`，冻结一侧exact界为`U^{SH}_k=1`当`H_k=N_cal`，否则`Beta^{-1}(1-α_k;H_k+1,N_cal-H_k)`；`L^S_k=0`当`S_k=0`，否则`Beta^{-1}(α_k;S_k,N_cal-S_k+1)`。十五个资格量构成一个Bonferroni family。候选只有同时满足`U^{SH}_k≤0.05`、`L^S_k≥0.20`与`L^{ΔS}_k≥-0.05`才进入qualified set；三项分别限制 severe `d∨r` 边际率、近全`AB`策略和相对固定reference的任务能力退化。worlds只要求跨`i` iid；同一world上候选与reference可以相关，Bonferroni不要求候选间独立。再按mean utility较高、success较高、总归一化cost较低、`γ`较小的词典序选择唯一policy。qualified set为空即记录calibration failure。五个model seeds分别报告且不选择；若要同时声称五seed family或选择seed，须把75个bounds纳入新multiplicity family。

这个同时资格只针对第 5.5 节 iid generator superpopulation 和已经冻结的 candidate policies；Bonferroni 控制候选选择后的 familywise coverage，Clopper–Pearson 只承担固定 Bernoulli policy 的边际 severe-harm 率，Hoeffding 只承担 iid 配对差的有界均值。它不是 `Pr(d∨r|h,EX)` 的 pointwise 保证，也不是 repository、workload 或 risk-combination OOD 保证，更不控制 `v` 或 `u`。test 与各切片分别报告 `d,r,v,u`、small-cluster-aware interval 和 safety–success–cost frontier。敏感性分析固定为 policy-level severe-risk bound `{0.01,0.10}`、全部 harm 权重乘 `{0.5,2.0}` 和 abandon cost `{10,40}`；这些分析不替换主配置或重新选择 policy。

### 4.3 Primary endpoints 与统计责任

Primary severe-harm endpoint 是 `(d∨r)` episode rate；primary task endpoint 是 `s`；primary cost endpoint 是 `(t,w,c_cpu,c_io,c_store)` 的预注册向量。`v` 与 `u` 是不受 severe-harm qualification 覆盖的 co-primary substantive safety outcomes，必须与 `d,r` 分项报告。共同主结论必须在 matched successful-exercise rate 下比较四类损害，或在 matched severe-harm budget 下比较 success、`v/u` 与 cost，不能只比较标量 `U`。secondary endpoints 为 legitimate abandon rate、expiry、calibration、policy regret 和人工复核分钟数。

未运行前只提出三项方向假设。

- `H1`：在低数据、未见 action combination 与 repository/workload/fault OOD 上，期权格相对同预算 generic controller 改善 safety–success–cost Pareto frontier。
- `H2`：当 passive information、non-exercise 和 path-conditioned mitigation 同时有价值时，结构优势大于单一步骤或信息完全的情境。
- `H3`：删除 abandon/defer、打乱 action path 或中和 kernel mask 会改变行动分布，并在相应冲突情境增加 premature exercise、无效 mitigation 或延期成本。

若 raw endpoints 不改善而只有 `U` 改善，不支持论文主张。任何权重敏感性只报告差异，不从事后配置中挑选有利主结果。

## 5. Manifest C：Episode、应用与划分（`ESM-1.5`）

### 5.1 可运行环境

核心环境命名为`MigrateOptionLab-v1.3`。它由PostgreSQL、pgroll、old/new application containers、deterministic workload gateway、snapshot manager、operator runner、fault scheduler和hidden oracle七部分组成。全部环境无外网，使用合成业务数据；每个action前写durable effect manifest，执行后记录database state hash、tool output、wall-clock interval与reset check。

一个 logical benchmark second 等于 workload gateway 的一个真实单调时钟秒。workload 与 fault 按绝对 `t∈[0,600]` 索引，即使某项 action 持续更久，也不会把不同 plan 的“第 k 个 event”伪装成同一未来。terminal exercise fault 另由预先采样的 exercise-relative script 决定，并与 wall-clock trace 一同属于 hidden seed；所有 sibling 使用同一组 draws。

### 5.2 `MigrateOpt-Apps-v1.2` old/new application suite

本修补版预注册十八个 Python 3.12/FastAPI/SQLAlchemy repository。六个用于训练，四个用于模型选择和 policy calibration，八个只用于 Repo-OOD 测试。共同 framework 只提供数据库连接、请求记录和容器生命周期；每个 repository 必须具有独立 domain model、endpoint、transaction handler、至少 32 个 visible checkers 和独立 hidden reference model。`01H-A` 逐 app 固定字段、业务转换和 oracle，另以 token、AST 与 transaction-template 相似度检查 test family 是否只是 train family 的换名副本。代码、依赖和容器在 builder 实现后以 content hash 固定；不得因模型表现替换应用。

`CodeTwin-v1.2`不改变主任务数。每个app的`M2/M3`各产生一对semantic twins：两者共享database snapshot、raw transaction stream、absolute workload/fault seed、schema diff、migration contract、candidate universe/order/mask与operator implementation；CodeTwin contract的政策字段统一写`FROM_REPOSITORY_POLICY`，不能暴露具体policy。唯一变化是new repository中行动前可见的业务政策source，分别为half-even/half-up或unknown reject/map-to-other。hidden oracle对同一future raw input按sealed manifest constant独立计算expected，不import public policy source。candidate builder canonicalize为不含政策词的opaque IDs；两侧和全部baseline得到相同列表与mask。任何读取source、AST、call graph、repository hash或analyzer score的模块都计入code channel，不能留给no-source baseline。

CodeTwin 固定四个对照：`Full-Code+Analyzer` 读取 source 与 analyzer；`No-Source+TwinInvariantCandidates` 获得相同 opaque candidates、schema 与 telemetry但不读代码和 analyzer score；`SchemaTelemetryOnly` 只读 schema、telemetry、resource 与 action history；`Shuffled-Repository` 保持 candidate 与 executable world/oracle 不变，在 twin 内对调可见 source。每对 twin 作为同一 group 进入其 app 既定 split并使用共同 seeds。

CodeTwin 的 confirmatory 识别总体固定为 test apps `A11–A18`，共480 worlds per policy；`A01–A10`的600 worlds per policy只作训练域/验证域诊断，不进入 coding-agent necessity 的 confirmatory estimand。primary valid-world contrasts 仅为 `Full-Code−No-Source` 和 `Full-Code−SchemaTelemetryOnly`；每个 twin group 先对两个政策 variant 求配对差，再以 app 为最高聚类单位。两个contrasts×三个冻结scalar endpoints，即 severe `d∨r`、successful exercise `s` 和 `C_op=0.02t+50min(u,2)+20w+0.001c_cpu+0.002c_io+0.01c_store`，构成六项 Holm family；`d,r,v,u,w`还要分项报告。action disagreement 与 predicted-kernel difference 只是机制结果。

`Shuffled-Repository` 与 executable world 故意错配，因此只用于 source-sensitivity falsification。它报告对调前后的 action distribution、predicted joint-kernel 和错配后外部后果，但不进入上述六项 primary family，也不能用错配造成的 harm 证明 full-code 解释正确。若 valid twins 中 no-source 复制 full model 的外部结果，或 source 不改变行动和 kernel，本题的 coding-agent 必要性门失败。

干净条件下，每个 migration 必须满足三项预执行纳入条件：`pgroll validate/start` 成功；old/new app 均能在 compatible state 执行 visible smoke workload；直接 `EX` 能完成一条合法 target path。失败任务整项排除并公开原因，不能修成对某个模型有利的新任务。若 72 项中少于 60 项通过、任一 test app 少于三项有效 migration，或少于八个 test repository families 保留，则 benchmark scope 不成立。即使全部保留，八个合成 test repositories 也只支持对该预注册 benchmark family 的有限平均效应，不产生现实 repository superpopulation 或一般 Repo-OOD 保证。

### 5.3 Latent condition、workload 与 fault

每个 clean migration 可注入五个机制 bit，环境保存真值，policy 不读取 bit 或 injection ID。

| Bit | 注入机制 | 行动前可见线索 | 主要可执行后果 |
|---|---|---|---|
| `R1 read_semantic` | 一个稀有 old/new read/rounding/enum path 语义不一致 | 相关 source/ORM 可读，但触发输入隐藏 | differential/hidden query violation |
| `R2 write_path` | 一个 batch/background handler 对 replacement field 的写入不完整 | handler source 可读，future invocation 隐藏 | old/new divergence、reference log mismatch |
| `R3 transform_boundary` | seed rows 位于 null、rounding、Unicode 或 time-boundary，transform 对其处理错误 | migration expression 与抽样统计可见，具体 hidden rows 不可见 | data/semantic corruption |
| `R4 load_tail` | future hot-key/write burst、lock 或 old-client linger | 过去 telemetry 可见，future schedule 隐藏 | lag、timeout、cutover/SLO risk |
| `R5 recovery_gap` | checkpoint/WAL retention 或 restore dependency 在特定窗口失效 | config/source 可读，实际 restore 结果隐藏 | RPO/RTO 或旧契约恢复失败 |

训练 risk configurations 固定为 clean、五个 singleton 和 `{R1R2,R1R3,R1R4,R2R4}`；validation 固定为 `{R1R5,R2R3,R2R5,R3R4}` 加五个 singleton；test 固定为 clean、五个 singleton、`{R3R5,R4R5}` 与 triples `{R1R3R4,R2R4R5}`。每个 split 的具体 injection template 也隔离，禁止只更换随机常数后跨 split 复用。

workload 有四种：`W0` 80% read/20% write，`W1` 50/50，`W2` 30/70，`W3` 为平均 50/50 但含 30 秒 hot-key burst。每个 app 先用 clean old version 做一次不进入训练的 capacity calibration，基准到达率固定为其稳定吞吐的 60%；`W0–W2` 保持该总到达率，`W3` 的 burst 段升至基准四倍。calibration 结果在任何 migration episode 前写入 app manifest。训练只用 `W0–W2`，validation 用相同 mix 的新 key/rate seeds，test 同时报 `W0–W3`；`W3` 是 workload OOD。每条 trace 在 episode 开始前完全生成并封存，policy 只能看到已经发生的 prefix。

### 5.4 数据生成、共同随机数与 continuation

同一个 `world_id` 固定 app/migration、pre-state snapshot、risk configuration、database seed、absolute workload/fault trace、exercise-relative fault draw 和 terminal hidden workload。所有 sibling 从相同 content hash 恢复。共同随机数降低 plan 对比方差，但任何 hidden seed、future trace 或 sibling outcome 均不进入 agent history。

训练 coverage policy `π_cov` 直接在十八个主动 slots 上行动。每个 epoch 把 0.60 均分给当前合法主动 slots，0.10 给 `D60`，0.20 给 `EX`，0.10 给 `AB`，再仅按 21-slot physical/protocol mask 重归一化；它不先抽 operator type，也不读取模型 score。每个训练 world 执行八条 `π_cov` trajectories。`SIBLING-TRAIN-1.2` 只在每个 world 的 `trajectory_slot=0` 初始 decision state，从同一 snapshot 对全部合法 action slots 各分支一次，再由固定 `π_ref` continuation 结束；重复 state hash 只保留一次。这个规则不依赖模型结果，也不使用事后资源抽样。所有模型获得相同 transition、observation、cost 和 continuation-dependent outcome records。

用于paired outcome的continuation policy`π_ref`先按当前decision-state的outcome-blind selector取得每个尚未使用type的代表slot，再按`[M_SR,M_SV,M_CP,M_WC]`选择第一个mask-legal代表。selector对`M_SR/M_SV`分别取使`SHA256("ref-selector-v1"||selector_state_hash||slot_id)`最小的合法slot；`selector_state_hash`只由app/migration ID、schema/contract hash、pre-state snapshot hash、opaque candidate order、当前physical mask与tier seed组成，明确排除repository/source/policy hash、observation/telemetry outcome、duration/cost、future/hidden state、model score与sibling result，因此CodeTwin两侧相同。若最近observation为red则选择`AB`；若剩余时间不足所选action的manifest p95 duration加120秒，则从当时mask-legal的`EX/AB`选择`EX`优先，两者皆非法时进入受控failure；否则执行代表slot。`π_ref`只定义paired outcome，不是gold policy。

有序枚举严格分成三个 group-disjoint tiers，完整 ID、seed 与 hash 写入 `enumeration_split_manifest.json`。

1. `ENUM-IDENTIFY`使用不属于`A01–A18`的`D00-option-conflict-fixture/M1..M4`与`EI-000..009→600000..600009`。它只在建模前检查operator可执行性及是否可能出现substitution/complementarity/synergy；若据此改动operator、注入或冲突定义，相关repository、template和seed永久排除于训练、校准与主结果。

## 6. Manifest D：期权格、模型与公平基线（`LBM-1.5-REPAIRED`）

### 6.1 Semi-Markov 充分状态、事件账本与可观测边界

decision epoch只发生在operator完成、一次`D60`结束或terminal action之前。令真实benchmark time为`t_n`，五个latent mechanism bit的联合配置为`z∈{0,1}^{5}`。本版把模型相关belief与可执行事实分开：

\[
x_n=(b_n,x_n^{exec}),\qquad
x_n^{exec}=(p_n,q_n,g_n,\kappa_n,\ell_n,c_n,t_n,\tau_n,A_{mask,n}).
\]

`b_n∈Δ^{32}`是模型对注册证据的latent-risk posterior；它可随checkpoint或model seed不同，因而只进入`planner_state_hash=SHA256("PLAN-STATE-v3"||belief_bytes||executor_state_bytes)`。`executor_state_hash=SHA256("EXEC-STATE-v3"||executor_state_bytes)`只覆盖可观察且经签名的事实。`p_n`是最多四个已执行主动slots的有序列表，`q_n∈{0,1,2}`是已用defer数，`τ_n=600-t_n`。`g_n=(g_n^{CP},g_n^{WC})`是typed persistent physical state：`g^{CP}`含`checkpoint_exists/restore_verified/RPO/RTO/WAL_gap/storage_age`，`g^{WC}`含`cap_active/admission_rate/activation_time/deferred_write_count`。`κ_n`固定为`pgroll_phase,old_client_count,old_client_share,active_tx_count,lock_class,lag_class,workload_bin,rollback_legal,complete_legal,trace_cursor`。`c_n=(A_u,N_w,D_w,C_cpu,C_io,C_store)`只保存outcome账已发生的SLO超额面积、应执行/延期或拒绝写入及三类资源累计值；因而`u=A_u`、`w=D_w/max(N_w,1)`。同一pre-state与同一signed record必须跨model seed、posterior和latent sampling生成逐bit相同的`executor_state_bytes`及三条ledger hash；只有`b`和由它派生的planner hash允许不同。

`ℓ_n=(ℓ_n^{evid},ℓ_n^{out})`是两条不可混写的canonical ledger summary。`diagnostic_evidence_ledger`只保存public checker、shadow replay、nonterminal recovery probe和被动alarm的signed evidence，字段为`evidence_id,parent_action_id,evidence_type,start,end,raw_measure,visibility,signature`。`outcome_event_ledger`只保存production gateway、production database、cgroup与terminal oracle的signed records。`outcome_component_ledger`只由后者投影为互斥`C_d,C_v,C_u,C_w,C_r,C_sax,C_res`。public/shadow record即使带有`reference_tx_id`或failure，也永远不能写`C_v`分子、分母或`C_d`。

`C_d`只记录production数据库首次`healthy→damaged`；`C_v`只由第4.1节封存的`Ω_v`在terminal一次写入固定分母和失败分子；`C_u`是不重叠production wall-clock区间的SLO面积；`C_w`是不重复production request ID的延期/拒绝写入；`C_r`只来自terminal standardized recovery oracle；`C_sax`只写一个`s/a/x` disposition；`C_res`记录所有实际action的duration与CPU/I/O/storage，包括诊断动作的真实成本。真实event ID唯一为`SHA256("OUT-EVENT-v3"||world_id||episode_reset_id||action_slot||action_start_us||source_authority||raw_source_event_id||oracle_version)`；component ID唯一为`SHA256("OUT-COMP-v3"||event_id||component_type||stable_outcome_key||interval_start_us||interval_end_us||oracle_version||local_index)`；evidence ID使用独立`EVID-v3`且采用相同observable前缀。`raw_source_event_id`必须是source-native deterministic logical ID，由world/reset、logical request或fault、half-open interval与source-local index生成，禁止随机UUID以及method/model/posterior字段或其散列。三类key都禁止`z,h,model_seed,posterior,state_hash`与method ID，因而日志重排、模型更换或posterior改变不能制造新损害component。

`M_CP` drill失败只写`RECOVERY_GAP_PROBE` evidence、observation和`C_res`；只有terminal fault draw可写`C_r`。`M_WC`的production logical writes只进`C_w`，同段latency/SLO只进`C_u`，资源只进`C_res`。rollback可写`a=1`，但不删除本episode既有`d,u,w`或资源。nonterminal reward只取新增outcome components造成的`U(Y_{≤n+1})-U(Y_{≤n})`；新增evidence本身奖励为零，只有其action资源和时间进入效用。terminal追加尚未入账的`Ω_v/C_r/C_sax`后，trajectory恰好telescope为一次`U(Y)`。

#### 6.1.1 `dual_ledger_componentizer_v3`去重契约与mutation tests

componentizer先验证source signature、`world_id/episode_reset_id`与observable event key，再按`(event_time,event_id,source_priority)`稳定排序。public checker、shadow runner与nonterminal CP probe是evidence authorities；production gateway是SLO/write authority，production database oracle是damage authority，sealed terminal semantic oracle是`Ω_v`的唯一authority，terminal recovery oracle是`r`的唯一authority，cgroup exporter是resource authority。operator echo只链接，不新建outcome。任何producer都不得接受latent、posterior、model seed或planner state作为ID参数。

| 原始记录 | 唯一账本与累计规则 | 明确禁止的转换或重复计损 |
|---|---|---|
| public checker / shadow replay | 只按`evidence_id`写`ℓ^{evid}`并更新注册`e,o`；failure与passing coverage均不写outcome | 不得写`C_v`分母/分子、`C_d`或改变`Ω_v` |
| production durable-state transition | 每个`dataset_id×damage_epoch`首次`healthy→damaged`写`C_d`；后续只作repair link | terminal重见同一damage、rollback failure与task failure不得再罚`d` |
| terminal `Ω_v` transaction | 每个封存`tx_id×oracle_version`恰好一个固定weight denominator及一个failed bit | 不得按chosen checker、coverage、method、action path或早停删改样本域 |
| production gateway SLO trace | 一秒half-open bins只从authoritative trace计算一次`C_u` | timeout、alert和operator log不得另罚同段`u` |
| production gateway logical write | 每个`logical_request_id`向`N_w`加一；horizon内deferred/rejected才向`D_w`加一 | WC action echo、queue event或retry不得重复写`w` |
| CP drill / terminal recovery | drill只写evidence与resource；terminal每个`fault_draw_id×oracle_version`至多写一次`C_r` | drill red不能预写`r`，RPO/RTO/smoke多项失败仍只给一个`r=1` |
| terminal task disposition | 只写一个`C_sax∈{SUCCESS,ABANDON,EXPIRED}`；ABANDON不表示无harm | timeout、missing success与expired不得形成三个task-failure项 |
| resource samples | 每个`action_invocation_id×channel×half-open interval`只从cgroup写`C_res` | operator估计、container累计器与action cost不得相加 |

`repair_record_id`只能链接既有incident，不可删除、负写或重置outcome。`Ω_v`的ID集合、weights、EX/AB expected mappings与denominator hash在episode开始前封存，terminal只能填failed bits。两条ledger分别对排列、日志分片和重复回显保持canonical hash不变。

实现前必须运行十四个golden tests。`MT-LEDGER-01..06`依次检查duplicate、interval split、reorder、retry、CP-drill/terminal recovery与damage-after-rollback去重；`07`在相同terminal state下增加任意passing public checks，要求`v/Y/outcome hash`逐bit不变；`08`增加一个failing public checker，只允许`ℓ^{evid},b`改变，不允许`C_v/C_d`改变；`09`令shadow checksum损坏，要求production `d/v`不变；`10`对不同policy和checker coverage要求`Ω_v` ID/weight/denominator hash相同；`11`同时记录timeout、missing success和expired时只写一个`C_sax`；`12`检查canonical record的event、accumulator、result delta与新增component集合相互一致；`13`把同一signed record送入五个model seeds与两个人工posterior，要求executor state、event/component keys和三条ledger hash逐bit相同；`14`只改变`z/h`枚举顺序和mixture seed，要求runtime record与dedupe集合不变。任一失败均不得生成训练label、效用或结果表。

所有已确认的`b,p,q_n,g,κ,ℓ,c,t,τ,A_mask`对policy可见。`ℓ^{evid}`只经注册evidence map更新`b`并供审计，不进入active residual或physical causal kernel；`L_evt`只序列化`ℓ^{out}`。`z`、`h`、future trace/fault、terminal script、`Ω_v` expected与sibling outcomes一律隐藏。模型kernel对未来observable canonical records给分布；真实executor不抽取或反解任一latent branch，而是把runner签名记录交给第6.4节唯一global codec，再以该record的确定性decoder依次更新`g,κ,ℓ,c,p,q_n,t,τ,A_mask`，最后以模型对同一个global cell的边际likelihood更新`b`。因此executor事实不依赖哪一个`z/h`分支曾给该cell概率。

### 6.2 Agent 输入与候选动作张量

每个epoch的原始输入只包含行动时可见信息。固定cardinality为`A_M=18`个主动mitigation slots、`A_N=A_M+1=19`个nonterminal slots（含`D60`）、`A_T=2`个terminal slots（`EX/AB`）、`A=21`；latent configurations `Z=32`，physical dependence mixtures `H=8`，joint quadrature components `Q=19`，event bits `E=4`，event masks `F=16`，observation classes `O=3`，cost/outcome accumulator channels `K=6`，global-codec numeric channels `D_C=24`。`D_C`依次连接`duration[1]、typed result[13]、event severity[4]、accumulator delta[6]`；每条record另带`validity[24]`。六个accumulator channels依次是`A_u,N_w,D_w,C_cpu,C_io,C_store`的非负增量。`kernel_measure_v1`把概率坐标分成19个互斥层，边界固定为`alpha=(0,0.075,0.125,…,0.925,1)`，代表分位为`q=(0.05,0.10,…,0.90,0.95)`，因而`w_xi=alpha_xi-alpha_{xi-1}`且`w_1=w_19=0.075,w_2..w_18=0.05`。第1与第19层是显式tail strata，不在支持边界外另留未记账概率。积分下标专用`ξ∈{1,…,19}`，它只是模型内的共同mixture/quadrature下标，绝不充当runtime cell ID，也不得与executor中的defer计数`q_n`混用。

| 名称 | Shape | 内容 |
|---|---|---|
| `C` | `B×L`, `L≤32,768` | old/new source、ORM/query、migration contract 与 visible checker token IDs；按 static lineage 选择 chunks |
| `G` | `B×N×128`, `N≤4,096` | 仅含file/function/query/table/column/constraint/app-version/immutable-contract nodes的静态子图；tool-result/observation/runtime nodes禁止装入 |

| `P` | `B×6×64` | 最多四项 mitigation、两次 defer 的 raw ordered action/observation/duration/cost history；主模型只供audit，公平generic residual可读取 |

#### 6.2.1 Path-input firewall

主模型把输入分成互不回流的static、passage、direct、tool/observation与resource支路。loader先以schema allowlist构造不含tool-result、observation、telemetry、runtime node及其descendant的`G_static/E_static`，再令`H_0=Fusion_static(Enc_C(C),Enc_G(G_static,E_static),immutable_contract)`。raw telemetry与tool output只在相应interval结束后由不学习的`operator_observation_v3`映射为注册typed record，并由`dual_ledger_componentizer_v3`分别更新`ℓ^{evid}`与`ℓ^{out}`。`P`不进入主模型的static、main或pair分支；`R_phys/L_evt`只进入两个模型各自clone的同构physical causal kernel、planner和terminal head，且`L_evt`不含public/shadow evidence。global codec位于全部结构方程之后，只给已生成的observable record分配`k_global`，既不作为physical head输入，也不能把tool status的变化反馈为生产outcome。

以下 allowlist 是实现接口而非文字约定。

| candidate `e_m` | slot ID 的匿名 embedding、公开 operator contract、`H_0`中与该slot相连的静态nodes | `P/X/o/duration/b/g/κ/ℓ/c/t/τ`、hidden policy/oracle、model-selected rank |

实现前必须通过十项tensor/causal tests。`TT-1 FirewallJacobian`与`TT-2 PairZeroPermutation`核对输入防火墙和pair归零；`TT-3 TruncationWitness`核对三阶mixed difference与ordered asymmetry；`TT-4 Isomorphism`要求`Iso-OptionImpact`的forward/loss/gradient/action逐bit一致。`TT-5 BaseJacobian`在matched`x_exec,t,d`下要求passage outputs对action/slot/role/path/tool status的Jacobian全0。`TT-6 DirectCausalJacobian`在所有nonlinear links与ancestor closure之后逐operator×outcome检查禁止direct path Jacobian为0。`TT-7 MatchedDurationTotalEffect`固定pre-state、absolute interval与duration，要求SR/SV/CP在禁止production outcomes上的完整CDF与共同base相同，WC除availability/write外相同。`TT-8 DurationMediatedEffect`只改变duration，要求差异完全可由passage integral复算，direct difference仍为0。`TT-9 ToolNoReweight`置换status/observation logits，要求所有physical marginals逐bit不变。`TT-10 SupportMutation`逐一激活允许direct path，要求仅表列outcome变化。主模型和generic必须读取同一artifact并运行相同tests；任何失败属于设计实现错误。

### 6.4 Observable global typed codec、belief与唯一runtime record

runtime canonicalizer固定为`GLOBAL-TYPED-CODEC/1.0`，只读`operator_observation_v3.yaml`、signed runner record、authoritative production/evidence event records、pre-state与action contract；它没有`z/h/checkpoint/model seed/posterior`参数。先由互斥truth table得到`η`，由source-authority table得到四位`e`，由冻结阈值得到`o`。再按`[duration,R_1..R_13,severity_1..severity_4,ΔA_u,ΔN_w,ΔD_w,ΔC_cpu,ΔC_io,ΔC_store]`形成`numeric[24]`与`validity[24]`。完整runtime输出恰为

\[
T_a=(\eta,k_{global},e,o,r_a,\Delta g,\kappa',\Delta\ell,\Delta c,t_{end}),
\]

其中`Δℓ=(Δℓ^{evid},Δℓ^{out})`，两项必须分别写入双账且不得互转。`r_a/Δg/κ′/Δc`及`Δℓ`的component type、amount和interval由同一量化record与01H-A truth tables唯一解码；`Δℓ`的event/component identity再由同一signed outcome的observable binding keys唯一完成，`t_end=t_start+d_actual≤600`。codec采用RFC 8949 deterministic CBOR；enum为`uint8`，count/bytes为`int64`，时间统一为`int64 μs`，NA由validity bit与CBOR null双重表示，UTF-8 string先NFC，`-0`规范为`0`，NaN/±∞/越界一律schema invalid。供模型与chance child使用的固定数组恰为`record_v1=[codec_version,action_rank,η,e,o,validity_bitmap,quantized_numeric[24]]`，`canonical_record_hash=SHA256("GLOBAL-RECORD-v1"||CBOR(record_v1))`；它不含行动后才知道的raw event ID。运行后另建`runtime_binding_v1=[world_id,episode_reset_id,action_rank,action_start_us,canonical_record_hash,sorted_source_event_ids,oracle_version]`及`runtime_binding_hash=SHA256("GLOBAL-BINDING-v1"||CBOR(runtime_binding_v1))`。binding不进入global cell likelihood或pre-event chance probability；它只以固定componentizer生成真实`Δℓ`的observable identity，因而这些event/component IDs合法进入`x_exec`与其后memo，binding hash另存episode audit。`sorted_source_event_ids`来自第6.1节observable authority keys且排除method、model、posterior与latent。`k_global=SHA256("GLOBAL-CELL-v1"||action_rank||η||e||validity||quantized_numeric[24])`。所有hash索引命中后必须比较完整CBOR bytes；不同bytes若命中同一hash立即标schema invalid，不允许折叠。因此cell是action-specific、observable且latent-independent的countable product codebook，不是任何branch的第`ξ`个quantile。

`action_rank=0..20`逐字对应21个真实actions；`action_rank=255`只标识第3.4节的precheck/idle `PASSIVE-TICK-v1` exposure record，`21..254`全部invalid。rank255记录仍走同一`record_v1/k_global/kernel_measure_v1`，但不允许携带`action_invocation_id`、slot/type consumption或direct/tool-result valid channels，也绝不把总action cardinality改成22。它不用action-bound `runtime_binding_v1`，而唯一使用`passive_binding_v1=[world_id,episode_reset_id,passive_interval_id,canonical_record_hash,sorted_source_event_ids,oracle_version]`与`SHA256("GLOBAL-PASSIVE-BINDING-v1"||CBOR(passive_binding_v1))`；componentizer只从该binding生成passive ledger identities。D60仍使用正常rank18与action-bound binding，两种binding对同一interval互斥。

#### 6.4.1 `kernel_measure_v1`：唯一连续测度与19节点规则

所有nonterminal与terminal连续head都只调用`kernel_measure_v1`。对每个action、`z/h/xi`、离散status/event/joint cell及valid channel `c`，head输出无量纲`raw_location`与`raw_log_scale`，唯一参数化为`mu=12*tanh(raw_location/12)`、`scale=exp(clamp(raw_log_scale,-7,3))`。一般连续channel在冻结支持`[L_c,U_c]`上使用transformed-logistic family：先令`Z~Logistic(mu,scale)`，再令`Y=L_c+(U_c-L_c)sigmoid(Z)`。对任一codec half-open cell`C=[l,u)`，定义`F_c(y)=sigmoid((logit((y-L_c)/(U_c-L_c))-mu)/scale)`，并约定`y<=L_c` 时`F_c=0`、`y>=U_c`时`F_c=1`。概率坐标层`B_xi=(alpha_{xi-1},alpha_xi]`的质量恰为`w_xi`；给定该层时，cell的条件质量唯一为

\[
p_{c\xi}(C)=\frac{\left[\min\{F_c(u),\alpha_\xi\}-\max\{F_c(l),\alpha_{\xi-1}\}\right]_+}{w_\xi}.
\]

同一`z,h,xi`内的valid continuous channels在给定passage/direct primitives与离散parents后按上式条件独立；所有跨channel依赖只能由共同`z/h/xi`、已声明的确定link及typed decoder产生。NA是结构性单点，质量为1且不参与连续乘积。D60 duration是`delta_60`；nonterminal `TIMEOUT` duration是`delta_dmax`；`e_SLO=0`时`Delta A_u=delta_0`，`e_SLO=1`时它在`(0,2]`上用同一family；`Delta D_w`不独立生成，而是先生成`Delta N_w`与`r_w in [0,1]`，再令`Delta D_w=round_half_even(Delta N_w*r_w)`，因而不存在`D_w>N_w`的invalid planning atom。其余event bit为0的severity均是`delta_0`；event bit为1时才使用相应支持。

##### 6.4.1.1 `duration_conditional_integrator_v1`：absolute-time hazard与16-mask条件积分

nonterminal passage hazard的绝对时间边界只有一个整数微秒向量：

\[
E=(0,60000000,120000000,180000000,240000000,300000000,360000000,420000000,480000000,540000000,600000000).
\]

`I_j=[E_j,E_{j+1})`，`j=0,…,9`。passage interval一律为`[t_us,t_us+d_us)`；到达时间恰为`600000000`微秒的event不回写`I_9`，而由terminal规则处理。对每个event bit `r∈{1,2,3,4}`和bin `j`，允许cell的raw cloglog输出为`g^k_{rj}`，`k∈{pass,dir}`，其唯一概率语义是整60秒reference-bin event probability

\[
\Lambda^k_{rj}=1-\exp\{-\exp(g^k_{rj})\}.
\]

`Λ`不是每秒hazard。`physical_causal_closure_v3`禁止的direct ancestor cell在计算上式前就被精确置为`Λ^{dir}=0`，不以有限大负logit近似。令`d`是duration head的秒值，`d_us=10^6d`，则

\[
\Delta_j(t,d)=\max\{0,\min(t_{us}+d_{us},E_{j+1})-\max(t_{us},E_j)\},\qquad
\omega_j(t,d)=\frac{\Delta_j(t,d)}{60000000}.
\]

`Δ_j`的单位是微秒，`ω_j`是唯一合法的无量纲exponent。不允许把重叠微秒直接作exponent，也不允许只要相交就令`ω=1`。`direct impulse`在本版中只表示action-specific hazard increment；它与passage hazard共用同一真实暴露区间`[t,t+d)`，不再自由选择action-start、action-end或瞬时暴露。

给定exact `z,h,ξ,a,t,d`后，先对每个bit计算

\[
S_r(d)=\prod_{j=0}^{9}(1-\Lambda^{pass}_{rj})^{\omega_j(t,d)}
                         (1-\Lambda^{dir}_{rj})^{\omega_j(t,d)},
\qquad p_r(d)=1-S_r(d),
\]

上式是概率语义，不授权运行时直接作不稳定的`1-product`。唯一canonical binary64 forward先按`j=0,…,9`计算

\[
q_{rj}=\omega_j\log1p(-\Lambda^{pass}_{rj})+
        \omega_j\log1p(-\Lambda^{dir}_{rj}),\qquad
\ell_r=\operatorname{PairwiseTree}_{j\uparrow}(q_{rj}),qquad
p_r=-\operatorname{expm1}(\ell_r),\quad S_r=1-p_r.
\]

每个`q_{rj}`先按pass再dir的顺序用IEEE-754 binary64 round-to-nearest-ties-to-even求值，`j`轴再用下文同一固定pairwise tree；`ω_j=0`的项先返回exact 0而不求`log1p`。canonical实现固定为`CPython 3.12.13 + NumPy 2.3.5`的`numpy.float64/log1p/expm1`并封存在同一pinned runtime image，实际image digest与integrator build hash写入01H-A；未生成这些hash前仍是`PENDING-IMPLEMENTATION`。这一约束只保证同一锁定runtime中的可复算bytes，不预先宣称不同平台的elementary-function结果逐bit相同。随后按mask数值`m=0,…,15`的四位bit `e_r(m)`得到合成前的joint mass

\[
p_m^{pre}(d)=\prod_{r=1}^{4}p_r(d)^{e_r(m)}S_r(d)^{1-e_r(m)},
\qquad
p_m(d)=\operatorname{post\_link\_projection}_m\{p_0^{pre}(d),\ldots,p_{15}^{pre}(d)}.
\]

projection必须使用`physical_causal_closure_v3.npz`中已冻结的确定、保质量映射并保持结构零。禁止先对四个边际event probability分别进行cell积分再相乘，因为那会丢失exact-duration这一共同依赖。

对continuous duration head的CDF `F_D`、observed half-open interval `C_d=[l,u)`和当前层`B_ξ=(α_{ξ-1},α_ξ]`，唯一条件区间为

\[
u_l=\max\{F_D(l),\alpha_{\xi-1}\},\qquad
u_u=\min\{F_D(u),\alpha_\xi\}.
\]

若`u_u>u_l`，对每个mask计算

\[
P_{phys}(e=m\mid C_d,B_\xi)=
\frac{1}{u_u-u_l}\int_{u_l}^{u_u}
p_m\{F_D^{-1}(v);t,z,h,a\}\,dv.
\]

`Μ`中duration primitive的条件cell mass仍唯一为`p_{dξ}(C_d)=(u_u-u_l)/w_ξ`；上式不再乘该mass。若`u_u≤u_l`，该micro-branch的duration mass为0且不建child，禁止以0/0默认值恢复分支。D60、TIMEOUT和rank255 signed elapsed是真实结构atom，它们直接在其exact duration上评价上述16-mask法则；这不是representative点值化。rank255与D60的`Λ^{dir}`全为0。

continuous cell积分只使用`GL-CDF-SEGMENTED/1.0`。先把`[u_l,u_u]`在所有严格内部的`v_j=F_D((E_j-t_us)/10^6)`处升序分段；区间外的bin edge不产生分点，重合的binary64分点只保留一次。每段`[a,b]`使用64-node Gauss–Legendre表，以`v_i=(a+b)/2+(b-a)x_i/2`升序求值，对`w_i p_m(F_D^{-1}(v_i))`按node index升序做固定pairwise tree求和：每层从左到右相邻两项相加，奇数末项原样进入下层。各segment的结果按start升序用同一tree求和，最后除以`u_u-u_l`。64-node结果是training、Bayes、planner和terminal-boundary audit共用的唯一canonical forward值；128-node在同一runtime中只作audit。两者都调用上段stable `log1p/expm1` event law，不允许adaptive quadrature、representative fallback或临时容差。

node/weight表是按`x_0<…<x_{n-1}`排列的IEEE-754 binary64常数。规范生成记录为`numpy==2.3.5, numpy.polynomial.legendre.leggauss(n)`；实际runtime必须携带固定表，不在运行时重生成。唯一hash payload为ASCII `GL-BINARY64-v1\0`，后接全部`x_i`再接全部`w_i`的big-endian binary64 bytes。64点表SHA-256为`92CD28D4CC2EA02574BCE1C0C2D7CF769BCC3A528D214EDE7493BBCD6411F3C2`，128点表SHA-256为`81ADFE772788FD490376F5807520A7CAC419F8767584CBEE2CB5CBA74E2F5B2F`。独立reference path使用MPFR 256-bit precision、round-to-nearest-ties-to-even；Gold-09读取下文闭式，其他审计fixture读取等价的256-bit segmented reference，不进入训练、Bayes或planner。对任一mask必须同时满足`|P_64-P_128|≤5e-12`、`|P_64-P_ref256|≤5e-12`与`|P_128-P_ref256|≤5e-12`，且canonical forward 16-mask向量满足`|Σ_mP_m-1|≤5e-12`；任一超阈值都标`KERNEL-SCHEMA-INVALID`，禁止以clamp、事后重归一或更换积分器逃逸。64/128具体binary64值不作为跨平台预填常数；实现必须在同一pinned image内记录forward bytes、audit bytes、image/build hash与reference report，training、Bayes和planner只复用该64-node canonical bytes。

对任一observable global numeric cell`C(k_global)`，`kernel_measure_v1`返回

\[
M_{azh\eta e\xi}\{C(k_{global})\}=
\sum_{\substack{C^{prim}:\;Link_{codec}(C^{prim},\eta,e)=C(k_{global})}}
\prod_{c\in\mathcal P_{valid}}p_{c\xi}(C^{prim}_c),\qquad
P^G_{azh\eta e}(k_{global})=\sum_{\xi=1}^{19}w_\xi M_{azh\eta e\xi}\{C(k_{global})\}.
\]

`P_valid`只含真实随机primitive continuous heads；NA和结构性atom以质量1进入，derived `ΔD_w`不在乘积中，而由`Link_codec(ΔN_w,r_w)=round_half_even(ΔN_wr_w)`连同其他typed deterministic links push-forward。上式因此会对映入同一global cell的全部primitive cells求和，不会暗中恢复一个`ΔD_w` head。它是training observed-cell NLL、belief、nonterminal planning和terminal integration的唯一numeric likelihood接口。不存在一个用CDF训练、另一个把location当点质量规划的实现。离散`eta/e/o/j`仍按相应softmax/hazard质量乘入，tool-quality mixture不能重加权physical head。

#### 6.4.2 observed likelihood、proper NLL与Bayes update

episode起点、`PASSIVE-TICK`与任一action后的belief都消费同一observable tuple，并在更新前显式对`xi`与`h`边际化：

\[
L_z(T_a)=\sum_{h=1}^{8}\hat\pi^P_{zh}\sum_{\xi=1}^{19}w_\xi\,
P_{phys}(e\mid x^{exec},a,z,h,\xi,C_d)\,
\hat\Gamma^{tool}_{azh\xi\eta}\,M_{azh\eta e\xi}\{C(k_{global})\}\,
\hat O_{azh\eta\xi e o},\qquad
b'(z)=\frac{b(z)L_z(T_a)}{\sum_{z'}b(z')L_{z'}(T_a)}.
\]

`M`已同时包含observed duration/result/severity/accumulator cells；`P_phys(e|C_d)`只能由第6.4.1.1节的joint 16-mask函数经`duration_conditional_integrator_v1`得到。它在同一`B_xi`与observed duration cell内积分，不再乘一次duration cell质量，不先平均四个边际再相乘，也不把未观测的`d_xi`代表点当作真实duration。这一个64-node forward bytes必须同时进入`L_z`、`L_globalN`、Bayes denominator与chance-child mass；128-node只写audit。belief只影响下一次planner probability，不回写已确定的`x_exec`或ledger。若duration intersection为零、status、authority、signature、codec、decoder或积分审计任一不唯一，所有methods共同标`KERNEL-SCHEMA-INVALID`并报告failure-as-harm sensitivity，禁止选择“最接近的latent branch”或用raw float旁路。

`L_globalN`撤销旧版未定义的class-balanced score，唯一为统一测度的proper joint NLL。对一个由train split均匀按record抽取的、含`B_v`条schema-valid records的batch，

\[
L_{globalN}=-\frac{1}{B_v}\sum_{i=1}^{B_v}\log\left(\max\{P_\theta(\eta_i,k_i,e_i,o_i\mid x_i,a_i),2^{-52}\}\right).
\]

每条record的训练权重恰为1，归一分母恰为`B_v`；无效record不进入分母且另报invalid rate。schema-valid rank255 PASSIVE-TICK records也各以权重1进入该分母，其中结构性`η/o/duration`的质量为1，梯度只来自passage event/severity/accumulator cell likelihood；不得因其不是action而从训练删去、也不得重复计入相邻D60 record。仅为错误分析定义不反向传播的192类`c=(eta,e,o) in 4×16×3`宏平均NLL；零记录类不入该diagnostic均值，非零类每类权重为`1/|C_plus|`。该diagnostic不进入总损失、checkpoint selection或Bayes update。推断时Bayes式直接读未重权的`P_theta`，不做class-prior、temperature或importance correction；如果训练loader进行过采样，整个run为schema invalid。

### 6.5 Hard option-lattice recursion

期权格而非 neural policy 选择动作。对可行状态 `x`，定义

\[
V_\theta(x)=\max\{Q^{AB}_\theta(x),Q^{EX}_\theta(x),Q^{D60}_\theta(x),\max_{m\in\mathcal M(x)}Q^m_\theta(x)\}.
\]

`Q^{AB}`与`Q^{EX}`都由第6.5.1节唯一terminal kernel积分。由该kernel求得的`p̂_θ(d∨r|x,EX)`只是一项预测概率；候选`π_{θ,γ}`仅在其不高于`γ`且protocol mask合法时开放`EX`。checkpoint固定后，第4.2与5.5节仍只以独立`VAL-CAL-POLICY`真实outcomes资格化 severe `d∨r`、success和reference noninferiority。

#### 6.5.1 唯一联合semi-Markov kernel、observable branch与event-after-action更新

任一nonterminal action只有在`HARD_START_a(x)=1{mask_protocol=1,t+d_max(a)≤600}`时进入kernel。模型内的micro-branch为`(z,h,ξ,η,e,o,C_global)`，其中`ξ∈{1,…,19}`是`kernel_measure_v1`的共同stratum，`C_global`含duration、typed result、severity与accumulator codec cells。唯一允许的生成顺序为

\[
\begin{aligned}
\widetilde Q_\theta^a(z,h,\xi,\eta,e,o,C_{global}\mid x)
=&\ b(z)\hat\pi^P_{zh}w_\xi\,
P_{phys}(e\mid x^{exec},H_0,z,h,a,p,t,\xi,C_d;M^{closure})\\
&\times \hat\Gamma^{tool}_{azh\xi\eta}\,
M_{azh\eta e\xi}\{C_{global}\}\,
\hat O_{azh\eta\xi eo},
\end{aligned}
\]

`P_phys(e|C_d)`不是把passage与direct的最终event概率相乘，也不在duration representative上取hazard点值。它严格调用第6.4.1.1节：对同exact duration先用冻结10-bin整60秒概率和`ω=Δ/60000000`合成pass/direct bit survivals，再形成joint 16-mask、执行`post_link_projection`，最后在`C_d∩B_ξ`内用hash-locked 64-node分段Gauss–Legendre积分。`M{C_global}`以同一测度给出duration/result/severity/accumulator cell mass，内部仍使用冻结的`D/R/K`、passage/direct/resource heads与deterministic links；它不重复乘duration质量。并令`Δg=G_a(x_exec,η,r_a)`、`κ′=KAPPA_a(x_exec,r_a,C_d,e)`、`Δℓ=Componentize_v3(observable_record)`。`Δg`没有独立随机head、cell或loss；CP/WC的persistent path只能由action-valid `R_tool` fields经01H-A truth table解码。`P_pass`没有action/status/path输入；`P_dir`的全部祖先先乘`physical_causal_closure_v3`再过nonlinear link；`Γ_tool/O`位于physical links之后。不允许先分别积分四个边际概率再相乘，不允许为direct另选暴露时点，也不允许在给定micro-branch cell后另外重抽duration、result、severity或accumulator。

micro-branch随后由`GLOBAL-TYPED-CODEC/1.0`投影为observable typed record`T_a`。规划用的唯一branch distribution是push-forward

\[
Q_\theta^a(T\mid x)=\sum_{\widetilde T:\;\operatorname{Canon}_a(\widetilde T)=T}\widetilde Q_\theta^a(\widetilde T\mid x),
\]

上式的求和符号只对离散`z,h,ξ,η,e,o`和第6.4.1节已定义的global cells求和；唯一cell内积分已被`duration_conditional_integrator_v1`完全定义，不存在另一个点密度、adaptive或representative积分器。其key为`canonical_record_hash`，不含`z/h/ξ/model seed/posterior`。多个latent micro-branches或多个`ξ`若产生同一observable record，必须按`kernel_measure_v1`先合并包含64-node event conditional mass的全部质量再建一个chance child；不得让同一record产生多个next states。`KAPPA_a`逐字段唯一，`trace_cursor=t_end`且不再用`min(·,600)`掩盖越界，因为hard-start与runner已保证`t_end≤600`。真实planner projection key为`SHA256("PLAN-COMP-v3"||world_id||episode_reset_id||action_slot||action_start_us||canonical_record_hash||component_type||oracle_version||local_index)`；evidence/outcome用独立domain separator，全部删除latent与state-hash输入。

terminal action仍从`b`与第6.3节terminal allowlist投影后的`x_exec`积分；`p/q_n/ℓ^{evid}`和既往tool status不得进入下式任一head。令`C_v,C_t,C_K`分别为terminal semantic rate、duration和六个accumulator的global-codec cells，唯一terminal branch为

\[
Q_\theta^a(j,C_v,C_t,C_K,z,h,\xi\mid x)=b(z)\hat\pi_h^T(x^{exec},a,z)w_\xi\,
\mathrm{Cat}(j;\hat J_{azhj})M^T_{azhj\xi}\{C_v,C_t,C_K\},
\]

其中`j=(s,d_new,r)`，`M^T`是第6.4.1节的同一CDF/cell测度，而不是`location`的点相等指示。`v_T`使用固定`Ω_v` ID/weight/denominator，`u_T,w_T`只由`c+Δc`确定。EX的state-level severe risk唯一计算为上式在所有`z,h,ξ,j,C_v,C_t,C_K`上对`1{C_d_pre=1 or d_new=1 or r=1}`的总质量；连续cell必须先按`M^T`积分，不得代入median或用`v_hat=V_hat`判定风险。第6.4.1.1节的10个hazard bins只覆盖nonterminal passage的`[0,600)`；exact `t=600`及EX/AB后续窗口由当前terminal `Π_T/J/M^T`与sealed trace一次处理，不外推`Λ_pass/dir`或回写`I_9`。EX/AB duration分别结构限于`[0,120]`与`[0,60]`；`t_T`可到720/660，但terminal开始后不再开放nonterminal。已有`C_d`与`d_new`按逻辑或合并，terminal只写一次`C_r/C_sax/C_v`。真实rollout以sealed oracle记录为准，模型只用于事前积分。

第三轮`F_a^{v3}`已被撤销，不是runtime、测试或基线可选接口。

实现前运行六项state mutations。`MT-STATE-01/02`固定同一CP/WC pre-state与`η/e/o/d`但改变合法quantized result fields，要求不同`k_global`产生不同`g`、executor/planner hashes和后续typed kernel。`MT-STATE-03`固定pre-state与signed record，仅改变posterior/model seed，要求executor与ledger hashes相同、planner hash允许不同。`MT-STATE-04`在`t=590`遍历所有nonterminal actions，要求无kernel branch、无invocation与无consumption；`MT-STATE-05/06`分别执行下段Gold-03/04。任何失败属于实现错误。

唯一runtime接口为`F_a^{v4}`：①wrapper运行最多`min(1.000s,600-t)`的precheck，并无条件先用`PASSIVE-ADVANCE-v1`把实际elapsed区间推进为新canonical state；②在该post-passage state同时核验protocol与hard-start mask，到600时直接terminal-only；③若所选action仍合法则创建唯一`action_invocation_id`并由runner在`d_max`内返回signed record；④global codec生成`canonical_record_hash`，再由同一invocation的observable source IDs生成`runtime_binding_hash`并以固定componentizer补全`Δℓ` identity，形成唯一`T_a`；⑤只从`T_a`应用`r_a,Δg,κ′,Δℓ,Δc,t_end`并生成`executor_state_hash`；⑥以`kernel_measure_v1`对global cell的未重权边际likelihood更新`b`；⑦按started status更新`p/q_n`并重算`τ,A_mask`。若步骤②失败，只记录`mask_changed`且不创建invocation、不消耗slot/type/action-invocation resource，但步骤①中真实的passage outcome与maintenance cost已入账。`MT-STATE-05`重放Gold-03，对“只改`t`”或丢失区间event的实现必须失败；`MT-STATE-06`对Gold-04的无native-deadline precheck要求`t=600`、terminal-only且不存在越界state。

因此nonterminal Bellman项只用observable component增量：

\[
Q_\theta^a(x)=\sum_T Q_\theta^a(T\mid x,a)\left[U\{Y(F_a^{v4}(x,T))\}-U\{Y(x)\}+V_\theta(F_a^{v4}(x,T))\right].
\]

terminal项同理积分`U(Y_T)-U(Y(x))`，trajectory reward严格telescope为一次`U(Y_T)`。在任一epoch重算hard-start后，所有不满足`t+d_max≤600`的nonterminal位立即清零；到`t=600`只比较mask-legal的`EX/AB`，两者均不合法才`EXPIRED`。

#### 6.5.2 可采纳上界、memo key与确定性搜索

最多四项mitigation、两次defer和一个terminal action，depth不超过七。对任一可见canonical state，定义不读取future truth的terminal-credit上界`R_max(x)`：若只用当前protocol automaton、剩余slots和mask的宽松可达性图仍存在到`EX`的路径则为100；否则若存在到`AB`的路径则为`-25`；否则为`-40`。可采纳state upper bound唯一为

\[
UB(x)=R_{max}(x)-500\mathbf1[C_d\in\ell]-50\min(A_u,2)-0.02t-0.001\bar c_{cpu}-0.002\bar c_{io}-0.01\bar c_{store}-U\{Y(x)\}.
\]

`V(x)`与`UB(x)`都按“从当前state起尚可获得的效用增量”计，因此最后减去当前partial utility `U{Y(x)}`；terminal精确值相应为`U(Y_T)-U(Y(x))`。`\bar c`使用第4.2节冻结normalizer。该式有意忽略未来`v,w,r`和所有未来非负cost，只在可达terminal total上扣除不可逆的已发生成分；宽松可达性也忽略未来duration与event，故不会低估剩余可实现增量。任何使用hidden `z`、future trace/fault、terminal truth、sibling outcome或test statistic的bound均判为泄漏。

memo key是`SHA256("LBM-1.5"||world_id||episode_reset_id||checkpoint_hash||gamma_value||utility_hash||H0_hash||candidate_universe_hash||operator_schema_hash||planner_state_bytes)`。`planner_state_bytes=CBOR(b,executor_state_bytes)`；`executor_state_bytes`按固定字段序编码`p,q_n,g,κ`、去重后的observable evidence/event/component IDs及累计量、`c,t,τ,A_mask`。这些ledger IDs已经按`world/action/start-time/raw-event/component/oracle-version`构造，所以真实post-state memo保留必要的observable identity而不读binding hash旁路。defer计数`q_n`是可观察executor事实并必须进入memo；raw payload、future fields与latent/mixture/quadrature索引`z/h/ξ`永不进入memo key。固定world/action/start下的pre-event chance child以`canonical_record_hash`区分，其假想ledger identity由`PLAN-COMP-v3`唯一生成。碰撞必须比较完整bytes。不同world/reset、`γ`、utility或checkpoint绝不共享memo table；相同executor事实但不同belief使用不同planner key，这是规划差异，不改变executor/ledger identity。

搜索采用AND-OR branch-and-bound。terminal node有相同精确上下界；decision node取子action bounds最大值；chance node按已对`z/h/ξ`边际化的observable record probability加权。未展开state的lower bound来自固定fallback：`AB`若合法，否则`EX`，否则`EXPIRED`。priority tuple固定为`(-probability_weighted_gap,-UB,depth,root_action_rank,action_sequence_lex,result_status_rank,event_mask_numeric,observation_rank,k_global_hex,canonical_record_hash,planner_state_hash)`，status rank为`OK<DEGRADED<TIMEOUT<FAILED`。若decision child的`UB`不高于incumbent lower bound可prune；chance child不得因低值删除，只能在observable record和上下界均相同后折叠。任何priority、memo或dedupe tuple都不得恢复`z/h/ξ`；这里的禁止项不包括可观察defer计数`q_n`。

每个root state最多展开200,000个states。cap前若root gap为0，记录exact certificate；触及cap则选择lower bound最高的root action，平手按上述action rank，并记录selected lower bound、root upper bound、certificate gap、frontier size与pruning counts。若所有terminal fallback都不合法，执行`EXPIRED`而不凭未来truth挑动作。所有planning baselines共享同一`kernel_measure_v1`、fallback、memo codec、priority、cap和tie-break。

训练时把 `max` 替换为 temperature 0.10 的 log-sum-exp，仅用于让 lattice-calibration loss反向传播；推断和 episode evaluation 使用 hard max。value of waiting、active information 和 non-exercise 因此在同一 recursion 内比较，不由独立辅助分数拼接。

### 6.6 损失函数与监督

模型只从 train split 学习。总损失固定为

\[
\mathcal L=0.5L_z+L_{globalN}+0.5L_{pass}+0.5L_{direct}+0.5L_{tool}+0.5L_{resource}+L_{term}+0.2L_{lat}+0.1L_{cal}.
\]

- `L_z`：五个 injection mechanism 的 multi-label BCE；只用训练环境已知 bit，test bit从不输入。
- `L_globalN`：对同一observable`(η,k_global,e,o)`的未重权proper joint NLL；每条schema-valid train record权重为1，按valid-record count归一。它只调用`kernel_measure_v1`，先在每个`z/h/ξ`上用global codec boundaries计算CDF/cell质量，再用`duration_conditional_integrator_v1`对observed duration cell计算joint 16-mask conditional mass，最后按冻结`w_ξ`与`Π_P`边际化`ξ/h`。它同时监督`Π_P/Γ_tool/O`、hazard logits及连续cell likelihood；不得另造latent-specific cell、class-reweighted deployment probability、belief-only likelihood、边际event先积分后相乘的surrogate或representative-duration NLL。`(η,e,o)`的192类macro NLL只作stop-gradient diagnostic。
- `L_pass`：只用absolute interval、production authorities与passage labels监督`g_pass/S_pass/K_pass`；对passage-only记录把`Λ_dir`结构置0，并以同一fixed 64-node integrator计算observed 16-mask joint NLL。matched-duration records跨action共享target，public/shadow/probe不得生成production label。
- `L_direct`：只用source-authority可归因的声明direct paths监督`g_dir/S_dir/K_dir`；允许cell在同一exact duration上与shared passage survival合成后，仍以同一fixed 64-node joint-mask likelihood计算，不训练一个与deployment不同的direct-only边际分类器。`physical_causal_closure_v3`在forward中精确归零禁止ancestor，禁止用惩罚项近似结构零。`Δg`不设独立loss，只由`L_tool`监督的action-valid result fields经固定decoder产生。
- `L_tool`：监督duration、status、action-valid 13-channel result与observation的discretized-logistic/分类NLL；这些heads不反向连到physical marginals。
- `L_resource`：只由cgroup与gateway opportunity records监督CPU/I/O/storage及合法WC write/availability direct increments；accumulator label只消费`ℓ^{out}`和`C_res`，public evidence不产生`v/d` label。
- `L_term`：对`Π̂_T,Ĵ,V̂_v,D̂_T,K̂_T`的联合mixture NLL与conditional quantile loss；`V̂_v`只监督同一`Ω_v` denominator上的weighted rate，`u/w`只由`K̂_T`派生。
- `L_lat`：只在`ENUM-TRAIN`中当次 selector冻结的四个代表slots及其仍合法subset上计算。label是common-seed、fixed-slot-selector、fixed-`π_ref` continuation的empirical partial return ranking；未选的十四个参数slots及`D60/EX/AB`不进入该项。soft lattice与每个可比baseline只在完全相同四-slot comparison set上以权重0.2消费同一records；它是辅助partial label，不是full oracle。
- `L_cal`：仅对由`Ĵ`求和得到的`d∨r`边际计算Brier loss与differentiable calibration-bin penalty。

主模型的`L_lat`不能另建policy head；梯度必须通过recursion回到primitive kernels。global codec、truth table、hard-start mask与causal-closure artifact均无可学习参数，不能因loss下降而移动cell boundary或开放direct path。它不能用`ENUM-TEST`、CodeTwin test或任何calibration world。loss weights在本修补规格中预注册，不按test调整。另报告不含`L_lat`、不含injection-bit auxiliary supervision与只用observational trajectories的消融，检验优势是否来自额外标签。

同一partial label的消费接口也冻结：主模型、`G-PhysicalFactoredSMDP`、`G-JointSMDP`与`G-AdditiveOption`都经各自soft recursion产生四slot logits；`G-POMDP`使用同一state下actor的四slot logits；`G-DirectQ`使用四slot distributional-Q均值 logits。它们都在相同records、comparison mask、temperature与权重0.2上计算cross entropy，不能只把label文件交给某模型却不给loss入口。

### 6.7 训练和推断动作

optimizer 固定为 AdamW，learning rate `2×10^-4`、weight decay `0.01`、gradient clip `1.0`、5,000-step linear warmup 后 cosine decay，transition batch 64，最多120,000 updates。每2,000 steps只在冻结的`val-select` transition dataset上评估primitive NLL、Brier/calibration error、duration/cost error和fixed-continuation mitigation-order regret；不为每个checkpoint重跑端到端数据库policy，也不使用raw test endpoint。early stop patience为八次evaluation，并以预注册 composite `NLL_zscore + order_regret_zscore + calibration_zscore` 最小为准。

checkpoint及所有hyperparameters冻结后，为每个model seed实例化五个`γ`候选。每个候选与固定`threshold-canary` reference在相同1,000个`VAL-CAL-POLICY` worlds上从snapshot分别真实执行；按第4.2节以`α/15`同时计算harm CP上界、success CP下界和paired Hoeffding noninferiority下界，形成qualified set后按冻结词典序选择唯一`γ`。这一过程不能更新weights、operator、utility、reference、candidate set或generator。`VAL-CAL-POLICY`不进入论文主效应估计；test解封后不得重新选择`γ`。model seeds固定为`{17,31,47,61,73}`并分别报告，不按结果挑选。

推断时analyzer只为十八个固定slots构图，网络输出joint primitives，hard lattice在统一21-slot protocol+hard-start mask上选唯一action。executor不接收latent branch；它把signed output交给`GLOBAL-TYPED-CODEC/1.0`，取得唯一`T_a=(η,k_global,e,o,r_a,Δg,κ′,Δℓ,Δc,t_end)`后只用该record写回`x_exec`，再独立更新belief。若执行前precondition或`t+d_max≤600`变化，返回`mask_changed`且不创建invocation、不消耗slot/type/resource；started后的timeout/failure在`d_max`内形成相应status、计真实资源并消耗type。合法started action不跨600秒，到`t=600`严格terminal-only。

### 6.8 同数据、同参数的通用替代

所有learned baselines接收同一份`C/G/X/P/R_phys/L_evt/τ`、十八slots与21-slot order/action mask、逐slot `d_max`、同一个`physical_causal_closure_v3.npz`、typed passage/direct prior、raw signed transitions、global codec records、siblings、risk bits、`Ω_v` terminal labels、ENUM partial rankings和split。主模型与`G-PhysicalFactoredSMDP`用字节相同但storage独立的clones实现`Fusion_static/H_0`、candidate embeddings、passage/direct/tool/resource heads及`Π_P/Γ_tool/D/R/K/g→Λ/S/O/J/V_v`接口、global codec、`kernel_measure_v1`、同一`time_bin_edges_us`、cloglog整箱语义、`ω`规则和hash-locked `duration_conditional_integrator_v1`、belief、typed `g/κ/dual-ledger` transition、全部loss、optimizer hyperparameters、qualification worlds、hard recursion、memo/pruning/tie-break和200k cap。两者获得同一visible serializer；主模型按理论firewall读取显式ordered slots，generic用下段history residual读取同一`P`，不会少拿任何标签、状态或行动。唯一结构差异是direct residual parameterization。

| Baseline | 保留信息与预算 | 与 `OptionKernelNet+Lattice` 的唯一结构差异 |
|---|---|---|
| `G-PhysicalFactoredSMDP` | 上段逐对象相同的visible inputs、labels、21 actions、`d_max`、codec、causal artifact与预算 | 保留相同action-invariant passage和post-link causal closure，只把main+ordered-pair direct factor换成下段unrestricted history residual；其余kernel、transition和planner逐对象同构。它是理论生死基线 |
| `G-JointSMDP` | 相同encoder、action/history/time/mask、raw labels、全部actions与search | action-conditioned Transformer直接预测joint next-observation/state/outcome；physical mask作为输入并禁止不合法action，但不拆分primitive impulse；用generic finite-horizon SMDP DP |
| `G-POMDP` | 相同encoder、risk-bit auxiliary label、episode/transition、全部actions、参数与FLOPs | recurrent latent belief、learned transition/observation/reward与risk-constrained actor-critic；defer/exercise/abandon作为普通actions但不被移除 |
| `G-DirectQ` | 相同history、`SIBLING-TRAIN`与`ENUM-TRAIN` labels、action/physical masks | Transformer直接预测distributional Q/advantage；同样经过policy-level risk calibration，无world-kernel或option-impact recursion |
| `G-AdditiveOption` | 相同primitive heads、physical masks、lattice、actions、labels与search | 固定`v_{r,j→m}=0`，只保留各action main impulse，检验independent/additive方向错误 |
| `G-LatticeNoRole` | 与主模型相同factor、terminal lattice、全部actions、physical masks、time、search与labels | 只把`R_{r,ρ(j),ρ(m)}`替换为该family九个role-pair gains的共享均值，并打乱进入该表的role labels；slot/candidate identity、ordered pair、physical masks和typed persistent state全部保留，因而是role-tying干预而非删物理知识 |
| `Iso-OptionImpact` | 完全相同 | 只把`base/main/pair`和role构念改成匿名代号；应逐batch、逐梯度、逐action完全一致，用作实现同构检查，不作为可被击败的竞争基线 |

`G-PhysicalFactoredSMDP`的residual serializer顺序固定为`[CLS],H_0,e_m,a_contract,b,g,κ,ℓ^{evid},ℓ^{out},c,t,τ`后接六个`P` tokens，恰为18 tokens；`a_contract`含相同slot与`d_max`。十八项各用一个带bias的独立linear投影到384维。encoder唯一为4层pre-LN bidirectional Transformer，每层`d_model=384`、6 heads、attention dropout=0.10、residual dropout=0.10、一个`Linear(384,W,bias=True)→GELU→Linear(W,384,bias=True)` FFN，并用learned absolute position18且无causal mask；四层使用同一整数宽度`W`，但不共享参数。`[CLS]`对固定family序`(tool,obs,dur,evidence,persist,availwrite,resource)`分别经`Linear(384,r_f,bias=True)→GELU→Linear(r_f,d_f,bias=True)`输出closure允许轴的residual，其中`d_f=(608,29184,152,464,1976,7528,21888)`；禁止共享rank、额外adapter或未进入该族forward/loss的补偿参数。

`GENERIC-QUOTA-v4`不留人工选择。候选域唯一为`W∈{384,385,…,3072}`且七个`r_f∈{1,2,…,128}`；待选tuple顺序固定为`q=(W,r_tool,r_obs,r_dur,r_evidence,r_persist,r_availwrite,r_resource)`。将所有不随`q`变化的generic可训练参数数目记为`P_fixed`，主模型实际`requires_grad=True`的数目记为`P_main`，则候选数目必须按包含bias的精确整数式

\[
P_G(q)=P_{fixed}+4(2\times384W+W+384)+\sum_f\{(384+1)r_f+(r_f+1)d_f\}
\]

计算。先丢弃`P_G(q)≠P_main`的tuple，再丢弃固定probe上训练或推断multiply-add相对差大于0.005的tuple。对剩余有限集取唯一字典序最小值

\[
\arg\min_q\big(\max\{\delta_{train}(q),\delta_{infer}(q)\},\delta_{train}(q),\delta_{infer}(q),W,r_{tool},r_{obs},r_{dur},r_{evidence},r_{persist},r_{availwrite},r_{resource}\big).
\]

该`argmin`是规范本身，实现可用有界dynamic programming或分支剪枝加速，但不得改变候选集、比较key、可行性判据或全局最优解。若可行集为空，整个配置无效；不得放宽参数等式、0.5%阈值或整数域，也不得在观察结果后改tuple。

初始化只共享bytes，不共享活对象。唯一`quota_seed/model_seed=2026081604`，PRNG为PyTorch Philox且deterministic-algorithms开启。builder先用该seed生成`shared_init_v4.bin`，分别load到`MAIN-CLONE`和`GENERIC-CLONE`中同名同shape部分，在step0核对逐tensor SHA后立即检查data pointer全部不同；两个optimizer state、gradient buffer和checkpoint独立。generic专属residual按tuple序及各module内部parameter名的UTF-8字典序，从`SHA256("GENERIC-RESIDUAL-v4"||quota_seed||module_name)`派生彼此不重叠的Philox子流；这个seed只确定initial bytes与probe形状实例，搜索本身无随机性。`CLONE-GOLD-01`令main单独更新一步，要求generic所有bytes不变；02反向检查；03从两checkpoint reload后重做pointer与hash审计。

前六个竞争模型的trainable parameter count须与主模型完全相同；理论生死比较中`G-PhysicalFactoredSMDP`还必须使用与主模型完全相同的visible bytes、raw/global/partial labels、21-action mask、每动作`d_max`、训练records与split、update次数、batch order、optimizer/scheduler、precision、gradient-accumulation/clipping、early-stop metric、tool invocations、rollouts、tree expansions、200k cap和wall-clock limit。`FLOP-PROBE-v4`在数据解封前用上段seed构造两组shape-valid但不含数据的tensor：train固定`B=64,L=18,A=21,Z=32,H=8,Q=19`，inference固定`B=1`且其余形状相同；二者分别遍历21个root-action rank，每个rank使用其在01H-A中冻结的action-validity、physical-closure与result-validity masks，数值payload只由seed生成，不得把不合法axis设为active。`parameter_count_v4.py`从PyTorch FX展开后对所有实际执行的dense/sparse linear、attention、einsum和matmul统一计整数multiply-add，一次乘加记1 MAC；train值为forward、parameter-gradient和input-gradient三条实际graph之和，inference值只取forward。定义`δ_train(q)=max_{a=0..20}|MAC^G_train(a,q)-MAC^M_train(a)|/max(MAC^M_train(a),1)`，`δ_infer`同理；稀疏分支按probe中真实执行的index计数，禁止以padding、未调用branch或只报dense theoretical count补平。

唯一选中tuple、完整候选域、比较key、`P_main/P_fixed/P_G`、两组逐21-action MAC、软件版本、seed、script/source hash在解封任何train/validation/test labels前写入`generic_quota_v4.json`，再由`parameter_count_v4.py --verify-manifest`从空进程重算并字节比对。该manifest只记录上述唯一`argmin`，不是实施者选型入口；当前hash为`PENDING-IMPLEMENTATION`，不冒充已生成。任一参数不等、任一逐action的train/inference MAC差超过0.5%或重算bytes不同，配置整体无效；不能缩小输入、labels或actions补平。`G-POMDP/G-DirectQ`匹配同一预算但不伪造tree nodes；理论生死比较以共享DP的`G-PhysicalFactoredSMDP`为准。

如果`G-PhysicalFactoredSMDP`与主模型能通过全局参数置换在所有输入上得到同一forward/loss/action，属于设计级同构失败，须由独立再红队处置。若两者不同构但generic模型在finite-data、unseen-combination及本benchmark各held-out slices上的harm、success和cost均落入预注册等效界限，即harm差不超过1 percentage point、success差不超过2 points、cost差不超过5%，则不再主张Benaroch带来独立算法贡献。后者是结果门，不得因尚未运行而提前判定。`Iso-OptionImpact`不完全一致则是实现错误。

## 8. 实验矩阵、机制干预与统计

### 8.1 评价切片

除第5.5节的repository-OOD test cube外，再从六个train repositories构造不参与训练的`ID-eval`：24个migration tasks、risk configurations`clean+五个singleton`、`W0–W2`和seeds`{300,301,302}`，共1,296个worlds。它与训练只共享repository/migration identity，不共享snapshot、data、workload、fault或injection seed。四个预注册切片为：

1. `ID`：`ID-eval`，检验在见过 repository/motif 后的新 episode。
2. `Repo-OOD`：`A11–A18`、`W0–W2`和clean/singleton risks，以八个repository family为最高推断单位。
3. `Workload-OOD`：`A11–A18`上的`W3` hot-key burst。
4. `Risk-combination-OOD`：`A11–A18`上两个held-out pairs与两个triples。

每个冻结 policy 在同一 `world_id` 上独立 reset 后运行。主要 learned models 各用五个 model seeds；非学习基线无 model seed但使用所有 world seeds。若环境失败导致 world 缺失，则所有 policy 同时删除该 world，并报告 paired-complete 与 failure-as-harm 两种口径，不能只删除某一模型的 executor failure。

### 8.2 主比较

主比较首先是`OptionKernelNet+Lattice`对`G-PhysicalFactoredSMDP`，再对`G-JointSMDP`、`G-POMDP`和`G-LatticeNoRole`。每个切片同时报告`d∨r`、`s`、`v`、`u`、`w`、wall-clock、resource、abandon、expiry和`U`；在matched success下比较harm，在matched harm下比较success/cost，并给bootstrap Pareto dominance probability。fixed-system与direct-policy baselines提供实践位置，但不替代理论反证。

有限数据实验固定使用完整 train 的 `{10%,25%,50%,100%}` world groups，整个 sibling group按比例抽取；所有模型使用同一 subset。组合泛化实验从训练中删除所有同时包含 `M_CP` 与 `M_WC` 的 path records，但保留两个 action 的单独数据，再在这些 sequence 上测试。长序列实验按 terminal 前 decision count `{1–2,3–4,5–7}` 分层。不能用 lattice 额外获得被删除组合的 terminal label。

### 8.3 理论机制干预

以下干预不改变 encoder 参数预算；释放的参数移入 active FFN 并重新训练。

1. `No-Abandon`：移除 `AB`，检验 non-exercise boundary。
2. `No-PassiveInfo`：保留 `D60` 的时间和成本，但把 defer observation随机置换，检验 wait-and-see。
3. `Unordered-Path`：令`W_r^{→}`对称并忽略先后次序，只保留无向pair interaction。
4. `Additive-Impulse`：固定全部`v_{r,j→m}=0`，只保留各action独立main impulse。
5. `Role-Neutral`：仅把九个role-pair gains中和为family均值并打乱role-table索引；保留slot identity、ordered pair、physical residual mask与typed persistent state。
6. `No-Lattice-Loss`：删掉 `L_lat`，检验 recursion 是否真正影响训练。
7. `Code-Blind`：采用`No-Source+TwinInvariantCandidates`，删除source/ORM/query与analyzer score，同时保持candidate universe/order/mask完全相同。
8. `Observation-Blind`：保留 action完成与成本，打乱 `green/amber/red`，检验信息是否改变后续 action。

每个干预同时报告 primitive parameter error、belief calibration、action distribution和 episode outcome。若只改变 auxiliary loss而实际 action不变，不能声称理论机制成立。

### 8.4 预注册冲突测试

`ENUM-TEST`用共同随机数计算四个冻结代表slot的fixed-`π_ref` mitigation-order regret，并检验语义定位、恢复—负载两个mitigation顺序冲突；它不是完整option-policy oracle。

- 对每个可比较 state/path，计算 `M_SR→M_SV` 与 `M_SV→M_SR`、`M_CP→M_WC` 与 `M_WC→M_CP` 的 empirical return difference及置信区间。
- 按`R1–R5`和冻结的pre-action canonical state分层，检验两个mitigation动作对的排序是否反转。
- 比较lattice与65条fixed-continuation mitigation-order sequences中的最佳顺序；只报告这一限定对象的regret，不写“完整sequence”或“exhaustive oracle”，也不把future outcome输入任何policy。
- 信息—到期冲突另在held-out full-policy worlds上比较包含全部21 slots的冻结policy；这些worlds不进入训练、early stopping、calibration、selector或conflict定义，且不能与65条order regret合并。
- 在CodeTwin-v1.2上以`A11–A18`为primary、`A01–A10`仅作diagnostic，比较`Full-Code+Analyzer`、`No-Source+TwinInvariantCandidates`与`SchemaTelemetryOnly`；`Shuffled-Repository`只作source-sensitivity falsification，不进入primary superiority family。外部severe `d∨r`、success与cost必须闭环，shuffled条件的mismatched harm不得解释为代码正确性。

排序反转、code necessity 和 lattice advantage均是待运行假设。若真实执行没有产生反转，不通过 rescue gate 1；不能事后增加 action、改 defect或修改 utility制造反转。

### 8.5 统计方案

test的primary estimand是八个预注册synthetic app families上的有限平均paired effect。binary endpoints的secondary model使用method与migration motif固定效应、migration task nested within app的random intercept，并把model seed nested within method；不再把app与migration写成交叉抽样总体。primary不确定性以八个app级paired effects计算，报告small-cluster wild cluster bootstrap-t区间、app-level sign/randomization敏感性与逐一leave-one-app-out结果。continuous heavy-tailed cost使用相同app级paired聚合的median/trimmed-mean差与Cliff's delta；普通world或migration bootstrap不能创造额外repository units。四个primary slices与三个primary method contrasts构成一个Holm-controlled family，双侧`α=0.05`，同时报告未校正区间、绝对效应和world-level data。

等效性门使用第 6.8 节 margin 与 two one-sided tests。Pareto结论要求 harm、success和至少一个 cost endpoint在 cluster bootstrap 的 95% 区间内满足弱优势，且至少一项为严格优势。failure case按 code interpretation、observation、hazard、severity、planner、executor、substrate与oracle failure分层；无法判定的 episode单列，不归入成功。

### 8.6 泄漏与公平审计

在训练前运行以下自动检查：同一 sibling group是否跨 split；source/target hash、injection template hash和 workload trace是否近重复；hidden file路径是否出现在 tokenizer input；future telemetry timestamp是否晚于 decision time；test repository token n-gram是否进入 retrieval index；parameter/FLOP/search budget是否越界；任一 baseline是否缺少主模型拥有的 raw label。审计脚本失败则整次 run 无效。test只能在所有 hyperparameter、utility、operator threshold与checkpoint selection冻结后解封一次；额外调试产生新 benchmark major run并完整披露。

### 10.3 理论中间状态的不可装饰门

ACAA的专门attention需要指出common affinity在特定机制下的错误方向，DSDL的`F-E`具有不可交换方向。本研究对应的最低标准是：`OptionImpactFactor`必须让重叠措施的后置边际impulse能够收缩，让相反顺序具有不同作用；ordered path、defer information和exercise/non-exercise必须同时进入recursion；kernel mask必须改变可传播的作用路径；删除pair、打乱顺序或中和role后应在预注册冲突中改变actual action。只让一个auxiliary head更准、最终action不变，不满足该标准。

同时，本研究没有资格声称raw POMDP“天然不懂期权”。一般模型在函数类上能够表达同一policy。`G-PhysicalFactoredSMDP`获得完全相同的物理知识、动作和Bellman边界，只删除option-impact tying；`G-JointSMDP/G-POMDP/G-LatticeNoRole`继续检验更一般替代。这个对等替代门是理论贡献的组成部分。若公平物理基线与主模型逐梯度同构，属于设计失败；若不同构但经验等效，属于结果失败。

## 11. 条件设计的再红队纪律与撤题门

设计失败与结果失败分开登记。path firewall可被绕过、global codec或executor hash依赖`z/h/model/posterior`、同一signed record产生不同`x_exec/ledger`、任一合法action仍可跨600秒、evidence可改写结果分母、tool status可重加权physical head、matched-duration禁止direct path仍有非零Jacobian、main/generic存在live parameter alias、主模型与公平物理SMDP全局置换同构、joint terminal/typed state/causal artifact无法实例化、CodeTwin在t=0非代码通道不等值或checker必然矛盾，属于设计错误并回到独立再红队。四项mitigation不可省略、defer无信息、code channel不改善外部结果、generic模型经验等效、排序不反转或Pareto优势不成立，属于预注册结果门；结果尚未运行本身不能作为当前设计否决依据。

尚未实现的container digest、repository hash、episode count和checkpoint hash必须写成`PENDING-IMPLEMENTATION`，不能留空或伪造。任何会改变app family、migration motif、operator、utility、policy candidate、continuation、split、enumeration tier、codec、causal kernel或baseline的修改都使`MOL-RC/1.5-REPAIRED`失效，必须产生新版本并重新独立红队。
