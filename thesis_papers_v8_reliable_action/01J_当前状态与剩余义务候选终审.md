## 1. 被终审的最强版本，而非三状态分类器

为了避免否决一个过弱稻草人，本次审查采用该候选可能达到的最强版本。研究对象是一个能够读取仓库、执行命令、修改文件、运行测试并保留或回滚工作区的 coding agent。它收到问题描述和一个不保证处于初始状态的仓库快照。仓库可能尚未开始修改，可能保留了部分正确工作，也可能已经解决任务；现有修改还可能混有无关改动、错误尝试或新增回归。agent 在每个时点都要在继续取证、局部修复、验证、保留现状、回滚部分修改、请求人工确认和停止之间选择。

本候选真正要减少的损害有四类。

1. **无谓修改。** 已经满足任务的仓库仍被编辑，带来评审、合并和部署风险。
2. **正确工作的覆盖。** agent 未识别已满足的行为义务，重写正确实现或用一个整体补丁覆盖局部正确改动。
3. **新增回归和连锁破坏。** 修复剩余问题时破坏已经满足的目标行为、既有功能或跨文件约束。
4. **错误停止与错误继续。** 证据不足时过早宣布完成，或者已经完成后仍持续消耗计算、工具调用和人工复核。

风险发生在每一次实际工具行动之前，而不只发生在最终提交时。行动时可见的信息包括问题文本、当前代码与差异、版本历史、已公开测试、编译和静态分析结果、此前工具轨迹及其成本。不可见或不确定的信息包括隐藏测试、真实剩余义务、当前补丁的全部副作用、某个证据动作的价值，以及局部修改能否沿一条无回归路径继续到完成。仓库内容还可能陈旧、无关或错误，因此“已有改动”本身不是可信监督。

拟议控制器的正常动作空间应至少包括：

- 取证动作：查看历史、定位符号、构造或运行最小复现、获取动态切片、运行目标测试、运行回归测试、比较行为；
- 修改动作：局部编辑、生成候选补丁、撤销一个 hunk、恢复一个文件、保留受保护 hunk；
-状态管理动作：创建 checkpoint、切换分支、回滚到 checkpoint、丢弃失败分支；
- 边界动作：继续、请求人工确认、在受限环境中运行、停止并返回无修改、停止并提交当前修改。

这个最强版本不是 Novel/Partial/Resolved 三分类，也不是给现有 agent 增加一个置信度头。它是部分可观察条件下、带回归与不可逆成本的序贯行动问题。正因为采用了这一最强定义，它与现有 POMDP、恢复路由、长程义务图和 abstention 工作的重叠才成为决定性问题。

## 3. 严格 Partial 的定义、监督性与不可识别性

### 3.1 可构造的严格定义

设任务的行为义务集合为 $O=\{o_1,\ldots,o_m\}$，在仓库状态 $x$ 上由隔离的 oracle 给出满足集合 $S(x)\subseteq O$，并令 $G(x)$ 表示新增回归集合。现有数据冻结规格可构造：

- Novel：从健康基线注入全部目标缺陷，尚未满足本任务新增义务；
- strict Partial：$\varnothing\subset S(x)\subset O$，$G(x)=\varnothing$，且从该状态存在一条经核验、不先破坏已满足义务而到达 Resolved 的继续路径；
- Resolved：$S(x)=O$ 且 $G(x)=\varnothing$。

这个定义比 FixedBench 的 Partial 严格。FixedBench 的 Partial 只是一个较弱模型产生的失败补丁状态，不能保证至少完成一项义务、没有新增回归或存在干净继续路径。strict Partial 因而是有用的数据质量条件。

### 3.2 可监督不等于可识别

strict Partial 的标签要依赖三类行动时不可见的信息。

1. $S(x)$ 需要完整行为义务和隐藏测试；公开测试通过不能等价为义务满足。
2. $G(x)=\varnothing$ 需要覆盖既有行为的回归 oracle；常规测试缺失时无法确定。
3. “存在一条干净继续路径”是关于尚未采取行动的反事实性质；即使 gold continuation 存在，也不能证明这是唯一或在其他 agent 策略下可达的路径。

因此，strict Partial 是研究者在构造环境中可赋予的外延标签，不是 agent 从当前观察中可确定的自然状态。agent 真正能维护的是关于 $S(x)$、$G(x)$ 和继续后果的信念分布。把训练标签用于监督这种信念可以成立，把它宣称为新的可识别状态构念则不成立。

### 3.3 三类状态不是自然本体

真实任务中的 Partial 是高维连续集合。两个状态都满足一半测试，可能分别涉及不同功能、不同依赖层级、不同回归半径和完全不同的安全动作。Novel 状态也可能已经具备任务所需的部分基础行为，只是尚未有显式补丁。Resolved 状态可能通过一条替代实现满足测试，但仍违反未编码的组织约束。三标签丢失了决定行动的结构。

LoopsBench 进一步暴露了这一点。其 DAG 是源材料支持的评测契约，作者明确限制它并不声称是唯一因果计划，也不假定真实软件开发天然单调。ready frontier 和 completed-node obligation 对评测非常有用，但不能因此把一个固定 DAG 当作真实开发状态的完整本体。本候选若从三标签升级为义务图，就进入 LoopsBench 已占据的表示空间；若停留在三标签，则只剩简单分类。

### 3.4 strict Partial 可以保留的价值

strict Partial 仍适合作为一个困难评价切片：

- 检验 agent 是否会覆盖已经正确的工作；
- 检验是否能只修复未满足义务；
- 检验停止策略能否区分“完全完成”和“仍有剩余义务”；
- 检验验证预算是否会因状态不确定性而重新分配；
- 检验安全收益是否只是高拒绝率。

这个价值属于 benchmark/control evaluation，不足以单独证明理论和算法贡献。

## 4. coding-agent 特有损害与研究边界

本候选确实满足“不是普通分类问题”的现实动机。普通代码模型只给出文本建议，coding agent 能够直接编辑工作区、运行命令、改变依赖和提交状态。它还会把前一步自己的输出当作下一步的环境事实，造成错误累积。相同的状态误判因而可能从一段错误代码扩张为覆盖正确工作、破坏测试、污染分支和浪费人工审批。

但这些后果只能证明问题重要，不能证明候选已有独立解决机制。应当区分三层结果：

| 结果层 | 可测指标 | 为什么不能只看任务通过率 |
|---|---|---|
| 风险结果 | 新增失败测试数、受保护义务失效数、正确 hunk 覆盖率、回滚后残留损坏、无谓修改文件和行数 | 总任务最终通过也可能经历危险中间状态或大面积不必要重写 |
| 任务结果 | 目标义务完成率、完整 resolve rate、跨状态成功率、time-to-resolution | 一律停止能获得低风险但没有任务价值 |
| 成本结果 | 工具调用、测试分钟、token、checkpoint 存储、人工审批次数和等待时间 | 通过无限验证获得安全不具实践可行性 |

核心评价必须是安全、任务成功和成本的 Pareto 改善。不能以拒绝所有动作、只跑全量测试或无限请求人工确认获得表面安全。主要决策时点应是每次证据动作和代码改变之前，次要时点是验证失败后以及提交前。若只在最终补丁后做一次 verifier，本候选会退化为已有验证工作。

### 5.2 不能按“已有公开资产”使用的部分

- FixedBench 的现象和构造方法可作为文献证据，但截止日未定位到官方公开 benchmark repo 或可下载数据。不得写成“我们将直接在公开 FixedBench 上训练”。
- Change2Task 主文提供可复现的重建路线，但截止日未确认官方 900-task artifact。不得把论文报告的任务数当作已下载本地数据。
- Wink 的生产轨迹、Abstain and Validate 的工业缺陷数据并非公开训练资源。
- trace-economic underwriting 的 1,000 条 SWE-smith 轨迹和风险标签可用于风险估值近邻对齐；若本候选不做货币损失或 CVaR，则不应为了扩大数据量强行混入其标签。

### 5.3 数据构造能否得到可执行监督

可以。最严谨的训练实例不是给一个静态状态标签，而是在同一起点创建多个受控分支，执行不同动作并用隐藏 oracle 评估后果。对每个任务和时点 $t$：

1. 从健康上游 commit 和任务补丁得到 Novel、多个 strict Partial、Resolved 以及错误 partial 对照；
2. 固定当前观察，分叉执行 evidence、edit、test、rollback、stop 等候选动作；
3. 在隔离容器内计算目标义务增量、受保护义务变化、新增回归、运行成本和是否可恢复；
4. 将动作后果而非 gold patch 字面相似度作为监督；
5. 把所有 oracle 结果仅写入训练标签和 evaluator，推断输入中不暴露隐藏测试、gold diff 或未来 commit。

这能训练一个行动后果模型，但不会自动解决新颖性或理论归属问题。

## 6. 反事实最高强度算法规格

本节给出一个能够实际实现的最高强度版本，目的在于确认 NO-GO 不是因为缺少工程方案。该规格**没有冻结为论文工件，没有训练，也没有结果**。

### 6.1 输入、输出和真实行动

模型输入为：

- 任务文本 $q$；
- 当前仓库快照 $x_t$，含代码、配置、依赖和工作区差异；
- 有截止时点的 git 历史 $h_{\leq t}$；
- 已公开测试与此前工具观察 $e_{1:t}$；
- 当前 checkpoint 树和行动成本 $c_{1:t}$；
- 候选动作集合 $\mathcal A_t$。

模型输出不是一个三分类标签，而是：

- 每个潜在义务的满足概率、未决概率和证据覆盖；
- 每个已满足义务被候选动作破坏的概率；
- 每个候选动作对义务完成、回归、可恢复性和成本的分布；
- 下一实际动作的策略分布；
- 停止时的校准完成置信度和未决义务说明。

推断时模型必须真实调用工具或改变仓库。选择 evidence 时运行指定的复现、测试、trace 或 slice；选择 edit 时只应用一个有边界的局部补丁并建立 checkpoint；选择 rollback 时恢复指定 checkpoint 或 hunk；选择 stop 时返回当前工作区并显式区分“无修改完成”“提交当前修改”“证据不足升级人工”。

### 6.2 义务与仓库证据张量

设 batch 为 $B$，每个实例最多 $M$ 个义务，表征维度为 $d$，软件理解通道暂按 cognitive-fit 文献中的 function、data flow、control flow、state 四类构造。最高强度版本包含：

- 仓库证据张量 $R_t\in\mathbb R^{B\times M\times4\times d}$；
- 剩余义务张量 $O_t\in\mathbb R^{B\times M\times4\times d}$；
- 义务依赖邻接 $D_t\in\{0,1\}^{B\times M\times M}$；
- 满足/受保护后验 $P_t\in[0,1]^{B\times M}$；
- 回归风险 $G_t\in[0,1]^{B\times M}$；
- 证据缺口 $U_t\in\mathbb R_+^{B\times M\times4}$；
- 表示匹配矩阵 $F_t\in\mathbb R^{B\times M\times4\times4}$，其中每个元素估计某类任务义务与某类仓库证据之间的匹配；
- 候选动作后果张量 $\Delta_t\in\mathbb R^{B\times|\mathcal A_t|\times M\times K}$，$K$ 至少包含义务增量、回归、可恢复性、时延和人工负担。

四通道并不是现成的真值。function 可由行为规范和输入输出测试提议，data flow 由 def-use/taint/slice 获取，control flow 由 CFG、branch trace 和调用图获取，state 由持久变量、对象状态、配置和运行快照获取。每个通道同时保存来源、时间戳和置信度，防止把静态分析输出当作无误差事实。

### 6.3 架构

1. **任务—义务诱导器。** 编码问题文本、公开测试和历史变更，提出带置信度的义务节点及候选依赖边。它不能读取 gold patch 或 hidden test。
2. **多通道仓库编码器。** code Transformer 与 CPG/trace encoder 共同生成四类证据；基础结构必须与等参数 generic baseline 共享。
3. **义务信念更新器。** 图 Transformer 根据新工具结果更新 $P_t$、$G_t$ 和 $U_t$。已满足节点作为保护对象进入后续动作评分。
4. **表示转换动作库。** 候选的 cognitive-fit 版本为每个 $k\rightarrow l$ 学习转换 $T_{k\rightarrow l}$。当任务需要 data-flow 证据而当前只有 control-flow 表示时，策略应先选取可产生相应证据的工具，而不是简单增加无关上下文。
5. **行动条件 world model。** 对每个候选动作预测 $\Delta_t$ 的分布，包含 epistemic uncertainty 和 aleatoric uncertainty；用 ensemble 或 distributional head 校准尾部回归风险。
6. **受约束策略。** 在最低任务成功和最大回归风险约束下选择 evidence、local edit、verify、rollback、escalate 或 stop。不得只输出风险分数。

这个架构已经比三状态分类、简单 router 和附加评分头更强。然而，除第 4 项外，它是标准结构化 POMDP/world-model 实现；第 4 项的理论资格又在第 8 节失败。

### 6.4 训练样本和标签

一个训练样本应是：

$$
(q,x_t,h_{\leq t},e_{1:t},a_t,\;S_t,G_t,\Delta S_{t+1},\Delta G_{t+1},c_t,r_t).
$$

标签来源为隔离 evaluator：

- 义务满足标签：目标行为测试、变形测试、规范检查及必要的人审义务 manifest；
- 回归标签：基线行为测试、项目原生回归、LoopsBench completed-node tests 或等价保持测试；
- 保护标签：在 strict Partial 构造中已满足且无回归的义务；
- 行动后果：分支执行后义务和回归的真实变化；
- 可恢复性：checkpoint 能否完整恢复文件、依赖、生成物和服务状态；
- 成本：wall-clock、CPU/GPU、token、工具次数、人工审批；
- 策略监督：同一观察下多动作的受约束效用排序，而不是以 gold patch 动作为唯一正确答案。

为了避免“一个最优标签”掩盖多条等价路径，策略标签应为可接受动作集合或 pairwise preference。若两个动作都满足风险约束且结果等价，不应强迫模型复制 gold trace。

### 6.5 损失函数

最高强度设计可以使用：

$$
\mathcal L =
\lambda_o\mathcal L_{\text{obl}}
+\lambda_g\mathcal L_{\text{reg}}
+\lambda_d\mathcal L_{\text{dyn}}
+\lambda_\pi\mathcal L_{\text{policy}}
+\lambda_c\mathcal L_{\text{cal}}
+\lambda_p\mathcal L_{\text{preserve}}
+\lambda_f\mathcal L_{\text{fit}}.
$$

- $\mathcal L_{\text{obl}}$：义务满足的 focal/BCE 或集合预测损失；
- $\mathcal L_{\text{reg}}$：新增回归的多标签与尾部损失；
- $\mathcal L_{\text{dyn}}$：行动条件状态转移的 distributional NLL；
- $\mathcal L_{\text{policy}}$：离线行为克隆、pairwise action ranking 与 constrained offline RL 的组合；
- $\mathcal L_{\text{cal}}$：Brier、ECE surrogate 或 conformal calibration 相关损失；
- $\mathcal L_{\text{preserve}}$：对已满足义务被破坏施加非对称高代价；
- $\mathcal L_{\text{fit}}$：要求匹配证据通道优先直接支持义务，不匹配通道先经明确转换或取证动作。

风险约束不能复用 trace-economic underwriting 的货币损失或 CVaR 作为新颖性。若采用 CVaR，它只能作为已知控制基线；候选的主要结果仍应是实际义务保持、回归和任务成功。

### 6.6 推断效用

候选动作效用可写为：

$$
U(a_t)=
\mathbb E[\Delta\text{Obligation}]
-\alpha\,\mathbb E[\Delta\text{Regression}]
-\beta\,\Pr(\text{overwrite protected work})
-\gamma\,\text{Cost}
-\eta\,\text{HumanBurden}.
$$

只有当风险上界低于预注册阈值时才允许 edit 或 submit。该形式能运行，但它仍是普通受约束决策。阈值、效用和尾部风险并没有来自一个独有 IS 理论；换用等参数 generic POMDP 可以完成相同计算。

## 7. 数据划分、泄漏隔离、算力与训练工件

### 7.1 划分

必须按上游仓库、issue/PR lineage 和缺陷生成模板同时分组。建议：

- train/validation/test 按 repository group 完全隔离；
- 同一真实 issue 的 Novel、多个 Partial、Resolved 和错误 partial 全部进入同一 split；
- 同一补丁的语法重写、测试变体、相邻 commit 不得跨 split；
- LoopsBench、USEbench/SWETRY、SWE-CI 保留为外部测试，不用于调节阈值；
- partial-fix sequences 若重建成功，应按项目和提交血缘隔离；
- FixedBench 在官方资产公开并核对 commit 前只作为现象近邻，不列入实验表的可运行行。

### 7.2 隐藏信息隔离

- gold patch、未来 commit、hidden tests 和最终状态标签只进入数据构造器或 evaluator；
- action policy 只能看到截止时点以前的历史；
- 检索索引在 split 后分别建立，禁止测试仓库代码进入训练 retrieval；
- 预训练模型污染无法完全排除，应以新提交、私有生成变体和代码相似度审计降低风险；
- 每个任务保存 base commit、容器 digest、测试文件哈希、任务 manifest、义务 manifest、状态生成 seed 和分支 ancestry；
- 对提交消息、patch header、测试名中的答案泄漏做自动扫描；
- 结果报告必须分别给 seen-language/unseen-repository/unseen-risk-type。

### 7.3 算力量级估计

以下只是资源估计，不是已经执行的训练记录。

| 阶段 | 建议资源量级 | 主要瓶颈 |
|---|---|---|
| 数据构造与多分支执行 | 32–64 CPU cores、256 GB RAM、10–20 TB 可清理容器/trace 存储 | 上千任务的镜像构建、隐藏测试和多动作分叉 |
| 3B–7B code backbone 的 LoRA/QLoRA pilot | 2–4 张 A100 80 GB 或同级卡，数天至一周 | 长上下文、轨迹序列和动作候选批处理 |
| 7B 级策略、world-model ensemble 与完整消融 | 8 张 A100 80 GB 或同级卡，一至两周以上 | 多 seed、ensemble、外部 benchmark 和等参数基线 |
| 在线 agent 评价 | 与训练分离的容器 farm，至少 32 cores/128–256 GB RAM | 测试时延和 API/本地推断成本 |

若本地资源只能训练小型 graph head，而主要行为来自云端闭源 coding model，本候选会进一步退化成辅助评分器，不满足“实质算法工件”要求。

### 7.4 必须产出的训练工件

- obligation inducer、belief updater、world model 和 policy checkpoint；
- tokenizer/backbone/adapter 的精确版本与许可证；
- 每个数据分支的 manifest、容器 digest 和 oracle hash；
- train/validation/test group 文件；
- 所有超参数、随机种子、action budget 和停止阈值；
- 训练/验证曲线、校准器与 conformal split；
- 推断轨迹、checkpoint tree、实际 diff 和测试日志；
- 失败任务的可重放包。

这些工件证明可复现性，不证明理论贡献。

## 8. IS 理论终审

### 8.1 最自然的候选：cognitive fit

检索到的最直接 IS 理论来源是 Shaft and Vessey 的软件维护 cognitive fit。已回读项目中的全文：

Shaft, T. M., and Vessey, I. 2006. “The Role of Cognitive Fit in the Relationship between Software Comprehension and Modification,” *MIS Quarterly* 30(1), 29–55. DOI: [10.2307/25148716](https://doi.org/10.2307/25148716).

该理论在软件维护情境中的具体机制是：

- 软件理解与修改是相互关联但不同的任务；
- 人会形成关于软件的 dominant mental representation，修改任务也要求某种 task representation；
- 当两种表示强调相同知识时，理解结果可直接服务修改，避免表示转换；
- 不匹配时需要转换，并产生 dual-task interference 和注意错配；
- 论文区分 function、data flow、control flow、state 四类知识；
- 实证结果不是“理解越多越好”，而是理解改善与修改绩效在 fit 情境正相关、在 mismatch 情境可能负相关。

这比“风险感知”“高可靠性”或“信息更多更好”更接近本候选，因为它给出一个方向冲突：继续收集不匹配的理解可能伤害修改，任务要求应决定取证类型。Samuel et al. 2022 的 adaptive cognitive fit 进一步讨论 AI 动态调整信息呈现以改善人的决策表现：

Samuel, J., Kashyap, R., and Samuel, Y. 2022. “Adaptive Cognitive Fit: Artificial Intelligence Augmented Management of Information Facets and Representations,” *International Journal of Information Management* 65, 102505. DOI: [10.1016/j.ijinfomgt.2022.102505](https://doi.org/10.1016/j.ijinfomgt.2022.102505).

### 8.2 理论若进入算法，最强映射是什么

若勉强保留，理论应产生而非仅命名以下计算：

1. 义务表示 $O_t$ 与仓库证据 $R_t$ 必须按 function/data-flow/control-flow/state 分解；
2. 匹配矩阵 $F_t$ 进入前向计算，决定直接编辑还是先做 representation-transforming evidence action；
3. 不匹配时不能简单追加更多上下文，而应选择 slice、trace、behavioral test 或 state inspection，把证据转换为任务所需表示；
4. 已满足义务改变剩余任务表示，因而同一仓库在不同 Partial 状态应选择不同证据通道；
5. 删除类型、打乱 $F_t$、中和转换动作后，在理论规定的 mismatch cell 应出现可观察下降；
6. 最关键的方向冲突是：在同样证据和计算预算下，增加不匹配表示应比不增加更差，而匹配表示应更好。

这确实比在损失中增加一个风险权重更有内容。

### 8.3 决定性的层级迁移断裂

然而，Shaft–Vessey 研究的是**人类维护者的 mental representation、有限注意和 dual-task interference**。拟议模型中的四通道张量是设计者指定的机器表示。两者之间缺少以下桥梁：

- 没有证据说明 Transformer 或 coding agent 具有与人类相同的 dominant mental representation；
- 没有可观察测量能确认某个 agent 内部状态是 function model、program model 或 situation model；
- 模型在 mismatch 数据上变差可能来自上下文干扰、检索噪声、token 预算或训练分布，而非 cognitive-fit 机制；
- 强制四通道后获得改善，可能只说明 program-analysis feature 有用；
- 让工具向人呈现适配信息符合 adaptive cognitive fit，但那研究的是 human–AI dyad；本候选的主要行动者和结果是 agent 自身。

如果诚实遵循肖老师 ACAA-L9-S01–S04 的边界控制，就必须明确“人类 cognitive fit 与 neural representation 不是同一概念，前者至多提供设计动机”。一旦这样限定，它不能承担独立理论算法贡献。

### 8.4 通用替代可复制

给等参数 generic graph Transformer/POMDP 同样的义务节点、程序图、工具动作和 hidden-oracle outcome supervision，它可以直接学习：

- 哪类证据对哪类任务有价值；
- 什么时候先取证、什么时候编辑；
- 哪些已完成义务应保护；
- 哪个动作会引入回归；
- 什么时候停止或回滚。

它无需把通道命名为 cognitive fit，也无需显式 $F_t$。如果 generic baseline 达到相同性能与方向性行为，则理论机制没有不可替代能力；如果不给 generic baseline 相同输入结构，则优势来自特征与先验不公平。当前没有理论证明通用模型会系统性朝相反方向计算，也没有先验结果显示显式 fit 表示在 held-out repository 上产生人类理论预期的符号翻转。

### 8.5 其他 IS 理论为何更弱

| 理论候选 | 表面联系 | 不能承担算法责任的原因 |
|---|---|---|
| problemistic search | 绩效低于 aspiration 后在邻近处搜索，可解释局部修复 | 原理论位于组织决策层；阈值和局部搜索能被 generic controller 直接表达，不能导出剩余义务张量 |
| information foraging | 证据 scent、搜索成本、patch locality | 可指导检索预算，但不能独特决定保留、回滚或修改后果；容易退化为学习型 retrieval |
| escalation/de-escalation of commitment | agent 是否继续投入一个 partial patch | 原机制涉及人或组织的 sunk cost、self-justification；agent 轨迹中没有被测量的同等心理机制 |
| organizational information processing / equivocality | 不确定状态需要获得更多信息 | 只能给“何时多取证”的一般理由，等价于 value of information/POMDP |
| high-reliability organizing、mindfulness | 对异常、恢复和操作敏感 | 既有内部红队已证明层级迁移和组件命名问题；本候选也被明确要求不继承 Butler–Gray mindfulness |
| affordance、control、accountability | 权限与可行动边界 | 本候选的核心不是组织授权或责任分配；强行使用会让理论只在治理层解释结果 |

没有找到一个自然、经原文支持、能使算法朝通用模型不会想到的方向计算的 IS 理论。因此不应为了维持选题而套用理论。

## 9. 与最强基线的公平比较要求

即使作为工程实验继续，该候选也必须面对下列基线，不能只与“直接编辑”或一个提示词 agent 比较。

| 基线组 | 必须控制的内容 |
|---|---|
| Frontier coding agent | 同一模型、上下文、工具、token、wall-clock 和测试预算；无状态控制版本 |
| FixedBench abstain-or-fix 与 reproduce/git inspection | 同一 benchmark 状态和可见证据；分别测无修改、Partial、Resolved |
| USEagent | 同一 USEbench/SWETRY 环境和工具预算；比较动态 project/task state、review 和 termination |
| EviACT | 同一 setup/localize/patch/verify 成本；比较先证据后编辑 |
| LoopsBench loop profiles | 同一 ready frontier、隐藏测试释放和 continuation budget；比较义务保持与回归 |
| CodeRescue | 同一失败轨迹、reflect/replan/escalate 动作和训练数据；比较恢复路由 |
| Agentic Abstention POMDP | 同一观察和 evidence/edit/stop action space；比较序贯停止 |
| TRIM | 在成功补丁上同一执行验证预算；比较最终冗余编辑和功能保持 |
| verifier/process reward | 同一执行轨迹和 hidden-oracle supervision；比较直接 progress/reward learning |
| equal-parameter generic Transformer | 完全相同的 code/graph/tool 输入、参数量、训练样本、损失预算和推断动作，但移除理论类型、fit matrix 和专门转换 bank |
| equal-parameter generic POMDP/world model | 相同状态容量、action model、uncertainty head 和约束优化；只使用端到端 learned latent state |

关键公平性是让 generic baseline 获得相同结构信息。若理论模型独占 obligation graph、program analysis 或 branch outcome，它的优势不能归因于理论。若两者相同，当前预期是通用替代可以复制，故本候选不具独立理论资格。

### 9.1 理论机制干预

最低限度需要：

- 打乱 function/data-flow/control-flow/state 标签但保留数值；
- 对每个任务随机置换 $F_t$；
- 用等参数 cross-attention 替换所有 $T_{k\rightarrow l}$；
- 中和受保护义务的非对称损失；
- 保持总证据量不变，只交换 matched 与 mismatched evidence；
- 固定候选动作和成本，检查理论预期的符号翻转；
- 跨仓库和跨语言复现，而非只在训练仓库内显著。

如果性能只在“移除全部结构化证据”时下降，说明结构有用；只有在等信息、等参数的理论打乱下仍按预注册冲突方向变化，才可能支持机制。

## 10. 评价设计与结果证据边界

### 10.1 主要指标

- **义务保持率**：行动前已满足义务在提交时仍满足的比例；
- **新增回归率**：原生测试、保持测试或 completed-node tests 新失败的比例；
- **无谓修改率**：Resolved 状态中产生实质 diff 的比例，以及功能等价但可删除的 edit/file 数；
- **正确工作覆盖率**：strict Partial 中已核验 hunk 被删除或语义破坏的比例；
- **剩余义务完成率**：只针对行动前未满足义务；
- **风险调整任务成功**：同时满足全部目标义务且无新增回归；
- **停止校准**：完成置信度的 Brier/ECE、选择性风险与 coverage；
- **恢复质量**：失败分支后返回无损 checkpoint 的比例；
- **成本**：token、工具调用、测试时间、总 wall-clock、人工介入。

### 10.2 分布外评价

- 仓库 OOD；
- 语言 OOD；
- 风险类型 OOD；
- strict Partial 到自然失败轨迹的转移；
- 单任务混合状态到 LoopsBench 长程 DAG 的转移；
- 当前快照控制到 SWE-CI 未来演进保持。

### 10.3 统计计划

以任务为配对单位，报告 bootstrap 置信区间和层级模型或按仓库聚类的稳健标准误；二元结果给风险差、相对风险和置信区间；成本给中位数、尾部分位数和 paired effect；安全—成功—成本同时报告 Pareto frontier。多 seed 模型至少报告 seed 方差。阈值和停止策略只在 validation 确定。

### 10.4 当前结果状态

没有运行任何上述实验。不能写“模型减少了回归”“理论机制显著改善”或填入任何数字占位。可运行设计与实证成立是两件事。

## 12. 为什么 LoopsBench 改变了终判

若没有 LoopsBench，本候选尚可把“义务满足不是一个标量，已完成部分必须成为后续行动约束”视为潜在结构贡献。LoopsBench 在截止日前已经公开并做到：

- development unit 级任务分解；
- source-evidenced prerequisite DAG；
- 每一时点的 ready frontier；
- 节点完成后测试继续保留，显式成为 regression obligation；
- 按 flow、plan fidelity、state continuity 和 regression 评价长程 coding loop；
- 公开任务、测试、runner 和 5,300 余单元。

这与本候选拟议的 residual-obligation graph、受保护节点和动作前沿不是术语相似，而是计算对象和 evaluator 责任直接相同。本候选仍有一个情境差异：它混合未知 Novel/Partial/Resolved 快照，且希望训练一个行动策略；LoopsBench 从固定 source-recovered DAG 开始，重点是长程持续开发。但“情境不同＋学习策略”不足以证明理论算法新意，因为：

1. 在 LoopsBench runtime 上训练 policy 是自然下一步，不是新的义务表示；
2. FixedBench 已占据混合快照状态；
3. CodeRescue 和 Agentic Critical Training 已占据训练行动/恢复策略；
4. Agentic Abstention 已占据序贯 evidence/stop；
5. USEagent 已维护动态 project/task state 并在 partial-fix 情境采取行动；
6. TRIM 已直接优化无谓修改。

由此，本候选变成对五类现成能力的组合。除非 IS 理论能产生不可由这些方法组合得到的新计算方向，否则应当 NO-GO。第 8 节已说明当前理论不能做到。

## 13. 与 trace-economic underwriting 的边界

本候选不应把“风险价值”作为逃生方向。trace-economic underwriting 已在 customer–task–trace episode 上显式表示不可逆性、blast radius、不确定性、时间和归责，并把 trace 映射到 loss、CVaR、allow/review/sandbox/stop 控制。其论文在 1,000 条 SWE-smith 轨迹上报告了 trace-conditioned control 结果，并发布标签和审计材料。

本候选若采用以下表述，将被直接挤压：

- 根据 coding trace 预测经济损失；
- 以 CVaR 决定是否 review、sandbox 或 stop；
- 比较预期损失与人工介入成本；
- 把不可逆性和 blast radius 组合成风险评分。

可以保留的差异只有行为义务层：预测哪一项已满足、哪一项会被具体修改破坏、应执行什么代码与测试动作。风险结果应以真实回归、覆盖和任务失败测量，而非货币估值。即使如此，这个边界只能避免与 trace-economic 工作重复，不能恢复本候选的 IS 理论资格。

## 14. 复活门与撤题条件

下列条件必须**全部**满足，才值得重新立项。任一项失败，维持 NO-GO。

1. **构念效度门。** 在不读取 gold patch/hidden test 的情况下，对 function/data-flow/control-flow/state 义务和仓库表示建立可复核标注协议；多标注者一致性、跨语言稳定性和与程序分析来源的一致性达到预注册标准。
2. **层级迁移门。** 通过专门实验表明 coding agent 存在 cognitive fit 所预测的方向冲突，而非仅有检索噪声或长上下文退化。相同信息量与计算预算下，matched comprehension 对修改有益，mismatched comprehension 有害，并在 held-out repository 重现。
3. **通用等价门。** equal-parameter generic Transformer、cross-attention、obligation POMDP 和 world model 在相同结构、数据和动作监督下不能复制理论模型；差异必须有稳定效应量，而非单次显著。
4. **LoopsBench 增量门。** 在 LoopsBench 已有 DAG、ready frontier 和 persistent regression obligations 之上仍产生新的可训练能力，而不是给 benchmark 加 policy head。
5. **恢复近邻增量门。** 相比 USEagent、CodeRescue、Agentic Abstention、EviACT 和 TRIM，在相同预算下同时改善正确工作保持、剩余义务完成和成本。
6. **strict Partial 外部效度门。** 严格构造状态上的优势必须转移到 USEbench/SWETRY、可执行重建的 partial-fix sequence 和自然 agent failure traces；只在合成严格单调序列上成立不够。
7. **非拒绝安全门。** 风险降低不能由高停止率、无限测试或人工升级获得；必须在预注册任务成功下限上改善安全—成功—成本 Pareto frontier。
8. **行动而非分类门。** 核心模型必须真实选择取证、局部编辑、保留、回滚和停止；三状态预测或风险 head 的结果不能成为主要贡献。
9. **泄漏门。** 仓库、PR 血缘、生成模板、gold tests、future commits 和检索索引全部隔离；任何隐藏 oracle 泄漏即撤销结果。
10. **公开资产门。** 每个训练和外部测试集必须固定下载地址、commit、license、容器 digest 与 manifest。FixedBench/Change2Task 未公开资产不得以“即将发布”替代。
11. **理论责任门。** 必须逐项通过 ACAA-L11-S01–S08 和 DSDL-T2-S01–S07 的责任：指出 generic 算法的确定错误方向，并由原理论导出不可替代的有方向计算。
12. **独立规模门。** 即使移除三状态命名、LoopsBench DAG、现成 verifier 和 recovery router，剩余工件仍须独立解决一个重要问题。若移除后只剩辅助模块，撤题。

这些门不是待补充的小消融，而是当前候选缺失的成立条件。最可能失败的是第 2、3、4 和 11 项，且它们共同决定独立理论算法资格。

## 16. 最终判定

这个候选的问题真实、数据可构造、系统也可训练。它最有价值的部分是把严格 Partial 作为评价切片，测试 agent 能否在不破坏已完成工作的前提下完成剩余义务。然而，论文资格不能由问题重要性和工程可行性代替。

严格 Partial 不是行动时可识别的新自然状态；升级后的剩余义务图、ready frontier 和回归保护已被 LoopsBench 直接实现；继续、停止、恢复、回滚和无谓修改控制分别被 Agentic Abstention、CodeRescue、USEagent、checkpoint 系统与 TRIM 占据。cognitive fit 虽然是检索到的最自然 IS 理论，并能提出“匹配证据”和“表示转换”的方向冲突，但其原机制属于人类软件维护者，无法直接授权 agent 内部张量。遵循肖老师 ACAA-L9 的类比边界后，它至多是设计动机；遵循 ACAA-L11 和 DSDL-T2 的算法责任后，当前又无法证明通用等参数模型会朝错误方向计算。

因此，本候选应从独立论文序列中撤下。可保留 strict Partial 数据构造和保护性指标，作为其他已冻结论文的鲁棒性或外部安全评价，不保留其理论主张、论文题目或独立算法地位。
