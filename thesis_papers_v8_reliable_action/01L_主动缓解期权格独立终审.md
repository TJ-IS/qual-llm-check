## 1. 终审结论

01H 已经实质修复 01D 最严重的构念错置。研究不再把 expand、necessary backfill、old/new propagation 和 complete 的必经协议阶段称为 optional mitigation。分析起点被固定在 `READY_COMPATIBLE`，额外措施可以做零项、一项或多项，`AB` 可以取消本次 release，`D60` 期间可以到达自然 workload 证据。因而，Benaroch 的 deferral、proactive mitigation、exercise/non-exercise 和 path conditionality 现在有了可以成立的数据库迁移对象。

本题也没有被已核验的直接工作完整覆盖。pgroll、F1、BullFrog、Tesseract 和 Google 的 Datastore–Firestore 迁移解决了协议、并发、验证、切换和回退的大量底层问题。Horizon 处理 LLM 驱动 SQL migration 的语法和功能等价检查。AA-POMDP 和 risk-sensitive POMDP 处理了主动取证、部分可观察和风险敏感决策。这些工作挤压了单个模块的新颖性，但尚没有直接给出“从 old/new repository 语义与在线证据中学习额外缓解措施的零项或多项、顺序、延期和取消决策”这一整体工件。

然而，01H 现在还不能被判为 `DESIGN-FROZEN`。这不是因为排序反转、D60 信息价值和 Pareto 增益尚未实证，而是五个会改变主结论的规格问题仍未闭合。

1. `hard option lattice` 的递归本身就是一个普通 constrained SMDP 的 Bellman 递归。现有 `G-FactoredMPC` 通过拿掉合法 `AB`、zero-or-more 路径和物理 kernel 知识制造了不对等差异，因而没有隔离 Benaroch 真正额外的计算责任。
2. `y-\hat p` 的 split-conformal residual 不是每个状态上条件风险概率的 95% upper confidence bound。policy-induced state distribution 和 repository/workload OOD 又破坏了普通 split conformal 所需的 exchangeability。这使 `EX` 的硬安全门没有它声称的统计含义。
3. `CodeTwin-v1` 尚未隔离 source-code 语义。code-derived candidate set、checker catalog、candidate ID 和 `A_mask` 可能向 `Code-Blind` 基线泄漏 twin policy，而当前文本又没有固定 twins 是否共享完全相同的 future raw transaction inputs。
4. 来自 train split 的同一组 65-sequence records 既进入 `L_lat` 监督，又被用来检验 action-order regret 和理论冲突。这可以用于训练环境识别，不能作为独立机制证据。更根本的是，65 只等于四项 mitigation 的全部有序子集，不包含 `D60` 的插入、中途 `EX/AB` 或 observation-contingent branches，因而不是完整 option-policy oracle。
5. 十个 app 和四十项 migration 目前只有域名和 motif 表，没有字段级 old/new contract、transform expression、checker 源码分离、injection template、observation-threshold 或 sibling-sampling manifest。`按资源允许`抽 first-action siblings 不是可复现规则，现有资源表也漏算多 seed、多 policy 和高频 validation rollout。此外，Repo-OOD 只有两个 app clusters，不足以支撑当前声称的交叉随机效应和 cluster-bootstrap 外推。

这五项都可以在不伪造结果的前提下修复，但修复会改变基线、安全 gate、coding-agent 必要性识别、数据划分或 benchmark 有效总体。因而本次终审不判 `DESIGN-FROZEN`，也不在这些修复完成前进入正式论文正文。

## 3. Benaroch 构念忠实度

### 3.1 原文实际承担的命题

本次重新逐段回读了 Benaroch（2018）的引言、第 2.1–2.3 节、第 3–6 节、讨论和 Appendix A。原文支持下列责任。

1. 经理灵活性赋予决策者改变投资进程的权利，而不是必须行使的义务。
2. passive deferral 通过时间中到达的信息截断不利投资的 bad tail，proactive mitigation 在延期期间主动改变可控不确定性。
3. optional mitigation 与 compound investment 的必经 stage 不同。投资可以在一项都不做的情况下 exercise，也可以先做一项或多项。
4. mitigation 对结果分布产生离散 impulse，其 cost 和 impact 可以随已经实施的路径发生 substitutive、complementary 或 synergetic conditionality。
5. learning 主要改变对不确定性的认识，prevention/control 主要影响风险事件的频率或根源，coping 主要限制事件后损失。
6. Appendix A 的 binary lattice 在不同 decision points 部署多项 optional mitigations，并使后续 sublattice 取决于已实施路径的 impact 参数。

原文没有给出 repository graph、semi-Markov duration、Bayesian latent defect bits、hazard/severity neural kernels、chance constraint 或 coding-agent executor。01H 第 2.3 节已经正确把这些写成本文的情境化设计推论，没有伪称为 Benaroch 原有的 tensor。

### 3.2 cutover 投资期权映射现在可以成立

`READY_COMPATIBLE` 之前的 sunk effort 不是研究动作。在这一快照上，组织拥有把已知 release 切换为新应用的机会，同时保留取消本次 release 并继续使用稳定旧版本的选项。`EX` 对应 exercise，`AB` 对应 non-exercise，`D60` 对应 passive waiting，四项额外 operator 对应 deferral 期间可以做零项或多项的 proactive mitigation。这一映射比 01D 的“所有 migration stage 都是 option”忠实得多。

这一通过有明确边界。可映射的是 `READY_COMPATIBLE` 之后的**剩余完成与运营承诺期权**，不是已经沉没的整个 migration 投资。`EX` 必须真实执行 100% 新流量接管与 `pgroll complete`，从而放弃 active-migration 状态下的直接 rollback；若实现把 `complete` 留到 120 秒终端评价之后，或仍可无成本恢复到 old version，关键的 commitment/irreversibility 就消失，构念应退回 `FAIL`。正文还必须把 release 成功的组织收益与剩余 exercise cost 分开报告，不能只用任意 `+100/-25` utility 代替投资 payoff 证据。

`AB=-25` 是 benchmark utility，不是 Benaroch 的经验参数。它的数值任意性应由 raw outcome 报告、预注册敏感性和外部组织成本依据限制。这不使 non-exercise 构念自动失效，但正文不得声称 `-25` 由理论推导。

## 4. 动作、离散作用和路径条件审查

### 4.1 四项措施在设计上确实可选

| 措施 | 省略后是否仍有合法路径 | 执行签名 | 独立结论 |
|---|---|---|---|
| `M_SR shadow_replay` | 可以直接 `EX`、做其他措施或 `AB` | 在 content-addressed shadow 中运行，不写 compatible database | 真 optional；主要改变 observation 和 cost |
| `M_SV semantic_validate` | 可以直接 `EX`、做其他措施或 `AB` | 只读 checker 对 compatible state 运行 | 真 optional；主要改变 observation 和 cost |
| `M_CP failback_drill` | clean 或低恢复风险世界可在无 drill 时安全 exercise，其他情况仍可 `AB` | 保留 checkpoint/WAL，并在隔离实例中真实 restore | 真 optional；可改变 recovery/severity 和 observation |
| `M_WC temporary_write_cap` | 非高负载世界可不用 cap 完成迁移 | workload gateway 将写入 admission 降至 50% | 真 optional；可改变 hazard、observation 和业务成本 |

可选性的正式含义是“不采用该措施仍存在合法终端路径”，不是“所有 hidden conditions 下不用它都能安全 exercise”。按这一标准，四项都通过设计门。

### 4.2 路径作用在设计上可以反转，但不得预写已反转

01H 锁定的三类冲突并非纯语言游戏。replay 结果可以改变后续 checker set，validation counterexample 也可以改变后续 replay scope。write cap 可以降低 drill 期间负载，但也可以掩盖原负载下的 RTO 瓶颈。在剩余时间不同时，passive wait 与 active evidence 的相对价值也可改变。因此，顺序反转具有可执行条件。

是否实际出现反转必须由实验回答。未运行不是设计否决理由。但若 builder 实现后所有 state/path 上的排序都相同，则它们退化为 checklist，应按 01H 自己的结果门 NO-GO。

### 4.3 `D60` 具有独立 passive information 过程

`D60` 不执行主动 operator，只让 absolute-time workload 前进 60 秒，同时观察自然 transaction、lag、divergence alarm 和 old-client occupancy。这些信息不需要 replay 或 checker 才会到达，因而与主动措施有可区分的生成过程。600 秒 expiry 及延期成本又防止无限等待。

它对 latent condition 是否有 mutual information，以及这些信息是否改变 terminal action，都是预注册结果门。当前设计已经具备“可以产生独立信息”的机制，不应因未实证而先行判否。

### 4.4 `AB` 是合法 non-exercise，不是 failure 改名

pgroll 官方 README 明确区分 `complete` 和迁移期间的 `rollback`，并说明 rollback 删除 new schema 而保留 old version。v0.16.2 release 与 commit `cdbe9b0` 可核验。01H 的 `AB` 取消本次 release，使 old application 继续服务，然后单独运行 stability workload。它有 release/rework 机会成本，也有保全现有服务的正面结果。这与 data corruption、unrecoverable exercise 或 expiry 都不相同，所以可以承担 non-exercise。

## 5. Coding-agent 必要性终审

### 5.1 CodeTwin 的基本反事实是正确的

01H 没有仅用“输入中有代码”证明 coding-agent 必要性。`CodeTwin-v1` 试图固定 schema diff、database pre-state、已发生 workload prefix 和 telemetry，只改变 new repository 中的 half-even/half-up 或 reject/map-to-other 业务语义。如果只有读取 repository 的模型才能选出正确 scope/checker 并减少外部损害，它确实比普通 telemetry controller 多出了一种 code-semantic 能力。

### 5.2 当前对照仍有三条泄漏路径

1. `M_SR` 的 scope candidates 由 code–query analyzer 产生，`M_SV` 的 checker-set candidates 来自 visible checker catalog。若 twins 的 candidates 或 mask 随 repository policy 改变，即使 `Code-Blind` 看不到 source token，也可通过候选集身份推断 policy。
2. 01H 的 `Code-Blind` 删除 source/ORM/query nodes，但没有明确删除 visible checker 文本、checker graph node、candidate token 中的语义和 stable-hash 顺序。checker 本身可以暴露 half-even 或 unknown-enum policy。
3. “future hidden workload 和 oracle 与各自可见政策一致”没有明确 twins 是否共享完全相同的 future raw input transactions 和 absolute-time schedule。若 future inputs 也变化，code difference 会与 workload difference 混杂。

### 5.3 正文前必须冻结的 CodeTwin 修补

`CodeTwin-v1.1` 必须满足以下约束。

- 每对 twins 共享同一 database snapshot hash、同一 raw transaction input sequence、同一 absolute-time workload/fault seed、同一 schema diff、同一 candidate universe、同一 candidate ordering 和同一 `A_mask`。两者的 repository hash 必须不同，不得用没有类型的单一“pre-state hash”混过这个差异。
- hidden oracle 在同一 raw input 上使用各自可见 policy 定义期望结果。不能因 policy 不同而替换 future input distribution。
- candidate set 使用跨 twins 相同的 superset。若 analyzer 本身读取 code 并缩小 superset，该 analyzer 必须明确计入 coding-agent artifact，不得作为所有 baselines 共享的“无学习预处理”隐藏贡献。
- 冻结三个对照：`Full-Code+Analyzer`、`No-Source+TwinInvariantCandidates` 和 `SchemaTelemetryOnly`。另加 `Shuffled-Repository`，在保持候选集不变时对调 twin source，检验行动是否按可见语义改变。
- primary code-necessity endpoint 不只是 action disagreement。必须同时报告 scope/checker coverage、terminal harm、success 和 cost。仅让 full model 选了不同 checker 而外部结果不变，不证明 coding-agent 必要性。

这一修补完成前，“code-blind 不如 full model”无法归因于 repository semantics。

## 6. Episode、oracle、sibling 与未来泄漏

### 6.1 已经写对的部分

- `world_id` 共享 app/migration、snapshot、risk configuration、database seed、absolute workload/fault trace、exercise-relative draw 和 terminal hidden workload。
- policy 只能看到已发生的 prefix，hidden seed、sibling outcome、reference state 和 future telemetry 都不入模。
- 动作持续时间使 absolute wall clock 向前推进，不用“第 k 个 event”对齐不同时长的计划。
- `π_ref` 只用来定义局部 first-action paired outcome，不被写成 gold optimal policy。
- sibling group 整体划分，repository、migration、injection template、workload seed 和 fault seed 不跨 split。
- hidden oracle 和 visible checker 分离，主要标签不由 LLM judge 产生。

这些规格修复了 01D 中 `Δ/J` 缺 continuation policy 和 semi-Markov time 的问题。

### 6.2 exact-enumeration 的范围误称与训练—检验混用

01H 第 5.4 节从 train split 选八个 migration IDs，执行四项 mitigation 的 65 个 ordered subsets。这个数字来自 `Σ_{k=0}^4 4!/(4-k)!=65`。它没有枚举 `D60` 在序列中的位置、到达 observation 后的条件分支、任一中间 epoch 的 `EX/AB`，也没有枚举终端 action 的 chance-constraint 可行性变化。因此，它只能叫“在固定 `π_ref` continuation 下的 mitigation-order enumeration”，不能叫完整 option-policy exhaustive oracle，也不能直接产生七类 first actions 的全局 gold label。

第 6.6 节让这些 records 产生 `L_lat` 的最佳 first-action label，第 8.4 节又说用“精确枚举 tier”检验 action-order regret、sequence choice 和三类理论冲突。如果这三处指同一组 records，模型已经用最佳 first action 训练，不能再把其在同一 states 上的 regret 称为独立机制证据。

必须冻结三个不重叠的 exact tiers。

1. `ENUM-IDENTIFY`：只用于在建模前确认 operator 不是固定 checklist。一旦用来选择 conflict 或修改 environment，其 app/migration/injection/seeds 永久排除于训练和主结果。
2. `ENUM-TRAIN`：只在 train app/migration/seeds 上产生 `L_lat`。若仍只执行 65 条序列，label 必须限定为 mitigation actions 在固定 `π_ref` 下的 partial ranking，不能监督 `D60/EX/AB` 的全局最优性。若要给全部合法 first actions 贴 gold label，必须加入 `D60`、中途 terminal choice 和 observation branch 的完整树或带可证明 gap 的 exact solver。所有可比 learned baselines 获得同样的 ranking supervision，并必须写出这一监督进入各自 loss 的具体方式。
3. `ENUM-TEST`：使用从未进入 `L_lat`、early stopping、calibration 或 conflict 选择的 repository/migration/seed groups，用于 action-order regret和顺序反转。只有实现上一项完整树或 exact solver 后，才可报告“完整 sequence/exhaustive oracle”；否则结果名称必须是“fixed-continuation mitigation-order regret”。

不做这一分离，rescue gate 1 和理论机制检验没有 hidden-test 边界。

### 6.3 自建 10 app/40 migration 目前是可构造，不是已闭合 manifest

十个 FastAPI/SQLAlchemy 应用、四类 migration motif、五个 risk bits、四类 workload 和独立 hidden reference model 给出了可实现的 builder 边界。1 GiB synthetic data、一百万 reference transactions、PostgreSQL/pgroll containers 和 600 秒 horizon 在原理上能够运行。大量 episode 的 CPU、I/O 和 snapshot 成本很高，但不是不可实现的级别。

问题在于，当前规格仍留下了可以在看到模型行为后调整的大量自由度。每个 app 的具体 fields、M1–M4 transform、32 个 visible checkers、hidden reference transactions、R1–R5 injection code、green/amber/red thresholds、scope/checker superset 和 clean inclusion scripts 尚未实例化。文本中写“将来用 hash 固定”不等于现在已经闭合。

在任何 outcome generation 和 model training 前，至少必须生成并冻结下列实例文件。

- `apps_manifest.yaml`：每个 repository 的 old/new source tree、dependency lock、endpoint、transaction handlers 和 source hash。
- `migration_contracts/<app>-<M1..M4>.yaml`：四十项字段级 source/target contract、transform expression、pgroll operation、clean path 和 acceptance oracle。
- `visible_checker_manifest.json` 与 `hidden_oracle_manifest.json`：checker source IDs、所覆盖 invariant、禁止共用的 source files、build image 和 hash。
- `risk_injection_manifest.yaml`：R1–R5 的具体 code/data/config changes、行动前可见线索、hidden trigger 和 split-isolated template hashes。
- `operator_observation_v1.yaml`：连续 raw results 到 green/amber/red 的所有阈值，在数据生成前固定。
- `code_twin_manifest.yaml`：第 5.3 节所列的 twin-invariant inputs、candidate universe、mask、raw workload 和 variant-specific oracle。
- `sibling_sampling_manifest.json`：每类 first-action state 的纳入概率、最大 sibling 数、抽样 seed、缺失处置和各模型共同可见的 record IDs；不得保留“按资源允许”的运行时裁量。
- `split_manifest.json` 与 `runtime_lock.json`：所有 group IDs、seeds、container digests、PostgreSQL/pgroll binary 和 retrieval boundaries。

这些文件的内容会决定任务是否 trivial、顺序是否可反转和 code 是否必要，因此不是可以推迟到运行时的普通 digest 字段。

资源表也还没有闭合。仅 `ID-eval+test` 就有 `2,160+3,200=5,360` 个 worlds；主模型加六个 learned baselines、各五个 seeds，至少需要 187,600 次独立 policy episodes，尚未计五个固定基线。更大的缺口来自每 2,000 steps 在 648 个 `val-select` worlds 上评价 raw episode endpoint：若七个 learned methods、五个 seeds 都训练至 120,000 updates，最多是 1,360,800 次 validation policy episodes。01H 的 32–64 workers 与 8–16 TB 估计只明确计了 23,040 个基础训练 episodes和未定数量的 siblings，没有说明这些 evaluation 是真实 PostgreSQL rollout、可复用的冻结执行数据，还是 learned-model simulation。三者的证据含义不同。设计冻结前必须给出按 `dataset generation/training/validation/test/exact tier` 分项的 episode count、是否实际执行、缓存边界、worker-hour 与 storage 上界；这属于可运行规格，不是要求提前得到性能结果。

### 6.4 Repo-OOD 的有效推断单位过少

01H 使用 6 train apps、2 validation apps 和 2 test apps。每个 test app 只有四项 migration，因而 Repo-OOD 只有两个真正的 repository clusters 和八个 migration tasks。world seeds、risk configurations 和 workloads 增加的是同一任务内的重复，不会把两个 repository clusters 变成大样本。以 app 和 migration 为交叉随机截距，再在 Repo-OOD 上做 cluster bootstrap 和普遍外推，统计责任过强。

设计冻结前必须二选一。

1. 扩大 independent test repository families，使 Repo-OOD 至少有八个 app families 和三十二个 field-level migration tasks，并以 repository family 为最高重采样单位。共享 framework 的应用仍要检查 code/template 相似度。
2. 保留两个 test apps，但撤销广泛 repository-OOD 推断和 mixed-effect population claim，把结果严格限定为这两个预先冻结 repositories 的 finite-population paired evaluation。这会显著降低 ISR 级外部有效性，不应在结果后才选择该口径。

## 7. 期权格、kernel 与普通 SMDP 的计算责任

### 7.1 hard lattice 本身是 Bellman recursion

01H 定义

\[
V_\theta(x)=\max\{Q^{AB}_\theta(x),Q^{EX}_\theta(x),Q^{D60}_\theta(x),\max_{m\in\mathcal M(x)}Q^m_\theta(x)\}.
\]

对 mitigation 或 defer，`Q` 是当期 cost、event loss 和 next-state value 的期望。这正是一个有动作持续时间、部分可观察状态和 terminal actions 的 risk-constrained SMDP 的 Bellman optimality equation。令 generic model 使用同一可观察历史、同一 belief `b`、同一 ordered path `p`、同一 action mask 和同一 utility，并作以下映射：

- observation kernel 等于 `Ô`；
- transition/event kernel 等于 `Λ̂` 与 `Ŝ`；
- duration/cost kernel 等于 `D̂` 与 `K̂`；
- terminal distribution 等于 `T̂`；
- action set 为 `{M_SR,M_SV,M_CP,M_WC,D60,EX,AB}`。

则 generic SMDP 的递归在每个状态、每个 observation branch 和每个 search node 上与 01H 的 hard lattice 相同。若 soft recursion 使用同一 temperature，`L_lat` 的反向传播也相同。因而，“使用 max recursion 同时比较 mitigate/defer/exercise/abandon”不是 Benaroch 专属算法能力，而是把合法动作完整放入 SMDP 后的标准规划。

这一结论不等于用“通用网络可以逼近任何函数”否决结构偏置。它只说明 hard recursion 的独立责任为零。本题可能仍有价值的部分，只剩下 Benaroch 导出的 **parameter tying and factorisation** 是否在有限数据下优于非限制 joint dynamics。

### 7.2 当前 `G-FactoredMPC` 不是公平理论反证

01H 说 `G-FactoredMPC` 保留相同 primitive heads，但“不使用 zero-or-more path lattice、non-exercise boundary 或 ordered impulse gate”。前两项不能从公平 generic SMDP 中删除。

- `AB` 是环境的合法 terminal action，不是只允许 theory model 看到的理论标签。
- zero-or-more 是 action mask 和 once-only action state 的结果。普通 SMDP 若使用同一环境，也必然允许零项或多项。
- ordered path 是真实历史状态。一个公平 generic model 必须看到它，否则 baseline 被人为去除了可观察因果前因。

同样，`M_SR/M_SV` 在隔离环境中不能改变生产 physical state，`M_CP` 只改变 recovery path，`M_WC` 改变 production workload。这些是 operator permission 和 sandbox 的可执行事实，不是 Benaroch 独占的 hidden label。若 generic baseline 需要用数据重新学习“shadow action 不会改变 production hazard”，而theory model 获得 hard mask，优势可能来自物理知识不对称。

### 7.3 必须新增的公平通用替代

正式正文前必须加入 `G-PhysicalFactoredSMDP`，其获得：

- 完全相同的 repository/schema/telemetry/path inputs、risk-bit auxiliary supervision 和 sibling labels；
- 完全相同的 `{D60,EX,AB}` 和 mitigation actions、duration nodes、action masks、chance-constraint interface 和 search budget；
- 完全相同的物理 zero masks，即 shadow/read-only 不改变 production state，checkpoint 不降低 event incidence，write cap 不直接修复 semantic defect；
- 标准 finite-horizon Bellman recursion，并允许一个等参数 action-history Transformer 直接预测合法 physical factors 的 path-conditioned next distributions。

主模型与这一基线之间允许的唯一理论差异应被写成：主模型把 passive base kernels 与 mitigation impulse 分开，并用同一低秩参数化在未见的 zero-or-more ordered subsets 间复用 conditional impact/cost；generic baseline 使用相同物理信息，但不做这种 option-impact parameter tying。

然而，01H 当前的 `η(a|p,h)` 与 `k(a|p,h)` 由一个 unrestricted two-layer MLP 输出，可以表示任意正负 interaction。Benaroch 只说明 interaction 可以替代、互补或协同，即所有方向都允许。因而这个 gate 尚未形成像 ACAA 的 inverse matching plus redundancy 或 DSDL 的 `F-E` 那样的非交换运算。修订规格必须明确：

1. 哪些跨路径参数被强制共享，以及为何该共享来自 option impulse/conditionality；
2. 哪些 generic interaction 被禁止或收缩，而不是只把一个 unrestricted MLP 命名为 option gate；
3. 当路径冲突不存在时，该偏置应当如何退化为普通模型；
4. 相同物理知识的 generic baseline 为何不能在每个 batch 上与它精确同构。

若修补后的唯一差异仍是模块名称，或 `G-PhysicalFactoredSMDP` 使用同一前向和 loss 就能逐梯度复制，则这是设计级 **NO-GO**，不需等待实验。若形成非同构的 parameter-tying bias，它是否产生 finite-data/OOD 外部增益才是合法的结果门。

## 8. 安全 chance constraint 与 conformal 校准错误

### 8.1 当前公式不是条件风险概率上界

01H 为每个 val-cal episode 保存 binary harm label `y` 与 predicted probability `\hat p` 的 residual `y-\hat p`，取 0.95 quantile `q_cal`，并把 `min(1,\hat p+q_cal)` 称为

\[
\Pr(d=1\lor r=1\mid h,EX)
\]

的 95% upper confidence bound。这一解释不成立。普通 split conformal 在 exchangeable calibration/test examples 下提供的是新 **outcome** 的边际 prediction-set coverage。它不会自动把 binary outcome residual 转换为每个 history `h` 上 conditional event probability 的置信上界。全局 `q_cal` 还可以在低风险和高风险状态之间平均覆盖，无法证明被放行的某一 `EX` 状态低于 0.05。

### 8.2 当前 val-cal 与 test 还没有 exchangeability

学得 policy 会根据模型预测选择哪些 histories 到达 `EX`，从而反过来改变 calibration 与 deployment state distribution。Repo-OOD、Workload-OOD 和 held-out risk combinations 又是 01H 主张的目标，它们明确不与两个 validation apps 同分布。标准 split conformal 不会在这种 policy feedback 和 distribution shift 下继续自动有效。

这一问题已被当前 primary 文献明确研究。JAWS-X 针对 standard 和 feedback covariate shift，Prinster et al.（2024）讨论 agent-induced sequential shifts，Mirzaeedodangeh et al.（2026）更直接指出 policy update 会使 interactive-environment conformal guarantee 失效，并为此构造 robust adjustment。01H 没有使用这些假定或方法。

### 8.3 必须在正文前替换的风险 gate

新规格必须在以下两条中选一，不能继续把当前 residual quantile 称为 conditional probability UCB。

1. **有限总体风险控制。** 在 checkpoint 和 policy 冻结后，用完全独立的 `val-cal-policy` worlds 真实运行该 policy，仅对“该冻结 policy 在该预注册 calibration population 上的边际 harm rate”使用 binomial/Clopper–Pearson、learn-then-test 或 conformal risk-control 上界。论文必须将 guarantee 限制在该总体，不声称是 pointwise `Pr(harm|h,EX)`。
2. **显式 shift-robust 约束。** 预先给出 calibration-to-target shift 的可估计模型、importance weights、sensitivity set 或 robust conformal/risk-control 方法，并证明 policy feedback 与 sequential dependence 满足它的假定。每个 OOD slice 分开声明 guarantee 或明确无 guarantee。

两条都必须定义 calibration sample 的有效 cluster 单位、被 policy 选择进入 `EX` 的 denominator、zero-harm cell 的 finite-sample bound、multiple thresholds 和 OOD 处置。如果资源不支持有效风险控制，可把它降为经验 calibration score，但不得继续作为“95% 概率上界”的硬安全保证。

### 10.2 键真实不等于理论责任已通过

ACAA-T6a/T6b 不只是说“评论之间有关系”。selection effect 和 preference differentiation 先产生 semantic diversity 责任，随后作者指出普通 affinity 会向相似 keys 集中而制造 redundancy，所以方法必须对 query 互补、对 key–key 减冗余。ACAA-M10a/M10b 再把这个错误方向写进公式。DSDL-T2 则规定 expectation `E`、experience `F` 和不可交换的 `S=F-E`，方法节把该方向送入前向、代理监督、稀疏约束、预测分支和联合目标。

01H 当前的 MEC-2 说 independent addition 会忽略顺序，direct policy 需要逐 sequence 学习。第一句只对真正 additive baseline 成立，不对 action-history SMDP/POMDP 成立。第二句也不能被写成定理，因为通用 history Transformer 同样做参数共享。更重要的是，`substitutive/complementary/synergetic` 允许所有作用方向，不会像 `F-E` 那样给出一个不可交换运算。

所以，01H 的句段功能链是真实的，但它的核心 MEC 还差一个肖老师式责任：不是泛说 generic model 可能样本效率较差，而是精确说明 **哪一个合理的普通计算在哪种迁移冲突中会产生什么错误方向，以及 option-impact parameter tying 怎样排除这一方向**。第 7.3 节的修补是正式写作前的理论门。

## 11. 修补后才可 DESIGN-FROZEN 的精确门

以下七项是正式论文正文前的设计门，不是结果门。任一未闭合，本题保持 `CONDITIONAL`。

1. **理论计算差异门。** 固定主模型的 option-impact parameter tying，说明它强制共享或禁止的具体计算，不得仅保留 unrestricted `η/k` MLP 和理论名称。
2. **公平 SMDP 门。** 加入 `G-PhysicalFactoredSMDP`，给它相同 actions、AB/D60、path、physical masks、labels、parameters、FLOPs 和 search nodes。撤销当前 `G-FactoredMPC` 不可公平的动作剔除。
3. **风险约束门。** 用有明确 population/shift 假定的 risk-control 方法替换 `y-\hat p` conditional-UCB 表述，冻结 policy-specific calibration 和 OOD guarantee 边界。
4. **CodeTwin 去泄漏门。** 冻结 twin-invariant future raw inputs、candidate universe/order/mask，标注 analyzer 是否属于 code channel，定义 full/no-source/schema-telemetry/shuffled-code 对照。
5. **枚举隔离与范围门。** 建立 `ENUM-IDENTIFY/ENUM-TRAIN/ENUM-TEST` 三个 group-disjoint manifests，主机制结果不得使用进入 `L_lat` 的 records。65 条有序子集只可标为 fixed-`π_ref` mitigation-order oracle；若主张全行动 exhaustive oracle，必须纳入 `D60`、中途 `EX/AB` 和 observation branches。
6. **实例 benchmark 与运行预算门。** 在观察任何模型结果前固定四十项 field-level migration contracts、checker/oracle/injection/operator/sibling-sampling manifests 及 hashes，并通过至少 32 项 clean inclusion 条件；同时冻结各阶段真实执行或模拟的 episode count、缓存边界、worker-hour 和 storage 上界。
7. **推断单位门。** 选择“扩到至少八个 independent Repo-OOD app families”或“撤销 population-level Repo-OOD 主张”之一，然后重写 mixed model/bootstrap 规格。

七项完成后，可进行一次简短的再红队。如果主模型与公平 generic SMDP 在前向、loss 和 action 上仍然精确同构，终局应为 `NO-GO`。若不同构且其他规格闭合，则可不等待性能结果而进级 `DESIGN-FROZEN / RESULTS PENDING`。

## 12. 只能由实验回答的预注册结果门

下列门不得被用于当前的设计否决，也不得在未运行时写成已通过。

1. 四项 mitigation 中至少三项在可观察 state/path 下发生有统计与实质意义的 plan-ranking reversal。
2. `D60` 的 passive observation 对 latent condition 有净校准价值，并在时间—成本冲突中改变 actual action。
3. `M_SR/M_SV`、`M_WC`、`M_CP` 分别在执行数据中形成 observation、hazard 和 conditional-severity/recovery 的可识别签名，且 positivity 足够。
4. Full-code model 在 CodeTwin-v1.1 上的代码语义利用改变外部 harm/success/cost，而不只是 action ID。
5. 主模型相对 `G-PhysicalFactoredSMDP`、`G-JointSMDP`、`G-POMDP` 和 direct policy 在同 data/parameter/FLOP/search 下形成 finite-data、unseen-combination 与 OOD 的 safety–success–cost Pareto 改善。
6. Unordered path、additive impulse、No-PassiveInfo、No-Abandon 和 theory-neutral parameter tying 会在预注册冲突中改变 actual action 与 executable outcome。
7. 改善不来自额外 labels、hidden injection IDs、更大 search budget、不对等 physical masks、更强 substrate 或选择性删除 failed worlds。

任一核心结果门失败时，应按预注册处置撤销理论或整题，不得把论文改名为 migration risk score、checker router 或 pgroll tuning 后继续占用 thesis 题位。

01D 的 `Q0/Δ/I/P/J/O + generic world model` 方案仍然是终局 `NO-GO`，01H 不得被用来反向修改该前案的判定。01H 的新研究单位、optional operators、AB、D60、semi-Markov clock 和 common-seed sibling design 已经足以证明这不是一个平庸风险分类题，也不应因未运行结果而直接撤题。

但本次独立终审的终局仍是：**CONDITIONAL**。01H 尚未达到 `DESIGN-FROZEN`，也尚不进入正式论文正文。

其最大的实质风险不是环境建不起来，而是修正公平 generic SMDP 后，Benaroch 可能只解释了合法动作类别，却没有产生一个独立于普通 Bellman planning 和物理 tool semantics 的计算结构。第 11 节七道设计门中，第 1–2 条是最终理论生死门。若它们闭合，其余数据、风险和 CodeTwin 问题均有明确修补路径；若它们无法闭合，则不应因已经写了六万余字规格而保留本题。
