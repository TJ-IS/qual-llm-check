# 有限审核容量下的安全审核分配候选终审

> 终审日期：2026-08-15  
> 终审状态：**NO-GO，终止候选，不保留试写、预留席位或弱化版**  
> 文件性质：内部选题与算法责任审计，不属于任何论文正文  
> 结果边界：本候选没有运行实验。本文只报告已核验文献事实、可行性推演与终审判断；没有任何候选方法结果。

## 0. 终审结论

有限审核容量确实会把 coding agent 的高产出转化为组织风险。多项代码、配置与依赖变更同时到达时，错误的审核分配可能让高影响变更交给缺少相关经验或已经疲劳的开发者，也可能让安全变更长期积压。这个问题具有明确的外部损害、真实的资源约束和可执行的安全评价结果，因而不是伪问题。

它仍然不能成为本系列的一篇独立论文。最强版本把变更表示、审核者专长、错误相关性、负荷、疲劳、切换成本、可用时间和队列状态一起输入，输出单审、双审、延后或沙箱隔离。该动作空间已经被四条直接工作共同封闭：代码审核者推荐研究已联合处理专长、负荷、知识分布和追加审核者；多专家 learning-to-defer 已学习异质专家错误并在容量约束下全局分配；动态人机协作已把累积负荷与疲劳放进 CMDP；一般人员调度已联合处理多技能、学习遗忘、疲劳恢复和工作休息。2026 年的两项代码审核工作更直接地对高风险变更增加专家审核者，并在真实生产随机试验中部署风险审核者推荐。把这些能力重新组合到 coding-agent 队列上能够形成有用系统，却没有产生 ISR 级的独立算法能力。

理论检索也没有补上缺口。TMS、组织注意、习惯化、疲劳、情境切换、专家互补和审核学习都能解释为什么分配重要，并能建议状态变量；它们没有推出一种等信息、等参数的匹配 Transformer、CMDP、POMDP、restless bandit 或学习型人员调度器不能表示的方向性运算。公开历史数据又只观察实际被分配者的审核行为，既没有同一变更交给其他真实开发者时的反事实错误，也没有由隐藏可执行 oracle 给出的审核正确性。AIDev 中的审批、评论与延迟轨迹不能把疲劳、信任校准、任务质量和选择效应分开。隐藏测试能够修复结果测量，却不能修复审核者反事实或创造理论算法新颖性。

因此，本候选同时未通过“直接近邻后的新增能力”“理论改变内部计算”“coding-agent 身份必要性”“真实多审核者因果监督”和“与现有候选动作独立”五道实质门。后文给出的最强救援设计只用于证明这个结论，不构成冻结规格。若未来出现新的理论机制或新的随机化多人审核数据，那应当作为新候选从头终审，不能据此保留本候选。

## 1. 被终审候选的不可变边界

### 1.1 决策情境

组织在一个滚动时间窗内同时收到多项由 coding agent 提交的代码、配置或依赖变更。真实开发者审核者在专业领域、项目熟悉度、历史错误模式、可用时间、当前队列、累积负荷、疲劳、情境切换成本和可能的学习收益上存在差异。候选算法可以读取冻结的变更描述、代码与仓库结构表示、审核历史和实时队列状态，但不能自行检索、选择、生成或改写审核证据。

### 1.2 唯一允许的算法动作

在每个调度时点，算法只能为队列中的候选变更选择下列动作之一：

1. 分配给一名指定审核者，并确定开始时点；
2. 分配给两名指定审核者，并确定并行或预先固定的顺序；
3. 延后至后续时点；
4. 送入预先定义的沙箱隔离流程。

算法不得选择 `approve`、`deny`、`merge`、证据集合、风险阈值或“何时向人求助”。单审和双审之后如何汇总人类判断必须由实验协议预先固定；沙箱内运行哪些检查也必须在算法之外冻结。否则，候选会越界成为升级策略、证据选择或批准决策论文。

### 1.3 必须报告的外部结果

安全结果只能由对调度策略不可见的可执行 oracle 判定，包括被人类批准或合并后仍违反隐藏测试、安全不变量、配置约束或依赖约束的变更比例与严重度。任务结果必须同时报告安全变更吞吐、队列积压、端到端延迟和截止期违约。人类结果至少包括主动审核时间、判断错误、疲劳或负荷测量，以及在预先注册时间窗内可独立测得的技能学习。点击推荐、接受推荐、评论数、历史审核者命中率和是否最终合并只能作为过程变量，不能替代这些外部结果。

### 1.4 不得借边界漂移制造贡献

若模型自行预测哪些变更应进入人工审核，它已经进入 when-to-ask 或风险阈值问题。若模型选择供审核者查看的文件、测试、历史案例或解释，它进入固定审核者后的证据选择。若模型决定人类判断如何汇总为批准或拒绝，它进入最终行动决策。若模型以长期培养某类人类技能为首要行动后果，它进入 human-skill preservation。终审只评价上述狭窄的人员—时间—审核强度分配问题。

## 2. 直接近邻已经覆盖到哪里

### 2.1 代码审核者推荐与风险审核

| 直接工作 | 已实现的核心能力 | 评价与资产 | 对本候选的封闭作用 |

| Saini and Britto 的 [Pineapple](https://arxiv.org/abs/2102.05916) | 用 Bayesian Network 估计 merge probability，并结合变更类型与冲突对一名开发者的审核请求队列排序 | 在 Ericsson 超过 150 名开发者的真实项目部署并做静态用户评价 | “审核者面对积压时应先处理哪一项”已有工业机器学习系统；其 merge proxy 不满足安全结果，但队列排序动作并非空白 |
| Yang et al. 的 [GPP](https://conf.researchr.org/details/ase-2024/ase-2024-research/9/GPP-A-Graph-Powered-Prioritizer-for-Code-Review-Requests) | 以多重图表示一组审核请求及其共享文件、作者等关系，用 GNN 输出联合优先序 | ASE 2024；15 个 OSS 项目、超过 420,000 个 CRR，并公开材料 | “组合队列＋请求间关系＋学习型排序”已有直接工作；候选须改变安全结果和人员动作，而不能以图排序本身主张贡献 |
| Sefidi Esfahani and Rigby 的 [Mitigating the Risk of Defects and Improving Knowledge Distribution with Code Reviewer Recommenders](https://users.encs.concordia.ca/~pcr/paper/Sofia_Change_Safety_Ratio.pdf) | 以整个审核团队的知识定义 CCSR，并用 `AddExpertRec(D_t)` 对缺陷倾向高的 PR 增加一名专家审核者 | Proc. ACM Softw. Eng. 3(FSE), 160–181；有复制包 | “高风险变更＋追加第二审核者＋负荷/知识权衡”与候选最核心动作直接同构 |
| Paraspatki et al. 的 [Code Reviewer Recommendation for High Risk Diffs at Scale](https://conf.researchr.org/details/fse-2026/fse-2026-industry-papers/19/Code-Reviewer-Recommendation-for-High-Risk-Diffs-at-Scale-Workflow-Recommender-and) | 对高风险 diff 增加推荐审核者并训练专门的 risky-diff recommender | FSE 2026 工业论文；超过 15,000 个 diff 的工作流随机试验和超过 5,000 个 diff 的推荐器 A/B 试验 | 已在生产中直接检验“有限专长应集中于高风险变更”；候选改用隐藏 oracle 能加强因变量，却不能宣称动作首创 |

上述工作并非都满足本任务的安全结果要求。尤其是历史审核者命中、CSR/CCSR、评论、接受和风险分数下降都不是隐藏可执行 oracle 下的 unsafe merge。然而，评价缺口与算法缺口必须分开。用更可靠的因变量重做一个已经存在的审核者选择或追加审核者动作，可以成为重要复现或测量论文，不会自动形成新的理论算法论文。

### 2.2 多专家分配、相关错误与容量约束

| 直接工作 | 已实现的核心能力 | 本候选仍可能声称的差异 | 终审判断 |
|---|---|---|---|
| Alves et al. 的 [DeCCaF](https://arxiv.org/abs/2403.06906) | 仅需每实例一名专家标签即可学习每位专家的实例相关错误，再用约束规划在专家容量与错误成本下做全局分配；公开代码 | 代码变更结构、动态疲劳、双审 | 代码结构只是输入域；动态疲劳由 FALCON 覆盖；多人追加价值由下项覆盖 |
| Kelly et al. 的 [Bayesian Inference for Correlated Human Experts and Classifiers](https://proceedings.mlr.press/v267/kelly25a.html) | 以联合潜变量表示专家相关错误，推断未观察专家标签和追加专家查询的边际效用 | 队列与开始时点 | 已封闭“错误不独立所以需双审/多样化审核者”的主要技术动机 |
| Verma, Barrejón, and Nalisnick 的 [Learning to Defer to Multiple Experts](https://proceedings.mlr.press/v206/verma23a.html) | 给出多专家 deferral 的一致 surrogate、校准与 conformal ensemble | 人类状态会随工作变化 | 多专家路由本身是成熟问题；剩余动态状态必须与 FALCON 和调度文献比较 |
| Gao et al. 的 [Human-AI Collaboration with Bandit Feedback](https://www.ijcai.org/proceedings/2021/0237.pdf) | 从观察性决策与结果学习人机互补，并扩展到多名不同能力的人类决策者 | 审核的执行真值与资源耦合 | 个性化路由和部分反馈不是新增能力；反事实假设反而是候选的数据风险 |
| Alves et al. 的 [OpenL2D/FiFAR](https://pmc.ncbi.nlm.nih.gov/articles/PMC12019285/) | 提供 50 名异质合成专家、容量清单、完整生成器、训练/测试文件和可复现实验 | 真实开发者与代码安全 | 可直接跑通算法，但不能支持真实审核者疲劳、学习或错误相关性的经验结论 |

DeCCaF 的局限并不能单独构成空白。把静态专家误差换成动态审核者状态，再把单人动作扩为双人动作，是一个自然扩展；FALCON、Kelly et al. 与动态人员调度分别提供了三个缺失部件。候选尚未找到一个必须联合建模而且现有通用策略系统性算错的关系。

| 直接工作 | 已实现或发现的机制 | 证据边界 | 对候选的含义 |
|---|---|---|---|

## 3. 数据、结果与因果识别终审

### 3.1 公开资产分别能回答什么

| 公开资产 | 可直接运行的内容 | 缺少的关键量 | 可否独立支撑候选 |
|---|---|---|---|
| [AIDev](https://arxiv.org/abs/2602.09185) | 大规模 agent-authored PR、评论、审核、时间和仓库元数据 | 对未分配审核者的审核结果；隐藏执行真值；主动审核时间；随机负荷 | 否，只能构造到达流和观察性现象 |
| [c-CRAB](https://arxiv.org/abs/2603.23448) | 184 个 PR、234 条由真人评论转成的可执行测试，可验证评论引导后的修复 | 多名真实审核者对同一 PR 的独立判断；队列、疲劳与分配反事实 | 只能提供部分隐藏 oracle，不提供策略训练所需的审核者响应面 |
| [SWE-PRBench](https://arxiv.org/abs/2603.26130) | 350 个 PR、真人标注问题与冻结上下文设置 | 可执行安全真值；真实多审核者反事实 | 不满足主要安全结果 |
| [BulkPR-Bench](https://arxiv.org/abs/2608.02685) | 581 个新编 PR、18 个真实仓库、状态化隐藏安全检查与精确队列 oracle | 真人审核者、审核者状态与审核判断 | 适合队列级 merge 子集和顺序治理，不是审核人员分配基准 |
| [OpenL2D/FiFAR](https://pmc.ncbi.nlm.nih.gov/articles/PMC12019285/) | 50 名合成专家、完整专家响应和容量情境 | 代码语义、真人状态、真实组织学习 | 可做管线测试和负控制，不能承担主结论 |

这些资产是互补的，却不能简单拼接。把 AIDev 的审核者身份贴到 c-CRAB 的测试上，会创造从未发生的审核行为；把 FiFAR 的合成专家错误映射到开发者，会把模拟假设当成经验事实；把 BulkPR-Bench 的精确 merge oracle改作审核者标签，会混淆“变更是否安全”和“某人能否发现不安全”。数据处理规模再大，也无法从缺失的潜在结果中恢复真实审核者响应。

### 3.2 最小因果对象

令 `i` 表示变更，`j` 表示审核者，`h` 表示其在分配时的负荷与历史状态，`d_i∈{safe,unsafe}` 表示隐藏执行 oracle，`r_ij(h)` 表示审核者在该状态下是否给出与 oracle 一致的判断。历史平台只观察实际分配 `A_i=j` 后的 `r_ij(h)`；对所有 `k≠j`，`r_ik(h')` 均缺失。由于作者和维护者会依据模块、关系、紧急度与预期专长选择审核者，缺失机制不是随机的。用实际审核者命中率训练推荐器只能复现选择，不能识别审核正确性。

双审还需要联合潜在结果 `r_ij(h), r_ik(h')` 及其在同一变更上的条件相关性。不同审核者分别看过不同变更时，历史错误相关性可能只是任务组成差异。Kelly et al. 的联合潜变量可以在有重叠专家标签的数据中估计相关性；公开代码审核日志缺少足够的随机重叠和执行真值，不能直接识别该量。把评论相似度当成错误相关性也不成立，因为不同表述可能发现同一缺陷，相似评论也可能共同遗漏隐藏失败。

### 3.3 最强可行的数据采集设计

若只评价数据可行性，最严谨的方案是前瞻性、授权且隔离的真人实验：

1. 在冻结仓库快照上由多个 coding agent 生成代码、配置与依赖变更；每项变更配置对审核者和策略均隐藏的功能测试、安全回归、配置不变量和依赖完整性检查。
2. 先按仓库和缺陷类型分层，再随机将同一变更的复制件分配给多名开发者；每名开发者独立审核，不看到其他审核结果，且不能运行隐藏 oracle。
3. 以随机化队列负荷、时间段与上下文切换构造可识别的短期状态；疲劳需用预先注册的主观量表和行为/生理测量，而不能从“批准更多”反推。
4. 审核者只提交预先定义的批准、阻止或请求修改判断。研究算法只选择审核者、时间和单/双审；判断汇总规则在随机化前冻结。
5. oracle 在判断完成后运行，产生 `unsafe approval/merge`、安全变更吞吐、积压、延迟、主动审核时间和判断错误。学习结果需用不同但同构的保留任务在后测测量，不能用历史评论量代替。
6. 训练、验证和测试按仓库与时间双重隔离。隐藏测试生成者、审核者、策略训练者和最终评测执行者分权；任何测试名称、失败日志或 gold 修复均不得进入输入。

这个方案能解决部分因果识别问题，但需要大量真实开发者对同一变更做重复审核，且需在疲劳操纵、劳动伦理和报酬上投入显著资源。更重要的是，即使完成采集，得到的仍首先是一项稀缺的多审核者代码安全数据资产。若算法只是以 DeCCaF/FALCON/Kelly/人员调度的组合模型优化这些标签，数据价值不能替代理论—算法新增能力。

### 3.4 结果定义的硬边界

`unsafe approval` 应定义为审核协议输出可合并、而隔离执行随后触发至少一个预先登记的隐藏失败。`safe throughput` 只能计入 oracle 全部通过并在时间窗内完成审核的变更。延后和沙箱不能被记作安全成功；它们分别进入 backlog/latency 与隔离成本。一个拒绝所有变更的策略会得到零 unsafe approval，但同时得到零 safe throughput，必须被 Pareto 曲线或预注册效用函数识别为退化策略。任何结果表都必须同时展示安全、任务、人力与计算成本四组指标。

## 4. 最强算法救援推演及其同构坍缩

本节不是候选规格，也不授权开始实验。它把候选推到技术上最强的版本，以检查是否仍存在不可替代的理论结构。

### 4.1 能够实现的最强通用模型

在时点 `t`，令变更张量为 `X_t∈R^{B×N×d_x}`，审核者张量为 `U_t∈R^{B×M×d_u}`，变更—审核者边张量为 `E_t∈R^{B×N×M×d_e}`。`X_t` 可含 diff、配置/依赖类型、调用图位置、预先冻结的风险描述与等待时间；`U_t` 可含领域专长、可用时间、当前工作量、最近任务序列、疲劳测量与历史学习曲线；`E_t` 可含文件熟悉度、作者协作、预计审核时间、预计错误率和切换成本。双审再加入 `C_t∈R^{B×N×M×M}` 表示同一变更上两名审核者错误的条件相关性或互补效用。

一个二部图/集合 Transformer 可以在相同信息上产生单审 logits `z_ij`、双审 logits `z_ijk`、延后 logit `z_i^D` 与沙箱 logit `z_i^S`，再由可微匹配层或整数规划层满足时段、并发和容量约束。世界模型分别预测审核正确性、主动时间、状态转移和学习后测；策略在固定汇总协议下最小化 unsafe approval，同时约束 safe throughput、积压、延迟和人时。监督损失可写成

`L_world = L_oracle + λ_t L_time + λ_h L_state + λ_c L_corr + λ_l L_learning`，

策略目标可写成

`J(π)=E[Σ_t(c_u·Unsafe_t+c_b·Backlog_t+c_l·Latency_t+c_h·HumanTime_t−c_s·SafeThroughput_t)]`。

训练数据只能来自上一节的随机化真人审核；历史非随机日志至多用于预训练，并需用倾向权重、重叠诊断和敏感性分析限制主张。推断时模型仅输出允许的四类动作，绝不读取隐藏 oracle 或生成证据。

### 4.2 为什么这不是理论驱动的新工件

上面的最强版本已经把候选能提出的有用状态全部纳入，但每一部分都有直接的通用来源：`E_t` 中的专长和负荷对应 WhoReview、SofiaWL 与 Meta RevRec；实例相关人类错误和容量对应 DeCCaF；`C_t` 对应 Kelly et al.；动态负荷状态和约束策略对应 FALCON；学习、遗忘、疲劳、恢复与工作休息转移对应 Asadayoobi et al.；双审动作对应 AddExpertRec 与多专家查询。所谓“理论张量”没有执行不同的前向运算，只是为通用状态变量赋予组织学名称。

同信息、同标签、同动作与同预算下，以下替代模型必须作为公平基线：

1. 等参数二部图 matching Transformer，直接学习全部单审、双审、延后和沙箱 logits；
2. reviewer-as-arm 的 restless bandit，审核者状态随工作与休息演化，动作受联立容量约束；
3. 带潜在疲劳和相关错误状态的 POMDP；
4. 与候选相同世界模型、仅移除理论命名与专门损失的 CMDP；
5. DeCCaF 式人类错误模型加动态约束规划；
6. 与候选参数量、训练样本、调参次数、并发审核数和总人时完全相同的直接策略网络。

若理论版只因多一个状态标签、额外监督、更多参数或更强可行域约束而领先，就不能归因于理论。若把所谓理论状态随机置换、中和或由通用隐藏状态替换后性能不变，理论责任失败。若等参 POMDP/CMDP 在同一状态上复现所有冲突选择，理论算法贡献同样失败。当前检索没有找到可提前说明通用替代为何会在某一方向冲突中必然作出错误选择的机制，因此没有理由投入高成本真人实验来检验一个尚未成立的理论差异。

## 5. 理论候选逐项否决

| 理论或机制 | 它真正解释的对象 | 若进入算法，最强可接受表示 | 必须出现的方向冲突 | 等信息通用替代 | 终审 |
|---|---|---|---|---|---|
| 交互记忆系统 TMS | 群体通过专长分化、可信度与协调形成“谁知道什么”的共享元知识，并进行编码、存储、检索与沟通 | 审核者本人、同伴与分配者对专长的分布式信念；任务—知识—人员单元及其验证更新 | 当前最熟练者可立即降险，但分配给另一成员可能校准共享元知识并提升未来协调 | 中央 `E_t` 专长表加长期学习回报即可产生同样选择；若加入查询、检索、交接与信念共享，又越界回到 C2 的知识协调 | **NO-GO**。中央审核推荐器不是 TMS；完整 TMS 动作又超出本候选 |
| 组织注意/attention-based view | 组织注意稀缺、情境化且受结构分布，议题进入注意焦点才影响行动 | 组合层面的注意预算、议题显著性、组织结构与跨期注意状态 | 高显著但低边际安全收益的变更可能挤出低显著高损害变更 | 队列优先级、容量约束与组合效用可由 scheduler 直接表示；Bendig et al. 的 TMT 数字创新研究层级也不等于个体代码审核 | **NO-GO**。提供问题框架，不提供专门计算 |
| 习惯化—敏化双过程 | 重复 IT 中断可同时引发反应递减与反应增强；过程随重复暴露变化 | 两个可分离的潜在状态及各自的更新方程，最好有生理与行为多源监督 | 对重复相似变更可能减少警觉，而高后果刺激又提高敏感，不能把两者压成单调疲劳 | 带双潜变量的 POMDP 可原样表示；AIDev 的审批/评论/延迟不能识别两个过程 | **NO-GO**。Weinert et al. 能解释轨迹，不决定分配给谁或何时双审 |
| 疲劳与自我调节资源 | 连续认知劳动会使表现变化，休息可能恢复 | 审核者特定的状态转移与恢复曲线 | 最专长但已疲劳者与较弱但清醒者之间的短期选择 | FALCON 和一般动态人员调度直接覆盖 | **NO-GO**。近邻过强 |
| 情境切换 | 任务域切换产生重建上下文的时间与错误成本 | 前一任务域—后一任务域的转移张量 | 同一审核者连续处理同域变更可能节省切换，却集中相关遗漏或推迟紧急任务 | sequence-aware scheduler/Transformer 直接读取上一任务与切换成本 | **NO-GO**。只是转移成本，不是理论特有运算 |
| 专家互补与群体多样性 | 不同知识和错误模式使第二判断具有边际价值 | 条件联合错误或边际信息增益 `C_t` | 两个单独更准确但高度相关的审核者，可能劣于一强一弱但互补的组合 | Kelly et al. 已直接建立联合潜变量与追加查询效用；AddExpertRec 已进入代码审核 | **NO-GO**。核心方向已被直接算法化 |
| 审核学习/技能保持 | 分配会改变未来专长、知识扩散和组织韧性 | 个体技能状态与任务后测转移 | 立即安全与未来能力培养发生冲突 | Asadayoobi et al. 和 SofiaWL 已处理学习/知识扩散；若把长期能力作为核心贡献则与 C15 同题 | **NO-GO**。要么普通状态，要么候选重叠 |

TMS 是最接近自然理论的选项，因 Brandon and Hollingshead 已把 task–expertise–person 单元置于 TMS 发展核心。然而，TMS 的独特对象是群体成员对彼此知识位置的共享、验证与调用，不是中央平台根据历史文件记录计算一个专长分数。若保留狭窄动作，TMS 被压缩成推荐器特征；若忠实实现 TMS，模型必须决定询问谁、检索什么知识、如何交接及如何更新共享信念，直接跨入已淘汰的 C2 知识协调。这不是可以靠命名修复的两难。

Weinert et al. 的重复 IT 中断研究也已通过 Otero 全文核对。该文的双过程机制能支持“重复暴露不等于单调疲劳”，并报告生理唤醒、耗竭与任务表现的不同轨迹。它没有推出审核者—变更匹配或第二审核者配置；将习惯化和敏化设成两个潜变量之后，公平 POMDP 仍可使用相同变量、更新和动作。理论因此能够解释状态，却没有改变政策类。

## 6. coding-agent 身份必要性检验

把候选输入中的“agent 作者”替换为“人类作者”，保留 diff、配置变更、依赖变更、队列、审核者、负荷和隐藏测试，算法的张量、损失、动作和评价均无需变化。这说明 coding agent 目前只是改变变更到达率、分布和可能质量，不是算法所依赖的行动者机制。

AIDev 与 Habituation at the Gate 提供了真正的 agent 情境证据：agent PR 数量大，重复审核者的审批、评论和延迟会随暴露改变。这一现象可以证明组织问题变得更迫切，却不能区分 agent 代码质量变化、维护者选择、信任校准、仓库规范化与疲劳。若要让 coding agent 身份不可删除，理论至少需要一个由 agent 的自主迭代、工具轨迹、批量相互作用或可适应审核政策所造成的状态转移，并使人员分配动作产生人类 PR 中不存在的后果。候选又禁止选择证据、阈值和批准动作，现有边界内没有找到这种运算。

BulkPR-Bench 的相互作用队列看似能加强 agent 特异性，但它让 agent 决定哪些 PR 以何种顺序合并，核心状态是变更间关系。把它改成人员分配论文后，审核者只是执行资源；若算法还决定合并子集与顺序，就越出候选边界。因而该基准适合另一类队列治理研究，不能救回本候选。

## 7. 与 C3、C2、C15 及普通 recommender 的独立性

### 7.1 与 C3 的动作冲突

C3 的原则边界是升级动作已经冻结之后，为固定审核主体选择可信证据。然而当前本地冻结稿仍在动作集中保留“选择知识域第二审核者”：见 `00H_论文三可信取证与真人实验冻结规格.md` 的 L76，以及 `00J_候选三共同基础理论责任红队与撤题判定.md` 的 L136。那不是证据选择，而是本候选的双审分配动作。若保留当前文字，两篇在行动层直接碰撞；若 C3 删除该动作并把审核者集合完全外生固定，本候选才获得形式边界。形式边界仍不能解决前述直接近邻和理论失败，因此无需为本候选要求 C3 改稿。

### 7.2 与 C2 的理论与对象冲突

本地 `00B` 已将 C2 记为 NO-GO，原因之一是 TMS 被简化为中央专家表或检索路由后，知识协调机制不再成立；`00P` 进一步核对了 MISQ TMS 全文及相应失败。若本候选用 TMS 为“哪个审核者懂什么”重新包装中央分配，它会复活同一失败。若加入共享元知识、询问、知识检索与交接，则与 C2 的研究对象重合并越过本候选“不选择证据”的边界。

### 7.3 与 C15 的长期能力冲突

把审核者学习仅作为状态转移，算法只是一般动态调度器；把技能保持、知识扩散或去技能化设为主要外部结果，分配动作的首要责任转为保护未来人类能力，和 C15 的 human-skill 研究对象同题。SofiaWL 又已直接处理知识扩散、负荷和人员流失风险。候选无法同时借“学习”制造理论深度并保持与 C15 独立。

### 7.4 与普通 reviewer recommender 的最小差异不足

普通 recommender 往往优化历史审核者命中并输出排序。本候选可以在三个方面更严格：输出队列级联合匹配而非逐项排序；使用执行 oracle 的安全错误而非历史选择；显式处理动态状态和单/双审。可是 WhoReview 已输出审核者集合，Meta 与 RDR 已做真实分配试验，AddExpertRec 已追加审核者，DeCCaF/FALCON/调度研究已提供联合与动态决策。三项差异的组合需要工程和数据，却没有一个是未被提出的基本能力。

## 8. 公平替代、机制干预与撤题门

如果无视终审继续做实验，任何正面结果都必须至少通过以下对照才可能谈机制：

| 责任 | 必须给出的对照或干预 | 不能接受的替代 |
|---|---|---|
| 审核匹配 | WhoReview、SofiaWL、RAR/RecRDR、DeCCaF、直接 ILP/CP-SAT | 只和 RevFinder 或随机分配比较 |
| 动态策略 | FALCON 式 CMDP、restless bandit、相同世界模型的 POMDP | 只和静态 top-k 比较 |
| 双审互补 | Kelly 式相关专家模型、AddExpertRec、独立错误假设变体 | 只比较一人和两人数量 |
| 通用容量 | 等参数二部图 Transformer，完全相同输入与动作掩码 | 给理论版更多状态或更多标签 |
| 理论责任 | 打乱 TMS 信念、交换习惯化/敏化状态、删除方向更新、用同维自由潜变量替换 | 只删除一个损失权重 |
| 评价 | 隐藏执行 unsafe approval、safe throughput、backlog/latency、人时/错误/后测学习 | 推荐命中、点击、评论、合并与风险分数代理 |
| 隔离 | 跨仓库＋跨时间测试；隐藏 oracle manifest 与训练 manifest 分离 | 随机 PR 划分导致同仓库/同模板泄漏 |

该候选在实验前已经触发撤题门：如果等信息通用模型可以表达同一状态、同一方向和同一动作，理论不构成独立算法贡献；如果主要训练依赖历史实际审核者，安全正确性的反事实标签不可识别；如果用真人随机实验补齐标签，算法新增能力又被直接工作组合覆盖。三者不是可用消融修复的实现细节。

ACAA 的关键并不是多模态或模型复杂，而是先证明通用相似性运算在偏好冲突中会把理论上负向的局部差异当成正向相似，再由该错误推出非对称计算。DSDL 的关键也不是给深度网络增加一个辅助头，而是由期望不一致理论保留 `E`、`F` 与有方向的 `F−E`，并用角色非对称改变交叉注意。当前候选没有找到等价责任。把“注意稀缺”写成容量约束，或把“谁知道什么”写成审核者 embedding，都达不到肖文的理论—算法闭合程度。

| 是否需要本地训练工件 | 世界模型、相关错误模型、状态转移与策略均需训练 | 通过“硬度”，但硬度不等于新颖性 |
| 是否超越最强直接方法 | AddExpertRec/RDR、DeCCaF/Kelly、FALCON/人员调度共同覆盖 | **未通过** |
| IS 理论是否改变内部计算 | 理论只产生状态、约束或回报；未产生不可交换方向或专门兼容函数 | **未通过** |
| 等参数通用替代是否可能复制 | matching Transformer、CMDP/POMDP、restless bandit 可用相同全部信息和动作 | **未通过** |
| 数据能否识别审核者反事实、疲劳与相关错误 | 需新建高成本随机化真人数据；公开日志不能识别 | **未通过** |
| 与 C3/C2/C15 是否动作和理论独立 | 当前 C3 保留第二审核者动作；TMS 与 C2、学习与 C15 冲突 | **未通过** |
| 是否足以独立成为 ISR 论文 | 实践与数据问题重要，理论和算法责任不足 | **未通过** |

## 12. 同步用终止摘要

**终止理由不是“算力不够”或“公开 benchmark 太小”，而是理论与算法责任在实验前已经坍缩。** 更强的隐藏执行 oracle 会显著改善安全评价，但无法把已有的风险审核者推荐、多专家容量分配、相关错误查询和动态人员调度变成新的理论工件。AIDev 的行为轨迹又不能识别审核正确性、疲劳或审核者反事实。当前 C3 还保留第二审核者选择动作，C2/TMS 与 C15/学习也形成理论边界冲突。故本候选应从三篇论文候选池中删除，不进入正文、算法实现、真人招募或占位实验。

后续若出现三项同时成立的新事实——一种会强制产生非通用方向运算的自然 IS 理论、一套随机化真人多审核者加隐藏执行 oracle 的数据、以及不触碰证据选择/批准决策/技能保持的独立动作——那将构成另一个新候选。本文件的 NO-GO 不应被改写成 CONDITIONAL，也不应以“先做数据集论文”为由占用当前 thesis 的独立论文席位。
