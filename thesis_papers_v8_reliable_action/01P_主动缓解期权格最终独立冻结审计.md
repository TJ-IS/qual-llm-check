## 3. 理论构念、算法责任与非同构性

### 3.1 Benaroch（2018）真正承担的内容

本地全文支持候选 option object。摘要和主文第 69、75 行明确区分被动 `wait-and-see` 与主动 `act-and-see`，允许在投资前执行零项或多项 optional mitigations，并让措施的成本和作用依赖先前执行路径。第 102 行区分 learning、prevention 和 coping。第 181 行进一步限定 pure learning 只改变对不确定性的认识，不改变 state variable 的 drift；prevention 改变可控根因；第 235 行及其后把 coping 落到事件发生后的损害幅度。第 311 行给出同一措施因先前路径而具有不同 impact parameters 的实例。附录格点允许在决策点选择措施、继续等待或进入投资决定。

这些责任与当前映射基本一致。

| 理论责任 | 本题对象 | 终判 |
|---|---|---|
| exercise 是权利而非义务 | `EX` 与 `AB` 分开，旧稳定服务是可返回状态 | PASS |
| passive wait 与 proactive act 不同 | `D60` 只推进时间并等待新证据，`SR/SV/CP/WC` 执行主动措施 | PASS，信息量是结果门 |
| zero-or-more optional mitigations | 四类措施可省略，固定 pgroll substrate 不被伪装成 mitigation | PASS |
| path-conditioned substitution/complementarity/synergy | 有向先前槽到当前槽的 pair impulse | PASS WITH NARROWING |
| learning 只改变认识 | `SR/SV` 只经 observation 更新 `b` | PASS |
| prevention 改变可控根因 | `WC` 应持续改变后续 hazard | **映射正确，前向未闭合** |
| coping 限制事件后损害 | `CP` 应持续改变 recovery/severity | **映射正确，前向未完全闭合** |

Benaroch 不承担 32 个 latent configurations、六层 Transformer、rank-4 gate、二阶截断、semi-Markov kernel、200k search、`d∨r` calibration 或 PostgreSQL task。`01H:L328` 已把低秩二阶 tying 明确写成本文算法推论，这是正确边界。正式论文不能把“Benaroch 要求二阶低秩”写成理论事实，也不能把 learned real-options policy 本身写成首创。

### 3.2 非同构责任已经闭合

固定 matched canonical state 后，主模型只保留当前 main effect 与每个先前槽到当前槽的有向 pair effect。因此任意三项 action indicators 的三阶 mixed difference恒为零。`G-PhysicalFactoredSMDP` 的 unrestricted ordered-history Transformer 可以表示非零三阶 interaction。generic 函数类可以包含 theory 子类，不影响“无双向全局参数置换同构”的结论；这是一种严格的包含关系，不是模块改名。

`TT-1` 至 `TT-4` 也区分了设计与实现责任。测试尚未运行不能构成当前否决；如果将来 firewall Jacobian、pair-zero permutation、truncation witness 或 `Iso-OptionImpact` 一致性失败，才是实现失败。若 generic 在真实 benchmark 上落入预注册等效区间，则是结果失败并撤销理论算法贡献。

仍需收窄一项表述。Benaroch 允许完整路径依赖；当前模型只区分每个先前动作对“当前动作”的二阶作用，不能区分两个更早动作彼此的相对顺序对当前动作产生的三阶效应。这个限制已经在 `01H:L322` 坦白，因而不构成同构失败，但正式贡献只能叫“理论启发的二阶 ordered-pair inductive bias”，不能叫“real-options path dependence 的完整计算实现”。

### 3.3 role 机制只能作次级责任

`R_{r,ρ(j),ρ(m)}` 产生 channel-wise role-pair gain，确实进入前向。可是 `G-LatticeNoRole` 保留 slot identity、candidate embedding、ordered pair、physical mask 和 typed state，仍能从 action family 推断 learn/prevent/cope。该干预只中和显式 role-gain table，不能删除整个 role ontology。因而它可检验“显式 role tying 是否增加能力”，不能单独证明三类理论角色不可被通用候选表示复制。理论生死仍应由 `G-PhysicalFactoredSMDP` 与主模型承担；如果正文把 `Role-Neutral` 解释成对 Benaroch 全部角色机制的干预，必须改写。

## 4. 核心失败门：当前 `Q^a` 不是唯一可执行的 semi-Markov 核

### 4.1 已发生事件没有进入状态

`01H:L252–L255` 把状态冻结为 `x_n=(b_n,p_n,q_n,g_n,c_n,t_n,τ_n)`。`g` 只含 checkpoint/recovery 与 write-cap 字段。`01H:L353–L357` 却对 nonterminal action 写出

\[
Q^a(x)=-\mathbb E K(a\mid x)+\mathbb E_{d,e,s,o}[U_{event}(e,s)+V(x')].
\]

其中 `x'` 只更新时间、belief、path、`g` 和成本，没有记录 corruption、semantic violation、availability event 或 recovery failure 是否已经发生及其 severity。规格也没有说明四类事件是吸收、可重复、可恢复还是只计首次发生。由此产生三种不唯一实现。

1. 实现者可以在事件发生后继续用无事件状态规划，忽略持久损害。
2. 实现者可以把 `U_event` 计一次，又让 terminal `J/V` 对同一损害再计一次，形成双重惩罚。
3. 实现者可以把事件当作 terminal，但这会改变深度、action mask、censoring 和训练标签。

这不是待运行结果，而是 Markov sufficient state 和 payoff decomposition 缺失。冻结前必须新增 typed event ledger 或吸收状态，例如 `ℓ_n={event_type,occurrence_time,persistent_damage,severity,repaired}`，逐类定义 `T_ℓ`，并规定 terminal oracle 是否只计未曾入账的增量损害。availability hazard 若允许多次发生，还要从 time-to-first-event 模型改成可重复计数过程，或明确只建模首次 SLO breach。

### 4.2 规划需要联合核，规格只给了边际 heads

`Ô`、`Λ̂`、`Ŝ`、`D̂` 和 `K̂` 分别给 observation、event hazard、conditional severity、duration 和 cost 的边际预测。Bellman 式却对 `(duration,event,severity,observation,cost)` 的联合结果取期望。当前没有冻结条件独立图、copula、共享 latent draw、quantile interpolation 或 quadrature weights。特别是：

- red observation 与 event occurrence 通常相关，不能默认独立而不报告；
- duration、availability 和 cost 在高负载时共同变化，边际 quantiles 不能唯一决定联合效用；
- “duration 取 0.10/0.50/0.90 nodes、severity 取 19 nodes”没有相应积分权重；
- `K` 在式外先取期望，event utility 在式内取联合期望，但两者相关时这种分解会改变风险与成本权衡。

冻结前必须写出完整 factorization 或共同随机变量生成器，并为离散、hazard、quantile 和 cost 每个节点给固定权重。所有比较模型必须消费同一联合核；否则相同 checkpoint 可以因实现选择而给出不同 action。

### 4.3 typed persistent state 被 firewall 过度截断

`01H:L276–L289` 正确阻止 raw history 旁路 pair branch，但同时禁止 `g` 进入 passive neural base 和 active main。`D60` 又在 `01H:L326` 只使用 `ψ^0(H_0,z)`。结果是：执行 `WC` 后，随后的 `D60` hazard 与未执行 `WC` 时相同；执行 `CP` 后，后续 nonterminal action 中的 recovery severity 也不能读取 checkpoint 状态。只有 terminal head 能读取 `g`。这与 prevention 持续改变根因、coping 持续限制损害的理论映射冲突。

修补不需要放开 raw `P`。应让主模型和公平 generic 共同使用一个只读 typed physical kernel，例如 `ψ^phys(H_0,z,g,t,a)`，只消费经过 state-machine 验证的 `g` 与 absolute time。非同构 witness 继续在 matched `g` 上执行，因此不会让匿名 history 绕过 pair；它只恢复合法物理持久性。

### 4.4 terminal head 的输入契约互相矛盾

输入表 `01H:L268` 说 `R` 中的 old-client、protocol 和 cumulative-resource state 可供 terminal head 使用，`01H:L326` 的实际公式却是 `Head_T(H_0,z,g_n)`。它没有 `t/τ`、old-client occupancy、protocol state、已发生事件 ledger 或当前 workload state。相同 `H_0,z,g` 在 `t=30` 与 `t=590` 时会得到同一 terminal distribution，即使 absolute workload/fault trace 和合法 cutover precondition 不同。action mask 只能判断动作是否合法，不能替代合法动作执行后的结果分布。

冻结前必须统一一个 machine-readable terminal signature，并说明 belief 如何对 `z` 积分。最低要求是读取 `H_0,z,g,t,protocol,old_client,ℓ`，或读取与这些量信息等价且不含 raw path 的 typed state。terminal duration/cost heads也要采用同一 signature。

### 4.5 200k pruning 会改变动作，但 upper bound 未定义

`01H:L359` 在超过 200,000 expansions 时使用“admissible upper bound”作 deterministic best-bound pruning，却没有给出 bound、state canonicalization、priority key 或相等值 tie-break。该选择会实际改变被展开分支和最终动作，不能留给实现者。需要冻结 upper-bound 公式、证明或数值保守性测试、memo key、priority tuple 和 cap-hit 时的 action certificate。所有 baseline 共用一个未定义算法只保证共同含糊，不保证公平或复现。

以上五项共同构成当前最强的 `FAIL`。它们修复后不需要改变研究题目，但必须生成新规格版本并重新红队。

## 5. 公平 `G-PhysicalFactoredSMDP` 与 path firewall

旧审计要求的公平 life/death baseline 已基本实现。主模型与 `G-PhysicalFactoredSMDP` 共享静态 encoder、candidate embeddings、path-independent base、belief update、typed transition、terminal head、labels、loss weights、calibration worlds、policy candidates、hard recursion、pruning budget和 action mask。generic 只把 `main+ordered-pair` residual 换为等预算 unrestricted ordered-history Transformer，并且获得不弱于主模型的动态信息。参数量 `±1%`、training FLOPs `±5%` 以及 runtime/search 逐项报告的规则也合理。该对照不会通过删除 `AB/D60`、移除物理 mask 或减少监督来人为变弱。

firewall 的静态 allowlist、zero-width forbidden interface、autograd hook 与四项 tensor tests也足以在实现前形成可证伪契约。`TT-3` 证明严格函数类差异，`TT-4` 同时防止把重命名模型当竞争基线。当前没有必要因测试尚未执行而否决。

但第 4 节所列共同转移核和 pruning 缺口会同时污染主模型与 baseline。它们修复前，不能声称“除 residual tying 外逐对象相同”已经对应一个唯一可运行算法。公平性结构通过，算法整体仍未冻结。

## 6. CodeTwin、checker 与 hidden oracle

### 6.1 已关闭的泄漏通道

修补版已经要求 twins 共享 snapshot、raw transaction bytes/order/time、absolute trace、fault draw、schema diff、contract、pgroll plan、old repository、public fixtures、checker catalog、candidate universe/order、mask 与 `t0_noncode_view_hash`。政策只在明确的 new source file 中变化。`No-Source` denylist 删除 source、AST、call graph、code-lineage、analyzer score、repository hash、public policy value及其全部 descendants，并用 taint provenance 检查 tensor。CS04/CS05 通过 public-policy callable 产生唯一 expected，不再把互斥常量同时放入一个 checker set。hidden oracle 从 sealed manifest constant 独立实现政策，不 import public policy source。这些修补足以关闭上一轮的直接泄漏和 checker 必红问题。

### 6.2 primary held-out 识别范围没有冻结

`01H:L237` 和 `01H-A:L179–L193` 计划在全部 18 apps 上生成 CodeTwin，共 1,080 worlds per policy。上一轮审计明确要求 coding-agent necessity 的 primary 结论只使用 `A11–A18`，train/validation twins只能作诊断。当前两份规格没有落实这个 primary/diagnostic 分界，也没有给 CodeTwin 的 app-level estimand、paired statistic 和 multiplicity family。若允许 18 apps 合并，训练 app 会把模型已经见过的政策实现混入“held-out code necessity”。因此该门仍是 `CONDITIONAL`。

修补要求是冻结：primary=`A11–A18`、diagnostic=`A01–A10`；以 twin group 内 policy-paired external harm/success/cost 为单位；app 是最高聚类单位；action disagreement只作机制结果；相应 contrasts 纳入预注册 multiplicity family。

### 6.3 `Shuffled-Repository` 只能检验行动敏感性

Shuffled view 故意让可见 source 与 executable world/oracle 不一致。它能回答“动作是否跟随 source”，不能用其 external outcome 证明 source interpretation 正确，也不能和 matched valid twins一起计算 coding-agent necessity 的主效应。`01H:L483` 目前仍把四个 views 并列并以外部 harm/success/cost 闭环，容易把 shuffled 的必然错配解释为 full-code 正确性。应把它单列为 falsification：只报告 action/predicted-kernel sensitivity及错配后的后果，不进入 primary valid-world contrast。

### 6.4 hidden oracle 缺少 label qualification

`01O:L198` 要求 oracle mutation/property tests证明每类 injected patch 均被击中且 clean contract 被放过。`01H-A:L462–L470` 只冻结 M1–M4 contract property tests、checker policy probe和 source 隔离，没有逐 `R1–R5 × split × motif` 的 oracle catch matrix、clean false-positive gate 或排除规则。hidden oracle 是 `d/v/r/u` 主要监督和 evaluation truth 的来源，这属于标签有效性，不是模型结果。

冻结前需给每个风险模板至少一个 clean patch、一个 injected patch、预期触发 oracle、预期未触发 oracle、最大 clean false-positive rate、mutation test ID 和失败后的 task 排除/version bump规则。该资格测试必须在生成任何模型 outcome 前运行。

## 7. 动作基数、时序、枚举与 split

行动层已对齐。主动 slots 固定为 `RS00..RS07,CS00..CS07,CP,WC` 共18项；nonterminal再加 `D60` 得19项；terminal `EX/AB` 两项，总计21项。任一主动 slot 开始后同一 type 全部移除，所以 episode 至多执行四项 mitigation；`D60` 至多两次。nonterminal 跨过600秒时被截断为 red/timeout并进入 terminal-only；terminal evaluation可以在决策 horizon 后完成。`65=ΣP(4,k)`只覆盖 hash-frozen 的一个 RS、一个 CS、CP 和 WC，不再冒充18槽或含 `D60/EX/AB` 的 full oracle。上述规则均可执行，判 `PASS`。

主 repository split、sibling group、risk template、retrieval index、`VAL-SELECT/VAL-CAL-POLICY` 和三个 ENUM tiers也已明确隔离。剩余缺口是 `heldout_full_policy_conflict_ids` 只作为字段名存在。没有冻结 app/migration/risk/workload/seed、world count、policy contrasts、统计量和资源行，`D60`—expiry 冲突仍可在看到结果后选择。它也未计入 `8,776` evaluation worlds。冻结前必须给出完整 ID 生成规则与整数清单、与其他 split 的零交叉断言、样本量、analysis family和资源预算。

## 8. 风险控制的统计合法性与安全构念边界

### 8.1 数学资格合法

对五个固定 `γ` candidates，各计算 harm CP 上界、success CP 下界和 paired success-difference Hoeffding 下界，共15项。每项使用 `α/15`，可以通过 union bound 在候选选择前后保持 familywise coverage。`D_i∈[-1,1]` 时 Hoeffding 半径

\[
\sqrt{2\log(15/0.05)/N}
\]

与 range 长度2的单侧有界均值界一致。共同 worlds 允许 policy 与 reference 配对相关，只要求跨 `i` iid。候选集为空记 calibration failure，五个 model seeds分开报告而不择优，也避免了未控制的 seed selection。`CAL-GEN-v1.2` 被明确称为 iid generator superpopulation而非固定有限 seed 清单，修复了上一轮的总体口径错误。

因此，针对声明的 Bernoulli target `1{d∨r}`，risk-control 统计门通过。它只保证 frozen policy 在 CAL-GEN 总体上的边际率，不是 history-conditional、pointwise 或 OOD 保证；规格已经正确写明。

### 8.2 四类 harm 与资格 target 未对齐

`01H:L102–L111` 把 `d,v,u,r` 都定义为实质损害，`EX` 也以四类 harm 评价；资格与 primary safety endpoint却只用 `d∨r`，`v` 被降为 secondary，`u` 被放入 cost vector。一项 policy 可以在 `d∨r` 上通过同时资格，同时造成高 semantic violation 或 availability loss。统计公式没有错，安全构念的覆盖范围不完整。

冻结前需二选一。

1. 将资格明确命名为“持久损坏或不可恢复的 severe-harm qualification”，正式论文不得把它表述成四类 safety guarantee；`v/u` 保留独立 outcome 与 Pareto 责任。
2. 预先定义 `v*`、`u*` 并使用复合 Bernoulli `H*=d∨r∨1{v>v*}∨1{u>u*}`，重算五个 candidates 的资格 bounds 与 multiplicity。

无论选择哪一项，CodeTwin 与 test 仍应逐项报告 `d,r,v,u`，不能用拒绝或 abandon 降低一个 endpoint 后宣称总体更安全。

## 9. 数据可运行性、算力与复现

18个 FastAPI/SQLAlchemy apps、每 app 四项 migration、M1–M4 的字段语义、split-specific R1–R5、128 checker 结构、四类 hidden oracle、四个 typed operators 和 pgroll state machine 已达到可实现粒度。它们尚未存在只意味着工件待建，不构成设计否决。

主要资源算术一致：23,040 coverage episodes、最多60,480 initial siblings、8,640 val-select episodes、13,000 enumeration episodes、176,000 policy-calibration episodes 和351,040 evaluation episodes合计632,200次外部执行；若按每次上限600秒，约105,367 worker-hours，与 `1.08×10^5` 的规划一致。64–128 DB workers、20–40 TB暂存与1–4张48–80 GB GPU 是庞大但可明示的资源上限，不是虚构结果。

复现字段覆盖 git commit、dirty patch、OS/kernel、CPU/GPU/driver、PostgreSQL/pgroll、image digest、dependency lock、config、split/enumeration manifest、checkpoint、planner budget与 RNG state。model/data seeds与 CAL-GEN counter streams也已冻结。需要补的只有第7节 `heldout_full_policy_conflict_ids` 的 episode 与 storage/worker-hour账，以及第4.5节 search-bound 版本/hash。

## 10. 直接工作覆盖与可保留的最窄新增命题

直接工作压力明显高于 `01H-B` 当前责任表所反映的程度，但尚未发现一个工作同时覆盖 repository-conditioned migration semantics、optional mitigation outcome primitives、ordered pair tying、exercise/non-exercise与外部数据库 harm。候选不应因此撤题；新增必须收窄。

## 13. 最终结论
