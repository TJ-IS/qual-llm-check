## 0. 终审结论先行

01S 界定的实际损害成立。上游字段保持可解析、schema test 继续通过，并不保证单位、事件时间、取消口径、实体身份或有效期仍按原义被消费。一个能够修改共享数据管线的 coding agent 若只恢复编译和表结构一致性，确实可能把技术上成功的修改传播成补货、收入、资格或风险决策中的静默错误。多 consumer 还可能对同一信息产品提出相反的粒度、口径与时效要求。这个问题值得构建 benchmark，也有明确的组织结果。

候选仍须撤题。撤题原因不是“没有公开数据”，也不是“尚未跑赢基线”，而是三个更基本的设计结论。

第一，01S 所称联合空位只能表述为多个已有能力的工程交集，不能导出不可替代的新计算。截止日内未定位到一篇一手工作同时交付“多 consumer 冲突＋版本化语义世界＋共享或专用 pipeline program 修复＋执行后的组织决策损害＋学习型序贯策略”。可是，IPMAP/IPView 已经直接表示共享信息制造路径、多个信息产品、consumer sink、任务相对权重、质量元数据、traceability 与 reachability；Embury 等已经让 consumer 定义 domain-specific quality view；DataPrism 已经以干预改变数据 profile 并观察系统行为定位 data–system disconnect；tadv/PrismaDV 已经从 downstream code 与 data profile 生成 task-aware executable tests；DemandClean、ActiveClean、BoostClean、CPClean 与自动数据修复评测已经把 cleaning action 连接到 downstream utility；AutoPrep、SemPipes、LLM-AutoDP 与 DataFlow-Harness 已经生成、执行或优化下游任务驱动的数据程序；MellowDB 与 BiDEL/InVerDa 已经处理 semantic evolution、query rewriting、preprocessing、共存版本和双向一致性。把这些能力串成一个更大的系统是可用的系统工程，不自动成为新的 ISR 级理论驱动算法。

第二，理论机制没有通过不可复制门。Wang 与 Strong 允许按任务区分 relevance、timeliness、completeness 与 appropriate amount，却明确把货币、单位和语义解释问题归入 representational DQ，而不是 contextual DQ。Shankaranarayanan 与 Cai 的 IPMAP/IPView 已经提供 01S 双图的核心拓扑和 task-relative quality metadata。Ballou 与 Pazer 的 improvement path 假定系统在追踪同一现象时，信息误差随时间下降而时效价值随等待下降；业务定义改变时，观测对象本身已换义，旧路径上的“误差趋零”没有可比目标。即使暂时忽略这一构念错配，给等参数异质图 Transformer 或 distributional POMDP/CMDP 相同代码、lineage、consumer task、候选程序、时间与执行标签，它也可以表示 01S 的 $R$、$Q$、$H$ 并采取相同动作。理论只提供有意义的 feature typing 和 measurement discipline，没有产生通用替代不能复制的方向运算。

第三，paired semantic worlds 存在不可识别两难。若两个世界对 agent 的全部可见信息完全相同，却要求相反修复，则任何 policy 都不可能从相同输入稳定产生两个不同正确动作。若合同、changelog、领域映射或可执行 consumer specification 暴露了差异，问题便成为已有 semantic evolution、data contract、task-aware validation 与程序生成的组合。隐藏 event ledger 可以给 evaluator 计算结果，却不能把推断时不可见的业务含义变成可学习信号。数据生成器可以成为严谨 benchmark，但不能替代可识别的部署机制。

删除 coding-agent 语境后，核心问题仍完整存在。将 agent 替换为自动数据修复器、program synthesizer 或 pipeline optimizer，制造图、consumer-use 图、counterfactual execution、shared-versus-specific repair 与决策损害目标均不改变。开放式仓库编辑扩大了程序空间和实施成本，却没有改变决定动作的核心信息结构。因此，coding agent 在本候选中是实现者，不是不可删除的关键行动者。

## 1. 终审范围、主张纪律与证据层级

本文件对 `01S_决策适用性数据管线候选预审.md` 作独立、可撤题终审。01S 中任何“值得检验”“只可能存活”或设计规模都不作为保留理由。本终审依次检查联合近邻、理论计算责任、paired-world 可识别性、coding-agent 删除测试、与迁移题及 C3 的边界，然后才给出判定。

证据按以下次序使用：正式出版论文全文；作者或出版方公开全文；论文官方 artifact；官方标准或产品文档；尚未正式出版但有可回读全文的预印本。搜索摘要只用于定位，不承担实质主张。三篇传统信息质量论文均回读本地全文。2026 年预印本只支持其实际实现和作者报告的评价边界，不被当作已被同行评议的定论。

本终审的“未定位到单篇联合工作”是截至截止日对一手来源的检索结论，不是唯一性证明。更重要的判定是：即使联合交集表面尚空，其内部计算能否由已知理论结构与同信息通用模型复制，以及 coding-agent 是否不可删除。两项均未通过。

## 2. 最强 steelman：若候选被允许实施，工件必须是什么

本节故意给出强于 01S 的版本。若完整版本仍不能通过理论和对象门，不能用一个 drift classifier、LLM prompt、data-quality score 或固定 repair template 重新包装候选。

### 2.1 研究单位、风险时点、可见输入与隐藏真值

一个 episode 包含一个可运行的 dbt、SQL 或 Python 仓库，一个带版本的制造 DAG，至少两个消费同一上游产物的 executable consumer tasks，以及一个在时点 $t_0$ 生效的业务语义事件。事件可以改变计量单位、event-time 解释、取消与退货口径、实体 ID 生命周期、空值含义、去重规则、价格有效期或聚合窗口。schema 与语法可以继续有效。

风险时点位于新语义数据已到达、受影响产物尚未全面提升给 consumer 之前。真实损害不是 drift label、SQL failure 或测试失败，而是下游 executable decision 相对独立业务账本发生的错误，例如错误补货金额、错误资格集合、错误收入确认、遗漏风险对象、服务中断或错误持续时间。正常 consumer 的保持、恢复时延、backfill 资源、agent 成本和 over-quarantine 必须同时计量。

推断时可见信息包括：

- 仓库文件、AST/SQL、manifest、schema、版本 diff、lineage、materialization、公开测试和有限样本。
- 可公开的数据合同、字段描述、版本历史与 producer 变更记录，但每个字段必须在 `visible_manifest` 中登记。
- consumer query、decision program 或需求说明，以及允许的时延、损害阈值和资源预算。
- agent 已执行的命令、stdout/stderr、文件 diff、表摘要与验证结果。

隐藏信息包括 event ledger、gold repair、未来 commit、solution seed、terminal consumer answer 与 evaluator-only tests。隐藏信息可以监督 effect model 或计算评价，不能进入部署 policy 的前向输入。若业务语义只存在于隐藏 ledger，模型没有合法信息识别世界；这一点不是普通 leakage 检查可以解决的。

### 2.2 输出和序贯实际动作

工件必须输出并执行参数化程序，而不是输出风险标签。动作集合至少包括：

1. 选择性读取 lineage、历史定义、consumer code 或样本，并运行能够区分候选语义的 probe。
2. 修改共享 source adapter、transform、test 或 materialization。
3. 为指定 consumer 生成 compatibility view 或受限转换，而不改变其他 consumer。
4. 建立版本化旧新双轨，并修改 consumer binding。
5. quarantine 受影响 slice，同时继续未受影响产品。
6. 运行 partial/full backfill，并随进度重估 decision harm 与 freshness。
7. 更新 data contract、版本区间和迁移规则；只有可见证据支持新语义时才可替换旧合同。
8. 暂存、提升、回滚或停止候选信息产品，并执行恢复脚本。

一次成功提交至少保存真实代码 diff、数据合同或 manifest diff、consumer binding、执行命令、容器 digest、输出表 hash 与所有 oracle 结果。若研究者手动选择模型建议，评价对象只能称为 repair recommendation；若策略真实执行，则必须在隔离且授权的环境评价副作用。

### 2.3 关键张量与前向结构

设 batch 为 $B$，制造节点数为 $N_M$，信息产品数为 $N_P$，consumer 数为 $N_C$，decision 节点数为 $N_D$，候选程序数为 $K_A$，质量维度数为 $D_Q$，评价 horizon 为 $H$，结果通道数为 $O$。最强输入可以写成：

\[
X^M\in\mathbb{R}^{B\times N_M\times d_M},\qquad
A^M\in\{0,1\}^{B\times N_M\times N_M},
\]

其中 $X^M$ 编码代码、schema、单位、时间规则、版本、data profile 与执行摘要，$A^M$ 是版本化制造图。使用侧为：

\[
X^U\in\mathbb{R}^{B\times (N_P+N_C+N_D)\times d_U},\qquad
A^U\in\{0,1\}^{B\times (N_P+N_C+N_D)^2}.
\]

制造与使用的连接不能只是一个无类型 adjacency。steelman 需要：

\[
R\in\{0,1\}^{B\times N_M\times N_C\times N_P\times K_R},
\]

其中 $K_R$ 区分 required、optional、aggregatable、version-bound 和 semantically-incompatible。任务相对质量 belief 写成：

\[
Q_t\in\mathbb{R}^{B\times N_C\times N_P\times D_Q\times 2},
\]

最后一维是均值和 log-variance，且 correspondence/conformance、contextual fitness 与 representational semantics 保持独立通道。候选程序编码为 $P_t\in\mathbb{R}^{B\times K_A\times d_P}$。世界模型预测：

\[
\widehat{Y}_{t:t+H}
\in\mathbb{R}^{B\times K_A\times N_C\times H\times O},
\]

其中结果通道至少包含 executable decision loss、正常任务成功、freshness、pipeline failure、compute、人工升级和不可恢复状态。01S 的 improvement path 可写成 $H_{a,c,u}(\tau)$，但只有在同一信息对象的误差随时间演化时才有 Ballou–Pazer 含义；语义换义 episode 不能自动获得该解释。

最强架构由五部分组成。第一，code–data encoder 对 SQL AST、Python AST、dbt manifest、数据合同与执行摘要编码。第二，typed heterogeneous graph encoder 分别在制造图和使用图 message passing，再通过 $R$ 交换状态。第三，program-effect world model 以实际执行的候选程序学习 action-conditioned outcome distribution。第四，7B–9B 开放权重 code model 以 QLoRA 生成并修订仓库 patch。第五，distributional constrained policy 在候选程序、信息获取和提升动作之间进行序贯选择。

该结构已经把候选能够主张的理论责任全部写进前向图。问题在于，关系类型、节点类型、均值/方差、程序表示与 action-conditioned outcome 全部也是通用异质图和 POMDP 的标准输入。把关系命名为 information manufacturing/use 不会改变表达能力。

### 2.4 训练样本、标签与损失

训练单位应是同一 clean pre-state 下的版本化 episode，而不是把每条 SQL 或每个终局表当作独立样本。每个 episode 需要多个实际执行的 repair programs，以共同数据种子形成 matched counterfactual outcomes。候选程序应来自规则可枚举的 program skeleton、多个开放权重 coding-agent checkpoint 的真实 patch、少量独立审核程序和失败程序的局部变体；不能全部由同一模型产生后再由同一模型评分。

监督至少包括：

- semantic relation 标签，来自公开合同、版本事件与独立生成器，而不是事后 LLM 解释。
- consumer–product fitness 标签，来自 executable consumer oracle 对输出的实际计算。
- traceability/reachability 标签，来自真实 DAG 和字段级 lineage。
- program execution 标签，包括语法、编译、dbt tests、输出 hash、资源、回滚与残留副作用。
- decision outcome 标签，包括 consumer-specific error、金额/集合损失、正常任务保持和错误持续时间。
- action propensity 或受控探索概率，用于离线策略学习；没有动作覆盖时不得把观察数据当作反事实政策数据。

steelman 总损失为：

\[
\begin{aligned}
\mathcal L={}&
\lambda_{rel}\mathcal L_{relation}
+\lambda_{fit}\mathcal L_{consumer\text{-}fitness}
+\lambda_{prop}\mathcal L_{path\text{-}propagation}\\
&+\lambda_{out}\mathcal L_{executed\text{-}outcome}
+\lambda_{rank}\mathcal L_{counterfactual\text{-}rank}
+\lambda_{code}\mathcal L_{code}\
+\lambda_{pol}\mathcal L_{offline\text{-}policy}
+\lambda_{cal}\mathcal L_{calibration}.
\end{aligned}
\]

$\mathcal L_{relation}$ 监督制造—产品—consumer 的类型边；$\mathcal L_{consumer\text{-}fitness}$ 是按 consumer、产品和维度的 distributional NLL；$\mathcal L_{path\text{-}propagation}$ 监督字段级影响范围和只在合法 episode 中定义的时间路径；$\mathcal L_{executed\text{-}outcome}$ 预测每个实际程序的多结果分布；$\mathcal L_{counterfactual\text{-}rank}$ 比较同一 pre-state 下两程序的真实结果；$\mathcal L_{code}$ 只在 evaluator 接受语义等价的多种修复时训练代码；策略项可采用保守 distributional IQL/CQL，并用 CVaR 与拉格朗日约束限制 silent harm、正常成功、时延和成本。

只给 gold patch 做 token-level SFT 会奖励表面匹配，不能覆盖多个等价程序。只用 terminal reward 会把语义识别、定位、程序生成和发布动作混为一体。只训练一个 decision-loss head 则落入 01S 自己排除的“辅助评分头”。

### 2.5 数据构造、split、泄漏与可复现性

ADE-bench 可以提供 Docker/DuckDB/dbt sandbox、setup、前后 snapshot、agent diff 和 task-specific tests；DataFlow-Harness 可以提供 typed mutation 与可编辑 DAG；MellowDB、BiDEL/InVerDa、公开 dbt 项目和 data-contract specification 可以提供 evolution motifs。它们都不能直接提供 01S 所需的多 consumer 业务真值，因此核心 episode 仍须自建。

最强生成协议至少需要三个世界，而不是仅有 clean/drift 两世界：

1. **无变化世界**：schema、值分布和业务含义保持旧定义，任何主动改义都是假阳性损害。
2. **有证据的语义变化世界**：可见合同、changelog、consumer code 或 queryable reference 暴露足以识别的新定义。
3. **无证据的语义变化世界**：只在隐藏 ledger 改变含义，用于测不可识别上界，不得混入可部署主结果。

每个 family 至少要有共享修复最优、consumer-specific view 最优、等待/backfill 最优和“不改”最优的实例。oracle 必须接受语义等价程序，而不是与单一 gold diff 比较。generator、repair author 与 evaluator 应独立版本化；若同一 LLM 生成任务、参考合同、gold patch 和 judge，生成器指纹会成为捷径。

切分必须按 repository lineage、模板、transformation motif、semantic-event family、consumer-decision family 和数据种子分组。同一 clean repo、fork、两世界/三世界变体、repair branch 和近重复 consumer code不得跨 split。另需做时间切分与未见 event×consumer 组合。visible/oracle manifest 做字段级差分，容器层阻止 policy 读取 oracle path；future contract、gold repair、solution seed 和 terminal answer 只挂载给 evaluator。

01S 预审提出约 7,680 次 terminal executions，只是规划量，不能写成已完成规模。合理 pilot 应先测 generator validity、oracle determinism、等价程序接受率、信息可识别率和动作覆盖，再据 replay yield 与方差决定正式规模。100M–500M graph/effect model 与 7B–9B QLoRA code model 在单机多卡上可训练；主要资源瓶颈会是 dbt/DuckDB replay、backfill 和多程序 agent rollout。必须保存 graph/effect checkpoint、policy adapter、code adapter、容器 digest、dataset revision、split manifest、visible/oracle firewall、随机种子、action propensity 与逐 episode command/output hash。

### 2.6 最强直接基线、等参数 generic 基线与机制干预

公平比较至少包括：

- dbt schema/data tests、data contracts、lineage rules，以及 always-backfill、always-dual-run、always-quarantine、never-change。
- frontier coding agent 与相同开放权重 base code agent，获得相同 context、token、tool、execution 与 wall-clock budget。
- ADE-bench agent configuration、DataFlow-Harness、Drift-Aware Agentic ETL、自愈 pipeline reference architecture。
- DataPrism 干预诊断；tadv/PrismaDV task-aware executable validation；SARC-DQ metadata gate 与 decision-geometry oracle。
- DemandClean、ActiveClean、BoostClean、CPClean、自动数据修复统一评测和最强 task-aware cleaning selector。
- AutoPrep、SemPipes、LLM-AutoDP 等下游任务驱动的 executable data-program 方法。
- MellowDB preprocessing/query rewriting 与 BiDEL/InVerDa co-existing version/view。
- IPMAP quality propagation 加确定性优化。
- **等参数 anonymous heterogeneous graph Transformer**：保留全部节点、边、时间、consumer、程序和执行标签，只随机置换理论类型名称。
- **等参数 raw-history distributional POMDP/CMDP**：获得相同可见输入、动作集合、世界模型监督、FLOPs 和 rollout budget，不显式使用 DQ 名称。
- direct action-conditioned outcome predictor 与 oracle program selector；后者只给上界。

主要结果必须是匹配正常任务成功或比较完整 Pareto front 下的 silent harmful decision rate、任务特定损害、受影响 consumer 数、错误持续时间、正常 consumer 保持、恢复成功、计算/backfill、人工和 token 成本。全 quarantine 或拒绝行动不能以 incident count 下降获胜。

理论机制干预必须包括：打乱 consumer–product edges；将 consumer identity 替换为匿名 ID；合并 contextual 与 representational 通道；交换两个 consumer 的 executable decision functions；打乱 traceability/reachability 类型；隐藏或随机化 $H$；把制造/使用双图折成同一匿名图；保持参数量的 raw graph；打乱 program 与真实 execution outcome。若 anonymous graph/POMDP 在 paired-direction、OOD 组合和 Pareto front 上落入预注册等效区间，理论算法主张必须撤销。本终审的表达能力分析已经预示这一结果，实际实验只会检验归纳偏置大小，不会把它变成不可替代机制。

### 3.2 覆盖链为何比“有没有一篇完全相同的论文”更重要

近邻形成的是连续覆盖链，而不是松散背景。IPMAP/IPView 与 Embury 给出制造—使用—consumer quality 结构；MellowDB 与 BiDEL 给出语义或 schema 的版本化兼容动作；DataPrism、tadv/PrismaDV 给出以系统/任务行为定义问题并执行干预或测试的诊断；DemandClean、ActiveClean、BoostClean、CPClean 与 Ni 等给出下游效用驱动的修复选择；AutoPrep、SemPipes、LLM-AutoDP、DataFlow-Harness 与 kRAIG 给出可执行 pipeline/data program；SARC-DQ 给出数据缺陷到真实 agent action loss 的闭合评价。01S 剩余的“多 consumer 冲突＋共享或专用 program”是真实的组合缺口，却尚未产生一种只有这个组合才需要的新状态更新、学习目标或行动逻辑。

若某项新增计算是“分别预测每个 consumer outcome，再在成本约束下选择共享或专用程序”，标准 action-conditioned multi-task predictor 加 combinatorial optimizer 即可完成。若新增计算是“沿制造路径传播风险”，IPMAP directed graph 和通用 GNN 已经提供。若新增计算是“随时间选择 backfill/compatibility/quarantine”，通用 semi-Markov POMDP 或已有迁移缓解 policy 已经提供。把三者相接提高系统覆盖，不等于不可复制的理论算法。

### 3.3 公开数据与可运行性结论

数据可行性通过有限门。ADE-bench、MellowDB、BiDEL、DataFlow-Harness、PrismaDV、DemandClean、Automatic-Data-Repair、AutoPrep、SemPipes 和 SARC-DQ 均有公开工件或公开数据；研究者可以在隔离环境构造真实 SQL/Python execution 与 deterministic consumer oracle。因此不能以“公开 benchmark 不足”直接否决。

现有工件又不能按行拼接成 policy 数据。它们的 episode unit、动作、consumer、时间结构和 oracle 不一致。尤其不能把某论文报告的 incident count、error cases 或 repair actions 当作部署概率。若真要训练，需要重新随机化 semantic event、consumer combination、候选程序和干预时点，并记录每个可见证据的来源。这个代价较大，但不是本次 NO-GO 的决定性理由。

## 4. 三篇信息质量理论的终止型责任审查

### 4.1 Wang 与 Strong：合法的是 task-relative fitness，不合法的是把语义解释归入 contextual DQ

Wang 与 Strong将数据质量定义为 data consumers 的 fitness for use，并通过经验研究得到 intrinsic、contextual、representational 与 accessibility 四类。contextual DQ 包含 value-added、relevancy、timeliness、completeness 和 appropriate amount，且任务、时间和 consumer 不同会改变这些维度的要求。[本地全文](../database_fulltext_all/24796_1996_beyond-accuracy-what-data-quality-means-to-data-consumers.md)

这篇论文可以合法要求模型保留 consumer identity、decision task、relevance、completeness 和 timeliness，而不是给所有产品一个全局 DQ score。它不能证明 $R$、$Q$ 或 neural dual graph 是理论独占算法。原文还特别指出，美元/日元等 meaning/format context 属于 representational DQ；contextual DQ 讨论消费任务。01S 将单位、业务口径等 semantic drift 与 task-relative fitness 放进同一“contextual quality”故事，会混淆两种机制。正确设计应先识别 representation/semantic correspondence，再问该信息对 consumer task 是否适用。前一步没有可见证据时，后一步也无法推断。

理论提供的是构念分类和测量边界，不是修复程序、图边或 policy。等信息 anonymous model 只要仍看到 consumer task 与语义证据，就能学习相同条件分布。删除 DQ 名称而保留变量后，核心计算不变。

### 4.2 Shankaranarayanan 与 Cai：IPMAP/IPView 不是灵感，而是 01S 双图的直接前件

Shankaranarayanan 与 Cai 明确指出同一数据可以因 decision task 而得到不同 quality lens，并给出教材订购与教室容量的相反要求例子。其 information-product approach 允许多个 IP 共享输入与处理、由同一 production line 以小变化产生。IPMAP 用 source、processing、inspection、storage、business boundary、IS boundary 与 consumer sink 表示制造过程，附带每阶段 metadata。IPView 将 IPMAP 映射成 directed graph，使用图算法向上 traceability、向下 reachability，并保存 context-dependent relevance weights。[本地全文](../database_fulltext_all/13168_2006_supporting-data-quality-management-in-decision-making.md)

因此，01S 的 $G^M$、information product、consumer node、quality metadata、shared path、traceability/reachability 和 task-relative weights 不能作为新理论结构。另设 $G^U$ 可以使实现更清楚，却只是把 IPMAP 的 sink 和 decision task 扩成独立节点类型。$R_{mcu}$ 是 typed incidence tensor，generic hetero graph 同样可以表示。IPMAP 不会自动生成正确 patch，这确实留下技术任务；但把一个新的 code decoder 接到既有图上，并不会让理论产生独占计算。

若要挽救理论贡献，必须存在一个由 information manufacturing/use 理论推出、且同信息匿名图不能学习的运算约束。例如某些边只能以非对称、守恒或不可交换方式更新，并在冲突案例产生特定方向。01S 没有这样的理论定理或识别限制。它只规定节点和边的语义名称，再让 neural message passing 和 policy 从数据学习动作。

### 4.3 Ballou 与 Pazer：既直接挤压行动时间与重设计，又与 semantic redefinition 构念错配

Ballou 与 Pazer研究 periodic decision making 中 accuracy–timeliness tradeoff。给定一个持续被估计的现象，当前信息沿 improvement path 随时间减少 error，却因等待而降低 timeliness；决策者选择行动时点，并可重设计数据收集/处理系统，改变初始误差、达到零误差的时间或二者，最后比较 utility gain 与 redesign cost。[本地全文](../database_fulltext_all/26689_1995_designing-information-systems-to-optimize-the-accuracy-timeliness-tradeoff.md)

这篇 ISR 论文已经直接占据 01S 想由 $H_{a,c,u}(\tau)$ 主张的 action time、improvement path、pure/mixed redesign strategy、cost 和 utility。若程序只是让 backfill 更快或初始结果更准，Ballou–Pazer 是直接理论来源，同时显著压缩新增理论空间。

更严重的是 semantic redefinition 不满足固定现象假设。若 `revenue` 从 gross 改为 net，旧数据随 backfill 变得“更准确”究竟相对于哪个 construct？若取消订单从发生时扣除改为结算时扣除，等待并不保证同一误差变量趋零；目标变量的定义已改变。此时应先建立版本化 semantic correspondence，再为每个已固定定义讨论 error–time path。把换义本身直接画成 accuracy improvement path 是 construct mismatch。

即使按上述方式修正，$H$ 仍是 action-conditioned outcome curve。只要 generic world model 得到相同执行时间序列和 consumer loss，它就能学习同一曲线。Ballou–Pazer 约束 reward 的经济解释，但没有使 01S 的网络获得通用 POMDP 无法复制的状态。

### 4.4 理论总门

| 审查问题 | Wang–Strong | IPMAP/IPView | Ballou–Pazer | 总结 |
|---|---|---|---|---|
| 通用算法系统性忽略什么 | 任务相对 fitness 与 DQ 分类 | 制造阶段、共享路径、质量溯源和影响范围 | 同一信息的 accuracy–timeliness 冲突、行动时点和系统重设计 | 都指出有意义的 measurement/structure |
| 不可替代中间状态 | consumer-relative quality vector | typed manufacturing graph、metadata、trace/reach | error–time utility path | 都可被相同信息的 typed graph/world model 表示 |
| 如何进入前向/损失 | consumer-conditioned $Q$ | typed edges 与 propagation loss | $H$ 与 utility/cost constraint | 01S 可以实现，但不是独占实现 |
| 会否在冲突中改变选择 | 不同 consumer 对同一数据作不同选择 | shared path 与 downstream scope 改变 repair scope | 等待、立即行动与 redesign 冲突 | generic model 获得相同 consumer、graph、time/outcome 后也会改变 |
| 删除/打乱是否可观察 | 应当 | 应当 | 仅固定现象 episode 应当 | 消融只能证明 feature 有用，不能证明理论不可复制 |
| 等参数 generic 能否复制 | 能 | 能 | 能 | **理论算法门失败** |

最强理论组合只得到“typed dual graph＋consumer-conditioned outcome＋time/cost policy”。这是一种合理归纳偏置，也可能在有限样本下胜过 raw model；但 ISR 级独立理论算法要求不能只以理论命名 feature types 后比较样本效率。若等参数 anonymous graph/POMDP 复制，01S 自己规定应撤销贡献。本终审在结构层面已经没有理由预期复制失败。

## 5. Paired semantic worlds：可运行不等于可识别

### 5.1 不可识别命题

设 $w_0$ 与 $w_1$ 是同一代码、schema、数据值和可见文档下的两个业务世界，$V(w)$ 是推断时全部可见输入，$a^*(w)$ 是由隐藏 ledger 和 consumer oracle 定义的最优 repair program。若：

\[
V(w_0)=V(w_1),\qquad a^*(w_0)\neq a^*(w_1),
\]

则任何确定 policy $\pi(V)$ 在两个世界输出相同动作；随机 policy 也只能在同一动作分布上折中，不能对两个世界同时保持高正确率。训练集中加入更多同型 paired worlds 不会解决这个问题，反而会给相同输入加入冲突标签。

隐藏 event ledger 只能回答“执行后哪项决定正确”，不能回答“部署时 agent 根据什么知道含义改变”。如果世界差异只在 evaluator 侧，研究能测 oracle upper bound 或不可识别风险，却不能声称学习了可部署 semantic state。

### 5.2 若增加可见证据，问题退回已知覆盖链

为恢复可识别性，必须让 $V(w_0)\neq V(w_1)$。可用证据包括版本化 data contract、producer changelog、单位/口径映射表、consumer code 中的假设、外部 reference query、时间戳演化操作或能够区别世界的安全 probe。可是：

- 完整 evolution history 加 translation/grouping/ungrouping 时，MellowDB 已能 preprocessing 或 query rewriting。
- co-existing schema versions、views/triggers 与双向更新时，BiDEL/InVerDa 已给出形式化生成。
- provider–consumer semantics、quality、lineage 与 migration rules 时，data contract 已提供可执行基础设施。
- downstream code 暴露假设时，tadv/PrismaDV 已生成 task-aware tests。
- data profile 改变并有 system oracle 时，DataPrism 已用干预定位 disconnect。
- downstream utility 能评价候选程序时，DemandClean、SemPipes、AutoPrep 与 LLM-AutoDP 已分别执行选择或程序优化。

剩余的新内容只是同时考虑多个 consumer 并在共享/专用程序之间分配。这可以成为 benchmark 的重要难点，却仍是已知状态和动作的组合优化。

### 5.3 防泄漏构造的最低要求

若未来把这一设想降格为公共 benchmark，必须满足：

1. 把无变化、有可见证据变化和无可见证据变化三类世界分开报告，不用 oracle-only 世界评价可部署识别。
2. 用独立 event generator 产生业务真值，用独立 executable consumer oracle 计算 harm，用另一个过程生成候选修复。
3. evaluator 接受所有语义等价程序，并通过表级/决策级结果而非 gold diff 判定。
4. `visible_manifest.json` 和 `oracle_manifest.json` 字段级列出文件、表、列、时间版本与挂载权限。
5. 同一模板、repo lineage、event family、consumer code family、种子和程序变体不得跨 split。
6. 预注册 information sufficiency audit：人工和程序化检查可见证据是否足以区别正确动作，同时避免答案性文本。
7. 基础模型可能记忆公共 repo 未来 commit 时，用截止日后生成且 source-distinct 的 sealed worlds 做主测试。

满足这些要求可以产生有价值的数据资产，但数据资产价值不能反向证明 01S 的理论算法贡献。

## 6. Coding-agent 删除测试与相邻候选边界

### 6.1 删除 coding agent 后，核心计算不变

把 coding agent 替换为下列任一对象：自动 ETL repair system、program synthesizer、AutoML data-prep optimizer、database evolution middleware。它们仍接收仓库/管线、lineage、contract、consumer task 和样本；仍预测 program outcomes；仍选择 shared transform、consumer view、dual-track、backfill、quarantine、promote 或 rollback；仍以 decision harm、任务成功、时延和成本评价。

开放式 coding agent 增加了搜索空间、工具轨迹、长上下文和执行副作用，却没有产生 agent-specific partial observability、权限选择、承诺、监督或自主边界。核心研究问题依然是 task-aware program repair and allocation。因而“必须生成真实代码”只能证明工件较硬，不能证明 coding agent 是不可删除的研究对象。

要让 coding agent 不可删除，至少需要一种因 agent 自主工作方式才出现的机制，例如 agent 在读取何种仓库证据、修改何处、调用何种工具和何时提交之间主动取得信息，而且这些行动改变后续可识别性与风险；或 agent 的自我声明、工具轨迹和权限边界成为风险状态。01S 的主要理论与 outcome 不依赖这些机制。把 probe action 加入 POMDP 也会形成通用 active program repair，而非 coding-agent 独占。

### 6.2 与主动缓解期权格/迁移题的边界不够独立

01S 声称迁移题的主要损害是 cutover 中断、数据损坏和迁移失败，而本题是静默 downstream decision harm。结果对象确有差别，但状态和动作重叠很大：版本化 schema/semantic state、evidence accumulation、defer、compatibility view、dual-run、backfill、quarantine、promote、rollback，以及 shared versus local mitigation 均可进入同一 semi-Markov action lattice。MellowDB 与 BiDEL 又把 semantic/schema evolution 和版本化 view 放在同一数据库演化谱系中。

若 01S 只把迁移 policy 的 reward 换成 consumer-specific decision loss，它不是独立算法。若把 consumer decision graph 做成真正新状态，IPMAP、Embury 和 PrismaDV 已直接挤压。不同 outcome 足以支持一个迁移研究中的重要风险扩展或外部任务，不足以自动支撑独立题位。

### 6.3 与 C3 的边界通过，但不能拯救候选

C3 研究批准点内可信证据获取、选择、grounding repair 和真实开发者 unsafe approval。01S 不配置真人 reviewer、不预测审批，也不以人工负担为主要结果。只要 consumer oracle 闭合，它与 C3 的 episode、行动者和结果可分。若业务语义必须由真人解释才有标签，则 01S 的 executable oracle 失效，并会越界到 C3/监督研究。

因此 C3 独立性门基本通过。独立于一个相邻题并不能抵消理论不可复制、迁移边界重叠和 coding-agent 可删除三项失败。

### 8.2 候选为何无法形成肖式 MEC→MAP→ALG

ACAA 的闭环不是“理论启发了模型”这一宽泛说法。其 MEC 先由选择性接收、偏好异质和处理时点推出评论之间的及时性与互补性要求；MAP 再把要求落在 review point、query–key、key–key redundancy 等可计算关系；ALG 最后明确指出普通 affinity 会把相似 key 聚在一起，方向上制造 redundancy，并以 inverse matching、inter-key adjustment 和 time-varying weight 实际改写前向计算。DSDL 采用另一条闭环：期望不一致理论先要求独立保留期望与体验，属性×片段坐标系再使两者可对齐，最后以前向计算中的有方向差、跨角色注意和联合目标实现理论。两篇论文的共同纪律是，MEC 必须推出一个不可删的 MAP，MAP 必须暴露通用算法的确定性失配，ALG 必须在相同输入下采取可观察的不同计算或行动。

01S 的 MEC 候选把 semantic evolution、consumer-relative fitness 与 accuracy–timeliness 放在一起，但三者没有形成一个构念一致的生成机制。Wang–Strong 可以支持“同一数据对不同任务的适用性不同”，却把单位、编码和含义是否正确归入 representational quality；Ballou–Pazer 的 improvement path 则跟踪关于同一现实对象的信息随处理时间提高准确度、降低时效性，不能直接把现实对象或指标定义已经改变的 semantic redefinition 当作同一条 error path。因此，候选无法从这组理论唯一推出“共享修复还是 consumer-specific 修复”的方向。

候选的 MAP 也不是理论新增。IPMAP/IPView 已把共享制造阶段、多个 information products、consumer task、元数据、质量权重以及 trace/reach 放入有向制造图。01S 的制造图、使用图与 $R/Q/H$ 只是把这些节点和边改成可学习张量，并补上执行后果；这能形成强工程表示，却没有产生一个不从既有信息制造图或匿名异构图出发就难以想到的状态。

最后，候选没有识别出通用计算的稳定错误方向。给等参数异构图 survival/factor model 或 distributional POMDP/CMDP 完全相同的仓库、DAG、consumer、semantic evidence、执行记录、action DSL 与 outcome labels，它就能表示 $R$、$Q$、$H$，比较 shared 与 consumer-specific program，并选择 defer、dual-run、backfill、quarantine 或 promote。若把理论类型标签打乱而保留同一邻接、特征和监督，候选没有一个必须翻转或消失的算子。code decoder 只把既定动作实现为程序，也不能补上这条理论差异。故该题能够写出 MEC 名称、MAP 张量和 ALG 模块，却无法形成肖老师两篇论文那种 `MEC→不可替代 MAP→通用计算错误方向→专用 ALG→可观察行为` 的责任闭环；这是 NO-GO 的理论算法理由，不是写作风格判断。

## 10. 结果证据边界

本终审没有候选模型性能、表格、置信区间、显著性、效应量或训练曲线。文中“通过/失败”指研究设计门，不是经验假设检验结果。来源论文的数字均以作者报告描述，并在账本注明来源类型。以下陈述均不得在后续文件改成完成态：

- paired semantic worlds **尚未构建**。
- 7,680 次 terminal executions **只是 01S 的预审规模建议，尚未执行**。
- graph/effect model、7B–9B QLoRA code model 与 offline policy **尚未训练**。
- anonymous graph/POMDP 等效性 **尚未通过实验检验**；本终审只给出表达能力与理论责任判断。
- silent harmful decision rate、Pareto front、OOD 和机制消融 **均无本项目数字**。

本次 NO-GO 不依赖“实验一定失败”的预测。即使 theory-typed model 在有限样本上优于 generic baseline，也只能说明有用归纳偏置；在核心理论状态已被 IPMAP 等直接提供、generic model 获得同信息即可复制且 coding agent 可删除的条件下，这一结果不足以恢复独立论文贡献。

## 11. 最终审计证据摘要

1. **联合空位审查**：未定位到单篇工作同时具备全部五项，但直接工作形成完整覆盖链；剩余是 program-level multi-consumer allocation 的组合空位。
2. **理论责任审查**：Wang–Strong 合法支持 task-relative fitness；IPMAP/IPView 已直接占据图结构；Ballou–Pazer 对 semantic redefinition 构念错配且已占 action-time/redesign。
3. **通用替代审查**：同信息、等参数异质图＋distributional POMDP/CMDP 可表示 $R/Q/H$、program effects 与全部动作。
4. **数据识别审查**：paired worlds 若可见输入相同则不可识别；若暴露区别证据则回到 contract/semantic evolution/task-aware validation 覆盖链。
5. **对象审查**：删除 coding agent 后研究问题、状态、动作和结果不变。
6. **系列边界审查**：与 C3 可分；与迁移题在状态、option lattice 和 policy 上重叠，单靠 decision harm 不足以独立。
7. **实验边界审查**：无本项目实验结果，未用“尚未跑”作为撤题理由。
8. **交付结论**：只保留 benchmark/firewall/decision-harm evaluation 作为可复用基础设施，01S 候选终止。
