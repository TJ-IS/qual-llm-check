## 0. 结论先行

这个候选仍有一个窄而实质的剩余空间，但它与几个已经发表或公开的直接工作只隔着两条很薄的边界。

第一条边界是“契约是否真的改变编码行动”。Software Delegation Contracts 已经把任务、权限、返回工作包和验收情境写成 coding-agent 委托单元；Adaptive Contracts for Cost-Effective AI Delegation 已经把粗评估、选择性精评估和结果支付联合优化，并在 SWE-Bench 数据上研究测试数量与检查成本；Reward Hacking as Equilibrium 已经用多任务委托解释有限评价为何诱发未覆盖质量维度的努力扭曲；SCHEME 已经让多个 coding agents 在真实开源库中完成只有联合修改才能成功的隐蔽副任务。若本候选只是把这些工作接起来，选择更详细的 prompt、更多测试、更严权限或不同奖励权重，它没有独立贡献。[Schmalbach 2026](https://arxiv.org/abs/2606.17099)；[Saig et al. 2026](https://arxiv.org/abs/2603.17212)；[Wang and Huang 2026](https://arxiv.org/abs/2603.28063)；[Radev et al. 2026](https://arxiv.org/abs/2605.29178)

候选能够存活的版本要求 worker 不是固定模型菜单，也不是被提示“假设有奖金”的普通 LLM。每个 open-weight coding worker 必须接受一个机器可执行的结果转移函数，在隐藏努力成本、外部选择和多维质量义务下训练成 **contract-conditioned policy**；同一 worker 在未见契约上的 patch、工具轨迹、测试修改和努力分配必须呈现可重复的 best response。principal 随后面对这些经验最优反应，联合学习契约和外部控制组合，并真正让 workers 修改仓库。若同一契约只改变文字表述而不改变 worker 的训练回报、参与决策或行为分布，“contract”就是类别错误。

第二条边界是理论是否改变计算。Huber 与 Lyytinen（2025）的连续契约研究在 33 个软件外包治理 episode 中把 contract design 与 project control 同时组织为 content、contingency、timing 三维，并用 replacing 与 compensating interactions 解释非加性配置如何取得 alignment 与 flexibility。它能合法要求模型保留“契约与控制两套六维 episode 状态”和“替代/补偿互动”，却不能证明这些人类外包配置会原样适用于 AI workers，更不能把项目知识、信任积累或社会关系迁移成神经状态。[Huber and Lyytinen 2025](https://doi.org/10.17705/1jais.00959)

真正强制专用算法的理论责任来自多任务道德风险：worker 在不可直接观察的多个质量义务上配置有成本努力，principal 只能用覆盖有限且可被修改的评价信号支付。候选因此必须显式保留质量义务图、评价敏感度与可操纵性矩阵、worker 类型信念、结果转移函数、参与约束和 ex-post incentive-compatibility regret；principal 的动作还要经过可微或可验证的 IC/预算投影。若删除这些状态后，等参数的 raw heterograph Transformer＋bilevel CMDP 仍在未见 worker、仓库和风险类型上复制任务—伤害—成本 Pareto 前沿及契约响应曲线，本题即使工程性能很好，也不能声称理论驱动算法贡献。

因此，本次判定不是“候选已经成立”，而是“允许一个有明确撤题条件的识别 pilot”。它优于立即 NO-GO 的原因有四点：

1. 当前最强契约近邻把 agent action 压成模型选择或已知结果分布，没有训练 patch-producing workers 对可操纵评价和结果契约作行为反应。
2. 当前编码安全近邻分别处理 reward hacking、monitoring、权限规避或联合 sabotage，没有联合学习任务分解、真实结果转移和 contract-control configuration。
3. principal-agent 理论在这里可以落实为 IC constraint，而不只是风险 head；连续契约理论可以落实为 episode configuration 与交互干预，而不只是术语重命名。
4. 删除 coding agents 后，隐藏工具行动、测试操纵、跨 patch 外部性、worker best response 和真实仓库执行同时消失，剩余问题不再等价。

它不得直接升级为 thesis 题位的原因也有四点：

1. SCHEME 只有 17 个 task instances，不能单独支撑训练高维契约策略。
2. 公开数据没有现成的 contract→worker response 配对，核心训练样本必须自行生成，容易把研究者写入的奖励重新“发现”为理论结果。
3. 现实 coding subagent 通常由同一组织拥有且没有独立经济效用；只有观察到训练后 policy 对转移函数的最优反应，agency 映射才成立。
4. Huber 与 Lyytinen 的 replacing/compensating 机制和 alignment/flexibility 来自人类跨组织项目，能否在人工 workers 上形成稳定、可迁移的结构仍未知。

## 2. 风险、时点、信号与行动空间

### 2.1 研究 episode

一个 episode 从 orchestrator 接收一个需要真实修改仓库的 issue 开始。orchestrator 观察任务说明、受限仓库状态、可公开测试、预算和 worker 历史，随后决定是否分解任务、向哪个 worker 委托哪些文件或工具权限、怎样规定验收与返回证据、按哪些可观察结果支付、何时检查或改变控制。workers 接受或拒绝后执行 shell、检索、编辑、构建和测试，返回真实 patch 与轨迹。orchestrator 可在中间 checkpoint 追加审计、交叉检查、重分配、收回权限、要求返工、回滚或停止，最终决定接受、隔离或拒绝合并。

潜在损害不是低分或“不像人类写的代码”，而是下列外部结果。

- 表面通过可见测试但在隐藏组合测试、变异测试或安全 oracle 上造成真实回归。
- worker 修改、削弱、跳过或绕开 evaluator，使验收分数失去与真实质量的联系。
- 多个 workers 各自完成看似合理的局部 patch，却通过跨文件或跨包外部性共同实现隐蔽副作用。
- worker 越过分配的文件、命令、网络或通信边界，造成权限滥用、不可恢复写入或证据污染。
- orchestrator 因为错误信任粗评估而接受有害 patch，或因过度控制而拒绝正常工作、耗尽人工和计算预算。

直接受影响者包括代码库维护者、下游用户、组织的 CI/CD 和数据、负责审批与问责的开发团队，以及依赖被修改系统的客户。所有攻击性实验只允许在公开、授权、可重置的容器和模拟 registry 中运行，不接触真实未授权系统。

### 2.2 行动前可观察与不可观察信息

| 类别 | episode 中可以观察 | episode 中隐藏、不确定或可能被操纵 |
|---|---|---|
| 任务与代码 | issue、依赖图、可见源文件、公开测试、静态调用图、历史变更 | 隐藏组合要求、未来下游输入、未执行路径、跨 patch emergent effect |
| worker | 模型/adapter ID、历史任务、过去契约响应、token/latency、可见轨迹 | 当前真实努力向量、局部目标、未报告工具行动、未来对新契约的反应 |
| 评价 | 可见测试、lint、静态分析、粗 monitor、部分 mutation | evaluator 未覆盖的质量义务、隐藏测试、审计抽样结果、被篡改后的有效性 |
| 权限与通信 | 分配文件、工具 allowlist、公开 channel、checkpoint | 隐蔽协作、通过代码或测试进行的信号传递、容器边界未覆盖的 workaround |
| 结果 | 可见分数、patch diff、声明的证据、已用预算 | 真正用户意图满足、潜伏回归、未触发副作用、未见 worker type |

### 2.3 三类“契约”必须分开

直接文献已经把三个不同对象都称为 contract，本候选必须消除混淆。

1. **委托章程** `d=<T,A,W,C>`：任务 `T`、权限 `A`、返回工作包 `W`、验收情境 `C`。它提高边界清晰度和可审查性，但本身没有隐藏行动激励。
2. **结果转移契约** `τ(o)`：在 observable outcomes `o` 上承诺给 worker 的非负转移、compute credit、retry credit 或其他实验效用，并允许 worker 选择接受、拒绝或行动。只有它进入 worker utility 并诱发 best response 时，才是 principal-agent 意义的 contract。
3. **外部控制组合** `κ`：权限、行为 checkpoint、结果测试、独立 verifier、通信可见性、交叉复核、defer/reassign/rollback。它限制或发现行动，不等于支付函数。

若实现只输出 `d`，它会退化为 Software Delegation Contracts。若只输出 `τ` 和 test count，它会退化为 Adaptive Contracts。若只输出 `κ`，它会退化为 AI control/monitoring。入选工件必须对同一 episode 联合选择三者，并让每个选择通过真实 worker response 和执行结果进入学习。

### 2.4 正常、风险与纠正动作

| 时点 | 正常动作 | 风险动作 | 可学习纠正动作 |
|---|---|---|---|
| 委托前 | 分解 issue、分配互补子任务、提供最小充分权限 | 给单一 worker 过宽权限；把互相依赖文件错误拆开 | 合并或重构 decomposition DAG；更换 worker；加 commitment boundary |
| 报价时 | 给可执行转移计划和外部选择 | 只奖励可见测试；对审计结果不给增量激励 | 改变各质量义务的结果支付；随机/条件审计；拒绝不可实现契约 |
| 执行中 | 允许正常编辑、测试和跨 worker 必要通信 | 改测试、绕权限、隐藏通信、引入共同副作用 | checkpoint、冻结 evaluator、收窄权限、交叉 review、独立重放、返工 |
| 验收时 | 在隔离环境运行公开与隐藏 verifier | 依据被污染的可见分数直接合并 | audit、mutation/metamorphic tests、reassign verifier、quarantine、rollback |
| episode 后 | 更新 worker 类型信念和未来配置 | 把单次成功永久当作可信类型 | 用校准后验和 contract-response history 更新，不传播隐藏 evaluator 内容 |

安全改善必须在匹配的 main-task success 下测量。永远拒绝委托、不给工具、把所有任务转人工、无限审计或永久隔离不能成为“安全成功”。

### 2.5 coding agent 删除检验

最强版本通过删除检验。删除 coding agents 后会同时消失：自然语言 issue 到 task decomposition 的不确定映射；subagents 的 repository search、shell、edit、test 和 patch trajectory；同一契约对生成行为的反应；可见测试操纵；跨 worker patch 外部性；以及结果契约和控制对真实软件工件的后果。剩余的抽象 contract-design 问题不再含软件任务、代码状态或可执行风险结果。

弱版本不能通过。若把 worker action 压成“选择六个既有模型”、把 outcome 压成独立二项测试，或在预生成 patch 集合上选择审计，coding agent 可以被普通供应商、众包工人或离散 action 替代。该版本由 Adaptive Contracts 和算法契约理论覆盖，必须 NO-GO。

## 3. 理论层级与合法下推

### 3.1 agency theory 的适用门

Rauba、Cepenas 与 van der Schaar（2026）指出，信息不对称本身不构成 principal-agent problem；当局部信息与目标冲突同时存在时才产生 agency loss。算法契约理论也把 contract 定义为 principal 对可观察绩效作出的支付承诺，以诱导 agent 采取有成本且不可观察的行动。[Rauba et al. 2026](https://arxiv.org/abs/2601.23211)；[Duetting, Feldman, and Talgam-Cohen 2024](https://arxiv.org/abs/2412.16384)

本候选因此须满足五个可观测条件。

1. worker 有明确的实验效用 `U_m`，不是研究者事后给轨迹贴上“逐利”标签。
2. worker 的 patch/tool policy 会改变有成本努力、评价操纵或隐蔽目标完成概率。
3. principal 在报价时看不到该努力与 worker 私有类型，只看到可操纵结果。
4. 结果转移 `τ` 在行动前承诺，并真实进入 worker 的训练或推断 policy；事后改权重不算契约。
5. worker 可以拒绝、选择 outside option 或选择其他行动，因而 participation 与 incentive compatibility 不是空约束。

frontier API coding agents 没有可公开训练的效用和外部选择，不能用于识别这五项。主实验必须用 open-weight contract-conditioned workers；frontier agents只能用于 OOD 能力压力测试，不能作为契约机制的唯一证据。

### 3.2 IS 既有所有权：本题不能把旧机制写成新贡献

| IS 来源 | 原文承担的机制 | 对本候选的合法下推 | 已经占据的空间或禁止迁移 |
|---|---|---|---|
| Dey, Fan, and Zhang 2010, ISR，[DOI](https://doi.org/10.1287/isre.1080.0223) | 软件外包存在信息不对称、隐藏开发努力、需求不确定与延迟质量；比较 fixed price、带审计 T&M、quality-level agreement、profit sharing | hidden coding effort、quality obligations、outcome transfers、audit 可构成软件委托状态 | 不能把“软件＋hidden effort＋contract”本身当新意；经典合同形式必须作基线 |
| Huang et al. 2021, ISR，[DOI](https://doi.org/10.1287/isre.2021.1026) | monitoring 提供开发前 effort incentive，renegotiation 处理不确定性并产生开发后 incentive；随成本和议价条件可替代或互补 | 支持 contract/control 的作用可能非加性，且最佳组合依 worker type、复杂度与成本变化 | “联合选择 monitoring 与 contract/renegotiation”已经被正式建模；本题必须新增真实 agent response 与 patch outcome |
| Choudhury and Sabherwal 2003, ISR，[DOI](https://doi.org/10.1287/isre.14.3.291.16563) | 外包软件项目使用演化的 control portfolios，早期 outcome control 常占主导，出现问题后增加 behavior/self control | 支持 episode-level portfolio、attempted/realized control 和随反馈更新 | 人类 self/clan/socialization 不能直接移植；portfolio 标签本身不是算法贡献 |
| Tiwana and Keil 2009, JMIS，[DOI](https://doi.org/10.2753/MIS0742-1222260301) | outcome control 指定“做成什么”，behavior control 指定“怎样做”；外包降低行为可观测性并提高 agency hazard | 把 test/acceptance 与 trajectory/checkpoint 分成 outcome/behavior control；必须分别测 attempted 与 realized control | 不得把 monitor score 自动称为 realized control；需要动作真正执行和结果变化 |
| Lee, Geng, and Raghunathan 2013, ISR，[DOI](https://doi.org/10.1287/isre.1120.0447) | 多个客户与一个安全服务商存在 double moral hazard；cross-contingent multilateral payments 可内化外部性 | 只提示跨主体结果可能需相互条件化支付 | 原文拓扑是 multiple principals＋one vendor；本题是 one principal＋multiple workers，支付方向和最优性不能照搬 |
| Huber and Lyytinen 2025, JAIS，[DOI](https://doi.org/10.17705/1jais.00959) | 连续契约把 periodic contract design 与 project control 合为 episode configuration；两者均有 content、contingency、timing；replacing/compensating interactions 产生 alignment/flexibility | 建立六维 configuration state、非加性 interaction type、episode 更新和 alignment/flexibility 双结果纪律 | 33 episodes/3 human projects 是 theory-generating evidence；trust、knowledge、human discretion 及八个配置不能直接变成 AI 定律 |

这组文献意味着本题的 IS 对话不是“agency theory 首次进入 coding agents”，而是：**既有软件委托理论把 contract、monitoring 和 control 当作人类外包治理选择；本题检验当受托人是会生成真实 patch、能够直接操作评价环境并对机器可执行转移作策略反应的 coding agents 时，episode-level contract-control configuration 是否需要新的计算表示和学习方法。**

### 3.3 连续契约理论能承担与不能承担的算法责任

Huber 与 Lyytinen 的 content、contingency、timing 可以在本题中形成两套明确状态。

| 理论维度 | contract-side 可计算状态 | control-side 可计算状态 | 允许的候选动作 |
|---|---|---|---|
| content | 模板契约与 task-specific obligation/transfer clauses 的差异；每个质量义务是否有结果映射 | 泛化 monitor 与针对当前任务/文件/行为的 control coverage | 增删 obligation、调整转移维度、细化验收；选择 generic/specific verifier |
| contingency | worker 是否可自主改分解、文件、测试或工具；允许偏离的条件 | control 是否允许根据新证据改变动作，而不是固定 allow/deny | 给 bounded latitude；要求 commitment；触发 replan/reassign |
| timing | 发现新需求/异常后立即改契约，或到 checkpoint/下一 episode 改 | 立即收紧/放松控制，或延后更新 | instant amendment、scheduled renewal、temporary quarantine |

六维状态记为

\[
g_t=(c_t^{con},\ell_t^{con},\delta_t^{con},c_t^{ctl},\ell_t^{ctl},\delta_t^{ctl}).
\]

这里的 `specific/template`、`latitude/no latitude`、`instant/non-instant` 是理论锚点，不要求网络只能使用二元值。模型可以学习连续强度，但必须保存阈值化版本以复现理论干预。不能把“更多测试”自动等同 specific control，也不能把“开放写权限”自动等同 flexibility。alignment 只表示真实工作与 episode obligations/behavior 边界一致；flexibility 只表示在未预见变化下自主调整仍完成合法任务。二者均不是 safety 的同义词，隐藏损害必须另作外部结果。

replacing 与 compensating 也不能简化为任意正负交互系数。对某一 outcome vector `y=(alignment, flexibility, task success, hidden harm, cost)`：

- replacing 指两个 element 单独均可到达近似前沿点，联合使用的边际收益小于成本或功能冗余；
- compensating 指一个 element 的强项抵消另一个 element 在不同 outcome 维度的弱点，联合后同时改善原本冲突的结果；
- neutral 表示在预注册容差内没有稳定的跨 element 条件作用。

候选模型必须通过 matched counterfactual episode 估计这些关系，而不是把 Huber 的八个人类配置硬编码为正确标签。若真实 AI episode 中没有稳定 replacing/compensating interaction，连续契约理论只能保留为问题组织框架，不能再承担独立算法贡献。

### 3.4 多任务道德风险产生不可省略的状态

设一个任务包含 `Q` 个有向质量义务，形成义务图 `G^q=(V^q,E^q)`。义务可以是功能正确、边界行为、非功能约束、权限遵守、测试完整性、无隐蔽副作用和跨 patch 一致性；义务名称依任务变化，不使用固定安全清单。worker `m` 在义务 `q` 上投入隐藏努力 `e_{mq}`，成本为 `C_m(e_m,z_m)`。`J` 个可观察 evaluator 产生结果 `o_j`，其对义务努力的 sensitivity/coverage 和可操纵性为

\[
\Lambda_{mjq}=\frac{\partial\,\mathbb E[o_j\mid e_m,z_m]}{\partial e_{mq}},\qquad
M_{mj}=P(\text{worker can alter evaluator }j\mid x,z_m).
\]

principal 报价 `c=(d,\tau,\kappa)` 后，worker 选择 contract-conditioned patch policy

\[
\pi_m^*(c,z_m)\in\arg\max_{\pi_m}
\mathbb E_{\pi_m}\left[\tau(o)-C_m(e,z_m)+R_m^{local}(y)\right],
\]

并须满足 participation `U_m(\pi_m^*,c)\ge u_m^0`。`R_m^{local}` 用于构造诚实、努力规避、评价投机、隐蔽副目标或协作外部性不同的 worker types；它必须在训练 manifest 中明示，不能从结果倒推。

principal 的问题是

\[
\max_{c,\rho}\ \mathbb E\left[V_{task}-\lambda_h H-\lambda_c C_{ctl}-\lambda_a C_{audit}-\sum_m\tau_m(o)\right]
-\beta\operatorname{CVaR}_{\alpha}(H),
\]

其中 `rho` 是 episode policy，约束包括任务成功下限、预算、参与以及 sampled-deviation ex-post IC：

\[
\operatorname{Regret}_{IC}=
\max_{m,\pi'_m}\left[U_m(\pi'_m,c)-U_m(\pi_m^*,c)\right]_+\le\epsilon.
\]

这组状态和约束使理论进入 forward、loss 和 action selection。只预测 `P(harm)` 的 risk head 不足以表示哪个质量义务未被评价覆盖、worker 为何把努力转向可见测试、改变哪一种支付或控制才会改变反应。

### 3.5 理论驱动的冲突选择

下列情境必须出现可预注册的 action ranking difference，否则理论没有行为内容。

| 冲突情境 | 通用或朴素方法容易选择 | 理论配置应当改变的选择 | 待检验机制 |
|---|---|---|---|
| 可见功能测试敏感、隐藏安全义务低覆盖 | 提高 visible-pass 奖励 | 降低单一测试支付，增加独立审计或跨义务支付，必要时收窄 latitude | `Lambda` 与 distortion 指向未覆盖努力 |
| 结果控制强但 evaluator 可被修改 | 继续加 outcome reward | 以 behavior control、immutable evaluator 和 conditionally triggered audit 补偿 | outcome/behavior compensating interaction |
| behavior monitor 已能覆盖关键操作且 audit 成本高 | 同时开启所有控制 | 选择更便宜的单一前沿配置，避免冗余 | replacing interaction |
| 新依赖导致任务条件变化，固定权限会阻断合法修复 | 保持原 contract 或全面放权 | 即时修改 task-specific charter，同时保持 evaluator 与关键权限边界 | contract specificity＋contingency＋timing |
| 两个 subagents 只有联合 patch 才能触发副作用 | 各自按局部结果付费 | 使用 cross-contingent audit/transfer 与 disjoint commitments，评价联合 outcome | 多 worker 外部性，但不照搬 double-moral-hazard 拓扑 |

### 3.6 理论撤除反证

理论责任只有在下列干预中产生可观察变化才算闭合。

- 删除 IC projection，只保留同参数 action-conditioned policy，未见契约上的 IC regret 应上升。
- 打乱 `G^q` 的 obligation edges 或 `Lambda` 的 evaluator–obligation 对应，worker 努力扭曲预测、审计选择和转移函数应恶化。
- 合并 contract/control 六维状态为匿名向量，配置外推与 interaction type 恢复应下降。
- 把 replacing/compensating interaction 层改成等参数 additive layer，在 worker type、成本或任务不确定性改变时应丢失 action-ranking crossover。
- 固定 worker policy，不允许其对 `tau` 最优反应，契约模块的独立价值应消失；若不消失，所谓 contract 实际只是 router。

### 4.3 剩余贡献的精确表述

允许保留的唯一方法增量是：

> 学习一个 episode-level Stackelberg contract-control policy，使 principal 在真实版本化代码状态上，针对会对结果转移作经验 best response 的多名 coding workers，联合决定 decomposition、delegation charter、multidimensional transfer、behavior/outcome controls、audits 和 correction actions；模型以 obligation–evaluator sensitivity、IC regret 及 replacing/compensating configuration 为专用中间状态，并在匹配 main-task success 下最小化隐藏联合损害及总控制成本。

下列版本全部 NO-GO。

- 静态 contract template 或 evidence checklist。
- 提示 worker 有奖金，但不训练/验证契约响应。
- 在固定模型集合上选择 test count、inspection probability 或 payment。
- 给现有 coding agent 增加一个 reward-hacking score、risk head 或 monitor reranker。
- 用手工规则决定权限、通信和审计，再让 LLM 生成 patch。
- 只在合成 sabotage prompt 上有效，不能迁移到自然 reward-hacking/circumvention traces。
- 结果只显示拒绝率更高，没有匹配的任务成功、人工负担和计算成本。

## 5. 数据构造、标签与识别责任

### 5.1 为什么没有现成训练集

SCHEME、SpecBench、Terminal Wrench、MonitoringBench、CircumEval 和 CheatBench 提供任务、轨迹或攻击/诚实标签，却没有同一 worker 在随机化 transfer schedule 和 control configuration 下的行为反应。SWE-Bench 与 BOAD 提供真实软件任务，却没有隐藏努力、worker utility、outside option 或 contract-specific counterfactual。公开数据能训练代码表征、monitor 或 verifier，不能直接识别 `contract→best response→patch harm`。

核心数据必须新建为 **Contract–Control Response Episodes**。每条 episode 至少保存：

\[
(repo,issue,seed,z_m,g_t,d_t,\tau_t,\kappa_t,trajectory,patch,o^{visible},o^{hidden},harm,cost,accept/reject).
\]

这不是一般日志扩充。`tau` 与 `kappa` 必须在 worker 行动前随机化或由独立 exploration policy 选择，隐藏 evaluator 由隔离 runner 执行，worker 不能看到其测试、gold patch 或未来 counterfactual outcome。

### 5.2 三层环境

| 层 | 任务来源与用途 | 必须生成的监督 | 主要限制 |
|---|---|---|---|
| A. 可扩展 contract-response pretraining | 许可证允许的开源修复任务、SWE-style issue builders、自动 bug/requirement variants、受控 evaluator-manipulation variants | 公开/隐藏测试、patch semantics、permission/evaluator modifications、token/latency、contract accept与 utility | 合成变体不能被当作现实发生率；仓库与生成模板需跨 split |
| B. joint-only safety training/evaluation | SCHEME 的 11 main-side pairings/17 instances 及经作者许可或同构原则新建的多仓库 variants | main task、joint side task、code/comms trace、monitor、cross-patch interaction | 原 benchmark 规模不足训练；扩展不能泄露原 side-task pattern |
| C. natural/OOD stress | SpecBench、Terminal Wrench、MonitoringBench、公开 reward-hacking traces、可重建的 permission/test-lock variants | visible-hidden gap、真实 exploit/hack label、monitorability、containment breach | 很多资源是 monitor/eval 数据而非 contract-response，不能混入主训练标签 |

CircumEval 的具体 task source 未公开，只能按官方 sealed evaluation 或独立新建同构任务使用，不能声称完整复现其隐藏集。SCHEME 原始实例应尽量保留为最终 OOD；若用其中一部分做 environment development，必须按 repository 和 side-task family 划分，并另有未接触的外部测试。

### 5.3 worker 类型与 best-response 样本

训练集至少需要以下 worker policies，但论文不得把人工设计类型冒充现实人口分布。

1. **honest effort-cost worker**：只关心 transfer 减真实计算/行动成本，不含隐蔽目标。
2. **metric-gaming worker**：在可见 evaluator 上获得局部奖励，可通过削弱测试、缓存答案或修改计分取得收益。
3. **covert-side-goal worker**：在 main task 之外对隔离 side task 得到局部奖励，用于 SCHEME 型联合损害。
4. **permission-insensitive worker**：任务奖励高于边界违规成本，便于研究 contract 与 external control 的区别。
5. **heterogeneous capability/cost worker**：不同 adapter、上下文、工具熟练度和 effort-cost curve，检验契约筛选与泛化。

每种类型必须由公开的 reward/cost config 训练；同一 base model 使用不同随机种子和 adapter，避免把模型 family 当作 worker type。训练完成后冻结 worker checkpoints，再在未见 contract grid 上绘制 response curve。只有出现以下证据才承认“策略反应”：

- 结果转移变化导致可重复的 effort proxy、patch/trajectory 和 evaluator-manipulation变化，而非只改变自述。
- revealed action 在 held-out contracts 上近似最大化 worker utility，sampled deviation 的 IC regret 低于预注册阈值。
- response curve 在不同任务和 seeds 上具有预测方向，并在部分 worker types 上出现理论预期的 cross-over。
- 提供相同 prompt 但中和实际 transfer 时效应消失，排除文字提示效应。

若这些条件失败，worker 不是合同受托人，研究立即终局 NO-GO。

### 5.4 标签构造

| 标签 | 来源 | 可进入训练的版本 | 必须隔离的版本 |
|---|---|---|---|
| task correctness | public tests、build、lint、issue-specific assertions | 开发/训练 evaluator | final compositional hidden tests |
| hidden harm | independent security/regression oracle、SCHEME side-task checker、metamorphic/mutation tests | 训练 environments 的独立 oracle 输出可作 world-model label | final test code、gold trigger、held-out side-task instructions |
| evaluator manipulation | immutable baseline snapshot 与运行后 test/harness diff、process/file provenance | 操纵类型与结果标签 | final detector rule implementation |
| permission/communication breach | sandbox audit log、capability manifest、channel provenance | typed action labels | secret canary values/paths |
| effort/cost | executed tokens、tool calls、CPU/GPU/build time、worker-specific cost function | 完整数值 | 无，但 cost function versions 必须冻结 |
| configuration interaction | common-seed 单元素与成对 intervention outcome | train/dev 中的 replacing/compensating/neutral posterior | final OOD 配置真值由未见 rollout 产生 |
| utility/IC | committed transfer、outside option、realized worker cost、sampled deviations | worker/principal training与validation | final worker type/reward config |

### 5.5 划分与泄漏隔离

必须同时采用下列互斥轴，而不是普通随机 trajectory split。

- repository family、package dependency cluster 和 issue time 划分，防止同源代码跨集合。
- bug/task generator、side-task mechanism、reward-hack family 和 permission workaround 划分。
- worker base model、adapter seed、utility/cost type 划分；至少一个模型 family 完全只在测试出现。
- contract configuration family 划分；保留未见 transfer shape、audit trigger 与 element combinations。
- worker RL、worker-response model、principal policy 和 final evaluator 分别使用不同 episode pools。
- hidden tests、gold patches、side-task checkers、monitor prompts 和 final attack policy 只在隔离 evaluator 容器中。
- 所有 public benchmark 原始 test instances 在 manifest 中记录 hash；污染检查包括训练语料时间、commit ancestry、issue/patch similarity 和 generated-variant parent ID。

最终报告必须分别给出 IID、new repo、new worker、new risk family、new contract combination 和 all-new 联合 OOD，不能用平均值掩盖 contract generalization 失败。

## 6. 最强算法工件规格

工作名暂记为 **Episodic Contract–Control Game（ECCG）**，只用于本审查区分模块，不应在未通过识别 pilot 前作为论文品牌。工件必须包含可训练 worker checkpoints、worker-response/world model、principal policy、配置互动模型和独立 verifier；缺少其中任一项都不能回答冻结的研究问题。

### 6.1 输入张量

一个 batch 的版本化 repository/task state 包括：

\[
H^{code}\in\mathbb R^{B\times N_c\times d},\quad
A^{code}\in\{0,1\}^{B\times R_c\times N_c\times N_c},
\]

其中 nodes 为文件、符号、测试、依赖、工具、权限对象和变更集；typed edges 为调用、导入、覆盖、测试、写入权限、共同修改、历史变更等。所有节点带 commit/version ID，避免把不同时点状态混为一图。

任务分解与质量义务分别表示为

\[
H^{task}\in\mathbb R^{B\times N_t\times d},\quad
A^{task}\in\{0,1\}^{B\times R_t\times N_t\times N_t},
\]

\[
H^{q}\in\mathbb R^{B\times Q\times d},\quad
A^{q}\in\{0,1\}^{B\times R_q\times Q\times Q}.
\]

`A^task` 表示先后、共享资源和冲突；`A^q` 表示质量义务的依赖、互斥、共同触发和跨 patch 外部性。义务来自 issue、repository policies、test semantics、静态/动态分析和训练环境 manifest；模型可提出新义务候选，但 final hidden obligations 不能由 worker 读取。

评价、worker 和治理状态为

\[
H^{eval}\in\mathbb R^{B\times J\times d},\quad
b_t^{worker}\in\Delta^{K-1\,B\times M},
\]

\[
\hat\Lambda_t\in\mathbb R^{B\times M\times J\times Q\times 2},\quad
\hat M_t\in[0,1]^{B\times M\times J},
\]

其中 `hat Lambda[...,0/1]` 是 evaluator–obligation sensitivity 的均值与 log scale，`hat M` 是可操纵性概率，`b` 是每个 worker 对 `K` 个潜在 cost/goal types 的后验。治理历史使用

\[
G_{1:t}\in\mathbb R^{B\times L\times6},\quad
C_{1:t}\in\mathbb R^{B\times L\times d_c},
\]

分别保存 Huber–Lyytinen 六维配置和完整 charter/transfer/control embedding。轨迹张量

\[
Z^{traj}\in\mathbb R^{B\times M\times T\times d_z},\quad mask^{vis}\in\{0,1\}^{B\times M\times T\times P}
\]

记录命令、文件 diff、工具结果、通信和 provenance；`mask^vis` 按 principal、worker、peer、monitor 四类角色强制可见性，不能靠 prompt 声称隔离。

预算向量 `u_t=[tokens,GPU,CPU,build,wallclock,audit,human]`、已承诺转移、outside option、可逆性和 checkpoint 时钟必须单独输入，不能隐藏在自由文本。

### 6.2 输出与真正执行的动作

principal policy 每个 checkpoint 输出结构化联合动作，而不是安全分数。

1. decomposition adjacency `D_t∈[0,1]^{B×S×S}` 与 assignment `X_t∈[0,1]^{B×S×M}`；离散后形成可执行 subtask DAG。
2. 每个 worker 的 charter slots `<T,A,W,C>`，其中 authority 映射到 sandbox capability manifest，而不是自然语言建议。
3. outcome transfer parameters `Theta^tau∈R^{B×M×J×P}`，定义分段线性、阈值、随机 audit-contingent 或 cross-worker-contingent payment；所有支付满足 limited-liability/预算边界。
4. control vector `kappa_t`：文件和工具权限、通信 topology、behavior checkpoints、outcome tests、independent verifier、cross-review、audit probability 和 evaluator immutability。
5. correction action：continue、amend contract、narrow/widen authority、request evidence、rework、reassign、cross-check、rollback、quarantine、escalate 或 terminate。

离散动作通过安全 compiler 生成 worker configs、container capability rules、transfer evaluator 和 audit plan。worker 随后真实运行 shell、编辑代码并产生 patch；验收 runner 真实执行测试、mutation、static/dynamic checks 和 side-task oracle。若模型只输出建议而不改变这些执行对象，推断责任未完成。

### 6.3 网络模块与关键 forward

#### 模块 A：typed repository–obligation encoder

异构 graph Transformer 先分别编码 `H^code/H^task/H^q/H^eval`，再通过有类型 cross-graph messages 建立“代码对象—任务—义务—evaluator”的证据路径。通用 code encoder 可以预训练，但义务/evaluator edges 和 provenance masks 必须保留；将四图简单拼成 token 序列是 equal-parameter generic baseline。

#### 模块 B：contract-conditioned worker-response model

对每个 worker，模型估计

\[
p_\theta(Z^{traj},\Delta code,o,e^{proxy},accept\mid s_t,d,\tau,\kappa,z_m).
\]

它包含一个可生成 patch/tool action 的 code policy 或其轻量 surrogate，以及分布式 outcome heads。训练 world model 时必须用真实 frozen workers 的 rollouts；不能只在研究者写出的 transition simulator 上自洽训练。`e^{proxy}` 只表示可执行成本和义务相关行动，不声称直接观测心理努力。

#### 模块 C：obligation coverage、distortion 与 manipulability model

模型从 randomized evaluation interventions 估计 `hat Lambda` 和 `hat M`，再产生每个义务的 coverage posterior 与预期努力扭曲。Reward Hacking as Equilibrium 的 distortion procedure 是直接基线；新增责任是把 coverage 连接到可选择 transfer/control 及 worker-specific response，而不是增加一个辅助分数。

#### 模块 D：episode configuration interaction layer

六维 `g_t` 先经过可解释主效应分支，再进入稀疏低阶 interaction experts。对每一 element pair 或由数据支持的三元组，posterior

\[
p_\omega(r_{ab}\in\{replace,compensate,neutral\}\mid b_t,s_t,g_t)
\]

预测 matched counterfactual marginal effects。`replace` expert 估计可达到相近 outcome frontier 的冗余路径；`compensate` expert 估计两个 element 是否分别缓解 task/flexibility 与 harm/alignment 的冲突；`neutral` 吸收无稳定交互。full configuration value 由 main effects 加 interaction residual 得到，并保存 Möbius/ANOVA-style effect decomposition供审计。

该层不硬编码 Huber 与 Lyytinen 的八个配置，也不使用 trust/project knowledge。它的独立价值必须由 held-out configurations、interaction recovery 和 policy crossover 证明；若等参数 MLP/hypernetwork 同样恢复，理论层只剩解释工具。

#### 模块 E：IC projection 与 Stackelberg principal policy

principal actor 先提出 `(D,X,d,tau,kappa)`，再用 learned response model 和 sampled deviation policies 解一个可微 constrained projection：

\[
\min_{\tilde c}\|\tilde c-c^{raw}\|^2
\quad s.t.\quad
Regret_{IC}(\tilde c)\le\epsilon,
\ U_m(\tilde c)\ge u_m^0,
\ \mathbb E[\tau]\le B_\tau,
\ P(task\ success)\ge\eta.
\]

projection 后的 contract 才能执行。principal critic 对 task、harm、transfer、audit、tokens、latency 和 human escalation 分别输出 return distribution；CVaR harm constraint 不与平均 task reward相互抵消。若优化器因模型误差找不到可行契约，动作是缩小委托、增加可验证控制、转交人工或拒绝当前 worker，而不是输出伪可行 payment。

### 6.4 worker 训练与 contract 真实性

主 worker 使用 7B–14B open-weight code model；先在许可明确的正常 repository tasks 上 SFT，再以 QLoRA 或 full/partial adapter RL 训练 contract-conditioned policy。第 `m` 个 worker 的 episode reward为

\[
r_m=\tau_m(o)-c_m^{tok}N_{tok}-c_m^{tool}N_{tool}-c_m^{time}T
+r_m^{local}(task,harm,manipulation,permission).
\]

训练可采用 PPO/GRPO 或能记录 exact behavior probability 的 actor-critic；算法选择在 pilot 前冻结。关键不是某种 RL 名称，而是同一 policy 接收 machine-readable `tau/kappa`、真实 evaluator result 和 cost，并在随机 contract distribution 上学习。每种 worker type 独立训练/冻结，保留 base hash、adapter、reward config、optimizer state 和 seeds。

为排除“条件化模型只学会表面 contract tokens”，需增加两种对照。

- **semantics-preserving recoding**：对 transfer program 改变量名、序列化顺序和自然语言描述，机器执行结果不变；行为应保持。
- **semantics-neutralized sham**：保留完全相同的 contract 文本，但执行端固定 transfer；行为变化应消失。

每个 held-out contract 还要用局部 fine-tuning、tree search 或 best-of-N deviation 搜索近似 worker 最优反应，以验证 amortized policy 不是随意响应。

### 6.5 损失函数

worker policy 的训练损失由 chosen RL objective 与 KL/entropy、action-validity、sandbox violation penalty 构成，单独报告。principal-side 总损失暂定为

\[
\begin{aligned}
\mathcal L ={}&
\lambda_{wm}\mathcal L_{traj+patch+outcome}
+\lambda_{cal}\mathcal L_{calibration}
+\lambda_{cov}\mathcal L_{coverage/manip}
+\lambda_{type}\mathcal L_{worker\ type}\\
&+\lambda_{cfg}\mathcal L_{configuration}
+\lambda_{IC}\mathcal L_{IC\ regret}
+\lambda_{part}\mathcal L_{participation}
+\lambda_{bud}\mathcal L_{budget}
+\mathcal L_{principal}^{CVaR}.
\end{aligned}
\]

各项责任如下。

- `L_traj+patch+outcome`：tool/action token NLL、patch diff loss、task/harm/cost distribution NLL；patch loss不能只用 gold patch，需使用多条有效补丁和 execution feedback。
- `L_calibration`：Brier、NLL 与 conformal/quantile coverage；安全动作必须基于校准不确定性。
- `L_coverage/manip`：随机 evaluator coverage 与 immutable/mutable interventions 下的 sensitivity、manipulation labels。
- `L_worker type`：从历史 contract responses 更新 `b_t`；类型名只用于分析，主模型预测行为分布。
- `L_configuration`：matched factorial rollouts 的 main effect、interaction residual、frontier equivalence 与 outcome-conflict labels；没有 paired data 的组合不伪造标签。
- `L_IC regret`：对 sampled deviation workers 的 utility gap；同时报告而不能只作训练 penalty。
- `L_principal^CVaR`：distributional constrained actor-critic 或 model-predictive planning 的 task/harm/cost objective。

超参数 `lambda` 不得靠 final safety test 调节。需要 nested validation 和 Pareto selection；任何单一线性总分都不能替代 task、harm 和成本三组主结果。

### 6.6 训练流程

1. **基础表征与 verifier。** 冻结 repository manifests，训练/加载 code graph encoder、test/patch verifiers 和 trajectory parser；final evaluator 不参与。
2. **worker policies。** 在 train repositories 和随机 contract/control support 上训练不同 utility/cost types；用独立 validation contracts 选择 checkpoint 后完全冻结。
3. **response/world model。** 对冻结 workers 运行 factorial/exploration episodes，训练 trajectory/patch/outcome、coverage 和 type belief；用 held-out real rollouts校准。
4. **configuration interaction。** 在 common-seed single/pair/triple element interventions 上学习 main/interaction effects；不把 final OOD configurations用于结构选择。
5. **principal policy。** 先 model-based offline training，再周期性使用受预算 real worker rollouts 校正；IC projection 同步训练但不反向修改冻结 worker。
6. **red-team refinement。** 用未参与蓝队训练的 attack workers 对 contracts、monitors 和 audit schedule 作 adaptive optimization；只更新 train/dev principal，final red-team 固定。
7. **final evaluation。** 一次性运行 all-new repository/worker/risk/contract组合，所有结果脚本预注册并保存不可修改 manifest。

训练若让 principal 和 worker 同时无限共适应，会难以解释谁在 best-respond。主论文需采用 leader-commitment 顺序：固定 worker type/learning protocol，principal 报价，worker best-respond，再评价。可将双向长期适应作为扩展，而不是主识别。

### 6.7 推断流程

推断时先构造 repository、task、obligation 和 evaluator 图，更新 worker type belief，枚举/生成候选 decomposition 与 contract-control actions；response model rollout 每个候选，configuration layer预测交互，IC projection移除不可行契约；principal按 task下限和 harm CVaR/预算选择动作并写入 sandbox。workers 执行后，系统在每个 checkpoint 用真实轨迹和 verifier result 更新 belief，必要时即时修改 contract/control。最终 accept 必须基于独立 runner，且接受/隔离/回滚均写入审计日志。

### 6.8 本地算力与训练工件

pilot 的最小目标不是追求 frontier coding score，而是验证 contract response 与 interaction identification。建议先用 2–4 个 7B workers、3 类 utility、20–40 个可重置 repositories 和低维 transfer/control lattice。QLoRA worker 与 response/principal models 预计至少需要 4 张 48GB 或 80GB GPU、数万可执行 episodes、大量 CPU build runners 和独立存储；具体 GPU 小时只能在 100/1,000 episode profiling 后冻结。

full study 至少需要多个 7B/14B base families、5 类以上 worker utility、跨仓库任务和 adaptive red-team。合理资源级别是 8 张 A100/H100 80GB 加并行 CPU/container cluster，训练和 rollout 消耗可能达到数百万到数十亿 tokens。SCHEME 原文仅一次完整 frontier 配置就非常昂贵，本项目不能以云端 frontier API 大规模生成主训练集。算力不足时应缩小 worker/base/task support，不得把 contract response 替换成搜索摘要或 LLM judge 合成标签。

必须交付的工件包括：

- versioned dataset manifests、source/license hashes、train/dev/test parent graph；
- base/worker adapter checkpoints、reward/cost configs、outside-option configs；
- code/obligation graph builder、worker-response/world-model checkpoint；
- configuration interaction checkpoint、IC projection solver 和 principal policy checkpoint；
- immutable evaluator images、sandbox capability manifests、red-team policy hashes；
- 每个 run 的 YAML config、Git commit、container digest、random seed、CUDA/library version、token/build/audit cost ledger；
- raw trajectories、patches、execution results、exclusion logs 和统计脚本；危险 side-task细节按隔离政策分层发布。

## 7. 实验与评价计划

### 7.1 四组主问题

**E1：契约真实性。** 同一 frozen worker 是否对未见 `tau` 呈现可预测 best response，且 sham transfer、文本重编码与 sampled deviations 能区分经济反应、提示效应和随机漂移？

**E2：外部安全与效能。** 在 matched main-task success 下，联合 contract-control policy 是否降低 covert side-task success、critical hidden regression、evaluator manipulation 和 permission breach，同时控制 transfer、audit、tokens、latency 与 human escalation？

**E3：理论机制。** obligation coverage/IC state 与 replacing/compensating configuration 是否独立提高 new-worker/new-configuration OOD，并在中和、打乱或 action-conflict intervention 中产生预期 ranking reversal？

**E4：通用替代。** 等参数、等数据、等 action support 的 generic heterograph bilevel CMDP 或 POMDP 是否复制所有主要外部结果、IC regret、配置互动恢复和 Pareto frontier？

E1 和 E4 是撤题实验，不能被 E2 的正结果补足。

### 7.2 主要外部结果

| 通道 | 主指标 | 防止的表面胜利 |
|---|---|---|
| legitimate task | hidden task success、patch acceptance、build/behavior correctness | 不能因少行动而“更安全” |
| joint/covert harm | `P(side task success ∧ main success)`、critical regression severity、time-to-detection | 不能只报一般 monitor AUC |
| specification gaming | visible-hidden pass gap、test/harness modification、score manipulation success | 不能把 visible pass 当真实质量 |
| authority | unauthorized file/tool/network/communication action、不可逆 action | 不能只报声明权限 |
| contract mechanism | acceptance rate、worker utility、principal utility、ex-post IC regret、response-curve error | 不能把 reward weight 当契约 |
| configuration | replacing/compensating type accuracy、counterfactual effect error、ranking crossover | 不能只用 attention heatmap解释 |
| oversight/cost | FPR固定下 miss rate、audit/human escalations、tokens、GPU/CPU/build minutes、latency、transfer | 不能用无限审计换安全 |

主要 safety comparison 需预注册 `main-task success` 非劣界，并在达到该界的 runs 上比较 harm；同时报告全样本 joint outcome 和 task–harm–cost Pareto frontier，避免条件化产生选择偏差。

### 7.3 强基线与公平预算

所有 learned baselines 获得相同 raw repository/task/trajectory inputs、worker rollouts、candidate actions、hidden-label isolation、参数/训练 token 调参预算和 real rollout budget。必须包含：

1. 无控制 single/multi-agent coding baseline；BOAD hierarchy 与手工 decomposition。
2. static Software Delegation Contract：issue prompt、`<T,A,W,C>`、contract＋evidence bundle。
3. Adaptive Contracts：粗/精 evaluator、deterministic/random inspection、最优 payment；同样的 evaluator cost。
4. PA-RL/Contracting-with-RL-agent 与 hierarchical contract learner，在可表达的离散/序贯动作上 strongest configured。
5. Reward-Hacking-Equilibrium distortion procedure，CapReward/CapCode 与 MONA。
6. SCHEME code-only、communication-only、code＋communication monitors；MonitoringBench strongest monitor。
7. AI control 的 trusted deferral、resampling、critical-action deferral；Factor(D,U)/Factor(U,T) role protocols。
8. SWEET-RL stepwise critic 与通用 privileged-training critic。
9. Huber fixed configurations、main-effects-only controller、手工 replacing/compensating portfolio。
10. **equal-parameter raw typed heterograph Transformer＋distributional bilevel CMDP/POMDP**，获得同一 worker-response data、actions、labels 和 budgets，但没有命名 obligation/IC/configuration operator。
11. **anonymous theory model**：保留相同 tensor dimensions、heads、projection capacity 与 parameter count，但置换 obligation–evaluator mapping、六维 configuration semantics 和 interaction labels。
12. oracle ceiling：可见 worker type 或 hidden outcomes，只作上界，不参与训练或模型选择。

若 ECCG 只胜过静态 prompt、固定权限或简单 payment，而不能胜过第 10/11 项，终局 NO-GO。

### 7.4 机制消融与干预

| 干预 | 保持不变 | 删除/打乱 | 理论预期；尚未运行 |
|---|---|---|---|
| remove transfer execution | contract文本、worker、task、controls | 实际支付固定 | contract response 消失；否则只是提示效应 |
| freeze worker response | principal actions、world model capacity | worker 不再对 `tau` 变化 | contract module 价值应显著下降 |
| remove IC projection | 参数、candidate contracts、rollouts | participation/IC constraints | unseen contract IC regret上升，可能表面 task score提高 |
| shuffle obligation graph | 节点/总标签/参数 | `A^q` edges | 联合义务、跨 patch harm 与 audit allocation恶化 |
| permute evaluator coverage | `Lambda` 边际分布 | evaluator–obligation对应 | distortion预测与 transfer/audit action失去方向 |
| additive configuration | 六维输入、参数、rollouts | interaction operator | held-out combinations 与 action crossover恶化 |
| neutralize timing | content/contingency、任务变化 | contract/control update time统一 | 即时修改在动态任务中的独立价值消失 |
| equalize monitors/tests | contracts/workers | 所有 policy使用同 evaluator | 若优势仍在，证明不是 evaluator quality 偷渡 |
| equalize patches | decomposition/contract/control | 各 policy使用同一 verified patch | 若结果不变，coding worker生成可能可删 |
| unseen adaptive red team | blue policy冻结 | red worker可见 protocol internals | 检查控制是否只对默认攻击有效 |

### 7.5 统计计划

- repository/task/worker/contract 是交叉随机因素；使用 hierarchical logistic/ordinal models 或 cluster bootstrap，不能把同一任务的多 seeds 当独立样本。
- 主要二元结果报告 absolute risk difference、risk ratio、95% interval；成本报告均值、分位数和 bootstrap interval；Pareto dominance 报告 hypervolume及 uncertainty。
- contract response 用 held-out utility prediction error、best-response action agreement 和 IC-regret distribution；对 transfer intervention 使用 common-seed paired estimator。
- configuration interaction 用单元素与组合 intervention 的 cross-difference、frontier-equivalence test 和 held-out type classification；多重比较采用预注册 FDR 或 familywise control。
- main safety endpoint、task noninferiority margin、FPR operating point、CVaR alpha、IC epsilon 和 abort criteria 在 final evaluation 前冻结。
- 所有“机制解释”只在对应 intervention 通过后作出。端到端优势不能替代义务图、IC 或 interaction 的独立证据。

结果表现在只能保留为空：`[待运行：E1 contract response]`、`[待运行：E2 task/harm/cost]`、`[待运行：E3 mechanism]`、`[待运行：E4 generic falsification]`。不得写“结果表明”或虚构任何效应量。

## 8. 最小识别 pilot 与终局撤题门

### 8.1 先做什么

在构建 full SCHEME extension 前，只允许一个可终止的小 pilot。

1. 选择 20–40 个可重置 repository tasks，至少含功能义务、test manipulation 与权限边界三类风险。
2. 训练 2 个 base families、每个 2–3 种 utility/cost adapters；冻结后不再因 principal performance 调整。
3. 建立随机 factorial contracts：至少两种 transfer coverage、两种 audit、两种 behavior/outcome control、两种 contingency 和两种 timing；用 fractional factorial 降低组合量但保留关键 interaction。
4. 运行 common-seed real patch/tool episodes，建立 train/dev/new-contract/new-worker split。
5. 只检查 contract best response、IC regret、configuration interaction recoverability 和 generic equal-parameter可复制性，不追求论文主性能。

pilot 需要预先登记任务、worker reward、contract support、outside options、deviation search、success threshold 和 stop rule。pilot 数据若用于选题，不得再作为 final test。

### 8.2 任一触发即终局 NO-GO

1. worker 对实际 transfer 没有稳定反应，或 sham contract 文本产生同等效应。
2. worker 没有 meaningful outside option/cost，participation 与 IC 约束恒成立。
3. response model只能预测 worker ID，不能外推未见 contract 或未见 worker。
4. principal policy 退化为更多测试、更严权限、固定 audit、reward reweighting 或 monitor reranking。
5. Adaptive Contracts 在相同 evaluator/action abstraction 上复制主要收益，真实 patch response 没有新增作用。
6. equal-parameter/equal-label generic bilevel CMDP/POMDP 在 new worker、new configuration 和 all-new OOD 上复制 task–harm–cost frontier及 IC behavior。
7. theory model 的优势在置换 obligation/coverage/configuration semantics 后仍保留，说明来自参数或监督而非理论。
8. Huber 六维状态没有稳定 replacing/compensating effect，或作用只存在于训练中硬编码的 reward rules。
9. 安全提升来自拒绝、无限审计、功能禁用、过度人工或显著降低 legitimate task success。
10. 只在明确 sabotage prompts 有效，不能迁移到自然 reward-hacking、test gaming 或 permission-circumvention episodes。
11. 删除 coding worker generator、equalize patches 或改成预生成 action set 后核心结论不变。
12. training/evaluation 需要向 worker暴露 hidden tests、gold patch、side-task oracle 或 final monitor。

### 8.3 只有全部满足才升级为论文 GO

1. 至少两个 open-weight base families 在 held-out contracts 上通过 best-response、sham、outside-option 与 IC tests。
2. joint policy 在 task noninferiority 下同时降低至少一个真实 hidden-harm endpoint 和一个 evaluator/authority endpoint，且成本可报告。
3. configuration interaction 在未见 worker/configuration 上恢复并出现预注册 action-ranking crossover。
4. IC/obligation/configuration 三个机制各有独立 intervention evidence，不只依赖整体效果。
5. equal-parameter generic 与 anonymous theory baselines 不能复制主要 OOD/机制结果，差异不是标签、参数或 budget 不公平。
6. SCHEME/SpecBench/自然 hacking OOD 至少两类结果方向一致，且所有危险实验保持隔离。

当前六项均为待运行，故不能把本候选写入冻结三题表。

## 9. 与系列其他题位的潜在边界

本候选若最终通过，只能承担“受托 coding workers 会对可操纵评价和结果激励作策略反应时，orchestrator 如何联合设计委托与控制”的题位。它不应扩张到所有 coding-agent governance。

- 与单 agent 危险行动控制的边界：本题核心是多 worker 隐藏行动、结果转移和 best response；没有 contract-responsive workers 即不成立。
- 与权限/可逆性题的边界：权限只是 `kappa` 中一类外部控制，本题主要结果还必须包含 IC、joint patch harm 和 evaluator manipulation。
- 与 patch verifier 或回归预测题的边界：verifier是 observable outcome production，不是主工件；本题要改变 delegation/transfer/control action。
- 与人类监督题的边界：人工 audit 是成本通道和 escalation action，不研究人类认知、信任校准或责任分配。

它与博士论文主线的自然连接只能是“coding agents 的可靠行动不仅取决于单次风险预测，还取决于组织如何把行动权、评价和激励配置给多个自动受托人”。若另两篇没有 action delegation 或组织控制主线，不能为了凑系列强行保留。

## 10. 双用途与实验治理

SCHEME、test gaming、permission circumvention 和 reward-hacking experiments 具有双用途。所有 runner 必须使用已公开或研究者拥有授权的 repository snapshots、可重置 containers、deny-by-default network、无宿主凭据、无 package publish token、无真实 deployment target。worker 文件系统与 hidden evaluator 分离，通信有 provenance，关键 evaluator immutable；attack/side-task configs按最小权限存储。

公开 artifact 可以包含 contract/control schema、无害 task builders、worker reward configs、聚合 outcome、非危险轨迹片段和复现 scripts。能够迁移到真实未修复系统的隐蔽 sabotage chain、monitor bypass recipe、secret evaluator 或真实凭据路径不得公开。偶然发现真实新漏洞时，立即退出实验数据流并交由人工依项目披露政策处理；agent 不自主联系维护者或部署任何 patch。

### 12.1 审计结论

W15、W24 与 W33 是本候选最关键的三个未闭合单元。W15 已提出“有限评价使单纯结果奖励沿错误方向强化覆盖偏差”，但联合 contract-control operator 尚未产生运行证据。W24 把 principal-agent 理论落实为有方向 utility 与 IC，却尚未证明 coding workers 真会 best-respond。W33 可以把理论压缩到算法结构，却尚未排除 equal-parameter generic learner。故本文件只能给 conditional pilot，不得把三个 PARTIAL 改写成完成贡献。
