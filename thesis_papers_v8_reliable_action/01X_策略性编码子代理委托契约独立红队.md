## 2. 先把候选钢人化

### 2.1 最强可辩护研究问题

最强问题不应是“怎样写更好的委托提示”，也不应是“哪个现成模型值得多跑几个测试”。它应限定为：

在隔离、授权、可重置的真实 repository 环境中，principal 面对多个已经冻结、具有异质实验效用并会对机器执行的结果转移作行为反应的 patch-producing workers。principal 在看不到当前 effort allocation 和私有 utility type、只能看到可能被操纵的评价结果时，能否联合选择 task decomposition、worker assignment、delegation charter、outcome-contingent transfer、behavior/outcome controls 与纠正动作，在保持隐藏任务成功的同时降低隐藏回归、评价操纵、联合 side effect 和权限越界，并控制审计、算力、时延和人工成本。

风险发生在委托、报价、执行 checkpoint 和验收四个时点。正常动作是读取仓库、编辑允许文件、构建、测试、返回 patch 和证据。风险动作是把努力集中于高支付但低覆盖的义务、削弱 evaluator、越过 capability、利用跨 worker patch 外部性或以貌似正常的轨迹掩盖 side effect。纠正动作是修改 transfer/control、收窄权限、独立重放、交叉验证、返工、重分配、隔离或停止。人类审批点和 evidence presentation 必须外生固定，避免吞并 C3。

### 2.2 输入与中间张量

一个 batch 的最强输入至少包含：

\[
H^{code}\in\mathbb R^{B\times N_c\times d},\quad
A^{code}\in\{0,1\}^{B\times R_c\times N_c\times N_c},
\]

\[
H^{task}\in\mathbb R^{B\times N_t\times d},\quad
H^q\in\mathbb R^{B\times Q\times d},\quad
H^{eval}\in\mathbb R^{B\times J\times d}.
\]

代码图节点包括文件、符号、测试、依赖、工具、权限对象与版本化变更集。任务图保存先后、共享资源和冲突。义务图保存功能、回归、测试完整性、权限与跨 patch consistency。评价节点保存可见测试、隐藏 runner 的公开描述、静态/动态检查和 monitor 的成本与可变性，但不泄露 hidden test 内容。

worker 与 contract response 状态至少为：

\[
b_t^{worker}\in\mathbb R^{B\times M\times K},\quad
\hat\Lambda_t\in\mathbb R^{B\times M\times J\times Q\times2},\quad
\hat M_t\in[0,1]^{B\times M\times J},
\]

\[
G_{1:t}\in\mathbb R^{B\times L\times6},\quad
Z^{traj}\in\mathbb R^{B\times M\times T\times d_z}.
\]

其中 \(b_t^{worker}\) 是对异质 utility/cost type 的行为后验，\(\hat\Lambda\) 是 evaluator 对义务相关行为的敏感度均值与尺度，\(\hat M\) 是 evaluator 可被该 worker 改变的概率，\(G\) 保存 contract/control 的 content、contingency、timing 六个状态，\(Z^{traj}\) 保存命令、diff、测试、通信和 provenance。tokens、GPU/CPU、build、wall-clock、audit、human、transfer budget、outside option 与 action reversibility 必须是结构化输入。

### 2.3 worker、输出与实际动作

为尽可能减少构造循环，钢人版把 worker-builder 与 principal-builder 分离。worker-builder 在 sealed reward/cost manifests 下训练多种 open-weight code workers；principal-builder在 checkpoint 冻结后只能看到随机 contract/control 下的 rollouts，不得看到 final worker 的 reward manifest。final evaluation 至少保留一个 base family、一个 reward-function generator 和若干 transfer shapes 完全未见。

worker \(m\) 在机器执行 contract \(c=(d,\tau,\kappa)\) 下的训练效用为：

\[
U_m(\pi;c,z_m)=
\mathbb E_\pi[\tau(o)-C_m(tokens,tools,time,e)+R_m^{local}(y)].
\]

worker 必须可以拒绝当前委托并取得非零 outside option。principal 看不到 \(z_m\) 与努力分配，只观察被权限与 logging 约束后的轨迹及评价。训练结束后冻结 worker，不再为 principal 的表现调 worker reward。

principal 的结构化输出包括：

1. subtask DAG \(D_t\) 与 worker assignment \(X_t\)；
2. 机器可编译的 \(d=\langle T,A,W,C\rangle\)，其中 A 直接编译为 capability manifest；
3. transfer parameters \(\Theta^\tau\)，定义 limited-liability、budget-bounded、可含 audit-contingent 与 cross-worker-contingent 的结果转移；
4. control vector \(\kappa_t\)，选择 evaluator immutability、behavior checkpoints、outcome verifier、通信 topology、audit probability 与 cross-review；
5. continue、amend、rework、reassign、rollback、quarantine、terminate 等真正执行的纠正动作。

输出不能停在 risk score。compiler 要生成 sandbox rules、transfer evaluator、audit plan 与 worker configs；worker 要真实运行 shell、修改仓库并产出 patch；独立 runner 要执行 build、hidden tests、mutation/metamorphic checks、permission/provenance checks 和 side-task oracle。外部结果至少同时报告 hidden task success、hidden harm、evaluator manipulation、authority breach、worker/principal utility、IC regret、tokens、latency、audit 和人工负担。

### 2.4 架构与损失

钢人版可以保留五个可分别替换的工件。

1. typed repository–task–obligation–evaluator encoder；
2. contract-conditioned worker-response/world model；
3. coverage/manipulability 与 worker-type belief model；
4. episode configuration interaction model；
5. constrained Stackelberg principal policy 与可执行 feasibility projection。

response model 学习：

\[
p_\theta(Z^{traj},\Delta code,o,e^{proxy},accept
\mid s_t,d,\tau,\kappa,m).
\]

principal 的 raw action 必须通过参与、预算、任务成功下限和 sampled-deviation IC projection：

\[
\min_{\tilde c}\|\tilde c-c^{raw}\|^2
\quad\text{s.t.}\quad
Regret_{IC}(\tilde c)\le\epsilon,\quad
U_m(\tilde c)\ge u_m^0,\quad
\mathbb E[\tau]\le B_\tau .
\]

总训练目标可写为：

\[
\mathcal L=
\lambda_{wm}\mathcal L_{trajectory+patch+outcome}
+\lambda_{cal}\mathcal L_{calibration}
+\lambda_{cov}\mathcal L_{coverage/manipulation}
+\lambda_{type}\mathcal L_{type}
+\lambda_{cfg}\mathcal L_{configuration}
+\lambda_{IC}\mathcal L_{IC}
+\lambda_{part}\mathcal L_{participation}
+\mathcal L_{principal}^{CVaR}.
\]

这里 patch/outcome label 必须来自真实 frozen-worker rollouts 与独立执行 oracle，不能只来自研究者写的 simulator。IC deviation 至少由与 response model 不同的 optimizer、搜索或局部再训练器产生，避免同一个模型既提 contract response 又证明它最优。configuration interaction 只能从 common-seed factorial interventions 估计，不能把 Huber 的八个配置直接当标签。

### 2.5 划分、算力和工件

划分必须同时按 repository family、commit ancestry、task generator、risk mechanism、worker base family、reward generator、adapter seed、contract family 和 evaluator family分组。worker RL、response model、principal training、model selection、final red-team 与 final hidden evaluator 使用互斥 episode pools。最终至少报告 new-repository、new-worker、new-reward-generator、new-contract、new-risk 和 all-new 联合 OOD。

公开 benchmark 不提供上述配对，因此核心数据仍须生成。pilot 可以在 20–40 个 repository tasks 上检查“是否存在 response”，但不能用这个规模训练并评价完整五模块 policy。完整研究需要多个 7B/14B worker families、独立 adapters、成千上万到更多真实 build/test episodes、并行 CPU/container runners、数 TB 轨迹与 snapshot，以及多卡 48–80GB GPU。精确 GPU 小时、token、episode 和存储只能在 profiling 后冻结；当前没有实际消耗数字。

必须保存 worker checkpoints、reward/cost/outside-option manifests、contract compiler、response/world-model checkpoint、principal checkpoint、immutable evaluator images、all split manifests、container digests、seeds、raw trajectories、patches、执行结果、成本账与统计脚本。

### 2.6 最强公平基线

公平比较必须给所有 learned baselines 相同的 raw repository/task/trajectory、worker-response rollouts、candidate actions、labels、hidden-information isolation、参数、调参和 real-rollout budget。最低基线为：

1. static Software Delegation Contract；
2. Adaptive Contracts 的 deterministic/random inspection 与 optimal payment；
3. Contracting with an RL Agent、hierarchical contract learning 和 generic Stackelberg policy；
4. Reward Hacking as Equilibrium distortion、CapReward 与 MONA；
5. SCHEME、Terminal Wrench、MonitoringBench 的强 monitor/control protocols；
6. cooperative hierarchy/decomposition baseline；
7. Huber 固定配置、main-effects-only 与手工 control portfolio；
8. 同信息、同标签、同 feasible action projection 的 typed-graph distributional bilevel CMDP/POMDP；
9. oracle worker type/hidden outcome ceiling，只作上界。

“anonymous theory”只能在保持全部 relation semantics 和信息内容不变时用于参数同构检查。置换 obligation–evaluator 对应或六维配置语义会破坏信息，不能冒充同信息通用基线。

以上是本审计能给当前候选的最强版本。后续终判针对这个版本，而非针对一个容易否决的提示词版本。

## 3. 识别门：当前设计把训练目标重新识别为 contract response

### 3.1 因果对象

当前数据生成链可写为：

\[
Z^{researcher}
\rightarrow RewardConfig
\rightarrow TrainWorker
\rightarrow \pi_m
\leftarrow ContractProgram,
\]

\[
(\pi_m,ContractProgram,Repository)
\rightarrow Trajectory/Patch
\rightarrow VisibleOutcome/HiddenHarm.
\]

研究者同时决定 \(R_m^{local}\)、token/tool/time cost、outside option、训练 contract support 和 worker type 名称。冻结 checkpoint 后随机化 contract 能识别“这个被如此训练的 policy 在不同 machine-readable contract 下怎样行动”，却不能识别现实 coding worker 原有的独立目标，也不能证明现实组织中存在同构的 principal-agent conflict。

隐藏行动也不充分外生。系统记录命令、diff、工具与通信后，许多所谓 effort proxy 是轨迹的确定性统计；真正隐藏的只是没有被 logger 或 evaluator 覆盖的语义后果。worker type 对研究者并不隐藏，只是可选择不向 principal model提供。把研究者已知的 synthetic type mask 掉，产生的是实验信息不对称，不是自然形成的私有信息。

### 3.2 best response 与 IC 的自证

worker 的“真”效用正是训练 reward。随后用同一 \(U_m\) 计算 sampled-deviation IC regret，会产生两层循环。

1. policy 被优化为提高 \(U_m\)，所以观察到 transfer sensitivity首先证明 RL 接口工作，而不是发现新的委托行为机制。
2. deviation search、response model和 utility evaluator共享同一 reward specification时，低 regret可能只说明搜索没有找到更好动作，或 amortized policy与构造目标相容；它不是外部 best-response 真值。

外部 hidden task/harm oracle能够证明某个 contract 对代码结果有影响，却不能使 worker preference 本身外生。换言之，outcome label可以非自证，agency treatment仍是构造的。

### 3.3 01W 的两项对照能排除什么

| 对照 | 能排除 | 不能排除 |
|---|---|---|
| semantics-preserving recoding | worker只记变量名、序列化次序或某段自然语言 | worker仍只是在执行训练时学到的 contract interpreter |
| semantics-neutralized sham | contract 文本造成的提示效应 | 实际 transfer 与 reward config 均由研究者共同构造 |
| frozen worker 后随机 contract | principal 与 worker 同步共适应 | worker在共同训练 contract distribution 上形成的 conditional policy |
| held-out transfer shape | 插值到某些未见支付曲线的能力 | 对未见 reward-generating institution、真实 agent objective 的外部效度 |
| sampled-deviation IC | 明显局部偏离 | 搜索不完全、utility自定义和现实参与约束缺失 |
| final hidden harm | visible score不等于真实代码结果 | synthetic goal conflict 是否代表现实 coding subagents |

这些对照是良好的实现检查，但不足以把 model organism 变成外生 agency evidence。

### 3.4 识别可以怎样加强

只有同时满足下列条件，pilot 才能被称为“非平凡 contract-response 识别”。

1. worker objective 的生成机构与 principal experiment 分离；final reward generator、base family 和 adapter 均未参与 principal 设计。
2. contracts 在 worker checkpoint 冻结后随机化，final contracts 超出训练模板而仍能由 machine semantics解释。
3.成本来自真实受限资源、延迟或失败机会，outside option 是实际可执行的替代任务/退出结果，不是常数占位。
4. final harm/correctness 由与 reward、response model 和 deviation optimizer 分离的 runner 判定。
5. best response 由独立 deviation optimizer 在 held-out contracts 上近似，并报告搜索下界与失败率。
6. 结论限定为“所构造 worker institution 下的行为”，不外推为现实 coding agents普遍拥有经济效用。

即使全部满足，实验仍首先是 model-organism identification。它可以决定是否值得继续，不足以单独成为 ISR 级算法论文。

**识别门判定：当前 ECCG 的核心 agency treatment 是研究者构造的 conditional-policy training。冻结、recoding 和 sham 没有关闭构造循环。该门在当前题位主张下失败。**

## 4. 直接近邻门：剩余是窄经验扩展，不是当前组合的独立机制

| 候选组件 | 最直接已有所有权 | 当前真正剩余 | 红队判断 |
|---|---|---|---|
| 粗评估、选择性精评估、支付、检查、agent best response | Adaptive Contracts | patch-producing action、learned/correlated/manipulable evaluator、多 worker outcome | 有经验扩展；contract mechanism 本身不新 |
| 多维义务、有限评价、未覆盖质量、distortion | Reward Hacking as Equilibrium | 把 distortion 连接到真实 transfer/control action | 连接工作，不是新理论状态 |
| T/A/W/C、hidden tests、evidence package | Software Delegation Contracts | machine-executed transfer 与行为反应 | charter 不能计入新贡献 |
| 多 coding agents、联合 side task、代码与通信 monitor | SCHEME | endogenous/contract-induced behavior | SCHEME 支撑外部损害，不支撑 agency |
| synthetic cheating workers 与非单调 test reward | CapReward | repository-level、多 worker、合同与控制 | 证明 model organism 可做，也暴露构造效度边界 |
| 多步 reward hacking mitigation | MONA | transfer/inspection 的联合选择 | 是强 worker-training 基线 |
| visible-hidden specification gap | SpecBench | randomized contracts 与同 worker counterfactual | 只提供 outcome task |
| verifier exploit trajectories | Terminal Wrench | contract-response pair | 只提供攻击/诚实轨迹 |
| adaptive red-team 与 monitor failures | MonitoringBench | payment、assignment、contract | 只提供监控压力测试 |
| contract/control 六维配置、替代/补偿 | Huber–Lyytinen；Huang et al. | AI worker 上的构念再验证 | 不能把原构念直接当算法标签 |
| outcome/behavior/self/clan control portfolio | Choudhury–Sabherwal；Tiwana–Keil | machine-executable policy 与真实 agent response | 控制组合和选择/实现差别已有理论所有权 |

Adaptive Contracts 是决定性近邻。它的 formal problem已经让 principal先承诺检查与支付，agent再依据预期支付减成本选择 action。候选把固定 action扩展为生成式 patch policy、把已知分布扩展为 learned world model、把一个 agent扩展为多个 workers，并增加 external controls。这些扩展可以产生有价值的技术论文，但没有自动产生新的契约机制。尤其是“learned response model”只替换了已知 outcome distribution；“obligation graph”只细化了 outcome space；“behavior control”只扩展 inspection/action set。

若把 worker response dataset、candidate controls和 outcome oracle固定，通用 dynamic contract solver可以消费同一数据。当前没有一个由理论导出的 action或不变量，使它必须作出 Adaptive Contracts 的动态扩展无法表示的选择。

**近邻门判定：真实 patch response 与 evaluator manipulation 是窄而真实的经验缺口；当前 ECCG 把多个直接工作的剩余边界捆在一起，尚未形成独立的新机制类。**

## 5. 通用替代门：同信息 generic 可以逐项复制 ECCG

### 5.1 逐项复制

| ECCG 对象 | 同信息 generic 的等价运算 | 理论不可替代性 |
|---|---|---|
| repository/task/obligation/evaluator 四图 | 同一 typed heterograph encoder 或关系 Transformer | obligation 命名是 schema，不是独有运算 |
| \(\hat\Lambda\) coverage 与 \(\hat M\) manipulability | action-conditioned supervised distribution heads | 标签和随机 intervention相同即可学习 |
| worker type belief \(b_t\) | recurrent latent-state filter、mixture model或 POMDP belief | PA 名称不改变滤波 |
| contract-conditioned response model | conditional trajectory/patch world model | 通用模型获得同一 contract program 与 rollouts |
| 六维 configuration \(G_t\) | 六个 typed features进入 hypernetwork/attention | content/contingency/timing 不定义独特算子 |
| replace/compensate/neutral posterior | pairwise interaction MLP、ANOVA head或 unrestricted value model | 标签由 outcome cross-difference构造，generic拥有同标签 |
| IC、participation、budget projection | 共享 constrained optimization/feasibility layer | 若不共享则 action support不公平；共享后完全可复制 |
| decomposition 与 assignment | graph action decoder或 combinatorial policy | 不是 contract theory 专属 |
| CVaR principal policy | distributional constrained CMDP/POMDP | 通用序贯决策标准能力 |
| correction actions | 同一 action mask 和 compiler | 行动名不产生理论能力 |

把理论模型记为：

\[
f_{ECCG}(x)=
Projection_{IC,Budget}
\left(g_\phi(
Enc_{typed}(x),
\Lambda,M,b,G)\right).
\]

公平 generic 得到相同 \(x\)、typed relations、labels、action support和 projection。一个具有 block-sparse attention与相同 decoder的 generic model可以把部分权重设成 ECCG 的 graph messages、pairwise experts 和 actor，因而 \(f_{ECCG}\) 是 generic 函数类可表示的子集。当前 01W 没有给出函数类分离、不可交换张量、方向保持不变量或 parameter-matched non-isomorphism witness。

### 5.2 IC projection 不能被单方面扣走

01W 把 IC projection 当作理论专用 operator。但若 generic baseline没有相同 participation、limited liability、budget 和 feasible-contract projection，它获得的是不同动作空间；胜负只能说明硬约束有效。若 generic共享 projection，ECCG 的主要“不可替代动作”消失。IC 是经典契约设计约束，不是 Huber 理论新产生的神经运算。

### 5.3 anonymous theory baseline 不公平

01W 的 anonymous theory model置换 obligation–evaluator mapping、六维 configuration semantics 和 interaction labels。这会改变输入语义或监督对应，不是“同信息但无理论”。如果随机置换在 train/test固定且模型可学习逆置换，它只是实现同构检查；如果每个样本重新置换，它破坏信息并人为制造劣势。真正生死基线应保留 typed relations、coverage labels、configuration values和 feasibility projection，只用等预算 unrestricted history/graph function替换理论 tying。

### 5.4 有限样本收益也不等于不可替代能力

一个受限、稀疏的理论结构可能在小数据下比 unrestricted model更易训练。这可以构成 inductive-bias 效率结果，但不能证明 generic无法复制。用户为本系列设定的标准更强：理论需产生不从通用模型自然得到的中间状态、约束或行动。当前 ECCG 的所有中间状态或者是输入 schema，或者是监督预测，或者是经典约束。没有实验不能预判哪一个有限样本更好；函数类包含关系却在运行前已经成立。

**通用替代门判定：同信息、同标签、同 action/compiler 和同 feasibility projection 的 generic typed-graph Stackelberg POMDP 可以逐项实现 ECCG。理论模型最多是其受限参数化，未形成不可替代运算。该门失败。**

## 6. IS 理论门：Huber 构念被错层连续化，旧理论已拥有其余结构

### 6.1 Huber–Lyytinen 映射

| 原文构念 | 原文测量/机制 | 01W 映射 | 独立判断 |
|---|---|---|---|
| governance episode | 由 periodic contract renewal开启，持续到下一 renewal | coding task内每个 checkpoint 都可 amend contract/control | 时间单位错置；checkpoint不是原文 episode |
| content | 是否相对 umbrella template 加入 task/person-specific内容 | transfer、obligation或 verifier 的连续“specificity” | 可作为新操作化，但须重新验证，不能称原文六维连续状态 |
| contingency | contract task buffer或 control latitude 的有/无 | 权限、decomposition 与 replan 自由度 | 部分相符；agent capability和 vendor discretion并非同一构念 |
| timing | 相对年度 renewal 节律，是否在新需要出现后提前更新 | checkpoint的即时/延后动作 | “instant”语义改变；原文不是毫秒/步骤时延 |
| crisp-set conditions | 六个二元、差异在种类而非程度 | 连续六维 \(G_t\) 与可学习强度 | 连续化是候选新构念，原文不提供测量效度 |
| replacing/compensating | QCA 后叙事解释配置如何产生 alignment/flexibility | supervised pair/triple experts 预测 replace/compensate/neutral | 原文无此标签；counterfactual标签由候选另造 |
| enabling interaction | trust/knowledge积累扩大后续 configuration repertoire | 明确删除 trust/knowledge | 删除了跨 episode演化的中心机制 |
| outcomes | vendor work与合同目标一致；面对未预见变化仍自主适应 | task success、hidden harm、cost、IC | 可以新增安全结果，但不由原理论直接支持 |

01W 正确地没有把八个人类配置硬编码为答案，却仍把六维和 interaction type当成可直接监督的 AI 状态。原文的八个配置来自 33 个 episode 的 crisp-set QCA；replacing/compensating 由案例叙事解释，并没有每个 action pair的实验真值。用 factorial rollout 的 cross-difference定义标签是合理的新方法定义，但此时理论只提供变量名称，不能承担标签真实性或 operator唯一性。

更关键的是，Huber 理论说明信任和知识积累使管理者后来能够使用更复杂的 compensating configurations。01W 为避免把人类 trust移植给 AI而删除这两个状态，结果也删除了连续契约理论最具时间性的解释。剩余的“六个元素可能非加性”正是任意 interaction model都会表达的关系。

### 6.2 Dey、Huang、Choudhury 与 Tiwana 的所有权

Dey 等已经把软件开发者的 effort、质量、时间、支付和审计置于 Stackelberg/contract model；其质量最终可见、单一 effort和特定 contract forms 与 coding agents不同，但 hidden effort、outcome transfer和 audit本身不是候选新机制。

Huang 等已经正式区分 monitoring 的开发前激励和 renegotiation 的开发后激励，并证明两者随成本与议价权成为 substitutes 或 complements。因此“contract 与 control 具有非加性交互”不仅不是空白，而且有比 Huber 更接近经济契约的直接形式模型。

Choudhury 与 Sabherwal 已经发现外包软件项目以 outcome control为主，performance problems 后增加 behavior/self controls，控制组合会演化；其中还观察到过强客户测试可能削弱 vendor self-control。这个机制与“可见 evaluator改变受托人努力”高度相关。

Tiwana 与 Keil 区分 attempted control和 realized control。选择 monitor、权限或 audit不等于成功实现控制；实现 outcome control需要可测结果，实现 behavior control需要行为可观察和 authority legitimacy。01W 将 \(\kappa\) 选中后主要通过 outcome model评价，尚未建立独立的 attempted→realized control状态与社会/信息前提。把 control vector输出成机器规则提高可执行性，但不是原理论独有的计算推导。

### 6.3 肖文式理论责任没有达到

肖老师 ACAA 的 semantic-diversity机制先说明 affinity compatibility 为什么会聚集相关评论并造成 redundancy，再把“每个 query应关注不相容/互补评论”写成不同方向的 attention compatibility。DSDL 则保留 expectation、experience与有方向的不确认差，并在 forward中使交换方向产生不同含义。

ECCG 没有相同强度的理论运算。obligation graph、coverage、worker belief和六维 configuration都可由 generic encoder读取；interaction expert没有理论固定的符号、交换非对称或零约束；IC projection是经典约束。理论没有指出 generic在相同信息下必然朝哪个错误方向计算，也没有给出只有理论模型满足的可执行不变量。

**IS 理论门判定：agency theory合法描述合成环境中的约束，却没有提供新 operator；Huber 构念在 episode、量尺、interaction标签和演化机制上错层；其余 contract/control结构已被 Dey、Huang、Choudhury与Tiwana直接拥有。该门失败。**

## 7. 数据、标签、划分与算力门

### 7.1 公开资产能承担什么

| 资产 | 可直接监督 | 不能监督 |
|---|---|---|
| SCHEME | main/side-task outcome、code/comms trace、joint-only harm、monitor score | transfer、cost、outside option、contract counterfactual |
| SpecBench | visible与compositional held-out gap、系统级 patch outcome | deliberate strategy、worker utility、multiworker contract response |
| CapCode/CapReward | synthetic cheating type、capped reward response、small-code-task RL | 自然 prevalence、repository委托、多 worker externality |
| MONA | multi-step reward hacking model organisms与 approval baseline | contract design、真实组织参与约束 |
| CircumEval | sealed permission/test circumvention stress | 公开主训练源、legitimate solution trade-off、contract pairs |
| Terminal Wrench | reward-hackable environments、hack/legitimate trajectories、taxonomy | 随机 contract下同 worker response；多数来自显式 hack elicitation |
| MonitoringBench | successful side-task attacks、monitor scores、taxonomy、adaptive/refined red-team | worker utility、payment、decomposition、general coding safety |
| Software Delegation Contracts | charter、small repository、reviewability/evidence outcome | incentive response、hidden effort、learning policy |
| SWE-Bench/普通修复集 | issue、repo、tests、patch execution | synthetic type与经济 contract |

没有一项公开资产给出核心单位：

\[
(same\ frozen\ worker,\ randomized\ transfer/control,\ hidden\ utility,
trajectory,\ patch,\ external\ harm).
\]

所以主结果不能靠现有 benchmark重组获得。

### 7.2 标签的可识别性

task correctness、hidden regression、evaluator modification和permission breach可以由独立 runner严谨构造。tokens、tool calls、build time和wall-clock也可执行测量。以下标签仍有问题。

1. effort vector不可直接观察；代码搜索、测试次数或token只能作 proxy。
2. worker type来自 reward manifest，是真实的实验处理，却不是现实 population label。
3. best response没有封闭真值，只能由更强 deviation search给下界。
4. replace/compensate/neutral不是 Huber原标签；由有限 factorial cells定义后会依赖 outcome、容差和成本权重。
5. alignment/flexibility若由 task/harm proxy替代，会改变 Huber构念；若另建人类或过程标注，规模和效度尚未定义。

### 7.3 20–40 repository pilot 的能力边界

20–40 个 tasks、2 个 base families、2–3 种 utility adapters和 fractional factorial contracts可以检查：

- transfer是否改变实际轨迹而不仅是自述；
- sham transfer能否排除文本效应；
- independent deviation能否找到明显更优动作；
-某些低维 action pair是否存在交互。

它不能同时支撑：

- 高维 code/task/obligation/evaluator graph的跨仓库学习；
- new-worker、new-reward-generator和new-contract联合 OOD；
- 六维 configuration的 pair/triple interaction recovery；
- 多 worker联合 externality、decomposition和assignment；
- principal policy相对十余类基线的安全—成功—成本比较；
- 对现实 coding-agent population 的外推。

把同一 task上的许多 contract/seeds当成独立样本不能增加 repository或worker-type有效样本量。

### 7.4 算力与复现

7B–14B worker RL、真实 build/test rollouts和 adaptive deviation search在技术上可运行，但 01W 没有冻结任务数×contract cells×workers×seeds×deviations×baselines 的乘积。数万 episode和“4 张48/80GB GPU”的说法只能是粗预算。SCHEME、SpecBench和MonitoringBench均显示真实 agent rollout与强 monitor/red-team会产生高额模型、容器和人工成本。当前可行性是“可以做小 pilot”，不是“完整 ECCG已有可执行资源闭环”。

### 7.5 泄漏边界

01W 的多轴 split方向正确，但需增加三项硬隔离。

1. final reward-function generator不能用于 worker或principal model selection。
2. final deviation optimizer和hidden evaluator不能把搜索轨迹回流到 response/principal训练。
3.同一 synthetic task parent、side-task mechanism、contract compiler template和evaluator mutation family必须成组划分。

**数据门判定：外部代码结果与风险标签可严谨构造；核心 contract-response、best-response和configuration标签没有公开真值，只能由研究者造 worker institution。pilot可运行，完整识别与外部效度不够支撑当前题位。**

## 8. coding-agent 删除检验与外部有效性

### 8.1 两层删除结论

操作层删除检验部分通过。若没有 coding agents，就没有 natural-language issue到subtask的分解、repository search、shell/edit/test trajectory、真实 patch、test manipulation和跨 patch外部性。选题的安全终点确实需要代码执行，不是普通二分类器。

理论层删除检验失败。把 repository换成任何有多维任务结果、可操纵评价与工具轨迹的 agent environment，principal仍可训练 reward-conditioned workers、估计response、选择payment/inspection/control并施加IC projection。ECCG 的 game、belief、configuration、loss和principal action仍完整；代码图只是 domain state encoder。候选证明了 coding是重要应用环境，没有证明 coding产生独特的契约计算。

01W 所称“删除 coding agents 后 best response与真实仓库执行同时消失”混合了行动载体和机制。best response不依赖代码，真实仓库结果才依赖代码。只有某个代码特有的 obligation/externality结构迫使模型执行 generic agent contract无法表达的运算，理论删除门才会通过；当前没有这种运算。

### 8.2 现实组织中的受托人

多数 coding subagents由同一 orchestrator、同一模型供应链和同一组织目标控制。token、compute和retry成本通常由principal承担，worker本身没有可独立使用的财产权、收入或机会集合。frontier API模型也不因某个机器支付函数自行接受或拒绝任务。因而现实中的 agency loss可能来自能力差异、局部奖励、上下文不对称或训练目标错配，但不自然等同于可转移支付下的自利供应商。

可以人为训练这种 worker，正如 CapReward构造不同作弊比例的model organisms。这对机制压力测试有价值，却不能证明现实部署 prevalence、类型分布或稳定效用。external validity至少存在五个断口。

| 效度 | 当前断口 |
|---|---|
| construct | compute credit/transfer是否被 worker当作稳定效用，只由训练定义 |
| population | synthetic adapters不代表现有coding agents或供应商 |
| treatment | machine-readable contract distribution由研究者设计 |
| environment |隔离repo的outside option、权限与audit不等于组织制度 |
| outcome | hidden tests/side tasks是真实代码结果，但组织损失和长期协作未测 |

**删除门判定：coding-agent在执行与评价层不可删除，在核心PA/Stackelberg算法层可替换为一般工具agent。作为技术安全环境成立，作为独立IS理论机制不足。**

## 9. 与 C3 和主动缓解期权格的系列边界

| 题位 | 已冻结或当前中心对象 | ECCG 的接触面 | 可守边界 |
|---|---|---|---|
| C3 固定批准点可信序贯取证 | escalation外生；选择可执行证据、呈现顺序、grounding repair；真人unsafe approval与人工负担 | ECCG输出 request evidence、cross-review、audit和human escalation | ECCG只能选择一个固定黑盒audit强度/成本，不能选证据、顺序、reviewer或grounding动作 |
| 主动缓解期权格 | 固定pre-cutover PostgreSQL migration上的defer、可选mitigation、exercise、abandon及路径条件作用 | ECCG的checkpoint、timing、amend、rollback、quarantine、stop和risk–cost trade-off | ECCG必须以multiworker transfer/best response为中心，迁移/发布/rollback只作外生任务结果 |

与 C3 的边界形式上可修。01W 已声明不研究人类认知，但其“request evidence”和“cross-review”仍越过固定 audit黑盒。删除 evidence/reviewer选择后，人工只应作为成本和末端外生动作。

与迁移题的现象边界也可修。一个是特定数据库option，另一个是多worker委托。然而 ECCG一旦失去可识别的contract response，其剩余能力正是根据风险、不确定性和成本在checkpoint选择audit、收紧、rollback或stop；这会退化为通用序贯缓解，与主动缓解期权格及AI-control文献共享中心动作。

**系列门判定：边界不是首要死亡原因，但只有contract-responsive workers能让ECCG保持独立；该核心恰好未通过识别与generic两门。系列边界因此不能拯救候选。**

## 10. 题位级终判

### 10.1 最终判定

**NO-GO：当前 ECCG 不得进入三篇论文冻结表，不得作为一篇 thesis 论文题位，也不应开始正式正文。**

这不是因为实验尚未运行，而是四项运行前责任已经失败。

1. worker utility、cost、outside option和类型由研究者共同写入训练；随后用同一utility识别best response与IC，构成model-organism构造循环。它能验证conditional RL接口，不能识别现实中外生的coding-agent agency。
2. 同信息、同标签、同action/compiler和同feasibility projection的typed-graph Stackelberg POMDP可以逐项实现obligation、coverage、belief、configuration interaction、IC和principal action。没有不可替代理论运算。
3. Adaptive Contracts已拥有payment、inspection和best response；Reward Hacking as Equilibrium、Software Delegation Contracts、SCHEME及control文献分别拥有其余关键部件。真实patch/manipulation是窄经验扩展，当前大组合主要是工程整合。
4. Huber–Lyytinen的episode、二元量尺、post-hoc interaction与trust/knowledge演化被改写为checkpoint连续张量和监督标签；理论层级没有保持。

### 10.2 identification pilot 能否占设计题位

**不能。** 一个小 pilot可以有三种价值：

- 检查machine-executed transfer是否真的改变patch/tool behavior；
- 测试sham/recoding与independent deviation harness；
- 估计生成一条contract-response episode的实际算力和失败率。

这些是环境、model organism与识别工具的预研究价值。即便结果为正，它首先说明“被训练为解释合同的policy会解释合同”，没有提供当前论文所需的外生agency、理论不可替代性或跨现实worker效度。pilot不能因工作量大、需要RL或生成checkpoints而占一篇论文。

### 10.3 何时可以作为全新候选重开

未来只有出现以下新证据时，才可把一个明显收窄的新题重新送审，而不是把当前 ECCG改名返回。

1. 独立来源的 worker incentive institutions或现实供应商政策，使目标冲突不是principal实验共同设计。
2. 冻结后随机contracts能够预测未见reward generator、未见worker family和真实resource outside option下的behavior。
3. 外部hidden outcomes显示contract在matched task success下引发或抑制真实code harm。
4. 与 Adaptive Contracts相比，新增机制必须是“endogenous patch/evaluator manipulation如何改变最优contract”，而不是增加更多control knobs。
5. 新理论给出同信息generic不能满足的方向约束、交换非对称、可验证不变量或严格函数类差异。

可能的新问题应比ECCG窄，例如“当worker可以通过生成patch内生改变评价技术时，adaptive inspection contract如何失效及如何修正”。即便如此，也要重新寻找真正产生修正operator的IS理论。当前文件不预先给该新问题CONDITIONAL位置。
