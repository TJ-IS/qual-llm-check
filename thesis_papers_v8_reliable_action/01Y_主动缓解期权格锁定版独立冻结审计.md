## 3. 关键失败一：联合核没有唯一生成 canonical next state

### 3.1 反例

`01H` 把 canonical state 固定为

\[
x=(b,p,q,g,\kappa,\ell,c,t,\tau,A_{mask}),
\]

并把 nonterminal 联合核的随机输出固定为

\[
(d,\Delta c,e,\sigma,o,z,h,k).
\]

但同一文件随后把状态更新写成

\[
x'=F_a(x,d,\Delta c,e,\sigma,o,result).
\]

这里的 `result` 没有出现在联合核、quadrature branch、训练标签或 Bellman 求和中，也没有被定义为前述随机变量的确定函数。由此可以构造两个满足现有联合核、却导向不同下一状态的执行：

1. 对同一个 `M_CP` 分支，`d,Δc,e,σ,o,z,h,k` 全部相同，signed result 可以分别是 `checkpoint_exists=1,restore_verified=1,RPO=0,RTO=31,WAL_gap=0` 与 `checkpoint_exists=1,restore_verified=0,RPO=120,RTO=210,WAL_gap=1`。
2. 对同一个 `M_WC` 分支，现有变量相同，signed result 可以分别是 `cap_active=1,admission_rate=.50` 与 activation timeout 后的 `cap_active=0,admission_rate=1.00`。

这两组分支拥有相同的现有核概率，却必须产生不同 `g'`，继而在 `D60`、后续 action 和 terminal kernel 中产生不同 hazard、accumulator、recovery 和 action mask。颜色 `o` 只有三类，不能唯一恢复上述多个布尔、连续量和计数。

同样的问题发生在 `κ'`。现有核没有生成或确定映射以下字段：`old_client_count/share`、`active_tx_count`、`lock_class`、`lag_class`、`workload_bin`、`rollback_legal`、`complete_legal`、`trace_cursor`。`d` 只推进 elapsed time；`e/σ/o/Δc` 不足以唯一确定这些协议和暴露状态。声称 `PhysicalKernel` 在下一时点读取 `κ`，不能回答当前分支如何先得到那个 `κ'`。

所以，在同一个已展开 chance branch 上，当前规格允许两个不同的 `canonical_bytes(x')`、两个不同 memo key、两组后续 action mask 和两个 Bellman 值。“执行后 runtime 能读 signed result”只能闭合真实 rollout，不能闭合行动前 planner 对未知 result 的积分。

### 3.2 event ledger 也没有被联合核闭合

`ℓ` 的 canonical summary 包含去重后的 component IDs、累计量和 event summary。联合核只给四个 event bits、severity 和六个 accumulator 增量，却没有给出：

- `parent_incident_id`、`reference_tx_id`、`logical_request_id`、`fault_draw_id` 或等价的 planner branch stable key；
- event bit 与 `C_d/C_v/C_u/C_w/C_res` 的唯一映射；
- `e=SLO_BREACH` 与 `ΔA_u`、`e=RECOVERY_GAP_PROBE` 与 CP result 之间的可行支持约束；
- 本分支新增 component 集合、修复链接及其 canonical ordering。

因此，同一个 `(e,σ,Δc)` 仍可对应不同 `ℓ'`。例如 `e_SLO=0,ΔA_u>0` 与 `e_SLO=1,ΔA_u=0` 在当前公式中都未被结构零排除；同一 amount 也可由一个或多个 component ID 组成。memo key 又明确编码 component IDs，这不是只影响展示的细节。

### 3.3 duration likelihood 的公式和文字不是同一实现

belief 公式用 `1[d_n=D̂_{a_nzhk}]`。实际连续 duration 几乎不会逐 bit 等于某个预测 quantile，按该公式会使全部 latent state 的 likelihood 同时为零。紧接着的文字改称运行时落入最近 quantile 的 Voronoi cell，训练时使用相邻 quantile 定义的 piecewise-linear density，但没有冻结：

- Voronoi 中点、等距 tie-break 和首尾 tail support；
- duration 超出第 5%/95% quantile 时的密度；
- 重合或近重合 quantile 的数值规则；
- planner、belief 和 `L_jointN` 究竟共同调用 cell mass 还是 density。

这不是符号美观问题。不同选择会改变 posterior、后续 action 和训练 likelihood。

### 3.4 最小可执行修复

新版本必须把 next-state 变量加入同一个联合核，而非在 planner 外补一个 runtime-only 回调。一个足够窄的接口是：

\[
Q_*^a(d,\Delta c,e,\sigma,o,r_a,\Delta g,\kappa',\Delta\ell,z,h,k\mid x),
\]

其中 `r_a` 是按 action schema 定义的 joint typed result cell，`Δg,κ',Δℓ` 要么是 `r_a,e,σ,d,Δc,x` 的逐字段确定函数，要么也是同一 joint cell 的显式随机输出。不得让它们在 `Q_*` 之外独立重抽。至少要同时补齐以下内容。

1. `M_CP` result schema 必须冻结 checkpoint/restore 状态、RPO/RTO、WAL gap、storage age 的 dtype、unit、support、missing/timeout cell、结构不可能组合和状态更新式。
2. `M_WC` result schema 必须冻结 activation、cap rate、activation time、deferred-write count 的 dtype、support、失败 cell 和持续至 terminal 的 passage-of-time 规则。
3. 全部 nonterminal action 和 `D60` 必须给出 `κ→κ'` 的字段级转移；布尔合法性必须由同一个 `κ'` 确定，不得由另一个隐式 automaton 生成。
4. `Δℓ` 必须给出 branch-stable component key 的确定生成规则、event/component support matrix、事件与 accumulator 的一致性约束，以及实际 signed ID 与 planner surrogate ID 的对应关系。
5. 新增变量必须有 shape、link、label source、loss、missing/censoring 规则、train/validation/test isolation 和 planner branch order。
6. `G-PhysicalFactoredSMDP` 必须逐对象获得同一个新接口、相同 labels/loss、相同 joint support 与 search branch；不能只给理论模型 typed result head。
7. `canonical_bytes`、memo key、priority tuple 和 200k cap 的 state expansion 必须同步加入新 branch axes，并补一个反例 mutation：两个 color 相同而 CP/WC result 不同的分支必须生成不同 state hash 和不同后续 kernel。
8. duration 似然必须只保留一个规范函数。若采用 cell mass，应明确所有 cell/tail/tie；若采用 piecewise-linear density，planner、belief 和 joint NLL 必须调用同一实现及数值 floor。

完成这些字段不要求提前跑赢任何模型，但在完成前，所谓“唯一联合 kernel”不是唯一可执行的 semi-Markov transition。

## 4. 关键失败二：component ledger 混合了证据取得与外部结果

### 4.1 去重原则中已经成立的部分

现有 ledger 正确地建立了 source authority、stable key、half-open interval、retry 去重、CP drill 不直接记 `r`、WC write 与 SLO 不重复记 action cost，以及 repair 不删除既有 harm。八项 mutation test 也覆盖复制、分片、乱序、retry、drill/terminal、rollback 和 timeout 的典型双计风险。

WC/CP 的理论持久性也不是被 path firewall 截断。`R_phys` 允许共享 `PhysicalKernel` 读取 `g^{WC}` 与 `g^{CP}`，并明确要求它们持续影响 `D60`、后续 action 和 terminal。这条 typed-state 路径是合法且必要的。问题在于上一节所述 `g'` 尚未由 planner kernel 生成，而不是持久状态没有下游消费者。

### 4.2 `C_v` 的可操纵分母

`OUM-1.3` 把 `v` 定义为 hidden transaction/query 的语义违反率；`M_SR/M_SV` 又是隔离 shadow 或只读 checker，其生产 physical impulse 固定为零。可是 componentizer 规则写成每个“public/terminal reference transaction”都向 `C_v` 写一个 denominator，并可能写 numerator。

这会产生两种不可接受的策略依赖。

1. agent 多执行一组通过的 public checker，就能在 terminal physical state 完全不变时增加 denominator、稀释 `v`。
2. 隔离 shadow 中发现的既存 defect 若写 numerator，会把“获得了风险证据”当成“agent 已经造成外部语义损害”。

这样，信息动作本身改变效用标签和评价 endpoint。模型可以通过选择检查数量而改变 outcome，而不是通过减少 terminal harm 改善 outcome。它也与 `M_SR/M_SV` 只通过 observation 和 belief 创造价值的设计责任冲突。

### 4.3 最小可执行修复

必须把 ledger 分成 evidence 与 outcome 两条不混账的 typed 路径。

- `public_evidence_ledger` 保存 checker/replay 的 transaction、coverage、failure 与 counterexample，只进入 `o`、belief 和资源成本。
- `C_v` 的 numerator/denominator 只由冻结且 policy-invariant 的 terminal reference population产生。该 population 的 ID 集合、抽样权重、重复规则和分母必须在 action 前封存，不能随已选 checker、coverage 或路径改变。
- shadow instance 中的 durable/semantic 变化不得写生产 `C_d/C_v`；它只产生 evidence 和 `C_res`。
- 增加 mutation test：在 terminal database state、terminal reference population 和全部生产 ledger 相同的条件下，多执行任意数量的 passing public checks，最终 `v`、`Y` 与 outcome-component hash 必须不变。
- 增加失败 checker 的对应测试：它可以改变 posterior 和后续 action，但在 terminal physical state相同时不能直接增加 `C_v` numerator。

另一个较小的语义歧义是 `a` 被称为“安全 abandon”，而 `C_sax` 对任何 `ABANDON` 都写 `a=1`，即使 rollback 同时产生 `d/r`。新版本应把 `a` 改名为 abandon disposition，或冻结“只有无新 harm 的 abandon 才是 a”的判定。前一种做法与现有效用分项最兼容。

## 5. 关键失败三：physical mask 没有阻断 mixture 积分后的越权作用

### 5.1 张量 shape 与理论类边界

现有主效应计算在 shape 上可以实例化：`q_r` 为 `B×32×16`，`V_r e_m` 为 16 维，逐元素相乘后经 `U_r` 得到 `d_r`；pair 分支的双线性项是标量，`B_r q_r` 为 `d_r`，广播后得到 `B×18×32×d_r`。六个 family 的 flatten 次序、quantile 递增 link、`D_w≤N_w` 和 terminal joint cell 也已说明。

理论函数类在 matched canonical state 上只保留 main 和 ordered second-order pair，因此三项 action indicator 的三阶 mixed difference 恒为零。公平 generic residual 可以使用完整有序 history 并产生非零三阶项。generic 能包含理论子类不意味着两者全局同构；不存在把 unrestricted history Transformer 的每个函数双向映射到这个低秩二阶类的全局参数置换。`TT-3/TT-4` 的函数类反证方向成立。

### 5.2 exact masks 未被冻结

规格只给 `M_r∈{0,1}^{18×d_r}` 与 `M_pair_r∈{0,1}^{3×3×d_r}` 的 shape，并称其由 operator contract 冻结。文字合同不能唯一决定 18×各 family 宽度中的每一个 bit，也没有给出可校验的数组、生成器或 hash。尤其没有逐 bit 回答：

- 8 个 SR slot 和 8 个 SV slot 在 `mix/obs/dur/acc` 的哪些 mixture、event、quantile 和 channel 位置为 1；
- CP 在四类 hazard/severity 中只能影响 recovery probe severity、不能改变 event occurrence 的确切位；
- WC 可影响 damage/SLO hazard 但不可修复 semantic defect 的确切位；
- 九个 ordered role pair 对六个 family 的 `M_pair` 哪些维度开放。

所以，当前至少存在两个都符合文字描述、却产生不同 forward 的 mask 实现。

### 5.3 共享 mixture 绕过 head-level zero

更严重的是 `mix` 本身也是 active residual family。`Π_N` 的同一个 `h` 权重共同混合 duration、accumulator、hazard、severity 和 observation。即便某 action 在 SR/SV 的生产 hazard 或 severity logits 上与 physical base 逐 bit 相同，只要它改变 mixture logits，而各 `h` component 的生产 head 不完全相同，积分后的生产 hazard、severity 或 cost 分布就会改变。

同理，CP 若可改共享 mixture，即使 occurrence head 没有 residual，也可能通过重加权不同 `h` 的 occurrence probabilities 改变 event frequency，违反“CP 不能降低事件本身发生率”。WC 的 mixture residual也可能间接改变被禁止的 recovery/semantic channel。`TT-4` 只比较 mask 外 logits 为零，不能检出 link 和 mixture marginalization 之后的这种越权。

### 5.4 最小可执行修复

1. 把每个 `M_r` 和 `M_pair_r` 的 binary array 作为 versioned artifact 固定，记录 shape、axis names、bit count、SHA-256 和生成脚本；不能仅记录“operator-derived”。
2. 最小且最稳妥的修复是禁止十八个 active action 改共享 `Π_N`，即 active `M_mix=0`，让 dependence mixture 只由共同 physical base 决定。若坚持 active mixture，必须改成按受影响 family 分离的 mixture，并证明不会重加权被禁止 channel。
3. physical-zero tests 必须在 natural link 和对 `h,k` 积分之后比较完整边际分布，而非只比较 pre-link logits。对每一 action/channel 生成 counterfactual `base` 与 `base+residual`，被禁止 outcome 的 CDF、hazard 和期望应逐 bit 或在冻结数值容差内相同。
4. CP 的 occurrence invariance、SR/SV 的 production-state invariance、WC 的 semantic/recovery invariance都要成为显式 mutation tests。
5. 主模型和 `G-PhysicalFactoredSMDP` 必须读取同一个 mask artifact，并在参数计数前验证相同 support。

## 6. 公平 generic、terminal、上界和搜索

### 6.1 `G-PhysicalFactoredSMDP`

公平合同已经避免了最常见的人为削弱。generic 获得相同 raw files、candidate/action masks、typed physical prior、shared encoder/base/head、joint labels、loss weights、belief、typed transition、componentizer、qualification worlds、hard recursion、quadrature、memo、pruning和200k cap；它还可以读取理论模型主动拒绝消费的 raw ordered history。±1% 参数与 ±5% training FLOPs、相同 rollout 和 tree-expansion 预算也已写明。

不过，这一公平性只有在共同 kernel、next-state 和 exact mask 修复后才可验证。否则“逐对象共享”的对象本身尚不唯一。另需在 manifest 中物化 unrestricted residual Transformer 的层数、宽度、head、FFN、position encoding、history serializer、pooling、normalization、dropout、family output projection 和 initialization；只写“等预算 Transformer”仍允许人为选择弱架构。宽度只可在未看 episode outcome 前按固定 count script 调整一次的原则可以保留。

结论是：generic 没有在概念合同上被故意扣信息或扣预算，但本版还不能出具公平执行证书。修复后若 generic 与理论模型经验等效，应撤销独立理论算法贡献；这仍是未来结果门。

### 6.2 terminal input 与时间

terminal head 明确以当前 `H_0,z,R_phys,L_evt` 为输入，`R_phys` 包含 `g,κ,c,t,τ`，EX/AB 共享 joint `J,V_v,D_T,K_T` 接口；600 秒后只保留 terminal actions，120/60 秒 evaluation 不重新开放 mitigation。这个时间边界和 hidden terminal oracle 隔离在设计上成立。

需要随 next-state 修复同步明确 terminal reference population 和 AB disposition；除此之外，没有发现 terminal head 通过 future truth 选动作的接口。terminal 结果尚未运行不是设计失败。

### 6.3 pruning upper bound

`R_max` 只按当前 protocol automaton 的宽松可达性给出最高 terminal credit；`UB` 扣除已发生且不可逆的 damage、SLO、时间和资源项，再减当前 partial utility。它故意忽略未来 `v,w,r` 和未来非负成本，只会使上界更松，不会把可能的剩余增量压低。chance node不得删除低值 child、fallback 和 tie-break 也已冻结。因此上界的可采纳方向成立。

实现证书仍需以修复后的完整 canonical state 运行：memo collision full-byte 比较、bound monotonicity、exhaustive tiny-tree 对照和 cap fallback 测试。未实现这些测试应保留 `PENDING-IMPLEMENTATION`，但不构成当前设计 NO-GO。

## 7. benchmark、隔离与统计保证

### 7.1 CodeTwin 与 checker/oracle

CodeTwin 的 primary/diagnostic 分工、相同 snapshot/trace/schema/contract/candidate universe/order/mask、opaque candidate、sealed policy constant、`t0_noncode_view_hash`、serializer taint 和 AST denylist形成了可执行的代码必要性识别设计。`A11–A18` 的 480 worlds 是 primary，`A01–A10` 的 600 worlds只作 diagnostic；Shuffled-Repository 只检验 source sensitivity，不用错配 harm 证明代码正确。

visible checker 与 sealed oracle 的 image、imports、credentials、future fields 和 method-ID 边界也较完整。所有 digest、builder、mutation matrix 和 episode hash 仍是 `PENDING-IMPLEMENTATION`，所以只能判设计接口通过，不能声称隔离已经实测通过。

### 7.2 FULLPOLICY-D60 与 65 条枚举

`FULLPOLICY-D60-v1` 的算式 `8×4×3×2×2×3=1,152` 正确。它使用全部21 slots比较 Full、No-PassiveInfo 和 No-D60，seeds `910..912` 与 train、validation、主 test、CodeTwin、calibration 和三个 ENUM tiers 零交叉。D60 选择率、后继 action 和 belief change只作 held-out 机制结果，不回调 profile、threshold 或 utility。

`65=Σ_{k=0}^4 4!/(4-k)!` 也计算正确，但只枚举 hash-frozen 的 SR、SV、CP、WC 四个代表 slot 的 ordered subsets，再由固定 `π_ref` continuation。规格已诚实称其为 partial ranking，而非十八 slot、D60、EX/AB 的 full oracle。这个范围不构成泄漏。

### 7.3 split 与 risk qualification

world sibling group、repository/app、migration、injection template、workload/fault seed、CodeTwin pair 和 retrieval index 均有 split 约束。`VAL-SELECT`、`VAL-CAL-POLICY`、test 和机制 held-out worlds分离，test只在 checkpoint、utility、operator threshold 和 candidate policy冻结后解封。

五个 `γ` policy在同一冻结 `CAL-GEN-v1.2` iid simulator superpopulation 上用1,000个独立 draw完整执行，15项 simultaneous qualification覆盖每个候选的 severe `d∨r`、success 和相对 reference noninferiority。只要 generator、policy hash 和真实 rollout按 manifest实现，这个程序可以支持该 generator 总体上的边际资格。它不能支持逐 state conditional guarantee、`v/u` 保证、现实 repository superpopulation 或 OOD 保证；现有正文大体已经承认这一边界。

### 7.4 18 app、72 migration 与推断单位

18个合成 app、每个4个 migration motif产生72项候选；少于60项通过、任一 test app少于3项或少于8个 test families保留即撤销 benchmark scope。这个纳入门、八个 app 级 paired effects、small-cluster wild bootstrap、randomization sensitivity 和 leave-one-app-out足以构成一个有限 benchmark 的严谨设计。

它不把72个 migration当成72个独立 repository units，也没有把四种 motif当作从现实 migration 总体随机抽样，因而不能提供一般意义的 Repo-OOD。正式稿应把 `Repo-OOD` 首次出现明确写成“合成 benchmark 内的 held-out repository-family slice”，并持续以八个 app为最高单位。实际功效、区间宽度和跨 app 稳定性是待运行结果；建议在解封前登记最小可检测效应，但不能因当前没有效应值判设计失败。

## 8. Benaroch 理论责任、coding-agent 必要性与直接近邻

### 8.1 理论下推

Benaroch（2018）原文确实承担以下构念。

- 源 L67 把 real option 定义为随不确定性展开而改变投资进程的权利而非义务。
- 源 L59、L69–L75 区分被动等待信息和主动部署 mitigation，并允许零项或多项 mitigation按不同序列执行。
- 源 L75、L128–L130、L311–L315明确说明 mitigation 的成本与不确定性作用受既往序列条件化，可表现为替代、互补或协同。
- 源 L81、L102、L229–L247区分 learning、prevention 和 coping。learning获得信息，prevention控制不确定性来源，coping降低风险事件发生后的损害。
- Appendix A 的 lattice给出离散决策点和 optional mitigation，但并没有给出本文的神经状态、joint SMDP、mask 或张量 tying。

把 `D60` 映射为 passive waiting，把 SR/SV 映射为 learning，把 WC 映射为 prevention，把 CP 映射为 coping，并把 EX/AB映射为 exercise/non-exercise，是有理论机制依据的情境化设计。必须继续限定两点：Benaroch 的 learning 是改变主观不确定性分布，不自动证明任何具体 checker有信息；Benaroch 的 path dependence允许完整路径条件作用，并不推出“低秩、只到二阶、共享 role gain”。

现有规格已把低秩二阶 tying、三阶 mixed difference为零和 role sharing标为本文可检验算法推论，没有伪称为 Benaroch 原句。这个理论责任可以保留。若公平 generic在 finite-data、unseen-combination和 held-out slices 上经验等效，必须撤销理论算法贡献；这是合理的结果生死门。

### 8.2 coding-agent 删除检验

本候选不是把普通数据库控制器直接改名为 coding agent。Full 模型读取 old/new source、ORM/query lineage和公开 policy；CodeTwin保持非代码状态与候选完全相同，只改变可见 repository semantics；No-Source baseline删除该 code channel。这个设计能检验代码是否在 matched physical state 中改变正确 mitigation及外部 harm/cost。

但是 coding-agent 身份仍是待验主张。若 No-Source复制 Full 的外部结果，或 source只改变 action ID而不改善 `d∨r,v,u,w,success/cost`，本题只能降为数据库控制器，不能占用 coding-agent thesis题位。尚未出现这种结果不能成为当前设计否决理由。

### 8.3 截至 2026-08-16 的直接近邻边界

现有近邻表覆盖 DBA-Bench、BridgeScope、Cordon、DART、ARBITER、FreshBrew、BranchBench 和 Change2Task 的不同边界，未发现一篇已经同时提供 repository-conditioned live-schema-migration、optional mitigation path、wait/exercise/non-exercise、可训练 joint consequence kernel与 policy-level外部风险评价的直接替代。这是检索后的范围判断，不是唯一性证明。

必须补入更近的 [AgenticDB, arXiv:2606.20318v3](https://arxiv.org/abs/2606.20318)。其全文 §4 明确给出跨 DBMS/OS 的 safe action catalog、context-grounded诊断、连续 diagnose–act–observe、Validator、Executor、Recovery、Auditor以及依据执行反馈继续、换方向或终止的 closed loop。它比只提供 benchmark 或 typed guard 的工作更直接覆盖“数据库 agent根据反馈安全执行并恢复序贯动作”。

AgenticDB仍未覆盖本题的核心组合：它保持 LLM参数固定，目标是 performance reconfiguration，不研究 code-conditioned live schema migration、zero-or-more mitigation option lattice、terminal exercise/abandon、学习型 joint physical kernel 或本文的风险 qualification。因此它不会直接杀死题目，但遗漏它会夸大现有研究空白。正式 ACK/LIM 必须先承认其闭环、安全 action与 recovery能力，再把剩余差异限定到上述可检验机制。

BranchBench只提供 branch–mutate–evaluate基础设施，Change2Task只提供从 repository变化重建任务的路线；它们可支撑环境构造和 lifecycle边界，不能充当现成的 migration option-policy label。

## 10. 设计失败与未来结果门

### 10.1 当前必须修复的设计门

下列问题无论未来实验数字多好都不能被结果补救：

1. joint kernel不生成 typed action result、`g'`、`κ'` 和 `ℓ'`，因而 planner next state不唯一。
2. duration likelihood 的 exact-equality、Voronoi cell 和 piecewise-linear density 三种口径没有统一。
3. public evidence写入 `C_v` outcome分母，使策略能用检查数量操纵终局结果。
4. exact main/pair masks没有物化，共享 mixture residual可在边际化后绕过 head-level physical zero。
5. 公平 generic residual架构仍须字段级物化，并随共同 kernel/mask获得完全相同接口。
6. `01H-B` 至少七个自称功能同位行存在错锚、功能错位或一行多命题。
7. 直接近邻 ACK/LIM漏掉 AgenticDB 的安全闭环数据库重配置能力。

这些修复会改变 kernel state schema、loss/labels、planner branch、ledger endpoint、mask artifact和句级账，必须产生新的规格/manifest/责任账版本与新 SHA，不能在实现代码中静默补丁。

### 10.2 只能由真实实验决定的生死门

以下项目仍是 `RESULTS PENDING`，不能因当前为空而判 NO-GO，也不能在正文写成已经成立。

- 四类 operator 是否在真实隔离环境中产生可识别且可逆/可控的效果。
- `D60` 的 passive observation是否包含 latent-condition信息并改变后续 action。
- 至少两个预注册冲突分层是否出现排序反转。
- CodeTwin 的 code channel是否降低外部 harm或cost，而不仅改变预测和 action ID。
- 删除 pair、role、defer、non-exercise 或 typed persistence是否改变实际行动和外部结果。
- 主模型是否相对 `G-PhysicalFactoredSMDP` 在 finite-data、unseen-combination和有限 held-out synthetic families上形成 safety–success–cost 改善。
- policy qualification、Pareto关系、small-cluster区间与等效检验是否达到预注册阈值。

如果修复后的主模型仍未跑赢公平 generic，或上述机制没有外部结果作用，应按预注册规则撤销理论算法贡献或 coding-agent身份。这是正确的实证生死门，不反推当前必须先把设计写成唯一可执行对象。
