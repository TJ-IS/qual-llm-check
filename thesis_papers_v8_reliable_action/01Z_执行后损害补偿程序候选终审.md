# 执行后损害补偿程序候选终审

## 0. 审查对象、截止日与证据边界

本文件终审一个严格替代候选。coding agent 已经执行了错误或有害动作，代码、配置、依赖、进程与模拟外部服务的状态已经发生变化。候选系统需要从执行轨迹与当前跨资源状态中学习并执行最小补偿程序，使可执行不变量重新成立，避免恢复动作造成二次损害，并尽量保留原任务中仍然有效的工作。

检索截止日为 2026 年 8 月 16 日。直接工作核验覆盖 post-execution harm recovery、agent compensation、semantic recovery、transactional tool use、selective rollback、coding-agent recovery、AIOps self-healing、Sagas 与自动恢复策略。AIS Basket 理论核验覆盖 digital HRO、mindfulness-based reliability、digital resilience、goal-directed error recovery、IS incident recovery、real options 与业务连续性。核心结论只使用已经取得全文或可定位原文段落的证据。仅取得摘要的材料只用于提醒检索边界，不承担方法细节或撤题结论。

本文件是内部选题终审，不是正式论文正文。文中提出的模型、样本数、算力和检验均为钢人化研究设计。没有运行本候选的训练或实验，不报告任何候选性能、效应量或显著性。

## 1. 终局判定

**最终判定：HIGH-CONFIDENCE NO-GO，无保留，不重开题位，不降格为另一篇论文的主要模块。**

这个判断不是因为补偿恢复不重要，也不是因为实验尚未运行。执行后的删除、覆盖、错误依赖更新、错误进程操作和外部副作用会形成真实损害，恢复动作还可能扩大影响范围。撤题来自三项已经成立的终止条件。

第一，旧案 00V 所审的最强版本与本候选实质同构。本次把状态明确扩展到代码、配置、依赖、进程和模拟外部服务，并把输出收窄为最小 compensating program，仍然没有改变其分析单位、行动结构或主要结果。它仍是从 post-harm state 生成 effect-conditioned recovery program。

第二，新增直接工作进一步覆盖了旧案尚可声称的剩余能力。RAC 已经把工具调用记录为持久事务日志，重建执行图，寻找补偿对与参数映射，并按依赖顺序执行 post-hoc compensation。Mnemosyne 已经提供 effective-state projection、dependency-closed compensation、evidence-preserving repair 与 bounded reactive repair。Ikeuchi 等人在 2020 年已经从日志学习可执行恢复命令序列。PASE 又明确把恢复定义为 recovery-primitive program synthesis，并用学习型 world model 验证计划。单篇工作没有完整覆盖拟议的 coding-specific 五类资源，但本候选的新增部分已经被压缩为把既有恢复工件迁移到 repository-aware 状态并扩大动作语法。

第三，没有找到能够合法产生非交换计算算子的 AIS 理论。Salovaara、Lyytinen 与 Penttinen 的 digital HRO 是最强候选，因为它明确区分 epistemic 与 pragmatic operations，并把 digital core、improvement layer 和 anticipation layer连接起来。原理论却把高层 context-sensitive pragmatic control 放在人类 mindful operations 中，没有规定补偿节点、effect edge、程序最小性、动作先后或 loss direction。把 frame adequacy 做成 belief，再在低 adequacy 时取证、隔离或升级，是合理的安全门，但同信息的 constrained POMDP 或 world model 可以逐输入复制。其余理论只提供恢复结果、组织容量、人类学习或服务满意度，层级更远。

因此，00V 的撤题条件没有被新数据、新理论或严格不同的行动结构解除。新增检索使 NO-GO 更强，而不是为旧题换名重开。

## 2. 旧案 00V 的先验约束与本次增量

### 2.1 00V 已经否决的对象

00V 的原候选已经包含四个核心任务。

1. 从 agent trace、repository、process、service state 与 hidden invariant failure 中定位关键故障。
2. 构造 typed effect graph，区分可逆、可补偿和不可逆状态，并保留仍然有效的下游工作。
3. 生成低层可执行 patch 或 action sequence，而非自然语言恢复计划。
4. 以功能恢复、残余损害、二次损害、任务保留和成本评价实际执行结果。

本次候选只是把第三项命名为 minimal compensating program，并把跨资源集合写得更精确。模型仍需完成相同的 effect reconstruction、action synthesis、counterfactual selection 与 invariant verification。若没有新的理论算子或直接数据，重开会违反旧案的终局性。

### 2.2 只有三类证据本可重开

在阅读 00V 后，本次预先规定只有以下证据可以解除旧判。

- 出现公开、可复放的 paired post-harm execution data，同一有害前缀后包含多条可执行补偿分支及外部结果。
- 出现一个 AIS 理论，能够从原构念推出补偿程序特有的状态、顺序、约束或目标，并在冲突情境中与通用策略产生方向差异。
- 出现严格不同的行动结构，使研究不再是通用 effect-conditioned recovery，例如新的组织承诺关系或不可由现有 agent transaction 表示的责任边界。

检索没有找到前两类证据。第三类也没有出现。RAC、Mnemosyne 和自动恢复命令学习反而直接占据了原先可能用来重开的技术空间。

## 3. 研究对象的最强可辩护定义

### 3.1 真实损害

候选处理的损害不是一次错误文本输出，而是 coding agent 已经改变持久状态后出现的可执行后果。至少包含以下五类。

- 代码损害。删除或覆盖实现，绕过检查，修复一个缺陷却制造安全或功能回归。
- 配置损害。改变权限、feature flag、CI、deployment 或运行参数，使代码在不同环境表现不一致。
- 依赖损害。更新 lockfile、包版本或来源，造成 ABI、许可、安全或可重复构建问题。
- 进程损害。终止错误进程，启动冲突服务，留下 stale lock、端口占用、缓存或未完成任务。
- 外部状态损害。向模拟数据库、对象存储、工单、消息、邮件或部署服务写入已经可见的结果。

风险影响 repository 所有者、开发团队、下游服务用户与组织运行过程。二次损害包括过宽 rollback 删除良性工作、错误补偿使依赖链断裂、隐藏故障证据、重复外部调用和在恢复过程中产生新的不可逆效果。

### 3.2 介入时点

介入发生在至少一个有害动作已经成功返回、状态已经改变、随后由 verifier、运行错误、用户反馈或环境信号确认发生损害之后。若动作尚未提交，问题属于 Cordon 或 Atomix 的 staging 与 pre-commit containment。若只是在首次失败后选择 retry 或 escalation，问题属于 CodeRescue 或 ToolMaze。若只是给仍在运行的 agent 一句纠偏 guidance，问题更接近 Wink 或 PROBE。

### 3.3 可见、隐藏与受污染状态

推断时可见信息包括用户任务、初始 commit、agent thought-action-observation trace、工具输入输出、文件 diff、配置与 lockfile diff、进程表、测试日志、mock service receipts、已声明权限和可查询 provenance。

推断时不可见或不确定的信息包括隐藏功能与安全不变量、真实用户损失、未被日志捕获的外部效果、并发 actor 的后续行动、未来依赖行为和 action 的完整反事实后果。repository 内容、工具输出和依赖 metadata 也可能因原错误或恶意内容而受到污染。

训练与评价可使用隐藏 oracle，但 oracle 不得进入 agent context。否则模型只是在读取答案，不是在不完全信息下恢复。

### 3.4 正常、风险与纠正动作

正常动作包括读取状态、查询 provenance、运行隔离探针、保存证据、暂停受影响进程和执行只读验证。

风险动作包括全仓回退、删除测试或日志、强制覆盖配置、无差别重装依赖、重复外部写入、跳过幂等键、在不清楚影响闭包时重启共享服务，以及把所有失败都视为可逆。

纠正动作包括 scoped code patch、配置恢复、dependency pin 或 downgrade、选择性 process restart、缓存与锁 reconciliation、dependency-closed rollback、domain compensator 调用、quarantine、outbox cancellation、联合 invalidation、证据保全、人工升级和停止。

输出若只剩 rollback、retry、escalate 三选一，就退化为恢复路由。主要工件必须输出带目标、参数、先决条件和验证步骤的可执行程序。

## 4. 直接近邻的全文终审

### 4.1 post-execution harm recovery 与 coding-agent recovery

[Human-Guided Harm Recovery](https://arxiv.org/html/2604.18847) 明确定义从 harmful state 返回 safe state 的 post-execution safeguard。它构建 50 个 BackBench 场景，收集 1,130 对恢复计划判断，训练 reward model 并对候选计划重排。原文同时明确，自然语言计划只是 executable trajectory 的 high-level proxy，原因是低层 GUI 或 OS state 的标注与评价代价过高。因而本候选不能把自然语言计划重排、人类偏好分数或八维 rubric 作为主要算法贡献，但低层可执行分支数据仍是公开缺口。

[AgentRx](https://arxiv.org/html/2602.02475) 发布 115 条失败轨迹，标注 critical failure step 与九类 failure taxonomy，并用 constraint synthesis、validation log 和 judge 定位 first unrecoverable failure。它提供诊断监督，不提供从同一 post-harm state 出发的补偿分支或执行后状态。

[Wink](https://arxiv.org/abs/2602.17037) 来自真实 coding-agent traffic，识别 misbehavior 并异步给予 targeted intervention，使 agent 回到 productive path。它证明 coding-agent recovery 是真实部署问题，但行动是 trajectory guidance，不是 persistent cross-resource compensation。

[CodeRescue](https://arxiv.org/abs/2607.19338) 在五个 coding benchmark 的失败后 rollout 上训练 supervised router，在继续 cheap recovery 与 escalation 之间作预算校准选择。它直接覆盖 post-failure routing、成本控制和 conformal deployment frontier，不能作为本候选的辅助头或主要比较弱基线。

[PROBE](https://www.microsoft.com/en-us/research/publication/debugging-the-debuggers-failure-anchored-structured-recovery-for-software-engineering-agents/) 把失败后的 telemetry、diagnosis 与 bounded guidance 连接起来，并覆盖 repository repair、enterprise workflow 和 AIOps service mitigation。它仍把 guidance 交给下一次尝试，不执行拟议的跨资源 compensating program。

### 4.2 agent transaction、compensation 与 semantic recovery

[RAC](https://arxiv.org/html/2605.03409) 是本候选最直接且不可绕开的工作。它把工具开始、完成和错误事件写入 persistent transaction log，失败时先 retry 和寻找 alternative，再重建 execution graph，取得 compensator 与 input mapping，并按依赖顺序执行补偿。补偿对可由 framework API 或 MCP annotation 提供，也可由 LLM 发现。它在扩展的 tau-squared-bench 与 REALM-Bench 上处理动态和不可解故障。

RAC 的已声明局限只留下狭窄空间。当前实现假设找不到 compensator 的工具没有副作用，默认回滚全部已记录操作，而且没有实现 scope-aware partial compensation。这恰好暴露 learned scope 与 undeclared compensator synthesis 的空间，却不能让新论文再次主张“agent compensation”。新工件必须证明学习的跨资源程序在真实外部结果上超越 RAC 的 declared pairs、LLM discovery 和 full rollback，而不是把 scope predictor 接到 RAC 前面。

[Mnemosyne](https://arxiv.org/html/2607.00269) 又覆盖了 RAC 留下的一部分空间。它将 LLM 动作视为无权 proposal，用 declared executable constraint set 决定 admission，并在 committed transition log 上构造 effective StateView。其 dependency-closed compensation 防止 orphaned dependents，evidence-preserving repair 防止删除失败测试或告警证据，localized cascading repair protocol 只修改 disruption 的 dependency closure，并把 repair 重新送入同一 admission gate。其安全保证明确相对于 constraint set，而不声称 constraint set 语义完备或 repair 全局最优。

Mnemosyne 是 2026 年 7 月预印本，不能替代同行评审证据。它仍是最接近的公开工作，因为本候选的“恢复可执行不变量、避免二次损害、最小改动”分别对应其 constraint validity、evidence and dependency preservation、bounded edit radius。剩余部分主要是从 coding state 学习 constraint、transition 与 proposal，而不是新的恢复问题。

[DART](https://arxiv.org/html/2605.23311) 区分机械可回滚与 semantic recoverability。它定位 failed instance，认证 boundary，检查 committed downstream consumers 与 effect policy，只有存在 admissible checkpoint 才做局部恢复。其定理要求在回滚上游时对依赖的下游进行 compensation、invalidation 或 joint rollback。由此，依赖闭包和良性工作保留不能再作为本候选的新机制。

[Atomix](https://arxiv.org/abs/2602.14849) 用 epoch、per-resource frontier、buffered effect、compensation handler 与 retry 为 agent tool calls 提供 transaction semantics。[Cordon](https://arxiv.org/abs/2606.17573) 用 task-level semantic transaction 绑定 lineage、shadow state、staged external effect、delegated authority 与 audit metadata。[DeltaBox](https://arxiv.org/abs/2605.22781) 为 filesystem 与 process state 提供毫秒级 checkpoint 和 rollback。这些工作分别成为 effect execution、commit containment 与 sandbox reset 基线，不能重新命名为学习工件。

[Revisable by Design](https://arxiv.org/abs/2604.23283) 已经区分 idempotent、reversible、compensable 与 irreversible action，并用 earliest-conflict rollback 保留有效前缀。该分类可用于数据 manifest，不能作为理论创新。

[Dependency-Guided Rollback Repair](https://arxiv.org/html/2608.10502) 在 memory-augmented agent 上构建 typed memory-to-action graph，找到受影响闭包，保留独立可信状态并 selective replay。其原文边界也说明不可逆外部效果需要可重置接口或 domain compensator。它不处理代码与进程，但直接覆盖 dependency slicing、benign preservation 与 selective replay。

### 4.3 学习型自动恢复与自愈系统

[Ikeuchi et al. 2020](https://arxiv.org/abs/2003.10784) 是旧案遗漏的关键历史近邻。论文把 log IDs 作为输入，把 recovery command words 作为输出，用 Seq2Seq 学习可变长命令序列，并以执行命令后系统是否恢复定义成功。真实 OpenStack 实验只含 13 类 component-unavailable failure，训练监督来自既有 operator commands，模型不追踪 code/config/external effect，也没有二次损害 oracle。范围较窄不改变其直接性。学习“日志到可执行恢复命令”已经是正式 NOMS 研究问题。

[Joshi et al. 2005](https://doi.org/10.1109/RELDIS.2005.11) 与其后续 probabilistic model-driven recovery 将不完美监控、Bayesian diagnosis 和 Markov decision control 联合起来选择恢复动作。[Zhu and Yuan 2007](https://doi.org/10.1109/DSN.2007.11) 用 offline reinforcement learning 从 recovery history 生成恢复规则。它们说明 belief-state recovery、诊断与动作联合优化不是 agent 时代才出现的算法结构。

[PASE](https://arxiv.org/html/2607.01595) 以 logs、metrics 和 alarms 构造语义状态，从 recovery primitive library 生成多步计划，用 neural-symbolic world model 预测 primitive 后的 latent state 与 health delta，再用 SAC 优化 prompt embedding。这个预印本在数据责任上存在明显边界。它使用的 Failure-Dataset-OpenStack 原始资产提供 injected fault、workload、effects、logs 与 fault-free round，不自然提供论文所需的大规模 recovery-plan interaction labels。论文没有给出足以从公开数据重建每条 primitive outcome 的 manifest。故本终审不采用其数值结果，也不把它视为可靠 benchmark。不过，它已经公开提出“恢复程序综合加 world-model 验证”的通用架构，候选不能再把该组合本身作为新能力。

### 4.4 harm generation 与评价环境

[SABER](https://arxiv.org/abs/2606.01317) 在 stateful project workspace 中按最终环境状态评价 coding-agent operational safety，并公开任务与 verifier 资产。它能提供有害前缀、workspace delta 和 harm predicate，却没有同一有害状态后的 executable compensation lattice。

[Agent Meltdowns](https://arxiv.org/abs/2605.19149) 在 benign error 下系统注入 local 与 remote failure，表明 agent 可能通过越权探索扩大损害。Noisy Container 可作为 harm-prefix 生成器，却没有标注补偿程序。

[ToolMaze](https://arxiv.org/abs/2606.05806) 用 DAG topology 与 explicit or implicit、transient or permanent perturbation 评价 dynamic replanning。其动作目标是绕过失败工具或终止，不是修复已经外化的损害。

BackBench、SABER 和 Agent Meltdowns 共同证明 post-harm risk 可以运行评价。它们仍未提供本候选所需的 paired program outcomes。

### 4.5 事务与补偿的历史基础

[Garcia-Molina and Salem 1987](https://doi.org/10.1145/38713.38742) 将 long-lived transaction 分解为可交错的子事务并由 compensating transactions 处理已完成步骤。[SagaLLM](https://arxiv.org/abs/2503.11951) 已把 Saga 式补偿带入 LLM-generated workflow。RAC、Atomix、Cordon 和 Mnemosyne 延续并扩展这条路线。

所以，LIFO compensation、predeclared inverse、retry、snapshot restore、dependency slicing 与 escalation 都必须作为 substrate 或 baseline。把它们拼成 pipeline 不能构成独立贡献。

## 5. 直接覆盖后的真实剩余空间

没有一篇已读工作同时满足以下全部条件。

- 研究对象明确是 coding agent 已经造成的持久损害。
- 状态同时覆盖 code、config、dependency、process 和 mock external service。
- compensator 不是预定义 inverse，而由训练数据产生低层可执行程序。
- action selection 使用实际 counterfactual execution，而非自然语言 judge。
- 主要目标联合约束 invariant restoration、secondary harm 与 task salvage。

这个交集在字面上仍为空。它却不足以支持 ISR 级新题，因为交集中的每个计算对象都来自既有技术近邻，剩余只是 domain composition。

若去掉 coding-specific feature extractor，核心算法变为：

\[
(\text{partial state},\text{effect history},\text{constraints})
\rightarrow
\text{recovery action program}
\rightarrow
\text{predicted outcome}.
\]

这正是通用 model-based recovery、constrained planning 或 program synthesis。repository information 增加状态维度，却没有改变决策问题的类型。理论必须产生一个通用模型不应当、或不能在同信息下复制的计算方向，候选才可能重开。第 6 节表明这一条件不成立。

## 6. AIS Basket 理论的层级与通用反证

### 6.1 Digital HRO 是最强候选，但仍然不合格

Salovaara、Lyytinen 与 Penttinen 的 [High Reliability in Digital Organizing](https://doi.org/10.25300/MISQ/2019/14577) 以 F-Secure 为案例，指出 algorithmic digital operations 受 frame problem 限制。原文将 operations 区分为 epistemic 与 pragmatic，并形成三层结构。core layer 依靠快速、可扩展却 mindless 的算法处理。improvement layer 对可见的 known unknown 进行监测和规则修正。anticipation layer 面向 unknown unknown，给 improvement layer 提供新视角。原文还区分 digital operations 的 epistemic role、pragmatic control role 与 pragmatic execution role。

这一理论能指出通用恢复模型系统性忽略的机制。模型可能把训练分布内的高置信恢复能力误当成对未框定状态的可靠理解，并在证据不足时继续 pragmatic mutation。理论因此支持一个 conflict direction。

- frame adequacy 高、effect scope 低且 constraint coverage 完整时，自动执行最小补偿。
- frame adequacy 低、耦合高或出现训练框架外证据时，先做 epistemic action，再隔离、保全证据或升级给人。

这是所有候选理论中最接近 forward/action 的下推。它仍没有达到不可替代性。

第一，原理论的分析单位是组织如何耦合人类 mindful operations 与数字 mindless core，使 collective mindfulness 作为系统属性涌现。一个自动 compensator 的 hidden vector 不是 collective mindfulness。

第二，frame problem 是算法表示边界的理论限制，不是一个已经有 gold label 的连续因子。用 OOD score、ensemble uncertainty 或 constraint coverage 近似 frame adequacy，是候选方法定义，不是理论原文给出的测量。

第三，理论指向人类在 core 外承担 context-sensitive pragmatic decisions。若忠实迁移，低 frame adequacy 时的核心动作应是人类升级，而不是由另一个模型自动合成更复杂的补偿程序。这会把候选变成人类监督或 C3 的证据获取问题。

第四，相同的 belief、uncertainty、scope 和 action costs 交给 constrained POMDP，便可得到完全相同的 inspect、quarantine、compensate、handoff 与 stop 策略。三层命名没有新增状态转移算子。

结论是 digital HRO 可支持“未知框架下不得自动扩大损害”的设计原则，也可解释 handoff。它不能产生补偿程序本身，因此不能承担本题的独立理论算法贡献。

### 6.2 Butler 与 Gray 的 mindfulness-based reliability

Butler 与 Gray 的 [Reliability, Mindfulness, and Information Systems](https://doi.org/10.2307/25148728) 区分 routine-based 与 mindfulness-based reliability，并讨论 IT 对可靠实践的支持。它可以解释何时标准化 recovery routine 应与例外处理结合。它没有规定跨资源 effect semantics，也没有给出从 observed damage 到 minimal program 的转换。若把 mindfulness 写成 uncertainty threshold，generic controller 可以复制。结论为背景可用，算法理论 NO-GO。

### 6.3 Digital resilience

Tim 与 Leidner 的 [Digital Resilience](https://doi.org/10.17705/1jais.00842) 明确定义个人、组织与社区通过 IS 的设计、部署和使用从 exogenous shocks 中恢复的 capacity，并以 assets、abilities、activities 与 continuity、adaptation、advancement 组织框架。

coding agent 自身错误是内生 action-induced harm，不自然等同于原理论的 exogenous shock。即使宽松视为 disruption，continuity、adaptation 和 advancement 也是恢复结果分类，不是 compensator grammar。把三者做成 output heads 或 reward terms，只会添加结果标签。删除理论名称后，图编码器、world model 与 decoder 不变。结论为结果解释可用，核心理论 NO-GO。

### 6.4 Goal-directed error recovery

Sein 与 Santhanam 的 [Learning from Goal-Directed Error Recovery Strategy](https://doi.org/10.1287/isre.10.3.276) 研究 novice end users 在 far-transfer tasks 中采用 goal and subgoal-oriented recovery 后的 system comprehension。原文明确，即使没有完全恢复，只要行为朝向目标也可归为 goal-directed；其研究关注 strategy adoption 对学习的影响，而不是 actual recovery；极严重与不可恢复错误也不在实验范围。

因此，goal decomposition 不能被直接改写为 compensating program supervision。原理论的 actor、mediator 与 dependent outcome 分别是人类 novice、认知策略和后续理解，不是 coding agent、程序结构和 invariant restoration。层级、机制与结果均不匹配。结论为 NO-GO。

### 6.5 IS incident recovery 与 service-dominant logic

Najjar、Kettinger 与 Kettinger 的 [IS Incident Recovery and Service Value](https://doi.org/10.1080/0960085X.2020.1869915) 研究 IS service provider 与用户互动中的 responsive handling、supportive communication、effective resolving actions、recovery satisfaction 与 service value。它的主要对象是服务接触与用户评价。recovery level 和 speed 可提示实践指标，无法规定代码、依赖或进程补偿。把 apology、explanation 或 fairness 作为额外结果会转移到人机沟通，不会改变程序正确性。结论为 NO-GO。

### 6.6 Real options、IS flexibility 与 business continuity

Benaroch 的 [proactive mitigation real-options model](https://doi.org/10.1287/isre.2017.0714) 能合法产生 learning、prevention、coping mitigation 的 impulse effects，以及 sequential mitigation 的 substitutive、complementary 和 synergetic interaction。它适合迁移候选，因为迁移在不可轻易逆转的 cutover 前拥有 wait-and-see、act-and-see、defer 与 abandon 的真实 option。

post-harm compensation 已经越过原始 commitment。此时任务不是决定是否投资，而是在已发生损害下恢复可接受状态。把每个 patch、restart 或 compensator 叫作 coping option，不会产生 option exercise 的经济语义，也没有自然的 underlying asset、exercise boundary 和 deferral value。若人工补齐这些量，模型退化为通用 distributional recovery controller。结论是该理论仍留在迁移题，不迁入本候选。

business continuity 与 organizational resilience 可以支持服务持续、恢复速度和组织影响的重要性。它们不规定低层状态与动作，结论同样为背景可用、算法 NO-GO。

### 6.7 理论终审总表

| 理论 | 原分析单位与结果 | 可合法下推的状态 | 是否改变 forward、loss 或 action | 通用替代能否复制 | 终判 |
|---|---|---|---|---|---|
| Digital HRO | sociotechnical organization；collective mindfulness 与 high reliability | frame insufficiency、epistemic or pragmatic role、core or improvement or anticipation layer | 只改变未知框架下的自动化边界与 handoff | 能，belief-state POMDP 可复制 | 最强但 NO-GO |
| Mindfulness-based reliability | organizational routines 与 mindful practice | routine or exception context | 至多增加 exception gate | 能 | NO-GO |
| Digital resilience | individual, organization, community capacity；continuity, adaptation, advancement | outcome taxonomy | 只增加 outcome heads | 能 | NO-GO |
| Goal-directed recovery | novice strategy；system comprehension | goal and subgoal trace | 错误层级，且不以实际恢复为结果 | 不应迁移 | NO-GO |
| IS incident recovery | provider-user service encounter；satisfaction and value | communication 与 resolving quality | 不改变 executable compensation | 能 | NO-GO |
| Proactive mitigation real options | IT investment；uncertainty 与 option value | mitigation impulse 与 interaction | post-harm 无真实 exercise boundary | 能，且构念错置 | NO-GO |

## 7. 钢人化后的算法工件

以下设计展示本候选在技术上可以有多硬。它不是保留题位的建议，而是用最强实现检验是否仍被 generic model 与直接工作覆盖。

### 7.1 输入与图状态

每个训练实例以同一 post-harm snapshot 为起点。输入由任务、执行轨迹和跨资源状态组成。

\[
\mathcal{I}_t=(q,c_0,H_{0:t},G_t,O_t,P_t).
\]

其中 q 是任务与权限，c0 是初始 commit，H 是 action and observation history，G 是异构时序 effect graph，O 是当前可见 observations，P 是可执行但对 agent 隐藏实现的 policy and invariant handles。

图节点至少包括 file、symbol、config key、package version、process、port、database object、mock external artifact、effect event、task obligation、invariant 与 evidence。边包括 reads、writes、imports、configures、launches、depends-on、produces、consumes、commits、compensates、invalidates 与 evidences。

节点张量 X 的字段包含 type embedding、content or diff representation、version or hash、owner、visibility、commit status、reversibility class、latest observation time、invariant history 和 taint bit。边张量 R 包含 relation type、direction、timestamp、confidence 与 source event。轨迹编码 H 属于 R 的 L 乘 d，图编码 X 属于 R 的 V 乘 d，edge encoding 属于 R 的 E 乘 d。

### 7.2 输出与真实动作

模型输出一个受类型约束的程序：

\[
\pi=(a_1,\ldots,a_K),\quad
a_k=(opcode,target,args,precondition,expected\ effect,verifier).
\]

opcode 可取 inspect、preserve-evidence、patch-code、restore-config、pin-dependency、restart-process、reconcile-state、call-compensator、invalidate-dependent、quarantine、notify、handoff 与 stop。target 由 pointer network 指向图节点或 bounded scope。args 从可见状态复制或由 typed decoder 生成。precondition 和 verifier 必须在每步执行前后检查。

推断时不是只返回分数。runtime 在隔离环境执行一个动作，观察真实 state delta，更新图和 belief，再决定下一动作。遇到 verifier failure、effect scope 扩张或低 frame adequacy 时，策略可以停止、隔离或升级。

### 7.3 架构

最强版本可由五个可训练部分组成。

1. Trajectory encoder 将 task、tool calls、outputs 与 diffs 编码为 H。
2. Heterogeneous temporal graph encoder 在 resource 与 effect relations 上做 relation-specific message passing，输出 Z 属于 R 的 V 乘 d。
3. Belief and world model 预测 action 后的 node delta、invariant probability、external effect 与 uncertainty。
4. Typed program decoder 自回归产生 opcode、target pointer、arguments 与 verifier pointer。
5. Constrained critic 在真实执行分支上估计 residual harm、secondary harm、task salvage、step cost 与 human burden 的分布。

工件包括 graph encoder checkpoint、world-model checkpoint、program-decoder checkpoint、critic or calibrator checkpoint、typed action vocabulary、execution manifest 和 hidden-oracle manifest。仅有一个 risk head 不足以成为本题。

### 7.4 损失

可预注册以下目标。

\[
\mathcal{L}=
\lambda_{tr}\mathcal{L}_{transition}
\lambda_{inv}\mathcal{L}_{invariant}
\lambda_{prog}\mathcal{L}_{program}
\lambda_{rank}\mathcal{L}_{counterfactual}
\lambda_{safe}\mathcal{L}_{secondary}
\lambda_{cal}\mathcal{L}_{calibration}.
\]

transition loss 预测每个 action 的实际 state delta。invariant loss 预测隐藏 verifier outcome，但训练时只给 outcome，不给 oracle implementation。program loss 学习已执行成功程序。counterfactual loss 在相同 post-harm state 的分支间学习安全、salvage 与成本的 Pareto preference。secondary loss 对新增 harm 或 evidence destruction 施加约束。calibration loss 约束 abstain and handoff threshold。

若采用 offline RL，还需以 conservative objective 限制未在数据中覆盖的危险动作。该目标仍是 generic constrained model-based RL，没有理论专属项。

### 7.5 Digital HRO 的最强下推

为了给理论最大机会，可以加入四个显式状态。

- f_t：当前观察落在已知 recovery frame 内的 posterior。
- e_t：epistemic action 对后续 belief reduction 的预测值。
- c_t：effect graph 的 coupling 与 committed-consumer exposure。
- l_t：core、improvement、anticipation 三层责任标签。

forward 时先比较自动 pragmatic action 与 epistemic or handoff action：

\[
a_t^*=\arg\min_a
\mathbb{E}[harm+cost-task\ salvage]
\eta(1-f_t)\,pragmatic\_exposure(a)
\rho c_t\,blast\_radius(a).
\]

理论冲突情境是：generic task-success model 在一个高置信但 constraint coverage 低的未知错误上立即 patch；theory-factored model 先 inspect、quarantine 或 handoff。中和实验可打乱 f_t、交换 epistemic and pragmatic role、删除 layer tag，观察自动 mutation 与二次损害是否上升。

这仍然不能救题。f_t、c_t、exposure penalty 与 information action 都属于标准 POMDP 可表达量。l_t 没有原文给出的可执行更新律。等参数 generic model 获得相同字段和 action outcome 后可以学习同一边界。

## 8. 可运行数据环境与监督可识别性

### 8.1 严谨自建环境

若不考虑终判，一个可运行环境可由以下部分组成。

- 选择许可明确、测试可离线运行的 Python、JavaScript、Java 与 Rust repositories，并固定 commit、依赖 cache 和 toolchain。
- 使用 Docker 或 microVM 隔离每个 episode。filesystem 与 process state 由 DeltaBox、CRIU 或普通 snapshot reset。
- 附带本地 PostgreSQL、object store、package registry、CI runner、deployment controller、mail、chat 和 issue service mock。所有外部 endpoint 只存在于隔离网络。
- 从 SABER、Agent Meltdowns 和真实 coding-agent failure taxonomy 构造 harm templates，再让多个 coding-agent scaffold 在权限边界内实际产生 harmful prefixes。
- 对每个前缀冻结 pre-harm、post-harm snapshot、effect log、receipts、hidden invariants 和 task obligations。
- recovery action 只能调用 typed primitives。任何攻击性或不可逆试验都停留在公开代码和隔离 mock，不连接真实账户、凭据或生产系统。

### 8.2 样本与标签

样本单位是同一 post-harm state 下的一条实际执行分支，而不是一个自然语言方案。候选 programs 来源可包括 RAC handler composition、DART closure、通用 planner、coding agent proposals、mutation of successful human-authored programs 与 bounded enumerator。

每条 program 必须在相同 snapshot、相同 seed family 和相同 resource budget 下执行，记录：

- 每个 action 的 typed state delta。
- 每项 hidden invariant 的 pass、fail 与 severity。
- 原始损害是否清除。
- 新增 secondary harm。
- 保留的 task obligations 与最终 task success。
- 外部 mock effects 的 remaining exposure、duplicate 与 compensation status。
- action count、wall time、tool calls、token or GPU cost 与 handoff。

监督信号来自 deterministic hidden verifiers、service receipts、diff and process facts、dependency graph checks 和 task tests。LLM judge 只能用于人工难以形式化的补充评价，不能成为 primary safety label。

### 8.3 反事实分支的识别问题

公开资产没有上述 paired lattice。自建也面临四个不可消除的偏差。

1. 若 gold programs 来自预定义 handler，模型主要学习 RAC 的 handler selection。
2. 若 programs 来自同一个 LLM planner，训练支持被 planner proposal distribution 限制，最优程序不可识别。
3. 若穷举 action sequence，跨资源参数空间组合爆炸，只能覆盖短 horizon 和人工 primitive library。
4. mock service 使结果可重复，却不能证明真实邮件、部署、支付或用户沟通等不可逆效果能够恢复。

可以通过 randomized branch execution、common random numbers、diverse proposers 与 held-out primitive composition 缓解偏差。它们不能把数据变成理论专属监督。

### 8.4 划分与泄漏隔离

训练、验证和测试按 repository family、organization、harm generator、resource topology 与 compensation family 分组。建议先按 repository 与时间切断，再在 test 中保留未见 harm and topology 组合。不能把同一 post-harm snapshot 的不同分支分到不同 split。

隐藏 test 不暴露 gold program、handler name、oracle source、future state、task ID shortcut 或 seed。agent context 不含 hidden tests。依赖 cache、mock service IDs 与 filenames 必须去除能够编码标签的固定模式。所有 split 由 manifest 冻结，记录 commit SHA、image digest、package hashes、random seeds、agent model version 与 tool policy。

### 8.5 算力与复现工件

识别性 pilot 可从 20 个 repository、每个 3 类 harm、每类 8 至 16 条 program branch 开始。只有确认相同 state 的 branch outcomes 有足够方差，才扩展到 100 至 200 个 repository。完整执行可能需要 64 至 128 个 CPU cores、256 至 512 GB RAM、数 TB snapshot storage，以及 2 至 4 张 48 GB GPU 训练 graph world model 与 decoder。这里是计划估计，不是已经消耗的资源。

复现包应包含 environment builders、task and harm manifests、typed action schemas、oracle containers、split manifests、all checkpoints、optimizer states、configs、seed list、container digests、execution receipts 与 metric scripts。

## 9. 最强基线、公平比较与外部结果

### 9.1 直接系统基线

1. RAC，分别使用 API or MCP declared pairs、LLM-discovered pair 与 full rollback。
2. Mnemosyne，以 dependency-closed compensation 和 LCRP 作为最强 deterministic repair boundary。
3. DART，以 admissible local rollback、whole-task rerun 和 joint invalidation 比较。
4. Atomix 与 Cordon，以 staged effect、handler compensation 和 commit containment 比较。
5. DeltaBox snapshot restore 与 repository git revert。
6. Human-Guided reward-model plan selection，再由相同 executor 执行。
7. Ikeuchi-style log-to-command Seq2Seq。
8. PASE-style plan generator plus world model，若其代码不可复现则实施 matched reimplementation 并明确非作者实现。
9. CodeRescue、Wink 与 PROBE 只在各自匹配的 routing or guidance outcome 上比较，不虚构其跨资源补偿能力。

### 9.2 等参数通用替代

1. Raw trajectory Transformer，直接预测 typed action program。
2. Equal-parameter heterogeneous temporal GNN 加相同 decoder。
3. Equal-parameter latent POMDP or world model，接收相同 graph、oracle outcome supervision 与 action budget。
4. RAC or Mnemosyne substrate 加 generic program synthesizer。
5. Same architecture with anonymized theory fields，保持参数量、数据与 loss scalar 数量一致。

所有模型使用相同 base model、同一训练 execution budget、相同 candidate program budget、相同 hidden verifier calls 和 wall-clock cap。若一个方法使用更强外部 LLM，应单独报告能力与成本，不与本地小模型混为算法增益。

### 9.3 主要外部结果

主要结果必须是实际执行后的安全与任务结果。

- executable invariant restoration rate。
- residual harm severity 与 unresolved effect count。
- secondary harm incidence 与 severity。
- task salvage ratio、task success 与 preserved benign work。
- irreversible or externally visible mock exposure。
- duplicate compensation、compensation failure 与 recovery-during-recovery failure。
- handoff、refusal 与 stop rate。
- action count、tool calls、wall time、compute and token cost。

比较应在 matched task success 或 matched cost 下报告 harm，或报告 safety、salvage 与 cost 的 Pareto frontier。不能通过停止所有任务获得表面安全。

### 9.4 消融与机制干预

- 删除 world model。
- 删除 effect relations，只保留 raw trace。
- 删除 typed constraints，允许 free-form action。
- 删除 secondary-harm loss。
- 删除 task-salvage objective。
- 打乱 dependency edges。
- 打乱 frame adequacy。
- 交换 epistemic and pragmatic labels。
- 中和 core, improvement, anticipation layer。
- 用相同维度匿名 latent factors 替代理论状态。
- 将 learned programs 换成 RAC declared handler composition。

若 frame 或 layer 消融不产生预注册方向变化，理论机制失败。若匿名 latent factors 恢复相同结果，理论不可替代性失败。

### 9.5 统计与结果占位

以 post-harm episode 为统计单位，repository 与 harm family 作为分层因素。主要二元结果报告 paired bootstrap confidence interval 与 mixed-effects logistic model；severity and cost 报告 paired difference、cluster-robust interval 与 effect size；Pareto comparison 预注册 hypervolume 或 dominance criteria。多重主要结果控制 family-wise error 或 false discovery rate。

本候选未运行。结果表、模型性能、显著性与 effect size 均为空。未运行不是 NO-GO 的理由；直接覆盖、理论错置和通用可复制性已经独立触发撤题。

## 10. Coding-agent 删除检验

删除 coding-agent 身份后，把输入 actor 换成一般 computer-use agent、DevOps bot、workflow agent 或 cloud remediation controller，以下部分全部保留。

- post-harm effect graph。
- code 以外的 config、dependency、process 与 external resources。
- inspect、rollback、compensate、quarantine、handoff 与 stop action。
- world-model state transition。
- invariant restoration、secondary harm、salvage 与 cost objectives。
- RAC、Mnemosyne、DART、Sagas 与 POMDP baselines。

coding-specific 部分只剩 repository parser、symbol and test nodes、patch opcode 与 build or test verifier。把一类资源从 service object 换成 source-code object，不改变核心 recovery policy。PROBE、Wink 与 SABER 证明 coding context 真实，却没有使补偿算法依赖 coding agent 的独特意图、代码生成过程或软件义务。

因此，coding-agent 删除检验大体成功。这是致命结果。一个 ISR 级 coding-agent 题目不能只靠输入中包含 repository 来维持身份。

若为了反驳而要求 program 必须修改 code，研究又退化为 multi-artifact program repair。此时应与 automated program repair、configuration repair、dependency repair 和 test-based repair 分别比较，跨资源只会扩大工程范围，不自动形成 IS 理论贡献。

## 11. Equal-parameter generic graph、POMDP 与 world-model 反证

### 11.1 表示等价

theory-factored model 使用的 f_t、e_t、c_t、layer、effect graph 与 action outcomes 都是 generic model 可观察或可监督的变量。给 equal-parameter GNN 相同 graph relations 和 node features，它可以通过 relation-specific weights 表示相同 coupling。给 latent POMDP 相同 observations、actions、cost 与 hidden-verifier feedback，它可以形成相同 belief 与 stopping policy。

### 11.2 目标等价

theory loss 只是在 generic expected harm、task salvage、information value、blast radius 与 handoff cost 上加权。没有一项只能由 digital HRO 构念定义。匿名变量加同方向 monotonic constraints 可以复现目标。

### 11.3 行动等价

在预注册 conflict case 中，generic risk-constrained POMDP 也会在不确定性高和潜在损害大时先 inspect 或 quarantine。Digital HRO 解释这种方向为什么在组织上合理，却没有排除通用决策理论。

### 11.4 可证伪门

若仍要 pilot，唯一有意义的检验是：

1. theory-factored 与 generic model 参数量差不超过 1%。
2. 输入、监督、训练 execution count、decoder 和 verifier 完全相同。
3. generic model 可以使用匿名的等维状态与同数量 loss constraints。
4. test 包含 high confidence but frame-incomplete、low coupling known frame、epistemic action costly 和 human delay costly 四类冲突。
5. theory model 必须在多个 unseen repository and topology 上同时改善 secondary harm 与 matched task salvage。
6. 打乱 f_t 或 role labels 后出现预注册方向退化，匿名 factors 不能恢复。

当前没有理论依据预期第 6 条成立。这个 pilot 最多检验一种 inductive bias，不足以在立项前推翻已经成立的 generic equivalence。

## 12. 与 C3、迁移候选和契约候选的边界

| 候选 | 决策时点与核心对象 | 与本候选的边界 | 边界失败条件 |
|---|---|---|---|
| C3 人审可信取证 | 固定 approval point 前后选择后果探针、证据顺序与 reviewer grounding | 本候选在 harm 已提交后直接恢复系统状态，不建模 reviewer belief 或 approval | 若忠实采用 digital HRO，在低 frame adequacy 时主要选择人类升级与证据，则进入 C3 |
| 状态迁移可靠行动 | 外部给定 migration target 下，在 cutover 前选择 learning、prevention、coping mitigation 与 commit timing | 迁移候选保留真实 defer and commit option；本候选已越过 harm commitment | 若用 Benaroch real options 组织补偿序列，本候选只是把迁移的 coping substrate 错置到事后 |
| 策略性编码子代理委托契约 | principal 面对有隐藏行动、目标冲突和 best response 的 coding worker，设计 contract and control | 本候选默认错误或有害 action 已发生，不学习 worker utility 或 incentive response | 若 harm 来自策略性 sabotage，应由契约候选处理 ex ante behavior；事后 compensation 仍是通用 runtime |

本候选与三者可以在时间上区分，却没有因此获得独立理论。作为共享基础设施，RAC、Cordon、Mnemosyne 或隔离 mock 可以被三题使用；“共享 substrate”不能成为第四篇论文。

## 13. 为什么不能降格为子模块

把本候选缩成 C3 的恢复动作库会改变 C3 的核心研究问题。C3 研究什么证据能使有限人审作出正确决定；自动补偿 program synthesis 需要另一套数据、模型和评价，反而稀释 reviewer mechanism。

把它放入迁移候选会重复 01D 已经明确排除的边界。迁移题的新增能力是 cutover 前对措施时机、交互和未来分布的学习；compensation 只是 predeclared coping substrate。若主要收益来自 learned rollback program，迁移题会退回已撤销 C4。

把它放入契约候选也不成立。契约研究要识别 worker 对 transfer、monitoring 和 control 的 best response。损害发生后的恢复并不识别激励机制。最多把 deterministic compensator 当环境保护层。

因此，本题不应以“工程模块仍有用”为理由保留研究贡献。工具和环境可以复用，论文题位撤销。

### 14.3 肖老师标准下的最终检查

情境、重要性、近邻承认、理论机制、计算映射、方法、评价和边界依次出现，没有在问题建立前堆叠模块。近邻段首先准确承认已解决能力，再按输入、状态、动作和结果限定，而不是用“尚未用于 coding”制造空白。理论段先回到原分析单位和 dependent outcome，再决定是否下推。算法段虽然完整，却被放在理论终审之后，防止技术复杂性掩盖理论失败。

## 16. 终局门表

| 硬门 | 最强证据 | 判定 |
|---|---|---|
| 安全损害真实且可测 | stateful workspace、external mock、hidden invariant 与 secondary harm 可运行 | PASS |
| coding agent 是不可删除的关键行动者 | 换成通用 tool or DevOps agent 后 recovery problem 保持 | FAIL |
| 公开数据可直接训练核心策略 | 没有同一 post-harm state 的 executable compensation lattice | FAIL |
| 自建数据可严谨执行 | 隔离多资源环境可建，但 action support、handler circularity 与 real irreversibility 仍受限 | PARTIAL |
| 独立可训练工件足够硬 | graph world model、typed decoder、critic checkpoints 可形成 | PASS |
| 直接近邻未覆盖 headline | RAC 直接覆盖 agent compensation；Mnemosyne 覆盖 bounded dependency-closed repair；NOMS 覆盖 learned commands | FAIL |
| 理论产生不可替代中间状态 | digital HRO 只产生 frame-aware automation boundary；其余理论更弱 | FAIL |
| 理论改变 forward or action 且 generic 不能复制 | equal-information POMDP/world model 可复制 inspect, compensate, handoff | FAIL |
| 不是 NL plan rerank、snapshot、slice、retry or escalation | 钢人版本超越这些组件 | PASS |
| 与 C3、migration、contract 独立 | 时间边界可分，但理论救援会进入 C3 或 migration | PARTIAL |
| 未运行结果证据边界清楚 | 没有候选结果句，所有规格均标为设计 | PASS |
| 00V 的重开条件成立 | 无新 paired data、无合法 theory operator、无新 action structure | FAIL |

任何一个理论不可替代性、direct coverage 或 coding-agent deletion 硬门失败都足以撤题。本候选同时失败三项。

**终局状态：NO-GO / TERMINAL / DO NOT RESERVE A PAPER SLOT / DO NOT RUN AN IDENTIFICATION PILOT。**

若未来出现新的公开 paired execution corpus 与一个真正规定跨主体承诺或补偿责任顺序的 IS 理论，必须从新的研究问题重新立项，再次检索 RAC、Mnemosyne 及其后续引用。不能以本文件的钢人化架构或 00V 作为自动重开依据。
