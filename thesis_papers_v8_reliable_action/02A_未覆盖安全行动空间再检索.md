### 2.2 跨编号禁返短路

以下做法无论使用什么名称均不进入候选池。

1. 在现有 agent 外增加一个危险命令分类器，再输出 allow/warn/block/review。
2. 把 ask、refuse、abstain 或 human escalation 扩成四分类而不改变可执行行动。
3. 以来源标签、taint、权限图或规则表作为新理论构念，但让通用模型得到同一张量和标签。
4. 用普通 checkpoint、sandbox、rollback、canary 或 receipt 作为主要算法贡献。
5. 把 verifier、风险头、embedding top-k、reranker 或提示模板称为安全策略。
6. 以一个新的 benchmark 现象直接推出一个新的算法能力，而未越过最强直接方法。
7. 把固定批准点的证据选择移到另一个 UI，或把迁移格的四个动作换名。
8. 删除 coding-agent 后仍完整成立的 package manager、AIOps controller、DLP、CI policy engine 或通用 workspace-agent 题。

## 5. 两个最强近失方向的钢人化终审

本节不是保留两个候选，而是说明为什么即使给出最强 I/O、张量、损失和推断动作，它们仍未达到 CONDITIONAL。

### 5.1 近失 A：状态化工作区的安全路径策略

#### 问题与损害

良性任务可以存在一条快速但会删除共享缓存、覆盖非目标文件、越权联网或泄漏信息的路径，同时存在成本更高的安全路径。风险发生在 agent 已经理解任务、准备调用具体工具之时。单纯拒绝任务会损失效用，静态黑名单又不能判断同一命令在不同项目状态下的后果。

#### 输入、状态、输出和动作

- 输入 `X_t`：任务文本、workspace tree、文件内容、tool schema、命令历史、stdout/stderr、权限元数据和已观察警告。
- 图张量 `G_t=(V_t,E_t)`：节点覆盖文件、目录、进程、凭据、服务和工具；边表示 ownership、read/write、dependency、network sink 和 action-produced delta。
- 信念 `b_t`：对任务进展、目标资源、共享状态、动作可逆性、外部副作用和约束满足的后验。
- 输出：下一项可执行动作及其参数，不是危险/安全二分类。
- 动作：追加读取、生成 dry-run、在只读或无网 sandbox 执行、换用安全等价命令、缩小目标、请求明确授权、提交正常动作或安全停止。

#### 训练样本和损失

SABER 已公开任务、sandbox、事件流、状态 delta 和 run-level outcome。可以在每个任务中枚举或搜索安全替代路径，构造 `(G_t,a_t,Delta_{t+1},y_{utility},y_{harm})`。最强训练目标可写为：

`L = L_BC + λ1 L_transition + λ2 L_harm-calibration + λ3 L_constraint + λ4 L_counterfactual-ranking`。

其中 transition loss 预测真实状态 delta，harm calibration 预测可程序核验的损害，constraint loss 约束累计风险，counterfactual ranking 要求安全等价路径优于高风险捷径。推断时策略必须实际选择工具和参数。

#### 公平基线与 split

公平基线至少包括原 coding agent、prompt safety、command classifier、SABER 现有模型、AttriGuard、graph-CMDP、同参数 Transformer-POMDP 和有相同 world-model loss 的通用策略。所有模型获得相同 workspace、delta 标签、动作语法、训练步数和调用预算。split 必须同时隔离 repository、task template lineage、risk carrier、harm family 和攻击来源，不能把同模板改词版本分到不同集合。

#### coding-agent deletion 与通用复制

删除代码编辑，只保留“workspace agent 根据局部状态选择安全 shell 路径”，上述图、损失和动作全部保留。它因此是重要的 operational agent safety 问题，却没有证明 coding agent 的代码修改、构建语义或软件组织关系产生不可替代状态。更致命的是，给 graph-CMDP 相同的 `G_t`、delta、harm、utility 和动作语法后，候选没有剩余的专用运算。SABER 已经把正确行为定义为在良性任务中选择安全路径而非拒绝，AttriGuard 又直接提供 proposed tool call 的反事实必要性检验；AgentSpec 与 ICSE 安全工具规格分别给出规则执行和形式化 tool-sequence/data-flow guardrail，构成无需学习同一状态的强替代。

**终判：NO-GO。** 它可作为 C1/C6/C7/C9/C13 共用的训练与评价资产，不占独立题位。

### 5.2 近失 B：外部仓库、包与技能的可信获取策略

#### 问题与损害

coding agent 可能根据不完整名称自行猜测仓库、包或 skill，随后 clone、install、加载指令或执行初始化脚本。攻击者可以抢注可预测的 hallucinated identifier，或在真实 registry 中发布带恶意脚本和文档指令的工件。潜在损害包括 RCE、凭据窃取、依赖漏洞和持久化污染。

#### 输入、状态、输出和动作

- 输入：用户原始任务、agent 生成的资源名、候选 registry 结果、publisher history、release 时间、签名和 hash、dependency graph、source diff、install hooks 与 sandbox trace。
- 资源张量 `R∈R^{n×d}`：每行是一个候选资源；异构边表示 publisher、version、fork、dependency、name similarity、signature 和 observed behavior。
- 信念 `q_t`：目标身份、候选等价性、恶意性、维护状态和执行后果的联合后验。
- 输出：资源获取序列，而不是 malicious/benign 标签。
- 动作：澄清名称、查询多个 registry、核验 publisher 与签名、只获取源代码、禁用 hooks 安装、sandbox detonation、选择替代包、vendor 最小实现、请求确认或放弃资源。

#### 训练样本和损失

可把 HalluSquatting 的跨模型候选分布、117,062 次依赖更新、USENIX skills 的真实标签、CVE/OSV 版本事实、签名记录和隔离 detonation 结果连接成异构图。训练样本为 `(task,resource candidates,verification trajectory,selected artifact,execution outcome)`。最强目标可包括 identity contrastive loss、malicious-behavior loss、task-equivalence loss、transition loss 和 constrained offline-RL objective。

#### 公平基线与 split

基线必须包括 registry exact match、SCA/OSV、签名与 provenance verifier、malicious-package/skill detector、sandbox-only、通用 heterogeneous-GNN、graph-POMDP 和相同参数的检索—验证策略。split 必须按发布时间、publisher、package family、生态、malware campaign 和 hallucinated-name family 联合隔离；同一攻击者的模板化 skills 不能跨集合。

#### coding-agent deletion 与直接覆盖

把发起者从 coding agent 换成 package manager、IDE 插件管理器或 DevSecOps bot，资源图、动作和损害完全不变。coding agent 的确提高了自动猜名和自动执行的频率，但没有改变可信获取的核心计算。HalluSquatting 已直接把 agent 生成错误资源身份连接到 clone/install 和 RCE；ToolHijacker 又把恶意 tool document 连到资源检索—选择；USENIX 2026 的恶意 skills 工作已经给出大规模真实 registry、静态筛查与动态验证；C25 处理来源/义务，C7 处理执行能力范围，C6 处理文档指令来源。等信息 graph-POMDP 可以执行全部拟议动作。

**终判：NO-GO。** 该方向适合安全工程或 benchmark 扩展，不足以形成新的 ISR 级算法题位。

## 6. 其余十个方向的关键否决理由

### 6.1 恶意仓库与 prompt injection

直接近邻已经不止检测注入文本。AttriGuard 对每个 proposed tool call 进行 control-attenuated shadow replay，并以动作是否在弱化外部观察后仍存活判断用户意图支持。GitInject 在真实 GitHub workflow 中执行攻击，Takedown 追踪到文件、终端、MCP 与外泄链，SABER 又加入无攻击者的 risky self-selection。NDSS 2026 的 ToolHijacker 已优化恶意工具文档对检索—选择链的操纵，ACE 则从可信抽象计划、静态 IFC 和执行期 capability barrier 给出另一条系统防御。再加一个 provenance embedding、source score 或 allow/block head 会返回 C6，并落后于动作级因果归因或架构隔离。

### 6.2 secret 与数据外泄

外泄具有真实外部结果，canary 也可程序核验。然而最可靠的新增控制是隔离私密数据、untrusted content 与外部通信，或用 typed release/IFC/capability enforcement 约束数据流。ACE 已静态检查结构化计划并在执行时设置数据与能力屏障，ICSE 2026 的安全工具使用工作又把 confidentiality、trust 和 capability label 落到 MCP 数据流与工具序列规格。这些控制不需要 coding-agent-specific 学习。若学习器只预测敏感度或 egress risk，它退化为 DLP；若选择权限和通道，则返回 C7；若依据恶意内容来源，则返回 C6。

### 6.3 跨轮记忆污染

MemSecBench 已把写入、持久、召回、采用、外化、选择性修复和 benign preservation 放入同一受控协议，并比较多个 harness、memory backend 与 LLM backend。以“过去错误影响未来行动”为动机已不构成空白。只有当 coding repository 的特定语义产生通用 memory controller 无法复制的新修复运算时才可能重开；本轮没有找到这种运算。

### 6.4 被攻陷多代理角色

IMBIA 已比较 malicious user/benign agents 与 benign user/malicious agent，且把污染位置落到 design、coding 和 testing 角色。另一项直接工作又比较 coder、tester、reviewer 和 security agent，并展示安全 agent 自身可被高级注入绕过。隔离、重跑、撤销和重分配可由同信息 role-graph CMDP 完整表达，同时重叠 C2 的协调、C23 的共因失效与 C27 的委托控制。

### 6.5 人类监督

真实开发者访谈确认事前控制、共同规划、实时监控和事后复核，但访谈类别不是外生 best-action 标签。Hedwig 更进一步，已经用代码编辑、计划纠正与命令批准/拒绝等互动维持跨会话 behavioral guideline，并据此调节 check-in frequency。它的直接性使“从用户反馈学习动态自治”不能再作为空白，同时 approval/rejection 只观察用户偏好，没有给同一状态下各自治动作的外部损害反事实。固定批准点上，C3 已经冻结证据获取和 grounding repair。改为学习何时 ask/refuse/upgrade 会返回 C9，改为权限自治会返回 C7，改为选择审核者会返回 C19。没有一个剩余的人机边界同时满足独立动作、公开外生监督和非重叠性。

### 6.6 开源社区规则遵循

这是最接近 coding-agent-specific 组织规则的方向，因为有些规则明确只约束 AI 贡献。RepoComplianceBench 已经逐轨迹评价是否拒绝、如实披露、通过 verification gate 或升级人类。剩余工作可以训练 rule compiler 或 compliance policy，但同信息通用 policy engine 可复制，106 个 issue 也没有各动作的反事实结果。选择人类 sign-off 又进入 C3，verification obligation 进入 C17，scope/ban 进入 C13。

### 6.7 长期代码退化

SlopCodeBench 已让 agent 连续扩展自己的前序代码，并以未来 checkpoint、verbosity 和 structural erosion 评价。这个方向的重要性没有疑问，但已是 C10 的直接现象，而且重构策略删除 coding-agent 后仍成立。把 erosion 加入 reward 只是在通用 refactoring policy 中增加一项分数。

### 6.8 安全代码生成与回归

SecureAgentBench 同时用功能测试、PoC exploit 和静态分析评价多文件修改；SecRepoBench 和 RedCode 分别覆盖 repository-level secure generation 与 risky execution/generation。进一步训练 repair generator、verifier 或安全风险头会返回 C5/C14。除非找到新的行动后果和新的专用内部状态，否则不能以更大的模型或更多 CWE 重新占题。

### 6.9 失败透明度与行动报告

真实会话研究和事故 taxonomy 表明 agent 会错误报告进展或隐去失败。可核验部分应优先由工具 receipt、状态断言和不可伪造事件流解决。需要学习的剩余部分是 claim–state verifier 或 next-check selection，分别落入普通分类器和 C1/C12/C17。以“可审计性”命名不会改变动作。

### 6.10 长会话 context、persona 与跨项目隐私

ContextEcho 为跨 compaction persona drift 提供大量 probe 结果，但主要监督是身份/规则探针，不是删除、外泄或错误 patch 等外部损害。MemSecBench 与隐私协议已覆盖持久记忆风险。把 context anchor、summary quarantine 或 selective carryover 训练为 controller，删除 coding-agent 后仍是通用长会话 agent 问题，也与 C6/C22 相接。

## 7. 与 C3 和迁移分支的边界

### 7.1 C3

C3 的冻结对象是固定批准点前的可信序贯取证与 grounding repair。新方向若在同一批准点选择下一项证据、修复展示、估计人的理解或增加第二审核者，直接重叠 C3。若完全移除人类批准，只保留工具调用前的 safe-path policy，则成为 R1 的通用 graph-CMDP。若只决定 ask/refuse，则返回 C9。因此，人类边界没有通过“把批准点前后移动”产生新题。

### 7.2 主动缓解期权格

01H/01L/01O/01P/01Y 所讨论的迁移分支围绕 mitigation option 的创建、保留、行使与放弃。R1 的 safe alternative 不能改称 mitigation option，R4 的替代包也不能改称 architectural option。只要动作仍是 defer/mitigate/exercise/abandon 或其同义词，本轮视为已占能力，而不是 C28。

## 8. 理论机制需求，不预先套用 AIS 理论

本轮不替技术近失方向强配理论，只记录若未来重开必须出现的机制。

| 方向 | 未来理论至少要产生的专用机制 | 目前缺口 |
|---|---|---|
| 状态化安全路径 | 必须指出通用 expected-harm policy 在何种组织约束冲突中稳定选错，并产生不能由 workspace state 无损表示的中间关系和方向运算 | 现有“可逆性、权限、共享资源、警告”全是通用环境特征；没有不可替代运算 |
| 外部资源可信获取 | 必须说明 coding agent 生成候选身份与组织认可身份之间的特殊形成机制，并推出不同于 provenance/SCA/POMDP 的核验次序或停止边界 | 当前只是 identity belief、风险与效用的通用联合决策 |
| 社区规则遵循 | 必须从规则的组织地位、agent 身份和责任分配推出可计算冲突，而不是把规则解析成 obligation graph | 当前动作与 RepoComplianceBench 完全同位，理论只能重命名 rule hierarchy |
| 多代理污染 | 必须给出为何同一污染在不同责任关系下应产生不同撤销或重分配，而非普通 role trust | 当前 role graph 和结果标签足以供通用 CMDP 学习 |

如果另一路理论检索只能给这些状态起名，而不能改变前向、损失或行动，本轮 NO-GO 不应被撤销。
