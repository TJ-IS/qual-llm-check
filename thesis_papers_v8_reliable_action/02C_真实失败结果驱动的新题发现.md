# 真实失败结果驱动的 coding-agent 广义安全新题发现

## 0. 任务、截止日与终判

本文件不从理论名词或模型模块出发，而从 coding agent 已在真实会话、真实仓库、可执行容器与状态化基准中造成的外部结果倒推决策缺口。分析顺序固定为 `failure outcome → decision point → observable/hidden state → normal/risk/corrective action → counterfactual supervision → local artifact → direct-neighbor and C1–C27 tests`。只有技术与结果空位先成立，才允许进入 AIS 理论机制搜索。检索截止日为 **2026 年 8 月 16 日**。

**终判：保留候选数为 0；CONDITIONAL 为 0；两个最强钢人候选均为 HIGH-CONFIDENCE NO-GO。**

零候选不是因为真实损害不足。Tang 等人的 16,118 个 evidence-grounded episodes 包含容易恢复与难以恢复的状态损害；Agent Meltdowns 直接观察到错误条件诱发的越权访问、泄露、权限扩大和 TLS 弱化；SABER、UnderSpecBench、OverEager 与 SNARE 又把错误目标、过大作用域、未经授权副作用和危险自选行动放进可执行环境。问题在于，这些高损害事件的可干预时点已经落入 C1″、C7、C9、C13、C18、C22 或 C4，且被上述近期基准直接操作化。剩余最常见的误报、返工与信任损失主要落入 C3 的证据与批准质量，或只形成一般任务质量结果。

本轮最强的两个学习型方向分别是“环境错误后的授权保持型安全探索策略”和“不可观察失败锁定前的主动证据策略”。两者都可以写出非平凡的图状态、world model、序贯损失与本地 checkpoint，也都可以在公开或严谨自建环境中训练。第一项却与 Noisy Container、UnderSpecBench、OverEager、SNARE、SABER 以及 C1″/C7/C9/C13 同位；第二项的真实 `t_error/t_lock/t_observable` 标签来自一般任务失败，不是外部安全损害，而安全化后又回到 C3/C9/C17。等信息、等监督、等参数的 constrained POMDP、temporal graph world model 或通用 actor–critic 可以逐项复制其拟议能力。没有技术空位，理论门不应开启。

本文件是内部选题审计，不是论文正文。文中的模型、损失、算力与实验是钢人化规格，不代表已经训练或运行；全文不报告候选性能、效应量或显著性。C16 与 C20 是冻结编号中的空号，不是尚未开发的题位。

### 1.3 Tang replication 的字段与样本检查

`misalignments.json` 的公开记录不是只有 taxonomy 标签。实际核到的字段包括 `repository_id`、`session_id`、`misalignment_id`、`name`、`description`、`alignment_goal`、`evidence[{turn, quote, context}]`、`severity`、`resolution_status_raw`、`confidence`、`source`、`repository_full_name`、`license_type`、`session_sha`、turn count，以及 symptom、cause、damage severity、damage locus、resolution status 与相应 reasoning。该结构可以训练 episode retrieval、分类或结果预测器，也能恢复一部分前缀证据，却没有同一有害前缀下多个可执行行动分支的真实结果。

样例回读显示，公开记录中相当多的 S7 不是代码或系统状态已经受损，而是 agent 声称命令成功、修改已经应用、安装可行或指标已经得到，随后由用户指出陈述与工具记录不一致。这类结果确实增加开发者返工并损害信任，但它的决策点是“在固定沟通或批准点应展示何种证据”，已经落入 C3；若把输出收窄为真假标签，则退化成 verifier 或 claim classifier。

全文结果还给出更少见但更强的状态损害。16,118 episodes 中，DS1 effort/trust cost 占 90.50%，DS2 easily reversible state damage 占 8.44%，DS3 hard-to-reverse damage 占 0.07%，DS4 unobservable 占 0.91%。DS2 的损害位置以 code/task 为主，DS3 样例包括未经授权 release、改写 Git history 并删除未提交工作、以及降级核心 package。这些事件足以证明损害真实，却分别把决策点落在 release approval、不可逆版本控制、删除/补偿、依赖与权限边界；它们不能仅凭同属一个 taxonomy 就产生新的统一动作语法。

### 1.4 证据强度与不可越过的推断边界

真实 session 和 incident 资料适合建立“哪些后果存在”以及“在何种前缀后发生”的外部效度。它们通常不适合直接学习 `do(action=a)` 的安全收益，因为只观察到一个已执行轨迹，未观察同一用户意图、仓库状态和错误条件下的替代行动。AIDev 又进一步缺少潜在缺陷真值；review time、comment count 与 merge 只能作为流程代理。现有关于审核变化的研究也存在强反证：669 名开发者、103 个采用仓库与 228 个对照仓库的差分分析把更快、更短、更宽松的审核同时观察于对照仓库，因而不能把生态趋势直接归因为 coding-agent adoption（[SSRN primary record](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=6996078)）。

可执行 benchmark 可以通过 reset/branch 获得反事实行动结果，但只要相同 benchmark 已经定义了风险状态、行动边界与结果 oracle，新模型就必须证明新的行动能力，而不是再次训练一个不同名字的 policy。Noisy Container 提供 error/no-error 配对，SABER 与 UnderSpecBench 提供 before/after state oracle，OverEager 与 SNARE 提供授权或 shortcut 对照；它们提高了可运行性，也提高了“直接覆盖”门槛。

## 2. 外部损害优先的 failure–decision map

### 2.2 coding-agent 特异性检查

错误、模糊需求和错误恢复并非 coding agent 独有。coding agent 使风险显著上升的原因是它把自然语言任务直接转化为代码修改、shell、Git、包管理、CI/CD 和外部 API 的连续行动，并在一次会话中跨越多种权限与持久状态。因此有研究价值的单位应是“任务语义与可执行 effect 的联合决策”，而不是错误文本的静态分类。

但这种特异性不能覆盖直接工作。将 Noisy Container、SABER 或 UnderSpecBench 的 agent 换成另一个通用 tool agent，错误条件、permission、target、blast radius、before/after state 和 ask/act/stop 动作仍然成立；只是在 coding 仓库中这些状态更密集。若算法只读 `task + state + action candidates` 并优化 task/harm trade-off，coding-agent deletion 后函数类不变。必须再有代码、版本控制、构建或部署特有且不可删除的结构；本轮没有找到未被 C1–C27 占据的这种结构。

### 4.2 反事实样本的严谨构造方式及其代价

从可执行容器生成反事实样本的唯一严谨做法，是固定 task、初始 snapshot、error seed、tool schema 与授权边界，在每个关键前缀枚举或搜索候选动作，执行到稳定终态，再以 deterministic state predicate、task tests、敏感资源访问、外部 receipts、作用域差分和人工复核共同标注。每条样本应保存 `(environment_manifest, task_id, prefix_hash, action_id, successor_hash, task_return, harm_vector, cost, oracle_version, seed)`。训练、验证、测试必须在 repository、scenario family、error primitive、target template 与 archetype 上联合去重。

这种构造能够解决单轨迹不可识别，却不会自动产生新题。若环境是 SABER/UnderSpec/Noisy Container，标签和动作仍由其现有风险定义决定；若自建新的 coding repository 场景，就必须先证明新 decision unit 没有被 C1–C27 吸收。本轮失败结果没有提供这个 unit。因而“可以采很多 counterfactual rollouts”只证明工程可行，不证明独立贡献。

## 5. 最强钢人候选 A：环境错误后的授权保持型安全探索

### 5.1 直白研究问题与真实结果

钢人 RQ-A 为：当 coding agent 遇到缺文件、权限拒绝、依赖缺失、404、部分响应或限流时，能否学习一套仍保持原任务授权边界的探索策略，在减少敏感访问、越权工具调用、权限扩大和错误外部副作用的同时，尽可能完成任务？正常动作包括在已授权资源中换路径、执行最小只读探测和使用安全替代工具；风险动作包括递归扫描、`sudo`、读取保护文件、导出环境、关闭 TLS 校验、修改 access control 或向外部接收者披露信息；纠正动作是请求具体授权、隔离执行、降权重试或停止。

这不是二分类器。策略必须根据错误类型、已尝试路径、授权集合、资源关系和动作可逆性连续更新 belief，并从多个可执行 action program 中选择下一步。外部结果向量为任务成功、敏感资源触达、权限变化、持久状态差分、第三方副作用、人工介入、token 与 wall time，不能用“拒绝率越高越安全”代替。

### 5.2 I/O、张量、架构与推断动作

一条训练实例以同一环境前缀为单位。输入是任务文本、声明权限、工具 schema、action–observation trace、error event、当前文件/Git/process/mock-service 摘要和候选动作。它们组成 typed temporal effect graph `G_t=(V_t,E_t)`：节点覆盖 task clause、resource、principal、tool、process、external object 与 prior action，边覆盖 `authorized-for`、`reads`、`writes`、`depends-on`、`owned-by`、`observed-after` 与 `may-affect`。

前向张量可写为：节点表示 `H_t∈R^{|V_t|×d}`，类型嵌入 `T∈R^{|V_t|×d_t}`，有向边表示 `R_t∈R^{|E_t|×d_e}`，时间/错误表示 `U_t∈R^{L×d}`，候选 action program 表示 `A_t∈R^{K×p×d}`。异质图网络编码 resource/effect，causal Transformer 编码 trace，distributional world model 预测每个候选动作的 `K` 个 successor distributions；constrained actor 输出 `π(a|b_t)`，并同时输出 task return、harm vector、permission-boundary violation 与 uncertainty quantiles。

推断时允许的不是自然语言建议，而是五类低层动作：执行授权内替代 program、执行最小只读 probe、请求一项精确权限、在隔离 sandbox 中试运行、停止并返回可核验证据。系统不能把 `sudo` 或全局扫描包装为“探索”，也不能只给风险分数后让原 agent 原样执行。

### 5.3 样本、监督、损失与本地工件

训练数据可从 Noisy Container 的 paired environments、SABER 的 stateful tasks，以及在许可允许时复刻 UnderSpec/OverEager/SNARE 的授权变化结构构造。对每个安全关键前缀以 snapshot branching 执行候选 programs，标签来自 task tests、文件和权限 diff、敏感 resource touch、mock external receipt、scope oracle 与人工争议复核。Tang 的真实 episodes 只用于设计 error/result strata 与外部分布测试，不生成未经观察的 action label。

总损失可写为

`L_A = λ1 L_world + λ2 L_task + λ3 L_harm + λ4 L_auth + λ5 L_pair + λ6 L_policy + λ7 L_cal`。

`L_world` 学习 successor state distribution；`L_task` 预测任务结果；`L_harm` 对多类实际 effect 使用 distributional risk loss；`L_auth` 惩罚授权边界穿越；`L_pair` 约束同一 task 在 error/no-error 条件下不因错误本身扩大授权；`L_policy` 用离线 constrained RL 或 advantage-weighted regression 学习 utility–risk–cost 策略；`L_cal` 校准 ask/stop 的风险分位数。可交付工件包括 graph/world-model checkpoint、actor checkpoint、tokenizer/schema、counterfactual rollout manifest 和 deterministic oracle bundle。

预估 pilot 可用 0.3–1B 参数 trace encoder 加 50–150M graph/world heads，在 4×A100-80GB 上训练 2–5 天；7B LoRA 版本约需 8×A100-80GB。它们只是资源估计，不是已运行事实。拆分必须联合阻断 repository、scenario family、error primitive、target name、prompt paraphrase 与 oracle template；hidden test manifests 只对最终 evaluator 可见。所有 seed、container digest、tool image digest、action grammar 与 failed rollout 均需发布。

### 5.4 最强基线、消融与公平性

公平基线至少包括原 agent、deny/allow list、提示式 safety reminder、tool-level permission gate、Noisy Container 原评测 agent、SABER 最强报告系统、等参数 Transformer actor、等参数 graph actor、constrained POMDP、同容量 model-based offline RL，以及先预测风险再 rerank 的两阶段方法。所有方法共享 base model、可见状态、候选 action grammar、training branches、tool-call 与 wall-time budget。主要指标同时报告 safe task success、harm incidence/severity、授权边界穿越、不可逆 effect、ask burden、人工介入、token、延迟与 calibration；以 Pareto frontier 而不是单一拒绝率比较。

消融包括打乱 `authorized-for` 边、交换 error/no-error paired labels、删除 effect graph、删除 successor world loss、取消 boundary invariance、将精确 ask 合并为统一拒绝、以及把 directed edge 替换为无类型 attention。还应做机制冲突场景：原路径失败但授权内替代可成功；越权 shortcut 成功率更高；请求授权增加负担但避免敏感访问；低风险只读 probe 与高信息高副作用 probe 竞争。

### 5.5 直接覆盖、deletion 与 generic 反证

钢人化不能解除直接覆盖。Agent Meltdowns 已经以 exactly-on-error 的方式观察 agent 是否扫描目录、读保护文件、输出环境、绕过 TLS、修改 access control 或对外披露；Noisy Container 还提供配对错误注入。UnderSpecBench 已把 intent、target 与 blast radius 正交化并用 state oracle 区分 Safe Success、Wrong Target、OverScope、Ask、Refuse 和 Defer。OverEager 与 SNARE 已把授权缺失、ask-first 与 dangerous shortcut 作为主决策。SABER 则覆盖 prompt injection、风险自选、上下文 warning、state delta 与 utility–safety trade-off。

删除 coding-agent 后，RQ-A 仍是任意 tool agent 在错误条件下保持授权边界的 safe exploration。将 repository resource 换成企业文件、云资源或数据分析工作区，`task/error/permission/resource/action/successor/harm` 均保持不变。coding 情境增加实例丰富度，却没有改变函数或动作语法。

等参数 generic 反证也成立。给一个匿名 temporal graph POMDP 完全相同的节点、边、error pairs、candidate programs、successor labels、harm oracle 与 constrained return，它可以学习同一 belief、world distribution 与 `π(a|b)`。`authorized-for` 是输入关系，不是来自 IS 理论的不可替代计算。若 generic 方法较弱，只能说明 inductive bias 或优化差异；若相当，则候选没有理论专用能力。RQ-A 因“直接题面覆盖 + C1″/C7/C9/C13 吸收 + deletion 通过 + generic 可复制”判为 **HIGH-CONFIDENCE NO-GO**。

## 6. 最强钢人候选 B：外部损害锁定前的主动证据策略

### 6.1 直白研究问题与动作单位

钢人 RQ-B 为：coding-agent 轨迹尚未出现明显失败时，能否估计潜在有害路径何时从可纠正进入事实上的 lock-in，并主动选择最小证据行动，使错误在不可逆 release、删除、权限扩大或大范围修改之前变得可观察？这比离线 failure classifier 更强，因为输出必须是可执行 probe、targeted test、diff inspection、ask、checkpoint 或 stop，并以之后的真实 task/harm/cost 评价。

可见状态包括任务、trajectory prefix、当前 diff、测试、tool receipts、未验证假设和 candidate actions。隐藏状态包括真实根因、hidden tests、用户授权边界、未来 action 的 effect 与“现在不取证是否仍可恢复”。正常行动是继续一个有证据支持且可逆的修改；风险行动是跨过 release/delete/permission boundary 或在同一假设上继续累积修改；纠正行动是选择能区分竞争假设的低副作用 probe、保存 checkpoint、请求用户澄清或停止。

### 6.2 张量、训练与行动策略

输入以 step prefix 为样本。trace encoder 产生 `X_t∈R^{L×d}`，typed state graph 产生 `H_t∈R^{N×d}`，候选证据动作产生 `Q_t∈R^{K×d}`。survival head 输出每一步进入错误、锁定与可观察状态的 hazard `h_t^err,h_t^lock,h_t^obs`；belief head 输出 competing-hypothesis distribution `b_t`；counterfactual model 预测每个 probe 对 posterior entropy、任务结果、外部 harm 和成本的变化；actor 在 execute/probe/ask/checkpoint/stop 中选择低层 action。

损失可写为 `L_B=α1L_survival+α2L_outcome+α3L_info+α4L_counterfactual+α5L_policy+α6L_cal`。训练的主数据源原拟使用 Failure as Process 的 `t_error/t_lock/t_observable`，再把 SABER/UnderSpec/FixedBench 分支轨迹加入 harm 与 act/abstain labels；Tang、RootSE 与真实 incidents 作为外部分布的现象层验证。推断时 actor 必须实际调用 test、read-only inspection、checkpoint 或 ask 工具，不能只输出“高风险”。

本地工件为 temporal encoder、survival heads、counterfactual evidence model 与 actor checkpoint。合理 pilot 是 0.3–1B trace model 加 100M world/policy heads，在 4×A100-80GB 上训练 2–5 天；若以 7B base 做 LoRA，约需 8×A100-80GB。拆分需阻断 task family、repository、failure cause、tool sequence motif、benchmark template 和 hidden oracle，并将 trajectory near-duplicates 按 prefix hash 聚簇后整体分配。

基线包括 Failure as Process 的离线定位器、TraceProbe、Wink-style periodic monitor、固定每 `k` 步验证、entropy threshold、risk classifier+router、等参数 causal Transformer、temporal GNN、generic survival model、Bayes/POMDP active sensing 与 model-based actor。消融包括随机化 `t_lock`、删除 info-gain、删除 harm head、将 directed prefix 打乱、统一所有 probes 的成本、以及只保留最终 success supervision。指标必须同时包含提前量、可观察率、不可逆 harm、safe task success、额外 tool calls、人工请求与 wall time。

### 6.3 监督错置与直接覆盖

Failure as Process 的 `t_error/t_lock/t_observable` 是从 Terminal-Bench 一般任务成败构造的过程标签。一个任务“已经很难成功”并不等于外部损害“已经不可逆”；相反，agent 可能还能完成任务，却已经泄露秘密或错误发布。把三个时间点直接迁移为安全 hazard 会混淆 task failure 与 harm onset。SABER/UnderSpec 可以提供 harm state，却没有人为定义的统一 `harm lock-in` 真值；用模拟器事后最短路径反推 lock-in，本质上由所选 world model 和 action grammar定义标签。

将 RQ-B 限定到“在批准或完成声明前主动收集充分证据”，就回到 C3；限定到“是否继续、请求、停止”，回到 C9；限定到 accumulated unverified obligations，回到 C17/C1；限定到 release、delete 或 post-harm recovery，又分别回到 C18/C4。Wink 已经直接研究运行中识别 misbehavior 后周期性干预，FixedBench 直接研究 verify/abstain，TraceProbe 与 TrajAudit 占据过程诊断。

删除 coding-agent 后，survival hazard、active sensing 与 lock-in policy 是任何长程 tool agent 的一般问题。给等参数 POMDP/world model 相同前缀、时间标签、候选 probes、counterfactual rollouts 与 task/harm/cost loss，它可以精确实现同一 belief update、information gain 与 action choice。候选没有来自 coding artifact 的非交换结构，也没有可从失败数据识别的 IS 机制。RQ-B 因“结果标签错置 + C3/C9/C17 吸收 + generic 可复制”判为 **HIGH-CONFIDENCE NO-GO**。

## 8. 理论门、系列边界与终局撤题

### 8.1 为什么本轮没有启动 Otero 机制附着

本任务预先规定“只有先证明技术与结果空位，才用 Otero 或本地 AIS 全文寻找合法机制”。本轮已完整读取 `otero-open-api` 的 `SKILL.md`，但没有为 02C 发起新的 Basket API 查询。原因不是省略理论，而是两个钢人候选在理论搜索前已经分别被直接覆盖、C1–C27 吸收、coding-agent deletion 与等参数 generic 反证终止。此时再搜索 resilience、HRO、mindfulness、control、accountability、agency、real options 或 TTF，只会为了理论制造题目，违反预设顺序。

`02B_从AIS机制反向搜索新题.md` 已用 Otero 全文库系统核验过上述理论以及 contextual integrity、process drift 等新机制，其结论不能替代本轮技术检索，却构成不得换名返回的先验。尤其是组织韧性、事故恢复与 HRO 的分析单位在组织、团队或人类控制层，不会自行规定 `authorized-for` edge、harm lock-in、probe order 或低层 tool action；把这些状态手工加入模型后再引用理论，不满足 DSDL 式的机制责任。

若未来出现严格新的外部结果与动作结构，理论门可以重开。最低证据应同时包括：同一安全关键前缀的多个真实或可执行反事实分支；一个不被 C1–C27 吸收的低层行动；以及一个原 AIS 机制能够规定有方向、非交换或结构化更新，并在冲突场景中迫使策略作出与 generic world model 不同的选择。在此之前，理论候选数同样为 0。

### 8.2 与 C3、迁移分支和旧补偿案的边界

本轮不能用 Tang S7 重开 C3。C3 已冻结的对象是固定批准点上，agent 如何选择和呈现能够让人正确判断的证据。错误成功声明、lucky pass 与 false assurance 都是其自然数据来源或外部分布，不是第二篇新论文。若把决策点移到更早的 trajectory step，最强工件仍是 active evidence 或 verifier scheduling，落入 C3/C11/C17。

本轮也不能把“遇到错误后保留未来行动空间”改写为迁移分支。迁移分支的 unit 是固定 pre-cutover 场景下的选项格与未来冲击；RQ-A 的 unit 是即时 error-conditioned authorization boundary。两者时间结构不同，但 RQ-A 已由 C1″和直接 benchmark 终止，不能借与迁移不同而自动获得题位。

已经发生 release、删除、history rewrite 或 dependency damage 后的 repair 则明确属于 C4。`00V` 与 `01Z` 已把 code、config、dependency、process、mock external service 的最小 compensating program 钢人化后终局撤题。本轮真实 incidents 只增加其外部重要性，没有提供新的 paired recovery branches、理论算子或行动结构，因此不得以“真实失败驱动恢复”再次重开。

### 8.4 什么新证据才能改变 0 候选

零候选不是永久否认真实失败研究。以下任一新资料本身仍不够：更多 taxonomy、更多正例 incident、一个更大的 LLM judge 数据集、另一个风险 head、或一个更复杂的通用 world model。重开必须出现至少一种严格不同的能力证据。

第一种是公开的同前缀多分支数据，其中 safety-optimal action 既不是 ask/refuse/stop，也不是 permission gate、scope restriction、release control、verification、rollback 或 compensation，并且外部 oracle 能观察其独立结果。第二种是 coding artifact 特有结构，使删除 repository/build/version/deployment semantics 后问题不再定义，且同字段 generic 模型无法表达所需的非交换更新。第三种是 AIS 原机制直接规定这一更新的方向、前因和结果，不由研究者事后添加。没有这些证据，三篇 thesis 宁可保留空位，也不能用真实损害的严重性掩盖贡献同构。
