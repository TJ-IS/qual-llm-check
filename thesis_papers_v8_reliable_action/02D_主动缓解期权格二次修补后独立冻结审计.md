## 4. 唯一联合核：branch 内闭合，runtime 匹配与跨 600 秒未闭合

### 4.1 未跨 horizon 的 branch 已达到唯一性要求

修补后的 nonterminal kernel 显式联合

\[
Q^a_\theta(d,r_a,\Delta g,\kappa',\Delta\ell,\Delta c,e,\sigma,o,z,h,\eta,k\mid x).
\]

给定 `x,a,z,h,η,k,e,o`，它以同一个 `k` 取得 duration、13维 typed result、severity 与 accumulator；`Decode_a` 唯一得到 `r_a`，随后 `G_a`、`KAPPA_a` 与 `C_a` 分别唯一得到 `Δg`、`κ′` 与双账 `Δℓ`。`F_a^{v2}` 又禁止在 cell 匹配后读取 raw signed record 改写 canonical state。CP/WC 的相同 status、不同 result cell 也由 `MT-STATE-01/02` 明确要求产生不同 `g`、state hash、memo key 和后续 physical kernel。

因此，若审计者先把完整 latent branch `z,h,η,k,e,o`作为已知输入，旧版“同一 branch 对应多个 next state”的反例已经被消除。terminal kernel给定 `d` 后也唯一以 `t_T=t_start+d` 取得绝对结束时刻，EX 与 AB 的上限分别是 720 秒与 660 秒；它们不会重新开放 nonterminal action。

### 4.2 runtime 无法在隐藏 `z,h` 下唯一选择 canonical branch

设计同时规定 `z` 与 joint-mixture draw `h` 对 policy隐藏。可是 joint Voronoi cell 的 representative按 `a,z,h,η,e`分别由 `D/R/K/S` 节点定义；同一个真实 `y_cont` 在不同 `z,h` 下可以离不同的 `k` 最近。于是 observation到 `k` 的映射不是全局函数，而是 `k=CELL(y;a,z,h,η,e)`。

这与三处 runtime责任冲突：

1. `F_a^{v2}` 要把 raw signed record匹配到唯一 `η,k,e,o` 后，才允许由该 branch写 `r_a,Δg,κ′,Δℓ,Δc`；
2. 01H-A 的 `joint_branch_schema` 更要求 raw output只可匹配唯一 `z,h,η,k,e,o` branch，并在 episode record中保存 matched `z,h`；
3. belief公式却正确地把未知 `h,k` 边际化，并对每个 `z`计算 likelihood，这说明 runtime本来不应知道真实 `z,h`。

若 executor使用 benchmark隐藏 risk bit或一个未观测 mixture ID来选 branch，就把 future/hidden truth送入 canonical state；若选 MAP `z,h`，则 state mutation取决于模型当前信念而非同一真实工具结果；若对 `z,h`边际化，则 `g/κ/ledger`成为多个离散 next states的混合，不再是当前规格宣称的唯一 canonical state。01H 的 episode schema只保存 matched `(η,k,e,o)`，01H-A 则保存 `(z,h,η,k,e,o)`，也直接暴露了两种不兼容理解。

这个歧义还进入去重键。`C_a` 的 planner component key显式串接 `z,h,η,k`；同一个真实 outcome若因模型 seed、posterior或 mixture解释不同而选择不同 latent branch，就可能得到不同 component key，破坏“双账已经按真实事件唯一去重”的承诺。

冻结前须选择一个可执行定义。最小修补是把 runtime canonical typed cell/codebook定义为不依赖 `z,h` 的全局 action-specific grid：固定 canonicalizer先将 signed record映射为唯一 `η,k_global,e,o,r_a,Δg,κ′,Δℓ,Δc`；各 `z,h` branch只预测这些共享 global cells的概率，belief在 `z,h` 上边际化而不改变外部 state。若坚持 latent-specific quantile cells，则 canonical state必须提升为对 next physical states的 belief distribution，并重写 planner、memo、ledger和executor；当前并未采用这条复杂路径。

### 4.3 跨 horizon 反例

取一个合法 CP pre-state，`t=590,τ=10`。现有 kernel 可以抽到 `η=OK,d=30`，并据此：

1. 从 OK decoder 产生 `checkpoint_exists=1` 和可能的 `restore_verified=1`；
2. 用完整 `[590,620)` 计算 absolute-bin event exposure；
3. 取得与 30 秒 duration 同 cell 的 `Δc,Δg,κ′,Δℓ`；
4. 在 `F_a^{v2}` 末尾再因跨 600 秒把 branch 截为 `TIMEOUT`。

然而，01H-A 的 CP/TIMEOUT truth table 要求 `checkpoint_exists=0,restore_verified=0`，channels 1–4 为 NA，只执行到 600 秒的 age passage。两条规则对 `η`、`r_a`、`Δg`、event exposure、`Δc` 和 `Δℓ` 给出不同答案。`t′=min(t+d,600)` 虽数值唯一，完整 terminal-entry state 并不唯一。

问题不是结果尚未运行，而是公式先对未截尾 `η,d` 生成全部后果，文字再重写 status，却没有定义重写后的 cell、decoder 和 exposure。`joint_kernel_manifest` 写“跨 horizon 截为 TIMEOUT”不能替代确定性变换。

### 4.4 冻结前所需修补

须在 `Q` 内定义唯一 censoring branch，例如先采样 `d_raw`，再令

\[
d_{eff}=\min(d_{raw},\tau),\qquad
\eta_{eff}=\begin{cases}
TIMEOUT,&d_{raw}>\tau\\
\eta_{raw},&d_{raw}\le\tau,
\end{cases}
\]

并要求 `Decode/G/KAPPA/C`、event exposure、severity、accumulator、observation、joint-cell likelihood 与 next state全部只消费 `d_eff,η_eff`。若选择“临近 horizon 时不允许启动会越界的主动 action”，则必须把该规则写进 action mask并对主模型和全部 baseline 同用；当前规格没有选择这条路。

## 5. 双账与 `Ω_v`：设计层已防止所有已识别稀释旁路

新版把 evidence 与 outcome 分为不同 domain、不同 key 和不同写入 authority。public check、shadow replay 与 probe 只写 `ℓ_evid`；production database、gateway、cgroup 和 sealed terminal oracles 才能写 `ℓ_out`。`c` 只由 outcome components 投影，repair 或 rollback 不能删除既有 component。

更关键的是，`Ω_v(world_id,oracle_version)` 的 reference transaction IDs、positive weights、denominator 与 hash 在任何 policy rollout 前封存。同一个 world 的 EX、AB、早停、checker coverage 与不同方法必须逐字节共享它。即使一项 transaction 没被某个 policy 的 public checker 触达，terminal oracle 仍在同一 frozen population 上评价；因此多做 passing checks、少做 checks、提早 AB 或扩大 shadow coverage均不能改变 `C_v` 分母。

本轮没有发现仍能从 evidence domain 写入 `Ω_v/C_v` 的字段旁路。`MT-LEDGER-07..12` 当前仍为 `PENDING-IMPLEMENTATION`，所以只能签发“设计通过、实现证书待补”，不能声称 anti-dilution 已在代码中运行成功。

## 6. physical zero 的新旁路：action-conditioned base、`η` 与 `d`

### 6.1 physical-only mixture 修补有效但不充分

新版明确删除 active `Π_N` family，因而 mitigation residual 不能再重加权 shared mixture `h`。这个修补真实有效。

第一条旁路甚至发生在 residual 之前。公式写成

\[
\psi_r^{phys}(H_0,z,R_{phys},L_{evt},m)
+M_{r,m}\odot[\text{main} + \text{ordered pair}],
\]

而 shared `PhysicalKernel/ψ^{phys}` 明确读取当前 action contract `m`。`physical_mask_v2` 只物化 `M_main/M_pair`，没有任何公式把同一个 forbidden support mask施加到 action-conditioned base。因而即使把全部 theory/generic residual置零，shared base仍可让 CP 改变 hazard、让 SR/SV改变 production outcomes，或让 WC改变 semantic/recovery outputs。这个 base由两个比较模型共享只保证公平，不能证明物理零。

第二条旁路来自 active families仍包含 `stat` 和 `dur`。所有 hazard、severity、accumulator、result 和 observation heads又以 `η` 为条件，event occurrence还以 `d` 决定 absolute-bin exposure。以某一 event `r` 为例，边际发生率包含

\[
\sum_{z,h,\eta,k} b(z)\,\pi_h^{phys}\,
\Gamma_{azh\eta}^{active}\,w_k
\left[1-\prod_j(1-\Lambda^{phys}_{azh\eta rj})^{\omega_j(d^{active}_{azh\eta k})}\right].
\]

即使该 action 的 `haz` residual bit 全为零，`stat` 改变 `Γ` 权重、`dur` 改变 `ω_j`，一般仍使上式改变。直接 mask 只把目标 head 的参数置零，没有把目标边际的全部可行动因果祖先置零。

### 6.2 三类明确冲突

| 文字要求 | 现有允许 residual | 绕过路径 |
|---|---|---|
| CP 全部 hazard bits 为零，不能改变 event occurrence | CP 可改 `stat,dur` | `stat→η→Λ` 条件混合；`dur→absolute exposure→event probability` |
| SR/SV 不产生 production impulse | SR/SV 可改 `stat,dur`，其余 production heads按 `η,d` 条件化 | 改变 status mixture 或暴露时长后，production hazard/severity/accumulator 边际可变 |
| WC 不改变 semantic/recovery 边际 | WC 可改 `stat,dur` | 通过 status mixture、时长 exposure及其后 conditional heads改变被禁止边际 |

`TT-5` 要求在 softmax/sigmoid 以及 `h/k` 边际化之后，forbidden marginal 对全部 active 参数的 Jacobian 严格为零；`TT-6` 要求激活允许 residual 后 forbidden support/CDF/hazard 不变。二者都没有检查 action-conditioned base相对 action-neutral counterfactual 的总作用。即使把测试扩展到 base，当前 forward graph也没有使这些等式恒真的结构。测试可以发现失败，却不能把一般非零的 base difference或 residual Jacobian变成结构零。

### 6.3 冻结前所需修补

`physical_mask_v2` 必须从“逐 head bit 表”提升为“forbidden marginal 的因果闭包表”。可接受的实现方向包括：

1. 把同一 total-output support projection施加在 `ψ^{phys}+residual` 之后，或使 action-conditioned base在 forbidden channels上严格 action-invariant；共享 base不能享有 mask豁免；
2. 对每个 action/outcome 明确屏蔽所有可行动祖先，包括相应 `Γ` status cells和 `D` duration cells；
3. 把 action status、物理 status 与 observation-quality status 分解，使允许的工具质量变化不会重加权禁止的 production distribution；
4. 对允许 duration 变化但禁止 event occurrence 的 action，显式固定 censor/exposure measure或把 occurrence建模为 action-invariant base，再只允许指定的 conditional severity变化；
5. 在 natural link 后加入可证明的 exact projection，而不是只在实现后测 Jacobian。

完成结构修补后，才有意义物化 `physical_mask_v2.npz`、content hash以及 `TT-1..6` 的 golden outputs。当前 hash 为 `PENDING-IMPLEMENTATION` 本身不是经验结果失败；真正阻断冻结的是生成规则尚不能满足自己声明的 post-link zero。

## 7. 公平通用替代、动作数、枚举和资源算术

### 7.1 `G-PhysicalFactoredSMDP` 没有被故意削弱

公平 generic 获得与主模型相同的 raw/canonical inputs、候选与 action masks、typed physical prior、joint labels、risk bits、`Ω_v` terminal labels、ENUM partial rankings、split、loss、optimizer、belief、cell matcher、componentizer、qualification worlds、hard recursion、memo、pruning、tie-break 与 200k search cap。它还额外读取 raw ordered history、belief、双账 summary 和全部可见动态状态。

其 residual 不再是“等预算 Transformer”的空口描述，而是固定为18 tokens、384维、4层 pre-LN bidirectional Transformer、6 heads、GELU、dropout 0.10、learned absolute positions和16维 family bottleneck。`d_budget` 只由预先固定的参数脚本选择，不读 episode outcome；不能用 idle parameters 凑数。这个接口足以构成强而公平的理论生死基线。

仍有两个需同步的小缺口：

1. 01H 第6.8节要求 trainable parameters `±1%`、**training FLOPs `±5%`**；01H-A 的 `parameter_flop_match` 字段只要求 **inference FLOPs `±5%`**。冻结 manifest 应同时登记并约束 training 与 inference FLOPs，不能让实现者任选一种。
2. “共享 module 复用同一 initialized object”应改写为“从同一初始化 state bytes 克隆后独立训练”，避免被实现为两个方法 live-alias 同一可变权重对象。

这两项不构成 `NO-GO`。若修补后 generic 在预注册 finite-data、unseen-combination 和 held-out slices 上与主模型落入等效界，应撤销 Benaroch 的独立算法贡献；那是未来结果门，不是现在的设计失败。

### 7.2 动作 cardinality 与最大深度闭合

- 主动 slots 为 `RS00..RS07`、`CS00..CS07`、CP、WC，共18。
- nonterminal 另含 D60，故 `A_N=19`。
- terminal 为 EX、AB，故总 action slots 为 `A=21`。
- 同一 operator type 最多执行一次，所以最多四项主动 mitigation；D60 最多两次；再加一个 terminal action，最大 depth 为 `4+2+1=7`。
- 四个代表 slots 的全部有序子集数为 `Σ_{k=0}^4 4!/(4-k)!=65`；它没有被误称为全部18 slots的 exhaustive oracle。

### 7.3 每 policy 的 9,928 worlds 算术正确

| Tier | Worlds per policy |
|---|---:|
| 主 test：`32 tasks×10 risks×4 workloads×5 seeds` | 6,400 |
| ID-eval：`24 tasks×6 risks×3 workloads×3 seeds` | 1,296 |
| CodeTwin：18 apps 的 primary 480 加 diagnostic 600 | 1,080 |
| FULLPOLICY-D60 | 1,152 |
| 合计 | **9,928** |

因而 `6,400+1,296+1,080+1,152=9,928`，没有静态计数缺口。资源表的 `7 learned methods×5 seeds×9,928 + 5 fixed baselines = 397,120` 也闭合；再加训练、siblings、validation、ENUM和 calibration 后的 678,280 episodes 算术一致。

### 7.4 时间规则除跨 horizon 外一致

`D60` 只在 `t+60≤600` 时合法，因而合法 D60 的 duration 实际为60秒。到 `t=600` 后移除18个主动 slots 与 D60；只保留 mask-legal EX/AB。EX/AB 从 terminal action 开始时的 current state 出发，分别最多再运行120/60秒，最晚 720/660秒，并不延长决策 horizon。这些规则彼此一致。唯一未闭合的是第4节所示主动 action 跨 600 秒的核内 censoring。

## 9. Benaroch 理论责任与直接近邻

### 9.1 理论映射可以保留，但不得扩大成 Benaroch 已证明的神经结构

Benaroch（2018）全文明确给出四项与本题直接相关的结构：零项或多项 proactive mitigations、wait-and-see 与 act-and-see、mitigation 对 outcome distribution 的离散 impulse，以及 mitigation cost/impact 随此前序列而产生 substitutive、complementary 或 synergetic 条件作用。正文和附录 Table A.1 还展示了多项既往 mitigations 条件下的 path-dependent impact parameters。

01H 把这些责任下推到 `p` 的有序 action list、learning/prevention/coping roles、main+ordered-pair residual、D60 与 EX/AB 的同一 recursion。它也明确承认：低秩二阶 tying、三阶 mixed difference 为零和具体 tensor 都是本文算法推论，不是 Benaroch 原句。这个理论责任边界是合格的。

二阶截断不能被写成理论真理，因为 Benaroch 的附录允许多项历史条件化。它在本研究中只能作为有限数据下的可证伪归纳偏置。共享 `PhysicalKernel` 读取已实现的 `g/κ/c/t` 以表示此前行动的实际物理后果是合理的；理论 residual 则表示在 matched physical state 上由 action identity与顺序产生的条件 impulse。能否相对 unrestricted history generic 产生不可替代的行动改进，必须由 pair-zero、role-neutral、order reversal与公平 generic 实验决定。

### 9.2 AgenticDB 定位准确

AgenticDB 已提供跨 DBMS/OS 的受控 action catalog、context-grounded diagnose–act–observe、Validator/Executor/Recovery/Auditor和根据执行反馈继续、改向或终止的闭环。01H 因而没有再声称“数据库 agent 的安全序贯执行与恢复无人研究”。它将剩余差异限定为 repository-conditioned live schema migration、zero-or-more mitigation lattice、EX/AB、可训练 joint consequence kernel和本研究的 policy qualification；同时说明 AgenticDB 的目标是 performance reconfiguration、LLM 参数保持固定。这个 ACK/LIM 与全文相符。

### 9.3 仍须补入 SysInsight，并取得 DBAgent 全文

SysInsight 是本轮发现的直接邻近工作。其 PVLDB 19(6):1358–1371 全文及 DOI `10.14778/3797919.3797940` 明确说明：系统从 DBMS source code 的 control/data flow中定位 knob-controlled execution paths，以 LLM code reasoning提出 tuning hypotheses，再用真实 tuning observations形成 quantitative、verifiable rules，在线根据诊断采取配置行动。它不做 application-repository schema migration、optional mitigation lattice或本文的外部 harm评价，因此不会直接杀死本题；但它已经占据“代码包含行动后果知识，代码驱动 agent可把这种知识变成可验证数据库行动”的近邻位置。正式 gap 不能再把 code-derived database action暗示为无人研究。

DBAgent 的公开书目信息把它定位为 RL-based autonomous database operations and maintenance，并被列为 VLDB 2026 Industrial Track。由于本轮未取得全文，不能以作者主页短介绍替代方法、训练、动作、评价和安全边界的逐段核验。在取得全文并与 `G-POMDP/G-DirectQ`、AgenticDB及本题动作格逐项对齐前，最强 learned database-agent 近邻审查仍未闭合。

## 11. 冻结前必须完成的设计门

以下项目不能由未来好结果补救。

1. **可观测 runtime canonicalizer**：消除 cell对隐藏 `z,h` 的依赖，或把 canonical state正式提升为分布；不得把 benchmark latent truth或任意 MAP branch写入执行状态。
2. **核内 horizon censoring**：把 `d_eff/η_eff`、typed decoder、event exposure、accumulator、ledger、belief likelihood和 next state统一进同一个 `Q` branch；新增跨 horizon golden counterexample。
3. **post-link 因果闭包**：禁止边际的 mask必须约束 action-conditioned shared base，并覆盖 `Γ/stat`、`D/dur`等全部可行动祖先；用代数结构而非测试偶然通过保证 total action effect与 residual Jacobian均为结构零。
4. **共同 mask工件**：完成第3项后物化唯一 `physical_mask_v2.npz`、axis labels、hash及主模型/generic共同读取证明，运行 `TT-1..6` 与 `MT-STATE-01/02`。
5. **公平预算同步**：`parameter_count.json/flop_report`同时锁定 training 与 inference FLOPs；共享初始化使用 byte-identical clone而非 live alias。
6. **近邻闭合**：在 ACK/LIM 中补入 SysInsight；取得并逐段阅读 DBAgent 全文后，与 learned joint kernel、RL动作、反馈、训练和外部风险评价逐项对齐。找不到全文时明确保留 `[待核验全文]`，不得用主页摘要填满能力边界。
7. **肖文句级重审**：对35个自称同位行逐一重新执行 `source_function_code/candidate_function_code + PRE→SRC_NEW/CAND_NEW→REL→CIT→NEXT→RESULT`；任何一命题、后继义务或证据责任不一致的行降为位置参照或无锚点。

只有上述七门全部闭合，才值得再次申请 `DESIGN-FROZEN / RESULTS PENDING`。

## 12. 只能由真实实验决定的结果门

以下为空不影响本轮设计判断，也不得提前写成已成立。

1. 72项任务达到预注册 clean inclusion门，八个 test app各保留至少三项 migration，且没有 source/template/seed泄漏。
2. CP/WC typed cells在真实执行中产生可区分且持久的 `g/κ`，SR/SV、WC、CP的 physical zeros经真实实现验证。
3. D60 observation对 latent condition有信息并改变后继行动，而非只增加等待成本。
4. 至少两个预注册 conflict strata出现 mitigation order reversal；pair-zero、role-neutral、No-PassiveInfo、No-D60或 No-Abandon必须改变 actual action和外部结果，而不只是内部分数。
5. CodeTwin 的 Full-Code相对 No-Source/SchemaTelemetry在 severe harm、success或 cost上产生外部结果增量；只改变 action ID不建立 coding-agent必要性。
6. 五个 `γ` 的 policy qualification按冻结15项 family执行；若 qualified set为空，必须报告 calibration failure，不得放宽阈值。
7. 主模型相对 `G-PhysicalFactoredSMDP` 在预注册 finite-data、unseen-combination和 held-out slices上形成 safety–success–cost增量。若落入等效 margin，则撤销独立理论算法贡献。
8. Repo-OOD、Workload-OOD和Risk-combination-OOD只按有限 benchmark scope解释；不得由好结果升级为现实总体保证。

## 13. 最终结论

二次修补已经解决旧版最严重的 typed next-state缺失、evidence稀释、active mixture重加权、generic空规格和 AgenticDB遗漏。研究题、理论映射、benchmark总体和反证设计仍具有可保留价值。

然而，当前真实观测不能在隐藏 `z,h` 下唯一映射到 runtime canonical branch，action-conditioned base及 active status/duration又可以继续改变禁止边际，跨 600 秒 action还在联合核之外重写 `η/d`。这些问题直接影响 agent会预测什么后果、进入什么 state以及选择什么行动，属于不可由未来性能弥补的设计缺口。最强近邻与肖老师五十条责任账也尚未闭合。

据此，本次唯一允许的终判为：**CONDITIONAL / DESIGN NOT FROZEN**。结果继续保持 **RESULTS PENDING**，本审计没有因结果缺失本身作出负面判定。
