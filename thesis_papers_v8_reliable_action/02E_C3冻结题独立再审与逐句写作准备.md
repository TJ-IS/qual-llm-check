# C3 冻结题独立再审与逐句写作准备

## 0. 审查结论

**截至 2026-08-16 的独立终判是：将 C3 从 `DESIGN-FROZEN / RESULTS PENDING` 降级为 `CONDITIONAL / DESIGN-NOT-FROZEN / RESULTS NOT RUN`。**

这一判定不是因为检索到一篇已经完整实现 C3 的论文。精确到输入、状态、动作和外部结果，目前仍未发现工作同时研究以下组合：外部机制已经决定升级，可信中介已经把审核对象绑定为即将执行的 coding-agent 行动，学习型策略随后在有限预算内选择可执行后果证据及其呈现、事实探针和理解修复，最后以真人对真实状态变化的危险误批为主要结果。C3 因而没有被直接近邻整题覆盖。

降级发生在设计门，而非结果门。现有冻结规格有四项尚未闭合的设计责任。

1. `00J` 把 Clark 的 identification、ability、willingness、mutual belief 与 objective、resource、risk、commitment 写成近似一一转译。Mastrogiacomo 等人的原文不是这个层级。其表 3 把 ability 同时展开为 resources 和 risks，把 mutual belief 解释为在项目会议和对话中持续寻求相互理解证据的过程。四类项目内容来自对前三项条件的情境化改造，不是四项 joint-purpose 条件的同构张量。
2. 等信息、等标签的 Human-state POMDP 或通用历史 POMDP 在表达能力上可以重建 `F_cg` 的乘性门及其策略。common-ground 结构可以是有方向、可干预的归纳偏置，却不是通用模型无法计算的独占能力。当前规格承认这一点，但尚未给出足以把理论状态与同源事实问答、最终批准和任务结果分离的测量设计。
3. 公开数据足以预训练技术证据编码器，却不提供序贯真人 grounding、反事实证据动作和危险误批的联合监督。现有“至少 90 名开发者，每人 12–18 个 trial”的下限可以成为效应检验的功效起点，不能自动证明有足够支持度训练高容量 `F_cg`、`T_ev` 和离线策略，再用独立参与者作前瞻评价。
4. `00H` 禁止把 gold patch 和 hidden test 内容作为模型特征，但还需把禁令扩展到候选证据格、动作可用性、action mask、剪枝顺序、运行时延和命题生成。否则 hidden oracle 即使不出现在张量中，也会通过“哪些动作被提供”泄漏。

这四项均可修订，故本判定不是 NO-GO。完成第 8 节的再冻结条件后，C3 可以重新申请 `DESIGN-FROZEN`。任何实验结果尚未产生；本文不把设计预期写成发现。

## 2. 钢人化后的 C3 研究合同

先把 C3 写成最强、最窄的版本，避免用边界漂移制造新颖性。

### 2.1 决策时点

外部风险机制已经作出“该动作必须由人审核”的决定。C3 不决定何时询问、不预测是否应升级、不自动批准或拒绝。可信中介已经冻结以下对象：canonical command 或 diff、tool arguments、repository/container identity、base commit、pre-state、working-tree hash、权限、作用域和 action hash。动作、仓库状态或权限一旦变化，已有证据与 grounding 状态按绑定关系失效。

这一时点使 C3 与 Hedwig、When Should Users Check、PCAA 的 route 阶段形成可检验分界。`second-reviewer` 与 `stop` 也必须只把事件交还外部 gate。若策略用这两个动作决定是否继续自动执行，或用证据预算重新判断是否需要人类，研究会重新落入 when-to-ask 和 allow/deny 空间。

### 2.3 理论前向的可保留部分

`00H` 提出的四路门可以作为待检验结构：

`g_est,t = g_pot,t ⊙ q(B_H,t) ⊙ c(C_t) ⊙ sqrt(M_t[:,1]⊙M_t[:,2])`。

其可保留主张是：可见性、审核者的 action-specific 解释、grounding 互动进展和可观察的双向 uptake 都是“当前系统有理由认为理解已建立”的必要证据来源。其不可保留主张是：Mastrogiacomo 或 Clark 已经推出上述乘法、平方根、单调门或数值可辨识性。公式是理论启发的结构假设，必须由校准、反捷径和行为干预检验承担经验责任。

### 3.2 是否被直接覆盖

精确组合没有被覆盖，但各层已高度拥挤。C3 的新增能力不能写成 canonical binding、可执行证据、问答 grounding、POMDP 或真人审批中的任何单项。它只能是一个因果链完整的新能力：在固定审核事件内，oracle-blind 策略主动取得真实后果证据，并依据同一审核者对 action-bound 命题的可测误解选择下一项 repair，最终在匹配 safe approval、审核时间和算力的条件下降低危险误批。

任何下列退化都会被近邻覆盖。

- 只生成更好的测试或验证证明，退化为 BSG-VA、Archer、RECEIPT 或测试生成。
- 只把完整证据摘要给人，退化为静态 bundle 或 trace/specification 界面。
- 只预测何时询问或谁来审批，退化为 Hedwig、CDCR 或 intervention prediction。
- 只分类 reviewer 是否理解，退化为 interpretation matching。
- 只实现 hash、canonical renderer、receipt 或 certificate，退化为 Consent Integrity、CAVA 或 PCAA。

## 4. common ground 的 MEC→MAP→ALG 层级复核

### 4.1 原理论实际支持什么

Mastrogiacomo 等的原文建立了四个层次不同的命题。第一，joint activity 中各方行动相互依赖，必须预期彼此行动。第二，common ground 包含各方相信彼此共享知识、信念和假设的递归成分。第三，grounding criterion 是对当前目的而言已经有足够相互理解证据，点头或简单确认不能自动证明这一点。第四，在 IS 项目中，作者用设计科学和实践知识把 Clark 的条件转成一个会话工具并在三个案例中评价。

Table 3 的精确转译是：identification 对应 joint objectives；ability 同时对应 joint resources 和 joint risks；willingness 对应 joint commitments；mutual belief 对应在项目会议或相关对话中寻求四类内容的相互理解证据。原文还明确承认 willingness 到 commitment 的关系出于选择与实用考虑，留待后续研究。由此可见，`objective/resource/risk/commitment` 是情境化内容家族，`mutual belief` 是围绕这些内容发生的互动过程。

Tolzin 与 Janson 的系统综述把 embodiment、social features、joint action、knowledge base 和对 conversational agent 的 mental model 归为宽泛机制，并区分动态、情境化 common ground 与更稳定的 shared understanding。该综述支持把 common ground 带入 HAI 的合理性，不推出 C3 的命题类型、门函数、损失或策略。

Poelitz 的真人 benchmark 表明 shared view 会影响任务表现，也发现多项人类对话预期并未在 HAI 中稳定复现。Li 等进一步显示，静态任务内容可能让模型把潜在共享误判为已经建立的理解。这两项工作支持“可访问不等于已建立”的问题，但不能为 coding approval 中的中介效应提供现成证据。

### 4.2 必须改写的 MEC→MAP→ALG

| 层级 | 可保留内容 | 必须删除或降格的内容 |
| --- | --- | --- |
| MEC | 相互依赖行动需要对彼此理解进行校准；理解证据不足会形成 coordination surprise；grounding 需达到当前目的的充分标准；clarification 与 repair 是更新过程 | “四个 Clark 条件就是四类 coding 命题”；“递归理解天然服从乘性门”；“common ground 保证证据事实正确” |
| MAP | `J_content` 表示 objective/resource/risk/commitment 的任务内容 manifest；`B_H` 表示审核者对具体 post-state 的解释后验；`C` 表示互动阶段；`M` 表示可观察 uptake；`κ` 表示审核目的预先要求的内容 | 把 `J_content` 命名为四个 joint-purpose condition；把 approve、停留时间、confidence 或一次复述直接标成 established common ground |
| ALG | 结构门阻止只有静态可见性时把 `g_est` 补高；残余缺口改变下一证据、probe、repair 和停止动作；对 access/history/participant/purpose 做有方向干预 | 声称乘法门由理论唯一推出；让 raw history 旁路理论状态；用最终批准或 hidden harm 反向定义 `κ`、`M` 或 `g_est` |

### 4.3 建议的层级修正

正式设计应把原 `J` 改名为 `J_content`，其四列只是任务内容类型。另设 `D_joint={identification, ability, willingness}` 作为理论条件到内容家族的稀疏关系：objective 主要连接 identification，resource/risk 主要连接 ability，commitment 主要连接 willingness。mutual belief 不成为第五类内容，而由 `C`、双向 `M` 和 criterion 过程承担。这个修正不是增加术语，而是防止把内容分类和递归理解过程混成同一轴。

`κ` 必须在任何参与者回答、批准和 hidden outcome 出现之前，由任务作者或独立专家依据审核目的冻结。它可以规定哪些命题必须达到何种事实正确率或不确定性阈值，却不能从最终是否误批学习，否则“达到目的”会被结果标签循环定义。

## 5. 等信息 Human-state POMDP 反证

### 5.1 表达能力结论

设 C3 的结构状态为 `z_t=f_θ(h_t)`，其中 `h_t` 是同一技术图、命题、事实响应、互动历史和预算，策略为 `π_ψ(a_t|z_t)`。一个读取相同 `h_t` 的通用 POMDP 可以在其隐状态中近似 `f_θ`，再近似同一策略。如果它还获得相同 `L_interp`、phase、uptake、purpose 与 outcome 标签，则结构模型没有额外信息。乘法、单调门和掩码都属于通用网络可表示的运算。

因此，理论无法以“通用模型不能复制”为设计贡献。可以检验的主张只有三类。

1. 在较少真人轨迹下，结构约束提高样本效率或校准。
2. 在新仓库、新审核者、新风险类型或 action/state swap 下，结构状态带来更稳定的分布外行为。
3. 对 potential、history、uptake 和 purpose 做语义明确的 clamp/shuffle 时，模型动作按理论方向变化，而通用模型没有同等稳定的干预响应。

若等参数通用模型复制安全—效率前沿和上述干预行为，必须撤销独立 common-ground 算法贡献。C3 仍可能留下一个 learned evidence-and-grounding engineering artifact，但不能继续以理论算法作为独立贡献。

### 5.2 当前标签为什么可能自证

`00H` 让 `B_H` 来自 factual response、让 `M` 来自 clarification/repair、又让 `g_est` 决定下一 probe 和停止。如果 phase、uptake 和 established 的训练标签仍由同一组系统发问、审核者回答及最后批准派生，模型可能只是把“答对系统题目”重述为 common ground。这个风险不靠多任务损失自行消失。

再冻结前应分离六类监督来源。

| 状态 | 允许的监督 | 禁止的监督捷径 |
| --- | --- | --- |
| `J_content` | 独立任务作者在行动前冻结的 proposition manifest；双人审校 | hidden test、gold patch 或模型事后从结果生成的命题 |
| `V/g_pot` | 界面实际暴露日志、证据访问权限、可用性记录 | 审核者是否答对或批准 |
| `B_H` | 决策前的 post-state 预测、范围/权限/回滚事实题，答案由可信执行事实核定 | confidence、停留时间、approve click |
| `C` | 独立标注的 presentation/clarification/repair/acceptance 行为及其时序 | 仅凭模型自己输出的 act tag |
| `M` | 人的 clarification 是否被系统显式 uptake，并在后续证据或命题中可观察地采用；再由人确认系统理解了修正 | 一次礼貌确认、同源语言模型自评分 |
| `κ` | 审核前由目的与风险规范确定的 required propositions 和阈值 | 由 unsafe approval、最终批准或模型 reward 反推 |

还应加入独立的 paired-interpretation 标注：审核者说明自己认为证据意味着什么，系统给出其对该说明的结构化 uptake，另一名不接触最终 outcome 的标注者判断二者是否一致。这样仍只能测量 established common ground 的证据，不应声称读取人的真实信念。

## 6. 数据、训练、真人实验与 coding-agent deletion

### 6.1 公开数据能训练什么

BSG-VA、SWT-Bench、c-CRAB、FixCheck、AgentLens 和 action-swap/stale-state 分支可以为技术图、证据有效性、状态差异、成本和候选转移提供监督。BSG-VA 的 G 回放定义 gold-aligned 与 candidate-specific 证据，因而适合离线标签和评价，不是部署时可观察输入。Consent Integrity 的命令语料可以压测 action rendering 和分类边界，不提供真人批准或 grounding 标签。

这些公开资产不能直接训练下列对象：审核者对某一绑定行动的事实解释后验，clarification 后的 reciprocal uptake，证据动作对同一审核者理解的反事实增量，以及理解变化对危险误批的中介效应。公开数据因此足以支撑 `E_tech`，不足以单独支撑 `F_cg`、`T_ev` 和 `π_cg`。

### 6.2 当前真人下限为何尚不足以冻结

90×12–18 只产生 1,080–1,620 个 trial 级结果。每个 trial 可以产生多个互动 step，但这些 step 在参与者和任务内相关，并不等于同数量的独立 unsafe-approval 样本。对于 acquire、present、probe、clarify、repair、second-reviewer、stop 等多类动作，离线策略还需要在相似状态上观察多个可行动作，才能满足 positivity/support。若开发阶段只按当前策略收集数据，未选择动作的反事实价值不可识别。

建议把数据流程改为三个互不复用参与者的阶段。

1. **测量与支持度 pilot。** 使用少量、低风险、完全隔离任务验证事实误解是否存在，冻结命题、题目和 `κ`，并用预注册随机 logging policy 在合法证据动作间制造覆盖。该阶段只决定设计是否可学，不宣称主效果。
2. **策略学习集。** 在新参与者和训练仓库上收集足以覆盖 action×risk×reviewer-support 的随机或已知 propensity 轨迹。冻结 `E_tech` 的大部分参数，限制 `F_cg/T_ev/π_cg` 容量，并报告每动作有效样本量、propensity、ESS 和 OOD 支持缺口。
3. **前瞻评价集。** 冻结权重、阈值、界面和预算后，在完全新参与者、新仓库和至少一个未见风险类型上比较静态 bundle、通用 POMDP 与 C3。此阶段不再更新 reviewer model 或 policy。

形成性 pilot 本身不能占据完整论文设计题位。如果 pilot 只能证明有 factual misunderstanding，却不能支持序贯策略学习和前瞻安全—效率评价，C3 应停留为识别研究或被重新设计，不能以“已有真人数据”维持算法论文规模。

### 6.3 coding-agent deletion

删除 coding agent 后，common-ground filter、事实 probe 和 repair 可以迁移到任意高影响人机决策。因此 common-ground 理论层本身不是 coding-agent 独有。C3 仍能成为 coding-agent 论文，依赖的是技术动作与结果链：agent 提出会改变仓库或运行状态的 diff/command；同一 agent 还可能选择弱验证；策略可以在隔离环境实际运行 patch、test、mutation、scope 和 rollback 探针；审核者对这些后果的误解会改变是否允许真实状态变化。

正式实验必须证明这一技术层是 load-bearing。至少加入一个“相同 grounding 界面但只允许静态通用解释”的删除实验，以及一个“保留 executable evidence acquisition 但删除 reviewer-state repair”的删除实验。若前者与完整 C3 相同，coding-agent 特有取证没有贡献；若后者相同，common-ground 理论没有贡献。

## 7. action-derived evidence 与 hidden oracle 隔离

### 7.1 当前最大泄漏通道

BSG-VA 的 G 状态和 hidden benchmark tests 可以在离线阶段判定某证据是否 gold-aligned，也可以定义最终 unsafe action。危险在于，候选动作集合若依据这些标签生成或筛选，策略会从动作可用性得到 oracle 信息。例如，只有对 hidden failure 有判别力的 test 被纳入 lattice，即使模型看不到 hidden test 内容，“该 test 被提供”本身已经泄漏。

同样的泄漏可以经过 proposition manifest、action mask、运行失败类型、证据生成时延、候选排序、缺失值模式和二审知识域标签发生。只检查模型输入列中是否出现 `gold` 或 `hidden` 不够。

### 7.2 再冻结所需的 oracle-blind 协议

1. **角色隔离。** candidate generator 只能看到公开 issue/task、绑定行动、当前 repo/pre-state、公开测试和授权工具。oracle evaluator 位于独立容器，只在候选 lattice 冻结后计算 hidden functional/security/scope/state-damage 标签。
2. **候选先冻结。** 每个 trial 的 action grammar、候选动作、mask、成本和超时在读取 hidden outcome 前写入带 hash 的 manifest。任何 oracle 后剪枝都会使该 trial 退出主分析。
3. **生成与评价分开。** gold patch/G replay 只产生训练 split 的离线标签和 sealed test 的评价。它们不能影响 proposition 内容、证据文本、动作排序、availability 或 latency feature。
4. **B replay 的边界。** 原始 pre-state 是审核时真实可得状态，针对审核者可见的候选 test 在 pre-state 上执行可以是合法 action-derived evidence。G replay 和 hidden evaluator 不可见。论文必须逐项声明哪个状态在真实部署时可得。
5. **分组划分。** repository、base commit、issue/bug family、gold-derived sibling、生成 test lineage 和参与者全部成组隔离。测试参与者的互动不得回流训练 reviewer model。
6. **状态失效。** action hash、working tree、permission 或 scope 变化后，所有依赖旧对象的 evidence node、factual answer、`B_H`、`M` 和 `g_est` 都按依赖图失效；不能只清缓存文本。
7. **机械审计。** 保存 generator/evaluator 镜像 digest、可见字段白名单、候选 manifest、hidden oracle access log、split hash 与数据 lineage。对 action availability 训练一个 oracle-prediction probe；若仅凭 mask/成本/时延即可异常预测 hidden label，先修复泄漏再训练主模型。

## 8. 设计门、结果门与再冻结条件

### 8.1 设计门

以下条件在任何正式训练和真人主实验之前必须满足。失败代表设计不可冻结，不是等待结果即可补救。

- 外部 escalation 与 canonical action-binding 是不可被策略改变的前置条件；`stop` 和 `second-reviewer` 只返回外部 gate。
- 把 objective/resource/risk/commitment 改为 `J_content`，按原文修正 identification/ability/willingness 与内容家族的关系，mutual belief 由互动过程承担。
- 为 `J_content,V,B_H,C,M,κ` 建立相互独立、按可见时点冻结的 label manifest；最终批准和 hidden harm 不定义理论中间状态。
- 先运行 measurement/support pilot，并给出 action-level propensity、覆盖与 ESS。若没有支持度，不能训练离线序贯策略。
- 候选 evidence lattice 在 hidden oracle 前冻结，generator 与 evaluator 角色隔离，所有 availability side channel 接受机械 probe。
- 预注册等信息、等标签、等参数的 Human-state POMDP、Raw-POMDP、generic proposition Transformer 和 contextual-bandit/POMDP；不能让 C3 独享 proposition labels 或额外人类反馈。
- 把 `00J` 的段落蓝图重新做成 `00W` 精确句键、source/candidate function code、完整责任链和法定 RESULT 的逐句记录。

全部通过后，可恢复 `DESIGN-FROZEN / RESULTS PENDING`。通过设计门不等于证明 common-ground 机制有效。

### 8.2 结果门

结果门只能由未见参与者、未见仓库和 sealed evaluator 的真实数据判定。

- 在匹配 safe approval、屏幕空间、token、取证时间和计算预算后，C3 降低 unsafe approval，而非靠更多拒绝或更多警告。
- 策略先改善 action-specific factual grounding，grounding 的变化进一步解释危险误批变化。若只有直接效果，优先归因于 evidence quality。
- potential-content、grounding-history、participant-response、purpose-type、action-binding 和 stale-state 干预产生预注册的状态与动作变化。
- 等信息 Human-state/Raw POMDP 未复制安全—效率前沿、低样本优势、OOD 行为和理论干预响应。复制即撤销独立理论算法贡献。
- 新仓库、新审核者和未见风险类型上的结果具有不确定区间、效应量和失败案例；不得只报告 pooled accuracy。
- oracle-blindness probe、split lineage 和 access log 全部通过；任何 hidden 信息进入候选生成、mask 或测试参与者训练都会使相关组退出主分析。

## 9. `00J` 对 `00F/00W` 的写作合规复核

`00J` 第 9–11 节有 24 个段落蓝图，分别是 I1–I8、T1–T7 和 A1–A9。它们有助于保持“情境—机制—理论—工件”的总体节奏，但不满足 2026-08-16 版 `00F` 的逐句审计标准。

1. 大多数参照写成“ACAA 第 39 行”或“DSDL 第 45 行”，没有同时填写 `00W` 段落主键和语法句 ID。

## 11. 正式写作前的段落顺序

在修正设计后，引言不应从 POMDP 或乘性门开头。建议沿以下功能链推进，每一步都要再建与第 10 节同规格的逐句卡。

1. coding agent 的持久状态行动与人工审核情境。
2. action binding 已解决“审核对象是什么”，但可信显示不等于正确理解。
3. executable evidence 已解决部分事实可信性，仍未解决同一审核者是否建立 action-specific interpretation。
4. 以 supervision 实证建立误解与负担，不让 common-ground 理论替代场景事实。
5. 以递归理解、grounding criterion 和 repair 建立机制，再诚实说明其向 coding approval 的迁移尚待识别。
6. 修正后的 content-family 与 mutual-belief process 映射。
7. 两个研究问题：如何估计 action-bound grounding state；如何在固定审核事件内学习下一证据与 repair 动作。
8. 安全—任务—成本联合评价，最后才概览四个训练工件。

理论节必须先交代原文的非一一映射，再提出本研究的结构假设。方法节必须把 canonical action 与 verifier 明确列为技术基座，不得作为 common-ground 理论贡献。实验节必须把 measurement pilot、policy-learning data 和 prospective test 分开，避免用同一批参与者同时定义状态、训练策略并检验效果。

## 12. 最终判定与责任归属

C3 的精确技术空位仍存在，固定 post-escalation 和 canonical action-binding 也确实能把它与 when-to-ask、allow/deny 研究分开。最新工作增强了其必要基座，同时压缩了可主张贡献：binding 属于 Consent Integrity/CAVA，路由与证书属于 PCAA，executable verification 属于 BSG-VA/Archer/RECEIPT，知识获取属于 ACQUIRE，一般 grounding benchmark 属于 Poelitz/Li。C3 必须用真人危险误批和可干预理解状态证明这些基座之间尚缺的能力。

现设计最严重的问题不是没有实验，而是理论内容轴与互认过程轴混位、监督可能同源自证、策略学习支持度未冻结，以及 oracle 可通过候选动作集合泄漏。这些属于实施前可修正的设计问题。故结论是降级为 `CONDITIONAL / DESIGN-NOT-FROZEN`，而非直接撤题。

再冻结时只需回答一个严格问题：在不改变升级时点、不拥有 hidden oracle、不独享标签和算力的条件下，修正后的 common-ground 状态是否使序贯取证策略在新审核者和新仓库上作出通用 Human-state POMDP 不稳定作出的、理论方向明确的 repair 选择。这个问题属于结果门，但使其可识别所需的映射、标签、logging support、split 与 oracle-blind protocol 必须先通过设计门。
