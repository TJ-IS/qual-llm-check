# 开放源码维护者注意力外部性候选终审

> 审计日期：2026-08-16  
> 审计对象：贡献者侧 coding agent 在多个 issue／PR 之间决定何时调查、实现、提交与持续跟进，以免把生成成本下降转化为维护者注意力外部性。  
> 终审结论：**终局 NO-GO；保留候选数为 0。**  
> 结论范围：不能占用三篇论文题位。跨 PR 承诺容量仍值得做现象测量或随机化识别试点；本文件不否认该实践问题，只否决当前的独立“IS 理论驱动算法论文”主张。

## 0. 终审结论先行

coding agent 可以同时生成、提交并遗留大量看似合理的贡献。维护者必须判断这些贡献是否重复、是否符合项目方向、是否安全正确，并在反馈后等待贡献者继续修复。生成端扩张与审核端稀缺之间因此存在真实损害。AI-DDoS 已记录贡献洪峰、低质或虚构内容、一次性贡献和维护者倦怠；AIDev 系列显示 agent PR 已形成大规模真实生命周期数据；最新并发研究又发现同一仓库中 agent PR 的重叠十分普遍。问题情境成立，且不应被简化为“PR 能否合并”。

钢人化后尚未被单篇直接实现的技术对象，是一个**贡献承诺控制器**。它在提交新 PR 前，同时考虑当前开放 PR、待回复评论、可用跟进容量、重复或冲突贡献、项目规范和补丁证据；它可以继续调查、缩小或拆分补丁、先发 draft 或预协调、提交、回复并修复、撤回、延迟或放弃。它必须实际修改代码和 PR 状态，不能只输出一个风险分数或给维护者排序。

这个联合对象仍未通过四个独立门槛。第一，直接工作已覆盖其绝大多数原子能力：RepoComplianceBench 覆盖规范读取、验证、披露、移交与拒绝；AGM 已把风险分区、贡献报告、测试证据、trace、linked issue、缺失证据、已知限制、贡献者确认和 maintainer review packet 串成贡献前治理工件；Learning to Commit 覆盖仓库历史适配与“有机”补丁；SWE-Review 覆盖单 PR 自审与修订；Google 的生产系统覆盖按审查评论生成修复；AI-DDoS 和 PR 放弃研究已明确提出预讨论、证明理解、缩小贡献与保持响应；并发研究直接测量多 PR 冲突。余量主要是把这些动作放进跨 PR 时序策略。

第二，Safadi、Lalor 与 Berente（2024）的可核机制来自 Reddit 中的 reflexive bots 和 supervisory bots。原文明确把 anticipatory bots 与 prescriptive bots 留给未来研究。把“恒定注意、宽 reach、表层 interactivity”延伸为 contributor agent 的“承诺债务”和“跟进容量保留”可以形成新假设，却不是原理论已经观察或推导的算法状态。Butler（2001）能解释规模、交流收益与注意成本的对立，但其分析单位是在线社会结构的成员持续性，同样不产生贡献者侧动作算子。

第三，在相同输入、标签、动作和参数预算下，普通 temporal HGT、CMDP 或 POMDP 可以直接学习开放 PR 图、回复历史、补丁证据、预期人工分钟和跟进失败，并执行完全相同的延迟、拆分、提交、修复或撤回动作。理论分支若只增加 reach、reciprocity 或 commitment-debt 头，就是可删除的辅助表示；若强行加入单调阈值或“债务守恒”，则是研究者新造的规范规则，而非 Safadi 机制。

第四，删除 coding agent 后，批量化的人类贡献者、外包贡献团队或传统自动化 bot 仍可使用同一状态、动作、损失和评价环境。coding agent 显著放大并行生成和低成本提交，是问题的重要规模条件，却没有改变当前候选的核心决策结构。因此，候选不能证明其算法能力是 coding-agent 特有研究空间。

本终审据此保留 0 个候选。重开必须同时获得新的机制、识别和独立能力证据，不能仅把跨 PR 调度实现得更复杂。

## 1. 研究对象与真实损害

### 1.1 安全含义与介入时点

本候选中的广义安全不是传统入侵防护。风险是 agent 以近零边际生成成本占用有限维护者注意力，并让错误、不安全、重复、超范围或无人跟进的补丁进入真实审核流程。损害对象包括维护者的时间与认知切换、项目的审查积压和安全边界、正确贡献者的进入机会，以及 agent 已承诺却未完成的任务。

介入点位于贡献生命周期中的多个时点。

1. 在选择 issue 或开始实现前，agent 可调查规范、项目方向、已有 PR 和重复工作。
2. 在提交前，agent 可补充测试与证据、缩小或重构补丁、拆分或合并相邻任务、发起预协调或 draft，并决定延迟或不提交。
3. 在审核中，agent 可读取反馈、执行代码修复、更新测试和解释、撤回失效贡献，或在能力不足时明确移交。
4. 在准备启动另一项贡献前，agent 可根据未结义务与跟进容量限制新的 reach。

### 1.2 可见状态与隐藏状态

提交时可见的信息包括仓库代码与历史、贡献指南、issue 和 PR 文本、当前开放 PR、公开 CI、补丁与测试、公开评论、agent 自己的未结任务和剩余计算预算。可能隐藏的信息包括维护者真实可用时间、每次上下文重建分钟数、尚未公开的项目路线、隐含的安全约束、其他贡献者即将提交的工作、隐藏测试和补丁的长期语义后果。公开队列长度不能合法替代维护者的私有工作负荷。

### 1.3 动作空间

| 类别 | 可执行动作 | 风险含义 |
|---|---|---|
| 正常动作 | 检索规范与重复项；运行测试；生成或修改补丁；提交经过验证且可持续跟进的 PR；按评论修复 | 完成真实贡献并维持可审查证据 |
| 风险动作 | 并行铺开多个低价值 PR；未读规范即提交；用表面说明掩盖错误；在收到反馈后失联；把大型必要变更机械拆碎 | 扩大人工负担、让错误进入审核或牺牲正确高价值贡献 |
| 纠正动作 | 预协调；draft；补证；缩小、重构、合并或拆分；暂停新任务并回复旧 PR；撤回、移交、延迟或放弃 | 降低已施加或即将施加的注意成本，同时保留可行贡献 |

### 1.4 不能被代理指标替代的外部结果

主结果必须直接记录维护者在指定 PR 上的有效审核分钟、重建上下文的次数与时长、错误或不安全补丁到达真人审核的比例、正确补丁最终集成、新人贡献者获得有效通道、agent 在承诺后的回复与修复完成率，以及总任务成功和计算成本。merge、评论数、关闭时长和评论情感只能作为辅助描述。特别是零评论快速合并既可能表示低负担，也可能表示未经真实检查，On Autopilot 的结果不能被写成安全收益。

### 2.3 对 agent-side follow-up escrow／portfolio policy 的专门搜索

截至 2026-08-16，本轮分别以 `coding agent follow-up capacity pull request`、`coding agent portfolio pull requests maintainer`、`agent submission commitment pull request`、`coding agent multiple open pull requests follow-up policy`、`follow-up escrow coding agent PR` 检索 arXiv、ACM／MSR、Google Research、GitHub 官方材料和已下载 SE 全文。结果返回 PR 生命周期角色分类、并发冲突、unmerged／ghosting、主动 agent 观点论文、静态 PR limits、贡献规范与 maintainer-side triage；没有发现一个已实现的 **agent-side follow-up escrow** 或 **learned PR portfolio policy**。

因此，最窄技术余量可命名为 **reciprocity-backed submission commitment**：agent 打开一个需要真人审核的 PR 之前，联合预测随后发生 reviewer 质询、代码修复和重验证的需求，并从自身未来执行容量中预留可兑现的 follow-up reserve；多个 PR 的 broad reach 与每个 PR 的 dyadic follow-through 构成方向冲突。这个名字只描述待检验设计，不能声称 Safadi 已提出此机制。AGM 已覆盖单项贡献进入审核前的证据与责任状态，pytest 已把理解、负责和实质回应写成实践义务，GitHub 又已有静态并发限制。剩余空位只能是**学习型、跨 PR、序贯且执行真实代码跟进的容量承诺政策**，不能是 manifest、evidence package、one-open-PR 规则或 rate limit。

本轮仍没有找到一个同时满足以下条件的系统：由 contributor-side coding agent 执行，跨多个真实 issue／PR 维护承诺状态，能选择不提交或暂停新贡献以保留跟进能力，实际修改代码和 PR 状态，并用真实维护者分钟、错误补丁到达人类审核、正确集成与新人通道做联合结果。这个“联合未覆盖”是真实的技术余量，却不能自动推出理论贡献或算法独立性。

## 3. 最强可实现版本

以下规格用于钢人化和反证，不代表已经冻结设计，也不代表终审放行。

### 3.1 直白研究问题

当 contributor-side coding agent 能并行处理多个 OSS 任务时，它能否学习一种跨 PR 的贡献承诺政策，在保持正确贡献集成和新人可达性的同时，减少错误贡献到达人类审核、真实审核分钟、上下文切换和无后续回应？

### 3.2 输入、张量和模型状态

每个决策时点输入仓库快照、issue／PR 文本、贡献规范、公开历史、当前开放 PR、agent 自身评论与 commit、补丁、测试和剩余预算。低层代码内容仍由可训练代码模型处理，不能只做图路由。

| 张量 | 形状示意 | 内容 |
|---|---|---|
| 任务／PR 节点 | `X_t ∈ R^{B×N×d_x}` | 任务价值、风险、补丁规模、测试证据、重复／依赖候选、当前阶段、最后交互时间 |
| 仓库／角色节点 | `M_t ∈ R^{B×R×d_m}` | 公开规范、开放队列、历史响应、贡献者所有权；不得臆测维护者私有空闲 |
| agent 承诺节点 | `C_t ∈ R^{B×K×d_c}` | 未结 reviewer 请求、待修复测试、已承诺截止点、剩余工具／计算预算和 checkpoint 可用性 |
| 多重关系边 | `E_t ∈ R^{B×N×N×d_e}` | duplicate、文件重叠、语义依赖、同一 reviewer 互动、reply、supersede 与并发关系 |
| 代码表示 | `H_t ∈ R^{B×L×d_h}` | 相关代码、diff、测试、评论与规范 token 表征 |

Safadi 式状态若被纳入，只能标成待识别的新映射：同时贡献范围 `ρ_t`、直接回应欠额 `d_t`、广义曝光 `g_t` 和可用互动容量 `κ_t`。原理论没有定义 PR 承诺债务，也没有给出这些状态的可测更新式。

### 3.3 架构与前向计算

最强版本可以由等参代码编辑器、temporal heterogeneous graph encoder、递归 belief state 和分层 actor 组成。图编码器汇总 repo—issue—PR—comment—commit 关系；belief module 估计下一时段真人反馈、隐藏测试失败、合并冲突、审查分钟和 agent 跟进完成的分布；高层 actor 先选择目标 PR，再选择调查、生成、拆分、合并、draft、预协调、提交、回复、修复、撤回、延迟或放弃；低层代码模型实际生成补丁、测试和 PR 更新。

### 3.4 训练样本与监督

1. AIDev 及 GitHub timeline 可提供观察性行为克隆样本，包括开放、评论、follow-up commit、关闭和合并，但不能把历史行为当最优动作。
2. 历史 PR 对的同起点 sandbox replay 可为拆分、合并、rebase、测试和冲突动作产生可执行结果；隐藏测试与语义安全标签必须重新构建，不能从未来 gold patch 泄漏。
3. 真实维护者注意力只能通过同意参与的隔离研究队列采集。每个标准化任务从同一仓库起点随机分配 contributor policy，维护者记录主动审核分钟和上下文切换；训练参与者与确认性参与者必须完全分离。
4. 对 submit／draft／pre-coordinate／defer 等社会动作，不能用 LLM judge 制造反事实。确认性估计应以随机分配为主，报告意向处理效应、依从性和 attrition；观察日志只能用于预训练和异质性探索。

### 3.5 损失函数

一个可训练但尚未获理论授权的目标可写为：

`L = L_BC + λ_w L_world + λ_q L_CQL + λ_code L_edit + λ_h L_harm + λ_c L_cost + λ_f L_follow + λ_n L_newcomer`。

- `L_world` 预测下一次反馈、测试、安全错误、冲突、人工分钟和上下文切换的联合分布。
- `L_CQL` 或其他保守离线 RL 项学习时序动作价值，避免对日志外动作过度乐观。
- `L_edit` 训练代码修改、测试补充和评论后修复。
- `L_harm` 惩罚错误或不安全补丁到达人类审核，而非惩罚所有提交。
- `L_cost` 使用实测人工分钟和切换，不能以评论数完全替代。
- `L_follow` 惩罚承诺后的失联或未完成修复。
- `L_newcomer` 约束新人来源的正确高价值贡献不因历史地位被系统性延迟。

这组损失本身是通用多目标控制，不是 Safadi 或 Butler 推出的理论算子。

### 3.6 推断动作与安全边界

推断必须在授权的研究仓库、fork 或明确同意的 OSS 项目中执行。每一步都落为 git、测试、PR draft／更新／关闭或评论动作，并保留 manifest、tool trace 和可回放 checkpoint。不得为了降低人工成本而隐瞒 agent 身份、伪造人工理解、刷屏预协调或绕过仓库禁止 autonomous submissions 的规则。

### 3.7 划分、泄漏和算力

- 至少采用时间前推、仓库隔离、issue family 隔离和维护者隔离四种划分；最终确认性人群不可参与训练、提示调优或 pilot 复盘。
- 行动时不得读取未来评论、未来合并状态、未来 competing PR、hidden tests、gold patch 或审核分钟。
- 重放同一仓库时，历史规范与代码只可截取到当时版本；同一问题的派生 PR 不能跨训练／测试。
- 一个可行的工程量级是用 1–2 张 80GB GPU 训练时序图／world model，并用 4–8 张 80GB GPU 对 7B–14B 代码模型做 LoRA 或离线策略训练；沙箱分支数量和真人实验规模需由 pilot 方差决定。这里没有声称已实际训练，也没有结果数字。
- 必须发布数据 manifest、事件时间戳、仓库 commit、规范版本、处理分配、隐藏测试哈希、代码与配置、随机种子、模型权重和失败轨迹。

### 3.8 reciprocity-backed submission commitment 的最窄前向版本

若只钢人化最后一层余量，高层 policy 在动作 `open_pr(i)` 前不应只预测 PR `i` 的一次性质量或 size，而应预测未来 `H` 个决策期内它将触发的 reviewer question、requested change、rebase、CI rerun 和安全复核分布，并从 agent 的可用执行容量中预留 `r_i`。此后 `respond(i)`、`repair(i)` 和 `revalidate(i)` 消耗或释放该 reserve；开启另一个 PR 会同时扩大 broad reach 和挤压现有 dyadic follow-through。顺序具有实践上的非交换性：先打开多个 PR 再补留容量，可能已经把人类引入无法兑现的互动；先完成证据与 reserve 检查再提交，则可能避免该外部性。

这一前向版本确实区别于静态 size gate。大型、高价值、已由项目授权且证据充分的 patch 即使预测审核时间长，也可能值得分配 reserve 后提交；许多单项测试通过但低价值的 PR 即使各自 size 小，也可能因共同稀释 follow-through 而被延迟。它也区别于“一次只开一个 PR”：当两个互不冲突、价值高且 agent 有足够修复容量时，可以并行提交。

但 `r_i`、容量释放式和“提交即形成可兑现 dyadic obligation”均不是 Safadi 原文变量；AGM 只定义单项贡献的证据与责任状态，pytest 只规定人类理解、负责和回应，二者也没有给出 learned reserve update。最窄版本因此是一个可以随机化识别的新设计假设，尚不是由既有 IS 理论授权的机制。更重要的是，generic CMDP／POMDP 只要取得相同未来 workload labels、动作和容量，就能计算完全相同的 reserve 与时序选择。

## 4. 理论机制终审

### 4.1 Safadi、Lalor 与 Berente（2024）的原机制

本轮通过 Otero AIS Basket 全文库定位并完整回读本地全文 `database_fulltext_all/01030_2024_the-effect-of-bots-on-human-interaction-in-online-communities.md`。论文元数据为 Hani Safadi、John P. Lalor、Nicholas Berente，MIS Quarterly，2024，DOI [10.25300/MISQ/2023/17901](https://doi.org/10.25300/MISQ/2023/17901)。原文的分析单位、前因、方向、结果与边界如下。

| 原构念 | 原文定义或作用 | 原方向 | 原结果 | 对本候选的合法程度 |
|---|---|---|---|---|
| Awareness | bot 持续关注，而人类注意是 episodic | reflexive bot activity 增加后，人类注意被分散／转移 | 人类 direct reciprocity 下降 | 可作“自动化扩大注意曝光”的背景；不能直接等同 PR 跟进容量 |
| Reach | bot 可跨广泛参与者响应，人类互动更 local | reflexive bot 扩大互动机会 | generalized reciprocity 上升 | 可提出“宽贡献面增加广义参与机会”的新假设；原文不是贡献提交或代码生产 |
| Interactivity | reflexive bot 互动较 superficial、procedural，人类互动较深且 negotiated | 表层自动回应与深度人际互动存在替代 | 深层 dyadic interaction 受限 | 仅可提示 follow-through 不等于一次评论；不能推出 reserve-capacity 动作 |
| Supervisory bot | AutoModerator 受 moderator 委托执行程序化治理 | 程序化治理替代 negotiated decisions | preferential attachment to human leaders 下降 | 属于维护者／平台侧治理，和本候选被禁止的 maintainer gate 更接近，应删除 |

论文研究的是 1,074 个 subreddit、近 7,000 万条帖子、2007–2019 年 subreddit-month 面板，并使用 PVAR 与 Granger-predictive 分析。它没有随机化 agent 行动；替换 bot 列表、排除 AutoModerator 与更严格 subreddit 阈值时，部分假设显著性会改变。最关键的边界是作者明确把 anticipatory bots 与 prescriptive bots 留作未来研究。Reflexive bot 受触发后回应，contributor coding agent 则会选择任务、编写代码、同时提交多个贡献并承诺后续修复。两者不是同一行动结构。

### 4.2 Butler（2001）与其他相邻理论

本轮完整回读本地全文 `database_fulltext_all/26430_2001_membership-size-communication-activity-and-sustainability-a-resource-based-model-of-online-socia.md`。Butler 的资源模型说明，成员规模和交流活动既带来知识、参与和吸引力，也增加信息暴露、协调复杂度、搭便车与注意成本；这些对立力量共同影响在线社会结构的成员获得与流失。研究对象是 206 个 listserv 的社会结构持续性，结果是 membership change，而非单个贡献者在提交前的时序动作。它能支持“更多贡献并非无条件有益”，却不能生成 PR 级状态更新、非交换动作或损失。

知识 commons 的设计原则主要面向平台／治理者的边界、监督、制裁、冲突解决与嵌套治理。OSS responsive design 研究企业参与者如何在社区规范与企业目标之间进行 interconnection、opportunism 和 domestication，作者亦未观察出一套可直接编码的固定方向关系。两者可以解释情境和治理边界，却会把研究推回 maintainer／platform design，不能冒充 contributor-side policy 的前向机制。

### 4.3 MEC→MAP→ALG 审计

| 层 | 钢人化映射 | 严格反证 | 结果 |
|---|---|---|---|
| MEC | 自动化的恒定 awareness 与宽 reach 扩大广义互动机会，也可能分散稀缺的人类直接互动；跟进深度决定表面触达能否变成 direct reciprocity | 原研究的 bot 是触发式 Reddit bot，不生成补丁、不承担跨 PR 义务；anticipatory／prescriptive 情况由作者留给未来 | 只保留为待识别假设 |
| MAP | 把开放 PR、待回复评论和剩余容量映射为 `ρ_t,d_t,g_t,κ_t`，并设定“提交会增加回应义务，完成回复会偿还义务” | “义务债务”和容量更新并非原构念，也没有原文量尺或方向函数；这是候选作者新造的状态 | 不成立 |
| ALG | 当 reach 增长而 interactivity reserve 不足时延迟新 PR；当大型高价值补丁充分授权时，即使预期审核分钟高也提交；为新人正确贡献保留探索通道 | 同信息 temporal graph／POMDP 可从结果标签学到同一政策；若理论分支强制单调方向，就是手工规则；若允许任意学习，就没有不可替代理论责任 | 不成立 |

理论产生的方向冲突本身有实践意义：大量正确但低价值 PR 可能应延迟；宽 reach 但无法跟进时可能不应提交；大型且高价值、经过授权的补丁不应被 size gate 误杀；维护者效率与新人进入存在冲突。然而，这些都是多目标决策命题。现有理论没有提供其比较权重、动态更新或不可交换顺序，因此不能把合理的冲突例子当作理论算法证据。

## 5. 识别设计终审

### 5.1 公开数据能做什么

AIDev 及其派生数据可重建 PR、评论、review、commit 和 issue 的观察序列；AI Agent PR Concurrency 可重放文本 merge；RepoComplianceBench 可检查 pre-submit policy 行为；SWE-Review 可验证单 PR 功能修订。这些资产足以预训练表示、构建一部分代码执行分支和定义候选动作，却不能识别“如果当时延迟／draft／预协调／撤回，维护者会用多少分钟且正确补丁是否仍集成”。历史日志的 action selection 同任务难度、贡献者能力、维护者偏好和项目拥堵共同混杂。

### 5.2 严谨自建试点

识别试点可以在授权研究仓库中构造多个同起点任务包。贡献者侧 agent 被随机分配到普通单任务 agent、只做规则／CI 的控制、creation-time effort predictor、单 PR review—revise、无理论 temporal policy 和理论映射 policy。真人维护者在不知道算法标签的条件下审核，工具主动记录前台审核分钟、上下文切换、需要返工的错误和最终正确集成。训练队列与确认队列使用不同维护者和不同任务；新人通道可以通过随机提供等质量、不同贡献者历史的任务来测量是否发生身份惩罚。

对动作 `a` 的主要潜在结果可定义为 `Y(a)={human_minutes, context_switches, unsafe_reach, correct_integration, follow_through, newcomer_access, task_cost}`。同一 PR 不能同时执行多种社交动作，因而需要随机分配或明确的 sequential randomization；离线日志的 inverse propensity 只能做补充敏感性分析。对 delayed action 还必须固定观察窗，否则“延迟”会机械减少短期审核量而把成本移到窗外。

该试点在方法上可实施，尚未运行不是 NO-GO 理由。NO-GO 的原因是：即使试点识别出某个贡献策略有效，也首先证明的是一个通用时序控制政策，而不是当前 IS 机制不可替代地改变了 policy。

### 5.3 reciprocity commitment 的可识别性边界

最窄 pilot 应在“有至少两个可提交任务且旧 PR 可能在未来收到真人反馈”的 portfolio state 上随机化，而不是事后比较自选并发度。对每个 portfolio 起点，先固定任务价值、补丁正确性、风险级别和 maintainer review bundle，再随机分配三类 contributor policy：静态并发上限、generic learned CMDP、显式 reserve policy。维护者不知道分组，只看到真实 PR 材料；agent 必须真正响应评论、修改代码和重跑验证。

主要估计对象不是 merge，而是提交政策对 `Y={human_minutes, context_switches, unsafe_reach, correct_integration, response_latency, repair_completion, newcomer_access}` 的序贯处理效应。为识别“预留”而非单纯少提交，三组应取得相同的总任务到达流和最终观察期，且将 defer 后的任务继续追踪到完成、撤回或研究窗结束。维护者按人 cluster，任务按 repository／issue family block；训练用 agent、任务和维护者不得进入确认性样本。预注册还应报告因政策导致的未提交数量和机会损失。

这个设计能够识别显式 reserve policy 是否优于静态 one-open-PR rule，也能够检验大型高价值 patch 与大量小型低价值 PR 的方向冲突。它仍不能仅凭有效性证明 Safadi 迁移，因为相同随机化数据也向 generic CMDP 提供同一监督。只有显式机制的预注册状态更新在等参 generic 条件下产生稳定的增量和可解释干预效应，理论主张才可能继续；当前没有该状态更新的原理论来源。

## 6. 最强基线与公平反证

### 6.1 必须比较的直接基线

1. 无控制的 repository-level coding agent。
2. 贡献规范、静态规则、CI 和 disclosure／verification reminder。
3. MSR 2026 creation-time review-effort predictor 与 size-only circuit breaker。
4. RepoComplianceBench 式规则反馈。
5. AGM 的 risk zone、evidence package、contributor confirmation、missing-evidence diagnosis 和 review packet。
6. pytest 式理解／负责／回应政策与 GitHub 式每人同时开放 PR 上限。
7. Learning to Commit 式历史适配。
8. SWE-Review 的单 PR review—revise loop。
9. Google 式 comment-to-edit follow-up repair。
10. duplicate／overlap 检索和 git merge-replay awareness。
11. 简单“最多 K 个开放 PR”与先完成后启动规则。

### 6.2 等信息、等标签、等动作、等参数 generic 基线

公平反证不能只说 Transformer 是万能逼近器。generic temporal HGT、CMDP 和 POMDP 必须取得与理论模型完全相同的 repo／PR／comment／code 输入、真实分钟与安全标签、sandbox 分支、动作集合、代码编辑器容量、推断工具预算和总参数。理论模型因额外状态增加的参数应从其他层扣除；两个模型使用相同 offline／randomized data 和相同超参数搜索预算。

generic 模型若能学出以下行为，就复制了候选声称的能力：在开放义务过多时优先回复旧 PR；发现 duplicate 或文本冲突时合并／撤回；对小而低价值贡献延迟；对大型但高价值且证据充分的贡献保留提交；在新人历史较少但补丁正确时不以经验代理拒绝。这里没有任何一个动作需要显式命名 direct reciprocity 才能计算。

理论模型的最低存活条件应是：打乱 `ρ_t,d_t,g_t,κ_t` 会系统性改变这些冲突选择；等参 generic 模型在相同数据上不能恢复；该差异来自原理论的有向、非交换更新而非手工阈值。当前原文无法提供这样的更新，因此公平 generic 反证成立。

## 7. 机制干预与消融若强行推进应如何做

即使本候选被判 NO-GO，以下试验可防止未来重开时只做名字消融。

- 删除 multiplex reply／obligation edges，检验是否只剩 PR 大小或队列长度。
- 在不改变总度数的前提下打乱 direct reply edges，区分互动结构与 activity volume。
- 时间置换 follow-up capacity，检验 policy 是否真的使用未来承诺而非当前拥堵。
- 中和 newcomer constraint，报告正确贡献集成、人工分钟和新人可达性的共同变化。
- 以同参数 raw temporal graph 替换理论状态，比较动作分布、校准和外部结果。
- 用大型高价值 PR、许多小型低价值 PR、宽 reach 但容量不足、低历史新人正确补丁四类预注册冲突场景做定向机制测试。
- 报告拒绝／延迟率并验证风险下降不是靠停止所有贡献；延迟的结果窗必须延伸到最终处置。

这些消融能验证状态是否被模型使用，却不能倒推状态来自 Safadi 理论。

## 8. coding-agent deletion test

将 contributor coding agent 替换为人类批量贡献者、外包团队或能创建多个 PR 的传统自动化系统后，输入仍是 repo／issue／open PR／guideline／patch／tests／queue／history，动作仍是调查、缩小、draft、提交、回复、撤回和延迟，结果仍是维护者分钟、安全错误、集成和放弃，Safadi／Butler 的注意与互动解释也仍成立。删除后算法没有失去必要状态或动作。

coding agent 的确改变三个量级条件：生成速度更快、复制实例更容易、规范文本可能被忽略，且工具能自动完成评论后的代码修复。这些条件解释为什么问题在 2026 年变得紧迫，也使本研究需要真实 coding agent 实验；它们目前只是外生规模放大器，没有产生人类批量贡献者不具备的理论机制。删除测试因此失败。

## 9. 与现有候选边界

### 9.1 与 C3 的边界

C3 处理固定审批点之前如何取得可信序贯证据并修复 grounding。本候选若只学习“哪些测试／证据能说服 reviewer”、输出 warrant 或决定是否批准，就回到 C3。合法余量只能是贡献者自己的跨 PR 承诺与执行，不能选择审批结论或把 reviewer evidence 当中心工件。

### 9.2 与 C19 的边界

C19 处理有限审核能力下的 reviewer allocation、疲劳、专家错误与人员调度。本候选不得预测或选择具体 reviewer、给维护者队列排序、决定第二审核者或改变维护者班次。输入只能使用公开队列作为情境，动作必须由贡献者 agent 施加在自己的任务、代码和 PR 上。若最终收益来自替 maintainer 选人或排队，直接并入 C19 的既有 NO-GO 边界。

### 9.3 与 RepoComplianceBench 的边界

读规范、披露、验证、拒绝和 handoff 已被 RepoComplianceBench 直接操作化。把该 benchmark 加上 risk score、提示或 allow／block 不是新题。跨 PR 时序义务是唯一技术余量，但它不能以“更好合规”作为主结果，也不能在仓库明令禁止 autonomous contribution 时继续提交。

### 9.4 与 AGM、pytest 和静态 PR limits 的边界

AGM 已经把贡献侧证据准备、人类确认、风险分区和维护者独立审核构造成完整的 project-level governability artifact。候选若输出 contribution report、test／trace manifest、linked issue、missing evidence、known limitation 或 review packet，即使换成神经网络，也只是重做该工件。pytest 已把理解、负责和实质回应规定为进入其项目的实践条件；GitHub 的并发 PR limit 又提供静态平台控制。剩余空位不能是 responsibility declaration、evidence bundle、one-open-PR 或 rate limit，只能是学习型的跨 PR reserve policy 及其真实 follow-through 结果。

### 9.5 与 ordinary self-review 和 queue control 的边界

只审一个补丁并 revision 属于 SWE-Review；按 reviewer comment 修补属于 Google 系统；根据 PR 大小预测 effort 属于 MSR 2026；根据队列和奖励延迟任务属于 generic queue control。候选只有在跨 PR 互动结构、真实代码动作、真实人工结果、理论有向更新和 coding-agent 特异性同时成立时才可能重开。当前只有前三项可以工程化，后两项失败。

### 10.2 最终编辑动作

**删除。** 本候选不进入三篇论文池，不以 CONDITIONAL GO 占位。可以单独保留一个 measurement／identification pilot：测量 agent 多 PR 承诺、真实审核分钟和 follow-through 的因果关系。只有同时满足以下条件才允许重开。

1. 在 anticipatory／prescriptive software contribution 情境中获得新的 IS 机制或原始实证，明确给出有方向、非交换的互动状态更新，而不是沿用 Reddit reflexive bot 标签。
2. 随机化试点证明不同 contributor actions 对真实人工分钟、错误到达审核和正确集成具有可识别的异质作用，并且不靠普遍延迟或拒绝获胜。
3. 同信息、同标签、同动作、同参数 generic temporal policy 无法复制理论政策；差异经状态打乱与机制中和仍存在。
4. coding-agent deletion 后至少一个必要状态、动作或结果机制消失，而非仅减少提交规模。
5. 相对于 RepoComplianceBench、AGM、pytest／GitHub 静态边界、Learning to Commit、SWE-Review、comment-to-edit 和并发 awareness 的组合，仍有一个不可拆成普通 queue controller 的新增能力。
