## 2. 独立终判

本次终判为：**CONDITIONAL / DESIGN NOT FROZEN**。所有经验状态仍为 **RESULTS NOT RUN**。

这一结论没有把未运行的支持度模拟、模型训练、真人 pilot 或前瞻实验当作失败。修补稿已经通过理论映射、标签来源分账、三 cohort 主体隔离和等信息通用反证等主要责任，且没有被某一篇直接工作整题覆盖。暂不恢复设计冻结，来自四个仍可在实施前精确修补的合同缺口。

1. `clarify/repair` 的内容和 eligibility 会在真人回答后才具象化，而当前 manifest 同时要求 T−2 已冻结“全部候选”。文件已经冻结 action grammar、参数 schema 和 precondition，却尚未给出从 T1 人类回答到运行时分支实例的 hash commitment。若这一分支由自由文本生成器临时产生，候选内容、mask 和 ordering 仍可能脱离 T−2 lattice。
2. availability-only probe 把候选数、mask、公开时延或工具家族对 hidden label 的任何预测增量都视为 oracle 泄漏。部署可见的任务和工具信息本来就可能与真实风险相关，因此单纯 `AUC>0.55` 不能区分合法信号与 hidden evaluator 对 generator 的因果影响。当前规则可能在完全无泄漏时持续误杀同一类 trial。
3. `action×risk×reviewer-support` 支持门没有把 `clarify/repair` 等动作的历史依赖 eligibility 写进 estimand cell 主键；T2 又允许“human or external process”作最终批准。前者使 n/ESS 规则在结构性不合法 cell 上含混，后者使主要 unsafe-approval 结果可能不再由与 C3 互动的同一审核者产生，削弱理论中介链并重新接近 C19 的监督分配问题。
4. 修补稿要求真人中介链成立，却只预注册了终局 mixed-effects models，没有冻结 mediator 的测量时点、处理后混杂处理和间接效应估计。`00H-B` 的 18 张句卡机械字段齐全，但五张卡仍需改写或拆分，另有数张把“局部相似”留在了 `00F` 要求的功能同位与位置参照二分之间。

这些缺口都有字段级闭合方案，未触发 NO-GO。它们也不能留到看过 confirmatory outcome 后再修；否则分支候选、样本支持、中介定义和写作责任都会随结果移动。

## 3. 理论原文回读与第一门

### 3.1 Mastrogiacomo 映射

本审计回读了本地全文 `database_fulltext_all/10982_2014_talk-before-it-s-too-late-reconsidering-the-role-of-conversation-in-information-systems-project.md` 的 joint activity、grounding criterion、L211–L225 的概念转译、Table 3、评价和局限。原文的责任关系是：

- identification 被情境化为 joint objectives。
- ability 同时被情境化为 joint resources 和 joint risks。
- willingness 被情境化为 joint commitments，且作者明确承认这一关系包含选择与实用考虑。
- mutual belief 被情境化为项目会议或项目相关对话中的过程，即围绕上述内容寻找相互理解证据。

`00H` 第 37–45 行、`00J` 第 52–58 行和 `00H-A` 第 62–71 行已经按这一原文修正。`R_joint→content` 是 3×4 的稀疏常量，mutual belief 不再是第四行、第五列或 risk 的别名。`J_content` 由 task author 根据可部署信息事前冻结，共同基础模型不得生成、补写或依据结果修改它。这个映射通过。

### 3.2 理论责任是否越界

四份修补稿反复将下列责任留在技术层：canonical identity、action/state binding、test 和 dry-run 的事实有效性、hidden functional/security/scope/state-damage 真值、harm prediction 与 evidence invalidation。共同基础只负责 potential/established 区分、action-specific interpretation、grounding phase、reciprocal uptake、purpose-relative criterion/gap 和 repair。该分账与原文边界相符。

四路门也已从“理论必然推出的函数”降为可证伪结构假设。`00H` 明确承认同信息通用 POMDP 可以表达同一乘法、单调函数；这避免了把理论概念占用误写成计算独占。第一门通过。

需要保留一个正文边界。Mastrogiacomo 等人研究的是人类 IS 项目团队的会话工件，不能直接证明 coding-agent 审批中的中介效应。Poelitz 等人的共同拼图任务和 Li 等人的 MapTask interpretation matching 为人机迁移提供了相关证据，但仍未给出 coding approval 的安全结果。因此，正式正文必须把迁移写成待检验机制，不写成已被原文证实的事实。

### 4.2 两个需在实现前补齐的字段

第一，`κ` 是与校准后的 `g_est` 比较的连续阈值，但 manifest 还没有冻结它的量纲。`criterion_manifest` 至少应增加 `criterion_scale_version`、`criterion_basis`、`required_response_bank_hash`、`threshold_unit` 和 `threshold_sensitivity_grid`，说明 0.8 之类的数值究竟表示正确解释概率、覆盖率还是其他量。阈值可以在 logging 前冻结，不能在看见 outcome 后按结果调节。

第二，`M_t[:,2]` 必须表示审核者确实获得了“系统已经接收并使用其修正”的可观察证据，而不只是系统生成了一条 repair。`label_manifest` 应增加 `system_uptake_event_id`、`human_exposure_receipt_id` 和 `paired_confirmation_item_id`。若没有人的可观察 exposure 或后续 paired confirmation，该方向保持 UNKNOWN。`C.acceptance` 也应显式命名为 `grounding_acceptance`，并用 schema validator 拒绝 gate-level approve event。

这两个补丁不改变题目或算法主线。乘性门继续只是结构假设，不能因为字段变得可标注就被写成已获经验支持。

## 5. Oracle-blind lattice 与第三门

### 5.1 已闭合责任

- generator 只读 issue/task、canonical action、B/pre-state、public tests、authorized tools 和预先预算。
- `J_content/m_req/κ`、action binding、lattice hash 均早于 hidden evaluator。
- B 是部署可见 pre-state，S 只能由 canonical proposed action 在 public sandbox 产生，G/gold/hidden 对 generator、policy、renderer 和 participant 全部封闭。
- 候选 class、参数 schema、precondition、mask、cost、timeout、ordering、proposition binding 和 provenance 都被要求进入 hash manifest。
- generator、public sandbox、hidden evaluator、logger、trainer 与 confirmatory runner 有独立角色、镜像 digest、白名单和 access log。
- action hash、working-tree hash、permission 或 scope 变化会使 lattice、evidence、response、`B_H/M/g_est` 全部失效，而非只清理 UI 缓存。
- 策略顶层动作仅为 `acquire/present/factual_probe/clarify/repair/stop`，没有 allow、deny、risk score、when-to-ask、reviewer assignment 或 second reviewer。

这些条款已经闭合了 hidden 内容直接进入张量、mask、ordering、cost、timeout、latency 与命题生成的主要通道。

### 5.2 互动分支尚未形成可验算承诺

T−2 的“全部候选冻结”与 T1 后才观察到的 clarification/repair 需求之间仍有一个未写出的实例化层。当前 `parameter_schema` 与 `precondition/eligible` 可以成为解决办法，但 manifest 没有规定运行时 repair 内容只能由哪一组已承诺输入产生，也没有给分支实例 hash。

若采用有限预枚举，`candidate_lattice_manifest` 必须为每个 `K_p∪{UNKNOWN}` 分支保存 `candidate_content_hash`、`static_mask`、`eligibility_expression_digest` 和完整 ordering。若采用参数化 grammar，则 T−2 必须承诺 `branch_template_id`、`instantiator_image_digest`、`runtime_input_whitelist`、`response_feature_schema` 与 seed；T1 后只允许以 `parent_lattice_hash + human_response_hash + public_execution_hash` 确定性产生 `branch_instance_hash`。自由文本 LLM 不得在 T−2 后生成新候选；若确需生成，整个 trial 必须重新执行 bind→lattice-hash，并在新 hash 后才能运行 evaluator。

这个补丁不是为了增加文档字段，而是为了使“候选内容也不携带 hidden 答案”成为可机械验算的不变式。

### 5.3 availability-only probe 的判定逻辑需修正

当前 probe 的输入包含 action availability、mask、ordering、expected cost、timeout、public latency、missingness、proposition count、tool family 和 generator source。即使 generator 从未接触 hidden evaluator，这些部署可见变量也可能因任务本身而预测真实风险。例如，回滚工具不可用、action scope 更大或 public test 失败都可能合法地与 hidden harm 相关。因而“probe AUC 高”不是 oracle 泄漏的充分条件。

冻结版应把机械非干扰与统计敏感性分开。

1. 机械门保持绝对：hidden access log 非空、T−2 前后 bytes/hash 改变、同一 public input 在 evaluator absent/present 条件下生成不同 lattice，任何一项即失效。
2. 统计门改为条件增量：先以 T−3 前全部合法 public covariates 建立基线，再检验 availability fields 的增量；在相同 `public_input_equivalence_group` 内做 label permutation 或 paired hidden-label swap。只有无法由 public 信息解释的增量才触发泄漏调查。
3. `leakage_probe_report.json` 增加 `public_covariate_baseline_hash`、`equivalence_group_key`、`delta_auc`、`paired_noninterference_result` 和处置。原始 AUC 仍报告，但不单独证明 oracle 影响。

在互动分支 commitment 和 probe 因果解释写入合同前，第三门不通过。

## 6. 三 cohort、支持度与第四门

### 6.1 不以未运行结果否决

三阶段使用不同 participant，split key 同时包含 repository、base commit、bug/risk family、generated-test lineage、gold-derived sibling 与 evidence-lattice family。pilot 不训练，logging cohort 以随机或已知 propensity 训练，confirmatory cohort 不更新任何模型。E_tech 的下部和 code encoder 冻结，`F_cg/T_ev/π_cg` 有预注册容量上限；所有通用基线按参数、FLOPs、wall clock、训练步数、seed 和搜索预算匹配。这一路线通过。

规划下限的算术是：logging cohort 至少 180×16=2,880 个 trial clusters，每个 trial 3–6 个合法决策时点，即 8,640–17,280 条相关 decision rows；confirmatory cohort 至少 180×12=2,160 个 trial clusters。六类动作、五类 risk outcome 与三档 reviewer support 形成最多 90 个边际组合。若动作近似均匀且全部合法，logging 下限可能提供约 96–192 rows/cell；在概率下限 0.05 时只有约 28.8–57.6 rows/cell，而且 clarify/repair 在早期状态结构性不合法。这个计算说明下限不是支持保证，但修补稿已经明确以 simulation 选最终 N、失败即扩容或把 cell 标为 unsupported。因此，本审计不把未跑 simulation 当作失败。

### 6.2 必须把 cell 改为 eligibility-conditioned estimand

当前 raw n≥40 与 ESS≥30 的规则写成“每个 action×risk×reviewer-support cell”，容易把结构性不合法动作也放进分母。`logging_propensity_manifest` 应增加：

- `history_state_signature` 和 `eligibility_state_signature`。
- `estimand_cell_id = action × risk × reviewer_support × eligibility_state`。
- `eligible_opportunity_count`、`selected_count`、clustered raw support 与 clustered ESS。
- `repair_trigger_rate`、`clarification_trigger_rate` 和 absorbing-stop 后可达性。
- 主策略在 unsupported cell 的 deterministic fallback 与该 cell 不作反事实主张的标志。

`sample_support_simulation.json` 已包含动作合法率、轨迹长度、随机效应和 attrition；补上上述状态转移后，就是可执行而非凭直觉的支持门。

### 6.3 主要结果必须由同一审核者产生

`00H-A` 的 T2 目前写成“人类或外部流程作 approval/deny”。C3 的主要中介链要求与系统交换 factual response、clarification 和 repair 的人就是最终 approver。primary estimand 应增加 `interaction_participant_id == final_approver_id` 的硬校验；外部 gate 只负责记录或执行该决定，不得在主实验臂内更换人、增加第二审核者或根据 C3 trajectory 重新路由。若组织流程确需 secondary review，应另列为 C19 边界外的次级分析，不能混入 C3 的主要 unsafe-approval 结果。

完成 eligibility 和 same-reviewer 字段补丁后，第四门的设计即可通过；pilot、simulation、training 和 confirmatory outcome 仍然保持 PENDING。

## 7. 公平通用替代与理论机制识别

### 7.1 等信息反证通过

Human-state POMDP、Raw-POMDP、generic proposition Transformer 与 contextual bandit 获得相同 `J_content`、proposition labels、factual/phase/uptake feedback、candidate lattice、action mask、external reward、propensity、pretrained E_tech、split、训练步数、随机种子和搜索配置。理论损失使用的标签也向通用多任务头开放。主模型与基线按可训练参数±1%、推断 FLOPs±5% 和 wall-clock budget 匹配。

修补稿还明确承认通用 POMDP 在表达能力上可以重建四路门。理论贡献只在有限真人数据、未见 repository/reviewer/risk、方向性 clamp/shuffle、中间状态校准和安全—效率前沿上成立；公平通用模型复制即撤销独立理论算法贡献。这个判定诚实且可证伪。

### 7.2 真人中介仍缺识别合同

修补稿要求“策略改善 action-specific factual grounding，grounding 改善进一步解释 unsafe approval 下降”，但结果节只给 mixed-effects logistic/survival model。将 treatment 后的 `g_est` 或 factual score 直接放入结果回归，不能自动识别间接效应，因为 evidence 数量、trajectory length、clarification 触发和 reviewer fatigue 都可能同时受策略影响。

冻结前应在统计 manifest 中增加：

- treatment 是前瞻随机臂，mediator 是在最终 approval 之前、由 `confirmatory_factual_bank` 或预注册 transfer item 取得的 action-specific factual-grounding score，outcome 是随后发生的 unsafe approval。
- mediator measurement time、缺失规则和 trial-level aggregation 在首名 confirmatory participant 前冻结。
- 预注册 interventional indirect/direct effect 或适合序贯处理的 g-computation；列出基线混杂、处理后混杂和识别假设。
- 一个不改变技术 evidence quality、只随机改变 grounding repair/paired uptake 的机制 encouragement，或明确承认只能作关联中介而不写因果中介。
- participant/task/repository clustering、bootstrap/区间、multiple mediator 处理和失败解释。

这是设计定义，不要求现在得到显著中介结果。若最终只有 evidence-quality 直接效果而没有 grounding 改变，修补稿现有撤题门仍应执行。

## 8. 直接近邻、完整联合覆盖与研究边界

[Consent Integrity](https://arxiv.org/html/2606.02668) 负责 trusted rendering 与 bind-to-execution，并明确把人的 comprehension 放在范围外。[CAVA](https://arxiv.org/html/2607.13716) 和 [PCAA](https://arxiv.org/html/2606.04104) 负责 canonical action、route/review/prove、receipt 和 authority closure，没有学习同一审核者的 factual grounding repair。[BSG-VA](https://arxiv.org/html/2607.28871) 负责 B/S/G replay 与 evidence role，数据全是机器生成 execution records，没有真人审核者。

[Hedwig](https://arxiv.org/html/2605.11495) 和 [When Should Users Check?](https://arxiv.org/html/2510.05307) 决定是否或何时 check-in，正是 C3 固定 post-escalation 后排除的时点。[Poelitz 等](https://arxiv.org/html/2602.21337) 研究共同拼图中的 presentation、clarification、repair 与 acceptance；[Li 等](https://arxiv.org/html/2606.31719) 研究 potential/established common ground 的静态 interpretation matching。二者没有 canonical coding action、可执行后果取证或 unsafe approval。[Habituation at the Gate](https://arxiv.org/abs/2606.22721) 直接观察 coding-agent PR 的人类批准变化，却没有 hidden code-quality truth、序贯 evidence policy 或随机 grounding repair。

[PICK](https://doi.org/10.4230/LIPIcs.ECOOP.2026.7) 已经在受限语言合成中按信息增益与覆盖主动选择可区分 scenario 并询问人类；[AutoSD](https://doi.org/10.1007/s10664-024-10594-x) 已经运行 debugger experiments 并把 scientific-debugging trace 用于真人 patch judgment。前者没有真实 coding action 的状态损害与固定审批，后者的主动实验服务于 patch generator，真人只判断最终解释。两者阻止 C3 把“主动选一个区别性例子”或“展示可执行调试轨迹”单列为贡献，却仍未覆盖 reviewer-state-conditioned sequential repair。

因此，最新工作覆盖了 C3 的各个基座，但尚未有单篇工作覆盖“固定升级与可信行动绑定→oracle-blind 序贯可执行取证→同一真人的命题级 grounding repair→真实危险误批”这一联合对象。不能因为多个近邻可拼接就整题撤销；也不能把这些已占据基座重新写成 C3 的贡献。

两项 coding-agent deletion 是有效反证。第一项保留 grounding 界面却把 action-derived executable evidence 换成通用静态解释，检验 coding-agent 技术层是否 load-bearing。第二项保留可执行 acquisition，却删除 reviewer-state filter 与 repair，检验 common-ground 层是否 load-bearing。两项都与同一预算和主要结果比较，不是普通消融。

C3/C19 的边界也基本清楚。C3 策略不选择审核者、不启动升级、不决定 ask/allow/deny。前述 same-reviewer primary estimand 补丁将消除 T2 外部流程的剩余歧义。
