# 纵向审查记忆安全固化候选终审

> 审计日期：2026-08-16  
> 审计对象：coding agent 将一次代码审查反馈或用户纠正固化为跨会话、跨任务或跨仓库的持久行为规则，并在以后检索、修订、隔离或遗忘这些规则。  
> 终审结论：**终局 NO-GO；保留候选数为 0。**  
> 结论范围：不得占用三篇论文题位。局部纠正的过度泛化值得继续做 coding-agent 失效测量、产品评估或组合系统工程，本文件否决的是“尚有独立的、IS 理论驱动的可训练算法论文能力”这一主张。  
> 结果边界：本文没有运行候选模型，没有报告候选性能；终判不以“尚未训练”或“没有现成反事实数据”为理由。

## 0. 终审结论先行

一次被接受的审查意见可能只在某个仓库、版本、文件路径或特定失败情境下成立。coding agent 若把它写成无条件的全局规则，以后可能跳过必要验证、禁止合法工具调用、删除本应保留的代码，或在依赖和规范已经变化后继续执行过时约束。与一次输出错误相比，持久规则会跨任务重复介入真实代码与工具行动，因此会把一个局部判断放大为纵向回归。这个损害真实、可执行，也不能由“所有反馈都不记”获得表面安全。

最强版本不是接受或拒绝一条规则。它在纠正发生后维护多个尚未定论的规则假设，获取近边界证据，选择 episodic、project、repository-family 或 global 作用域，运行反例任务，决定分支、合并、延迟固化、衰减、修订、隔离、回滚或删除；以后每次使用前还可重新检验版本与代码状态。其训练标签应来自同一起点、不同记忆动作在未来任务上的隐藏测试、状态差分、功能与安全结果，不能来自 LLM 对规则“是否合理”的自评。

即使按此钢人化，候选仍不能成立为独立论文。

第一，直接技术覆盖已经形成闭环。Aggarwal 与 Ghalaty 已把真人审查意见转成持久 coding-agent 行为规则并实践了分层作用域、冲突修订和版本化。TRACE 又正面覆盖 correction detection、原子规则与适用边界、`Noop/Update/Supersede/Split/New` 生命周期，以及 prompt、tool、file 和 termination hook 的运行时执行。TrustMem、MCMA、FedWorld、MemGate、MemSkill、CODESKILL 和 Memory Transfer Learning 分别覆盖可训练 consolidation、抽象层级、shared/cluster/private/unresolved 作用域、良性记忆的跨域误用、选择与修剪、下游可执行反馈驱动的 coding skill-bank 管理，以及 coding 记忆抽象度与负迁移。普通“反馈—作用域—维护—未来约束”已经不是空位。

第二，安全专用余量也被直接压缩。Zhao 等人的 Findings ACL 论文已用干预与对照说明，完全良性的执行经验也会通过 execution bias 使高风险任务更倾向行动，拒绝经验虽能缓解却引发 over-refusal。SHE 把 System Prompt、Rule Bank、Safety Memory 和 Tool Policy 分责，并用失败轨迹形成 artifact-specific boundary refinement 后做安全—效用验证。FATE 从同一起点重执行修复候选，以 security、utility、over-refusal 和 trajectory validity 形成 Pareto 监督并训练本地政策。因而，“安全—效用约束下学习何时固化或撤销规则”也不能仅靠换成 coding 数据获得独立能力。

第三，最接近的 AIS 理论无法合法承担候选的前向责任。Sturm 等人研究的是多个自然人、ML 系统与组织代码构成的组织学习系统。`p1` 是人从组织代码学习，`p2` 是有知识的人类信念进入组织代码，`p3` 是 ML 信念进入组织代码，`α` 是人通过数据、算法或超参数重配置 ML 学习能力，`q` 是 ML 对未知现实的正确概率。单一 agent 的 Markdown 规则库不是该文的组织代码；reviewer correction 属于人源 codification 的近似，而不是 ML-centric `p3`；写入 project/global scope 也不是重配置 `α`。把这些符号直接改名为写入动作会改变构念。若扩为多 reviewer、多 coding agent、共享组织规则库和双向人机学习，研究对象已经变成另一项社会技术组织学习研究，并且仍被 TRACE、CODESKILL、FedWorld、SHE 与组织记忆架构的组合覆盖。

第四，在相同输入、标签、动作、参数和 FLOPs 下，普通 temporal HGT、memory Transformer 或 POMDP 可以读取完全相同的反馈、代码、版本、规则图与反事实执行结果，并输出完全相同的证据获取、作用域、分支、合并、隔离与删除动作。候选没有一个由合法 IS 机制产生、通用模型不能以同样监督学习的方向性更新。最后，删除 coding agent 后，客服 agent、业务流程 agent、机器人操作程序和人类 SOP 系统仍面临局部纠正过度泛化、过时与冲突，同一状态、动作和损失基本不变。代码的可执行测试提高了结果可测性并放大损害，却没有改变核心记忆治理机制。

因此，本终审保留 0 个候选。重开需要一项新的直接事实，而不是扩大集成规模：必须发现 coding-agent 独有的纵向固化机制、可合法映射且改变前向计算的 IS 构念，或证明等信息、等动作、等监督的通用时序控制器无法复制该能力。

## 2. 广义安全对象与行动模型

### 2.1 真实损害

候选中的风险是**纵向安全固化错误**：agent 从一条在局部情境中有效的纠正生成持久规则，随后在超出该规则有效边界、版本已经变化或新证据与规则冲突时仍执行它，使错误跨任务复现。外部损害必须落到可执行结果，例如必要认证检查被跳过、正常文件被删除、依赖升级被错误阻断、合法命令被无条件拒绝、危险命令因例外过宽而被放行、补丁虽通过公开测试却破坏隐藏安全或功能约束。

良性纠正的过度泛化与恶意投毒必须分开。前者没有攻击者，风险来自有限样本、隐含适用条件、环境变化和冲突反馈。只有当仓库内容、工具输出或用户故意诱导 agent 写入高权限记忆时，才采用 TMA-NM 的来源、权限、laundering、corroboration 和信任边界威胁模型。

### 2.2 决策时点

候选有三个实质决策时点。

1. **纠正后、写入前。** agent 判断反馈是否只属于本次 episode，是否需要取得额外代码或 reviewer 证据，以及应保存为哪一个尚待检验的规则假设。
2. **未来任务、执行前。** agent 发现规则可能适用时，判断版本、依赖、文件路径、风险情境与反例是否仍支持它，并选择应用、局部应用、暂缓或隔离。
3. **纵向维护时点。** 新的通过、失败、审查或环境变化到来后，agent 决定提升、分支、合并、衰减、修订、撤销、回滚或删除已有规则。

只在第三时点发现已知错误并追踪其下游影响，会滑入 From Faulty Memories to Corrected Actions 的 post-failure rollback repair。只在第二时点要求更多真人证据，会滑入当前系列的 C3 post-escalation 证据问题。候选要独立成立，必须解释三个时点之间不可约的纵向因果，而非把已有模块串起来。

### 2.3 可见、隐藏与可能污染的状态

| 状态类别 | 决策时可见 | 决策时隐藏或不确定 |
|---|---|---|
| 纠正来源 | review comment、关联 diff、接受后的 patch、reviewer 身份、时间与会话 | reviewer 未写出的例外、是否代表团队共识、纠正是否只是临时妥协 |
| 代码环境 | 当前 commit、AST、依赖清单、CI、公开测试、工具 trace、规则库 | 隐藏测试、未来 API 与依赖版本、部署流量、未公开安全不变量 |
| 纵向证据 | 规则过去被检索的任务、执行动作、通过或失败结果、后续修订 | 未执行的替代记忆动作结果、选择偏差、未触发但潜在的错误 |
| 组织状态 | 公开规范、CODEOWNERS、多个 reviewer 的可见意见、规则来源 | 权威层级、私下共识、未来政策变更、跨团队适用边界 |
| 安全信号 | 静态与动态分析、sandbox state delta、权限与工具调用 | 不可逆外部效果、延迟故障、未建模的系统耦合 |

### 2.4 正常、风险与纠正动作

| 类别 | 低层可执行动作 | 判定依据 |
|---|---|---|
| 正常动作 | 完成本次补丁与测试；将纠正保留为 episode note；在明确相同情境中检索经验证规则；按版本化规则运行工具 | 证据与作用域相符，执行结果通过隐藏功能、安全和状态检查 |
| 风险动作 | 一次正反馈即写成 global rule；把描述性建议编译为强制 hook；忽略版本变化；用旧规则覆盖新证据；为降低风险而拒绝所有行动 | 未来任务出现安全或功能回归，或正常任务成功率与人工负担显著恶化 |
| 纠正动作 | 请求代码或 reviewer 证据；生成近边界反例；保持 competing hypotheses；选择 episode/project/repo-family/global；branch、merge、decay、revise、quarantine、rollback、delete | 在保持正常任务能力的同时减少真实回归，并保留可审计来源与恢复点 |

### 2.5 外部结果

主结果不能是“规则分类准确率”或“agent 拒绝得更多”。确认性评价至少同时测量：

- 由记忆触发的危险工具或代码行动，以及其真实 state delta。
- 隐藏功能测试、安全测试、跨版本构建和部署前仿真中的新增回归。
- 正常任务成功率、完成时间、工具调用和计算成本。
- 用户或 reviewer 需要重新纠正的次数与有效人工分钟。
- 规则误触发、漏触发、冲突、过期和回滚成功率。
- 持久影响的跨度，即一个错误规则影响的未来任务、仓库和版本数量。

| [FedWorld](https://arxiv.org/html/2608.01561) | 将规则表为 action、pre-state、condition、effect、exception，以 supporting/contradicting evidence 分成 shared、cluster、private、unresolved，歧义规则暂不传播。 | shared/private、冲突证据和 ambiguous withholding 已正面覆盖。候选不能靠把 cluster 改名为 repo-family 获得新颖性。 |
| [MemGate](https://arxiv.org/html/2606.06054) | 研究真实良性记忆跨域误用导致 leakage、sycophancy 与 tool-call drift，并训练 admission/retrieval policy。 | “不是投毒但会过度泛化”的问题本身及学习型入场控制已有直接近邻。 |
| [When Continual Learning Moves to Memory](https://arxiv.org/html/2604.27003) | 用 forward/backward transfer、reuse 与负迁移指标研究 sequential experience reuse，指出 retrieval pollution、context competition 与过度具体经验造成 negative forward transfer。 | 纵向迁移、遗忘和负迁移已有成体系评价；coding 数据并非新机制。 |
| [MemSkill](https://arxiv.org/html/2602.02474) | controller 选择 skills，designer 从 hard cases 做 Insert/Update/Delete/Skip、consolidation 与 pruning，使用 downstream outcome、PPO、bank snapshot 和 rollback。 | 学习型选择、维护、修剪、hard-case evolution 与恢复动作被联合覆盖。 |
| [DecentMem](https://arxiv.org/html/2605.22721) | 多 agent 各自维护 exploitation pool 与 exploration pool，在线路由并保持角色差异，避免 centralized memory homogenization。 | shared/private、探索/利用和多源多样性不是 Sturm 映射后的独有动作。其 judge-based 结果不是安全真值，但直接压缩结构空位。 |

### 3.3 coding-agent 记忆与可执行反馈

| 工作 | 原文能力 | 对候选的直接覆盖 |
|---|---|---|
| [CODESKILL](https://arxiv.org/html/2605.25430) | 从 coding trajectory 提取多粒度 procedural skill；学习 `Mθ(τ,C) → (action, content)` 的 generation、evolution 与 maintenance policy，动作含 add、merge、drop。先用教师目标 SFT，再以 GRPO 训练；混合 reward 含 frozen downstream coding agent 的可执行验证增量，并维持固定 skill-bank 容量。 | 已经把 coding 轨迹、可训练 skill-bank policy、合并删除与下游 executable feedback 放在同一工件。候选若只把 trajectory 换成 review correction、把 reward 加上 safety test，剩余是数据与标签迁移。 |
| [Memory Transfer Learning](https://arxiv.org/html/2604.14004) | 在六个 coding benchmarks 比较 trajectory、workflow、summary 与 insight 等记忆层级。原文直接记录低层 trace 的过度特定、domain anchoring、false validation confidence 与 misapplied best practice，并显示抽象度影响跨域迁移。 | coding-specific overgeneralization 和 negative transfer 已有直接实证对象。 |
| [Self-Evolving Coding Agents](https://arxiv.org/html/2608.03392) | 综述归纳选择性过滤、抽象、检索、验证、负面经验与脆弱补丁风险，并定位 CODESKILL、SWE-Exp、EvoCoder、EvoRepair、SAGE 等。 | 只作版图索引。原文未逐一取得的被引工作不承担关键覆盖，但综述说明“coding-specific executable feedback 下维护 memory”已是显性研究流。 |

CODESKILL 是最重要的同输入—动作—结果挤压项。它尚未以 reviewer correction、未来安全回归和组织规则为对象，但已经训练一个 coding-specific、可执行反馈驱动、具备合并与删除动作的 bank-management policy。把隐藏安全测试加入其 reward 是重要工程改进，仍不足以证明一个新的理论算法能力。

### 3.4 安全演化、良性经验风险与恢复

| 工作 | 原文机制与评价 | 对候选的覆盖与边界 |
|---|---|---|
| Zhao et al., [On Safety Risks in Experience-Driven Self-Evolving Agents](https://aclanthology.org/2026.findings-acl.2091/) | 在 web 与 embodied 环境中比较无记忆与良性执行经验。作者用 length-matched control、归因分析和多记忆数量干预，将安全下降归因于 execution-oriented experience，而非简单上下文变长；更多良性执行经验提高高风险任务的行动倾向。加入 refusal experience 能缓解风险，却提高 benign over-refusal。 | 已直接建立“良性经验也可造成安全下降”的现象、机制归因和 safety–utility 方向冲突。它不是 coding-specific，也未学习固化政策，但候选不能再把这一冲突声称为未发现机制。 |
| [SHE](https://arxiv.org/html/2608.09885) | 将 System Prompt、Rule Bank、Safety Memory、Tool Policy 分责。failure trajectory 经 structured diagnosis 路由到特定 artifact，做 bounded boundary refinement，再以 safety、utility、unintended blocking 等信号选择。评价含 Agent-SafetyBench held-in evolution、held-out AgentHarm 与模型迁移。 | 已覆盖 failure trajectory 到 rule/safety-memory/tool-policy 边界演化，并把良性豁免与 utility 写入选择。候选不能只说“从回归反例修订 safety rule”。SHE 主要由大模型生成/选择，不是本地训练 checkpoint，这是实现边界，不是概念空位。 |
| [FATE](https://arxiv.org/html/2605.11882) | 从当前 policy 的失败收集 repair candidates，从同一初始状态重执行，并由 security、utility、over-refusal、trajectory validity verifier 过滤 Pareto front；SFT 后以 PFPO/LoRA 训练 policy。严格区分开发与测试，并在 AgentDojo、AgentHarm、ATBench 评价。 | 已提供本地 checkpoint、同起点反事实执行和多目标安全政策训练。候选若采用同一识别结构，只是把 action space 改成 memory edit。 |
| [From Faulty Memories to Corrected Actions](https://arxiv.org/html/2608.10502) | 给定失败 execution 与已诊断 faulty memories，构建 typed memory-to-action graph，求下游 reachability，保留有独立可信支持的状态，停用受影响 memory 并 selective replay。 | 已覆盖已知记忆故障后的 dependency-guided quarantine、rollback、benign preservation 和 replay。候选只可研究故障前/不确定阶段；一旦以 diagnosed fault 为起点即直接重叠。 |
| [TMA-NM](https://arxiv.org/html/2606.24322) | 形式化 memory poisoning 和 laundering，将权限绑定到 write-time origin，要求 non-malleable provenance 与 Sybil-resistant corroboration；提供 benchmark 与 TLA+ machine-checked guarantees。 | 恶意来源、taint、authority 与 corroboration 已有威胁模型。良性 reviewer feedback 过度泛化不应被伪装为 poisoning。 |

Zhao 负责现象与机制归因，SHE 负责 safety-harness 的边界演化，FATE 负责同起点安全—效用政策训练，Faulty Memories 负责事后恢复。四项联立后，候选只剩“将这些能力集中到 coding review rule bank”的组合，不再是无人处理的技术链。

### 3.5 组织共享规则库的最新近邻

[Organizational Memory for Agentic Business Process Execution](https://arxiv.org/html/2607.03228) 已把组织特定程序知识定义为 shared、governed、agent-consumable、evolving reference layer。其 process atom 明确包含 source、applicability、action、purpose 与组织标签；curation 阶段检查 duplicate、overlap 和 conflict，支持 add、remove、modify 后由人类专家审批；runtime 以 process、activity、role、unit、case state 请求最小充分 atom 集。论文还明确把 repeated human corrections 视为候选 memory update。

该工作不是训练型因果政策。proof-of-concept 仅含一个合成采购过程、9 份 PDF、11 条规则、10 个场景，比较 Base、普通 RAG 与 Memory；作者报告的剩余错误恰含 applicability 过宽造成的 over-restriction。其代码不公开，真实多来源纵向变化、人类治理成本与大型组织部署未测。即便如此，它已压缩“多 agent 共享、可追踪、可治理、会演化的组织规则库”这一概念空白。候选若扩为 Sturm 合法的组织单元，不能再只用 organizational memory 的命名证明新颖性，余量必须是多源 codification 的可训练因果政策。

## 4. 最强可实现版本

以下规格用于钢人化后进行反证，不代表设计冻结或已取得结果。

### 4.1 直白研究问题

当 coding agent 从真人审查、多个 agent 的可执行经验与组织规范中持续获得纠正时，它能否学习一个纵向记忆固化政策，在保持未来正常 coding 任务成功的同时，减少局部规则被过度泛化、过时或错误合并后造成的安全与功能回归？

### 4.2 输入与关键张量

| 张量 | 形状示意 | 内容与不可偷换的语义 |
|---|---|---|
| 反馈与修复轨迹 | `F_t ∈ R^{B×L_f×d}` | review comment、用户纠正、前后 diff、测试、tool trace、接受或拒绝状态；不是只有 correction 文本 embedding |
| 时序代码图 | `G_t=(V_t,E_t), X_t ∈ R^{B×N×d_g}` | file、symbol、test、dependency、version、tool、rule、reviewer、task 节点及修改/引用/冲突/来源/适用关系 |
| 规则库 | `R_t ∈ R^{B×M×L_r×d}` | rule content、condition、scope、provenance、version interval、status、past use 与反例 |
| 证据计数 | `C_t ∈ R^{B×M×K×3}` | 每条规则在情境 cluster `K` 下的 support、contradiction、unresolved 证据；不能把 LLM 自评当 support |
| 作用域 belief | `S_t ∈ R^{B×M×J}` | episode、project、repo、repo-family、organization、global 等 `J` 个候选作用域的后验或置信区间 |
| 未来结果 belief | `O_t ∈ R^{B×M×H×Q}` | 未来 `H` 个任务中功能回归、安全回归、正常成功、人工纠正、计算成本等 `Q` 类结果分布 |
| 动作候选 | `A_t ∈ R^{B×M×A×d_a}` | inspect、ask、test-counterexample、write、promote、branch、merge、decay、revise、quarantine、rollback、delete 与 apply |

模型输出不是一个风险分数，而是结构化动作序列、经编辑的规则及作用域条件、后续证据请求，以及 future coding task 中实际允许或阻止的 tool/code action。

### 4.3 架构与前向计算

最强版本可以由四个可训练组件组成。

1. 代码—审查 encoder 对 correction、diff、测试、规范与 tool trace 编码，并保留 token 到 AST/symbol 的对齐。
2. temporal heterogeneous graph transformer 更新 rule—reviewer—repo—version—task 的多重关系状态，显式保留来源、时间与冲突边。
3. counterfactual world model 预测在给定记忆动作后，未来任务中的 tool action、代码 state delta、hidden test、安全不变量、人工纠正与成本。
4. hierarchical policy 先选择 evidence-acquisition 或 memory-transition 动作，再由低层 coding agent 在 sandbox 中生成反例、执行测试、应用规则或修改代码。

一次推断可以依次执行：读取 correction 与关联状态，提出多个 applicability hypotheses，选择最有信息价值的近边界反例，在隔离分支执行，更新支持与冲突状态，决定暂存或分层写入；未来检索时再次核验版本与代码状态，再决定 apply、局部 apply、quarantine 或 rollback。顺序不可随意交换，因为先全局编译再补反例，可能已经让规则在其他会话执行真实动作。

### 4.4 训练样本与标签

历史 review 数据只能用于表示预训练与行为克隆，不能直接把“曾被写入”标成正确固化动作。确认性训练样本应从同一起点建立分支：

1. 选取有明确 accepted correction、可重建环境和未来相邻任务的仓库时点。
2. 在纠正发生时冻结 commit、依赖、工具版本、规则库与基础 agent checkpoint。
3. 为 `episodic/project/repo/global/withhold/branch/merge/revise/delete` 等可行记忆动作建立隔离分支。
4. 让同一个 frozen coding policy、相同 tool budget 与 decoding seeds 执行预先隐藏的未来任务和近边界 counterexamples。
5. 用 executable hidden tests、security properties、build results、state delta、权限使用、人工复核和任务成本产生 outcome labels。
6. 只用人类判定 correction intent 与组织授权；人类或 LLM 不直接给“未来是否安全”的最终标签。

任务可以来自公开 PR review 历史、SWE-bench family 的可重建仓库、真实依赖版本演化、项目规范更新和授权研究仓库。近边界任务需在不泄漏未来 gold patch 的前提下，从同一语义任务生成版本、路径、依赖、调用上下文与风险条件的最小变化。若无法执行隐藏功能与安全结果，只能做现象测量，不能训练本文声称的安全政策。

### 4.5 损失函数

一个工程上可训练但尚未获得独立理论授权的目标为：

`L = L_transition + λ_o L_outcome + λ_cf L_counterfactual + λ_app L_applicability + λ_time L_staleness + λ_pi L_offlineRL + λ_edit L_code`。

- `L_transition` 对规则分支、合并、修订、隔离与删除动作做监督或偏好学习。
- `L_outcome` 预测未来 executable 功能、安全、state delta 与人工纠正结果。
- `L_counterfactual` 对同一起点不同记忆动作的成对或 listwise 结果排序。
- `L_applicability` 以近边界正反例学习条件表示，而不是把 scope 当单标签分类。
- `L_staleness` 预测规则在依赖、规范和代码状态变化下的有效生存期。
- `L_offlineRL` 用保守离线 RL 或 constrained policy learning 平衡真实 harm、正常成功、人工负担和计算成本。
- `L_code` 训练低层 agent 生成并执行补丁、测试与反例，防止高层策略退化为建议器。

这些损失来自通用结构化预测、world model 与序贯决策。除非 IS 理论产生一个不可替代状态和方向冲突，它们不能因变量名写成 codification 或 organizational code 就变成理论算法。

### 4.6 推断动作

推断必须真实执行下列至少一种低层动作：打开相关源文件与测试，构造并运行 counterexample branch，修改 rule artifact，更新版本和来源关系，在 future coding task 中允许或阻止具体 tool call，回滚错误 rule 所触发的代码修改，或删除／隔离规则后重新执行受影响任务。只输出“建议 project scope”或给现有规则排序，不满足 coding agent 关键行动者要求。

### 4.7 划分、泄漏和算力

- 采用时间前推、仓库隔离、reviewer 隔离、rule family 隔离、语言／框架隔离和依赖版本隔离。
- correction 后的 future comments、future CI、gold patch、hidden tests 和 downstream task outcome 在决策时完全隐藏。
- 同一 issue 的派生 PR、相同补丁的 cherry-pick、同一规则的改写和 fork 仓库不得跨训练与测试。
- counterexample 生成器不可读取测试集规则边界；确认性 hidden tests 与 pilot 调参人员分离。
- 可行工程预算估计为 4–8 张 80GB GPU 对 7B–14B coding policy 做 LoRA/离线 RL，另训练 temporal HGT/world model，并运行 `10^4–10^5` 量级的隔离分支。数字是设计估计，不是已发生用量。
- 必须发布 commit、依赖镜像、tool version、review event、rule version、branch manifest、hidden-test hash、训练配置、随机种子、数据拆分、HGT/world-model/policy checkpoints 与失败轨迹。

### 4.8 最强基线与公平性

确认性比较至少包括：

1. 不记忆、全部 episodic、全部 global、固定过期、GitHub/VS Code scope+verify+expiry。
2. Aggarwal 规则框架与 TRACE 全生命周期实现。
3. TrustMem、MCMA、FedWorld、MemGate、MemSkill、CODESKILL 和 SHE 的可适配实现。
4. FATE 式同起点多目标政策训练，以及 Faulty Memories 的 post-failure rollback。
5. 相同代码 backbone、相同检索、相同反事实分支与相同 tool budget 的 raw temporal HGT、memory Transformer、SMDP/POMDP 与 bilevel controller。

公平通用替代必须获得完全相同的输入、可执行标签、动作集合、参数量、训练 steps、FLOPs、context window、counterfactual execution budget 和调参预算。不能让候选看到 reviewer source、version graph 与 hidden outcomes，却让 generic baseline 只看规则文本。

### 4.9 消融与机制干预

- 删除 provenance 或随机打乱 reviewer/source 节点。
- 把时间戳、版本和环境动荡状态中和。
- 将分层 scope 压平，或打乱 support/contradiction cluster。
- 删除 near-boundary counterexample acquisition。
- 删除安全结果，仅保留 task pass；再反向仅保留安全，测 over-refusal。
- 将 theory-labeled state 替换为等维随机向量或等参 learned latent。
- 固定 rule-bank 容量，比较 merge/drop 与无限增长。
- 将同一规则的正反反馈顺序置换，检验序贯不可交换性。
- 单独报告 detector、world model、policy 与低层 code executor 的误差传播。

## 5. 反事实识别与可运行环境终审

### 5.1 可严谨自建，但不是现成识别

公开审查轨迹可以告诉我们某条纠正随后是否被重复提及，却不能告诉同一 agent 当初选择另一个作用域会发生什么。历史 reviewer 也不是随机分配，成功项目更可能保留更完整的未来任务和测试，规则被检索的任务又受 policy 自身选择影响。把观察到的未来通过率直接作为 scope label 会产生 policy-induced missingness 与 survivorship bias。

可识别的最小环境是一个**同起点未来任务分支试验**。每个 correction event 在完全相同的 commit、依赖、基础 policy、tool permissions 与 random-seed block 下随机分配 memory action；未来 task suite 在分配前冻结并隐藏；所有分支在隔离 runner 中执行。若规则会影响真人 reviewer 或真实组织过程，训练 pilot 与确认性人群必须分离，并以 randomized assignment 或可说明的 encouragement design 估计外部结果。

### 5.2 可执行标签优先级

标签优先级从强到弱为：

1. 明确定义的安全不变量、权限边界、文件与服务 state delta。
2. 隐藏功能测试、安全测试、跨版本 build 与依赖兼容性。
3. 授权 reviewer 对 correction intent、适用范围与组织权威的盲审。
4. 静态分析、公开 CI 和历史 merge 作为辅助信号。
5. LLM judge 只可用于候选生成或低权重诊断，不能作为最终安全真值。

SHE 与 FATE 依赖 verifier，TrustMem 和 DecentMem 也使用模型评判，因此本候选若重开必须把 verifier error 单独测量，并以 executable outcome 作确认性标准。未取得现成数据不构成 NO-GO；这里的终局理由是即使自建识别环境，候选能力仍被直接工作与通用替代覆盖。

### 5.3 预注册结果结构

若仅作 identification pilot，应预注册以下结果而不预写方向数字：

- intention-to-treat 的未来安全回归、功能通过、人工纠正与总成本。
- 规则作用域、版本跨度和冲突密度的异质效应。
- task success 与 harm reduction 的 Pareto frontier，而非单一加权分数。
- detector、world model 和 policy 的校准误差及置信区间。
- 规则触发稀疏导致的有效样本量、聚类标准误与多重比较控制。

本文件没有运行这些试验，所有结果单元保持空白。

## 6. AIS 理论机制终审

### 6.1 Sturm et al. (2021) 的原分析单位

Sturm 等人扩展 March 的组织学习模型。组织由多个具有多维 beliefs 的 human agents、专门维度上的 ML agents，以及一个传播 routines、rules、procedures、conventions、strategies 与 technologies 的 organizational code 构成；外部 reality vector 对组织未知。组织知识是 belief 与 reality 的匹配程度，不是 rule-bank 的测试通过率。

原模型中的关键更新是：

- `p1`：human agent 从 organizational code 采用 belief，表示组织社会化或教育人类的速率。
- `p2`：比 code 更有知识的 human agents 的多数 belief 进入 organizational code。
- `p3`：ML agent 的 belief 进入 organizational code，表示 ML-centric codification。
- `q_init` 与 `q_t`：ML 对其专门 reality dimension 学到正确 belief 的初始与动态概率。
- `α`：人类根据其当前 problem understanding 重配置 ML 的数据选择、特征工程、算法或超参数，从而改变 `q_t` 的强度。
- `p_turb`：外部 reality dimension 翻转的概率，使既有组织知识过时。

原文在第 55–57 行说明，过早传播看似正确的 belief 会消除多样性并造成 inferior routine 或 competency trap，长期有效性需要在探索与利用之间管理 homogenization。第 104 行说明 turbulence 使 repository knowledge 过时。第 116–154 行分别定义 code、`p1/p2/p3`、`q` 与 `α`。P2b 针对高 `q_init` 且人类探索时给出过度 reconfiguration 的倒 U 形关系；P3 的 codification 方向取决于 turbulence 与 ML initial capability。

这些命题有清楚方向，但不能直接移植为 rule write policy。

### 6.2 层级与构念校正

| 原构念 | 最诱人的候选映射 | 层级审计 | 结论 |
|---|---|---|---|
| organizational code | 单一 coding agent 的 `MEMORY.md` 或 rule bank | 原 code 调节组织成员共同 beliefs，并反向吸收 human/ML beliefs；单 agent 文件没有组织成员社会化与双向学习 | 构念错置 |
| human-centric `p2` | reviewer correction 被写入 rule | 只有当多个有知识人类的 belief 经组织程序进入共享 code 才接近；一次 comment 被 agent 自动编译缺少组织单元与多数知识条件 | 至多弱近似 |
| ML-centric `p3` | coding agent 写入自己的经验 | 原 `p3` 是 ML 产生的 belief 进入组织 code，不是人类 correction 进入 agent memory | 方向和来源均错 |
| `p1` | agent 在 future task 检索 rule | 原 `p1` 是人类被组织 code 社会化；机器读取 memory 不是 human adoption | 层级错置 |
| reconfiguration `α` | promote、scope、revise 或 delete rule | 原 `α` 改变 ML 数据、算法或超参数，使 learning capability `q_t` 随人类 problem understanding 变化；memory edit 没有这一含义 | 不可替换 |
| `q_init/q_t` | rule confidence 或 reviewer authority | 原 `q` 是 ML 对未知现实学到正确 belief 的概率；rule confidence、source status 与安全边界不是同一构念 | 测量错置 |
| turbulence | repo/API/version 变化 | 环境变化确可使规则过时，这一映射方向合理；但仅有 turbulence 不能承担整个算法 | 可保留为情境变量 |
| belief diversity | competing rule hypotheses | 原多样性是组织成员 beliefs；单模型 beam 或 rule branches 只是算法候选 | 层级错置 |

因此，不能把 Sturm 的 `α` 写进 loss 作为 promotion intensity，也不能把 `p3` 命名为 global-write probability。那样只保留了数学外形，改变了主体、对象、更新方向与结果。

### 6.3 唯一较合法的社会技术扩展及其失败

最强可辩护映射必须同时包含：

1. 多个 human reviewers 的独立 beliefs 与探索行为。
2. 多个 ML/coding-agent sources 通过可执行任务产生独立 beliefs。
3. 一个由组织治理、会反向约束人和机器的 shared instruction artifact。
4. `p2` 对应人类知识进入 code，`p3` 对应 ML-derived lesson 进入 code，`p1` 对应人类真正采用 shared code。
5. `α` 对应人类实际改变 ML 的数据、算法或超参数，而非简单 memory write。
6. `q` 由时间隔离的未来任务正确率或校准结果估计，turbulence 由 repo/API/policy regime change 操作化。

这会形成“reviewer—coding agents—organizational code 的双向组织学习政策”，而不再是原候选的单 agent 纵向审查记忆。它需要观察人类从 code 学习、机器知识进入 code、人与机器彼此改变的整套动态。公开 PR 日志通常看不到 `p1`、真实 `α` 和组织 reality，识别需要新的组织现场或多主体实验。

即使建立该环境，TRACE 已处理 correction-to-rule，CODESKILL 已处理 coding trajectory-to-bank policy，FedWorld 已处理多 client 作用域与冲突，DecentMem 已处理去中心化多样性，SHE 已处理安全 artifact 边界演化，Agentic BPM 已处理 shared governed organizational memory。剩余贡献是把这些组件组织成多主体试验与统一系统；等信息通用 POMDP 仍能学习同一状态和动作。它可以成为另一项组织学习研究的 identification pilot，不足以挽救本候选题位。

### 6.4 Stein and Zwass (1995)

Stein and Zwass 将 organizational memory information systems 分为 acquisition、retention、maintenance、search 与 retrieval 等 mnemonic functions，并讨论 memory 对组织有效性的正负作用、选择性忘却与旧新知识共存。该框架自然说明为何持久规则需要来源、维护、检索和 forgetting，也支持把“记住更多”与“组织效果更好”区分开。

它仍是组织层设计框架，没有给出 reviewer feedback 在何种可观察条件下必须 project 而非 global、何时 branch 而非 merge，或哪一个方向性 loss 应更新 coding-agent rule bank。将五个 mnemonic functions 做成五个模块会机械复制生命周期，且已被 TrustMem、TRACE 与 MemSkill 的动作覆盖。因此它可用于问题边界，不能负责算法独特性。

### 6.5 Markus (2001)

Markus 区分 shared-work producers、shared-work practitioners、expertise-seeking novices 与 secondary knowledge miners 等知识复用情境，并说明 producer、intermediary、consumer 的成本与需求不同。知识距离较近的复用者可能需要丰富上下文，较远复用者往往需要重新包装、来源、质量与 freshness；为一个群体和目的建立的 repository 通常不能无重构地供另一群体复用。

该理论可解释 reviewer correction 从本仓库迁移到陌生仓库时为何丢失语境，却没有产生唯一的 scope lattice 或固化动作。把 knowledge distance 编成一个 embedding 距离、router 或 attention head 会退化为通用相似性；把 recontextualization 写成强制规则又超出原文。MCMA、Memory Transfer Learning、FedWorld 与 MemGate 已以可训练形式处理抽象、迁移与跨域误用。因此 Markus 只提供情境论证，不提供不可替代的 forward/loss/action。

### 6.6 Xu and Ramesh (2008)

Xu and Ramesh 研究的是人类软件过程裁剪者。generalized semantic knowledge 主要提升效率，contextualized episodic knowledge 同时提升效率与效果；任务复杂性通过 cognitive fit 改变知识支持的价值。其分析单位、因变量与机制均涉及人类认知负荷和过程裁剪表现。

把 generalized/contextualized knowledge 直接映射为 agent 的 abstract/episodic tensors，会把人类 cognitive fit 当成模型内部表征机制。该工作可以提示实验分层 task complexity，却不能证明一个 agent 抽象层的因果作用。MCMA 与 Memory Transfer Learning 已直接训练或测量相应技术结构，所以此理论映射不合法。

### 6.7 理论责任总结

四项 Basket 理论都能解释为什么组织不应无差别记忆。只有 Sturm 提供较强方向冲突，但它要求真实多主体、双向人机学习与组织 code；当前单 agent 规则题无法满足。其余理论停在 lifecycle、reuse context 或 human cognitive fit 层。因而，本轮没有找到一个可合法进入候选 forward、loss 与 action，同时在冲突情境下给出通用模型不容易想到的方向性机制。

## 8. 等信息、等标签、等动作、等参数通用反证

### 8.1 公平 generic baseline

定义一个不使用任何理论变量名的 temporal graph POMDP：

- observation 与候选完全相同，包括 correction、diff、tests、rule bank、reviewer/repo/version graph、past use、hidden-outcome training labels。
- latent state 由等参数 temporal HGT 加 recurrent belief encoder 学习。
- action 与候选完全相同，包括 inspect、ask、counterexample、scope、write、promote、branch、merge、decay、revise、quarantine、rollback、delete、apply。
- reward/constraint 与候选完全相同，包括 executable harm、task success、human corrections、compute 和 over-refusal。
- code executor、counterfactual branches、训练 steps、FLOPs、context、seed block 和调参预算完全相同。

若候选只把 latent dimensions 命名为 organizational code、codification、diversity、turbulence，通用模型可从相同监督中学习等价 decision boundary。若候选加入 hard-coded `p1/p2/p3/α` 更新，则它模拟了一个与实际数据不匹配的组织模型，并失去构念效度。若候选只加一个 theory-shaped loss 或 source-capability head，等参 generic baseline 也可加入同样维度的 free latent/head；需要预注册可观察的方向冲突才能证明不可替代性。

### 8.2 候选需要但无法合法声称的方向冲突

候选可提出以下合理冲突：

- 一条来自权威 reviewer 的纠正在当前 repo 多次通过，但依赖版本即将变化，故保持 project scope 而非 global。
- 多条来源独立、跨 repo 通过的规则可提升作用域；来源很多但相互冲突时应保留 branches 而非多数合并。
- 安全规则减少危险执行，却在正常任务上大规模误触发，应缩窄条件而非整条删除或继续扩大拒绝。
- 高动荡环境中旧规则更快失效，但高能力、独立来源的新证据又需要快速传播。

前两项由 FedWorld/MCMA/Memory Transfer Learning 与通用时序图直接表达，第三项由 Zhao/SHE/FATE 正面覆盖，第四项若归给 Sturm，则必须先识别真实 `q`、human exploration、`p3` 与 organizational code。当前候选没有一个理论专用、不可交换的更新式。

### 8.3 联合覆盖不是“每篇都做完”门

终审不采用“没有单篇论文同时拥有所有模块，所以仍有空白”的组合新颖性论证。TRACE 给规则结构与执行动作，CODESKILL 给 coding-specific 可训练 bank policy，FedWorld/MCMA 给 scope 和 transfer，TrustMem/MemSkill 给 transition 与 pruning，Zhao/SHE/FATE 给安全机制与同起点安全—效用学习，Faulty Memories 给事后 rollback，Agentic BPM 给共享组织治理。候选没有说明联合之后出现哪一个新的可识别机制，而只是把既有动作放到一个更完整系统中。

这类系统可能很有实践价值，也可成为 benchmark 或工程平台。它不满足本 thesis 对每篇论文独立算法能力和理论不可替代性的要求。

## 9. Coding-agent deletion test

删除 coding agent，换成能把客服纠正写入服务规则的业务流程 agent、把操作员反馈写入机器人策略的 embodied agent、把审核意见写入合规 SOP 的人类团队，仍然会出现：

- 局部有效纠正被扩大到错误群体或环境。
- 旧规则随政策、工具或现实变化而过时。
- 多来源反馈冲突，需要分支、合并、隔离与删除。
- 执行经验促进行动倾向，安全记忆造成过度拒绝。
- 共享记忆传播更快，却可能消除多样性。

相同 temporal graph、world model、memory actions 和 safety–utility loss 仍可直接使用。coding agent 带来的独特部分是代码、测试、版本、依赖、git 与 tool-use 提供了更丰富的可执行观测，也使规则误用能跨仓库迅速放大。这些是强评价环境和危害规模条件，却没有产生一个只在 coding agent 中成立的纵向固化机制。

删除检验因此失败。若未来发现某类 reviewer correction 只有通过 code graph 与 agent tool action 的联合反事实才能识别，并且通用 agent memory 环境不存在等价状态与动作，才可重开；当前文献与钢人化设计没有证明这一点。

### 11.1 已触发的终止条件

### 11.2 为什么不是 CONDITIONAL

如果仅缺公开反事实数据，结论应是 IDENTIFICATION PILOT。如果仅缺本地 checkpoint，结论应是 DESIGN NOT FROZEN。本候选的问题更早发生：合法理论不能进入原动作空间，技术近邻组合已经占据核心能力，公平通用模型又能以相同监督执行同一政策。即使 tomorrow 获得完美数据并训练成功，也只能证明一个完整系统有效，不能证明独立的理论算法贡献。

### 11.3 终局结论

**终局 NO-GO，保留候选数 0。**

允许保留的后续工作只有三类，不占三篇题位：

1. 在 coding-agent 环境复现 Zhao 的 benign-experience execution bias，并量化 review rule 的安全回归。
2. 构建 correction-to-future-task 的同起点反事实 benchmark，服务于多种 memory systems。
3. 将 TRACE、CODESKILL、FedWorld、SHE/FATE 和 executable hidden outcomes 集成为生产原型，明确按工程系统而非理论算法论文定位。

重开必须同时满足：新直接工作未覆盖的 coding-specific decision mechanism；合法 AIS 构念产生的方向、非交换更新；等参 generic baseline 的预注册差异；可执行外部 harm；以及 coding-agent deletion 通过。缺一项仍为 NO-GO。
