## 3. 压力测试一：T−2 动态 clarify/repair 是否在任何回答前可重放

### 3.1 通过的合同

`00H` 第 198 行与 `00H-A` 第 136–142 行已经给出两种允许模式。

1. 完整预枚举每个可达 branch instance 的 bytes/hash。
2. 无法预枚举可见回答时，冻结 branch grammar、template bytes/root、slot schema、content-instantiator 版本与 image digest、runtime input whitelist、全部 allowed factual source bytes/hash/Merkle root、parent-state/hash rule、action-bound proposition IDs、budget/cost/latency/termination、确定性 seed 派生和 replay executable hash。

分支只能由可见 factual response、`UNKNOWN` 或明示 clarification request 触发。public execution record 只能填充已触发分支的预承诺 factual slot，不能决定是否出现分支。相同承诺和相同可见输入必须重放同一 bytes/hash，失败则 trial 失效并重做 bind–commit。该合同在 participant response、approval、hidden outcome 和 evaluator access 前写入。

### 3.2 基线开放性

`00H-A` 第 136、262–264 行明确规定 C3 与全部基线共用同一 instantiator、seed、动态 branch instances、action mask、cost 和 replay contract。不存在 C3 可动态修复而通用基线只能使用静态候选的资源优势。

### 3.3 结论

这一项已达到实施前可重放标准。它不需要现在生成全部 manifest 实例；`PENDING-IMPLEMENTATION` 是待实施状态，而不是设计缺口。实施时只需按已冻结字段生成并通过 byte-level replay validator。

## 4. 压力测试二：hidden-byte paired noninterference

### 4.1 固定量是否完整

`00H` 第 200 行及 `00H-A` 第 223–237 行要求 mirror pair 固定 B/public state、部署可见 risk signals、history、response、public execution、candidate IDs、candidate bytes、order、mask、cost、latency features、generator trace、branch replay trace 和 action logits，只交换 G/hidden bytes。另设 evaluator absent、evaluator present-but-sealed 与 hidden-byte-swapped 三条件检查 access log、file/network syscall trace 和 branch trace。

这比“模型输入中没有 hidden label”更严格，因为候选存在性、排序、超时、缺失和延迟都被纳入可观察 side channel。任一机械差异使 group 失效，不能以效果方向或统计不显著挽救。

### 4.2 conditional incremental probe 是否再次用 oracle 选候选

没有。该 probe 先冻结完整 public covariate baseline 和 equivalence group，再增加 hidden-only ID 或 label-store pointer，报告 delta AUC/AUPRC、conditional log-loss/deviance、calibration delta 与 paired permutation。它只诊断 availability/mask/order/cost/timeout/public latency/missingness 是否残留 hidden-only 增量信息，不参与候选生成、筛选、排序或策略动作。

### 4.3 结论

本项通过。必须维持“机械 paired equality 是主门，conditional incremental prediction 只是诊断”的优先顺序，不能在实现时反转为以裸 AUC 判泄漏。

## 5. 压力测试三：eligibility、propensity、support 与同一审核者

### 5.1 same-reviewer primary outcome 已通过

`00H-A` 第 219–221 行冻结了行级硬校验：

`interaction_participant_id == evidence_recipient_id == final_approver_id`

且 `canonical_decision_action_hash == canonical_action_hash`。专家只用 sealed hidden tests/state-delta oracle 产生 safe/unsafe 真值，不能替代 participant 的 approve/deny。外部 gate 不得换人、增加 second reviewer 或根据 C3 trajectory 重路由后仍进入 primary estimand。这一设计使 primary unsafe approval 来自与 C3 交互的同一真人和同一行动，C3 没有滑回 C19 的人员分配问题。

### 5.2 `eligibility_state` 含当前 action，主键不成立

`00H-A` 第 201 行将状态定义为：

`top_action_class × action_subtype × risk_stratum × reviewer_support × grounding_phase × budget_bucket × lattice_availability × history_state_signature`

随后又令：

`estimand_cell_id = action × risk × reviewer_support × eligibility_state`

这里有一个决定性二义性。

- 若 `top_action_class/action_subtype` 表示 T0 被抽到的当前动作，它们是处理变量，不是其自身 propensity 的处理前条件。每个 cell 已经锁定 action，`p(action|state)` 会退化，不能在同一状态比较替代动作。
- 若它们表示“当前至少存在某类候选”或候选集合摘要，字段名和取值合同并未这样定义，而且六类动作可以同时合法，单个 `top_action_class` 无法表示可行动作集合。

`history_state_signature`、grounding phase 与 budget 可以包含过去动作造成的历史，但必须在抽取当前 `A_t` 之前冻结。它们可作为序贯 decision state，却不能包含当前 selected action、当前 selected subtype 或由当前动作执行后才得到的 repair trigger。

### 5.3 候选级 positivity 下界可能数学不可行

`00H-A` 第 206 行要求“每个 eligible action”的 `p(a given eligibility_state)≥0.05`。C3 的 `a_k` 是候选动作，不只是六个顶层 class；`acquire`、`present`、`factual_probe`、`clarify` 和 `repair` 每类都可能含多个 candidate ID。一个合法集合若有 21 个候选，所有候选概率均至少 0.05 已使概率和大于 1。

锁定稿没有冻结每个时点候选数不超过 20，也没有定义 class-then-candidate 的分层 propensity。因此当前 logging policy 不能对所有允许 lattice 保证执行。

### 5.4 clustered ESS 未唯一化

锁定稿要求每个 cell clustered raw `n≥40`、稳定权重 clustered ESS `≥30`、每个顶层动作 ESS `≥200`，并按 participant/task/repository cluster 计算。但它没有说明：

- 三者是嵌套 composite cluster、交叉多向 cluster，还是分别计算后取最小值；
- cluster weight 如何由同一 cluster 内多 decision rows 聚合；
- `ESS=(Σw)^2/Σw^2` 是对 row weight、trajectory weight 还是 cluster-aggregated weight 计算；
- 同一 trial 的 3–6 个决策时点进入哪个 opportunity unit；
- support threshold 在 class、subtype 与 exact candidate 哪一级承担主要主张。

所以两个独立实施者仍可在同一日志上得到不同的 supported/unsupported cells。

### 5.5 最小修补 P1

在任何 support simulation 前冻结以下合同。

1. 将当前处理前状态重写为只含当前动作抽取前可观察字段，例如 `risk_stratum × baseline_reviewer_support × grounding_phase_pre × budget_pre × eligible_action_set_hash × public_history_hash`。从 state 删除 selected `top_action_class/action_subtype`。若需要候选集合摘要，使用可同时容纳多类动作的 `eligible_action_set_hash/class-availability bitmask`。
2. 单独定义 `A_t=(top_action_class, subtype, candidate_id)`，并明确 primary estimand 是 class、subtype 还是 exact-candidate contrast。`estimand_cell_id` 不得在 state 内重复编码 selected action。
3. 冻结一个概率和必然可行的 logging grammar。可以使用 class-then-candidate 的联合 propensity，并分别冻结 `p(class|S_t)` 与 `p(candidate|class,S_t)` 的下界函数；也可以在 T−2 公开承诺每个时点的候选上限。不得继续对不受限的每个 candidate 统一写 0.05。
4. 冻结 primary cluster unit、trajectory/cluster weight 聚合、clustered ESS 公式、多向依赖的处理和阈值层级。结构空 cell 永远标为 ineligible，不做重加权或模型外推。
5. simulator 必须按这套最终语法复现 `eligible set → propensity denominator → selected action → trajectory weight → cell support/ESS`，并由第二实现重算一致。

完成 P1 前，离线策略学习的支持门既不唯一也不总可执行，因此本项不通过。

## 6. 压力测试四：factual-grounding mediator

### 6.1 已经正确的部分

`00H` 第 256–260 行和 `00H-A` 第 245–258 行做对了五件事。

1. Treatment 是 prospective confirmatory cohort 在任何 response/outcome 前随机分配的 policy arm。
2. Mediator 是最终决定前由独立 factual/transfer bank 测得的 action-specific accuracy/calibration，不是神经 hidden state `g_est`。
3. Outcome 是随后由同一真人对同一 canonical action 产生的 unsafe approval。
4. clarification/repair、evidence count、trajectory length、latency、fatigue 和 trigger 被承认为 treatment 后历史，不能在普通回归中当作无害协变量。
5. sequential ignorability/positivity/consistency 不能辩护时，只报告 factual grounding 与 unsafe approval 的关联，不使用因果中介语言。

这些修补解决了旧稿把 `g_est` 或一个 treatment 后 score 直接放入 mixed-effects regression 便声称中介的错误。

### 6.2 estimand 仍未唯一

当前文本写“interventional/organic direct 与 indirect effect”，再写“longitudinal g-formula 或 TMLE”，并以稳定序列权重为替代模型。这里至少混合了三个决定。

- organic effect 与 randomized/interventional effect 依赖的干预定义和识别条件不同，不能用斜杠视为同一对象。
- g-formula 和 longitudinal TMLE 可以针对同一 estimand，但必须先固定纵向变量顺序、stochastic mediator intervention 和 treatment-induced history 的条件集合；当前没有给出这一映射。
- “或”使用 g-formula/TMLE 没有指定 primary estimator。若分析者可以在看到结果后选择，两者不是一个冻结分析。

### 6.3 sequential assumptions 只列名，尚未变成可核合同

arm randomization 识别 total policy effect，但不会自动消除 mediator–outcome confounding。当前仍需冻结：

- 每个决策时点的 `L_t`、action、clarify/repair、grounding response、factual measurement 和 Y 的先后顺序；
- 哪些 baseline/history 足以主张 mediator–outcome sequential exchangeability；
- factual items 的聚合、阈值、校准误差、UNKNOWN 与 missingness；
- consistency 对动态 policy、repair 版本与 measurement protocol 的定义；
- positivity 是 policy-arm、repair encouragement、mediator distribution，还是三者都要求；
- treatment-induced confounder 进入哪一个 g-formula/TMLE factor，而不是被普通调整阻断或打开错误路径。

敏感性分析不能替代 primary identification contract。若关键 fatigue、理解动机或 repair uptake 的处理后混杂不可观察，锁定稿现有“降为关联”规则应执行。

### 6.4 micro-randomized encouragement 仍是备选草案

文本允许在 repair/paired-uptake 合法状态随机化一项不改变 technical evidence quality 的 grounding encouragement，但没有冻结：

- 哪些 eligibility states 进入随机化；
- 每个时点的随机概率、最大次数与 washout；
- encouragement 的 exact bytes/interaction、compliance 和 exclusion restriction；
- proximal mediator、distal unsafe approval 与 primary contrast；
- repair 本身、uptake 和 factual score分别是 treatment、mediator还是 treatment-induced history。

因此 micro-randomization 目前不能承担 causal mechanism 的主要识别。它要么被完整冻结为独立嵌套随机设计，要么从 primary causal claim 移到未来或敏感性研究。

### 6.5 mediator measurement 可能改变 final approval

confirmatory factual bank 在 final approval 前出现。即使界面不显示正确答案，问题本身也可能提示被忽略的风险、促使重新阅读或改变 confidence。此时“测量 mediator”同时成为一项共同施加的干预。

这不必取消实验，但必须冻结 no-feedback/no-correction protocol、相同测量在全部 arms 的位置和 bytes、回答后是否允许返回证据、measurement duration，以及 Y 被定义为“在该统一测量制度下的 unsafe approval”。若 measurement 会触发 repair 或给出新事实，就必须把它写入 treatment history；不能同时把它当作纯被动读数。

### 6.6 最小修补 P2

在首名 confirmatory participant 进入前完成一份可执行 `mediation_estimand_manifest`。

1. 只选一个 primary causal object。若选 randomized/interventional indirect effect，写出两个 policy arms 下 stochastic mediator distribution、direct/indirect contrast 和 treatment-induced histories 的条件规则；organic effect 只能作为另有假设的 sensitivity，不得并列为同一主 estimand。
2. 冻结 longitudinal DAG/变量表、观测时点、mediator aggregation、missing/UNKNOWN、repair intercurrent-event strategy 和 consistency 版本。
3. 冻结一个 primary estimator，例如带 cross-fitting 的 longitudinal TMLE；g-formula 与稳定权重只能按预注册次序作 sensitivity。给出 nuisance models、truncation、cluster bootstrap 和 failure rule。
4. 若采用 micro-randomization，冻结 eligibility、随机概率、encouragement 内容、技术证据等质门、compliance、proximal/distal estimand 与分析。否则明确它不承担 primary mechanism identification。
5. 冻结 mediator measurement reactivity 处理。全部 arms 使用同一 silent/no-feedback bank；任何题目触发的新证据或 repair 都进入历史并改变 estimand，而不是被遗漏。
6. 若 mediator–outcome sequential exchangeability、positivity 或 consistency 无法由观测与随机化支持，提前将 mechanism result 限定为 association。该降级不否定 total policy effect，却撤销“因果中介已识别”的主张。

本项缺的是唯一设计，不是显著结果；故这是 design-freeze blocker，而不是 results-pending 问题。

## 7. 压力测试五：`κ/M/C/UNKNOWN` 与 action binding

### 7.1 字段来源与时点基本通过

`00H-A` 第 66–79 行已经把关键对象分开。

- `J_content` 由独立 task authors 在 T−5 从 public task、canonical action、pre-state 与组织约束标注。
- `m_req/κ` 是外生 criterion specification，冻结 scale version、basis、required-response bank hash、threshold unit 与 sensitivity grid。
- `criterion_measurement_t` 来自 T1 的独立 factual/transfer bank，与 `κ` 的 field ID、producer 和 lineage 不同。
- `C_t` 记录 grounding phase；`M[:,1]` 使用独立 understanding/interpretation event；`M[:,2]` 要求 uptake–exposure–paired-confirmation 三联 ID。同一 response/event 不能循环定义 C 与 M。
- `UNKNOWN/NOT_APPLICABLE/INVALIDATED/MISSING_LOG` 均保存 status time、annotator、reason 与 forbidden-source check，不以 0 回填。

因此，`κ` 不再由 participant score 或 outcome 反推，M 与 C 也不再共用一个礼貌确认事件。这部分理论责任真实进入前向状态与缺失规则。

### 7.2 T−5 早于 T−4，action-specific purpose 没有闭环

`00H-A` 第 32 行让 task authors 在 T−5 冻结 proposition、`J_content`、`m_req/κ` 与 factual bank；第 33 行才由 trusted mediator 在 T−4 冻结 action hash、base commit、pre-state、权限与作用域。虽然 T−5 的字段说明声称读取 canonical action 和 pre-state，但状态机没有给出当时可核的 immutable action digest，也没有要求 T−4 与 T−5 对象逐字节相等。

更关键的是，第 42 行规定 T−4 后 action/pre-state/permission/scope 改变时，旧 lattice、branch、evidence、response、`B_H/M/g_est` 失效并重做 `T−4→T−2`，却没有明确使 action-specific propositions、`J_content`、factual bank、`m_req/κ` 失效。这会允许新 action 沿用旧 purpose criterion。

### 7.3 最小修补 P3

二选一冻结，不得只靠文字意图。

1. **bind-first：** 先产生 immutable canonical action/pre-state/permission/scope digest，再由 task authors 针对该 digest 冻结 proposition、`J_content`、bank 与 `m_req/κ`；或
2. **T−5 prebind：** T−5 manifest 内保存 canonical action bytes/hash、pre-state hash、permission/scope hash，T−4 mediator 必须机械验证完全相等才可继续。

无论采用哪种顺序，action、pre-state、permission 或 scope 变化都必须使 `proposition_manifest/J_content/criterion/factual-bank` 连同后续理论状态全部 `INVALIDATED`，重新执行 purpose→bind→commit 全链。完成这一补丁后，本项可转为通过。

- [A Benchmark to Assess Common Ground in Human-AI Collaboration](https://arxiv.org/abs/2602.21337) 与 Li 等的 [potential/established common-ground 研究](https://arxiv.org/abs/2606.31719) 负责互动 grounding、potential/established 分界及其迁移风险，没有 canonical coding action 与 unsafe approval。

## 11. 理论责任是否真实闭合

### 11.1 已闭合的责任

第二轮稿没有把 common ground 用来生成技术真值、漏洞标签或危险结果。

- objective、resource、risk、commitment 是 task authors 冻结的 `J_content` 内容轴，不是 Mastrogiacomo 原文四条件的一一“理论翻译”。
- 原文 identification、ability、willingness 和 mutual belief 分别承担共同目的识别、行动资源/约束、承诺与递归互认的机制启发；mutual belief 不成为第五内容列，而由 C/M/criterion 的互动过程承担。
- `V` 负责 potential access，`B_H` 负责 action-specific interpretation posterior，`C` 负责 grounding phase，`M` 负责独立理解证据与 reciprocal uptake，`κ/m_req` 负责 purpose-relative criterion。
- 这些状态进入 `g_est/r`、结构损失、候选转移和策略动作；shuffle/clamp、action change、shared-view 错觉与重复展示会产生可观察行为差异。
- 通用模型获得全部相同字段和标签，因而理论模型不能凭私有信息取胜。

这满足“理论改变内部表示、监督和动作”的最低责任，而非仅在引言解释结果。

### 11.2 尚未闭合的责任

理论状态必须绑定当前 exact action。T−5/T−4 顺序缺口会让 `J_content/κ` 在行动变更后失去对象，直接破坏 purpose-relative criterion。因果机制主张又必须依靠唯一可识别的 factual-grounding mediator，而当前仍是多个 estimand/estimator 的菜单。二者分别由 P3 与 P2 修补。

此外，`B_H` 与 `M[:,1]` 都涉及“系统取得审核者理解证据”。当前用独立 event ID 防止循环，已足以进入 pilot；但标注手册仍应把二者写成不同目标：`B_H` 是对具体事实解释类别的 posterior，`M[:,1]` 是双方已形成相互可见理解证据的 recognition/receipt 状态。若 pilot 显示二者标签无法区分，应合并或撤销独立机制，不得用不同变量名掩盖同一信号。
