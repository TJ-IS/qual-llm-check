## 2. 检索漏斗与候选总表

### 2.1 检索方法

检索以“理论能否改变动作”而不是“理论是否能描述风险”为准。每个候选依次经过八道门：

1. **MEC**：理论必须指出通用策略系统性处理错误的机制。
2. **MAP**：机制必须映射到行动时可识别的状态、关系或约束。
3. **ALG**：映射必须改变前向计算、损失或真实动作顺序。
4. **等信息替代**：通用模型得到完全相同的可观测信息。
5. **等标签替代**：通用模型得到相同 outcome、动作、成对干预和成本标签。
6. **等参数替代**：参数量、训练 token、rollout、工具调用与运行时间匹配。
7. **coding-agent deletion**：删除仓库读写、执行工具、patch 分支和集成动作后，研究是否仍原样成立。
8. **直接覆盖与资源**：核对主文、公开 benchmark、数据、代码、训练算力和隐藏测试隔离。

## 3. C29c 的研究对象与真实安全问题

### 3.1 直白问题定义

多个 coding agents 可以在同一 issue 下读取仓库、运行不同工具、形成不同故障假设并修改隔离分支。它们共享 issue、基础仓库和相近预训练知识，因此常生成成批的相似理由；与此同时，某个 agent 可能因运行了不同探针、读取了局部配置、跟踪了运行时状态或检查了依赖约束而持有真正独特的证据。若系统按多数、置信度或长篇 rationale 合并，错误的共同理由会淹没少数正确分支。若系统始终服从少数“专家”，一个陈旧、误校准或被操纵的 agent 又会获得过强权力。

C29c 研究的不是“哪个 agent 更聪明”，也不学习任务分派。它研究一个更窄的行动问题：在 agent 身份和任务职责已经固定后，控制器如何让独特证据先成为可复现的仓库执行 witness，再决定是否让少数分支抢占多数、继续隔离探索、合成 patch、保持并行或拒绝集成。

### 3.2 风险、时点、对象与结果

| 要素 | C29c 定义 |
|---|---|
| 风险 | 多数错误分支或伪专家分支被集成，导致隐藏功能回归、安全不变量破坏、依赖错误、数据或配置损害；或者正确少数分支被稀释，任务最终失败 |
| 决策时点 | 多个隔离 patch/diagnostic branches 已存在、尚未写入目标主线且尚未进入 human approval 之前 |
| 影响对象 | 仓库主线、测试与构建状态、依赖图、随后继续工作的 agents，以及接收软件变更的团队或用户 |
| 可见信号 | 固定 base commit、任务说明、每个 agent 的 sealed proposal、工具调用与文件读写 provenance、branch diff、不可篡改 sandbox receipts、已执行 probe 结果、支持拓扑与成本 |
| 不可见信息 | 隐藏测试内容、完整未来使用分布、未执行路径、agent 内部预训练来源、真实部署后的全部后果 |
| 正常动作 | 继续隔离探索、选择 probe、运行 probe、请求分支给出可执行 witness、处理已揭示证据、集成或合成候选 |
| 风险动作 | 直接多数合并、按身份盲从专家、在 witness 未验证时执行分支、把 agent 自写测试当作独立真值 |
| 纠正动作 | preempt 多数、fork/replay、quarantine 分支、discard、defer、追加区分性 probe、回到 sealed checkpoint |
| 主要风险结果 | unsafe branch adoption、hidden-regression rate、security/invariant violation、不可恢复工作树损害 |
| 任务结果 | issue resolution、正确 patch adoption、至少一条正确分支存在时的 recovery rate |
| 成本结果 | probe 数、容器秒、token、通信轮次、墙钟时间与无效分支计算 |

安全改善不能以拒绝所有分支、总是串行、总是追加测试或总是选择人工介入获得。主要评价是安全—任务—成本联合前沿，并分别报告错误少数、错误多数与恶意/陈旧专家条件。

### 3.3 coding agent 不可删除性

删除 coding-agent 身份后，hidden-profile 群体决策仍可存在；这不足以证明 C29c。C29c 的不可删除部分是：

1. 每个参与者能够自主读取仓库、选择工具、改变隔离代码状态并生成新的执行证据。
2. 候选不是静态答案，而是有 base commit、diff、依赖和可重放执行后果的 patch branch。
3. “可证明”不是自然语言说服力，而是同一 immutable probe 在 branch/base 或 competing branches 上产生的区分性结果。
4. 控制器最终执行 `fork/replay/integrate/discard/quarantine` 等软件状态动作，而非输出一个类别或答案。
5. 错误结果由隐藏测试、安全不变量与状态差分判定，而非 debate 正确率。

若实验只保留最终答案聚合，或把 patch 换成任意文本候选后算法和指标不变，coding-agent deletion test 失败，C29c 撤题。

### 3.4 对抗边界

C29c 的主体问题不要求攻击者。主实验包含诚实但错误、诚实但陈旧与相关错误 agents。为检验“利用真专家而不牺牲鲁棒性”，另设受控 corrupt-expert 条件：一个 agent 可以提交错误 rationale、伪造普通文本测试结果或引用陈旧运行，但不能改写 sandbox supervisor、隐藏测试、base commit、receipt 签名和只读评价镜像。所有破坏性实验限制在公开或授权的隔离仓库/容器内，不接触真实生产系统。

## 4. 理论责任：MEC → MAP → ALG

### 4.1 Qiu、Cheng 与 Pu 的独立责任

Qiu 等人的分析对象是企业预测市场。其可迁移机制只有一项：当每个参与者的判断都混入同一公共信号时，聚合会把公共部分重复计数，使公共噪声被放大。Proposition 2 进一步给出条件反转：在非网络市场中，当 `ρ_V / ρ_ε ≤ (n−2)/n` 时，提高公共信息精度反而提高 MSE；提高私有信号精度则始终降低 MSE。其 homophily 分析表明相关私有误差削弱社交共享的纠偏。

这项机制在 C29c 中只授权两个计算责任。第一，完全相同的 common evidence 不得随着支持人数重复进入聚合，候选必须满足 duplicate-public-evidence invariance。第二，分支专属 evidence 的边际价值必须依据可观察来源和执行差异估计，不能按 agent 数量或文本置信度相加。Qiu 不授权 commit–reveal、probe、branch merge 或 quarantine；这些动作必须另有机制和 coding-specific 证据。

### 4.2 Dennis 1996/1997 的独立责任

Dennis 1996 证明信息被交换并不等于信息被使用。Dennis、Hilmer 与 Taylor 1997 又报告条件反转：存在明确 majority/minority 时，GSS 增加信息交换并改善决策；uniform 意见结构下，GSS 虽交换更多信息，决策却变差且耗时更长。原文把 parallelism、anonymity 与 group memory 视为可操作的媒介属性，并指出 unique information 缺乏 demonstrability 时更难被接受；结论建议把 information exchange 与实际 decision 分开，为评估和整合新信息留出阶段。

C29c 只迁移可观察结构：分支在看见其他分支前是否 sealed、信息是 shared 还是 branch-exclusive、支持拓扑是 majority/minority 还是 uniform、证据能否由 immutable execution 重放，以及 reveal 后是否经过独立的 processing state。人类认知负荷、面子、从众压力和可信感受不进入 agent 隐状态，也不作为标签。

### 4.3 组合后的机制链

**MEC。** 通用多数、置信度加权或全量 cross-attention 同时犯两类错误。它们把重复公共理由当作多份支持，并把“信息已被说出”当作“信息已改变可靠决策”。结果是在多数错误时压低独特证据，在 uniform 条件下又为无区分价值的信息支付额外通信和处理成本。盲目反多数则在 corrupt-expert 条件下反向放大风险。

**MAP。** 该机制产生四个不可省略的中间状态：`origin ledger` 区分 exact-common 与 branch-exclusive evidence；`support topology` 描述多数/均匀/离散结构；`demonstrability state` 记录 witness 是否由只读 supervisor 在绑定 branch 上重放并区分候选；`phase state` 区分 sealed、acquiring、revealed、processed 与 admissible。它们均来自 harness 日志和真实执行，不推断 agent 心理。

**ALG。** 四项状态进入专门计算与行动语法：公共证据经 set-unique operator 只编码一次；分支专属 residual 只有在 witness gate 后才能取得 preemption 权；revealed evidence 不能绕过 processing transition 直接触发 integration；策略按 support topology 和 witness validity 在 `probe/reveal/process/preempt/integrate/isolate/defer` 中选择。理论因此改变前向结构、成对损失和允许动作顺序，而不只改变变量名。

### 4.4 非交换顺序

令 `S` 为独立分支封存，`A` 为获取分支专属证据，`D` 为在绑定分支执行区分性 probe，`P` 为依据新 witness 更新 branch belief，`I` 为 integrate/preempt/isolate。C29c 只允许：

`S → A → D → P → I`

以下交换会改变行为，必须作为机制干预：

- `reveal → S` 使后写分支受多数 rationale 污染，无法识别原始独特证据。
- `A → I` 把 agent 自述当作执行真值，伪专家可直接抢占。
- `D → I` 跳过 branch belief 更新，交换仍被误当作使用。
- `P → D` 让控制器先按文本形成偏好，再选择确认性 probe。
- 对 uniform 条件无差别重复 `A/D/P` 会增加成本并可能引入低价值证据；对 majority/minority 条件完全跳过它们又保留共识惯性。

这不是声称所有任务都必须固定五步，而是定义一个有类型约束的 action grammar。策略可以在证据充分时提前 `integrate`，在证据不足时追加 `D`，在 witness 无效时 `isolate`，但不能让未证明的分支自述直接获得集成权。

### 4.5 三组成对方向反转

| 条件 | 理论预期动作 | 不应采用的统一规则 |
|---|---|---|
| majority-wrong / minority-correct 且少数有可复现区分 witness | 为少数分支分配 probe，完成 processing 后允许 preempt 多数 | 永远多数、永远平均、只按支持数加权 |
| uniform 且分支证据无明显区分价值 | 减少重复 reveal/probe，在预算内保持或快速结束低价值交换 | 因“更多信息总是更好”而强制更多轮次 |
| corrupt/stale expert 且 claim 无有效 witness 或与 supervisor receipt 冲突 | quarantine/isolate，保留其他分支或重新探测 | 永远服从已知专家、永远翻转多数 |

只有三种条件在同一控制器中共同改善，才能证明候选解决的是 expertise utilization–robustness conflict，而非 anti-consensus 分类。

## 5. 算法与训练规格

### 5.1 工件边界

候选工件暂称 **EDCI controller**，即 executable-demonstrability-conditioned integration controller。名称只用于内部规格。工件由一个可训练 evidence/branch encoder、一个区分性 probe policy、一个 phase-typed sequential controller 和一个 outcome world model 组成，输出真实仓库动作。它不训练 agent 身份发现器，不改变人类审批，也不把基础 coding LLM 的自然语言回复作为最终产品。

### 5.2 输入与输出

**输入。** 固定 issue 与 base commit；`N` 个 sealed agent branches；每条 branch 的 patch、file/AST/change graph、读取与工具事件、claims、可见测试结果、agent-local evidence provenance；公共任务包；supervisor 生成的 immutable execution receipts；历史 action/cost；当前 phase 与 support topology。

**输出。** 下一步动作及参数：

`KEEP_SEALED(i)`、`REVEAL_CLAIM(i,j)`、`SELECT_PROBE(m, branches)`、`RUN_PROBE(m,i)`、`REQUEST_WITNESS(i,m)`、`PROCESS_UPDATE(i)`、`FORK(i)`、`REPLAY(i,t)`、`PREEMPT(i)`、`INTEGRATE(i)`、`SYNTHESIZE(i,j)`、`QUARANTINE(i)`、`DISCARD(i)`、`DEFER`、`STOP_SAFE`。

动作由 runtime supervisor 执行。控制器不能直接读取隐藏测试，也不能改写 receipt、base image 或 evaluation harness。

### 5.3 关键张量

| 张量 | 形状示意 | 来源与含义 |
|---|---|---|
| `C ∈ R^{B×N×L_c×d}` | batch × branch × claim × hidden | branch claim、代码位置与局部 rationale 的编码 |
| `O ∈ {0,1}^{B×N×L_c×3}` | common/private/derived | 由 harness 事件日志确定的来源 mask，不由模型猜测 |
| `P ∈ R^{B×N×L_p×d_p}` | patch nodes | diff、AST、file、dependency 与 scope 表示 |
| `W ∈ R^{B×N×M×d_w}` | branch × probe | 编译、测试、trace、invariant、退出码、状态差分及 receipt validity |
| `R ∈ [0,1]^{B×N×N}` | branch pair | 从 exact source overlap、prompt/model lineage 与可见执行残差估计的相关性；不声称恢复全部预训练相关性 |
| `T ∈ {0,1}^{B×K_t}` | topology | majority/minority、uniform、fragmented、unknown 的可见支持结构 |
| `Q ∈ {0,1}^{B×K_q}` | phase | sealed/acquiring/revealed/processed/admissible/terminal |
| `H ∈ R^{B×T_a×d_h}` | action history | 先前 probe、reveal、cost 与 branch transitions |

“public/common”只指任务包、相同仓库快照、相同广播消息或相同 receipt ID 等可审计相同来源。模型预训练知识、相似措辞和未记录记忆不得事后命名为公共信号。若无法在数据中建立这一操作定义，Qiu 机制不可识别，候选撤题。

### 5.4 专门前向结构

1. **Common-once encoder。** 对完全相同 source ID 与 content hash 的公共 evidence 先作集合去重，再形成一次 `z_pub`。把同一公共 claim 复制给更多 agents 不得改变 `z_pub`。
2. **Private residual encoder。** 每个 branch 形成 `r_i = Enc(C_i,P_i) − Proj_pub(Enc(C_i,P_i))`，并结合 exact provenance overlap 与 `R_ij` 估计非重复部分。该 residual 不是“独特即正确”。
3. **Executable demonstrability module。** probe policy 在 competing branches 上选择预期区分度高、成本受限且不泄漏隐藏测试的 probe；world model 预测 probe outcome 与 patch harm；receipt verifier 只接收 supervisor 绑定结果。
4. **Witness-gated preemption。** 分支 preemption logit 由 `r_i`、valid witness、branch outcome prediction 与 topology 共同计算。文本 claim 或身份 alone 不能打开 gate。
5. **Phase-typed controller。** masked actor 根据 `Q` 屏蔽非法 transition。`REVEAL` 后必须至少一次 `PROCESS_UPDATE` 才能 `PREEMPT/INTEGRATE`；invalid receipt 只能进入追加探测、隔离或停止分支。
6. **Outcome world model。** 预测下一 repo state、hidden-risk proxy、task completion、probe value 与成本，为 offline planning 和 constrained RL 提供状态转移。

common-once、witness gate 与 phase transition 是候选的硬结构。若去掉这些结构后只剩一个带额外分数头的 HGT/POMDP，独立算法贡献不成立。

### 5.5 训练样本构造

基础任务来自有可重放容器和隐藏评价的公开仓库任务，优先级如下：SWE-bench Verified/Live、Multi-SWE-bench、Defects4J 与 Recent-Java；CooperBench 只用于补充真实双 agent interaction，不单独提供安全真值。每个任务先按仓库划分，再运行独立 agent rollouts，形成 branch pool。所有 agent 在生成 sealed proposal 前不得看到其他 proposal。

同一底层任务构造三类 paired episodes：

1. **Majority/minority。** 从 branch pool 选择多个相关错误分支和至少一个隐藏评价正确分支；少数分支必须有可由公开输入生成、由 supervisor 重放的 candidate witness。
2. **Uniform。** 选择支持分散、没有明确多数且额外消息的区分价值低或不稳定的分支组合；保持任务、branch 数与预算匹配。
3. **Corrupt/stale expert。** 在隔离环境中替换一条 expert claim、绑定陈旧 base 的 receipt，或提供不能由 supervisor 重现的 agent-authored result；不泄漏隐藏测试。

每个 episode 保存 base SHA、branch SHA、agent/model/prompt 版本、tool trace、container digest、probe manifest、receipt hash、隐藏 evaluator version、随机种子和成本。训练语料不得包含测试仓库的隐藏测试文本或 gold patch。

### 5.6 标签与监督信号

| 标签 | 获得方式 | 行动时是否可见 |
|---|---|---|
| branch task correctness | 在隔离 evaluator 中运行隐藏测试/官方 harness | 否；仅训练 reward/评价 |
| safety/regression harm | 隐藏安全不变量、回归测试、state-diff oracle | 否；仅训练 reward/评价 |
| evidence origin | harness 的 source ID、read/event log 与 content hash | 是 |
| witness validity | supervisor 对 branch SHA、probe SHA、container digest 的绑定与重放 | 是 |
| probe discrimination | 同一 probe 在 competing branches/base 上的结果差异 | 执行后可见 |
| topology | sealed proposals 的支持关系和 branch equivalence | 是 |
| oracle action/value | 在训练 episode 上用完整 terminal outcome 做 budgeted search 或 dynamic programming | 否；作为 offline supervision |

隐藏结果可用于训练 terminal reward，但测试期控制器只能看到 rollout 当时可见信号。若 branch correctness 在构造阶段被编码进 agent 名称、proposal 顺序、test filename、日志路径或 cache，视为泄漏。

### 5.7 损失函数

总损失预注册为：

`L = λ_act L_action + λ_out L_outcome + λ_probe L_probe + λ_rl L_CRPO + λ_dup L_dup + λ_min L_minority + λ_uni L_uniform + λ_cor L_corrupt + λ_phase L_phase + λ_cal L_calibration`

- `L_action`：oracle/best-known budgeted trajectory 的 next-action cross entropy，并允许多条等价最优动作。
- `L_outcome`：branch task success、harm、integration effect 与 next-state 的多任务损失。
- `L_probe`：预测 probe 对 competing branches 的区分度、有效性与成本；正样本来自真实重放差异。
- `L_CRPO`：约束策略优化，在 unsafe adoption、task failure、probe/communication cost 间学习 Pareto policy。
- `L_dup`：复制、重排同一公共 evidence 后 policy distribution 与 `z_pub` 保持不变。
- `L_minority`：在 paired majority-wrong episode 中，加入有效少数 witness 后，preemption/adoption probability 按正确方向改变。
- `L_uniform`：uniform 条件下加入重复低价值消息不应诱发更多无效 reveal/probe。
- `L_corrupt`：将有效 witness 替换为不可重放或错误绑定 receipt 后，专家 preemption probability 必须下降，并增加 quarantine/defer。
- `L_phase`：非法 phase transition 的 mask loss 与合法序列辅助监督。
- `L_calibration`：branch harm、witness value 与 action risk 的 Brier/ECE 校准。

`L_minority` 不能独立训练成“见少数就翻转”；它必须与 `L_corrupt` 共享任务并接受相反梯度。`L_dup` 不能用隐藏正确性标签，而只依赖相同 source/content 的反事实复制。

### 5.8 训练、验证、测试划分与泄漏隔离

1. 先按 repository family 和提交时间做 train/validation/test 划分，再生成 rollouts；同一 issue、fork、backport、near-duplicate patch 不跨 split。
2. 所有由同一 base commit 派生的 majority、uniform 与 corrupt paired episodes 留在同一 split。
3. 测试仓库的官方隐藏测试、gold patch、developer solution 和未来 commit 不进入 agent context、retrieval index、probe generator 或缓存。
4. 对测试集使用独立 evaluator service；controller 只得到 coarse receipt，不得到隐藏 assertion 文本。
5. 训练 split 可用 terminal reward；validation 用于 checkpoint/constraint selection；test 只运行预冻结 checkpoint、action grammar 与预算。
6. 提交近邻、函数克隆、issue 文本相似度、模型知识截止和污染探针写入 leakage report。
7. adversarial condition 的伪造模板按 repo 留出，避免模型只识别固定坏 receipt 格式。

### 5.9 本地算力、checkpoint 与复现工件

建议把基础 coding agents 冻结，只训练 300M–1.3B controller/world-model 组件。形成性阶段可在 4×A100/H100 80GB 或等效本地 GPU 上完成：branch encoder 与 world model 监督训练、paired counterfactual training、offline RL/CRPO；大规模 branch rollouts 可用本地 7B/14B coding models 加容器集群生成。最终论文必须报告实际而非计划算力。

必须发布或归档：

- `data_manifest.jsonl`：task、base、split、license、container、hidden-evaluator version。
- `branch_manifest.jsonl`：agent/model/prompt、sealed timestamp、branch SHA、tool trace。
- `probe_manifest.jsonl`：probe source、scope、cost、receipt、branch outcomes。
- 训练配置、action mask、所有 `λ`、optimizer、scheduler、seed、checkpoint SHA256。
- 完整合取基线与等参通用基线配置。
- 结果生成脚本、统计分析计划、失败案例与 excluded-run log。

若主要能力依赖云端 judge、提示词拼接或手写 topology switch，而本地训练只产生一个辅助打分头，候选撤题。

## 6. 评价设计与不可移动基线

### 6.1 主要评价任务

评价至少覆盖四种任务家族：仓库级 issue resolution、运行时逻辑错误修复、依赖/配置变化、带安全或回归不变量的协作 patch integration。每个任务报告是否至少存在一个可安全采纳分支，以区分“团队没有正确候选”和“系统压制了已有正确候选”。

主要终点包括：

- `Unsafe Adoption Rate`：集成分支触发隐藏安全/回归损害的比例。
- `Safe Recovery@Existing`：branch pool 中至少有一条正确安全分支时，最终采纳正确分支的比例。
- `Task Resolution`：官方隐藏 evaluator 通过。
- `False Quarantine`：安全正确专家分支被隔离。
- `Corrupt Preemption`：不可重放专家 claim 获得抢占权。
- `Probe Efficiency`：每次避免错误采纳所需 probe、容器秒与 token。
- `Communication/Wall-clock Cost`：消息、轮次、GPU/CPU 与墙钟。
- 安全—任务—成本 Pareto hypervolume，并提供分条件置信区间。

### 6.2 直接基线

1. 单一最强 coding agent 与 best-of-N。
2. 多数投票、平均置信度、LLM-as-judge。
3. HiddenBench 风格 forced disclosure 与固定多轮协议。
4. diversity-aware + calibrated-confidence debate。
5. response anonymization。
6. InfoDelphi 的 public/private routing、rationale exchange 与 confidence aggregation。
7. Minority Sentinel。
8. AgentAuditor 与 AgentAuditor-ACPO。
9. SWE-Debate。
10. TraceRepair 与 AgentForge。
11. C2C communication scheduler。
12. Shepherd generic supervisor 与 Claim Plane admission/integration。

### 6.3 决定性的最强合取基线

不能只分别比较上述工作。必须实现一个 matched full-conjunction baseline：

`InfoDelphi evidence partition/de-correlation + AgentAuditor/ACPO divergence audit + TraceRepair executable probes + C2C cost-aware communication + Shepherd fork/replay/discard + Claim Plane immutable admission/integration`

该基线得到与 C29c 相同的 branches、source IDs、probe catalog、receipts、动作集合、terminal labels、rollout 数和工具预算。其 controller 可以用等参数通用 Transformer/HGT 或通用 constrained POMDP 学习联合策略。若 C29c 只比单项基线好、不能越过完整合取，论文贡献不足。

### 6.4 等信息、等标签、等参数通用替代

通用替代模型接收 `C,O,P,W,R,T,Q,H` 的全部原始字段，获得相同 action/outcome/probe/counterfactual labels，使用相同 action mask、训练 steps、参数量、token、容器调用与超参搜索预算。其区别仅是取消 common-once factorization、witness-gated branch residual 与理论配对结构，让 generic cross-attention/temporal graph 自行学习。

这项替代不是在设计期宣布必胜。C29c 的 hard common-once operator、phase-typed transition 和相反梯度的 minority/corrupt pairing 与 generic 前向并不逐项同构，因此按肖文的算法论证标准可以进入结果检验。若 generic baseline 匹配或超过主要联合终点，理论专门算法贡献撤销；若 C29c 仅在较小参数或较少数据时收敛更快，则只能主张归纳偏置和样本效率，不能夸大为不可复制能力。

### 6.5 消融与机制干预

必须运行：

- 删除 common-once，允许公共 claim 按 agent 数重复。
- 复制公共 evidence 1、2、4、8 次，检验 action distribution 是否不变。
- 交换 common/private masks，但保持内容不变。
- 取消 sealed proposal，让 agents 先看多数 rationale。
- 把 `reveal → process → integrate` 改成 `reveal → integrate`。
- 删除 demonstrability gate，只用文本 claim/identity/confidence。
- 打乱 receipt 与 branch SHA 的绑定。
- 删除 `L_minority`、`L_uniform`、`L_corrupt`，以及分别/联合删除。
- 把 majority/minority、uniform、corrupt topology labels 打乱。
- 对已知 expert identity 做匿名/实名干预；身份不能替代 witness。
- matched parameter 的 generic Transformer/HGT/POMDP。

理论责任只有在以下可观察模式同时出现时成立：公共证据复制不改变候选策略；有效少数 witness 在 majority-wrong 条件下提高 preemption；同样的少数身份在 corrupt 条件下因 invalid witness 降低 preemption；uniform 条件下额外交换的边际动作减少；跳过 processing 或打乱 provenance 破坏安全—任务前沿。

### 6.6 统计与失败分析

主要比较按同一底层 task 的 paired episode 进行，使用 repository-cluster bootstrap 或 mixed-effects model，报告绝对差、相对风险、效应量与 95% 区间。多个主要终点采用预注册层级检验或 FDR。失败案例按以下类型编码：正确分支未生成、正确 witness 未发现、probe 伪区分、公共 evidence 错分、processing 更新错误、恶意 receipt 未隔离、过度 quarantine、成本预算耗尽。任何数字结果在真实运行前均保持空白。

| C2C, arXiv `2510.19995` | sequential action framework；成本感知 when/whom/how communication | 动态通信调度已覆盖 | 缺少真实 patch execution truth、demonstrability 与风险结果 |
| Shepherd, arXiv `2605.10913` | typed Git-like trace、fork/replay/merge/discard、Tree-RL | branch runtime 与干预动作已覆盖 | 不决定哪份少数证据值得以安全代价获得采纳权 |
| Claim Plane, arXiv `2607.21909` | exact base、typed resources、admission、scope promotion、immutable patch/evidence、fail closed | integration/admission/isolation primitives 已覆盖 | 不学习 hidden-profile 条件下的 evidence acquisition 与 expertise–robustness reversal |
| From Agent Traces to Trust, arXiv `2606.04990` | evidence/tool/memory/claim/action provenance 的统一图谱 | provenance graph 本身不是贡献 | provenance 必须进入 counterfactual loss、witness gate 与动作选择 |

### 7.1 为什么纯 Qiu 路径终止

若 C29 只把 common prompt、shared repo、private tool observation 编成 source mask，再做 correlation-aware weighting，它与 InfoDelphi 的 public/private partition、AgentAuditor 的 semantic dedup、ComplLLM 的 complementary signal training 和通用 provenance graph 合取后没有独立动作。若再加一个“公共证据只算一次”的权重，主要贡献只是常见 de-dup/ensemble correction。更严重的是，自然 coding rollout 中 private evidence 往往是 agent 自主选择工具后内生产生，`ρ_V`、`ρ_ε` 和真实误差相关性在行动时不可观察；用隐藏测试估计后再输入会造成泄漏。因此 C29a 为终局 NO-GO，Qiu 只能约束 C29c 的 duplicate-public invariance，不能单独授权论文。

### 7.2 为什么固定 hidden-profile 协议终止

`sealed independent commit → anonymous reveal → processing interval → vote` 有明确顺序，却仍是手写协议。HiddenBench 已直接操作 distributed evidence 与 disclosure，InfoDelphi 已操作 public/private 分配与轮次，ACL 2026 已操作 confidence/diversity 和 anonymization，Dennis 原文的间隔建议也不是学习算法。若输出只是在几种 protocol 中选择，动作退化为 router。C29b 因此为 NO-GO。

### 7.3 最强合取是否已经杀死 C29c

现有合取几乎覆盖整个表面流程：InfoDelphi 提供分散输入，AgentAuditor/ACPO 保留少数分支，TraceRepair 提供执行 probe，C2C 决定通信，Shepherd 管理 branch，Claim Plane 管理 admission。C29c 仍暂留的原因不是这些部件尚未被人接在一起，而是候选把三种冲突条件做成同一训练对象，并引入三个现有合取没有逐项规定的计算责任：

1. common evidence duplication 是结构不变性，不是普通来源特征或附加分数。
2. branch-exclusive claim 只有经 supervisor-replayed discriminating witness 才能获得 preemption 权，真实专家与 corrupt expert 对同一身份产生相反梯度。
3. exchange、processing 与 integration 是类型化状态转移；公开消息不能直接变成 merge，uniform 条件又必须学习抑制低价值交换。

这三项构成 specialized representation、loss coupling 和 action protocol，和 unrestricted generic policy 不是逐层同构。因此按设计审查标准可标 CONDITIONAL。可是它们是否带来独立能力只能由完整合取和等参通用实验决定。若实施时 common-once 只是 preprocessing、witness gate 只是静态规则、phase state 只是 action mask，而所有学习仍由一个普通 scorer 完成，候选将退化为现有部件的工程拼接并撤题。

## 8. 七项终审与撤题门

| 审计项 | 当前结论 | 不可移动的撤题条件 |
|---|---|---|
| 真实外部损害 | 通过 | 只测 debate accuracy、patch preference 或静态 label，不测隐藏回归/安全损害 |
| coding agent 不可删除 | 条件通过 | 换成静态文本候选后输入、动作、指标不变 |
| 公开可执行底座 | 通过 | 不能在公开容器/仓库上构造 majority/uniform/corrupt paired episodes |
| 标签可识别 | 条件通过 | common/private 依赖不可观测预训练来源；witness validity 由同一 agent 自报；隐藏测试字段泄漏 |
| 本地训练工件 | 条件通过 | 只有 prompt、固定协议、规则 gate、云端 judge 或辅助打分头 |
| 理论非装饰 | 条件通过 | common-once、phase separation、paired reversal 删除后没有预期行为变化 |
| 直接新增能力 | 极窄条件通过 | full-conjunction 或 equal-label/equal-parameter generic 复制主要联合前沿 |

正式进入完整数据生产前，只允许做一个小型 smoke study。该 study 必须同时含三种 topology、真实 executable branches、immutable receipts、完整合取和等参 generic。若不能观测“有效少数应抢占、均匀低价值交换应减少、无效专家应隔离”的成对反转，不扩大数据、不包装为 domain adaptation，立即终止 C29。

## 9. C30–C32 的终局 NO-GO 说明

### 9.1 C30：collective mindfulness 驱动的事故遏制

McAvoy、Nagle 与 Sammon 的 AIS Basket 全文把 mindfulness 用于分析 ISD 团队行为与例程，强调 preoccupation with failure、reluctance to simplify、sensitivity to operations、commitment to resilience 和 deference to expertise，也指出这些过程失衡可能带来 information overload 或 learned helplessness。该理论可以解释为什么事故响应不能只看一次成功，却没有给机器 agent 的可识别事故状态、containment 动作语法或损失。

技术侧已出现直接覆盖。AIR 定义 incident-response DSL 并把 detect、contain/recover、eradicate/guardrail synthesis 接入 agent loop；SecRespond 提供 10 个 post-compromise cyber ranges；SIR-Bench 提供 794 个 investigation cases 与 triage/novel evidence/tool appropriateness 指标；SREGym 提供 90 个 live SRE problems。把五项 mindfulness 做成五个 head，或令策略在 investigate/contain/recover 间选择，既发生组织层到 agent 层的迁移断裂，又被现有 DSL、benchmark 与通用 CMDP 覆盖。删除代码生成后，它仍是原样的 SRE/SOC agent。C30 为 NO-GO。

### 9.2 C31：workaround/exception 生命周期

Karanasios 等人的 AIS Basket 全文以活动理论解释企业系统 workaround：总部模板与本地工作发生 contradiction，使用者集体形成 data/procedure/parallel-system adjustments，管理者随后 formalize、permit 或 prevent。该过程说明绕行不应一律视为恶意，也说明临时实践可能制度化。

coding agents 确有真实对应风险：训练 rollout 已观察到抑制失败测试、利用 git state、使 test collection 中止等 reward hacking；coding agents 也大量修改 tests 并使用 mocks，配置平台甚至允许关闭慢速 checks。可是，若候选控制 `propose exception → bind scope/time → execute → observe → formalize/revoke`，核心动作分别落入 permission/exception、test-control、verification debt 和 rollback，直接重返 C7/C11/C17。活动理论的 contradiction 与组织学习无法给每个机器例外的真实潜在结果；若用 hidden tests 直接标注，又由通用 policy controller 完成。C31 为 NO-GO，不能以“learned safe workaround”改名返回。

### 9.3 C32：自生测试证据的独立性与停止控制

这一候选针对 patch agent 同时写测试、反复运行并引用自己证据的问题。最新实证已显示 agent-written tests 的数量与 issue resolution 关联很弱，许多测试主要产生 print-style observation；coding agents 更频繁加入 mocks；大规模静态分析还发现 agent tests 的 non-determinism 与 file-I/O flakiness 风险。TEBench 已把 breaking、stale、missing test evolution 做成项目级 benchmark，mutation-guided regression augmentation 又直接检验测试充分性。

若主要工件判断“是否信任自写测试”，它退化为分类/verification head；若强制独立 tester、恢复原测试、重复运行或 sequential stopping，则重返 C5/C11/C14，且已有现成机制。若把同源性放入 provenance graph，再做来源折扣，仍是 C29a 已否决的普通去重。C32 为 NO-GO。

## 10. 与迁移题和 C3 的系列关系

若 C29 最终越过结果门，三个研究可共享一个上位问题：

> **在知识不完全、分散且会变化的条件下，自主 coding agent 如何可靠地改变软件状态。**

三题不是工作流切片：

| 研究 | 核心不完全知识 | 决策主体与时点 | 独立动作 | 独立真值与工件 |
|---|---|---|---|---|
| 固定 pre-cutover PostgreSQL 迁移候选 | 未来运行状态与迁移后果未知 | 单/多 agent 在 cutover 前选择主动缓解期权 | probe、prepare、shadow、stage、commit/defer 等迁移动作 | 迁移 outcome/world model 与 option policy checkpoint |
| C29c | agent 间 repo-local 独特证据被相关多数稀释，专家又可能陈旧或被操纵 | agent-agent pre-integration，尚未进入 human approval | acquire、demonstrate、process、preempt、integrate、quarantine | evidence/branch controller、probe policy、world model checkpoint |
| C3 | 人类审核者没有形成足以授权具体行动的事实共同基础 | 固定 human approval point | 选择和排序绑定行动的证据动作，更新 reviewer grounding | human-grounding policy、真实 unsafe approval 结果 |

C29 必须停在 agent-agent pre-integration。它不决定给人类展示什么、不预测人类批准、不选择审核者，也不调用人类作为 fallback action。C3 可以接收 C29 最终形成的一个候选行动及其可信 receipts，但 C29 的成立不依赖 C3，C3 也不依赖 C29 的结果。迁移题研究未来运行状态和 staged commitment；C29 研究分散证据下 competing patch branches 的采纳权，两者的状态、动作、标签和 checkpoint 均不同。

## 11. 冻结前最小证据包

C29 只能在以下证据全部形成后申请 design freeze：

1. 公开脚本能够在至少两个语言/仓库家族中稳定生成同 task 的 majority-wrong、uniform 与 corrupt-expert paired episodes。
2. common/private 来源完全由 harness manifest 标识，不依赖研究者阅读隐藏答案后的主观编码。
3. probe 在不读取隐藏测试的前提下对 competing branches 产生可重放区分结果。
4. C29 越过单项基线、完整合取与等参 generic，而非只越过 majority vote。
5. duplicate、minority、uniform、corrupt 与 phase-order 干预呈现预注册的相反行为方向。
6. 主要改善出现在真实 unsafe adoption/hidden regression，同时 task resolution 与成本仍可接受。
7. 至少一个跨仓库/时间/风险类型 OOD split 成立，且失败案例不集中于泄漏、固定模板或 agent 身份捷径。

任何一项缺失均维持 CONDITIONAL；第 2、3、4 或 5 项失败则直接 NO-GO。论文正文在真实实验前只能写研究设计、假设和评价方案，不能写“结果表明”。

## 15. 本轮终判

C29c 是本轮唯一没有在设计期被逐项同构或直接覆盖完全消解的候选。其可守核心不是 hidden profile 这一现象，也不是多 agent debate，而是：**在真实 patch branches 上，把公共证据不重复计数、少数 claim 的可执行可证明性、信息交换与实际使用的阶段分离，以及真专家/伪专家的相反监督共同写进一个多动作序贯控制器。**

这个核心足以支持一次小型训练与直接反证，因此标为 **CONDITIONAL**。它还不足以 design-freeze。最强直接工作合取已经覆盖绝大多数基础设施；如果专门结构不能越过该合取和等参通用策略，或者理论干预没有产生 majority/minority、uniform、corrupt-expert 的成对方向反转，就必须终止，不得以“coding executable extension”“更安全的 debate”或“理论增强的 orchestrator”继续包装。
