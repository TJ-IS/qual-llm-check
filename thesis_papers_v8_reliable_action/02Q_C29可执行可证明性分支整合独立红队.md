## 0. 一句话结论

C29c 尚未触发设计期终局 NO-GO。没有一篇直接工作在同一仓库分支、同一行动时信息、同一 probe 预算、同一多动作控制和同一安全—任务—成本结果上完整实现它，也没有证据表明一个公平通用替代与其当前最强可行版本在前向和梯度上精确同构。可是，`02N` 仍把 Qiu 的精度加权公共先验外推成 exact-hash common-once，把 Dennis 的人类群体实验外推成 demonstrability gate 与固定 `S→A→D→P→I`，又没有把 action-time topology 与 hidden outcome strata、receipt validity 与 witness value、规则脚手架与可训练新增能力分开。probe policy、world model、belief update、offline controller 和 full-conjunction adapter 也未达到可以照规格唯一实现的程度。因此，当前只能保留候选，不能 design freeze。

这个判断不以尚未运行实验为理由。完整合取或等参 generic 是否取胜，majority/minority、uniform 与 corrupt 条件是否出现预注册方向反转，以及任务成功率是否非劣，全部是未来 RESULTS/KILL 门。只要本报告第 12 节的字段级设计门闭合，设计可以在没有性能结果时冻结；之后的经验失败再撤销经验贡献或整篇论文。

## 2. 判定规则：设计门与结果门必须分开

### 2.1 设计期可以直接 NO-GO 的四类证据

本轮只在以下情形给设计期 NO-GO。

1. **精确同构。** 主模型和公平替代在相同输入、标签、状态转移、动作、前向运算和梯度上可逐项重参数化，仅理论名称不同。
2. **直接完整覆盖。** 已有工作或一个已经实现的直接系统在相同行动时信息、动作和外部结果上实现候选全部能力。
3. **理论错置。** 理论的分析单位、因果机制或经验边界无法合法映射到算法状态，候选核心结构只能由研究者任意发明。
4. **工件退化。** 删除规则、提示词、固定 gate、action mask 或辅助头后，不再剩下独立可训练的决策能力。

“通用 Transformer 原则上能表示这个函数”不属于设计期反证。专门表示、更新、损失或动作语法只要已被唯一规定且理论责任合法，就可以 design freeze，再交给等参实验判断是否有价值。

### 2.2 DESIGN-CLOSED 只问什么

DESIGN-CLOSED 只问当前文件能否让两个独立实现团队得到相同的：数据实例、行动时可见字段、张量、前向、损失、动作参数、训练目标、split、基线接口和评价公式；同时确认理论只承担原文可以承担的责任。它不要求候选已经优于 generic，不要求条件反转已经出现，也不要求显著性结果。

### 2.3 RESULTS/KILL 只问什么

冻结后才检验：候选是否越过 full-conjunction 和 generic，是否呈现预注册方向干预，是否减少真实 unsafe adoption 而保持 task resolution，成本是否可接受，增益是否跨仓库、时间和风险类型。结果失败可以撤销理论算法贡献或整篇论文，但“结果尚未运行”不能阻止一份已经唯一、合法、可实施的设计冻结。

## 3. C29c 当前主张与唯一可能存活的内核

### 3.1 风险、时点与外部行动

风险发生在多个 coding agents 已在隔离分支读写真实仓库、运行工具并产生 competing patches 之后，任何分支进入主线之前。潜在损害是错误多数、陈旧专家或表面可重放但不区分正确性的证据获得采纳权，进而造成隐藏回归、安全不变量破坏、依赖或状态损害，并污染后续 agent 工作。控制器能够追加区分性 probe、更新分支结果信念、fork/replay、synthesize、integrate、quarantine、discard、defer 或安全停止。它不能用拒绝全部分支获得表面安全。

这一对象在 coding agent 情境中成立的必要条件是，分支由实际 agent 的读、写、测试、命令和 Git 行动形成；receipt 绑定真实代码与工具状态；控制动作改变真实 repo branch 或集成状态；评价含隐藏功能、安全和状态损害。若换成几段静态答案后输入、动作和指标不变，coding-agent deletion test 失败。

### 3.2 三个硬结构本身不是可训练贡献

| `02N` 结构 | 本轮判断 | 可以承担的责任 | 不能承担的责任 |
|---|---|---|---|
| exact source/content hash 的 common-once | 确定性去重规则 | 数据完整性基线、exact duplicate 的零距离边界 | Qiu 理论算法、语义公共因子、精度或相关性学习 |
| receipt validity / witness gate | 密码学与运行时规则 | branch/probe/container 绑定、重放完整性、非法输入 fail closed | 证据是否区分分支、分支是否正确、Dennis demonstrability 的可训练机制 |
| phase mask | 静态合法动作约束 | 防止引用不存在分支、修改 immutable receipt 等执行非法动作 | Dennis 推出的固定五阶段理论语法，或独立学习能力 |

这三项必须作为所有模型共享的安全基础设施，或分别放入“rule-only scaffold”基线。若候选的优势只来自把这些规则给主模型而不给 generic，比较不公平；若所有学习只剩一个普通 scorer，设计期直接 NO-GO。

### 3.3 唯一可保留的可训练能力

唯一仍有独立论文可能性的对象是：**在来源相关且分支结果未知的条件下，联合学习 source-factor belief、成本约束的 active discriminating-probe policy、branch-outcome world model 和多动作 repo controller。** 它必须同时做到：

1. 从审计来源谱系而非 agent 数量形成公共、半公共与分支专属因子，并估计精度与相关性；
2. 预测某个公开可生成 probe 在各 competing branches 上的结果分布、区分价值、风险发现价值和成本；
3. 将新 receipt 通过显式 utilization update 改变 branch belief，而不是让 reveal 文本直接开 integration logit；
4. 在多步预算内选择 probe、replay、fork、synthesize、integrate、quarantine、discard、defer 和 stop 等真实行动；
5. 以隐藏任务/损害结果只作训练 reward 和评价，不在测试时泄漏。

这套内核并未被证明必胜，也未被证明 generic 不能学习。它的 source-factor representation、利用更新、probe-value world model 和参数化多动作控制如果字段闭合，属于合法的 specialized representation/function/loss/action grammar，可以进入结果检验。

## 4. 理论授权审计

### 4.1 Qiu 2017 授权什么

Qiu et al. 的基准模型有一个带精度的共同先验，参与者接收带噪私有信号；有效汇总对共同先验只使用一次，同时依据公共与私有信息的相对精度加权。论文进一步研究社会互动、公共信息精度、同质连接和误差相关性，得到的是条件性的权重偏离与结果差异。由此可合法迁移三项设计约束。

1. 同一共同原因不能因为被多个 agent 转述而被当成相互独立的多份证据。
2. 公共与私有不是常数标签；精度和相关性决定有效聚合。
3. 社会传播会形成半公共、相关或谱系相连的信息，独立误差只是基准条件而非所有现实数据的事实。

### 4.2 Qiu 没有授权什么

Qiu 没有把公共信息定义为 `source_id + content_hash`，也没有证明所有重复文本应投影到一个定长 `z_pub`。一条公共任务描述的语义后代、由不同执行独立确认的同一结论、从公共文件衍生但包含 branch-local 运行结果的 claim，都不能仅按哈希判断。论文也没有推出

`r_i = Enc(C_i,P_i) − Proj_pub(Enc(C_i,P_i))`。

这个 residual 是研究者选择的几何分解，不是 Qiu 的贝叶斯信号结构。它可能把独立确认错误删掉，也可能保留由同一公共原因生成的语义复述。把 Proposition 2 概括为“聚合会重复计数公共信号”同样过强；命题涉及信息精度、市场机制和条件方向，不是普适去重定理。

### 4.3 Qiu 合法进入算法的最低形式

设计必须把 exact hash 去重降为基础情形，新增可训练 source-factor graph：

- `S` 个 source/common-cause nodes，含任务包、repo snapshot、广播、工具输出、衍生分析和独立执行；
- claim-to-source incidence `A_src ∈ {0,1}^{B×N×L×S}`；
- source lineage/semipublic edges 与估计的 precision、covariance；
- 对 exact duplicates 保持不变的因子边界，同时允许独立确认增加精度、语义后代共享相关误差；
- branch posterior 或 outcome belief 由因子消息和 receipt 更新，而不是按 agent 数加权。

Qiu 的理论责任只能是“公共原因、私有信号、精度与相关性必须显式保留”。source extractor、precision estimator、covariance learner、消息传递和 probe policy 都是本文技术设计，必须独立报告和消融。

### 4.4 Dennis 1996/1997 授权什么

Dennis 1996 的核心边界是，被交换或可访问的信息不必被团队实际用于决策。Dennis et al. 1997 又显示媒介效果依赖初始意见结构：在其人类 GSS 实验中，存在 majority/minority 时，更多交换与更好决策同向；uniform 条件下，更多交换伴随更差决策和更高时间成本。这两篇全文可以合法支持：

1. `exchange state` 与 `utilization/update state` 不能合并；
2. 更多通信或更多轮次没有单调收益；
3. support topology 可以作为条件异质性假设，但方向必须在 coding 数据中重新检验。

### 4.5 Dennis 没有授权什么

`02N` 对 Dennis 的外推超过原文。

- 1997 文中关于缺乏 demonstrability 的信息较难被接受，是作者借助既有群体决策文献的论述，不是该实验直接操纵和识别的 treatment。
- 结论关于把 information exchange 与 decision 分开并留出间隔，是人类 GSS 的实践建议，不是 `sealed→acquire→demonstrate→process→integrate` 的形式定理。
- 原文没有 active code probe、immutable receipt、branch preemption、quarantine，也没有五阶段 action grammar。
- cognitive load、face-saving、credibility feeling、normative pressure 和社会从众不能移入 LLM latent state 或成为隐藏标签。

因此，Dennis 可以要求计算图显式区分“新信息到达”和“该信息改变了 branch belief/后续动作”，却不能为固定 witness gate 或每个任务都必须经过 `S→A→D→P→I` 背书。sealed branch、独立执行、probe 和 immutable receipt 是 coding-specific technical design，必须用技术必要性与结果检验负责。

### 4.6 理论责任重写

| 责任 | 合法来源 | 应进入的计算 | 不得写成 |
|---|---|---|---|
| common cause 不按转述数重复 | Qiu | source-factor incidence、precision/covariance、posterior update、duplicate invariance | exact hash 去重就是理论贡献 |
| public/private/semipublic 的相对信息价值 | Qiu | learned factor reliability 与相关误差、branch belief | common/private 二值 mask 就足够 |
| exchange 不等于 use | Dennis | 独立 `E_exchange` buffer 与 `U_update=f(b,E,W)`，policy 读取更新后的 belief | 人类“思考”成为 agent 潜变量 |
| 通信效果依情境变化 | Dennis | topology-conditioned hypothesis/loss，方向由 coding 实验验证 | human GSS 方向自动等于 code branch 方向 |
| executable witness 的完整性和区分价值 | coding execution literature与本文设计 | supervisor receipt verifier + learned probe value/outcome model | Dennis demonstrability 的直接算法推论 |
| 多动作 repo control | 本文技术设计 | model-based constrained controller | 理论原文已经规定五阶段顺序 |

| `Σ_src ∈ R^{B×S×S}` | 可见谱系条件下的相关误差估计及不确定性；不得用测试正确性直接构造 |
| `X_branch ∈ R^{B×N×d_b}` | patch graph、diff/AST/dependency/scope、agent action trace、公开测试和成本 |
| `X_probe ∈ R^{B×M×d_m}` | 冻结 probe catalog 的类型、目标、预计副作用范围、静态成本、生成来源 |
| `Y_receipt ∈ R^{B×N×M×d_r}` | 执行后结果；exit、trace/state delta、stdout/stderr digest、读写集、完整性与重放状态 |
| `T_vis ∈ R^{B×N×N×d_t}` | 行动时可见的支持/差异拓扑，不含 correct、wrong、low-value 或未来 outcome |
| `Q_phase ∈ {0,1}^{B×N×K_q}` | branch lifecycle 和已完成的更新类型；执行合法性与理论 utilization 状态分列 |
| `H_act ∈ R^{B×T×d_h}` | 历史动作、参数、预算、receipt references 与 repo state transitions |

`N`、`L`、`S`、`M` 的截断、padding、mask、缺失值和 graph batching 规则必须写入配置。当前 `02N` 的 `C,O,P,W,R,T,Q,H` 仍不足以让两个团队获得同一 source factor、probe candidate 和 transition state。

### 5.2 四个可训练组件的 I/O

#### Source-factor belief model

输入 `X_src,A_src,E_src,Σ_src,X_branch`。输出 source precision/correlation posterior、每条 branch 的任务成功和损害 belief，以及 epistemic uncertainty。训练使用训练 split 的 terminal outcome、source-lineage counterfactual、独立确认与重复公共信息干预。exact duplicate 只提供不变性样本，不提供 correctness 标签。

#### Probe policy

输入当前 branch beliefs、`X_probe`、尚未执行的 branch–probe pairs、预算和 action history。输出参数化 probe 选择分布及 predicted value：结果区分度、预期风险减少、预计 task information、失败概率与成本。它必须从真实执行 receipt 学习，不得以 gold patch 或隐藏测试生成 probe。若输出仅是“要不要测少数分支”，它退化为 minority router。

#### Outcome world model 与 utilization update

world model 预测 `p(outcome, repo_delta, harm_proxy, cost | state, action)`；对 `RUN_PROBE(m,i)` 预测 receipt outcome，对 integrate/synthesize/quarantine 等动作预测下一 branch/repo state。`U_update` 接收旧 belief、exchange buffer 和新 receipt，输出后验 belief 及不确定性变化。raw reveal 不能直接进入最终 adoption logit；必须先经可消融的 update operator。`PROCESS_UPDATE` 若只是一个无计算的动作 token，应删除；若保留，必须给出前向公式、监督和可观察 state delta。

#### Budgeted multi-action controller

输入 belief state、probe/world-model distribution、可见 topology、phase、预算和历史，输出 `(action_type, target_branch, probe_id, scope, continuation_budget)`。至少使用有限时域 model-based planning 或 offline constrained policy learning；动作不应被压成 `minority/majority` 二选一。需要冻结 horizon、discount、terminal semantics、uncertainty propagation、constraint multipliers 和多条等价最优轨迹的处理。

### 5.3 损失责任

总损失不能继续只列名称。冻结规格至少应明确：

`L = λ_src L_src + λ_out L_outcome + λ_probe L_probeNLL + λ_rank L_probeValue + λ_bc L_multiaction + λ_c L_constraint + λ_dup L_dupInv + λ_pair L_pair + λ_cal L_cal`

- `L_src` 监督可审计 source lineage、precision proxy 与相关性，不用测试真值伪造 public/private；
- `L_outcome` 对 task success、明确安全损害和 state delta 给出分布损失及 censoring 规则；
- `L_probeNLL` 预测真实 receipt，`L_probeValue` 在同 episode probes 间学习风险减少/区分价值排序；
- `L_multiaction` 允许多个等价最优动作，必须写明 set-valued target 或 soft value target；
- `L_constraint` 由 unsafe adoption、task failure 和成本约束形成，阈值与 dual update 预注册；
- `L_dupInv` 只对相同 common-cause 的复制干预保持 posterior/policy 不变；
- `L_pair` 使用 hidden outcome 只在训练目标中形成 majority/uniform/corrupt 条件对，不把 regime ID 输入模型；
- `L_cal` 分别校准 branch harm、probe value 和 action risk。

当前 `L_minority/L_uniform/L_corrupt` 只给方向叙述，尚未定义样本对、margin、权重、冲突梯度处理和多最优动作；不能据此冻结。

### 5.4 动作语法与公平 legality

动作必须分三层。

1. `M_legal` 是所有方法共享的物理/安全 legality，例如 branch 存在、receipt immutable、probe scope 合法、隐藏 evaluator 不可读。
2. rule-only scaffold 另外使用 exact dedup、invalid receipt fail-closed 和固定 phase mask，检验规则本身能做多少。
3. C29 的新增能力是 learned source posterior、probe value、utilization update 和多动作 controller。若保留特殊 phase grammar，应同时实现 `generic + same grammar`，避免把 mask 当算法优势。

这一区分解决 `02N` 的公平性矛盾。`02N` 一面把 common-once、witness gate、phase transition 称作候选 hard structure，一面又把同 action mask 给 generic。若全部共享，它们不能算候选贡献；若不给 generic，安全 legality 不公平。唯一稳健做法是共享完整性和物理规则，把可训练增量单独比较。

## 6. 数据构造、可识别性与隐藏真值隔离

### 6.1 `T_vis` 与 `Z_eval` 必须拆开

`majority-wrong`、`minority-correct`、`uniform-low-value` 和 `corrupt` 含有结果判断，不能整体写入行动时 topology。冻结时应有：

- `T_vis`：由 sealed patches、claims、code/diff equivalence、公开执行结果和来源谱系形成的可见支持结构；
- `Z_eval`：由隔离 hidden evaluator 定义的评估 strata，例如 majority-wrong/minority-safe、uniform-low-marginal-value、valid-but-misleading witness、integrity-invalid receipt；
- controller 只接收 `T_vis`，训练 sampler、terminal reward 和分层报告可以使用 `Z_eval`。

`T_vis` 的 cluster/equivalence 算法、阈值、冻结模型和训练语料必须预先规定，不能读 correctness。模型可以看出“三条分支相似、一条不同”，但不能在行动时知道哪边正确，也不能知道继续 probe 的未来价值低。

### 6.2 Majority/minority episodes

训练期可用 hidden oracle 从自然 branch pool 中筛选 majority-wrong/minority-correct episodes，这不自动构成泄漏。不过，必须满足：

1. 同一 base commit 的全部 siblings 和三种衍生 strata 留在同一 split；
2. branch ID、生成顺序、文件路径、缓存、日志命名和 agent/model family 随机化或匹配；
3. 对训练、验证和测试分别生成 branch pool，先 split 后 rollout；
4. 报告自然 branch pool 的总体分布，不能只报告经 hidden outcome 选择的容易反转子集；
5. 用 metadata-only leakage classifier、branch-order permutation 和 agent-family holdout 检查捷径。

### 6.3 Uniform-low-value episodes

“low value”依赖未来 probe outcome 或 terminal utility，行动时不可见。它只能是 `Z_eval`，不能是 `T_vis` label。为避免选择未来结果造成伪机制，应同时构造：

- 预先按可见 support shape 匹配的 natural uniform episodes；
- 在同一 episode 上随机添加重复或非区分消息的 counterfactual sibling；
- 由 hidden outcomes 事后计算的 marginal probe value strata；
- 全分布结果和 strata 结果并报，防止仅在筛选子集上宣称“uniform 应停止”。

Dennis 的 uniform 结果只能提出方向假设。coding-agent 数据中没有出现相同方向，不是理论非法，而是未来结果门失败。

### 6.4 Corrupt/stale episodes不能由格式规则轻易解完

无签名、错误 branch SHA、错误 container digest 或无法重放的 receipt 应由共享 verifier 确定性拒绝。这类样本适合测试完整性，但不能支撑学习贡献。主要训练难例应包括：

- receipt 完整、可重放，但 probe 同时被正确和错误分支满足，区分价值低；
- BRT 在 buggy branch 失败、在生成 patch 通过，却不能在独立 oracle 或额外规范上区分语义正确性；
- receipt 绑定合法的旧 base，且版本关系可见，需要 controller 选择 replay/rebase probe，而不是把 stale flag 直接当答案；
- 多个独立 probes 部分冲突，需要 world model 估计 branch outcome 与追加 probe 价值；
- agent claim 与 supervisor execution 一致，但该 execution 没覆盖安全不变量。

Dynamic Cogeneration of BRT 已明确区分 candidate BRT 与借助 oracle fix 判断的 plausible BRT，并指出 deployment 时后者不可见。这正好表明“测试在自己生成的 fix 上通过”不能成为独立 witness。

### 6.5 Witness 的独立性和 chain of custody

valid receipt 只证明完整性和可重放，不证明 correctness。每条 receipt 至少绑定：

`task_id, base_sha, branch_sha, probe_ast/hash, probe_generator_version, container_digest, dependency_snapshot, test_data_snapshot, execution_seed, start/end_time, exit_state, read_set, write_set, stdout_digest, stderr_digest, trace/state_delta_digest, supervisor_signature`。

执行必须由 branch agent 之外的 immutable supervisor 完成。决定性 probe catalog 应由独立生成器、公开测试/规范、metamorphic relation、静态 invariant 或预冻结检索器产生。patch agent 自写测试可以作为候选 probe，但不能同时自证 probe 语义和 patch 正确；至少需要独立 generator/reviewer 或第二类 evidence。hidden tests、gold patch、developer solution、future commit 只能用于训练 terminal reward 或最终评价，不能进入 probe text、retrieval index、cache、filename、排序或 judge prompt。

### 6.6 Split 和 manifest

冻结顺序必须是：repository family/time split → base/near-duplicate grouping → agent rollout → branch pool → paired episode construction。所有 fork、backport、同 issue、同 base、近重复 patch、同 probe template 的衍生样本不得跨 split。至少发布：task manifest、branch manifest、source-factor manifest、probe manifest、receipt manifest、episode sibling map、hidden evaluator version、agent/model/prompt version、container digest、seed、excluded-run log 和污染检查。

## 8. Full-conjunction 与等参 generic 的可运行性

### 8.1 `02N` 的 full-conjunction 目前只是责任清单

`InfoDelphi + AgentAuditor/ACPO + TraceRepair + C2C + Shepherd + Claim Plane` 来自不同任务、数据结构、代码状态、动作和许可条件。把名称用加号连接不等于可运行基线。当前缺少：统一 observation ABI、每个模块的输入适配、动作冲突仲裁、probe catalog、receipt schema、budget accounting、unsupported primitive 处理和公开代码/权重版本。因此，当前 DESIGN NOT FROZEN 的一个独立理由是“决定性基线没有唯一实现”，不是“尚未跑出结果”。

### 8.2 必须冻结的 baseline ABI

所有方法应运行在同一 `EpisodeState`：base/branch SHA、raw source log、patch graph、公开 probe catalog、receipt history、budget、visible topology 和 repo state。统一动作 ABI 至少包括：

`REVEAL, RUN_PROBE, REPLAY, FORK, SYNTHESIZE, INTEGRATE, QUARANTINE, DISCARD, DEFER, STOP`。

每个动作必须定义 target、参数域、执行副作用、失败返回、费用和 terminal semantics。full-conjunction adapter 应逐项保存原方法责任：InfoDelphi 提供 evidence partition/routing，AgentAuditor 提供 divergence audit/branch scoring，TraceRepair 提供 trace/probe strategy，C2C 提供通信调度，Shepherd 提供 branch actions，Claim Plane 提供 admission/integrity。一个等参 generic sequential controller 在这些模块输出上选择统一动作；模块不支持的动作必须记录 `unsupported`，不能由研究者默默替换为 C29 模块。

PhoenixRepair 的 test-quality/regression selector、Dynamic Cogeneration 的 ranked test-aware selector、CT-Repair 的多视角策略、ECLoop 的 evidence-condition compiler/gate、RETRACE 的独立 reconstruction/reconciliation、Claim Plane static/dynamic/always-serial 三臂和 fixed/random probe policy 应加入直接强基线。许可证、commit、checkpoint、backbone、token、container、probe、serialization rate 和 wall-clock budget 必须冻结。Claim Plane confirmatory 的主文结果要求单列 effective serialization 与 undeclared-scope block；低 coder cost 若来自 fail-closed early stop，不能解释为效率收益。

### 8.3 通用基线的公平层级

至少需要四层。

1. **Rule scaffold**：exact dedup、receipt integrity、固定 phase legality，没有学习型 source/probe/world model。
2. **Raw generic**：得到所有行动时 raw fields、全部训练 labels、相同 `M_legal`、参数和预算，用 Transformer/HGT/通用 model-based controller 学习。
3. **Generic + same grammar**：再给与 C29 相同的非物理 phase grammar，检验收益是否只是 mask。
4. **Full-conjunction generic**：使用上述模块 adapter 和统一 controller。

C29 可以独占 source-factor computation、utilization update 和理论配对损失，但不能独占 raw source/probe/receipt fields、terminal labels、hidden reward、合法动作或超参预算。generic 原则上可学习相同函数不构成 NO-GO；若未来经验上复制主要前沿，则撤销专门理论算法贡献。

## 9. Coding-agent 不可删除性与系列边界

### 9.1 删除测试

C29 通过 coding-agent deletion test 需要同时满足：

- branches 来自能够读取仓库、修改文件、执行测试/命令和管理 Git 状态的 coding agents；
- probe outcome 与 receipt 绑定 branch/base/container 和真实 code state；
- controller 的 fork/replay/synthesize/integrate/quarantine 等动作改变 executable repository state；
- harms 至少含 hidden functional regression、安全 invariant 破坏、依赖/配置或持久状态损害；
- 静态文本答案替换 branches 后，输入图、probe、动作和安全结果不再成立。

该机制可迁移到其他 executable-artifact agents 不会自动撤题。研究对象不必在数学上只适用于代码，但 coding agent 必须是关键行动者。若评价只剩 debate accuracy 或静态 patch ranking，撤题。

### 9.2 与 C2/TMS 和 C28

C29 固定 agent 身份、角色与 branch generation budget，不学习 competence、credibility、谁知道什么、whom-to-ask、route、allocate 或 handoff。否则回到 C2。它也不能把一个 `knowledge application A` 头门控 integrate 作为贡献；C28 已证明这会约化为旧 TMS application 子 SMDP。C29 的区别必须是主动获取 branch-discriminating execution evidence 并控制 competing repo branches，而非一般“专家知识被应用”。

### 9.3 与 C14 verifier selection

如果工件只选择下一测试或 verifier，然后交给固定 selector，核心会返回 C14。C29 必须联合维护 branch/source belief、预测 probe/branch outcome，并在同一 policy 中执行多种 repo actions；probe 只是行动之一。消融掉 integration/quarantine/fork/synthesize 等 branch actions 后若性能和研究问题不变，应撤题或降格为 C14 数据资产。

### 9.4 与迁移研究和 C3

迁移研究处理 cutover 前对未来运行状态和 staged option 的选择；C29 处理当前多个 agent branches 在 pre-integration 时的分散证据和采纳权。C29 不创建未来迁移 option。C3 固定在 human approval point，研究 reviewer factual grounding；C29 不预测人类、选择人类或决定展示。三者可共享“不完全知识下可靠改变软件状态”的上位主线，但 checkpoint、输入、动作、真值和实验必须独立。

## 10. 安全—任务—成本结果

### 10.1 主要联合决策目标

安全主终点应是 `Unsafe Adoption Rate`，即最终 integrate/synthesize 的分支触发预定义 hidden regression、安全 invariant 或状态损害的比例。必须同时报告：

- `Safe Recovery@Existing`：branch pool 至少有一个安全正确候选时最终安全解决；
- `Task Resolution`：官方 hidden evaluator 通过；
- `False Quarantine`：安全正确分支被隔离或丢弃；
- `Corrupt/Misleading Adoption`：完整性非法或完整但无区分价值的专家证据获得采纳权；
- `Probe Efficiency`：避免一次 unsafe adoption 所需 probes、container-seconds、tokens；
- message、GPU/CPU、wall-clock 和 branch storage；
- 条件化与总体 Pareto frontier/hypervolume。

预注册决策可写为：在 `Task Resolution ≥ baseline − δ_task`、`False Quarantine ≤ δ_fq` 和固定预算下最小化 unsafe adoption 与成本。`δ_task`、`δ_fq` 和等价区间在 test 前由领域重要性或 pilot variance 冻结，不能看 test 结果调整。

### 10.2 防止“拒绝全部即安全”

每个任务必须报告 branch pool 是否已有正确安全候选。主要安全比较在 `correct-safe candidate exists` 条件下进行，并设置 task-resolution floor、false-quarantine ceiling 和 fixed action budget。`STOP_SAFE/DEFER/QUARANTINE` 的使用率单独报告。候选若仅通过更多拒绝、更多总串行或更少任务获得较低风险，不能主张改善可靠行动。

### 10.3 真正的安全结果

普通 hidden tests 只证明功能正确性，不自动等于广义安全。至少一个任务家族必须有明确损害 oracle，例如权限/秘密泄露 invariant、持久数据状态、依赖供应链约束、配置/部署回归、并发一致性或关键安全属性。攻击性样本只在公开、授权、隔离环境运行；非攻击性回归按实际损害模型评价。

## 13. 两阶段 smoke pilot

### 13.1 冻结前 implementation smoke：只检验可实施唯一性

建议使用 24 个 task families：12 个 Python repository issues，12 个 Java Defects4J/Recent-Java bugs；至少来自两个互不重叠的 repo families。每个 task 生成至少四个 sealed agent branches，并构造 majority/minority、uniform 和 corrupt/misleading 三类 siblings，三 seeds，共 `24×3×3=216` 个 episode units。这个规模不是性能结论样本量，只用于验证 schema 和控制器可运行。

implementation smoke 必须检查：

1. manifest/schema validator 对 task、branch、source、probe、receipt 和 sibling map 全部通过；
2. receipt 在相同 container/seed 下可重放，并清楚区分完整性、稳定性与 correctness；
3. controller 看不到 `Z_eval`、gold patch、hidden assertion、future commit 或其路径/顺序代理；
4. metadata-only classifier 在预注册等价/随机基线范围内，branch ID permutation 不改变输出分布；
5. full-conjunction adapter 与 generic 可在同一 ABI 完成 episode，不出现候选专属隐藏字段；
6. source factor、probe outcome、utilization update 和 action transition 的单元测试覆盖；
7. 至少存在多个非终止 action 的合法轨迹，policy 接口不是二元 minority router；
8. 两名独立实现者依据规格对同一 episode 得到相同 tensor/label/action legality。

这些检查属于 DESIGN-CLOSED 证据。若 adapter 不可实现、witness 无法独立、低价值只能靠未来结果输入、模型无法定义成多动作，设计期终止；这不是性能结果失败。

### 13.2 冻结后 result smoke：决定是否扩大实验

冻结 checkpoint 和预算后，在相同 216 units 上运行：rule scaffold、random/fixed probe、PhoenixRepair/test-aware selector、ECLoop、RETRACE、Claim Plane static/dynamic/always-serial、full-conjunction generic、raw generic、generic+same grammar 和 C29。结果只作扩大/撤题决定，不回改 test 数据或设计。对 ECLoop 报告 condition grounding/hold/fallback，对 RETRACE 报告 reconstruction verdict/revision，对 Claim Plane 报告 effective serialization、undeclared-scope block 和 physical/logical time，不能只比较 Pass@1。

## 14. 撤题条件

### 14.1 设计期撤题

出现任一项即 NO-GO，不等未来性能。

1. Qiu 最终只落实为 exact hash 去重或 common/private 二值 mask，没有 precision/covariance/source factor；
2. Dennis 最终只落实为固定 `S→A→D→P→I`、静态 witness gate 或 human cognition latent，无法形成合法 utilization operator；
3. hidden correctness、gold patch、未来 commit 或 low-value outcome 进入行动时状态、probe generator、cache 或顺序；
4. witness validity/semantic value由同一 branch agent 自报，无法独立执行与绑定；
5. probe policy、world model、update 和 controller 无法给出唯一 I/O、损失和动作；
6. full-conjunction 无法在共同 ABI 实现，却仍被用作名义强基线；
7. 训练后唯一新增 checkpoint 是普通 score head，行动由规则 gate/mask 完成；
8. 公平 generic 与主模型可逐层共享全部 encoder、update、loss、actor 和 grammar，只改变理论变量名；
9. 静态文本候选替换 coding branches 后研究对象、动作和主要结果不变；
10. 核心退化为 verifier/probe selection、TMS routing/application 或 human approval。

### 14.2 未来结果撤题

下列条件只在设计冻结并运行后判断。

1. full-conjunction 或等参 generic 在预注册等价区间内复制/超过主要安全—任务—成本前沿；
2. source factor、utilization update 或 active probe 的中和不改变行为和结果，增益完全来自规则 scaffold；
3. majority/minority、uniform 和 valid-but-misleading/corrupt 条件没有预注册的相反 action shifts，或方向只在筛选子集存在；
4. active probe 相对 fixed/random/TraceRepair/PhoenixRepair test selection 没有提高风险发现或 probe efficiency；
5. 风险下降完全由更多 quarantine/defer/serialization 获得，task floor 或 false-quarantine ceiling失败；
6. 增益只在同 agent 自写测试上出现，独立 probe 或 artifact-neutralization 后消失；
7. metadata/agent identity/order 捷径解释主要效果，跨 repo/time/agent-family OOD 消失；
8. 只改善普通 patch accuracy，不改善预定义安全或状态损害。

结果门失败不证明研究设计从未冻结；它证明经验或理论算法主张不成立。应撤销论文贡献，而不是事后更换 strata、margin 或 baseline。

## 15. 为什么本轮不是 NO-GO，也为什么仍不能冻结

### 15.1 尚无可约化/完整覆盖证明

C28 的 NO-GO 有两条设计期证明：固定旧状态后成为旧 TMS application 子 SMDP，且 equal-label generic 可逐行共享 forward；动作又由 Shepherd/Claim Plane 同层原语还原。C29 当前没有同样证明。一个合法重写后的 C29 含 source common-cause factor graph、precision/covariance posterior、active probe outcome/value model、显式 exchange→utilization update 和带安全约束的参数化多动作 controller。现有单篇工作未同时规定这些状态、损失和行动；`02N` 的 full-conjunction 也尚未成为已经实现的同构系统。generic 可以表达不等于当前已有逐层或逐梯度同构。

### 15.2 当前仍未达到可冻结唯一性

当前文本的核心差异仍混在三条规则中，理论外推过强，行动时和 hidden state 未分开，world model/controller 只有名称，full-conjunction 没有 ABI。这些问题即使完全不看性能也会让两组实现得到不同算法和数据，故 DESIGN NOT FROZEN。

### 15.3 可撤销的最终裁定

本轮保留 C29c 仅代表“存在一个尚未被设计期等价杀死的窄研究对象”。它不占用已冻结论文题位，不授权正文宣称新增能力，不授权把 Qiu/Dennis 写成五阶段门控理论，也不授权任何结果性语言。完成第 12 节后可重新审查并在无结果时 design freeze；任何设计期撤题条件成立则终局 NO-GO；设计冻结后的性能与机制失败则按第 14.2 节撤题。

**最终状态：CONDITIONAL / DESIGN NOT FROZEN / RESULTS NOT RUN。**
