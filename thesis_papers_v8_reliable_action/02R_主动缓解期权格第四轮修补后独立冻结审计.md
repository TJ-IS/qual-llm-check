## 4. 唯一未关闭门：duration-cell hazard 条件积分

### 4.1 已经写清楚的部分

三稿已经共同要求：

1. `L_globalN` 使用同一 observable joint cell 的未加权 proper NLL，每个 schema-valid record 权重为 1。
2. duration、result、severity 与 accumulator 的 cell mass 由 `kernel_measure_v1` 的同一 CDF 测度给出。
3. `P_phys(e|C_d)` 是给定 `B_ξ` 和 observed duration cell 后的离散 event 条件质量。
4. `M` 已含 duration cell mass，`P_phys` 不得再乘一次该 mass。
5. hazard 必须在 duration cell 内积分，不得在 representative、location 或 median 上点值化。
6. passage 与允许的 direct hazard 先形成 physical primitives，再经 complementary link 与 post-link projection 得到最终 event mask。

这些约束排除了旧版的点值替代和 duration mass 双计，但还没有定义唯一的被积函数与积分实现。

### 4.2 缺失字段

`01H` 只把 `Λ_pass/Λ_dir` 声明为 10 个 absolute-time bins，并写出

\[
P(e_r=0\mid d)=\prod_j(1-\Lambda_{rj})^{\omega_j(d)}.
\]

三份锁定稿均未冻结下列字段：

- 10 个 absolute-time bin 的精确边界及端点归属。
- `Λ_{rj}` 是每秒 hazard、整 60 秒 bin 的 event probability，还是其他 reference exposure 下的概率。
- `ω_j(t,d)` 是重叠秒数、重叠占整 bin 的比例，还是只要相交即为 1。
- passage 与允许 direct hazard 在给定 exact duration 时怎样合成，四个 event bits 的 joint mask 是先合成再共同积分，还是分别积分后相乘。
- `B_ξ∩C_d` 上的条件 CDF 分母、零质量分支规则及积分变量。
- 固定解析式或固定数值算法、分段点、节点数、求和顺序和误差阈值。

`time_bins=10` 与 600 秒 decision horizon 不能自行推出这些字段。尤其是 `ω` 的单位不由“absolute-time bin”或“complementary-log-log”唯一决定。

### 4.3 最小反例

取 action start `t=59.950000s`，observed duration codec cell

\[
C_d=[0.0995,0.1005)\text{ seconds}.
\]

令 duration head 在 `[0,120]` 上取 `raw_location=0, raw_log_scale=0`。此时 `F_D(d)=d/120`，在 `ξ=1` 和该 cell 内的条件 duration 为均匀分布。令与该 event 有关的前两个 hazard bins 为 `Λ_0=0.1, Λ_1=0.2`，其余为 0，且 direct hazard 为 0。

两个实现都可以：

- 对 cell 内所有 duration 做真实条件积分；
- 不使用 representative 点值；
- 不把 `M` 中的 duration cell mass再乘一次；
- 使用当前文本给出的 survival product。

唯一差异是 `ω` 的合理解释：

| 实现 | `ω_j` | cell 条件 event probability |
|---|---|---:|
| A | 与 bin 的重叠秒数 | `0.016291043184550658` |
| B | 与 60 秒 bin 的重叠秒数除以 60 秒 | `0.00027371590422042846` |

两者相差约 59.5 倍。即使选择实现 B 的单位，若在 cell 中点 `d=0.1` 取值，会得到 `0.00027371592210334583`，与正确条件均值相差约 `1.7883×10^-11`。该差异大于下述最小修补建议的 `5×10^-12` 积分审计阈值，能够同时识别单位分叉与点值化。

由于 `P_phys` 直接出现在 `L_z(T)` 中，这个反例会依次改变 joint NLL、posterior `b′`、chance node 权重、bound propagation，并可能改变唯一 tie-break 之前的 action value。它属于设计闭合问题，不是未来结果门。

### 4.4 字段级最小修补合同

下一版只需冻结下列最小合同，无须重写模型主线。以下给出一套与当前 10-bin、cloglog 与 600 秒 horizon 相容的具体合同；实施者不能在这些选项中自行选择。

1. **absolute-time bin。** 固定 `time_bin_edges_us=[0,60000000,120000000,…,600000000]`。`I_j=[edge_j,edge_{j+1})`，`j=0..9`；最后一个 bin 对 passage exposure 仍采用 half-open 规则，exact `600s` event 归 terminal 规则，不回写上一 passage interval。
2. **hazard 参数语义。** 对每个 raw cloglog 输出 `g_{rj}`，定义整 60 秒 reference bin 的 event probability `Λ_{rj}=1-exp[-exp(g_{rj})]`。所有 direct structural-zero cells先被 closure 精确置为 `Λ_dir=0`。
3. **重叠与单位。** 定义 `Δ_j(t,d)=max(0,min(t+d,edge_{j+1})-max(t,edge_j))`，单位为微秒；唯一 exponent 为无量纲 `ω_j(t,d)=Δ_j(t,d)/60000000`。
4. **exact-duration event law。** 本次最小合同把允许的 direct hazard 与 passage hazard都定义在同一真实暴露区间 `[t,t+d)` 上；“direct impulse”表示 action-specific hazard增量，不另引入未声明的瞬时时点。对每个 event bit `r`，先计算 `S_r(d)=∏_{j=0}^{9}(1-Λ^{pass}_{rj})^{ω_j(t,d)}(1-Λ^{dir}_{rj})^{ω_j(t,d)}` 与 `p_r(d)=1-S_r(d)`；禁止的 direct ancestor 已在本步前精确置零。给定 exact `z,h,ξ,d` 时，16 个四位 mask 的质量固定为 `p_e(d)=∏_{r=1}^{4}p_r(d)^{e_r}S_r(d)^{1-e_r}`，再执行已冻结的 `post_link_projection`。条件积分必须对这个 joint-mask 函数逐 mask 进行，不能先分别积分四个边际再相乘，也不得再为 direct 选择 action-start、action-end或独立 exposure convention。
5. **条件 CDF 公式。** 令 `U=F_D(D)`，`u_l=max(F_D(l),α_{ξ-1})`、`u_u=min(F_D(u),α_ξ)`。当 `u_u>u_l` 时，

   \[
   P_{phys}(e\mid C_d,B_ξ)=\frac{1}{u_u-u_l}\int_{u_l}^{u_u}p_e(F_D^{-1}(v);t,z,h,a)\,dv.
   \]

   当 `u_u≤u_l` 时，该 micro-branch 的 duration mass 为 0，分支不得建 child；不能用 0/0 默认值恢复分支。`M` 仍只乘一次 `p_{dξ}(C_d)=(u_u-u_l)/w_ξ`。
6. **固定积分器。** 把 `[u_l,u_u]` 在所有 `t+F_D^{-1}(v)=edge_j` 的内部交点处分段。每段使用 hash 锁定的 binary64 64-node Gauss–Legendre nodes/weights，按 segment start、node index升序求值，并用固定 pairwise tree 求和。64-node结果是唯一 forward 值；128-node同分段结果只作审计。若两者绝对差大于 `5×10^-12` 或 joint mask normalization 误差大于 `5×10^-12`，该 configuration 为 `KERNEL-SCHEMA-INVALID`，不得改用 representative 或临时 adaptive tolerance。
7. **跨 bin golden fixture。** 增加上述 `t=59.95`、`C_d=[.0995,.1005)`、`Λ=(.1,.2,0,…)` fixture。在采用第 1–6 项合同且 passage-only 时，期望 conditional event probability 为 `0.00027371590422042846`，center-point值必须被拒绝。另保存 16 个 event-mask probabilities 之和为 1、`M` 只含一次 duration mass、Bayes/observed/planner bytes一致的断言。

## 6. Benaroch 理论责任与直接近邻边界

### 6.1 Benaroch 构念使用合法

Benaroch（2018）原文实际支持：被动 wait-and-see 与主动 act-and-see；零项或多项 optional mitigations；措施在离散时点产生 impulse effect；措施成本与不确定性影响受既往顺序条件化；替代、互补与协同；learning、prevention、coping 三类作用；最终 exercise 或不 exercise。附录还实际展示同一措施在不同先前路径后可以有不同参数。

锁定稿没有把下列内容冒充 Benaroch 原有结论：数据库迁移 operators、`b/p/q_n/g/κ/ℓ/c`、neural tensor、global codec、hazard head、二阶低秩截断、causal closure、POMDP/SMDP 或经验优胜。main+ordered-pair 与二阶截断明确标为本文可否证的算法推论；generic等效时撤销独立理论算法贡献。optional mitigation、AB、defer 与 EX 的构念责任因此合法。

### 6.2 最新近邻没有删除该研究对象，但收窄了可主张空白

- DBA-Bench 已直接覆盖 live writable PostgreSQL、active workload、persistent state、多源observability、开放 remediation、post-fix verifier 与逐行动 operational-safety trace。它还把 business change 明确包含 schema、data、index 与 migration。因此正文不能声称这些 evaluation elements尚不存在。它没有读取 application repository source、学习 repository-conditioned optional-mitigation kernel，也没有 exercise/abandon lattice。
- AgenticDB 已有 safe cross-layer action catalog、Planner、Validator、Executor、Recovery、Auditor与 execution feedback loop。它证明 pre-execution validation和post-failure recovery已被直接研究。其对象是 DBMS/OS performance reconfiguration，Validator主要为 deterministic local constraints；它不覆盖 application-repository live schema migration、CodeTwin source necessity或 Benaroch option lattice。
- SysInsight 已用 DBMS code tracing、LLM reasoning、association-rule verification与online diagnosis/tuning把 code-derived system knowledge变成可验证 action guidance。因此“代码可提供数据库行动知识”不是本研究空白。它没有建立 live application migration 的 external-harm option policy。
- Change2Task 已提供 repository-grounded API Migration coding-agent tasks、healthy→task→restored三态 lifecycle、target/regression checks与 agent reconstruction。它强化了可执行 migration task 构建近邻，但其输出是 repository patch及测试恢复，不是 active database上的optional mitigation、passive exposure、cutover/rollback与外部风险权衡。
- DBCooker 已进入 VLDB 2026 demonstration program，题名直接表明 database-kernel-specialized coding-agent harness。由于当前正式页面只有题名与作者，不能据此推断其任务、算法、数据或结果，须保持 `[待核验全文]`。
- DBAgent 已有正式题名、作者和 VLDB 2026 记录，作者页面称其为 RL-based tool-using closed-loop database O&M agent，DBA-Bench也把它列为相关工作；主文仍未取得，所以 state/action/reward、训练与安全协议继续是 `[待核验全文]`，不能用于扩大或消灭gap。

coding agent 在当前设计中仍不可删除。CodeTwin 让同一 non-code state、candidate、mask、trace与oracle只在公开 application policy source上变化；Full-Code 与严格 No-Source 的确认性 contrast检验 source semantics是否改变 action/outcome。若去掉 repository reader与 analyzer，研究问题和关键可否证机制会随之消失。该结论仅说明对象与识别设计成立，不预写 Full-Code 将获胜。
