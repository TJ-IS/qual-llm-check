## 0. 一句话终判

本轮修补已经闭合理论责任、行动时可见信息、hidden oracle 隔离、独立 witness、可训练 source belief/utilization/world/probe/controller、十一动作与六槽 next state、split-before-rollout、full-conjunction adapter、等信息通用替代和大部分复现协议，但仍有两个会使独立实现得到不同算法或不同主评价样本的设计硬门，以及一个肖老师逐句功能责任账硬门。第一，`SUPPORTS→μ_g`、`CONTRADICTS→−μ_g` 没有 claim/proposition 到十维 outcome 的适用性与方向观察矩阵，且 posterior precision 对无关维也整块增加。第二，Vul4J 原生 PoV/fixed-warning 与 secondary overlay 没有逐 entry×harm 的 eligibility/origin、NA、分母及 smoke 配额隔离。第三，`02S-B` 的 N-10 在 `source_function_code=MEC+MAP`、`candidate_function_code=ALG` 时仍标为“功能同位”，违反 `00F` 的主功能同位规则。因此本审计不能签发 `DESIGN-FROZEN / RESULTS PENDING`。

## 4. OPEN-A：claim 到十维 outcome 的观察语义没有闭合

### 4.1 当前公式为什么不是唯一实现

`02S §3.4` 固定十个 outcome，前四维越大越好，后六维越大风险越高。`§3.5` 随后规定：

\[
\tilde\mu_{ig}=\mu_g\quad\text{for SUPPORTS},\qquad
\tilde\mu_{ig}=-\mu_g\quad\text{for CONTRADICTS},
\]

并对每个 incident factor 把完整的 \(R_g^{-1}\) 加进 \(\Lambda_{i,t}\)。ontology 中 CLAIM 只有 `proposition_hash、claim_type、subject_ref、polarity`。全文没有定义 `claim_type/subject_ref/polarity` 怎样确定十维中的适用维、每个适用维的正负方向，以及同一 factor 内多个 claim 的冲突怎样合并。`§4.2` 的十维 `conflict` 只说“由 claim polarity 与十维 outcome order 形成”，没有给出 canonical mapping、truth table、缺失规则或 observation matrix；它只进入 κ 的输入，不能替代 posterior 的 observation operator。

因此两个都忠实读取当前文本的实现团队可以作出不同选择。一个团队可把“build passes”解释为只观察 `build_validity`；另一个团队会依现式把 factor 的十维 μ 全部加入。一个团队可把“no secret leak”解释为风险维负方向；另一个团队可因 SUPPORTS 使用 `+μ_g`。两者的 shape、loss 和 seed 都相同，belief 与动作却不同，故这是设计门，不是结果门。

### 4.2 整向量翻转的反例

设 factor 只支持命题“该 patch 可以 build”。它对第二维有信息，对 secret exposure、越权写、availability、dependency expansion 与 external side effect 没有陈述。当前 SUPPORTS 更新仍会：

1. 把 μ_g 的十个坐标全部送入 η；
2. 把完整 \(R_g^{-1}\) 送入 Λ，使九个无关维的 posterior 也更有把握；
3. 通过低秩 covariance 进一步改变跨 outcome 相关性。

若同一来源 CONTRADICTS “该 patch 可以 build”，当前 `−μ_g` 会同时翻转秘密暴露和外部副作用等无关坐标。更严重的是十维方向混合。支持“没有 secret leak”在第五维应推动更低风险，而支持“task resolved”在第一维应推动更高成功；统一 `SUPPORTS→+μ` 无法仅凭 edge type表达二者。`CONTRADICTS→−μ` 也不能解决 claim 本身可能是否定命题的问题。

### 4.3 必须补入的唯一最小结构

修补至少需要一个由 visible claim schema 确定、在 split 和 rollout 前版本化的 observation operator。可接受的最小形式是：

\[
H_{ig}=\operatorname{diag}(m_{ig}\odot s_{ig}),
\]

其中 \(m_{ig}\in\{0,1\}^{10}\) 是该 factor/branch claim 对十维 outcome 的 applicability mask，\(s_{ig}\in\{-1,0,+1\}^{10}\) 是在固定 outcome order 下的 canonical signed semantics。SUPPORTS/CONTRADICTS、claim 自身 polarity 与 good/risk outcome 方向都必须进入 \(s_{ig}\)，而不是对完整 μ 作最后一次全局符号翻转。若沿用线性高斯更新，posterior 至少应明确为：

\[
\Lambda_{i,t}=\Sigma_{i,0}^{-1}+
\sum_g\kappa_{ig,t}H_{ig}^{\top}R_g^{-1}H_{ig},
\]

\[
\eta_{i,t}=\Sigma_{i,0}^{-1}\mu_{i,0}+
\sum_g\kappa_{ig,t}H_{ig}^{\top}R_g^{-1}o_g.
\]

这里 \(o_g\) 的十维语义、多个 applicable claim 如何形成一个 \(H_{ig}\)、同一 factor 同时 SUPPORTS 与 CONTRADICTS 时的确定仲裁、全零 mask 的 NOOP、NA/MISSING 与 padding 必须一并固定。也可以采用等价的行选择 observation matrix，但不能只给 η 乘 mask而仍给 Λ 加完整 \(R_g^{-1}\)，否则无关维仍得到虚假 precision。

这个 mask/sign 不能从 hidden outcome、gold patch 或 evaluator label 在行动时生成。它必须来自公开 claim ontology、签名 compiler 版本和 T_vis 可复算字段；train-only outcome 只监督模型权重，不决定 test claim 的适用维。若机器 normalizer 无法唯一分类，必须有固定 AMBIGUOUS/NO_UPDATE 规则，不能由 controller 临场猜测。

### 4.4 OPEN-A 的最小验收 fixture

修补后的 validator 至少应加入：

1. `SUPPORTS(build_pass)` 只改变 build 的 η/Λ 子空间，其他九维保持不变；
2. `SUPPORTS(no_secret_leak)` 在第五维使用与“risk 越大越高”一致的方向；
3. `CONTRADICTS(build_pass)` 只反转 build 观察，不翻转 harm 坐标；
4. factor 含两个适用维或互相冲突 claim 时，两次独立实现产生相同 H、η、Λ；
5. 全零 applicability 返回签名 NOOP，不凭 factor 文字给十维加 precision；
6. claim order、branch id、public id permutation 不改变 H 与 posterior；
7. observation compiler 的输入不含 Z_eval，cache key 不含 hidden label 或其派生值；
8. 将 H 打乱或中和是独立机制干预，不能与 SHUFFLED_LINEAGE 混为一个消融。

上述测试通过后，M01、M02、M05 可以在没有模型效果数字时闭合。

## 5. OPEN-B：Vul4J natural oracle 与 overlay 没有形成两套可审计分析集

### 5.1 当前设计已经做对的部分

`02S §12.1` 与 `02S-A §8` 已正确把 task result 与 security result 分列。build、普通 regression 和 issue alignment 形成 `y_task`；官方 PoV 仍复现或 fixed SpotBugs warning 仍存在形成实际 vulnerability 保留。patch 即使功能通过，只要 security oracle 失败仍是 unsafe adoption。overlay 也明确写为同一容器内的 secondary stress，不取代主 security oracle。这些原则应保留。

### 5.2 为什么当前六类表仍不唯一

六类表把自然与外加 evaluator 写在同一单元。例如 confidentiality 是“Vul4J PoV 或 canary taint”，integrity 是“Vul4J PoV + kernel audit”，dependency 是“SpotBugs/lock/IAM audit”，external side effect 只有 side-effect ledger。`02S-A` 又要求每个 entry 依据 CVE/CWE/PoV effect 映射一个 harm class，并要求 smoke 中六类各四 task。

这里缺少三个决定性字段：

1. 某个官方 PoV/fixed-warning 是否自然识别第 k 类 harm；
2. 该标签来自 `NATURAL_OFFICIAL` 还是 `OVERLAY_STRESS`；
3. 对不适用或没有自然实例的类别，分母、mask 和统计 stratum 如何处理。

如果某类没有四个自然 Vul4J entry，当前文本允许一种实现用 overlay 填足 smoke 四例，另一种实现让 ILP 失败；若某次 adopted patch 没有该类 natural oracle，当前 `INTEGRATE/SYNTHESIZE 十维都必须评价` 又可能被实现为运行 overlay并把它并入主 `any harm`。两种结果都会污染 Vul4J 原生频率，且让主 UAR 的含义不同。`outcome censoring mask` 只能说明某个 evaluator 是否运行，不能说明它属于 natural 主结果还是 secondary stress。

### 5.3 必须冻结的 eligibility/origin manifest

修补必须在 split-before-rollout 之前生成并签名至少以下字段：

| 字段 | 唯一语义 |
|---|---|
| `canonical_vul4j_id` | 与 dataset.lock 的 immutable entry 对齐 |
| `harm_k` | 固定六维顺序 |
| `natural_eligible` | 官方 PoV/fixed-warning 是否直接判别该 harm；不能由 broad CWE 名称单独推断 |
| `natural_oracle_id` | PoV command/outcome 或 fixed-warning identity 与 hash |
| `overlay_eligible` | secondary fixture 是否适用于该 entry |
| `overlay_oracle_id` | canary/kernel/Merkle/lock/IAM/deployment-stub ledger 与 hash |
| `label_origin` | `NATURAL_OFFICIAL`、`OVERLAY_STRESS` 或 `NA` |
| `coding_evidence` | CVE/CWE、advisory 与实际 PoV effect 的双盲编码及仲裁 receipt |
| `mask_reason` | `NOT_APPLICABLE`、`NOT_RUN`、`INFRA_FAILURE`、`TIMEOUT` 分开 |

`natural_eligible` 必须依据官方 oracle 是否能区分 vulnerable/fixed outcome，而不是为了凑足六类按 broad narrative 分配。一个 entry 可以多维 eligible，也可以在某维 NA；若设计坚持每 entry 单类，必须说明从多效应到单类的确定优先序。任何 overlay 只能拥有 `OVERLAY_STRESS` origin，不能把 `natural_eligible` 从 0 改为 1。

### 5.4 主结果、secondary stress 与 NA 规则

至少应分别报告：

1. `UAR_natural`：只在 adopted 且至少一个 natural official harm oracle eligible、实际成功执行的 episode 上计算 `any natural harm`；
2. `UAR_natural,k`：分母只含 `natural_eligible[id,k]=1` 且 oracle 成功执行的 adopted episode；分母为 0 时写 `NA`，不写 0，不并入 pooled class estimate；
3. `UAR_overlay,k`：只作为 secondary paired stress，使用独立分母、CI 和清楚的 origin 标题；
4. `unsafe-decision_natural` 与 `unsafe-decision_overlay`：若并行报告全 episode composite，也不能混源；
5. Task Resolution、False Quarantine 和成本继续使用既有定义，不让 overlay 改写功能结果。

对 `NOT_RUN/INFRA_FAILURE/TIMEOUT` 继续 mask，不补成 safe。对 `NOT_APPLICABLE` 必须在运行前由 eligibility 表确定，不能与 evaluator failure 共用一个 0。若 overall safety endpoint 需要合并多个自然 harm，合并集合与至少一个有效 oracle的要求必须预注册。

### 5.5 smoke 与统计的唯一修补

当前“六 harm 各四 task”的 24-task ILP 只能在六类均有满足 group/split 条件的四个 `NATURAL_OFFICIAL` entry 时声称自然平衡。修补应二选一并在看结果前锁定：

1. 若 eligibility manifest 证明六类均可自然满足，ILP 只用 `natural_eligible=1` 的 entry，overlay 不参与配额；
2. 若任一类别自然不足，该类别记 `NATURAL_STRATUM_UNAVAILABLE`，不得由 overlay 填四例。24-task 主 smoke 应采用预先规定的 official-oracle sampling 规则；overlay 另建不计入自然频率的 evaluator coverage fixtures。报告不能继续声称“六类自然 harm 各四”。

统计脚本必须在模型拟合前输出每个 method×origin×harm 的 eligible、evaluated、adopted、unsafe 精确计数。空 natural cell 为 NA，不作零填充；是否进入 Holm family、interaction 或仅描述性报告必须固定。这样才能使 E01、E02、E04 与 R01 同时闭合。

## 6. T_vis/Z_eval、witness、训练模型与动作空间复核

除 OPEN-A/B 外，下列关键设计经反证后成立。

### 6.1 行动时信息与 hidden oracle

Sampler 使用 Z_eval 构造 majority-wrong、uniform-low-value 和 valid-but-misleading 并不自动泄漏，因为 `strip_Z_eval` 在 public id、branch order、JSON serialization、embedding 和 cache 之前执行。ActionView 只返回 public task/scope、sealed diff/trace/claim/source graph、public receipt、budget 和 legal mask。HiddenEvaluator 的 branch correctness、harm、stratum、future outcome、oracle action、gold patch 和 hidden tests 不进入 controller channel。train-only teacher 可用 terminal labels 形成 utilization supervision和 recorded-DAG oracle，但 test action只接收模型预测。

### 6.2 独立 witness 链

独立确认要求不同 probe family、不同 seed、独立 supervisor、canonical base+branch diff、不得读 branch 自写 BRT/receipt，并保留 container、argv、cwd、read/write、pre/post tree、cleanup 和 signature。相同 probe instance 的重复只估计 flakiness，不增加 factor count。该规则比“不同表述”严格，且由 custody validator 承担，不诉诸理论。

### 6.3 可训练工件

C29 不是 prompt、二分类器或简单 reranker。source HGT/head 产生 μ、D、U；κ operator 学习 evidence utilization；五成员 world ensemble 预测 action-conditioned six-slot next state、repo delta、exchange、outcome 与成本；probe ensemble预测执行结果和价值；constrained offline IQL 与 pessimistic MPC 选择动作。OPEN-A 要修的是 source observation semantics，不抹去这些可训练工件的独立存在。

### 6.4 真正多动作与 six-slot next state

十一动作具有不同参数和物理副作用。PROCESS_UPDATE 改 belief，REVEAL/REQUEST 改信息，RUN_PROBE 真实执行，REPLAY_FORK/RESTORE 改 branch state，QUARANTINE 改可采纳集合，INTEGRATE/SYNTHESIZE 改 repository，DEFER/STOP_SAFE 改终止或人类协作。world next-state 明确预测六个 branch status；生成新 branch 时替换固定槽而不改变 b=6。该空间不能退化为 minority/majority 二选一。

## 7. 基线公平性与新增能力边界

### 7.1 full-conjunction adapter

`02S §11` 已给 common ABI、六模块 proposal、UNSUPPORTED、确定仲裁和独立 generic action selector。它不再是论文名称拼接。官方 artifact 缺失时有 `BASELINE_UNAVAILABLE` 证据规则；存在官方训练代码时同 split 重训，只有推断 artifact 时冻结 checkpoint。这个 unavailable 规则不能用来跳过研究者自己定义的 full-conjunction adapter 外壳。

### 7.2 generic 的等信息、等标签、等参数与等 FLOPs

Raw generic、Generic+same grammar 和 matched direct baseline selector读取与 C29 相同的 raw ABI、训练 labels/reward、legality和执行环境，不见 C29 posterior或 Z_eval。P*、FFN matching、18-trial grid、optimizer step、GPU-hour、tool/probe/replay/synthesis/token、wall 和 search FLOPs 规则固定。参数表达力“原则上能表示”不是设计期同构证明；实际能否复制联合端点要由公平结果决定。

### 7.3 保留的未来结果门

即使 OPEN-A/B 修复并重新冻结，以下结论仍不能预写：

1. C29 必须在预注册联合端点上越过 Generic+same grammar 与 Full-conjunction；只胜 Rule scaffold 不足；
2. SHUFFLED_LINEAGE、FREEZE_STATE、NO_ACTIVE_PROBE 及新增 observation operator 中和应产生预注册的机制差异；
3. majority、uniform、corrupt 的作用方向可以与理论预期相反，反转不允许被事后改写为支持；
4. UAR 改善必须同时守住 Task Resolution、False Quarantine、成本、wall、serialization 和 parallel retention；
5. 任一强通用替代复制主要安全—任务—成本前沿时，独立理论算法贡献必须撤回。

这些都是 `RESULTS/KILL`，不是本轮 `DESIGN-CLOSED` 的替代条件。
