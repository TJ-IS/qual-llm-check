### 3.2 最小反例复跑

1. 对 `SUPPORTS(SECRET_EXPOSURE, NEGATED)`，唯一合法结果是第五维 `m=1,s=-1`。把它编码成正风险、另造 SAFE_SECRET 坐标或翻转十维都违反 schema 与 fixture 2。
2. 对 `CONTRADICTS(BUILD_VALID, AFFIRMED)`，唯一合法结果是第二维负方向。翻转 harm 坐标违反 `H` 和 fixture 3。
3. factor 只激活 BUILD_VALID 与 SECRET_EXPOSURE 时，只有 `{2,5}×{2,5}` precision 子块可非零。先求完整逆再清零会受 Schur complement 污染，违反 `B/P` 公式和 fixture 4。
4. 同一命题同时 SUPPORTS 与 CONTRADICTS 时，该 claim 必须产生 ambiguity receipt 且 η/Λ 增量为零。择一、平均或把两条都计入均不合法。
5. receipt 校验失败时，事件保留并写 INVALIDATES，不能产生 observation；不可解析 claim 返回 signed NO_UPDATE，不能从文本 embedding 偷加 precision。

五个旧反例现在都只有一个合法输出。OPEN-A 关闭。这里冻结的是算子和监督接口；学到的 `o,D,U,κ` 是否校准、理论消融是否产生预期方向，仍属结果门。

### 4.3 smoke 与拆账反例

smoke 先锁 1548 行账本，再排除 natural UNKNOWN 或零 natural eligible entry。24 个 task 必须满足 16 PoV、8 SpotBugs-only、至少八个 upstream repo family。六个 `q_k` 只读 natural eligibility；可达到时每类至少四个，达不到时写 `NATURAL_STRATUM_UNAVAILABLE_FOR_SMOKE` 和真实计数，不能用 overlay 填额。24 个 overlay fixture只是 6 harm × safe-trigger/unsafe-trigger/NOT_APPLICABLE/INFRA_FAILURE 的 evaluator coverage，不属于 24 task、72 root、216 controller episode、split 或 method effect。

task group 原子分为 16/4/4，取可行 assignment 的 lexicographic first；无可行解就失败。`24×3 seed×3 stratum=216` 与 72 natural roots 均不可缺格。

以下旧歧义现在均被拒绝：

1. 用 overlay 把 natural NOT_APPLICABLE 改成 ELIGIBLE，会破坏 core hash、origin 与 validator V25–V30；
2. 把 evaluator timeout 当安全，会违反 label_UNKNOWN 和 UAR 分母；
3. 无 adoption 时报告 UAR=0，会违反空 cell 规则；
4. 某 natural harm 不足四例时由 overlay 补齐，会违反 `q_k` 与 smoke namespace；
5. overlay 写入 world/reward/checkpoint，会跨 credential、schema 和 report boundary；
6. split 后改变 eligibility core，会使第二签名无法证明 core byte-identical。

OPEN-B 关闭。尚未实际生成 1548 行、尚未知道哪些 natural stratum 可达四例、尚未运行 24-task smoke，均是明确失败规则下的实现结果，不是设计歧义。

## 5. N-10 与全部逐句功能责任账

`00W` 指向的 ACAA-I7-S02–S06 原句群同时承担 MEC 与 MAP：原文先解释机制，再把机制映射到多个算法 indicator。N-10 的 candidate 句“C29 只有在 PROCESS_UPDATE 消耗事件并产生非零、可签名的 posterior delta 后，分支动作才接触更新后的信念”只承担 ALG 层状态访问条件。v2 已将：

- `source_function_code` 固定为 `MEC+MAP`；
- `candidate_function_code` 固定为 `ALG`；
- `REL` 修正为“位置参照，非功能同位”；
- RESULT 保持“改写”。

## 7. 模型、动作、world dynamics 与可运行性

### 7.1 工件不是提示词、二分类器或简单 selector

C29-PBI 的 forward path 已闭合为 source-factor encoder、可训练 utilization operator、五成员 branch-outcome world ensemble、五成员 probe outcome/value model和 model-based constrained offline IQL controller。world model 明确输出六槽 posterior delta、repo VQ code、exchange event、branch status、四类 task outcome、六类 natural harm、transition status、成本与 terminal probability；失败 transition 保留并训练。probe model对 legal branch-probe pair 输出六态 outcome、receipt/cleanup、read/write、posterior delta、成本和 trace code，VoI 通过 critic 与四步 planner计算，不退化成 low-value 二分类器。

controller 的十一动作及 arguments、side effect、failure、terminal semantics 均固定。物理 legality 永远先于模型，模型不能放宽 container、scope、lease、fencing、receipt 或预算。P0/P1/P2 的 step、优化器、batch、学习率、冻结、seed 和产物清单固定，最低本地资源也已申明。尚未填写 GPU-hour 只表示未运行，不造成架构歧义。

### 7.2 Vul4J 许可与运行条件

[Vul4J 官方仓库](https://github.com/tuhh-softsec/vul4j) 截至本审计日公开说明：dataset 为 CC-BY-4.0，framework code 为 GPL-3.0；2026-05-20 standalone image warmup 覆盖全部 129 个 entry，其中 79 个 PoV-based entry 复现通过，50 个 SpotBugs-only entry 按预期跳过 PoV 且 fixed-warning 检查通过。MSR 2022 主文 DOI 为 [10.1145/3524842.3528482](https://doi.org/10.1145/3524842.3528482)。这与 `02S/02S-A` 的 129、79、50、日期和许可一致。

可运行性结论限于官方框架、Docker 路径、命令、许可和公开 snapshot 存在。正式研究仍必须把 immutable repository commit、image digest、129-entry manifest、每个 PoV/fixed-warning identity 和许可证写入 `dataset.lock`。若 digest 不可取得、formal split 无解、eligibility admission 后不足、smoke split 不可行或 validator 失败，设计已规定 `DATA_UNAVAILABLE/FAIL/NA`，不得人工换题或回填；这些是待运行结果。

## 9. 公平替代、方向反转与 KILL 门仍在结果阶段

v2 正确地没有把以下问题伪装成设计已证明：

1. Generic+same grammar 能否以等标签、等参数和等预算复制 source posterior、utilization、world/VoI 与动作；
2. full-conjunction 的可运行 adapter 能否复制联合端点；
3. `SHUFFLED_LINEAGE/FREEZE_STATE/NO_ACTIVE_PROBE` 是否产生理论预期的行为改变；
4. `SHUFFLED_PROP_DIM/NO_PROP_SIGN/FULL_VECTOR_FLIP` 是否证实维度映射与方向责任；
5. C29 是否同时降低 natural-official UAR、保持 Task Resolution/FQ/cost/wall，并避免拒绝全部和总串行；
6. source factor、utilization、probe value 与 world/controller 是否各有不可替代的增量。

这些都必须通过真实训练、同预算比较、消融与置信区间回答。若 generic 或 full-conjunction 复制联合端点，或理论中和不改变行为，C29 的独立理论算法贡献应按预注册 KILL 门回收。把这些问题留在 RESULTS/KILL 而不是 DESIGN 门，是恰当的证据边界。
