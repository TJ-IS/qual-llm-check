## 0. 用户新硬约束与终判

用户新增的不可移动约束是：论文三不得招募真人，不得让真人进入训练、调参、在线辅助、标签生成、偏好拟合或策略更新，不得用 LLM persona、自报信念或模拟审核者替代真人数据。公开仓库、冻结规范、容器执行、静态与动态分析、程序化 oracle、开放权重模型和研究者事前写定的实验合同仍可使用，但研究者构造的合同只能被如实写成合成识别环境，不能冒充自然组织意图或真人共同理解。

在这一约束下，本审计没有找到能够替换旧 P3 的新题。评价器双轨治理、依赖治理和机器证据契约均可形成无真人工程系统，也都具有真实外部损害、相反方向的正常行动和可构造的执行反事实；然而，它们分别在 C11、C25，以及 C3/C14/C17/C21/C27 与现论文二 C29 的终审边界内失去独立理论—算法责任。agent-skill、flaky evidence 和纵向 memory 三条补充路径也没有打开新空间。

这一否决不是因为模型尚未训练、实验尚未运行或算力不足。相反，三条主路线都能写出数据生成器、训练工件、损失和离线政策。否决发生在运行前的构念单位、自然标签、直接近邻、等信息通用复制、coding-agent 删除和系列独立性门。本文没有运行任何候选模型、kill-pilot 或确认性实验，不报告准确率、风险下降、显著性或相对基线胜负，全文不含 `RES` 候选句。

## 2. 旧 P3 为什么不能“去真人降级”

旧 P3 的研究对象不是一般 evidence selection。它把批准点固定在外部机制之后，要求证据绑定 canonical command、diff、pre-state 与 snapshot hash，再学习下一项可执行取证动作，并以同一真人审核者的 action-specific factual grounding、unsafe approval、safe approval、审核时间和计算成本形成结果链。common-ground 层的核心结果门是：可见证据是否经真人理解与 repair 改变实际误批，以及理论状态能否越过等资源 Human-state POMDP。

删除真人后有三种表面替代，均不合法。

1. 把真人理解换成 test pass、receipt 或 condition satisfaction，会把因变量从共同理解改成协议有效性，研究随即退化为 verifier、ECLoop 或现论文二的证据—行动控制。
2. 把真人换成另一个 LLM 并询问“是否理解”，会以 persona/self-report 制造 mutual-belief 标签。该标签既不是 common-ground 原文中的人际递归信念，也不能独立于生成它的模型核验。
3. 保留旧张量和损失但删除真人结果，只能说明工程前向仍可运行，不能识别 `证据→共同基础→批准` 的中介，更不能合法宣称原理论机制。

因此，旧 P3 在本硬约束下不是“降级为无真人版”，而是撤题。其冻结材料继续保留历史与反证价值，本文件不修改旧 P3 文件。

## 3. 候选 A：评价器双轨完整性治理

### 3.1 安全对象与 I/S/A/O

真实损害有两个方向。agent 删除断言、篡改 evaluator 或使用隐藏测试泄漏可制造 false-green，使带功能回归或漏洞的补丁被合并；反向的永久锁定又会阻止合法需求变化、必要 test update 与新行为发布。

| 元素 | 最强无真人版本 |
|---|---|
| I | 事前签名的 spec/contract version，code/test/evaluator diff，文件访问与 provenance trace，旧回归集、独立 oracle、时间与分支绑定 |
| S | contract validity、tamper posterior、旧行为保留义务、新行为允许范围、oracle independence、false-green/false-reject 尾险 |
| A | `LOCK_ORACLE`、`QUARANTINE_TEST_DIFF`、`PROMOTE_SOURCE_ONLY`、`RETAIN_OLD_LANE`、`INDEPENDENT_TEST_CERTIFY`、`DUAL_PROMOTE`、`REJECT_TAMPER`、`REQUEST_NEW_SIGNED_SPEC`、`STOP` |
| O | 隐藏功能/安全回归、合法新行为通过、错误拒绝、可审计 evaluator mutation、执行成本与发布延迟 |

### 3.2 数据、反事实、工件与损失

篡改侧可以使用 RewardHackingAgents、BenchJack、Protocol Validity 与 SpecBench 的公开或可复现环境；合法演化侧可以使用 TEBench 与 TestEvo-Bench。最强构造从同一 pre-state 分叉旧合同保持、prospectively signed 新合同、source-only、test-only、联合修改和 tamper arms，并由独立 accepted solutions、mutation、brute-force dispute、隐藏安全属性及两套回归 runner 评价。

决定性数据缺口仍在。TEBench/TestEvo 的开发者后续 test patch、commit message 和 post-change code 对早期决策点属于未来事实。把它们摘要成新 charter 再交给 solver 仍是语义泄漏。公开资产没有同一 diff 下两个事前合法 purpose、两套独立组织签发记录和各自唯一相反 control portfolio。研究者可以合成这类合同，但得到的是 instruction-following truth，不是自然 controller intention。

训练工件可为 `spec_version—code/test/evaluator diff—provenance/access trace—oracle relation` 异构图，加 action-outcome world model 与离线 constrained policy。候选损失可写为

\[
\mathcal L_A=\mathcal L_{contract}+\mathcal L_{tamper}+\mathcal L_{outcome}+\mathcal L_{cf-rank}+\lambda\operatorname{CVaR}(false\mbox{-}green)+\mu C.
\]

该规格说明候选可训练，不构成通过终审的证据。

### 3.3 MEC→MAP→ALG 与终止反证

- **MEC：** Wiener 等区分 value-appropriation 与 value-creation purpose，并把 purpose 锚定于 controller 的控制意图；Kirsch 与 Choudhury–Sabherwal说明 control portfolio 会随可观察性、可测量性和关系条件调整。
- **MAP：** 尝试把“防 evaluator 操纵”映射为 appropriation，把“允许合法 test evolution”映射为 creation，再把合同版本、provenance 与双 lane 表示成 purpose-conditioned state。
- **ALG：** 用该状态选择锁定、隔离、独立认证、source-only 或 dual promotion。

链条在 MEC→MAP 处失败。合同是否合法不是控制者为何配置控制的意图；测试修改的字节与执行结果不能恢复 appropriation/creation purpose。value-creation 还依赖 stewardship、cooperation 与 coordination，不能把接受训练的 coding model直接当作有内在合作动机的 controllee。理论标签若由研究者合同生成，就没有比合同本身增加独立信息。

**Equal-info/equal-label/equal-param：** 让同参数异构图 POMDP 或 per-action distributional Q 模型获得完全相同的合同、diff、provenance、oracle、branch outcome、动作标签、参数和 FLOPs，它可以复制每项决策。若只有理论模型获得 purpose 标签，就是 privileged supervision；若两者都获得，则理论结构没有不可交换运算。

**Coding-agent deletion：** 把 coding agent 换成 ML evaluator、科学计算 workflow、CI policy engine 或普通测试维护者，输入、双 lane、动作和 false-green/false-reject 损失仍成立。

**直接近邻与系列边界：** BenchJack 已执行攻击—修补式 benchmark hardening；RewardHackingAgents 与 Coding Agents as Test-Suite Auditors 已覆盖 evaluator locking 与独立认证；TEBench/TestEvo 已覆盖合法测试演化。项目内 `00X_CPTC测试控制面候选独立终审.md` 已以相同 contract-purpose、future-spec leakage 与 generic 反证终判 C11。故本候选为 **HIGH-CONFIDENCE NO-GO**，不得作为 C11 的换名返回。

## 4. 候选 B：依赖与 package 多动作治理

### 4.1 安全对象与 I/S/A/O

真实损害包括恶意或易受攻击依赖造成的 RCE、凭据泄漏和供应链传播，不安全版本选择造成的已知漏洞，升级造成的 API/ABI 破坏，以及无必要依赖带来的攻击面和维护负担。反向错误是拒绝一切外部依赖，导致任务失败、重复实现和安全修补延迟。

| 元素 | 最强无真人版本 |
|---|---|
| I | task/repo snapshot、lockfile、package/version/publisher metadata、签名、时间冻结 registry/OSV、dependency/reachability graph、API callsite、sandbox install trace |
| S | 资源身份与发布者 posterior、版本漏洞与可达性、兼容性、task-equivalence、hook/permission risk、长期维护成本 |
| A | `REUSE_EXISTING`、`QUERY_REGISTRY`、`SELECT_SAFE_VERSION`、`PIN_FULL`、`VENDOR`、`FORK`、`REPLACE`、`REMOVE`、`SANDBOX_NO_HOOK`、`ABORT` |
| O | build/test/exploit/reachability、凭据 canary、任务成功、依赖数量、升级与维护成本、state delta |

### 4.2 数据、反事实、工件与损失

公开起点包括 Dependency Updates 的七生态变更记录、PinTrace 的版本选择任务、HalluSquatting 的 repository/skill hallucination、OSV/registry 的时间事实和恶意 skill 标签。可在同一 repo snapshot 上构造 install/pin/vendor/fork/replace/remove 分支，冻结网络与 registry 时间，禁止真实外部副作用，在容器中运行 build、hidden tests、exploit、reachability 和 clean-up runner。

训练工件可为 package/version/publisher/dependency/API/callsite/sandbox outcome 异构图，连接 action-conditioned transition model 与离线风险约束策略：

\[
\mathcal L_B=\mathcal L_{transition}+\mathcal L_{vuln/reach}+\mathcal L_{compat}+\mathcal L_{task}+\mathcal L_{cf-rank}+\mathcal L_{offline\mbox{-}RL}+\lambda\operatorname{CVaR}(harm).
\]

公共记录通常只观察一次真实选择，完整兄弟动作结果仍由研究环境生成。这个缺口不妨碍系统研究，却不能自行产生 IS 理论标签。

### 4.3 MEC→MAP→ALG 与终止反证

- **MEC：** boundary-resource 理论描述平台所有者通过 API、SDK 和规则同时 resourcing 外部贡献与 securing 平台控制，并在生态演化中反馈调整。
- **MAP：** 尝试把 package API/metadata 视作 resourcing，把签名、版本、sandbox 与 policy 视作 securing，再把兼容与供应链风险映射为张力状态。
- **ALG：** 在 reuse、pin、vendor、fork、replace、remove 与 abort 间执行多动作规划。

链条在分析单位处失败。单仓库 adopter 选择依赖不是平台 owner 设计边界资源；理论也不规定某个 repo 应 pin、vendor、fork 还是 replace。把 resourcing/securing 写进 loss 只是对 task utility 与 risk 的重新命名。

**Equal-info/equal-label/equal-param：** 同参数 heterogeneous graph Transformer、SCA planner 或 distributional POMDP 若看到相同图、registry/OSV、branch outcomes、action mask 与损失，就能逐项复制政策。

**Coding-agent deletion：** 将发起者替换为 package manager、Dependabot/Renovate、IDE 插件管理器或 DevSecOps bot，资源图、动作、外部损害和训练目标不变。coding agent 增加自动猜名和自动执行频率，但未改变核心可信获取计算。

## 5. 候选 C：proposer–executor 机器证据契约

### 5.1 安全对象与 I/S/A/O

真实损害是 executor 将 proposal 应用于陈旧 pre-state、错误仓库、错误目标或未满足的依赖条件，造成回归、漏洞、数据破坏或错误发布。反向错误是因证据合同过严而拒绝所有可安全执行的修改。

| 元素 | 最强无真人版本 |
|---|---|
| I | proposal、canonical diff/command/parameters、pre-state digest、repo snapshot、required witnesses、tool receipts、版本与作用域绑定 |
| S | proposal–state binding、condition satisfaction、evidence freshness/independence、缺失 witness、可逆性、执行与停止后果分布 |
| A | `VALIDATE_BINDING`、`REQUEST_WITNESS`、`PROBE`、`REPLAY`、`REBIND`、`QUARANTINE`、`EXECUTE`、`RECOVER`、`STOP` |
| O | hidden function/security tests、错误目标或 stale-state damage、任务完成、证据成本、恢复成功与 state delta |

### 5.2 数据、反事实、工件与损失

无需真人即可从同一 proposal 建立 sibling repository worlds：一侧满足前提，另一侧移除符号、改变依赖、推进 commit、污染 receipt 或修改作用域；随后对 REQUEST/PROBE/REPLAY/REBIND/QUARANTINE/EXECUTE/STOP 分支运行隐藏测试和副作用 runner。该反事实在工程上比 A/B 更干净。

训练工件可为 proposal–evidence–state typed graph、condition-satisfaction filter、action-outcome world model 与 constrained policy：

\[
\mathcal L_C=\mathcal L_{binding}+\mathcal L_{condition}+\mathcal L_{transition}+\mathcal L_{harm}+\mathcal L_{cf-rank}+\mathcal L_{policy}.
\]

### 5.3 MEC→MAP→ALG 与终止反证

- **MEC：** common ground 是参与者认为彼此共享的知识、信念和假设；joint activity 需要识别、能力、意愿及对“已经充分理解”的 mutual belief，并通过对话、问题与 repair 更新。
- **MAP：** 尝试把 proposer 与 executor 当作参与者，把 evidence contract 当 boundary object，把 condition/receipt 状态当作 action-specific common ground。
- **ALG：** 根据 contract gap 选择请求、探针、重放、重绑定、隔离、执行或停止。

链条在构念映射处失败。机器显式状态只能证明某个 condition 被记录或 receipt 被验证，不能证明参与者对彼此理解形成递归 mutual belief。Rosenkranz 等的 situation model 是人的 mental representation，broker 是社群中的个人；无真人条件下把这些对象换成模型节点改变了分析单位。用 LLM 自报理解补标签正是本审计禁止的 persona 数据。

**Equal-info/equal-label/equal-param：** ECLoop 式 condition compiler 加同参数 graph POMDP 获得同一 proposal、state、evidence、probe、action outcome、参数与预算后，可以复制全部动作。从消息派生的 `g_est` 不增加信息；隐藏 belief 标签若由模型或研究者生成，则不具独立效度。

**Coding-agent deletion：** 该合同可原样用于 planner–executor、数据库两阶段提交、机器人 plan–execute 或一般工具 agent；coding 只提供可执行 oracle，没有改变核心协议控制。

**直接近邻与系列边界：** ECLoop 精确覆盖 action-specific evidence condition、satisfaction tracking 与 unsupported-action postponement；Software Delegation Contracts 已提出 explicit contract 和 evidence bundle；CollabSim 已把 CSCW/common-ground/repair 用于 LLM multi-agent。更重要的是，现论文二已将 ECLoop 作为直接适配器，并已有主动 probe、REQUEST_BRANCH、PROCESS_UPDATE、replay、recover、isolate、integrate、synthesize 与 stop。该候选实现最清楚但独立性最差，终判 **NO-GO**。

## 8. 条件分叉：只禁止真人调参时的边界

如果用户真正禁止的是“真人参与调参和训练回流”，但允许一次独立、预注册、结果不回流模型的确认性真人实验，那么旧 P3 可以另行重设计：先完全冻结模型、动作、界面、样本量规则、排除标准和统计分析，再由独立 cohort 只提供最终 unsafe/safe approval、理解中介与时间结果；实验结束前不得据真人结果改模型、阈值、任务或证据库。

这个条件分叉仍需伦理审批、招募与功效设计，且必须重新审查 common-ground 中介、同一审核者结果和 Human-state POMDP 公平比较。本文件不据此恢复旧 P3，也不授予设计冻结；在用户当前“完全不加入真人”的硬约束下，该分叉不生效。

## 9. 最小 kill-pilot：只作为搜索，不占题位

唯一值得保留的最小搜索是评价器双轨路线的**自然双合法合同可得性 kill-pilot**，目的不是证明模型优越，而是尽快检查终止性数据门能否被事实推翻。

1. 在公开仓库历史中寻找 20–30 组在变更前已经分别签发、时间可核且相互独立的旧/新 API contract、ADR、issue acceptance criteria 或 release policy；不得从后续 test patch 或 commit message反向生成合同。
2. 对同一 pre-state 构造 source-only、test-only、联合合法演化、断言削弱、evaluator tamper 与 independent-certification arms；所有 runner、hidden oracle 和时间 cut 在执行前冻结。
3. 只回答三个可行性问题：是否存在两个自然合法而非研究者虚构的 purpose world；是否能在不泄漏未来规格的前提下给出唯一可审计 portfolio truth；在 identical I/labels/params/FLOPs 下，purpose-structured model 是否产生通用 graph POMDP 无法复制的中和差异。
4. 任一问题失败即停止搜索，不扩大样本、不训练大模型、不占 P3。即使三个问题均通过，也只获得“可重新送审”的资格，不能自动复活 C11 或宣布论文成立。

该 pilot 尚未运行，没有样本、日志或结果。
