## 终审口径

本轮只接受能形成独立、可执行、可证伪的行动机制题目。
题目必须有同一 pre-state 下的多行动自然结果，且有外部、可执行的 claim oracle。
若 oracle 由模型自己生成，或结果只能由人工事后判断，则不满足替代题的最低识别条件。
RT/STM 可以支持映射、追踪、外部事件与序列化，也能定位 RM 缺陷。
但 RT/STM 不会单独推出行动排序，更不能把排序选择伪装成因果识别。
Price–Shanks 的 pragmatic IQ 可说明消费者判断为何重要，但不能替代独立 oracle。
本轮没有运行结果；所有“不可行”均为设计级 NO-GO，而非统计拒绝。

## 候选一：计算科学主张保真与主动证伪

判定：NO-GO。
表面问题是：代理能否在计算科学任务中保留主张、主动寻找反例，并在证据变化后安全修正行动。
问题本身过度压缩为验证—反驳—重跑的控制器，和当前 P2 的 source-utilization branch controller 算法同构。
POPPER（ICML 2025，arXiv:2502.09858）已直接压缩 claim fidelity 与 active falsification 的核心空间。
Paper-replication（2607.02134）把复现执行、证据对齐与失败暴露放进同一类评测。
Runnable-to-Verifiable（2608.09567）进一步把可运行产物转成可核验主张。
Auditing Discovery Claims（2608.00981）直接覆盖发现主张的审计、反证和证据边界。
AutoMat（2605.00803）覆盖计算材料科学主张复现中的可执行验证接口。
SocSci（2606.11447）与 SocSci（2606.11456）覆盖社会科学计算主张的复核、审计和可重复性路径。
因此新题的理论差异只剩把已有验证步骤换成更细的动作标签，无法形成非同构机制。
已有 RT/STM 对状态映射、追踪、外部事件与序列化的解释力仍不足以推出 action ordering。
公共数据也没有同一 pre-state 下的多 action natural outcomes 与独立 executable claim oracle。
同信息 HGT/POMDP 可以复制候选控制器；删除 coding-agent 后同一机制仍成立，因此 agent 身份不是不可删除的机制变量，二者都不能补足观测设计缺口。
结论：撤题，不进入 pilot，不以“再加一个 verifier”救援。

## 候选二：多工件原子性

判定：NO-GO。
候选主张代理能否跨代码、配置、文档和发布元数据执行 all-or-nothing 的多工件变更。
AtomicCommitBench 已把提交边界、部分成功和恢复协议作为通用基准对象。
HWE-Bench 以真实硬件缺陷修复覆盖 RTL、配置与验证工件之间的跨工件协调及失败暴露。
relational conformance 文献则研究 claim–evidence–authority–lineage 发布图、已发布字节与独立重算之间的一致性。
generic workflow deletion、回滚、C14A 以及普通事务日志都能复现该候选的主要观测变量。
候选若排除这些通用机制，只剩“删除是否同时完成”的工程检查；若纳入，则没有非同构理论增量。
公开仓库缺少同一 pre-state、多工件自然结果、独立一致性 oracle 的成对观测。
人工核验提交树也不能替代可执行、外部、预先冻结的 oracle。
结论：NO-GO；不把原子提交语义改名为论文三的新机制。

## 候选三：异步副作用

判定：NO-GO。
候选主张代理能否在异步通知、队列、定时任务和外部写入并发发生时保持可靠行动。
Verified Tool Calls（2608.02645）已明确覆盖 postcondition、verify-before-retry 与 idempotency。
这些要素已经给出异步副作用的可观察失败模式和基本修复协议。
受控 failure injection 能制造丢失、重复、乱序和迟到回调等对照；删除 coding-agent 身份后，该机制仍退化为通用 workflow reliability。
若只研究删除，题目退化为队列消费或幂等写入的工程回归测试。
若加入人工判断，则 oracle 依赖研究者解释，不能识别“可靠行动”本身。
若加入端到端日志，核心变量又回到 P2 的来源利用与分支控制。
RT/STM 可解释事件映射与记忆追踪，但不证明副作用的真实完成顺序。
结论：NO-GO；不以“异步”这一时间词汇制造新理论贡献。

## 小型 kill-pilot（只用于永久否决）

本节不是实验结果；RESULT 仍为 NOT RUN。
只允许做一个最小数据审计：从三个公开候选仓库各抽取不超过 20 个任务。
每个任务先冻结一个 pre-state，再枚举至少两个可执行 action。
每个 action 必须有外部可执行 claim oracle，且 oracle 不能由被测代理生成。
同时记录是否存在自然发生的 competing outcomes、独立时间戳和可重放工件。
若任一候选不能形成 10 个以上满足条件的 paired cases，立即永久 kill。
若候选的 action order 可由事务、幂等、验证重试或 P2 controller 直接解释，立即永久 kill。
若 oracle 需要人工裁判、临时 prompt 或事后补标签，立即永久 kill。
本 pilot 不估计效应量、不运行显著性检验、不宣称完成实验。

## 永久 kill gates

KG-1：没有同一 pre-state 的多行动自然结果，永久 kill。
KG-2：没有独立 executable claim oracle，永久 kill。
KG-3：机制可被 P2 source-utilization branch controller 同构实现，永久 kill。
KG-4：机制可被 AtomicCommitBench、HWE-Bench、relational conformance 或 Verified Tool Calls 覆盖，永久 kill。
KG-5：主要操纵只是 deletion、rollback、retry 或 idempotency，永久 kill。
KG-6：RT/STM 只能映射或追踪，无法独立推出 action ordering，永久 kill。
KG-7：需要真人事后裁判才能判定结果，永久 kill。
KG-8：公共数据不足以冻结 pre-state、action、postcondition 和时间顺序，永久 kill。
KG-9：新增候选不能同时给出机制差异、识别策略和可复现实验工件，永久 kill。
KG-10：检索只找到通用 HGT/POMDP/编码代理模板，永久 kill。
