## 1. 旧方案中真人承担的不可替代责任

旧规格中的真人数据同时承担以下责任：

1. `B_H,t` 的审核者解释后验；
2. `P_t^{phase}` 与 `R_t^{mut}` 的阶段、理解和 reciprocal-uptake 监督；
3. `T_ev` 的 factual response、`Δg_est`、human effort 与 latency 转移；
4. `π_cg`、HumanState-POMDP 和 checkpoint 选择所需的 approval、cost 与 propensity；
5. 同一审核者对同一 canonical action 的最终批准，以及与 sealed executable truth 联结后的 unsafe/safe approval。

这些责任不是普通超参数调节。删除 180 人 logging cohort 后，旧 `F_cg/T_ev/π_cg` 失去合法监督目标；使用 LLM persona、自报“理解”或从 merge/comment 反推共同基础都不能修复该缺口。

## 2. 推荐保留路线：Frozen Grounding Protocol

### 2.1 新工件定位

可行版本应改成：

> **机器训练技术证据层 + 完全冻结且无可学习参数的共同基础状态机 + 首次且唯一的真人确认性随机试验。**

论文贡献由“理论驱动的人类状态学习器”收窄为“共同基础理论如何约束可重放的审核协议”。真人回答只在单个 trial 内触发已冻结分支，不产生梯度、不改变阈值、不跨参与者形成 memory，也不用于事后改任务、题库、界面或策略。

状态机的唯一分叉为：

- `UNSEEN → PRESENTED → PROBED(correct) → CLOSED`；
- `UNSEEN → PRESENTED → PROBED(wrong/UNKNOWN) → GAP_FOUND → REPAIRED → TRANSFER_TESTED(correct) → CLOSED`；
- `TRANSFER_TESTED(wrong/UNKNOWN)`、预算耗尽或无合法 repair 时进入 `UNRESOLVED`，随后只允许 `ACK_AND_ADVANCE` 或 `STOP`。

动作闭集唯一为：

`PRESENT → INITIAL_PROBE → REPAIR → TRANSFER_PROBE → ACK_AND_ADVANCE → STOP`

一个 required proposition 只有在下列条件同时成立时才可写 `CLOSED`：

1. 存在 exact exposure receipt；
2. initial probe 正确，或错误/UNKNOWN 后已展示同命题 repair 且不同表述的 transfer probe 正确；
3. 回答确实改变了下一冻结动作，并已向参与者展示 uptake receipt。

该状态只表示取得了满足预注册 grounding criterion 的可观察证据，不等同于模型读出了递归 mutual belief。

### 2.3 损失与训练边界

仅保留机器可监督的技术目标：evidence validity、causal discrimination、state-delta prediction、execution cost 和 repository-disjoint calibration。

删除 `Linterp`、`Lphase`、`Lpot_not_est`、`Lreciprocal`、`Lpurpose`、human-response/effort/latency transition loss、`LCQL`，以及以真人 approval 或时间训练的 constraint loss。

共同基础结构改成可穷举的不变量，而非可学习 loss：

- exposure 单独不得关闭命题；
- wrong/UNKNOWN 后必须经过同命题 repair 与独立 transfer probe；
- 非 required proposition 不能抵消 required gap；
- uptake receipt 缺失时不得写 `CLOSED`；
- 全部 response alphabet、预算与 mask 路径必须在首位参与者进入前穷举 replay。

### 2.4 首例前机器冻结

机器阶段应分别冻结：

1. technical checkpoint；
2. proposition/compiler manifest；
3. evidence lattice；
4. initial 与 transfer factual banks；
5. FSM transition table；
6. 三臂策略、UI、预算、serializer；
7. 随机化、功效与分析代码；
8. 全部输入、输出与 executable-oracle SHA-256。

三个 oracle 必须隔离：`technical_evidence_oracle` 只判证据有效性，`factual_item_oracle` 只给 action-bound 事实答案，`sealed_action_truth` 只由 hidden tests、exploit/state delta 和 invariant runner 判定 safe/unsafe。不能由机器唯一判定的任务在 admission 阶段排除，不得在结果揭示后补人工 truth。

确认性日志只进入 analysis-only store；训练服务没有读权限。首例后的 checkpoint、题目、阈值、动作表、UI 或 serializer 修改会使该 cohort 失去确认性身份。

该路线还必须建立与论文一、二的资源防火墙。P3 的 task generator、repository/base-commit 样本、proposition 与 factual banks、标签服务、hidden oracle、split、technical checkpoint 和全部确认性参与者不得进入 P1/P2 的训练、选择或测试；P1/P2 的状态、动作标签、world outcomes 与 checkpoint 也不得进入 P3。三题只可共用容器调度、哈希、序列化和日志存储等不传递任务信息的工程基础设施，并为每项共用服务保存版本和无跨题数据流 receipt。

### 2.5 一次性真人确认实验

建议由旧四臂改为三臂：

- `S=StaticBundle`：初次 probe 后不依回答改变证据；
- `G=GenericReactive-v1`：读取同一回答并形成无理论类型的 `need[p]`，其中 correct 置零、wrong/UNKNOWN 置一；随后在全部未展示 evidence atom 上按 `(need[p]×technical_score, required_flag, evidence_hash)` 的固定字典序取首项。它没有 phase、同命题 repair 义务、transfer closure 或 reciprocal-uptake receipt；若所有 `need` 为零则按 required coverage 与 technical score 继续或停止；
- `T=FrozenGroundingProtocol-v1`：wrong/UNKNOWN 后执行同命题 repair、显示 uptake，再进行独立 transfer probe。

三臂在出现 treatment-specific 行为前共享逐字节相同的 canonical action、证据池、第一证据、initial probe 和预算。参与者按人固定分臂，final approve/deny 由接收证据的同一人对同一 action 作出。策略不得运行新代码探针、改变 worktree、改 action 或读取 hidden truth；否则立即侵入论文二的主动分支控制边界。

主要联合判据为：

1. `T−G` 降低 participant-average unsafe approval；
2. safe approval 满足预注册非劣界；
3. active-human time 与互动负担不超过预注册上界。

三臂都在同一固定槽位收到来自同一独立 transfer bank、同难度分层且不向策略反馈的 analysis-only transfer measurement；S/G 的该测量不改变后续动作，T 的在线 closure 使用另一份互斥 transfer item，分析时只使用三臂共同的 measurement item。机制检验比较共同 initial prefix 后、initial answer 为错误或 UNKNOWN 的预先定义 subgroup 中 `T−G` 的 analysis-only transfer correctness。该 subgroup 在 treatment-specific 行为前形成；仍不得把 transfer improvement 宣称为 unsafe approval 的因果中介。

最终样本量不能从旧数值直接缩小。首例前先冻结最小值得部署的 unsafe-approval 差、safe-approval 非劣界、人工时间上界、α、power 和最大可招募人数；再对 baseline rate、participant/task ICC、gap rate、完成率、缺失以及每人 6/8 trial 进行 participant-cluster assurance simulation。若所需人数超过实施上限，路线判为实施 NO-GO，不能事后放宽效应或边界。

## 4. 完全取消新真人招募：公开历史数据路线

AIDev、MOSAIC-agentic-3m、AgentReviewChat 和 SWE-chat 能提供 PR、review verdict、评论、工具轨迹、部分 commit/diff 和修复互动，但不能共同提供：随机 assignment、审核者 exposure receipt、action-specific factual answer、sealed unsafe truth、executed harm、已知 logging propensity 和同一分析单位的替代证据序列。

因此，公开历史数据不能替代旧 GEAP 的主要研究。把 approval 当 unsafe approval、把 merge 当执行结果、把 comment 当 established understanding，都会改变 estimand。跨数据集按 commit SHA 拼接也不能证明后续审核者看过 agent session 中的证据。

最窄可做版本是观察性研究“coding-agent 轨迹中的 observable grounding work 与后续审查摩擦”：只报告 challenge/correction、repair/tool-test、uptake signature 与 `CHANGES_REQUESTED`、review latency、rework、code survival 或静态发现的条件关联。它不能使用 unsafe approval、human understanding、harm reduction、OPE 或 causal policy value。由于 Human–AI Synergy、SWE-chat、From Human-Centric to Agentic Code Review 等直接近邻已覆盖大量相邻问题，该路线最多适合作为高风险 research note，不足以替代当前 ISR full-paper 题位。

## 5. 完全机器化的新第三题：ESTD kill-pilot

若完全不允许新真人，当前唯一仍值得一次撤题型 pilot 的候选是 **可执行状态转移偏差**（Executable State-Transition Discrepancy，ESTD）。它是 measurement theory 与 construct-validity benchmark，不是 learned controller。

### 5.1 定义

在 agent 运行前，由显式任务规范和初始仓库状态机器编译带类型、前置条件、不变量和后置条件的义务偏序 DAG `G*`。把实际工具效果规范化为 repository state-delta 序列 `Δ_{1:T}`，定义：

`ESTD = min_{π∈LE(G*)} CostAlign(Δ_{1:T},π)/Z`。

五个预注册分量为 required-obligation omission、prerequisite inversion、无新状态信息的重复或重建、off-contract side effect 和 invalid substitution。它允许多条合法线性扩展，不与单一 gold plan 或 gold patch 对齐。

Representation Theory/STM 只承担 mapping、tracking、external-event 与 sequencing fidelity；Ye 等人的 execution discrepancy 只承担“理论序列—实际序列偏差可测”的先例。义务 DAG、state-delta ontology、alignment cost 和所有 severity 均为本文测量设计，不归给理论原文。

### 5.2 生死门

在进入正式论文前，ESTD 必须先通过 30–50 项、随后至少 150 项的 kill-pilot：

1. contract 全部 pre-action、零真人、零 LLM judge、零 future artifact；
2. 每任务至少两条独立生成且通过 oracle 的合法轨迹，ESTD 对合法替代路径的假阳性率不超过 5%；
3. 删除或倒置真实前置义务会造成可执行失败或伤害，交换无关动作不会增加偏差；
4. 在 held-out repo/language/model/scaffold 上，相对 final test、raw sequence distance、steps/tokens/diff size、generic process-mining 与 checklist compliance 有增量效度；
5. 构造 `G*` 不读取 gold patch、future PR、hidden outcome 或人工 implementation plan；
6. 简单 deterministic checklist、SWE-RPG/OctoCodingBench 类过程合规、ACT*ONOMY/ProcGrep trajectory 指标不能达到同等端点；
7. coding-agent deletion 必须失败：若同一 ontology、算法与端点可原样成为一般 process-mining conformance，永久撤题；
8. 不复用论文一、二的状态、动作、标签或 checkpoint。

ESTD 当前是 **HIGH-RISK CONDITIONAL / KILL-PILOT ONLY / NOT P3**。任何生死门失败即终局 NO-GO；不能再降格为普通 trace taxonomy、冗余编辑指标或 benchmark checklist。
