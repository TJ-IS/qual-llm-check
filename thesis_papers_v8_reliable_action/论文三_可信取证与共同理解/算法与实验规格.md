# 论文三算法与实验规格

## 1 规格状态与研究边界

本规格对应正文中的共同基础引导可信取证策略（Grounded Evidence Acquisition Policy，GEAP）。模型训练、真人试验、功效模拟、支持度模拟与结果检验均尚待运行；所有人数、算力和执行次数都是实施规划。

外部机制在 GEAP 启动前已经决定一次行动需要人工审核。可信中介随后绑定 canonical action。GEAP 只执行 `acquire`、`present`、`factual_probe`、`clarify`、`repair` 与 `stop`，不输出 `approve`、`deny`、`allow`、风险分数、人工审核触发时点、第二审核者或审核者分配。`stop` 只把事件交还外部 gate。

## 2 角色、时序与绑定合同

| 时点 | 唯一写入角色 | 输入 | 输出 | 禁止读取 |
| --- | --- | --- | --- | --- |
| T−6a split | split manager | salted participant ID、repository、base commit、bug/risk family、generated-test lineage、opaque recipe-lineage ID | `split_group_manifest`、participant 到 `anonymous_schedule_block_id` 的私有映射 | recipe catalog/seed、gold/oracle/hidden bytes、safe/unsafe label、arm、response、approval、outcome |
| T−6b recipe commit | 独立 evaluator authority | `anonymous_schedule_block_id`、十二个 slot ordinal、recipe catalog 与 recipe seed | `oracle_recipe_commitment_root`；每个匿名 block 六 safe/六 unsafe 的封存承诺 | participant/salted ID、repository split、arm、lattice、candidate score、response、approval |
| T−5 bind | trusted mediator | exact diff/command/tool args、repo/container、pre-state、working tree、permission、scope | canonical bytes/hash、`binding_digest` | gold、oracle、hidden、approval |
| T−4 purpose | 两名 task author 加一名裁决者 | binding digest、task/action manifest、公开组织约束 | proposition、`J_content`、`m_req/κ`、四套题库 | response、approval、outcome |
| T−3.5 arm | HMAC allocator | baseline support stratum、salted participant ID | 固定 `A/B/C/D` arm receipt | trial 过程与结果 |
| T−3 generate | candidate generator | 部署可见字段、授权工具 | 静态候选及动态 branch working set | gold、oracle、hidden、response |
| T−2 commit | commitment service | generator working set、函数版本与 seed | lattice、branch Merkle root、函数 hash | evaluator output |
| T−1 sealed eval | 独立 evaluator | frozen binding、T−6 recipe/seed commitment；接口拒绝 lattice 输入 | 此时才生成 gold/oracle/hidden bytes 与 sealed outcome | generator、policy、participant 均不可见；不得依候选自适应生成 oracle |
| T0 log action | logger | cap 后集合、`S_t^pre`、`q-policy-v1` | propensity、选中动作、完整 denominator | post-action response、outcome |
| T1 interact | runner/logger | 选中动作、可见 response | exposure、response、clarify/repair、uptake receipt | hidden outcome |

`binding_digest` 覆盖 exact action bytes、repo/container identity、base commit、pre-state、working-tree hash、permissions 与 scope。任一字段改变时，旧 digest 下的 proposition、`J_content`、`m_req/κ`、题库、候选、branch、evidence、response、`V/B_H/P^{phase}/R^{mut}/g_pot/g_est/r` 全部标记失效，新 trial 重新执行 T−5 到 T−2。禁止只刷新显示缓存。

## 3 输入、输出和核心 schema

### 3.1 模型输入

- `canonical_action`: diff、command、tool arguments、scope、permission、binding hash。
- `state_graph`: pre/post snapshot、working tree、repository/container identity。
- `agent_trajectory`: tool、file、line、content hash、intent 与 action receipt。
- `authorized_tools`: test、build、dependency、call、taint、scope、provenance、simulation、rollback。
- `budget_t`: human attention、latency、sandbox compute、model compute。
- `J_content∈{0,1}^{P×4}`: 列为 objective、resource、risk、commitment。
- `m_req∈{0,1}^P` 与 `κ∈[0,1]^P`: T−4 外生确定。
- 截至 `t−1` 的 evidence exposure、factual response、clarification、repair 与 uptake receipt。

Gold patch、oracle state、hidden tests、hidden unsafe truth、final approval、当前未观察的人类信念和 confirmatory 交互不得进入输入。

### 3.2 模型输出

- `E_tech`: evidence validity、causal discrimination、cost、transition-delta 分布。
- `F_cg`: `B_H,t`、`P_t^{phase}`、`R_t^{mut}`、`g_pot,t`、`g_est,t`、`r_t`。
- `T_ev`: 每个合法候选的技术后果、factual-response、`Δg_est`、effort、latency、compute 分布。
- `π_cg`: 六个顶层动作类与类内 candidate 的条件概率。
- 执行层动作必须属于 cap 后合法集合，所有拒绝或授权决定由外部 gate 产生。

### 3.3 符号表与命名空间

| 符号 | 唯一含义 | 禁止复用 |
| --- | --- | --- |
| `A_i^{arm}` | 参与者固定实验臂；D=1、C=0 只用于主要机制比较 | 不表示日志动作或最终决定 |
| `U_{irs}^{act}` | 第 `r` 个 trial、第 `s` 个互动槽的已选动作类与候选 | 不表示实验臂 |
| `Y_{ir}^{dec}` | 同一审核者对原绑定行动的最终决定；1=approve、0=deny | 不表示纵向过程节点 |
| `T_{ir}^{truth}` | T−1 产生的封存行动真值；1=unsafe、0=safe | 不进入策略输入 |
| `O_{ir}^{oracle}` | gold、hidden test 与 state-delta oracle 的封存对象 | 不用字母 `G` 表示 hidden truth |
| `P_t^{phase}` | presentation、clarification、repair、acceptance 的命题级阶段张量 | 不表示删失 |
| `R_t^{mut}` | 独立理解证据与可观察 system uptake 的双列张量 | 不表示第七槽测量 |
| `G_{irs}^{proc}` | 纵向过程中的 grounding/repair 宏节点 | 不表示 oracle 或过程 law |
| `M_{ir}^{meas}` | 第七槽终端事实测量 | 不表示共同基础张量 |
| `C_{ir,u}^{obs}` | 节点 `u` 的 observation/censoring 指示与首次失败码 | 不表示互动阶段 |
| `H_{ir}^{−}` | trial `r` 开始前已观察的处理前记录、较早 decision、公开 runtime 与部署可见 carryover | 不含 gold、oracle、hidden truth，也不在标准化中递归生成 |
| `\mathcal L_{a,r}^{J}` | 给定 `H_{ir}^{−}` 时臂 `a` 的当前 trial 联合过程 law | 不表示跨 trial 反事实、hidden truth 或 grounding 状态 |
| `g_{pot,t},g_{est,t}` | 本文操作化的 potential/established 概率 | 仅用小写 `g` 与 process/oracle 区分 |

所有持久 ID 都带显式 `source_namespace`。字符串先做 Unicode NFC，再以 `LP(x)=UInt32BE(len(UTF8(NFC(x))))∥UTF8(NFC(x))` 长度定界；`namespace`、`source` 或无长度拼接形式均为 schema error。在线张量中的 `source_namespace_code:uint16` 是 `source_namespace_codebook.json` 按 NFC UTF-8 bytes 升序分配的索引，codebook bytes 与 SHA-256 在 T−4 固定；该索引不替代 salted ID 消息中的原始长度定界 `source_namespace`。

## 4 标签、监督信号与 producer 隔离

| 标签 | Producer 与可见时点 | 正监督 | 禁止来源 | 缺失处理 |
| --- | --- | --- | --- | --- |
| `J_content` | T−4 task author | bound action 与 task manifest | 模型输出、approval、hidden outcome | 无法归类则重写 proposition |
| `m_req/κ` | T−4 task author | approval purpose、公开约束 | response、approval、harm、后验调阈 | 未达一致不进入主实验 |
| evidence validity/role | lattice 后 evaluator | state replay、bug/candidate/gold contrast | generator availability side channel | `UNKNOWN` 单列 |
| `V_t` | renderer/access logger | exposure、permission、receipt | response correctness、approval | 未知保持 UNKNOWN |
| `B_H,t` | factual bank | action-specific state/scope/permission/rollback response | confidence、停留、approval、harm | UNKNOWN mask loss |
| `P_t^{phase}` | 盲态话轮标注 | presentation、clarification、repair、grounding acceptance | gate approval、模型 act tag、outcome | UNKNOWN 单列 |
| `R_t^{mut}[:,1]` | 独立理解事件 | paired interpretation 或另一时点的理解证据 | `P_t^{phase}` 或 `B_H,t` 的同一 event、礼貌确认、approval | UNKNOWN |
| `R_t^{mut}[:,2]` | uptake 三联证据 | system uptake、human exposure、paired confirmation | 未曝光 repair、同 response、outcome | 任一 receipt 缺失则 UNKNOWN |
| external reward | outcome joiner | same-reviewer approval × sealed truth；cost | 不回写理论标签 | 按预注册 censoring 处理 |

四套题库互不复用：`probe_train_bank` 训练解释后验，`paired_interpretation_bank` 校准理解证据，`transfer_item_bank` 测量迁移，`confirmatory_factual_bank` 用于第七槽终端测量。事件在创建时固定 `producer_role∈{BH_RESPONSE,PHASE_EVENT,M1_INTERPRETATION,M2_UPTAKE}`，四组 event ID 两两不交；`B_H,t` 与 `R_t^{mut}[:,1]` 可以因共同参与者、证据和历史而相关，联合滤波器用共享 prefix 估计相关性，但同一 event bytes 不能重复提供两个监督标签。

## 5 架构、关键张量与参数上限

### 5.1 技术证据编码器 `E_tech`

- 图类型：action–state-transition–evidence typed graph。
- 图节点上限 `N`，batch `B`，隐藏维 `d=384`。
- 六层 relational graph Transformer，输入 code embedding 来自冻结开放权重 code encoder。
- 输出 `H_tech∈R^{B×N×384}`。
- 边类型：supports、contradicts、causally-discriminates、regression-only、candidate-specific、misleading、depends-on、invalidated-by。
- Heads：validity Bernoulli/categorical、causal-role categorical、cost distribution、transition delta structured prediction。
- 真人 logging 时冻结 code encoder 和图网络下部四层；可训练上部、adapter 与 heads 总计 `≤15M`。

### 5.2 共同基础滤波器 `F_cg`

- `H_prop∈R^{B×P×384}` 由 `J_content`、manifest 与 `H_tech` 产生。
- 序贯层数 `≤2`，内部 state `≤192`，可训练参数 `≤10M`。
- `V_t∈[0,1]^{P×2}`。
- `B_H,t∈Π_pΔ^{K_p∪{UNKNOWN}}`。
- `P_t^{phase}∈[0,1]^{P×4}`，列为 presentation、clarification、repair、grounding acceptance。
- `R_t^{mut}∈[0,1]^{P×2}`，列为 human understanding evidence 与 human-visible system uptake。
- `g_pot,t∈[0,1]^P`。
- `g_est,t=g_pot,t⊙q(B_H,t)⊙c(P_t^{phase})⊙sqrt(R_t^{mut}[:,1]⊙R_t^{mut}[:,2])`。
- `r_t=m_req⊙max(0,κ−g_est,t)`。

`q` 与 `c` 是命题级单调可校准神经门。Clark 与 Schaefer承担 presentation、acceptance、repair 与 purpose-relative grounding criterion；Clark 承担共同活动、共同目的及 identification、ability、willingness、mutual belief 四项要求；Mastrogiacomo 等人承担这些机制在信息系统项目会议中的适配、objective/resource/risk/commitment 四类内容及会议中的理解问题与 repair；potential/established 来自 Li 等人。`g_pot/g_est`、乘性门、平方根、`r_t` 及其全部 loss 是本文可证伪操作化，安全 `risk` 是 action-manifest 适配。该实现保留 access、interpretation、phase、reciprocal uptake 四个可中和接口，并实现等参数 generic gate 检验结构是否可复制。

### 5.3 证据转移模型 `T_ev`

- 候选数 `K_t`，cross-attention block `≤2`，state `≤192`，参数 `≤12M`。
- Query：候选 action embedding；Key/value：`H_tech`、`H_prop`、`r_t`、reviewer history、budget。
- 输出 `Z_next∈R^{B×K_t×(P+q)}`。
- 前 `P` 维包含 factual-response logits 与 proposition-level `Δg_est`。
- 其余维包含 validity/technical-state、effort、latency、sandbox compute、model compute 与 budget transition 参数。
- 工具是否可用只读环境 action mask，不由模型推测或生成。

### 5.4 受约束策略 `π_cg`

- Distributional conservative offline POMDP，层数 `≤2`，state `≤192`，参数 `≤5M`。
- 输入只含技术摘要、显式理论状态、候选后果与预算。
- 主路径禁止 raw trace 绕过 `g_est/r`；raw bypass 只作反证基线。
- 动作：`acquire/present/factual_probe/clarify/repair/stop`。
- 外部约束：unsafe approval、safe approval、false rejection、time、interaction、compute。

## 6 候选动作、动态分支与 logging policy

每个机会严格执行：`instantiate-all → candidate hash → public-only class cap 8 → persist retained/discarded → build S_t^pre → evaluate q → mix propensity → sample U_t^{act}`。

`candidate_content_hash=SHA256(instantiated_bytes)`。

`candidate_id=SHA256(CBORcanonical([binding_digest,parent_state_hash,action_class,template_id,slot_bytes,instantiated_bytes,generator_version]))`。

`Cap8Fn-v4` 以 `(-proposition_coverage_count, expected_public_cost_millis, candidate_content_hash)` 升序排序，每类保留至多八个，`stop` 只保留一个。`q-policy-v1` 只看 retained set。Dynamic clarify/repair 只能由 T−2 冻结的 grammar、template/slot、source-bank Merkle root、instantiator image、seed 和 replay executable 决定性产生；运行时禁止自由文本 LLM 生成。

令 `𝒜_t^{cls}` 为 cap 后非空合法动作类集合。顶层混合策略：`p_cls(c|S_t^pre)=.70q_cls(c|S_t^pre)+.30/|𝒜_t^{cls}|`。

类内混合策略：`p_cand(k|c,S_t^pre)=.60q_cand(k|c,S_t^pre)+.40/|K_t(c)|`。

`S_t^pre` 只含 risk stratum、baseline reviewer support、grounding phase、budget、class availability、eligible-set hash 与 public-history hash。定义 `h=φ(S_t^pre)=risk_stratum×baseline_reviewer_support×grounding_phase_pre×budget_bucket_pre×class_availability_pattern`，`c∈𝒜_t^{cls}`，`t` 遍历参与者的 eligible opportunity。对 participant `i`，`w_it(h,c)=I{φ(S_it^pre)=h,U_{it}^{act}.class=c}/p_cls(c|S_it^pre)`，`W_i(h,c)=Σ_t w_it(h,c)`，`ESS_Kish(h,c)=(Σ_iW_i(h,c))^2/Σ_iW_i(h,c)^2`；分母为零即 unsupported，禁止在 decision row、task 或 repository 层重算 ESS。全部 logits、normalizer、denominator、propensity、retained/discarded IDs 和 sum-to-one 检查只写入 audit-only policy sidecar，不进入审核过程 law。

## 7 损失函数与优化

`L_D=1·Ltech+1·Linterp+0.5·Lphase+0.5·Lpot_not_est+0.5·Lreciprocal+0.5·Lpurpose+1·Ltransition+1·LCQL+1·Lconstraint`。`L_C` 把 D 的三个结构项等权替换为 `0.5·Laccess+0.5·Luptake+0.5·Lcriterion`，其余项、标签、batch 与优化器完全相同。

- `Ltech`: validity、causal-role、state delta 与 cost 的多任务损失。
- `Linterp`: 命题解释 posterior 的 masked cross-entropy 与 calibration penalty。
- `Lphase`: 盲态 grounding stage 的多标签/序列一致性损失。
- `Lpot_not_est`: evidence content 固定、interaction history shuffle 的对比损失；约束 `g_pot` 稳定、`g_est` 变化。
- `Lreciprocal`: 双向 recognition 与 receipt consistency；单向 exposure 不可跨 criterion。
- `Lpurpose`: required proposition 的 gap 不可由不相关高分抵消。
- `Ltransition`: candidate-conditioned next-state distribution NLL/CRPS。
- `LCQL`: conservative offline policy objective，使用已知 class×candidate propensity。
- `Lconstraint`: Lagrangian safety/task/cost constraints。

`Lpot_not_est/Lreciprocal/Lpurpose` 及 `g_pot/g_est/r` 均为本文操作化，不归给共同基础理论原文。通用替代模型获得相同原始 labels、等总权重的 auxiliary supervision 与同维多任务 heads。优化器、超参数搜索次数、训练 step、early-stopping 数据和 seed 数按第 10.2 节执行。

## 8 数据构建、划分与训练阶段

### 8.1 技术预训练资料

- BSG-VA：3,730 validation events、643 rollouts、110 tasks。
- SWT-Bench（Mündler et al. 2024）：2,294 Full、276 Lite、433 Verified tasks。
- Code Review Agent Benchmark（Zhang et al. 2026）：184 PR、234 validated review comments/tests、67 repositories。
- FIXCHECK（Molina et al. 2024）：随机测试与 fault-revealing evidence。
- AgentLens（Sahoo et al. 2026）：1,815 tool/file/line/content-hash trajectories，用于过程表示监督，不产生 unsafe-approval 真值。
- Action swap、stale state、binding swap 与 public-equivalent hidden-byte mirror 合成组。

Repository、base commit、bug family、risk family、generated-test lineage 与 opaque gold-sibling lineage group 在 gold bytes 产生前成组划分。T−6 只有 lineage ID 与 oracle-recipe Merkle commitment；T−1 evaluator 才从已承诺 recipe 生成 gold/oracle/hidden bytes，且其接口不能读取 lattice。任何 group 不得跨 train/validation/test。

### 8.2 四阶段训练

1. 预训练 `E_tech` 与技术 heads。
2. Pilot 冻结任务、标注、criterion、题库、合法动作和 UI；不训练最终策略。
3. Logging cohort 训练 `F_cg/T_ev/π_cg`；已知 propensity；支持不足 cell 不外推。
4. Confirmatory cohort 只评价；任何 response、decision 或 outcome 不更新 checkpoint 与 calibration。

## 9 三个真人 cohort 与支持度

| Cohort | 参与者下限 | 每人 trial | 用途 | 是否更新模型 |
| --- | ---: | ---: | --- | --- |
| measurement/support pilot | 48 | 8–12 | 可理解性、标注、题库、动作合法性、支持模拟 | 否 |
| policy-learning logging | 180 | 16；总计≥2,880 | 已知 propensity 轨迹、filter/transition/policy 训练 | 是 |
| prospective confirmatory | `N_confirm=max(N_power,N_support)`，且 `N_support=432` | 12；总计≥`12N_confirm` | 固定权重随机评价 | 否 |

三批 participant 完全不复用。`baseline_reviewer_support` 使用独立练习仓库的十二道强制作答事实题，正确为 1，错误或不确定为 0，满分 12；`low=0–4`、`medium=5–8`、`high=9–12`，未完成全部题目者不能进入随机化。Logging cell 的支持算法使用第 6 节的 `h,c,w_it,W_i(h,c)`，主要 cell 需 `eligible≥80`、`selected rows≥40`、`selected participants≥30`、participant-cluster `ESS≥30`；每类跨 cell 需 `selected participants≥80`、`ESS≥60`。`N_power` 由首例前锁定的 participant-cluster 模拟产生。支持样本用精确动态规划计算：在每个 baseline-support 层招募 `n_s` 人，每人进入 `A-retained,B-retained,C-retained,D-retained,dropout` 五类的规划概率固定为 `(0.225,0.225,0.225,0.225,0.10)`；选择最小的四的整数倍 `n_s`，使 `P{min_a N_{sa}^{retained}≥20}^3≥0.95`。以 capped-count multinomial recursion 逐人更新并保留十位小数时，唯一最小值为 `n_s=144`，单层概率 `0.9863606515`、三层联合概率 `0.9596375127`，因此 `N_support=3n_s=432`。实现脚本、状态转移次序与 checksum 在首例前保存；这只是样本规划，实际 support 仍按第 12 节门限判断。`N_confirm=max(N_power,432)` 后向上取 12 的整数倍，并在三层使用相等的 `N_confirm/3` 招募配额；180、240 与 276 均只属于早期或算术下界。

## 10 Confirmatory 固定四臂

按处理前 `baseline_reviewer_support∈{low,medium,high}` 分层。每层 `P(A_i^{arm}=A)=P(A_i^{arm}=B)=P(A_i^{arm}=C)=P(A_i^{arm}=D)=1/4`，同一 participant 十二个计划 trial 全程同臂。D/C 子比较条件 propensity 固定 `1/2`。

- A：canonical raw action/diff。
- B：`StaticBundle-v1`。
- C：`HumanState-POMDP-v1`。
- D：GEAP。

Salted-ID 字节合同为 `LP(x)=UInt32BE(len(UTF8(NFC(x))))∥UTF8(NFC(x))`。隐私服务生成独立 256-bit `K_id`，并输出恰为 64 个小写 ASCII hex 字节的 `salted_participant_id=lowerhex(HMAC-SHA256(K_id,LP(source_namespace)∥LP(source_id)))`；原 ID、`K_id` 与分析表隔离。分臂 HMAC 域为 `GEAP-CONF-ARM-20260816-v1`。首例前生成不同的 256-bit `K_arm` 并公布 `seed_hash=SHA256(K_arm)`；消息唯一为 `LP(domain)∥LP(stratum)∥LP(salted_participant_id)`。取 `HMAC-SHA256` 前八字节为 UInt64BE `u`，令 `j=floor(4u/2^64)`，按 `0→A,1→B,2→C,3→D`。Enrollment lock 后公开 `K_arm`，两个实现独立重放。

每人的十二个 `planned_trial_id` 在 arm assignment 前写入。顺序域固定 `GEAP-TRIAL-ORDER-20260816-v1`；按 `SHA256(LP(domain)∥LP(salted_participant_id)∥LP(planned_trial_id))` 的 32-byte unsigned value 升序排列，hash tie 按 `planned_trial_id` 的 NFC UTF-8 bytes 升序。保存 order、每项 hash 与整个列表 SHA-256；分臂、响应、缺席、删失和结果均不能改变顺序。

### 10.1 `StaticBundle-v1`

输入只含 T−2 retained public lattice 和 `static_bundle_selector_v1.ckpt` 的 public-only 技术分数。Selector record 字段顺序固定为 `binding_digest,candidate_id,candidate_content_hash,action_class,subtype,required_proposition_ids,source_namespace,source_ordinal,source_fact_hash,public_execution_receipt,p_valid,p_discrim,p_valid_q24,p_discrim_q24,expected_public_cost_millis,expected_latency_millis,candidate_bytes`；`source_namespace` 是 NFC UTF-8 bytes，`source_ordinal` 是 UInt32BE，二者都在候选生成时写定。Response、phase、uptake、approval、`O^{oracle}` 与 hidden label 均不可见。进入 subset 枚举前先按 `candidate_id` 去重：相同 ID 且 bytes 相同时保留 `source_namespace,source_ordinal` 字节串全序最小记录；相同 ID 对应不同 bytes 时输出 `STATIC_CANDIDATE_ID_COLLISION` 并停止 B 臂确认性运行。

Checkpoint 的两个校准概率先分别截到 `[0,1]`，再以 round-half-to-even 转成 `p_valid_q24=round(2^24p_valid)` 与 `p_discrim_q24=round(2^24p_discrim)`；selector 的所有比较只用这两个 UInt32 整数，浮点原值只进 audit sidecar。在预算允许的所有 subset 中，selector 按下列 tuple 作确定性全序：最大化 required proposition union cardinality；再最大化 `Σ(p_valid_q24+p_discrim_q24)`；再最小化总 sandbox milliseconds；再最小化总 serialized bytes；再取升序 `candidate_content_hash` 列表最小者；最终以升序 `candidate_id` 列表破除全部剩余同分。Selector score 只存在于机器选择记录。Human-visible `StaticCard-v1` 字段恰为 `schema_version,binding_digest,candidate_id,action_class,subtype,required_proposition_ids,source_fact_namespace,public_execution_summary,public_execution_receipt,candidate_bytes`，不得呈现 `p_valid`、`p_discrim`、量化分数、候选排名或选择器置信度。

`StaticCard-v1` 以 RFC 8785 canonical JSON、Unicode NFC、UTF-8、LF 与无额外空白序列化上述固定字段；`schema_version` 的值固定为字符串 `StaticCard-v1`，32-byte digest/ID 用 64 个小写 hex 字符，任意 bytes 用无 padding 的 base64url，`required_proposition_ids` 按其 32-byte unsigned value 升序。Renderer 只消费 exact card bytes。每卡上限 8,192 bytes。低、中、高预算的 bundle cardinality、累计 render bytes、sandbox 秒与 active-human 秒分别为 `(3,16384,300,240)`、`(5,32768,600,480)`、`(6,49152,900,720)`；若无合法 evidence，输出固定零卡 receipt。B 在首个展示时一次渲染完整 bundle，后续 response 不触发再选择，未用预算作废。

`EvidenceAtom-v1` 是 B/C/D 跨界面公平性比较的机器视图，字段依次为 `binding_digest,candidate_id,proposition_ids,source_fact_namespace,public_execution_summary,public_execution_receipt,candidate_bytes`；`StaticCard-v1.required_proposition_ids` 在映射时规范化为 `proposition_ids`。同一 `candidate_id` 的这些原子依共同 dtype 解码后必须逐值相同，`evidence_atom_hash=SHA256(RFC8785(EvidenceAtom-v1))` 也必须相同。`StaticCard-v1` 与 `ActionCard-v1` 的 human-visible schema、控件和整体 payload bytes 可不同；公平合同只声明 machine-view 原子等值，不声明两种卡整字节相等。任一原子不同输出 `EVIDENCE_ATOM_ASYMMETRY` 并停止相应比较。

`static_bundle_selector_v1.ckpt` 冻结为共享 `E_tech` 的 384 维 public candidate embedding 加 `LayerNorm→Linear(384,192)→GELU→Linear(192,2)`，两个 sigmoid 输出 `p_valid/p_discrim`。训练标签只来自技术预训练 split 的 evidence-validity 与 bug-discrimination 真值，损失为两项等权 binary cross-entropy；优化器 AdamW、学习率 `3e-4`、weight decay `0.01`、batch `256`、global gradient clip `1.0`、seed `2026081651`。最多训练 100 epoch，每 epoch 在 repository-disjoint validation 上计算两头平均 NLL；连续十次未改善 `10^-5` 即早停，平局取较早 epoch。温度校准只拟合 validation split，每头单独拟合一个正标量，校准后 checkpoint、temperature、optimizer state、split lineage 与 SHA-256 在确认性候选生成前固定。

保存 `static_bundle_selector_v1.ckpt`、训练 split/hash、serializer executable/hash、去重 trace、selector records、human-visible cards、subset enumeration count、winner tuple、candidate/order bytes、payload bytes/hash、`evidence_atom_equivalence_manifest.json`、budget trace 和 renderer receipt。Selector 不使用真人 response、phase、uptake、confirmatory interaction 或 outcome。

### 10.2 `HumanState-POMDP-v1` 与 D/C 公平接口

C 与 D 的机器可读 `feature_availability_manifest.json` 必须逐字段相同。每条记录固定含 `feature_name,dtype,shape,producer_role,available_after_event,source_namespace,online_or_audit_only,missing_code,serializer_version`；manifest 及其 SHA-256 在策略训练前锁定。两臂共享 `E_tech/H_prop`、全部 `J_content`、T−2 lattice/branch、mask、external reward、logging propensity、split、训练机会、五个 seeds、六类动作和同档预算。两臂都读取同一 `M1_INTERPRETATION` raw event record，即 `event_id,proposition_id,answer_code,UNKNOWN_flag,response_latency_ms,exposure_receipt`；exact response bytes 与 hash 只进 audit log。任一字段只在一臂 online 可用即输出 `FEATURE_MANIFEST_ASYMMETRY`，D/C 主要比较不运行。

两臂以同一 pooling 和 mask 形成策略输入。`H_tech` 与 `H_prop` 分别先对 padding 和 invalidated node 施加布尔 mask，再拼接 masked mean pooling 与单头 query-attention pooling；空有效集合返回固定零向量及 `EMPTY_POOL=1`，不得读取 padding。Candidate mask 在任何 normalizer 之前应用，结构不合法候选 logit 固定为负无穷。C 的唯一隐状态是两层 GRU 的 `h_t^C∈R^192`，输入依次为 pooled `H_tech`、pooled `H_prop`、原始 `V_t`、`M1_INTERPRETATION` record、phase multi-hot、uptake receipt、`m_req/κ` 与预算。它是不预设共同基础分解的非结构化隐状态。

C 的 factual head 输出每个 proposition 的 `K_p+1` 个解释 logits，phase head 输出四个 Bernoulli logits，uptake head 输出三联 receipt logits，candidate-transition head 输出 factual/phase/uptake/cost/latency 分布，policy head 输出六类动作及类内 candidate logits。C 的非分解 auxiliary readout 另含 `access_aux∈R^{P×2}` 与 `criterion_aux∈R^P`；前者预测 renderer/access logger 产生的 `V_t` 两列，后者预测 factual bank 依据 action-bound answer key 与 `m_req/κ` 产生的 required-item criterion-met 标签，拒答或无独立题目时为 UNKNOWN。Distributional value head 输出 51 个固定分位，`τ_j=(j-0.5)/51,j=1,…,51`。D 获得相同 raw labels 与输出容量；其有意差异限于 `g_pot/g_est` factorization、乘性门、reciprocal square-root 与 residual-gap 路径。C/D 两臂共用 `ActionCard-v1` serializer；相同 candidate 被展示时 human-visible bytes 必须逐字节相同，这项整字节合同不延伸到 B 臂 `StaticCard-v1`。

`ActionCard-v1` 的 union schema 字段顺序恰为 `schema_version,binding_digest,planned_trial_id,slot,action_class,candidate_id,proposition_ids,source_fact_namespace,public_execution_summary,public_execution_receipt,prompt_code,option_codes,repair_relation,candidate_bytes`；不适用字段写 JSON `null`，禁止省略。`schema_version` 的值固定为字符串 `ActionCard-v1`，32-byte digest/ID 用 64 个小写 hex 字符，任意 bytes 用无 padding 的 base64url，`proposition_ids` 按 32-byte unsigned value 升序，`option_codes` 按题库 schema 的冻结 ordinal 升序。模型 logits、value、`g_pot/g_est`、residual gap、风险分数、候选排名、propensity 和 hidden/audit-only 字段均不得进入 card。Serializer 使用 RFC 8785 canonical JSON、Unicode NFC、UTF-8、LF 与无额外空白，renderer 只消费 exact card bytes；serializer/renderer executable、version 与 SHA-256 在首例前固定。单卡不超过 8,192 bytes，低、中、高 budget tier 的累计 render bytes 分别不超过 16,384、32,768、49,152，超限候选在 policy normalizer 前 mask；每次曝光保存 payload bytes/hash 与 renderer receipt。

共同损失权重固定为 `λtech=1,λinterp=1,λphase=0.5,λdyn=1,λpol=1,λcost=1`。D 的结构项为 `λpe=λrec=λpurpose=0.5`；C 以相同 raw labels 和总权重使用 `λaccess=λuptake=λcriterion=0.5` 的非分解 heads。`Laccess` 是 `access_aux` 对 `V_t` 的 masked BCE，producer 为 renderer/access logger；`Luptake` 是 uptake head 对 M2 uptake 三联 receipt 的 masked BCE；`Lcriterion` 是 `criterion_aux` 对独立 factual-bank criterion-met 标签的 masked BCE，producer 不读取批准或损害。三项都先在一个 event 的可观察分量内平均，再按 participant trajectory 平均，UNKNOWN 不进分子或分母，participant 全 UNKNOWN 时该项 mask 为零；因此高频回应者不获得额外权重。优化器为 AdamW，新增模块学习率 `3e-4`、技术 adapter 学习率 `3e-5`、`β=(0.9,0.999)`、weight decay `0.01`、participant-trajectory batch `16`、global gradient norm clip `1.0`；CQL 系数固定 `α_CQL=1.0`。每个约束的 Lagrange multiplier 从零开始，以学习率 `0.01` 做投影上升并截到 `[0,100]`。C 与 D 都训练最多 100,000 step，每 1,000 step 评价一次。

最强等信息替代 `HumanState-POMDP-v1` 与 GEAP 使用同一 validation 合同。Participant-disjoint validation 记录上的标量回报固定为 `R=-1.00Y^{UA}+0.25Y^{SA}-0.001·active_human_s-0.0005·sandbox_s-10^{-6}·model_mFLOP`；self-normalized doubly robust participant value 经域 `GEAP-VAL-BOOT-20260816-v1` 的 500 次整 participant bootstrap 后，以 2.5% 分位为唯一主验证分数。Checkpoint 的资格门同时要求 safe-approval 单侧 95% 下界不低于 `0.75`、unsafe-approval 单侧 95% 上界不高于 logging policy、三类成本的单侧 95% 上界不超过所属预算 tier、每个动作类 participant ESS 不低于 60，且 replay 与 feature manifest 检查通过。每个 seed 内先最大化主验证分数；差值不超过 `10^-6` 时依次取较小 model mFLOP、较低 participant-mean candidate-transition validation NLL、较早 step。连续十次没有至少 `10^-4` 改善即早停；bootstrap 失败率超过 5% 或资格集合为空时该 seed 不可部署。

容量配平不改变 C 的两层 GRU-192 核心。脚本固定枚举进入 candidate-transition、value 与 policy heads 的共享 residual capacity adapter，`blocks∈{0,1,2,3,4}`、`width∈{0,64,128,256,384,512,768,1024,1536,2048}`、`rank∈{0,8,16,32,64}`，并在共同的 batch-1、六类各八候选、六槽 trace 上计算 trainable parameters 与推断 FLOPs。D 架构先固定，候选 C 需同时满足参数差 `≤1%` 和 FLOPs 差 `≤5%`；全序依次最小化最大归一化偏差、参数偏差、FLOPs 偏差、blocks、width、rank。唯一胜者写入 `capacity_match_manifest.json`；空集输出 `CAPACITY_MATCH_EMPTY`，D/C 主要比较不运行。硬件、搜索次数、训练时间上限与 human budget 相同。

确认性 C/D policy kernel 固定 temperature `0.7`。每个决策以 masked softmax 产生顶层分布，再在选中类内产生 candidate 分布；动作类全序为 `acquire,present,factual_probe,clarify,repair,stop`，候选按 `candidate_id` 的 32-byte unsigned value 升序。`eligible_set_hash` 是上述全序下 `LP(action_class)∥candidate_id∥UInt8(mask)` 列表的 SHA-256，`public_history_hash` 是截至当前槽的 `ActionCard-v1` 与 public response-event canonical bytes 长度定界串的 SHA-256。唯一确认性实现使用预注册 `policy-kernel-v1` executable/container：masked logits 先转 IEEE-754 binary64，按固定全序减去有限最大值，以该可执行文件的 versioned log-sum-exp 计算并序列化 binary64 normalizer；可执行文件及容器 SHA-256 在首例前公布，独立重放不能逐 bit 复现即记 `POLICY_KERNEL_REPLAY_FAILURE`。类级与候选级随机数分别来自 `HMAC-SHA256(K_policy,LP("GEAP-CONF-POLICY-20260816-v1")∥LP(salted_participant_id)∥UInt16BE(trial_order)∥UInt8(slot)∥eligible_set_hash∥public_history_hash∥UInt8(level))`，其中 `level=0` 用于 class、`level=1` 用于 candidate；各取摘要前八字节为 UInt64BE 并除以 `2^64`，再按相应分布的逆 CDF 抽样，边界相等时取全序较早项。联合 propensity 固定为 `p_joint=p_cls·p_cand`，联合 log-probability 为两级 log-probability 之和。`K_policy` 的 SHA-256 在首例前公布，数据锁定后公开 key。两级 logits、temperature、normalizer、propensity、log-probability、HMAC message/hash、uniform variate 与 selected ID 只写入 `policy_audit_sidecar_v1`，不属于 `U^{act}` 或任何 process-law 节点。

预算向量按 `active_human_ms,sandbox_ms,model_mFLOP` 预扣；低、中、高档的 trial 上限固定为 `(240000,300000,30000)`、`(480000,600000,60000)`、`(720000,900000,90000)`。每个槽先对产生本次 masked logits 的完整前向图扣 `decision_mFLOP`，该计数覆盖 encoder adapter、state transition、全部 heads、mask 和 stop logit；随后 `acquire` 加扣 `(0,candidate_declared_sandbox_ms,0)`，`present` 加扣 `(max(15000,ceil(1000·render_bytes/120)),0,0)`，`factual_probe` 加扣 `(30000,0,0)`，`clarify` 加扣 `(45000,0,0)`，`repair` 加扣 `(60000,candidate_declared_sandbox_ms,0)`，`stop` 不加扣并进入吸收态。因而 stop 仍支付生成该决定的完整前向计算，所有槽的 `K.model_mFLOP` 之和必须等于 profiler receipt；误差非零即记 `MODEL_COMPUTE_NONCONSERVATION`。动作专项预扣后任一分量为负的候选在 softmax 前 mask，已扣预算不退款；stop 在完成前向扣款后始终合法。`repair` 只能改变 evidence/understanding history并保持 bound action bytes；需要新 action 时，原计划 trial 以 `ACTION_CHANGE_REQUESTED` 和 final-decision missing 结束，新对象只能形成不计入十二个确认性主试次的次级独立 trial。

Seeds 固定为 `2026081601,2026081602,2026081603,2026081604,2026081605`，工件分别命名 `human_state_pomdp_v1_seedXX.ckpt` 和 `geap_policy_v1_seedXX.ckpt`。每臂每个预算档从五个 seed 的 seed 内胜者中选唯一 deploy checkpoint：先保留上一段全部资格门通过者，再最大化主验证分数；分数差不超过 `10^-6` 时依次取较小 model mFLOP、较低 participant-mean candidate-transition validation NLL、较早 step、较小十进制 seed。确认性试验不使用 ensemble；五 seed 只承担训练稳定性和唯一 checkpoint 选择，不产生五倍推断预算。若某臂某档没有合格 checkpoint，输出 `DEPLOY_CHECKPOINT_EMPTY` 并停止该档 D/C 主要比较。保存训练/验证曲线、优化器状态、constraint multipliers、feature/capacity manifests、参数/FLOPs 报告、选择 trace 与完整 kernel replay。

## 11 结果、时间轴与 cluster likelihood

T−6a split manager 只保存 salted participant 到 `anonymous_schedule_block_id` 的私有映射与 split lineage；它看不到 recipe、seed、truth class 或 commitment leaf。T−6b evaluator authority 只见匿名 block、十二个 slot ordinal、recipe catalog 与 seed，为每个匿名 block 的六个 safe 和六个 unsafe recipe 作 Merkle commitment；它看不到 participant、repository split、arm 或 lattice。T−1 evaluator 依已承诺 recipe 生成 exact gold/oracle/hidden bytes，接口拒绝 lattice、candidate score、response 与 arm，因此 truth balance 先承诺而 oracle bytes 后生。

对 trial `ir`，`Q_{ir}=I(interaction_participant_id=evidence_recipient_id=final_approver_id)I(canonical_decision_action_hash=canonical_action_hash)`，`Y_{ir}^{dec}=0` 表示 deny、`Y_{ir}^{dec}=1` 表示 approve，`T_{ir}^{truth}=0` 表示 sealed safe truth、`T_{ir}^{truth}=1` 表示 sealed unsafe truth。`Q_{ir}=0` 时写入 `C_{Q,ir}=1,reason=ACTION_BINDING_FAILURE`，原 planned trial 仍留在 ITT 分母，`Y^{UA}` 与 `Y^{SA}` 记为未观察而非零。`Q_{ir}=1` 时定义 `Y_{ir}^{UA}=I(Y_{ir}^{dec}=1,T_{ir}^{truth}=1)`、`Y_{ir}^{SA}=I(Y_{ir}^{dec}=1,T_{ir}^{truth}=0)` 与 `Y_{ir}^{FR}=I(Y_{ir}^{dec}=0,T_{ir}^{truth}=0)`。Unsafe 与 safe 分母分别固定为六个预承诺 truth-specific planned trials，participant aggregate 先在六项上等权，再由 arm 对 participant 等权。

主表逐臂报告 `Q` mismatch 与 `arm_mismatch=I(runtime_arm≠A_i^{arm})`。两类 mismatch 都保留原分配臂和原 planned-trial ID；保守界把 unsafe trial 的缺失或 mismatch 置为 1、safe trial 置为 0，乐观界反向赋值。任何分析均不得把 mismatch 乘以零形成表面安全结果，也不得用另一审核者、另一行动或另一 arm 的记录替换。

Clarify/repair 只能新增或更正 evidence、presentation、interpretation 与 uptake history。确认性 repair 必须保持 exact diff、command、tool args、repo/container、pre-state、working-tree、permission 与 scope bytes 不变。若回应表明需要新行动，原 planned trial 以原对象、`ACTION_CHANGE_REQUESTED` 与 final-decision missing 终止并进入 censoring 与 bounds；只有 altered action bytes 被写回原 trial 时才另记 `Q=0,C_Q=1,reason=ACTION_BINDING_FAILURE`。新对象从 T−5 重新绑定，只能成为不计入十二个确认性主试次的次级独立 trial。

ITT 保留全部 randomized participant 及 `A_i^{arm}`。真实退出、日志损坏、final decision 缺失、`C_Q=1` 或 arm mismatch 在第一个受影响节点记录 `C_{ir,u}^{obs}=1,τ_{C,ir}=u,reason_code`，后续 planned nodes 为 `CENSORED_ABSORB`，不重随机、不补任务。H1 不用 complete-case 删除或 cross-fitted observation hazard 恢复缺失结果；每臂固定六个 truth-specific planned-trial 分母，并并列报告 observed-case 描述值、把 unsafe 缺失置 1 的保守 ITT 界与置 0 的乐观 ITT 界，safe 结果反向赋值。两界跨越预注册判定门时只报告随机化描述和 bounds，不宣称优效或非劣。次级结果包括 task success、review time、clicks、clarify/repair count、compute、post-state factual prediction、calibration 与 workload。

H1 的 safe-approval 非劣界在首名参与者进入前固定为 D−C 绝对风险差下限 `−0.05`。主要成本约束也在首例前固定：D−C 的 participant-average active-human time 单侧 95% 上界不得超过每 trial `120` 秒，sandbox compute 单侧 95% 上界不得超过每 trial `180` 秒。Unsafe-approval 优效要求 D−C 绝对风险差的双侧 95% 区间上界低于零；上述非劣与成本约束任一不满足时，H1 不获得联合支持。

IID 观测单位固定为 participant cluster。完整运行记录写为 `O_i^{obs}=({Z_{ir}^J,C_{ir,1:V_r}^{obs},τ_{C,ir},Y_{ir}^{obs}}_{r=1}^{12})`，并条件于 `B_i,X_{i,1:12},A_i^{arm}`；`B_i` 含 baseline-support 12题原始分数、经验、工具熟悉度和人口统计，`X_ir=(repository_stratum,task_stratum,risk_stratum,task_complexity_bin,canonical_action_type,canonical_scope_bin,public_risk_bin,initial_budget_bin,trial_order_block)`，全部在 arm 前冻结。对 trial `r`，`H_{ir}^{−}` 追加较早 trial 的 final decision、公开 runtime、公开 measurement、疲劳、信任调整、missingness code 和部署可见交互；gold、oracle、hidden truth 与 audit sidecar 永不进入该历史。H3 只从该记录中提取当前 unsafe trial 的 `R_{ir}^{cc}=1` 行，不将十二 trial 联合 likelihood 当作 H3 目标。

每 trial 固定六个互动槽与两个终端槽。前六槽 `s=1,…,6` 的宏节点顺序为 `D_{irs}→U_{irs}^{act}→E_{irs}→F_{irs}→G_{irs}^{proc}→K_{irs}`；第七槽为 `M_{ir}^{meas}`，第八槽为 `R_{ir}^{post}`。每个宏节点内部字段也按表中次序逐字段条件化。`online` 字段可以进入策略与标准化过程模型，`audit-only` 字段只用于重放或联结；exact bytes、hash、receipt signature、策略概率与 ordinal 均不得进入 process-law density。

十二次重复审核的运行记录可按已观察 prefix 序贯展开，但该记录 factorization 只用于描述部署历史。H3 在任何 nuisance 拟合之前先以冻结的 `R_{ir}^{cc}` 筛出当前 unsafe trial，其密度从 `k_D` 开始并以 `k_R` 结束，不含 `π_{obs}`、observation hazard、`CENSORED_ABSORB` 或 inverse-observation weight。较早 trial 的 decision、runtime、measurement 和 missingness code 仅作为实际 `H_{ir}^{−}` 输入，H3 不生成、积分或重估这些早期节点。No-interference 只在 participant clusters 之间假定，人内 carryover 由实际 `H_{ir}^{−}` 显式条件化。

## 12 目标参数与估计

目标选择总体固定为 `A_i^{arm}=D,R_{ir}^{cc}=1` 的当前 unsafe trial 记录，其外层协变量分布是这些记录的实际 `H_{ir}^{−}`。用 oracle commitment 中冻结的 `unsafe_ordinal j∈{1,…,6}` 区分六个 unsafe planned trial；每个 `j` 内 participant 等权，再对六个 ordinal 各赋 `1/6` 权重。十二个 planned trial 只形成各次实际 `H_{ir}^{−}`；不用缺失的 unsafe trial 换入另一 trial 或另一 participant。该总体由处理后完成条件选择，因而 H3 数值不外推到 `R^{cc}=0` 或全部随机入组者。

令 `\mathcal L_{a,j}^{J,cc}(dz|H_{ir}^{−},R_{ir}^{cc}=1)` 为臂 `a∈{C,D}` 下当前 unsafe ordinal `j` 全部必需过程节点的完整案例 law，`μ_{D,j}(z,H_{ir}^{−},R=1)=E[Y_{ir}^{UA}|A_i^{arm}=D,Z_{ir}^J=z,H_{ir}^{−},R_{ir}^{cc}=1]`。定义 `Ψ_{cc}^{sel}(D,a*)=6^{-1}Σ_{j=1}^{6}E[∫μ_{D,j}(z,H_{ir}^{−},R=1)\mathcal L_{a*,j}^{J,cc,clip}(dz|H_{ir}^{−},R=1)|A_i^{arm}=D,R_{ir}^{cc}=1,unsafe_ordinal=j]` 与 `Δ_{cc}^{sel}=Ψ_{cc}^{sel}(D,C)−Ψ_{cc}^{sel}(D,D)`。积分只改变当前 trial 的 `Z_{ir}^J`；较早 decision、public runtime、measurement 和 missingness code 均保持实际 `H_{ir}^{−}`，不按另一臂生成。该量固定称为 complete-case conditional selection association，不称纵向反事实、中介、间接效应或因果机制，`g_est` 也不是分析节点。Wang 等人（2025）只承担一般重复过程 factorization 背景，本研究承担 `R^{cc}`、该关联泛函、participant cluster、六 ordinal 等权与报告边界。

Participant randomization 识别 D 对 C 的 H1 总效应，但不把 H3 的完整案例选择关联变成因果作用。H3 要求 frozen `R^{cc}` definition、action/measurement version consistency、在 D 臂完整案例实际 `H_{ir}^{−}` 上的 C/D process shared support，以及只跨 participant 的 no-interference。当前 trial 的 budget、fatigue、回应和 repair 保留在 `Z_{ir}^J` 的先行位置；terminal measurement 也是当前过程的一部分，但删失指示与吸收态不是可积分节点。未登记的 decision 前过程字段记 `PROCESS_SCHEMA_OMISSION` 并停止报告 H3 数值。

Participant support 先要求每个 baseline-support 层的 D/C 各至少 `20` 名拥有至少一个 `R^{cc}=1` unsafe trial 的 participant，并要求每个 `arm×unsafe_ordinal` 至少 `20` 名完整案例 participant。Required process cell 由首例前 schema 与 public grammar 定义为在任一计划 unsafe prefix 可达、且理论上应在两臂结构存在的 `node u×outer fold f×arm a`，`unsafe_ordinal` 作为模型条件输入而分母在六 ordinal 池化。其集合 `\mathcal R_{afu}^{cc}` 只含 held-out fold `f` 中处于 arm `a`、`R_{ir}^{cc}=1`、节点 `u` 的 structural-presence bitmap 为一且 C/D public action-family mask 均允许的当前 unsafe-trial 记录，分母 `N_{afu}^{cc}=|\mathcal R_{afu}^{cc}|`。每个 required cell 均须 `N_{afu}^{cc}≥30`；任一分母为零或不足、任一 participant/ordinal 门不足，或两臂 structural-presence/mask 不对称，立即输出 `MECHANISM_NOT_ESTIMABLE`。不合并 baseline 层、不按 outcome 重分箱，也不用 probability floor 伪造支持。

对 `a*=C`，当前 trial 每个完整案例过程随机字段 `u` 计算 `ℓ_u(z,h)=k_{C,u}^{cc}(z|h)/k_{D,u}^{cc}(z|h)`，并定义 `k_{C,u}^{cc,clip}(z|h)=clip(ℓ_u,1/20,20)k_{D,u}^{cc}(z|h)/N_u(h)`；`N_u(h)` 是同一完整案例支持上的条件积分。对 `a*=D`，`k_{D,u}^{cc,clip}=k_{D,u}^{cc}`。对每个 required cell，`C_{afu}^{raw}=Σ_{j∈\mathcal R_{afu}^{cc}}I{ℓ_u(z_j,h_j)<1/20\;or\;ℓ_u(z_j,h_j)>20}`，`ρ_{afu}=C_{afu}^{raw}/N_{afu}^{cc}`；唯一 clipping 门是 `max_{a,f,u}ρ_{afu}≤0.05`，同时报告各 cell 完整案例分母、越界数、比例和全局汇总。离散字段按 schema 全部合法值精确求和。连续字段使用 32 点 Gauss–Legendre 规则：binary64 节点与权重由 `quadrature32-v1.json` 固定并校验 SHA-256，节点 `ξ_j` 映射为 `z_j=(L+U)/2+(U−L)ξ_j/2`，权重为 `(U−L)ω_j/2`。`subjective_probability` 的边界为 `[0,1]`，latency、sandbox、model compute 的边界为 `[0,该时点剩余预算]`，q15 字段为 `[0,65535]`；拟合密度落在边界外的左、右尾质量分别作为边界 `L,U` 的点质量参与归一化。边界相等时退化为单点质量。任一 required cell 超过 5%、normalizer 非有限或不在 `[10^-8,10^8]` 均输出 `MECHANISM_NOT_ESTIMABLE`。

`quadrature32-v1.json` 的十进制字符串先按 round-to-nearest-ties-to-even 解析为 binary64，负节点以正节点取反、权重不变。正节点—权重依次固定为 `(0.0483076656877383162,0.0965400885147278006)`、`(0.144471961582796493,0.0956387200792748594)`、`(0.239287362252137075,0.0938443990808045656)`、`(0.331868602282127650,0.0911738786957638847)`、`(0.421351276130635345,0.0876520930044038111)`、`(0.506899908932229390,0.0833119242269467552)`、`(0.587715757240762329,0.0781938957870703065)`、`(0.663044266930215201,0.0723457941088485062)`、`(0.732182118740289680,0.0658222227763618468)`、`(0.794483795967942407,0.0586840934785355471)`、`(0.849367613732569970,0.0509980592623761762)`、`(0.896321155766052124,0.0428358980222266807)`、`(0.934906075937739689,0.0342738629130214331)`、`(0.964762255587506431,0.0253920653092620595)`、`(0.985611511545268335,0.0162743947309056706)`、`(0.997263861849481564,0.0070186100094700966)`。Canonical JSON 键为 `negative_by_symmetry,positive,schema`，`schema="GL32-v1"`，无空白 UTF-8 bytes 的 SHA-256 固定为 `b3a1478548663fb06692c5d85909bab09e3b60002e290e05044f3893c5e3ab8d`。

Primary estimator 是 participant-level 五折 cross-fitted complete-case standardized plug-in。Fold key 为 `SHA256(LP("GEAP-CC-CF-20260817-v1")∥LP(salted_participant_id))`，在每个 baseline-support 层内按 unsigned hash 升序轮转到五折，同一 participant 的全部 trial 与展开行留在同一 original fold。Nuisance 基础 seed 集固定为 `{2026081661,2026081662,2026081663,2026081664,2026081665}`；256-bit `K_assoc` 的 SHA-256 在 T3 outcome 解封前提交，分析代码 hash 固定后公开 key。角色 `role∈{C_PROCESS_CC,D_PROCESS_CC,D_OUTCOME_CC}`、fold `f` 与基础 seed `s` 的实际 seed 唯一为 `UInt64BE(HMAC-SHA256(K_assoc,LP("GEAP-CC-ASSOC-NUISANCE-20260817-v1")∥LP(role)∥UInt8(f)∥UInt64BE(s))[0:8])`。每个 outer-training fold 只用 `R_{ir}^{cc}=1` 行分别拟合给定实际 `H_{ir}^{−}` 的 C/D 当前 trial process-law model 与 D outcome model；模型为两层 GRU-192 history encoder，categorical head 是全支持 softmax，连续 head 是八成分 truncated-logistic mixture，outcome head 是 sigmoid，不训练 observation head。优化器 AdamW，学习率 `3e-4`、weight decay `0.01`、participant batch `16`、gradient clip `1.0`、最多 `50,000` step，每 500 step计算 participant-disjoint validation NLL，连续十次未改善 `10^-5` 早停；每角色每 fold 在五个 seed 中依 validation NLL、较早 step、较小实际 seed 选唯一 checkpoint。D outcome NLL 对 D 臂 `R^{cc}=1` 行使用未加权 binary cross-entropy，禁止 inverse-observation weight。

对每个 held-out D 臂且 `R_{ir}^{cc}=1` 的 unsafe trial，固定其实际 `H_{ir}^{−}`，先取 D 臂 outcome regression，再按当前 trial 的 field-major、macro-node-major、slot-major 逆序逐节点积分，分别使用 `k_{C,u}^{cc,clip}` 与 `k_{D,u}^{cc}` 得到 `q_{ir}^{(C)}`、`q_{ir}^{(D)}`；不遍历、拟合或生成早期 trial。每个 unsafe ordinal 的 fold 估计先在 held-out `A=D,R^{cc}=1` participant 上等权，五折按该 ordinal 的完整案例 participant 数加权合并，最后对六 ordinal 各赋 `1/6`；`Δ_{cc}^{sel}` 是 C 与 D 两个 plug-in 分量之差。该实现没有 observation-hazard、inverse-observation weight、fluctuation、clever covariate、influence-function 更新或 targeting；任一产物出现这些字段即 fixture 失败。单节点闭式 fixture 固定为 binary `Z`、`μ_D(0)=0.50,μ_D(1)=0.20`、`P_C^{cc}(Z=1)=0.25,P_D^{cc}(Z=1)=0.75`，应得到 `Ψ_{cc}^{sel}(D,C)=0.425`、`Ψ_{cc}^{sel}(D,D)=0.275`、`Δ_{cc}^{sel}=0.150`；ratio 为 `1/3` 与 `3`，不触发 clipping。把两臂 `P^{cc}(Z=1)` 同置 `0.50` 时应得到 `Δ_{cc}^{sel}=0`。两套实现误差超过 `10^-10` 即停止机制分析。

区间采用 2,000 次 `arm×baseline_reviewer_support` 分层 participant-cluster bootstrap。Replicate `b` 的 seed 是 `UInt64BE(SHA256(LP("GEAP-CC-BOOT-20260817-v1")∥UInt32BE(b))[0:8])`；每次有放回抽完整 cluster，保留冻结的 `R^{cc}` 资格、multiplicity 与每个 source participant 的 original fold，重复抽中的副本仍在该 fold，禁止重分 fold。每次按固定 nuisance seed 合同只重拟 C/D complete-case process models 与 D complete-case outcome model，重算 quadrature 与两个 plug-in 分量，95% interval 取 percentile。失败 replicate 不补抽；失败率 `>5%`、任一 required cell/ordinal 分母不足或 `maxρ_{afu}>0.05`、任一 outer fold 的 D 臂 `R^{cc}=1` unsafe approval event 少于十、schema 遗漏、非有限 density/normalizer、两个实现不能逐节点重放，均输出 `MECHANISM_NOT_ESTIMABLE`。缺失对 H3 的主处置只是报告每个 `arm×unsafe_ordinal×reason_code` 的 planned count、`R^{cc}=1` count 与比例；辅助选择敏感性为 `Γ∈{1,1.25,1.5,2}`，允许每个完整案例行的非负权重在同 ordinal 内相对等权值落于 `[1/Γ,Γ]` 并分别优化 `Δ_{cc}^{sel}` 上下极值，再在 ordinal 内归一化；该包络只诊断对选择构成的敏感性，不填补 `R^{cc}=0` 行、不改写主 estimand。H1 的随机化 ITT 与 bounds 单独报告，不能替代该选择关联。

## 13 公平基线与消融

基线包括 raw canonical display、StaticBundle-v1、top-k、reranker、cross-attention selector、contextual bandit、Raw-POMDP、HumanState-POMDP-v1 和 generic proposition Transformer。所有学习基线共享 `J_content`、labels、human feedback、lattice、dynamic branch bytes、mask、reward、propensity、splits、steps 与 seeds。参数差 `≤1%`，FLOPs 差 `≤5%`，wall-clock 与搜索预算相同。

必须运行的机制干预：potential-content shuffle、grounding-history shuffle、participant-response swap、purpose-type shuffle、established clamp、action/state swap、binding shuffle、budget shuffle、order shuffle、逐项 loss removal、raw bypass、static-explanation 替换 action-derived evidence，以及删除 reviewer filter/repair 的技术价值策略。

## 14 泄漏、隐藏测试与 mirror noninterference

Paired mirror 保持全部部署可见字段、history、response、candidate grammar 与 public risk signal 相同，只交换 evaluator-side gold/oracle/hidden bytes。先在 evaluator-absent public run 记录 `response_event` exact bytes、event order、relative timing 和 exposure receipts；T−2 lattice/branch commit 后，read-only `mirror_replay_adapter` 将同一 transcript bytes 注入 evaluator-absent、evaluator-present-but-sealed、hidden-swapped 三次离线 replay。Mirror replay 不产生 confirmatory participant outcome，也不更新模型。每个 raw binary64 logit 另生成 `logit_q24=Int64(round_half_even(2^24·logit))`，溢出即 `MIRROR_Q24_OVERFLOW`；transcript hash、candidate IDs/bytes/order/mask/cost/latency、generator/branch traces、serialized q24 logits、selected action 与全部 public bytes 必须逐字节一致。Raw float logits 只存 audit sidecar，不进入 human-visible card，也不作为 mirror public-equality 对象。T−6 只存在 opaque oracle-recipe commitment，Gold、oracle 与 hidden test 到 T−1 才由不接收 lattice 的 evaluator 从已承诺 recipe 生成。任何模型、generator、task author、renderer 或 participant 读取 hidden 字段，或任何 public replay 字段不一致，均使相关 binding group 退出主分析。

## 15 复现清单与算力

必须发布或在许可允许范围内保存：四个 checkpoint、tokenizer/code encoder revision、图 schema、所有 manifests、candidate/branch hashes、generator 与 evaluator image digest、calibration map、constraint multipliers、propensity logs、split lineage、HMAC/fold/bootstrap domain 与 seed hash、配置、环境锁文件、五个模型 seeds、分析代码和结果 checksum。
